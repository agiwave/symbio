# 长期记忆与语义检索（插件专题设计）

> 本文件是 `symbio-plugin-memory` 的实施自述。系统级机制与跨插件判据见
> [DE-036 长期记忆与语义检索](../../../../docs/003-design/036-长期记忆与语义检索.md "DE-036-长期记忆与语义检索")；
> 本文只讲本插件怎么落地——事件格写方、检索打分面、巩固 / 遗忘闸门、校准与验收落点。

## 1. 落地状态：逐条对代码

四张事件格全在生产；检索打分面基本只是目标。

| 增量 | 今天 | 实现落点 |
|---|---|---|
| `memory/opened`（encoded） | 已在生产 | 情景记忆能力包的收束贡献 `src/episodic/contributor.rs`（经验 + 判断，轮末经 `land_contributions` 落格，DE-026）；载荷 `{content,tag,generation,vis_scope}`，没有 `vec` 键（恒空预留键与「有值的向量键」都不进事实形状，理由见 [DE-036 §3.2](../../../../docs/003-design/036-长期记忆与语义检索.md "DE-036-长期记忆与语义检索")） |
| `memory/progressed`（consolidated） | 已在生产 | `src/consolidate.rs::merge_next` 的合并产物，过 `accept`（max_gen=3 / min_fidelity=0.7）才入格 |
| `memory/closed`（forgotten） | 已在生产 | 同一模块尾部的排除式遗忘；无独立遗忘写入口 |
| `memory/asserted`（recalled） | 已在生产 | `src/semantic/contributor.rs::SemanticRecall` 收束贡献出事实、宿主落格；载荷 `{found, top, degraded}`，`degraded` 是降级的生产读数口。写方、名字与格位同住该包：这条事实没有第二个读方，不是共同读面 |
| `memory/asserted`（calibrated） | 已在生产 | 事件常量与格位由声明方持有（不在共享事件表，CS-007）；写方与读方各自在声明该事件的能力包内，统计列按对外视图名读同一份观测（DE-026） |
| 检索者 / 巩固者 | 形态 = 步内函数（非 ActorSpec 行） | 检索 = 会话主体轮内的一步（输入侧经 `src/recall/provider.rs::RecallProvider` 取 `recall` 段），巩固 = `memory-consolidate` 债的端口执行体（`src/consolidate.rs`；非「空闲触发」）。「非独立主体」的跨插件判据见 DE-036 §3.1。预算：检索者 500 有真读方（`memory_events::recall_view` 的 `Budget::new(0, RECALL_SCAN_QUOTA)`）；巩固者 86400000 的读方 = 读史窗口（`recall::decl::COST` = 4096 条） |
| 可见域 `vis_scope = thread_private` | 已在生产（召回读侧预过滤） | 缺省隔离两层：投影的 `actor==viewer` 过滤 + 读侧预过滤（`memory_events::recall_view` 的 `memory_visible`）；`thread_private` 只给记录它的会话，`shared`/`public` 跨会话按 `can_see` + 属主收放。`recall_view` 的读方 = 本轮主体。扫描范围 = 平级会话是刻意范围（判据 `recall_view_scan_is_one_level_deliberately`） |
| 投影 `recall` 混合打分 | 已在生产（语义维） | `src/recall/mod.rs::RecallRetrieval::retrieve`（入参 `{events, query}`）：`query` 非空 ⇒ 内容重叠分降序（`src/recall/score.rs::rank`，分词 = 拉丁词 + CJK 二元组），平手 ts 降序、再平手 seq 降序；`query` 空 ⇒ 纯 ts 降序（J2 平凡值）。读方 = 宿主 `memory_events::recall_view(...)`，只交可见域收放后的切片（I-8）。`tag` 已从检索面退出：折叠交出全部标签、读方自己挑（`every_tag_stays_in_the_live_set_so_the_reader_picks`）。`density/layer/spread/decay` 逐条判过、一个都不落（系统级结论见 DE-036 §3.2）。排序内核是生产与 `verify/recall_eval.rs` 共有的一份源码（`#[path]` 包含） |
| embedding / 向量索引 | 判过、不落 | 语义索引是实现细节，不喂记忆召回：`memory.encoded` 载荷没有 `vec` 键——写进事实等于把索引搬进事实源 |

## 2. 验收断言的落点

判据随能力走——投影搬进能力包，四条断言跟到折叠与检索面上：

1. `src/recall/live.test.rs::as_of_hides_events_that_have_not_happened_yet`（as-of）；
2. `src/recall/mod.test.rs::exhausted_quota_degrades_with_partial_results_instead_of_silently_empty`（配额耗尽降级出部分结果，而非静默空）；
3. `src/recall/live.test.rs::only_the_cognitive_owner_is_folded`（跨会话隔离；跨会话隔离的判定点由能力包读侧收放守，原宿主读侧闸已随 B2 退场）；
4. 折进验收 1 的反向锚（`live(&events, i64::MAX)` 必然被巩固改变 ⇒ 忽略 as-of 的实现抓得住），不单列。

溯源 / Translator 判据：`src/semantic/contributor.test.rs::the_anchor_points_at_the_turn_opening` /
`the_fact_keeps_the_invariants_green`（写方随 L2c 迁进能力包）。巩固入库闸门（N8）：
`src/consolidate.rs` 的 `accept` 边界，判据 `consolidate.test.rs::accept_rejects_beyond_the_generation_ceiling` /
`accept_rejects_below_the_fidelity_floor`。e2e = `t29-memory-recall.mjs`。

验收 2 的出口（读数口 + 注入段标注）：`src/semantic/contributor.test.rs::degraded_is_recorded_instead_of_dropped`
（事实那一半）+ `src/recall/section.test.rs::says_degraded_instead_of_pretending_completeness`（排版那一半）。

verify 面：`verify/recall_eval.rs` 跑生产排序内核（`#[path]` 包含 `src/recall/score.rs`），出生产检索面的
recall@k；`consolidation_fidelity.rs`、`cognitive_fit.rs` Q3.1/Q3.2 俱在。

## 3. 名册锚点（订正后）

- 情景记忆 → `src/episodic/contributor.rs`（编码是能力包的收束贡献；读侧与巩固的合并算法按

- 语义记忆 → `src/semantic/contributor.rs::SemanticRecall`（召回事实的写方；非文件形态的 `src/memory.rs`）；
- 世界模型 → 「—」诚实（未落地）。
