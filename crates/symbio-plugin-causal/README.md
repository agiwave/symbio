# 因果结构插件（causal）

一条领域事实、一个工具、一张视图：模型可以断言语义世界里的「A 导致 B」，每次成功断言
落成一条 `causal.link`（`domain × asserted`），那些事实再被折成一张可读的因果图。
名册 #33「因果结构」+ #39「因果表征工具」的能力包。

## 它交什么

| 面 | 交出物 | 谁用 |
|---|---|---|
| 工具 | `causal_assert(cause, effect, confidence?)` | 模型（经工具面调用） |
| 行为 | 一次成功断言 ⇒ 一条 `causal.link` 草稿 | 宿主唯一的写口（I-1，D-213） |
| 事实 | `causal.link`，格位 `domain × asserted`，字段 `cause` / `effect` / `confidence` | 写闸按声明校验名字与格位；`seal` 按归宿行判它有没有人看护 |
| 视图 | `causal.links` → `{ count, edges, causes }` | 任何按名字读的插件（`shared_views`，D-221） |

**没有自有路由、没有配置、没有 VDFS 挂载点、没有新端口。**

## 为什么三件事必须同包

名册把它们记成两行，但它们**共用一条事实**：没有写入方，视图永远是空的；没有视图，
事实只能靠读转写看。分成两个包就得让其中一个跨包读别人的私有事实——那正是 D-221
要消灭的形状。故同包落地，逐行处置账见 `docs/003-design/026-能力拆分与影响类.md` §2.3。

## 幂等与拒止

- 幂等键 = 轮锚 + 调用 id + **方向**（`c-a->b`）：A→B 与 B→A 是两条断言，不能互相吞掉；
- 同向重复在执行**前**被拒（`before` 只看本插件自己的 `causal.link` 事实，不看工具名），
  模型拿到的工具结果带拒因；
- 自环（因 == 果）在工具与行为两层都拒：图里多一条自环只会让每个读方多滤一次。

## 视图的口径

`causes` 是**只出不进**的节点（图上没有入边的起点），不是「根本原因」的判定——那要
结合读方自己的领域知识，而本插件不认识任何领域。把结构说成结论是这类视图最容易犯的
错，故只交结构事实。

## 路由

**无自有路由**（`route` 恒 `NotFound` 并指路到工具与视图）。断言的入口是工具（模型侧）、
读出口是视图（宿主侧），两条都比一条自造协议更短，且都不需要本插件认识调用方。
