# 技能编译与自我改进（插件专题设计）

> 本文件是 `symbio-plugin-skill` 的实施自述。系统级机制与跨插件判据见
> [DE-041 技能编译与自我改进](../../../../docs/003-design/041-技能编译与自我改进.md "DE-041-技能编译与自我改进")；
> 本文只讲本插件怎么落地——字段常量、配置开关、测试 / e2e 落点、校准与退避。

## 1. 能力怎么做到的

成功的执行轨迹被编译成可直接命中的技能，下次遇到同类情况不再走 LLM；同时保留
「反自动化回退」——异常或高不确定时退回完整推理。

| 看起来新的东西 | 本插件里的实现 |
|---|---|
| 技能 | 写 `memory.encoded{tag:"skill"}` 事件——是事实，不是特殊类型 |
| 编译 | 写侧函数 + 开关：轮末贡献者 `contributor::SkillCompile` → `memory.encoded{tag:"skill"}`。**编译不是投影**——投影是纯读函数（事件进、视图出），编译有外部输入（本轮收束正文）与 `append` 副作用，类型上不可投影化；「一个 `Decider` 产出事件」里的 Decider 是角色行，未立项。投影侧读技能的是 `recall{tag:skill}` + `calibration` |
| 加速 | 命中技能后走 `budget_ms` 更小的 ActorSpec |
| 回退 | 同一批事件下的另一个 ActorSpec 取值 |

编译后的技能是一条 `budget_ms` 更小的 ActorSpec，不是另一套机制。系统 1 / 系统 2 在 v2 里
不是两个系统——由 `skill_compile` 与回退规则动态转换：
`reasoner`（慢、有中间轨迹）→ `skill_compile` → `decider`（快、直接命中）→ 异常时回退。

## 2. 落地状态：逐条对代码

本阶核实：快路已随 B2 退场；事件格行已按生产格收敛。

| 增量 | 今天 | 说明 |
|---|---|---|
| 事件格子 | **部分在产（判定已退场）** | 编译写 `memory/encoded{tag:"skill"}`（标签常量 `src/decl.rs::SKILL_TAG`；sdk 读侧词汇已退场，编译策略在 `src/contributor.rs`）、观测写 `memory.calibrated{skill_id,fallback}`；判定 `skill.answered` 已随 B2 退场 |
| ActorSpec 技能命中者（80ms） | **已随 B2 退场** | 技能行 `skill.recall` 的零模型往返命中随 B2 与实现一并删除，本包不再有这一行 |
| ActorSpec 编译者（5000ms） | **裁决：形态 = 步内贡献**（非 ActorSpec 行） | 编译是轮末的一条 `Contributor`（`contributor::SkillCompile`；已确定「写侧函数 + 开关即目标形态」）。按 [DE-038 §3.1](../../../../docs/003-design/038-多主体与对等承诺.md "DE-038-多主体与对等承诺") 的「规格粒度 = 主体」判据，编译者**不是独立主体** ⇒ 不建 ActorSpec 行；其声明的 `capabilities: []` 在 `PermissionMatrix::new` 直接被拒（空能力行表形状表达不出），本就落不进表。**预算 5000 撤下**：编译不读任何投影（它的历史读只有「这轮 trigger 编过没有」的一次线性查重），给它编一个读方就是给拟人化记账续命。与巩固者的区别在于巩固者有一处全史聚合读，那里的护栏是 `recall::decl::COST`（巩固护栏） |
| 投影 `skill_compile` | **裁决：写侧函数 + 开关即目标形态** | 无此名 Projection，且不应有：编译 = `contributor::SkillCompile`（交 `FactDraft`，宿主落格；输入含本轮收束正文），投影是纯读函数。开关 `skill_compile_enabled`（默认 false，`src/config.rs`）的翻向前置条件见 §4 |
| 投影 `calibration` | **已在生产** | `src/decl.rs::calibration_ledger`（DE-026；对外名 `skill.calibration`），消费方 `skill.retreat` 视图 + 读出口 `stats.rs` 的校准列（按名字读）；行侧置信度闸已随 B2 退场 |
| 反自动化回退 | **视图在产；宿主侧过滤已退场** | 作用点 = 提示词摘出：技能包 `skill.retreat` 视图（`src/decl.rs::retreating_skills`，阈值 `CONFIDENCE_THRESHOLD = 0.8`）；宿主的请求装配按 seq 过滤 `turn.recall_view` 已随 B2 退场 |
| 凸度/密度 | **裁决：划出 S11** | 全仓 grep「凸度/sharpness/density」0 命中。读数今天不存在：`calibration` 只有 `uses`/`fallbacks`（按 skill_id），那是 reliability（1−回退率）；凸度要的是竞争分布（命中 vs 回退的分离度）、密度要的是 recall 的 `density` 形参——两样输入都没有。按 exit 纪律：只测 reliability 不许顶着「凸度」的名字记账。DE-040 登记表 `C02` 行的「四层是同一个投影的四个参数值」同批订正为登记形态（非生产刻度） |

## 3. 验收断言的执行方

1. 编译产出的技能事件 `produced_by` 必须非空（指向源轨迹）→ `src/contributor.test.rs::compiled_skill_requires_provenance`；
2. 命中技能后 `cost_ms` 显著低于未命中路径 → e2e t41「命中轮请求数不增」（技能快路行已随 B2 退场）+ `src/decl.rs::ROWS`（技能快路行）；
3. 置信度低于阈值 → 必须走 `reasoner`，不得走技能路径 → `src/decl.test.rs::only_low_confidence_skills_retreat`（置信度 0.5 < 0.8 ⇒ 不命中且进 `skill.retreat`，反向 0.95 ⇒ 命中）；
4. 反向用例：把编译者的 `produced_by` 置空 → 断言 1 必须失败 → `compiled_skill_requires_provenance` 的反向半（`produced_by` 置空 ⇒ I2 抓住）。

e2e = t35（编译-召回接线）/ t41（快路）；verify = `latency_gate.rs`（反射档不调模型的构造形态）。

**S11 名册行**：程序记忆→`src/contributor.rs`（生产编译链的写方）；技能编译→
`contributor.rs::SkillCompile`、反自动化回退→`src/decl.rs::retreating_skills`；自我模型 / 校准→
`src/decl.rs::calibration_ledger` ✓ 生产消费。

## 4. `skill_compile_enabled` 翻默认值的前置条件

写死，翻默认值的动作须满足以下两条：

1. **S11 读数落地**——凸度读数或明确替代的刻度（§2 裁决：今天不存在），即「这条技能有多强」
   不止 reliability 一个数；
2. **价值验收埋点出数**——编译链路的价值读数在真实流量上出得来做证据（见
   [DE-016 价值验收埋点](../../../../docs/003-design/016-工程落地与验证.md "DE-016-工程落地与验证")）。

两条都满足才可翻向。在此之前 `default_skill_compile_enabled = false` 是安全退路口
（关掉它系统仍完整运行），默认翻向等于把未验证的自我改进塞进默认路径。

## 5. 静默失效与强制

| 约束 | 违反时信号 | 强制方式 |
|---|---|---|
| 技能必须有溯源轨迹 | 无 | I2 断言：`produced_by` 指向源轨迹 |
| 高不确定时必须回退完整推理 | 无——可能一直用错技能 | `calibration` 投影 + 阈值断言 |
| 「凸度 / 密度」不许由 reliability 冒充 | 无——把 1−回退率印成「凸度」即可读数失真 | 裁决：读数今天不存在（§2），`stats` 的校准列只许报 `uses`/`fallbacks`；要立凸度读数先补竞争分布的观测面，另立批次 |
| 编译不得污染在途决策 | 无 | `Timestamp` as-of（同 S06） |

> 必须保留反自动化回退（Beilock & Carr 2001 *choking under pressure*）：全自动化在压力下
> 会以异常方式失效。这不是保守，是被实证过的失效模式。

## 6. 边界

- 「哪些轨迹值得编译」是算法问题，架构只提供 `skill_compile` 这个位置。
- 凸度 / 密度读数不存在：观测面只有 uses / fallbacks（reliability），没有竞争分布；
  `recall` 也没有 `density` 形参——补读数要先补观测面，另立批次（裁决）。
- 从「改参数」到「改架构」的跨越不在本阶范围内（那是决策，不是数据）。
