# 安全运行环境插件（sandbox）

沙箱是**被调用的执行环境**，不是反过来依赖工具实现。本插件是横切沙箱机制的实现方 /
发布方：它提供一份运行环境的句柄，其它插件通过上下文取用，
不关心它是怎么实现的。

## 交出什么

| 面 | 交出物 | 谁用 |
|---|---|---|
| ctx 句柄 | `Arc<dyn SandboxFace>`，经收集期发布进共享槽 | 编排层拦截、工具许可查询 |

接口的形状定义在 `symbio_platform::sdk::sandbox`，门面转出为 `symbio_plugin_api::SandboxFace`。
SDK 与门面**不含任何工具名、op 常量、黑白名单配置项**——那些全是本插件的内部数据。

## 两个维度，一个句柄

`SandboxFace` 的两个方法对应沙箱的两个正交维度：

- `intercept(tool_name, args)`：执行隔离 / 审批载荷。编排层在工具执行前调用；
  工具名在这里是不透明透传，本实现只对用户显式配置的工具有拦截条目。
- `permits(facts)`：能力约束。工具把执行期意图事实（开放 kind + value）交上来查询，
  只得到 bool；「问用户」这种事在沙箱层统一处理，不在每个工具里实现。

两种机制的形状不同（一个是转发式拦截，一个是查询式），由接口屏蔽差异，
调用方不需要知道沙箱内部走哪条路。

## 不做什么

- **不认识工具**：没有工具清单、没有 op 常量、注册收口没有沙箱分支；
- **不进架构层**：策略、具名沙箱配置、拦截规则都住在 `src/engine.rs`；
- **不写前端**：会话里选哪个沙箱是机制化配置，前端不理解沙箱概念。

## 缺席语义

没有装本插件、或用户没选沙箱时，共享槽里没有句柄，调用方全放行。
这是**诚实降级**，不是假装有隔离——前端既有的「批准不等于隔离」提示继续承担声明责任。
