## 内容

规则 / 机制 / 任务之外的第三类条目性元素是**决策**。owner 不变：决策正文归
[DECISIONS.md](../../docs/DECISIONS.md) 索引 + `decisions/*.md` 分册（职责表），
registry **不复制决策正文**。本任务清点散落在 plan / 参考文档里、不属于 ADR owner
的决策型表述，逐处定处置：在 ADR owner 补条目 + 原处改链接，或确属「跟进动作」
（落地批次）则登记为 `task`。定案写回 14 §6，不在两处复述。

## 处理过程

- **清点范围**：`docs/plan/*.md`（含 `roadmap/`）、`docs/design/*.md` 的决策型表述
  （「定案 / 决定 / 裁决 / 取舍 / 否决 / 采纳 / 倾向」等措辞），逐处问「这条事实的 owner 是谁」。
- **清点结论——三分**，只有第三类才是散落决策：
  1. **架构面取舍（owner = plan/README §2/§3）**：如「1 个原语 + 1 条签名约束」、
     「投影不做 trait」、「只承诺 L0+L1」——它们的 owner **就是** [plan/README §2](../../docs/plan/README.md)
     （职责表：「目标架构（v2）与迁移计划」的 owner，其余文档只引用），`01 §1.4/§1.5` 是它的
     细节落地。**有 owner，不是散落**——不迁、不改。
  2. **落地决策（owner = ADR）**：plan 文档里的行为面决策（如委派者三项真源 = ADR-047、
     出厂档位改 full = ADR-048）**都已引 ADR 编号**，满足职责表「其它文档只引用 ADR 编号」。
     **有 owner，不是散落**。
  3. **散落决策（无 owner）**：清点出的**唯一**一处 = `docs/design/third-party-plugin-spec.md`
     §10「待确认的决策」——6 条（`D1` 已定案 = ADR-032；`D2` 外部插件形态 / `D3` 权限强制程度 /
     `D4` 连接信息放哪 / `D5` 是否引入 JSON-RPC / `D6` 生命周期钩子形态**未定**）。
     该文自己写着「定案后每条写成一条 ADR」，但**没有任何东西追踪它们**。
     ⇒ 处置：登记为跟进任务 [`T-007`](./T-007.md)（决策正文归 ADR，registry 只 track 跟进），
     原处 §10 加指路（**备案在登记处**）。
- **形态定案**（写回 [14 §6](../../docs/plan/14-登记与汇总机制.md)）：
  **决策正文的 owner 永远是 ADR，registry 不复制决策**（「明确不接管」已在 14 §6）；
  散落决策的**接管边界**只有两种情况——① 已定案 ⇒ 在 ADR owner 补条目、原处改链接（若原文有正文，
     删正文只留指回）；② **未定案的决策** ⇒ 登记为 `task`（它就是一条「跟进动作」，
     `exit` = 「定案并写 ADR」），原处只留指路。**不为决策新开 kind**（同 T-005/T-006 的判法）。
- **验证**：`registry-audit` 零违规（`T-007` 的 `deps: [T-004]` 在本条闭环后成立）。
