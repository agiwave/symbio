## 内容

[04 §3.1](../../docs/plan/04-工程落地.md) 的 **A 表**是「22 步到底做完没有」的登记处。它的**状态**
是 task 类元素（条目的 `status` 字段），但**明细**（每步引入了哪些符号、摘了哪些批次的标记、
什么判据证明接入）是逐批施工的事实，已由清偿批次提交与 `dead-code-audit` 的 R-002 账本承接。

本条目是 A 表的**状态主语**：它把「22 步状态」从手抄表收敛成一条登记——
`done` = 四判据（实际接入 / 死码归零 / 门禁绿 / 出厂档位压过）全部成立。若将来某步回退，
开一条独立的 `task` 条目并把本条目退回 `doing`（`signal` 写回退证据）。

**明细不迁**（14 §6 owner 判断前置）：A 表的「缺口 → 接入判据」列是**owner 指认**
（每步接哪条链路、摘哪批标记），owner 是清偿批次提交与 [`S31-1`](../spec/S31-1.md) 的死码账本，
本条目只登记「整体是否闭环」这一件事，不复述逐批明细。
