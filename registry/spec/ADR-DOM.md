## 规范

每条 ADR 必须声明 `domain`——它回答「**这条决策约束谁**」，决定 README 该往哪指、
读者该去哪找。五册正文（`docs/decisions/*.md`）合流进 `registry/adr/` 后，
**册不再是边界**，域退化成**条目上的一个字段**：过滤 / 分组从「翻到哪一册」变成
「按字段筛」，而字段是机读的、可判的。

域是**闭集**，全职在 [`registry-lib`](../../scripts/registry-lib.mjs) 的 `ADR_DOMAIN`：

| 域 | 收什么 |
|---|---|
| `平台基座` | 插件架构 / 路由 / 注册 / 执行接口 / `symbio_core` 准入 / 身份 / 生命周期 / 对象创建 |
| `会话与执行` | 编排 / 上下文 / 转写节点与实时面 / 输入 / 响应性 |
| `资源与地址` | `VdfsProvider` / 读侧成本 / 变更信封 / 新建与导入 / 地址归属 |
| `模型与协议` | 多协议适配 / TLS / 本地嵌入 / SSE 解析 |
| `智能体与记忆` | agent 目录宿主 / 记忆的两个作用域 |

**按域归而不是按编号区间归**：区间是**时间**的产物，读者找的是**职责**。
一条决策改属（例如会话响应性从「实现」升为「架构」）只该动它自己的 `domain` 字段，
而区间拆法会让每次新增都撞上「该塞进哪一段」。

## 判据

`scripts/registry-audit.mjs`（经 `registry-lib`）的 **RG-019**：`domain` 不在 `ADR_DOMAIN`
闭集内即红——新增域必须同批进闭集与本条，不能随手写。闭集与本表的相等性由人工核对
（表小且变动极低频，不值得再开一条对账判据）。
