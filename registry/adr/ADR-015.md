## 决策

**背景**：会话实时显示原基于**事件流**（`Status{busy|idle}` / `Abort` / `Error` / `Connected`，前端 `switch (event.type)` 逐类处理，另靠 `last_failed`、`sessionErrors` 等平行状态拼补）。代价是**正确性依赖到达顺序**，而顺序不是免费保证的——`eventBus.ts` 里那段 `replayBuffer`（切会话防乱序缓冲）就是为修顺序而存在的机制。**一段只为修顺序而存在的机制，说明模型本身选错了**：把「现在是什么」表达成「刚刚发生了什么」的增量序列。

**决策**：**把运行态从事件里拿出来，变成节点的属性**，前端按地址消费节点状态。
- 会话节点 `<根>/session/<sid>` 承载 `status`（`working` / `active` / `failed`）+ `attributes.outcome`（`completed` / `aborted` / `failed`）+ `attributes.error`；
- 消息节点承载 `status`（`pending` / `streaming` / `waiting_user_action` / `completed` / `failed`）；
- 状态类变更**必带全量节点视图**，消费端**零回读**；
- 前端只有按地址分派，**没有 `switch (event.type)`**；等待审批、活动文字、可重试性等都由节点表**派生**（纯函数）。

**理由**：状态**幂等、可交换、丢一次不影响正确性**，事件是增量、有顺序、丢了没有第二次机会——一次变更携带全量视图后，「谁先到」只影响收敛**速度**；顺序敏感类补丁随之消失；判据只剩一处（「上一轮失败了吗」= `status == 'failed'`）；修掉 `completed` 与「未标注」都映射成 `active` 的有损映射。

**后果与不变量**：
- **任何送达前端的会话状态变化都必须经 `emit_session_state`**（运行态的唯一出口），且 `updated` 必带节点视图。漏发即 UI 永久停在旧状态且无人纠正。消费者侧**不做静默回读兜底**（那会把它掩盖成「看起来能用」），只记 warn，靠下一次 `list` 快照收敛。
- **词汇不合并**：`streaming`（消息）与 `working`（会话）保持两个词——合并会连带改 `status-*` CSS 类名与 `isWorkingStatus()`，而**漏改 CSS 类名不报错、不失败，只会让流式动画静默消失**。
- `kind = "session"` 频道已整体废除，会话实时面收敛到 VDFS 变更频道（ADR-025）；机制细节见 [session/docs/node-state-streaming.md](../../symbio/src/plugins/session/docs/node-state-streaming.md)。
