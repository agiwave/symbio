# Work 插件

**工作区记忆**：让模型跨会话记得住这个项目的约定，并且**改得动**它。

会话是一次性的——每开一个新会话，上一轮说过的偏好、已定的约定、反复踩过的坑都要再说一遍。本插件给工作区补上一份跨会话保留的记忆，并在每轮请求里注入系统提示词。

## 职责

两件事，**缺一不可**：

| 交出什么 | 机制 | 缺了会怎样 |
|---|---|---|
| 系统提示词片段 | `CapabilityVisitor::register_system_prompt` | 模型不知道记忆存在，等于没有 |
| VDFS 挂载点 `<根>/work` | `CapabilityVisitor::register_vdfs_provider` | 只能读不能改，记忆永远长不大 |

两者都在 `traverse(TRAVERSE_AVAILABLE_TOOLS)` 这一次广播里交出——与工具、模型服务、其它挂载点共用同一次收集，不新增任何收集通道。

## 落位与地址

```text
{workdir}/AGENTS.md                      记忆本体（行业通行约定，随仓库可版本化）
<根>/work/AGENTS.md                     可编辑地址（模型与用户共用）
{homedir}/work/PLUGIN.yml        本插件配置（两道闸门开多大）
```

文件名与位置**刻意对齐行业惯例**（`AGENTS.md`：给编码智能体的工作区级指令文件），于是记忆**不属于 symbio**：换工具照样生效，能被 `git` 版本化、被 review。

## 作用域闸门：选了工作区才有记忆

`ctx[WORKDIR]` 缺失 / 为空 = 用户没在工作区上下文里提问 → **什么都不注入**。这不是优化，是语义：把 A 项目的约定带到 B 项目、或带进一个根本没选工作区的闲聊会话，都是错的。闸门在 `plugin::WorkPlugin::store_with` 一处收口。

## 归属：这一层只归本插件

`{workdir}/AGENTS.md` 只由本插件读写与注入——约定是 **谁能读写它，谁负责注入它**，一个作用域只有一个所有者。（两个插件各读一遍就会让同一份内容两次进上下文，而模型改不动它。）

## 路由

**无自有路由**（`work/*` 由 home 终结，清单见 [ROUTES.md](../../../../docs/reference/ROUTES.md) §Home 插件）：`route()` 直接返回 `NotFound` 并指引到 VDFS。记忆的读 / 写 / 编辑全部由 `<根>/work/AGENTS.md` 承接——宿主与模型走同一条链路，不为「记忆」再造一条协议。

记忆**不可删除**（`delete` 恒 `Forbidden`）：删除即丢失全部长期事实，而抹掉之后没有东西能把它找回来。要清空就写入空内容——那是一次可读、可审、可撤销的显式动作。

## 机制在共享实现，本插件只剩「个性」

工作区 / 会话 / 智能体三层记忆形态相同，共用 `providers/memory` 一份实现——**形态、两道闸门（写侧拒绝 / 读侧截断）与「谁能读写它，谁负责注入它」的归属原则见该模块文档注释**。本插件负责的只有：**落位、地址、标题、空内容提示、两道闸门开多大**（`memory_max_bytes` / `memory_inject_max_bytes`）。

## 关联

- 记忆的共享实现：`providers/memory`（三层共用；文件名各层自定，本层为 `AGENTS.md`）
- 另两层记忆：`../session/README.md`（会话记忆）、`../agent/README.md`（智能体记忆）
- 系统提示词的拼接与消费：`../session/README.md`
