## 0. 三句话

1. **两个真实页面**：`tauri/src/views/MainLayout.vue`（全局壳：路由出口 + Toast + 引导浮层）
   与 `tauri/src/views/VdfsView.vue`（唯一的资源地址页，宿主是唯一的三栏控件
   `tauri/src/components/vdfs/VdfsWorkbench.vue`）。其余路由是旧地址重定向。
2. **用户看到的一切都是节点**：列表项、详情、消息、压缩记录在后端都是节点
   （`VdfsNode` / `ChatMessage`），前端按节点的 `ext` / `msg_type` **分派渲染器**
   （`tauri/src/registry/vdfsRenderers.ts` / `tauri/src/registry/messageRenderers.ts`）。
   新增一类资源或一种消息，交互代码零改动。
3. **交互时间轴由后端驱动**：前端不做乐观回显，等待期一律用「状态 + 骨架」表达
   （理由见 `tauri/docs/FRONTEND.md`）。

## 1. 页面与导航

| 位置 | 是什么 | 用户动作 | 结果 |
|---|---|---|---|
| 首页（`/vdfs`，绑 `<根>`） | 资源根：左侧图标栏 = 挂载点（类别） | 点类别 | 中栏换成该类内容（**不换页面**） |
| 地址页（`/vdfs/<dir…>`） | 钻入某一层后的页面（如会话内部） | 点中栏目录 / 详情里的「进入下一级」 | **push 新地址页**，由同一个 `VdfsView` 承接 |
| 左上角（非首页） | 返回键 | 点 | 回 **push 来源页**（浏览器历史 back）；深链直开无来源时回首页 |
| 左下角（全页面） | 系统目录入口（本地 / 远端） | 点 → 切换目标 | 重挂三栏控件、重拉会话清单、回首页 |

- 页面**不出现面包屑**、**不出现「新建目录」按钮**——路径即导航，新建 = 新建一种资源类型。
- 一个地址 = 一个可回退的页面；层级靠「左栏切目录 + 中栏钻入 + 返回键上溯」三段承担。
  规范见 `docs/design/vdfs-frontend.md`。

## 2. 全局反馈通道（跨页面只有这四条）

| 通道 | 何时出现 | 落点 | 实现 |
|---|---|---|---|
| Toast | 保存 / 新建 / 删除 / 切换目标成功或失败 | 全 App 单例，浮在最上层，3s 自动消失 | `tauri/src/components/common/Toast.vue` + `tauri/src/composables/useToast.ts` |
| 提示音 | 一轮结束（completed / aborted / failed 三种音色），按 `(会话, 结局)` 去重 | 无声通道，设置在「外观」页 | `tauri/src/services/completionChime.ts`、`tauri/src/stores/soundSettings.ts` |
| 骨架 | 数据未到（列表 / 详情 / 会话历史） | 就地占位，不遮挡已有内容 | `tauri/src/components/common/SkeletonBlock.vue`、`tauri/src/components/message/TurnPending.vue` |
| 错误条 | 失败需要用户决策 | **在流内**（会话流末尾 / Turn 组内 / 工具卡内），不是页面顶部横幅 | `tauri/src/components/message/MessageErrorBox.vue` |

- 唯一的**全局状态角标**是系统目录左侧的红点（连接目标不可用）；重连与重新同步是
  自动的，界面不弹窗、不阻断输入（见 `tauri/src/services/eventBus.ts`）。

## 3. 资源浏览器（`VdfsWorkbench`）

| 动作 | 反馈 |
|---|---|
| 点左栏类别 / 子目录 | 中栏就地换内容，右栏清空（详情属于**当前目录**） |
| 点中栏卡片（文件） | 右栏按 `ext` 出详情；普通资源是定义驱动的表单 |
| 点中栏卡片（目录） | push 进入该目录地址页 |
| 列表筛选框 | 只筛**已加载**的那些条目；命中 0 与「目录为空」文案不同；还有更早的页时提示「可能不全」 |
| 滚到底 | 自动续页（去重后新项为 0 即收敛，不提示「没有更多」） |
| 新建（右上角 / 空态按钮） | 右栏进入该类资源的**新建详情**（中栏在此时整体收起）；新建的空态本身给一个可执行入口「新建第一个 ⟨类型标题⟩」 |
| 详情里的动作 | 全部来自**节点定义**（后端声明）与**页面机制**（删除）两处，位置由机制统一排（导航类动作恒在行尾） |
| 保存 / 删除 | 成功 → Toast + 就地重载；失败 → 字段级错误高亮或详情区错误文案 + Toast |
| 「进入下一级」 | push 进该节点的同名目录地址（会话、agent 等都是这一条通道） |

## 4. 会话工作区

会话是唯一**有状态**的资源：它的详情不是一个表单，而是一块聊天工作区
（`tauri/src/components/vdfs/Session.vue` → `tauri/src/components/session/ChatMainPanel.vue`）。

### 4.1 进入

| 入口 | 形态 |
|---|---|
| 列表点会话卡片 | 已落盘会话：头部 + 消息流 + 输入区 |
| 「新建」 | **草稿**：同一张详情页的另一种状态（输入区与选项栏在场，发送第一条消息时才真正创建会话） |

### 4.2 头部

- 左：会话标题、运行中圆点「● AI 处理中」；点标题旁的铅笔进入**内联重命名**
  （Enter 提交 / ESC 取消 / 失焦取消）。
- 右：**动作区** = 会话自有动作（「进入下一级」）+ 页面机制动作（「删除」），
  两者由机制去重合并、导航类动作恒在最右并有分隔线。

### 4.3 正文的五态（互斥，按顺序判定）

1. 未选会话 → 文案引导；
2. 历史加载失败 → 错误文案 +「重试 / 忽略」；
3. 历史加载中 → 「正在加载会话历史…」（**消息准备好之前不挂聊天面板**，避免中间态闪烁）；
4. 会话没有工作目录 → 引导选择目录（原生对话框 / 用最近一次的目录）；
5. 正常 → 消息流 + 输入区。

### 4.4 消息流

- 每个节点由**统一外壳**呈现：图标 + 标题 + 状态标签（运行中带三点与**已运行秒数**）
  + 收起态单行摘要 + 悬停/聚焦操作（编辑 / 重试 / 删除）。折叠策略来自 `msg_type` 的登记表，
  外壳只持有「用户是否手动展开」这一交互态。
- 节点头是**折叠开关**（键盘可达：Enter / Space）；用户消息右对齐、可编辑；
  失败的工具调用可就地重试；**只有根级节点可删除**（深层节点删了会留下悬空引用）。
- 嵌套只用「缩进 + 左侧引导竖线」表达；工具调用的「过程」段以同一套节点形态递归直排。
- 等待骨架有两个来源（Turn 节点已在但还没内容 / 会话在跑但流里还没有在途节点），
  同一时刻只会出现一条。

**两类系统节点**（都在流里、都有位置，但都不是对话内容）：

| 节点 | 形态 | 它交代什么 |
|---|---|---|
| `🗜 上下文压缩` | 运行中带三点与已运行秒数；完成后正文是「已压缩上下文（N → M 条）」+ 一行事实 | 压缩后水位 / 上限 / 触发来源（自动整理 · 模型主动 · 手动重试）/ 压掉几条 |
| `🧠 历史记忆` | 默认收起；展开是那段记忆的**原文**（原样，不剥内部标记） | 压缩后水位、「完整历史已转存」 |

历史记忆**本身是一条消息**：后端把它写成 `role = user`（多数 provider 要求对话以 user
开头）并在 `meta.compacted` 打标，前端据此走记忆形态而**不是用户气泡**——没有这一步，
系统写的记忆会被读成「你说的那句话」。它也不提供悬停操作（系统记忆的编辑 / 删除
不走悬停）。

两类节点的事实行都是**按字段渲染**：字段由后端随节点下发，旧后端没有这些字段时
只剩正文那一行（同一份前端两代后端都能用）。

### 4.5 输入区

| 动作 | 反馈 |
|---|---|
| Enter | 空闲时发送；Shift+Enter 换行；**运行中不提交**（回车是发送手势，不该用来中止正在跑的一轮——此时它就是换行，可以先把下一句写下来） |
| 发送键 | 空闲时 = 发送（无内容时禁用）；**运行中 = 停止**（红色方块，输入框里有没有字都一样——呈现与动作是同一个语义点） |
| 停止 | 中止当前轮 **并清空排队**（只中止不清队会让它立刻跑下一条） |
| 上传图片 | 选文件（可多选）或**直接粘贴**（含截图）；缩略图可单个移除；发送时随消息一起提交 |
| 发送后 | 输入框清空并复位高度、视线贴底；发出的内容**不立刻上屏**，等待期由骨架表达 |

### 4.6 会话选项栏（输入区下方一排按钮）

- 渲染的是后端随节点下发的**配置定义**（工作目录 / 智能体 / 模型 / 模式 / 风险等级…），
  前端不含任何具体选项：字段按 `widget` 分派交互（下拉候选 / 原生目录选择 / 子表单 / 开关）。
- 已落盘会话：改一项立即回写该会话；草稿态：选择先缓冲，随「创建会话」一次性写入。
- 候选为空时给**可执行去向**，不放一个点不动的死选项。
- 一个会话的选项定义与当前值都来自「它手上那个节点」，因此列表与详情两处渲染不会分叉。

## 5. 流模式时间轴（点一次发送之后，用户依次看到什么）

| 时刻 | 用户看到 | 由什么驱动 |
|---|---|---|
| 点击发送 | 输入框清空、视线贴底；已发出的内容**尚未出现** | 发送 = 往会话收件箱写一条 |
| 立刻 | 输入区变成**停止**态；流末尾出现三点骨架「正在思考…」 | 会话节点置为运行中（乐观置位） |
| 后端取出并落库 | 用户消息作为一个节点出现在流里 | 权威消息帧（不是回显） |
| 一轮开始 | Turn 节点（等待骨架挂在它内部，文案带智能体名） | Turn 节点帧 |
| 思考 | 「思考过程」行，标题呼吸闪烁；收起态摘要在**左端**裁切（让最新的字留在可见区） | 增量帧 |
| 工具调用 | 工具卡（请求 / 过程 / 结果三段），运行中带三点与**已运行时长**；子步骤缩进直排 | 增量帧 + 秒级共享时钟 |
| 正文 | 逐字流式上屏；仅当用户仍在底部时才自动贴底（离开底部后不抢滚动） | 增量帧 |
| 收尾 | 运行态结束、秒数停止；按结局响起对应提示音 | 会话节点状态迁移 |
| 失败 / 中止 | 流内出现错误条：**失败**给「重试」，**中止**文案与图标区分但同样可重试 | 失败/中止节点 |
| 中途发生上下文压缩 | 消息流里插进一个**压缩节点**（位置就是它发生的时刻）：运行中「正在压缩上下文…」+ 已运行秒数，完成后「已压缩上下文（N → M 条）」+ 事实行（水位 / 来源 / 丢了几条） | 压缩的发生本身就是一个消息节点 |
| 压缩之后再看历史 | 被压掉的那些消失了，取而代之的是一条 `🧠 历史记忆` 节点（默认收起，展开可看摘要原文与转存提示） | 快照是一条消息，不是横幅 |
| 切走再切回 | 输入草稿与滚动位置按会话恢复；正在跑的节点仍在流里可见 | 按会话记忆的 UI 状态 + 在途节点叠加 |

**恢复动作**（失败/待响应节点上的按钮）走后端统一的会话恢复通道，语义是「从哪条消息、
做哪件事」：整轮重试 / 单工具重试 / 压缩重试 / 审批通过 / 拒绝 / 补参数 / 回答提问。
用户看到的是按钮，语义由消息登记表决定（面板不认识具体动作名）。

## 6. 状态与失败

| 层级 | 表现 | 恢复入口 |
|---|---|---|
| 会话级 | 流内末尾一条错误条（**有失败节点时不重复显示**——同一条错误只说一次） | 「重试」= 重发最后一条用户消息 |
| 轮次级（Turn） | 组级交代条（失败 / 中止） | 「重试」= 删除响应子树后重新请求 |
| 节点级（工具） | 工具卡内的错误框；工具结果子节点不重复显示错误 | 「重试此工具」 |
| 压缩 | 失败时按故障样式呈现原因并给重试；**一条历史都不会因此丢失** | 「重试」= 再试一次压缩 |

- 「**中止**」不是故障：文案、图标、音色都与失败区分，但同样提供重试。
- 错误条一律**在流内**，不抬成页面级横幅。

## 8. 刻意不做（改交互前先读这一节）

1. **不做乐观回显**：界面上的消息必须来自后端落库后的权威帧，等待期由状态与骨架表达。
2. **不做面包屑、不做「新建目录」**：路径即导航；新建只针对「资源类型」。
3. **列表筛选不做全库搜索**：筛选是「在当前这一页里找」，全库检索是另一件事。
4. **不在会话流里放折叠态以外的操作条**：节点的操作一律挂在节点自己身上（悬停/聚焦出现）；
   系统节点（压缩 / 记忆）不给这些操作。
5. **一个控件只有一种语义**：运行中的发送键就是停止，提示语不得承诺代码不做的动作。
6. **不引入 UI 库**：外观全部来自语义 token（`tauri/src/styles/tokens.css`），
   组件自带样式与主题变量。

# 附：仍未落地的方向（提案）

> 上面 §0–§9 描述的是**现状**，本节只列**还没做**的。做完了就把属于现状的行并回上面
> 的小节、从这里删掉——提案不积压成历史。

## B1. 会话头部的**实时水位**

现在「水位」只在压缩发生的那一刻可见（压缩节点的事实行：压缩后水位 / 上限）。
用户真正会问的是**任何时刻**的「我还剩多少」，这需要在每轮请求组装时把估算记进
会话运行态、并作为**节点属性**下发（与既有 `message_count` / `outcome` 同一层），
头部显示一行小水位。

**判据**：水位是**节点属性**，不是前端状态。同一份数字必须来自后端——
前端自己估算就会与真正决定压缩与否的那个数字分叉，比不显示更糟。

## B2. 归档可回溯

压缩前的完整历史已经落盘，路径也有（快照节点的 `meta.transcript_path`），但会话内部
目录里还没有对应的集合段，界面上够不到。把它挂成会话内部的一个集合（与消息 / 收件箱 /
子会话 / 工作目录并列），列表与只读详情直接用**现成渲染器**——前端零开发。

⚠️ 代价在两处，不是「挂上去就完了」：归档是**整份历史**（可能很大，不能直接喂给
通用 JSON 渲染器），且「打开它」对用户意味着什么（只读回溯，不是恢复历史）需要先定。

## B3. 本轮请求视图的交代

淡化 / 骨架化（L1–L4）发生在请求组装期，用户完全看不出「模型这一轮没看到某段」。
可选的呈现是在 Turn 节点上带一行「本轮请求视图：N 条 · 估算 X tok · 被淡化 M 条」，
默认收起。

代价最高的一条：它要先设计「请求视图摘要」这个自述的形状，且它**只解释、不改变**
行为，因此在配额有限时应当排在最后。

## B4. 两条沿用中的判据

1. **缺字段即退回当前行为**：新增的字段一律「有就渲染、没有就不显示」，
   前后端因此可以错版上线（两个已落地的例子：压缩节点的事实行、
   `meta.compacted` 的历史记忆形态）。
2. **系统材料不得伪装成用户内容**：压缩记忆、水位提醒这类系统产出，在界面上
   必须能一眼看出不是用户说的话。
