## 缺口与明确不做（写入时点的判定，注销须有编号引用）

| 项 | 判定 | 理由 |
|---|---|---|
| LLM 4xx（401 / 400）与起点不可达 | **已清偿：t53** | 不可重试的错误态（401）与连接级失败（端口不可达）此前与 5xx 重试共用一个失败通道判据（t5），错误语义不同（不重试）应有独立锚。t53 覆盖两形态 + 恢复轮 |
| MCP 断连 / 挂死（stdio 无响应） | **暂不补（待接线批次）** | mock-mcp 已有断连编排能力（`e2e/README` 组件表），但「外部执行与熔断」的上游能力接线在 ST-009 阶段；届时按接线判据纪律（开关翻红）配用例，先补判据会测到自己 mock 的想象行为 |
| 断流重发后的槽位形态（幽灵调用 / 重复卡片） | **已清偿：t54** | 「单响应工具超限卡死」修复三件套中，超限丢弃+反馈（t48）与断流可见失败（t49）有锚；第三件——**重发批次只产出更少调用**时的用户可见形态（不留同批两套卡片、不产出空壳调用）此前只有 `tool_accumulator.test.rs` / `stream.test.rs` 白盒判据。t54 用 mock-llm 编排「首批吐 3 个调用增量后中途 destroy → 原样重发的第二批只产出 1 个并正常收尾」，判据只走用户可见出口：实时面（与前端同构）钉「重发复用 id、不新建」，生产读出口钉「转写恰好 1 个调用、id 前缀复用、无空壳幽灵」 |
| 实时面断链重连（WS 断开 → 自动恢复） | **明确不做** | 断链的用户可见行为已经是全局红点角标 + 自动重同步（`eventBus`，AR-024 §2）；在 e2e 里制造中间层网络断链是给 mock 连接摆布写判据，不给用户行为锚——撤销此线需另立任务并写 ADR |
| 压缩进行中的用户插话 | **暂不补（待评估）** | 压缩与插话分属两个批的判据面（t18 / t34）；交叉形态的「用户插话被压缩吞掉/错位」读数没有生产出口可读，需要先回答「用户怎么看见」再立判据，不宜直接 mock 出结果。排期 [T-074](../task/T-074-压缩中插话判据补齐.md "T-074-压缩中插话判据补齐") |
| 面缺失六项（Web 外取 / 本地检索组 / 通道自动化 / 多协议适配 / 存储切换 / 前端形态） | **待补（面审计发现）** | 本矩阵的行集由能力域导出，从未与出厂面（`docs/CURRENT.md` §1 插件 · §2 LLM 可见工具）对账过——整插件面（如 `web` 的三个工具、`telegram` 全部路由）不进行就进不了缺口表，「格子全入格」的自洽掩盖了行的缺席。六行已于本次审计开进表内；排期 [T-076](../task/T-076-e2e面缺失补齐批.md "T-076-e2e面缺失补齐批")（前端形态单列 [T-075](../task/T-075-前端形态e2e补位.md "T-075-前端形态e2e补位")） |

## 读法

- 格子里的编号 = 「这条能力域 × 形态至少有一条钉它」的最小证据集合，**不排他**；
- 新增用例时：先找行与列，有格子就**并入既有编号行**（用例文件头写清钉什么），
  没格子就开新行——开行即改表，改表即归属登记（本文件）；
- 「暂不补 / 明确不做」的注销 = 缺口清偿，登记处是本轮批次任务（用例落 `e2e/cases/`、
  表格改格子），历史去 git log。
