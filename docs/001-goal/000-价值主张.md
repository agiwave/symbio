# GO-000 · 价值主张

> **这个 kind 回答什么**：要达成什么——价值主张与可度量的验收判据。
> 四层分工（goal / stage / plan / task 各回答什么、依赖怎么表达）的唯一解释在
> [docs/README · 目标分层与依赖链](../README.md "docs/README")，本文不复述。

## 0. 一句话

本层只有一类内容：**要达成什么**，以及「达成了没有」的**可度量判据**。
设计本身（要变成什么样、一句话架构是什么）在 [plan/README](../003-design/002-架构总览.md "DE-002-架构总览")，
分步走法在 [stage/GO-120 路线图总览](120-路线图总览.md "GO-120-路线图总览")——
本层不放设计，只放判据（§1）与判据当前的诚实缺口（§2）。

## 1. 要达成什么

<!-- list:goals owner -->

| 目标 | 具体含义 | 兑现方式 | 服务对象 | 可度量判据 |
|---|---|---|---|---|
| **能力规划得足够远** | 覆盖到当前能设想的最高阶形态 | 五维 × 五轴的**坐标系**（轴带四级刻度、天梯由名册算出、每条判断写明反证现象），而不是一张会过时的能力清单（[DE-008](../003-design/008-能力注册表与能力坐标系.md "DE-008-能力注册表与能力坐标系")） | 往平台里加能力的人 | 新场景只加数据不加机制：事件格子 + 投影参数 + ActorSpec + grants 各一行（机制表顶层键数由 生成物 出，`doc-count-audit` DC-002 判） |
| **架构足够简洁** | 到达可论证的下界，无冗余机制 | 1 个原语 + 3 条判据，其余全部是参数（[DE-001 §1](../003-design/001-核心架构.md "DE-001-核心架构")） | 审这个架构的后来者 | 机制表顶层键数 = 生成物里的数（DC-002）；`symbio_core` 根出口的单消费方存量只减（`core-export-audit` C-003） |
| **扩展永不推翻重构** | 能力增长只新增数据与配置 | 冻结 6 个锚点 + 守恒律审计（[DE-016](../003-design/016-工程落地与验证.md "DE-016-工程落地与验证")） | 加新场景的开发者 | 触碰任一冻结锚点 ⇒ 守恒律审计红（[DE-016 §5.1](../003-design/016-工程落地与验证.md "DE-016-工程落地与验证") 纪律 1） |
| **关键声称有证据** | 可复现，而不是修辞 | 16 个可编译运行的验证程序，全部带反向用例（[verify/](../003-design/verify/)） | 质疑这些声称的评审者 | verify 程序数与各程序 `assert!` 总数只增不减（门禁基线 `BASELINE` 的 `verifyPrograms` / `verifyAsserts` 两格） |

每条判据的执行方都是门禁里的机械判定（码表见 [ref/GATE_CODES.md](../004-ref/GATE_CODES.md)），
不靠人工核对——**判据之所以是判据，是因为它会在违反时变红**。

## 2. 尚未成为判据的（诚实缺口）

§1 四条判据全部回答「**架构有没有失控**」（机制键数、出口存量、冻结锚点、证据程序），
没有一条回答「**用户得到了什么**」。后者的读数**已经存在**，但不在本层：
该批 已给五轴中的四条挂上效标：三条出读数
（时域跨度 = `span`、自主程度 = `autonomy`、主动性 = `conation`），
自我模型精度有口径（`calibration`，见 [RE-004](../004-ref/004-slo-calibration.md "RE-004-slo-calibration")）尚未出数；
口径与三条纪律的唯一 owner 是 [DE-008 §3.1.1](../003-design/008-能力注册表与能力坐标系.md "DE-008-能力注册表与能力坐标系")，本文不抄数。
第五轴「抽象层级」有了**离线**读数（措辞依赖度 = 原述 − 换述 recall@k，由
`verify/recall_eval.rs` 出数，口径见 [D-097](../003-design/016-工程落地与验证.md "DE-016-工程落地与验证")）——但它不在生产
读数口内，且测的是**排序器**的性质而非系统的归纳能力，所以 DE-008 那一格写的是
「离线读数 + **残余人工判**」；本层不因为它改任何判据。

本层判据表**仍只放架构项**——不是因为没有读数，而是因为「用户得到了什么」的 owner
是 DE-008 §3.1 那张表：同一事实写两处，改一次要动两处，且必然漂移。本层只引用，不抄数。
等 §3.1 的读数稳定到可直接当验收阈值时，再决定是否上提。
