# GO-003 · 表单机制

> **这个 kind 回答什么**：要达成什么——价值主张与可度量的验收判据。
> 父目标：[GO-001 · 前端去业务化 / 机制化](001-前端去业务化.md "GO-001-前端去业务化")
> （`parent` 指向它；四层分工见 [docs/README · 目标分层与依赖链](../README.md "docs/README")）。

## 1. 要达成什么

表单（设置 / 新建 / 编辑）**schema 驱动**：渲染与校验由一份声明推出，业务只描述
字段与约束，不写组件分支——与三栏机制同款哲学（机制跑全部场景，差异是数据）。

## 2. 可度量判据

| 判据 | 执行方 / 现状 |
|---|---|
| 新增一类表单 = 一份 schema + 一份校验声明；表单框架零 kind 分支 | 读数待建（本条目的出口）——分支读数建立前不编数 |
| 表单校验失败有机读出口（错误码表驱动，不是散落的 toast 文案） | 关联 [RE-002 错误码表](../004-ref/002-ERROR_CODES.md "RE-002-ERROR_CODES")（现行） |

## 3. 本层不放什么

设计（schema 形状 / 校验 DSL / 与后端的契约）归 plan 层，本条目不描述「怎么实现」。
