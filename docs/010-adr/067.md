## 决策

**背景**：[ADR-065](065.md) 裁决「收束格按种类判」（发言收束问 `reply.*`、产物收束问
`produce.artifact`），并把「对等主体跑一轮」定为 [T-072](../009-task/072-对等主体生产增量.md "T-072-对等主体生产增量")
的合并批。本条裁决的是那次裁决**没有覆盖的三处下游口径**——它们不在 ADR-065 的决策文本里，
但收束分种类一落地就必然撞上；三处口径若各拍各的，产物收束会同时表现为「不变量假红」
「派生事实丢失」「恢复链路断裂」三种互不相干的故障。

**决策**（三条一起生效，同批复退）：

1. **C4（`unresolved_turns`）认产物格。** 开过的 turn 有同号 `artifact.added`
   （`artifact × asserted`）即算收束——与 final / fallback 并列的第三条收束路。
   **必需性论证**：对等主体（只持 `produce.artifact`）跑一轮，产物落格、发言格被闸拒
   （这是 ADR-065 分种类**想要的形态**，不是故障）⇒ 若 C4 不认产物，每一轮都永久留一条
   「静默中断」违规——而本仓的 e2e 纪律是 `stats.invariants` 为空（t30 起逐条断言），
   对等主体的每一条判据 e2e 都会**结构性变红**。不变量的语义也随之更真：I3「到点必答」
   问的是「用户没有被晾着」，工具结果是说给用户的话（界面上就是一张卡片），它落格即算答过。
2. **`TurnOutcome::closure_denied` 数产物。** 发言闸拒 ⇒ `closure_denied =
   (本轮新落产物格数 == 0)`；落过产物就不算拒，`v2_exec` 的派生事实
   （承诺 / 任务表 / 熔断 / 记忆）**照写**。**必需性论证**：对等 offer/assert 的写方住在
   轮末收束族（ADR-065 决策 3，不开第二条写通道——I1），而收束族只在 `closure_denied ==
   false` 时执行。若产物落了格还判「收束被拒」，对等主体的 `commitment.*` 依旧永远写不进
   ——ADR-065 合并批的全部目的（对等体以产物收束、其承诺入格）就只完成了一半。
   计数范围是**本次执行新落的产物**：等待轮历史落过的不算（`artifact_no` 的初值含它们，
   另立计数器从 0 起）。
3. **恢复锚（`v2_exec::last_open_turn`）刻意不认产物。** 它仍只按 final / fallback 找
   「已开未收束」的轮。**必需性论证**：等待用户动作的那一轮（审批 / 问答恢复的前置态）
   往往**已经落过产物格**——若恢复锚也认产物，它会判定「该轮已收束」，恢复请求直接报
   「找不到未收束的轮次」，t27 整条审批恢复链路断裂。等待轮的收束格**刻意留给恢复幕**
   （进展格不是收束格），这是原设计；C4 认产物只是「不再报它静默中断」，不改变恢复锚的
   找轮口径。**两处口径的差异是显式决策，不是漏改**——两处函数文档各自声明。

**同批的另外两件事**（ADR-065 决策 5 的既定内容，此处只记落地位置）：

- **ActorSpec 真值**：`chat_loop::request_actor_spec(ctx, tier)` 成为 `ActorSpec` 的唯一生产
  构造点——`capabilities` 取**授权表行**（`matrix_for` ⇒ `grant_names_of`，单一真源），
  `pattern` 按矩阵谓词判（持 `reply.*` ⇒ Reasoner；无发言权而有 `produce.artifact` ⇒
  Translator；其余 ⇒ Decider），`budget_ms` 按档位。`ActorSpec::trivial` 退到测试面。
- **入站来源主体**：`SOURCE_PRINCIPAL`（`define_string_key!`，WIRE 键，线上形态
  `metadata.source_principal`）→ 收件箱入队口随条目寄存进 `session_chat::Request` →
  消费时 `run_inbox_turn` 挂回执行 ctx → 轮末 `record_derived` 用作 `commitment.*` 的 `to`。
  缺省（无来源声明的本机路径）⇒ `PRINCIPAL_USER`，与接线前写死的常量逐字一致。

**理由**：

1. **不变量必须为真服务，不能为「判得严」服务。** C4 的价值在「静默中断被看见」；把
   「说了话（以产物）」报成「静默中断」，是在制造假红——而 e2e 的 `invariants` 为空
   纪律会把假红放大成对等侧**整批无法验收**。宁可把收束的完成形态定义对，也不给
   不变量加「对等主体豁免」这种特例开关（特例开关才是不变量的腐蚀剂）。
2. **「口径只活在 core」在下游同样成立。** 产物收束的三个下游（C4 / `closure_denied` /
   恢复锚）都必须消费**同一个事实**（该轮有没有落过产物格），各自复述判据迟早漂移。
   三处的差异（认 / 数 / 不认）全部来自**各自回答的问题不同**——函数文档把「为什么不同」
   写在判据旁边，判据本身一处不改两处。
3. **本条不新增任何格、任何键的语义**：产物格、`SOURCE_PRINCIPAL`、`closure_denied`
   都是既有词汇表成员，本条只定它们的**读法**。写法一侧（谁落产物格）由 ADR-065 的
   产物闸（`ClosureKind::Artifact`）管辖。

**被否决的方案**：

- **C4 对「对等主体」加豁免参数**：否决。不变量带主体特例后，每加一个窄行主体就要改一次
  C4 的签名；且「该轮有没有落产物」本来就是对主体无关的判据——特例是伪解。
- **`last_open_turn` 同步认产物**：否决，见决策 3 的论证——它会当场弄断审批恢复链路
  （等待轮被当成已收束）。
- **对等轮结束后补写一条 `chat.assistant.final`（空正文）让 C4 闭嘴**：否决。发言闸拒的
  就是这格——用一条被闸拒绝的格去安抚不变量，等于让闸与不变量互相抵消，两个机制同时失效。
- **把 `closure_denied` 退役、改成「按格判断派生事实该不该写」**：否决。`closure_denied`
  是运行器与 `v2_exec` 之间**已接线**的契约（六个发言调用点 + 一个早退分支），为一次
  语义细化换掉契约面，改动面与风险都大于在既有字段上给准确定义。

**后果与不变量**：

- **C4 的反向用例同批补齐**：`invariants/mod.test.rs::fault_timeout_avoided_by_artifact_event`
  （只落产物的轮不报 + 别轮的产物不替本轮收束）；等待轮两处判据（`turn_runner.test.rs`）
  按新口径改写并注明理由。
- **`closure_granted` 的调用点纪律（ADR-065 不变量）保持**：六个发言调用点全走
  `ClosureKind::Speech`，两条产物路径（续写轮 / 工具结果）走 `ClosureKind::Artifact`，
  谓词只活在 `governance`（`can_reply` / `can_produce_artifact`）。
- **本机路径零行为变化**：`agent:main` 与派生主体两道闸都放行（产物闸对它们恒真），
  `SOURCE_PRINCIPAL` 缺省回落 `PRINCIPAL_USER`——回归面由全量单测与 e2e 覆盖。
- **恢复链路不回退**：`last_open_turn` 口径不变的判据由 t27（既有）继续覆盖。
