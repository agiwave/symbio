# ADR-118：引擎与执行体的边界

## 背景

PL-017 §4 的步 5 要求 `turn` 执行体退成薄壳，内环的驱动权回到引擎。现状是三件事
叠在一起：

1. `decl::ring::drive`（取最小可还的债）仍是 `#[cfg(test)]`，生产里没有调用点；
2. `turn_exec::drive_steps` 自己写着 `begin` / `step` 循环，`TurnRunner` 的
   `StepFlow` 持有跨步状态并决定「下一步做什么」；
3. 工具批次的创建 / 授权 / 执行三笔债被 `DispatchPort::dispatch` 打包成一次调用，
   `open_batch` 在一次调用里同时写 `request`、`authz.*`、`sent` 并执行工具。

[ADR-115](115.md "ADR-115") 已裁决执行体契约（异步、可取消、失败落事实、步数上界、
无进展收束），但没有裁决**谁选下一笔债**、**谁写哪一半事实**。本裁决补这两条。

## 决策

1. **`decl::ring::drive` 是唯一的选债口。** 它保持纯函数（事实切片 + 冻结视图 +
   `now`），只返回 `Option<Debt>`；生产入口直接调用它，不再有第二套「问某一行
   欠不欠再决定下一步」的调度分支。它多收一个**执行体注册表谓词** `accept`：
   只有 `by` 命中注册表的债才参与裁决——注册表没覆盖的 `by` 在选债面上被跳过，
   而不是被选中后无人可跑。求解器不看这个谓词（见决策 8）。
2. **`turn_exec::drive_steps` 是派发器，不是决策者。** 它做四件事：读切片 → 调
   `drive`（带注册表谓词）→ 按 `Debt.decl.by` 找执行体 → 跑**一个**执行体；
   然后重新读切片。它不按行名、端口名或业务语义分支。
3. **执行体按 `by` 寻址，一行一个执行体。** `by` 字段就是执行体名（T-222 已落）；
   派发器查注册表，**哪些执行体能被选中由行表的 `owes` / `prio` 决定**。粗端口期
   （PL-016 §7.2）`execute-turn` 在整轮收束前恒欠；注册表现在只有 `execute` 一档，
   `policy.*` 与工具三笔债都由它在内部完成，因此它们**不参与派发器选债**
   （否则一笔内环债会把整轮顶成 `no_progress`）。工具三笔债由它内部按三个动作写
   （决策 5）。下表其余执行体
   随对应行在 PL-017 的细端口里变得可选中再接：现在接它们只会得到永远不会被
   调用的死代码。

   | `by` | 承担的行 | 一次调用做什么 |
   |---|---|---|
   | `authorizer` | `authorize-tool` | 读 `request`，写 `authz.granted` / `authz.denied` |
   | `decide` | `policy.classify` | 轮首判决，写判决事实 |
   | `report` | `policy.report` | 中途汇报，写汇报事实 |
   | `compress` | `policy.compress` | 自动压缩，写压缩事实 |
   | `recall` | `policy.recall` | 记忆 / 技能 / 任务段召回 |
   | `reflex` | `policy.reflex` | 技能快路 |
   | `execute` | `execute-turn` | 写 `request(port=turn)`（本幕欠一次往返） |
   | `courier` | `dispatch-turn` / `dispatch-model` / `dispatch-tools` | 按债键里的端口跑**一次**调用（轮 / 模型往返 / 单次工具），写应答或失败 |
   | `lease_keeper` | `lease` | 按 `PortDecl` 重试或判死 |

   `await-*` 的 `by = None` 不变：它们是「在等」的声明位，`drive` 不会选中。
4. **轮内草稿归派发器，不归引擎。** `TurnRunner` 的 `Prepared` / `StepFlow` 改成
   不透明的 `TurnSession`（本轮消息、节点、成本、步号），由 `execute` 执行体创建、
   派发器在步与步之间持有并交给 `courier`。引擎只看事实，不持有、不理解这份草稿。
5. **`stream_round` 拆成两个执行体动作。** `dispatch-model` 只做「拼消息 → 调模型 →
   分类」：收束就落 final / fallback；请求工具就把应答留在草稿里。
   `open-tools` / `authorize-tool` / `dispatch-tools` 各自读上一步落下的事实，分别写
   `request` / `authz.*` / `sent` + 工具结果。`DispatchPort` 的打包调用退役，三笔债
   不再由一次调用代劳。
6. **写权按行切，单写者仍是 store。** 每个执行体只写**自己那一行**的领域事实；
   派发器只写协议信封（`PortDecl.before` 指向的 `sent`、执行体失败时的 `failed`）和
   终止格（`exhausted{step_limit|no_progress}`）。没有执行体写别人那一行的 `until`。
   ADR-115 决策 3 的 `Vec<Fact>` 是执行体的**产出形状**，不禁止它在流式过程中先落
   自己那一行的领域事实；两者都经同一个 store，单写者是 store，不是引擎。
7. **停机判据不搬家。** `MAX_STEPS_PER_DRIVE = 64`、每步后比较日志头（无变化即
   `exhausted{no_progress}`）、中止信号检查、租约重试都留在派发器；它们是 ADR-115
   决策 3–4 的契约，不是执行体可以自行决定的优化。
8. **不新增事实名、端口或端口字段。** `drive` 新增一个执行体注册表谓词参数
   （`accept: impl Fn(&str) -> bool`），`owed` 与声明表的字节不变；本裁决只改
   「谁调用、按什么顺序调用、哪些债参与选债」。加端口仍然只加 `PortDecl` +
   适配器 + 两行模板。PTS-003 的求解器指纹基线同批更新（`drive` 字节变了、
   `owed` 没变），理由挂本条。

## 理由

| # | 依据 | 本裁决做了什么 |
|---|---|---|
| 1 | PL-014 §2.1 的不动点由引擎求，不由执行体自觉 | `drive` 成为生产唯一的选债口 |
| 2 | ADR-115 决策 3 的执行体契约 | 契约保留，补上「谁选债、谁写信封」 |
| 3 | PL-017 §3.3 / ADR-117 的三段债 | 创建 / 授权 / 派发各自由一行执行体承担，不再打包 |
| 4 | 一行只写「什么时候欠、什么算还」（T-222） | 执行体只做一行，不读别的行做调度 |
| 5 | 回放可重建 | 引擎只读事实与视图；草稿不参与 `owed` |

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 保留 `StepFlow` 的内环，让 `drive` 只在旁边做一致性检查 | 驱动权仍在执行体，`drive` 是装饰；换掉「依据」这件事没有发生 |
| 引擎直接调用 `flow.step`，由 `flow` 自己报告下一步 | 选债仍是执行体的内部状态，`owed` 不是权威 |
| 把 `drive` 搬进 loop 插件 | 求债是机制层，搬进插件后每个端口都要复制一份；PTS-002 也会被端口字段污染 |
| 每次执行体返回全部事实、由引擎统一 append | 流式与读改写需要 store；把写路径拉成「先缓存再统一落」会让流式节点、幂等与错误处理各多一层，收益不抵复杂度 |
| 保留 `DispatchPort` 打包，只把它的内部拆成三次函数调用 | 三笔债仍由一次执行体调用代劳，`drive` 看不到中间的 `open-tools` / `authorize-tool`，授权拒绝没有独立作用点 |

## 后果

- **实现面**：`drive` 是生产入口（带执行体注册表谓词）；`drive_steps` 读切片 →
  `drive` → 按 `by` 查注册表 → 跑一个执行体。`execute` 执行体内部把工具批拆成
  `open` / `authorize` / `dispatch` 三个动作（`request` / `authz.*` / `sent` + 结果），
  `DispatchPort` 打包契约退役、`DispatchOutcome` 住插件；`TurnSession` 承接轮内草稿。
- **选债面与注册表同源**：`Executor::accepts` 既是 `drive` 的 `accept` 谓词，也是
  派发器查表的同一函数——「能选中」与「有人跑」在构造上同真。注册表没覆盖的行
  （粗端口期的 `policy.*` / 三笔工具债）不参与选债，守卫用例
  `accept_skips_rows_without_an_executor`。
- **续写幕旁路留在派发器**：行表只有单一全局表头（`turn_head` 取最新一轮），恢复
  一段已被后续轮次归档的旧轮时，旧轮在表里不可见（用例
  `an_open_turn_archived_by_the_next_turn_is_still_the_resume_anchor`）。删旁路要
  先让表头按轮参数化，属另一次裁决；在表头改形状之前删它会让这类恢复永远
  `no_progress`。
- **用例面**：空表不前进、步数上界、租约重试均有用例；「执行体返回空即
  `no_progress`」按构造不可达（每个生产动作至少写一格，无通道的工具请求在模型段
  已按 config gap 收束），该守卫保留为不变式检查，不造夹具。
- **行为差异**：工具批次的 `request` / `authz` / `sent` 从一次调用内的连续写变成
  三步各自可观测；崩溃恢复的粒度从「整批」变成「已落哪一笔债」。
- **代价**：`drive` 每步读一次切片并求一次 `owed`（与旧 `next` 同量级）。事实量
  不变，CPU 可接受。
- **不改变**：`owed` 与声明表的字节（PTS-003 基线不动）、行表 `prio`、协议名闭集、
  端口载荷形状。
