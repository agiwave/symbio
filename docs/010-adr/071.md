## 决策

**背景**：[PL-014 §4](../004-plan/014-单环一表收敛.md "PL-014-单环一表收敛") 把统一注册表的目标形状冻结为 **6 值** `RowKind` 封闭集
（Policy / Tool / Model / Prompt / Mount / Option），并在 §8 登记义务写明「`RowKind` 封闭集
需要偏离，那是一条 ADR，不是实现细节」；§5 步骤 4 的熔断线同向（「某族塞不进 → 停下修模型，
不加封闭集之外的口子」）。施工到 [AR-025 §5](../005-arch/025-capability-registry.md "AR-025-capability-registry") 步骤 4e 时遇到这条裁决该管的场合：
`CapabilityVisitor` 四族之外还住着两个同源的专服单族 trait——`OptionVisitor`（六值里有其位）
与 `ConfigurableVisitor`（六值里**没有**：设置页里的一份配置声明）。不收它们，
「插件注册只有一个入口」就是空话——表收敛了四族，第五、第六族仍各长一个 trait，
正是「一个机制实例化多族 trait」的糜烂来路（AR-025 §2）。

**裁决**：`RowKind`（代码中 `CapabilityRowKind`）**加第 7 值 `Configurable`**。
这个值唯一的必要理由：`list(kind)` 的过滤键必须区分「设置页条目」与「选项字段」两个读面。
它不在 trait 上加方法（4e 恰是两个 trait 退场的步骤），也不加机制键。

**否决的替代**：

- **塞进 `Option` 族**：载荷不同（`DetailField` vs `VdfsItem`）、覆盖键语义不同
  （`field.key` vs 目录名）、读面不同（会话输入区表单 vs 设置页清单）。两种载荷共用一个
  `kind`，就得在载荷里判别类型——等于把刚从签名侧消掉的「同一事实的第二种答案」
  重新长回数据侧。
- **塞进 `Mount` 族**：可配置条目确实带一个 VDFS 地址，但那是**地址引用**不是 provider
  （它不服务任何子树）；挂载族的生效位（根槽）语义与此完全无关。
- **保留 `ConfigurableVisitor` 独立 trait**：与 [T-165](../009-task/165-控制面收敛.md "T-165-控制面收敛") 出口条件
  「收集口收敛为 1 个 trait 3 方法」直接矛盾——每族一个专服 trait 正是被收敛的形状本身。

**与「Capability 七值封顶」的关系（澄清一处易误读）**：PL-001 的 `Capability` 七值是
**授权枚举**（grants 矩阵的键：JudgeIntent / ReplyFirst / ReplyAppend / DefineWork /
ProduceArtifact / AssertVerification / AssignWork），与 `RowKind`（**收集通道的族别**）
不是同一根轴。本条裁决的是 PL-014 §8 所指「RowKind 封闭集的偏离」；授权七值未因本批
被触碰（机制键守恒审计零新增）。

## 后果

- `CapabilityRowKind` = { Policy, Tool, Model, Prompt, Mount, Option, Configurable }；
  `Policy` 随 PL-014 步骤 6 与 `State` / `Step` 一并定义，其余六族已全部落位可达。
- 4e 落地（提交 `486e8cef`）：`OptionVisitor` / `ConfigurableVisitor` 两个 trait 退场，
  `OPTION_VISITOR` / `CONFIGURABLE_VISITOR` 通道键保留、值类型改指统一收集口
  （行的族别从载荷派生，`put(CapabilityRow::configurable(…))` / `put(CapabilityRow::option(…))`）；
  core 三格 20/60/18 → **18/56/18**（`SHAPE_BASELINE` 随之收窄）。
- [PL-014 §4](../004-plan/014-单环一表收敛.md "PL-014-单环一表收敛") 的 `RowKind` 草图随本条订正为七值。
- **本裁决向前生效**：封闭集若需第 8 值，仍按本先例逐条开 ADR——加枚举值不等于免费，
  每个值都是 `list(kind)` 的一个永久读面。
