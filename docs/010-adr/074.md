## 决策

**背景**：[ADR-073](073.md) 清掉 `TurnState` 里没人读的簿记格，留下
`tool_rounds` 与它的三个读方，并把「该由谁喂真实轮数」登记在
[T-165](../009-task/165-控制面收敛.md "T-165-控制面收敛") 的 5b 条。本轮做这个裁决。读写矩阵的
结论比上一批更难受：那三个读方**不是死代码，是静默失效的判据**——

- 工具轮次不经这里（[ADR-072](072.md) 立的事实：工具在 `execute_turn` 内部经
  `DispatchPort` 一批批跑完，`chat_loop` 一轮只经过一次请求），所以 `tool_rounds` 恒 0；
- 于是闸门那条「软上限 ≥ `tool_rounds`」恒不命中，**而它的默认值恰好也是「不限制」**——
  配错与没配看起来一模一样，没有一条信号能区分；
- fade（老旧工具结果淡化）的激活式 `tool_rounds > fade_activate_rounds` 恒假，三层裁剪
  永远不激活；这一层的归属在
  [T-166](../009-task/166-上下文淡化层级未接入v2请求.md "T-166-上下文淡化层级未接入v2请求")，本裁决不越界；
- 轮边界抽干分支的 `tool_rounds > 0` 恒假 ⇒ 用户的中途补充**在 v1 外壳里一条也折不进本轮**。
  真实抽取早已搬进工具循环的批次边界（`v2_exec` + `turn_runner.rs` 2f），而那条分支里还写着
  一句只有它知道的纪律：「抽到补充 ⇒ 静默时钟归零」。分支失效，纪律也跟着失效——
  用户刚补完话，助手可能立刻抢报一句进度。

**裁决一：`TurnState::tool_rounds` 改名成它实际能数的那个东西 —— `request_round`（本轮已
发出的 LLM 请求数），唯一写方是主循环的 `TurnFlow::NextTurn` 分支（长度截断后的续写）。**
它服务的判据全都是「这是不是本轮第一次请求」：轮首判决（`classify`）、长期记忆召回、
`user_prompt_submit` 钩子、`emit_streaming_start` 的轮次标注、日志那一行。工具轮数的真源
另在两处——运行器环体的 `tool_round`（`turn_runner.rs`）与轮边界汇报的 `RoundProgress::rounds`
——字段文档写明「它**不是**工具轮数」，并把这条区分同时写进
[AR-015-core-loop](../../symbio/src/plugins/session/docs/015-core-loop.md "AR-015-core-loop")。
`loop_registry::LoopState` 的形参随之改名 `round`，字段表点名它的两个取值点。

**裁决二：v1 外壳里的抽干分支删除，「先抽干 ⇒ 静默时钟归零」从注释纪律升格为入参。**
`RoundHookFn` 的入参由 `Option<u64>`（锚点，无人读）改为 `Option<i64>` —— 本批次边界**抽到
补充的时刻**：`v2_exec.rs` 的注入闭包在 `supplement_into_request` 之后取 `clock_now_ms()`，
判定方（`chat_loop::round_report_hook`）收到非空就 `RoundProgress::stirred(at)`（时钟归零，
**不占汇报配额**）。契约保持「一个可选时刻」而不是换成一条结构体：core 的回调是同步闭包
`Fn(Option<i64>)`，塞结构体进去要靠转型，而判定方要读的只有这一条时刻。

**裁决三：`max_tool_rounds`（工具轮软上限）整条链退役**，沿用
[ADR-072](072.md) 那条「死旋钮」的先例。删除的名册（符号级）：
`SessionConfig::max_tool_rounds` / `default_max_tool_rounds()` /
`SessionConfig::model_chat_max_tool_rounds()`、`model_chat::Request::max_tool_rounds`
（下发到请求层的 wire 字段）、`TurnRequest::max_tool_rounds`、`TurnExit::MaxToolRounds` 与
`finish_turn` 里那条告警文案、`plugin.rs` 配置 schema 的那一行。
`fade_activate_rounds` **保留**，判定式改读 `request_round`，但**不裁决它的归属**——三层淡化的
接入与退役整族归 [T-166](../009-task/166-上下文淡化层级未接入v2请求.md "T-166-上下文淡化层级未接入v2请求")，
配置项文档已带 ⚠️ 把判据真源指过去。

**否决的替代**：

- **把真实工具轮数喂进闸门，让软上限活过来**：判得上限要求**在主循环里**读一个只有运行器
  环体知道的数，只有两种写法——轮内回调反向推进主循环状态，或者把上限判定搬进 `turn_runner`
  的环体。后者不是「删死代码」，是一次**新的收束语义设计**（到上限时怎么收尾：本批未执行的
  工具调用怎么办、要不要落一条 `terminated`、给用户什么文案、与审批中断怎么相处）。真要加，
  位置在 2e（结果接进 `exchange`）与 2f（轮内注入）之间，这条已写进 `gate_turn` 的文档。
- **保留 `tool_rounds` 这个名字，只是不再判**：留着它，下一个人读到的仍然是一个「在数工具轮」
  的字段名，而它恒 0 ——这次的病灶正是这么来的。改名并把区分写进文档是唯一的防复发手段。
- **fade 判定继续读恒 0，等 T-166 一起处理**：那等于一个恒假的判据躺在主循环里。改读
  `request_round` 之后它**在续写轮里可判定**（行为仍然保守：一次请求的轮次几乎总是 0/1），
  同时不假装三层已接入——配置项文档带 ⚠️ 指向 T-166，判据真源与接入一起归那边。

## 后果

- **配置面少一项**：`session/PLUGIN.yml` 的 `max_tool_rounds` 行、前端设置页据此渲染的控件、
  [session README](../../symbio/src/plugins/session/README.md "symbio/src/plugins/session/README") §2 与策略表那行随之删除。
  本结构未开 `deny_unknown_fields`，旧存档与用户手写的配置里残留的这个键被 serde 静默忽略，
  无需数据迁移（与 `storage_backend` 那批同一条，见 `config.rs` 的结构文档）。
- **v2 现在没有任何工具轮数上限**（如实登记）：只剩单条响应内的
  `MAX_TOOL_CALLS_PER_RESPONSE = 32`（`plugins/model/stream.rs`，超出的调用合成一条「未执行」
  结果喂回）、用户中止、provider 断流。这是**放开**不是收紧——它与默认值（0 = 不限制）逐字
  等价，所以没有行为变化；被去掉的是一条「看起来能限、实际限不住」的假承诺。
- **抽干点搬家由 S-011 守着**：那条守卫原先钉的是 `chat_loop.rs` 里
  `gate_turn → orchestrator.supplements → prepare_turn_inputs` 的三点行序，三个锚点现在两个
  已不存在。判据换成搬家后的**两处行序断言**——`turn_runner.rs` 的 2e < 2f（补充不得插进工具
  批次中间）、`v2_exec.rs` 的抽干 < 汇报（静默时钟归零发生在判定之前）；锚点缺失仍判 ERROR、
  不接受豁免。文档侧的 C-D2b 表述同步（[PL-007](../004-plan/007-对话面插件拆分实施方案.md "PL-007-对话面插件拆分实施方案") §5）。
- **测试与棘轮**：`chat_loop.test.rs` 删软上限那 5 条（`max_tool_rounds_reached_exits_with_reason` /
  `below_max_tool_rounds_proceeds` / `none_means_unbounded_rounds` /
  `max_tool_rounds_zero_is_unbounded_not_instant_break` / `max_rounds_is_judged_before_abort`）、
  新增 2 条（`request_count_is_not_an_exit_condition` / `abort_wins_over_request_count`），
  7 → 4 条：闸门只剩一条退出条件，而「请求数不构成第二条退出条件」这件事需要有人钉。
  `plugin.test.rs` 的 2 条契约翻译测试（`max_tool_rounds_zero_maps_to_unlimited` /
  `default_max_tool_rounds_is_effectively_unlimited`）随字段退场，同族的 wire 契约
  「缺键 ≠ 零值」由 `model_chat.test.rs` 改以 `tool_context_window` 继续钉住；
  新增 `progress.test.rs::a_user_supplement_resets_the_clock_without_spending_the_quota`
  钉住裁决二（净 −4，棘轮基线 `rustTests` 落 1752，逐条归属见 `35-baseline` 的 `baseline-allow` 注）。
