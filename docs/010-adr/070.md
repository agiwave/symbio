## 决策

**背景**：`ChatMessage` 的 `MessageType::Turn` 名义上是"一轮响应"，实际承担的是**容器**职责——
文档原话（`symbio/src/symbio_core/schemas/session/chat_message.rs:22`）：「`Turn` 与 `ToolCall` 是组合节点，
不含实际内容，仅分组子节点」。但「轮」这个词绑了三件事：

1. **C4 配对不变量**：一个 `user.message` 必须配一个 `Turn.Opened` 与一个 `Turn.Closed`（[ADR-052] 的 abort 路径也按 turn 走）
2. **写侧半格**：`resume.rs::RetryTurn` 只允许靶子是 `Turn`，VDFS 动作 `truncate` / `retry_turn` 也绑 turn
3. **读侧根**：`transcript_window` 取"最后一轮"、`count_user_messages` 数 turn 号

[PL-013] 要把前端切成「只认树、不认轮」的机制形态，同时 [T-135]（中断轮的收束缺位）与
[T-137]（CLI 交互卡无呈现）在旧协议下的修法要么是先补一对 Opened/Closed，要么是加一个专名节点，
两种都是把"轮"当协议原语。

**决策**（一条 ADR 里两件事，因为它们共用同一条判据）：

### 1. `Turn` 语义从协议退役，改用 `Skeleton`

- `MessageType::Turn` → `NodeKind::Skeleton + style_tag: "run"`（`"run"` 是**渲染层的字符串**，不进协议 enum）
- `ResumeAction::RetryTurn` → `ResumeAction::RetrySubtree`（靶子=任意骨架，不再校验 `msg_type=Turn`）
- VDFS `truncate` / `retry_subtree` 动作的靶子检查从「必须是 Turn」改成「必须是 Skeleton」
- `count_user_messages` 那类「按 turn 配对」的不变量从协议层删除——骨架之间的**嵌套形状**
  由后端建树策略决定（见 [PL-013 §5]），前端不感知

「一轮」这个词从协议、注释与现行文档里**清空**；它是**特定建树策略下的显示效果**，不是概念。

### 2. 顶层字段消费纪律

`ChatNode` 顶层字段**只承载**"前端不依赖业务语义就能消费"的东西——四轴 + 内容三件套：

| 允许进顶层 | 不允许（沉 `meta` 或只留后端） |
|---|---|
| `id` / `parent_id` / `seq`（树 + 顺序锚） | `tool_call_id`（provider wire id，前端不消费） |
| `kind`（呈现分派） | `role`（与 `principal` 前缀重复——见 [ADR-069]） |
| `status`（生命周期） | `name`（业务专名 → 用通用 `title`） |
| `principal`（主体） | 具体子类型枚举（`skeleton_kind` → 用自由字符串 `style_tag`） |
| `content` / `delta` / `error` / `timestamp` | 业务专名 MessageType（`Compression` / `UserPrompt` / `Reasoning` → 合并到 `Notice` / `Interaction` + `style_tag`） |
| `stats`（只 Skeleton 携带） | |
| `style_tag`（呈现分派的第二轴，自由字符串） | |
| `title`（呈现文本） | |
| `meta`（业务兜底） | |

**判据**：一个字段能不能进顶层，只问一处——前端 / CLI 有没有**不查看 meta 语义**就能消费它的地方？
答案没有 ⇒ 沉 `meta`。这条判据**落守卫**（`scripts/protocol-mirror-audit.mjs` G 组，[T-152]）：
扫 `chat_node.ts` 每一顶层字段，grep 前端 / CLI 消费者；命中但判据里读 `meta.xxx` 的算违规，红。

### 3. 协议里的 `NodeKind` 是闭集，`style_tag` 是开集

这条与上一条一体——**协议 enum 只表达"前端如何呈现"这一族决策**（展开 / 折叠 / 容器 / 交互 / 占位）；
"是工具还是压缩还是子智能体"这种**业务分类**走 `style_tag` 字符串，注册表按 (kind, style_tag) 分派。
新工具 / 新事件类型 ⇒ **只加 style_tag 取值 + 注册表条目**，不动协议 enum、不动前端组件里的 if 链。

### 4. `role` 字段删除

[ADR-069] 把四前缀铺到与 `role` 等宽之后，`role` 就成了**同一事实的第二份定义**——删。
`MessageRole::{User,Assistant,Tool,System}` 从协议里移除；前端所有 `role === 'user'` 判据换成
`principal_prefix_is('person')` 之类的**前缀判定**。

## 后果

- **改名（Rust 侧）**：`chat_message.rs` → `chat_node.rs`；`ChatMessage` → `ChatNode`；
  `MessageType::Turn` 与 `MessageRole` 一并删除
- **改名（TS 侧）**：`tauri/src/schemas/chat_message.ts` → `chat_node.ts`；
  `MESSAGE_TYPE_TURN` / `MESSAGE_TYPE_REASONING` / `MESSAGE_TYPE_COMPRESSION` / `MESSAGE_TYPE_USER_PROMPT`
  常量删除；`CHAT_ROLES` 常量删除
- **改语义**：`ResumeAction::RetryTurn` → `RetrySubtree`；VDFS 动作靶子从 `Turn` 换成 `Skeleton`
- **加守卫**：`protocol-mirror-audit.mjs` G 组——顶层字段消费点判据（[T-152]）
- **兼容**：读历史 `messages.json` 时对旧 `type: 'turn'` / `type: 'reasoning'` / `type: 'compression'` /
  `type: 'user_prompt'` 做**一次性映射**（`turn` → `Skeleton + style_tag:"run"` 等），不保留双读
- **注释清理**：`docs/010-adr/052.md` / `docs/010-adr/055.md` / `docs/005-rev/*` 里凡「一轮 / Turn」表述
  重写为「一次运行的骨架 / Skeleton」——这条列入 [T-153]
- **风险**：100+ 单测会红一次；这是**原子改**（同一批 diff 内改完），[T-147] 的 exit 判据要求"改名批一次绿"
