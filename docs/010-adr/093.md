## 决策

策略行的行形状从 `{name, prio, 纯判据}` 扩为 **`{name, site, prio, 纯判据}`**：

1. **`Site` 是闭集枚举**（`TurnHead` / `RoundBoundary` / `Compress` / `TurnPrepare` / `Reflex`），
   与 [`Capsule`](../010-adr/088.md "ADR-088") 同一条纪律：加值必须改枚举，`name()` 的
   `match` 会编译错误。
2. **`prio` 的唯一性从全局收窄到格内**：跨格共用一个 `prio` 不是冲突（它们从不在
   同一次判定里相遇），同格重号仍然启动期 fail-fast。
3. **`decide(&Call)` 只扫本格**：`Call` = 格 + 状态，由构造器一起给出，调用点无法把
   A 格的状态喂给 B 格的判定。
4. **返回值从 `Option<Hit>` 改为 `Verdict` 三值**：`Hit` / `Declined { rows }` /
   `Unmanned { site }`。前两者对调用点都是「不做事」，但只有后者是配置缺口。

这不是新机制：不增机制键、不增 trait、不增插件 id。它是行形状的一个字段，与
[ADR-089](../010-adr/089.md "ADR-089")「一个行形状 + 两个目录」不冲突——改的是
**策略目录**里行的形状，能力目录未动。

## 背景

PL-014 §5 步骤 2–3 已把五个决策点的判据搬进表，但「这一行属于哪一格」只活在
**调用点的隐含约定**里：`chat_loop` 用 `turn_head` 构造的状态、期待 `Decide`；
`progress` 用 `round_boundary`、期待 `Report`。表本身读不到这层信息，于是三条
横向扩展的摩擦同时存在。

### 摩擦一：`prio` 被迫全局唯一，同格加第二行要挤全局编号

内建五行的 `prio` 是 10 / 20 / 30 / 50 / 60，每个决策点恰好一行。PL-014 §5 步骤 3
明确写着「记忆与技能拆成两行推迟」——一旦要拆，两行同属 `turn_prepare` 格，而
`put` 的判据是 `rows.iter().find(|r| r.prio == row.prio)`：**全局**取第一个同号者。
于是新行必须从一个全局编号空间里挑一个没被占的数，而「两行同格谁先」与「两格撞号」
根本不是一回事。判据错了一个作用域，代价是每一次同格扩容都要先做一次全局协调。

### 摩擦二：每格扫全表，4/5 的判定是陪跑

`decide` 从头扫 `rows`。五格各问一次 ⇒ 25 次判定，其中 20 次是本格之外的行：
它们的判据读的全是 `blank()` 的假值，恒不成立。数字上不算贵（`fn` 指针 + 布尔），
但它掩盖了一件更要紧的事——**「行只读本格字段」这条不变量只能靠人读构造器确认**
（见下）。

### 摩擦三：`None` 三义不分，「某一步怎么没发生」无从下手

PL-014 §3 规则 g 写着「`decide` 返回 `None` 意味着规则缺口，必须可见」。
在直线代码的过渡形态下，调用点看到的 `None` 有三种成因：

- 本格有行、判据不成立（正常，本步不做）；
- 本格一行都没有（配错，那一格永远不做事）；
- 本格不属于任何一行（结构上不可能，但返回值也表达不出来）。

`chat_loop` 的日志只在 `Some` 时打，于是前两种在日志上长得一模一样——正是
规则 g 要防的「静默 quiesce」。

## 为什么不直接做 `drive`

PL-014 §4 的 `drive` 是这层信息的**终极消法**：`store.project()` 成为唯一状态来源，
N 个构造器合并成一个 `project()`，格由「现在投影到哪一步」隐含，不需要显式字段。

但 `drive` 属步骤 5，前置是步骤 1 的 Step 循环与批序定义。在那之前，「格」必须
有个落点，否则步骤 3 的「记忆 / 技能拆两行」无法施工。本 ADR 是**过渡形态的
最小机制**，不是对 `drive` 的替代：`drive` 落地后 `Site` 会随之消失（格由投影
位置给出），届时本 ADR 状态改为 `superseded`。

## 判据（全部可执行，`loop_registry.test.rs`）

| 判据 | 用例 | 反证方向 |
|---|---|---|
| 每格都有行 | `builtin_rows_are_conflict_free_and_ordered` 断言 `unmanned_sites()` 为空 | 删掉任一内建行 ⇒ 红 |
| `decide` 只扫本格 | `decide_only_scans_its_own_site`：别格放一行恒返回 `Some` 的行，本格结论仍是 `Unmanned` | 改回扫全表 ⇒ 拿到 `Hit(policy.bomb)` |
| 跨格同 `prio` 不冲突 | `same_prio_in_different_sites_is_not_a_conflict`：五个内建行 prio 全 10 | 改回全局唯一 ⇒ 表自己注册不进来 |
| 行不跨格读字段 | `no_row_reads_across_sites`：把非本格字段全推到极端值，结论必须不变 | 让 `policy_compress` 多读一个 `has_facts` ⇒ 实测红（报「compress 格读了非本格字段」） |
| `Unmanned` ≠ `Declined` | `declined_and_unmanned_are_distinguishable` | 把两者压回 `None` ⇒ 红 |

第四条值得单独说：它把「行只读本格字段」从**人肉审查**变成**可执行判据**。
此前 5 个构造器共用一个 10 字段的 `LoopState`，其余字段用 `..blank()` 填假值，
所以「某行读了一个别格没填的字段」会静默按假值判定——不崩、不报。哨兵用例
是这条不变量的第一次可验证形态。

## 代价

1. **构造器多一层包装**：`Call::turn_head(...)` 而非 `LoopState::turn_head(...)`。
   换来的是调用点不再可能喂错格（`site` 由构造器给定，不由调用方传）。
2. **`site_fields` 表要与构造器同屏维护**：构造器多填一个字段而本表没跟，哨兵
   会把它推到极端值，于是误报为「跨格读」。方向是**多问一句**，不是漏报；
   反过来本表多写一个字段才会漏（构造器改动时必须同屏改）。
3. **格是闭集**：加一个决策点要改 `Site` 枚举 + `ALL` + `name()`。这与 `Capsule`
   同理，是想要的——格是环的**决策点清单**，不是插件可自由扩展的注册项。

## 失效边界

- 出现**同一格内多行都要在同一问里基于彼此结论仲裁**的需求（现在只有「先命中
  者胜」）。`prio` 表达的是全序，表达不了「A 命中则 B 让路」这类依赖；届时
  需要的不再是格内序号，而是格内的一次 fold——属 `drive` 的范畴，不在本 ADR。
- 若某个格的状态量增长到与 `LoopState` 其余字段不可区分（例如两格开始共读同一
  个字段），`LoopState` 的并集形态就该拆成每格一个结构。现在五格字段集**两两
  不交**（`site_fields` 是判据），这是可以不拆的前提。

## 后续

- 步骤 3 的「记忆 / 技能拆两行」现在可以施工：两行同属 `TurnPrepare`，`prio`
  在格内取 10 / 20（或 5 / 10 让新行先），不必动别格。
- `drive` 落地时删 `Site` 与 `Call`，把 `site_fields` 的语义（行只读本格字段）
  转交给「投影只产出当前步需要的量」。
