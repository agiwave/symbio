## 决策

**背景**：事实网格记的是「**发生过什么**」。有两处产出被按「完成态」筛掉了：

1. **思考不入格**。收束格载荷只有正文与模型（`chat.assistant.final` = `text` +
   `model`），模型的推理过程只活在转写节点里，网格里查不到。
2. **半截产出不入格**。轮次被中断（用户按停止）或收束于等待用户时，落格纪律写的是
   「**不落任何收束格**」，于是模型已经产出的半截正文、半截思考连同终止的原因与
   时刻一起消失。

第 2 条有可复现的后果：LLM 回复到一半提到某个名词，用户立即中断并追问这个名词是
什么。重建出的上下文里**没有那半句话**，模型看到的是一个没有前文的追问——最需要
上下文的那一刻，恰恰是被丢掉的那一刻。

**决策**：

1. **事实是「发生过什么」**：思考、正文、工具调用与结果是事实；一轮的产出无论完成、
   失败、被中断还是悬在等待用户，都入格。完成态不是事实的前提。
2. **完成 / 终止 / 等待是事实的「状态」，不是事实的种类**。状态随事实入账
   （`status`：`completed` / `failed` / `aborted` / `pending`），终止原因（用户中止 /
   服务端异常 / 超时 / 等待用户……）与终止时刻是状态的元信息（`terminated: {reason,
   at}`）。**不为中止 / 等待新增事实 kind**——那会把同一「模型产出」按终止方式分裂成
   多种事实，重建与统计都要特判。
3. **思考是事实**。随收束 / 兜底 / 中止一并入账（正文与节点身份同级记录）。
4. **半截产出是事实**。中止与等待用户时，模型已产出的半截正文、半截思考、已发出的
   工具调用及其结果照常入格，状态标 `aborted` / `pending`。
5. **呈现态仍不入格**（[ADR-049](049.md)）：
   `delta` 逐帧增量、在途 `seq`、Streaming 状态都不入格。**半截内容不是呈现态**
   ——它是「模型说到这儿」这个事实的正文，逐帧 delta 才是它的传输形态。
6. **一轮至多一条收束格的不变量不变**，中止也占这一格：收束格记的是「本轮模型产出」
   这一事实，`status: aborted` 区分它不是定稿；不复用兜底格（兜底是另一种产出事实：
   兜底话术）。等待用户是「还没完」——轮次仍未收束，半截产出以进展格入账
   （`turn × progressed`，`status: pending`），恢复后再收束。

**理由**：

1. 按完成态筛事实 = 系统性丢掉最需要上下文的那一刻。事实源要能回答「发生过什么」，
   而不是「完成了什么」。
2. 追问依赖被中断的那半句。少了它，模型面对的是悬空问题——这不是精度问题，
   是上下文完整性问题。
3. 「不把用户按停止记成模型答不出」与「不丢中止内容」是**两件事**，都要做。
   现在只做了前一件，把后一件当成了前一件的代价。

**被否决的方案**：

- **中止不入格，留作「诚实的缺口」**：否决。「诚实」是相对假象而言的——少记一条
  确实发生的事不是诚实，是缺口。缺口的正确处置是连原因一起入格，不是留白。
- **把半截产出归入呈现态**：否决。`delta` 是传输形态，半截内容是事实，两者不在
  同一层；混为一谈会把「用户看到过这句话」当成交付细节。
- **中止复用兜底格**：否决。那会把「用户按了停止」记成「模型答不出」，既污染兜底率
  也掩盖了真实经过。
- **为中止 / 等待新增事实 kind**：否决。kind 是**事实的种类**（用户发言 / 模型产出 /
  兜底话术 / 工具结果），完成与终止是**同一事实的不同状态**。为状态立 kind，同一句
  半截正文会因「谁按的停止」分裂成多种事实，投影与统计每处都要特判状态；状态字段
  一处即可表达。

**后果与不变量**：

- WAL 仍 append-only，同轮单一写方不变。
- v2 下一轮的产出在任何终止方式下都入格：收束格一条（`status` 区分 `completed` /
  `aborted` / `failed`），或等待用户时的进展格一条（`status: pending`，轮次收束后照常
  另有收束格）。「一轮至多一条收束格」不变，中止占这一格。
- **本条是真源切换的前置**：[ADR-049](049.md)
  一旦把 WAL 定为消息正文的唯一来源，这里没补上的产出就永久消失。顺序是先补事实、
  再切真源。
