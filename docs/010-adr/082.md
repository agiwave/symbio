## 决策

**背景**：[ADR-081](081.md "ADR-081") 把批次 6 分成了 6a（P4 收敛，已落地）与 6b（真切片），
并把 6b 的判据钉成卸载形——停用 ⇒ 不再开新一轮、在飞的轮在有限时间内收敛、存储侧读写照常。
6b 前置读数（2026-10-19，T-167 处理过程同日晚些条目）实测了成片清单（驱动器片 ≈14,352 行 +
resume 647 待裁）、出口两面（provider 臂与收件箱消费者的两处 `start_turn`）、入边九组反向引用，
并把六个问题留给本裁决：装配形状、留守侧拿「开跑一轮」的接线、九组反向引用归属、
`Convergence` 物理落点、`io.rs` 豁免到期处置、守卫用例形状。六个一起答。

**裁决一：装配形状 = 独立插件 `plugins/loop`。**

判据决定形状：卸载形的「停用 ⇒ 不开新轮」要能被**运行期表达**，而「停用」的既有机器只有一种
粒度——插件（装配期不构造 ⇒ 路由 `NotFound` ⇒ 消费方按「缺插件」处理，`assembly/mod.rs` 文档
原话；批次 2b 已用它验过心跳）。「驱动器留在 session 内做编译期分层」给不出这个动作：停用
session 连存储面一起失去，「存储侧读写照常」这条断言直接不可达。且落点不是新发明——
PL-014 §5 步 6 原文就写着 `session`(存储+生命周期) / `loop`(驱动器)；
T-167 出口判据「卸载它之后 session 只剩存储与生命周期」也只有独立片才配得上。
`loop` 进 `ASSEMBLY_SUB_AGENT_PLUGINS`（与 session 同批入列，子 Agent 树分形各得一份），
构造注册照 `submit_object_creator!` 先例；本片能力行仍 0，但贡献 **1 条 Mount 行**（裁决二的
起始地址）⇒ 它同时落入 T-167 出口 ② 的卸载判据形式（不再纯依赖方向形——读数 ④ 的预判随本裁决
修正：Mount 行就是它的「该片能力行在下一轮收集里消失」断言对象）。

**裁决二：两个方向的接线各走各的既定机制——触发（session→loop）走地址面，服务
（loop→session）走 core 端口，词表走 core。**

- **触发 = 地址面**。loop 注册自己的 VDFS provider（一条新根，根名与载荷形状落地批登记进
  ROUTES），两个入口各改成一次地址面写：`plugin/vdfs_provider.rs:525` 的恢复臂在 session 侧
  **再派发**（公开地址不动——前端仍写会话地址，避免把 ADR-066 的退役单轨改成第二次公开面变更）；
  `transcript/inbox.rs:617` 的收件箱消费者写 loop 起始地址。写是**同步回包**的（心跳先例：
  失败 ⇒ `Conflict` ⇒ 不入队），忙碌拒绝那条线格式随载荷原样迁移——provider 臂的
  「忙碌时明确回绝」是 UI 可见契约，不可破。消费者**留守**：收件箱队列 owner 在存储
  （ADR-081 裁决三「到达归存储」），loop 停用期间消息继续入队、恢复后照常抽干。
- **服务 = 两个 core trait，形状照 `ModelProvider`（AR-025）**：
  ① `TurnHost`——由留守侧的 `Convergence` 实现（它就是为此存在的收敛半身）：句柄工厂三臂、
  sink 落一帧、broadcast 运行态、consume 清在途、store 读写、配置与目录快照、收件箱取批与变更通知；
  ② 会话句柄端口——`PersistentChatSession` 的方法面（驱动器现用 12 个：`session_id` /
  `session_dir` / `get_messages` / `replace_all` / `persisted` / `context_window` / `cfg_or_default` /
  `delegating_principal` / `parent_session_id` / `list_sub_sessions` / `load_sub_session` /
  `skill_compile_enabled` / `skill_fast_path`，读数时把 19 处 `.apply` 误算进句柄面，实测那是
  投影 apply，不计）。**面 = 迁移既有调用，不新增能力**；`SESSION_HANDLE` 的 ctx 值随端口类型改
  （`ChatSessionHandle` 已是现成载体）。`chat_session.rs:26`「不设 ChatSession trait（唯一实现
  即本结构体）」的旧判词随本裁决反转：切片之后端口有了第二个消费方（跨插件的 loop），
  单实现多态的判断前提不在了。
- E-009（插件互不可见，测试同样判）把「不经端口碰存储」从纪律措辞变成编译事实——
  P3/P4 这条链的最终执行方。

**裁决三：九组反向引用逐条定归属（ADR-075 裁决四兑现——词汇在切的那一刻定）。**

| 组 | 边 | 裁决 |
|---|---|---|
| 1 | `stats.rs:758` → `chat_loop::request_principal` | **上移 core**：它是对 core 既有键（`SOURCE_PRINCIPAL`/`AGENT_ID`）的纯派生函数，不住任何片。 |
| 2/3/6/7 | `rebuild.rs` → `dialog_node` / `ReportDraft::to_message` / `llm_build_*`；`plugin/{nodes,vdfs_provider}.rs` → `flatten_whole_tree`；`memory_events.rs` → `merge_kernel` 两函数（第二消费方是 `skill_events.rs`，它今天经 `memory_events` 转手） | **上移为节点构造词表**：全部是 core `ChatNode` 上的纯构造/整形函数。落点分三处——构造与折叠 = **新模块 `symbio_core::schemas::session::node_build`**；`ReportDraft` 这条跨端口记录类型 = 新模块 `symbio_core::schemas::session::facts`（与 4/5 组同判）；`merge_kernel` 是只依赖 `std`、被 verify 以 `#[path]` 共有同一份源码的**纯计算内核**，归位 core 文本域 `symbio_core::text::merge_kernel`（根开 `pub(crate) use text::merge_kernel`）。**不是 `chat_node.rs`**——那个文件是前端机制化显示节点的**形状定义**（角色/形状/style_tag/线格式），不收留写侧机制；构造与折叠是「按该形状产节点」的后端手艺，与形状源同目录紧邻而各住各的文件（落点纠偏见 T-167 处理过程 2026-10-19 批次 6b-①）。留守读侧投影（rebuild）与驱动器写侧用同一份形状源，这正是 rebuild 模块头「形状来源不在这里定义」想要的那个住处。`ReportDraft` 的其余半身（汇报落格）留 loop。 |
| 4/5 | `derived_facts.rs` / `task_events.rs` → `tools::{Delegation, TaskDeclaration, TaskItem, TaskStatus}` | **随端口进 core**：写侧是 loop（工具执行产出），落侧是留守（derived_facts 落事实）——它们是**跨端口载荷的记录类型**，与事实源上同族（`types::Session` 一族同判：存储的记录类型，归属随留守层，跨插件者上移）。 |
| 8 | `orchestrator/broadcast.rs:30` → `plugin::session_node` + `OUTCOME_*` | **原样合法**：`Convergence` 归位留守层后这是 session 插件内部边，不成环、不动。 |
| 9 | `resume.rs` → 驱动器五个符号 | **归驱动器片**，随 ① 搬家；signal 六段表把它算进「存储与生命周期」是误分类，随本裁决订正（import 面全是 `chat_loop::ChatOrchestrator` / `tools::execute_tool_async` / `turn_exec::ResumedTool` / `context::retry_compaction` / `message_build::turn_root_of`）。 |

**裁决四：`Convergence` 归位的物理落点 = 留守层顶层。** 它与 `chat_session` / `active` / `store`
同级（6a 裁决已登记归属，随 6b 换目录兑现）；`orchestrator.rs` 底座 238 行随两侧拆分
（词表部分按裁决三第 8 组）。提前换目录不等于卸载能力那条旧理由不再适用——切片就在这批。

**裁决五：`io.rs` 豁免到期 = 废除豁免条目、回退改经端口，契约原样保留。** ADR-081 把豁免期限
钉在 6b，兑现方式是：缺句柄回退构造（「交付失败 ⇒ 降级内存会话、不阻断对话」）作为
`TurnHost` 句柄工厂的既有 ephemeral 臂留在留守侧，io.rs 调用那一下即可——它今天调的本来
就是 `PersistentChatSession::detached` 的同款构造。**豁免名册归零**，不是废除契约而是契约换载体。

**裁决六：守卫用例 = composite 真实挂载 + 停用 loop，三条断言一条不少。** 形状照批次 2b 先例
（工厂 id + 真实 `mount_all`）：① 停用 ⇒ 写 loop 起始地址 `NotFound`，provider 臂与消费者按
「缺插件」处理、**不再开新一轮**（消息继续入队不丢）；② 在飞的轮在有限时间内收敛——spawned
任务持端口 `Arc` 克隆，`Convergence` 的存储格子比插件活得久（3c-1 设计的这半），看门狗与 abort
路径不动；③ 存储侧读写照常（`list` / `stat` / 读转写 / 写收件箱全绿）。②的「有限时间」断言
若受 1800s 看门狗牵制，用例以注入短时限实现——机制不动，只加测试可注的既有配置面。

**否决的替代方案**：

- **同插件编译期分层**（不独立、判据降回纯依赖方向形）：被否——卸载形不可表达（见裁决一），
  且 PL-014 §5 步 6 原文与 T-167 出口的最强形态都以独立片为准。
- **消费者迁 loop + resume 统一入收件箱队列**：被否——resume 若排队，运行中会被 2f 补充合并
  吸进当前轮（答复语义丢失），而「忙碌同步拒绝」是 UI 可见契约；改契约不是切片的副产品，
  是另开的行为变更。
- **`TurnStarter` 服务端口（session 缓存 loop 的 `Arc`）/ 每派发跑一次收集取行**：被否——
  缓存的 `Arc` 停用不失效（陈旧服务继续开轮 = 判据 ① 的反例），每派发再收集等于每条消息
  双份 traverse；且「持兄弟插件的具体对象」正是 P2 清零、downcast 那条形态的新皮。
- **公开面直改**（前端/CLI 直接写 loop 地址）：被否——ADR-066 刚把 chat/send 退役单轨到会话
  地址，公开面第二次改形要前端、CLI、e2e 三处重对，代价由全体消费方付；session 侧再派发
  把变更封在插件内部。
- **把 Policy 行入表 / Registry 消失混进 6b**：被否——那是 PL-014 的「注册即事实」收尾小步
  （§5 步 4 收尾注）的账，一刀只服务一条判据；6b 切片不需要策略行也能被卸载形判完。

**后果与施工分刀**（每刀门禁全绿独立提交，同批次 3/4 先例）：

- **6b-① 词表上移**（行为不变）：节点构造族 + `request_principal` + 四个事实记录类型 +
  跨端口记录词汇进 core；判据 = 九组反向引用的 1/2/3/4/5/6/7 组清零（留守/宿主文件不再
  `use` 驱动器侧符号）。CS-001 只加数据不加口（本刀 0 个 trait）。
- **6b-② 端口成形**（片还在原地）：`TurnHost` + 句柄端口立进 core（Convergence 实现之），
  驱动器侧对 `chat_session` / `active` / `store` / `config` / `paths` / `types` 的具体类型触点
  全部改经端口；判据 = 驱动器文件 grep `use super::super::{chat_session, active, store}` 归零。
  **CS-002 变宽在此**：`pub trait` 18→20（+2 口），基线行挂本裁决；方法总数按落地实测补
  allow 注（面 = 迁移，不新增）。
- **6b-③ 成片搬家**：驱动器文件整体迁 `plugins/loop/`（外壳 = build + Mount provider +
  `stop`），`ASSEMBLY_SUB_AGENT_PLUGINS` 加 `"loop"`；两入口改地址面写、恢复臂再派发；
  `Convergence` 按裁决四归位留守顶层。判据 = E-009 全绿 + `cargo check` 依赖方向成立。
- **6b-④ 守卫用例**（裁决六三条断言）+ 棘轮对账（RE-006 的 Mount 行 +1、session 常驻任务
  仍 1、loop 常驻 0——消费者在留守侧）+ 文档随批（`017-module-layout.md` 双插件化、
  ROUTES 登记新地址）。
- 落地后：[ADR-081](081.md "ADR-081") 的豁免名册条目到期关闭（裁决五兑现）；T-167 只剩
  出口 ③ 的收尾对账；PL-014 剩「注册即事实」收尾小步与 §9.3 对齐宣告。
