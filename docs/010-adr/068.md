## 决策

**背景**：[T-138](../009-task/138-审批闸只覆盖local插件的能力.md "T-138-审批闸只覆盖local插件的能力")
的实测现场：`vdfs_delete` 在 `CapabilityMeta.risk` 里声明 `High`，`--mode interactive`
的会话里直接被执行——连一张审批卡都没出。闸门本身没错，`local::plugin::approval_gate`
的判据（工具自声明风险 vs 会话阈值 + `approved: true` 放行 + `mode=auto` 走
`PERMISSION_DENIED`）在过去若干次改动里都是对的；**问题是它长在 `local` 插件自己的
注册循环上**（`SecureToolWrapper`）。`vdfs` / `web` / `mcp` / `skill` 走的是另一条
`visitor.register(tool)`——工具裸进表，声明的风险执行期没人读。

不是把 `SecureToolWrapper` 复制给每个插件的注册循环——那会把「谁被裹壳」变成
逐插件的人工纪律，下一个新插件忘一次就漏一次。本条裁决**闸门住哪里**。

**决策**：

1. **闸门搬到能力注册的收口点** [`DefaultToolVisitor::register`]：每条进表的能力
   统一裹一层 `ApprovalGate` 装饰器；`meta` / `name` / `risk_for` 原样透传，
   `execute` 落到内层之前先过判定。这条一路覆盖 `vdfs` / `web` / `mcp` / `skill` /
   session 心跳工具——它们都通过 `CAPABILITY_VISITOR` 写入同一份内存注册表。
2. **判定与装饰器拆开、判定只有一份**：判定住在自由函数
   [`providers::collectors::approval_gate`]，装饰器 `ApprovalGate` 只是它的**注册面
   投影**；`local::route` 与 `web::route` 的**注册表未命中兜底**直接调判定，
   不再各自实现一遍。分发**两处入口**（`visitor.invoke` 命中 / `Plugin::route`
   兜底），判据**一处真源**——过去两处各写一份就必然漂移。
3. **判据不认工具名**：`risk > threshold` 里的 `risk` 由工具经
   [`Capability::risk_for`] 回答——静态档来自 `meta().effective_risk()`，
   动态档（shell 按命令分级）覆写它。`PrefixedCapability`（子 Agent 改名壳）
   必须**透传** `risk_for`，否则动态档在包装层下丢失，退化成默认档——本条与
   决策 1 一起改。
4. **`mode=auto` 不产卡**：`approval_gate` 判定要拦时，若 `ctx[MODE]="auto"` 则
   返回 `PERMISSION_DENIED` 友好错误（"请勿反复重试" / 提示切换模式），
   **不**产出 `NEEDS_APPROVAL` 卡载荷。无人值守时产卡等于把会话钉死在等待态；
   把「授权被拒」告诉模型才是可续跑的形态。**这是刻意的行为**，不是缺失——
   旧写法把这条藏在 `local` 插件里，容易被下一次「统一分发」误改成两处都产卡。

**为什么住在 `providers/collectors/` 而不是 `symbio_core`**：
`symbio_core` 的三格形状冻结在 CS-001（20 traits / 72 methods / 24 defaults），
把审批概念塞进 core 需要新加 trait——但判据本质是 `providers::collectors` 那条
**唯一的内存注册实现**的注册侧行为，不是机制层的抽象。判据不吃任何插件的私有
状态（`SecurityPolicy::check_tool_approval_needed` 只是 `tool_risk > threshold` 的
纯比较，随决策 2 一起删除），因此**能**也**该**落在收集器层。
`local::SecureToolWrapper` 与 `SecurityPolicy::check_tool_approval_needed` 都不存在——
两者都是「把判定说两遍」的写法。

**理由**：

1. **覆盖面 = 一处改动。** 「闸门长在 local 上」的形状下，加一个新插件
   注册入口就要重学一次纪律；现在加插件不必再关心审批——它只要走
   `CAPABILITY_VISITOR` 就自动过闸。**默认安全的形状**只有落在唯一的收口点
   才成立。
2. **判据与投影分离让「两处入口」不再漂移。** 分发有两条真实路径（注册表
   命中 / `route` 兜底）：装饰器把「命中」那条走通，`route` 兜底手工调判定，
   两处**读同一个函数**——判据内联在两处时，`route` 兜底与 `traverse` 各写各的，
   就会出现「本地工具在两条路径上表现不一致」。
3. **`risk` 是工具自声明、执行期读的量**——它必须是「分发路径上必过的一次比较」，
   而不是「目录页读的宣传语」，`CapabilityMeta.risk` 这个字段的语义因此**兑现**：
   声明了就生效，不看工具名，不看注册方。这是 ADR-055 芯形状（core 只留
   trait/键/信封，机制在 providers 层）的自然延拓。

**后果与不变量**：

- **`vdfs_delete` / `http_request` 不再裸奔**：实测判据由 e2e
  [T78](../../e2e/cases/t78-approval-gate-vdfs.mjs) 钉住（交互首轮停在卡上、
  批准后文件真被删；`auto` 模式不产卡、走 `PERMISSION_DENIED`）。
- **`local` 的行为不变**：`local::traverse` 交裸工具给 `visitor.register`，
  注册表命中路径的 wrapper 就是新的闸门口；`local::route` 兜底显式调判定。
  `ask_user` / `shell` 等既有用例（T27）继续绿。
- **`MCP` 默认档不受影响**：MCP 工具 `meta.risk = None`，`effective_risk() =
  Medium`；会话缺省阈值 `Medium` ⇒ `Medium > Medium` 为假 ⇒ 放行。既有 T26 无变化。
- **`web_fetch` / `http_request` 走注册表命中路径**：`web::traverse` 交裸工具给
  `visitor.register`，`http_request`（`High`）在 `interactive + medium` 会话下
  从此**必须过审批**——这正是本条的预期行为改变。`web::route` 兜底同样加闸，
  手工调用的绕过路径（例如 direct route 到 `http_request`）被封死。
- **判据一处、包装一处，`prefixed` 透传一处——三处文档同步**：
  `providers/collectors/approval.rs` 头部说明判据与投影的形状；
  `plugins/agent/host/scope.rs::PrefixedCapability::risk_for` 处注释说明透传理由；
  本 ADR 说**为什么住这里**——三处各自只回答一件事，不在两处复述。
- **默认阈值下会话行为会变**：新阈值语义生效意味着过去「声明了 High 但直接跑」
  的所有工具从此出卡（或 auto 模式下 `PERMISSION_DENIED`）——这是本 ADR
  **想要的行为**，不是回归。前端与 CLI 恢复链路（t27 的 `approve` action →
  `approved: true` 重放）本来就是为这条设计的，现在多了一族工具用它。

**被否决的方案**：

- **让每个插件的 `traverse` 各自 `SecureToolWrapper::new(tool)`**：否决。把
  「谁过闸」变成逐插件的人工纪律，下一个新插件忘一次就漏一次；本仓的插件面
  每年都在长，靠纪律守不住。
- **把 `approval_gate` 塞进 `symbio_core::Capability` trait 的默认 `execute`**：
  否决。CS-001 芯形状只允许**收窄**——加个默认 execute 反而让所有实现都拿到
  「默认带审批」的语义，比加一个装饰器更宽；且判据要读 `ctx[RISK_LEVEL]` /
  `ctx[MODE]`，把会话阈值概念拉进 core 是错的方向。
- **把 `SecurityPolicy::check_tool_approval_needed` 留在 local 里，让
  `providers::collectors::approval_gate` 调它**：否决。那个方法**不吃**任何
  `SecurityPolicy` 状态（`_tool_name` 都忽略），留在 local 就是给「判据住在
  local」留一个假象入口；本 ADR 决策 2 要求判定只有一份真源，同批删。
- **给闸门加「按工具名白名单」**：否决。判据不认工具名是这个机制**能否扩展**
  的前提——加一次白名单就多一处「新工具忘登记 ⇒ 漏过闸」的可能。工具的风险
  由**它自己**通过 `CapabilityMeta.risk` / `risk_for` 表达，闸门读它。
