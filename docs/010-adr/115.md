# ADR-115：义务环的输入闭包与执行契约

## 背景

[ADR-114](114.md "ADR-114") 把控制面单元从 `Step` 换成「债」，方向成立。但按现网代码
逐点核对后，PL-016 初稿漏了三块**承重墙**——不是措辞问题，是形状一落地就会暴露的空洞：

1. **`owed` 的入参不闭包。** 今天五个策略读的不只是事实：配置开关（`classify_enabled` /
   `auto_compress` / `has_facts`）、墙钟差（`quiet_ms`）、内存里的匹配结果（`skill_hits` /
   `resume_allowed`）都在 `LoopState` 里。若照初稿把 `LoopState` 换成视图，这些量要么
   继续从旁路读（`owed` 不再纯），要么凭空消失。
2. **执行体没有契约。** 初稿的 `actors.run` 是同步、无返回值、无取消、无超时；`drive`
   是 `fn`。而现网整条链路是异步的，中止信号随时到达，模型 / 工具调用会失败。
   照初稿写，失败只能靠执行体自觉落事实，漏一条就是静默停摆。
3. **端口粒度没有分期。** T-223/T-224 的文件面写的是 `loop_registry.rs` / `chat_loop/`，
   但模型与工具调用在 `turn_runner` / `turn_exec` / `tools` 里。按初稿"先做模型端口"，
   等于在 T-216 里倒置 `run_with_tools` 的内环——那是 PL-014 步骤 1 的活，会顶穿
   T-216 自己的 300 行熔断线。

另外两处表述必须钉死：授权不能用 `¬permitted` 这种否定模式（fail-open 风险），
`port` 放载荷而不是信封（否则"每条事实都有端口"在 30/35 情况下是假话）。

## 决策

1. **`owed` 的输入闭包为三样：事实切片、视图值、触发事件的时间戳。**
   `owed(&[Fact], &[View], now_ms) -> Vec<Debt>`。配置、墙钟、内存缓存一律先落事实或
   折成视图。视图可以把 `now` 折成布尔字段（`report_due` / `stale_sent`），但
   **`owed` 自己不读时钟**。
2. **`user.message` 必须先于任何判决入格。** 今天它在 classify 之后才落（
   `turn_runner::prepare_turn`），义务环里非法：`owes` 要匹配它。写入点前移到 `drive`
   之前，`produced_by` 仍指向用户请求。"这一步做过没有"用既有的 `turn.stage` 事实
   （`stage_events::done`），不再有 `TurnState` 缓存这第二份状态。
3. **执行体契约：异步、可取消、返回 `Result<Vec<Fact>, ActorError>`。**
   引擎在 `Err` 时写 `failed{id, why}`；每步前检查中止信号；`MAX_STEPS_PER_DRIVE = 64`；
   每步后比较日志头，无变化即收束 `exhausted{no_progress}`。失败不是异常分支，是事实。
4. **在途请求用租约 + 尝试号。** `sent` 之前由引擎写、之后由 `lease` 行按
   `PortDecl.lease_ms` 重试或判死；`request` / `sent` / `response` / `failed` / `retry`
   都带 `(id, attempt)`，幂等键是逻辑 `id`。目标是 at-least-once 可恢复，不是
   exactly-once。
5. **端口分两级。** T-223 落粗粒度 `turn` 端口（执行体内部仍是 `run_with_tools`，
   零改动）；模型 / 工具**单次调用**的端口化归 PL-017 / T-227。两者之间没有双调度器：
   `turn` 是普通 `by=Some` 执行体，PL-017 只是把它的内部拆成更多行。
6. **授权用正事实级联，不用否定模式。** `authorize` 行 `owes: request(port, id)`，
   `until: authz.granted(id) | authz.denied(id)`，`prio: 0`；`dispatch` 行
   `owes: request(port, id) ∧ authz.granted(id)`，`prio: 10`。没有 `granted` 就永不
   dispatch（fail-closed），拒绝是写了的 `denied` 事实。矩阵与判定位置不动。
7. **`port` 是载荷，不是信封；`FactDecl` 是一个事实名一条。**
   新增端口 = 0 个新事实名 + 1 个 `PortDecl` + 适配器 + 2 行主模板（租约行通用）。
   这同时修正 PL-016 判据 1 的"3 条 `FactDecl`"口径。

## 理由

| # | 依据 | 本裁决做了什么 |
|---|---|---|
| 1 | "回放可重建"要求 `owed` 是纯函数 | 把配置 / 墙钟 / 内存结果全部推回事实面 |
| 2 | 现网执行链是异步且可中止的 | 契约写进 `drive` / `ActorDecl`，不靠执行体自觉 |
| 3 | `run_with_tools` 是 PL-014 步骤 1 的范围 | 粗端口先让控制面成为唯一债环，细端口另立 PL-017 |
| 4 | `open` 的公式已含"不存在 `until`" | 再叠否定原子会让"无记录"与"被拒绝"不可分 |
| 5 | 协议名全局、端口是取值 | `FactDecl` 按名字声明，`PortDecl` 携带端口参数 |

**这不是对 ADR-114 的改判。** 调度单元仍是债、意图仍落为请求事实、`Wait`/`Ask` 仍折叠。
本裁决补的是 ADR-114 决策 1 的签名（加 `now`）、决策 3 的执行语义（失败 / 取消 / 重试）、
决策 4 的落地粒度（先 `turn` 后 `model`/`tool`）。目标形状不变。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| `owed` 直接读 `clock_now_ms()` 与配置 | 同一日志重放两次结论不同；"纯函数"退化成口号 |
| 视图 `eval` 接 `&Store` / 其他视图 | 视图互相调用会让求值图无环检查失效，且第二条状态通道复活 |
| 同步 `drive` + 执行体自己保证不阻塞 | 现网是异步的；中止与超时无处安放，失败只能靠自觉 |
| 先做模型端口，再铺工具 | 模型端口要求内环倒置，范围是 PL-014 步骤 1，不是 T-216 的一步 |
| 用 `¬permitted` 表达未授权 | 否定原子与"不存在 `until`"叠加，fail-open 风险不可静态排除 |
| `port` 放信封 | 只有 5/35 个名字有端口；信封字段会让绝大多数事实带一个空维度 |
| 每个端口声明一套 `FactDecl` | 端口是载荷取值，不是事实种类；按端口声明会让事实名随端口膨胀 |

**代价（全部已知）**：

- 输入闭包每轮多落 `session.config` / `turn.stage` / `user.message` 几条事实。
- 粗端口期间，崩溃只能重放整轮，不能重放单次模型 / 工具调用。
- 单写者 + 异步意味着同一会话的债串行还；并发来自多会话与执行体内部。
- 租约重试是 at-least-once，非幂等适配器必须声明并要求人工确认。
- 时间只随事件前进：没有事件时"静默够久"不会被求值；独立定时唤醒是唤醒源的事。
