## 决策

**背景**：`ChatNode.principal: Option<String>` 今天承载两件事——「主体是谁」与「主体是哪一族」。
值域 `agent:main` / `user` 把 kind 编进了字符串本身；`AGENT_PREFIX = "agent:"` 是判定用的形状，
`matrix_for` 与 `visible_to` 都靠它分岔。三处形状问题：

1. **kind 混在 id 里 ⇒ id 不再可路由**。`agent:main` 里的 `main` 是主体名，`agent:` 是类别——
   「谁的 main」没人说得出。VDFS 地址、route 常量、`plugin/name` 都是**可路由的**，principal 应该同族。
2. **`user` 是裸字面量**（无冒号）——与 `agent:xxx` 的语法不对称；多用户 / 具名人类主体没有
   `<id>` 段可挂。
3. **工具不是主体**——工具的返回今天挂 `NodeRole::Tool`，`principal` 却是调用它的 `agent:*`；
   「谁在回答」在角色与主体之间飘。

**决策**：Principal 是**三字段结构体**，kind 与 id 分家。

### 1. 形状

```rust
pub enum PrincipalKind { Person, Agent, Tool, System }

pub struct Principal {
    pub kind: PrincipalKind,       // 一族：枚举，编译期闭集
    pub id: String,                // 可路由地址 `<namespace>/<name>`
    #[serde(skip_serializing_if = "Option::is_none")]
    pub title: Option<String>,     // 显示名（渲染层用；与 kind 无关）
}
```

序列化：
```json
"principal": { "kind": "tool", "id": "vdfs/write", "title": "VDFS 写文件" }
```

### 2. id 规范（可路由地址）

**核心思想**：id 是**主体地址**——拿着这个地址可以找到这个主体、调用它、查看它的各种信息。
这与 VDFS 地址（`<sid>/message/<mid>`）、route 常量（`/session/:sid`）、`plugin/name`
是**同族形状**——都靠「第一段 = 归属，后续段 = 归属内的名字」支撑路由。

**规则**：id 是 `<namespace>/<name>` 或更长的路径段。第一段是**该主体的归属**——通常是
**插件名**（可路由到那个插件的注册表），没有插件时用**概念名**（`person` / `system`）。
归属段决定「找谁解析」；name 段决定「解析到归属内的哪一个」。

| 主体 | kind | id 例子 |
|---|---|---|
| 主智能体 | `Agent` | `session/main` |
| Worker / Planner / Verifier / Reflex / Peer / Market / Arbiter / Gatekeeper / Autonomous | `Agent` | `session/worker` · `session/planner` · … |
| 本机用户 | `Person` | `person/local` |
| vdfs 写工具 | `Tool` | `vdfs/write` |
| 网页取回工具 | `Tool` | `web/fetch` |
| 本地检索工具 | `Tool` | `local/content_search` |
| 压缩器 | `System` | `system/compactor` |
| 心跳 / 调度器 | `System` | `system/heartbeat` · `system/scheduler` |
| 抢占判定者（若拆到独立 decider 插件） | `Agent` | `decider/reflex` |

**要点**：
- **kind 不进 id**——id 是**地址**，kind 是**类别**，两者正交
- **id 全局唯一**（namespace 不撞）⇒ 授权表按 id 索引；kind 是运行时判定用的元数据，
  不做存储主键
- namespace 由**归属插件 / 概念**决定，不由 kind 决定——`Agent` 一族可以住在 `session/*`
  也可以住在 `decider/*`；`Tool` 一族住在各自的插件下（`vdfs/write` / `web/fetch`）

### 3. 判定面（kind 是**结构体字段**，不是字符串前缀）

原来的 `AGENT_PREFIX = "agent:"` 从**协议判定**里退役。判定面拆两块：

- **协议侧**：任何「谁在发言」的判据**读 `principal.kind` 字段**，不解析 id 字符串。
  `visible_to(actor, viewer)` 的「非智能体一律可见」这一半换成 `!actor.kind.is_agent()`。
- **派生侧**（`matrix_for`）：`session/*` 一族里未登记的 ⇒ 派生主智能体那一行
  （S08 §4 身份分层 ≠ 权限分层）。派生判据取自**「哪些 namespace 承载 Agent」**这张
  命名空间登记表，而不是字符串前缀——`const AGENT_NAMESPACES: &[&str] = &["session"]`；
  将来把 reflex 拆到独立 decider 插件，登记表加一条 `"decider"` 即可。

### 4. 写侧规则（唯一入口 `plugins/session/append_and_publish::attributed` 附近）

- 用户正文 → `Principal { kind: Person, id: "person/local", title: None }`
- 助手正文 / 思考 → `Principal { kind: Agent, id: "session/<role>", title: None }`
- 工具调用**请求**节点 → `kind: Agent, id: session/<调用者>`（是 agent 在说"我要调这个工具"）
- 工具**响应**叶子 → `kind: Tool, id: <plugin>/<name>, title: Some(<显示名>)`
- 压缩 / 心跳 / 调度器触发 → `kind: System, id: system/<name>`
- 已带身份**不覆盖**（覆盖就是串主体）；`None` = 尚未接线，可见域判据视为**可见**
  （沿用今天 ADR-032 的定性）

### 5. 授权表按 id 索引，kind 不参与主键

`ROWS: &[(&str, &[&str], VisScope)]` 的**第一列从 `"agent:main"` 变成 `"session/main"`**——
仍然是 `&str`，值是 id。`matrix_for(id: &str)` 签名不变。工具行按 ADR-069 §决策 2 表里的 id
（`vdfs/write` 等）登记，kind=Tool 由**协议侧携带**（Principal 字段），不进表本身。

### 6. `ChatNode.principal` 字段类型迁移——分批

这是**协议字段类型变更**，影响面大。分两批：

- **本批 [T-146]**：`ChatNode.principal: Option<String>` **不变**，但**值域**改成新的
  id 形状（`session/main` / `person/local` / `vdfs/write` 等）。所有 `PRINCIPAL_*` 常量值改到
  新形状；`AGENT_PREFIX` 保留但语义从"agent 前缀"变"session/* 命名空间的判定"——
  实际实现是 `AGENT_NAMESPACES` 列表 + `is_agent_id(&str) -> bool`。
- **下一批 [T-147]**：`ChatNode.principal: Option<String>` → `Option<Principal>`，
  kind 与 title 作为字段挂到协议上；历史 `messages.json` 里的旧字符串一次性映射
  （`"agent:main"` → `{kind: Agent, id: "session/main"}`，`"user"` → `{kind: Person, id: "person/local"}`）。

## 为什么不合并 principal 与 role

`role`（User / Assistant / Tool / System 四值）与 `principal.kind` 表达同一件事——
「这条发言属于哪一族」。两份定义必然漂移。[ADR-070] §决策 4 把 `role` 从协议顶层**删掉**，
本 ADR 是它的前置：`kind` 已经能覆盖 role 的四取值。

## 后果

- **改**：`authz.rs` 所有 `PRINCIPAL_*` 常量值（从 `agent:*` 迁到 `session/*`，`user` → `person/local`）；
  `AGENT_PREFIX` 常量替换为 `AGENT_NAMESPACES: &[&str] = &["session"]` + `is_agent_id()` 判定
- **加**：本批只加**常量与判定**，不加 `Principal` 结构体（那属于 [T-147]）
- **加行**：`tool:vdfs_write` 等三条工具主体在 ROWS 表里从 `tool:*` 键改成 `vdfs/write` 键，
  语义不变（`produce.artifact`）
- **兼容**：历史 `messages.json` 里的 `principal: "agent:main"` / `"user"` **本批不做读侧别名**——
  本批只是常量迁移；读侧兼容 [T-147] 一并处理
- **测试**：`authz.test.rs::all_principals_match_prefix_wordlist` 判据改为「所有 `PRINCIPAL_*` 常量
  是 `<ns>/<name>` 形状」；`view/mod.test.rs` 的 `principal_prefixes_are_closed_set` 判据改成
  「kind 是枚举，`is_agent_id` 用命名空间登记表」
- **前端**：`ChatNode.principal?: string` **不变**（值域变宽），[T-147] 才动 TS 类型
