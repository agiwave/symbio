## 决策

**背景**：会话协议里「这条发言是谁说的」今天由 `ChatMessage.principal: Option<String>` 承载，值域只有
`agent:<name>` 一族加一个裸字面量 `user`（`symbio/src/symbio_core/authz.rs::PRINCIPAL_USER`）。
两个形状问题：

1. `user` **是裸字面量**——与 `agent:main` 的冒号前缀规范不对称；一旦要引入「多用户 / 具名人类主体」，
   它没有 `<id>` 段可挂，只能改字符串本身，改一次动一片。
2. **工具不是主体**——今天工具的返回被塞进 `MessageRole::Tool`，`principal` 却是调用它的
   `agent:<name>`；「谁在回答」这个语义在角色与主体之间飘。[PL-013 §4](../004-plan/013-前端机制化.md "PL-013-前端机制化")
   把前端从「按 role 分派」改成「按 principal 分派」，工具不升为主体就没有稳定的显示归属。

**决策**：PRINCIPAL 的词表统一为**四前缀 + 冒号 + `<name>`**，全部小写短横线：

| 前缀 | 值 | 今天的对应 |
|---|---|---|
| `person:<id>` | 人类主体 | `PRINCIPAL_USER = "user"` → `"person:local"`（多用户时换 `<id>`） |
| `agent:<name>` | AI 主体 | 已存在——`main` / `worker` / `planner` / `verifier` / `reflex` / `peer-b` / `market` / `arbiter` / `gatekeeper` / `autonomous` |
| `tool:<name>` | **新**：工具主体 | 今天不存在；工具返回的发言方 |
| `system:<name>` | **新**：系统主体 | 今天不存在；compaction / heartbeat / scheduler 等无 agent 参与的自发事件 |

**写侧规则**（唯一入口：`plugins/session/append_and_publish::attributed` 附近）：

- 用户正文 → `person:<id>`
- 助手正文 / 思考 → `agent:<name>`（沿用今天）
- 工具调用**请求**节点 → `agent:<调用者>`——是 agent 在说"我要调这个工具"
- 工具**响应**叶子 → `tool:<name>`——是工具在回答
- 压缩 / 心跳 / 调度器触发 → `system:<name>`
- 已带身份的帧**不覆盖**（覆盖就是串主体）；`None` = 尚未接线，可见域判据视为**可见**（沿用今天 ADR-032 的定性）

**授权表**按前缀扩行——`tool:*` 与 `system:*` 每族至少要有若干条 `ActorSpec`，值域与
`plugins/*/tools/spec.rs` 的 `SPECS` 表、`plugins/*/plugin/*.rs` 里自发事件的主体名对齐；缺行由
`registry-audit` 的 C 组（能力名册 ↔ 代码锚点）判红。

## 为什么不合并 principal 与 role

`role`（User / Assistant / Tool / System 四值）与 `principal` 的**前缀**表达的是同一件事——
「这条发言属于哪一族」。两份定义必然漂移：改 principal 词表时 role 分支不改，前端就出现
「principal=tool:web_fetch 而 role=assistant」。[ADR-070] §决策 4 把 `role` 从协议顶层**删掉**，
本 ADR 是它的前置：只有先把前缀词表铺开并覆盖到 `role` 的全部四取值，删才有落点。

## 后果

- **改**：`authz.rs` 的 `PRINCIPAL_USER` 常量值；`chat_loop::request_principal` 的返回值；
  `session/append_and_publish::attributed` 的补身份分支（加 `tool:*` / `system:*` 两族写入点）
- **加**：`tool:vdfs_write` / `tool:web_fetch` / `tool:content_search` / … 若干 `ActorSpec` 行；
  `system:compactor` 一行；`person:local` 一行；`grants` 表按新行同步
- **兼容**：读侧对旧值 `user` **一次性别名**到 `person:local`（不保留双写）；`agent:*` 一族完全不动
- **测试**：`chat_message.test.rs` 加一条 `principal_prefixes_are_closed_set` 单测锁四前缀；
  `authz.rs` 加一条 `all_principals_match_prefix_wordlist`——所有 `PRINCIPAL_*` 常量必须落在四前缀内
- **前端**：`ChatMessage.principal?: string` 类型不变，只是**值域扩宽**；分派层加一张
  「前缀 → 默认图标/颜色」的表（T-148）
