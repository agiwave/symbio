# ADR-122：入账不是调用点的责任——classify 与 compress 的模型往返搬进环里发生

## 背景

[T-247-插件内部模型往返进环](../009-task/247-插件内部模型往返进环.md) 登记的缺口：
`obligation-ring-accept` 的 J8（真实模型 HTTP 调用数 == `sent(port=model)` 数 + 豁免）
在每一轮都差一次调用。差额来自**插件内部**的模型往返：`classify` 的快速档判决、
自动压缩的摘要。编排层手里只有「路由一次 `classify/decide`」这一个动作，
调用发生与否、发生几次，都在插件里。

三个候选（登记在 T-247 的 `exit`）共同的前提是：**入账动作发生在调用点附近**。
本对话里三次 CLI 实证把这条前提否掉了（T-243 复验会话 `verify-seal-1`）：
`classify` 各打了一次模型，应答不可解析 ⇒ `Escalate{unclassified}` ⇒ `source=fallback`，
事实层**连观测都没有**——`turn.stage{decide}` 的 `source` 记的是**判决的来源**，
不是「有没有打过模型」。候选 ② 「先问这次会不会打模型」在这个形状下连问都问不出来：
调用前插件自己不知道规则表命中，调用后事实层只留下来源。

## 决策

1. **协议格的写方不增加。** `request` / `sent` / `response` / `failed` / `retry` 只由引擎在
   它自己派发的那一次往返里写（[PL-016-义务环](../004-plan/016-义务环.md) §4 五事实、
   [ADR-118](118.md "ADR-118") 决策 6 写权按行切）。**任何插件都不经由 `ctx` 拿事实源句柄
   自己 announce 一组三格**——候选 ① 否。
   理由是管辖错位，不是洁癖：账上的 `sent` 一旦被引擎之外的东西写过，
   `lease`（看护派出未应答的往返）与 `retry`（按尝试号重放）就开始管**引擎无法重放**的调用，
   「崩溃后重放到上一次模型请求」这句话对这几笔成为假话。
2. **要入账就让它进环里发生：调用搬进行表，不搬记账。** `policy.classify`（prio 10，
   现 `by: None`）与 `policy.compress`（prio 30，现 `by: None`）各接一个执行体
   （`decide` / `compress`，名单见 [ADR-118](118.md "ADR-118") 决策 3），
   它们的模型往返走**引擎的 `model` 端口派发路径**——与 `dispatch-model` 同一条路、
   同一组三格、同一个 `Key::trace()`。插件侧不再保留直接打模型的入口。
   这样入账是**副产品**而不是责任：谁派发，谁写格，J8 的等式按构造成立。
3. **候选 ③ 的两半分开处置。** 「消灭插件内部路径」这一半**取**——第 2 条就是它的实现形状。
   「把模型分类并入工具循环首轮」这一半**否**：它改的是产品行为（路由判决由谁来出），
   而 PL-016 的行表里**已经为 classify 留了行**（`policy.classify` 的 `owes` / `until`
   都已定义），把能力并进首轮等于让那行永远空转，也否掉了「判决可能有、也可能没有模型
   往返」这个真实区别（规则表命中 ⇒ 零往返，这条在第 4 条里仍要可判定）。
4. **零往返的轮必须是「行不成立」，不是「行成立但没写格」。
   ** 规则表命中时 `policy.classify` 的 `until`（`turn_stages{decide}`）照样被落
   （判决这一步确实跑了），但**没有** `model` 端口的一组三格——这条与「打了模型并入账」
   在事实面可分，正是 T-247 验收口径 2 要的两条用例的形状。
5. **退化应答照样有应答格。** 本地模型 `finish=Length`、正文 0 字符那一类（T-142 出口）
   仍是一次真实往返：`request` + `sent` + `response` 三格齐，`calls` 为空数组。
   「本轮未产出答话」是**收束侧**的判断（落在收束格的 `reason`），不是端口侧缺格的理由。
   这条写明是为了 J8 在失败轮也成立（T-247 处理过程 2026-10-23 补记的那次差额）。

## 后果

- `scripts/obligation-ring-accept.mjs` 的 `MODEL_PATHS` 里 `classify/decide` 那条豁免
  （`task: T-247` / `until: 2026-11-05`）**删除**，且这条路径的观测从「读 CLI 日志的
  `logMarker`」改回「读事实层的三格」——日志口径是事实层不可判时的临时手段，
  本裁决把它要解决的成因消掉了。豁免表不许长第二行。
- 压缩路径按同一形状处理：`policy.compress` 接回执行体后，摘要调用成为一次端口往返；
  零模型调用的压缩（没有可压内容）与 classify 同判——行不成立或 `until` 由阶段事实关掉。
- 两处插件侧调用点随本裁决**消失**，实现批要一起收掉它们的登记，否则门禁当场红：
  `symbio/src/plugins/classify/decide.rs:161`（`ProviderLlmAdapter::generate_turn` 直调）
  与 `symbio/src/plugins/loop/context/pipeline.rs:957`（压缩摘要，`internal-model-allow
  IM-001` 豁免）。后者是 `IM-003`（悬空豁免）的判据对象——调用点搬走而标记留着，
  `scripts/internal-model-audit.mjs` 判红，不是「以后再说」。
- 实施是 T-247 的后半批（改模块），本 ADR 只是它的准入条件；
  在那之前 `classify` / `compress` 两行的 `by: None` 不许为了「让 J8 绿」而改成
  任何让插件自己写格的形状。
