# ADR-104：意图闸门不另立令牌

## 决策

删掉 `GateWarrant` / `IntentGate::issue_warrant`。E2「欲不得直接变成行」的强制力改由
**两件真东西**承担：

1. `ApprovedIntent` 字段私有，唯一构造点是 `IntentGate::approve`——模块外连结构体字面量
   都写不出，绕过闸门的路径在编译期不存在；
2. `approve` / `evaluate` 的入参里带**授权判据**（`EffectiveMatrix` + 主体），闸内判
   `define.work`，与任务表写侧闸同一把尺。

预算与审计**不进闸**：它们是执行面的闸（熔断闸对真实调用计费）与事实流（`task.opened`
带 `produced_by` 指回欲事件）。升格本身不花预算，也不产生第二条写入通道。

## 为什么不是「给发牌口补三道检查」

原签名 `issue_warrant(/* 三道检查通过 */) -> GateWarrant` 的承诺是「经授权 / 预算 / 审计
三道检查后才发牌」。要在现有类型面上兑现，只能新造两样东西：一份「预算余量」入参
（本仓没有意图级预算类型，只有执行面 `CircuitBreaker` 的 spent/requested/budget）
与一个审计出口（core 的 conation 没有 store 句柄）。两样都是**为签名而造的类型**：

- 预算若做成 `spent_ms <= budget_ms` 的入参，判的是「调用方自己填的两个数」——
  假边界的形态与它要修的缺陷一模一样，只是从「没检查」升级成「看起来像检查」；
- 审计若做成入参，最省事的写法是传一个布尔或一个已构造好的事件——同样不自证。

所以本批**原地重裁**（[T-178](../009-task/178-过度机制清偿批.md "T-178-过度机制清偿批")
允许「施工中发现无处安放则退回本批重裁」，不允许「降级后就地混过」）：删掉令牌，
把能判的授权判进闸里，判不了的交给本来就在动作面判它的机制。

## 否决的替代

- **保留令牌，发牌口接授权**：授权进了闸，令牌仍是无检查的壳——它只在 `approve`
  的参数表上多一个位置，而 `ApprovedIntent` 本来就已经不可伪造。多一个元素、零增益。
- **保留令牌，三道检查都写成注释**：那是原状（J3 静默失效），批目的正是清掉它。
- **删掉 `ApprovedIntent` 的私有性、只留 `approve` 作约定**：约定不拦人，
  且这正是本条要避免的方向。

## 后果

- 意图闸门第一次在生产里有**授权读方**：`EffectiveMatrix::can_write` 的
  `#[cfg_attr(not(test), allow(dead_code))]` 随之摘掉——它不再是「只有测试在读」的谓词。
- `ApprovedIntent` 的读取口是 `source_seq()` / `goal()`；字段私有由
  `verify/conation_minimal.rs` 的 `should_not_compile` 用例（E0451）继续钉住。
- 新增一条可执行反例：开关打开但不持 `define.work` 的主体升格被拒
  （`unauthorized: define.work`），被拒的候选不得变成已批准。
- [PL-001 §4.2](../004-plan/001-核心架构.md "PL-001-核心架构") 的口径同步为「字段私有的
  批准类型」；「同一机制用了三次」的表述收为两处 + 第三种形态的说明，不再暗示
  「令牌 = 强制」。
- core 三格不变（本条只动固有方法与类型可见性，不动 `pub trait` 面）。
