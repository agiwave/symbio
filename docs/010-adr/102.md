# ADR-102：Agent 权限声明当前无执行方——字段改回声明性质，补齐须四字段同批

## 决策

`manifest.yaml` 的 `permissions` 四个字段**保留线格式**，但 Rust 侧改名为
`declared_permissions`，模块文档、Agent 目录规范 §5.3 / §11-4 同步明写
「**本字段当前没有执行方**」。它是包作者与宿主之间的**沟通面**，不是安全边界。

## 为什么不是补执行方

四个执行点分布在不同层，且**每一个单独接都会产生新的假边界**：

| 字段 | 要接在哪 | 只有它接上时的后果 |
|---|---|---|
| `fs.read` / `fs.write` | 能力过滤（`host/scope.rs`）+ 路径前缀检查 | 只过滤工具名不安全：`vdfs_list` / `vdfs_tree` / `shell` 仍能绕过；要真隔离得包一层**作用域 provider** |
| `network.domains` | `web` 族出网域检查 | `http_request` 与 MCP 自带的 HTTP 不经过同一个出口 |
| `limits.max_tools` | 工具注册处截断 | 截断顺序未定义（注册是并集），「截掉哪一个」没有判据 |
| `limits.max_prompt_bytes` | 提示词拼接处截断 | 截断会**静默改变人格与指令**；必须先有「截断点与告知模型」的裁决 |

这不是「实现难」，而是**部分执行比不执行更坏**：包作者看到两个字段生效，会合理地假设
另外两个也生效，而系统实际只执行了一半——那正是本仓最要拦的「看起来像安全边界的假边界」。
四个字段要么一起接，要么都留作声明。

## 补齐的前提（四条，缺一不接）

1. **作用域 provider**：`fs` 两字段的真执行点在 VDFS 视图层（不是工具名），且
   `shell` / `vdfs_tree` 等派生读路径必须走同一层，判据是「同一路径的两种取得方式给同一答案」；
2. **出网单口**：所有出网（web / mcp / hook http）经同一个 host 检查点，判据是
   「新增一种出网方式不需要回来改第二处」；
3. **截断裁决**：`max_prompt_bytes` 超出时截断还是拒绝、截断哪一段、是否告知模型，
   三选一先成文（现在没有）；
4. **默认方向**：`fs` / `network` 空列表是「不限制」还是「全拒」——存量 Agent 包大多
   没有 manifest 权限段，直接取全拒会让它们一夜之间失去全部能力；这条必须有迁移方案。

## 现状下真正的边界

- **身份 / 能力**：授权表 `authz::ROWS` 未登记即拒（[ADR-099](099.md "ADR-099")）；
- **工具风险**：审批闸按工具自声明的风险与参数分级，缺省阈值 `Medium`
  （[ADR-068](068.md "ADR-068")）；
- **执行偏好**：`local/policy` 是用户自己的策略（[ADR-101](101.md "ADR-101")）。

三条都不读 `declared_permissions`——这不是遗漏，是分层：Agent 包的声明管「包想做什么」，
宿主的三道闸管「实际允许做什么」。

## 判据

- `manifest.test.rs` 钉住「线格式仍是 `permissions`、Rust 侧叫 `declared_permissions`」——
  改名不得变成线格式破坏；
- 机制强制等级清单（[RE-010](../006-ref/010-机制强制等级清单.md "RE-010-机制强制等级清单")）
  把这一条记为 ③ 并挂本条 ADR 作为期限。补齐四前提后，那一行改成 ② 并删豁免；
- 规范 §5.3 / §11-4 的措辞与代码注释不得再出现「宿主按 permissions 约束」这类承诺。
