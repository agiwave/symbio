## 决策

**触发**：批次 6b-②「端口成形」施工前冻结的候选面（`TurnHost` ≈25 法 + 会话句柄端口 ≈16 法，
CS-001 预估 18/56/18 → 20/~97/18、两条 `core-shape-allow` 挂 ADR-082）是**自下而上**从实现触点
凑出来的契约面。按 [PL-014 §0](../004-plan/014-单环一表收敛.md "PL-014-单环一表收敛") 复核——
目标形状与 §6 判据是裁决，施工口径不得反向改判据——该面在架构层**不成立**。本记录从 PL-014
出发做完整再推导：机制缺陷是什么（§2）、为什么必须调整而不是修小（§3）、跨层怎么系统规划（§4）、
施工路径怎么重排（§5）、完备性怎么论证（§6）。结论：**废除** [ADR-082](082.md "ADR-082")
裁决二「服务 = 两个 core trait」及其订正裁决第 1（trait 半）/2/3/5 条，补立切片前置 **P5
「运行态归源」**；判据不降、方向扳正，目标形状一步不减。

### §1 标尺：体系顶上的裁决说什么（推导前提）

1. **一源**（PL-014 §2）：`State` 是 Store 的投影，**不允许第二份状态表示**——治双写漂移。
2. **判据 2**（PL-014 §6）：core 收集口收敛是**达成线**——16+2+2 方法四族收敛为 1 个 Registry
   trait 3 方法；trait 数 20 → ≤19，实测 **18 已达成**（T-165 4e/4f）。
3. **判据 3**（PL-014 §6）：core 三格（`pub trait` / `fn` / 默认体）**只降不升**；CS-001 棘轮，
   收窄不需批准，变宽需要论证。
4. **终点坐标**（PL-014 §2.1）：一函数 · 一日志 · 一端口；in-flight 集合本就是事实（派发格 /
   租约格）；「注册即事实」收尾之后 `Registry` trait 消失，core 形状**再降一格**。
5. **P3 原文**（[ADR-075](075.md "ADR-075") 裁决前置）：跨片调用「经**能力行或路由臂**拿到，
   而不是同结构体的方法调用」；PL-014 §5 步 6 转述为「走表或端口」——先例口径是心跳片
   （[ADR-076](076.md "ADR-076")）**八个宿主触点全走地址面清零，一个新 trait 都没立**。
6. **§0 三问**：偏离由三件事判——①仍属哪个迁移步；②§6 判据与门禁是否仍全绿；③有没有留记录。

### §2 机制缺陷推导：切片边界为什么必然把双写面镜像上墙

候选面 41 个方法按用途分组，每组都指向同一个病根（逐方法归宿的覆盖表见 §6.1）：

- **A 组 · 既有通货的重复包装（≈10 法）**：`apply_frame` / `transcript_writer` / `finish_notice` /
  `emit_transcript_rewritten` / `clear_transcript` / abort 登记注销族。core 已有世界端口词汇
  （`ExecEventSink` / `ExecTranscriptWriter` / `ExecAbortSignal`），转写域的发布出口也已跨墙——
  这一组是给**已存在的端口**再套一层第二端口。
- **B 组 · 宿主双写状态的镜像（≈13 法）**：`mark_working` / `announce_working` / `is_working` /
  `is_superseded` / `reset_working` / `finish_turn` / `set_warning` / `converge_inflight` /
  `persist_failure` / `clear_working_and_abort` 等。每一个都对应 `ActiveSessionState` 的一格字段
  （`is_working` / `last_outcome` / `last_error` / `last_warning`）或一次会话记录的读-改-写。
  **这就是缺陷本体**：PL-014 的「一源」在会话域只落了**轮内容**那半（turn 事实已入网格），
  **轮生命周期与运行态**那半仍是内存表示 + 广播双写。ADR-082 订正把 `SessionStateChange` 类型
  改为 `&'static str` 传值——类型没过关，**状态本身还是逐字段变成了端口方法**：
  `ActiveSessionState` 有几格双写，端口就有几法。端口臃肿不是设计失误，是缺陷在切片边界上的
  必然投影。
- **C 组 · 留守层自身职责的外化（≈18 法）**：句柄端口十六法 + `open_session` 三臂 /
  `ensure_auto_title` / `take_supplement_batch` / `turn_settings`。这些是会话引擎的写路径与
  多步编排，ADR-081 裁决一第 4 条刚把它们裁定成**留守的单入口**，端口案又把它们翻到墙的另一面
  ——留守义务被翻成对外契约义务。

**缺陷的陈述**：会话引擎的跨插件通货是**双轨**的——事实轨（WAL 事件 + 投影）之外，还镜像着
一份未归源的生命周期双写面和一整张引擎方法表。在这个缺陷上切插件，端口面必然 ≈40 法、必然
要进 core（E-009 插件互不可见）、必然破 §1 的判据 2 与判据 3。**把端口修小不解决缺陷**：
双写面还在原地，小端口接不住它，只会逼出「半个端口 + 半份旁路豁免」的复发形状（豁免名册正是
这个形状的前身）。仓内「架构模块臃肿」的成因（T-165 动机清单：一个机制实例化四族 trait、
16+2+2 方法收集口）正是这种把实现触点端口化、再钉进机制层的积累的产物。

### §3 为什么必须废除而不是修小（§0 三问对施工方案的判定）

把 6b-② 现案按 §1.6 三问判：

- **① 属哪个迁移步**：步 6 切片——目标不变，过；
- **② 判据是否仍全绿**：**红**。trait 数 18 → 20：回到判据 2 收敛前的起点数字（原文达成线
  ≤19），比「未收敛」更糟的是它发生在收敛**之后**——已达成资产被回吐；方法成员 56 → ~97：
  判据 3「只降不升」方向性违背。`core-shape-allow` 行是**棘轮的豁免机制**，不是**改写判据的
  通道**——用它给一个判据方向性的方案放行，等于用门禁的口子掩护门禁要防的事；
- **③ 记录**：本裁决即记录。

② 红 ⇒ 构成偏离 ⇒ 按 §0「不许拿『方案就是这么写的』掩护走不通的形状」往回扳。裁决文本还
自证了矛盾：ADR-082 同批订正刚立下「跨插件契约**只走 WAL 事件轨**」的统一通货判据，紧接着
裁决二又立两个非事件轨的 RPC 端口——**统一通货判据与端口案是双通货的两半**，同墙并存必有一半
是假的。废止的是端口，保全的是通货。

**废除清单**（点名到位）：

| 对象 | 处置 |
|---|---|
| ADR-082 裁决二「服务 = 两个 core trait（`TurnHost` + 句柄端口）」 | **废除**；触发臂（地址面）不动 |
| ADR-082 订正裁决第 1 条的 trait 半（「进 core 只有两 trait」） | **废除**；纯值记录半**成立** |
| 订正第 2 条（句柄四语义写法）/ 第 3 条（广播口三法） | **废除**（裁决对象是端口面，面废 ⇒ 条废）；其论证（owner 判定由语义承担、类型不过墙）**并入 P5 约束** |
| 订正第 4 条（纯值记录入既有 facts、会话记录不过墙、`worker_progress` 整链留守、`PathBuf` 不交磁盘词汇） | **成立**，且成为 §4 闭族的成员 |
| 订正第 5 条 + 裁决五（`io.rs` 豁免经 `TurnHost` ephemeral 臂兑现） | **废除兑现方式，豁免本体随 P5 就地废除**（契约「缺句柄降级内存会话不阻断对话」随 ephemeral 编排留留守） |
| 裁决一 / 三 / 四 / 六（独立插件形状、九组词表归属、`Convergence` 归位、守卫三断言） | **成立不动** |
| 「统一通货（同批第二判据）」段 | **成立并升级**：从施工口径升为本裁决 §4 闭族的机制依据 |

**这条调整到底要不要做**也一并裁决：目标形状（步 6 切出可卸载的 `loop`、§2.1 注册即事实后
core 再降一格）不减分毫；废端口不是放弃切片，而是把切片踩回判据上——41 法端口若落地，
§2.1 的「core 再降一格」方向被它永久反转成机制层的第二通货。**该废就废。**

### §4 系统规划：三层各自拿什么形状

- **core（机制域）**：本裁决**三格 18/56/18 不动、新增 trait 0**。跨插件通货**闭族**（穷举即
  白名单，族外无通货）：
  1. **事实轨**：`EventWalStore` / `WalStore` / `Store` / `Seq` / 信封 + 具名投影
     （`transcript` / `turnstate` / 后续具名投影）——会话引擎的唯一状态通货（统一通货判据的
     机制化）；
  2. **世界端口**：`ExecEventSink` / `ExecTranscriptWriter` / `ExecAbortSignal` / `ExecEnv`；
  3. **地址面**：VDFS write / action / watch（触发与入队的通货，ADR-076 心跳先例）；
  4. **纯值记录与词汇**：`facts.rs` 一族（`ReportDraft` / `WorkerProgress` / `DrainedSupplement` /
     `TurnSettings` / `OUTCOME_*` 等）——**数据搬家不是机制加宽**，6b-① 先例。
  进闭族唯一门票：**「它代表哪一条事实，或哪个方向的世界端口」**；答不出即族外。
  **新纪律（本裁决的机制沉淀）**：凡请求 CS-001 变宽 allow 行的 ADR，必须先按 PL-014 §6
  判据方向完成一次自上而下推导——判据为裁决，不为批次让路。
- **session（存储 + 生命周期，留守层）**：拿 **P5「运行态归源」**批次——轮生命周期与运行态
  落事实轨（§5.1），`ActiveSessionState` 降格为**投影缓存 + 进程局部在途集**；`Convergence`
  三臂工厂、`worker_progress` 编排、`persist_failure` / `converge_inflight` 收口**留守不跨墙**。
- **loop（驱动器片）**：派发数据 = **一份 `TurnSpec` 纯值包**（会话 id / 标量配置快照 /
  `PathBuf` / principal / 预算档 / 生成元值）+ 闭族 1/2 的对象交付，跨墙后只准用闭族通货。
  卸载形判据（ADR-082 裁决六）不减反强：结局成事实后，停用 ⇒ 在飞轮可对账。

### §5 施工路径重排（§0 权限内的路径修正，随批写入 PL-014 §5 与 T-167）

1. **6b-② 的内容从「端口成形」改为 P5「运行态归源」**：
   - working / 结局 / 告警 = turn 事实格的投影值——开轮格与收轮格已在网格，`runtime_of` 的三处
     口径（`list` / `stat` / 变更发射）改读投影，内存字段退为缓存（单写者 = 投影订阅）；
   - `persist_failure` / `converge_inflight` 收敛为「失败是事实」（PL-014 §3 规则 e 的宿主半身），
     前端 Error 条 / idle 广播是投影反应，不是被端口调用的服务；
   - `wait_state_superseded` / 看门狗 / 忙碌守卫属**进程局部活性**，与 §2.1 的 in-flight 集合同判
     （本就是事实或端口态），留守或随派发包以生成元值承载——逐口施工基线在 P5 读数时定；
   - **验收判据**：运行态三点径与现网逐格一致；行为清单（§6 判据 6：审批 / `ask_user` / 心跳 /
     流式中断 / 并发排队 t15/t32/t34）逐项不变；测试基线不降。
2. **6b-① 已落地部分不受影响**（纯词汇/数据上移，与判据零冲突）。
3. **`io.rs` 豁免就地废除**：P5 后句柄类型不过墙，`SESSION_HANDLE` 的 ctx 值改为闭族对象；
   降级内存会话的契约随 ephemeral 构造留留守——豁免名册归零由「面消失」兑现，不由「换载体」兑现。
4. **6b-③ 成片搬家**前置 = P5 验收；判据从「grep `use super::super::{chat_session, active, store}`
   归零」改为「驱动器文件 import 根 ⊆ §4 闭族（枚举白名单，进 ④ 守卫）」。`Convergence` 归位、
   两入口地址面、恢复臂再派发照 ADR-082 裁决一/二/四不动。
5. **6b-④ 守卫**：裁决六三断言不动，新增两条——CS-001 三格 ≤ 18/56/18（无需任何 allow 行）；
   闭族 import 白名单核对。

### §6 完备性论证

**6.1 候选面 41 法穷尽覆盖表**（归宿五类：闭=闭族既有词汇；值=TurnSpec 纯值；源=P5 投影读；
留=留守不跨墙；死=双写镜像随 P5 自然死亡。无一悬空）：

| 候选方法 | 归宿 | 候选方法 | 归宿 |
|---|---|---|---|
| `apply_frame` / `transcript_writer` / `finish_notice` / `emit_transcript_rewritten` / `clear_transcript` | 闭（sink / `ExecTranscriptWriter`） | `mark_working` / `announce_working` / `reset_working` / `finish_turn` / `set_warning` | 源 |
| abort 登记 / 注销 / 置位族（`register` / `clear` / `try_clear` / `abort_signal` / `clear_working_and_abort`） | 闭（`ExecAbortSignal` 原语）+ 留（登记册在留守） | `is_working` / `is_superseded` | 源 + 留（活性） |
| `open_session`（三臂含 ephemeral） | 留（`Convergence` 工厂即为此存在） | `persist_failure` / `converge_inflight` | 源（失败是事实）+ 留（收口） |
| `session_metadata` / `turn_settings` | 值（装配期一次交齐） | `ensure_auto_title` / `notify_change` | 留（落库事实的反应） |
| `take_supplement_batch` / `sub_session_progress` | 源（inbox 与进展本就是 WAL / 名册投影——`progress_from_wal` 已自证） | 句柄 `get_messages` / `get_context_messages` / `persisted` / `replace_all` | 源（具名投影 / 快照事实，见统一通货判据③） |
| 句柄 `add_by_runner` / `add_here` / `edit_nodes` / `remove_nodes` / publish 两式 | 闭+源（驱动器写侧 = 事实 append + 转写发布；`MessageChange` / `Carrier` 留守不变） | 句柄 `session_id` / `session_dir` / `context_window` / skill 两开关 / `delegating_principal` | 值（TurnSpec 字段） |

**6.2 判据对照（§6 全量六条）**：判据 1（加能力 = 1 行注册）不受影响；判据 2 traits 18 不动
（对照：端口案 20）；判据 3 无变宽（对照：+41 方法）；判据 4 机制键 +0；判据 5 被 P5 **推进**
（运行态成为网格投影 = 「State 输入必须是 Store 投影」在生命周期段的兑现，decide 读侧归一）；
判据 6 行为清单列为 P5 验收。审计口径：E-009 过（跨墙只见 core）；C-001/C-002/C-003 无新出口
（对照：端口案需 WAIVERS + 命名空间导出两案）；测试基线 1753 只升。

**6.3 场景抽验**（PL-014 §7 中最难的四格）：SC-004 并发排队——忙碌守卫留守 + 地址面同步回绝
（裁决二既有形状），不变；SC-005 断点恢复——结局成事实后重建面即知上次终态，白拿改善；
SC-007 插话——2f 抽批改读 inbox 投影，入队仍走地址面，时序判据（S-011 行序 / 时钟归零）随
留守单入口不动；SC-017 心跳——已落地先例（ADR-076 地址面）正是本闭族的第 3 类通货，自洽。

**6.4 对已提交两笔订正的复核**：4807faa9（订正五条）——如 §3 废除清单逐条判定，其**论证**
（类型不过墙、记录不是通货、多步链留守）全部被 P5 吸收为约束；7e9bf113（统一通货第二判据）——
**全部成立**，它已是自上而下的一次推导，本裁决把它从施工口径升为机制裁决；端口案恰是对它
的违背（RPC 面 = 第二通货），本次即按它把自己另一半纠正掉。

### 否决的替代方案

- **6b-② 原案（两肥端口进 core + CS allow 行）**：§2/§3 全量否决。
- **瘦身端口（3–5 小接口）**：否——双写面不因口小而消失，逼出旁路与豁免复发（§2 末段）。
- **loop 直用 session 具体类型**：否——违 E-009，切片即失去卸载判据的意义。
- **`EventWalStore` 下沉 session**：否——沿用 7e9bf113 已立论证（core 投影机制消费其 snapshot；
  下沉逼每个事实读方经留守开专属 getter，「契约到处都是」恰由此起）。
- **取消 6b / 不切 `loop`**：否——步 6 目标形状与卸载判据是裁决；缺陷在路径不在目标，
  P5 就是这一步的正确落点。

## 后果

- ADR-082 的 `impl` 口径不变（残余逐条指得出归属），裁决二与订正节加指向本裁决的复核标注；
  本裁决取代其中端口相关条文（§3 清单）。
- PL-014 §5 步 6 行按 §0 权限记路径修正（P5 前置补立；目标形状与判据一字不动）——随批写入。
- T-167 台账：6b-② 施工中止条目之后追加再推导条目；任务「端口成形」更名为 P5 运行态归源。
- **core 三格 18/56/18 不动、机制键 0、CS-001 基线不动、allow 行 0**；下一施工批次是 P5，
  不是端口。
- 若未来 P5 读数证明某一口确实在闭族与投影上都无处安放（残余风险），处理方式是**回到本裁决
  补一条点名论证**（它代表哪条事实），不是重启端口面——防止本扇门的口子从批内再打开。
