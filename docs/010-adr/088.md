## 决策

**环认识的指令集必须是闭集**。臂名（`decide` / `report` / `compress` / `recall` /
`reflex`）是环与策略表之间的唯一接口，它由枚举承载，不是自由字符串。

PL-014 §3 的 `Step` 五值（`Ask` / `Act` / `Emit` / `Wait` / `Halt`）与 §4 的
`drive()` 不动点迭代**不落地**：它们的每个变体缺生产者（§2），且阶段之间有数据
依赖（§3）。写出来就是四个永不构造的变体加一层假抽象。

### §1 闭集：`Capsule` 从自由字符串收成枚举

```rust
// 之前：任何字符串都能当臂名，拼错 / 重名 / 环里没这条臂，全都不报错
pub(crate) struct Capsule(pub(crate) &'static str);

// 之后：环认识的指令集是闭的；臂名只有一个来源
pub(crate) enum Capsule { Decide, Report, Compress, Recall, Reflex }
impl Capsule { pub(crate) fn name(self) -> &'static str { … } }
```

它换来的不是「更短的代码」，是三种失效从静默变成编译错误或单测红：

| 失效 | 自由字符串 | 闭集枚举 |
|---|---|---|
| 新臂名拼错（`"dceide"`） | 行永远不命中，某一步**悄悄不发生** | 编译错误 |
| 两条臂同名（`"report"` 写两遍） | 日志分不清、冲突报错指认不出 | 编译错误（变体不能重名） |
| 新臂忘了在环里处理 | 运行时走不到（字符串没人 match） | 加变体后每个 `match` 立刻不穷尽 |

`name()` 是臂名的**唯一字面量落点**：日志（`[Loop] 轮首命中策略行 policy.classify →
decide`）、冲突报错、测试断言都从它取，表与环不可能各持一份。

**可执行判据**（`plugins/loop/loop_registry.test.rs`）：

- `lower_prio_wins_regardless_of_insertion_order`——两行**同格竞争**，先注册 `prio 30`、
  后注册 `prio 10`，胜者必须是 10。这条把「按 `prio` 排序」与「按插入顺序扫描」两种
  实现分开。`prio` 本来就在裁决里（`put` 按 `(prio, name)` 插入有序位置、`decide`
  顺序扫描取先命中者），缺的是**竞争用例**：内建表没有两行会在同一格同时命中。
- `a_new_policy_reusing_an_existing_arm_is_pure_registration`——新策略复用已有臂时，
  「一个函数 + 一行注册，环不改」是可执行的：表在原来不认领的格上认领成功。
- `capsule_names_are_unique_and_stable`——臂名去重 + 首名固定（它是日志词）。

### §2 `Step` 五值：每个变体都要有生产者

落地的判据不是「论证过承重」，而是**每个变体有没有生产者**：

| 变体 | 生产者 | 结论 |
|---|---|---|
| `Act(Capsule)` | 有（5 条策略行） | 就是今天的 `Capsule`，已闭集化 |
| `Ask(Prompt)` | 无——`ask_user` 在环里是**顺序调用**，不是表能派发的决策 | 死变体 |
| `Emit(Fact)` | 无——事实落盘由各阶段内联写，没有「先决定要发事实、再发」的两段 | 死变体 |
| `Wait(WaitSet)` | 无——「等工具齐」已由 ADR-073 取消 | 不存在 |
| `Halt(Reason)` | 无——退出条件是 `gate_turn` 的硬闸（步骤 2），刻意为「唯一判定点」 | 搬进表 = 把安全闸变成可注册项 |

四个 `dead_code` 变体等于用「架构看起来完整」换掉编译器的一次真话。**`Step` 这个名字
留给第 2 个变体真有生产者那天**：届时 `Capsule` 成为 `Step::Act` 的载荷，`name()` 与
各分派点的 `match` 会强制每一处显式处理新变体。

### §3 `drive()`：阶段之间有数据依赖，不动点不成立

`loop { project → decide → execute }` 的前提是**阶段可交换**，而这里不是：

- 步骤 2b（判决）的产出 `Verdict` **决定**步骤 4 走哪条路（答话 / 派活 / 升级）；
- 步骤 6/7（结算 / 封根）必须在本轮最后一个工具批次之后，且**只做一次**；
- 压缩（步骤 3 ①）改写上下文，必须在「取请求视图」之后、「发模型」之前。

塞进 `while let Some(step) = decide(&state)` 需要两样不存在的东西：①`LoopState` 长出
「本轮已做过哪些步」的簿记（而 PL-014 §2 的硬规则是 `State` 必须是既有投影，不许有
环的私有簿记）；②每个阶段的「做完」标志，它会在 `State` 里变成第二份真相。
收益（去掉 5 次 `decide` 调用）远小于引入的状态复杂度。

保留的是可检验的一半：`Registry::decide` 的签名（`&LoopState → Option<Hit>`）不变，
表仍只回答「这一格归谁」；直线代码按**语义顺序**调用它，顺序写在代码里、不进数据。

### §4 不做的四件事

| 不做 | 理由 |
|---|---|
| `Step` 五值 | §2 的生产者表 |
| `drive()` 不动点 | §3 的数据依赖 |
| 把 `LoopState` 的五个决策点构造器合并成一个 `project()` | 合并的收益依附于 `drive`（单一投影点）；直线代码里五个构造器各填自己那几格，恰恰保证「一格不会因为另一格的字段默认成真而误命中」。合并只会造出一个「全字段有默认值」的巨型构造器，把误命中从编译期问题变成运行期问题 |
| 让 `Capsule` 携带执行闭包 | `Step` 一旦携带闭包就不可序列化，PL-014 的三条承重判据（L1 回放、Step 可 diff、整轮决策日志）同时失效——拿扩展方便换掉整个可审计性。**`Step` 必须是数据，不是行为** |

| # | 判据 | 命令 | 现状 |

| 1 | 臂名不是自由字符串 | `rg 'struct Capsule'` 无命中 | ✓ |

## 对 §3 的修订（[ADR-107](107.md "ADR-107")）

§3「`drive()` 不成立」的**适用面收窄**为「一次性阶段的事实缺席时，外环 drive 不成立」。
收窄的理由是 ADR-107 给出的那条结构事实：`policy.classify` / `policy.recall` /
`policy.compress` 的谓词在一轮内没有「转假」的来源，drive 只会反复命中同一个 no-op。
事实就绪后（阶段输出与「本步已做」落为事实）须重审 §3 的数据依赖论证；§1、§2、§4
四条与本节的判据 1–5 均不变。
