## 决策

**背景（为什么补这一条）**：ADR-048 把出厂档位翻到 `full` 后，**写侧**已经换成
WAL 原生记账（`v2_exec` 落格、`session/stats` 读格），但**读侧**大面积仍在读
`SessionStore`：

| 读者 | 读什么 | 位置 |
|---|---|---|
| `transcript_of` | `session.messages` ∪ 在途缓冲 | `plugin/vdfs_provider.rs:911` |
| `session_content` | 会话存储的消息副本 | `plugin/nodes.rs:709` |
| `save_session` | **整份** `atomic_write` | `store/mod.rs:195` |
| `persist_messages` | 只写尾部增量，但仍写进 `messages.json` | `chat_loop/io.rs:52` |

于是同一个会话有**两份东西在记同一件事**：WAL（append-only 的事实源）与
`messages.json`（整份覆盖的镜像）。今天它不出错，是因为 `full` 档的写侧保证两者
内容收敛——但这是**巧合层面的正确**，不是构造层面的：两边的写方不同、时机不同、
失败路径不同（WAL 追加失败与 `atomic_write` 失败各自怎么走），而**没有任何判据
在对账它们**。本仓为此已经付过一次学费：八个静默缺口全部源于「事实网格不是模型
看到的完整记录」这一类分叉（ADR-048 补记）。

轨 S（S1–T-056）就是把这个分叉消掉。**动事实源之前先立本条**：它定目标态、
定迁移顺序、定回退的数据语义。

**决策**：

1. **目标态**：`<会话目录>/v2-events.wal` 是会话消息的**唯一事实源**；
   `messages.json` 降为**可重建的缓存**（删掉后会话仍能开）。
2. **`SessionStore` 不删接口，换职责**：它继续承担「会话元数据 / 摘要 / 索引」，
   但**消息正文不再由它写**（呈现态——`delta`、在途 `seq`、等待态——一律不入格）。
3. **迁移顺序固定**（S1 → S2 → T-051 → T-052 → T-056），每步只动**一个汇聚点**，且前一步的判据绿了才动下一步。
4. **回退语义写明**：T-056 之后回退**不再无损**（见下节）。

**理由**：

1. **一个事实只能有一个 owner。** WAL 已经是写入时的那一份（`full` 档的轮次事实
   只由 v2 运行器落格，ADR-048 理由 3）。留着 `messages.json` 当第二个写方，
   就意味着「同一句话有两个地方能改」——而这正是本仓纪律反复要消的形态，
   也是八个缺口能同时活着的结构性原因。
2. **整份覆盖写不可扩展，且它的失败形态是丢历史。** `save_session` 是
   load-modify-write 全程临界区（`store/mod.rs:119` 的自述），并发保存靠那把锁
   串行化。消息量上去之后，每次轮末都重写整份文件；而 WAL 是追加。
3. **缓存可重建 ⇒ 真源可换。** 若 `messages.json` 删不掉，说明它还在当事实源；
   判据「删掉后会话仍能开」（S5）因此不是性能优化，是**真源是否已换的证明**。
4. **呈现态不入格。** `delta` / 在途 `seq` / 等待态是**传输与呈现**的形状，
   不是「发生过什么」。它们进格会让网格承载一次渲染的快照，而快照会过期
   （流式期间的半截状态），那是把易变物写进不可变日志。

**被否决的方案**：

- **让 `messages.json` 继续当读侧真源、WAL 只做审计**：否决。那就是把 v2 按在
  旁路位置——与 ADR-048 否决「保留 `bridge` 档作回退旋钮」是同一条理由：
  **不被真实消费的那一份永远得不到验证**，而缺口会在它身上一直活着。
- **一次性切换（不分六步）**：否决。读侧切流的中间态必须可观测：S1 的并读对账
  就是为这个存在的。一次切完，中间出了偏差没有地方能看见。
- **双写两边都当真源（互相校验）**：否决。双写的正确性依赖「两边永远一致」，
  而这需要判据；没有判据的双写是两份会漂移的真源（且漂移静默）。
- **把 `messages.json` 的读改写成「每次从 WAL 重放」而不动写侧**：否决。
  那是给一个已被取代的形状续命，且重放成本落在每一次读上。

**迁移与回退的数据语义**（[13 §0 纪律 4](../archive/13-质量改进总纲.md) 要求的一节）：

| 阶段 | 迁什么 | 回退会丢什么 |
|---|---|---|
| S1（并读对账） | 只读：读路径同时问两源，不一致只记警告 + 落一条事实 | **零**（零行为变更） |
| S2（读侧切流：子会话进展） | 子会话进展读切 WAL，旧读法留作对账余路 | **零**（还原一个调用点） |
| T-051（废 v1 档，[ADR-051](051.md)） | `V2Mode` 旋钮、v1 分支与转写桥移除（只删退役档） | **零**（纯删代码，从 git 取回即可） |
| T-056（消息真源切换） | 收束落库以 WAL 为主，`messages.json` 停存消息正文；组 prompt 读与前端列表读一并切到转写投影 | **不再无损**：回退后消息要靠 WAL 重建镜像；未重建的会话看到的是 WAL 的那一份（内容是同一批事实的投影，但**呈现细节可能不同**——如 `seq` 分配、节点父子关系）。**这一步之前必须已经能证明「真实用户数据已迁」**（判据 = 删掉 `messages.json` 后会话仍能开且历史完整） |

**关键判界**：S1–T-051 是**零风险可逆**的（旧路完整保留或纯删退役档，判据是「一致时输出逐字不变」）；
**T-056 是分水岭**——它把回退从「还原一个调用点」变成「重建一份数据」。因此 T-056 之前
必须先有 S0 要求的那个证明，且 T-056 自身要带「删掉 `messages.json` 后会话仍能开」
这条判据。在此之前不动写侧。

**后果与不变量**：

- **不变量**：WAL 仍是 append-only（不因换真源改变写入语义）；同轮不两份记账
  （ADR-048 不变）；`session/stats` 的读数列与口径不变（轨 S 不动投影）。
- **影响面**：S1–T-051 只改读路径或删退役档，对用户**零可见变化**（判据就是「输出逐字不变」）；
  T-056 起用户可见的是「重启后历史仍在」这件事从「靠缓存」变成「靠真源」。
- **本条不实施任何代码**。S1–T-056 各自单独立批、独立可回退；每批的出口判据在
  [13 §轨 S](../archive/13-质量改进总纲.md) 表内。

**与 ADR-048 的边界**：ADR-048 定「写侧走 v2 原生记账、`bridge` 退役」；
本条定「读侧也切过去、`messages.json` 降为缓存」。两者都已落地，本条的判据现在住在
三处单测里——`store/tests.rs` 的 `save_writes_metadata_only`（存盘只写元数据）、
`chat_session.test.rs` 的单真源回放（`messages.json` 不存在时从 WAL 重建）、
`turn_runner.test.rs` 的双投影对账（prompt 装配不吃 `messages.json`，故它不是真源）。
