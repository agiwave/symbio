## 决策

**背景**：[PL-014 §5](../004-plan/014-单环一表收敛.md "PL-014-单环一表收敛") 步骤 5 要删 v1 外壳的
`close_turn` 死分支。那条分支不是孤立的：它是 `context_compact`（模型主动调用的
压缩工具）的**唯一执行处**，而这条链的三个环节在 v2 现实下已经各自断开——

- **工具从未被注入**：v2 执行路径不把 `context_compact` 放进工具清单（事实表 §2 已登记
  「不暴露」），模型看不到它，因此 `TurnOutput.tool_calls` 里永不含它；
  v1 外壳的分发分支生产与测试都不可达。
- **提醒指向空处**：55% 水位提醒（nudge，`policy.nudge`）的**全部存在理由**是引导模型在
  安全时机调用那个工具（[PL-014 §5](../004-plan/014-单环一表收敛.md "PL-014-单环一表收敛") 步骤 3 落地时它已经是「三条条件里第一条恒假的一行」）。
  工具不存在，提醒就是一条面向空气的指令——它自己就是缺陷。
- **开关是死配置**：`enable_compact_tool`（`SessionConfig` + `model_chat::Request` wire 字段 +
  设置面板 toggle）只服务上面两者；前端与 tauri 侧没有任何镜像读它。

**裁决**：三者**同时退役**，压缩收敛为**唯一入口** `auto_compress_process`：

- 70% 自动压缩（`policy.compress` → `prepare_turn_inputs`）保留，它是真实生效的那条路径；
- 用户点「失败压缩节点重试」（`ResumeAction::RetryCompaction`）**保留**，走
  `auto_compress_process(force = true)`——判定链与自动路径同一条，只是越过迟滞；
  这是「人在环」的压缩入口，不需要模型主动调工具；
- `policy.nudge` 行、`Capsule::NUDGE`、`LoopState` 的三格（`enable_compact_tool` /
  `nudged` / `over_watermark`）、`should_emit_context_nudge`、`CONTEXT_NUDGE_THRESHOLD`、
  `build_request_view` 的 `inject_nudge` 参数、`find_turn_user_split_idx`（唯一读方是被删的
  工具切分点）、`extra_hints` / `compact_hints`（只为工具那句「用户补充」而存在）全部删除；
- `run_context_compact` 删除后，trigger 词表只剩 `threshold` / `retry` 两个值。

**否决的替代**：

- **把 `context_compact` 迁成能力行（[PL-014 §5](../004-plan/014-单环一表收敛.md "PL-014-单环一表收敛") 步骤 4 的形状）留下**：
  它要的是「拿着编排器的上下文就地改写历史」，而 v2 的分发口（`ToolDispatch`）只给工具一份
  参数与一个结果槽——把副作用塞回去要么复活 `close_turn` 那段拦截，要么给运行器开一个
  「能改写 `context.messages` 的工具」特例。两者都比删掉它贵。**真要做「模型自选时机压缩」时**，
  注册成能力行走 v2 分发（这条路径写在 `chat_loop/inputs.rs` 的注释里，不是口头承诺），
  判据是那时才出现的。
- **只删工具、留提醒**：留一条恒不引导任何东西的 User 消息进请求视图。它会改变「最后一条
  user 消息」的所有权（轮次窗口与 mock 场景匹配都靠它），而收益是零。
- **把 nudge 改造成「自动压缩的预告」**：那是新的语义设计，不在「删死代码」这一步的范围里；
  70% 触发点由 `should_start_compression` 判定，它不需要模型配合。

## 后果

- **配置面变小**：`enable_compact_tool` 从 `SessionConfig` / `model_chat::Request` / 设置面板
  三处消失。磁盘上已有的旧配置文件带这个键会被 serde 静默忽略（多余键不报错），
  不需要迁移；跨语言键集合契约（`model_chat.test.rs`）随之少一键。
- **请求视图少一段**：`build_request_view` 从 12 参降到 11 参，注入段只剩记忆 / 就绪 /
  委派三段，「视图末尾 = 用户自己说的话」由此成为可直接断言的性质
  （它不再依赖「nudge 恰好在末尾」这种约定）。
- **水位策略只剩一行**：`policy.compress`。`prio` 40 留空洞——prio 是排序键而不是名额，
  补号要用一行真实判据，不为齐整造行。
- **压缩失败的处置不变**：「压缩失败不得裁剪历史」（[ADR-018](018.md)）与连续失败计数
  （`active.rs`）都在，只是那份计数不再有「主动路径不计」的第二种口径——**只剩一条路径**。
- **「巨型单轮」少了一道轮内手段**——这是这条裁决真正付的代价：主动压缩原本号称对单轮洪峰
  最有效（阈值路径的 User 边界切分在单轮里找不到切分点）。退役后单轮膨胀的兜底只剩确定性防线
  （单条守卫 / 轮内淡化 / 窗口骨架化），语义压缩等到下一个轮边界；找不到切分点就是**本轮不压**，
  不会退化成裁历史。分层口径见 [上下文压缩设计](../../symbio/src/plugins/session/docs/014-context-compression-design.md "AR-014-context-compression-design") §3。
  ⚠️ 这条代价的**实际大小比这里写的更大**：那三道防线里只有第一条（单条守卫）真正生效，另两条
  （轮内淡化 / 窗口骨架化）所在的请求视图层**已整族退役**——退役裁决见
  [ADR-078](078.md)，理由与「不改写投影正文」的判据在那边，本 ADR 不复述。
- PL-014 §5 步骤 3 的落地清单里 `policy.nudge` 那一行作废，就地记在本文而不是改写步骤 3 的
  历史描述（「一个事实只有一个 owner」是工作区指令里的分层规则）。
