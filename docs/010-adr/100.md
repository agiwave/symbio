# ADR-100：绑定即登记——能力随会话创建而来、与会话同寿，可见域不登记

## 决策

**会话创建点把会话主体的能力行登记进运行期绑定面**（`session::commands::session_upsert`
的 create 分支 → `authz::bind_root` / `authz::bind_inheriting`），能力面按**登记过的
绑定行为有效行、未登记才回退部署表**合流判定（`authz::EffectiveMatrix`，取表口
`production_matrix` 的返回类型）。运行期装配点（`request_actor_spec`）保留同一登记的
**幂等兜底**：只在「本请求显式改写了身份」（请求级 `agent_id`）或临时会话没有创建点时
补登记，不再承担每轮登记的职责。四条口径：

1. **登记即诞生**：会话一创建就声明主体行，读侧第一轮即可判定，不依赖某一轮先跑过；
2. **能力随绑定来，委派取交集**：根会话（`Scope::Root`）未部署时继承**会话面缺省行**
   （主智能体行），已部署时原样用自己的行；委派子会话（`Scope::Child(parent)`）
   取**父行 ∩ 自己的显式声明**（即它在 `ROWS` 里的部署行），未部署时整行来自父行
   ——两个方向都不放大权威（[T-195](../009-task/195-委派权威交集批.md "T-195-委派权威交集批")）；
3. **可见域不登记**：`sees_of` / `can_see` 只认部署表——绑定不使任何主体成为矩阵成员；
4. **登记与会话同寿**：绑定行的登记者是会话 id；同一会话改写身份先撤旧行再登记新行，
   会话（及其子会话）删除时整册回收。进程级只增不减只属于「会话还活着」的那些行；
5. **静态行不被放大**：部署表本身不被改写；根主体用自己的行，委派子主体的部署行
   只作为交集的一项。绑定行（含空行）**替换**部署行走合流，不是与它取并集。

`governance::PermissionMatrix` 保持「常量表 + fail-closed 谓词」原样不动；合流住在
`authz`（「部署事实怎么看待运行期身份」是这张表的裁决，不是判定机制的裁决）。

## 背景

[ADR-099](099.md "ADR-099") 把「未登记 = 拒」立成全表唯一口径，删掉了派生分支——
对一切未登记的 `agent:<id>` 不再**静默**派生主智能体整套能力。删得对：「忘配窄行」
从此是一条会被看见的拒绝，不是一次静默超权。

但删干净之后暴露出**可用性**的真空：e2e 的根会话以 `--agent <id>` 选定身份
（t30 / t39 / t57 / t76 的形态），这些身份**不在部署表里**（`ROWS` 是部署事实，
只登记 `session/main` / `worker` / `planner` / `verifier` 等固定角色），于是——

- 收束闸（`turn_runner::closure_granted`，读 `ActorSpec` 自带能力集）拒 ⇒ 收束落不了格；
- 记忆不编码 ⇒ 下一轮召回段为空（t76 的「C 的请求应有召回段」、t57 的召回段断言落空）；
- 工具闸拒（t39 的 `vdfs_read`：`Refused: 未持外部执行能力（produce.artifact）`）。

这四个失败**同一个根因**：身份会话缺一行，而缺的这行**本应由「会话选定了这个 agent」
这件事**给出来。

## 为什么不是「派生回滚」

回到 `matrix_for` 派生是一种**隐式**给权：没有任何一处登记动作，任何 `agent:<id>`
都自动拿到会话面整套能力。ADR-099 否决的正是这个——「少一行」不再是一条判据，
因为永远会有一行凭空长出来。

本条形态相反：给权仍然需要一次**可见的登记动作**，这次动作发生在**会话创建点**
（`session_upsert` 写出会话之后）——它天然知道两件派生面不知道的事：**这个会话的
主体是谁**（`metadata.agent_id`）、**它挂在哪个父下**（`metadata.parent_session_id`
→ 父主体）。运行期装配点不再每轮重新登记，只保留幂等兜底（请求级身份改写 /
无创建点的临时会话），因此判据链更短：**登记跟着会话走，判定也跟着会话走**。

## 边界（逐条有判据，见 `authz.test.rs`）

| 边界 | 判据用例 |
|---|---|
| 能力随绑定来 | `a_bound_subject_takes_the_source_row`：绑定前谓词全假，绑定后收束闸放行 |
| 静态行不被放大 | `binding_never_widens_a_deployed_row`：绑 `worker` 后其行仍是单能力 |
| 可见域不登记 | `binding_grants_no_visibility_scope`：绑定主体 `sees_of` 仍为 `None`、读不到他人 `shared` |
| 淘汰面只认部署表 | `the_elimination_face_ignores_bindings`：`deployed_can_write_name` 看不见绑定 |
| 委派两侧都在册 | `delegated_binding_registers_both_sides`：`from` 无行时先给它登记缺省，子继承父行 |
| 委派取交集 | `a_delegated_child_gets_the_intersection_of_parent_and_declaration`：父窄子宽 ⇒ 子只保留交集；`an_empty_intersection_registers_a_denying_row`：空交集登记为空行，不退回部署行 |
| 根不是委派 | `a_deployed_root_keeps_its_own_row`：verifier / arbiter 的根行不被会话面缺省夹窄 |
| 创建即登记 | `creating_a_session_registers_its_principal_row_and_deleting_it_reclaims_it`（session 插件集成用例）：创建后第一轮之前既有行 |
| 登记与会话同寿 | `a_binding_is_reclaimed_when_its_session_ends`；`bindings_of_two_live_sessions_outlive_each_other`：回收较新的行不误删较旧活会话的行 |
| 身份改写不叠行 | `rebinding_a_session_replaces_its_previous_identity_row`：同一登记者换主体只留新行；`rewriting_the_agent_identity_replaces_the_session_binding`（session 插件集成用例）：metadata 改写 `agent_id` 后旧行即撤、新行即时可用 |
| 子会话随父回收 | `a_delegated_child_is_registered_at_creation_and_reclaimed_with_its_parent`（session 插件集成用例）：删父会话连同子会话的登记一并回收 |

### 第三条为什么必须单列（可见域与能力分家）

`governance::PermissionMatrix::can_see(Shared)` 的判据是 `sees_of(viewer).is_some()`
——即「是矩阵成员」。若把可见域也随绑定登记，任何绑定 agent 都会变成矩阵成员、
**读到他人 `shared`**（t76「ghost 读不到他人 shared」的反判据当场破）。所以：
**能力可以随绑定来，「看见别人的 shared」只能来自部署登记**。

### 第五条为什么必须单列（委派上限两侧都在册）

`turn_runner::within_delegation_ceiling` 判**父主体也持有**对应能力。委派链上若父主体
自己不在册，子会话会因「父也不持」而收束不了——所以 `from` 无行时先给 `from` 登记
会话面缺省，两侧都在册，上限判得出来。「两侧都在册」说的是**登记事实**；子会话
能做什么由下一条的交集决定——缺了交集，两侧在册只是一本账。

### 第六条为什么必须单列（委派取交集）

「委派不放大权威」必须落在**能力集合**上，而不只是「谁在册」：

- **子已部署**（`ROWS` 里有显式声明）：有效行 = 父行 ∩ 声明行。父窄子宽时，
  父没有的能力不会因子会话自己的宽行而生效；
- **子未部署**：没有显式声明，整行来自父行（交集退化为父行）；
- **空交集是合法结果**：登记为**空行**——「父不持 ⇒ 子也不持」是一条拒绝，
  不能把空行当成「没登记」而退回部署行；
- **根不适用交集**：根没有父行。已部署的根主体原样用自己的行，否则
  verifier / arbiter 的 `assert.verification`（主智能体刻意不持，C15）会被会话面
  缺省夹空。根与委派因此是两条入口（`bind_root` / `bind_inheriting`）。

合流面随之从「部署行 ∪ 绑定行」改为「绑定行**替换**部署行」（未登记才回退部署行）：
先取交集再取并集，会把刚夹掉的能力加回来。

## 与 ADR-099 的关系（同一条纪律的两段，不是矛盾）

- 合流面仍 fail-closed：既未部署、又未绑定 ⇒ 每个谓词为假；
- 给权仍需一次**可见动作**：部署配表，或会话创建点按会话身份登记（装配点只在身份
  被显式改写时幂等兜底）；
- **少一次登记动作 = 一条拒绝**（不再是「一条静默超权」）。

## 代价（诚实划界）

- **登记与会话同寿**：`BOUND` 仍住在进程内全局 `RwLock`，但每一行都挂在**会话 id**
  这个登记者上——会话删除（含级联删除的子会话）时整册回收，同一会话改写身份先撤旧行
  再登记新行。进程级只增不减只属于「会话还活着」的那些行，不是无限的。
  同一 agent id 被多个**并行活会话**持有时，有效行取最后登记的那一条；各条都满足
  「根 ≤ 会话面缺省行 / 子 ≤ 父行」（委派不放大权威），故不构成超权，差异只在
  同一身份在不同父下的窄化程度。
- **空绑定行是有意的拒绝**：交集为空时 `BOUND` 存 `[]`，合流面据此拒绝该主体，
  不会回退部署行。登记面因此不能把「空」与「缺席」混为一谈。
- **绑定不带可见域**：绑定主体读不到他人 `shared`——这是与能力面**有意**的不对称
  （见上第三条）。
- **登记失败 = 不登记**：锁中毒只告警跳过，未登记的主体照旧每个谓词为假（fail-closed
  的方向不因登记通道故障而松开）。
