# 真实会话有界压测——把「full 被真实负载压过」落成可执行的出口判据

## 内容

### 现场

[DE-016-工程落地与验证](../003-design/016-工程落地与验证.md "DE-016-工程落地与验证") 的 `D-058` 段把终点第 3 条记成：

> 「`full` 是出厂路径，且被真实负载压过——不是『跑过 e2e』，是『跑过真实会话』」（登记条目待立项）。

今天已有的证据停在两处：

| 已有什么 | 覆盖不到什么 |
|---|---|
| e2e t47（21 轮负载，MockLLM） | 不是真实 provider；轮数不足以逼出多次压缩与长历史 |
| `session/stats` 的读数口（`invariants` / `tiers.*` / `checkpoint` / 用量列） | 没有一轮「真实 provider + 有界预算」的运行去读它 |

所以缺口不是「没有 e2e」，而是**没有一条能回答『压过之后还成立吗』的出口判据**。

### 判定

- **真实负载 = 真实 provider + 真实多轮会话**（含工具调用与多次压缩），不是 MockLLM 的 e2e 回放；
  因此这条任务**不进默认 CI**，也不进 `pre-commit`。
- **有界 = 事先写死三个上界**：轮数、墙钟、token / 成本。任一项触顶即中止并留下读数，
  不用「跑到崩」来当压力。
- **判据只读生产出口**：`session/stats` 的 `invariants` 必须为空、`checkpoint.event_count`
  随轮数线性增长且无重复 seq、`tiers.*` 的 P99 落在 `budget_ms` 内、用量列可对账；
  不新开旁路计数器。
- **入口是 opt-in**：缺真实 provider 配置时明确拒绝启动并说明缺哪一项，不允许悄悄回退到
  MockLLM——那会把「压过真实会话」偷换成「跑过 e2e」。

### 施工顺序

1. **定入口与预算**：在 `e2e/` 或 `scripts/` 下加一条独立入口（环境变量显式开启），
   参数为 `turns` / `max_wall_ms` / `max_tokens` / `max_cost`；缺参数即拒绝运行。
2. **定场景**：固定一段多轮脚本，至少逼出一次压缩、一次工具调用与一次长历史回读；
   场景本身不依赖外网资源，只依赖真实 provider。
3. **定读数与红线**：跑完读 `session/stats`，按上一条判定逐项断言；任一红即非零退出，
   并把读数摘要写到运行日志（不入库、不带密钥）。
4. **落一次真实运行**：用真实 provider 跑一遍，记录本次预算、读数与结论；运行记录只留摘要。

### 判据

- 缺真实 provider 配置时入口 **非零退出**，错误指名缺的配置项；
- 固定预算内能跑完；`invariants` 为空；`checkpoint.event_count` 与轮数同向增长；
  `tiers.*` 的 P99 不超过对应 `budget_ms`；
- 任一红线触发时退出码非零，而不是只打日志；
- `node scripts/gate.mjs --full --ci` 绿。

### 不做什么

- 不把真实 provider 调用塞进默认 CI、`pre-commit` 或 `pre-push`；
- 不用 MockLLM 的 e2e 结果冒充「真实会话压测」；
- 不新增旁路计数器或第二份统计口径——读数只从 `session/stats` 取；
- 不把密钥、完整响应或运行记录入库；
- 不在本条里顺手做逐 crate 覆盖率 floor（那是 `D-060` 的对象）。

## 处理过程

- 2026-11-16：登记。`D-058` 把这件事记成「登记条目待立项」但没有对象；本条把对象钉成
  **一条 opt-in 的有界压测入口 + 一组只读生产出口的红线**，先回答「怎么算压过」，
  再谈具体轮数基线。
- 2026-11-16：入口落地为 `e2e/real-session-load.mjs`（不在 `e2e/cases/`，不会被默认用例
  发现；缺 provider 配置退出码 2）。已用局域网真实 OpenAI 兼容端点实跑：
  - **6 轮 / 32k 窗口**：通过。wall 166512ms，单轮 `[16693, 5994, 31079, 38569, 56144, 17588]`，
    `deep` P99 55804ms（预算 60000），`checkpoint.event_count=180`，工具调用 5 次，
    `invariants` 为空。
  - **15 轮 / 4k 窗口压力**：入口按预期非零退出。`invariants` 命中 I3：
    `cost_ms 104163` 与 `69025` 均超出主体预算 60000——真实模型在长历史下会撞穿 deep 档。
  - **3 轮 / 4k、3 轮 / 8k**：均通过；两次都没有出现 `session.consolidated`。
- 压缩未触发的边界：该 provider 不回 usage，`context.request_tokens` 缺席，compact 的
  水位判据读不到数（`model` 侧只写测得到的数，不补 0）。这是入口的 provider 前提，
  不是压测脚本失败；要覆盖「一次真实压缩」，需要换一个回报 usage 的 provider，或另给
  一条可测水位的数据源。
- 因此本条保持 `doing`：入口、真实运行与失败路径都已成立；剩余只有「一次真实压缩」。
