## 内容

**事实**（2026-10-23 实测，机器计数）：

| | 数量 |
|---|---|
| `ROWS` 总行数 | 17 |
| `drive()` 真正驱动（`by: Some`） | 6 —— `authorize-tool` / `close-turn` / `execute-turn` / `open-tools` / `dispatch-tools` / `deny-tools` |
| `by: None` | 11 —— 5 条 `policy.*` + `dispatch-turn` + `dispatch-model` + `lease` + `await-turn` / `await-model` / `await-tools`（后者三条属 D-114 的 Wait 折叠，见 T-261） |
| **绕开 `drive` 直调 `owes()` 的旁路** | **12** |

12 处：`chat_loop.rs:125/457/583`、`chat_loop/inputs.rs:172/336`、`port.rs:693`、
`tool_dispatch.rs:411/541/614/818`、`turn_exec/assemble.rs:218`、`turn_runner/stream.rs:75`。

**这不是 bug**。DE-015 §8 自己叫它「旁路收编」，是已知过渡态。问题是：
- GO-003 E5 说「过渡结构与死码只减不增」，但旁路**没有计数** ⇒ 这句话无从执行；
- 「收口完成」没有定义 ⇒ 没人知道什么时候能删掉这些旁路；
- J8 的口径写着「DE-015 §0『没有别的调度代码』」，却**只对账模型往返**，
  工具与策略行的旁路它看不见 ⇒ 这句声称实际只有 1/3 被检查。

**为什么选「计数棘轮」而不是「立刻收编」**：13 处旁路各自依赖不同的上下文
（有的在流式回调里、有的在工具批次里），一次性搬进 `drive` 是一次重构，
风险远大于收益。而计数棘轮**立刻**给了 E5 一个可执行的形式，并且把
「收口完成」定义成「计数归零」——这是个可以被逐步逼近的目标，不是一个口号。

**判据形状**：

1. 扫 `symbio/src` / `cli/src` / `tauri/src-tauri/src` 下的 `.rs`（排除 `*.test.rs`），
   统计 `owes(` **调用点**；
2. 排除 `fn owes(` 的定义行与 `drive_steps` 的函数体（后者问债不是旁路，它就是派发器本体）；
3. 计数 ≤ 基线（12），超出即红；低于基线时**提示下调基线**（否则余量白留，
   与 `core-shape-audit` 的 `SHAPE_BASELINE` 同类问题）；
4. **额外一条**（OB-003）：每处点名的行必须真实存在于 `ROWS`。点名一个不存在的行时
   `owes` 恒 `false`，那段旁路代码**永不执行**，而编译、测试、门禁全绿——与 DE-015
   判据 11「拼错的名字永不被消费」是同一个病，只是发生在派发面这一侧。

**DE-015 要补的条文**（与 T-257 的 §5 覆盖边界合写）：

> 环的派发面 = `drive` 驱动的行 + 旁路直调点。收口完成的定义是后者归零。
> 今天的数字写在判据的基线里，不写在正文里——正文会漂，基线不会。
