# 压缩失败后的跨轮抑制与重试出路

## 内容

压缩能力本身**没有丢**：`D-336` 把它拆成两行债（`compact-summarize` 走端口 `model.assist`、
`compact-write` 走端口 `compact`），执行体归端口提供方，水位阈值住能力包内
（`crates/symbio-plugin-compact/src/debt.rs::COMPACT_AT`）。`t8` / `t11` / `t18` / `t45` / `t63`
钉的是这条新链路，全绿。

丢的是**失败之后的两条用户出路**，它们原先长在会话内的压缩实现上，随实现退场后没有等价物：

| 原契约 | 原来靠什么 | 今天的实际行为 |
|---|---|---|
| E：连续失败 ⇒ 开闸，其后轮次跳过自动压缩、不再重发注定失败的摘要请求 | `active.rs` 的失败计数 + 冷却窗（`compression_should_skip` / `compression_record_failure` / `compression_record_success`），判据在会话运行期状态里 | **每轮照欠**。`unless_id` 钉的是**本轮**的 `session.consolidated`（`debt.rs:83`），失败不落该事实 ⇒ 下一轮水位仍越线就再欠一次摘要。`NonRetryable` 只抑制**环内重试**，不抑制下一轮重新欠债——`t18` 文件头自己写明「每轮越线、每轮都欠一次摘要」 |
| F：失败压缩节点上有「重试」入口，绕过熔断重压一次 | 失败的压缩节点（`Failed` + `meta.failure_kind`）+ `resume retry_compaction` | **入口不可达**。`CompactExecutor::execute` 拿不到摘要时返回成功、不落事实（`port.rs:71-74`），落出来的压缩节点恒为 `Completed`（`port.rs:119`）⇒ 没有失败产物；`ResumeAction::RetryCompaction` 只在 `is_compression() && failed` 时派生（`symbio-sdk/src/chat/chat_node.rs`），因此永不出现；即便出现，`retry_compaction` 在会话侧掉进 `_ => Err(VdfsError::NotImplemented)`（`plugin/vdfs_messages.rs:373`） |

**用户可见后果**：摘要服务持续失败时，每一轮都多付一次注定失败的模型往返，而界面上
既没有「已停止自动压缩」的交代，也没有可点的重试——失败只以一条 `failed` 环事实存在
（`t18` 契约 C 钉的就是它），用户读不到。这与 `SC-009` 判据 3「熔断触发后有可见兜底，
不是静默继续」正好相反。

## 为什么不在删除批里顺手补上

三条都堵死，且每条都是**机制裁决**，不是实现难度（`SP-003` §3 纪律 0）：

1. **债语法没有「过去 N 轮失败过」的表达位。** 四个谓词（`when` / `when_id` / `unless_id` /
   `after`）全部按事实判，`unless_id` 钉的是本轮那一条。要表达跨轮抑制，要么给债语法加
   一个谓词，要么让能力包持有自己的运行期状态（「状态应随能力包走，宿主只给租约与预算」
   ——S7 的迁移口径）——**两条路都还没裁**。
2. **永久失败格不存在。** `PortErrorClass` 只有 `Retryable` / `NonRetryable` / `NeedsHuman`
   （`crates/symbio-plugin-api/src/port.rs:262-269`）。「这一笔判死」与「这一类以后别再欠」
   是两件事，今天只有前者。加一格是机制面增量，须先立 `### D-NNN`。
3. **既有 `CircuitBreaker` 不是失败计数闸。** `crates/symbio-plugin-tool/src/breaker.rs`
   判的是授权 + 成本预算 + 判定超时（`GateInputs`），输入里根本没有「失败过几次」。
   拿它当熔断复用会造出第二套口径。

因此本条只做登记，**不新增能力、不自造机制**。删除批（`Migration`）与本条分开：
删掉的是没有生产调用方的旧实现，缺口是那条实现退场时未清偿的判据。

## 重启条件（满足其一即推进，不满足则保持 todo）

- **实测后果**：拿到「摘要服务持续失败时每轮多付一次往返」的真实读数（成本或时延），
  把它写进本条的 `signal`——那时缺口从推理变成实测，优先级随之上调；
- **机制裁决落地**：跨轮失败记忆的归属（能力包运行期状态 / 一条 `compact` 域事实 / 债语法
  新谓词）与永久失败格是否进 `PortErrorClass` 有了 `### D-NNN`。

## 处理过程

1. 先裁机制：跨轮失败记忆归谁、永久失败格要不要开。裁决落宿主设计文档的「关键决策」节，
   不在本条里复述口径。
2. 按裁决在 `compact` 包内落判据与状态（能力包持有自己的状态，宿主不新增字段）。
3. 失败要有**产物**才谈得上重试：裁清「压缩失败」在新链路里落什么（一条 `compact` 域事实，
   还是仍产一个失败节点），再决定 `RetryCompaction` 是接上派发还是随旧形态一起退役
   （退役则同批删机制词表里的那一格与前端的 `canRetryCompaction`，不留双地址）。
4. `t18` 补回 E / F 两条契约，断言只走生产出口（摘要请求命中数、`session.consolidated`、
   读出口读回的产物），不数引擎内部的计数器。
5. 收口登记：`SC-009` 判据 3 改回「已有」并指向用例；`RE-005` 的缺口行注销；
   `DE-101` / `DE-105` 里仍按旧会话内压缩描述的段落（熔断、`force`、`RetryCompaction`）
   按新 owner 收口——压缩的设计事实今天没有单一 owner，`symbio-plugin-compact` 连模块
   `README.md` 都没有，这一步要一并定下来。
