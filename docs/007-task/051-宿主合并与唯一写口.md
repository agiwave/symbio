# 宿主合并与唯一写口

> 对应架构分析：**P1（裁决类）**。
> 架构批第 2 笔。裁决（用户既定，不再开讨论）：
> **宿主是一个运行时层，不是一个对象。**
> 依据：P1 核实四项全中；`symbio-host` 当前依赖 kernel / plugin-api / providers / sdk，
> 不含任何插件 crate，搬家暂无造环风险。

## 内容

今天宿主被拆成两半：

| 住在 `symbio`（上层装配） | 住在 `symbio-host`（运行时） |
|---|---|
| `HostDrive` 的 kick/settled 状态机、`KickState`、`drain`（`crates/symbio/src/drive.rs` 150-440 行） | `Host`、`HostDriveSupport`、投影游标、`declared_owner`（`crates/symbio-host/src/lib.rs` 50-563 行） |
| 每轮 `Host::with_store` 现造（`crates/symbio/src/drive.rs` 129 行） | 行收集 `gather`（`crates/symbio-host/src/lib.rs` 204-276 行） |
| `write_stall` 用 `principal_of` 直写事实源（`crates/symbio/src/drive.rs` 477-486 行） | 世界写口走 `declared_owner`（`crates/symbio-host/src/lib.rs` 495-533 行） |

后果是两个写口并存、两套身份来源并存；「哪一份实例在等」只能靠一层薄封装挡住
第二次 `new`，而不是结构上不存在第二份。

## 是否阻塞横向扩展

**是（裁决类）**。两套写口与两套身份来源并存时，每新增一种写事实的能力都要先判断
「走哪条路径」，横向扩展只会继续复制第二套。必须在改代码或改判据之间二选一，
不许留一条与代码相反的判据。

## 处理过程

1. **搬状态机**：`HostDrive` / `KickState` / `drain` / `FactWorld` / `drive_on_new_fact`
   连同 `IN_DRIVE` 任务局部一起进 `symbio-host`；`symbio` 只留 `assembly` / `init` /
   链接行与对外的再导出。
2. **写口只许一条**：`write_stall` 不再用 `principal_of` 当 owner，改为与 `WorldWriter`
   共用 `declared_owner`（声明表查不到即按既有策略 panic，不静默落无主事实）。
3. **不造环**：若搬动需要 `symbio-host` 依赖任一 `symbio-plugin-*`，**停下报**，不搬
   （`symbio-host` 今天不依赖插件 crate，这一点必须在 Cargo.toml 上保持）。
4. **报三件事**：哪一份实例在等（`BOUND` 表键 / 实例身份）、谁在通知（`Notify` 的
   持有者）、通知落在哪个事实之后（`in_flight` 与 `NoDebt` 的先后）。t29 / t84 的
   「等错实例」症状要能说清是否随之消失。
5. 跑 `gate --full`，全绿后提交。

## 方案（2026-11-09 实测，待裁，不改代码）

### 1. `symbio` 里的长生命周期状态：逐项判「装配 / 宿主运行时」

| 状态 | 现址 | 寿命 | 判断 | 依据 |
|---|---|---|---|---|
| `HostDrive { root, kicks }` | `crates/symbio/src/drive.rs:154-159` | 进程级（按根绑定） | **宿主运行时** | `kicks` 按会话累积，跨轮存活；装配只该决定「造哪一个」 |
| `KickState { running, dirty, in_flight, latest, idle }` | `drive.rs:281-296` | 与 `HostDrive` 同寿 | **宿主运行时** | 五个位全是推进状态，装配不读也不写 |
| `BOUND`（根地址 → 实例 的进程级表） | `drive.rs:257` | 进程级 | **宿主运行时** | 「一根本一份」是运行时唯一性，不是装配选择 |
| `HOST_DRIVE_BINDING` + `inventory::submit!` | `drive.rs:255/259-261` | 链接期 | **装配** | 它只是把实现登记进装配表，**留在 `symbio`** |
| `IN_DRIVE`（任务局部） | `drive.rs`（`mod host` 内） | 单次驱动 | **宿主运行时** | 判「驱动自身调用 `settled` 不许自锁」的执行上下文 |
| `FactWorld<'a>` | `drive.rs:49-78` | 单次驱动 | 一次性 | 借用一份事实源与根，跑完即弃 |
| `MainDriveEntry` / `DriveEntryDecl` | `drive.rs:337-345` | 链接期 | **装配** | 入口登记，不是状态 |
| `HostDriveSupport` | `crates/symbio/src/drive.rs`（`Host::new` 处构造） | 单次驱动 | 一次性 | 投影 / 计划 / 主体 / 执行体每轮现造 |
| `Host { root, source, idle, concurrency }` | `crates/symbio-host/src/lib.rs:50-57` | 单次驱动（`drive.rs:129` 现造即弃） | 一次性 | 但 `idle` 是**机制状态**，寿命应跨轮（见 3） |

### 2. 「状态住错 crate」的点（全量）

1. **`HostDrive` / `KickState` / `BOUND` / `IN_DRIVE` / `drain`**：宿主运行时住在装配 crate `symbio`，方向反了。
2. **`Host::idle` + `idle_at()`**：机制状态挂在一次性对象上。生产路径 `drive.rs:129` 造完就跑、跑完即弃，**没有任何生产读者**；读者只有 `symbio-host/src/tests.rs:75` 与 `symbio-demo-probe/src/plugin/tests.rs:78`（都是测试）。
3. **`Host::concurrency` + `with_concurrency` / `with_store_and_concurrency`**：生产恒为 1（`with_store` 传 1），`with_concurrency` **全仓零调用者**。
4. **写口函数 `record_stall` / `write_stall` / `stall_draft` / `stalled_keys`**（`drive.rs:468-529`）：事实写入口住在装配 crate，而另一条写口 `WorldWriter` 住在 `symbio-host`。
5. **`open_fact_source`（`drive.rs:80`）**：事实源打开器，运行时职责，却由装配 crate 持有。

### 3. 两条写口的归属分叉

| | `WorldWriter`（`symbio-host/src/lib.rs:495-533`） | `write_stall`（`crates/symbio/src/drive.rs:477-486`） |
|---|---|---|
| owner 从哪来 | `declared_owner(name)`：查 `EventDecl::host` / `FactDump` 的声明字段 | `principal_of(Some(agent_id.trim()))`，**绕过声明表** |
| `@principal` 由谁解析 | `SessionFactSource::append` 用**事实源打开时**的 `agent_id` 快照 | `DriveTarget.agent_id`（**kick 时**装配层给的快照） |
| 声明变了会不会跟 | 跟 | **不跟** |

**会分叉的具体事实名：`driver.stalled`**（常量 `crates/symbio-plugin-api/src/drive.rs:185`，声明 `crates/symbio-plugin-loop/src/vocab.rs:30`，owner `@principal`）。

- **场景 A（声明改了，今天就能发生）**：把 `driver.stalled` 判成「平台级机制事实」并改成 `.owned("person/local")`。`WorldWriter` 写 `person/local`，`write_stall` 仍写 `session/main` —— **同一事实名两种归属**；读方（`crates/symbio-plugin-session/src/runtime.rs:102` 把它判成 `RuntimeOutcome::Failed`）按 owner 归因时，一半事实找不到主体。
- **场景 B（两个 `agent_id` 快照不同）**：会话中途换绑 / metadata 读时不一致时，A 用事实源快照、B 用 target 快照 ⇒ 同一会话的 stall 与其它事实落在**不同主体**下，`stalled_keys` 的去重与审计都看不出是同一会话。
- **场景 C（`agent_id` 缺失）**：A 的 `append("@principal")` 返回「会话主体不可用」→ **事实不落、留可见错误**；B 在 `drain` 里 `target.agent_id` 为 `None` 时**静默 return**。同一事实的两种失败方式：一条可观测、一条无声。

**总影响面**：全仓引用这批符号的只有 **6 个文件**（`drive.rs` 27 处、`drive.test.rs` 9 处、
`host/lib.rs` 6 处、`drive_entry.rs` 2 处、`host/tests.rs` 2 处、`demo-probe/tests.rs` 2 处）；
`loop` / `session` **零改动**。三批各自可独立回退（回退单位是 git 提交）。
