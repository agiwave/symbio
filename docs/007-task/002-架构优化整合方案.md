### 2. 三案取舍

| 议题 | D 案 | G 案 | H 案 | 本方案取舍 | 当前理由 |
|---|---|---|---|---|---|
| 目标形状 | 平台 + 横向单元 | 微内核 + 插件化 | 薄核心 + 端口 + 注入 | **采纳 D 的形状，以 H 的边界原则约束它** | 平台/运行时/ providers 合并已经落地；从既有形状继续收窄比另起一套新分层更可回退 |
| 核心薄度 | 19,315 行下限 | ≤2k 行 | 按依赖闭包判定，不按行数 | **按依赖闭包与 owner 判定；不设 2k 硬指标** | 当前 `kernel` 9,202 行里既有语法也有共享机制；先搬走唯一消费方引擎，再谈更小的内核 |
| 控制面身份 | 仍归插件，引擎按符号搬 `session` | `session+loop` 合成编排插件 | 控制面也是插件，但经端口注入 | **保留 `session` 插件身份；编排逻辑离开插件面成为 provider 单元** | `session` 是会话语义的 owner；`loop` 的 `DriveRunner` 已具备 provider 形状，把两件事分开比合并成一个超重插件更清楚 |
| 插件依赖 | 1 个 crate | 门面 + manifest | 稳定端口 + 组合根注入 | **先收口为 1 个 crate，再逐步把白名单降为生成物** | 编译器约束比 review 更硬；一次性替换四臂白名单会同时改协议面和生成链，风险过大 |
| 三通道（route / traverse / VDFS） | 保留 | 合并为一份 manifest | 作为贡献面生成物 | **保留三通道，禁止新增第二 owner** | 三通道已有生成镜像与审计；合并 owner 是协议改型，不是本次简化范围 |
| 动态插件 | 未展开 | WASM / 子进程 RPC | 先注册发现，动态 ABI 后置 | **本阶段不做动态 ABI；组合根先按注册表装配** | 静态链接的编译期断链检查仍值钱；先拿到边界收益，不付出版本化 ABI 成本 |
| 声明式小插件 | 固定税仍在 | <1k 行降为 manifest 包 | 生成物替代样板 | **延后；不为存量小插件合并另设专案** | 合并小插件会动插件身份、e2e 和门禁账；新增插件先设准入门槛，存量保持现状 |
| 进程拓扑 | 未主张 | 插件注入决定落点 | `SessionExecutor` 端口，落点是实现 | **采纳端口目标，但不改变当前默认拓扑** | 进程边界的补偿层要由端口收口，不能靠直接切到进程内执行来“简化” |
| 网关入站 | 变宿主 ingress | 宿主接入壳 | 入站适配器 | **采纳：网关插件退场，规则归 `symbio-http`，宿主持有 ingress** | 已先把只读白名单与幂等键表收敛到 `symbio-http`；剩余是配置、状态面与 e2e 路径迁移 |
| 判据形态 | 三条硬判据 + 棘轮 | 微内核原则 | 删除测试 + 单一 owner | **合并为可机检判据；不新增逐案例决策号** | 判据必须能被门禁判定；具体案例理由写在规则码与代码旁，不沉淀成文档账 |

### 3. 当前事实基线

截至本文编写时：

- workspace 共 40 个包：33 个插件 crate、7 个非插件 crate（含 `symbio-plugin-api` 门面）。
- `symbio-platform` 已承载 kernel / contract / sdk / deploy；`symbio-runtime` 已承载 server / host / http / worker；`symbio-providers` 已收为单一单元包；`provider-memory` 已归位到 `plugin-memory`。
- 网关仍是插件；`loop` 仍是插件；`session` 仍持有控制面引擎主体。
- `symbio-http::ingress_policy` 已成为只读白名单与 `Idempotency-Key` 的唯一实现，网关与 runtime ingress 都复用它。
- 宿主已容忍空 `drive` 族：没有编排提供者时一次 `drive` 返回 `NoDebt`，多提供者仍判红。
- 规模信息以 [RE-006-当前事实表](../004-ref/006-当前事实表.md) 为准；其中 `crates` 实现约 11.5 万行，`kernel` 实现 9,202 行。

这些是**已经落地的结构**，不是仍待讨论的目标；后续每一刀都从这形状出发。

### 4. 目标形状

| 角色 | 包 / 位置 | 约束 |
|---|---|---|
| 平台 | `symbio-platform` | 只留事实语法、协议契约、公共机制、sealed declarations、生成的部署镜像；不持有 transport、具体 provider、`SessionExecutor` 实现；不写逐插件分支 |
| 门面 | `symbio-plugin-api` | 插件唯一生产依赖；白名单与转发臂只许收窄；生成镜像不算第二 owner |
| 运行时 | `symbio-runtime` | 入站适配、宿主路由、worker 监督；不点名具体插件或 provider；只接收组合根交来的装配 |
| 组合根 | `symbio` | 唯一知道具体实现是谁的地方；产出插件树与服务实例；身份、权限、端口绑定、配置来源在此收口 |
| 基础设施单元 | `symbio-providers` | 碰磁盘、原生库或外部世界的适配器；只由组合根链接，业务模块只认端口与工厂 id |
| 会话语义 | `plugin-session` | 会话引擎与会话数据的 owner；平台里唯一消费方是它的引擎按符号迁入，契约留平台 |
| 编排单元 | 新 provider 单元 | 实现现有 `DriveRunner`；声明行归平台 sealed declarations；可缺席、可替换；不持有账本或注册表 |
| 能力插件 | 其余插件 | 一插件一能力；插件间零直接依赖；跨能力调用经端口或事件 |
| 入站 | `symbio-http` + runtime ingress | 线路机制与必须同形的边界策略归 `symbio-http`；业务路由归 ingress；`gateway` 插件退场 |

目标不是“把包数压到某个数字”，而是让新增能力只改插件与声明，不改平台、门面白名单、transport 和执行拓扑。

### 5. 统一判据

1. 插件生产依赖只声明门面一个 crate；现存例外只许减少，不许新增。
2. 平台的依赖闭包不得出现 transport、插件实现、具体存储后端、进程/容器细节。
3. 平台源码不得手写插件 id、路由字面量、配置文件名；部署镜像由生成器产出。
4. 最长 crate 深度 ≤ 5；同层单元零编译依赖。
5. 一个结构事实只有一个 owner；生成页、镜像和前端常量是 `view`，不是第二个 owner。
6. 形状棘轮与目录基线只许收窄；引擎搬入 `session` 前必须先建立会话目录基线。
7. 删除测试：删掉任一能力插件，系统仍完整，且该能力的地址、工具、事实行随之消失。
8. 架构改动用规则码 + 当前理由署名；提交号只标识历史记录，不作为授权或理由。

### 6. 分阶段路线

每阶段独立可编译、可回退、门禁全绿后才提交；顺序按“已开头的前置先收口，再做更大搬迁”调整。

| 阶段 | 动作 | 验收 |
|---|---|---|
| A · 编排收口 | 把 `loop` 的 sealed declarations 迁到平台；`ring` / `drive` / `plugin_rows` 运行逻辑成 provider 单元；装配直接携带 `DriveRunner` | 无插件装配通过 seal 且 `drive` 返回 `NoDebt`；有单元时行为不变；两份声明不同时存在 |
| B · 入站归一 | 将网关的配置文档与 `status` 面迁到 runtime / CLI；迁移依赖网关 ingress 的 e2e 读回路径；删除网关插件 | HTTP / WS / SSE 端点等价；插件数减一；事实页与路由镜像重生成 |
| C · 引擎归位 | 建立 `session` 目录基线；按符号把平台中唯一消费方是会话的引擎迁入 `session`；协议契约留平台 | 平台行数与公开面只减；testkit 不产生逆依赖；全量门禁绿 |
| D · 组合根收口 | 统一身份、`VdfsCaller`、端口绑定、配置来源；把散落在 runtime / worker / 插件里的装配知识移到组合根 | 同一事实只有一个 owner；全局分发桥的消费者逐个消除 |
| E · 执行端口 | 抽 `SessionExecutor` 端口，先保留现有容器实现；再用同一契约测试验证可选进程内实现 | 两种实现共用事件契约与恢复测试；默认拓扑不因端口化被迫改变 |
| F · 长期候选 | 动态 ABI、manifest 合并三通道、声明式小插件包 | 仅在 A–E 完成且形成明确当前理由后重新立项；本方案不授权 |

阶段 A 先做的原因：宿主的空族容忍已经落地，声明归位是让它从“测试可行”变成“装配可行”的最短一步；网关退场涉及大量 e2e 读回路径，放在其后更稳。

### 7. 每刀纪律

- 顺序固定：实现 → 单元测试 → e2e → 全量门禁；提交前 `node scripts/gate.mjs` 全绿。
- 架构边界变化先改本方案的规范面，再改实现；实现困难不改变取舍。
- 生成页不手改，全部由脚本重生成；审计基线只许更紧。
- 同一提交不做“搬实现 + 改协议契约”两件事；旧路径删除与新路径启用同批完成。
- 本方案的实施进度只写 front-matter 与下一节的过程记录，不回写三份候选原文。

### 8. 明确不做

- 不把微内核行数当作近期 KPI，也不为“看起来薄”把共享机制迁进唯一消费方造成逆依赖。
- 不做 `dlopen` / WASM 插件通道；不把静态链接包装成热插拔。
- 不把 route / traverse / VDFS 合成新 manifest owner；已有镜像继续由生成脚本维护。
- 不批量合并小插件 crate；不为存量插件开逐案例处置账。
- 不把“每会话一进程”改成默认进程内执行来换取表面简化。
- 不新增逐案例决策编号；理由写在规则署名与实现旁。
