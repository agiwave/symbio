# 端口终态加严批

## 内容

SPRINT 父任务。D-440 只完成了「删除 Capability 执行接口」这一窄目标；本批收**加严评审**
留在代码里的实质残留：旧链回落、通用端口绑模型消息、SDK 承担领域实现、动态收集未闭环、
wire 名非单射、无暴露集合校验、固定 `tool` 端口等待、审批包装与事实写方未移交、静态端口
白名单。终态按 [DE-056-端口终态加严裁决](../003-design/056-端口终态加严裁决.md) 的
D-444–D-447 落地。

链路形状：活插件贡献 → 同次收集与校验 → 模型插件投影本次 tools → 模型返回调用 →
校验并记录调用意图事实 → 声明方生成逐调用债 → 义务环派发目标端口 → 结果事实 →
模型插件组装下一次请求。

**收口信号**：不装模型和工具总代理，自定义端口仍能跑通事实—债—执行闭环；新增端口不修改
既有基础模块；描述与执行不漂移；同名绑定明确报错；空工具集正常回答；wire 碰撞、未暴露
名称、非法参数都不能触发误执行；多调用、待批恢复、部分失败、取消、重试、迟归和重放
保持语义；消费面 e2e 与全量门禁全绿。

## 处理过程

- 子任务见父任务分解树；结论落进设计文档 `### D-NNN` 后按「收口即删」移除任务文件。
- 本批纪律：迁移期不得让旧、新两条执行路径同时生效；不为消红放宽判据或改审计关键词。
- 2026-11-11 第一轮：**D-444 / D-445 全部落地，D-447 的门禁收窄部分落地，D-446 只落到
  可判定的一半**。逐条位置与判据写在
  [DE-056-端口终态加严裁决](../003-design/056-端口终态加严裁决.md) 的「落地与残留」。
- 2026-11-11 第二轮：D-446 剩下的那一半（续跑等**本次调用集合**而非整条端口）落地——
  `when_no_open` 的作用域换成带 id 集合的 `NoOpenScope`（类型替换、不增字段，`model`
  侧从 `tool.call.requested` 读集合）；D-448 / D-449 裁决把 SDK 的两处领域实现与

  仍留开两项：T-336（非法参数反例、三项审计收窄）、T-337（硬验收逐条取证）；本任务作为
  父任务留开到两者收口。
