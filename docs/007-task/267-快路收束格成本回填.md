## 内容

`classify` 判 `Answered` 的轮有两个模型往返（分类 + 措辞），但收束格
`chat.assistant.final.cost_ms` 恒为 0：`persist.rs` 只把答话正文交给运行器，
措辞往返的实测耗时在插件出口被丢弃。

后果不是日志少一行，而是 `cost_ledger` 与 SLO 对**整类**答话轮系统性少记，
熔断阈值永远够不到——与 I3「到点必答」的读数直接冲突。

修法按值链贯通：`WordingReply.cost_ms`（`#[serde(default)]`，模板路径 0）
→ `execute_final_reply_turn(..., reply_cost_ms, ...)` → `TurnInput::final_cost_ms`
→ 收束格与 `TurnOutcome`。内部请求仍不写事件（D-044 不变），代价随**它所属的那一轮**
回来。
