# SPRINT：能力全面拆分与扩展性验证

## 内容

把 `loop` / `session` 里按能力名存在的实现全部搬进独立能力包，使「一个能力 = 一个插件」
在**存量**上也成立。口径归 [DE-026-能力拆分与影响类](../003-design/026-能力拆分与影响类.md "DE-026-能力拆分与影响类")
（D-239…D-249），本文只做分解，不复述判据。

**先后是硬约束，但「先后」≠「禁增」**：架构补件（S3–S5）已落定，I-1 / I-2 / I-4 / I-5
四项读数都已可用（D-241 / D-243 / D-242 / D-249）。补件期间允许改 `core` / `kernel` /
`plugin-api`，按 D-240…D-243 已裁定的形状、带决策、且通用（不含能力名）。S6 起进入**迁移
区间**：迁移提交 `core` / `kernel` diff = 0，`loop` / `session` 只含删除与绑定切换
（`EX-007` / D-247）。某一行迁不动说明**前置设计不足**——停下这一批，单独补决策与补件提交，
再恢复迁移；判失败的是「机制夹带在迁移提交里」「为一条能力定制端口」「把能力实现搬进架构
模块冒充端口」。

**账本对象是全表**：[DE-008-能力注册表与能力坐标系](../003-design/008-能力注册表与能力坐标系.md "DE-008-能力注册表与能力坐标系") §6.1 的
54 行能力逐行有处置，不是只处理几个样本。终态同时要求：

- **T1 新增**：新能力只改自己目录，`core` / `kernel` / `loop` / `session` diff = 0（`EX-002`）。
- **T2 拆除**：存量实现从控制面删除，行为由能力包等价交出，同提交完成（`EX-003` / D-245）。
- **T3 卸载**：卸任一个能力，系统其余部分完整运行，且该能力不留静默边（`EX-004`）。
- **全表覆盖**：54 行每行恰好一条处置；「能拆未拆」不合法（`EX-006` / D-246）。
- **残余归零**：控制面里的工具名归零（既有的 `SC-006`，基线只许降），能力名的归宿由
  `EX-006` 收口；留守只落五类（环、写口、全局守门、过程体、会话基底）。

**不做**：新增 `Entity` 变体（D-244）；把 `&mut Ctx` 或整轮状态开给插件（D-241）；
按能力名注册执行体（D-240）；为单条能力定制端口（D-247）；两份实现同时生效（D-245）。
