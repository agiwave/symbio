## 内容

### 它是什么

`port::round_trip`（`crates/symbio-plugin-loop/src/port.rs`）自己 `announce` 又自己 `dispatch`，是
三段**表外点问**共用的入账口：判决（`port/classify.rs` 的 `classify_round_trip`，调用点
`chat_loop/decide.rs`）、措辞（`chat_loop/compose.rs` 的 `wording_round_trip`，调用点同一文件）、
压缩摘要（`Compress::summary`）。

`D-222` 划界第 2 条给了它们的消失方式：**各自行化之后自然没有调用点**。压缩摘要那一格
按 `D-131` 明文出界（不入账，差额由 `obligation-ring-accept` 的 J9 钉住），不在本条射程；
剩下两段没有任何承载。

### 为什么单独立一条

`TC-1b` 判的是「派发器之外不再直问求解器再自行派发」。今天的读数说 `round_trip` **不构成**
第二选债口（不直问求解器、身份由入参 `Round` 定死、`awaited = false` 且付款方是闭包）——
但那是「当下无实例」，不是终态：只要还有一段在动作里自己 `announce`，环覆盖的就只是表上的
债，覆盖不到「动作里顺手打的一次往返」。那两段各自的消失方式已有裁决，缺的是施工。

### 终态

- 判决与措辞各自成为行表上的债：`owes` / `until` 按 `D-225`（`DE-022`）的往返身份
  编键，动作只声明「站在哪一行上」，`request` / `sent` / `response` 由派发器补全。
- `round_trip` 只剩压缩摘要一个调用点，或随最后一段行化删除。
- 账不变：判决往返与措辞往返在日志上仍是各自一笔三格，`via` 区分来源（`classify` / `wording`）。

### 不做什么

- **不动压缩摘要往返**：`D-131` 明文出界，差额由 J9 钉着——把出界的那一段拉进来只会让
  那条具名判据失去对象。
- **不改三格等式**：行化的目的是让派发器来写 `request` / `sent`，不是减少格数。
- **不加新事实名**：两段落的格沿用协议格（`request` / `sent` / `response`），身份由 `via` 与逻辑 id 表达。

## 处理过程

- 待开工。开工前置：无（`D-222` 划界第 2 条已裁），缺的是施工。
- 顺序：判决（`decide.rs`，调用点最独立）→ 措辞（`compose.rs`，同在一个上下文里，顺手把

  再跑 `obligation-ring-accept --strict` 看 J2 读数是否原地。
