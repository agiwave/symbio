# 端口集搬到装配期收集

## 内容

把端口集从**能力表的行**搬到**装配期的专用收集容器**，与 v3 的 `PortBindings` 同形：
登记是一次受检插入（同名即冲突、永久记下），读端是 `get` / `snapshot`，装配方用
`attach_executor` 换上真正的执行体。`PORT_FAMILY` 与 `port_row_name` 这两处旧载体已退役
（前者是 `multi("port")` 族，后者是 `<port:{port}>:{provider_id}` 表键）；`:` 的保留字符约束
因为不再进表键而消失。

现状（v2）：端口行与工具行同批写进能力表（`register_tool` 一次写两条），宿主 `gather`
从行上折执行体表，`plugin-tool` / `session` / `plugin-agent` 各自 `list(PORT_FAMILY)`
的旧读法已退役。判据本身不弱（受检插入、冲突指名），弱的是**载体**：
端口必须借一条能力行存在，于是「端口集」与「工具目录」在表上无法区分。

where: `crates/symbio-sdk/src/capability/port.rs`（→ `plugin/port.rs`）、
`crates/symbio-host/src/lib.rs::gather`、`crates/symbio-provider-collectors/src/tool_visitor.rs`、
`crates/symbio-plugin-agent/src/host/scope.rs`、`crates/symbio-plugin-session/src/plugin/turn.rs`、
`crates/symbio-plugin-tool/src/port.rs`、`crates/symbio-plugin-api/src/port.rs`。

exit: 端口族常量与行名表键在 `.rs` 里 0 命中；`PortBindings` 是端口集的唯一载体；
`register_ports` 的调用面不变（`ctx[PORT_BINDINGS]` 缺席即 no-op）；
`dynamic-port-registration-audit` 四码仍绿；`cargo test -p symbio-sdk -p symbio-host
-p symbio-provider-collectors -p symbio-plugin-tool -p symbio-plugin-agent
-p symbio-plugin-session` 全绿。

## 处理过程

- 2026-11-11：立条目。依赖序上排在 `T-344` 之后：先删第二条执行面，再换端口集载体，
  两次改动各自可回退（回退单位是 git 提交）。
- 2026-11-11：**开工前勘出唯一有语义的接缝——子 Agent 作用域**。这不是纯删除：
  容器住在 `ctx` 上，而 `plugin-agent` 的 `SubAgentVisitor` 是一个 `Registry` 包装层
  （它没有也拿不到那份 ctx）。现状是它**按行拦截**：把端口行的执行体暂存进 `pending`，
  等同批的工具行到齐后改名重注册（`register_tool` 先端口行后工具行，顺序是隐含契约）。
  载体一换成 ctx 上的容器，这条「行到行」的配对没有对应物——两个可选形状：

  1. **登记期前缀**（v3 的形状）：`register_ports` 从 `ctx[PORT_SCOPE]` 读前缀，端口名
     在登记前统一加前缀；作用域层不再碰端口，只做工具行的改名与 `SCOPE_TWIN` 声明。
     代价：`register_tool` 必须拿得到 ctx（签名从 `visitor` 改成 `ctx`），10 个调用点
     全改；好处：那条「先端口行后工具行」的隐含顺序契约一起消失。
  2. **容器交给作用域层**：`SubAgentVisitor` 构造时收一份容器句柄，自己写前缀化的
     绑定。代价：容器有两个写方（插件登记 + 作用域代理），D-445 ③ 的「一个端口一个
     写口」要重新论证；且代理要知道端口名与工具名的前缀规则是同一个——正是
     `D-428` 要求上层不认识的那套命名。

  倾向 1（与 v3 同形，且它把顺序契约一并删掉），但它是**机制面改动**：按 `AGENTS.md`
  「架构改动只认方案为源」，先落一条裁决再动代码，不在本任务里现编。未开工的原因写在这里，
  不让下一个人重勘一遍。
