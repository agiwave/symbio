# 运行期符合性与残余欠账收口

## 内容

### 现场

- `scripts/obligation-ring-accept.mjs` 的 `J1…J9` 是义务环**运行期**符合性判定器，
  在 `scripts/gate.d/30-docs.mjs:911/915-924` 登记为 `OUT_OF_GATE`（文档阶段静态跑不出输入），
  真实行使只有 `e2e/cases/t107-ring-acceptance.mjs` 一条（真实 CLI 会话 + `--strict`）。
- `J6` 的 `DECLARED_PORTS` 已从拒绝依据降级为**漂移对照**，孤名判据的拦截责任没有明确 owner。
- `scripts/loop-purity-baseline.json` 记 `lp003WorldRoots: { "plugin_rows.rs": 4 }`，
  `LP-001/002/004/005` 均为 0，这 4 个世界词根是纯度面仅剩的残余。
- `DE-053` 仍有 `D-345`（终答格两个产出点未共用构造器）/ `D-346`（两套 `FactDecl`）/
  `D-350`（授权放行无事实留痕）一类「登记，不修」项，后续裁决可能已部分落地。
- `e2e/run-tests.mjs` 头注释自陈「抖动类失败：每轮挂的用例不同、单跑 100% 通过」；
  阶段性提交时的全量门禁（并发 7）曾出现 `t4-multi-turn` 偶发红，而单例连跑 3/3 绿、
  并发 2 下 91/91 绿。不是代码回归，但「绿灯才算绿」在抖动面前没有可判的读法：
  同一份代码跑两次结论不同，门禁就不成其为判据。失败形态固定：两行 stdin 由
  `e2e/helpers.mjs::runCli` 一次性 `child.stdin.end(stdinText)` 喂入，REPL 打印第一个
  「你 ›」后第二轮读到 EOF（stdout 只剩两个空 prompt、stderr 以「再见。」收尾），
  指向「用例对 REPL 起跑时序的隐含假设」。单例连跑 3/3 绿、并发 2 下 91/91 绿，
  且该批次零 e2e / 零生产逻辑改动，故不是本批回归；复现日志见
  `.workbuddy-ai/gate-logs/20261112-150015/e2e-t4-multi-turn.log`。

### 判定

把判定器塞进静态门禁是**最省事**的假动作：它没有 WAL 输入，只会变成一个永远绿或永远跳过的
检查项。按终态标准，运行期符合性应该由**真实会话**行使，问题在覆盖面：
一条 e2e 覆盖 J1…J9，任何一条判据被悄悄绕过都没有第二条路径发现。

1. 为 `J1…J9` 补**至少第二条**真实会话行使路径（或明确每条判据的回归夹具归属），
   并保持 `OUT_OF_GATE` 的原因不变。
2. `J6` 降级后，给「孤名 = 0」重新指认拦截 owner（装载期 `seal` / 运行期判定器 / 门禁三选一，
   写清在哪判红），不让一条判据悬空。
3. `LP-003` 的 4 个世界词根按基线只许降的方向清零，或逐条写明为何属于机制层合法词汇。
4. `DE-053` 的三条「登记，不修」逐条核实当前状态：已落地的把结论写回设计文档，
   未落地的保留欠账并指认承载它的裁决编号。
5. e2e 并发抖动按**运行期稳定性欠账**跟踪：先连跑固定失败集，区分「用例自身对共享
   端口 / 时序的隐含假设」与「runner 起跑调度」，再决定修用例还是改并发度。不得以
   「单例绿」收口，也不得直接调低默认并发换绿灯——那是以实现简单代替架构目标。

exit: 运行期符合性有 ≥2 条真实行使路径且每条 J 判据有可打开的失败用例；
孤名判据有明确 owner；`LP-003` 清零或有逐条归属；`DE-053` 残余项状态与代码一致；
e2e 全量连跑无抖动红，或抖动源有可打开的复现记录与明确 owner。

不做什么：不把运行期判定器降级为静态门禁的装饰项、不放宽 `LP-003` 基线、
不为凑条数新增空跑用例。
