# 行内两出口合一——一条行既欠端口又落答复格

## 内容

### 现场

[DE-025-能力包与扩展面](../003-design/025-能力包与扩展面.md) §5.2 缺口账第 5 行写的是一条**位置缺失**：

> 轮内某步 + **提问 → 作答**：一条行既要一次模型往返、又要「这一步就是这一轮的答复」：
> `RowStep` 只从 `RowHandler::run` 出，`parse` 的产物是 `Vec<FactDraft>`，两个出口串不起来。

后果落在 [DE-051-机制形状规格](../003-design/051-机制形状规格.md) 的判据 3：`crates/symbio-plugin-session/src/answer.rs`
的答复路径能处理**单次**审批恢复（e2e t27 绿），但「同一轮两次待答复卡」的真链路
**至今没有接**（原文自陈「尚未接入，属批内多卡 / 逐笔债的同一裁决」）。

所以这不是两条欠账，是一条：**行的「派发」与「收束」是两个出口，而它们需要共用同一笔债的身份。**

### 判定

两条出口今天各自的形状：

- **派发**：`RowHandler::run` 返回 `RowStep`（可以是 `Ask`），环把它变成一笔 `request(port=…)`；
- **收束**：`RowHandler::parse` 收一份回执，产出 `Vec<FactDraft>`，由宿主落格。

缺口在于：一笔债走完「派发 → 等待 → 回执 → 收束」之后，**收束的产物无法声明「这一笔就是
本轮的答复」**——`parse` 只交事实草稿，而「答复格」的写方在 session 的 `answer.rs`。
于是两次卡同轮出现时，第二次的恢复键只能落在「最近一次请求」，与「较早请求」错位。

裁决方向（施工前需按 [SP-003](../005-spec/003.md) 落一条 `### D-NNN`，因为它改的是行机制契约）：
**让收束产物带一个「轮级出口」标记**，而不是让 session 去扫事实找答复。可选形状两种，
施工时二选一并写明否掉的另一种：

1. `FactDraft` 加一个 `terminal: bool` 类标记——收束即声明「这一格是本轮的答复」；
2. 行声明一个「轮末收敛格」，`parse` 的产物里有它时由环统一落。

### exit

- 「派发 → 收束」共用同一笔债的身份；同轮两次卡各归各的请求（这条口径已由
  `tool/debt.test.rs` 的四条用例证了配对，缺的是**真链路**）。
- 新增 e2e：同一轮两次待答复卡 → 两张卡 → 两次恢复 → 一轮收束，全绿。
- `DE-051` 判据 3 的「尚未接入」句按现状改写；`DE-025` §5.2 该行结论从「位置缺失」改为落地锚。
- `cargo test --workspace` 与 e2e 92 条全绿；`CS-001` 三格不涨。

### 不做什么

- **不把恢复改成逐调用债务**（批债 / 逐笔债另议，`DE-051` 的「不做什么」）。
- 不按「最近一次」兼容旧行为——位置配对正是缺陷本身。
- 不扩 `RowRequest` 的世界能力面（不加工具清单、不加配置快照，`D-306` 裁决二）。
