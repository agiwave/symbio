# 吸收 v3 机制面 SPRINT

## 内容

v2 已成为干线（切分与归属更近终态），但 v3 在**机制面**上有三件事更近终态，
外加一处只影响检索的台账缺陷。本批把这三件事按依赖序搬回 v2，一件一个子任务，
每件都以「删除型判据」收口（`grep` 归零 / 调用点只剩一处），不以叙述代替代码。

来源是一次只读对比（结论「v2 整体更近，机制面三项以 v3 更近」，反向读法同样成立）；
本批不重开该裁决，只执行其中**无争议的删除型**部分：

1. **端口集不是能力行**：v2 仍用 `PORT_FAMILY` 行 + `port_row_name` 表键承载端口集（全仓 24 处命中；该载体已退役，D-468），
   v3 改成装配期的专用收集容器（登记 → 受检插入 → 装配方换执行体，
   走自己的 ctx 键而非能力表）。差别在**载体**，不在判据——两边的判重
   都不弱；行名编码与 `:` 保留字符的隐含约束随载体一起消失。
2. **执行面唯一**：v2 的 `local` / `web` 仍各有一条「按工具名走 `route`」的执行分支
   （判闸 + 造 `PortExecContext` + 拆信封各写一遍），仓内生产侧没有读者。v3 一律
   `NotFound`。删掉之后，审批闸门的调用点从 3 处降到 1 处（`register_tool` 的
   `GatedExecutor`），与 `D-449`「闸门留在执行体一侧、不搬进各工具」对齐。
3. **协议命名归模型插件**：v2 的 wire 别名规则摊在 4 处（`model/types.rs`、
   `session/plugin/turn.rs`、`plugin-tool/port.rs`、门面转发），v3 收进
   `plugin-model/src/tool_projection.rs`（身份与别名分开 / 一一映射 / 协议名称转换归模型）。
4. **决策台账唯一**：`DE-056` 的 D-444…D-447 各出现两次（裁决节 + 「落地与残留」节），
   按编号检索会读到两段不同定义。门禁没抓到，因为 `D-007` 只校验引用锚点存在，不校验定义唯一。

**不做**（本批明确排除，理由随条目）：
- 不搬 `plugin-tool/src/port.rs` 的逐调用簿记出能力包（v2 赢的那一项，v3 要新建）；
- 不重建 `session` 两本账（`D-461` 已落，回撤没有判据支持）；
- 不动内核数据面棘轮的 3 变体 / 1 字段（属 `D-446` 已论证的放宽，不为凑水位删判据）。

exit: 本 SPRINT 的验收是三条**可执行**判据同时成立：

- `grep -rn "PORT_FAMILY\|port_row_name" --include=*.rs` 归零（端口集只剩收集容器一条载体）；
- `approval_gate(` 在生产 `.rs` 里只剩 `provider-collectors/src/approval.rs` 的
  `GatedExecutor::execute` 一个调用点；`plugin-local` / `plugin-web` 的 `route` 对工具名
  一律 `NotFound`，且各有一条反例用例；
- `capability_to_wire` 的生产调用点只剩模型插件的投影模块 + 门面定义；
- `grep -c "^### D-" docs/003-design/056-端口终态加严裁决.md` 的编号无重复。

四条判据都写进门禁（或由既有门禁读出），不以本文件的自述为准。
