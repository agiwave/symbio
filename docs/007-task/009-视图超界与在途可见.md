## 内容

### 为什么这两条在一起

它们不是同一个缺口，但同一种形状：**失败与成功在返回值上同形**，于是没有报错、没有判据、没有读数。

| # | 事实 | 后果 |
|---|---|---|
| ① 视图 `cost` 超界静默返回空集 | 求值器在超出声明的成本上界时回一个空集，调用方读到的是"没有欠账" | `exhausted{no_progress}` 与"确实没账"同形：整批行不开账，零告警 |
| ② `await-*` 在运行期不可观测 | 派出的 `sent` 与应答的 `response` 落在同一个动作里，两次选债之间 `waiting` 永远是假 | "已派出、未收清"在正常运行中读不到；只有"上一次生命崩在 `sent` 与应答之间"这一种输入才用得上 |

### ① 为什么不是"改求解器"

`ring.rs` 的 `owed` 在视图求值拿不到值时走 `_ => Vec::new()`，字节冻结（`PTS-003`）。
所以修法只有两条，都不在求解器里：

- **求值侧**：`Frozen::eval` 超界时留下可观测的信号（`None` 与 `Some(空集)` 已经分得开，
  是调用方把两者折成了同一个值）；
- **调用侧**：所有调用方已经先按 `turn_slice` 切过片（`control_decl` 的 `cost` 上界与
  `chat_loop` 的 `lease_tail` 是同值的一对）。若所有调用方都已先切，那么超界只可能是
  **声明与切片不同步**——那是装载期判据的事，不是运行期兜底。

**先确认是哪一种，再决定改哪一层**。这一条的第一步是取证，不是写代码。

### ② 为什么拆两个环步是它唯一的终态

`sent` 与 `response` 同窗 ⇒ 在途状态只存在于内存里，日志上"已派出"与"已应答"永远同时出现。
于是：

- `lease` 行（判死超时的往返）在正常运行中**永远选不中**（`stale_sent` 恒空）；
- `waiting` 这个停机理由（`D-130`）在正常运行中恒假，只在崩溃恢复的输入上才有意义；
- `TC-1c` 的空账本守卫判的是"环不前进"，而在途恰恰是"环合法地不前进"——今天这两种处境
  在事实面上同形。

拆成两个环步之后，`await-*` 行在两次选债之间是**开着**的：环可以合法地什么都不做，
而这种"不前进"是**可判**的（`sent` 有、`response` 无 ⇒ 在等，不是没账）。

**这一条同时是 [T-011](011-一个环.md "T-011-一个环") 的前件**：不先拆，T-011 合表之后这批行
还要再拆一次；而且 `lease` 行在 T-005 里刚接回派发器，若它永远选不中，"接回"就只是形式。

### 不做什么

- **不改求解器的选债与还债语义**：`ring::owed` / `ring::drive` 的字节仍是基线（`PTS-003`）。
  ① 的修法在求值器与调用方，不在求解器。
- **不为 ① 新造错误类型**：`ActorError` 只有两个变体是已裁的形状，报错走既有通道。
- **不把 ② 做成"超时即失败"**：判死仍归 `lease` 行（`D-138`），本任务只让它在事实面上看得见。

## 处理过程

- 待开工。前置 T-005 已闭环（端口组已退场、`turn` 那一段环已改成直线）。
- **前置变了，② 的判据要按新形状读**（写在这里免得下一轮照旧文找 `lease` 行）：`lease`
  行已在 T-005 删除，看护改为 `port::reap` 直接读 `stale_sent` 视图（「看护不是还债」，
  不经行表）。② 的动机**不变**——`sent` 与 `response` 同窗 ⇒ `stale_sent` 在正常跑里恒空、
  `waiting` 恒假，「已派出、未收清」读不到；变的只是判死的入口：不是某一行被选中，是
  `reap` 在漂移窗口里扫到过期尝试。反向用例因此改成「把派出与应答挪回同一个动作窗口 ⇒
  `reap` 永远扫不到过期尝试、`waiting` 恒假」。
- 顺序：①（取证 → 定层 → 改一处）→ ②（拆 `sent` / `response` 两个环步，动
  `port::round_trip`、`turn_runner/stream.rs` 的 `call_model` 与三个 `await-*` 行）。
  ② 的改动面比 ① 大一个量级：它要求「派出」与「收应答」分处两次选债，而今天两者在同一个
  `async fn` 里（`dispatch_full` 包住了 `run().await`）——这一步实质上是把端口派发改成
  「落 `sent` 就返回、应答由下一次选债收」。动手前先确认它与 T-011 的签名归一不冲突。

### ① 的取证（已完成，结论决定了改哪一层）

三处实测，缺一不可：

| # | 位置 | 实测 | 判 |
|---|---|---|---|
| 1 | `Frozen::eval`（`decl/mod.rs`） | 超界回 `None`，注释写着「超界不静默截断」 | 求值侧**已经**分得开，不是缺口所在 |
| 2 | `ring.rs` 的 `keys_of_expanded` | `_ => Vec::new()` 把 `None` 与 `Value::Null` 折成同一个空集 | 「静默」的唯一实际位置，但 `owed` 字节是基线（`PTS-003` 冻的就是 `fn owed` / `fn drive` 两段） |
| 3 | 两处切片 | `chat_loop::drive::LEASE_WINDOW = 4096` 与 `control_decl` 七处 `cost: 4096` **手抄同值**；`loop_rows::turn_slice` **只按轮起点切、不切长度**（且零测试覆盖） | 所以这不是「改哪一层」的二选一，是**两层各缺一半**：切点没有单一真源，而未切的那一处正是真实超界路径 |

因此终态是「两头收 + 一条装载期判据」，都不碰求解器：

1. **切点只有一个真源**：`Frozen::scan_bound()` 返回全表最小的 `cost`。理由是一份切片要喂给
   **每一条**视图，能同时满足所有视图的上界只有最小值。`loop_rows::scan_bound()` 是它的转发
   （调用方不该自己遍历视图表）。
2. **两处切片都从它取**：`turn_slice` 切尾到窗口内（超界时 `tracing::warn!`，写明超了多少、
   上界多少、该调 `cost` 还是该拆轮）；`LEASE_WINDOW` 常量删除，改为 `lease_window()` 函数。
3. **声明的分歧在装载期红**：新增 `Gap::ViewCostMismatch`。运行期没有第三种解法——按大的切
   声明小的那族每轮回 `None`，按小的切声明大的那族静默漏账，两支都是「算不出来」冒充
   「没有欠账」，所以那种表不许冻结。

**切尾而不是报错**，是因为失效方向不对称：切掉的是一轮里更早的事实，缺席的会是 `request`
（那一笔债还不上 ⇒ 环空转、可见），而 `response` 总在尾部（漏还账才是不可见的那一头）。

**为什么 ② 没有一起做**：`scan_bound` 的前提是「一份切片喂给所有视图」；② 要拆的是
「派出与应答分处两次选债」，动的是 `port::round_trip` 与 `dispatch_full` 包住的 `run().await`。
两者在类型上正交（一个管长度、一个管时机），但 ② 会改 `await-*` 行的前件与
`turn_runner/stream.rs` 的调用形状，与 ① 混在一起就没有可独立回退的中间态。① 单独绿、
单独提交之后再做 ②。

① 的用例（两两成对，缺一不成判据）：

| 用例 | 钉什么 |
|---|---|
| `the_scan_bound_is_the_cost_every_view_declares` | 一致表上切点 = 声明的那个数（不是 `0`、不是默认值） |
| `a_table_without_views_has_no_scan_bound` | 没有视图 ⇒ `None`，不是 `0`（`0` 会把切片切空 ⇒ 全都「没欠」） |
| `a_view_cost_that_disagrees_with_the_bound_is_rejected_at_load_time` | 分歧装载期红，且指名道姓报**偏大**的那一条 |
| `an_over_bound_slice_makes_the_views_uncomputable` | 缺口真实存在：不切时至少一条视图回 `None` |
| `the_turn_slice_is_trimmed_to_the_scan_bound_keeping_the_newest` | 切到上界、切的是尾部（`response` 留下） |
| `a_trimmed_turn_slice_leaves_every_view_evaluable` | 切完每条视图都算得出来 ⇒ `owed` 不再拿到空集 |
| `a_turn_inside_the_bound_is_handed_over_whole` | 不超界时原样交出（切点不改正常路径） |
