## 内容

### 为什么这是**一步**而不是两步

`D-222` 诚实划界 5 原写三步（删端口 → 并守卫 → 统一签名与表）。第 2、3 步在类型层上不可分，
理由是可核的：

- "守卫同处"的落点是**那个唯一的循环体**。三张表 + 三个 `Ctx` 类型 → 一旦把循环体抽成一个函数，
  得到的是"三处调用同一个函数"，而 `TC-1a` 判的是**循环体的份数与选债口的份数**，
  三张表意味着三个 `next(..)` 调用点 ⇒ 选债口仍是三个（`TC-1b` 红）。
- 反过来，只要把表与签名合成一个，守卫就已经在那个唯一的循环里了——不需要单独一步去"并"它。

所以 `D-222` 的兑现顺序已按此订正为两步（**先删后裁**：旧的"三步"表述在裁决里被替换，不留两份）。
把两步合成一次提交也不行：删端口是**可独立回退**的形状改动，它与合表失败时的排查面完全不同。

### 三件事，一件比一件深

| # | 要收的东西 | 今天 | 收法 |
|---|---|---|---|
| 1 | **绑定表**（4 → 1） | `ACTORS`（19 行）/ `HEAD_ACTORS`（4）/ `REPORT_ACTORS`（1）／幕那张表（已删） | 合成一张 `ROWS` 的绑定表；表数由 `run` 签名个数唯一决定——签名一种，表就只可能有一张（第二张表是编译错误，`D-222` 可判断言 C） |
| 2 | **签名**（4 种 → 1 种） | `TurnStep` / `HeadStep` / `ReportStep` 三种借用面，动作是 `for<'a> fn(&'a mut X) -> StepFuture<'a>` | 一个 `Ctx`：那一次动作借走的那片状态的**超集**，动作按步取字段；`run(&mut Ctx)` 之后"另一张表"没有对象 |
| 3 | **环**（4 段 → 1 段） | `chat_loop` 的幕间 `loop`（读 `next_stage_round`）/ `drive_steps`（轮内）/ `drive_head`（轮首，从 `prepare_turn_inputs` 里被调用）/ `drive_report`（批次边界，从 `RoundInjector` 里被调用） | 一个循环体。"再开一幕"是 `continue-turn` 一笔债（`D-222` 裁决 2/3：上界 `MAX_STAGE_ROUNDS` 折进那一行的前件）；轮首与批次边界是**行**，由同一个环按 `prio` 与 `owes` 选中（`drive_report` 今天是一次性选债、不是循环体——它属 `TC-1b` 的"第二选债口"那一类，不是 `TC-1a` 的循环体那一类） |

### 第 3 件是真正的难点：一个外层循环 + 两个嵌套点

这三处不是"顺手"，是 `TC-1c` 第五道守卫的三个反例：

- **幕间**：`chat_loop` 的外层 `loop` 读完 `next_stage_round` 决定"再开不开一幕"。它必须变成表上的一笔债
  （`continue-turn`）：轮已经存在，「再跑一段」就有完整的前件（`closure = exhausted` ∧ 轮次未到上限）与出口
  （新的 `round` 格）。留在代码里就是"按步骤号决定下一步"——判据 2 的最后一格（`D-222` 裁决 2/3）。

- **轮首**：`prepare_turn_inputs` 末尾调 `drive_head`。它之所以能成立，是因为那时的 `TurnState`
  还没有被轮内借走。合表之后，`policy.classify` / `policy.compress` / `policy.recall` / `policy.reflex`
  四行就是环的**开头几步**——幕一开，环先按 `prio` 选中它们，`execute-turn`（60）自然排在后面。
- **批次边界**：`RoundInjector` 每批工具跑完就自己调 `drive_report`。它之所以是嵌套，是因为
  "跑完一批工具"发生在 `dispatch-tools` 这个**动作内部**；而环本来就停在两次动作之间——
  把派发撤掉，`policy.report` 的 `report_due` 前件在下一问问表时天然为真，环自己会选中它。
  这一条同时解释了"为什么它有一个专用视图"：**视图是给选债用的，不是给回调用的**。

**判据形态**：合成之后，"再起一个环"应当**写不出来**——动作只拿到 `&mut Ctx`，
拿不到第二个 `&mut Session`/`&dyn Store` 的组合。类型守不住的地方（比如把 `store` 也放进 `Ctx`）
就是设计没做完，不许用运行期 `if` 补。

### 不做什么

- **不动求解器**：`ring::drive`（选债半边）字节冻结；本任务动的是调用它的那一侧。
- **不动 `TurnState` 的字段**：只把它从"三个借用面各自持有"变成"一个 `Ctx` 里的一项"。
  字段收敛归 [T-013](013-冗余残留收敛.md "T-013-冗余残留收敛")。
- **不删行**：19+4+1 行合成一张表之后**行数不变**。行的增删属各自的行化裁决，不属本任务。
- **不改 `MAX_STEPS_PER_DRIVE` 的取值**：上界是策略（`D-222` 裁决 3 把 `MAX_STAGE_ROUNDS` 折进前件，
  那一条在 T-005 随幕一起消失；轮内上界仍在派发器里，取值不变）。
