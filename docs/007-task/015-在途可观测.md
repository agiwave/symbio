## 内容

### 缺口：失败与成功在返回值上同形（第二处）

`sent` 与 `response` 落在**同一个动作窗口**（`port::dispatch_full` 把 `run().await` 包在中间），
所以在两次选债之间「已派出、未收清」在环里读不出来：

| 事实 | 后果 |
|---|---|
| `stale_sent` 在正常跑里恒空 | 租约看护扫不到任何过期尝试，「接回派发器」只是形式 |
| `waiting` 恒假 | 这个停机理由只在下一次生命读上一次崩溃的日志时才有意义 |
| `TC-1c` 的空账本守卫判「环不前进」 | 在途恰恰是「环合法地不前进」——今天这两种处境在事实面上同形 |

### 终态已裁，照着做（`D-222` 订正 2）

裁决写在 [DE-015-义务环](../../docs/003-design/015-义务环.md "DE-015-义务环") 的 `D-222` 订正 2，
这里只留施工要点：

1. **in-flight 槽**：`dispatch-*` 把「发出 → 等应答 → 落 `response`」整段 `async move` 包成
   future 寄存进 `TurnSession`，`await-*` 的动作 poll 它一次。
2. **借用面已经验过**：`call_model` 的闭包只捕获 `llm` / `tok` / `messages` / `tools` / `sink`
   五个参数，**不捕获 `&mut Prepared`** ⇒ future 不借草稿 ⇒ 槽是
   `Option<Pin<Box<dyn Future<Output = …> + 'a>>>`，代价是 `TurnSession` 带一个生命周期参数。
3. **三处必须同批改**（少一处就是死锁，见裁决正文的表）：`dispatch-*` 的出口、`await-*` 的
   `by`、`no_progress` 守卫。**`by = None` 从此不再表示「在等」**——那件事的唯一表达回到
   `waiting` 视图与 `exhausted{waiting}`。

### 不做什么

- **不把 `now` 加第二个来源**：`D-115` 的输入闭包不动。于是「等了多久」在轮内不流动——
  被判死的仍是上一个幕遗留的在途。要让轮内也判死是另一条裁决（裁决正文的"被否的候选"末条）。
- **不做成「超时即失败」**：判死仍归 `reap` 与 `D-138` 的两条前提（`awaited` ∧ 未到上限）。
- **不动求解器**：`ring::owed` / `ring::drive` 字节冻结（`PTS-003`）。
- **不为 `tool` 端口留旧形状**：模型与工具两条路必须同形。留一套旧的，等于承认有两个派发器。
