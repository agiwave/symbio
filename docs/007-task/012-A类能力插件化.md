# S9：A 类十条能力插件化——不用改架构的正向验证

## 内容

迁移账证明「存量能拆出去」；这一段证明「新增能长出来」。名册 §5.2 里判为 A 的十条——
因果结构、未来预测、世界模型、幂等与重试、因果表征工具、可逆性设计、制造工具（L2）、
抽象协议设计（L4）、人格语气一致、可解释——的共同点是：它们只需要今天已有的扩展面
（事实 / 视图 / 工具 / 效果 / 上下文 / 路由）。

正向验证的判据与 EX-001 同形：**落地 diff 里 `kernel` / `loop` / `session` 为零，`plugin-api` 只允许宿主词汇（behavior 名等）且逐条登记**（口径由 front-matter 的 `exit` 持有）。
如果某一条实测需要改这三个目录、或往 `plugin-api` 加机制，说明它其实不是 A，改判为 B 并先出决策——这正是验证的
价值，而不是失败。

## 处理过程

1. 每条一个能力包（可同包但账里写明），从最小可观察形态开始：先落事实或视图，再补工具 / 段。
2. 每条配一条端到端用例：能力出现 → 读数可见 → 卸任后消失（T3 形状）。
3. 逐条记录 diff：按 `exit` 判——`kernel` / `loop` / `session` 为零、`plugin-api` 只允许宿主词汇并逐条登记；出现其余非零即停下改判。
4. 受限条目（制造工具 L2、抽象协议设计 L4）写清限制：只能造自己插件的工具 / 协议需要第二方。
5. 十条走完后更新名册账与 DE-026 §5 的读数，绿灯后提交。

四条实现约束值得留给后面各条：

1. **能力表键是全表唯一的名字空间（族不参与键）**。`persona` 那条同时有一个挂载行
   `persona`，段若也叫 `persona` 会把挂载行顶掉，而顶掉之后**没有任何报错**——设置页
   少一项、VDFS 少一个挂载点、配置再也改不了。段名因此是 `persona-tone`（`memory` 的
   `agent-memory`、`model` 的 `model-persona` 是同一条纪律），单元测试里有一条结构性
   断言钉着它。
2. **平凡值必须让「装不装本插件」在没配置时逐字无差**。人格出厂为空 ⇒ 一条段都不交
   ⇒ 系统提示词与今天相同。这一条让 `t46` / `t57` 那类提示词形状判据不需要为新插件改
   基线——否则每落一条 A 类能力都要动一遍全局基线，「架构稳定」就成了纸面话。
3. **能力包自己的事实一定要有归宿行**（`ROWS`）。少了它 `seal` 报 `OrphanFact`，整张
   装配表失败；而在**单元测试**里也会失败，因为测试二进制不链接 `loop` —— 协议五格的
   自读行要由测试夹具补（`decl.test.rs` 里的 `protocol_rows`，与 `notes` 同形）。
4. **`plugin-api/src/behaviors.rs` 的行为名常量是宿主词汇，不是控制面 diff**。与
   `#33` / `#39` / `#49` 同档：新增一个常量 + 收进 `KNOWN` 只让插件能按名字声明行为，
   机制面不变宽。因此不逐条重判——按 `exit` 的口径，`kernel` / `loop` / `session` 为零、
   `plugin-api` 只允许这类宿主词汇，落地时在账的读数行里写明「加的是哪个词」；以外的
   机制新增仍走通用补件（不含能力名）并挂 `### D-NNN`。
