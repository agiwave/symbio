# 架构模块化梳理与简化空间评估

## 内容

本任务记录一次完整的架构梳理：从「当前分层是否合理」到「哪里还能简化」，再到**逐条代码核实后的可执行结论**。用户诉求三件事：① 方案写进 sprint 任务；② 推进实施；③ 适当时候 git commit。

### 一、现状分层（已核实，合理）

一次请求自顶向下穿过六层，依赖严格单向、无环（cargo metadata 实测 48 个内部 crate）：

1. 宿主/消费：Tauri 桌面（3 个 IPC 命令）、CLI、Gateway/Telegram 入站插件。
2. 装配/运行时：`symbio`（链接全部插件）、`symbio-host`（每会话一次驱动）。
3. 实现层：33 个插件 crate + 5 个 provider crate。
4. 扩展面：`symbio-plugin-api`（门面，扩展层唯一宿主依赖）、`symbio-contract`（ABI 纯形状）。
5. 机制层：`symbio-sdk`（约 1.4 万行，只依赖内核）。
6. 语法内核：`symbio-kernel`（约 0.9 万行，零内部出边）。
7. 侧挂生成物/设施：`symbio-deploy`、`symbio-testkit`。

**合理性结论**：分层站得住，且纪律被 CI 强制——可疑的「插件反向依赖 `symbio` / 直连 `kernel`」经区分后全是 `dev-dependencies`；生产依赖里唯二直连内核的是控制面 `loop`/`session`（符合 DE-026 影响类规则）。

### 二、原推荐方案（来自对话，逐条核实后**全部否决**）

| 原推荐「可直接动」项 | 核实结论 | 证据 |
|---|---|---|
| 清 34 条零生产调用 `pub fn`（降 AD 基线） | **否决**：逐条查验全部是类型自带的公开构造口/查询口，供第三方插件按契约调用；删除即破坏 ABI | `scripts/baselines/arch-dead-code.json` 的 `why` 全为「契约实现」；`arch-dead-code-audit.mjs` 只对新增零调用判红、基线只许降 |
| 清 session 48 条冻结符号 | **否决**：D-499 于 2026-11-15 已复核确权为「随身份永久保留」，不是欠账；`retire` 明确「不再按日期续期」 | `scripts/exemptions/plugin-session-sdk.json`；`session-retire-audit.mjs` SRA-002/003 |
| 收拢 verify 4 处 `#[path]` 生产源码耦合 | **否决**：这 4 处正是「跑的就是生产源码」这一保证的实现本身，去掉等于废掉验证能力 | `consolidation_fidelity.rs` / `invariants.rs` / `recall_eval.rs` / `termination.rs` 头注释 |
