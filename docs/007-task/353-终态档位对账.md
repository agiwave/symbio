# 终态档位对账——partial 按代码事实收口

## 内容

### 现场

设计登记 `active 90 / retired 2`，其中 **21 篇 `impl: partial`**；与义务环终态直接相关的是
`DE-002 / 021 / 022 / 023 / 025 / 047 / 048 / 051 / 053 / 056`。
`DE-023:31` 仍写「控制面这一半尚未兑现：行的执行体还不能由插件绑定」，
而 `RowHandler` + `submit_row!` 已在 8 个文件落地（`symbio-sdk/src/plugin/rows.rs:158-162`）；
`DE-026:29` 的 T2 才是终态；`DE-056` 自陈 `D-447`「现有绿灯只证明旧判据没被破坏」。

### 判定

把 `partial` 批量改成 `done` 是**最省事**的做法，但它让档位失去意义、且直接违反
「现行文档不写变更史 / 状态只写当前形态」。按终态标准：

1. 逐篇把 `partial` 的**残余项列出来**，每条指认「已落地锚」或「承载它的任务编号」；
   没有归属的残余就是真欠账，登记进本 SPRINT 而不是抹掉。
2. `DE-023:31` 这类**事实性断言**按代码对账：`submit_row!` / `RowHandler` 与
   `capability-ledger-audit` 的 54 行处置表逐条核，结论写进 `DE-023` 正文的当前形态
   （不写「曾经…现已…」），需要改判的地方走 `### D-NNN`。
3. 只有**全部残余都有落地锚**的篇目才把 `impl` 改 `done`；其余保持 `partial` 并写明还差什么
   （`SP-001` 要求 `partial` 的每处残余可解释）。
4. `EX-005` 反向用例栏「今天绿」与状态「已成」的字面歧义，按实际回归用例行为定稿。

exit: 每篇 `partial` 的残余项都有归属或落地锚；改 `done` 的篇目能指得出证据；
`registry-board` 的状态分布与代码一致；`capability-ledger-audit` / `SC-006` 绿。

不做什么：不批量改档、不用文档措辞代替实现、不把「绿灯」当成终态达成的证据。
