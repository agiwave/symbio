## 内容

来源：插件内部模型往返进环 实现批（`b0a1c772`）落地后的回表对账，
[D-122](../003-design/015-义务环.md "DE-015-义务环") 的「实施订正」第 4 条。

**事实**：用户点压缩失败节点上的重试（`ResumeAction::RetryCompaction` ⇒
`chat_loop/wake.rs::process_wake` ⇒ `context/pipeline.rs::retry_compaction` ⇒
`auto_compress_process(..., force = true, compress = None)`）时，摘要那一次模型往返
走的是 `compress_with_snapshot_core` 的 `None` 分支：

```rust
// pipeline.rs，D-122 落地的形状
let result = match compress {
 Some(c) => c.summary(|| run_compression_llm(...)).await..., // 入账：三格 + via=compress/summary
 None => run_compression_llm(...).await, // 轮外：本次不入账
};
```

**为什么 D-122 覆盖不到它**：决策 2 的前提是「要入账就让它进环里发生」，而进环需要两个
东西——`turn` 号与幕锚（`Round` / `Compress` 的 `turn` / `produced_by` / `drive_seq` 三个字段）。
重试压缩是**唤醒路径**（产物），它按定义不产生对话轮次（`WakeOutcome::Done`），
三格里写不下「这属于哪一轮」。这不是实现偷懒：硬凑一个轮号，等于让 `lease` / `retry`
去管辖一个引擎无法按轮重放的往返——正是 D-122 决策 1 拒掉的形状。

**为什么仍要登记**：DE-015 §0「没有别的调度代码」的边界在这里破了一个口，且它是
`obligation-ring-accept` **唯一抓得到**的形态——只有真的触发一次压缩重试，J8 才会
报出 `HTTP = sent(model) + 1`。不登记的话，下一个做实测的人会把它当成本批漏掉的账。

## 三个候选（裁决时挑一个，理由写进 ADR）

1. **给「无轮的往返」一个入账面**：三格的 `turn` 位改成唤醒事实的 id、`produced_by`
 指向那条 `session.wake` 格。代价是 DE-015 要承认「环的成员不都是轮」这个新形状——
 而 `lease`（看护派出未应答的往返）与 `retry`（按尝试号重放）在这条路上的语义要
 一并写清，否则「崩溃后重放到上一次模型请求」对这笔成为假话。
2. **明文出界**：把「轮外重试不入账」写进 DE-015 的覆盖边界，并让判据能**识别**这条
 路径（例如 J8 按 `[Compress] 压缩 LLM 请求开始` 与重试会话的 wake 格相减，或该场景
 单独一条判据），而不是往 `MODEL_PATHS` 的豁免表里加一行——豁免表只许减不许加
 （闭包定义）。
3. **重试也造一个最小轮**：把压缩重试当作一个「只有压缩、没有对话」的轮推进驱动。
 否掉的门槛很低： 正为此类「零模型往返的轮怎么进环」立裁决，两条要一起看，
 不能一条说「轮外不入账」、另一条说「什么都得当轮」。

## 验收口径

1. 裁决先行：一条 ADR 或 DE-015 小节写明选哪个候选、其余两个为什么否掉；未裁决不动模块。
2. 记账路线（候选 1 / 3）的判据：一次**真的触发压缩重试**的 CLI 会话，
 `node scripts/obligation-ring-accept.mjs --homedir=.symbio --session=<sid> --cli-log=<日志> --strict`
 全项通过、J8 差额 0；用例至少一条钉「重试往返的三格带 `via` 且 `turn` 位不是伪造的轮号」。
3. 出界路线（候选 2）的判据：判据脚本里能点名这条路径（专属判据或 J8 的显式分项），
 且反向自检实测过红（把重试路径改回静默 ⇒ 判据报差）。
4. 无论选哪条，`MODEL_PATHS` 的 `exemption` 仍全为 `null`。

## 处理过程

- 2026-10-23 登记（实现批回表对账，D-122 实施订正第 4 条）：`pipeline.rs` 的
 代码注释当时已如实写了「轮外路径（用户主动重试）⇒ 本次不入账」，缺的是**谁在什么时候
 把它销掉**。本任务就是那句注释的归属。

- 2026-10-23：裁决落地。选候选 2，三条理由都在 §5.2 的候选表里：候选 1 需要一个**真轮号**，
  而压缩节点不属于任何一轮（它折叠的是跨轮历史）；候选 3 与 D-125「环覆盖的是欠着的往返、
  不是轮」冲突。**关键判断**：边界本身无害，有害的是它**没有名字**——J8 的差额出现了，
  却没人说得清是哪一笔。所以判据不是「禁止出界」，而是「出界必须有名字且不许超编」。
- 2026-10-23：为什么不用 WAL 判。轮外那一笔在事实层**零痕迹**，这正是要说的那件事；
  改从日志数（`[Compress] 压缩 LLM 请求开始` 两个分支都打），并在 `retry_compaction`
  里加一行 `[Wake] RetryCompaction` 作**具名**来源——具名由代码位置保证，不由文档承诺。
- 2026-10-23：J8 的等式也跟着改。此前 `expect = sent + 豁免`，重试一出现就必然红；
  现在多一项「未入账摘要」，J8 只判「差额 = 未入账摘要」，J9 再判「未入账摘要 ≤ 具名重试」。
  两半分开放，是为了让「差额是哪一类」与「这一类有没有超编」各有一条判据。
