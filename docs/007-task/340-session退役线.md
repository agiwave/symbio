# session 退役线

## 内容

把控制面 `symbio-plugin-session` 的退役从「八条决策里的一句『随 session 退役同批删除』」
变成**有范围、有出口、有进度尺**的一条线。裁决是
[DE-054-判据欠账与到期豁免](../003-design/054-判据欠账与到期豁免.md) 的 `D-451`。

终态不是「删三万行」。三条边里只有**一条**是施工边（开轮 596 + 装配折叠 208 = 804 行），其余
两条各自的入场券答完之后都改判了：边一是**读数**（`D-456`）、边三是**验收条件**（`D-458`）。
`D-461` 之后多出**第四条边（读侧归位）**：它不来自 `D-451` 的三条，而是义务环判定式在读侧的
推论——本插件折的是别人写的载荷，那本账就该还给写方（已落：两本账 287 行搬回 `model`）。
而三条边只点到全 crate 的 30.9%（`D-457`），剩下的 69.1% 不是空壳：地址面 20.1% 是 CLI 与
子智能体都在写的外部契约，它没有边，也还没写出换 owner 的入场券。

**顺序在 `D-456` 改过一次**：`D-451` 原写「边一 → 边二 → 边三」，本轮按住处量了账本
（`session-retire-audit --breakdown`）发现 82 条里 67 条住在边二 / 边三 要搬的代码里——
边一归零依赖那两条边，那两条边又被规定要等边一归零，这条线**开不了工**。`D-456` 把边一
重新定性为**读数**（不是施工段），施工顺序改为「边二 → 边三」，边一的账随它们下降：

1. **边一（读数）**：`session → sdk` 的符号面 82 → 0。**它没有自己的施工动作**——每少一条，
   都是边二 / 边三 的代码搬走/改写、或机制归位的结果。其中 **15 条住在三条边都没点到的地**
   （命令面 6 / 统计读侧 5 / 配置 2 / 进度 1 / 投影 1），要单独立账。
2. **边二（施工）**：**开轮**——`plugin/turn.rs`（596 行）与它的装配折叠（`capabilities.rs`
   208 行）。入口原写作「装配换 owner」，**由 `D-457` 改判**：装配的产物在身份上依附开轮
   （`session-config:{user.message 的事实 id}`），换的是开轮本身。开轮同时是存储那一侧的
   调用点（寄存区补落就挂在它的开面路径上）。
3. **边三（不是施工边，是验收条件）**：存储（`store/` 与 `transcript/`，5107 行）。入场券原写作
   「把 `D-081` 的三问在存储侧逐条写成判据」，**由 `D-458` 答完并改判**：三问是 `D-081` 给
   *卸载形*定的**验收条件**（停用 / 收敛 / 照常），不是被搬对象的施工清单。存储不能换 owner
   ——`D-075` 早已判「会话记忆与存储不切出：它们是会话数据本身」，且开面是单槽（登记第二家
   静默生效由链接顺序决定）。所以三问从此是「任何一条边动过之后都要重新过一遍」的验收式。
4. **边四（读侧归位，`D-461` 新开）**：本插件**读别人载荷**折成读数的那些元素。判定式四行
   里它一行都占不上（不欠债、不执行债、不是七职）⇒ 只能降成数据，而「数据归谁」的答案是
   **写它的那个插件**。第一刀已落：`usage` / `spend` 两本账（287 行）搬到
   `crates/symbio-plugin-model/src/ledger.rs`，登记 `slot` = `usage` / `spend`；会话的出口按
   `slot` 收，手工两列退场。**同类的第二格由 `D-462` 答完，但答案不是「搬走」**：
   `projections::changes` 读 `artifact.added` 的 `args.path` / `file_op`——那一格有两个写点
   （`tool` 装基础格、行为 `annotate` 追加富化格）、三个读点（`sdk` 的折叠 / `session` 的
   变更账 / `model` 的回灌），`sdk` 在门面之下，搬给任何一方都够不着；所以入场券换成
   「把键声明出来」：键收进 `symbio-sdk` 的 `effects`，`SV-004` 钉写方键集合与读点字面量。
   `changes` 因此**留在 `session`**——它折的是「本会话的工作目录改过什么」，那是本插件的
   边界，键的契约由词表接着。**尚未作答**：`plugin/nodes.rs` 的工具卡投影（读
   `tool.requested` 的 `calls[]`）——它是呈现面，且 `calls` 这一格还没进词表。
5. **残余（没有边，69.1%）**：地址面 3462 行 + 其余 7809 行（命令面 / 统计读侧 / 配置 /
   活跃名册 / 工作目录）。地址面的入场券**已由 `D-459` 答完**：地址 = `<根>/<挂载名>/<七域>`，
   `<根>` 由 vdfs 插件静态声明、`<挂载名>` 是实例表的键（`session`），所以「换 owner 保地址」
   = 接管挂载名并重写七域，是**重写**不是退役；**不为它登记任务**。其余 7809 行的入场券仍
   写不出（谁消费这条命令面 / 这份统计），不登记。

边二 / 边三 **不登记子任务**：写不出入场券就登记，得到的是「以后再说」的假计划（D-451 §3）。
边二的入场券已由 `D-457` 答完（两问都有答案），但答完之后**出口改了名**——所以本线仍只有
`T-341` 一个子任务（边一的读数线），施工边一个都还没开。

where: `scripts/session-retire-audit.mjs`、`scripts/exemptions/plugin-session-sdk.json`、
`crates/symbio-plugin-session/`。

exit: **不再是「删掉 crate」**（`D-458` / `D-459` 已判：存储与地址面都不能换 owner，它们随身份
`session` 留下）。终态改为**两句话**：

- **能力面归零**：端口 / 工具 / prompt 段 / turn 钩子里不再有 session 贡献的**能力**——这一条
  在 `D-440` 那条线上已经成立，本条线只需守住回潮（门禁 + 反例）；
- **数据面与地址面随身份留下**：`store/`、`transcript/`、`<根>/session/<id>/{MEMORY.md,
  message,inbox,subsession,workdir}` 仍是 `session` 这个身份的一部分，不删、不搬；
- 豁免账（`plugin-session-sdk.json`）**不随退役删除**——它一开始就是符号级冻结白名单，
  「删除」这个出口写不出来（见 `T-341`）。
