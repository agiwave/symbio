# 行去 by——reads 上移与可还性三派生（D-306 施工）

## 内容

### 现场

[DE-048-端口机制裁决](../003-design/048-端口机制裁决.md) 的 `D-306` 裁决一要求「`Decl.by` 移除，『谁执行』与『还不能执行』
都由数据派生」，并给了迁移路径（先补 `reads` → 再删 `by` → 最后删绑定表）。今天的实测：

- `Decl { … }` 构造点 172 处，其中 **28 处**仍带 `by:`（`crates/symbio-plugin-loop/src/vocab.rs:74`
  的 `by: Some(PORT_ACTOR)`、`crates/symbio-plugin-session/src/declarations.rs:158` 的
  `by: Some(PLUGIN_ROW)` 是其中两处，其余为 `by: None`）。
- 内核仍在读它：`crates/symbio-kernel/src/decl/ring.rs:205` 的
  `blocked = decl.by.is_none() || unless.contains(&key)`；`:811` 的 `used_by` 做「每个 `by` 值
  都被某个 actor 用到」的孤儿检查。
- `reads` 仍是 `ActorDecl` 的字段（`crates/symbio-kernel/src/decl/mod.rs:108`），
  不是「这一行可执行前必须已在事实源里成立」的行级前件。
- `D-306` 裁决文本写的「89 处 / 44 个文件」是裁决时点的读数；P2 批删掉 `loop_rows.rs` 的
  16 行之后实际是 28 处。**按今天的数字施工，不照抄旧读数。**

### 判定

这是一条**内核冻结面变更**（`Core-Change` 必须挂 `D-306`）。三个动作有严格顺序，不能并行：

1. **补 `reads`**：给现存每一行声明「这一行可执行前必须已在事实源里成立」的名单
   （事实名或视图名）。旧 `blocked` 里被 `by` 挡住的那些行，其前件要在这一步说清楚——
   否则删 `by` 时它们会从「永远 blocked」变成「永远可还」，那是行为放宽而不是收窄。
2. **删 `by`**：`Decl` 字段集去掉 `by`，`ACTORS` 绑定表、`bound_rows`、`dispatch_gaps`、
   `actor_names` 一并删除；`PORT_ACTOR` / `PLUGIN_ROW` 降为**环内派生**（由 `owes` 是否指向
   `request(port=…)` 判定），不再是 `Decl` 上的字段。
3. **可还性三派生**取代旧判定式：① `reads` 未全部产出（`UnproducedPrecondition`）；
   ② 存在未配对的前序债（按 `(phase, anchor, name, key)` 更小且无 `response` / `failed` 同键事实）；
   ③ 端口 `provider` 缺失或被停用（按 `D-298` 响亮失败，不静默跳过）。
   同时 `unless` 语义收窄为「这笔债不成立」（与 `until` 同键同效）——存量 `unless` 全为空，
   本步不改行为。

### exit

- `Decl` 结构体无 `by` 字段；全仓 `by:` 构造点 **0**；`ACTORS` / `bound_rows` /
  `dispatch_gaps` / `actor_names` 四处标识符 0 处。
- 每一行（含插件自带行）都有行级 `reads`，且 `reads` 的每个名字能在冻结表里解析。
- `cargo test --workspace` 全绿；`arch-shape-audit` 的 `CS-001` 三格不涨（`pub trait` 数 /
  `fn` 成员总数 / 带默认体成员数）；`engine-ledger` / `loop-purity` 绿。
- 提交带 `Core-Change: D-306`；`arch-change-audit` 的 `CC-002` 放行。

### 不做什么

- 不动 `owed` 的求解语义与一笔债的五格；不动 `ring/engine.rs::plan` 的全序取债。
- 不把旧 `unless` 语义（「欠着但没人还」）留成第二套可表达态——它被三条派生替代。
- 不在中间态停留超过本批：`by` 与三派生并存只允许在批次内，收口时 `by` 不得残留。
