# 世界端口注册面：port 族、动态收集、装配期判重与缺席读数

## 内容

`D-298` 选 **(a) 复用 `Registry`**：端口名字与契约静态，提供者随活插件的能力行动态收集。
本任务是那次补件的**注册面**，不含任何端口实现（model / tool 各另立迁移批）。

三样东西：

1. **门面词汇**（`symbio-plugin-api`）：`PortProvider`（`port()` / `provider_id()` 两个声明位）、
   `PortPayload(Arc<dyn PortProvider>)`、`port.model` / `port.tool` 两个 `CapabilityFamily::single`
   与 `port_family(name)`。族名带端口名是**结构所需**：`single` 是族级策略，`put` 按族降位，
   两个端口放同一个 single 族会互相顶掉。
2. **收集**：提供者由插件在 `traverse(TRAVERSE_AVAILABLE_TOOLS)` 里 `put`，行名保留前缀
   `<port:<name>>:<provider_id>`（表键是全表唯一名字空间，端口名当行名会撞同名工具）。
   收集器（`DefaultToolVisitor`）不需要新方法，只按族读行。
3. **装配期读数**：`0` 行 = 缺席；`>1` 行（一活一降）= 判重——`capability_port_check`
   落错误进 `CAPABILITY_ERRORS`（装载期判红）、保留先注册行、不静默顶掉。`demote`
   保证「两个生效者」不可表达，行数保证「静默被顶掉」可判。

## 处理过程

1. 先写失败方向用例：停用提供者插件 ⇒ 该端口 0 行；两个提供者 ⇒ 判重读数成立且错误桶
   有一条；**消费面结构性用例**：port 行在表 ⇒ 六个消费族（工具 / 模型 / 提示词 / 挂载 /
   选项 / 可配置）`list` 全空——读方盘点已确认 `Registry` 读侧全走 `list(family)`，
   `list` 签名要求族参数，仓内无全表遍历读点，结构性用例把这条事实钉住。
2. 落 `plugin-api` 词汇与 `port_family(name)`；不新增 `submit_*` 收集器，不建静态提供者表。
3. 在 `T-024` / `T-025` 的迁移批里只调用这个注册面，不在迁移提交里改它。
4. 单独提交，挂 `Core-Change: D-298`；`EX-007` 输出的补件计数 +1。

## 边界

- 不改 `PortDecl` 字段，不新增端口名；端口仍是 `model` / `tool` 闭集。
- 不把 `port.*` 行混进工具 / 提示词 / 选项 / 可配置的读点；读侧按族过滤，不按名字猜。
- 不新开账本 / 脚本；`EL-001…003` 沿用 `T-014` 的读数。
