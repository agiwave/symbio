## 内容

四件互不依赖的读数，全部复用现有判据框架：

1. **首次落地也要过形态判据**：`EX-001` 今天是 `notes` 夹具；新能力第一次落地时，同样要
   有「四目录 diff = 0 + 端到端出现 / 卸载」的读数，不再只约束迁移提交。
2. **补件比进读数**：`EX-007` 已输出补件次数；门禁汇总同时给出迁移批次数与比值。
   比值 > 1:1 时每次补件必须挂 `### D-NNN` 并在账上写「为什么不能等第二条」。
   读数口径（`D-372`，每轮重算、不手抄）：

   | 读数 | 定义 | 范围 |
   |---|---|---|
   | 迁移批次 | 提交正文含一行 `Migration: <批次>` | `811b2e7d..HEAD`，只数触及五棵受审树的提交 |
   | 补件 | 无 `Migration:`，但在 `sdk` / `kernel` / `plugin-api` 新增非注释、非 import、非生成源码行 | 同上 |

   - `5 → 15` 是时间漂移：`Migration:` 定义未变；同一范围 `811b2e7d..4dc01a57` 新旧脚本都读
     **5**，今天的 15 = 5 + 11-01 后真实落下的 10。没有补计旧迁移，换尺贡献为 0。
   - `20 → 21` = 换尺 **−13** + 时间 **+14**：同范围同日，旧脚本读 20 个补件、今脚本读 7 个；
     差 13 来自旧尺把搬家行（`D-279`）、「碰过机制面」（`D-283`）、注释 / import 重写
     （`59646189`）算成补件。11-01 后真实新增 14 个（7 → 21）。旧 20 与今 21 不可比。
   - 欠账 `debt = 补件 − 迁移`，今天 21 − 15 = 6；按 `D-375` 的台阶递减（`2026-11-10 ≤5` …
     `2026-11-25` 归零）。`GRANDFATHERED` 只豁免逐提交决策号与 `EX-002` 历史本地性，不参与这条读数。
3. **验收编号逐条有 owner**：上一轮验收的三组编号（55 条验收清单、G1-G15、R1-R8）先落纸
   （`docs/004-ref/` 是文件 owner；仓内暂无同编号正文，来源由上一轮评审提供），再逐条映射到
   `EX-xxx`、任务 `exit`、五类残留或新增裁决项。映射表落在该 ref 文档，不另建总账。
