# 冻结表清零撤篇——20 行改指现行代码后撤下过渡机制

## 内容

### 现场

[DE-052-决策正文证据锚点冻结表](../003-design/052-决策正文证据锚点冻结表.md) 是 `D-326` 的附表，也是 [DE-053-环驱动与写口裁决](../003-design/053-环驱动与写口裁决.md) 的
过渡机制。它自己写明了**退役条件**：

> 决策正文里的旧锚点每改指一处现行代码，就从下表删对应行，本表只减不增。
> 表空即撤下本篇与 `scripts/doc-freeze-table.mjs` 的冻结分支，
> `D-017` / `D-005` 恢复对全部决策段按现行代码判；在此期间不新开豁免面。

今天表里有 **20 行**（表头之外），每行的「处置」列已经写了三种状态之一：
「已随 B2 退场（`D-318`）」「现落点」「决策时点的历史文件，仅作溯源」。
也就是说：**每一行其实都已经有结论，缺的是把结论落回决策正文**。

### 判定

逐行的处置动作按「处置」列分三种，不混：

| 处置列现状 | 该做什么 |
|---|---|
| 「现落点」 | 把决策正文里的旧锚点改成这个现落点，然后删行 |
| 「已随 B2 退场」 | 决策正文里的旧锚点不是「改指」，而是**判断这条证据还成不成立**：若该决策的证据本来就在退场文件里，改指到承接它的新落点；若该决策已不依赖这条证据，正文里删掉这句锚点；两种都要在正文留一句「证据改指/撤回」的现形态，不写变更史 |
| 「决策时点的历史文件，仅作溯源」 | 这类是**真历史**：裁决当时的文件确实已不在。处置是把决策正文改成「裁决时点读的是 X，现由 Y 承接」的现形态，然后删行 |

**表空不是终点**：撤下本篇与冻结分支之后，`D-017`（文档引用）与 `D-005`（符号锚点）
会重新对**全部**决策段按现行代码判。所以在删最后一行之前，必须先跑一遍「假设没有冻结表」
的 `doc-link-audit` / `doc-symbol`，确认不会红——否则撤下的当天门禁就红，
下一批只能把冻结表再加回来。

### exit

- 冻结表数据行 **0**；`docs/003-design/052…md` 按 kind 退场（`status: retired` 或删篇，
  按登记机制对「过渡机制撤下」的既有做法）；
- `scripts/doc-freeze-table.mjs` 的冻结分支删除，`doc-link-audit` / `doc-symbol` 不再读它；
- 撤下前跑「无冻结表」判据全绿（`doc-link` / `doc-symbol` / `doc-link-audit` 单测）；
- `registry-audit` 与 `gen-doc-refs` 在 `052` 退场后仍绿（入链已改指）；
- 门禁 `--full --ci` 全绿。

### 不做什么

- **不新增冻结行**（本篇「只减不增」是写死的退役条件）。
- 不逐行 `doc-link-allow` 代替改指——那是把「表外不开口子」换成「满地口子」。
- 不为了「让表快点空」把决策正文整段删掉：证据不成立要写清为什么不成立，
  不能靠删字消失。
