# 终答构造点归一——一个构造器产一种节点树（D-345）

## 内容

### 现场

[DE-053-环驱动与写口裁决](../003-design/053-环驱动与写口裁决.md) 的 `D-345` 登记了一个「只登记、不修」的事实：
`chat.assistant.final` 有两个产出点，各自拼载荷。

`D-345` 的复查（2026-11-10）把问题拆到了比「字段不同」更硬的粒度：**两处交的是两棵不同的树**。

| 路径 | 产出 | 节点拓扑 |
|---|---|---|
| model 端口（work 轮）`emit_outcome` | `produced_nodes` 交 `[Turn 根, Reasoning?, Text?]` | 由 `llm_build_text_node` / `llm_build_tool_call_node` 一族按 `text_id` / `reasoning_id` 合成，**挂在轮下** |
| session `answer.rs::answer_step`（answered 轮） | 载荷内联 `dialog{id,reason,text,exclude_from_context}` | 走 `produced_nodes` 第一支，产一条**根级** `dialog_node`（`parent_id = None`，与用户发言互为兄弟），思考是它的**子节点** |

所以「抽一个 payload 组装函数」不够——抽了也只是让两份载荷长得像，树还是两棵。
而树是**实时面、重建面、按根切窗口与前端渲染共同的输入**。

### 判定

先回答「哪一种树是对的」，再谈归一。两种拓扑各有代价：

- **轮下挂**：与 `turn.dispatch` 的轮锚一致，切窗口按轮切最自然；但 `dialog_node` 的
  `exclude_from_context` 与 `reason` 语义要重新安置。
- **根级兄弟**：与用户发言平级，前端渲染「一问一答」最直接；但与轮锚脱钩，重建时要靠
  `produced_by` 反查轮。

这个选择属**跨 crate 协议面**（`symbio-plugin-model` 与 `symbio-plugin-session` 两个写方），
按 [SP-003](../005-spec/003.md) 先落裁决再施工。`D-345` 已写明「修它要同时改 answered 轮的载荷形状与
model 端口的产出路径」，且与 `DE-053:455` 的「两套 `FactDecl` 登记」同批评估，不拆两轮。

### exit

- 一条 `### D-NNN` 裁「终答节点树的唯一形状」，写明否掉的另一种拓扑的代价；
- `chat.assistant.final` 的节点构造只有一个构造器，两个产出点调它；
- 实时面、重建面（`rebuild`）、按根切窗口、前端渲染四处读到同一棵树——判据是
  「同一条事实在四个面上产出的节点集逐字段相等」的一条单测；
- `DE-053:455` 的 `FactDecl` 两套登记同批处理完毕（合并或裁不合并）；
- `cargo test --workspace` 全绿；前端若受影响，`frontend-build` 绿。

### 不做什么

- 不同批动 `chat.assistant.reported`（进度汇报与终答构造无关，`D-345` 已说明）。
- 不只抽 payload 组装函数就宣称「已归一」——树不统一就不算。
- 不为兼容旧前端同时保留两种拓扑（双写会在重建面产生两份节点）。

- 2026-11-12：登记。`D-345` 的复查已把「字段差异」定位为「节点拓扑差异」，
  本条是它的施工单元；先裁形状，再改两个写方。
