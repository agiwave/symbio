# S10：B 类唯一缺口——多模态载荷形状裁决

## 内容

名册 54 行里只有 #46 多模态判为 B：provider 侧可以插件，但消息载荷的形状在 kernel
（`Event.payload` / `ChatNode`），不裁决就落不下去。这是**数据面**的缺口，不是执行体缺口，
所以它不影响 S6 / S7 的迁移，但必须进账——否则 54 行里会有一行永远停在「待裁决」。

两个候选方向、代价不同：

- **走 `Domain` + 附件引用**：图像 / 音频作为领域事实与产物引用，`ChatNode` 只存引用；
  数据面不动，但多模态内容不进入转写的原生读侧。
- **开放载荷形状**：`Event.payload` / `ChatNode` 接受新的内容种类；表达力最强，
  但撞 `CS-009` 数据面棘轮与回放承诺，必须走决策。

## 处理过程

1. 先写决策：两个方向各自的表达能力、回放影响、门禁影响，给出裁决与理由。
2. 按裁决落最小样本：一个 provider 插件 + 一条端到端用例（内容可见 / 可回放）。
3. 若裁决为「不开放」，把 #46 的处置改为「留 E / 过程体」并写明上限，54 行账随之收口。
4. 同步 DE-026 §2.2 的 B 类条目与名册账，绿灯后提交。
