## 内容

目标不是「少改 core」，而是**扩充能力不再需要改架构模块**：内核只保留语法与装载机制，
插件自己声明身份、路由、装配位、事实、视图与能力行；装配方只决定「接不接」。

顺序按「改一次就少一条进 core 的路径」排：

1. **T-313 插件身份与装配位外移**——`PLUGIN_ID_*` / `ROUTE_*` / `ASSEMBLY_*`
   不再由内核登记。新插件只在插件自己的目录与装配清单里出现。
2. **T-314 能力行开放**——`CapabilityRowKind` 的六个家族不再靠加枚举臂扩展；
   能力行由插件声明，内核只校验形状。
3. **T-315 投影与执行体归位、接入验收**——投影函数与 actor 策略按 owner 归位；
   用「禁用插件 ⇒ 能力消失」的端到端用例把「接入才有能力」钉住。

父任务只定顺序与最终验收；子任务各自写 exit 与证据。
