# 能力面收口 SPRINT——把「判过不落」与「真没做」分开推进

## 内容

### 判定总纲

1. **「判过不落」不是欠账，「真没做」才是**。前者已经有一条 `### D-NNN` 说明为什么不落
   （`D-152` 向量索引、`D-157` 五项能力、`D-108` 申诉触发器），重开条件写在各自条目里；
   把它们塞进任务表会让「承诺」与「边界」混成一列（`D-157` 的判据纪律）。
2. **能力面任务不许改架构来迁就实现**。前端缺一个交互就补交互，不许为了省事在机制面开新格；
   要开格按 [DE-025-能力包与扩展面](../003-design/025-能力包与扩展面.md) §5.1 的两条准入先过（不提能力名 ∧ ≥2 条能力要用）。
3. **一个事实只有一个 owner**：前端不复制后端事实，读 [RE-006-当前事实表](../004-ref/006-当前事实表.md)；
   后端能力「有但前端没消费」与「后端也没有」分开记（[DE-020-前端UI-UX](../003-design/020-前端UI-UX.md) 的两张表已这样分）。
4. 绿灯才算绿：`gate.mjs --full --ci` + `frontend-build` 是出口。

### 入口事实（2026-11-12 实测）

| 面 | 实测 |
|---|---|
| 前端六项 | 多开 / 列表操作 / 断连可见性 / 消息操作 / 命令动作执行 / 无障碍——逐项在 `DE-020` 的「还差什么」表里 |

### 子任务

| 任务 | 目标形状 | 序 |
|---|---|---|
| `T-369-前端六项` | `DE-020` 的六行逐项落地或逐项裁「不做」，不留「还差什么」的形容词 | 一 |

### 不做什么

- 不重开 `D-157` 的五项能力（SC-014…018 是草案，不立项；重开条件是「出现真实消费方且能
  指认一条已有读数作为判据」）。
- 不为前端补一条后端没有的事实（`DE-020` §11 的前件判据：先补事实，再补组件）。
- 不在机制面为「让外部插件接得进来」开豁免（`EX-008` 的边界）。
