# 前端六项——逐项落地或逐项裁「不做」

## 内容

### 现场

[DE-020-前端UI-UX](../003-design/020-前端UI-UX.md) 的「还差什么」表有六行，逐行都是**后端有能力或不必后端**的交互缺口：

| 面 | 还差什么 | 判据要点 |
|---|---|---|
| 会话多开 | 单 `activeId`，切会话靠重挂载 | 真多标签要状态按 id 分区，不能靠「重挂载时重读」 |
| 列表操作 | 无拖拽 / 无右键菜单 / 无批量 | 批量操作要有撤销，否则误删不可逆 |
| 断连可见性 | 自动重连在跑，没有全局连接状态面 | 状态要从真实连接事件来，不是定时器猜 |
| 消息操作 | 有编辑，无「编辑后重发」、无悬浮操作条 | 「编辑后重发」是**新轮**还是**改旧轮**要先定 |
| 命令动作 | 面板只做跳转，「切模型 / 切工作区 / 跳设置」要的是执行 | 执行要落事实，不能只改前端 store |
| 无障碍 | 消息节点与卡片已键盘可达，其余以点击为中心 | 焦点顺序与快捷键是判据，不是「加了 tabindex」 |

### 判定

六行的**工作量差一个量级**，不能合成一个「前端优化」批次：

- **一行代码级**：断连可见性（把已有重连事件接到一个状态组件）、命令动作执行（三个动作各一条）。
- **一轮交互设计**：消息操作（编辑后重发涉及「改旧轮」与「新轮」两种语义，选错会污染转写）。
- **一块子系统**：会话多开（状态分区 + 路由 + 持久化）、列表操作（拖拽 + 菜单 + 批量 + 撤销）。

所以本任务按「一提交一件事」拆成六次提交，**不追求一次全绿**；每行的出口是
「有落地锚」或「有一条 `D-NNN` 说为什么不做」，不是「看起来好一点」。

**「编辑后重发」先裁决**：它要么落一条新事实（新轮），要么改写旧轮（`message.removed` +
新答），两条对重建面的影响完全不同。这条属机制面语义，按 [SP-003](../005-spec/003.md) 先裁再写。

### exit

- `DE-020` 的六行逐行改写：落地锚（组件路径 + 判据）或裁决号；
- 涉及事实面的（消息重发、命令动作）有对应 `### D-NNN`；
- `frontend-build` 绿、前端单测绿、`gate.mjs --full --ci` 绿；
- 不引入第二份后端事实（前端不自己算「会话有几条消息」这类读数）。

### 不做什么

- 不把「后端有能力、前端没消费」与「后端也没有」混成一条（`DE-020` 已分两张表）。
- 不为了「补齐六项」给后端开新事实——需要新事实的先回设计文档立判据。
- 不在没有撤销的前提下做批量删除。
