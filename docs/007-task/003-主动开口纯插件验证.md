# S2：主动开口——零机制改动的 T1/T2/T3 模板

## 内容

主动开口是三个代表能力里唯一**今天什么都不缺**的：heartbeat 已经是插件，自带常驻扫描、
经路由写收件箱，不碰 `loop` 内部。它的价值不是「再搬一次」，而是证明
「插件能承载能力」不是假想，并把 T1 / T2 / T3 的模板冻结下来给后面两段照抄。

本段不改机制：只补**卸载读数**与**零 diff 读数**。若这里需要动 `loop` / `session`
才能让主动开口可卸载，说明模板不成立，必须回到 [DE-026-能力拆分与影响类](../003-design/026-能力拆分与影响类.md "DE-026-能力拆分与影响类") 重新裁决，而不是就地打补丁。

## 处理过程

1. 写 T3 用例：摘除装配行 ⇒ 系统完整运行、工具面 / 路由 / 上下文段不出现该能力的任何痕迹。
2. 写 T1 读数：记录装配前后 `core` / `kernel` / `loop` / `session` 的目录指纹。
3. 核对 `EX-004` 的反向用例：卸载后仍有一处按名字生效必须红。
4. 绿灯后提交，模板（用例形状 + 读数口径）留给 S6 / S7 复用。
