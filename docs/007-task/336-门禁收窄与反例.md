  降级为漂移对照（只 dim、不进 problems、不影响退出码）；夹具含未声明端口 `custom_probe`
  仍通过。23/23 绿，J1~J9 其余一条未放宽。
- 新增 `scripts/port-type-coupling-audit.mjs`（PTC-001/002）与
  `scripts/dynamic-port-registration-audit.mjs`（DPR-001…004），两份各带回归测试，
  且都接进了 `scripts/gate.d/30-docs.mjs` 的 `GUARDS`——`gate-wiring-audit` 因此从
  「4 处接线失效」转绿。
- 七类反例里有六类有可跑判据：wire 碰撞
  （`crates/symbio-plugin-session/src/plugin/turn.test.rs::wire_collision_is_rejected_before_the_request_is_shaped`）、
  未暴露名称（`crates/symbio-plugin-tool/src/port.test.rs::resolve_only_accepts_this_rounds_exposure_aliases`
  + 派发落 `NotFound`）、空工具集（`orphan_description_row_is_not_exposed` 的空绑定集分支）、
  同名绑定覆盖（host 装配期 `Err` + DPR-002）、子 Agent 泄漏
  （`crates/symbio-plugin-agent/src/host/scope.rs` 的端口键判重留痕）、
  **MCP 变化误绑**（`a_changed_mcp_tool_set_never_rebinds_last_rounds_wire_name`：
  上游服务换掉 `mcp.fs.read` 之后，上一轮那个 `mcp__fs__read` 不得被任何本轮身份占用）。

**未落地**：

1. **非法参数**一类还没有判据：`plugin-tool` 侧没有「参数不合 Schema 时不得执行执行体、
   只落失败事实」的反例（当前 4 份 `.test.rs` 与 `e2e/cases/` 里都搜不到）。开账路径
   （`crates/symbio-plugin-tool/src/port.rs` 的 `open_only` 段）对 `arguments` 是
   `unwrap_or(Value::Null)` 直通，没有形状校验——先要决定「谁来判 Schema」，才谈得上反例。
2. **核心形状 / 门面 / 端口三项审计收窄**未做：`arch-shape-audit`（CS-001 三格棘轮）、
   `plugin-surface-audit`（HS-002 / HS-006 门面白名单）、`port-surface-audit`（PTS-002 取值
   表）的基线仍是 D-440 之前的口径。本轮改动没有让任何一格变宽（`NoOpenScope` 是类型
   替换，不增字段），但那只是「没变宽」，不是「专门判只收不放」。

where: `scripts/port-type-coupling-audit.mjs`、`scripts/dynamic-port-registration-audit.mjs`、
`crates/symbio-plugin-tool/src/port.test.rs`、`e2e/cases/`、`scripts/arch-shape-audit.mjs`、
`scripts/plugin-surface-audit.mjs`、`scripts/port-surface-audit.mjs`。

exit: 七类反例逐条有正向 / 反向夹具；新增自定义端口不改验收表即可通过 J6；类型耦合审计能
判出 `PortReply` 绑模型消息；核心形状、门面、端口三项审计基线只收不放。
