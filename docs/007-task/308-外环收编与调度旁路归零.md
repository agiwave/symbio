## 内容

T-282 把「旁路直调 8 → 0」的单一口径拆成两类（裁见 DE-015 的 D-158）：

| 类 | 现数 | 归属 |
|---|--:|---|
| 调度旁路（未接执行体的行被外层代码直问） | 4（`recall` 已在第一批接回） | **本任务** |
| 幂等点问（执行体动手前复核本行，承认在册） | 3 | 已收口，不归零 |

现数的 owner 是 `BYPASS_BASELINE` 与 DE-090 §3，本表只为读任务时不必跳转。

**为什么把它们直接注册进派发面会坏**：`policy.*` 五行按格分形（D-107 之后 A1–A3 推迟的后果），
它们的动作需要「轮首上下文」——把行注册进派发面后，`drive_steps` 会按 `prio` 选中它
（`classify` = 10 抢先于 `close-turn` = 55），而那一步的 `entry_of` 在轮首之外取不到锚点，
`next()` 直接空 ⇒ 整轮以 `exhausted{no_progress}` 收尾。`policy.reflex` 的 `until` 就是
`turn_closed`（它的动作本身是收幕），`policy.report` 的触发点在 runner 的批边界。
这三条凑在一起说明：**缺的不是把七个调用点挪进引擎，而是外环的形状**——
「一张行表 + 按 host 分片的绑定表」，让每行自己回答「现在该不该做」，而不是把直线七步
换成假的不动点。那个形状此前在 DE-090 §1.1.2 标着「尚未开始」，也不在 §1 的六个迁移步里。

所以归零有一个前件，而不只是一个目标。本任务承接那个前件。

## 处理过程

- 2026-10-25：自 T-282 拆出。T-282 交付的是口径（两类计数、承认标记带 `by: Some` 的牙、
  反向用例与生产形状用例），本任务承接被 D-158 判为「有前件」的那一半。
- 2026-10-25：形状立成裁决 **D-159**（DE-015）——host = 执行体被 `&mut` 借走的那片可变状态，
  一个 host 一张绑定表，行的 host 归属**只从绑定表派生**（不在 `Decl` 上加 `host` 字段，那与
  `by` 是两个 owner 且能互相矛盾而装载不红）；装载面仍一张表（两片 `ActorDecl` 并进同一个
  `load()`，七道检查与 `symbio_core` 一字不动）；每个派发点向 `ring::drive` 传由自己绑定表派生的
  行子集（传整张表会被别的 host 的低 `prio` 债堵死）；执行体不交回产出（D-123 决策 5 照用，
  轮首的出口寄存进本轮状态）。五行归位：`classify` / `compress` / `recall` / `reflex` 住 `Head`，
  `report` 住 `Turn`——批次边界只是轮内的一个派发点，`report_due` 的静默判据自己决定何时轮到它，
  外层数批次的 `AtomicUsize` 与 `RoundHook` 随之退场。施工分批：机械 + 一行接回（`recall`）先行，
  `BYPASS_BASELINE` 按接回的行列降，五行接净才到 0。
- 2026-10-25：**第一批落地**（机械 + `recall` 接回）。轮首那台 host 立成 `loop/head_exec.rs`
  （`HeadStep` = 本轮状态 + 会话上下文 + 请求句柄 + 事实源，`HeadAction` 与轮内 `Action` 同形状）；
  `loop_rows.rs` 添 `HEAD_ACTORS` 绑定表，行子集由绑定表的名字派生（`host_rows`），轮首选债口
  `next_head` 与轮内 `next` 共用同一个 `pick` / 同一个求解器；`actor_decls()` 把两片 `ActorDecl`
  并进同一个 `load()`（装载面仍一张表）。`chat_loop/inputs.rs` 步骤 ⑤ 的 `owes("policy.recall")`
  直问换成 `drive_head`，`run_recall` 就此成为**执行体**：它自己落 `turn.stage{stage:"recall"}`
  那一格（带 `identity = drive_seq`，续写幕要重跑），「草稿交运行器落」那处寄存对这一行退场——
  不落格的执行体让派发点在下一问仍读到「没做过」，环一步都走不动。
- 2026-10-25：接回后装载红 29 例（`Gap::DependencyCycle { execute-turn ↔ policy.recall }`）。
  根因不在行形状，在**配图口径**：依赖图把视图出口按 `reads` 全集展开，而 `reads` 里混着
  「只帮我算锚点」的事实——共写 `turn.stage` 一族的行于是两两互等成假环。裁 **D-160**
  （DE-015）：`ViewDecl` 加 `evidence`（输出证据集 = 它替哪些事实关门），第 1 条按它展开，
  第 6 条仍按 `reads`（判的是执行体有没有能力写到出口线上的格，保守一档只多不少），装载期查
  `evidence ⊆ reads`（缺口 `Gap::EvidenceNotRead`——写一个没读的名字等于静默删一条边，
  比假环更难定位）。被否的便宜路线五条（拆 `turn.resume` / 本批顺带搬 `classify` + `compress` /
  出口写原始事实 / 每台 host 一张图 / 派发器代执行体落格）记在同一条裁决里。
- 判据与用例面：`BYPASS_BASELINE` 5 → 4（`35-baseline` 的 `obligation-bypass` 同格随脚本走）；
  DE-090 §1.1.3 的四分类（③ 待接执行体 5 → 4）与 §3 / §6 现数同步。新增用例六条——
  轮首派发三点（选中 `policy.recall` 并交出 `run_recall`；出口格落地即 `None`，反向去掉那一格
  又欠账；行子集不互抢：整张表的最小债是轮首那一行，故派发点不收整张表）、core 三点
