## 内容

一个迭代批次的父任务，不自己动手：本批的全部施工由子任务承载（闭环的按「收口即删」退场，只留 git 历史）。

### 为什么立这一批

控制面的**设计早已裁过终态**，实现停在一个形状上：

- [DE-015-义务环](../003-design/015-义务环.md "DE-015-义务环") §2.1 写的是**一段** `drive`——
  中止 / 步数上界 / 空账本 / 写封闭四道守卫全在同一层循环里，末尾一句"没有别的调度代码"。
  代码里有**四段**这样的循环，守卫各缺一部分。
- `D-168`（已删除）原裁"幕是迭代单位，开一幕是迭代器不是一笔债"，
  而 [DE-022-行表与派发面](../003-design/022-行表与派发面.md "DE-022-行表与派发面") §1.2
  把"本轮执行"列为端口之一——**幕既是迭代器又是一笔往返**，两句话不能同时为真。
  这个冲突已按「先删后裁」处理：两边一起删，[DE-015](../003-design/015-义务环.md "DE-015-义务环")
  的 `D-222` 重裁为「幕是身份，不是端口也不是迭代器」。
- [DE-002-架构总览](../003-design/002-架构总览.md "DE-002-架构总览") §3 的
  "清单会增长，判据不会"在控制面被违反：控制面判据码 30 余条，其中多条断言的是**过渡构件有几份**
  （host 数、旁路基线、幂等点问条数），而不是终态结构。

所以本批的正当性不是"换一种架构"，而是**让实现与已生效的裁决一致**，并把那些会挡住收敛的判据
按 [SP-033](../005-spec/033.md "SP-033") 的 `J0` 降为读数。

### 覆盖核对时发现的三处问题（两处已按"先删后裁"改掉，第三处是报告自身的账）

1. **`TC-1c` 少了一道守卫**：报告 §4.3 的表有五行（中止 / 步数 / 空账本 / 写封闭 / **环不重入**），
   而 `TC-1c` 只写了四道。`V-F2` 因此**没有任何执行方**——F 组 0/5 里就有这一条。
   已改：`TC-1c` 收五道，第五道"不重入"由**类型**守（动作只拿得到 `&mut Ctx`），判据判"签名给不给得出第二份"。
2. **报告 §4.3 的"四段循环"清单与代码不符**（不影响任何承载，但影响分工）：
   报告把 `drive_report` 算作一段循环、漏掉了 `chat_loop` 里的**幕间** `loop`（读 `next_stage_round` 决定再开不开一幕）。
   按源码，控制面的循环体是四段——`chat_loop:306`（幕间）/ `head_exec:146`（轮首）/ `stage_exec:547`（幕内行）/
   `turn_exec:919`（轮内）；`drive_report` 是**一次性选债**，不是循环体。于是：
   `T-005` 删的是"幕内行"那一段（4 → 3），第二步（一个环）收的是"幕间 + 轮首 + 批次边界"三处（3 → 1），
   而 `drive_report` 归 `TC-1b`（第二选债口）而不是 `TC-1a`（循环体份数）。
3. **`D-222` 的兑现顺序是三步，实际只能两步**：原写"删端口 → 并守卫 → 统一签名与表"。
   但"守卫同处"的落点是那个唯一的循环体，而唯一循环体的前提是一张表一个签名——
   先并守卫只能得到"三处调用同一个函数"，选债口仍有三处（`TC-1b` 红）。
   已改：`D-222` 诚实划界 5 订正为两步，第 2 步把表、签名、环、守卫一起收（**已成**）。

### 边界（本批不做）

- **不改 `symbio-kernel` 的求解器语义**：`ring.rs` 的 `owed` / `drive` 字节冻结仍然有效，
  本批只动编排层与"谁调用求解器"。
- **不为"更好看"重命名**：`Turn*` 类型名的清理不在范围内——名字只是症状，越界的位置才是问题。
  唯一的例外是 `R8` 的**同名不同义**（两义同名是病），处置归 T-013。
- **不动其它判据命名空间**：文档登记（`RG-*`）、插件入口（`E-*`）、SLO（`SX-*`）等不在本批范围。
- **不以"实现困难"改设计**：任何一条裁决需要改设计文本时，走 [DE-015-义务环](../003-design/015-义务环.md "DE-015-义务环")
  的关键决策节，不在实现里绕。

树只画还有 `deps` 边的项。`T-011` 的前置（端口组退场、视图超界、`model` 端口的在途可观测）
都已闭环，`tool` 端口的同一件事（`D-124` 订正 1）也已闭环，与上面各条互不阻塞，因此都不再画边——
**前置闭环即摘边**，闭环的编号不是门槛。

判据面先收敛（`SP-033` 已 active）→ 取基线（T-010）→ 两步形状收敛（T-005 / 一个环）→
三条互不冲突的清理（T-006 / T-013 / T-014）→ 判据执行方（T-007）→ 演练（T-008）。
**验收标准先于实施**在这里的具体形态：`SP-033` 的六条判据先落纸，执行方后落地，
落地时不许为迁就形状改判据（改判据必须引 `TC-n` 或 `J0`）。
