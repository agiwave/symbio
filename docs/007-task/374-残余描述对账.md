# 残余描述对账——六篇里「已收口 / 判过不落」的残余句子改成实测现状

## 内容

### 现场

`D-484` 那张 16 行表是「一次看完」的产物，但它读的是**文档措辞**。逐条核代码之后，六篇的
残余句子与实况不符，且不符的方向一致——**把「已经收口的」写成了「还在做」**：

| 篇 | 现在写的 | 实测 |
|---|---|---|
| 002 §4 末 | 「迁移批次与『本步不做』的正当性判据归 SP-003；本文不记录进度」 | 这句本身没错，缺的是**出口**：`D-313` 的 P2 六刀绿点已全部回填，`chat_loop` / `turn_exec` / `turn_runner` / `tool_dispatch` / `tools` 五个模块已删。应当写清「P2 迁移已按 `D-313` 收官」，不然读者会以为它还在跑 |
| 019 §2 盘点表 | 「Typing 占位：『兄弟到达即替换』未逐条核过，仍按原判定留着」「后端定显示策略：加 `presentation_tree` 开关」 | `presentation_tree` **已落地**（`config.rs` 的 `default_presentation_tree` + `chat_session/read.rs` 的读点 + 用例 `presentation_tree_defaults_to_grouped_and_parses_known_values`）——「差什么」那一格不再成立；Typing 的替换规则仍未核 |
| 020「还差什么」表 | 六行缺口（多开 / 列表操作 / 断连可见性 / 消息操作 / 命令执行 / 无障碍） | `D-485` 已逐行结账：断连可见性落地，其余五行裁「留档不做」并各写重开条件。表里六行仍是**缺口叙述**，没有一行指向裁决 |
| 021 §8 施工顺序 | 七批标「已落」——**这一篇已经写对了** | 但 §2 的「一条新时机改 **3 处** + 1 调用点」仍按旧口径写：`A2` / `A3` 落地后调用点已不存在；剩下的是 `prio` 占位这个**承认的代价** |
| 040 §3.1 | 「`recall:min_generality` 未落地」 | 与 `D-151` 的「四个参数逐条判过不落」并列时读起来像两件事：`min_generality` 是第五个、也是**判过不落**（缺分级器），不是「待落地」 |
| 047 §6 | `D-313` 的绿点清单被 `D-484` 引作「进度表」 | 它已经是**完成记录**：P2-1…P2-6 每条后面都是提交号。`D-484` 该改词 |
| 054 `D-484` 表 | 002 / 019 / 020 / 040 / 047 五行的「残余」列 | 同上；这一列是本次对账的对象 |

### 判定

**只改「残余」这一层，不动设计结论。** 三条写法规则：

1. **已收口的**：写成「落地锚 + 判据在哪」，不留「仍在进行」。
2. **判过不落的**：写成「`D-NNN` 判过不落，缺件是 X」，不留「未落地」——「未落地」暗示有人
   该去做，而它已经有结论。
3. **等条件的**：写成「重开信号（可观测）+ 谁等谁」，不留「待定」「排期待定」。

### 判据

- `node scripts/doc-link-audit.mjs` 的 `D-003`（行数预算）/ `D-004`（无变更史）/ `D-016`
  （非任务文档不引 `T-`）全绿——已收口的条目一律写**落地锚**，不写任务号；
- `node scripts/doc-section-audit.mjs` 绿（小节寻址）；
- `D-484` 的 16 行里，每行的「残余」列要么是空、要么是等条件 + 信号、要么指到一项任务；
- 门禁 `--only=docs --ci` 绿。

### 不做什么

- 不改任何 `### D-NNN` 的裁决正文（只改叙述段的现状描述）；
- 不给「等条件」的条目补一个假任务来「看起来在推进」；
- 不在六篇里复制 `D-484` 的表（同一份事实写七遍，改一次动七处）。
