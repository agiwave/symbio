## 内容

### 越界清单（尺子出自 `SP-033` 的 `TC-2`）

`turn` 合法出现的位置只有两个：**事实信封**（分区键，`owed` 的输入靠它才有限）与
**切片函数**（成本界）。一旦它开始回答"谁跑谁"，就比七个词多了一个。四处越界的现状与收法：

| 越界 | 位置 | 收法 |
|---|---|---|
| 端口名 | `PORTS` 里的 `turn` | **T-005 已删**；本任务只核"`PORTS` 里没有以幕命名的项" |
| 行键 | `close-turn` / `execute-turn` 的 `key` 只有 `["turn"]` | 键改成让位前件的那几格（与 `model` 端口同形）。一行以"幕"为键 ⇒ 一幕只能还一次，而"再还一次"恰恰是常态 |
| 调度分支 | `turn_round` 视图 + 幕间两个判据 | 折进"幕是否还开着"的一个格，不再作为任何判据的分支条件 |
| core 交付域 | `crates/symbio-core/src/turn`（788 行） | 只留 session→loop 的 DTO；`TurnState` / `TurnRunner` 不进 core |

### 为什么这一条不能留给"顺手改"

越界不是命名问题。行键决定"这笔债何时成立"，调度分支决定"下一步跑谁"。
**只要其中一处还在，`TC-1` 的"唯一循环体"就必须通过特判来满足**——两件事是同一个形状的两面。

### 词义扩散的那一处（最靠里）

模型端口的 trait 方法叫 `execute_turn`、返回 `TurnOutput`（`kernel/src/llm/model_provider.rs`、`llm/turn.rs`）——
语义上它只是"一次模型往返的产物"，却与曾经的 `port="turn"`（整幕）共用一词。读 trait 的人会以为
模型端口按轮执行。`D-222` 裁决 7 已经把行名改成 `announce-model`，trait 这一处同批改，口径才一致。

### `G14` 为什么是"保留"而不是"该收"

`turn_slice` 按轮裁日志，看起来像"把一个事实日志切成 N 份"。但它是 `owed` 成本界的**唯一**来源
（视图按幕声明 `cost`）——没有它，`owed` 要在整份日志上求值。所以 `D-222` §二 把它留在"合法两处"
之内，本任务在这条读数上写明"保留 + 理由"，不再作为缺口。

### 不做什么

- **不清理 `Turn*` 类型名**：名字是症状，位置才是病；体量与同名不同义归 [T-013](013-冗余残留收敛.md "T-013-冗余残留收敛")。
- **不动 `TurnState` 的寄存语义来源**：字段减少是 T-013 的结果，不是本任务的手段。
- **不留"两种表达并存"**：`turn_round` 视图与"幕还开着"的格同时存在，必然出现"哪一处算幕跑完了"的双真源。

**行键为什么单开一刀**（下一刀的入口，含一条查出来的硬约束）：

- 查了事实层：`I1` 要求**每 `turn` 至多一条 `final`**，而收束格的幂等键是 `f-{turn}`。
  两条合起来 ⇒ **一幕不可能收束两次**。所以「再还一次」在**收束**这一侧不成立，
  `close-turn` 的键取幕是对的，改它只会把一个正确的不变量写成一条假债。
- 「再还一次」成立的是**宣布**那一侧：一幕里可以有 N 次模型往返（工具循环），
  而 `announce-model` 的键只有 `["turn"]` ⇒ 一笔债要被还 N 次。`model_open` 那一格
  就是为这个补的补丁：它让同一笔债在往返在飞时让位，否则 `prio` 60 会压过 66 再宣布一笔。
  补丁本身说明键选错了对象——键该是「这一次往返」，不是「这一幕」。
- **收法**（下一刀）：行键取**它要还的那一格的身份格** `(port, id, attempt)`，与 `model`
  端口的另两行同形。新增视图 `next_round_trip`：折叠 `turn_head`，只在「幕未收束 ∧
  没有开着的工具批 ∧ 没有在飞往返 ∧ 快路未答」时吐出一笔
  `{port: "model", id: "model-{turn}-d{anchor}-s{n}", attempt: 1}`（`n` = 本幕已宣布的
  往返数，与 `Prepared::step` 同口径）；行的 `until` 就是那一笔 `request`。于是
  `model_open` 从行上退场，键面也不再以幕为唯一键。
- 这一刀要动 `turn_head`（补一格 `closed` 供视图判「幕收束了没有」）与那一批按旧键写的
  用例，改动面比改名大一个量级，所以与词义/漂移分开提交、分开回退。

**调度分支这一项收不了，不是遗漏**：`turn_round` 视图已随 `T-005` 退场，剩下的
`next_stage_round`（「`closure = exhausted` ∧ 轮次未到上限」两条判据）在 `chat_loop` 的
幕间分支上。它的终态是 `continue-turn` 一行（`D-222` 裁决 2/3），而那一条行归
[T-011](011-一个环.md "T-011-一个环")——行不立，判据就只能留在调用点。
