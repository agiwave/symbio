# 同一轮第二次提问的 tool_call 卡在消息面缺失

> **已裁 `D-382`：选 (a) 批内多卡。** 卡的存在改由 `tool.requested.calls[]` 决定，不再绑在
> 助手往返上；三条围栏写在决策里：① 只改消息面形状与配对，债行配对一律不碰；
> ② 不做两套读法，同一 `request_id` 下按 `call_id` 排序、只有一份投影；③ 恢复锚点仍要补，
> 落到多卡形状上。实现排在 `T-008` 收口后、`T-009` 之前。

## 内容

写方齐全：第二次 `tool.requested`、`artifact.added{needs_user_action: true}` 与
`user_prompt` 的投影事实都在；读方缺口：消息面只出现第一张 tool_call 卡，第二次提问的
`call_ask_2-result`（`user_prompt` / `waiting_user_action`）直接挂在轮节点下，
没有父调用卡。

后果与「写方在、读方没有」同型：写侧每一格都真，用户看到的却是「一张卡 + 一个没有
来处的提问」；恢复入口按调用节点 id 找提问时也找不到正确的锚点。

**触发条件**：出现「同一轮两次提问 / 连续两次审批」的需求或用例时，先处理本条。
它与「债行同族写法」台账里的批债 / 逐笔债同一片区域，**不要在配对改造里顺手带过**。

## 处理过程

1. 按 `D-382` 改卡的存在来源：`rebuild` 的 `tool.requested` 臂出卡，实时面与它同源；
   助手 `tool_calls[]` 只供增量内容。`node_of_call` 合并两个来源。
2. 同 `request_id` 下按 `call_id` 排序，`node_id` 重复只认首次；顺手把恢复锚点按 wire id
   落到具体那张卡。
3. 补 e2e（同轮两次提问的完整回路），落地后从 `RE-014` §7 的「已转出」条里摘掉本条。
