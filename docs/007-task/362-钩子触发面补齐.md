# 钩子触发面补齐——12 个无产者的变体要么有产者要么有裁决

## 内容

### 现场

`crates/symbio-plugin-api/src/hooks.rs` 定义了 **14 个** `HookEvent` 变体，
生产代码里只有 **2 个**有触发点：

| 有产者 | 位置 |
|---|---|
| `PreToolUse` | `crates/symbio-plugin-tool/src/port.rs:1796` |
| `PostToolUse` | `crates/symbio-plugin-tool/src/port.rs:1216` |

**12 个没有任何产者**：`PostToolUseFailure`、`Notification`、`UserPromptSubmit`、
`SessionStart`、`SessionEnd`、`Stop`、`SubagentStart`、`SubagentStop`、`PreCompact`、
`PostCompact`、`PermissionRequest`、`StopFailure`。

原触发点写在 `chat_loop` / `turn_runner` 里，随 P2 批（`F8d` / `T-350` 那一批）一起删了，
而 `fire_hook` 的模块注释与归档 `ADR-086` 仍写着它们会触发。**这不是文档问题**：
契约面有 14 个变体、消费方（用户的 hook 配置）按名字订阅，其中 12 个永远不会响——
订阅了 `Stop` 的用户得到的是静默。

### 判定

按「可接的难度」分三组，不同组的处置不同：

| 组 | 变体 | 现成条件 | 处置 |
|---|---|---|---|
| A. 已接 | `PreCompact` | `compact` 端口执行体拿得到 `ctx.ctx.parent()`（与工具端口同一手法） | **已接**：执行体在压缩前 fire，通知语义、不拦（拦压缩只会让上下文继续涨） |
| A′. 计数待账 | `PostCompact` | 载荷要「压缩前后消息数」，而 `snapshot()` 只产「压缩叶 + 可能的终答」，**原始段的消息账不在执行体手里** | 等 `T-360` 的轮级出口或上下文管线交出一份压缩读数；不拿错的数字凑载荷（订阅方按它评估压缩效果，错数比没数更坏） |
| B. 生命周期，需宿主钩子句柄 | `UserPromptSubmit` / `Stop` / `SessionStart` / `SessionEnd` | 要落在 session 的行里，但 `RowRequest` 今天**不带插件句柄** | 先补一格句柄（机制面改动，须裁决），再补产者 |
| C. 无消费需求 | `Notification` / `SubagentStart` / `SubagentStop` / `PermissionRequest` / `PostToolUseFailure` / `StopFailure` | 没有已知订阅方，也没有对应事实面 | 裁「不触发」并把变体降级或标注，不留「看起来会响」的空壳 |

B 组的关键判断：`RowRequest` 加句柄会扩行机制的世界能力面，而 `D-306` 裁决二明确
「不扩 `RowRequest` 的世界能力面」。所以 B 组要么走**宿主触发**（不经行），要么
走「行的声明里带一个回调名」而不带句柄——两条都要裁决，不能顺手加字段。

### exit

- 14 个变体**逐个**有结论：有产者（`grep` 得到非测试调用点）或有决策号说「不触发」；
- A 组：`PreCompact` 在 `compact` 端口执行体里有真实触发点（已接）；`PostCompact` 的计数
  来源有归属（`T-360` 或上下文管线的压缩读数），不在没有真数时编一个；
- B 组若补则落裁决 + 产者；若不补则在 `hooks.rs` 的变体上写明「无产者，见 `D-NNN`」；
- `fire_hook` 的模块注释与 `docs/` 里对钩子触发面的描述按现状改写；
- `cargo test --workspace` 绿；`plugin-surface-audit` 的 `HS-002` 不涨（新增公开项要论证）。

### 不做什么

- 不为了「让变体都能响」而给每个变体造一个假触发点——那是把契约面变成装饰。
- 不在 `RowRequest` 上顺手加字段（撞 `D-306` 裁决二）；要加先裁决。
- 不动 `PreToolUse` / `PostToolUse` 的既有语义与两个触发点。

## 处理过程

- 2026-11-12：登记。核实 14 个变体 / 2 个产者；A 组条件已具备（`ctx.parent()` 在
  `compact` 端口执行体里可用），B 组卡在「行不带插件句柄」这一格上。
- 2026-11-12：接 `PreCompact`（`crates/symbio-plugin-compact/src/port.rs`）：执行体从
  `ctx.ctx` 取父插件引用，压缩前 fire 一次。**通知语义、不读 `should_proceed`**——
  压缩的触发权在债源，拦在这里只会让上下文继续涨；要「不压」应该裁「不欠这笔」。
  `PostCompact` 未接：它的载荷要压缩前后消息数，而执行体手里只有压缩叶，
  原始段的消息账在上下文管线，等 `T-360` 一并把读数交出来。
  `cargo test -p symbio-plugin-compact --lib` 12 passed，其中
  `pre_compact_is_fired_by_the_executor_without_changing_the_outcome` 钉住两件事：
  记录器收到 `pre_compact`（不跑与跑了不同形）、压缩照常落 `session.consolidated`
  （旁路观察者不改判定链）。
