# B1：写口从函数变效果的 ADR

## 内容

**缺口不点名能力**：会说话、改对话面、落「已做」格的能力，结构上只能留 `session` / `loop`，
因为对话面只有一个写口（`D-020`）、阶段格只有一种写法（`D-228`）、实时上线属 I-7 不开放。
`D-291` 判判决 / 汇报留环，代价正是这条。要裁的是：**这些写口能不能从「宿主函数」变成
「可声明的效果」——能力只交草稿，宿主仍做唯一写入与幂等**。

| 选项 | 开放面 | 代价 | 判据 |
|---|---|---|---|
| B1 全开 | 对话面节点 + 阶段格 + 实时上线，能力声明形状、宿主盖章落格 | 新 `EffectDecl` 三类；`plugin-api` / `kernel` / `sdk` 各一处通用补件；把 `D-020` / `D-228` 从「唯一作者」改成「唯一写口」；需要幂等键、顺序与平凡值判据（未声明效果时逐字无差） | `classify` / `report` 的「出口」半边能迁出；`EX-008` 仍绿；停用能力无静默边 |
| B2 窄开 | 只开阶段格 + 转写卡片（节点身份 + 状态），对话正文仍宿主 | 补件小；判决 / 汇报只迁出一半，措辞与正文仍留控制面 | 只解决「落点」不解决「说话」；`D-291` 的代价仍在 |
| B3 不开 | 维持 `D-020` / `D-228` / I-7 | 零成本；能力永远到不了对话面，与父任务目标冲突 | 必须写进账：哪几行因此永久留守 |

## 处理过程

1. 逐条读 `D-020` / `D-228` / I-7 的原文与反例，列出现有写口的函数面与它的幂等、顺序、盖章职责。
2. 三套选项各写：能力交什么（草稿形状）、宿主做什么（唯一写入 / 幂等 / 盖章）、卸载后剩什么。
3. 安全与幂等判据逐条写：同一声明重复落格、误序上线、未声明效果的平凡值、`EX-008` 的端口词禁。
4. 裁决落进宿主设计文档（`### D-NNN`）；实现另立 `T-018`。不在裁决里改任何写口代码。
