## 内容

### 为什么单独立一条

`T-005` / `T-011` 收的是**拓扑**（谁跑谁、几个环），`T-013` 收的是**体量与重复**。
两者混在一起会让回退粒度失控：拓扑改错了要看几百行 diff 才找得到，而体量清理失败时
不该连带拓扑一起回退。这一条全部是"同一个问题的多种写法"，**不改变任何一条事实、任何一个前件**。

六项逐条的终态判据：

| # | 残留 | 今天的量 | 终态只允许两种 |
|---|---|---|---|
| `R3` | "这一步做过没有"三种写法（`turn.stage{inputs}` / 端口往返 / `turn_round.done`） | ~180 行 | 端口往返一种随 T-005 消失；`turn_round.done` 若在合表之后已无读者 ⇒ 删；留一种，理由入裁决 |
| `R4` | `TurnState` 22 字段（事实第二份拷贝 4 + 寄存位 6 + 请求级缓存 3 + 其余） | 22 | 逐字段处置；棘轮只降不增 |
| `R5` | `turn_head` 单视图 265 行（区间长度，非逻辑行） | 311 行含声明 | 幕从"推进单位"降为身份（T-005/T-011）之后它会缩——**缩到多少由归一后的行定，不由条文定**（`D-222` 诚实划界 3），本任务给出实测值 |
| `R6` | 收束 / 在途判据五套 | 5 处 | ≤ 2 套：一套答"这一轮结束了没有"，一套答"有没有在途往返"。**不许为零**：它们是两个不同的问题 |
| `R7` | 六种"结果"壳（`StageOutcome` / `TurnExecResult` / `TurnExecExit` / `TurnExit` / `TurnOutcome` / `TurnReport`） | 6 类 | `StageOutcome` 随 T-005 消失；其余五个各答一个问题，答不出问题的删 |
| `R8` | 同名不同义 | 2 组 | 改名或写清区分口径；**不许两义同名并存** |

### `TurnState` 的处理原则（这一条最容易做歪）

字段减少是**结果**，不是手段。判每个字段只有一问：

> 它是**事实**的第二份拷贝、**产物**的寄存位，还是**请求级**的缓存？

- 事实的第二份拷贝 ⇒ 退出，读日志；
- 产物的寄存位 ⇒ 只有一条路：变成事实（`D-123` 决策 5 允许寄存，是因为"执行体不交回产出"；
  它允许的是**不交回**，不是**不留痕**）；
- 请求级缓存 ⇒ 保留，但要能在注释里指出"为什么它不是第二份状态"。

**不许**为了把数字压下来而把字段塞进另一个结构体——那是把 `R4` 换个住址。

### 不做什么

- **不动前件与行**：本任务不改任何 `owes` / `until` / `unless`。
- **不为改名而改名**：`R8` 的处置允许"写清口径"而不是"改名"——名字是症状，两义同名才是病。
- **不删测试**：断言被删形状的用例随形状一起改，不随体量清理一起删。
