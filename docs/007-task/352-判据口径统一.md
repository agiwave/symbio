### 判定

同一个数字写在三处，改一次要动三处且必然漂移——这正是 `docs/README` 的「一个事实只有一个 owner」。
按终态标准：脚本常量是**唯一值**，文档与注释只作**引用或投影**，不得再抄一份具体数字；
能由门禁重生成的（`RE-006`、`rustfmt`）一律交给门禁，不手改。
`CS-009` 的 260 → 257 是**收紧**（只许降），不是放宽，直接做。
`D-372` 自陈「同一判据三处三套口径、手写读数漂了没有任何一道门会红」——本任务把**可机读的那半**
收干净，剩下的手写读数归属在 `T-353` 处理。

`host` 是否纳入受保护树**不在本任务**，独立走 `T-354` 的裁决。

`T-351` 施工批已同批收敛现行描述层的八处抄本（`DE-001` / `DE-022` / `DE-023` / `DE-044`×2 /
`DE-050` / `SP-033` / 本 SPRINT 父任务），以及 `decl` 模块内指向已删文件的源码注释；
`archive/` 与决策正文不在那一批的判定面内，故留在这里。`DE-026:34` 的 `drive` 指**环侧**
驱动（`ring/engine.rs::drive`）而非内核求解器，是正确描述，不改。

exit: 任一判据值只有一个机读 owner；`registry-audit` / `gen-doc-refs` / 全量门禁绿；
`RE-006` 的 HEAD 与提交后的实际 HEAD 一致；`arch-shape-audit` 不再提示同步基线。

不做什么：不改判据的判定规则、不放宽任何基线、不给 `DEBT_EXEMPTIONS` 加行。
