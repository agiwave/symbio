## 内容

**为什么需要**：这次推敲发现 8 类文档缺陷，门禁 130/130 全绿一条都没抓住。其中三类
（悬空节号引用、缺号、重复编号）是同一个根因：**节号没有判据**。

`doc-link-audit` 的 D-004 只校验**链接式**小节引用（方括号写节号、后面跟一个 `#` 锚点）——
因为那种写法能靠锚点机械解析。正文里裸写的 `§7.2` 没人管，于是节号被删改时
引用留在原地，读者点不到、也搜不到。

**判据形状**（只判 design 文档，避免对 archive / 任务册产生噪音）：

1. **连续性**：抽出一级标题里的 `§N` 编号序列，必须从 0 开始连续、无重复。
   无编号小节（`## 关键决策`）跳过——那是刻意的，不是漏号。
2. **可解析性**：正文所有 `§N` / `§N.M` 必须落在第 1 条抽出的集合里（`§N.M` 还需
   对应 `### N.M` 存在）。自引用（同一篇内）才判，跨篇引用要求写清文件名。
3. **例外**：代码块内的 `§` 不判（伪代码 / 注释里可能引用别处的编号）。

**落地顺序**：先让判据红着跑一遍，把三篇的真实缺陷列全（DE-001 缺 §13、DE-016 三套编号、
DE-015 悬空 6 处），再逐篇修。**不要为了让判据绿而放宽判据**——这三篇是真有缺陷。

**与 D-004 的分工**：D-004 管「链接指向的小节存在」，本判据管「裸引用的节号存在」。
两条合起来，「节号」这个维度才封闭。
