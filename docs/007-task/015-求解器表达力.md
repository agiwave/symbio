# 求解器表达力：owes 的合取与跨源键绑定

## 内容

[DE-044-引擎收口与简化](../003-design/044-引擎收口与简化.md) §4 给出一条判断：工具端口的实现之所以看起来「一个端口调用要这么复杂」，
**至少一半复杂度不在端口、也不在工具，而在求解器不会说「并且」**。本文把那条判断变成可裁的题。

现状（[DE-022-行表与派发面](../003-design/022-行表与派发面.md) 的 `D-265` 已把结论记成「认下」）：

| 表达力缺口 | 今天转嫁成的结构 | 代价 |
|---|---|---|
| 写不出 `request ∧ granted` | `authorize-tool` 与 `dispatch-tools` 拆两行，用蕴含代替合取 | 工具债 5 行里多 1 行；`D-265` 把这份税固定下来 |
| 写不出「这一批的 N 笔」 | `expand` 把集合债摊成 N 笔独立债 | 一次工具调用写 4N 条协议事实 |
| 写不出「没被拒」 | 靠「`denied` ⇒ 无 `granted` ⇒ 派发行永不成立」间接表达 | 否定只能靠 fail-closed 技巧 |

`Decl.owes` 是一个 `Pattern`：**单一事实源 + 键字段 + 等值约束**。没有跨源合取、没有否定原子、
没有集合。这不是实现偷懒——`PTS-003` 冻结了 `owed` 的字节，改它要一条裁决。

## 处理过程

1. **先量，再裁。** 把三条缺口各自的「结构代价」量成数：多几行、多几条事实、多几次读。
   量的口径与 [T-014-引擎收口](014-引擎收口.md) 的账本一致（行 / 格 / 通道 / 全量读），不另起一套。
2. **三案摆开**（判据面变化是主列，不是附带说明）：

   | 案 | 形状 | 收益 | 判据面变化 |
   |---|---|---|---|
   | 甲 补表达力 | `owes` 收 `&[Pattern]` 做合取 + 跨源键绑定 | 工具债 5 → 3；`authorize` 与 `dispatch` 合一行；两行模板退回一行 | `owed` 复杂度上升；`PTS-003` 基线重算；「加端口 = 0 改引擎」的保证要按 join 语义重述 |
   | 乙 认下摊平 | 不改求解器，两行税写成标准形状（**已由 `D-265` 落地**） | 零风险 | 无 |
   | 丙 换债的表达 | 端口调用 = 显式状态机，行表只写转移 | 记账从「行」回到「笔」 | 动 [DE-015-义务环](../003-design/015-义务环.md) 的「债 = 未命中出口的模式」核心定义，等于重写方案 |

3. **只裁甲或丙**：乙已经在 `D-265` 落了地，不需要再裁一次。裁甲 ⇒ 改 `Decl` + 挂 ADR +
   重算 `PTS-003`；裁丙 ⇒ 先改 DE-015 再动代码（顺序不能反）。
4. **落进宿主文档**：甲 / 丙的结论写进 [DE-022-行表与派发面](../003-design/022-行表与派发面.md) 的 `### D-NNN`，并让 `D-265` 的重开条件
   兑现（作废或改写）。

## 边界

- **不在本任务里顺手改 `owed`**：`owed` 的字节是 `PTS-003` 的判据面，改它必须先是裁决。
- **不为「少 2 行」动全表公共分母**：甲的收益是行数，代价是所有行的求解语义——这正是它值得
  单独立项、而不是在 [T-014-引擎收口](014-引擎收口.md) 的步 1 里捎带的原因。
- **丙不做前置优化**：丙换掉的是债的定义，不是实现；先做甲的实现优化再去裁丙，等于在错的
  模型上加零件。
