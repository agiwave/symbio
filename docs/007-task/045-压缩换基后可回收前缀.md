# 压缩换基后的可回收前缀

## 内容

### 缺什么

`FactSource::retire_prefix(before_seq)`（[fact_source.rs](../../crates/symbio-plugin-api/src/fact_source.rs)）
有声明、有完整实现（`symbio-plugin-session` 的 `store::fact_source` 调 `archive_before`）、
契约文字也写着「该前缀已固化，可回收」，但**全仓没有调用点**。归档因此永不发生。

这与「声明在、写方在、读方从未接上」是同一族（台账 037 §1）：不是机制坏了，而是
机制与消费面之间断了一根线。静态面看上去齐全，所有「事实存在」型断言都是绿的。

### 为什么它一直没人调

换基（`session.consolidated`）解决的是「模型输入不再带全量历史」；它把快照之前的消息
**取代**掉，但没有回答「被取代的那段现在归谁」。归档实现早就写好了，缺的是**由谁在
什么时刻宣布**「这段前缀已固化、可以回收」——这是一个决定，不是一行代码。

### 修法边界

- **调用点必须在换基落格之后**：`before_seq` 只能取已经落库的那份快照的位置，不能取
  「即将压缩」的位置，否则会把还没被取代的事件归档掉。
- **只宣布、不删除**：`retire_prefix` 的语义是「可回收」，读侧仍按快照回放；回收动作
  由存储层按自己的保留策略执行。
- **一条前缀只宣布一次**：重复调用要么幂等、要么由调用方按快照身份去重；不许每轮都调。

### 触发与承接

- 触发：压缩换基的读方已补齐（`82adcaa2`），下一次动压缩写方或存储保留策略时一并落地。
- 不在本条内做：改写归档格式、改快照回放语义、给 `retire_prefix` 加第二份实现。
