# 引擎收口：账本、三条收窄与求解器表达力裁决

## 内容

[T-001-能力全面拆分](001-能力全面拆分.md) 解决的是「控制面里不要有按能力名写的策略」；本任务解决的是它的
**另一半**：留下的五类残留（环 / 写口 / 全局守门 / 过程体 / 会话基底）本身是不是太厚。
判据与读数见 [DE-044-引擎收口与简化](../003-design/044-引擎收口与简化.md)，本文只做分解与施工，不复述论证。

四件事，按依赖排：

1. **步 0 账本**（无前置）：把 `loop` 里每一处**自持**列成一行——行表的行、`TurnState` 的格、
   出参通道、全量读点——逐项回答「日志能不能重算」。答得了的进删除清单，答不了的写明
   属于五类里的哪一类。这是本任务唯一的输入，也是收口的验收面。
2. **步 1 三条收窄**（无前置，与 T-007 并行）：出参三通道合一、工具路径 11 处全量读收成
   一份幕内切片、`TurnState` 逐格删减。三项各一个提交，各自可独立回退，端到端逐字不变。
3. **步 2 求解器表达力裁决**（**已裁，2026-10-31**）：`Decl.owes` 写不出合取，导致工具债
   5 行里至少 2 行的存在理由是表达力而不是业务。结论：**乙落地、甲立项、丙不做**——乙写成
   [DE-022-行表与派发面](../003-design/022-行表与派发面.md) 的 `D-265`（「认下，不是认可」，带重开条件），甲独立为
   [T-015-求解器表达力](015-求解器表达力.md)，丙不做。本步只剩「按裁决改条文」，已随 `D-265` 完成。
4. **步 3 合流**（需 T-007 / T-008 收口）：迁移完成后复核「五类之外没有名字」，
   并把本任务的账本与 `EX-006` 的账并成一份。

**不做**：为行数删功能；动 `owed` / `drive` 的字节（除步 2 裁「甲」并挂 ADR）；改五类残留的
定义；把 `session` 变小当目标。边界与理由归 DE-044 §7，本文不复述。

**与迁移任务的边界**：本任务的提交不写 `Migration:` 行（不是迁移提交），迁移提交也不许
顺手做本任务的收窄（`EX-007` 判夹带）。两者唯一交集是 `tool_dispatch`，冲突时以迁移批为先。

## 处理过程

1. 先出步 0 的账（表挂在下面「引擎账本」节，不写进设计文档——与 [T-008-session存量能力迁移](008-session存量能力迁移.md)
   的逐模块归属表同一处置）。账的每一行三列：**对象**（行名 / 字段名 / 通道名 / 文件:函数）/
   **自持的理由** / **答不了吗**（答得了 ⇒ 进删除清单）。
2. 步 1 按「出参 → 全量读 → 草稿格」顺序做，每一步单独提交并跑 prompt 形状基线与 e2e。
   全量读那一步的前件**已核（2026-10-31）**：**有**，而且是链式的——`open-tools` 落
   `request`、`authorize-tool` 读它，`authorize-tool` 落 `authz`、`dispatch-tools` 又读它。
   所以「一份幕首切片」不成立；做成 `Store` 视图（切片 + 经视图写入的增量）也不成立
   （幕内还有经原始 store 写的事实，视图看不见，实测 7 个用例红）。可做的收窄只剩
   `begin_calls` 那一处 N 倍放大：批首读一次，`begin` 收下切片。结论归
   [DE-044-引擎收口与简化](../003-design/044-引擎收口与简化.md) 的 `E-2`。
3. 步 2 发起一轮讨论，把 DE-044 §5 E-1 的三案按「收益 / 代价 / 风险 / 判据面变化」摆开，
   裁决写进 [DE-022-行表与派发面](../003-design/022-行表与派发面.md) 的 `### D-NNN`；同时决定「一个端口两行」要不要作为
   标准形状写进条文。**已完成（2026-10-31）**：裁决是「乙落地、甲立项、丙不做」，条文落成
   `D-265`；甲另立独立任务（未裁）。
4. 步 3 与 T-007 / T-008 合流后，跑 `EX-006`、`SC-006`、`CP-001`…`CP-008`、
   `PTS-001`…`PTS-006` 全绿，再把 DE-044 的 `impl` 按实况改档。
5. **进度（2026-10-31）**：步 0 账本已填满；步 1 三项各有结论——`E-3` 与 `E-2` 各一个提交
   落地（`PortOutput` 合并两条出参通道；派发批事实面批首读一次），`E-4` 逐格核完无删格。
   剩 §8 第 4 条（账本要不要脚本）与步 3（与迁移线合流）。

## 引擎账本

步 0 的产出，逐项填。空着的行就是没核过的行，收口前不许留空。

| 对象 | 自持的理由 | 事实面答不了吗 |
|---|---|---|
| 行 `authorize-tool` | 判定要在派发之前落一条可观测的事实 | **答不了，保留**：`D-265` 把它定为标准形状（带前置判定的端口固定两行）；合一是求解器的事，归独立立项 |
| 行 `await-model` / `await-tools` | `sent` 与终态分处两环步，「在飞」要在正常跑里读得到（`D-222` 订正 2） | **答不了，保留**：与 `stale_sent` 视图不重复——视图判「卡了多久」（租约看护），行判「派出未收束」（推进）；两者读同一批 `sent`，判的不是同一件事 |
| 行 `EVENT_ARTIFACT_ADDED`（归宿行） | 产物格要有行认领（`OrphanFact`） | 待核：认领能否由视图承担 |
| 出参 `PortOutput.nodes` / `.derived` | 节点与收束派生事实要跨 `await` 累积，而写方在别处（`D-123` 不许执行体自报账本） | **答不了，保留**：已由 `E-3` 合成**一条**通道（原先是 `produced` / `derived` 两个 `Mutex`）；消费方要从日志重建，得先有「写方在别处」那条链，而链本身就是它 |
| 出参 `DispatchOutcome` | 运行器要据此落产物格并拼下一轮 prompt | **答不了，保留**：它是**同步返回值**（一次调用即交齐），不是「通道」——塞进 `Mutex` 反而把它变成第二条通道（`E-3` 的订正） |
| 全量读 ×11 | 结论只有一个出处（`D-136`），每站现读 | **答不了，保留 10 处**：跨站是链式的（见「处理过程」第 2 条）。**答得了 1 处**：`begin_calls` 的 N+1 次 → 批首一次 |
| `TurnState` ×18 | 逐格（`D-226`） | **逐格核完，18 格全留**：没有一格是「事实的拷贝」——① **输入**（外部给的，事实面答不了）：`abort` / `turn_no` / `user_seq` / `drive_seq` / `now_ms` / `resume_root` / `resume_old_child` / `retry_of`；② **执行体产出寄存**（`D-123` 不许自报账本，动作交不回产出）：`opening_text` / `opening_dialog` / `head_answer`；③ **请求级缓存**（事实面答得了，但每次重算 = 一次求解器求值或全量读）：`recall_view` / `context_sections` / `request_overhead` / `facts` / `input_utterance`；④ **本幕参数**：`request_round`（`turn_next_round` 的求解器结论，读方 21 处）、`last_saved`（增量落库锚点）。**无删格**，`CS-010` 不动 |
