## 内容

GO-003 §3 与 GO-002 §3 自己列了三处「读数待建」。它们不是能力缺口，但**让「全面」
说不出口**：没有读数，「33 条规范都有判据」「注入是全面的」「前端零分支」都只是愿望。

本任务先定口径再写脚本——「什么算一个分支」「什么算无机器判据的合法理由」必须先落纸，
否则脚本只会造出一串没人信的数字。

## 判据

| # | 判据 | 承担者 |
|---|---|---|
| 1 | 每条规范解析出执行方（脚本名或判据码）或「无机器判据 + 理由」，计数进日志 | 新脚本（`gate-codes-audit` 旁） |
| 2 | 注入矩阵每格有用例号或缺口归属，未归属格计为缺口 | 矩阵生成物 + 一条用例 |
| 3 | 「kind 分支」有定义（按 `NodeKind` / 资源类型分派点计），计数进基线 | 前端静态审计 |
| 4 | 三条读数都只降不升（棘轮进 `35-baseline`） | 基线 |
