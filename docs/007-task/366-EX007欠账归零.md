# EX-007 欠账归零——先普查可迁移面，再谈净减

## 内容

### 现场

`node scripts/capability-migration-audit.mjs` 今日读数：

- 累计补件 **31** / 迁移 **29** = **1.07:1**（目标 ≤1:1）；
- **欠账 2 笔**：`f4774e99`（D-465 出口 owner 与折账 owner 在装配期对账）、
  `2ea1e93d`（`RowReply` 改名，`LP-003` 归零）；
- 台阶表：今日允许 ≤5、2026-11-13 允许 ≤4。**欠账今天不红**，但它是唯一一个
  「判据在，形态未收口」的计数账。

### 判定

抵账只有一条路：**做一次净减迁移**（迁移批次 +1 而补件 +0）。补件不减是因为它们
已经发生（历史事实），改计数口径等于把账做平——`D-404` / [DE-054-判据欠账与到期豁免](../003-design/054-判据欠账与到期豁免.md)
明令禁止。

所以本任务的第一步**不是写代码，是普查**：哪些面还能整块搬出控制面、且搬完不多一条依赖边。
`DE-023` 已经给过一次结论：`plugin-api` 剩下的是 `drive` / `debt` / `ports` 这些
**扩展层唯一契约**，搬走会多一条依赖边；再往下压要动的不是名单，而是 `dialog` / `plugin` /
`event_bus` 这些宿主子系统——「不是搬运，是切实现面」。

普查要回答三个问题，逐个候选写一行：

| 候选 | 搬得动吗 | 为什么 |
|---|---|---|
| `sdk` 里仍属「宿主实现」而非「插件契约」的模块 | ？ | 若插件不 import 它、且搬走后机制层不多依赖边 ⇒ 可搬 |
| `kernel` 的语法面 | 否 | 冻结面只收窄，`CS-001` 三格只许降 |
| `plugin-api` 的剩余模块 | 大概率否 | 扩展层唯一契约，搬走等于换名字 |
| `sdk/projection` 与 `plugin-session` 的读段 | ？ | 已按 `D-472` 拆过一轮，剩余部分要看消费方 |

**如果普查结论是「没有可搬的」**，那也是一个合法收口：把每条候选与拒绝理由写进
`DE-054`，并把「欠账 2 笔长期存在」这件事从「待办」改成「已普查的结论」——
但**不改判据的分子分母**。任务可以 `wont` 收口（带 `reason`），不能假装归零。

### exit

- 二选一，都要有据：
  - **做了净减迁移**：`EX-007` 读数 欠账 ≤1 且明细行减少，迁移批次带 `Migration:` trailer，
    补件 0；
  - **普查后判定无可搬**：`DE-054` 多一段「欠账 2 笔的普查结论」，逐候选列拒绝理由，
    并给出**可观测的重开条件**（例如「出现第二个消费方时」「某模块的插件消费方归零时」）。
- 两条路径都不改 `EX-007` 的计数口径与台阶表。
- `capability-migration-audit` 绿；`baseline-scope-audit` 绿。

### 不做什么

- 不搬一段没准备好的代码来抵账（`D-404`）。
- 不删欠账明细行、不改台阶表、不加 `DEBT_EXEMPTIONS`（豁免只在有对象、有期限时登记）。
- 不把 `plugin-api` 的契约面搬进 `sdk` 来「凑一次迁移」——那是换名字，不是拆边界。
