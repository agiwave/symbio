# 同名模块改名与门面收窄

> 对应架构分析：**P4（收敛类）/ P5（收敛类）/ P7（边界类）**。
> 架构批第 4 笔。依据：P4 / P5 / P7 核实。
> - 8 组镜像模块：`chat`（chat_node / principal）、`llm`（model_provider / turn）、
>   `plugin`、`vdfs`、`projection`、`capability`、`view`、`keys`——sdk 侧全部是
>   `pub use symbio_kernel::…`；`store` / `exec` / `present` 没有 sdk 镜像。
> - 同一符号多条合法路径：`ChatNode` 经 kernel / sdk / api 三处可达；`Plugin` 经
>   kernel / sdk / api 根三处可达。
> - `crates/symbio/src/lib.rs` 有 39 行 `pub use symbio_plugin_*;`，把每个插件 crate
>   的完整公开面挂到 `symbio::` 下（插件 crate 名即模块名）。

## 内容

### 1. 同名模块改名

镜像模块的害处不是「多一个文件」，而是同一个符号有两条以上合法路径：读者无法从 import
判断自己拿的是语法还是机制，审计也无法按路径归责。逐对改名，让每个模块只属于一层：

- `llm` 的形状类型与帧原语分名（`llm_types` / `llm_frames` 这类），不再两个 `llm`；
- `chat` / `plugin` / `vdfs` / `projection` / `capability` / `view` / `keys` 同法；
- 改名后 `symbio_sdk::chat::chat_node::ChatNode` 与 `symbio_kernel::chat::chat_node::ChatNode`
  只能留一条，另一条按归属改路径或删除。

### 2. 一条可机械判的边界判据

把「扩展层只经 plugin-api、控制面内部随便走」写成判据，不再靠人工分类：

- 扩展层 crate（依赖 `symbio-plugin-api`）源码与 manifest 里出现 `symbio_kernel` /
  `symbio_sdk` / `symbio_deploy` 即红（HS-001 已有，保持）；
- 控制面（`loop` / `session`）必须在判据里**显式列出**才豁免，不按名字前缀猜；
- 新增一条：门面（`symbio-plugin-api`）持有的实现条数只许降（`FA-002`，判据与读数见
  `DE-018` 的 `D-399` / `D-416`）。

### 3. `symbio` 门面收窄

`symbio` 只导出装配所需（`assembly` / `init` / 驱动入口 / CLI 与 Tauri 实际引用的符号）。
插件 crate 仍必须被链接（否则 `inventory` 注册项被链接器丢掉），但用私有 `use` / `as _`
保住链接，不再把每个插件的完整公开面挂到 `symbio::` 下。

## 是否阻塞横向扩展

**否（收敛类 / 边界类，可分批）**。镜像模块与门面宽度不阻止新能力落地，但每新增一条
符号路径就多一种合法写法；按批收敛即可，不与 P1–P3 的裁决抢先后。

## 处理过程

1. 先出「镜像对 → 新名」对照表，逐对改名；每次改名跑一次 `cargo check` 收口编译错误。
2. 补边界判据（HS-001 扩展 + 控制面显式白名单），反向用例：控制面名字前缀伪装成
   扩展层必须红。
3. 收窄 `symbio` 门面：把 39 行 `pub use symbio_plugin_*;` 改为私有链接行 + 显式导出，
   验证 `inventory` 注册项数量不变。
4. 跑 `gate --full`，全绿后提交。
