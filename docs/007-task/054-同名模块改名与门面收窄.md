# 同名模块改名与门面收窄

> 对应架构分析：**P4（收敛类）/ P5（收敛类）/ P7（边界类）**。
> 架构批第 4 笔。依据：P4 / P5 / P7 核实。
> - 8 组镜像模块：`chat`（chat_node / principal）、`llm`（model_provider / turn）、
>   `plugin`、`vdfs`、`projection`、`capability`、`view`、`keys`——sdk 侧曾全部是
>   `pub use symbio_kernel::…`；`D-419` 之后只剩 `chat` 两个组合模块未分拣
>   （`view` 与 `llm::model_provider` 已删除）。`store` / `exec` / `present` 没有 sdk 镜像。
> - 同一符号多条合法路径：`ChatNode` 经 kernel / sdk / api 三处可达；`Plugin` 经
>   kernel / sdk / api 根三处可达（`D-419` 已收掉 sdk 那一条，`ChatNode` 随 `chat`
>   分拣收口）。
> - `crates/symbio/src/lib.rs` 曾有 39 行 `pub use symbio_plugin_*;`，把每个插件 crate
>   的完整公开面挂到 `symbio::` 下（插件 crate 名即模块名）；现为 32 行私有链接行
>   `use symbio_plugin_* as _;`（`D-417`）。

## 内容

### 1. 镜像模块唯一归属（摘 glob，不改名）

镜像模块的害处不是「多一个文件」，而是同一个符号有两条以上合法路径。`D-277` 已裁
「同一概念两个名字，比同名更贵」，因此不改名，而是把 sdk 侧对内核的**整模块转出**
收成私有 `use`：同名模块保留，公开面只留自己的实现（`D-419` 落地：`llm::turn` /
`capability` / `plugin` / `vdfs` / `keys` / `projection`，并删除两条纯转出
`llm::model_provider` / `view`）。

- `chat` 是剩余项：`chat_node` / `principal` 两个模块是**组合模块**（内核词汇 + sdk
  自有函数），要逐个符号分拣并把门面切到内核侧。
- 两条宏例外保持公开：`$crate::plugin::PluginInvokeRequest`、`$crate::vdfs::{…}`——
  宏展开在消费方，路径必须以 `$crate` 指向 sdk，插件不必依赖内核。
- 删掉纯转出后，每删一个模块跑一次 `cargo check` 收口编译错误。

### 2. 一条可机械判的边界判据

把「扩展层只经 plugin-api、控制面内部随便走」写成判据，不再靠人工分类：

- 扩展层 crate（依赖 `symbio-plugin-api`）源码与 manifest 里出现 `symbio_kernel` /
  `symbio_sdk` / `symbio_deploy` 即红（`HS-001` 源码前缀 + `E-009` 生产依赖闭集，
  `D-418`）；
- 控制面（`loop` / `session`）必须在判据里**显式列出**才豁免，不按名字前缀猜；
- 新增一条：门面（`symbio-plugin-api`）持有的实现条数只许降（`FA-002`，判据与读数见
  `DE-018` 的 `D-399` / `D-416`）。

### 3. `symbio` 门面收窄

`symbio` 只导出装配所需（`assembly` / `init` / 驱动入口 / CLI 与 Tauri 实际引用的符号）。
插件 crate 仍必须被链接（否则 `inventory` 注册项被链接器丢掉），但用私有 `use` / `as _`
保住链接，不再把每个插件的完整公开面挂到 `symbio::` 下。

## 是否阻塞横向扩展

**否（收敛类 / 边界类，可分批）**。镜像模块与门面宽度不阻止新能力落地，但每新增一条
符号路径就多一种合法写法；按批收敛即可，不与 P1–P3 的裁决抢先后。
