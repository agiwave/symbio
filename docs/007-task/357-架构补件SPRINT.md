# 架构补件 SPRINT——把「拆分的前提」做实

## 内容

### 判定总纲（本 SPRINT 所有取舍的唯一标尺）

1. **补件是拆分的前提，不是例外**（[DE-002-架构总览](../003-design/002-架构总览.md) §4）。存量拆不动的地方，先补机制再拆；
   补件单列、带 `### D-NNN`、通用且**不含能力名**；迁移提交只做删除与绑定切换（`EX-007`）。
   判失败的是「夹带」「为一条能力定制端口」「把功能代码搬进架构模块冒充端口」，不是「加了机制」。
2. **收窄不需要批准，变宽需要论证**（`CS-002` / `DE-023 D-278`）。凡能让封闭语法面、门面三臂、
   扩展局部性覆盖面更紧的改动优先做；凡要放宽某条判据才能过的改动，先落裁决再动代码。
3. **裁决先于施工**（[SP-003](../005-spec/003.md) 纪律 0）：改内核 `Decl` 字段集、跨 crate 协议面、端口契约之前，
   先有 `### D-NNN`。「模块实现困难」永远不是改架构的理由。
4. **档位按代码事实对账，不用文档措辞代替实现**。`partial` 的每处残余要么有落地锚，要么指认
   承载它的任务；不批量改档，也不把「绿灯」当终态达成的证据。
5. **绿灯才算绿**：`node scripts/gate.mjs --full --ci` 是每批提交的唯一出口。

### 不做什么

- **不重开已裁决项**：`D-108`（申诉触发器不建）、`D-157`（SC-014…018 移出承诺清单）、
  `D-290`（不补 `owes` 的合取）、`D-152`（向量索引不落）。重开条件写在各自条目里，
  本 SPRINT 不拿「欠账清单长」当重开理由。
- 不为凑数迁移搬未准备好的代码（`D-404` / [DE-054-判据欠账与到期豁免](../003-design/054-判据欠账与到期豁免.md)）。
- 不改 `owed` 的字节语义、不新增谓词、不给行表加第二份清单。
- 不把架构面改动降级成文档措辞调整。
