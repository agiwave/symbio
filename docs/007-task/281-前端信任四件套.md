## 内容

DE-020 §1「差距盘点（只列仍成立的）」里，信任面的四项全是空的：
看不见 Agent 干了什么、看不见上下文水位（已补）、看不见花了多少、看不见分支。
本任务按 P2 的顺序做，**先做有后端事实的**：`<根>/session/<id>/workdir` 已存在、
`session/stats` 有成本列、`parent_id` 树已建——缺的都是「前端把它显示出来」。

## 判据

| # | 判据 | 承担者 |
|---|---|---|
| 1 | 变更面板：本会话 workdir 的增删改可见，点开复用既有编辑器打开当前文件（**无 diff**：没有写入前全文） | 组件用例 + e2e |
| 2 | 授权分级：三档选项落成授权事实，不是仅界面状态 | 服务层用例 |
| 3 | 用量：会话头显示累计 token / 成本，读的是 `session/stats` 同一份切片 | 组件用例 |
| 4 | 分支：同 parent 多候选可 `‹ ›` 切换且不重挂载会话 | 组件用例 + e2e |
| 5 | 四项都不新增专属资源页（GO-002 T4） | 评审 + 路由快照 |

## 处理过程

- 2026-10-24：登记。P2-4 的前置是 `model` 是否有价格字段——没有就先后端补，
  不许前端按名字猜价格。

- 2026-10-27（批 0 · 前件勘查）：四项**不是同一档工作量**，逐项对着代码核了一遍，
  结论落在 [DE-020 §11 的前件表](../003-design/020-前端UI-UX.md "DE-020-前端UI-UX")：

  | 项 | 前件 | 谁先动 |
  |---|---|---|
  | P2-2 变更面板 | 文件改动只有实时面（事件总线，进程退出即消失），没有可回读、可归因的记录 | 后端先补 |
  | P2-3 授权分级 | 「本会话放行」= 抬会话阈值，零新事实；「永久放行」没有任何落点（跨会话授权清单不存在） | 两档可做，第三档需先裁 |
  | P2-4 用量成本 | token 在手（`LlmTurn.usage`）但没入格；`model` 没有价格字段 | 后端先补 |
  | P2-5 分支切换 | `RetrySubtree` 是**删除式**（删掉失败轮按新轮重来），日志上不产生第二支 | 后端先补 + 一条裁决 |

  顺带纠正 DE-020 §1 的一处事实错误：原表写「重试会产生分支」，而 `wake.rs` 的
  `WakeOutcome::NewTurn` 是「删掉失败轮的消息，按普通新轮重来」——分支今天**没有数据
  来源**，所以 P2-5 不是「补个 `‹ ›`」，是先裁「重试 = 替换还是分支」。

  分批（前端判据一律挂一条后端判据在前）：

  | 批 | 内容 | 判据落点 |
  |---|---|---|
  | 1 | P2-3 前两档：`每次` / `本会话放行`（抬会话 `risk_level`） | 服务层用例 + 授权事实 |
  | 2 | P2-4 后端：`response` 载荷带 `usage` + 一张 token 投影 + `session/stats` 一列 | Rust 用例 + stats 读数 |
  | 3 | P2-4 前端：会话头显示累计 token（读数走 `present/reading` 方言） | 组件用例 |
  | 4 | P2-2 后端：可回读的变更记录（谁写的、哪条路径） | Rust 用例 |

  **只抬不降**，已是该档就不写（一次无意义的写会广播一次资源变更、白重拉清单）；
  ② 注入面 `ALLOW_FOR_SESSION_KEY`（`ModelChatPanel` 提供，闭包持会话 id，渲染器不传 id）；
  ③ `InteractionNode` 的第三键，档位校验走契约层 `isSessionRiskLevel`。
  **同批把写路径调平**：会话 metadata 的写入此前只有 `useSessionOptionBar.save` 一处，
  等于「改会话 metadata」被绑在选项栏这个 UI 机制上——抬阈值要么拿到选项栏实例，要么再写
  一遍 `updateSession` + 本地镜射。现在写（浅合并 + 镜射）收进 `stores/sessions.patchSessionMetadata`，
  选项栏退成「字段值 / 草稿态 / 禁用态」的语义层，两个动作共用一个写实现。
  判据：后端 `the_session_threshold_decides_whether_a_call_is_asked_about`（阈值抬一档 ⇒
  不再问，方向可复算）；前端 store 四条（写什么 / 已是该档不写 / 只抬不降 / 写失败不镜射）、
  组件四条（三键存在性 / 先抬后批的**顺序** / 批准不碰阈值 / 抬失败仍批准）。
  顺序判据做过变异验证：去掉 `await` 后用例当场转红（`['resume:approve','allow:high']`）。
  **未承接**：第三档「永久放行」——跨会话授权清单不存在（见 [DE-020 §11 的前件表](../003-design/020-前端UI-UX.md "DE-020-前端UI-UX")）。

- 2026-10-27（批 3 · P2-4 的前端半边）：会话头的常驻用量格。**不另算一份**：
  `session/stats` 新增 `usage` 字段（一格 `ReadingSection`），与面板里「用量」那段调
  同一个 `usage_section`（唯一装配，用例钉「逐行相等」）；`None` 时整个键不出现
  （`skip_serializing_if`），头上什么都不画。前端只做接线：`ChatMainPanel` 把
  `stats.usage` 交给 `ReadingMeter`（与抽屉里 `ReadingPanel` 同一方言的两个渲染器），
  **一个字符串都不认**——不按 `title` 从 `panel.sections` 里挑「用量」那节，因为方言的
  分节只有标题没有身份，按中文标签定位等于把标签变成跨栈的键（改一个字，头上静默少一格）。
  读取时机：切会话一次（`immediate`，路由恢复时 `activeId` 在挂载前就有值）+ 一轮跑完一次
  （`working → 不 working`），**仍不轮询**——一次读是一整套投影（`fleet` 列是部署级扫描）。
  用例：`ChatMainPanel.meter.spec.ts` 五条（挂载读一次并渲染 / 缺格不画 / 切会话换成新值且
  旧值不留 / 轮末重读而开始跑时不读 / 读失败留白）。
  **未承接**：钱（同上，要 `model` 的价格字段）。

  `response{port=model}` 的 `usage` 键——**键在不在就是「测到了」的唯一记号**（缺席时

  `stats_reading.rs::usage_section` 给读数面板加一段「用量」（输入 / 输出 / 合计，

- 2026-10-27（批 4 · P2-2 的后端半边）：变更账落地，但**不是**当初设想的事实族。
  动手前把「谁能在写的那一刻落一条事实」核了一遍：agent 的 `vdfs_*` 工具走
  `UnifiedFs → PhysicalFs`，不经过会话写侧；shell / MCP / 操作系统的写入完全不经过
  VDFS；唯一完整的观察者 `FsWatcher` 只在界面订阅工作目录时启动，且拿不到轮归属。
  在网格里加 `file` 行（`opened` / `asserted` / `closed`）会得到**第二份写点**：它只能
  记下「经由某条路径的变更」，却会被读成「工作目录的变更」，且与文件系统本体不一致时
  两边都自证正确。裁决落在 [D-169](../003-design/001-核心架构.md "DE-001-核心架构")：
  **变更账是 `artifact.added` 的一条投影，网格维持 11 行**。四处落点：① 新投影
  `symbio_core/projection/changes.rs::workdir_changes`——只认成功的写族工具
  （`vdfs_write` / `vdfs_edit` / `vdfs_delete` / `vdfs_mkdir`），路径取定稿参数
  `args.path`，界外 / 虚拟根下的路径不计，每路径最新一条胜出 + 次数，最近改过的在前；
  ② `vdfs_edit` 的结果补 `path` / `replaced`——无操作（`old_string == new_string`）
  因此能靠字段判，而不是匹配中文提示；③ 只读路由 `session/changes`（`read_changes`），
  行**呈现就绪**（`{path, address, op, label, turn, changes}`）：前端不解析参数、不拼
  VDFS 地址、不认识工具名；读侧闸与 `session/stats` 同一道（看不到内容 ⇒ 空清单）；
  ④ 前端常量随门禁生成。边界写进决策：用户编辑器保存 / shell / MCP 的写入没有轮归属，
  留在实时面不入账；没有写入前全文，**不做 diff**（打开的是当前文件）。
  用例：core 七条（成功过滤 / 最新胜出与计数 / 顺序 / 无操作编辑 / 界外与元数据路径 /
  路径归一 / 参数形状 / as-of）与会话出口三条（呈现就绪 / 有据的空 / 读侧闸）。
  **未承接**：面板本身（批 5）。

- 2026-10-27（批 5 · P2-2 的前端半边）：会话头的「变更」抽屉 + 「打开文件」的地址形态。
  **先修了批 4 的一处契约错**：`address` 原先写成 `<sid>/workdir/<path>`，那是物理半边的
  形状（虚拟地址以 vdfs 根名开头），直接喂 `vdfs/read` 会落到物理工作目录；且它与会话
  地址拼合时会把 sid 重复一遍。改为**相对会话容器**的 `workdir/<path>`，拼合由前端经
  `vdfsJoin(activeAddr, address)` 完成——出口只给「会话内部的那一段」，拼完整地址是地址
  代数的事。同时补 `readable`：有源但无权查看与「没改过」都是空行，只靠 `has_wal` 分不开
  （空表会被读成「没改过」）。
  前端五处落点：① `services/sessionChanges.ts` 原样透传；② `SessionChangesList.vue` 是
  纯排版器（`op` 只作判别词，文案取 `label`；三种空各一句话）；③ `ChatMainPanel` 的抽屉与
  **读数共用一个位置**（`drawer: 'reading' | 'changes' | null`——两个布尔会同时滑出、互相
  盖住，而界面看起来正常），读取时机与读数同一条纪律（打开 / 切会话 / 轮末，不轮询）；
  ④ 点行**不导航**：渲染器只 `emit('open-node')`，经 `Session` → `VdfsSessionDetail` →
  `VdfsWorkbench`（用 `vdfsParent` / `vdfsBase` 拆「父目录 + 末段名」）→ `VdfsView` push
  `?select=`；⑤ `useVdfs` 的落位：`?select=` 把当前目录**定在绑定地址自身**（缺省会选
  第一个子目录，文件所在那层反而不在中栏），本页找不到就按地址 `stat` 一次；落位只在
  「地址 + 选中项」真变时重放，用户随后自己点目录不会被抢回。
  判据：出口三条不变；`SessionChangesList.spec.ts` 五条（行原样呈现 / 点击上抛 / 三种空）；
  `ChatMainPanel.changes.spec.ts` 五条（关着不读 / 点行拼地址 / 切会话重读 / 两个抽屉互斥 /
  轮末重读）；`useVdfs.spec.ts` 深链五条（定住 + 选中 / `stat` 兜底 / 坏形状 / 用户离开后
  不重放 / 只换选中项不重订阅）；e2e `t86-session-changes`（真实写盘两行、no-op 编辑不计、
  读侧闸、无源）。文档：`RE-003` 的路由行、`DE-010` §4.5（深链形态的唯一 owner）、
  `DE-020` §11 与 P2-2 行、§3 P2-2 项。
  **未承接**：P2-5 的裁决与切换器（批 6）。
