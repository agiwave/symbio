# S1：名册 54 条逐条处置账

## 内容

[DE-008-能力注册表与能力坐标系](../003-design/008-能力注册表与能力坐标系.md "DE-008-能力注册表与能力坐标系") §6.1 的 54 行能力是拆分的完整输入。
[DE-026-能力拆分与影响类](../003-design/026-能力拆分与影响类.md "DE-026-能力拆分与影响类") 只定处置规则（A/B/C/D/E 五档怎么翻译成
「拆 / 留 / 待裁决」），本文负责逐行落账。每一行回答三个问题：

1. **本体是什么**：执行体 / 判定生产者 / 纯读数 / 机制；
2. **输出落在哪个影响类**：I-1 事实、I-2 段、I-3 裁决、I-4 模型往返、I-5 省略、I-6 下一段；
3. **若不能写进 I-1…I-6**：它属于哪一类留守——环、写口、全局守门、过程体、会话基底
   （五类，DE-026 §1），还是「共享折叠但第二读者尚未改名字读」（D-221 的过渡态）。
   E 机制本体是判定档（DE-026 §2.2），不另立残留类：它的每一行都落在这五类之一，
   理由列写明是哪一种封闭语法 / 判断种类 / 配对契约。

**判据是「能拆都拆」**：只有写不进影响类的才留守；「今天没有端口」先补端口，不作为留守理由。
两行共用一份实现是合法的（如技能路由的两行、校准的两行），但必须在账里写明「与某行同包」。

**`归` 列是交付承诺**：记为拆的行必须落到 S6（`loop` 存量）/ S7（`session` 存量，
含随 conation / 主动性包一起落地的四条未建能力）/ S8（共享折叠搬 owner）/ S9（未落地
能力包）之一；待裁决落 S10；留守行不给交付段（`—`）。`EX-006` 判这一列——缺段或段
不在闭集即红：「拆」不是一句承诺，得有人认领。

**「先补端口」= 补件单列，不是迁移里硬拆**（D-247 / `EX-007`）：账里记为「拆」的行，若进入
S6 / S7 后发现还需要一条新机制才迁得动，就把这一行改回「待裁决」，补一条带 `### D-NNN` 的
独立提交把端口落定（通用、不含能力名），再继续迁移。迁移提交里不许出现机制增量，也不许
把这一行的实现搬进 `core` / `kernel` 冒充端口。

已落地的能力里，**除机制本体之外没有一条无路可走**——C 的 15 行与 D 的 6 行
