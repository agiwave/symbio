## 内容

### 为什么要有这一次演练

`TC-5` 断言"加一个世界端口 = 声明 + 适配器"，但这条断言今天**没有被验证过一次**。
控制系统里唯一一次"加端口"（`turn`）的代价是：第四台 host + 一个只为避开假环而单开的视图 +
一段驱动循环 + 一个交付域，约 1200 行。用那一次当样本，结论会是"加端口很贵"——
所以不能拿它当基线，必须**从一个干净的形状上再加一次**，看看到底是几行。

### 验收的形状（不是"能跑就行"）

| 维度 | 要求 |
|---|---|
| 机制层 | `symbio-kernel` 的求解器字节不变、公开面不变（`TC-5` 可判） |
| 声明面 | 只加 `PortDecl` 一行 + 两行模板 + 五条协议名（协议名不加新的） |
| 编排面 | 不加 host、不加视图、不加驱动循环——若必须加，说明 `TC-1` 的形状还没收敛 |
| 适配器 | 只碰 I/O 的那一层，不含判断 |
| 读数 | 三个数字：声明行数 / 适配器行数 / 其它改动行数；"其它"必须接近 0，否则原因要写清 |

### 候选端口（由裁决决定，不在这里定）

- **`clock`**：方案列过、未落地。它是否算"世界端口"取决于它有没有"结果可能回不来"的性质——
  定时唤醒走的是事件，未必需要端口。
- **`storage`**：同理，它今天是 `Store` 能力，不是端口。
- **第三条路**：若不选上述两个，可用一个**真实的**新外部能力（例如某类远程检索）做演练——
  演练对象必须是真需求，不能为演练造一个假端口。

### 不做什么

- **不为了凑数加端口**：若裁决的结论是"端口闭集就是两个世界端口"，那本任务的正确产出是
  **一个反例记录**：写清"为什么不需要第三个"，并把 `TC-5` 的判据改成断言闭集本身。
  这不算任务失败——它比硬加一个端口更有价值。
