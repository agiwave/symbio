- 2026-10-25（续）：**T-280 收口（G-16 · 骨架惰性重取）**——动作的后端骨架与前端原语
  在 T-150-i / T-150-ii 已分别落（`words.rs` 常量、`messages_at` 的 Action 臂、
  `nodes.rs::subtree_nodes` BFS、`stores/skeletonLazy.ts` 纯函数与 localStorage 账本），
  本批补的是**五条判据的落点**：
  1. **入参（判据 1）**：`expand_skeleton` 的 `depth` / `since_seq` 由「非法即缺省」
     改为**非法即报错**——`depth` 只收字符串 `"1"` / `"all"`（数字 `1`、布尔都不认），
     `since_seq` 只收 i64，载荷必须 JSON 对象；非法报 `invalid` 并**点名实得值**。
     静默按缺省的后果是「以为只要直接子」的调用方拿到整棵树而回执里看不出来。
     显式 `null` 与缺省同义。判据落 `vdfs_provider.test.rs` 的
     `expand_skeleton_rejects_malformed_params`（七种非法载荷 + 两条合法边界）。
  2. **窄帧（判据 2）**：出参 `{ session_id, root, nodes }`，`nodes` 是按 `seq` 升序的
     子树窄帧（带 `id` / `parent_id` / `seq`，**不含骨架自身**）；骨架不存在回空数组
     ——只读动作，「没有」就是空，不是错误。
  3. **重取 = 全量读（判据 3）**：e2e **t85** 跑真会话（一次真实工具调用 ⇒ 整轮骨架 ⊃
     工具骨架 ⊃ 工具结果，天然两层），把「按骨架 id 重取的子树」与「从全量转写里按
     `parent_id` BFS 出的后代」逐条比三元组，并钉 depth="1" 只直接子、since_seq 只回
     更高的、只读（前后转写一条不少）、非法入参**不带 nodes**。后端单测造的是手工树、
     前端单测造的是手工扁平表，两侧各自自洽——只有真会话能把两份对上。
  4. **折叠态可见（判据 4）**：`ReleasedSummary` 补 `byType` / `running`，纯函数
     `statsOf` 结算（在途按 `isStreamingStatus`）；`SkeletonNode` 出一行摘要 chip
     （多少条 / 什么类型 / 还在跑几个，类型经 `messageTypeLabel` 翻成人话），并**抑制**
     「无响应兜底」——子节点是被本地摘掉的，不是「这次没跑」。折叠态变化由 `NodeShell`
     的 `collapse` 事件经 `SKELETON_LAZY_KEY` 注入面转给 `useChatConnection`
     （与 `RESUME_KEY` 同一条理由：相遇点在组件树深层，会话 id 只由闭包持一份）。
     判据落 `MessageNode.spec.ts` 六例（含「缺注入面 ⇒ 界面照常」）。
  5. **反向（判据 5）**：重取回 `ok` 但 0 条、而账本 `count > 0` ⇒ **不摘释放标记**
     并告警（数据不一致，保持折叠态可重试）；count=0 的空子树是正常情形照常摘。
     另两条守卫同批：**在途骨架不释放**（streaming / 待审批的增量会经落地口把节点带
     回来，当场与账本分叉）、无后代不入账。判据落 `useChatConnection.spec.ts` 七例。
  另两处是**面**问题：`hydrateFromHistory`（唯一水合口）回放账本——骨架已不在快照的
  条目就地清偿，`dropSessionState` 同批 `forgetSession`（否则账本随会话数单调增长）；
  DE-019 §6 按落地契约重写（`depth` 定类型、出参形状、只读边界、`unloaded` 是纯前端
  状态不进 wire）。T-280 收口即删。
