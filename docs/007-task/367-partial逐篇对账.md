# partial 逐篇对账——17 篇的每处残余指认归属

## 内容

### 现场

`impl: partial` **17 篇**。按残余的性质分三类，三类不是同一档工作量：

| 类 | 篇目 | 残余是什么 |
|---|---|---|
| **架构面残余**（等 `T-357` 落地） | 021 / 022 / 023 / 025 / 047 / 048 / 051 / 053 | 行去 `by`、会话端口、行内两出口、视图 owner 对账、终答拓扑——都在 `T-357` 的子任务里 |
| **产品面残余**（真功能缺口） | 007 / 019 / 020 / 036 / 040 / 043 | 外部插件三期未排期、折叠呈现轴未统一、前端六项、向量索引判过不落、分级器缺席、申诉触发器裁决不建 |
| **总纲与登记面** | 002 / 011 / 052 | 002 是「目标架构总览」的长期 `partial`（迁移未完成即如此）；011 的权限四字段已落地待复核；052 是过渡机制待撤 |

### 判定

对账的口径只有一条：**每一处残余要么指到落地锚，要么指到承载它的任务编号，要么被一条
裁决排除**。三者都不是的，是**真欠账**，要登记成任务而不是留在正文里当形容词。

`done` 的门槛是「所有残余都有落地锚」；`partial` 的合法形态是「残余有归属（任务编号或
裁决号）」。所以本任务的产出不是「把 17 篇改 done」，而是：

1. 每篇的残余清单化（现在有些是散在正文里的句子）；
2. 每条挂上归属：`T-357` 的哪个子任务 / 哪条 `D-NNN` / 哪条「判过不落」；
3. 残余全部落地的篇目改 `done` 并写 evidence；
4. 仍有残余的篇目保持 `partial`，正文那段改成「还差什么 + 谁在管」。

### exit

- 17 篇逐篇有对账结论，且 `registry-board --kind=design` 的档位分布与正文自洽；
- 改 `done` 的篇目能指得出落地锚（测试名 / 文件行 / 判据码）；
- 保持 `partial` 的篇目，正文里那段残余**不是形容词**——是清单，每行有归属；
- `registry-audit`、`doc-link`、`doc-symbol` 绿；`gate.mjs --full --ci` 绿。

### 不做什么

- 不批量改档（`RG-017`：`partial` 却没人解释还差什么是登记瑕疵，`done` 却指不出落地锚同样是）。
- 不把「裁决不建」写成「已完成」——`D-108`（申诉触发器）、`D-157`（五项能力）、
  `D-152`（向量索引）都是裁决排除，档位可以是 `done`（设计已定案）但正文必须写「不建 + 理由 + 重开条件」。
- 不在对账里顺手改架构——残余的实现归 `T-357`，本条只做登记与措辞的同步。
