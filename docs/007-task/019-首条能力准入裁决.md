# C1：第一条能力的家

## 内容

**缺口不点名能力**：位置闭表的准入是「不含能力名 ∧ ≥2 条能力」。当一条能力是**族里第一条**
时，它没有家——先补件会把机制按一条能力定制，不补件则这条能力无处可落。今天的处理是
「先落骨架，等第二条出现再补件搬迁」，但账上没有「期限」与「承接任务」，于是临时骨架
可能永久化。

| 选项 | 形状 | 代价 | 风险 |
|---|---|---|---|
| C1 骨架 + 计划 | 准入仍 ≥2；首条先落骨架，账里写期限、触发条件（第二条何时出现）与承接任务 | 控制面会短暂出现一段按能力写的实现；需要有判据把「有计划」与「没有计划」分开 | 计划过期不搬 ⇒ 临时骨架永久化；期限写了没人查 |
| C2 准入 ≥1 | 改 `D-269`：≥1 条能力 + 明确的移除计划即可开格 | 每条首条能力都能立即落包；补件面变宽 | 一次性端口合法化；「移除计划」若不可判就退化成口号 |
| C3 维持 ≥2 | 不做，等第二条能力 | 零风险 | 单条能力（族里没有同伴的）永远不做；与父任务「33 条可插件」冲突 |

## 处理过程

1. 读 `D-269` 两条准入与 §5.2 的缺口账，列出今天「首条能力」的实际案例与它们各自的第二条候选。
2. 三套选项逐条写：开格条件、移除计划的字段形状（期限 / 触发条件 / 承接任务）、谁来判「无计划」红。
3. 若选 C2，修订范围只到 `D-269` 的准入段，不改位置闭表本身；另立 `T-020` 落流程。
4. 裁决落进宿主设计文档（`### D-NNN`）；本任务不改任何代码与账本格式。
