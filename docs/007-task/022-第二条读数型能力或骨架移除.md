# C2 接棒：第二条读数型能力或骨架移除

## 内容

`D-294` 给第一条准入能力定的不是「永久保留」，而是一份**可判的移除计划**：期限、触发条件、承接任务。本任务是那份计划里写的承接方——它不新增架构，只负责在期限或触发条件到达时把骨架处理掉。

两种合法结束：

1. **触发**：第二条读数型能力进入 S9 ⇒ 这一格不再靠一条能力撑着，`forecast.remaining` 要么转正为独立的读数能力，要么并入新的读数能力包（同包合法的判据见 `DE-026 §2.3` 的「与 #N 同包」）。
2. **到期**：2027-06-30 仍未触发 ⇒ 撤掉 `crates/symbio-plugin-forecast` 与 `forecast.remaining`，把 #34 行的骨架计划换成普通处置记录。

两条路径都不改 `drive` 的语义，也不新开审计脚本。

## 处理过程

1. 每次 `EX-006` 或登记审计读账时确认 #34 行的计划仍指向本任务；若本任务已拆分或改名，同批改账。
2. 触发条件成立 ⇒ 落一条新的设计裁决（或改判现有行），再删骨架；不得只在账里删字。
3. 期限到达 ⇒ 删 crate、删 `shared_views` 条目、重跑 `gen-facts` 与门禁，账行同步改判。
4. 收口时按任务体系「收口即删」：结论先落 `DE-026`，再删本文件。
