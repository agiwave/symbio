## 内容

本批把「加一个能力总要改架构」收口成 **能力包 + 通用端口**。目标形状、扩展契约与判据
归 [DE-025](../003-design/025-能力包与扩展面.md "DE-025-能力包与扩展面")；事件词汇与跨插件地址的既有通路归
[DE-024](../003-design/024-能力横向扩充的通路.md "DE-024-能力横向扩充的通路")。

批次按依赖而不是编号推进：

1. **S1.0 事件词汇收口**：CS-005 的 21 条业务事件名迁到 0，删 `CELLS` 回退臂；
   它是「新事件零 core」这句话成立的前提。
2. **S1.1 行为位开放**：`CapabilityMeta.behaviors` 替掉三个布尔位；新行为实例只改能力包。
3. **S1.2 效果端口**：`ToolBehavior` 收集与 `FactDraft` 落地；任务表 / 承诺 / 文件变更
   的效果回到各自 owner。
4. **S1.3 领域扩展位**：`Entity` 的 `Domain` 扩展位 + `CS-009` 数据面棘轮；新领域零 kernel diff。
5. **S1.4 上下文端口**：`ContextProvider`；`run_recall` 从固定实现变成收集器。
6. **S1.5 部署生成**：主体 / 权限 / 工具命名空间 / 触发 kind / 链接行由清单生成。
7. **S1.6 验收**：`notes` 扩展夹具与零 core diff 的卸载判据。
8. **S1.7 判据反向**：`SC-006` 与扩展夹具接入门禁，防回流。

父任务只定顺序与验收；子任务各收一段。能一个任务说清的不硬造层级。
