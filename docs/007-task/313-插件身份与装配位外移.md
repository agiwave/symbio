## 内容

当前「加一个插件」要同时改内核的三张手写表：`PLUGIN_ID_*`（21 个）、
`ROUTE_*`（跨插件路由）、`ASSEMBLY_*`（装配清单）。这三样都是**部署事实**，
不是语法；它们住在内核里，等于每加一个插件都要改一次架构模块。

收口形状：

1. **身份归插件**：插件 id 由插件自己的清单 / 模块持有，内核不认识具体 id。
2. **路由归两端**：跨插件路由由发起方与承接方的契约声明，不再集中登记。
3. **装配归装配方**：装配清单是宿主数据，由装配方决定接哪些插件；内核只接收结果。
4. **生成簿记**：需要集中索引时由清单生成，不手写第二份。

验收用「新增一个最小插件」的改动集来判：内核目录零 diff。
