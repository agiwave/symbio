# 外部插件三期——D2 / D3 / D4 先裁决，再跑通端到端

## 内容

### 现场

[DE-007-第三方插件体系](../003-design/007-第三方插件体系.md) §2 列了**八类障碍**，逐条有处置方案；其中第 3 条已删除
（`PluginPayload` 的 `Native` 死变体，评审 P1 已落地），其余七条是方案而不是实现。§10 的三条决策仍是
**「本期暂不裁决（不实施外部插件）」**：

| 决策 | 悬着的点 |
|---|---|
| `D2` | 外部插件形态：stdio 首选 + HTTP 次选，去掉动态库 |
| `D3` | 权限强制程度：已定案「仅声明校验」（`D-032` 终态判定，已闭批） |
| `D4` | 外部插件连接信息放哪：扩展 `plugin_provider` 值语法，零新增键 |

第二期 / 第三期（开放 provider 与生命周期、HTTP 传输与权限强制）在文档里明确写着
**未排期（本期不实施）**。这不是缺陷登记，是一个**被推迟的整块能力**。

### 判定

「未排期」与「欠账」的区别在于：欠账是「该做、没做、有归属」，未排期是「还没裁决做不做」。
所以本任务的第一步不是写 transport，是**把三条决策裁掉**——裁「做」才排期，裁「不做」
就把 `DE-007` 的处置列改成「裁决不实施 + 重开条件」，八类障碍的账也就此收口。

裁「做」之后的施工顺序是硬的（每步都要端到端可跑，不能一次铺三层）：

1. **stdio 握手 + 生命周期**：`init` / `shutdown` 帧。这一步依赖 `T-362`——
   `HookEvent` 的 `SessionStart` / `SessionEnd` 正是生命周期的钩子面，钩子面没补齐时
   外部插件的「启动/退出」无处挂。
2. **一轮真实往返**：外部插件注册一个 provider，被环取到，跑完一次端口往返。
3. **HTTP 传输**：复用 `gateway` 的线上类型（`PluginMessageWire` / `PluginPayloadWire` /
   `PluginFrame`），方向相反——入站变出站。这是「复用而非新造」，所以放在最后。

### exit

- `D2` / `D3` / `D4` 三条各有裁决（做 / 不做 + 理由 + 重开条件）；
- 若裁「做」：一个最小外部插件走完「stdio 握手 → 初始化 → 跑一轮端口往返 → shutdown」，
  判据是一条集成测试而不是手工验证；
- 若裁「不做」：`DE-007` §2 的八类障碍处置列全部改为「裁决不实施（`D-NNN`）」，
  第二期 / 第三期的「未排期」改成明确的不做结论；
- `plugin-surface-audit` 的 `HS-002` 若新增公开项，有 `core-shape-allow` 或等价论证；
- `cargo test --workspace` 绿。

### 不做什么

- 不动态库（`D2` 已裁：stdio 首选 + HTTP 次选）。
- 不做运行时沙箱（`D3` 已定案「仅声明校验」，`D-032` 闭批）；权限只做声明校验。
- 不为「未来可能有外部插件」在机制面留恒空的槽位（`DE-007` §11 已明确否掉）。
- 不在钩子面补齐之前铺 transport——生命周期无处挂，铺出来的是半条链。

## 处理过程

  本条先裁后做，裁「不做」也是合法收口。
