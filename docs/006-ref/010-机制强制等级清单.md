# 机制强制等级清单

> 本文回答一个问题：**每条机制违规时，谁会红？**
>
> 它是「强制等级」这件事的唯一 owner。判据本体在同一目录的守卫脚本
> [`scripts/mechanism-enforcement-audit.mjs`](../../scripts/mechanism-enforcement-audit.mjs)
> （ME-001–005），本表只记**谁在执行**——执行细节住各自的守卫脚本与生产代码，
> 这里不复述规则（第二份规则必然漂移）。

## 0. 怎么读

三个等级按「约束的实际兑现方式」分，不按「设计意图」分：

| 等级 | 含义 | 典型形态 |
|:-:|---|---|
| ① | **编译期强制**：违规编译不过 | 类型 / 泛型边界 / 枚举穷尽 |
| ② | **运行时阻断**：违规被拒且有错误信号 | 闸门 / 守卫 / 白名单校验 |
| ③ | **纯声明**：规则写了，**没有执行方** | 文档 / 配置 / 默认值 |

三条边界（不随条目增长放宽）：

1. **豁免有上限**：③ 类条目数超过 `MAX_EXEMPTIONS` 即红——否则「全部挂豁免」等于没有清单；
2. **豁免带期限**：每条豁免指向一个承载它的任务编号或 ADR，解析不出即红；
3. **清单是判据的索引，不是判据本身**：执行细节住各自的守卫脚本。

③ 与「还没做」不是同义词：③ 是**已经承认的缺口**，必须挂 `mechanism-allow`
（见 §6）。从一个 ③ 变成 ①② = 在豁免块里删掉那一行，同时把执行方填进 §1–§5。

## 6. 豁免（③ 纯声明）

一行一条，格式 `mechanism-allow <机制键>: <ADR 编号或任务编号> <理由>`。
③ 类行**没有对应豁免 ⇒ 红**；①② 类行**带豁免 ⇒ 红**（等级与豁免必须一致）。
理由不可为空；总数超过 `MAX_EXEMPTIONS`（守卫脚本内）即红。

```mechanism-allow
mechanism-allow I2: T-188 写侧阻断归不变量写侧阻断批
mechanism-allow I3: T-188 写侧阻断归不变量写侧阻断批
mechanism-allow 闸·熔断: T-186 时间基准修复归虚闸清偿批
mechanism-allow 闸·local 策略: T-186 默认值翻向与一致性裁决归虚闸清偿批
mechanism-allow 闸·入站边界: T-194 并发上限与幂等键归入站边界加固批
mechanism-allow 投影签名·降级与预算消费: T-187 生产消费方与纯度守卫归投影签名兑现批
```
