# SLO 校准 · 首测（2026-09-30）

> 对应 [04 §1](./04-工程落地.md) 的告示：「所有百分比与毫秒数是初值，必须在阶段一埋点后校准」，
> 以及 [03 §7.3 G2/G3](./03-演进与验证.md)：G2「只有预算断言，没有实测」、G3「成本模型只有参数，无实测数字」。
> 本文是**第一份实测记录**——后续每次校准追加一节，历史数字不删（可回看漂移）。

## 1. 埋点设施（本轮落地）

| 设施 | 位置 | 说明 |
|---|---|---|
| `LlmAdapter::generate_timed` | `symbio_core/adapters` | trait 默认方法：adapter 边界 `Instant` 计时，返回 `(文本, 实测毫秒)`。桩与真实适配器零改动共享 |
| `Reasoner::reply_timed` | `symbio_core/actors` | 埋点版 reply；`reply` 委托它 |
| `cost_ms` 入事件 | final 事件字段 | 调用方把实测值写到 `chat.assistant.final` 的 `cost_ms` |
| ③ `cost_ledger` | `symbio_core/projection/cost` | 按主体累计——**熔断判据「已耗多少」从此读实测值**（S8 落地，本轮接上真实来源） |

闭环：**adapter 边界实测 → final 事件 `cost_ms` → cost_ledger 累计 → CircuitBreaker 判据**——
成本是同一份事实源算出来的，不是旁路统计（N1 同口径）。

## 2. 实测方法

- 链路：事件网格（`EventStore`）→ `Reasoner`（持 `FullModel` 令牌）→
  `ProviderLlmAdapter` → `BoundProvider::execute_turn`（五态机）→ openai_chat
  SSE 解析 → **真实 TCP + HTTP/1.1 + 流式响应**（本地 `TcpListener` mock 即答）；
- 样本：12 轮全链路（每轮新建连接——最坏情况，无连接复用红利）；
- 计量：`generate_timed` 在 adapter 边界的耗时 = 传输 + 协议 + 解析 + 聚合，
  **不含模型推理**（mock 即答）——这正是「系统自身开销」的定义。

## 3. 实测结果（2026-09-30，Windows，单进程）

| 统计量 | 实测 | 对比预算 |
|---|---|---|
| 样本 | `[1, 1, 1, 1, 1, 1, 1, 1, 1, 2, 2, 3]` ms | — |
| **P50** | **1 ms** | 反射档 80 ms → 占 **1.3%** |
| **max** | **3 ms** | 快速档 300 ms → 占 **1%** |

守卫固化：`reflex_tier_system_overhead_is_measured_and_bounded`
（P50 ≤ 80 断反射档、max ≤ 300 断快速档——超界即「链路自身失控，与模型无关」，
CI 每轮重测，数字回归会被当场抓住）。

## 4. 解读（G2/G3 的回答）

- **G2（硬实时预算）**：反射档 80ms 预算中，系统自身开销 ≈ 1ms——**98% 以上留给模型**。
  「预算断言」有了实测背书：预算约束模型为主，链路自身不是瓶颈。SLO 初值 80/300/60s/24h
  **在本机实证下无需下调**。
- **G3（成本模型）**：`cost_ms` 从声明值变为实测值，cost_ledger 与熔断判据的输入
  从此是真实测量。成本 SLO（兜底率 < 1%/3%/5%/5%）的**分母有了可信来源**；
  兜底率统计仍待真实模型流量（阶段三出 P99）。

## 5. 边界与后续

1. **本测不含模型推理**——模型时代单轮耗时 = 系统开销（~1ms）+ 模型延迟（主导项）。
   接真实 provider 后同法重测，才是完整校准（下一步候选 3：CLI 挂真 provider）；
2. 单进程 localhost，无 TLS/代理/跨机网络——生产网络开销另计；
3. **P99 出自阶段三**（[04 §1](./04-工程落地.md) §1.2 的承诺）：跑量后从事件日志
   扫描（final 事件自带 `cost_ms`，扫描器无需埋点设施——数据已经在事实源里）；
   **扫描口已就位**（2026-09-30）：`slo_report` 投影（时延列口径——final 实测
   按 turn 归档，兜底轮不混入样本）+ `slo_scan_wal_roots` 扫描（opt-in，
   `SYMBIO_SLO_SCAN_ROOTS` 指向会话存储根，递归找 v2 事实桥落的
   `v2-events.wal`，跨会话合并出 P50/P95/P99 + 兜底率）——三列同一事实源，
   判据零复制（[ADR-045](../decisions/core.md)）；
4. 兜底率（SLO §1.2 第三列）需要真实流量的 fallback 事件计数，同样待阶段三
   （读数口同上，`fallback_rate` 投影已被扫描口复用）。

## 5.5 完整校准 · 真实端点复测（2026-09-30，同日）

§5 第 1 条待办当日兑现：`real_provider_full_calibration`（opt-in，`#[ignore]`，
凭 `SYMBIO_REHEARSE_API_BASE/_API_KEY/_MODEL` 即跑）接**真实模型端点**复测。

- 端点：LMStudio（局域网，本地模型 `google/gemma-4-e2b`，OpenAI 兼容
  openai_chat 协议）——与 CI 校准完全同形，只把 mock 换成真实端点；
- 链路全程不变量守卫：每轮落 final 后 `check_all` 即时校验（N3 每轮
  独立成 turn、N5 溯源指向本轮用户消息）；
- **实测（6 轮）**：样本 `[3603, 3681, 4009, 4051, 4228, 4595]` ms，
  **P50 = 4051ms · P95 = 4595ms · max = 4595ms**——全部落在**深度档
  （60s）内**，预算余量 > 92%；
- 解读：单轮耗时 ≈ 系统自身开销（~1ms）+ 模型延迟（~4s，主导项）——
  与 §4 的归因一致；四层预算把「模型延迟是主导项」接住了。

端点连通性对照（同日排障记录，均为**真实边界行为**且按 I3 映射为
`GenerationFailed`，无 panic 无静默）：usrouter（402 免费额度需签到）、
b.ai（网络不可达，57s 超时）、xkiro（403 付费墙）——错误映射路径本身
就是兜底演练（I3 到点必答）。

## 5.6 兜底率统计口径（2026-09-30）

SLO §1.2 第三列（兜底率上限 <1%/3%/5%/5%）的**测量口径**落地：

- **③ `fallback_rate` 投影**：turn 档位 = `user.message` 载荷 `tier`
  （`LatencyTier::name`）——「装配进哪一档」是数据，写进事实源；
  兜底 = `chat.assistant.fallback`（`turn × closed`）按 turn 号归档；
- **缺失/未知档位进 `unspecified` 桶**——可观测，不静默归类；
- 投影只报数，达标判定交给读方（SLO 是承诺，投影是事实）；N1 双跑一致；
- 真实兜底率仍待真实流量（阶段三出数）——本地演练中失败注入的兜底率
  是演练数字，不是 SLO 实测。

## 6. 结论

**初值 80 / 300 / 60000 / 86400000 ms 保留为正式值**——首测证明链路自身开销
在反射档预算中占比 ~1%，预算的约束对象（模型与判定者）与设计假设一致。
G2 的「没有实测」降级为「有首测、待真模型复测」；G3 的成本输入已接实测。
**真实端点复测（§5.5）已补上模型延迟主导项**：本地小模型 ~4s/轮落深度档，
预算体系完整工作。G2/G3 均闭合。
