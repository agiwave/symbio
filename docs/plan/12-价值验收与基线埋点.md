## 0. 一句话

**v2 已经把事实写进网格，但网格没有读侧出口**：`slo` / `fallback` / `cost` /
`calibration` / `transcript` / `readyset` / `reputation` 七个投影在生产路径**零消费者**，
`<会话目录>/v2-events.wal` **只写不读**。所以「时延 / 兜底 / 成本」三类收益
**当前无法验收**——**不是缺数据，是缺读数口**。

ADR-044 说的是「实测与判据同源」。现状只做到了**实测**（`cost_ms` 真的入格了），
没做到**判据**（没人读它）。于是分支的全部价值主张停在**能力清单**（能做什么），
而不是**证据**（做到了多少）——这正是 ADR-044 要防的那种状态。

**这不是"推翻 v2"**：加固只加**读**（出口 + 复算），不改网格、不改写入路径。

## 2. 缺口：网格只写不读（D0 埋点）

### 现状

- **写**：`plugins/session/v2_bridge.rs`（bridge 档：每轮收束转写）与
  `plugins/session/v2_exec.rs`（full 档：事实原生入格）把每轮写进
  `<会话目录>/v2-events.wal`。
- **算**：`symbio_core/projection/` 下七个投影（`slo` / `fallback` / `cost` /
  `calibration` / `transcript` / `readyset` / `reputation`）都能从事件切片算出视图。
- **读**：**没有生产调用点**。`slo_report` / `fallback_rate` 的全部调用都在
  `*.test.rs` 里；`v2-events.wal` 除了**写方自己**（桥 / 执行器）再无人打开。

### 破的是哪条

**ADR-044 的后半句**（"判据同源"）。同一份事实既能写又能算，却没有任何一条
生产路径去**读它**——那么：

- 分支的收益主张（v2 是否真的降低了往返、兜底率是否真的下降、成本是否可控）
  **无法用数据回答**，只能靠"机制上应该更快"；
- 反过来，**回归也看不见**：兜底率悄悄上升、P99 悄悄劣化，门禁与运行时都无信号
  （与 [11 §0](./11-多执行器与多主体加固实施方案.md) 的"破了没有信号"同一个形状）。

### 兑现步

**批 0**（见 §3）。**读侧出口是纯读**——它不改写入、不改网格，因此可以先于
[11](./11-多执行器与多主体加固实施方案.md) 的加固批独立落地。

## 3. 分批计划

排序原则：**先把"已经能算、只是没人读"的接出来（P0，成本最低、证据最直接），
再补"要接线才有数据"的（P1），最后做与 [11](./11-多执行器与多主体加固实施方案.md)
合流的接线（P2）。**

> **完成判据（每批两件事同时成立，缺一不算完成）**：① 出口接进**生产**调用点（测试调用不算）；
> ② 它引出的 `#[allow(dead_code)]` 承认标记全部摘除——步状态与死码基线只登记在
> [04 §3.1](./04-工程落地.md)，本节不复述数字。

### 批 0（P0）· 读侧出口 —— 最小可用 —— **已完成**

- 归属：本文 §2。死码侧：[04 §3.1 批③](./04-工程落地.md)。
- 出口形态：二选一取 **② 一条只读路由 `session/stats`**（非 CLI 子命令），一次给出
  **四列**——时延（`slo`）、兜底（`fallback`）、成本（`cost`）、断点（`checkpoint`）。
  读数来源 = 该会话的 `v2-events.wal`（`WalStore::open_readonly` → `range` → `apply`；
  只读开档不创建、不截断撕裂尾行）。
- **第五列 `invariants`（随 [04 §3.1 批④](./04-工程落地.md) 补入）**：同一次读里顺带跑

  那张参数表受 `verify/mechanism_growth.rs` 守恒审计，为登记一个路由去加键会让审计失真。
- **为什么先这几个**：P95 与兜底率是报告点名的两类收益，四个投影**都已存在**——
  批 0 不新增计算，只新增**读数口**。
- 判据：✅ e2e（`e2e/cases/t28-session-stats.mjs`）—— 跑一轮成功 + 一轮兜底后，
  从出口读到的 P95 / 兜底率与**读方复算**（同一份 WAL 直接 `apply`）逐字相等；
  **反向用例**三刀：删掉收束事件 ⇒ 样本列 1 → 0，删掉一个开轮事件 ⇒ 兜底率分母
  2 → 1，把一格开轮事件**复制**成两条 ⇒ 不变量列报「每 turn 至多 1 条开轮」
  （第三刀随 [11 批 0-B](./11-多执行器与多主体加固实施方案.md) 补入；[批 1](#批-1p1-成本与校准--已完成)
  在同一用例上另加一注——证明它真的在算、不是常数）。单测 `stats.test.rs` 覆盖复算 /
  反向手术 / 缺源不创建文件。
- **写侧前提（已随本批订正）**：`v2_bridge::first_user_utterance` 的判据曾只认
  `status = Completed`，而 `chat/send` 的用户消息不填该字段 ⇒ 转写恒不发生且**无告警**，
  出口读到的四列恒零。详见 [04 §3.1 S2](./04-工程落地.md)。

## 4. 出口判据

与 [08 §2](./08-分步实施计划.md) 同一口径，三条缺一不可：

1. **单测**：读方**复算**——同一份事件切片，出口的读数与直接 `apply` 逐字相等；
   含**反向用例**（改一个事件 ⇒ 读数必须变）。
2. **e2e**：`node e2e/run-tests.mjs tNN` 绿，从**真实会话目录**的 WAL 读，不是造样本。
3. **门禁**：`node scripts/gate.mjs` 全绿。

> **为什么"复算"是硬要求**：本方案的唯一风险是"出口自己算了一遍，与投影漂移成两份口径"。
> 判据因此必须**同源**：出口只能调**已有的**投影，不得另写一份统计。缺了它，
> 加固等于给同一件事长出了第二个定义（[11 §4](./11-多执行器与多主体加固实施方案.md) 的反向用例纪律同源）。
