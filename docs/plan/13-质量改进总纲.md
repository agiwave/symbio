## 0. 四条改进纪律

这四条不是风格偏好，每条都对应一类已被实测到的腐烂。

| # | 纪律 | 判据 | 它防的是 |
|---|---|---|---|
| **1** | **只写目标态** | 注释以 `TODO` / `FIXME` 起头、或写「批 N」却不给 `plan/NN` 出处 ⇒ 红（`grep-audit` S-012 守） | 注释叙述过程 ⇒ 代码改了注释不改，且读者分不清哪句还成立 |
| **2** | **机制优先** | 每条问题必须落成**一个守卫 / 一份真源 / 一个类型约束**；只做人工修正不算闭环 | 人工修一次，同类问题下一轮再来（实测本仓同类削格已发生两次） |
| **3** | **不新增真相** | 改文档时先确认那条事实的 owner；本文只链接，不复述 | 同一事实写两处 ⇒ 改一次要动两处，必然漂移 |
| **4** | **出口可核对** | 批次的出口判据要么是一条守卫，要么是一处**脚本可核对的锚**（存在性 / 计数 / 逐字一致）；「靠人读完觉得对」不算出口 | 出口挂在一个不会有人去建的东西上 ⇒ 那一批退化成一次性人工修正，而它看起来已经闭环 |

> **为什么第 2 条要写死**：本仓的守卫体系已经证明「有判据的问题会消失，没判据的问题会复发」。
> **第 4 条是第 2 条的另一半**：第 2 条要求问题落守卫，第 4 条要求**出口不许依赖一个尚不存在的守卫**——
> 一批的判据写着「由 X 守」而 X 没有排进任何一批时，那一批实际无人守，且它看起来已经闭环。
> 决策型改进（如 [P1](#p--价值度量数字是设定的不是测的)）无法整条机械化时，
> 它的出口必须收窄到纪律 4 认可的那类锚，不接受「读过觉得对」。

### 终点不是「e2e 42/42」（2026-10-09）

[复盘 §5.4](../archive/v2-复盘-2026-10-09.md#54-终点的重新定义) 把终点改了。e2e 全绿是
**必要条件**，不是终点：

1. **双向完整性防线常绿**（[ADR-048 防线节](../decisions/session.md#adr-048-出厂档位改-fullv2-链路是出厂路径bridge-退役)）——
   含第三条判据「会话接受的每句用户发言都能在网格里找到出处」（第 4 步落）；
2. **有一份 prompt 形状基线**，能回答「这样对模型是变好还是变坏」——
   ADR-048a 判定了拍平是退步，但「结构化一定更好」同样**未经测量**；没有它，任何「更有效」
   的判断都是凭感觉拍板；
3. **`full` 是出厂路径，且被真实负载压过**——不是「跑过 e2e」，是「跑过真实会话」。

第 2 条不能省：ADR-048 自己承认「v2 让 agent 更强」目前是**未验证的假设**。所以在补上
基线度量之前，**不得基于「更有效」去翻任何默认值**（含反射档的三个开关）。

## 3. 推进顺序与依赖

```
第 1 阶（零行为风险，全是安全网）  M2 ✅ M3 ✅ M5 ✅ M6 ✅ M1 ✅ M7 ✅ M8 ✅ M9 ✅ M4 ✅ M10 ✅
                                 → M11 → M12 → M13
第 2 阶（真源与契约）              D0 → D1 → D2 → D3 → D4 → D5
第 3 阶（度量闭环）                P1 → P2 → P4 → P5
### 主线冻结（2026-10-09，E5 的直接兑现）

**e2e 回到全绿之前，不接受纯 `gate` / `verify` / `docs` / `test` / `chore` 类批次。**

理由（[复盘 E5](../archive/v2-复盘-2026-10-09.md#5-如何挽回)）：10-01 ~ 10-09 共 90 个
提交里，守卫 / 验证 / 文档类约占一半，而**主线链路零推进**。守卫的价值来自「它守住了什么
正在工作的东西」——在主线没跑通前把守卫建到顶配，等于**给一座还没通电的房子装最高级的
消防系统**。

这条冻结**不是永久的**：e2e 全绿即解冻。冻结期间唯一该做的是**主线批次**（P3d → P3e → P3c）
与**照亮主线的判据**（能红的守卫）。

**例外**：修主线过程中**必须**新增的守卫判据（它们直接决定主线红点能不能收敛），以及
文档里对红点的**登记**（红点没有归属就谈不上收敛）。

第 4 阶（行为面，各需 ADR）        P3 🟡 → **P3d → P3e → P3c** → P3b → C2 → C3 → C4 ✅ → C7 ✅ → C6
第 5 阶（迁移主轨）                S0 → S1 → S2 → S3 → S4 → S5 → S6
```

依赖理由：

| 依赖 | 为什么不可颠倒 |
|---|---|
| **M 轨先于一切** | M2 守基线、M5/D-005 守符号、M1 守证据、M11 守门禁自身、M12/M13 守棘轮的覆盖面与计量单位——后面每批的「改输入必须变红」都靠这些判据存在；先做 S 轨等于在无安全网下动地基 |
| **M11 先于 D/P/S 轨** | 门禁自身的结构约定（重生成阶段必须最后、守卫命名空间闭合）不成立时，后面每批新增的守卫都在一个「写错不报错」的体系里：漏登记的守卫与漏跑的反向用例长得和全绿一模一样 |
