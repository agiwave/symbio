## 0. 五条改进纪律

这五条不是风格偏好，每条都对应一类已被实测到的腐烂。

| # | 纪律 | 判据 | 它防的是 |
|---|---|---|---|
| **1** | **只写目标态** | 注释以 `TODO` / `FIXME` 起头、或写「批 N」却不给 `plan/NN` 出处 ⇒ 红（`grep-audit` S-012 守） | 注释叙述过程 ⇒ 代码改了注释不改，且读者分不清哪句还成立 |
| **2** | **机制优先** | 每条问题必须落成**一个守卫 / 一份真源 / 一个类型约束**；只做人工修正不算闭环 | 人工修一次，同类问题下一轮再来（实测本仓同类削格已发生两次） |
| **3** | **不新增真相** | 改文档时先确认那条事实的 owner；本文只链接，不复述 | 同一事实写两处 ⇒ 改一次要动两处，必然漂移 |
| **4** | **出口可核对** | 批次的出口判据要么是一条守卫，要么是一处**脚本可核对的锚**（存在性 / 计数 / 逐字一致）；「靠人读完觉得对」不算出口 | 出口挂在一个不会有人去建的东西上 ⇒ 那一批退化成一次性人工修正，而它看起来已经闭环 |
| **5** | **豁免必有清除任务** | 任何豁免（守卫豁免注释 / 豁免账本条目）必须[经 §2.1 豁免登记表](#21-豁免登记表每条豁免必须能指到清除它的任务项)登记成 [registry/spec](../../registry/spec/INDEX.md) 的 `WVR-*` 条目，且 `clears` **非空**（指到一个任务编号）；无清除任务的豁免不许登记 | 豁免是「现在不修」的决定——没有清除任务的豁免会变成**永久豁免**，问题被静默豁免掉之后再也没有人回来看它 |

> **为什么第 2 条要写死**：本仓的守卫体系已经证明「有判据的问题会消失，没判据的问题会复发」。
> **第 4 条是第 2 条的另一半**：第 2 条要求问题落守卫，第 4 条要求**出口不许依赖一个尚不存在的守卫**——
> 一批的判据写着「由 X 守」而 X 没有排进任何一批时，那一批实际无人守，且它看起来已经闭环。
> 决策型改进（如 [P1](#轨-p--价值度量)）无法整条机械化时，
> 它的出口必须收窄到纪律 4 认可的那类锚，不接受「读过觉得对」。

### 2.1 豁免登记表（每条豁免必须能指到清除它的任务项）

[纪律 5](#0-五条改进纪律) 的落地处：**全仓所有豁免通道各占一个登记条目**
（[registry/spec](../../registry/spec/INDEX.md) 里的 `WVR-*` 条目，`clears` 字段指到清除任务）——
豁免是「现在不修」的决定，清除任务就是给这个决定挂的倒计时。逐条豁免的**理由**不在本文
（owner 在各守卫的账本 / 豁免注释），条目只记「它存在」与「谁来清」这两件事；
现行五条：[WVR-01](../../registry/spec/WVR-01.md)、[WVR-02](../../registry/spec/WVR-02.md)、
[WVR-03](../../registry/spec/WVR-03.md)、[WVR-04](../../registry/spec/WVR-04.md)、
[WVR-05](../../registry/spec/WVR-05.md)（全集与新条目见 [registry/spec/INDEX.md](../../registry/spec/INDEX.md)）。

> **新豁免的登记姿势**：在对应守卫写豁免（注释 / 账本）**的同时**加一个 `WVR-*` 条目，
> `clears` 当场指到一个任务编号；编号若还不存在，先在 registry/task 加一条任务——
> 三件事一次提交，不留「先豁免、以后再补任务」的口子。

### P3b 未开工的理由（原子批次，不翻默认值）

要让 `session/stats` 的 `reflex` 桶有样本，须**同时**满足两个条件：`skill_compile_enabled`（产出已编译技能）、`skill_fast_path`（命中时跳过模型）。
两者出厂都是 `false`，且**各自带成文理由**（`config.rs` 的 `default_skill_*_enabled`）：

- `skill_compile_enabled = false`：S11 §4 平凡值 `projection = recall`（只检索不编译）。
  关掉后整条技能链路退到「没有技能」的形态，而召回 / 巩固照常跑——**技能从经验里学来，
  不是系统的前提**。
- `skill_fast_path = false`：S11 §4 平凡值 `actor.pattern = reasoner`（永远走完整推理）。
  开它是**行为改变**（命中时以技能正文收束、一次模型调用都不发生），
  「不加速」是安全退路口。

**关键事实**：只翻第一个 ⇒ `reflex` 桶**仍为零**（技能编译出来了，但命中时照样走完整推理，
没有 Reflex 档轮次）；只翻第二个 ⇒ 同样为零（没有技能可命中）。任一真子集观测值恒零，
按 [08 §0 纪律 1c](./08-分步实施计划.md#03b-纪律-1c原子批次多开关必须同翻) 这两个开关
是一个**原子批次**——无法拆成两个独立可回退的提交。故本批**只登记，不动默认值**（翻默认值
须有度量支撑而非「更有效」，ADR-048 后果节明令）；要做时按纪律 1c 的三条判据走。

本批的观测形态就是 1c 第 3 条（观测期与默认期分离）在本例的取法：「编译开、加速关」
（`skill_compile_enabled = true` 单独翻，不改出厂行为），此时 `calibration` 列
出真实回退率——那是翻 `skill_fast_path` 前唯一该看的度量。

### 终点不是「e2e 42/42」（2026-10-09）

[复盘 §5.4](../archive/v2-复盘-2026-10-09.md#54-终点的重新定义) 把终点改了。e2e 全绿是
**必要条件**，不是终点。终点的三条判据（对应编号见登记条目）：

1. **双向完整性防线常绿**（判据住 `symbio_core/projection/prompt_fidelity.rs`）——含第三条
   判据「会话接受的每句用户发言都能在网格里找到出处」（P3d 承接）；
2. **有一份 prompt 形状基线**，能回答「这样对模型是变好还是变坏」——ADR-048a 判定了拍平是
   退步，但「结构化一定更好」同样**未经测量**（S-end①）；
3. **`full` 是出厂路径，且被真实负载压过**——不是「跑过 e2e」，是「跑过真实会话」（S-end②）。

**第 2 条不能省**：ADR-048 自己承认「v2 让 agent 更强」目前是**未验证的假设**。
所以在补上基线度量之前，**不得基于「更有效」去翻任何默认值**（含反射档的开关）——
P3b 只登记不动默认值正是这条的落地。

> **红点收敛的方法**（本轮翻档位时一次踩到 10 个红点后定下）：修掉一个缺口会**露出**下一个
> ——红的是表层症状还是真因，不按失败信息猜，而是**每一条单独查清归属**（查 mock 收到的
> 真实请求体、查判据钉的是哪种形态），再决定是改判据还是改产品。详细教训见
> `symbio_core/projection/prompt_fidelity.rs` 的模块文档；逐条归属查
> `git log --grep=tNN`。

### 守卫批次仲裁（常设条款）

**守卫批次的价值 = 它照亮的主线。** 守卫的价值来自「它守住了什么**正在工作的东西**」——
在主线没跑通前把守卫建到顶配，等于**给一座还没通电的房子装最高级的消防系统**。
常设仲裁规则：当一个排期窗口里守卫 / 验证 / 文档类批次占了约一半、而**主线链路零推进**时，
默认判给主线——**暂停纯 `gate` / `verify` / `docs` / `test` / `chore` 类批次入排**，
只做主线批次与**照亮主线的判据**（能红的守卫）。

**例外只有两类**：

1. 修主线过程中**必须**新增的守卫判据（它们直接决定主线红点能不能收敛）；
2. 文档里对红点的**登记**（红点没有归属就谈不上收敛）。

条款是否生效看主线的 e2e 是否全绿（不全绿即冻结纯守卫类入排；全绿即解冻，
冻结**不是永久的**）。
