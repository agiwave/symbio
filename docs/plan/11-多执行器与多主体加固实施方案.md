## 0. 一句话

**v2 的网格口径（`Entity × Verb` + 不变量 + 投影）在多主体下依然成立，破的不是架构，
是三处「默认单进程单主体」的实现假设**：`Store` 没有跨进程单写者、事件 id 与 turn 号
由「进程内计数」派生、身份是硬编码字面量。三者都是**平凡值下的正确实现**，
在 S04（并发）/ S08（多主体）真正开启前必须补上——否则 I1（单写者单调）、
I2（断言必带溯源）、N3（每 turn 至多一条 final）会在并发下**静默破裂**，
而破裂的信号在现行门禁里**看不见**。

**这不是"推翻 v2"**：加固只加数据与构造点（`actor` 已是事件字段、`principal` 是
S08 的新增机制键），不新增机制键、不改网格。

## 2. 缺口分类（六组）

按「破了哪条不变量 / 在哪个迁移步兑现」分组。**每组一个 owner 概念，不重复描述机制。**

### A. 身份与归因（identity）

- 现状：`actor` 是事件字段（`actors/mod.rs:64` 起），但生产里恒为字面量
  `"user"` / `"agent:main"`（第 6 条）；`ActorSpec` 从未在生产构造。
- 多主体下破的是：**I2 的语义**（"断言必带溯源"成立，但溯源指向的是**同一个假主体**）
  ⇒ 无法回答"这条事实是谁说的"。归因缺失使 grants / `vis_scope` / 声誉投影
  全部无从谈起（[S08](./roadmap/S08-多主体与对等承诺.md) §3 的 `principal` 行）。
- 兑现步：**S08**（新增机制键 `principal`）。

### B. 并发与租约（concurrency）

- 现状：单写者约束**只由进程内 `RwLock` 保证**（`wal.rs` 的 `inner`），跨进程为零
  （第 2 条）；同会话互斥只在 v1 orchestrator（第 4 条）；inbox 是实例级单消费者 +
  进程内 `VecDeque`（第 15 条）。
- 多执行器下破的是：**I1（单写者单调）**。两个进程各持一份 `WalStore`，各自
  `head` 从文件重放算出，`append` 只 append 不校验 ⇒ seq 重号 / 事件交错，
  且**没有任何错误信号**（`Conflict` 存在但从不返回，第 1 条）。
- 兑现步：**S04**（租约是事件不是锁；单写者 FIFO 是 I1 的推论）。

### C. 存储安全（storage）

- 现状：`open` 恢复时把"第一行解析失败"当作**撕裂尾行**并截断其后的全部内容
  （第 2 条）；生产每轮 open（第 3 条）⇒ 每轮一次"可能截断"的机会窗口。
- 多写入者下破的是：**append-only 的耐久性**。进程 A 写到一半被 B 看见 ⇒ B 把 A 的
  完整行当成撕裂行截断，**已提交的事实被静默丢弃**——这比 seq 重号更隐蔽。
- 兑现步：**S05**（断点恢复）+ 本方案批 1（把"截断"从 `open` 的默认行为收窄为
  显式恢复动作）。

### D. 权限与治理接线（governance wiring）

- 现状：`PermissionMatrix` / `readyset` / `check_all` / `CircuitBreaker` /
  `PreemptionDecider` / `SkillCompiler` / `AutonomousInitiator` 全部**已实现、零生产接线**
  （第 7–9 条）。
- 多主体下破的是：**"能给自己授权看一切"的读侧/写侧分离**（`governance/mod.rs:13-14`）
  在接线之前不生效——治理件存在但没人问它。
- 兑现步：**S04**（readyset 接线）+ **S09**（熔断）+ **S12/S13**（自主层 / 多智能体社会）。

### E. 呈现面与投影过滤（projection）

- 现状：`ChatMessage` 无身份字段（第 10 条）；请求视图与窗口只按 `turn` 切（第 11 条）；
  工作区路径进用户消息体（第 12 条）；`compose` 落点靠 `meta.exclude_from_context`
  手工标记（第 13 条）。
- 多主体下破的是：**可见域**。请求包会把"别人的发言 / 别人的工作区路径"一并送给模型；
  前端也拿不到"这条是谁说的"。`vis_scope` 无处落地。
- 兑现步：**S08**（`vis_scope` 新增机制键）。

### F. 装配与入站（assembly / ingress）

- 现状：`register_vdfs_root` / `register_model_providers` 单槽（第 14 条）⇒ 子智能体
  的注册会**覆盖**父的；入站默认无鉴权可写（第 19 条）。
- 多主体下破的是：**"每个主体有自己的模型服务与根"**（`e2e/helpers.mjs` 的
  `makeAgentDir` 已经在按这个假设造夹具，而注册面还是单槽）。
- 兑现步：**S08**（多主体）。

## 3. 分批计划

排序原则：**先补"破了不变量且无信号"的（P0），再补"破了可见域"的（P1），
最后补"接线即有值但依赖前两者"的（P2）。** 每批仍守
[08 §0](./08-分步实施计划.md)：一步只改一件事 + 单测 + e2e + 门禁。

> **完成判据（每批两件事同时成立，缺一不算完成）**：① 本批内容接进**生产**调用点
> （测试调用不算）；② 它引出的 `#[allow(dead_code)]` 承认标记全部摘除——
> **步状态、死码基线与清偿批次只登记在 [04 §3.1](./04-工程落地.md)**，本节不复述数字。

### 批 0（P0）· 单写者与身份去冲突 —— **未完成（在办）**

- 归属：本文 §2-A + §2-B + §2-C。死码侧：[04 §3.1 批④](./04-工程落地.md)（不变量接进 CI/读侧）。
- 内容：① `Store` 的单写者从"进程内锁"升级为**可跨进程校验**的写者令牌
  （`AppendError::NotTheWriter` / `Conflict` 从"定义了不用"变成**真的会返回**）；
  ② 事件 id 与 turn 号不再由"进程内计数 / 计数派生"生成，改由**事实源分配**
  （消除 `u-{turn}` 的重号面）；③ `open` 的"截断撕裂尾行"收窄为显式恢复动作，
  非恢复路径只读不写。
- 判据：单测覆盖"两个写者交错 ⇒ 第二个拿到 `NotTheWriter`/`Conflict` 且**盘上零丢失**"；
  e2e 起两个进程写同一会话 ⇒ 网格不重号、不丢事件。
- 回退：本批不改网格、不改投影，退回 = 恢复 `open` 的截断语义（平凡值 = 今天的单进程行为）。

### 批 1（P1）· 主体身份进事件与消息 —— **未完成**

- 归属：本文 §2-A + §2-E。死码侧：[04 §3.1 批⑧](./04-工程落地.md)（身份是承诺/声誉的前置）。
- 内容：① `TurnRunner` 的 `"user"` / `"agent:main"` 改为**入参**（`ActorSpec` 首次
  在生产构造）；② `ChatMessage` 增身份字段（跨栈 schema，前端同步镜像）；
  ③ 请求视图与 `window_by_turn` 增加**按主体过滤**的入口（默认 `None` = 不过滤，
  与今天逐字一致）。
- 判据：单测覆盖"同一会话两个主体 ⇒ 各自视图只含可见发言"；e2e 用两个会话
  （父 / 子智能体）验证请求包不串主体。
- 回退：过滤参数默认 `None` ⇒ 行为与今天逐字一致（平凡值在参数上，不在代码路径上）。

### 批 2（P2）· 治理与自主层接线 —— **未完成**

- 归属：本文 §2-D + §2-F。死码侧：[04 §3.1 批⑥/⑨/⑩/⑪](./04-工程落地.md)
  （`PermissionMatrix`、`readyset` 随任务表、熔断抢占、自主层）。
- 内容：① `readyset` / `PermissionMatrix` 接入调度与请求路径（从"测试里才有"变成
  "生产真的问"）——**`PermissionMatrix` 半边已了结**（[04 §3.1 批⑥](./04-工程落地.md)：
  表住宿主 `crate::authz`、写侧收束闸 + 读侧可见域两处判定，e2e `t28` 读方三态；
  `readyset()` 仍只在测试 ⇒ 随任务表，即批⑨）；② `register_*` 单槽改多槽（子智能体注册不再覆盖父）；
  ③ `CircuitBreaker` / `PreemptionDecider` / `SkillCompiler` / `AutonomousInitiator`
  逐个接线（每个一个独立子批；**`IntentGate` 必须与 `AutonomousInitiator` 同批成对**，
  无门即写 = 自主层直写对话，破 [04 §3 步21](./04-工程落地.md) 的"自主写入对话 0"）。
- 判据：每件接线一条 e2e（接线前后**行为可见地不同**，否则等于没接）。
- 回退：每件一个子批，逐个可独立回退。

### 明确不在本方案内

- **入站鉴权默认值**（第 19 条）：属 [gateway](../reference/CONFIGURATION.md) 的配置面决策
  （默认空令牌 + 回环是**有意**的本机开发形态），不在这里顺手改；只在 [S08](./roadmap/S08-多主体与对等承诺.md)
  开启时重新评估。
- **本地构建产物**（第 20 条）：非仓库问题，见 §1 第 20 行。
- **工具轮 v2 化**（第 17 条）：已有独立方案 [10](./10-工具轮v2化实施方案.md)，不重复。

## 4. 出口判据

与 [08 §2](./08-分步实施计划.md) 同一口径，三条缺一不可：

1. **单测**：新增分支全覆盖（含"多写者 / 多主体"的**反向用例**——不变量在违反时
   必须**报错**，而不是静默通过）；
2. **e2e**：`node e2e/run-tests.mjs tNN` 绿，含 LLM mock 与 `/_requests` 回读；
3. **门禁**：`node scripts/gate.mjs` 全绿（棘轮按实测上调）。

> **为什么反向用例是硬要求**：本方案的所有缺口都有同一个形状——**破的时候没有信号**
> （第 1、2、4、5、7–9 条）。正向用例证明"新机制能工作"，只有反向用例证明
> "旧的静默破裂路径被堵上了"。缺了它，加固等于给一条不会报警的电路加了个灯。
