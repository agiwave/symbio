# S03 · 多步任务与返工

> 天梯 **T2** ｜ 前置：S02 ｜ **新增机制键 1**（`scope`）｜ 参数变化 5 ｜ 阶段三

## 1. 场景：要什么能力

一个请求拆成多步；某一步被独立验证判为不合格时，**产生返工而不是将错就错**。

相对 S02 高了什么：**从"一次动作"到"有向图 + 质量闸门"**。这是 T2 与 T1 的分界线：
T1 做一步看一步，T2 能规划并把质量判定写进流程。

## 2. 为什么它能落在 v2 上（J1）

| 看起来新的东西 | 实际是 |
|---|---|
| 任务图（DAG） | 事件的 `depends_on` 字段——**数据** |
| 子任务 | `scope = child:<id>`，一条参数 |
| 返工 | `task/asserted`（`task.rework_created`）事件——**不是回滚** |
| 独立验证者 | 一行 ActorSpec，`capabilities: [AssertVerification]` |

**关键**：返工是**新增一条事件**，不是修改历史。日志永不改，投影自然排除被取代的节点。
这一点决定了整个系统不需要"事务"——**append-only 已经提供了撤销语义**。

## 3. 增量清单（只加数据）

| 类型 | 内容 |
|---|---|
| 事件格子 | 新增 `task/opened|progressed|held|asserted` 各格（网格已有实体 `task`） |
| 新参数键 | **`scope`**（`root` / `child:<id>`）——本阶唯一新增机制键 |
| ActorSpec 行 | 规划者 `{ pattern: decider, capabilities: [DefineWork], budget_ms: 60000 }`<br/>验证者 `{ pattern: decider, capabilities: [AssertVerification], budget_ms: 5000 }` |
| grants 行 | 规划者 ▸ `define.work`；验证者 ▸ `assert.verification`；**二者互不可写** |
| 投影参数 | `projection = readyset`（只取终态 + `depends_on` 闭合） |

## 4. 平凡值与回退（J2）

| 参数 | 完整值 | **平凡值** | 平凡值下 |
|---|---|---|---|
| `scope` | `child:<id>` | **`root`** | 仍完整运行——不拆子作用域，主线程线性推进 |
| `actor.capability` | `assert.verification` | 空集 | 仍完整运行——无独立验证，退化为 S02 的一步到位 |

**`scope = root` 是本阶的退路口**：所有子任务压平到根作用域，递归结构消失，
但事件、投影、验证全都照常工作。这就是"递归是参数不是机制"的可检验后果。

## 5. 静默失效与强制（J3）

| 约束 | 违反时信号 | 强制方式 |
|---|---|---|
| 依赖图无环 | **无**——可能只是跑不完 | CI 断言（`termination.rs` 的 Kahn 检测） |
| 规划者不得自验 | **无** | grants 表强制：验证者 ≠ 产出者 |
| 返工次数有界 | **无**——可能无限返工 | 终止性前提：rework 有界（`termination.rs`） |

## 6. 验收断言

1. 构造含环的依赖图 → 无环检测必须报错。
2. 同一主体同时持有 `define.work` 与 `assert.verification` → 授权检查必须拒绝。
3. 注入 N 步任务 → 在 rework 上界内终止。
4. **反向用例**：把环去掉一个依赖 → 断言 1 必须通过（证明检测在算，不是常量 `false`）。

## 7. 这一阶做不了什么

- 各步骤串行，不能并行抢占 → S04
- 任务不跨会话存续，进程重启即丢 → S05
- "验证者判得准不准"不由架构保证——`AssertVerification` 只保证**有这么一次独立判定**，
  不保证判定质量。把这两件事混为一谈是高估架构的典型错误。
