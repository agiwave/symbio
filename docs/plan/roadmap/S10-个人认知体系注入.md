# S10 · 个人认知体系注入

> 天梯 **T4–T6** ｜ 前置：S06、S09 ｜ **新增机制键 0** ｜ **架构改动 0** ｜ 参数变化 5 ｜ 阶段二→四

## 1. 场景：要什么能力

让智能体带上**某个（些）人的认知能力**：七类认知内容（知识 / 经验 / 技能 / 判断 / 策略 / 直觉 / 情绪）、
内容密度分级、通用性分级（L0–4）、五层存储、激活扩散检索、内外双轨动作空间。
> 本阶对应 `reference/01-认知架构模型.md` 那套体系——**它是本阶梯里压力最大的一阶**：
> 16 条需求用满 10 个机制键里的 **9** 个（`cognitive_fit.rs` 算出）。唯一没被取用的 `store`
> 判的是**部署**，而认知体系要的是索引——索引是 `Store` 的实现细节，见 §2 的 `C06`。

相对 S09 高了什么：S09 加的是"能做什么"，本阶加的是"**像谁那样想**"。

## 3. 增量清单（只加数据）

| 类型 | 内容 |
|---|---|
| 事件格子 | 复用 `memory/*` 全部格子——**不加新格子** |
| 投影参数 | `recall:tag=...`、`recall:density=...`、`recall:layer=...`、`recall:spread=on`、`recall:decay=exp`、**`recall:min_generality=2`** |
| grants 行 | `person:*` ▸ 记忆 `vis_scope = shared`，智能体读、本人写 |
| 成本侧 | 保留策略（窗口 / 冷层 / 常驻 / 短，[01 §9.1](../01-核心架构.md) 已有）+ ingest Actor 的 emit 策略 |

### 3.1 落地状态：这一节里哪些参数今天存在

上表的「投影参数」是**设计记法**（`recall:<键>=<值>` = "这个投影取一个参数"），不是字符串
配置面——仓里没有按这个名字解析的入口。逐条对代码：

| 参数 | 今天 | 说明 |
|---|---|---|
| `recall:tag` | **已在生产** | `recall(viewer, tag)` 的 `tag` 形参。全仓**唯一传标签**的调用点是 `consolidate`（`recall_view` 与 `encode` 都传 `None`），它靠这个过滤只合并同标签的记忆 |
| `recall:layer` / `spread` / `decay` / `density` / `min_generality` | **未落地** | 形参不存在；各自的前置条件不同（`min_generality` 连**值的写方**都没有，见下） |

**为什么 `min_generality` 不照抄落地**：它过滤的是"通用性分级"，而**没有任何地方给一条
记忆标 L0–4**——分级器是算法问题，§7 已把它划在架构之外。参数加上去、值恒缺省 ⇒ 过滤器
**恒真**：多一个看起来在工作、实际从不排除任何东西的旋钮，比没有它更坏（[12](../12-价值验收与基线埋点.md)
全篇批的就是"能算却没人读"）。故本阶**只认机制、不落参数**：等分级器出现，落地动作是
"给 `memory.encoded` 的载荷加一个字段"，读侧那一半照 §5 的结论接。

**已落地的那个实例是承重的**，也是本阶唯一能在生产链上看见的后果：`recall` 的 `tag`
过滤若退化成恒真，`consolidate` 眼里的"最旧两条"会变成**技能**——技能被当经验合并、
随后被排除式遗忘，**没有任何报错**。判据 = `recall.test.rs`（排除 / 可逆 / 活参数三条）
+ `v2_memory.test.rs::consolidation_never_merges_across_tags`（生产后果）。
这也是 [04 §4 C16](../04-工程落地.md) 的机制形态。

**本阶点亮的机制键**（阶梯总表的「新增机制键」由这张块算出；`scripts/gen-verify-facts.mjs` 从这里取输入）：

```capability-assign
event.entity = memory
event.verb = asserted
projection = recall:tag=judgment
projection = recall:min_generality=2
vis_scope = shared
```

## 5. ⚠️ 一处被复核推翻的"架构改动"——本阶最值得读的一节

### 5.1 最初的判断（错的）

认知文档说 "Level 0–1：LLM 已覆盖，**无需存储**"。
我最初据此判断：要系统级保证，就得让 `append` 能拒绝 → 扩展 `store` 值域 → **触及唯一原语**。
据此在路线图里标了"13 阶中唯一触及原语的一处"。

### 5.2 复核：这是把读侧问题误当成写侧问题

问一句"不存 L0–1 到底防的是什么"，答案是两条：

| 声称的危害 | 它发生在哪一侧 |
|---|---|
| 浪费存储 | 写侧，但**由保留策略解决**（§9.1 已有：窗口 / 冷层 / 常驻 / 短） |
| 稀释个人记忆的检索质量 | **读侧**——稀释只在检索那一刻才存在 |

真正的目标**只有一个是写侧的，而且已有参数覆盖**；核心目标（检索质量）是**读侧现象**。
为读侧问题去改写侧的原语，是把问题的位置认错了。

### 5.3 系统里已经有同构的模式：遗忘

[01 §9.3](../01-核心架构.md)：

> **遗忘是 `memory.forgotten` 事件（不是物理删除；Log 永不删，只是投影不再包含）。**

"通用性过滤"与"遗忘"是**同一个模式**：某些内容不再进入 `Recall` 视图，但事实仍在日志里。
既然遗忘是投影参数，通用性过滤也必须是投影参数。**为它单开一条写侧机制，等于在同一个问题上做两套设计。**

### 5.4 决定性理由：可逆性

写侧过滤**不可逆**——一旦"通用性分类器"判断错了（把 L2 判成 L1），内容永久丢失，
而且丢的时候**没有任何错误信号**（J3 所说的静默失效）。
读侧过滤**可逆**——改阈值即可召回，且能回过头审计"当初过滤掉了什么"。

v2 的全部设计都押在"事实永不丢、只改投影"上（append-only + 投影派生）。
写侧过滤是**对这条立场的直接违背**。

### 5.5 结论与本阶的实际做法

| 关注点 | 做法 | 是否改架构 |
|---|---|---|
| 检索质量（核心目标） | `recall:min_generality=2`（读侧投影参数） | **否** |
| 存储成本 | 保留策略（已有参数）+ ingest Actor 的 emit 策略（数据） | **否** |
| 合规性"绝不落盘" | **尚未出现**；若真出现，走 ADR，且必须过 [03 §3 前置闸门](../03-演进与验证.md) | 待定 |

**因此本阶架构改动 = 0**，与其余 12 阶一致。

### 5.6 这一节的元教训（比结论更重要）

> **为某个场景改架构，本身就是架构没想清楚的信号。**
> 遇到这种提议，先问"系统里有没有同构的既有模式"——本例的答案是 §9.3 的遗忘。
> 我已经把这条写成 ADR 流程的**前置闸门**（[03 §3](../03-演进与验证.md)）：
> 动 F1–F6 之前必须先做第 0 步，找不到同构模式就要写清"为什么已有模式不够用"。

## 6. 验收断言

1. 认知体系 16 条需求 → 越界键 = 0 **且越界取值 = 0**（`cognitive_fit.rs`，取值逐条对 01 §8）。
2. 后台巩固后 `as-of=T` 视图逐字节不变（认知体系会长期跑巩固）。
3. 扩散检索超预算 → `degraded: true` 且带部分结果，不允许静默返回空。
4. **可逆性**：把读侧过滤的阈值调回 0 → 此前被排除的内容**必须重新可检索**（写侧过滤做不到）。
   已落地的实例是 `recall` 的 `tag` 过滤（`min_generality` 本身未落地，见 §3.1）——判据 =
   `recall.test.rs`：放宽阈值即召回，且两次调用之间**事实源逐字节不变**。
5. **反向用例**：注入一条要求"独立认知存储层"的需求 → 审计必须报越界键。
6. **反向用例**：改用写侧过滤实现 → 断言 4 必须失败（内容已丢失，无法召回）。
7. **反向用例**：把某条需求的取值改成 01 §8 之外的值 → 断言 1 必须失败。同一条注入里
   另带两个**合法**取值（通配段 `child:<id>`、子键参数 `recall:tag=…`）作放行对照——
   只会报错的判据与永真的标志一样不值钱。

> 5 / 6 / 7 三条跑在**设计级程序** [`verify/cognitive_fit.rs`](../verify/cognitive_fit.rs) 上
> （`rustc` 编译 + 运行，门禁的 verify 档）——它证的是"这套设计装得下"，与 1–4 里跑在生产
> 代码上的判据**不是同一种证据**，引用时别混。同理，1 的两个"= 0"审的是**设计记法**层面
> （键名 ∈ 机制表、取值 ∈ §8 值域），不检查那个取值今天有没有实现——§3.1 才是实现状态。

## 7. 这一阶做不了什么

- **检索召回质量架构层零保证**——本阶证明装得下，不证明想得起对的
- **反馈环收敛性未论证**：使用反馈调权让检索结果改变下一次检索，v2 无收敛性证明
- **纯度 / 增量的边界未划清**：扩散放投影层（纯函数、全量重算）还是 Store 实现层（可增量），
  [01 §3](../01-核心架构.md) 与 §9.2 之间缺这一句——百万级条目时会第一个撞上
- 认知内容本身的**正确性、代表性、隐私授权**全在架构之外
- 认知文档里的 System 1/System 2 与 L1–L5 拟合度数字**不采用**（理由见 [00 §6](./00-路线图总览.md)）
