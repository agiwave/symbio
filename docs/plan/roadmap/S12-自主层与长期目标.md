# S12 · 自主层与长期目标

> 天梯 **T7** ｜ 前置：S11、S09 ｜ **新增机制键 0** ｜ 参数变化 4 ｜ 阶段四

## 1. 场景：要什么能力

没有用户消息时，系统**自己发起**工作：定时触发、长期目标推进、跨天运行、自我排期。

相对 S11 高了什么：前面 11 阶全部是**响应式**的——有输入才有行为。
本阶第一次出现"**欲**（Conation）"这个维度：**没有外部刺激也会做事**。
[02 能力坐标系](../02-能力坐标系.md) 明确指出：缺了这一维，系统再强也永远在等指令。

## 2. 为什么它能落在 v2 上（J1）

| 看起来新的东西 | 实际是 |
|---|---|
| 定时触发 | `system/opened`（`system.triggered`）事件——**触发器产出事件，不是旁路** |
| 长期目标 | 一条 `task/opened` 事件，`budget_ms = 86400000` |
| 自主排期 | 一个 `Decider`，输入 `ReadySet`，输出 `task.assigned`（同 S04） |
| 健康自检 | `system/progressed`（`system.health`） |

**关键**：自主层**不是一个新架构层**，只是 `budget_ms` 的第四个取值（86400000ms）。
反射 80 / 快速 300 / 深度 60000 / 自主 86400000——**四层都是同一个参数，不是四种架构**。
这是本阶"新增机制键 = 0"的根本原因。

## 3. 增量清单（只加数据）

| 类型 | 内容 |
|---|---|
| 事件格子 | `system/opened`（`system.triggered`）、`system/progressed`（`system.health`）；<br/>**`conation/expressed`（`conation.expressed`）**——「欲」的事件形态（见 [02 §2.3](../02-能力坐标系.md)） |
| ActorSpec 行 | 自主发起者 `{ pattern: decider, capabilities: [DefineWork], budget_ms: 86400000, scope: root }` |
| grants 行 | 自主发起者 ▸ `define.work` 写；**不可写 `chat.assistant.*`**（自主行为不得冒充用户对话） |
| 投影参数 | `projection = readyset`（复用 S04）；**`projection = conation`**（读出当前未完成意图） |

> **「欲」不需要新机制键**：它是 `event.entity = conation` 与 `projection = conation` 两个**新取值**。
> 完整可执行形态见 [02 §2.3](../02-能力坐标系.md) 与 `verify/conation_minimal.rs`。

## 4. 平凡值与回退（J2）

| 参数 | 完整值 | **平凡值** | 平凡值下 |
|---|---|---|---|
| `event.entity` | `system` | **`turn`** | 仍完整运行——无定时触发，退化成纯响应式（S11 状态） |
| `actor.budget_ms` | `86400000` | `60000` | 仍完整运行——长目标被当成普通深度任务推进 |
| **`ConationPolicy.enabled`** | `true` | **`false`** | 仍完整运行——「欲」不升格为任务，读侧投影照常工作（纯响应式） |

**`system` 实体不启用 = 自主性整阶可关闭**，这是生产环境最需要的一个开关：
一个"会自己发起行为"的系统必须有能力被一键退回"只响应"。
同理 `ConationPolicy.enabled = false` 关掉的是**欲望侧**的升格，两层开关独立。

## 5. 静默失效与强制（J3）

| 约束 | 违反时信号 | 强制方式 |
|---|---|---|
| 自主行为不得写入用户对话通道 | **无** | grants：无 `reply.*` 写权 |
| 长目标必须在预算内产出或兜底 | **无**——静默挂起数天 | I3：86400000ms 到点必答 |
| 自主发起的工作可追溯 | **无** | I2：触发器产生的事件带 `produced_by` |
| **「欲」不得直接变成「行」** | **无**——绕过授权/预算/审计 | **ZST 能力令牌**（`GateWarrant`）：不持令牌则编译失败（[02 §2.3](../02-能力坐标系.md)） |
| **「欲」必须有溯源** | **无**——来路不明的意图混入 | I2 强化：`conation.expressed` 无 `derived_from` 时**构造不出** `CandidateIntent` |

## 6. 验收断言

1. 无用户消息时，定时触发必须产生 `system.triggered` 事件。
2. 自主发起者尝试写 `chat.assistant.final` → 授权拒绝且不产生事件。
3. 长目标超过 86400000ms → 必须产出兜底事件（`budget.rs` 已覆盖四层）。
4. **反向用例**：把预算改成 60000ms → 断言 3 的判定必须改变。
5. **「欲」治理三条**（`conation_minimal.rs` 已覆盖）：
   - `CandidateIntent` 造出来一定 `approved = false`，过闸门后才可执行；
   - 无溯源的 `conation.expressed` 构造不出候选意图（I2）；
   - 关闭 `ConationPolicy.enabled` → 无任何自主任务，但读侧投影仍完整工作（J2）。

## 7. 这一阶做不了什么

- **"该自主发起什么"是价值对齐问题，不是架构问题**——本阶只保证"发起了什么可追溯、可关停"；
  同理「欲」的**内容**（想要什么）不由架构决定，架构只管"欲如何被治理"（[02 §2.3](../02-能力坐标系.md)）
- 长期目标的**分解质量**依赖 S03 的规划能力，不因本阶提升
- T7 的**硬实时**部分（具身 / 闭环控制）未实测（G2）；本阶的"自主"是调度意义上的，不是控制意义上的
- 自主系统的**成本失控**风险：架构提供 `budget` 投影，但 SLO 数字仍未落地（G3）
