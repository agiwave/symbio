## 规范

限定名 `08 §0 纪律 3`。条文的唯一 owner：[PL-006 §3](../plan/PL-006-分步实施计划.md#3-架构改动登记每条必须论证必需 "PL-006-分步实施计划")——本条目**不复述条文**，
登记的是「这条纪律必须成立」与**它的判据**的对账关系（自 docs/README 纪律地图条目化）。

## 判据

2026-10-12 起分两半——**能被机械判的那一半不许再靠人记得去看**（立这套判据的决策：
[ADR-055](../adr/ADR-055.md)）：

- **核心形状变宽 ⇒ 守卫红**：[`core-shape-audit`](../../scripts/core-shape-audit.mjs) 的 **CS-001**
  把 `symbio_core` 生产侧的三格冻结成只许降的棘轮（`pub trait` 数 / `fn` 成员总数 /
  带默认体的成员数）。它拦的正是「论证不出即删」最容易被合理化过去的那一类：
  把核心契约面改宽看起来像实现层的事（实测实例：2026-10-12 那次「`VdfsProvider` 去样板」的
  处方 = trait 1→10 个方法，而当时全部门禁的口径里符号数不变、根出口不变）。
- **改棘轮数字 ⇒ 必须挂一条打得住的决策**：**CS-002** 要求基线旁的
  `core-shape-allow <格>: ADR-NNN <理由>` 里那个 ADR 在 `docs/adr/` 真实存在；
  「数字有没有比上一版更松」由 [`gate.d/35-baseline.mjs`](../../scripts/gate.d/35-baseline.mjs)
  比对基准版本判。两半各判一半，合起来才是「放宽 = 写一份决策」。
- **论证本身仍由人判**：机器只保证「这一步留下了一份能打开的决策」，
  那份论证成不成立不在机器视野内——人读面就是 `08 §3` 那张登记表与 ADR 的
  「被否决的方案」一节。**论证不出即删**这条仍然归人。
