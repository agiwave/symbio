## 规范

每篇文档是**一个带 front-matter 的单文档**：front-matter（受限 YAML 子集）承载机读字段，
正文承载人读内容。**文件本身就是条目**——没有第二处登记表。

**两种身份形态**（由 kind 的 `idRule` 决定，代码侧真相在 `registry-lib` 的 `KINDS`）：

| 形态 | kind | `id` = | 例子 |
|---|---|---|---|
| 条目类 | `task` / `spec` / `adr` | 文件名（无 `.md`），住 `docs/<kind>/` | `T-008` 住 `docs/task/T-008.md` |
| 文档类 | `goal` / `stage` / `plan` / `arch` / `ref` / `guide` | 仓根相对路径（去 `.md`），**就地存放** | `docs/arch/vdfs` 住 `docs/arch/vdfs.md` |

**目录不参与判定**：`kind` 只来自 front-matter，没有「`kind` 必须与目录一致」这条判据——
规范化的目录（`docs/<kind>/` + 模块文档就地）是组织习惯，文档换目录不破机制。
换目录的唯一义务是**把身份一起改**（条目类：文件名；文档类：`id`），两条都是两面对账
（RG-003），文档类另对 `title` 与首个 H1（RG-021）。

### 受限 YAML 子集（零外部依赖，只认以下形状）

- 首行 `---` 起始、`---` 闭合；键形如 `key: value`（取第一个冒号之后整段为值）；
- **值必须与键在同一行**：块标量 `|` / `>` 与缩进续行都不在这个子集里——续行会被当成
  一个没有冒号的行，按 RG-001 判红（**宁红不漏**，不会静默丢掉半截值）；
- 整行注释以 `#` 开头；**行内 `#` 属于值的一部分**，不剥离；
- 值四种形态：裸标量、`"..."` / `'...'`（去外层引号，不支持转义）、
  `[]` / `[a, b]` 行内列表、键后换行的 `  - item` 块列表；
- 未知字段、重复字段、不合形状的行一律判红（RG-001）——**宁红不漏**，
  拼错的字段名不会被静默忽略。

### 状态词（执行方在代码，本表为人读摘要）

| kind | 状态词 | 含义 |
|---|---|---|
| `task` | `todo` / `doing` / `done` / `wont` | 待处理 / 进行中 / 已闭环 / 不做 |
| `spec` | `draft` / `active` / `retired` | 草案 / 现行 / 废止 |
| `adr` | `active` / `superseded` / `withdrawn` | 现行 / 已被取代 / 已回退·未落地 |
| 文档类六种（`goal` / `stage` / `plan` / `arch` / `ref` / `guide`） | `draft` / `active` / `retired` | 草案 / 现行 / 废止（同 `spec` 一条轴：这篇文档还算不算数） |

文档类的六种共用同一条状态轴（`DOC_STATUS_RULES`）：**文档只有「还算不算数」这一条轴**，
「做到哪一步」属于 `task`，不压进文档的状态列（同理见 `adr` 的 `status` / `impl` 拆轴）。

`adr` 的 `status` **只管规范合法性**（这条决策算不算数）；「做到哪一步」是**另一个字段**
`impl`（`planned` / `partial` / `done` / `none`，见下）——两者正交：一条 `active` 的决策
完全可以 `impl: partial`（「现行但只落地了一半」）。此前这两件事被压在同一列自由文本里
（「现行（含未完成项）」「已接受 · 部分实施」），机读面因此表达不出最常见的中间态。

状态 × 字段矩阵（谁必须填、谁必须空）的**唯一执行方**是
`registry-lib` 的 `statusRules`；冲突时以代码为准，改状态机必须同批改本节摘要。

### 正文小节

条目类**缺一即红**（RG-009）；文档类**没有必有小节**——正文结构由文档自己定
（按 kind 强切只会逼出空壳小节）。

- `task`：`## 内容`（这条任务要做什么）+ `## 处理过程`（推进记录，闭环后仍可追加）；
- `spec`：`## 规范`（条文本身）+ `## 判据`（怎么核对；指认的脚本必须真实存在）；
- `adr`：`## 决策`（**ADR 正文本身**——状态 / 决策 / 理由 / 被否决的方案 / 后果与不变量）。
  `adr` 没有第二个小节：规范合法性与落地进展都由 front-matter 的 `status` + `impl` 承载，
  正文里再写一遍就是第二处状态（必然漂移）。

### 引用别的文档：只写编号（地址由机制生成）

正文引用其它已登记文档时，人**只写编号**：`[[编号]]`；要显示文字写 `[[编号|显示文字]]`，
要锚点写 `[[编号#小节]]`（可组合）。链接地址由
[`gen-doc-refs`](../../scripts/gen-doc-refs.mjs) 从登记解析生成并在每次门禁重算
（已展开的地址也重算，RF-002）；引用不存在的编号判红且不写盘（RF-001）；
指向已登记文档的手工地址（既无编号标签、也无编号标题）判红（RF-003）。
**不手写、也不维护站内地址**：身份在链接文字或链接标题（两者其一是编号），
地址是位置（会变）——机制见 [14 §1.1](../plan/14-登记与汇总机制.md "docs/plan/14-登记与汇总机制")。
行内代码段里的 `[[…]]` 是字面量，不展开。

### 优先级与取代

- `prio` 是**排序提示**（`now / next / later`，缺席 = 最低档）：只影响同一拓扑层内的排序，
  拓扑序（`deps`）永远在前——`deps` 是义务（事实），`prio` 是提示（判断）。
- `supersedes` 是**显式取代链**：同 kind 之间不允许两条 `active` 矛盾并存，消解方式是
  一条改 `superseded` / `withdrawn`（`reason` 写明被谁取代 / 为何作废）。
  **取代关系只在同 kind 之间**（`spec↔spec`、`adr↔adr`），跨 kind 取代没有语义。
  **优先级不参与裁决**——分层裁决规则的 owner 是
  [14 · 登记与汇总机制](../plan/14-登记与汇总机制.md "docs/plan/14-登记与汇总机制")，本文只登记字段。

## 字段

下表是全部合法字段的**封闭集合**——首列反引号键名的集合必须与代码侧 schema
（`registry-lib` 的 `ALL_KEYS`）恰好相等，不等即红（RG-011）。新增 / 删除字段必须
同批改这里与代码，两条腿一起走。

| 字段 | 归属 | 必填 | 说明 |
|---|---|:-:|---|
| `kind` | 公共 | ✓ | 九类之一，**只来自本字段**（目录不参与判定） |
| `id` | 公共 | ✓ | 全局唯一（含跨 kind）；条目类 = 文件名、文档类 = 仓根相对路径（RG-003） |
| `title` | 公共 | ✓ | 一句话标题；文档类必须**逐字等于正文首个 H1**（RG-021） |
| `status` | 公共 | ✓ | 状态词由 kind 的状态机决定 |
| `created` | 公共 | ✓ | `YYYY-MM-DD`，登记日期 |
| `deps` | 公共 | — | 前置编号列表，可跨 kind；`[]` = 无前置 |
| `track` | task | ✓ | 轨 / 分组（自由短词，如 `meta`、`doc`） |
| `prio` | task | — | 排序提示 `now` / `next` / `later`（RG-014）；**只影响同层排序，不参与冲突裁决** |
| `where` | task / adr | — | 落点（task：涉及的文件 / 章节；adr：正文所在分册）。**task 的 `where` 可指向尚不存在的文件、不判存在性**；`adr` 的 `where` 是**指认**，指认的文件必须存在（RG-012） |
| `exit` | task | — | 出口判据；其中反引号的 `docs/` `scripts/` `e2e/` 指认必须存在（RG-012）。**写路径时要写当前位置**：地址随文件搬走而变，机制只重算「标签是编号的站内链接」，不认自由文本里的路径 |
| `signal` | task | — | 问题核实快照（坏状态的证据）；`done` 后必须清空 |
| `evidence` | task | `done` 必填 | 完成证据（提交 / 守卫锚）；非 `done` 不得填 |
| `reason` | task / spec | `wont` / `retired` 必填 | 不做 / 废止的理由 |
| `scope` | spec | ✓ | 适用范围（一句话） |
| `supersedes` | spec / adr | — | 显式取代链（RG-015）：目标必须存在且**同 kind**，不得与自己同为闭环态、不得成环 |
| `clears` | spec | — | 清除任务编号（RG-016）：目标必须存在且为 `task`；**不要求闭环**——豁免挂在开放的清除任务上是合法语义（`deps` 是前置，`clears` 是指认） |
| `adr` | adr | ✓ | ADR 编号（`001` / `048a` 这种**序号**，与 `id` 的 `ADR-001` 区分）；用于与正文标题对账（RG-018） |
| `impl` | adr | ✓ | 落地进展（RG-017）：`planned` / `partial` / `done`，或 `none`（未落地 / 作废）。**与 `status` 正交**——`status` 管算不算数，`impl` 管做到哪一步 |
| `domain` | adr | ✓ | 域（RG-019）：这条决策**约束谁**。闭集见 `registry-lib` 的 `ADR_DOMAIN`（平台基座 / 会话与执行 / 资源与地址 / 模型与协议 / 智能体与记忆）；归域规则见 [`ADR-DOM`](./ADR-DOM.md)。域是条目上的可筛字段，过滤 / 分组按它筛，与目录无关 |

（RF-001 / RF-002 / RF-003），
逐条注入的回归测试是 [`registry-audit.test.mjs`](../../scripts/registry-audit.test.mjs) 与
[`gen-doc-refs.test.mjs`](../../scripts/gen-doc-refs.test.mjs)。

代码侧真相住 [`registry-lib`](../../scripts/registry-lib.mjs)，任何一边单改都会红。
