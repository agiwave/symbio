## 规范

限定名 `04 §3.1 死码台账`。**owner = 守卫源码** [`dead-code-audit`](../../scripts/dead-code-audit.mjs) 的 R-002 段
（`R002_BASELINE` 常量 + `<文> §3.1 <批号>` / `<文> §3.1 C 类` 的理由形状判据）——
本节登记「这套口径必须成立」，不复述每个标记与每个批次的明细（逐条清单由守卫**现算**）。

三条口径（本条目只把它们的**对账关系**固化）：

1. **承认必须挂计划步**：每处 `#[allow(dead_code)]` 的理由里写 `04 §3.1 批N`（或 `04 §3.1 C 类`），
   且 N 必须真实存在于下表（或 C 类）——「一处死码 ↔ 一个计划步」双向可查。
2. **棘轮只许降**：`R002_BASELINE` 随批次下调，不随本文件的意志上调；每次下调写 `// baseline-allow` 理由。
   终局基线 = **8**（A 类已清零，余下全是 C 类结构性承认）。
3. **C 类结构性承认**：消费方是前端镜像 / JS 审计而非 Rust 调用点，rustc 永远会报；
   其完成判据不是「接入」而是**理由必须写明消费方名**，且数量棘轮锁死不再涨。

**批号闭集**（`04 §3.1 批N` 里的 N；批次本身是逐批施工的事实，owner = 清偿批次提交，
本表只登记**批号这个封闭词表**，明细由守卫现算）：批① 摘 9 · 批② 0 · 批③ 摘 11 · 批④ 摘 2 ·
批⑤ 摘 16 · 批⑥ 摘 11 · 批⑦ 摘 13 · 批⑧ 摘 19 · 批⑨ 摘 10 · 批⑩ 摘 10 · 批⑪ 摘 23 · 批⑫ 摘 5；
