# ST-011 · 技能编译与自我改进

前置：S06、S03 ｜ **新增机制键 0** ｜ 参数变化 4 ｜ 阶段四

## 1. 场景：要什么能力

成功的执行轨迹被编译成**可直接命中的技能**，下次遇到同类情况不再走 LLM；
同时保留"反自动化回退"——异常或高不确定时退回完整推理。

相对 S10 高了什么：S10 是"有内容"，本阶是"**内容会自己变好**"。
T6 的定义就是"能从经验中改进自身行为"。

## 2. 为什么它能落在 v2 上（J1）

| 看起来新的东西 | 实际是 |
|---|---|
| 技能 | `memory.encoded{tag:"skill"}` 事件——**是事实，不是特殊类型** |
| 编译 | **写侧函数 + 开关**（`v2_skills::compile` → `memory.encoded{tag:"skill"}`）。[T-086](../009-task/086-技能编译落地形态批.md "T-086-技能编译落地形态批") 裁决：**编译不是投影**——投影是纯读函数（事件进、视图出），而编译有外部输入（本轮收束正文）与 `append` 副作用，类型上不可投影化。「一个 `Decider` 产出事件」里的 Decider 是**角色**行，归 [T-082](../009-task/082-角色行生产构造批.md "T-082-角色行生产构造批")；投影侧读技能的是 `recall{tag:skill}` + `calibration` |
| 加速 | 命中技能后走 `budget_ms` 更小的 ActorSpec |
| 回退 | 同一批事件下的另一个 ActorSpec 取值 |

**关键**：编译后的技能是**一条 `budget_ms` 更小的 ActorSpec，不是另一套机制**。
这也是为什么"系统 1 / 系统 2"在 v2 里不是两个系统——它们之间由 `skill_compile` 与回退规则**动态转换**，
而认知文档把它做成两套静态系统。这一处 v2 的表达力更强。

> 认知体系提出的 System 1 / System 2 **双系统**最终落在这一阶，并且只以"转换"的形式存在：
> `reasoner`（慢、有中间轨迹）→ `skill_compile` → `decider`（快、直接命中）→ 异常时回退。
> **不是两套并存的系统，而是一条参数化的转换链。**

## 3. 增量清单（只加数据）

| 类型 | 内容 |
|---|---|

| ActorSpec 行 | 编译者 `{ pattern: decider, capabilities: [], budget_ms: 5000 }`<br/>技能命中者 `{ pattern: decider, budget_ms: 80 }` |

| grants 行 | 无新增——编译者复用既有写权 |

**本阶点亮的机制键**（阶梯总表的「新增机制键」由这张块算出；`scripts/gen-verify-facts.mjs` 从这里取输入）：

```capability-assign

event.verb = progressed
actor.pattern = decider
projection = skill_compile
```

## 4. 平凡值与回退（J2）

| 参数 | 完整值 | **平凡值** | 平凡值下 |
|---|---|---|---|
| `actor.pattern` | `decider`（技能命中） | **`reasoner`** | 仍完整运行——永远走完整推理，退化成 S03 |
| 编译开关 | `skill_compile_enabled = true`（写侧编译 + route 命中） | **`false`** | 仍完整运行——不编译，只检索（`recall` 的平凡值路径：技能一条都没有，召回 / 巩固照常） |

**"不编译"是整个自我改进能力的安全退路口**：关掉 `skill_compile_enabled`，
系统性能退化但行为不变——所以自我改进是**可关的**，这一点对生产环境至关重要。

## 5. 静默失效与强制（J3）

| 约束 | 违反时信号 | 强制方式 |
|---|---|---|
| 技能必须有溯源轨迹 | **无** | I2 断言：`produced_by` 指向源轨迹 |
| 高不确定时必须回退完整推理 | **无**——可能一直用错技能 | `calibration` 投影 + 阈值断言 |
| 「凸度 / 密度」不许由 reliability 冒充 | **无**——把 1−回退率印成「凸度」即可读数失真而无人察觉 | [T-086](../009-task/086-技能编译落地形态批.md "T-086-技能编译落地形态批") 批②裁决：读数今天不存在（§3.1），`stats` 的校准列只许报 `uses`/`fallbacks`；要立凸度读数先补竞争分布的观测面，另立批次 |
| 编译不得污染在途决策 | **无** | `Timestamp` as-of（同 S06） |

> **必须保留反自动化回退**（Beilock & Carr 2001 *choking under pressure*）：
> 全自动化在压力下会以异常方式失效。这不是保守，是被实证过的失效模式。

## 6. 验收断言

1. 编译产出的技能事件 `produced_by` 必须非空（指向源轨迹）。
2. 命中技能后 `cost_ms` 显著低于未命中路径。
3. 置信度低于阈值 → 必须走 `reasoner`，不得走技能路径。
4. **反向用例**：把编译者的 `produced_by` 置空 → 断言 1 必须失败。

## 8. 这一阶做不了什么

边界的唯一账本：[SC-011-技能编译与自我改进](../002-scene/011-技能编译与自我改进.md)（用户语言）。机制面独有边界（用户可见范围之外的工程约束）：

- **"哪些轨迹值得编译"是算法问题**，架构只提供 `skill_compile` 这个位置。
- **凸度 / 密度读数不存在**：观测面只有 uses / fallbacks（ reliability），没有竞争分布；`recall` 也没有 `density` 形参——补读数要先补观测面，另立批次（T-086 批②裁决）。
- 从"改参数"到"改架构"的跨越**不在本阶范围内**（那是 ADR，不是数据）。
