## 内容

父设计：[PL-013 §6](../004-plan/013-前端机制化.md "PL-013-前端机制化")

用户诉求「已完成未展开的骨架节点：前端可释放内部子节点，展开时向后端请求加载」。这条**要求骨架自带 `stats`**——
折叠态也看得见"里面有多少 / 什么类型 / 还在跑几个"，`stats` 上线由 [T-147] 完成协议侧写入，本任务落前端消费与 VDFS 动作。

## 处理过程

### 150-i（后端 `expand_skeleton` 动作 + 子树读侧）— 已完成

- **动作词**：`VDFS_ACTION_EXPAND_SKELETON = "expand_skeleton"`（`vdfs/words.rs`，
  两处 mod 重导出）+ TS 镜像 `schemas/vdfs.ts` 同批加入（`protocol-mirror-audit` A 组
  34→35、0 错——两栈同名单条不许拆提交）。
- **落点**：`vdfs_provider.rs::messages_at` 的 Action 臂，**排在恢复 catch-all 之前**
  （catch-all 拿 `word` 反序列化成 `ResumeAction`，`expand_skeleton` 不在其词表会掉进
  `NotImplemented`）。地址是 `<sid>/message/<mid>`，`mid` 即被折叠的骨架自身——与
  `truncate`/恢复同一位置族。
- **只读**：动作不改存储，只回子树。出参 `data = {session_id, root, nodes: [窄帧…]}`。
- **读侧查询**：`nodes.rs::subtree_nodes(msgs, root, depth, since_seq)`（BFS 按
  `parent_id`）——`depth="1"` 只直接子节点，其余（缺省/`all`）整棵后代；`since_seq` 只回
  seq 更大的后代（增量补齐，父闭合由调用方负责）；root 不存在 ⇒ 空。不含 root 本身（已在本地）。
- **验证**：`nodes.test.rs` 五例（all / depth1 / since_seq / missing-root / 往返

  subtree_on_demand`（经 dispatch 回执断言四档 + 转写列表不变）；`seed_messages` 重构成
  委托 `seed_nodes`（带 parent_id 的种子）。全量 `cargo test --lib` 1714 绿。

### 150-ii（前端折叠释放 + 按需重取 + localStorage）— 已完成

依赖本批的 `expand_skeleton`。design §6 假定「骨架自带 `stats`（计数/类型/在飞）」由
[T-147] 协议侧写入，但**该 producer 从未落地**（仓内无 `NodeStats`、`ChatNode`/`VdfsNode`
无 `stats` 字段）。折叠态计数因此由**前端本地**结算——与 exit「本地字段，不写后端」一致，
不新造后端 producer。

落点 `tauri/src/stores/skeletonLazy.ts`（数据基座，纯函数 + 账本 store 两层）：

- **纯函数**：`subtreeOf(nodes, root, depth)`（BFS 按 `parent_id`，逐字镜像后端
  `subtree_nodes`——两侧必须同语义，否则「重取回来的形状」≠「释放掉的形状」）、
  `releaseSkeleton(dict, root)`（摘子树、留 root）、`mergeReleased(dict, frames)`（装回）。
- **账本 store** `useReleasedSkeletonsStore`：`会话→骨架→{count}` 存 localStorage
  （`symbio.releasedSkeletons`），`markReleased` / `markExpanded` / `isReleased` / `summaryOf`，
  init 时 `loadLedger()` 恢复 ⇒ **跨刷新保留被释放的骨架集合**（exit 判据）。
- **`unloaded` 不进 `ChatNode` 线格式**：它是纯前端状态，写进 wire 会被
  `protocol-mirror-audit` D 组（前后端字段名比对）判红多出一个。释放态由这张独立账本承载，
  等价满足「本地字段，不写后端」。
- **按需重取**：`useChatConnection.expandSkeleton(mid, depth)` 对 `<A>/message/<mid>` 发
  `expand_skeleton` 动作，把回执 `data.nodes` 走唯一落地口 `applyTranscriptMessages` 装回，
  再 `markExpanded` 摘除释放标记。**只读**：不动运行态、不改 seq。

**验证**：`skeletonLazy.spec.ts` 11 例（`subtreeOf` 三形状 + 「释放→重取→逐键相等」往返 +
localStorage 持久化/跨刷新恢复/损坏 JSON 退化）；`useChatConnection.spec.ts` 追加 3 例
（落点+payload+装回转写+摘标记 / 未生效不装回 / 异常不抛）。`vitest` 全绿（904）、`vue-tsc` 净、
`protocol-mirror-audit` 0 错。

**遗留（浏览器 QA，本环境不可无头验证）**：`NodeShell` 折叠态摘要 chip 的**视觉呈现**——
「超过阈值触发释放」的阈值策略与摘要 chip 渲染属 Tauri UI，需在真实浏览器里核对；数据侧与
动作侧的原语与接线已就绪且单测锁死，剩下的只是把 `releaseSkeleton` / `expandSkeleton` 接到
展开交互上。
