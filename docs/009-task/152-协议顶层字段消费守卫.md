## 内容

决策依据：[ADR-070 §决策 2](../010-adr/070.md "ADR-070")

把「前端机制化 vs 业务化」的分界**从口号变成可判红的一条判据**——没有守卫，一次「顺手加个 tool_call_id
到顶层」的 PR 就能把纪律抹掉。

## 处理过程

在 `protocol-mirror-audit.mjs` 收尾前插入 G 组。做法：

1. **取对象**——从 `tauri/src/schemas/chat_node.ts` 的 `ChatNode` 接口解析顶层字段名（复用 D 组已有的
   接口字段解析）。缺文件即报错，口径与 D 组一致（不是静默跳过）。
2. **建语料**——扫 `tauri/src` 的 `.ts`/`.vue`（排除 `__tests__`，测试持夹具是它的职责）与 `cli/src` 的
   `.rs`，剥注释后汇成一个待匹配的 code 行集合。
3. **判据**——对每个字段 `F`（`meta` 自身除外，它是间接读的宿主），正则抓 `\.F\b`（含可选链 `?.F`）命中点；
   命中点前文以 `meta` / `meta?` 收尾 ⇒ 记间接（`viaMeta`），否则记直接（`direct`）。
   **`direct===0 && viaMeta>=1` ⇒ 违规**：该字段住在顶层却被当 meta 用，本就该沉入 `meta` 或移出协议顶层。
   - 关键坑：切片 `code.slice(0, m.index)` **不含**本次匹配的起始点，故 `node.meta.F` 的 `before` 以 `meta`
     结尾（无尾点）。判据正则因此是 `/\bmeta\??$/` 而非带 `\.$` 的写法——否则会把经由 meta 的间接读误计为直接，
     守卫亮绿灯却不守。
4. **零命中不判**——G 管的是「住在顶层却被当 meta 用」的错位，不是死字段（后者归 D 组 / dead-code）。
   这条同时让测试基线仓库（`ChatNode` 只声明 `id`/`parent_id`、无任何消费）保持绿灯。

真仓库跑：13 个顶层字段（除 `meta`）全部有直接消费者（扫 16019 行生产代码），Errors: 0。
