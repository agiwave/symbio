## 内容

父设计：总报告 §4.2 断层二与 B1 · 06 报告建议 1 / 5 · [PL-014](../004-plan/014-单环一表收敛.md "PL-014-单环一表收敛") §3（Step 五值）与 §4 机制 1（单环驱动器）

**问题不是「函数太长」，是「阶段还不是数据」**。loop 是全仓体量与复杂度的双重热点
（三个文件合计 5117 行 = 生产代码的 6.1%），但核心病灶是一轮的阶段仍是**硬编码的直线代码**：

- 策略表只是过渡形态——「每格一行」已做，但主循环仍是七步直线代码，**策略表没有真正驱动控制流**；
- 三个巨型函数合计约 2100 行待拆；
- 工具调用串行、`is_working` 靠 50ms 轮询（后两条分别归
  [T-190](190-工具调用并行化批.md "T-190-工具调用并行化批") 与
  [T-191](191-运行态小状态机收口批.md "T-191-运行态小状态机收口批")）。

**为什么这是机制性而不是风格问题**：v2 的判据函数 `pattern(action) = 可写成规则→Decider，
只需重述→Translator，否则 Reasoner` 本可以直接当作「阶段 = 数据行」的载体——
一轮执行 = 一串 `(模式, 档位, 预算, 输入, 输出)` 的行。阶段数据化之后：

- 巨型函数自然碎成「行执行器 + 行表」，不需要另外按职责拆；
- 策略表从过渡形态转正，新增阶段是**加一行**而不是**加一段代码**；
- 时延闸门（预算）随行携带，不再靠散落判定；
- 这一处收敛的收益外溢到 M4（工具执行）、M5（会话派发）、M8（事件落格）四处。

**与两条前置的关系**（不重叠，只排序）：

| 前置 | 它做什么 | 本批接什么 |
|---|---|---|
| [T-179](179-三巨型函数阶段拆分批.md "T-179-三巨型函数阶段拆分批") | 把三个函数**按阶段切点**拆开（顺序过程按阶段切，不按职责切） | 拆开之后的每段，正好是一行的执行体 |
| [T-180](180-驱动器收敛批.md "T-180-驱动器收敛批") | 七步直线代码收成 `loop { project → decide → execute }`，臂分派收成穷尽 `match` | 三段环里的「段内直线」再数据化为行表 |

**一条熔断线**（照 [PL-014](../004-plan/014-单环一表收敛.md "PL-014-单环一表收敛") §0 的
「形状是裁决、路径是数据」）：若某个阶段无法脱离「直线代码里的位置」表达，那是**模型不够**，
不是本批该硬塞——按纪律 0 发起一次架构讨论，不得为赶进度把判据写残。

## 处理过程

- 2026-10-20 立批。来源：总报告 §4.2 / B1 + 06 报告建议 1 与 5。
- 2026-10-20 一处口径澄清：05 报告建议 1 写的「启动 PL-014 步骤 1（Step 环替换 `run_with_tools`）」
  与本批是同一件事的两个阶段——[T-165](165-控制面收敛.md "T-165-控制面收敛") 已把步骤 1 落地为
  **决策点抽取**（环体行数不变），本批接的是「环体本身数据化」这一段，不重做步骤 1。
- 2026-10-20 排在 T-179 / T-180 之后是硬顺序：先拆（结构）再收（驱动）后数据化（行），
  反过来会把同一批代码搬两次。
- 2026-10-21 排序改判（[ADR-107](../010-adr/107.md "ADR-107")）：[T-180](180-驱动器收敛批.md "T-180-驱动器收敛批")
  转 `wont`——外环 drive 缺「一次性阶段已做」的事实，先收驱动只能靠私有簿记。
  本批 deps 去掉 T-180，顺序改为 **① 阶段事实化（verdict 判决事实 + 一次性阶段的
  「已做」）→ ② 阶段行表**：① 是 ADR-107 判据 2「执行后下一次问表必须 `Declined`」的
  前提，也是 drive 将来重裁时要读的材料；② 是本批的行形状。drive 本身不在本批，
  事实就绪后另裁（届时可能直接与内环合一）。
- 2026-10-21 ① 落地（段一）。**一格事实**：新增 `turn.stage`（`turn × asserted`），
  幂等键 `st-{turn}-{round}-{stage}`，载荷 `{stage, round}`；`classify` 那次额外带
  `reason` + `source`（`rule` / `model` / `fallback` / `absent`）。来源由理由码词表
  **派生**（映射住 `plugins/loop/stage_events`，用一条用例对整张词表逐条钉住），
  不给 core 的 `Verdict` 加字段——那是把 `classify` 的实现细节写进契约面。
  **三格转假**：`LoopState` 的 `TurnHead` / `Compress` / `TurnPrepare` 各加 `done`，
  `policy.classify` / `policy.compress` / `policy.recall` 都多一条 `!done`；`done`
  只出现在这三格（轮边界 / 反射每轮重判，没有「已做」这回事，字段读不到）。
  **投影口径**：生产侧 `done` 是 `TurnState` 的**本次执行折叠**（续写幕复用轮号，
  扫全史会把本幕该重跑的召回 / 压缩误判为已做）；`stage_events::done` 是「事实 → 已做」
  的规范投影（PL-014 §3 规则 d 允许的增量投影 + 缓存折叠），当前由单测钉住、
  drive 转正时改用。**落格位置**：草稿由编排层产出，持写者令牌的
  `turn_runner::{prepare_turn, run_reflex}` 在用户格之后落格（I2 溯源）；重复落格
  按 `Duplicate` 吸收——续写幕重跑同一 `(turn, round, stage)` 不是失败。
  **验收**：`stage_events.test.rs` 10 条，含 ADR-107 判据 2 的逐行形态（classify /
  recall / compress 各一条：执行后下一次问表必须 `Declined`，compress 另钉「只挡本
  请求轮」）；`cargo test -p symbio --lib loop` 355 passed / 0 failed。
  ②（阶段行表）尚未开始。
- 2026-10-21 ② 落地（段二：阶段行表）。**行形状补两位**：`Row.effects`（`Effects { tier }`）
  与 `Capsule::owner()`（臂的归属格）。档位是约束执行的值，预算由
  `LatencyTier::budget_ms` **派生**（J1 不存第二份）；`owner` 把「臂由哪一格执行」
  从五个调用点各记一份的约定变成数据，补上 PL-015 §4.2 的静默失效。
  **五个调用点统一为**：取 `Hit` → `hit.trace()`（格 / 行 / 臂 / 档位 / 预算一行日志）
  → `match hit.capsule` **穷尽列举**本格接的臂 → 执行体。`turn_exec/assemble` 的档位
  不再由「有没有命中」反推，直接读 `hit.effects.tier`；`RoundProgress::due` 由
  `bool` 改为 `Option<Hit>`，汇报回调按臂分派。**执行体抽出**：`run_turn_head`
  （轮首判决，原步骤 2b 的 160 行体）、`run_recall`、`run_compress`——主循环与准备
  流程只剩「取行 → 分派 → 落格」。
  **模式为什么不进行**：模式是输出臂的固有属性（`Capsule` 决定动作形态），策略行
  没有独立读方；给 core 的 `Pattern` 加 `name()` 只为日志会抬高 CS-001。五位的落点见
  `Row` 的文档表（模式 → 臂、档位 → `effects`、预算 → 派生、输入 → `LoopState`、
  输出 → `Capsule`）。
  **诚实划界**：「新增一个阶段 = 加一行」在直线代码里的成立范围是**同格加行且复用
  已有臂**（`adding_a_second_row_to_a_site_is_pure_registration` 钉住，主循环零改动）；
  新**臂**要改枚举 + `owner` + 五处分派组（这是环的指令集，代价是想要的）；新**格**
  （新时机）仍要加调用点，属 drive（A2/A3，ADR-107 推迟）。
  **验收**：`loop_registry.test.rs` 31 条（新增 `every_capsule_is_owned_by_the_site_
  that_produces_it` / `capsule_owner_is_total_and_injective` /
  `builtin_rows_carry_their_declared_tier`）；`cargo test -p symbio --lib`
  1893 passed / 0 failed。② 完成，本批收口。
