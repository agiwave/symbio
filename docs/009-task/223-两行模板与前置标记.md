## 内容

父设计：[PL-016 · 义务环](../004-plan/016-义务环.md "PL-016-义务环") §2.3

**两行模板**——每端口固定两行，**差异只有 `by` 一个字段**：

```
行 A  dispatch-<port>   owes:   request(port=<port>)
                        until:  sent(port=<port>) | failed(port=<port>)
                        before: sent                        ← 引擎在运行前落
                        by:     courier

行 B  await-<port>      owes:   sent(port=<port>)
                        until:  response(port=<port>) | failed(port=<port>)
                        by:     None                        ← 全部差异就在这个 None
```

**`sent` 为什么必须由引擎写，不能由搬运者写**：搬运者的 `run` 可能**不产生事实就返回**
（异步派发就是这样）。如果 `sent` 由搬运者写，那么"派出去了"这件事依赖搬运者自觉；
一旦它忘了，`dispatch` 行永远不还清，环就死在那里——而**它不报错**。
所以引擎在调 `run` **之前**落 `sent`（`before` 字段），这是引擎仅有的两个写动作之一
（另一个是追加执行体交回的事实）。

**`Wait` 折叠**：`by = None` 对 `drive` 是透明的——恒 `blocked`、永不选中。
它存在的理由不是"它是一类债"，而是让 `open ≠ ∅ ∧ actionable = ∅` 这个状态**可表达**：
"在等"与"没事"必须能区分。**这是"这笔账不由引擎执行"的唯一声明位。**

**`Ask` 折叠**：`request{port:model}` 是一行普通的 `dispatch` 债。
PL-014 §3 自己写了 `Ask` 是 `Act(Model 行)` 的特例、"工程取舍不是逻辑必然"——
本任务兑现这条自认。**但预算档位不能丢**：今天 `Ask` 独立成值是为了把
`RuleOnly` / `ClassifyOnly` / `FullModel` 三档 ZST 闸在类型上（PL-001 §10）。
折叠后这层闸门必须落在 `Effects` 上（`Row.effects` 已有这个字段），
**不能因为 `Ask` 没了就把档位也丢了**——这是本任务最容易做丢的一处。

**在途进日志，是这一整步换来的东西**：今天"在途"是内存里的一个集合，崩溃即失忆；
折叠之后 `in_flight = sent ∧ ¬(response | failed)` 是个**视图**，重启后从日志重建。
崩溃恢复因此第一次能回答"上次死的时候还有哪些调用没回来"。

**施工顺序**：先只做**模型**这一个端口（两行），跑通 e2e，再铺工具 / 时钟 / 存储。
一个端口跑不通就铺开，会在四处同时埋同一个错。

**明确不做**：不新增机制键（`before` 已在 `Decl` 里，`courier` 是一个普通执行体名）。

## 判据

| # | 判据 | 检查方式 |
|:-:|---|---|
| 1 | 加一个端口 = 3 条 `FactDecl` + 1 个适配器 + 2 行，`drive`/`owed` diff = 0 | 源码级断言 |
| 2 | `sent` 只由引擎写 | 静态扫描：搬运者的 `run` 不产出 `sent` |
| 3 | 搬运者返回空事实时环不卡死 | 用例：`run` 返回 `vec![]`，`await` 行照常挂起、不重复派发 |
| 4 | 崩溃后 `in_flight` 可从日志重建 | 用例：只给日志，不给内存状态 |
| 5 | 预算档位仍被闸住 | 用例：反射档请求模型 ⇒ 拒绝（档位在 `Effects` 上生效） |
| 6 | 重复派发有幂等键 | 用例：同一债 `key` 二次 `run`，`sent` 不重复落 |

## 处理过程

- 2026-10-21 立项。前置 T-222（表化）——没有 `Decl` 就没有 `before` 字段可挂。
- 2026-10-21 一处已识别但需在实现时复核的风险：`sent` 是**每条搬运路径多一条事实**
