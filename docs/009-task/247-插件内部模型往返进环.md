## 内容

父任务：[T-236-义务环符合性收口批](236-义务环符合性收口批.md)。前置：[T-238-短路轮进债环](238-短路轮进债环.md)
（它把**编排层自己发起**的那次模型往返接进了环，并把剩下的未入账部分点名到这里）。

PL-017 判据 2 的全量口径是「每一次模型 / 工具调用都有 `sent` + 应答」。T-238 之后
CLI 实测（会话 `verify-ring-5` / `verify-ring-6`，`obligation-ring-accept` J8）显示
每轮仍**恒差一次**未入账的模型 HTTP 调用：`classify` 的快速档判决。它发生在插件内部，
编排层手里只有「路由一次 `classify/decide`」这一个动作，调用**之前**无法知道规则表
会不会命中。

这不是实现偷懒，是一条**契约缺口**：`sent` 的语义是「已派出」，在调用前补记就是
把可能没发生的往返记成发生了——日志从此数不出模型调用，判据 2 反被入账动作本身破坏。
所以本任务的第一件事是**裁决**，不是代码；裁决已出 = [ADR-122](../010-adr/122.md)。

同一形状的第二个候选是自动压缩的摘要调用：它在事实层连观测都没有
（`turn.stage{stage:"compress"}` 记的是「这一步跑过」，不是「打了模型」），
因此 J7 抓不到、只有 J8 的差额能抓到。ADR-122 一并给它定了观测形状
（与 classify 同：往返走引擎 `model` 端口派发路径）。

## 判据为什么现在敢挂着

`scripts/obligation-ring-accept.mjs` 的 `MODEL_PATHS` 里那条带 `task: T-247` /
`until: 2026-11-05` 的豁免是**有名有姓、有期限**的：期限过了 J7 直接红，
条目还在而观测消失（已进环）在 `--strict` 下也红，实际差额超过豁免额 J8 红。
本任务闭包的定义 = 删除该条目后脚本仍全项通过——豁免表不许长第二行。

## 验收口径

1. 架构裁决先行：一条 ADR 或 PL-016 小节写明三选一里选了哪条、其余两条为什么否掉；
   未裁决不动模块（`AGENTS.md`「架构改动：只认方案为源」）。**已兑现 = ADR-122**，
   后续改模块以它的五条决策为准。
2. 用例：`cargo test -p symbio --lib "loop::port"` 里一条「判决往返入账 ⇒ 三格 + `via=classify/decide`」
   与一条「规则短路 ⇒ 零入账格」（不许用「按构造不可达」代替后者）。
3. CLI 复验：`node scripts/obligation-ring-accept.mjs --homedir=.symbio --session=<纯问答轮>
   --session=<工具轮> --cli-log=<日志> --strict` 在**删掉豁免条目之后**全项通过，
   J8 输出 `HTTP == sent(model)`（差额 0）。
4. 压缩路径按裁决结论给出可判定形态：要么入账（J7 加一条 `MODEL_PATHS`），
   要么明文论证它零模型往返并让 J8 的等式在该场景下成立。

- 2026-10-23 补记（T-242 CLI 复验会话 `verify-loads-1`）：失败轮也漏账。那一轮本地模型
  退化（`finish=Length`、正文 0 字符、推理 12235 字符 ⇒ T-142「本轮未产出答话」出口），
  J8 报 `HTTP 3` 而账上只有 `sent(model) 2`。差额落在本任务已登记的「插件内部模型往返
  未入账」同一档，但**多一层**：判据 2 的口径是「每一次调用都有 `sent` + 应答」，退化的
  那一次同样发生了 HTTP，它的应答格是什么形状，本任务裁决时必须一并写明——否则收口后
  J8 的等式只在顺利轮成立，失败轮重新漏差。验收口径 3 的复验因此要**再补一条失败轮会话**。
- 2026-10-23 补记（T-243 CLI 复验会话 `verify-seal-1`，两幕 58 格 / 10 组往返）：
  **判决往返在事实层连观测都没有**，比原来记的更糟。原判据把观测钉在
  `turn.stage{decide, source:"model"}` 上，而 `source_of` 判的是**判决的来源**不是
  「有没有打过模型」：那次会话里 `classify` 确实各打了一次模型（日志两行
  `[Classify] 分类使用模型` + 两次 `tools=0` 的 HTTP），但应答不可解析 ⇒ 落
  `Escalate{unclassified}` ⇒ `source=fallback`，事实层零痕迹。于是 J7 数出「观测 0」，
  `--strict` 把还挂着的豁免判成假绿灯，J8 的 `HTTP 7 ≠ sent(model) 5 + 豁免 0` 一起红。
  判据脚本已改：这条路径的观测改读 CLI 日志（`MODEL_PATHS.logMarker`，日志切不出会话
  归属 ⇒ 整轮判），`--strict` 下没给 `--cli-log` 直接判红而不是「未判 = 过」。
  **裁决含义**：候选 ② 「先问这次会不会打模型」在本档形状下连问都问不出来——插件
  调用前不知道规则表命中，调用后事实层也只留来源；要让它可判定，入账动作必须发生在
  **调用那一步本身**（① announce 或 ③ 消灭路径），而不是靠事后补记来源。
  验收口径 4 同时给压缩路径定这一格：`turn.stage{compress}` 现状与 `decide` 同形，
  裁决时两条一起写明观测落在哪一格。
- 2026-10-23 裁决已出（[ADR-122](../010-adr/122.md) ⇒ 验收口径 1 兑现，本任务转为实现批）：
  **否 ①**（插件经 `ctx` 自己 announce ⇒ 协议格出现第二个写方，`lease`/`retry` 开始管辖
  引擎无法重放的调用，「崩溃后重放到上一次模型请求」对这几笔成假话）；
  **否 ②**（`verify-seal-1` 实证：调用前插件不知道规则表命中，调用后事实层只留判决来源，
  「这次会不会打模型」连问都问不出来）；**取 ③ 的「消灭插件内部路径」半，否它的
  「并入工具循环首轮」半**（行表已为 classify 留了 `policy.classify` 那行，并入首轮
  等于让它永远空转，还抹掉「规则表命中 ⇒ 零往返」这个真实区别）。
  形状：`policy.classify`(10) / `policy.compress`(30) 各接回执行体 `decide` / `compress`，
  模型往返走引擎 `model` 端口派发路径——入账是派发的副产品，不是调用点的责任。
  两条附带定死：零往返的轮 = **行不成立**而非「行成立但没写格」；退化应答照样有
  `response`（`calls` 为空数组），「未产出答话」归收束侧 `reason`（这一条让 J8 在失败轮
  也成立，正是上面两次补记的差额）。本任务剩下的是改模块与删豁免条目（验收口径 2–4）。
