## 内容

父任务：[T-236-义务环符合性收口批](236-义务环符合性收口批.md)。前置：[T-238-短路轮进债环](238-短路轮进债环.md)
（它把**编排层自己发起**的那次模型往返接进了环，并把剩下的未入账部分点名到这里）。

PL-017 判据 2 的全量口径是「每一次模型 / 工具调用都有 `sent` + 应答」。T-238 之后
CLI 实测（会话 `verify-ring-5` / `verify-ring-6`，`obligation-ring-accept` J8）显示
每轮仍**恒差一次**未入账的模型 HTTP 调用：`classify` 的快速档判决。它发生在插件内部，
编排层手里只有「路由一次 `classify/decide`」这一个动作，调用**之前**无法知道规则表
会不会命中。

这不是实现偷懒，是一条**契约缺口**：`sent` 的语义是「已派出」，在调用前补记就是
把可能没发生的往返记成发生了——日志从此数不出模型调用，判据 2 反被入账动作本身破坏。
所以本任务的第一个交付物是**裁决**，不是代码。

同一形状的第二个候选是自动压缩的摘要调用：它在事实层连观测都没有
（`turn.stage{stage:"compress"}` 记的是「这一步跑过」，不是「打了模型」），
因此 J7 抓不到、只有 J8 的差额能抓到。裁决时一并定它的观测形状。

## 判据为什么现在敢挂着

`scripts/obligation-ring-accept.mjs` 的 `MODEL_PATHS` 里那条带 `task: T-247` /
`until: 2026-11-05` 的豁免是**有名有姓、有期限**的：期限过了 J7 直接红，
条目还在而观测消失（已进环）在 `--strict` 下也红，实际差额超过豁免额 J8 红。
本任务闭包的定义 = 删除该条目后脚本仍全项通过——豁免表不许长第二行。

## 验收口径

1. 架构裁决先行：一条 ADR 或 PL-016 小节写明三选一里选了哪条、其余两条为什么否掉；
   未裁决不动模块（`AGENTS.md`「架构改动：只认方案为源」）。
2. 用例：`cargo test -p symbio --lib "loop::port"` 里一条「判决往返入账 ⇒ 三格 + `via=classify/decide`」
   与一条「规则短路 ⇒ 零入账格」（不许用「按构造不可达」代替后者）。
3. CLI 复验：`node scripts/obligation-ring-accept.mjs --homedir=.symbio --session=<纯问答轮>
   --session=<工具轮> --cli-log=<日志> --strict` 在**删掉豁免条目之后**全项通过，
   J8 输出 `HTTP == sent(model)`（差额 0）。
4. 压缩路径按裁决结论给出可判定形态：要么入账（J7 加一条 `MODEL_PATHS`），
   要么明文论证它零模型往返并让 J8 的等式在该场景下成立。
