## 内容

父设计：[PL-016 · 义务环](../004-plan/016-义务环.md "PL-016-义务环") · 形状裁决：[ADR-114](../010-adr/114.md)

**这一批只做一件事：把控制面的调度单元从「动作」换成「欠账」。**
它不是新架构——[PL-014 §2.1](../004-plan/014-单环一表收敛.md "PL-014-单环一表收敛") 早已写下终点语义
`agent = fixpoint(decide) over (事实日志 × 世界端口)`，本批是它的直接实现。

| 换掉什么 | 换成什么 | 为什么 |
|---|---|---|
| `decide -> Option<Step>`（短路选一个） | `owed -> Vec<Debt>`（全量取最小） | 能回答"还欠几笔"，而不只是"选中哪个" |
| `Step::Wait(WaitSet)` | `by = None` 的债 | PL-014 §2.1 自认"终点折叠" |
| `Step::Ask(PromptRef)` | `request{port:turn}` 事实 | PL-014 §3 自认"非极小点、工程取舍" |
| `[事实 \| 意图]` 两类产出 | 只有事实一类 | 意图本就是"还没落成事实的请求" |
| `LoopState` 从配置 / 墙钟 / 内存读输入 | 视图 + 触发事件时间戳（输入闭包） | 否则 `owed` 不是纯函数，回放重建是假的 |
| 执行体"返回事实"的无约束约定 | 异步 / `Result` / 取消 / 上界 / 无进展 / 租约 | 失败与崩溃必须成为事实，不能靠自觉 |

**十一步的排布不是按依赖图排的，是按"哪一步可能推翻方案"排的。**
只有步 3（权限）与步 6（输入闭包）是真的会返工——前者决定 `owed` 能不能不用否定原子，
后者决定 `owed` 能不能是纯函数。步 2（`produced_by` 不悬空）与步 4（`reason` 必填）
**独立于形状**，现在做的理由只是成本最低：这两个字段的构造点还少，协议名一入党（步 8），
它们要跟着改一遍。

**范围边界（2026-10-22 收准）**：本批的控制面停在 `turn` 粒度。
`run_with_tools` 的内环倒置（模型 → 工具 → 模型）是 [PL-017](../004-plan/017-端口细粒度化.md "PL-017-端口细粒度化")
/ T-227 的范围，**不属本批**。原 T-223 写"先做模型端口"与自己的文件面冲突——
模型调用在 `turn_runner` / `turn_exec` 里，按原写法施工等于在本批重写执行引擎。
裁决见 [ADR-115](../010-adr/115.md "ADR-115") 决策 5。

## 处理过程

- 2026-10-21 立批。来源：义务环设计与 PL-001/002/014 的逐项对比
  （17 场景纸面推演：平 11 · 强 3 · 弱 2，未实测）。
- 2026-10-21 为什么是 now：形状裁决已立（ADR-114），三处前置的补法都已想清且都很轻；
  再拖会让 PL-014 已落地的 `Step` 词汇继续固化，后换成本更高。
- 2026-10-21 与 [T-165](165-控制面收敛.md "T-165-控制面收敛") 的关系：T-165 收敛了"几个环"（单环），
  本批收敛"环里那个单元是什么"（债）。**T-165 是前置且已 done。**
- 2026-10-21 与 [T-189](189-轮执行阶段数据化批.md "T-189-轮执行阶段数据化批") 的关系：T-189 把"一轮"
  做成"一串阶段行"，本批把"下一步做什么"做成"一笔债"。两者共用"行表"这个底座，
  但**不重叠改动面**：T-189 动的是轮内阶段，本批动的是环的调度单元。
- 2026-10-21 **四处核对把方案的范围改小了，逐条记在这里**（初稿的四处判断与代码不符）：
  ① 溯源边**已有**（`Event.produced_by`，20+ 构造点 + 覆盖检查），缺的只是"不悬空"——
  步 2 从"加信封字段"缩为"加一条判据"；
  ② 权限**判定健全**（`authz.rs` fail-closed 三层），缺的是"否定不落事实"——
  步 3 从"把授权做成一行债"缩为"把拒绝落成事实"，搬迁部分推给 T-222 之后；
  ③ 停机原因**有三个形状**（`status` / `terminated.reason` / `why`）而不是没有载体——
  步 4 从"新增 `reason`"改为"三个形状收成一个"；
  ④ **"网格压成 4 个协议名"是错的**——现网 30 个业务事实名、385 处引用，
  压掉就是销毁语义；步 8 改为"新增协议名，业务名零改动"（终稿为 5 个，含 `retry`）。
  同批另发现一处**过度声称**：现网 `Verdict` 已是三值（`Declined` / `Unmanned`），
  CI 的 `every_site_is_manned` 已在拦"无人值守"——PL-016 初稿把"规则缺口移到装载期"
  算作本方案的实质改进，不成立；已改为"义务环加的是更硬的一档（每行收口 vs 每格有人）"。
- 2026-10-22 **第三轮核对补了三块承重墙**，裁决见 [ADR-115](../010-adr/115.md "ADR-115")：
  ① `owed` 的输入不闭包——配置 / 墙钟 / 内存匹配结果不在事实面；补 T-225（决策输入闭包），
  排在 T-221 之后、T-222 之前；② 执行体没有契约——补异步 `Result` / 取消 / 步数上界 /
  无进展 / 租约重试（PL-016 §2.6）；③ 端口粒度没有分期——首端口从 `model` 改为 `turn`，
  细粒度端口立 PL-017 / T-227，**不属本批**。同批把授权从 `¬permitted` 否定模式改成
  `granted` / `denied` 正事实级联（T-226），把 `port` 裁决为载荷（新增端口不新增事实名）。
  这三块不改变债的形状，但缺了它们，方案一落地就会在输入、失败、恢复三处同时漏。
