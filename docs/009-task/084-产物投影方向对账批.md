## 内容

T-122 §3.1 核实：正文写「产物引用进 UI，**不进上下文**」（`projection = display`），
生产实况相反——`artifact.added` 经 `projection/transcript.rs:520` 投成 tool 行**喂进 prompt**。
同一事实的两个方向只有一个能活：

- 若「不进上下文」是目标（省 token、防产物污染推理），那是待落地增量，动的是 prompt
  形状——`t46` 形状基线是现成的翻红判据；
- 若生产形态才是目标（模型必须看见自己产过什么），那 §3 的 display 行与相关断言是错的
  目标陈述，按总纲 §6「新定义 → 验证 → 删除老定义」修订。

这是「文档即登记」纪律的直接受益案例：审计发现的不是 bug，是一条**未被裁决的目标歧义**。
