## 内容

本任务由 [T-076](076-e2e面缺失补齐批.md "T-076-e2e面缺失补齐批") 的面审计开出。
RE-005 的「通道与自动化面」行三格全空，且这一行的缺席**从未被缺口表登记过**——
它是「格子全入格」自洽掩盖**行的缺席**那一类（见该矩阵 §行集对账）。

### 面有多大（取自 RE-006 §2 的路由族：§2.1 LLM 可见工具 · §2.2 VDFS 操作 · §2.3 前端 / 宿主路由）

| 插件 | 路由数 | 说明 |
|---|---|---|
| `telegram` | 6 | 收发消息与轮询；上游 = `api.telegram.org` |
| `hook` | 3（`hook/fire` · `hook/register` · `hook/list`） | 其他插件经它触发生命周期钩子 |
| `home` | 2（`home/reload` · `home/get_homedir`）+ 绝对路径终结 | homedir 切换与绝对路径路由的终结处理 |
| `work` | 2（`work/set_workspace` · `work/get_workspace`） | **是 home 的臂**（同在一个 `home/plugin.rs` 的 `match path` 里），不是独立插件 |

> **2026-10-15 订正**：本表原写 `hook` 1 条（`hook/fire`）、`home` 1 条、`work`「由既有行承载」——
> 三处都不准。逐插件读 `route()` 的 `match` 臂后：`hook` 是 **3** 条
> （`hook/plugin.rs:130-141`）；`home` 是 **2** 条（`home/plugin.rs:460-501`）；
> `work/*` 两条**同在一个 `home/plugin.rs` 的 `match` 里**（503-517），
> 因此归本行而不是「任务 · 自主层」行。

### 为什么先做 `hook` / `home`

两者的驱动面**已经在生产里存在**：`hook/fire` 与 `home/reload` 都是插件路由，
经 gateway 的 HTTP 边界（与 Tauri 前端同构的 `invoke`）直发即可，不需要 mock 任何
外部服务。判据也能取用户可见出口：

- `hook/fire`：钩子插件的输出（`HookOutput`）在回包里；「没有钩子插件时静默成默认值」
  这条**旁路观察者**语义（`fire_hook` 的文档明写「不否决主流程」）可以正面钉住；
- `home/reload`：切换 homedir 后 `vdfs/root` 的地址变了——这是「热重载真的生效了」
  的唯一用户可见读数。

> **2026-10-15 订正**：本节写「`home/reload` 经 gateway 直发即可驱动」是**错的**——
> gateway 的入站 router 是 worker composite，而 `home` 是它的**父**，`Composite::route`
> 不向上转发 ⇒ 实测 `home/get_homedir` 回 **400**。详见「处理过程」的落地记录。
> 本节关于 `hook/fire` 的那一条（旁路观察者语义可正面钉住）成立。

### 为什么 `telegram` 不能照抄

`plugin.rs:122` 是唯一构造上游地址的地方：

```rust
Some(format!("https://api.telegram.org/bot{}", config.bot_token))
```

`TelegramConfig` 的五个字段里没有地址位。所以「telegram 走可配 base_url 的 mock」
（T-076 原始出口里的写法）**在当前代码上做不到**——它预设了一个并不存在的配置面。
这正是本任务要先把前提摆出来的原因：**不能拿一个不存在的开关去写用例**，
那只会得到一个测自己 mock 想象行为的判据。

> **2026-10-15 订正**：本节说的是**打上游的那三条**（`send` / `get_updates` /
> `start_listener`）。`telegram` 的另三条（`status` / `set_chat_id` / `stop_listener`）
> 不引用 `api_url()` ⇒ **可以照抄**，已入格 t69。六条拆两半的划分见「处理过程」。

## 处理过程

- 2026-10-15 登记：T-076 面审计（2026-10-13 由用户提问触发）把该行开进 RE-005 之后，
  本轮逐插件核实驱动面时确认：`hook`/`home` 可直发，`telegram` 缺地址配置位。
- 2026-10-15 落地（第一批）：`e2e/cases/t69-channel-routes.mjs`。
  - **`hook` 三路由**：`list`（初始空）→ `register`（注册一条 `Http` 钩子指向本地靶子）
    → `list`（可见）→ `fire`（靶子收到 POST、正文是本次事件 JSON；回包 `context` 带上
    靶子的回答）。**为什么用 `Http` 而不是 `Command`**：`HookType::Command` 在 Windows 上走
    `cmd /C <command> <event_path>`，命令串含空格时被 Rust 转义成 `"echo X"`，`cmd` 对
    `/C "…"` 的引号解析把事件路径并进命令名 ⇒ 实测回包
    `Command error: 文件名、目录名或卷标语法不正确。 (os error 123)`。那是被测系统的
    真实行为，但拿它当主判据只会把用例变成平台行为记录。
  - **`telegram` 六路由拆两半**（本轮最重要的一处核实）：`status` · `set_chat_id` ·
    `stop_listener` 三条**不引用 `api_url()`**（只读 / 写内存配置、取消令牌）⇒ 无上游依赖、
    直发可驱动，已入格；`send` · `get_updates` · `start_listener` 三条都先取
    `self.api_url()`，而它把 `https://api.telegram.org/bot<token>` 写死
    （`plugin.rs:117-122`）⇒ 无靶子可打，转交 [T-114](114-telegram上游端点可配批.md "T-114-telegram上游端点可配批")。
  - **实测推翻原 exit 的一半**：原写「`home/reload` 经 gateway 直发即可驱动」，
    实测 `home/get_homedir` 回 **400**
    （`{"error":"插件未找到：Composite: 路径 'home/get_homedir' 无法识别或子插件未挂载"}`）。
    追到根：`gateway/plugin.rs::start_server` → `server::start(&cfg, parent)`，
    `parent = ctx.parent()` = **worker composite**；`composite.rs::route` 对认不出的名字
    直接 `NotFound`、**不向上转发**；而 `home` 是 composite 的**父** ⇒ `home/*` 与
    `work/*` 四条臂都不在入站可达面上。`hook/*` · `telegram/*` · `vdfs/*` 这些**子插件**
    路由可达，所以这个缺口此前一直被掩盖。`home` 四条臂的真实驱动面是 Tauri 的
    `callPlugin`（`tauri/src/services/home.ts`，进程内 `root.route`）⇒ 归前端形态
    [T-075](075-前端形态e2e补位.md "T-075-前端形态e2e补位")。
  - **顺带查出第二处不一致**：`gateway/config.rs::is_readonly_allowed` 的白名单含
    `home/get_homedir` · `work/get_workspace` 两条**走不到**的路由 ⇒ 死条目
    （只读模式放行后紧接着 404，而不是「拒绝调用」）。与 `gateway/server.rs` 模块头
    声称的「第三方拿到的能力与前端完全一致」合起来看，是同一个缺口的两面 ⇒ 归
    [T-115](115-入站边界可达面与白名单一致批.md "T-115-入站边界可达面与白名单一致批")。
  - **三处负向自检**（证明判据非恒真）：①注册事件与触发事件错配 ⇒ `list` 空即红；
    ②把「未注册事件」换成已注册 ⇒ 靶子计数增即红；③`set_chat_id` 不传 `chat_id` ⇒
    `status` 的 `has_chat_id` 不翻转即红。
  - 全量门禁绿，`BASELINE.e2eCases` 66 → 67。
