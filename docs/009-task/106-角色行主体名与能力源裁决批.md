## 内容

[T-082](082-角色行生产构造批.md "T-082-角色行生产构造批") 批②（S07 抢占判定者行）能落，是因为
[T-081](081-授权表缺行登记批.md "T-081-授权表缺行登记批") ① 先给了 `agent:reflex` 窄行——主体名、
能力集、pattern 三者都有**表源**。批③④⑤⑥ 的六行**一个都没有对应的 ROWS 行**：

| 阶 | 行（ST §3） | ROWS 有行？ |
|---|---|---|
| S02 | worker `{ reasoner, [ProduceArtifact], 30000 }` | 无 `agent:worker`（只在 `governance/mod.test.rs` 出现） |
| S03 | 规划者 `{ decider, [DefineWork], 60000 }` / 验证者 `{ decider, [AssertVerification], 5000 }` | 无 `agent:planner` / `agent:verifier` |
| S06 | 检索者 `{ translator, **[]**, 500 }` / 巩固者 `{ reasoner, [DefineWork], 86400000 }` | 无 `agent:recall` / `agent:consolidate` |
| S11 | 编译者 `{ decider, **[]**, 5000 }` | 无 `agent:compile` |

两条硬约束把「照抄一行进表」这条路堵死：

1. **空能力行在表里表达不出**：`PermissionMatrix::new`（`governance/mod.rs:233`）对
   `grants.is_empty()` 直接 `Err(PairingViolation::ReadOnly)`——S06 检索者、S11 编译者
   两行声明的 `capabilities: []` **不可能**成为 ROWS 行。这是表形状层面的排除，不是笔误；
2. **同主体多步的 pattern 冲突**：今天唯一的生产构造点是
   `chat_loop/state.rs::request_actor_spec`，它是 **per-principal** 的——`pattern` 由
   `Pattern::for_principal` 从表派生（`agent:main` ⇒ `Reasoner`）。而 S06/S11 的行是
   **同主体、不同步、不同 pattern**（检索步 `Translator`、编译步 `Decider`）。照抄进表
   会得到「同一主体两套规格」；硬编码 pattern/capabilities 则回到 T-082 要消灭的
   「两处各写一份」漂移形态。

于是六行卡在一个**更上游的粒度问题**：**ActorSpec 是「主体」的规格还是「步骤」的规格**？
不裁决就落，要么硬编码（漂移），要么造一个表里表达不出的行（假行）——两条都违反 T-082
自己的 exit 纪律。故独立成批，先行裁决。

批内顺序建议：先在 ST-001/ST-008 §3 划清粒度（纯文档裁决），再按裁决逐阶落行或落
「形态 = X」判词，最后补判据。
