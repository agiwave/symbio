## 内容

两件小颗粒的「账实不符」，都是今天实测时撞上的：

**① 每次开机一条 WARN。**

```
[composite WARN] 跳过插件目录（未找到 Provider）projection -> projection
```

`mount_all` 的规则是「扫 `<插件根>/*/`，有 `PLUGIN.yml` 且 `plugin_provider` 指向已注册工厂才构造」。
`.symbio/projection/PLUGIN.yml` 声明 `plugin_provider: projection`，而**全仓没有任何工厂叫 `projection`**
（`grep` 无一处引用；投影能力住在 `symbio_core/projection`，它不是插件）。于是这个目录是一具孤儿配置，
每次启动都喊一声。

危害不在吵，在**噪声里学真事**：本仓的 WARN 通道是留给「装配期真异常」的（同一条 `mount_all`
里，「没有 `PLUGIN.yml`」刻意只记 debug，理由写得很清楚——插件根下本来就有非插件目录）。
一条常态化的 WARN 会把这套分级磨平。

两种收法，选哪一种要先判明**这个目录是谁留下的**（旧版 `ensure_required` 名单？手工建的？）：
要么投影内省口确实该有一个插件工厂名 `projection`（那是装配面的缺口），要么它是历史残留
（那要让扫描把它识别成「不是插件」，并给一条迁移清掉存量目录）。判明之前先记着，不猜。

**② README 的 CLI 指路是错的。**

```bash
cd cli && node scripts/build-cli.mjs
../symbio/target/debug/symbio-cli.exe --homedir ~/.symbio -m "你好"
```

脚本在 `cli/scripts/`，产物落在**仓库根**的 `target/debug/`（工作区共享一份 target 根），
`../symbio/target/...` 这个路径在本仓的布局里不存在。今天照它找产物，直接撞上一次
「跑了个旧二进制、结论全错」的事故（旧 `target/release/symbio-cli.exe` 一直在被当成本轮构建物使用）。

## 处理过程

- ① 来源判明：`plugin_provider: projection` 不是「未注册」或「构造失败」，而是**全仓从未有过**这个
  工厂（git 历史无引用；投影能力住在 `symbio_core/projection`，它不是插件）。这类目录是 `.symbio/`
  数据目录跨构建存活的残渣——旧构建或手工留下的 `PLUGIN.yml` 指向一个编译期就不存在的工厂。
  收法选「机械识别成不是插件」：`mount_all` 把「配置合格、工厂不在本构建」与「没有 `PLUGIN.yml`」
  降为同一级别（debug），WARN 通道留给装配期真异常；它仍进 `PluginRegistry::entries`（未挂载、
  可停用可卸载），降级不影响管理面可见性。判据 = e2e `t80-orphan-plugin-residue`：干净系统目录
  启动零条 `[composite WARN]`；种下 `projection/PLUGIN.yml` 后仍为零，且默认级别下连目录名都
  不出现。负向自检：把降级临时改回 WARN 重跑，该用例变红并打印出旧消息「跳过插件目录（本构建
  没有 Provider projection）」——判据确实在看这条接线，而不是恰好有别的输出兜底。
- ② 漂移是仓级而非 README 一处：根 `README.md`、`cli/README.md`、`cli/docs/003-building.md`、
  `cli/docs/004-usage.md`、`e2e/README.md` 五处都指向旧位置（`../symbio/target/…`）。
  「CLI 产物在哪」的唯一来路收进 `scripts/cli-binary.mjs` 的 `cliArtifactRelPath`；
  `cli/scripts/build-cli.mjs` 成功后原样打印这一行，文档照抄它而不是各写一份。
  守卫是 `doc-symbol-audit` 新增的 **D-012**：现行文档里的 `target/<profile>/symbio-cli` 路径必须
  等于构建落点——带具名目录段（`symbio/target/…`）一律红；只带 `./` / `../` 的按该 md 的**命令
  执行目录**归一；任务登记册（`docs/009-task`）排除，那里的旧路径是记录本身。11 条回归测试双向
  钉住：真违规红、合法写法绿、历史行与登记册不误伤、讲构建却一处产物路径没写也红。
  `cli/scripts/repair-target-cache.mjs` 顺带改为向 `cargo metadata` 要 target 根，不再硬编码
  `symbio/target`——同一处知识不再有第二份。
- ③ 复核②的改动时撞上一条更宽的同类病：文档里写着**本机盘符路径**（仓库实际所在的
  `<盘符>:\Bing\symbio` 这类），而仓库会被克隆到任何目录，读者照抄必然落空或落到自己的
  同名目录上。处置分两步：
  · **清存量**：活跃文档里三处盘符示例（`docs/005-arch/013-vdfs.md` 与
    `symbio/src/plugins/vdfs/README.md` 的 `<盘符>:/tmp/a.txt`、
    `cli/docs/003-building.md` 的 cargo 指纹输出示例）改为占位写法；②改过的 homedir 示例
    （`cli/README.md`、`cli/docs/004-usage.md`）统一写 `~/.symbio`；
    `.github/workflows/002-SECRETS_SETUP.md`、`CONTRIBUTING.md` 与任务 113 / 134 / 139
    记录里的临时路径改为 `<仓库根>` 占位。
  · **立判据**：`doc-link-audit` 新增 **D-013**，判 Markdown 正文与 front-matter 里的
    盘符路径形态（单个字母 + 冒号 + `/` 或 `\`）；URL 协议段由前置字符边界挡掉（协议名
    末尾字母紧邻冒号，不构成盘符）；`docs/archive/` 整体豁免（历史快照），**登记条目
    照判**（盘符不是「当时的事实」，是换台机器就失效的写法）。7 条回归测试双向钉住：
    反斜杠红、正斜杠红、front-matter 红、登记条目红，占位写法绿、URL 绿、archive 绿。
