## 内容

「思考即正文」（`T-095`）这条机制的立足点是：某些模型把内容放在 `reasoning_content` 里
而正文通道为空，此时那段**就是**它要说的话，不提升就等于丢答案。机制没错，缺的是
**长度截断这一格**：模型在思考中途被 `max_tokens` 掐掉时，那段文字既不是答案、也不是
写完的思考，而系统照旧把它当答案交付。

实测（同一个 CLI，Provider 用默认 `max_tokens: 4096`，任务=产出质量报告）：

```
[model] 流正常结束 (耗时 348s, 4076 chunks / 1068553 bytes, 文本 0 字符, 推理 13045 字符, finish=Length)
stdout = 13067 字节 —— 整段草稿（「现在检查工具使用：vdfs_read 3次…让我写好后再检查一下字数。先确定每段的内容…」）
```

三重代价叠在一起：① 报告始终没写出来（模型还在「打算写」的阶段就被掐了）；
② stdout 被草稿灌满——而 stdout 是**要交给下游程序的**（`cli/src/main.rs` 顶部的输出约定），
非交互模式下这就是脏数据；③ 用户看不出这是「失败」还是「答案」，退出码还是 0。

对照实验：把同一 Provider 的 `max_tokens` 抬到 12288（本机另立一份
`.symbio/model/LMStudioR/provider.json`，不动用户那份），同一条任务就正常走完了
「读三处 → 写 `tmp/quality-report-cli.md` → 回读」——**说明缺的不是能力，是长度**。
所以本任务不是要关掉「思考即正文」，而是给它加一条判据：**思考通道被截断 ≠ 答案**。

同一条负载还量到一个相邻事实：这台本机模型每轮思考要 1~6 分钟、单次可达 12K 字符，
而轮中没有任何可见反馈（[T-136-轮中对话面节点不入实时面](136-轮中对话面节点不入实时面.md)）——「像卡死」的体验由这两条一起造出来。

## 处理过程

- **缺的那一格在类型上，不在措辞上**：`ModelFinishReason` 早就在 core 里归一化好了
  （协议层四条协议都填），但端口返回体 `LlmTurn` 没有这一格——运行器拿到的就是两段文本，
  任何「像不像答案」的启发式都判不了。所以先补**带得出**，再谈判据；`Other("unknown")`
  用在看不见原因的实现上，是为了不让「填了个 Stop」冒充「模型说完了」。
- **两条出口取兜底**：§exit 允许「标注这是未完成的思考」或走「本轮未产出答话」的既有形状。
  取后者——空答话 → 兜底格这一步就在同一个位置，而加标注要给载荷、重建、CLI 三处各开一个
  新字段，收束格的新种类还与 ADR-052「终止是事实的**状态**不是新种类」那条纪律同族冲突。
- **判据只关提升，不动正文**：`finish=length` 而正文非空时那半截正文照旧交付。截断正文该由
  自动续写接（v2 路径上没接上，另立 [T-144-长度截断的自动续写在v2执行路径不可达](144-长度截断的自动续写在v2执行路径不可达.md)），
  与「草稿别当答案」混在一次改动里就没法独立回退。
- **两条提升路一起判**：只改运行器会留下第二条——无工具的静默请求（摘要 / 措辞）在
  `provider_adapter.rs::generate_streaming` 里做着**同一条回退**，那里把半段草稿当成摘要正文
  存进事实源比当成答话打印更安静。同一条机制的第二个消费方不补，就等于把判据写成了局部的。
- **草稿不丢**：兜底格的载荷带的仍是桥上攒下的那份思考，`t77` 的第三条断言钉这一点。
  本条要的是「不当答案」，不是「当没发生过」——那 13K 字符是唯一能看出模型当时在干什么的线索。
- 一处**没有**顺手动：`§内容` 记的相邻事实（轮中无反馈 → 「像卡死」）归
  [T-136-轮中对话面节点不入实时面](136-轮中对话面节点不入实时面.md)，与长度无关；
  Provider 侧 `max_tokens: 4096` 对这台推理模型不够是**配置**事实，实测用的是本机并列的
  `LMStudioR`（12288），用户那份配置没动。
