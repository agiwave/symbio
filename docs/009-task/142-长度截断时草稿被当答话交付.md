## 内容

「思考即正文」（`T-095`）这条机制的立足点是：某些模型把内容放在 `reasoning_content` 里
而正文通道为空，此时那段**就是**它要说的话，不提升就等于丢答案。机制没错，缺的是
**长度截断这一格**：模型在思考中途被 `max_tokens` 掐掉时，那段文字既不是答案、也不是
写完的思考，而系统照旧把它当答案交付。

实测（同一个 CLI，Provider 用默认 `max_tokens: 4096`，任务=产出质量报告）：

```
[model] 流正常结束 (耗时 348s, 4076 chunks / 1068553 bytes, 文本 0 字符, 推理 13045 字符, finish=Length)
stdout = 13067 字节 —— 整段草稿（「现在检查工具使用：vdfs_read 3次…让我写好后再检查一下字数。先确定每段的内容…」）
```

三重代价叠在一起：① 报告始终没写出来（模型还在「打算写」的阶段就被掐了）；
② stdout 被草稿灌满——而 stdout 是**要交给下游程序的**（`cli/src/main.rs` 顶部的输出约定），
非交互模式下这就是脏数据；③ 用户看不出这是「失败」还是「答案」，退出码还是 0。

对照实验：把同一 Provider 的 `max_tokens` 抬到 12288（本机另立一份
`.symbio/model/LMStudioR/provider.json`，不动用户那份），同一条任务就正常走完了
「读三处 → 写 `tmp/quality-report-cli.md` → 回读」——**说明缺的不是能力，是长度**。
所以本任务不是要关掉「思考即正文」，而是给它加一条判据：**思考通道被截断 ≠ 答案**。

同一条负载还量到一个相邻事实：这台本机模型每轮思考要 1~6 分钟、单次可达 12K 字符，
而轮中没有任何可见反馈（[T-136-轮中对话面节点不入实时面](136-轮中对话面节点不入实时面.md)）——「像卡死」的体验由这两条一起造出来。
