## 内容

父设计：[PL-016 · 义务环](../004-plan/016-义务环.md "PL-016-义务环") §2.3 · §3.2 · §3.4

**为什么必须先有声明层，才能换形状。** 目标形状里每一行是**数据**：

```
行  dispatch-model   owes: request(port=model)   until: sent(port=model) | failed(port=model)
```

`owes` / `until` 是 `Pattern`，`Pattern` 匹配的是**字段**（`port=model`）。
而今天事实的载荷是 `serde_json::Value`——**没有字段清单**。于是：

- `Pattern` 里的 `port` 拼错了，运行期**静默不命中**（不是报错）。
- 装载期第 3 条检查（"字段都在声明里"）**无从查起**：没有声明，就没有"声明里有什么"。

**现状的两处空白**：

| 今天 | 缺什么 |
|---|---|
| `event/grid.rs` 有 `CELLS`：名字 → 格位 | 只有格位，没有**字段**。`port` 是信封字段，`key` 是载荷字段，两者都没有声明 |
| `projection/*.rs` 有 20+ 个手写投影，每个是 `fn(&[Event]) -> View<T>` | 没有**名字**、没有字段清单、没有成本声明。视图之间互不可见靠自觉，不靠类型 |

**补法**（五个注册口里的前两个）：

```rust
impl Builder {
    fn fact(&mut self, d: FactDecl);   // name / port / key / expand / fields
    fn view(&mut self, d: ViewDecl);   // name / ver / reads / cost / eval
    fn seal(self) -> Result<Arc<Frozen>, Vec<CheckError>>;
}
```

`ViewDecl.reads` 是 `&'static [(&'static str, &'static str)]`（事实名, 字段名）。
**注意：`Pattern` 还不存在**，所以本步能查的是"视图读了什么"；"模式引用了什么"
要等 T-222 的 `Pattern` 落地。T-221 的 §3.4 第 3 条检查因此只落视图一半，
模式一半在 T-222 补齐——这不是漏项，是声明层先于模式层。

`seal()` 的检查因此变得可执行：**`ViewDecl.reads` 的每个 `(事实,字段)` 都必须出现在
某个 `FactDecl.fields` 里**，否则装载期就红——不用等到运行期空转。

**本步刻意只做声明层，不接控制面。** 范围钉死：

- 首批声明 **8 个事实**：`request` / `sent` / `response` / `failed`（协议四名，
  各带 `port`、`id`；前三个还带 `attempt`，`failed` 关的是**逻辑 id**，所以没有
  `attempt`——失败不是「某一次尝试失败」，是这笔调用不再重试）、
  `chat.assistant.final`（收束格，带 `status` / `reason`，见
  [T-220](220-停机原因统一.md "T-220-停机原因统一")；**不新增 `turn.closed` 名字**）、
  `turn.stage`（阶段格，带 `stage` / `round`）、`user.message`（用户格）、
  `authz.denied`（带 `key`，见 [T-219](219-拒绝落事实.md "T-219-拒绝落事实")）。
  `retry` 在 T-223 落租约行时补声明，`session.config` 在 T-225 补。
- 首批声明 **2 个视图**：`in_flight`（在途 = `sent ∧ ¬(response|failed)`）、
  `turn_head`（轮头，即今天 `LoopState::TurnHead` 的投影版）。
  **视图点名决定了事实的下限**：`turn_head` 今天读 `user.message` 与 `turn.stage`，
  不声明它们，视图这一半的检查就没有对象——所以首批是 8 个而不是 6 个。
  `turn_head` 的 `classify_enabled` 要等 `session.config` 事实（T-225），
  本版（`ver: 1`）只声明能凭日志算出的 `turn` / `round` / `has_utterance` / `done`；
  T-225 加配置事实时把 `ver` 升到 2。
- `Registry` / `LoopState` / `decide` **一个字不动**。表化是 T-222 的事。
- **模块暂时 `cfg(test)`**：没有生产消费方时把它编进非测试构建，`dead_code` 会逐个
  点名，而 `#[allow(dead_code)]` 是只许降的棘轮。故与 `stage_events::done` 同一形态
  如实标 `cfg(test)`，不给死代码闸门开豁免；T-222 接线时删掉 `mod.rs` 里那一行即可。

**为什么视图的 `eval` 接 `&[Event]` + `now` 而不是 `&Store`**：签名即隔离。视图拿不到
写口，也"看不见别的视图"——PL-016 判据 3（视图互不可见）落在类型上，不落在纪律上。
`now` 是入参而不是视图自己读时钟：同一份日志重放两次必须得到同一视图（ADR-115 决策 1）。

**为什么 `ver` 是声明的**：视图口径一变，历史事实的投影结果就变。`ver` 让
"这一轮用的是哪版视图"可回放、可 diff，而不是靠代码版本猜。

**为什么 `cost` 是声明的**：`owed` 每轮对视图求值，成本必须有上界。
把它写进 `ViewDecl` 而不是让每个 `eval` 自己记账，是为了让"这张表一轮要花多少"
在装载期就能算出来。

**明确不做**：

- 不把 `projection/*.rs` 的 20+ 个模块一次性迁进来（那是逐个搬的活，且大部分与环无关）。
- 不动 `event/grid.rs` 的 `CELLS` 形状（`FactDecl` 与它并存：`CELLS` 管"落在哪一格"，
  `FactDecl` 管"有哪些字段"；两者合并要等协议名收敛 T-224）。
- 不引入运行期注册（`seal()` 之后没有可变注册口，这是类型保证，不是纪律）。

## 判据

| # | 判据 | 检查方式 |
|:-:|---|---|
| 1 | 视图引用未声明字段 ⇒ `seal()` 报错 | 反向用例：故意拼错一个字段名 |
| 2 | 两个 `FactDecl` 同名 ⇒ 报错 | 反向用例 |
| 3 | 事实名与视图名撞名 ⇒ 报错 | 反向用例（视图是合成事实，同一名字空间） |
| 4 | `seal()` 之后无注册口 | 类型上：`Frozen` 没有 `&mut self` 方法 |
| 5 | 首批 8 事实 + 2 视图能装载并冻结 | 用例 |
| 6 | 视图 `eval` 拿不到写口、也拿不到别的视图 | 类型上：签名只有 `&[Event]` + `now` |
| 7 | 控制面零改动 | `Registry` / `LoopState` / `decide` 无 diff；改动只落在新域目录、`mod.rs` 与 README 的域登记 |
| 8 | 扫描超过声明的 `cost` ⇒ 不求值 | 用例：`cost = 1` 的视图喂 2 条事件 ⇒ `None` |

## 处理过程

- 2026-10-21 立项。它是 PL-016 §5 的第 5 步，前置是 T-218（溯源边不悬空）——
  因为 `FactDecl` 的字段清单要包含溯源相关字段的声明口径。
- 2026-10-21 范围为什么这么小：本步的价值是**让"字段都在声明里"这条检查第一次可执行**，
  不在于把全项目的事实都声明一遍。声明少量事实就够验证机制成立；
  全量迁移是 T-222 之后逐批的活。
- 2026-10-22 施工订正一：首批从 6 个事实改成 8 个。`turn_head` 今天读
  `user.message` / `turn.stage`；不声明它们，被点名的视图无法装载，检查也没有对象。
  **视图点名决定事实下限**——这是初稿数错的那一处。
- 2026-10-22 施工订正二：`failed` 删掉 `attempt`。PL-016 §2.4 写的是
  `failed{port,id,why}`；失败关的是逻辑 `id`（所有尝试），带 `attempt` 会让
  「失败只关一次尝试」成为可表达的假状态。
- 2026-10-22 施工订正三：协议名暂住 `decl/` 私有常量，不升进 `event/mod.rs`。
  升上去而尚未登记 `CELLS` 时，四个常量在非测试构建里没有消费者（死代码）；
  T-224 把名字升进事件表与网格时一并搬走，避免临时造一处死代码。
- 2026-10-22 施工订正四：整模块暂标 `cfg(test)`。理由见内容节最后一条；
  T-222 把行表接上时删掉 `mod.rs` 的 `#[cfg(test)]`，不留下第二份声明。
- 2026-10-22 施工订正五：模块落成**域目录** `decl/`（`mod.rs` + `mod.test.rs`），
  不是单文件 `decl.rs`。`symbio_core` 下**每一个模块都是域目录**——「机制不是名字域」
  不构成例外：`decl` 有自己的对外面（5 个类型 + 1 个函数），按 §1 的四条标准就是域。
  目录形态带来两项登记义务，一并补齐：`core-naming-audit` N-004 要求 README §1.2
  前缀表有它一行（本域符号不进根公开面，行内如实标 `pub(crate)`），
  `test-layout-audit` 要求用 `<域>/mod.test.rs` 而非 `<域>/decl.test.rs`。
- 2026-10-22 施工订正六：同批把 `authz` 从单文件 `authz.rs` 收敛成域目录
  `authz/mod.rs`。它与 `decl` 是同一个形态问题（`symbio_core` 的一级模块一律分域），
  不是 T-221 的功能改动；代码零语义变化，只补 README 的域登记与测试宿主路径。
