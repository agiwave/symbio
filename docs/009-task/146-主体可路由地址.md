## 内容

决策依据：[ADR-069 主体可路由地址](../010-adr/069.md "ADR-069")
父设计：[PL-013 §4](../004-plan/013-前端机制化.md "PL-013-前端机制化")

**这一档只做"字符串层"**——`ChatMessage.principal` 字段今天已是 `Option<String>`，
本批改的是**值域的形状**：从 `kind:name` 前缀形态改成 `<namespace>/<name>` 可路由地址形态。
结构体升级（kind 与 title 进协议）留给 [T-147]，两件事不同批是为了让 T-146 能**独立回退**：
真出错时把常量值改回、`AGENT_NAMESPACES` 撤掉就完事，不破协议字段类型。

**id 是地址**——拿着它可以定位到那个主体、路由过去调用它。这与 VDFS 地址、route 常量、
`plugin/name` 是同族形状：第一段是归属（哪个插件/概念），后续段是归属内的名字。
kind 是**元数据**（一族），从协议侧的枚举字段读，不再编码到 id 字符串里；
`is_agent_id(id)` 用**命名空间登记表**判定——将 reflex 拆到独立 decider 插件时，登记表加一条
`"decider"` 即可，无需改判据。

写侧规则见 ADR-069 §决策 4。

## 处理过程

- 常量表：`PRINCIPAL_MAIN = "session/main"`，`PRINCIPAL_USER = "person/local"`，
  `PRINCIPAL_TOOL_VDFS_WRITE = "vdfs/write"` 等。工具行按 ADR-069 §决策 2 的表列。
- 判据：`AGENT_NAMESPACES: &[&str] = &["session"]`；`is_agent_id(id) = id.split('/').next() 
  ∈ AGENT_NAMESPACES`。`visible_to(actor, viewer)` 的第 3 条「非 agent 一律可见」的分支
  换成 `!is_agent_id(actor)`。
- 授权表：`ROWS` 第一列（principal key）跟着常量值改；工具行**新增**——`vdfs/write` / `web/fetch` /
  `local/content_search` 各带 `produce.artifact` 能力与 `Shared` 可见域；`system/compactor` 一行带
  `reduce.context` 与 `Shared`。
- 单测：把 `all_principals_match_prefix_wordlist`（前缀词表）换成 `all_principals_are_routable_ids`
  （每个常量含 `/`，且第一段在 namespace 白名单里）；新增 `agent_namespaces_are_a_registry_not_a_prefix`
  钉住「加一个 namespace 就多一族 agent，不动判据」。
