## 内容

父设计：13 报告建议 4 · [ADR-100](../010-adr/100.md "ADR-100") · [T-177](177-授权与声明面fail-closed批.md "T-177-授权与声明面fail-closed批")

**问题**：`bind_inheriting` 当前是**并集语义**（子会话继承父的全部能力，再叠加自己的显式声明）。
这让「委派不放大权威」这条 v2 不变量在**运行期绑定面**上不成立——父会话窄、子会话宽时，
子会话拿到的是两者的并集，而 ADR-100 第 5 条边界（委派两侧都在册）只在「登记」这一层成立，
在「能力集合」这一层没有约束。

**改成交集之后，「委派两侧都在册」才有意义**：两侧都在册说的是「谁在册」，
交集说的是「子会话能做什么」——前者是登记事实，后者是权威边界。缺了后者，前者只是账本。

**为什么依赖 T-177**：T-177 正在把授权默认翻成 fail-closed（未登记 = 拒），本批改的是
「已登记的两个主体之间能力怎么继承」。在 fail-closed 还没落地时改继承语义，会同时动两个方向
的默认值——那是最难判读的组合。等 T-177 闭环后，本批的改动面只剩「交集还是并集」这一件事。

**一处必须同步的注释**：原实现处有一段注释把并集说成「继承」的应有之义。改语义不改注释，
下一个读代码的人会以为并集是有意为之——注释与实现的对账是本批的出口条件之一，
不是可选的文档工作。

## 处理过程

- 2026-10-20 立批。来源：13 报告建议 4（该报告标为「高价值」，并指出它是
  「ADR-100 第 5 条边界才有意义」的前提）。
- 2026-10-20 与 [T-182](182-创建即登记迁移步.md "T-182-创建即登记迁移步") 的关系：T-182 收窄
  的是「登记的生命周期」（进程级 → 会话级），本批收窄的是「继承的集合」（并集 → 交集）。
  两者同属授权绑定面，但一个管时间、一个管范围，不合并。
- 2026-10-20 一条风险提示：交集语义会**让一些现有子会话少掉能力**——这是预期的（那正是
  「不放大权威」），但要在 e2e 里逐条确认少掉的是「本该没有的」，不是「本该有的」。
- 2026-10-20 落地：`bind_inheriting` 改为「父行 ∩ 子主体部署行」，新增 `bind_root`
  承接根会话（已部署根原样用自己的行、未部署根继承会话面缺省）——根没有父行，
  不能拿会话面去夹 verifier / arbiter 的 `assert.verification`（C15：主智能体不自持）。
  `EffectiveMatrix` 的合流从「部署行 ∪ 绑定行」改为「绑定行替换部署行」，空交集
  登记为空行（不回退部署行）；`insert_binding` 不再跳过空行。
- 2026-10-20 用例：`a_delegated_child_gets_the_intersection_of_parent_and_declaration`
  （父窄子宽 ⇒ 交集；子未部署 ⇒ 父行）、`an_empty_intersection_registers_a_denying_row`
  （空交集 = 拒绝，不退回部署行）、`a_deployed_root_keeps_its_own_row`（根不是委派）。
  自造小表验证判据，不污染同一进程里的共享绑定面。
- 2026-10-20 收口：提交 `7e55afbf`。全量门禁 124/124、e2e 77/77；lib 1836
  passed / 0 failed / 1 ignored（新增 3 条判据，基线随之上调）。e2e 逐例确认
  子会话少掉的能力都是父行本就不持有的，没有「本该有」的能力被夹掉。
