## 内容

**来源**：2026-10-20 的一轮只读机制审计——15 个机制逐个深审，产出 1 份总报告 + 14 份机制报告。
总报告的整体评级 **B+**，一句话结论是「**声明多于兑现**」：架构面（不可妥协的那一层）落地度高，
兑现面（把设计变成被强制的行为）有系统性缺口。

**本文是转化台账的 owner**。审计稿住在 `tmp/`（`.gitignore` 的临时区），不进版本库；
「每条建议归谁」是**要长期可查的事实**，所以它记在这里，不留在临时区。
审计稿里的诊断、证据、成本收益不复述——要读论证回原报告。

**转化纪律（四条，先于任何一条映射）**：

| # | 纪律 | 判据 |
|---|---|---|
| **1** | **架构性 / 机制性优先** | 影响面按「改一处外溢几处」排序，不按「改起来容易」排序。now 档三条全部是机制面（强制等级、停用语义、虚闸），没有一条是「顺手能清的债」 |
| **2** | **机制化优先于特殊性** | 同一问题在两份以上报告出现时，落点是**一个**收敛动作（见 §4），不是每个报告各立一条补丁 |
| **3** | **零新增机制键 / 零新增 trait** | 阶段数据化 = `actor.pattern` / `actor.budget_ms` 的新取值；强制等级清单 = 治理外化；幂等 = `store` 幂等语义在入站侧的应用。凡需要新增 `pub trait` 的（仅 02-3 一处），先走 ADR 论证 |
| **4** | **不为拆分而拆分** | 巨型函数按「阶段」拆（[T-179](179-三巨型函数阶段拆分批.md "T-179-三巨型函数阶段拆分批") 已立），不按「函数变短」拆；拆分批次与语义批次分开提交 |

**为什么要有这个父任务**：32 条子任务来自 14 份独立报告，若不收敛成一组，就会出现
「同一现象被三份报告各立一条补丁」——这正是本仓纪律「一个事实一个 owner」在任务层的应用。
父任务的出口不是「所有事都做完」，而是「每条建议都有归属，且没有两条在说同一件事」。

## 3. 优先级理由

**now（机制面，影响面最大且已在生产中留下可见缺口）**：

- **T-184 强制等级清单**——它是 9 个 B 的**共同根因**的唯一收敛动作。不做，后面每条建议都只是
  「再写一遍规则」；做了，后续新增机制才有一条「没有执行方就红」的判据。
- **T-185 停用收口**——唯一「已登记且已过期」的债（ADR-075 点名至今）；停用后后台仍在跑
  是**可观测的可靠性缺陷**，不是风格问题。
- **T-186 虚闸清偿**——两条「看起来有闸、实际没有」的判据（熔断不可达、local 默认全放开）
  直接落在安全面上，且成本低。

**next（机制面收敛 + 单源化，需一次裁决或一次较大施工）**：排序依据是
**改一处外溢几处** > 成本。[T-187](187-投影签名兑现批.md "T-187-投影签名兑现批")（投影签名，
v2 硬要求，外溢 19 个投影）已闭环；[T-189](189-轮执行阶段数据化批.md "T-189-轮执行阶段数据化批")
（阶段数据化，外溢 M4 / M5 / M8）外溢最大，但等 [T-180](180-驱动器收敛批.md "T-180-驱动器收敛批")
的裁决；[T-192](192-root装配为composite批.md "T-192-root装配为composite批")（根装配）因目标形状
没有方案裁决转 `wont`（§5-8）。此后按外溢面递减：[T-190](190-工具调用并行化批.md "T-190-工具调用并行化批")
（工具并行，改的是整个工具批处理的执行侧）、[T-188](188-不变量写侧阻断批.md "T-188-不变量写侧阻断批")
（不变量从记录改阻断）；[T-193](193-Agent权限声明执行方批.md "T-193-Agent权限声明执行方批") 与
[T-195](195-委派权威交集批.md "T-195-委派权威交集批") 落在安全边界（后者已闭环）；其余是单源化与观测面补齐。

**later（可导航性 / 协议面 / 纯文档）**：不是「不重要」，而是 ① 需要先有前置
（T-212 的大文件拆分要等 T-189，避免两次搬同一批代码）；② 需要先走一次架构讨论
（T-208 的 ADR-070 边界、T-215 的 trait 变宽、T-207 的值注入边界）；③ 或纯文档对账（T-214）。
