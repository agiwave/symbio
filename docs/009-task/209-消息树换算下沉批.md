## 内容

父设计：总报告 B4 · 07 报告建议 3

**问题**：275 行的消息树换算住在模型插件里，且**正确性靠注释里的经验维持**。
两处消费方（主路径与另一条消费路径）各自理解同一份换算，一旦分叉无人会红。

**两件事，一个目的**：

1. **拆模块**：消息形状换算 / 树形路径 / 跨轮降级三段——不是为了行数，而是为了让
   「哪一段错了谁会红」有答案；
2. **沉 core**：换算是不含 IO 的纯函数，两个以上消费方满足 ADR-023 的下沉判据。

**「事故知识从注释升级为绿」是本批真正的判据**：这段代码的历史事故（树形路径拼错、
降级后恢复轮丢失）都记在注释里，注释不会红。把 t27 / t38 的判据各配一条**具名测试**，
事故知识才变成「改错了就红」。

**风险如实写**：换算分支多（树形 / 降级 / 恢复轮），搬家时须**逐分支对照行为**。
这也是本批排 later 的原因之一——它不产生新能力，只降低下一次改换算的风险；
在机制面收敛（now / next）之前做，会与它们争同一批 review 注意力。

**不新增机制**：纯函数下沉不改契约形状，机制键 0、trait 0。

## 处理过程

- 2026-10-20 立批。来源：总报告 B4 + 07 报告建议 3。

  三步分开提交，任一步出错都能单独定位；合并成一步会让「行为变了」与「位置变了」混在一起。
