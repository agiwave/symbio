## 内容

父设计：[PL-017 · 端口细粒度化](../004-plan/017-端口细粒度化.md "PL-017-端口细粒度化")
§3.3；决策：[ADR-116](../010-adr/116.md "ADR-116")。

PL-017 §3.3 的目标形状里，`dispatch-tools` 的 `owes` 是一个模型响应，而需要逐笔
开债的是响应里的 `calls` 数组：

```
dispatch-tools   owes: response(port=model) ∧ response.has_tool_calls
                 expand: (calls, id)
```

T-227 当时的做法是**不改求解器**、派发时对每笔调用各落一条 `request` / `sent`；
T-228 把「同批能否并发」挪到了 `PortDecl.concurrent`。两者合起来仍然缺一件：
「一个实例 → 一个集合的债」这层投影不在求解器里。

本任务补这层投影，且**只改求解器**，不动生产行：

- `Decl` 增加 `expand: Option<(&str, &str)>`，语义 `(list_field, element_key_field)`；
- 只有 `owes` 走展开路径（`keys_of_expanded`），`until` / `unless` 照旧；
- 展开后键绑定对元素求值；`element_key_field` 必须在 `owes.key` 里；
- 事实源的 `list_field` 必须写进那条事实的 `FactDecl.expand`，否则装载期判红。

生产行（把 `dispatch-tools.owes` 从 `authz.granted` 换成 `response(port=model)`）
**不在本任务**：它要求恢复路径先成为 `await-tools` 的唤醒事实（PL-017 步 4→5），
否则 `tool-resume-*` 这类没有模型响应前件的恢复调用会失去债。本任务只把机制备好，
用求解器用例（而不是一条尚不存在的生产行）给能力背书。

## 判据

| # | 判据 | 检查方式 |
|:-:|---|---|
| 1 | `Decl.expand` 存在，语义是「逐元素开债」 | 编译 + 源码 |
| 2 | 展开只作用在 `owes`，`until` / `unless` 不展开 | `decl::ring` 单测 |
| 3 | 一个实例的 N 个元素 = N 笔债，键互不相同 | `expand_opens_one_debt_per_element` |
| 4 | 出口按键逐元素还，只关对应那一笔 | `expand_until_closes_elements_one_by_one` |
| 5 | 列表缺失 / 空 / 非数组 = 零笔债，不是空键债 | `expand_without_the_list_opens_no_debt` |
| 6 | 元素键不在 `owes.key`、事实未声明列表 = 装载期 gap | `expand_gaps_are_load_time_errors` |
| 7 | 自洽的展开行没有 gap（正例） | `a_complete_expand_row_has_no_gaps` |
| 8 | 求解器字节变化挂在一条决策上 | `port-surface-audit` PTS-003 / PTS-004（ADR-116） |
| 9 | 全量门禁与 e2e 绿 | `node scripts/gate.mjs` / `node e2e/run-tests.mjs` |

## 处理过程

- 求解器的改动是机制演进，不是端口渗进引擎：`owed` 的输入闭包（事实 / 视图 / `now`）
  不变，判据 1 防的是端口字段进求解器（PTS-002 仍绿）。
- `eq` 拦外层实例、键取自元素，是这次唯一一处语义细分：外层没有元素身份字段，
  展开后键如果再读外层就会开出一堆同键债。
- 基线更新与 ADR-116 同批落地；PTS-004 由「基线挂得住决策」这条判据兜底。
- 2026-10-22 收口：提交 d73426cb；全量门禁 130/130、e2e 78/78、clippy / fmt 绿。
  生产接入（`dispatch-tools.owes` 迁到 `response(port=model)`）留给 PL-017 步 4→5，
  本任务只把求解器能力备好，不假装生产行已经用上它。
