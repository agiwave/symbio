## 内容

父批次：[T-230 内环收口批](230-内环收口批.md "T-230-内环收口批") ·
机制：[ADR-116](../010-adr/116.md "ADR-116") · 前置：[T-231](231-恢复调用进债环.md "T-231-恢复调用进债环")。

T-227 步 3 的 `dispatch-tools` 用**蕴含**代替合取：

```
dispatch-tools   owes: authz.granted(port=tool)     ← granted ⇒ request 在数据上成立
```

这是因为求解器的 `Decl.owes` 是**一个** `Pattern`，写不出
`response(port=model) ∧ response.has_tool_calls`。T-229 给了求解器集合展开，
但它展开的是「一个实例的列表」——前件仍需是**单源**：`response(port=model)`。

本任务把派发行迁到目标形状：

```
dispatch-tools   owes: response(port=model)
                 expand: (calls, id)                 ← N 个调用 = N 笔子债
                 until: sent(port=tool) | failed(port=tool)
```

- `expand` 只作用在 `owes`；`until` / `unless` 按键命中，不展开。
- 键取自元素 `id`（工具调用 id），与 `sent(port=tool, id)` 同键。
- `response.has_tool_calls` 是视图字段，不是新事实名（PL-017 §3.1）。
- `authorize-tool`（prio 0）仍先于 `dispatch-tools`（prio 67）。

**边界**：本任务只迁派发行的前件与展开，**不改** `turn_exec::drive_steps`
的调度（那是 T-233），也不重写批次执行实现（PL-017 §7）。

## 处理过程
