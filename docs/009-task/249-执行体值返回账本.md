## 内容

父任务：[T-236-义务环符合性收口批](236-义务环符合性收口批.md)。前置：
[T-241-ActorDecl执行体注册表](241-ActorDecl执行体注册表.md) 按
[ADR-119](../010-adr/119.md) 把 `ActorDecl` 收成「声明面进机制层、动作面留部署层」——
声明面已就位，本任务收**动作面与账本**。

现网 `run_execute` 返回 `Result<Option<TurnOutcome>, AppendError>`，事实由执行体经
`TurnSession` 自己落格；`ActorDecl.writes` 只在装载期用——`decl/mod.rs:244` 自己写着
「『实际写入 ⊆ `writes`』那一半要有值返回账本才能对账，归 T-249」。

**账本怎么取，本任务登记时按 PL-016 §2.3 的字面签名（执行体交回 `Vec<Fact>`）写成了判据，
2026-10-23 施工前对账把它否了**：写不经过账本（§2.3 明文「单写者是 store，不是引擎函数」，
[ADR-118](../010-adr/118.md) 订正 2 同义），所以交回的 `Vec` 是执行体对「我写了什么」的
**陈述**，而判据问的是**实际写入**——漏报一条就对账不上一条，而漏报恰是这条判据要拦的事。
裁决见 [ADR-123](../010-adr/123.md)：账本 = 引擎在动作前后各读一次日志取尾段，
`run` 只交回 `Result<(), ActorError>`。

## 判据

逐条附实测位置；**已兑现的两条不重复实现**，只把「人工核对」升级成门禁。

1. `ActorError` 在**动作面所在的部署层**存在且不是 `String`（`ADR-123` 决策 3 的改判注：
   它跟着 `run` 住 `plugins/loop`，抬进 core 就是 C-003 要往下沉的单消费方导出）。
   失败种类从此只能靠加变体扩展，每加一个都要回答「引擎为它落哪条事实」——现码动作面
   只会因 `AppendError` 失败，故它今天是一元枚举，这是形状约束不是凑数。
   `run` 的返回逐字取 `Result<(), ActorError>`（`Option<TurnOutcome>` 通道退役、收束判断
   读账本、产出从草稿取）**随批二落地**：本批只把错误通道从 `AppendError` 换成
   `ActorError`——两个通道分两批改会造出「既不交回 outcome、又没有地方可读收束」的空档
   （`ADR-123` 决策 3 的改判注、决策 1 的签名同理待批二）。
2. 账本由派发器读：动作前取 `store.head()`、动作后取 `store.range(head)`；尾段里的
   **领域格名**逐条 ⊆ `ActorDecl::writes`（协议五格豁免——它们本来就不许出现在 `writes`
   里，`decl/mod.rs:400` 的 `ENGINE_ONLY_CELLS` 装载期已拦），越界 ⇒ 引擎落
   `exhausted{why:"undeclared-write"}` 停机格并出声（`ADR-123` 决策 2 的改判注：内环那笔
   债的键是 `turn=N`，没有 `(port, id)` 可填协议 `failed`，而收束判据只认停机格）。
   有夹具：**删掉对账就红**。
3. **已兑现（2026-10-23 实测）**：`Err` ⇒ 引擎写 `failed`。位置 `port.rs:248`
   （`dispatch_with` 的 `Err` 分支调 `failed(store, call, …)`）——整轮动作由
   `chat_loop.rs:590` 的 `port::dispatch` 派发，模型 / 工具往返各由 `stream.rs` /
   `tool_dispatch.rs` 的同一条派发包住，所以环形两行的失败**已经**在协议面留痕。
   `execute-turn` / `close-turn` 两行的 `until` 是 `turn_closed` 视图与
   `chat.assistant.final`（领域格），再补一条协议 `failed` 不收任何账，只是重复记账。
4. 判据 14 的夹具：返回**空账本**的动作 ⇒ 派发器落 `exhausted{no_progress}`，
   这条用例必须「不接线就红」。可达性来自 ADR-123 决策 4：执行体绑定表成为
   `drive_steps` 的入参，测试在同名 `by` 上注册一个空动作。现网 `no_progress` 的三个
   落点（`turn_exec.rs:890 / 926 / 993`）**零用例**——本条同时销
   [T-245-判据硬化批](245-判据硬化批.md) 的口径 ④。
5. **门禁已落地（本批）**：协议四格写方收口到引擎——`EVENT_SENT` / `EVENT_RESPONSE` /
   `EVENT_FAILED` / `EVENT_RETRY` 的写点只在 `plugins/loop/port.rs`，其余命中全是读
   （`tool_dispatch.rs:215,542`、`turn_runner/facts.rs:256`）。从人工 evidence 升级为
   **PTS-005**：判「协议四格的写点文件名单长度 == 1」（钉唯一而不是钉路径；名单为 0
   也判红）。`before` 那一支按变量名算写点，否则 `sent` 落在判据的盲区和模式里。
