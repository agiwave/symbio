## 内容

父设计：13 报告建议 3 · 04 报告建议 1 / 2 / 3 · [PL-015](../004-plan/015-可扩充性与插件切分.md "PL-015-可扩充性与插件切分")

**问题有两层**：

- **同构复制**：四道拒止闸各写一遍「拒因 → 结果节点 → 父节点收敛 → 记账 → continue」，
  不变量 1/2 因此在五处各有一份实现；
- **散落**：七道闸分散在函数的不同位置，「现在一共有几道闸、各自什么失败语义」读代码才知道。

**为什么这是机制性收益**：闸门表落地后，**新增一道闸 = 加一行 + 一个判据结构**——
闸从「散落七处」变成「一处可审计」。这正是本仓「约定 → 机制」的方向：
不是把代码写短，而是让「有几道闸」成为一个可读的事实。

**一条不能抹平的差异**（原报告特别点名）：四道闸的**出口判据不对称**——有的拒止零事件、
有的入格、有的走可审计拒绝。归一骨架时必须**保留差异**，把它们变成闸门表的一列
（失败语义），而不是统一成一种。抹平差异会让某类拒止失去它的审计痕迹。

**为什么依赖 T-179**：`tool_executor.rs` 是三个巨型函数之一（710 行函数），
本批要在批首读判据处建唯一执行点，等于重排该函数的结构。先按阶段拆开（T-179），
再在拆好的段里建表，改动面才可控；反过来做等于在一段未拆的代码里同时改结构与语义。

**不新增机制**：闸门表是「已有判据的结构化登记」，机制键 0、trait 0、新插件 0。

- 2026-10-20 落地：`dispatch::gates` 成为三道具名同步闸的唯一登记处——[`GATES`] 一行 =
  闸名 + 纯判据 + 该闸可能产出的失败语义；`first_refusal` 是判据的唯一执行点，

  不抹平。PreToolUse 钩子仍异步、不进表，但共用 `refuse` 与 `Refusal::blocked`。
- 2026-10-20 报告说「四道拒止闸」，表里只有三行：第四处是**重复调用台账**，它只回灌
  「绕圈」提示、不改执行结果，不是拒止（没有结果失败语义）。四种**出口**仍齐：
  `Refuse` 零事件、`Break` 入格、淘汰可审计、任务表可审计但不记承诺。
- 2026-10-20 三通道按报告给出的**另一个变体**落地：生产上没有「同一次遍历挂三键」的
  装配点——工具 / 选项 / 可配置是三趟独立遍历，各自要一个新实例（状态不跨请求）。
  因此收的是**共享构造点** `providers::collectors::new_registry()`（三个装配点同源），
  另加一条「同一实例挂三键 ⇒ 同一张表」的用例钉住将来若做单 pass 同挂时的不变量。
  **不**提供三键同挂 helper：工具遍历里插件会顺带声明可配置条目，其行名（插件目录名，
  如 `local`）与同次广播的挂载行同名，同一张表会跨族互相覆盖。
- 2026-10-20 `extract_result` 的生产方侧约定补在三个实际生产者上：`ask_user`（`content`）、
  `content_search`（`output`）、`vdfs_read`（`content`，含行号 / 分页回显）；`shell` 的
  `output` 断言原已存在。`todo_write` 刻意维持 `success=true` 整包 JSON（走第 3 条判据），
  不改形状去迎合第 1/2 条——结果文本本就没有强类型契约。
