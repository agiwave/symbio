## 内容

父设计：[PL-016 · 义务环](../004-plan/016-义务环.md "PL-016-义务环") §4.1

**这一条不是"加字段"——字段早就在。** 核对后的实况：

| 以为 | 实际 |
|---|---|
| 信封没有溯源边，要加 `caused_by` | `Event.produced_by: Option<u64>` 早已存在（`symbio_core/event/mod.rs`），20+ 构造点在填 |
| I2 落不了地 | `invariants::provenance_violation` 已在查「断言类 / 记忆类 / 收束类必须非空」 |

**真正的缺口只有一个**：`provenance_violation` 只问"有没有"，不问"指向谁"。
于是 `produced_by: Some(999)`——指向一条不存在的事件、或指向一条**更晚**的事件——
照样全绿。这类错**不报错**：日志能读、投影能算、回放不崩，只有"这条事实是被谁产生的"
这个问题的答案悄悄错了。

**为什么它排在形状替换之前**：义务环的 `owed` 要判"这笔债还清了没有"，判据是
"`until` 命中"。`until` 命中的事实如果溯源悬空，"这笔债是谁还的"就答不出来——
债的账本错了，而账本错了不会让任何东西变红。

**怎么判**（三件事，按代价排）：

1. **严格更小**：`produced_by < seq`。免费——`produced_by` 只能取自一条**已入库**事件的
   `seq`，而 `seq` 严格单调。但它必须写成断言：今天靠"构造点都很小心"保证，
   明天一个新构造点就破了。
2. **确实存在**：指向的 `seq` 在同一切片内。需要按 `seq` 建索引，一次线性扫描。
3. **切片边界**：真实日志回放是**切片**（`fixtures/real-session.tsv`），
   切片第一条的 `produced_by` 合法地指向切片外——直接判会**假红**。
   处理方式照 [`unresolved_turns`](../004-plan/001-核心架构.md "PL-001-核心架构") 的 `allow_trailing_open` 成例：
   加一个显式宽限形参，**宽限写在签名上，不写在判据里**。

**明确不做**：

- 不改名成 `caused_by`（20+ 构造点 + 一条不变量 + 两处审计都在用 `produced_by`，
  改名是零语义收益的机械 diff）。
- 不动 `needs_provenance` 的「按事件种类枚举」（那是 I2 的判据范围问题，见 PL-016 §7.3）。
- 不把溯源边做成独立表或图结构（`seq` 单调已经免费给出 DAG，PL-001 §13.3）。

- 2026-10-21 施工中撞到的三件事，都值得记：
  ① **测试夹具里普遍存在"首条事件指向自己"**——`invariants/mod.test.rs` 的 `pending()`
  默认 `.with_produced_by(0)`，于是 seq 0 的事件指向自己；`actors/mod.test.rs` 两处
  夹具同理（日志从 0 起，`source_seq = 0` 就是自指）。判据一上线，三处全红。
  **修法不是放宽判据，而是修夹具**：根事件本来就没有上游（`pending()` 改为不带边），
  需要边的用例显式写 `.with_produced_by(..)`；两处 actors 夹具改成**先落一条根
  `user.message`**，让 `source_seq = 0` 真正指向一条更早的事实。
  ② **`check_all` 从 8 条变 9 条**，`doc-count-audit` 的 DC-001 立刻抓出两处手填数字
  （`session/stats.rs` 的文档注释、T-170 的"明确不做"理由）。前者按实订正为九条并列出
  新增的那一条，后者**删掉手填数字改成回指代码**（那是 T-214 立下的口径：一个数字有
  两个 owner 时它必然先漂再红）。
  ③ **`caused_by` 口径在 7 处文档里漂着**（PL-001 两处、PL-004、PL-007、PL-008、
  T-122、两处源码注释）。代码里从来叫 `produced_by`——这不是"后来改名"，是文档一直写错。
  同批清零；`docs/archive/` 不碰（归档面冻结）。
- 2026-10-21 **判据抓出一处生产缺陷**，这是本任务最有价值的产出，不是夹具问题：
  `inbox::append_preemption` 拿 `store.head()`（"下一条的号"）当挂起事件的 `produced_by`。
  `head` 还不是事实，落格后那条边指向**自己**（`produced_by == seq`）。挂起路径因此
  一直在写自指边，而 `produced_by_coverage` 只查非空 ⇒ 全绿。
  修法：`head().value().saturating_sub(1)`（最后一条已落事实），幂等键不受影响——
  两次挂起之间必有一条恢复事实落格。`control.rs` 的 `held_event` 文档同步写清
  "不能取 `head`"，并把调用方的减法点明（否则下一个人会照抄 `head`）。
  同一处纪律在 `transcript/autonomous.rs` 早有先例（`head == 0` 时拒绝触发，
  理由正是"无可指的溯源锚"）——两条路径对同一个概念给了两种答案，现在一致了。
- 2026-10-21 **宽限形参改名**：初版叫 `allow_head`，实现却是**头尾对称**宽限
  （只宽头部等于假设"切片总是从头切"，而读侧窗口两头都会切）。名字说一半、
  判据做两半，正是下一个读者会踩的地方 ⇒ 改 `allow_slice_edges`。
  `verify/invariants.rs` 的对应注释同步。
