## 内容

父设计：总报告 B3 · 05 报告建议 2 · [PL-014](../004-plan/014-单环一表收敛.md "PL-014-单环一表收敛") §5 步骤 6 前置 P5（运行态归源）

**现状**：P5「运行态归源」只做了一半——`outcome` / `error` 已投影化
（[T-167](167-会话插件切分.md "T-167-会话插件切分") 的 6b-②′ 落地，17 条判别表用例钉住），
但 `is_working` 与 `warning` 仍是**宿主字段散落**：

- `is_working` 的置位 / 复位散在多条收尾路径（`begin_turn` / `finish_turn` / `reset_working` /
  `clear_working_and_abort_signal` / 中止兜底 / 收束）；
- 因为复位点分散，收件箱（`transcript/inbox.rs:69`）只好用 `BUSY_POLL = 50ms` 轮询兜底；
- **轮询是症状，病因是状态机分散**——只删轮询不归源，等于把「慢」换成「丢」。

**做法**：把 `is_working` / `warning` 收成会话宿主的一个**显式小状态机**（单点置位 / 复位，
每个转移有名字），然后删掉 `BUSY_POLL`。收尾路径的逐一核对**本身就是一次审计**——
它们之所以分散，是因为历史上每条收尾路径各自补了一笔，没有人列全过。

**一处必须保持的边界**：`working` 是**命名残余**（ADR-083 残余条款），不参与事实投影——
理由是「崩溃不得显示永久处理中」，且忙位必须在 `spawn` 前同步可见。本批收的是「置位复位分散」，
**不是**把它搬进事实轨；把这条边界写反，会把一个已知取舍变成一次行为变更。

**不新增机制**：状态机住在会话模块内部（可妥协层），机制键 0、trait 0。

## 处理过程

- 2026-10-20 立批。来源：总报告 B3 + 05 报告建议 2（该报告把它标为「P5 的收尾，成本低」）。
- 2026-10-20 一处实测：`BUSY_POLL` 在 `transcript/inbox.rs:69` 定义、`:247` 使用；
  Rust 侧只有这一处 50ms 轮询，前端与 CLI 无同类兜底——本批的删除面因此是收敛的。
- 2026-10-20 与 [T-189](189-轮执行阶段数据化批.md "T-189-轮执行阶段数据化批") 的关系：T-189 改
  控制流形状，本批改运行态归属，两者都动 loop/session 边界但不同面；若同期开工，本批先行
  （状态机是 T-189 行执行器读「忙不忙」的前提）。
- 2026-10-21 **状态机落点**：`session/working.rs`。两态（`Idle` / `Working`）+ 三事件
  （`Begin` / `EarlyExit` / `Finish`），唯一迁移函数 `apply` 返回「本次是否由忙变闲」。
  两态就够：`EarlyExit` 与 `Finish` 的区别在**谁**在收尾（提前让位 / 收完写结局），
  不在状态；多造一个「收尾中」态会让所有读方都得回答「这算不算忙」，而正确答案恒为
  「不算」——那只是布尔能表达的事实。
- 2026-10-21 **闭集与唤醒同点**：`apply` 的返回值直接决定 `turn_done.notify_one()`。
  于是新增一条收尾路径时，只要它要改变工作态就必须经 `apply`——**绕过去状态根本不会
  变**，而不是「变了但收件箱没人被叫醒」。后者正是 50ms 轮询一直在遮的失效。
- 2026-10-21 `turn_done` 用 `notify_one` 而不是 `notify_waiters`：前者会给**尚未挂起**的
  等待者留一个许可，而「收轮恰好发生在消费者重新挂起之前」正是轮询当初要兜的窗口。
  `inbox_wake` 同理由 `notify_waiters` 改为 `notify_one`（消费者每实例一个）。
- 2026-10-21 **`BUSY_POLL` 删除**，替代是「事件 vs 时间」二分：排队且会话在跑 ⇒ 等
  `turn_done`；空闲却有队（启动失败被回填）或队空却挂着 `Resume`（落格失败）⇒ **没有
  事件会来**，等一次 `RETRY_BACKOFF = 1s`。为什么是 1s：这两种都是「立刻再做一次也不会
  更好」的错误，50ms 只是把一次有界重试放大成忙等。
- 2026-10-21 **进入 / 退出路径审计（全部，六条）**：

  | 方向 | 路径 | 调用点 | 迁移 |
  |---|---|---|---|
  | 进入 | 开轮同步置位（`spawn` 前可见） | `orchestrator/entry.rs::start_turn` | `Begin` |
  | 进入 | 开轮广播 | `emit_session_state(Working)`（同函数、`spawn` 后） | `Begin` |
  | 退出 | 正常 / 中止收尾前置位 | `orchestrator/consume.rs`（`reset_working`） | `EarlyExit` |
  | 退出 | 中止 3s 兜底 | `orchestrator/consume.rs::handle_abort`（`clear_working_and_abort_signal`） | `EarlyExit` |
  | 退出 | 崩溃兜底 | `orchestrator.rs::WorkingGuard::drop`（`reset_working`） | `EarlyExit` |
  | 退出 | 收轮写结局 | `emit_session_state(Finished)` → `finish_turn`（正常 / 失败 / 中止三支路共用） | `Finish` |

  `finish_turn` 在提前让位之后到达时是幂等的（`became_idle = false`），不产生第二次唤醒。
- 2026-10-21 **字段私有**：`ActiveSessionStateInner.working` 对模块外只读
  （`is_working()`），生产侧没有直接写入口；测试要造忙窗时用
  `#[cfg(test)] set_working_for_test`（生产侧故意不开口子）。
- 2026-10-21 ADR-083 残余条款**不变**：`working` 仍是进程局部量——不参与事实投影、
  崩溃不会留下永久处理中（内存没了状态就没了，结局由投影补）。
- 2026-10-21 判据：`working.test.rs` 4 条（迁移、提前让位只唤醒一次、空闲路径不伪唤醒、
  提前让位后开新轮是真进入）；`active.test.rs` 4 条（收轮唤醒、提前让位唤醒、一次收轮
  只唤醒一次、空闲复位不唤醒）；`inbox.test.rs` 1 条（事件 vs 重试四形态：空 / 空闲有队 /
  忙有队 / 队空 `Resume`）。
