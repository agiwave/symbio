## 内容

父任务：[T-156-架构机制化与旧代码清理批](156-架构机制化与旧代码清理批.md)
依据：[ADR-051](../010-adr/051.md "ADR-051")（v2 是唯一执行路径，v1 执行链与 `V2Mode` 旋钮已退役）·
AGENTS.md「改标识符与改值是两件事」（改名是一次全仓替换，值不受影响）

**问题**：`session` 插件里有 8 个实现文件带 `v2_` 前缀。这个前缀是**迁移中途的命名**，不是终态：

1. **它是「还有 v1」的证据**——而按 [ADR-051](../010-adr/051.md "ADR-051")，v1 执行链已退役，
   v2 是唯一执行路径。一个唯一存在的东西不该带版本号（我们不给 `store.rs` 叫 `wal_store_v2.rs`）。
2. **它制造错误心智模型**——读代码的人会以为「v2 = 这 8 个文件」，而真正的 v2 是 core 那套
   Store / Projection / 事件网格（`symbio_core` 的 41 文件）。这 8 个是**消费者在自己插件里的实现**，
   蹭了机制的名字。
3. **它与同目录的既有命名不一致**——`turn_runner.rs` / `chat_loop.rs` / `stats.rs` 都按职责取名，
   没有版本号。

## 处理过程

- **纯改名批，零行为变更**：一次全仓替换 + `cargo test` 全绿即为完成判据。
  按 AGENTS.md，**标识符改名只需一次全仓替换**，携带的值（跨进程字面量）一个字节不变。
- **新名按职责取**，不是机械去前缀：`v2_exec` → 它是「turn 的执行器」（`turn_runner` 的编排入口）；
  `v2_facts` → 轮末派生事实（`derived_facts`）；`v2_messages` → 消息列表变更（编辑/截断/压缩）；
  `v2_skills` / `v2_tasks` / `v2_memory` / `v2_tools` / `v2_worker_progress` 同理逐个按内容取名。
- **区分两类 `v2_` 命中**：文件名（该改）vs 描述「v1→v2 迁移本身」的注释与文档叙述
  （合法，保留——它们在叙述这次迁移，是其职责）。这与 [T-159-messages.json过时双写注释清理](159-messages.json过时双写注释清理.md)
  的分类方法同款。
- **e2e 与 CI 不受影响**：文件名不进 wire，`protocol-mirror-audit` / `routes.gen.ts` 均不涉及。

## 落地

### 新旧名对照（新名取自各文件的模块自述，不是机械去前缀）

| 旧 | 新 | 职责（自述） |
|---|---|---|
| `v2_exec` | `turn_exec` | 轮次原生执行器——`turn_runner` 是编排入口，它是执行体 |
| `v2_facts` | `derived_facts` | 轮末**派生**副作用：承诺 / 任务表 / 熔断 + 记忆与学习 |
| `v2_memory` | `memory_events` | 记忆三段（写方 / 召回注入 / 巩固），落在事件网格上 |
| `v2_messages` | `message_events` | 消息变更事实的写方（ADR-053） |
| `v2_skills` | `skill_events` | 技能即事件：编译 / 路由 / 命中 |
| `v2_tasks` | `task_events` | 任务表写方（任务就是 `task.*` 事件） |
| `v2_tools` | `tool_dispatch` | core `DispatchPort` 契约的插件侧实现 |
| `v2_worker_progress` | `worker_progress` | Q3 进展的 WAL 读法 |

四个 `*_events` 是一族（**事实族的事件写方 / 读方**，名字里的 `events` 指它们读写的是事件网格
而非自己的存储）；三个动作型（`turn_exec` / `tool_dispatch` / `worker_progress`）按「做什么」取名；
`derived_facts` 单列——它不是某一个事件族，而是「本轮全部派生副作用的汇总写方」。
`memory_events` 与既有 `memory.rs`（`MEMORY.md` 文件形态）并置，两者的分工正是各自模块头写的
那一段，名字上不再靠猜。

### 功能性连带面：三处「按文件名找代码」的硬编码

改名不会让它们变红，**只会让它们悄悄不工作**——这是本批最容易漏的地方，逐条核过：

| 落点 | 形态 | 不同步的后果 |
|---|---|---|
| `scripts/grep-audit.mjs` | S-011 的 `file: 'plugins/session/v2_exec.rs'` | 锚点找不到 ⇒ 打印「跳过」而非 ERROR（守卫退化成空转） |
| `scripts/list-write-fact-audit.mjs` | LWF-001 正则 `\bv2_messages::` | 永远匹配不到 ⇒ 第二个写入口再也拦不住 |
| `scripts/gate.d/_shared.test.mjs` | 临时目录助手清单（按文件名 `readFileSync`） | 直接抛 ENOENT，红 |

另有 `scripts/gate.d/30-docs.mjs` / `dead-code-audit.mjs` / `core-export-audit.mjs` 的注释与
豁免理由、`e2e/**` 的说明注释（含 `t32` 里一条指向源文件的 Markdown 链接——D-010 链接档判它，
不同步就是坏链）一并跟上。

### 不改的两类，各有硬理由

1. **`v2-events.wal` 与 `V2_WAL_FILE`**：前者是**落盘值**不是标识符，后者是它的名字。改它等于给
   所有既有会话目录做一次数据迁移（ADR-044 同一事实一份持久化），属行为变更，不在这条「纯改名批」
   里。常量的名字与它命名的文件保持一致，比「名字干净」重要。
2. **已完成的任务卡 / ADR / `docs/archive/`**：它们记录「当时是什么」。改名不改写记录——
   分界线是「今天还要按名字找到那个文件吗」：源码、脚本、模块文档、活跃规划与架构文档
   （`docs/004-plan` / `docs/005-arch`）要改；已完成卡片与 ADR 不改。

### 符号层顺带清掉的两个同病项

- `V2Turn` / `V2TurnResult` → `ExecTurn` / `ExecTurnResult`：与文件同病、同文件，且同文件里已有
  `ExecAbortSignal` / `ExecEventSink` 的命名族，接上即可（`TurnRequest` 已被 `chat_loop/state.rs`
  占用，故不取）。
- 日志前缀 `[v2-exec]` → `[turn-exec]`：本批唯一可观测的变化；e2e 与门禁都不读它（全仓 `grep`
  无断言）。
- `e2e/cases/t42` 注释里原先拿一个**不存在的** `TurnState` 字段当判据（`v2_executed`，全仓无此
  定义；`TurnState` 只有 `opened` / `final_text` / `fallback_text`）——顺手改成陈述现状，不留一个
  指向不存在东西的名字。

### 判据

`grep -rn 'v2_' symbio/src` = **0**（改名前 317）；`cargo test -p symbio --lib` 1753 条一条没增
没减（纯改名不产生判据）；`cargo clippy` 无新警告；门禁 **111/111**（含 e2e 77/77）。
