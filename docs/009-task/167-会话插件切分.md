父计划：[PL-014 单环一表收敛](../004-plan/014-单环一表收敛.md "PL-014-单环一表收敛") §5 步骤 6。
前置已完成：步骤 0–5 全部落地并各自成提交（施工账见
[T-165-控制面收敛](165-控制面收敛.md "T-165-控制面收敛")，末批裁决见
[ADR-074](../010-adr/074.md "ADR-074")）。PL-014 的禁令随之解除——**在此之前启动本步只是搬家**，
因为驱动器还认 v1 外壳的簿记，切片边界对不上运行时的真实依赖。

判据只有一条硬的：**每个插件可独立卸载且系统仍完整**（v2 切分不得妥协的原判据）。
「切成五个目录」不是成果，「卸载其中任何一个都不塌」才是。

### 审计读数（2026-10-18，裁决已入 [ADR-075](../010-adr/075.md "ADR-075")）

步骤 1–5 把执行路径收成了**单环 + 一张能力表**，于是切分边界第一次可以用**注册表里的行**来描述，
而不是用文件归属来猜。审计的四条读数：

- **注册表侧不构成障碍**：`session` 的所有能力行只从一处 `put`——`SessionPlugin::traverse`
  （`plugin.rs` 579–632），而那张表**每次收集都新建**（`capabilities.rs:70`）。插件从容器摘掉，
  下一轮收集自然没有它的行 ⇒ **不需要给 `CapabilityRow` 加「贡献者」列**（ADR-075 裁决二）。
- **障碍一：常驻任务不可取消**。`heartbeat/mod.rs:149` 与 `transcript/inbox.rs:171` 两条 `loop`
  加 `workdir/fs_watcher.rs:60`，都在构造点 spawn（`plugin.rs` 367–375）、不留句柄、没有取消位，
  而 `SessionPlugin` **没有实现 `Plugin::stop`**（全仓只有 `composite` 一个实现）。
  「卸载」今天只是从名册里划掉一个名字。
- **障碍二：五处 `Arc`/`Weak<SessionPlugin>` 捕获**（`orchestrator/sink.rs:35`、
  `chat_loop/state.rs:454` 与 `:602`、`tools/heartbeat_tool.rs:31`、`plugin/vdfs_provider.rs:523` 的 `me()`）。
  全仓**没有** `dyn Plugin → SessionPlugin` 的 downcast，所以这一类耦合只有这一种形态，可逐条消掉。
- **已成立的两件事，别切第二遍**：`plugins/memory`（1,986 行）持的是**智能体与工作区**两腿，
  session 的 `memory.rs` + `v2_memory.rs` 是**会话**那一层（`MEMORY.md` 落会话目录、事件记忆就是
  会话 WAL 里的事件），三层各写各的文件；RE-006 §2.1 的 19 条工具里 session 只贡献 `heartbeat` 一条，
  `tools/` 是分发与执行基础设施（`tool_executor` 族 / `tool_result_guard` / `decls` / `task_table`），
  不是工具清单。

### 施工批次（顺序由 ADR-075 裁决）

判据先于搬家：**先让「卸载」这件事真的发生，再谈目录归谁**。

1. **P1 常驻任务可取消**——两条 loop 与 fs watcher 持取消位，`SessionPlugin` 实现 `Plugin::stop`。
   判据：停用 session ⇒ 心跳不再触发新一轮、收件箱消费者退出（用例或守卫钉住）。
   这一批不搬任何目录，但它是「独立卸载」这条判据能不能成立的前提。
2. **心跳片切出**（`heartbeat/` 501 + `tools/heartbeat_tool.rs` 198 + `heartbeat_state` 一格）——
   最小的一片，且它把 P1/P2/P3 三条都碰一遍（一条常驻循环、一处 `Weak<SessionPlugin>`、八个宿主触点）。
   **第一次做「卸载守卫」在这片上练手**。逐口归属裁决见
   [ADR-076](../010-adr/076.md "ADR-076")，它把这片拆成两个批次，顺序是**先迁落格、后切片**：
   - **2a 迁出落格**（行为不变、片还在原地）：触发落格（原 `heartbeat/mod.rs:351-488`）连同它读的
     运行时状态与配置一格，移进会话侧的自主触发入口 `transcript/autonomous.rs::request_autonomous_round`；
     运行参数 `mode` / `include_history` 改由该入口按会话自己的 metadata 推导，调用方不再随身带；
     钉着这段行为的四条用例随迁（`transcript/autonomous.test.rs`）。判据：心跳模块不再开事实源
     （`heartbeat/` 里零 `EventWalStore::open`），且那四条用例逐条仍绿。
     **写臂那一条分支（识别 `meta.trigger` ⇒ 落格失败 = 写失败）不在 2a**：它要用的标记词汇表在
     2a 只有一个消费单位，按 ADR-076 后果段那条它进不了 core 根出口——留到 2b 与切片同批。
   - **2b 切片 + 守卫**：调度半（间隔 / 抖动 / 空闲基线 / 常驻循环 / 设置工具 / 选项族那一行）
     切出去，读写只经地址面（`vdfs/list` 一次、`write(<sid>/inbox)` 一次、`write(<会话地址>)` 一次）。
     守卫判据（可执行形态由 [ADR-077](../010-adr/077.md "ADR-077") 裁决一订正为**停用**：本片的落点在
     `ASSEMBLY_SUB_AGENT_PLUGINS`，卸载对插件管理入口是拒绝的，而停用给出的正是「没有这个插件」的状态）
     ⇒ 停用该片后 Tool 行与 Option 行的 `heartbeat` 在下一轮收集里都不在、其余仍在、
     它的常驻句柄 `is_finished()`、session 侧读写照常。
3. **P2 `Arc<SessionPlugin>` → 窄手柄**：sink / emitter / drain 只拿它们实际用到的那件事，
   `me()` 那处把「开跑一轮」升成显式端口。判据：`session/` 里构造点之外的 `Arc<SessionPlugin>`
   捕获从 5 处降到 0。**按 owner 逐个下沉，一刀一片、每片门禁全绿独立提交**：3a emitter（拿名册）、
   3b drain（拿 `config` + `change_subs`）、3c sink 与 `WorkingGuard`、3d `me()` 的端口。
4. **P3 跨片调用走表或端口**：被切的那片不再 `use super::` 宿主的私有项。
   **实测口径要收窄**（批次 4a 读数）：心跳片切走后，「跨片调用」剩下的**代码**引用只有宿主外壳
   （`plugin.rs` / `plugin/`）那几处，而其中四类是**共享词汇**（`types::Session` 一族 = 存储的
   记录类型、`config::SessionConfig` / `PresentationTree` = 配置面、`paths::*` = 会话寻址、
   `plugin::OUTCOME_*` + `session_node` = 会话节点视图的渲染与词表），不是「调用宿主的私有方法」。
   真正 owner 放错的是**落库回包出口**（`append_and_publish` + `PublishTarget` 住在 `plugin.rs`，
   而它的依赖全在存储与名册上）——4a 把它归位转写域。**词汇那四类随批次 5 / 6 真切时定**：
   判据在搬的那一刻才咬人，提前把共享词汇搬一层只是把一次改动拆成两次（裁决见
   [ADR-075](../010-adr/075.md "ADR-075") 裁决四）。
5. **上下文与请求视图**（6,250 行）——排在 P3 之后、驱动器之前：它自己零 `SessionPlugin`
   引用（六段里最干净）。两条曾把边界拉住的理由都已解除：`context/pipeline.rs` 经
   `CompressionEmitter::target()` 拿发布通道去落库——3a 之后那条通道给的是名册而非宿主；
   三层淡化的接入方式会改这段边界——三层已由
   [ADR-078](../010-adr/078.md "ADR-078") 整族退役，`context/view.rs` 只剩三段注入。
   **排序理由清零，可以动刀。**
6. **驱动器最后**：`chat_loop` + `turn_runner` + `v2_exec` + `orchestrator` 是 10,143 行
   （含测试 17,800）的环。卸载它之后 session 只剩存储与生命周期——那才是「系统仍完整」的最强形态，
   也是 [AR-015-core-loop](../../symbio/src/plugins/session/docs/015-core-loop.md "AR-015-core-loop")
   描述的形状能不能真正拆开的验收。

**留守（永久，不再列为候选）**：存储与生命周期（13,956，四方反向依赖它，切成插件就是把一份持久化
交给两个插件写）、记忆两腿（会话数据本身）、宿主外壳（`traverse` / `route` / provider / 配置面
是「一个插件」的全部声明位）、分发与工具（随驱动器同片）。
