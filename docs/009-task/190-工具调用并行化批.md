## 内容

父设计：总报告 B2 · 06 报告建议 4 · [PL-014](../004-plan/014-单环一表收敛.md "PL-014-单环一表收敛") §3 规则 c（`Wait` 等待的是集合不是单项）

**现状**：工具调用**全串行**。一次响应带多个工具调用时，轮内时延是各工具之和。
批首闸门一次读数的骨架已经在（`tool_executor.rs` 批首读判据处），并行化的结构前提具备。

**三条不能省的约束**（原报告点名，逐条要有判据）：

1. **副作用类必须串行**：写文件、改配置、发消息这类工具并行会引入顺序不确定；
   分流依据应是既有的能力风险等级分档，而不是新造一个「是否只读」的布尔——
   分档到并行策略的映射要**单点定义**（否则每个调用点各判一次）。
2. **交互模式审批串行保留**：审批 / 提问是「一次只处理一张卡」的语义，并行会把两张卡同时推给用户。
3. **批内中止传播**：一个工具被中止后，批内其余在途请求必须收到同一信号——
   串行时代这件事是「自然」的（根本没在跑），并行之后必须显式传播，否则中止会退化成「等所有工具跑完」。

**为什么排在 T-179 之后**：`process_tool_calls_async` 是三个巨型函数之一，按阶段切点是
「批首闸门读数 / 逐条执行 / 未执行收口」——并行化改的正是「逐条执行」这一段。
先拆后并，改动面才落在一个有名字的段里；先并后拆，等于在一段 700 行的函数里同时改结构与并发。

**不新增机制**：并行是执行器的实现策略，机制键 0、trait 0、新插件 0。

## 处理过程

- 2026-10-20 立批。来源：总报告 B2 + 06 报告建议 4。
- 2026-10-20 判据选择的理由：**「事件批序逐项相等」是这批的守门判据**——并行最容易造成的是
  事件顺序漂移，而事件批序是回放与投影的前提；它比「更快了」更值得当出口条件。
- 2026-10-20 与 [T-196](196-闸门表与拒止骨架归一批.md "T-196-闸门表与拒止骨架归一批") 的关系：
  两批都动 `tool_executor`，但 T-196 动的是「拒止骨架与闸门表」（判定侧），本批动的是
  「执行侧」；若两批同期开工，须约定先后（建议 T-196 先行，因为它会重排批首结构）。
- 2026-10-20 **实现落点**：分流映射单点在 `dispatch/parallel.rs`（`policy_for_risk`：
  `Low` → 并行，`Medium` / `High` → 串行；`policy_for_mode`：`interactive` 整批压成串行，
  理由是审批 / 提问「一次只处理一张卡」）。风险表 `ToolRisks` 与 `ToolDecls` 共用批首
  那一次 `tool_metas` 读数——两个消费者不再各遍历一遍收集管线。
- 2026-10-20 **静态档而不是 `risk_for(args)`**：`Capability::risk_for(args)` 能随参数降档
  （`shell` 的 `git status` 是 `Low`），但它要有参数与能力实例；调度若先解一遍参数风险，
  调度就成了执行的一部分，两处解析还会漂移。调度按声明的静态档取保守值——`shell` 因此
  恒串行：少并行一次，不会错一次。审批闸门仍用动态档，两处各读自己需要的那个。
- 2026-10-20 **「事件批序逐项相等」的口径**：真正并发时，跨调用的帧**不可能**逐字同序
  （一组只读调用若先跑完第一条再亮第二条的运行态，就退回串行了）。本批钉住的是三条
  可判等的关系，tests 逐条断言：① 结果子节点与父节点终态按**调用顺序**收口（完成次序
  反过来也不许倒）；② 每条调用的 `Streaming` 帧先于**它自己的**结果帧；③ 每条调用
  产出的帧种类与数量不变（运行态 1 + 结果 1 + 父终态 1）。跨调用的交错是并行的代价，
  在此记为已知差异，而不是把它说成「完全相等」。
- 2026-10-20 **结构**：`batch.rs` 的循环拆成「准备（`prepare_call`）→ 执行（`start_execution`
  + `FuturesUnordered`）→ 按序收口（`flush_one` / `finish_call`）」。执行前就终结的出口
  （协议失败 / 超限丢弃 / 闸门与钩子拒止）**不在准备阶段发事件**：先 flush 在途、再按
  调用顺序发——否则「后一条被拒」的结果会插到「前一条正在跑」的结果之前。
  在途上限 `MAX_IN_FLIGHT = 4`（最小化的「有上限」，不是调优参数）。
- 2026-10-20 用例：只读并行（2 方屏障 + 完成次序倒置 + 帧序断言）、写侧不重叠（两个
  方向各一次，峰值并发 = 1）、交互模式整批串行、中止传播（两条长睡工具共用一个信号，
  中止后都收敛为「被用户中止」）。
