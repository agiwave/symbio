## 内容

父任务：无（自 [T-162-ClassifyOnly快速档路径裁决的勘察结论](162-ClassifyOnly快速档路径裁决.md "T-162-ClassifyOnly快速档路径裁决") 拆出——
那条已暂缓，本条的结论不依赖它的裁决，可独立处理）

依据：[ADR-051](../010-adr/051.md "ADR-051")（`V2Mode` 旋钮与 v1 执行链退役，档位语义只剩一套）·
`adapters/mod.rs` 的胶囊令牌族（`FullModel` / `ClassifyOnly` / `RuleOnly`，私有构造）

**先说清这条不是什么**：它**不是**「session 链路绕过闸门」——初版读数正是这么记的，核实后**不成立**。
`turn_exec.rs` 两处（`:1069` / `:1384`）每次都先 `ProviderLlmAdapter::for_turn` 把 provider 包成
adapter 再走。`ExecTurn.provider` 那个字段持的是 raw provider，但持它的目的是**每轮包一次**，
不是绕过。「持 raw provider」与「直调 `execute_turn`」是两件事，混为一谈就会把主链路也算成缺口。

**问题真正的形状**：档位闸门只挂在 `LlmAdapter::generate(&FullModel, …)` 这一个签名上，而
`ModelProvider::execute_turn` 是对所有插件开放的 core trait——**直调它就不经过闸门**。

枚举方法（可复现）：`grep -rn '\.execute_turn(' symbio/src --include=*.rs`，滤掉 `.test.rs` /
`tests.rs`，得四处：

| 调用点 | 是什么 | 过闸门吗 |
|---|---|---|
| `symbio_core/adapters/provider_adapter.rs:494` | `ProviderLlmAdapter::generate` 的方法体 | **它就是闸门自己**——闸门要管的就是这一条 |
| `plugins/classify/decide.rs:146` | 快速档判决（`tools: &[]`、`silent()` 出口） | 否 |
| `plugins/compose/wording.rs:105` | 答话措辞（同上形态） | 否 |
| `session/context/pipeline.rs:977`（`run_compression_llm`） | 压缩摘要（同上形态） | 否 |

后三处的共同形态：`tools` 传空切片、出口 `ExecEventSink::silent()`、固定 system prompt、
中止走共享信号。**它们全部是「内部请求」**——而「内部请求要不要受档位约束」正是档位闸门
存在的理由。闸门今天保证的是「经 `LlmAdapter` 的那条路受约束」，**不是**「所有调模型的路」。

与 [T-162](162-ClassifyOnly快速档路径裁决.md "T-162-ClassifyOnly快速档路径裁决") 的分工：T-162 问「快速档该不该做成闸门管的那一种」；
本条问「闸门声明自己管什么」。前者裁决 (i) 纯规则 ⇒ 本条只剩 `compose` 与 `pipeline` 两条；
裁决 (ii) 一次受限模型调用 ⇒ 三条一起。**两条不互相阻塞。**

## 处理过程

- **先枚举全、再谈接线**：调用点枚举口径（滤测试、留四处、认出一处是闸门自己）先钉住，
  否则「补一条内部请求」悄悄多一个绕过点也没有人发现——本条出口里的守卫就是钉这件事。
- **候选出路 A（接线）**：三处改走 `ProviderLlmAdapter::for_turn`，档位由 `FullModel` 携带
  （内部请求取 `RuleOnly` 或新立一个内部档）。代价：`for_turn` 每个调用点新造一个 adapter
  实例，要核它有没有按轮缓存的语义。
- **候选出路 B（声明）**：承认「内部请求不受档位闸门约束」是一句设计决策，给它一条 ADR
  与一条守卫（守卫判的是**新增**的绕过点，不是存量）。若走这条，T-162 的 (i) 分支会更顺。
- **不要选 C（现状）**：既不说它管、也不说它不管，正是本条要消除的形态。
- 2026-10-19 第一步落地（守卫先行，不等 A/B 裁决）：`scripts/internal-model-audit.mjs`
  （IM-001…003）+ 回归测试进门禁 GUARDS。理由：两条出路都要先知道「调用点有几处、各是什么」，
  没有清单就只能靠下一次架构复盘撞见——而那正是本条的失效形态。守卫**不判三处该不该在**，
  只判「在，且有人说过为什么」：每处调用点旁一条非空理由，新增第五处即红。
  判据 IM-001 未登记 · IM-002 空理由（写了像登记、实际不算，不显式报出来人会以为登记过）·
  IM-003 悬空（代码搬走而标记还在）。扫描口径：生产代码，`*.test.rs` / `tests.rs` 文件与
  `#[cfg(test)]` 模块不判；扫描根读空 ⇒ exit 1（不许「读空即全绿」）。
  四处存量已逐处登记（`provider_adapter` 闸门本体 + 三个内部请求）。落地时踩过一次方向错误
  （标记在代码上方，命中行应是「本行或**下一行**」），回归测试第 ③④ 条两头都钉住了。
  **剩下的仍是 A/B 裁决**——本步只是把裁决需要的事实定了格。
