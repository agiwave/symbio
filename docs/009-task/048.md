## 内容
在**真实模型**上做一次结构化 vs 拍平的对照，给 ADR-048a 的「不拍平」与 ADR-057 的形状
记录补上模型侧读数。**需要预算授权**才起跑（本仓纪律：花真钱的运行先问）。

## 处理过程

- 2026-10-12 由 [T-047](047.md) 的落地形态切出来：[ADR-058](../010-adr/058.md)
  被否决方案第 1 条明令它不能当门内判据（要授权、结果非布尔、不可重复），但缺口是真的，
  所以单独立条目而不是写进那句「仍未闭环」里丢掉。
- 起跑前先解决的三件事，落地形态是：
  - **任务集**：22 道，三类各测一件不同的事——`select`（该调哪个工具，14 道）、
    `control`（不该调时会不会硬调，3 道）、`attribution`（结果↔调用的对应关系还读不读得回来，
    5 道）。真值只有题面那一条事实，必填参数键不手写、直接从该工具 Schema 的 `required` 读。
    attribution 里成对放了一道**镜像题**（同一份上下文换问另一次调用）：它是偏置探测器，
    「按到达顺序取」这个启发式在一题上必错、在另一题上必对，两题给出同一个指向就不是碰运气。
  - **判据**：全部机械可读回，不含「答得好不好」。时延 / token / 字节只进观测列（与 ADR-057 同一取舍）。
    臂 B 独有以下两条**互不等价**的判据，第一版把它们合成了一条、读数是假的，改过之后才成立：
    「**协议有没有被遵守**」读调用是从哪一处解析出来的，「**正文有没有漏出内部标记**」读正文本身——
    实测有道题两枚定界符写在前面、后面照样跟了一行合法 JSON，出处是协议、正文却漏了标记。
    同理，判两臂公平必须给臂 B 的解析器**同等宽松度**（跨行 JSON 也认），否则掉的是解析器的分不是模型的分。
  - **可复现**：**回放**而不是跑两次端到端会话——两次端到端会话一旦第 1 步分叉，第 2 步比的
    就不是同一道题，差异无法归因给形状。这里把**同一份结构化输入**送两次：上下文整体取自
    真实链路捕获（CLI × mock-llm × mock-mcp，出厂 `full` 档、对话面关闭，与 ADR-057 形状基线
    同一条链路**同一个场景名**），臂 B 由 `flattenRequest` 从臂 A 的输入**派生**，
    除 `tools` / `tool_choice` 与工具交换的载体外逐字节相同。两臂**逐题交替**发送：按臂分块
    的跑法一旦环境中途变慢，整段漂移会全落在后跑那一臂上（实测撞到过一次）。
- 2026-10-12 读数（一个模型，MiMo-V2.6-Flash；预算经用户授权；**同一实验独立跑了两遍**，
  报告留的是第二遍 05:48Z，第一遍 05:29Z——两遍的判据逐项同分或差 1 题）。三条判据两臂**同量级**：
  `select` 选对 24/28 vs 24/27、参数合法 JSON 28/28 vs 26/26、必填键齐 26/28 vs 25/26、
  调了不存在的名字 0 vs 0、`control` 过触发 0/6 vs 0/6、`attribution` 4/10 vs 4/10——
  **拍平对模型「把题做对」既没有可测的收益也没有可测的伤害**（那 1 题之差在 2 组重复翻转的噪声内；
  未收束 1 行、请求出错 0 行）。差别出现在**拍平自己新引入的失败面**上：
  臂 B 26 道答出调用的 select 里 **6 道没按协议那行 JSON 答**，而是把训练形态里的调用标记
  （`function=` / `parameter=` 那一族，整条包在 `tool_call` 定界符里）直接打进正文。
  两遍各自独立收集：第二遍 43 答里 6 答含这种标记、第一遍 44 答里 8 答含——占比稳定在 14–18%。
  这一族标记在结构化臂是协议字段（`tool_calls`）里的内容，运行时按字段读；拍平之后它落在正文，
  **执行方必须再写一个「模型内部格式」解析器**才能拿到同一个工具名——这不是理论风险，本轮的判据
  之所以能两臂公平，就是因为给臂 B 补了那个解析器：把它去掉，臂 B 的 select 从 24/27 掉到 20/27，
  掉下去的那几题不是模型没做到，是**没人读它写了什么**（工具名与参数都在正文里，只是不在协议那一行）。
- 顺带读到一条与形状无关、但产品侧要记的事实：**这个模型配对「结果↔调用」用的是位置而不是
  `tool_call_id`**——两臂在镜像题上给出同一个错指向（问 `path=src` 答了先到那条的 `plan`，
  问 `path=docs` 答了后到那条的 `lib.rs`），五路逆序题两臂都答 `200`（= 按到达顺序数第 4 条），
  10 行 attribution 两臂**答案逐字相同**。
  ⇒ 「出厂形状保留 `tool_call_id`」是**给运行时**的关联，不是**给模型**的关联；不要指望模型读它，
  乱序结果的归属必须由执行方自己按 id 落账。
- **边界（读数不能超出这些）**：
  - **单模型、单 provider**：另一台授权内的 `qwen3-8-flash-next` 收不下出厂请求体（见
    [T-015](015.md)，它回 400 而不是给出答案，无法成臂）；本机 LMStudio 的模型实例这一轮
    处于坏状态（`max_tokens:32` 的一句话请求也吐 `<unused32>` 复读，需人工重载）。
  - **无工具执行方**：runner 只发一次 HTTP 请求，谁都不真的写、删、执行——所以读数只覆盖
    「模型答什么」，不覆盖多轮工具往返之后形状还成不成立。
  - **温度 0、单轮**：不是会话，是「同一份上下文的一次投影」。
- 因此对 ADR-048a 的影响是**换支撑不是改判定**：那条「不拍平」的判定当初只靠论证成立，
  现在多一条读数——「拍平不换来更好的题面表现，只多一个需要专门解析器才看得见、
  且会静默丢调用」的失败面（见上）。读数同时钉住一条不该误用的方向：
  attribution 两臂同分**不能**读成「`tool_call_id` 无所谓」，它读成的是「本模型不用 id 而用位置」，
  而臂 B 的散文里**连位置之外的信息都没有**（同名调用只重复同一个工具名）。
- 实验按 ADR-058 被否决方案第 1 条留在门外：`e2e/ab/` 不在 `e2e/cases/` 下（58-e2e 只按
  `/^t\d.*\.mjs$/` 发现用例），不进任何一条门禁阶段；报告 `docs/006-ref/PROMPT_AB.md` 的
  唯一写者是 `node e2e/ab/run.mjs`，重跑会覆盖，结论只写本条目。
