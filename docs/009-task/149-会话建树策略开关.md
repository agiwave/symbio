### 149-ii（`deep` 档 + flat 跨子会话护栏）— 已完成

`deep` 全部落在**读侧投影**，不碰 `agent` 插件、不加 ctx key——保持 grouped 与全部
既有子智能体 e2e（t15/t30/t36/t39）逐字不变。

- **`deep` 语义 = 「递归多智能体嵌套、不做读侧折叠」**：转播桥早已**无条件**把子会话
  顶层节点挂到发起它的父工具卡下（`relay_bridge`），存储侧 deep==grouped。`PresentationTree`
  加 `Deep` 变体（`as_str()="deep"`、`OPTIONS` 第三项、`presentation_tree()` 认 `"deep"`），
  `flatten_whole_tree` 的早返回判据写成 `mode != Flat` ⇒ Deep 与 Grouped 同为**零折叠**。
  两档的差别只在前端如何展开嵌套树，后端转写形状逐字相同。
- **顺带修掉的潜伏缺陷（flat 跨子会话护栏）**：转播进父**在途覆盖层**的子会话响应骨架
  仍带 `Skeleton{run}`（`set_legacy_role(Tool)` 不清 `style_tag`），旧 flat 折叠「凡 is_run
  就把其子节点升根」会把这棵子会话的孙节点错误升到会话根、拆散嵌套。修在
  `flatten_whole_tree`：`run_roots` 集合**排除父指向 `is_tool_call()` 的 run 骨架**，
  只折叠会话根级骨架。`detach_if_flat`（写侧）无需改——它的判据是「父==本轮 root_id」，
  转播节点的父是工具卡 id 而非本轮 root，天然不命中。
- **验证（与 exit 的一处诚实分歧）**：护栏是纯函数，权威锁定在 Rust 单测
  `message_build.test.rs::flatten_whole_tree_skips_run_skeleton_nested_in_tool_card`
  （构造「工具卡→子会话 run 骨架→孙正文」的确切形状，断言孙节点不升根、不孤立）+
  `flatten_whole_tree_deep_is_noop`（deep==零折叠）。config 三例覆盖 `deep` 解析。
  **exit 里「三档各一条 e2e」未按字面兑现，是刻意的**：e2e 探针实测——`agent_run` 一轮
  收束、CLI 退出后读**落库**父转写，子会话正文只作为工具卡的 `role=tool` **结果节点**
  持久化（正文带 `[subagent_session_id: …]` 标记），落库树里**没有**独立的子会话 run 骨架；
  被护栏保护的那棵形状只在子会话**流式在途覆盖层**（`overlay_live` 后 `flatten_whole_tree`）
  短暂存在。⇒ 该窗口无法在 e2e 稳定复现（Windows 子进程时序敏感，纯竞态），且落库形状
  有护栏无护栏输出一致（断言不可证伪）。与其写一条断言「代码路径不产出的形状」的假 e2e，
  不如把护栏钉在能确定性构造它的单测层。flat 的**落库**形状仍由 `t79` 单轮 e2e 钉住。
