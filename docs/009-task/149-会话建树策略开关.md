## 处理过程

### 149-i（config + grouped/flat 两档，一次改完）— 已完成

- **配置项落在 `symbio/src/plugins/session/config.rs`（不是 `symbio_core/config/`）**：
  `presentation_tree: String` 字段 + `PresentationTree { Grouped, Flat }` 枚举 +
  `presentation_tree()` 读侧（未知值回落 `grouped`）。出厂默认 `grouped` = 今天行为，
  存量数据零字节改动。面板控件走 `DetailField::select`（`plugin.rs`），受两条
  config-definition 覆盖闸约束。`deep` 留给 149-ii（不把惰性可选值暴露成假开关）。
- **三处树形状锁步站点全部接 `detach_if_flat`**（同一 mode 快照，v1/v2 逐字一致）：
  - 落库：`chat_loop/turn.rs`（v1 `into_messages`）、`v2_tools.rs`（v2 `produced` +
    就地 detach `call_nodes`，令执行器 clone 出的运行/终态帧继承脱父）。
  - 流式：`chat_loop/state.rs` 四处 finalize、`v2_exec.rs` emitter 的 Snapshot/Finalize、
    中止 `partial`。
  - 呈现投影：`chat_session/read.rs::get_messages`、`plugin/nodes.rs::session_content`、
    `vdfs_provider.rs::transcript_of` 三处经 `flatten_whole_tree`（重建 core config-free、
    从 `turn_id` 一律重derive 成 grouped，故读侧再投一次；`grouped` 即时返回零改动）。
- **脱父记号与后端遍历器**：升根节点带 `meta.turn_root = <骨架 id>`；`failure::subtree_of`
  与 `resume::process_retry_subtree` 的 BFS 各并集 `{turn_root==root}`，重试删除/失败级联
  够得着脱父子节点。工具结果节点不升根（仍挂自己的 `tool_call`，与建树策略正交）。
- **live 天然脱父的依据**：流式 delta 帧只带 `id`+`delta`、不带 `parent_id`，占位节点在根；
  finalize 脱父帧省略 `parent_id`（`skip_serializing_if none`）⇒ 合并保留其在根。
- **验证**：Rust 单测（`message_build.test.rs` 六例 + `failure.test.rs` 脱父并集 +
  `config.test.rs` 三例）、e2e `t79-presentation-tree-flat`（生产读出口断言升根+turn_root、
  工具结果不升根、无孤儿）；全量 `cargo test --lib` 1706 绿、e2e 76/76 绿、
  `protocol-mirror-audit` 0 错、`core-shape-audit` 形状未变宽。
