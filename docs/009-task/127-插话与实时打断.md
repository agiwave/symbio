## 内容

前置：S06 ｜ **新增机制键 0** ｜ 参数变化 4 ｜ 阶段四

## 1. 场景：要什么能力

智能体正在说话 / 正在跑长任务时，用户插一句话；系统能**在反射层内**决定"放行 / 挂起 / 排队"，
事后还能回到被打断的地方。

相对 S06 高了什么：**系统第一次需要在几十毫秒内对外部信号做决策**。
S06 及以前的所有决策都在 300ms 以上，本阶把反射层（≤80ms）真正点亮。

## 2. 为什么它能落在 v2 上（J1）

| 看起来新的东西 | 实际是 |
|---|---|
| 打断信号 | `control/opened`（`task.controlled`）事件 |
| 抢占判定 | 一个 `Decider`，`budget_ms = 80` |
| 被挂起的状态 | `task/held`（`task.held`）——**挂起就是一条事件** |
| 恢复 | 从 `seq` 重放 → 投影自动回到断点 |

**关键**："挂起"不需要新状态机。挂起 = 一条 `held` 事件；恢复 = 投影自然包含它。
这也是为什么本阶**新增机制键 = 0**——打断在 v2 里不是新机制，只是新的一格事件 + 一个更快的 Actor。

**裁决（2026-10-13，[T-081](../009-task/081-授权表缺行登记批.md "T-081-授权表缺行登记批") ③）：「改道」不落地，正文按实现口径订正。**
`Preemption`（`actors/control.rs`）只有 Proceed / Suspend / Queue / TimeoutDefaultContinue——**无改道分支**，且不该有：

1. 改道的语义是「把在跑任务的目的地换掉」，那要先**理解插话**——正是 §7 自己划给 `Reasoner` 层（300ms+）的事，与反射档（≤80ms）的预算相斥；
2. 它今天既**没有写方**（没有任何代码算出「改道到哪」）也**没有消费方**（调用方只处理那四种结论）——给一个两端都没有的名字建分支，是 [T-083](../009-task/083-调度租约裁决批.md "T-083-调度租约裁决批") 拒绝 `task.ready` / `task.assigned` 的同一条理由；
3. `Preemption` 是 core 枚举，加变体是**形状变宽**，按 [ADR-055](../010-adr/055.md) 要先立决策。

故本阶的真实能力 = 「放行 / 挂起 / 排队 + 超时默认继续」；§1 与 §7 的「停 / 继续 / 改道」措辞已同批订正为「放行 / 挂起 / 排队」。§6 的四条验收断言一字未动（它们判的正是那四种结论）。

## 4. 平凡值与回退（J2）

| 参数 | 完整值 | **平凡值** | 平凡值下 |
|---|---|---|---|
| `event.entity` | `control` | **`turn`** | 仍完整运行——不接受插话，退化为 S06 的"跑完再说" |
| `actor.budget_ms` | `80` | `60000` | 仍完整运行——判定慢，用户感到迟钝但不出错 |

**`control` 关闭 = 本阶整阶可跳过**，且系统仍完整。这是插话能力"是数据不是机制"的直接证据。

## 5. 静默失效与强制（J3）

| 约束 | 违反时信号 | 强制方式 |
|---|---|---|
| 抢占判定必须在 80ms 内产出 | **无**——只是慢，无人报错 | I3：超时必须产出 fallback 事件 |
| 被挂起的任务不得被二次调度 | **无**——可能重复执行 | `readyset` 排除 `held` 状态（投影过滤） |
| 抢占判定者不得直接发言 | **无** | grants 表：无 `reply.*` 写权 |

## 6. 验收断言

1. 注入打断事件 → 80ms 内必须存在一条 `task.controlled`（或 fallback）。
2. 挂起期间该任务不出现在 `readyset` 中。
3. 恢复后投影与挂起前一致（除新增的 `held`/`controlled` 事件外）。
4. **反向用例**：把预算放宽到 60000ms → 断言 1 的判定结果必须改变（证明预算参数真的在生效）。

## 8. 这一阶做不了什么

边界的唯一账本：[SC-007-插话与实时打断](../002-scene/007-插话与实时打断.md)（用户语言）。机制面独有边界（用户可见范围之外的工程约束）：

- 「改道」不在本阶：`Preemption`（`actors/control.rs`）没有改道分支，也不该有——改道要先理解插话语义（`Reasoner` 层，300ms+），加一个既无写方也无消费方的分支只会让「本阶能改道」看起来有代码支撑（裁决记录见 §3.1）。
- 真正的硬实时（T7 的具身 / 闭环控制）仍无实现；本阶只有预算断言（基准见 `RE-004-slo-calibration`，它量的是链路自身开销，不是闭环控制）。
- 多个插话并发到达时的优先级是 `readyset` 的打分参数问题。
