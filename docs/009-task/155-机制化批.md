## 内容

父设计：[PL-013 前端机制化](../004-plan/013-前端机制化.md "PL-013-前端机制化")
决策依据：[ADR-070](../010-adr/070.md "ADR-070")（§决策 3 本批复写：`NodeKind` 是唯一前端分派轴，
`style_tag` 降级为后端注记）

**起因**：T-147/T-148 落地的 (kind, style_tag) 分派被判定为**假机制化**——业务词（reasoning /
tool / compression）只是从 `MessageType` 挪进 `style_tag`，前端照样 `switch` 认识它们。且执行
走偏离了 [PL-013 §3]：`reasoning` 本应是 `Notice`（折叠叶子，与 compression 同格），却被实现成
`Body + style_tag:"reasoning"`。

**本批要买到的性质**：新增一种业务（新工具 / 新系统事件）⇒ **只改后端**（写 `meta.style_tag` +
填 `title`/`icon`/`actions`），前端一行不动。

## 分解

- **B1 core schema**：`reasoning` 归 `Notice`（`legacy_shape_to_style_tag` + `is_reasoning`/`is_text`/
  `is_compression` 谓词重定义，压缩判据加 `style_tag != reasoning` 防互撞）；`ChatNode` 加顶层
  `title` / `icon` / `actions: Vec<ResumeAction>`（CS-001 变宽，需本 ADR 授权）
- **B2 后端构造点**：reasoning×7 处 `Body+tag`→`Notice`；notice/run/tool 构造点填 `title`/`icon`；
  失败/审批路径在节点上算 `actions`
- **B3 前端契约层**：`schemas/chat_node.ts` 删 `CHAT_STYLE_TAG_*` / `PRESENTATION_KINDS` / 六业务呈现键
- **B4 前端注册表**：`registry/messageTypes.ts` 重写——`foldNodeKind`、`NODE_KIND_PRESENTATION`、`messageTypeOf` 已删除；`TYPE_PRESENTATION` 按 `NodeKind` 五值索引；`messageRetryTargetOf` 读 `node.actions`
- **B5 渲染器塌缩**：7 组件→5（SkeletonNode 容器、NoticeNode 折叠叶、BodyNode 正文、
  InteractionNode、TypingNode）；`messageRenderers.ts` 重登记
- **B6 CLI + 审计**：`cli/src/render.rs` 同步；`protocol-mirror-audit.mjs` A/C/D/G 组适配
- **B7 测试**：chat_node.test.rs / messageTypes.spec.ts / 后端 message_build 等断言随语义翻转

## 处理过程

- 2026-10-17 立批——起因是用户对 T-148 落地的「(kind, style_tag) 分派」的否决：换名不是机制化。
  ADR-070 §决策 3 就地改写给本批。
- **B1–B7 落地**：core 侧 `reasoning` 从 `Body + style_tag` 归位到 `Notice`（`is_reasoning` /
  `is_text` / `is_compression` 随之重定义，压缩判据加 `style_tag != reasoning` 防互撞）；
  `ChatNode` 顶层加 `title` / `icon` / `actions`。后端 reasoning×7 处与 notice/run/tool 构造点
  改填呈现字段，失败/审批路径在节点上算 `actions`。前端 `schemas/chat_node.ts` 去掉
  `CHAT_STYLE_TAG_*` / `PRESENTATION_KINDS` / 六业务呈现键，`registry/messageTypes.ts` 按
  `NodeKind` 五值索引、`messageRetryTargetOf` 读 `node.actions`，渲染器 7→5
  （SkeletonNode 容器 / NoticeNode 折叠叶 / BodyNode / InteractionNode / TypingNode）；
  `cli/src/render.rs` 与 `protocol-mirror-audit.mjs` 随新形状适配。
- **兑现的性质**：前端只剩一个折叠入口 `nodeKindOf`（存量业务词在**读取那一刻**折成五值，
  之后不参与任何判定），生产代码里再无 `style_tag` 读取（`grep -rn style_tag tauri/src` 只命中
  一条测试标题）；业务谓词 `is_reasoning`/`is_tool_call`/`is_compression` 全留在后端。
- **收尾·对话面开关**：`progress_enabled` 出厂默认改 false，Escalate 首响独立成
  `opening_enabled`（出厂 false）——对话面旁白与本轮机制化正交，默认关；断言靶子就是那句
  首响的用例（t20 / t22）显式开 `opening_enabled`。
- **收尾·e2e 折叠层**：`helpers.mjs::msgTypeOf` 是 e2e 侧的**折后**读法（不是前端镜像——前端
  已不认识这些词），`notice` 格按 `meta.style_tag` 分 reasoning / compression；此前无条件折成
  compression 让 t10 / t22 / t24 / t77 一起红。
- **收尾·t18 计量口径**：「连续 3 次失败触发熔断」改按**失败压缩节点（分幕）**计数——HTTP 命中
  数被客户端 5xx 退避放大 5 倍、不同请求体数被切分边界重复低估（实测 3 次失败只有 2 个不同
  请求体），只有分幕与 `active.rs` 的熔断计数同口径。故障注入改静态 500，「服务恢复」由新增的
  mock `POST /_plan`（`MockLlm.setPlan`）在重试前明确触发，不再靠 `failTimes` 的指纹名额恰好烧完。
- **两处门禁缺陷就地补全**（本批 exit 判据是「门禁全绿」，这两条挡在路上）：
  `scripts/gate.d/35-baseline.mjs` 把「这处棘轮比基准新」（基线在基准提交里才引入，其父提交
