## 内容

父设计：[PL-013 前端机制化](../004-plan/013-前端机制化.md "PL-013-前端机制化")
决策依据：[ADR-070](../010-adr/070.md "ADR-070")（§决策 3 本批复写：`NodeKind` 是唯一前端分派轴，
`style_tag` 降级为后端注记）

**起因**：T-147/T-148 落地的 (kind, style_tag) 分派被判定为**假机制化**——业务词（reasoning /
tool / compression）只是从 `MessageType` 挪进 `style_tag`，前端照样 `switch` 认识它们。且执行
走偏离了 [PL-013 §3]：`reasoning` 本应是 `Notice`（折叠叶子，与 compression 同格），却被实现成
`Body + style_tag:"reasoning"`。

**本批要买到的性质**：新增一种业务（新工具 / 新系统事件）⇒ **只改后端**（写 `meta.style_tag` +
填 `title`/`icon`/`actions`），前端一行不动。

## 分解

- **B1 core schema**：`reasoning` 归 `Notice`（`legacy_shape_to_style_tag` + `is_reasoning`/`is_text`/
  `is_compression` 谓词重定义，压缩判据加 `style_tag != reasoning` 防互撞）；`ChatNode` 加顶层
  `title` / `icon` / `actions: Vec<ResumeAction>`（CS-001 变宽，需本 ADR 授权）
- **B2 后端构造点**：reasoning×7 处 `Body+tag`→`Notice`；notice/run/tool 构造点填 `title`/`icon`；
  失败/审批路径在节点上算 `actions`
- **B3 前端契约层**：`schemas/chat_node.ts` 删 `CHAT_STYLE_TAG_*` / `PRESENTATION_KINDS` / 六业务呈现键
- **B4 前端注册表**：`registry/messageTypes.ts` 重写——`foldNodeKind`/`NODE_KIND_PRESENTATION`/
  `messageTypeOf` 删；`TYPE_PRESENTATION` 按 `NodeKind` 五值索引；`messageRetryTargetOf` 读 `node.actions`
- **B5 渲染器塌缩**：7 组件→5（SkeletonNode 容器、NoticeNode 折叠叶、BodyNode 正文、
  InteractionNode、TypingNode）；`messageRenderers.ts` 重登记
- **B6 CLI + 审计**：`cli/src/render.rs` 同步；`protocol-mirror-audit.mjs` A/C/D/G 组适配
- **B7 测试**：chat_node.test.rs / messageTypes.spec.ts / 后端 message_build 等断言随语义翻转
