## 内容

父设计：总报告 C6 · 10 报告建议 S-4 / S-6 / S-8 / S-9

**「语义检索」今天名副其实吗**——不完全。记忆事件里带着一个向量字段，但**它是空的**：

| 项 | 现状 | 后果 |
|---|---|---|
| 向量字段 | 恒空（无写方） | 「预留机制位」——J1 违反：声明了一个不存在的参数 |
| 同文去重 | 全量扫描历史 | 编码成本随会话历史线性增长 |
| 空查询 | 传空字符串而非空值 | 平凡值分支在生产里不可达，读代码的人看不出它存在 |
| 配置一致性 | 内存态与落盘态无断言 | 两处状态，一处漂移没人知道 |

**向量这条只能二选一**（原报告给的判断，本批沿用）：

- **接线**：直接提升召回质量（尤其近义表述），让「语义记忆 / 预测」两个标签从死旋钮变成活参数。
  成本高：写路径要做推理（编码是同步函数，要改异步或在写方前异步预计算），还要建索引、
  扩排序内核、扩评测集，并处理向量索引与 WAL 的双写一致性。
- **不接**：删掉字段（或改名 + 在事件文档写明「当前无写方」）。成本低，收益是**消除一处 J1 违反**。

**「写清楚比留空强」是本批的取向**：留一个恒空字段，等于告诉后来者「这里有个能力」，
而那个能力不存在。无论选哪条，都比现状好。

**去重有界化会改变行为**（原报告明确）：去重范围变小 ⇒ 同一句话在远处可能被重复记一条。
所以「去重窗口」必须是**参数**（按 v2 纪律它是参数不是机制），且要有一条判据说明窗口多大、
超出窗口后的行为是什么。

## 结案（四行逐条对账）

| 立批时那条 | 结案 | 落点 |
|---|---|---|
| 向量字段恒空 | 走出口 **②删字段**，并升为一条 ADR：位置裁决不变（向量落成时仍住这条事件的载荷），被淘汰的只有「没有写方先把键写空」 | [ADR-110](../010-adr/110.md) · `29290c39` |
| 同文去重全量扫描 | **不做有界化**：全量从 `read_all` 的副产物升为有人钉的判据（含配额窗口的反判据）；「去重窗口」参数**不登记** | `8c1b392e` · `dedupe_covers_the_whole_history_not_the_recall_window` |
| 空查询传空串 | 改 `Option`：`last_user_text -> Option<String>`、`recall_view(query: Option<&str>)`，内核折叠逻辑一行未动 ⇒ 行为逐字相同 | `050d6d11` |
| 配置两态无断言 | 走生产写口（VDFS `PLUGIN_FILE`）提交**部分字段**表单，断言内存槽与 `dir.load::<MemoryConfig>()` 逐字段相同 | `8c1b392e` · `config_write_leaves_memory_and_disk_in_agreement` |

**接线的前置条件写在账上，不是「以后再说」**（[ADR-110](../010-adr/110.md) 决策 3）：语义维要进排序，必须
同时解决「评测与生产同源」——`verify/recall_eval.rs` 用 `#[path]` 包含生产排序内核，是裸
`rustc` 单文件、拿不到真向量；先扩 `ScoreEntry` 只会把量具换成临摹件。撤销条件：**出现具体的
「近义表述搜不到」案例，或评测的 `dependency` 读数明显上升** ⇒ 按那条前置条件立项，
`vec` 与它的写方、索引、评测**同批**进来。

## 处理过程

- 2026-10-20 立批。来源：总报告 C6 + 10 报告 S-4 / S-6 / S-8 / S-9。
- 2026-10-20 为什么是 later：向量接线的成本高且会动写路径（记忆编码是热路径），
  而当前召回质量没有具体故障驱动；去重与可读性两项成本低但收益也小。
  撤销条件：出现「近义表述搜不到」的实际投诉，或编码成本成为可观测瓶颈 ⇒ 升级为 next。
- 2026-10-20 与 [T-200](200-记忆保真度口径裁决批.md "T-200-记忆保真度口径裁决批") 的分工：
  T-200 裁决**巩固的保真度口径**，本批处理**检索的兑现**（向量 / 去重 / 读数）——
  一个在写侧（巩固），一个在读侧（召回）。
- 2026-10-21 立批时那两张读数有两处不成立，按实测更正（这是裁决的依据，不是降标）：
  ① 「空查询 ⇒ 平凡值分支在生产里不可达」——取值点 `chat_loop/inputs.rs::last_user_text`
  当时写的是 `unwrap_or_default()`，取不到发言确实会喂一个空串进内核，所以段二不是纯
  可读性改动；② 「编码成本随会话历史线性增长 ⇒ 要窗口」——release 实测 2 万格一轮：
  把事实切片交回值（`range(0)`，ADR-084 的口径）≈9.8 ms，而在交回的切片上跑一遍全量去重
  投影 ≈0.14 ms。窗口砍掉的是这条链上最便宜的一节（约 1/70），代价是窗口外的同文被再记
  一条、重复那条继续挤占召回预算。两头一比，有界化是**负收益**，而它的收益本来就没有被测过。
- 2026-10-21 「去重窗口」参数因此**不登记**：登记一个测出来没有收益的旋钮，正是本仓点名的
  死旋钮形状（同一判据见 [T-130](130-个人认知体系注入.md "T-130-个人认知体系注入") §3.1 对
  无写方 tier 的处理）。留下来的是一条口径 + 一条把它钉住的判据，而不是一个参数。
- 2026-10-21 向量为什么不顺手接线（而不是删）：`grep '"vec"'` 全仓零个生产读方，召回投影只读
  `content` / `tag`，`ScoreEntry` / `RecallEntry` 里没有向量格；接线的账是把一次 ONNX 推理
  （bge-small-zh，CPU，`MAX_SEQ=512`）挂到每一轮两条编码上，再养一份与 WAL 双写的向量索引，
  去换换述评测 `dependency` 那 0.091 的残差——而唯一能说明「换来的确实更好」的量具会因上面
  那条前置条件失效。这笔账在本批算不过来，写进 [ADR-110](../010-adr/110.md) 的理由，撤销条件在本批上方。
- 2026-10-21 分段与提交：段一 `29290c39`（删键 + 判据从「恒空」升为「没有这个键」+ ADR-110
  + 三处文档口径同步）、段二 `050d6d11`（空查询 → `Option`）、段三 `8c1b392e`（两条新判据，
  lib 1955 → 1957）。段一带 ADR 同提交：那处形状变更的裁决与被淘汰面必须和改动一起可读，
  分两次提交会让中间提交的红绿没有归属。
