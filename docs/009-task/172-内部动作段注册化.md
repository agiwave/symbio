## 内容

父设计：[PL-014 §2.2](../004-plan/014-单环一表收敛.md "PL-014-单环一表收敛")（同一条需要只允许一种取得方式）·
[AR-025](../005-arch/025-capability-registry.md "AR-025-capability-registry") §2（收集口收敛的先例）

**这是 AR-025 在会话墙上的第二次实例。** 收集口那一次把 16+2+2 个方法收成
`put / get / list` 三个，判据是「加一族不用再往 core 加一个 trait」。会话墙上
同一件事还没做：

| 处 | 现在的形态 |
|---|---|
| `turn/dispatch.rs` | `run_ops::*` **15** 个动作常量 + `ALL` 闭集（授权判据第 3 条读它） |
| `session/plugin/run_actions.rs` | `dispatch_run_op` 的 **14** 个 `match` 臂（一个臂覆盖 `ADD_BY_RUNNER \| ADD_HERE` 两个常量） |
| `loop/session_port.rs` | `SessionPort` trait **14** 个方法（一动作一方法） |
| 同文件 | `impl SessionPort for LoopSession` 逐条委托 **14** 段 |
| 各调用点 | 每个动作一个 `self.port.xxx(..)` |

加一次交互要同时改这五处，且**没有一处会让编译器提示另外四处**——漏改的表现是
「新动作不在 `ALL` 里 ⇒ 授权层直接 `Forbidden`」，或者「臂加了、方法没加 ⇒ 编译
错误」（后者还算好的）。

## 与 AR-025 的差别：这里不能照搬

收集口朝向的是**开放扩展**（插件自己注册能力），所以行表按 `put` 增长。
内部动作段相反：**它是刻意的闭集**——
`session/plugin/run_actions.rs:70` 的授权判据第 3 条就是「`op` 不在 `run_ops::ALL`
里 ⇒ `Forbidden`」。所以机制化**必须保留「装配期可枚举」这个性质**：

- 行表在**装配期**（编译期常量表或组件装配时一次性构造）冻结，运行期不增不减；
- `ALL` 由行表派生，不再手写第二份——两份是这次要消掉的主要冗余；
- 授权层读派生出的 `ALL`，判据一个字不改。

换句话说：**这是一次「一份数据、多个视图」，不是一次开放注册。**

## 一条先要修掉的假守卫（本批第一刀）

`dispatch_run_op` 的末尾是：

```rust
// `run_ops::ALL` 已收口；新增词条而漏实现时由编译器在这里报错。
_ => Err(VdfsError::Forbidden(format!("内部动作未实现：{op}"))),
```

**那句话是错的。** 臂的模式是字符串常量，字符串不参与 `match` 的穷尽性检查——
新增一个 `run_ops` 常量而漏写臂，编译**照样通过**，运行期落到 `_` 返回
`Forbidden`。两处都错：以为有编译期保护，而实际的错误分类也不是「未授权」而是
「未实现」（`Forbidden` vs `Internal`）。

现在 15 个常量确实被 14 个臂全覆盖（`ADD_BY_RUNNER | ADD_HERE` 合一臂），
但这是**人工对账的结果**，不是机制。本批第一刀：给「`ALL` 的每个常量都有臂」
一条可执行判据，再动结构。

## 处理过程

**先答张力，再动结构。** 三个动作签名差异大（`messages` / `consolidate` /
`compression-begin` 的入参与返回都不同），行表的处理函数签名要统一，否则只能用
`trait object` 或泛型传染——两条都撞 `CS-001`（core 三格只降不升）。可行的出路是
把载荷统一成 `(op, Value) -> Result<Value>`：`dispatch_run_op` 现在**已经**是这个
形状，所以 `SessionPort` 那 14 个类型化方法可以退成**调用侧的便捷包装**，或者干脆
删掉、让调用点自己拼 `Value`——代价是丢掉编译期类型检查。这一条要在 ADR 里裁决，
不能顺手选。

**为什么排在 keys 环之前**：它是四处手写序列里收益最大的一处——五处 → 两处，且这
五处今天分散在三个文件、两个插件里。keys 环的收益是形状指标（用户与开发者都看不见
即时变化），动作段的收益是「下次加交互少改三处」——同一条判据（加一样东西要改几处）
下，它更靠前。
