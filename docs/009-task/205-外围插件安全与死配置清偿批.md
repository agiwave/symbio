## 内容

父设计：12 报告建议 4 / 6 / 7 / 8

**四项的共同形状**：**同族两实现，一有一无**。

| 项 | 一处有 | 一处没有 |
|---|---|---|
| 私网地址检查 | 通用 HTTP 工具 | `web_fetch` |
| `build_ctx` | gateway 自己写一份 | 桌面端命令层再写一份（同构拷贝） |
| 匹配器过滤 | 配置条目里有 `matcher` 字段 | 执行器从不读它 |
| 配置项生效 | 部分键有读方 | `streaming_enabled` 无读方、`web_timeout` 不生效、白名单构造期快照 |

**「同族两实现」为什么值得单独一批**：它不会红、不会崩，只会让**同一类操作有两种行为**。
用户看到的是「为什么 web_fetch 能访问内网、web_search 不行」这种没法解释的差异，
而排查要读两个插件的两份实现——这类债的利息是**认知成本**，不是缺陷。

**两处改动会改变既有行为**（必须写明）：

- `web_fetch` 补私网检查 ⇒ 可能挡住某些合法的内网调用，README 要写清；
- 白名单改动态 ⇒ 改配置不再需要重载，但「构造期快照」原本隐含的稳定性消失了。

**删除优先于实现**（原报告取向）：`streaming_enabled` 无消费方，删掉比补上便宜；
`matcher` 若无真实使用场景，删字段比接上便宜——「没人调用的能力比没有更糟」是本仓的既有判据。

## 处理过程

- 2026-10-20 立批。来源：12 报告建议 4 / 6 / 7 / 8。
- 2026-10-20 原报告建议 10（`config_definition()` 三份手写表）**不做**：底层已单点，
  剩下只是描述，成本高收益低；理由记在转化台账 §7-6。
- 2026-10-20 与 [T-194](194-入站边界加固批.md "T-194-入站边界加固批") 的分工：T-194 是入站
  （别人打进来），本批是出站与外围残余（我们打出去 / 配置是否生效）。
- 2026-10-20 排序说明：这批全是 later 档——不是因为不重要，而是它的收益是认知成本而非
  正确性，在机制面收敛（now / next 两档）之后做，才不会与它们争同一批文件的改动面。
- 2026-10-21 `build_ctx` 的落点是 **core 的 `PluginSimpleRequest::from_parts(payload, metadata)`**，
  不是各插件里的又一层包装：两份拷贝的差异只在「Metadata 中的字符串怎么存」（一份存
  `String`、一份存 `Value`），合并时取 `String`——它正是 `PluginInvokeRequestExt::get::<String>`
  期望的值类型，行为与两份原实现等价。core 根的 `PLUGIN_PAYLOAD_KEY` 随之收窄（唯一跨 crate
  消费者消失，`core-export-audit` C-003 由 1 降回 0），不再占根出口。
- 2026-10-21 出站守卫按 **IP 语义**判而不是字符串前缀：前缀比较只认得出字面 `127.0.0.1`，
  `127.0.0.2` / `0.0.0.0` / `::1` / `::ffff:127.0.0.1` 全都漏。判据放进 `net_guard.rs` 供两个
  工具共用，而不是在 `web_fetch` 里再抄一份——那正是本批要清掉的「同族两实现」。
  注意它仍是**字面判定**：域名解析到内网（DNS rebinding）不在本层的能力边界内，登记为已知残余。
- 2026-10-21 `web_fetch` 的补丁是**行为变化**：模型不能再借它访问本机 / 内网服务。e2e t65
  因此改判据——本地靶子从「取正文」改为「拒绝先于发请求，靶子零请求」；真实的 200 / 404 /
  超时投影在无外网 CI 上没有靶子可打，元数据头形状改由 `web_fetch.test.rs` 单测钉住。
  覆盖矩阵 [RE-005](../006-ref/005-e2e覆盖矩阵.md "RE-005-e2e覆盖矩阵") 同步记下这三条投影失去 e2e 锚的取舍。
- 2026-10-21 `web_search` 统一读 `web_timeout`，同时把配置读锁缩到入口：一次搜索最长可跑
  一个超时周期，持锁跨 `await` 会让「保存配置」被在途搜索堵住。
- 2026-10-21 死配置删除而非实现：`matcher` 无执行器读方、`streaming_enabled` 无消费方，
  补实现等于给没有需求的面增加机制。「没人调用的能力比没有更糟」；配置文件里的旧键由
  serde 默认「忽略未知字段」接住，无需迁移代码。
