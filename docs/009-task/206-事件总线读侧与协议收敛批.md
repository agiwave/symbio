## 内容

父设计：08 报告建议 7 / 8 / 9 / 10 / 11

**这一批是事件面的「协议债」**，各项严重度不同，但都指向同一个问题：
**事件总线今天更像「一条变更通知管道」，而名字与类型暗示它是一个通用总线。**

| 项 | 现状 | 后果 |
|---|---|---|
| 背压兜底 | 帧没有投递序号，兜底是一条 `resync` 指令；**并非每个订阅者都认它** | 漏认的那一方把「你可能漏了帧」也丢了：子智能体转播桥会一直等到父会话中止 |
| 读数与读侧闸 | 全量读数口径写在各调用点（26 处）、内容侧可见域取值与「属主 ∨ 矩阵」判据各写几处（段二核实的实情，原表记的「11 处直调、读侧闸与快照不一致」归因不准——调用点的**作用域**本就该不同） | 口径写错一寸是静默少读事实；判据写两份会漂成「stats 给看、召回不给看」 |
| 名实 | 叫总线，实为 VDFS 变更通道（`kind` 闭集只有 `system` / `vdfs`，业务发布点只有 vdfs 宿主一处） | 认知债：后来者按「总线」的期待设计，发现不是（段三已裁决：契约收缩到兑现的那一条，见处理过程） |
| 事件名 | 字符串匹配 + 静默分支 | 32 个常量靠字符串对齐，拼错即静默 |

**「帧序号」这一项不是债，是已裁决的取舍**：[ADR-025](../010-adr/025.md) 定了「顺序是**节点属性**
（`ChatNode.seq`），不是投递属性」，丢失靠**幂等重读**兜底而不靠序号。本批因此不动信封形状，
要做的是**把那条兜底契约真正兑现**——它今天只对部分消费方成立。

**订阅请求的 `kind` 过滤**（原建议 10）**已闭合，且闭在「删字段」这一支**：
`EventBusSubscribeRequest` 现在是空结构体（`event_bus/mod.rs` 写明「一个看起来能用、实际被
静默忽略的字段比没有更危险」），服务端过滤的真正落点是 `vdfs/watch` 的登记表——未登记的
路径根本不会进总线。这一项与「名实」是同一个裁决的两半（不做多频道总线 ⇒ 不做服务端
`kind` 过滤），两半现在一致了。

- 2026-10-21 段二（**读数与读侧闸各归一个写法**，不动任何一处的作用域）：
  先按「直调」的字面把 11 处逐个读了一遍，结论是**表里那一行写错了归因**——这些调用点
  重复的不是「读哪一份事实源」（那本来就该不同：本会话 WAL、跨会话 fleet 快照、已过闸的
  切片），重复的是**另外两件事**，而它们各自是一条事实：
  ① **读数口径**：`apply(events, i64::MAX, Budget::generous())` 在 26 个生产点各写一遍，
  写错一寸（`now` 给小、预算给窄）是**静默少读事实**。抽成 `Projection::read_all(events)`
  （[symbio/src/symbio_core/projection/mod.rs](../../symbio/src/symbio_core/projection/mod.rs)），
  25 处生产调用改为具名口径；**有意的窄读数刻意留在 `apply` 上**（召回扫描配额
  `RECALL_SCAN_QUOTA`、运行态小状态机的当前窗口）——窄是判据，不能被一个「全量」的
  名字吃掉。`reasoner::render_messages` 同款换名，它读的口径与写侧基线累积无关，
  作用域仍由上游 `turn_runner/facts.rs` 把门。
  ② **读侧闸那一条判据**：内容侧可见域的取值此前有三份写法（`payload["vis_scope"]` +
  `from_name` + 缺省），「属主恒放行 ∨ 矩阵判定」有两份。收成 `VisScope::of_event(&Event)`
  与 `authz::content_visible(scope, viewer)` 各一个（[symbio/src/symbio_core/authz.rs](../../symbio/src/symbio_core/authz.rs)），
  `session/stats` 的整列闸与召回的逐条预过滤都改为调用它，各自只保留**自己那一层作用域**
  的分支（stats 要表达「未声明读方 = 全量」，召回要表达「别处的 `thread_private` 连属主
  也不进召回」）。写侧三处 `"vis_scope"` 字面量**不动**：两处嵌在 `json!` 的键位上
  （宏不吃常量），一处与它们同源——键名是线上取值，单源化在**读侧**才有意义，
  只改一处反而造出第二种拼法。
  判据：`read_all_is_the_named_form_of_the_full_reading_dialect`（具名 ≡ 旧写法，逐格相等，
  含 as-of 那格的 `i64::MAX`）、`read_all_never_degrades_even_on_an_empty_slice`（空切片是
  「这里没数」不是「截断了」）、`vis_scope_of_event_only_ever_widens_on_an_exact_spelling`
  （测试侧故意写字面量键，产侧改名必红；大小写/近似拼写/非字符串一律落回最窄）、
  `the_read_gate_is_owner_or_membership_in_one_judgement`（删掉属主支即红——`user` 不在
  能力表里，单问 `can_see` 连自己的 `shared` 都读不到）。
  **两处时钟差保持原样**（`derived_facts.rs`：判据读的是刷新后的快照、写进事实源的
  载荷取当轮增量）：两侧各有文档说明「为什么必须重读」，改它是一次没有事故驱动的行为变更，
  不属于本批的「收敛写法」范围。
- 2026-10-21 段三（**名实对齐 = 把契约收缩到兑现的那一条**，建议 11 的裁决）：
  两个选项按本仓的标尺判过：
  ① **真做成多频道总线**（服务端按 `kind` 分流 + 新增频道）——今天业务发布点只有一处
  （vdfs 宿主的变更投递），消费方**四个全部按地址分派**，没有任何一方需要第三频道；
  为兑现一个名字去加一层路由，是拿机制面付名字面的账，且服务端 `kind` 过滤正是
  2026-09-26 那次「删字段」裁决否掉的东西（一个看着能用、实际无人消费的过滤器）。否决。
  ② **诚实命名为变更通道**——`event_bus` 是插件身份、`bus_event` 是跨栈线上名
  （前端 / `cli` / telegram / 转播桥四方都在解它），改它们是一次协议变更（旧连接当场失联）
  而**不是**认知修正；认知债的账主是说清契约的那段文字。选这条并落地：
  `symbio_core::event_bus` 模块头现在写明「一条进程内广播通道：频道闭集两条、帧只有两种、
  分发在消费方自己那一侧按地址做、服务端不过滤」，并写明要做多频道总线的前置条件（先立 ADR）；
  `plugins/event_bus/plugin.rs` 的「设计目标」改成它实际做的三件事（单连接 / 原样广播 / 握手），
  「中央路由」这一条是名实不符的正身（它不路由任何东西）；插件 README 与
  `docs/005-arch/004-PROTOCOLS.md` §事件总线频道各补一条同方向的裁决句。
  判据：本段不动代码形状，验收面就是那四处文字与 `E-008` 的 `kind` 词表双向比对
  （文档与常量同改才不红）——名实这条债的形态本来就是「文档说得多、代码兑现得少」。
- 2026-10-21 段四（**事件名 ↔ 格位收成一份数据 + 唯一写入口判它**，建议 7 的转化）：
  先按建议的字面形状（`EventKind` 枚举）判了一次，结论是**换成表**，两条理由都是硬的：
  ① 冻结锚点 F5 与 `PL-01 §6`「名字是数据，加名字不加枚举」——加了 `EventKind` 枚举，
  「加一个名字」就变成「改 core 的枚举」= L-schema 变化（要 ADR），把一个数据面问题
  升级成机制变更；② `kind` 是跨栈线上名（帧里、WAL 行里、前端与 `cli` 里都是字符串），
  枚举要么在边界上多一次转换，要么动协议。J3「网格之外的事件编译不过」钉的是**行与列**
  这两维（字符串确实写不出第 12 个实体，编译期已经在管），名字这一维本来就是数据，
  能给它的最强约束是**入库时对齐**——与 `ts = 0` 同一条纪律（逐构造点手收必然再漏，
  故收口在入库处）。落地形状三件：
  ① [`symbio/src/symbio_core/event/grid.rs`](../../symbio/src/symbio_core/event/grid.rs)：
  `名字 → 格位` 的表（32 行 = 名字表的 32 个事件名常量；两条 `EVENT_TRIGGER_*` 是写体键名
  与它的取值，不是事件名，故不入表）＋判据 `event_cell` ＋读侧口径 `Event::grid_cell()`；
  ② 强制点在**唯一写入口**：`WalInner::gate` 把这一臂排在 I2 / I1 / I3 **之前**——那三条
  判据全按 `(entity, verb, kind)` 取事实，坐标本身错位时它们读到的输入就是错位的；
  ③ 新拒绝形态 `AppendError::OffGrid { event_id, kind, declared, given }`（不住 `invariants`
  域、不占 `StoreInvariant` 的一条：I1/I2/I3 判事实**之间**的关系，这一条判事件自己的
  契约自述）。**覆盖是自迫的**：表上没有的名字落不了格，所以不需要为「忘了登记」再加一条门禁脚本。
  **迁移账**：全量单测（1939 条）在闸门上跑通，生产构造点的三元组**本来就一致 ⇒ 无需修数据**；
  唯一不合规的是 `plugins/session/plugin/run_actions.test.rs` 手搓的一条溯源锚
  `"session.probe"`（`System × Opened`，表上无此名）——换成表上的 `system.triggered`，
  而不是把编出来的名字加进表。顺带同源一处：`invariants::is_turn_open` 里的
  `"user.message"` 字面量改引常量（比较里拼错是**恒假**，开轮闸会静默失效）。
  与 `PL-01 §6` 的分工写进 `grid.rs` 模块头：方案的表拥有**行与列**（DC-005 已断言行数
  = 枚举变体数），代码这张表拥有**名字 ↔ 格位**——§6 自己写明「这张表是语法的闭集，
  不是事件的闭集」，名字列表不在它的所有权里。
  判据 5 条：`the_table_is_one_row_per_name_and_covers_every_declared_name`（一行一名，
  条数 ≡ 事件名常量数）、`event_cell_answers_only_the_exact_spelling`（拼错 / 大小写 /
  只命中前半段一律「不在表上」，不猜一格）、
  `the_table_agrees_with_the_read_side_about_which_cell_carries_a_node`（表 ≡ 读侧三目 `match`：
  正着读要 `Some`、挪一格要 `None`——那条 `None` 就是原先的静默失效现场）、
  `the_grid_gate_rejects_a_name_that_is_not_on_the_table`（`declared: None`，不消耗 seq、不落盘）、
  `the_grid_gate_rejects_a_name_claiming_another_cell`（同一事件**同时**缺溯源时仍答 `OffGrid`——
  排序可审；同名字回到同格照落）。
