## 内容

父设计：08 报告建议 7 / 8 / 9 / 10 / 11

**这一批是事件面的「协议债」**，各项严重度不同，但都指向同一个问题：
**事件总线今天更像「一条变更通知管道」，而名字与类型暗示它是一个通用总线。**

| 项 | 现状 | 后果 |
|---|---|---|
| 背压兜底 | 帧没有投递序号，兜底是一条 `resync` 指令；**并非每个订阅者都认它** | 漏认的那一方把「你可能漏了帧」也丢了：子智能体转播桥会一直等到父会话中止 |
| 网格直调 | 11 处直接调投影，含热路径 | 读侧闸与快照可能不一致；加一道读侧闸要改 11 处 |
| 名实 | 叫总线，实为 VDFS 变更通道（`kind` 闭集只有 `system` / `vdfs`，业务发布点只有 vdfs 宿主一处） | 认知债：后来者按「总线」的期待设计，发现不是 |
| 事件名 | 字符串匹配 + 静默分支 | 32 个常量靠字符串对齐，拼错即静默 |

**「帧序号」这一项不是债，是已裁决的取舍**：[ADR-025](../010-adr/025.md) 定了「顺序是**节点属性**
（`ChatNode.seq`），不是投递属性」，丢失靠**幂等重读**兜底而不靠序号。本批因此不动信封形状，
要做的是**把那条兜底契约真正兑现**——它今天只对部分消费方成立。

**订阅请求的 `kind` 过滤**（原建议 10）**已闭合，且闭在「删字段」这一支**：
`EventBusSubscribeRequest` 现在是空结构体（`event_bus/mod.rs` 写明「一个看起来能用、实际被
静默忽略的字段比没有更危险」），服务端过滤的真正落点是 `vdfs/watch` 的登记表——未登记的
路径根本不会进总线。这一项与「名实」是同一个裁决的两半（不做多频道总线 ⇒ 不做服务端
`kind` 过滤），两半现在一致了。

- 2026-10-20 立批。来源：08 报告建议 7 / 8 / 9 / 10 / 11。
- 2026-10-20 与 [T-187](187-投影签名兑现批.md "T-187-投影签名兑现批") 的分工：T-187 管
  「投影的签名与纯度」（读侧的形状），本批管「事件总线的协议」（帧、订阅、名字、直调出口）。
  两者都在事件面，但一个在投影层、一个在传输与协议层。
- 2026-10-20 一处顺序：kind 过滤（建议 10）与名实对齐（建议 11）应同批裁决——
  若决定「不做多频道总线」，那 kind 过滤就该改名而不是实现；两件事分开做会自相矛盾。
- 2026-10-21 **撤销条件命中，升为 next**（本批自己写的升级判据：出现一次「断线后状态
  不一致」的实际事故）。核对五项前提时发现：
  ① `kind` 过滤一项**已闭合**（2026-09-26 删字段，早于立批），本批据此把表里的两行改成
  一条「背压兜底」——真正的债是**契约没被每个订阅者兑现**，不是缺序号；
  ② 事故实例找到了：`plugins/agent/host/subagent.rs` 的转播桥把解不出变更的帧一律
  `continue`，也就是**把 `resync` 指令一起吞掉**，而「会话节点离开 `working`」是它
  「本轮结束」的唯一判据——漏掉那一帧它就再也收不到结束，一直等到父会话中止。
  它是本仓**第三个**手写这份判别的消费方（`cli` 与 telegram 各写了一份，它一份没写）：
  产帧方与解帧方各写一份、漏写无人发现，正是 `event_bus_vdfs_change_of` 存在的那个理由。
- 2026-10-21 段一（**解帧入口合一 + 契约补齐**，不动线上形状）：
  ① core 新增 `event_bus_resync_of(frame, kind)`，与 `event_bus_vdfs_change_of` 成对——
  「一帧要么是变更、要么是指令、要么不归本频道」从此在本域钉住；`resync_marker` 改走
  `event_bus_build_envelope`（它是自己声明的唯一构建入口，此前是第二份手搓的 `json!`）；
  ② 转播桥补 resync 臂：按自己的作用域重读会话运行态，判据抽成 `turn_end_of`（两个读数
  来源——变更帧自带的载荷、resync 后的回读——共用一份，与 `cli` / telegram 同一条）；
  ③ telegram 的 `is_resync` 与 `cli` 的 `bus_frame_of` 各删掉手写判别，改为引用 core；
  ④ 文档：`plugins/event_bus/README.md` 与 `docs/005-arch/004-PROTOCOLS.md` §事件总线频道
  补上「帧只有两种、解包入口只有一个对」「每个订阅者必须认这条指令」与四个消费方的名单。
  判据：`resync_of_recognizes_the_markers_this_module_produces`（产的标记要认得、且**解不出
  变更**、跨频道不误认）、`resync_of_unwraps_the_bus_envelope`（手搓线上形状同样认得——
  产帧方漂移必红）、`a_real_change_is_not_a_resync_marker`（两条入口互斥，消费方的
  「先试变更再试指令」顺序靠它成立）、`turn_end_of` 三格（working / 正常收尾 / 带错误）。
