## 内容

父任务：[T-156-架构机制化与旧代码清理批](156-架构机制化与旧代码清理批.md)
依据：[ADR-055](../010-adr/055.md "ADR-055")（core 形状棘轮：只许降不许升，收窄不需要批准、变宽需要论证）·
判据 J3（静默失效 → 必须做成断言）· AGENTS.md「不要拿机制面去付实现面的账」

**问题**：本仓有一套成熟的**可执行审计文化**——五个 core 审计 + 两个专项审计，每条判据都能红、
都带基线与回归测试。但**这套纪律只覆盖 core，插件层是空的**。

后果不是理论风险，而是本批**另外三条子任务各自照出了一次回流**：

| 回流类型 | 实例 | 今天的守卫 |
|---|---|:-:|
| 工具执行流程按工具名字符串判定 | `tool_executor.rs:1164` · `delegation.rs:39` | 无 |
| 协议层新增供应商 `if` 而不落档案表 | 三个协议各写各的 `max_tokens` 下限 | 无 |
| 冻结字段无生产读方（假机制） | `ActorSpec.pattern` · `ClassifyOnly` | 无 |

**这三条都能在合入时被一条守卫挡住，而不是等下一轮架构复盘再人工发现。**

## 处理过程

- **不是新机制，是平移**：照 `core-shape-audit.mjs` 的形状（提取 → 比基线 → 变宽判红 →
  基线可降不可升 → 带回归测试）做插件层的对应物。
- **首版守两条**（与本批子任务一一对应，判据即出口）：
  1. **特判审计**：`plugins/session/tools/**` 下对工具名的字面量比较判红（存量按基线压住）；
  2. **供应商审计**：`plugins/model/protocols/**` 下新增的供应商特判分支须落在档案表里
     ——这条依赖 [T-161-模型供应商参数档案表化](161-模型供应商参数档案表化.md) 先落地（有了表才有判据）。
- **第三条（假机制）单独议**：「字段有定义无读方」的判据需要跨文件的读方统计，
  形态上接近 `core-export-audit` 的消费方计数，成本更高，可作为本条的第二版。
- **基线纪律照搬**：存量判红会立刻炸一屏，须按棘轮惯例压进 `BASELINE`（`T-032` 已指出
  「BASELINE 是源码常量可被静默下调」的弱点，新守卫要一并考虑）。
- **依赖关系**：条目 2 依赖 [T-161-模型供应商参数档案表化](161-模型供应商参数档案表化.md)；
  条目 1 与 [T-158-工具名硬编码归一为能力元数据](158-工具名硬编码归一为能力元数据.md) 同向（那条做归一，这条防再散）。

## 落地

`scripts/plugin-special-case-audit.mjs`，五条判据各自钉一种「同一份逻辑被抄成特判」的**形态**：

| 码 | 判据 | 为什么它一定是特判 |
|---|---|---|
| SC-001 | 工具名以字面量进**比较位置**（`==` / `!=` / `starts_with` / `ends_with` / `contains` / `matches!`），扫 `plugins/session/**`（非测试） | 工具名是注册表里的事实，比较它就是按名分流；分流该由工具自声明的能力给出（T-158） |
| SC-002 | 协议层的**预算 wire 键**直接跟数字字面量，扫 `plugins/model/protocols/**`（非测试） | 预算是协议约束的取值，唯一的家是 `protocols/profile.rs`（T-161） |
| SC-003 | 档案表里的**思考字段名**在协议层被当作 delta 读字段（`get("x")` / `delta["x"]` / `path.is(&[…"x"])`） | 整行解析与前缀提取必须认同一份名单，抄第二份的代价是前缀截断重复或吃字 |
| SC-004 | **供应商名**进 if 式判据（`match` 臂不判——那是别名登记表） | 「这家网关要特殊处理」是数据，不是分支 |
| SC-005 | 豁免注释**悬空**（本行与上一行都没命中） | 登记了而代码没了，等于判据对那一处永久失效（`panic-audit` 的 PN-003 同族） |

**两份名单都不另写**：工具名从 `facts/_capability.mjs` 的 `toolFacts` 提取（关于整个仓库的事实），
思考字段名从 `profile.rs` 的字符串字面量提取——档案表加一个键，SC-003 自动跟上。
唯一手写的是**判据自己的定义**（哪些键算预算、哪些名字算供应商），那是本文件的职责。

**比较位置不含 `=>`**：`protocols/mod.rs` 的别名表就是一张 `match`，那是同一份数据换个写法；
不含 `unwrap_or("ask_user")` 与 `.get("heartbeat")`：缺省值与键名不是「按名判身份」，
把它们算进来豁免会写满整个仓——这两处是真实仓库里的现成写法，回归测试逐条断言不误报。

**失效形态**（回归测试 13 条，正反各钉一头）：工具名集合读不出来 ⇒ exit 1（不许「读空即全绿」）；
注释与 `.test.rs` 不触发；`"anthropic-version"` 这类头名不误判成供应商分支。
行号保真是刻意的：注释剥离走本文件自带的 `blankComments`（`rust-scan.stripComments` 会连换行
一起吃掉跨行块注释，行号上移后豁免会挂到别人身上——那比不豁免更坏，因为日志显示「已登记」）。

**第三条判据（假机制）留作第二版**：需要跨文件的读方统计，形态接近 `core-export-audit` 的
消费方计数，成本更高。本条不假装它已经守住了。
