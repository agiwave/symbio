## 内容

父批次：[T-230 内环收口批](230-内环收口批.md "T-230-内环收口批") ·
父设计：[PL-016 · 义务环](../004-plan/016-义务环.md "PL-016-义务环") §2.6 ·
边界裁决：[ADR-118](../010-adr/118.md "ADR-118") ·
终点语义：PL-014 §2.1（`agent = fixpoint(decide) over (事实日志 × 世界端口)`）。

T-227 步 5 把循环从 `turn_runner` 移到了 `turn_exec::drive_steps`：

```rust
let mut flow = match TurnRunner::begin(...).await? { ... };
loop {
    if let Some(outcome) = flow.step(...).await? { return Ok(outcome); }
}
```

运行器不再持有模型 / 工具循环（判据 1 的扫描面为空），但**驱动权仍在执行器**，
不在引擎。`decl::ring::drive`（取最小可还债）今天标着 `#[cfg(test)]`——它只在
优先级用例里被调用，尚未成为生产调度口。

本任务把这一步走完：引擎读全量欠账 `owed`、取最小 `drive`、派发对应执行体、
按契约处理失败 / 取消 / 无进展 / 租约；`drive_steps` 的手写循环消失。

**这不是「换一个地方写同一个循环」。** 换的是**依据**：从「执行器知道下一步该跑
哪一步」变成「引擎从行表读出来」。所以引擎与执行体的边界必须先裁决：

- 执行体只做「一件事」，返回事实或错误；不读别的行、不做调度判断；
- 引擎持有单写者与停机判据；事实的追加仍只经存储；
- 视图求值仍是纯函数（ADR-115 决策 1），引擎不把内存状态塞回输入。

**停机判据没有搬家**（T-227 步 5 的口径）：步数上界、无进展守卫、租约重试必须在
引擎侧原样保留；它们不是调度器的可选优化，是 ADR-115 决策 3–4 的契约。

## 处理过程

- 2026-10-22 立项。来源：T-227 形态偏差②（「读行债 → 派发」的引擎调度仍是
  T-216 / PL-016 的剩余迁移）+ 核对 `turn_exec.rs:783` 的 `loop` 与
  `decl/ring.rs` 里 `#[cfg(test)]` 的 `drive`。
- **为什么 `prio: later`**：它是本批最大的一步，且前置 T-232 决定行表里有
  集合展开；在行表形状稳定之前动调度器，会把两个变量混在一次改动里。
- 先做引擎 / 执行体边界的 ADR，再拆实现提交；边界没裁决之前不改调度。
- 2026-10-22 设计先行：[ADR-118](../010-adr/118.md "ADR-118") 裁决
  `drive` 是唯一选债口、派发器按 `by` 寻址、轮内草稿归派发器、三段工具债各自由
  一行执行体承担、停机判据留在派发器。实现按 ADR「后果」的三段提交拆，先在
  行为等价的前提下把驱动权换过来，再拆模型 / 工具，最后删 `resume.rs` 旁路。
- 2026-10-22 步 1（预备）：`stream_round` 拆成 `model_round`（一次模型往返 +
  分类，请求工具时寄存应答）与 `tool_round`（一批工具派发 + 产物 / 等待 / 交换）；
  `Prepared` 加 `pending_model` / `pending_round` 两个草稿寄存位。`stream_round`
  仍是两者的组合入口，行为等价；`turn_runner` 44 条用例、lib 2036 通过。
  下一步把 `announce(model)` 移出 `call_model`，由派发器按 `drive` 选
  `dispatch-model` / 工具批。
- 2026-10-22 步 2（ADR-118 后果 1）：`decl::ring::drive` 去掉 `#[cfg(test)]`，
  `drive_steps` 改为「读本轮切片 → `loop_rows::next` 选最小可还债 → 跑一个执行体」，
  手写的 `begin` / `step` 推进条件消失；`StepFlow` 只交出 `turn` / `exhausted`。
  过渡态：执行体注册表尚未接线，选中任一债都仍由整轮执行体跑一步
  （`dispatch-*` / `open-tools` / `authorize-tool` 在内部处理，`policy.report`
  由轮边界钩子触发）——选中的行只进 debug 日志，不据此停轮。新增无进展守卫
  （每步比较日志头，事实没长 ⇒ `exhausted{no_progress}`）与 `loop_rows::next`
  三条用例（空表 / 开着的幕 / 收束后）。
  续写幕的 `resume` 旁路保留到后果 3 的提交。lib 2039 通过、e2e 78/78 通过。
  剩余：后果 2（拆 `dispatch-model` 与工具三行、`TurnSession` 承接草稿）与
  后果 3（删旁路并补租约 / 步数上界用例）。
- 2026-10-22 步 3（ADR-118 决策 4 的第一半）：`StepFlow` → `TurnSession`，
  `step`（一轮 = 模型 + 工具）拆成 `model` / `tools` 两个动作；`stream_round`
  组合入口退役。派发器按**自己持有的草稿**选动作（有寄存工具批 ⇒ `tools`，否则
  `model`），步数上界与无进展守卫移到派发器；`turn_runner` 从此只回答「一个动作
  发生了什么」。行为等价（模型步与工具步连续执行，`t27` / 步数上界用例不动）。
- 2026-10-22 步 4（ADR-118 后果 2 收口）：派发器按 `by` 查执行体注册表，粗端口期
  只有 `execute` 一档。`DispatchPort` 打包契约退役，工具批次拆成三个动作
  `open` / `authorize` / `dispatch`（`tool_dispatch::ToolDispatch`），分别只写
  `request` / `authz.*` / `sent` + 结果；`DispatchOutcome` 随之下沉到插件（生产消费方
  只有本插件）。测试侧的步驱动改为直接调生产 `turn_exec::drive_steps`，不再复制一份
  循环——步数上界与无进展守卫的用例现在测的是生产路径。
- **选债面与注册表同源（实测纠偏）**：首版把「表头那一笔」直接查注册表，未覆盖的
  `by` 一律按 `no_progress` 收束——`t23` / `t24` / `t27` / `t78` 四条 e2e 因此超时
  （粗端口期 `policy.*` 与三笔工具债本来就由整轮执行体内部完成，它们却被表头选中）。
  修正：`drive` 多收一个注册表谓词 `accept`，只有 `by` 有执行体的债才参与裁决；
  `Executor::accepts` 同时是谓词与查表函数，「能选中」与「有人跑」构造上同真。
  守卫用例 `accept_skips_rows_without_an_executor` 钉住「未接线行不被选中、也不挡住
  更小的已接线债」。四条 e2e 单跑复绿。
- `resume` 旁路**保留**：`turn_head` 是单一全局表头，恢复一段已被后续轮次归档的
  旧轮时它指向新轮（用例
  `an_open_turn_archived_by_the_next_turn_is_still_the_resume_anchor` 钉住）；
  删它要先让表头按轮参数化，属另一次裁决。「执行体返回空 ⇒ `no_progress`」
  按构造不可达（每个生产动作至少写一格；无通道的工具请求在模型段已按 config
  gap 收束），守卫保留为不变式检查。
