## 内容

报告的问题（用户口径）：**「使用当前应用无法正常会话，特别是中断后的连续对话」**。

判据不能靠读代码立——本批把它换成一台真实负载：**用应用自己的 CLI、接本机模型
（`.symbio/model/LMStudio/provider.json`，`lfm2.5-24b-a2b`），指挥它自己产出一份本仓质量报告**。
这条负载同时压到了六个面：长轮次、工具循环、实时反馈、中断与接续、审批、上下文体积。
七处缺陷都是在这条负载上实测出来的，逐条拆成子任务（各子任务独立可回退）：

已在本批落地的两处（不需要子任务，记在「处理过程」）：CLI 把开场白/进度播报错投 stdout（修成 stderr），
`PATH_DESC` 缺「绝对 POSIX 地址会变影子树」这一格警示（补写），README 的 CLI 产物路径改正。

**用户口径的那句话经实测拆开后，「接续」这一半其实已经是好的**（杀掉进程再 `-s` 回来，
模型能原样复述被中断的任务），坏的是另外三件事：**轮中无反馈**（像卡死）、
**草稿当答案**（长度截断时）、**记忆劫持**（旧任务的祈使句被当成后续指令接着执行）。
本批因此按这三条排优先级。
