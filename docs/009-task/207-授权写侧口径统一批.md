## 内容

父设计：13 报告建议 5 / 6 / 9 / 10 / 13

**这一批是治理面剩下的「口径与手写同步」**，五项都不改判定方向（方向已由
[T-177](177-授权与声明面fail-closed批.md "T-177-授权与声明面fail-closed批") 与
[T-178](178-过度机制清偿批.md "T-178-过度机制清偿批") 定），只改**同一件事有几个说法**：

| 项 | 现状 | 后果 |
|---|---|---|
| 写出口径 | 按名判与按部署表判两个函数，差异未命名 | 读代码的人不知道「为什么淘汰面只认部署表」 |
| 能力闭集 | 枚举 + 名转换 + 字符串常量三处手写 | 加一个能力要改 3 至 4 处，漏一处即静默 |
| 淘汰闸输入 | 收别人折好的布尔（`delegation_revoked`） | 闸无法自证，审计要回到调用方 |
| 淘汰恢复 | 恢复事件只有测试构造器 | 诚实缺口与假缺口无法区分 |
| 淘汰阈值 | `THRESHOLD = 0` | 无梯度淘汰是否需要分档，没人复核过 |

**为什么是 later 而不是 next**：这些是**口径债**，不会造成错误行为（判定方向是对的），
但会让下一个改治理面的人多读三个文件。其中两条（淘汰闸事件入参、淘汰恢复）需要先过架构讨论——
[ADR-086](../010-adr/086.md "ADR-086") 的「值注入」边界是刻意裁决，动它要论证，
不是实现困难就可以改（[PL-006 §3 纪律 0](../004-plan/006-分步实施计划.md "PL-006-分步实施计划")）。

**一条允许「只写理由」的出口**：淘汰恢复若决定不做，正当做法是**在 ADR 里把「不可自动恢复」
记为永久边界**——一个诚实的缺口比一个假缺口好；反过来说，把 `#[cfg(test)]` 的构造器当成
「已实现」才是本批要消灭的形态。

- 2026-10-21 段一（项 6，枚举手写同步）：`governance` 的 `closed_set!` 用一张声明表
  同时生出**枚举体 + `name()` + `parse_name()`**，`Capability` 与 `VisScope` 同族各用一次；

  `capability_names_round_trip_through_the_declaration_table` 钉住（闭集外的名字必须
  `None`，两个下游方向都是拒）。
- 2026-10-21 段一同时收掉一处**已经在漂的口径**：能力枚举实为 6 项（PL-001 §7 表
  「否（6 个封顶）」列出六项），而 `authz` 模块头、`governance` 的散文与两条运行期
  文案、`symbio_core/mod.rs` 出口注、`symbio_core/README.md` 两处、PL-001 §4 字段注释
  共 7 处写着「7」——**数字写进散文就会漂**。收口口径：运行期文案不再报数
  （「不在能力闭集内」，报数对判据没有增益），代码散文只说「能力闭集」，
  **封顶数只留在 PL-001 §7 那一处**（owner）。
- 2026-10-21 段二（项 5，两套写出口径）：**差异不消除，命名收口**。`EffectiveMatrix`
  的两个读数在代码与 [ADR-100](../010-adr/100.md "ADR-100") 里同名定死——**合流面**
  （`can_write` / `can_write_name` / `can_reply` / `can_produce_artifact` / `grants_of` /
  `grant_names_of`，绑定行替换部署行）答「现在能不能做」，**部署事实面**
  （`deployed_can_write_name` / `is_deployed`，只认 `ROWS`）答「这台机器部署过谁」。
  ADR-100 新增一节写清**淘汰面为什么只认部署表**（三条：裁决对象必须在裁决之后仍被找得到、
  绑定行里的 `assign.work` 只是父行的影子、永久事实的判据必须同样永久），并如实写下
  效果：只靠绑定行运作的主体不进淘汰面。判据仍是 `the_elimination_face_ignores_bindings`。
- 2026-10-21 项 9（淘汰闸输入）：**不改，按既有裁决结案**。[ADR-086](../010-adr/086.md "ADR-086") §4
  的「`elimination-revoked` 为什么只回布尔」已经把这条讨论走完：部署级全量事件过墙再折
  布尔是 P6「值注入」的反面，折叠判据（`GrantsOverlay` / `verdict_grants_changes`）单点
  住在 core，闸收结论值。「闸自身可审计」的落点因此不在闸上而在**两处可复算的事实**：
  裁决载荷带 `score` / `threshold` 当时值（`elimination_event`），折叠入口唯一
  （`verdict_grants_changes`）。把事件切片塞进 `plugins/loop` 只会让同一个折叠判据长出
  第二个家——那才是本批要防的复述。
- 2026-10-21 项 10（淘汰恢复）：**记为边界，新立 [ADR-108](../010-adr/108.md "ADR-108")**。
  自动恢复不是漏接而是**判据闭合**的结果：分数只由「成功委派」抬升，而委派正是被收回的
  动作 ⇒ 任何「分数回升即 restore」的规则都是死臂。ADR-108 把「不可自动恢复」记为边界，
  写明重开条件（外部触发 = 申诉 / 人工复位；摘掉 `restoration_event` 的 `#[cfg(test)]`
  即可接上，载荷口径不变），并如实写下今天的后果（淘汰是单向门，唯一的既有出路是承载
  那条 `revoke` 的 WAL 随之删除——记为**存储布局的后果**，不当作申诉口）。不提前立项
  （[ADR-032](../010-adr/032.md "ADR-032") 同一条纪律），任务层的缺口账仍在
  [T-133](../009-task/133-多智能体社会.md "T-133-多智能体社会") §现状 ①，两处已互相指认。
- 2026-10-21 项 13（阈值复核）：**不分档，结论落在 `EliminationDecider::THRESHOLD` 文档**。
  分档的对象是**后果的梯度**，而今天只有一种后果（收回 `assign.work` 一格）；
  `plain_score` 只有计数差（±1），再切一档只是把「何时被永久锁死」挪进一个更难看清的
  参数里（它与项 10 的单向门是同一道门的两半）。真要有梯度，先要有第二种后果——那属
  S13 社会面的裁决，不在本批顺手加架构元素。
