## 内容

父批次：[T-230 内环收口批](230-内环收口批.md "T-230-内环收口批") ·
父设计：[PL-017 · 端口细粒度化](../004-plan/017-端口细粒度化.md "PL-017-端口细粒度化") §3.2 ·

今天的恢复路径（[T-227](227-端口细粒度化.md "T-227-端口细粒度化") 步 4）是：
审批动作到达 → `resume.rs` 调 `ToolPort::open_resume` → 直接造一笔 <!-- doc-symbol-allow: 记名的是恢复旁路时期的旧符号（`open_resume` / `resume.rs`），随 T-244 步 5d 的旁路退役而删除——「不存在」正是退役已落地的状态 -->
`tool-resume-{turn}-{target}-{n}` 的 `request` / `authz.granted` / `sent`。
这笔债的**前件是用户的审批动作**，不是模型响应。

原先的计划（T-232 的第一版）是把 `dispatch-tools.owes` 迁到
`response(port=model)`。ADR-117 核对实现后发现那会同时坏掉两件事：被拒绝的调用
仍有模型响应 ⇒ 派发绕过授权；恢复调用没有模型响应 ⇒ 失去债。

本任务因此收口为**形状裁决 + 判据**，而不是给恢复补一条合成事实：

- 工具调用有**两段债**：创建（`response(port=model)` → `request`）与派发
  （`authz.granted` → `sent`）；恢复是创建者，不是派发者；
- 恢复的 `request` 就是它的债前件，`dispatch-tools` 不需要认识模型响应；
- 这条性质由用例钉住，T-232 才能安全地在创建行上接 `expand`。
