## 内容

父批次：[T-230 内环收口批](230-内环收口批.md "T-230-内环收口批") ·
父设计：[PL-017 · 端口细粒度化](../004-plan/017-端口细粒度化.md "PL-017-端口细粒度化") §3.2。

今天的恢复路径（[T-227](227-端口细粒度化.md "T-227-端口细粒度化") 步 4）是：
审批动作到达 → `resume.rs` 调 `ToolPort::open_resume` → 直接造一笔
`tool-resume-{turn}-{target}-{n}` 的 `request` / `authz.granted` / `sent`。
这笔债的**前件是用户的审批动作**，不是模型响应。

T-232 要把 `dispatch-tools.owes` 改成 `response(port=model)`（配合 `expand`
表达批次集合）。问题是：恢复调用**没有**模型响应前件——一迁，恢复那一笔就没有债了。

本任务要先给出「恢复从哪来」的形状：

- 审批 / 补充 / 中止都是**外部唤醒源**（PL-017 §3.2），落的是它们自己的事实；
- 恢复调用是「一笔已被授权、但尚未执行完的调用」，它的前件应当是**那笔调用自己的
  未还债**，而不是「模型又回了一次响应」；
- 形状确定后，T-232 才能安全地把 `dispatch-tools` 迁到 `response(port=model)`。

**这是设计任务，不是接线任务。** 新事实名 / 新行 / 改求解器都要先过方案或 ADR；
实现难度不构成改形状的理由（PL-006 §3 纪律 0）。
