## 内容

父设计：[PL-017 · 端口细粒度化](../004-plan/017-端口细粒度化.md "PL-017-端口细粒度化") §3.3。

PL-017 §3.3 要求「并发集合是事实，不是执行体的自觉」：同一 `batch_id` 的子债
能否并发，先由端口声明。T-227 把工具调用落成了逐笔 `sent` / `response`，但批内
并行的开关仍只藏在执行层的风险档映射里——`PortDecl` 没有 `concurrent` 字段，
于是「这个端口允许并发」无法从声明面读到，新增一个端口时也没有地方说这句话。

本任务只补**声明与消费**这一层，不改 `expand`（批次展开仍归后续任务）：

- `PortDecl` 增加 `concurrent: bool`；
- `tool` = `true`，`turn` / `model` = `false`（单次调用没有「同批子债」）；
- 批首读数把该声明折成一个布尔交给阶段②；阶段②在新的
  `policy_for_port(concurrent, mode, risk_policy)` 里消费它：
  `concurrent=false` ⇒ 整批串行，`true` ⇒ 沿用既有风险档 / 交互模式策略。

这样「并发」不再是工具执行层的隐含假设，而是端口声明的一部分；`expand` 落地时
只需把子债集合接到同一道闸上，不需要再改阶段②的判定形状。
