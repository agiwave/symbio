## 内容

父设计：07 报告建议 1 / 2 / 5 · 总报告 §4.4 断层四（classify / compose 绕过端口的双消费形态）

**两件事，同一根源**：模型能力的「能不能碰模型」这件事，仓里有**两条调用链**。

| 现象 | 后果 |
|---|---|
| classify / compose 直连 `execute_turn`，不经 `LlmAdapter` 端口 | 令牌闸门有死角——「能不能碰模型」有两个答案；cost_ms 埋点口径分裂 |
| `resolve_protocol_id` 未识别协议时静默落 `openai_chat` | 「配了 anthropic 却发 openai 请求体」不报错，从运行期才暴露 |

**为什么端口是正解而不是加一层包装**：`ProviderLlmAdapter::for_turn` 已支持注入系统提示词与
中止信号——classify / compose 的需求面（消息进、文本出）**本来就在端口能力之内**。
所以这不是「为统一而统一」，是两条旁路本来就在重复实现端口已有的东西。

**兜底方向反转的判据来源**：同仓 `CapabilityRiskLevel::from_name` 的方向是「宁可报错，
不静默放宽」。协议解析是同一类判断，方向应当一致——存量配置里的合法别名已被覆盖，
反转只影响写错的配置（这正是该报的）。

**建议 5（位置复审）不是可选项**：`ProviderLlmAdapter` 住在 core 是因为「纯胶水住契约旁边、
依赖方向由编译器保证」。端口收敛之后依赖方数量会变，按 [ADR-023](../010-adr/023.md "ADR-023")
的判据应当复审一次——**复审的产出是登记，不是迁移**（很可能结论是留在 core，但要有理由）。

## 处理过程

- 2026-10-20 立批。来源：07 报告建议 1 / 2 / 5 + 总报告 C4 的 classify/compose 一项。
- 2026-10-20 顺序：先 1（端口收敛），再 2（兜底反转），最后 5（位置复审）——
  复审的输入是前两条落地后的依赖方数量，提前做复审等于用旧数字做判断。
- 2026-10-20 与 [T-189](189-轮执行阶段数据化批.md "T-189-轮执行阶段数据化批") 的关系：
  classify / compose 在 v2 里是「策略行 / 能力行」，T-189 会动它们的**调用位置**；
  本批动的是**取模型能力的方式**。两者不冲突，但若同期开工，本批先行
  （先让两条链走同一端口，再谈它们在哪一行被调用）。
- 2026-10-20 落地建议 1（端口收敛）：两处直调改为
  `ProviderLlmAdapter::for_turn` + `TokenIssuer::issue_deep()` +
  `generate_turn(&FullModel, …)`。内部请求语义原样保留：`&[]` 工具、`SilentDeltas`
  出口、就地 system prompt、调用方中止。对话线节点到 `PromptMessage` 的映射显式保留
  role / `tool_call_id` / 工具名——工具结果若被映射成用户发言，就是另一条已判定的退步。
  `compose` 的 `reasoning_id` 改由插件铸（静默端口只回文本，没有流式节点 id）。
  `internal-model-audit` 的存量随之从四处降到两处。
- 2026-10-20 落地建议 2（兜底反转）：`resolve_protocol_id` 从静默落
  `openai_chat` 改为 `Option<&'static str>`。三个落点分别是保存前校验直接报错、
  能力收集期跳过该条目并告警、未知者恰为生效 provider 时写进
  `CAPABILITY_ERRORS` 让启动链中止并展示原因。方向与
  `CapabilityRiskLevel::from_name` 一致：宁可报错，不静默放宽。
- 2026-10-20 落地建议 5（位置复审）：消费方从「会话 + 测试」变为
  「会话 + classify + compose + 测试」，跨过 [ADR-023](../010-adr/023.md "ADR-023")
  的多消费方判据；但实现仍只依赖 core 契约，迁到任一消费方会让另外两个跨插件深引。
  结论是**留 core**，对照表写进 `provider_adapter.rs` 文件头，理由与代码一起 review。
- 2026-10-20 cost 口径：内部请求不写事件（[ADR-020](../010-adr/020.md "ADR-020")），
  故 `cost_ms` 只进日志；`cost_ledger` 仍只由落格事件喂养（[ADR-044](../010-adr/044.md "ADR-044")），
  不为内部请求造第二套计时或旁路台账。
- 2026-10-20 用例：协议别名解析保持绿，新增「未识别值返回 `None`、不落
  `openai_chat`」；classify / compose 的提示词映射用例改为钉 `PromptMessage`
  （角色与工具身份逐字段过端口）。
- 2026-10-20 门禁自动修正：`grep-audit` S-014 基线 153 → 151（两处 role 直写随
  旁路消失）、删除 `model/plugin.rs::validate_config` 已无对应 panic 面的过期登记
  （PN-003）、rustTests 基线随新增判据上调至 1838。
- 2026-10-20 收口：提交 `54e3ab33`。全量门禁 124/124、e2e 77/77；lib 1838
  passed / 0 failed / 1 ignored。决策与失效边界写入
  [ADR-106](../010-adr/106.md "ADR-106")，ADR-080 转 `superseded`。
