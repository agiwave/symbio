## 内容

父任务：[T-236-义务环符合性收口批](236-义务环符合性收口批.md)。发现现场：
[T-244-唤醒事实接入与resume旁路退役](244-唤醒事实接入与resume旁路退役.md) 步 5b 施工前
对账要回答「`authorize-tool` / `dispatch-tools` 接回执行体之后能不能抬 `tool` 端口的
`max_attempts`」（原口径 4 后半），答案是不能——**与接线无关**，卡在键上。

行层的键口径是**有意**定的（`loop_rows.rs:565-567`）：「`failed` 关的是逻辑 id
（所有尝试），带 attempt 的键永远匹配不上它。尝试级口径归视图（`in_flight` /
`stale_sent`），行层是逻辑账」。这条定的本身对，但它有一个当时没往下推的推论：
一条 `request` 只要同键上有过任何一次出口，它就**永远不再欠**——重试补出来的那笔
`request{attempt+1}` 因此没有任何一行会选中它。而 PL-016 §2.6 契约 7 写着
「在途请求带租约 + 尝试号；`lease` 行重试或判死」，条文说的是两条路，
机制今天只走得通「判死」那一条。

求解器侧的约束（决定三条出口的成本）：`keys_of_all(decl.until, …)` 把所有出口的键
折成**一个集合**与债键比对（`ring.rs:204-207`）——所以 `until` 里**混用**两组键形
（一条 `(port,id)` + 一条 `(port,id,attempt)`）不成立：后者产出的键永远等不上
`(port,id)` 的债键。要让 attempt 进债，就得让同一个 `Decl` 的欠账/收口按各自的键
绑定 ⇒ 动 `owed` / `drive` 的字节 ⇒ PTS-003 基线 + 一条 ADR（这是出口 ① 的价）。

## 判据

1. **先把现状钉成用例**（不裁决也得钉）：给一段事实切片——`request{port:tool,id:X,attempt:1}`
   → `authz.granted{attempt:1}` → `retry{attempt:1}` → `request{port:tool,id:X,attempt:2}`，
   断言 `owes("authorize-tool")` 与 `owes("dispatch-tools")` **都是 false**、
   `drive` 在这一段切片上取不到这笔账。这条用例是「重试出来的 request 无人派发」的
   直接显形；反向自检：把 `granted` 那一格从切片里删掉 ⇒ `authorize-tool` 转真。
2. 裁决落地后，**二选一都有机器判据**：
   - 取出口 ①/③：一条用例证明 `attempt+1` 的那笔 `request` 会被派发器选中并落
     `sent{attempt:2}`（同键、尝试号跟着走）；PTS-003 基线同批更新并挂上那条 ADR。
   - 取出口 ②：`retry` 分支在真表上不可达由既有用例
     `no_port_in_the_real_table_retries_today` 钉住（已有），另加**条文侧**判据——
     PL-016 §2.6 契约 7 里「重试」一词必须带上「未启用」限定（脚本或 doc-symbol 判：
     契约 7 那一行含 `重试` 而不含 `未启用` ⇒ 红），杜绝条文与机制再次分叉。
3. 本任务不动 `ENGINE_ONLY_CELLS`、不动协议事实名集合（PTS-001 的判据面）；
   无论选哪条出口，`attempt` 都只在载荷里，不新增事实名。
4. 熔断线：单批非注释生产代码 ≤ 300 行（PL-016 §5）；取出口 ① 需要动求解器字节，
   **单独一批**，不与其它改动同批提交。
5. 验证方式：全量门禁 + e2e 绿 + 上述用例各带一次反向自检（实测记录进本任务的
   处理过程）。**CLI 不适用**并要写明理由：租约到期只在进程重启后发生（时间只随事件
   前进），本机没有「等够 10 分钟再重启再放行」的可重复审批链——那条路径的可观测形态
   就是事实切片，判据打在用例上，不假装 CLI 覆盖了它。
