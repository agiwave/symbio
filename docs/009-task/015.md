## 内容

出厂形状的 system 侧在**线上是两条**：`openai_chat::prepare_request` 先把 `system` 参数
prepend 成一条 `system` 消息，再把 `ChatMessage` 数组接在后面，而那个数组的第一元素
按 [ADR-048a](../010-adr/048a.md) 后果节就是「插在消息数组最前的一条 `system`」（记忆段 /
就绪段 / 委派者段）。两条都排在最前，位置合法，但**部分网关只认一条 system**。

后果不是「格式不好看」而是**硬失败**：那类 provider 上 `full` 档的第一轮请求就 400，
会话一步都走不出去。形状基线（[ADR-057](../010-adr/057.md)）钉的是「出厂送出了什么形状」，
本条目要定的是「这个形状在 provider 面上是不是人人收得到」。

## 处理过程

- 2026-10-12 由 [T-048](048.md) 的门外对照撞出来：实验需要一份能覆盖多个 provider 的
  出厂请求体，第一个障碍就是这条 400（同一份体、只把两条 system 并成一条即可通过）。
- 待办时要定的不是「怎么绕过」而是**口径**：前缀并入基础 system（一条，中间空行分段），
  还是保持两条、由各家协议自己合并。前者动的是形状基线（ADR-057 的场景名与计数会跟着变），
  后者把「合并」写进每一家协议——两条路都要有一条判据接住，否则下一轮又靠撞。
