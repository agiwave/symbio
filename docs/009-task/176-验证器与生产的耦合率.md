# 验证器与生产的耦合率——把 invariants / termination 挂到真实实现上

## 内容

**缺口**：`docs/004-plan/verify/` 的 16 个程序是 v2 方案的「硬证据」。但其中 14 个只与
**文档**耦合（读 `facts` 的生成物、读计划里的表），与**生产代码**零耦合——它们证明
「这套判据在自造样本上自洽」，不证明「跑起来的系统遵守它」。

两个最该耦合而没耦合的：

| 程序 | 现在验什么 | 该验什么 |
|---|---|---|
| `invariants.rs` | I1 / I2 / I3 在自造日志 + **真实会话信封**（`fixtures/real-session.tsv`）上成立 | 信封是真的，但**判定逻辑**是本文件自己实现的；生产侧的 `seq` 单调与「到点必答」由 `wal.rs` / `turn_runner.rs` 维持，那两处没有共用的判据 |
| `termination.rs` | 终止性三前提各自必要（自造代数） | 三前提在生产里对应 `loop` 的轮上限、预算闸门与收束路径；现在验的是「这三条在数学上必要」，不是「生产按这三条收束」 |

**为什么这件事值得做**：这两条是**能悄悄失效**的那一类。生产改一处（比如把收束判据从
「预算到点」改成「工具返回即收束」），`termination.rs` 仍会全绿，因为它压根没看生产代码。
而「验的东西与跑的东西不是同一个」是这类证据体系里最贵的失效——它不报错，只是让人误以为有证据。

**做法（两条，可分两次提交）**：

1. `invariants.rs` 的 I1：`#[path]` 包含生产侧 `seq` 分配 / 校验的那一段（今天是 `wal.rs` 的
   小函数），让「seq 单调」由生产实现本身来判。若那段代码不可分离，改成**回放真实 WAL**
   （`fixtures/` 已有先例：`real-session.tsv` 就是从 WAL 生成的），并把这个缺口写进程序输出的边界段。
2. `termination.rs`：把「轮上限 / 预算 / 收束」三处生产判据抽成可包含的纯函数（如果它们还不是），
   再让程序判「生产确实在这三处收束」。这一步可能需要**先动一点生产代码**（抽纯函数），
   而那不是重构洁癖——它是「判据只能与实现共处一处」的直接后果。

**为什么不是「把 16 个全挂上生产」**：有些程序验的是**文档一致性**（`capability_frame` 判名册与
轴/级的对应），它们的被测对象本来就是文档，挂生产只会造出一个假的耦合率。目标是
**把伪装成「验生产」的那几个**换成真的验生产，而不是把数字刷到 16/16。
