# A2A 对外互操作——先裁决「接不接」，再接一次真实往返

## 内容

**缺口**：外部智能体之间有一套事实上的互操作协议（Agent Card 发现 + task 提交 / 状态回传）。
本仓没有它，也没有一句话说明为什么不接。

**为什么这不是「补一个适配器」那么小**：A2A 的 `task` 有自己的生命周期（submitted / working /
completed / failed / canceled），而本仓的对应物是 `session` 的 `turn` ＋事件信封的 `seq`。
两边的边界不一致的地方至少三处：

1. **取消**：A2A 的 `cancel` 是 task 级操作；本仓的中止是执行期信号（`ExecAbortSignal`），
   轮内可中止、轮间不可「撤」。映射成「取消 = 杀会话」过粗，映射成「忽略」则是假支持。
2. **多轮**：A2A 的 task 可以带多轮消息；本仓的一轮由 `loop` 编排、由 `session` 在轮的边界
   派发——外部看不见「轮」，只看得见 task。
3. **谁产出的**：信封的 `produced_by` / `actor` 是本地主体模型；对端要的是「这个 task 由哪个
   agent 处理」，两者不是同一层概念。

**所以第一步是裁决，不是编码**。接的理由（入场券）与不接的理由（语义错位、维护两套生命周期）
都成立，但**必须选一个并写下来**——现状是两者都没写，于是它既不会被做，也不会被否。

**若选接，三条纪律**：

- 走现有路径协议：对端的每个能力都是一个 `route`，不为 A2A 造第二套路由表。
- 信封仍是唯一事实源：task 状态是**投影**，不新增一份可变状态。
- 失败形态要钉住：对端不可达 / 卡片声明的能力本地没有 / 对端中途取消——三种都要有 e2e 断言，
  否则「支持 A2A」这句话只在顺利路径上成立。

## 裁决（2026-10-20）：走 ②——暂不接，成文 [ADR-098](../010-adr/098.md "ADR-098")

原文说「必须选一个并写下来——现状是两者都没写，于是它既不会被做，也不会被否」。
现在写下了：**暂不接**，且把「不会被做」的原因从「没裁过」换成「对端没出现」，
把「不会被否」的部分（task 语义怎么归）用映射表钉死——**裁决是暂缓接线，不是悬置语义**。

两个关键翻转让「暂缓」区别于「拖延」：
1. 协议侧的所有推迟理由被搜证排除了（v1.0、AAIF、150 部署）——留下来的理由
   只剩部署形态，而部署形态是**事实**（gateway 绑 127.0.0.1），不是判断；
2. 三处语义错位（取消/多轮/谁产出）在 ADR 里各有明确解——将来触发条件满足时，
   剩下的工作是施工，不是思考。
