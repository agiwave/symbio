## 内容

v2 的会话在**多工具轮**上坏得比 v1 厉害，症状是前端「一串连续的思考过程，没有正文」。
拆开来是四处各自独立、但**只在这条链上一起出现**的缺陷：

| # | 缺陷 | 症状（实测会话 `f1566610`） | 修法 |
|---|---|---|---|
| A | 工具轮的交换每轮清空（`exchange.clear()`） | 第 N 次请求看不见第 1 次的结果 ⇒ 模型以为没读过，**同一份文件读四遍**、待办在 5 项与 6 项之间反复重置 | 改成**累加**（与恢复路同一条不变量：模型必须看见「我请求了什么、拿到了什么」）。唯一性代价由 id 承担，不由失忆承担 |
| B | 末轮判「答了没有」只看 `text` | reasoning 模型「想清楚了不复述」⇒ 末轮被判 `model returned empty text`，整轮落兜底格 | `LlmTurn` 带上 `reasoning`（端口面此前只有正文），正文空则取思考；**两样都空**才是失败 |
| C | 中途产出只在收束格里 | 重开会话后 13 个思考块整体挪到全部工具卡片**之后**连成一串（实时面是「思考→卡片→思考→卡片」） | 顺序锚是**格的发射顺序**：把每轮中途产出随该轮第一格产物入格（`round`），收束格 `rounds[]` 的同 id 重复由重建去重 |
| D | 收束帧把「思考即正文」标成 `Reasoning` | 同一段内容落库/重建是 `Text`、流式层是 `Reasoning` ⇒ live 与刷新后两种样子；CLI 非交互只回显 `Text`，于是正文一个字没打，还以「模型没有产出文本内容」退出 1 | 流式层跟着落库侧那条判据（`reasoning == text`）把同一个节点 id 定稿成 `Text`；CLI 的正文回显依据从「快照已累积长度」改成**该节点已打印长度** |

四处共同的取舍：**宁可跨轮累加把视图撑大，也不靠失忆换取「每轮只看最近一次交换」的假有界**——
有界性是请求视图一侧骨架化与轮次淡化的职责（代价与水位见「已知代价」一节）。

## 判据为什么分在三处

- **单测**（`turn_runner.test.rs`）证的是「运行器给了什么」，用假分发端口，看不到协议适配器
  按 `tool_call_id` 归并结果（`last_result_of`）与请求包清洗**丢弃无声明的 tool 结果**这两道——
  它们全在「结果到底有没有送到模型眼前」的路径上。
- **e2e**（t55）是唯一能证「第三次请求体里两条结果都在、且 id 逐调用互不相同」的地方
  （mock-llm 的 `/_requests` 回读），也是唯一能证 live 面（stdout + 退出码）的地方。
- **长跑**（t47）的形状判据从「每轮只带最近一次交换（峰值 1）」改判成「本回合的交换全带着
  （峰值 ≥ 45）」：旧形状是 A 的**症状**被写成了基线。骨架化与轮次淡化在这条负载上仍压不出
  字节效果（工具结果是小文件），但已经**可观测**，文件头的「没有压到的两处」随之改写。

## 已知代价（接受）

- 长轮请求体随步数增长（45 步的最后一个请求带 45 条 `role=tool`）。这是「模型看得见自己
  做过什么」的价格，有界性由视图一侧的裁剪按出厂水位按住，不靠丢结果。
- 交换累加后 id 的唯一性域从「一次请求」扩到「整个回合」：id 优先取调用自带的身份
  （wire id / 节点 id），两者都缺才合成 `call_<tool>_<轮>_<序号>`。同名工具在同一响应里
  调两次时**按调用配对**取结果 id——按名字配会把两条结果都挂到第一次调用上，
  第一次的真实结果被顶掉（错配比缺一结果更坏：模型据别人的正文改道）。
- 兜底格多带一个 `why`，重建把它折回 Turn 根节点的 `error`：失败原因在网格里一直是事实，
  此前到界面上丢了（用户只看到 failed 状态 + 一串产出）。
