## 内容

`scripts/gate-wiring-audit.mjs` 的 GW-005 要判的是「`autoWork`（重生成并暂存）的阶段必须排在
阶段序列末尾」——理由是暂存终态一旦被定格，后面再跑阶段就分不清谁碰过工作树。判据取的是
「阶段源码里**出现** `autoWork` 这四个字母」：

```js
const regen = stages.filter((f) => fs.readFileSync(…).includes('autoWork'))
```

这个形状在 [T-250-生成链阶段id失配](250-生成链阶段id失配.md) 之后已经和现实脱耦，两个方向都实测过：

1. **假阳性（实测 2026-10-23）**：把 `60-facts.mjs` 头注释里那句「生成链按 `autoWork` 逐格判差异」
   删掉（**零行为改动**，那只是叙述），判定立刻变成
   「重生成阶段 = `30-docs.mjs`」⇒ 对 `35-baseline` / `50-msrv` / `55-verify` / `56-frontend-build` /
   `58-e2e` 报出 **5 条 GW-005 红**。今天这条判据是绿的，而它绿在**一句历史措辞**上——
   `60-facts.mjs` 里唯一的 `autoWork` 就是那句变更史。
2. **假阴性（同一形状的镜像）**：真正在重生成的 `06-facts-write.mjs` 用的原语已换成
   `autoChain`，它进入名单同样只是因为注释里顺手提到了 `autoWork`。把那句改写成人话
   （只提 `autoChain`），这个会暂存文件的阶段就从判定里**消失**，GW-005 从此不再要求任何东西
   排在它之后——判据悄悄空转，门禁照旧全绿。这正是本仓反复登记的那一族失效形状
   （[T-089](089-ci触发分支守卫失配.md "T-089-ci触发分支守卫失配")、[T-092](092-fmt缺推送点闸门.md "T-092-fmt缺推送点闸门")、[T-250](250-生成链阶段id失配.md "T-250-生成链阶段id失配")）。

更深一层是**规则本身的前提变了**：GW-005 假定「重生成 = 定格暂存 = 必须最后」，而 T-250 把生成链
放到了静态审计**之前**（`30-docs` 的 D-007 / RF-003 要看展开后的末态，这是 `gate.test.mjs` 里钉着的
不变量），并让 `60-facts` 用两条只读 `--check` 收尾。实测的形状是：11 个阶段里**只有 `05-fmt` 与
`06-facts-write` 真的调用重生成原语**（`grep -o "autoWork(\|autoChain("` 逐文件计数，其余九个阶段
均为 0），它们排在第 1、2 位；`30-docs` 跑的是各审计脚本本体、不写文件。于是按 GW-005 的字面，
今天这条判据该红的形状正是设计要的形状——**它绿着完全是因为 `30-docs` / `60-facts` 的注释里出现了
`autoWork` 这个词**，让「最后一个重生成阶段」恰好落在序列末尾。
**这条要么承认判据写错了、把它改成它真正想判的事，要么承认证据不足、把范围收紧**；含糊地留着一条
靠注释措辞过检的判据，是本仓最不该有的形态。

## 口径

1. **自声明取代文本包含**：阶段文件 `export default` 里声明 `regenerates: true`（会改写并暂存
   受版本控制文件）或 `recheck: true`（只读地对一次末态），与 `id` / `title` 同级。GW-005 读这两个
   字段（动态 import，和 `gate.mjs` 加载阶段同一条路径），不再 `includes('autoWork')`。这与
   `55-verify` 读 `should_not_compile`、`@ns` / `@codes` 生成判据登记表同源：**能力由源码自声明**——
   但声明必须是**结构化字段**，不是散文。
2. **声明与实现双向对账**：`calls` 取源码里的**调用形状** `autoWork(` / `autoChain(`（带左括号，
   散文里提到名字不算）。GW-005 判四面——声明了 `regenerates` 却没有调用形状 ⇒ 红（生成器已被删掉
   就该撤声明，自己写文件绕过原语则末态判差异失效）；调用了却没声明 ⇒ 红（判据看不见这个生成阶段）；
   两个旗同时声明 ⇒ 红；有 `regenerates` 而 `recheck` 一个都没有 ⇒ 红（没人对整轮末态）。
   阶段文件 import 失败**不再静默按「没声明」处理**，报成一条 GW-005 失效。
3. **规则的裁决写进判据注释**：结论是**旧字面不成立**——实测正确形状是「生成阶段在前、只读复核在
   最后」。GW-005 改成判「最后一个 `regenerates` 阶段必须早于每一个 `recheck` 阶段」，并把被否决的
   一支（把 `06-facts-write` 挪到末尾）连同代价写进判据注释：那会让 `30-docs` 的静态审计读上一版
   投影，而 `gate.test.mjs` 钉着 `facts-write < docs` 这条不变量。「暂存要定格成 `git status` 的
   终态」这层保护已由 `autoWork` / `autoChain` **自己的前后快照**承担，不再依赖阶段位置。
4. **一句历史措辞清掉**：`60-facts.mjs` 头注释里「2026-10-23 的形态：生成链按 `autoWork` 逐格判
   差异…」改写为当下语义（现行注释不写变更史）。`06-facts-write.mjs` 里那句「分成四个 `autoWork`
   在本地没区别、在 `--ci` 下必红」**保留**——它是「为什么不拆成四格」的设计论证，不是变更史；
   新判据只认调用形状，这句留不留都不再影响判定，这一事实本身就是口径 1 的验收动作之一。

## 不是本任务范围

- 不动 `autoChain` 的末态判差异语义（T-250 刚落地的形状，本任务只判谁在用它）。
- 不给 `gate.mjs` 的阶段加载加新机制（`regenerates` 是元数据字段，runner 不消费它，只有 GW-005 读）。
