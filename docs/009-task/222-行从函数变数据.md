## 内容

父设计：[PL-016 · 义务环](../004-plan/016-义务环.md "PL-016-义务环") §2.1 · §2.2 · §5 第 6 步

**这是全案唯一的结构性改动，也是最容易被低估的一步。** 它不是"换个返回类型"：

| | 今天（`loop_registry.rs`） | 目标 |
|---|---|---|
| 一行是什么 | `fn(&LoopState) -> Option<Capsule>` —— **代码** | `Decl { owes, until, unless, by, prio, … }` —— **数据** |
| 判断在哪 | 函数体里（`if state.quiet_ms > …`） | 表里的 `Pattern`（`owes: report_due{due:true}`） |
| 输入是什么 | `LoopState`——手写五变体枚举，按格分形 | 视图（`in_flight` / `turn_head` / `report_due`，T-221/T-225 声明） |
| 返回值 | `Verdict::Hit/Declined/Unmanned` | `Vec<Debt>`，全量欠账 |
| 谁决定"下一步" | `decide` 顺序扫描取**先命中者** | `drive` 取**最小**可还的一笔 |
| `prio` 范围 | 格内（ADR-093），每格一行、从未真正行使 | **全局**，跨行可比；同号由 `(name, key)` 决出 |

所以本步真正要造的是三样东西：**`Pattern`**（模式语言：名字 + 字段等值 / 键绑定 /
布尔比较）、**视图**（替代 `LoopState`，输入闭包由 T-225 保证）、**`owed`**
（对每个 `Decl` × 每个 key 求 `open ∧ ¬blocked`）。

**三个不能省的施工前提**：

1. **输入闭包已由 T-225 落地。** 若 `owed` 还从配置 / 墙钟 / 内存里读，它就还是
   第二份状态——本步会退化成"把 `LoopState` 换了个名字"。
2. **`prio` 改成全局后，顺序要进表。** 五条策略行 + 执行行的先后（判决 → 召回/压缩 →
   执行 → 收束）必须由 `prio` + `owes` 前件表达，不允许靠"调用点在代码里的位置"。
   同 `prio` 的行由 `(name, key)` 决出，注册顺序不参与。
3. **执行行是临时的。** T-222 先让控制面成为真环：`execute-turn` 行 `by: execute`，
   actor 包住现有 `execute_turn`（零内部改动）。T-223 再给它 `before: sent` 与
   `await-turn` 行；PL-017 再把 actor 内部拆成模型 / 工具行。**三批之间没有双调度器。**

**两处必须写进判据的"不能丢"**：

1. **`Unmanned` 的可观测性不能丢。** 今天 `Verdict` 分 `Declined`（本格有行、都不认领）
   与 `Unmanned`（本格一行都没有，CI 的 `every_site_is_manned` 拦下）。表化之后
   "格"这个概念消失了，这个区分也随之消失——**但那个缺口不能跟着消失**。
   替代物是装载期一条新检查：**每个被声明的事实名，必须有某一行以它为 `owes` 或 `until`**。
   少了这条，一个拼错的事实名会静默永不被消费。
2. **`prio` 第一次真正被行使。** 今天每格恰好一行，`prio` 事实上从未生效
   （只有合成表的用例在钉它）。表化之后同一点上会出现多行竞争——
   `policy_recall` 内部那三件事（记忆 / 技能 / 任务段）就是现成的例子。
   **它们变成三行还是三个 `expand` 元素，是本步最重要的一个设计选择**：
   三行 ⇒ `prio` 参与裁决、顺序可 diff；三个元素 ⇒ 顺序在数组里、不进表。
   建议三行（顺序进表才可回放），但这是要写进提交信息里的判断，不是顺手决定的。

**熔断线按提交计，不按任务计**：**单次提交结构性改动 > 300 行 = 抽象错了，退回**
（PL-014 §5 步 1 的口径）。语义产出物（`LoopState` → 视图的映射表、`Capsule` → `Decl`
的对照表、对拍用例）不计入。`loop_registry.rs` 现 931 行，**这个数字本身不是目标**——
目标是有多少行是"判断"，多少行是"机制"。

因此本任务拆两个提交：

- **222a**：`Pattern` + `owed` + `drive` 骨架 + 六行数据（五策略 + 执行），五行行为
  与今天逐条对拍；旧的 `Site` / `LoopState` / `Verdict` 仍在，作为对拍的参照。
- **222b**：退役 `Site` / `LoopState` / `Verdict` 与五处旧分派，删对拍参照。
  这一步只删不加，通常远低于 300 行。

两个提交各自过线，不是一个任务整体过线。**这不是放宽判据**——是把"一次改 900 行"
变成"两次各自可验证的 300 行"。

**风险（写在这里，不写在事后）**：五条策略行里 `policy_recall` 是最难的
（它读三处、且是唯一有内部竞争的），`policy_classify` 最简单。**从最简单的开始、
每条一个提交**，如果第四条就撞上 300 行，说明抽象错了，应当退回而不是硬推。

  `Row.name` / `prio` / `effects` 三个字段原样保留。
- 2026-10-22 **222a 落地**，提交 `52328762`。引擎骨架 227 行代码（不含注释），
  在 300 行熔断线以内；视图 / 行表 / 对拍属本任务写明的语义产出物，不计入。
  旧 `Site` / `LoopState` / `Verdict` 一个字未动，六条行与旧表逐条对拍。
  门禁 128/128、e2e 78/78、rustTests 2010→2038。施工前的六处核对改变了交付形状：

  **订正一：三个视图不够；五条策略行的开账 / 关账要六个视图。** 立项时只写了
  `in_flight` / `turn_head` / `report_due`。实际落表时，`until` 必须与 `owes`
  绑定同一组键，而旧的三格 `done` 与收束状态在日志里没有可绑键的载体：新增
  `turn_stages`（`decide` / `compress` / `recall` 的阶段出口，键 `(turn, round)`）、
  `turn_closed`（`final` / `fallback` 的收束出口，键 `turn`）、`reported_anchors`
  （每条汇报关掉它之前那段静默，键 `(turn, anchor)`）。`turn_head` 升 v3、
  `report_due` 升 v2 输出区间锚 `anchor`。

  **订正二：「已完成」按**幕锚**收窄，不能按轮。** 续写幕复用轮号，按轮扫全史会把
  首幕的 `decide` / `recall` / `compress` 误判成已做。`turn_head` 因此先求本幕锚
  （`user.message` 或 `turn.stage{stage:"resume"}`），`done` 三格与 `turn_stages`
  都要求 `seq ≥ 锚`——与 `stage_events::done_since` 逐字同判。`round` 也从本幕的
  `turn.stage{stage:"round"}` 取，不取全轮最大值。

  **订正三：汇报的债务单位是「一段静默」，不是「一轮」。** 以 `turn` 作键，第一条
  汇报就把整轮的账关掉（配额 5 退化成 1）；以汇报事实作出口又永远晚一步。最终
  `owe: report_due{turn, anchor}`，`until: reported_anchors{turn, anchor}`——每段
  静默各开各关。配额按**本幕**锚之后计数：旧 `RoundProgress` 随请求新建，续写幕
  重新开账；按整轮数会让恢复后的第一句话永远报不出来。

  **订正四：`Unmanned` 的替代物是两跳归宿，不是一跳。** 立项时写「每个被声明的事实
  必须有某行以它为 `owes` / `until`」。行面向视图写，事实是视图的下游；只认直接
  引用会把所有视图源的事实全判成孤儿。`check_rows` 改为「行直接读它，或行用了某个
  读它的视图」。真正没有归宿的存量事实**不藏**：`request` / `sent` / `response` /
  `failed` 钉给 T-223，`turn.dispatch` 钉给 T-225 读侧，`authz.denied` 钉给 T-226
  ——每一族都有归属任务，装载期继续点名而不是豁免。

  **订正五：两处条件明写「不在表里」。** 汇报的触发前提 `round > 0 ∧ 工具轮数 ≥
  progress_min_rounds` 在日志里没有可读的「当前工具轮数」格（`reported.tool_rounds`
  只在说出口之后才有），留在触发点直到 T-223；执行行用 `turn_closed` 当出口，
  `sent` / await 是 T-223 的形态。两条都写在 `loop_rows` 模块头，不是默默留下的洞。

  **订正六：反射行的两个内存布尔搬进视图。** 旧 `LoopState::reflex(resume_anchor
  .is_none(), matched)` 的两个入参都来自执行侧内存。现在 `resumed` 由幕锚读出，
  `skill_hit` 由本幕召回阶段的 `result: hit` 读出——`take_match` 的结论第一次有
  事实形态。召回没跑（临时会话 / 未到轮首）时 `skill_hit` 为假，与旧侧空
  `skill_hits` 同判。

  **过渡形态**：`decl` 与 `loop_rows` 标 `cfg(test)`，控制面零改动；core 根以
  `pub(crate) use decl::{ring, builtin, Frozen}` 出根（C-002 禁插件深引域目录），
  其中 `ring` 整模块出根，是为了避开与 `actors::Pattern` 的重名。222b 接线时删掉
  `#[cfg(test)]`、退役旧三件并删除对拍参照。
