## 内容

父设计：[PL-016 · 义务环](../004-plan/016-义务环.md "PL-016-义务环") §2.1 · §2.2 · §5 第 6 步

**这是全案唯一的结构性改动，也是最容易被低估的一步。** 它不是"换个返回类型"：

| | 今天（`loop_registry.rs`） | 目标 |
|---|---|---|
| 一行是什么 | `fn(&LoopState) -> Option<Capsule>` —— **代码** | `Decl { owes, until, unless, by, prio, … }` —— **数据** |
| 判断在哪 | 函数体里（`if state.quiet_ms > …`） | 表里的 `Pattern`（`owes: report_due{due:true}`） |
| 输入是什么 | `LoopState`——手写五变体枚举，按格分形 | 视图（`in_flight` / `turn_head` / `report_due`，T-221/T-225 声明） |
| 返回值 | `Verdict::Hit/Declined/Unmanned` | `Vec<Debt>`，全量欠账 |
| 谁决定"下一步" | `decide` 顺序扫描取**先命中者** | `drive` 取**最小**可还的一笔 |
| `prio` 范围 | 格内（ADR-093），每格一行、从未真正行使 | **全局**，跨行可比；同号由 `(name, key)` 决出 |

所以本步真正要造的是三样东西：**`Pattern`**（模式语言：名字 + 字段等值 / 键绑定 /
布尔比较）、**视图**（替代 `LoopState`，输入闭包由 T-225 保证）、**`owed`**
（对每个 `Decl` × 每个 key 求 `open ∧ ¬blocked`）。

**三个不能省的施工前提**：

1. **输入闭包已由 T-225 落地。** 若 `owed` 还从配置 / 墙钟 / 内存里读，它就还是
   第二份状态——本步会退化成"把 `LoopState` 换了个名字"。
2. **`prio` 改成全局后，顺序要进表。** 五条策略行 + 执行行的先后（判决 → 召回/压缩 →
   执行 → 收束）必须由 `prio` + `owes` 前件表达，不允许靠"调用点在代码里的位置"。
   同 `prio` 的行由 `(name, key)` 决出，注册顺序不参与。
3. **执行行是临时的。** T-222 先让控制面成为真环：`execute-turn` 行 `by: execute`，
   actor 包住现有 `execute_turn`（零内部改动）。T-223 再给它 `before: sent` 与
   `await-turn` 行；PL-017 再把 actor 内部拆成模型 / 工具行。**三批之间没有双调度器。**

**两处必须写进判据的"不能丢"**：

1. **`Unmanned` 的可观测性不能丢。** 今天 `Verdict` 分 `Declined`（本格有行、都不认领）
   与 `Unmanned`（本格一行都没有，CI 的 `every_site_is_manned` 拦下）。表化之后
   "格"这个概念消失了，这个区分也随之消失——**但那个缺口不能跟着消失**。
   替代物是装载期一条新检查：**每个被声明的事实名，必须有某一行以它为 `owes` 或 `until`**。
   少了这条，一个拼错的事实名会静默永不被消费。
2. **`prio` 第一次真正被行使。** 今天每格恰好一行，`prio` 事实上从未生效
   （只有合成表的用例在钉它）。表化之后同一点上会出现多行竞争——
   `policy_recall` 内部那三件事（记忆 / 技能 / 任务段）就是现成的例子。
   **它们变成三行还是三个 `expand` 元素，是本步最重要的一个设计选择**：
   三行 ⇒ `prio` 参与裁决、顺序可 diff；三个元素 ⇒ 顺序在数组里、不进表。
   建议三行（顺序进表才可回放），但这是要写进提交信息里的判断，不是顺手决定的。

**熔断线按提交计，不按任务计**：**单次提交结构性改动 > 300 行 = 抽象错了，退回**
（PL-014 §5 步 1 的口径）。语义产出物（`LoopState` → 视图的映射表、`Capsule` → `Decl`
的对照表、对拍用例）不计入。`loop_registry.rs` 现 931 行，**这个数字本身不是目标**——
目标是有多少行是"判断"，多少行是"机制"。

因此本任务拆两个提交：

- **222a**：`Pattern` + `owed` + `drive` 骨架 + 六行数据（五策略 + 执行），五行行为
  与今天逐条对拍；旧的 `Site` / `LoopState` / `Verdict` 仍在，作为对拍的参照。
- **222b**：退役 `Site` / `LoopState` / `Verdict` 与五处旧分派，删对拍参照。
  这一步只删不加，通常远低于 300 行。

两个提交各自过线，不是一个任务整体过线。**这不是放宽判据**——是把"一次改 900 行"
变成"两次各自可验证的 300 行"。

**风险（写在这里，不写在事后）**：五条策略行里 `policy_recall` 是最难的
（它读三处、且是唯一有内部竞争的），`policy_classify` 最简单。**从最简单的开始、
每条一个提交**，如果第四条就撞上 300 行，说明抽象错了，应当退回而不是硬推。

## 判据

| # | 判据 | 检查方式 |
|:-:|---|---|
| 1 | 加一个端口 ⇒ `drive` 与 `owed` 源码 diff = 0 | 源码级断言（PL-016 判据 1） |
