## 内容

规则 / 机制 / 任务之外的第三类条目性元素是**决策**。owner 是
[`docs/010-adr/`](../010-adr/README.md "ADR-000-架构决策汇总")（每条一个 `ADR-NNN.md` 单文件条目，
编号即 `adr` 字段、正文在 `## 决策` 小节）。本任务清点散落在 plan / 参考文档里、
不属于 ADR owner 的决策型表述，逐处定处置：在 ADR owner 补条目 + 原处改链接，
或确属「跟进动作」（落地批次）则登记为 `task`。定案写回 14 §6，不在两处复述。

## 处理过程

- **清点范围**：`docs/004-plan/*.md`（含 `../003-stage/`）、`docs/005-arch/*.md` 的决策型表述
  （「定案 / 决定 / 裁决 / 取舍 / 否决 / 采纳 / 倾向」等措辞），逐处问「这条事实的 owner 是谁」。
- **清点结论——三分**，只有第三类才是散落决策：
  1. **架构面取舍（owner = plan/README §2/§3）**：如「1 个原语 + 1 条签名约束」、
     「投影不做 trait」、「只承诺 L0+L1」——它们的 owner **就是** [plan/README §2](../004-plan/012-高阶智能体平台v2.md "PL-012-高阶智能体平台v2")
     （职责表：「目标架构（v2）与迁移计划」的 owner，其余文档只引用），`01 §1.4/§1.5` 是它的
     细节落地。**有 owner，不是散落**——不迁、不改。
  2. **落地决策（owner = ADR）**：plan 文档里的行为面决策（如委派者三项真源 = ADR-047、
     出厂档位改 full = ADR-048）**都已引 ADR 编号**，满足职责表「其它文档只引用 ADR 编号」。
     **有 owner，不是散落**。
  3. **散落决策（无 owner）**：清点出的**唯一**一处 = `docs/005-arch/011-third-party-plugin-spec.md`
     §10「待确认的决策」——6 条（`D1` 已定案 = ADR-032；`D2` 外部插件形态 / `D3` 权限强制程度 /
     `D4` 连接信息放哪 / `D5` 是否引入 JSON-RPC / `D6` 生命周期钩子形态**未定**）。
     该文自己写着「定案后每条写成一条 ADR」，但**没有任何东西追踪它们**。
     ⇒ 处置：**原处 §10 那张表自持**——它已经写着「定案后每条写成一条 ADR」，
     这句话就是这张表的出口；决策正文的 owner 仍是 ADR（[索引](../010-adr/README.md "ADR-000-架构决策汇总")）。不另登 `task`。
- **形态定案**（写回 [PL-011 §6](../004-plan/011-登记与汇总机制.md "PL-011-登记与汇总机制")）：
  **决策正文的 owner 永远是 ADR，registry 不复制决策**（「明确不接管」已在 14 §6）；
  散落决策的**接管边界**只有两种情况——① 已定案 ⇒ 在 ADR owner 补条目、原处改链接（若原文有正文，
     删正文只留指回）；② **未定案的决策** ⇒ 它是设计文档自己的内容，**原表自持、不登记**；
     真要推进定案时才登记 `task`（`exit` = 「定案并写 ADR」）。**不为决策新开 kind**（同 T-005/T-006 的判法）。
- **走过的路（留此以防重演）**：本条一度把 ② 定成「未定案 ⇒ 登记 `task`、原处只留指路」，
  并据此登记过 `T-007`。执行它等于把一份设计文档的「待确认决策」表拆成 ADR 指路——
  **文档完整性受损，而跟踪收益只剩「别忘了」**，故该任务已撤销、条目已删除，② 的定案改回现在这版
  （14 §6 同步）。判据：`task` 表里不应出现「以改动某文档的决策表为 exit」的条目。
- **验证**：`registry-audit` 零违规；§10 表完整保留且无指向已删条目的链接（`doc-link-audit` D-001 零失效）。
