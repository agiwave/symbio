## 内容

父裁决：[ADR-100](../010-adr/100.md "ADR-100")（绑定即登记）· [PL-015](../004-plan/015-可扩充性与插件切分.md "PL-015-可扩充性与插件切分") §4（可扩充性）

[ADR-100](../010-adr/100.md "ADR-100") 落的是**装配点绑定**这一形态：每轮由
`chat_loop::request_actor_spec` 把本轮主体登记进运行期绑定面（`BOUND`）。
它补上了 [ADR-099](../010-adr/099.md "ADR-099") 删派生后的可用性真空，但留下一处
**已知代价**：`BOUND` 是进程级、只增不减——长驻进程里每个出现过的 agent 身份都会
留下一行。

本条把登记**前移到会话创建**：会话诞生的那一刻就声明它的主体能力行（根会话声明
会话面缺省行、委派子会话声明父行继承），登记的生命周期**与会话同寿**——
绑定面不再是进程级单调增，而是随会话创建 / 回收。

## 判据

- **创建即登记**：会话创建路径声明主体行，装配点不再需要补登记（`bind_inheriting`
  退化为幂等兜底或删除）；
- **同寿回收**：会话结束时其登记行随之消失（进程级 `BOUND` 不再是唯一载体）；
- **边界不变**：ADR-100 五条边界（静态行不改写 / 可见域不登记 / 淘汰面只认部署表 /
  委派两侧都在册 / 失败即不登记）在创建即登记形态下逐条仍成立。

## 处理过程

- 2026-10-20 立批（[ADR-100](../010-adr/100.md "ADR-100") 同批）。装配点绑定已落，
  本步是把登记生命周期从「每轮」收到「创建一次」的迁移，不改变任何判定口径。
