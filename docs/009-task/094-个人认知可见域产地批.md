## 内容

[T-081](081-授权表缺行登记批.md "T-081-授权表缺行登记批") ② 的裁决把 [T-130](../009-task/130-个人认知体系注入.md "T-130-个人认知体系注入")
§3 那条增量（`person:*` ▸ 记忆 `vis_scope = shared`）判为**不落地**，理由是它在今天的表形状下
表达不出来，三条证据见 T-130 §3.1 的裁决块。本任务承接那个落地方向。

要补的不是一行，而是**两端**：

1. **内容侧产地**：`can_see(viewer, owner, scope)` 的 `scope` 是**内容的**可见域，而今天
   没有任何载荷承载它（`memory.encoded` 的载荷里没有 `vis_scope`），读侧唯一调用点
   （`plugins/session/stats.rs`）恒传 `VisScope::default()`。所以「共享」要成为生产面，
   先得有「这条内容对谁可见」的事实产地——这与 [ADR-053](../010-adr/053.md) /
   [ADR-054](../010-adr/054.md) 把「变更」升为事实是同一条纪律：
   一个判定依赖的输入若没有事实来源，判定就只能是平凡值。
2. **主体侧归属**：`person:*` 这类**只读成员**在今天的表里不存在——`PermissionMatrix::new`
   要求 grants 非空（`PairingViolation::ReadOnly`），而 7 项能力闭集按「智能体的权威动作
   种类」划分，没有一项是「人」的动作种类（`symbio/src/symbio_core/authz.rs` 模块头
   「两张表里的人」已写明）。故「人的读权」要么走**不加行**的路（owner 相等，`thread_private`
   已如此），要么给表加一条新行形态——**后者是形状变宽，必须先过 [ADR-055](../010-adr/055.md)**。

次序：先立决策（③ 的归属裁决），再落产地与读侧调用点；写方与消费方同批，不留「有产地无人读」
或「有读方无产地」的半边。
