## 内容

父设计：[PL-016-义务环](../004-plan/016-义务环.md) · [PL-017-端口细粒度化](../004-plan/017-端口细粒度化.md)。

2026-10-22 对 PL-016 做过一轮「方案 → 代码 → CLI 实证」三面对账
（LMStudio 模型跑通纯问答轮与工具轮，逐格比对 WAL）。结论：**求解器半边真实落地**
（债形状 / owed 全量取最小 / 五协议名 / 两行模板 / 引擎写 before 与 failed /
租约 / 溯源不悬空 / 拒绝落事实 / 授权级联 / 输入闭包主体），**执行契约半边确凿未实现**
（ActorDecl / Builder 六口 / 四道装载检查 / 装载拒绝启动 / 事件时间戳 now /
短路轮进环），而 PL-016 §5 施工表把十一步全部标了 done——状态面失真。

本批把偏差按「文档自洽 → 行为缺口 → 契约补齐 → 判据硬化」四档收口。
每子任务一个提交，熔断线沿用 [PL-014-单环一表收敛](../004-plan/014-单环一表收敛.md) §5：**单次提交结构性改动 ≤ 300 行**。

## 批验收口径（机械、不留裁量）

每条子任务的 `done` 必须**逐项**满足以下口径，缺任一项即视为未闭：

1. **代码类子任务三件套**：
   - 定向用例 + `cargo test -p symbio --lib` 全绿（evidence 贴命令与通过数）；
   - `node scripts/gate.mjs` 全量绿（含 e2e）；
   - **CLI 复验**：`symbio-cli --homedir .symbio --provider <本机可用模型>` 新开
     会话跑**两幕**——纯问答轮 + 强制工具轮——由
     `scripts/obligation-ring-accept.mjs`（T-238 建，逐条判：每次模型往返有
     `request/sent/response` 三格、`user.message` seq 先于判决、`sent` 先于应答、
     收束格 `reason` 非空、`produced_by` 不悬空、孤名告警 = 0）判**全项通过**，
     脚本输出摘要进 evidence。
2. **文档 / 裁决类子任务**：`registry-audit` 与 `gen-doc-refs` 绿，evidence 逐条列改动小节。
3. **"仅单测绿"不构成 evidence**；出现"按构造不可达 / 不造夹具"式的判据弱化陈述，
   必须当场登记硬化任务或写明有期限的豁免——判据不落地即判据在空转（PL-006 §0 纪律 6）。
4. 裁决对账不受旧 ADR 惯性约束：与 PL-016 / PL-017 正文冲突的既裁条款，
   按订正流程回表（本批实例：ADR-118 订正节，accept 谓词退役、守卫用例补造）。
