## 内容

v1 的轮次收尾里有两件事靠 `TurnOutput::finish` 驱动（`chat_loop/turn.rs`）：

- **打标**：被长度截断的那条正文/思考节点在 meta 上戳 `finish_reason: "length"`，前端据此
  才有「继续」按钮与回溯的形状；
- **自动续写**：无工具调用而 `finish = Length` 时不收尾，再问一次模型，让它从断点接着写
  （上限 `MAX_CONTINUE_ROUNDS`），耗尽才发一句「输出因达到长度上限而中断…」。

这两格在 **v2 执行路径上都不成立**，而且是**类型上**不成立：`v2_exec` 收束时重建
`TurnOutput`（两处，正常出口与写侧闸被拒出口）用的是 `text` / `reasoning` / `usage` +
`..Default::default()`——`finish` 不在其中，而它的 `Default` 是 `Stop`。于是运行器之外
的所有消费方读到的都是「自然结束」，无论 provider 实际说了什么。

实测读数（一条最小负载：mock 回 33 字符正文 + `finish_reason=length`，会话关掉判决与措辞，
非交互 CLI 跑一次）——**同一条流、两个读数**：

```
[model]    流正常结束 (3 chunks / 455 bytes, 文本 33 字符, 推理 0 字符, 工具调用 0 个, finish=Length)
[session]  [Turn] 结束（正常收尾，无工具调用）finish=Stop
```

戳与续写都按后者办事：那条半截正文的节点 meta 上没有 `finish_reason`，而自动续写一次没跑
（半句话就这么当答话交付了，退出码 0）。

本条与 [T-142-长度截断时草稿被当答话交付](142-长度截断时草稿被当答话交付.md) 是同一格的两侧：
那条管「半段草稿不许冒充答话」（已在**运行器**内部把 `LlmTurn::finish` 用上，判据已闭），
本条管「截断的正文该接着写」——它需要一个**带得出运行器**的 finish，因为续写的决定权在
轮次收尾之外的那一层。两件事一起改就分不开回退，因此分登记。

## 处理过程

**修的是「带得出运行器」那一段**。运行器内部早就用上 `LlmTurn::finish`（T-142 已闭那侧），
缺的是把它带到 `TurnOutput` 上给 `chat_loop` 消费。三段同批：

1. **`TurnOutcome` 加字段**（`turn_runner.rs`）：`pub finish: ModelFinishReason`。
   文档同 `usage` 一条口径：**本轮最后一次响应**的事实——多轮工具循环里前面几轮的
   原因随 `rounds[]` 入格，不进这个字段。反射档 / 兜底 / 中止没有末轮 ⇒ 恒 `Stop`。
2. **13 处返回点分别填值**：末轮收束（无工具）两处 + 等待用户一处带 `rt.finish.clone()`；
   定稿答话 / 反射档 / 兜底 / 中止（两处 `AdapterError::Aborted` + `append_aborted` 两处 +
   `append_fallback` 两处）共 9 处填 `ModelFinishReason::Stop`——它们没有末轮，Stop 是
   诚实缺省而不是「被 max_tokens 掐断」的伪装。
3. **`v2_exec.rs` 两处 `TurnOutput` 重建**（正常出口 + 写侧闸被拒出口）：加
   `finish: outcome.finish`，与同函数上一行的 `usage: outcome.usage` 同一条「实测直通」纪律。
   `..Default::default()` 保留（其余字段仍用缺省），但被显式字段遮蔽。

**判据落点**：`chat_loop/turn.rs::settle_reasoning` 读 `out.finish` 打长度戳、
`close_turn` 同判据触发 `MAX_CONTINUE_ROUNDS` 自动续写——两处代码一字未动，只是此前
v2 路径喂进去的一律是 Stop；`finish` 一旦带出真值，两条现成判据即刻可达。

**锚用例**：`turn_runner.test.rs::truncated_answer_carries_length_reason_to_the_outcome`
——桩适配器末轮回 `LlmTurn { text: 非空, finish: Length, tool_calls: 空 }`，断
`TurnOutcome.finish == Length` 且 `EVENT_ASSISTANT_FINAL` 收束格照常入格（正文非空 ⇒
不进兜底，见 T-142 那条判据）。反向自检：删任一处 `finish:` 直通本用例必红。

**为什么不在 v2_exec 层再加一条集成用例**：`v2_exec → chat_loop` 是插件层同函数直连，
`finish: outcome.finish` 一写就是编译期事实（结构体字段），无旁路可断；断链的位置
从来是**运行器 → TurnOutcome** 这一格，本用例钉的就是这一格。
