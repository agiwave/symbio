## 内容

父任务：[T-236-义务环符合性收口批](236-义务环符合性收口批.md)。

2026-10-22 CLI 实证（LMStudio，会话 `verify-ring-1`）：一句话问答轮走了两次模型
HTTP 调用，WAL 里只有 `user.message / session.config / turn.stage / turn.dispatch /
chat.assistant.final`——**没有任何 `request` / `sent` / `response`**。同一 CLI 的工具轮
（`verify-ring-2`）协议格逐格齐整。说明存在一条**不经债环的第二执行路径**：
短路判定直接调模型，绕开了 `dispatch-model` 行。

这与 PL-016 §0「没有别的调度代码」和 PL-017 判据 2 直接冲突。收口方向：
短路轮也是「这一轮欠一次模型往返」的一条债，由行表派发；派发器里不许多出
「Answered 走捷径」的 if。

## 验收口径

1. 用例：短路轮（classify=Answered）的日志构造断言——含 `request/sent/response(port=model)` 三格且 `sent` 的 seq 介于二者之间。
2. CLI 复验（[T-236-义务环符合性收口批](236-义务环符合性收口批.md) 批口径）：**纯问答轮**这一幕在旧实测（会话 `verify-ring-1`）里协议格为 0——复验必须转为全项通过，反例基线转正即本任务的直接证据。
3. 源码扫描：短路路径上不存在绕过 `owed`/`drive` 的模型调用点（LLM 客户端调用仅存在于执行体注册表可达路径）。
4. `node scripts/gate.mjs` 全量绿（含 e2e）。
