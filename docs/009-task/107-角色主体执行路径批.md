## 内容

[T-106](106-角色行主体名与能力源裁决批.md "T-106-角色行主体名与能力源裁决批") 裁决「**规格粒度 = 主体**」
（[T-128 §3.1](../009-task/128-多主体与对等承诺.md "T-128-多主体与对等承诺")）之后，S02 worker 与 S03 规划者·
验证者三行的正确落地形态确定为 **行与执行路径同批**：

- 三者今天都**没有生产驱动路径**——`agent:worker` / `agent:planner` / `agent:verifier`
  生产 `grep` 零命中；产物写方主体仍是 `agent:main`（[T-122 §3.1](../009-task/122-工具调用与产物.md "T-122-工具调用与产物")）；
- 单独建行 = 「行在、主体不在」的**假行**——正是 [T-082](082-角色行生产构造批.md "T-082-角色行生产构造批")
  要消灭的形态（字段构造出来却没人读）；
- 且 S02 行自身与派生冲突：`pattern: reasoner` + `[ProduceArtifact]` 无 `reply.*`，
  而 `Pattern::for_principal` 对「无发言权而有 `produce.artifact`」派生的**是** `Translator`
  （对等行 `agent:peer-b` 正是此形）——worker 到底是「子智能体」还是「收窄的对等体」，
  须与「子智能体是否收窄」的口径一并裁（[T-128 §4](../009-task/128-多主体与对等承诺.md "T-128-多主体与对等承诺") 平凡值今天让子智能体派生主智能体整套）。

故三行**不单独建**，由本任务承载三条路径（行随路径同批落）。路径形态待裁决：
worker = 委派链上以产物收束的子主体？planner = 立任务（`define.work`）的规划步拆主体？
verifier = C15 要求「验证者 ≠ 产出者」的独立判定主体？三者各自需要的驱动点不同。

  **a. 三角色窄行（`symbio_core/authz.rs`）**：`PRINCIPAL_WORKER` / `PRINCIPAL_PLANNER` /
  `PRINCIPAL_VERIFIER` 三行入 `ROWS`（均 ThreadPrivate、各持一项能力：worker ▸ `produce.artifact`、
  planner ▸ `define.work`、verifier ▸ `assert.verification`），`matrix_for` 补登记分支。
  worker 与对等 `agent:peer-b` **分行**（树侧委派收束 vs 图侧协作，驱动路径与上限判据不同）；
  planner 与 `agent:autonomous` 同持 `define.work` 但独立登记（自主 initiator ≠ 规划者）；
  verifier 与 `agent:arbiter` 同持 `assert.verification` 但角色不同（任务质量判定 vs 声誉裁决）、
  可见域不同（ThreadPrivate vs public）。判据 `authz.test.rs::the_three_role_rows_are_narrower_than_derivation`
  （各单能力 + 严格窄于 main + C15 两面 + 可见域）。**规格订正**：S02 行原写

  `scope: root` 实际为 ThreadPrivate。

  **b. 任务表写侧闸（`tool_executor/task_table.rs`）**：写 `todo_write` 需 `define.work` **或**
  `assert.verification` 二居其一——给两项能力**真读方**（非假行），被拒对象 = 纯产出主体
  （worker / peer）与纯派活主体（market）。判据 `task_table.test.rs` 6 条 + `tool_executor.test.rs`

  （capabilities / pattern 派生 / budget 按档 / scope），判据 `state.test.rs` 3 条（worker=Translator、
  planner/verifier=Decider、委派 worker scope=Child）。

  **d. e2e（`e2e/cases/t75-role-paths.mjs`）**：主会话 `todo_write`（正对照）→ `agent_run{worker}` →
  工人子会话真跑一轮：`vdfs_read` 产生产物格（`artifact.added` actor=`agent:worker`、`produced_by`=
  开轮格 seq、**无 final/fallback 格**——收窄 vs 派生的分水岭）、`todo_write` 被闸拒（拒因回灌第三发
  请求）、子会话不变量空（C4 认产物收束）、父会话代际约 opened+released。

  [T-119](119-规划与验证会话驱动路径批.md "T-119-规划与验证会话驱动路径批")**。
