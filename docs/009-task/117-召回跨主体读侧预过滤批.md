## 内容

[T-094](094-个人认知可见域产地批.md "T-094-个人认知可见域产地批") 落了 `vis_scope` 的内容侧产地（`memory.encoded`
载荷字段，写方两值：经验→`shared` / 判断→`thread_private`）与 stats 读闸的消费。本任务承接
它暴露出的**第二个消费方缺口**——召回路径：

- `v2_memory::recall_view(session_dir, query)` 今天**没有读方入参**，内部
  `recall(PRINCIPAL_USER, None, Some(query))` 把 viewer 硬编码成属主 `user`；
- 投影 `projection/recall.rs` 按 `actor == viewer` 过滤，而所有记忆的 actor 都是
  `PRINCIPAL_USER`（认知归属人，不是跑轮主体）⇒ 单属主部署下投影恒取全量；
- 投影模块文档写明：「`shared` / `public` 的跨主体召回由**读侧**先用
  `PermissionMatrix` 预过滤可见切片，再调本投影」——这个预过滤**没有落地**。

后果（今天可观察）：`thread_private` 的**判断记忆**（智能体收束记录，T-085 批④ /
T-094 写的会话私有工作记忆）**跨会话可见**——另一会话跑轮时，召回段
（【长期记忆】跨会话召回）看得见本会话的收束记录。C10 的缺省隔离在召回路径上
只剩「按属主」这一层（投影文档自称的「最小必需隔离」），`vis_scope` 产地在这条
路径上没有任何消费方。

## 不是本任务范围

- stats 读闸的消费（T-094 ②，已落地）；
- `recall` 投影自身的参数与分级器（T-085，已闭环）——本任务不动投影签名，预过滤住读侧；
- 同文去重 / 巩固的写侧视角（`encode` / `consolidate` 内部以属主调投影）——去重问
  「在不在」不问「给谁看」，随写方口径，不随读方变；
- thread 实体（S4）落地前的**按线程**隔离——本任务只到「按内容可见域 + 按属主」，
  线程粒度等实体。

## 处理过程

- 2026-10-15 T-094 闭项时发现并登记：产地落成后查出召回路径不消费它（读方硬编码、
  预过滤缺席、判断记忆跨会话可见）。按「写方与消费方同批」纪律，产地已有消费方

   blast radius 与 stats 读数口不同量级，需要自己的正反用例（含 e2e）。
