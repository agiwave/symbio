# 任务总览

任务是可勾销的最小工作单元：`todo → doing → done/wont` 一条状态轴，done 必须有证据（evidence）、wont 必须有理由（reason）。分解（parent）只在任务之间，跨 kind 关联走 deps。

## 任务分解的推荐形态（阶段任务 / SPRINT 任务）

大目标不直接平铺成一批小任务，而是**先立一个父任务，再往下分解**——`parent` 字段是父子分解树的边（RG-024 / RG-025：同 kind、不自指、不成环、父子状态档位单调），可多级：

- **阶段任务**：一类能力扩充的全部工作。路线图 = [T-120](120-路线图总览.md "T-120-路线图总览")，13 份阶段文档（原 `stage` kind，2026-10-16 废除并入）= T-121–133 挂其名下；各阶实现任务再挂对应阶段任务名下——三层分解。
- **SPRINT 任务**：一个迭代批次。一批同目标的任务立一个 SPRINT 父任务（如「T-xxx 批」），批内任务挂它名下，批闭则父任务随子任务一起 done。
- **何时分解**：一个任务写不下 exit、或要分多次提交推进时，就拆父任务 + 子任务；能一个任务说清的不要硬造层级。
