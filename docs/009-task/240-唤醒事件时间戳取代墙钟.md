## 内容

父任务：[T-236-义务环符合性收口批](236-义务环符合性收口批.md)；前件条款由 [T-237-方案自洽与命名统一](237-方案自洽与命名统一.md) 写入 PL-016 §2.1。

求解器本身是纯的（`now` 为入参），但五个生产调用点全部现取墙钟当 `now` 注入——
「回放可重建」在这些路径上是假的。补法沿用 PL-014 F3 唤醒源：
启动 / 心跳 / 插话等触发先落一条**唤醒事实**，其 ts 就是本次 drive 的 `now`；
`owed` 只见事件 ts。这是把既有语义接线，不新增机制键。

## 验收口径

1. grep 判据：五个生产调用点（`turn_exec.rs:794-798`、`chat_loop.rs:463,590`、`drive.rs:120`、`inputs.rs:163,327`）不再出现 `clock_now_ms()`；全仓 `clock_now_ms` 调用点清单进 evidence，且 ⊆ {唤醒事实落格处, 与判决无关的展示/计时层}。
2. 用例：同一日志 + 同一唤醒 ts ⇒ `owed`（生产表 `loop_rows::table()`）两次求值逐字相同。
3. CLI 复验两幕全过，且租约求值由唤醒 ts 驱动（用例或日志证据）。
4. 门禁与 e2e 全绿。

## 处理过程

- 2026-10-22 登记（PL-016 三面对账：方案 → 代码 → CLI 实证，见 T-236 内容节）。
- 2026-10-22 收口。落点选择：任务原名「唤醒事件时间戳取代墙钟」指向**入参来源**，
  实施时把这条来源收敛成**日志里的一条定义**——`loop_rows::wake_now_ms(切片, 幕锚)`。
  理由是接到调用点上要付的代价与它要防的错不成比：`now_ms` 若沿 `TurnInput` 往下灌，
  17 处测试夹具字面量被迫同步，而这些字面量正是判据 12 最不该被绕过的地方；换成从
  日志读回后，每一侧都只认 `(events, drive_seq)`，`now` 不可能与它所判的那段日志脱钩。
- 收租（`port::reap`）从唤醒格**之前**挪到**之后**：之前跑时本次 drive 还没有 `now`，
  只能现取墙钟，正是判据 16 要求由日志承载的那一笔。扫描窗口仍切在开幕前的快照尾部，
  被收的那几笔属于它们自己那一轮，与刚落的唤醒格无关。
- 恢复幕（`resume.rs` 的 `ToolPort::new(..., drive_seq=0)`）此刻还没有锚，`wake_now_ms`
  返回 0。这不危险且**必须**如此：0 让所有时间条件一律不满足，而这三行工具债不读带
  时间的视图；唤醒事实的正式接入（心跳/恢复落自己的格）归 T-244。
- 一处返工：先按「`now_ms` 放进 `Drive` 结构体」实现，`-W dead-code` 判红——字段写了
  没人读，真载体是 `TurnState.now_ms`。删掉 `Drive.now_ms` 后只剩一条通道，正是要的形。
- 顺带收掉 `RoundHookFn` 的 `Option<i64>` 入参：它是一次 `clock_now_ms()` 读数留在判决
  路径上，而判决已经不读它（静默锚 = 抽干时落的 `turn.supplemented` 格，视图自读）。
  ADR-074 裁决二按 ADR-027 的先例记部分取代，裁决一、三不动。
- CLI 复验两次 exit=1（`verify-now-2/3`）逐条查过 WAL：`finish=Length`、正文 0 字符、
  工具调用 0 个，走的是 T-142 既有的「本轮未产出答话」出口；同一二进制换一条短提示
  （`verify-now-4`）exit=0 且唤醒格带真实 ts，据此判为本地模型退化，不是本次回归。
