## 内容

父计划：[PL-014 单环一表收敛](../004-plan/014-单环一表收敛.md "PL-014-单环一表收敛") §5 步骤 5
（删 v1 外壳）；「压缩入口唯一」的裁决见 [ADR-072](../010-adr/072.md "ADR-072")。

分层口径（L1–L6 各挡什么）归
[AR-014 上下文压缩设计](../../symbio/src/plugins/session/docs/014-context-compression-design.md "AR-014-context-compression-design")，
本文不复述。本文只登记一件事：**其中三层在 v2 的执行路径上没有接入**，以及接入或不接入各要付什么。

### 证据（2026-10-18 逐行核过）

- `chat_loop.rs` 步骤 4 交进 `V2Turn` 的只有 `prefix: request_view_prefix(&inputs.request_view)`——
  即 `build_request_view` 产物里**只有置顶三段**（记忆 / 就绪 / 委派）进请求；裁剪后的历史
  部分没有消费者。
- **裁剪的成本照付**：`prepare_turn_inputs` 每轮仍完整跑一遍 `build_request_view`（三层淡化 +
  骨架化都在内存里对全历史重算），产物随即被丢弃。所以这不是"为了省时间没接"，而是
  **算了不用**——接不接都要先解释这条。
- 运行器自己起基线：`turn_runner.rs` 从 `store.range(Seq::new(0))` 取全量，过
  `window_by_turn` / `filter_visible`，再 `render_messages` 成消息；每一轮请求是
  `base_messages.clone()` 拼本轮 `exchange`。这条路**不经过** `context/view.rs`。
- 于是 `build_request_view` 内的三层恒不生效：L1 `fade_aged_content_nodes`（老正文内容淡化）、
  L2 `fade_aged_tool_results`（轮次淡化，还被 `fade_active` 双重挡着）、
  L3 `apply_layered_sliding_window`（分层滑窗骨架化）。
- v2 实际在限制上下文的只剩三件：`window_by_turn` 的轮次窗口、L0 单条守卫、
  L5 语义压缩（`auto_compress_process`：70% 阈值自动 + 人工重试）。
- 后果可测：长会话里工具结果与老轮次正文按原文进每一次请求，token 水位比设计口径高；
  而 `SessionConfig` 的 fade / window 旋钮与 AR-014 的分层表读起来像「已生效」。

**相邻但不同的一条（已闭环，归 [T-165](165-控制面收敛.md "T-165-控制面收敛") 的 5b-2）**：
轮边界「先抽干、后汇报」的纪律里，「抽到补充 ⇒ 静默时钟归零」那句只写在 `chat_loop.rs` 的
抽干分支，而该分支的前提在 v2 恒假 ⇒ 用户补充到达后助手可能立刻抢报一句进度。5b-2 把它做成
了**入参**（`RoundHookFn` 带出 `supplemented_at`，判定方走 `RoundProgress::stirred`），
裁决见 [ADR-074](../010-adr/074.md "ADR-074")；本文不再挂着它。

**本文还剩的 fade 口径**：`fade_activate_rounds` 的激活判定读的是 `TurnState::request_round`
（本轮已发出的 **LLM 请求数**，v2 下几乎总是 0 或 1），它不是工具轮数——真实工具轮数只在
`turn_runner.rs` 环体的 `tool_round` 与 `RoundProgress::rounds` 里。接入三层（或裁决它们不需要）
时要一并定「激活阈值按哪个计数」，否则这个旋钮拿着的是错的口径。归属与判据真源都在本文。

### 为什么它不并进 5b

删死簿记（5b）改的是「谁在读恒 0 的字段」；本条改的是「请求里的历史由谁裁剪」。后者两个方向
都是形状决策：要么给运行器接上视图层（新时序——裁剪发生在每轮请求组装时，而运行器基线跨轮复用
`base_messages`），要么裁决三层不再需要（那 `SessionConfig` 的旋钮与 AR-014 的分层表一起改）。
都要 ADR，都不属于「删不可达代码」这一批。

## 处理过程

- 2026-10-18 立项：5b-1 对 `TurnState` 逐字段做读写矩阵时，把 `build_request_view` 的产物追到
  消费点，照出「裁剪结果被丢弃」。5b-1 不动这条，只删死簿记。
- 2026-10-18 相邻那条闭环（5b-2）：静默时钟归零改由回调入参承担，本文剩下的只有三层接入
  本身；同时把 `fade_activate_rounds` 的计数口径登记清楚（激活判定要按哪个数，接入时一并裁决）。
- 2026-10-26 **结论：exit 的第二条成立，三层整族退役**（[ADR-078](../010-adr/078.md "ADR-078")）。
  核前提时发现 signal 只说对了一半，而错的那一半决定了处方——**接线不是「没做」，是接不了**：

  | 前提 | 核出来的事实 |
  |---|---|
  | 三层在算但没用上 | 成立。`inputs.rs` 每轮照常调，只有三段前缀被 `chat_loop.rs:713` 用掉 |
  | 接上就能生效 | **不成立**。运行器每请求跑 `verify_prompt_fidelity`（`turn_runner.rs:990`），配对判据是正文**精确相等**（`projection/prompt_fidelity.rs:295`）；三层改的正是正文 ⇒ 同一节点同时报「网格有、prompt 无」与「prompt 有、网格无」 |
  | 接线只需加一个字段 | **不成立**。环体 mid-turn 复用 `base_messages.clone()`（`turn_runner.rs:1110`），而三层是「每请求重算」的 ⇒ 得在 `render_messages` 之外另立一条组装路径，正是 ADR-048 要消灭的东西 |
  | 三层有生产消费方 | **不成立**。L3 只服务 `tool_context_window`，而 v2 的口径是工具轮不设上限；`context_retention` 的唯一消费方是 L3；`viewer` 过滤是死代码（`render_messages` 已按同一 viewer 滤过） |

  于是取 exit 的第二条：**成文裁决 + 让它们从文档与配置面退场**，判据落在两处——
  `prompt_fidelity` 每轮复核（既有）+ `build_request_sections` 的五条注入段判据
  （`every_section_carries_its_kind` 等，钉次序与 `meta.kind`）。

  **退役面**（符号级）：`context/view.rs` 的 `fade_aged_content_nodes` /
  `fade_aged_tool_results` / `line_head_tail` / `visible_for` 与那个消息体积上限常量；
  `context/window.rs` 整模块与 `apply_layered_sliding_window`；`SessionConfig` 的
  `compress_line_threshold` / `compress_keep_recent` / `tool_context_window` /
  `fade_activate_rounds` / `fade_keep_recent_turns` 五键与 `chat_session` 的四个访问器；
  `tool_result_guard` 的 `summarize_tool_result` / `summarize_head_tail`；`tokenizer` 的
  `truncate_head_chars_if_over` / `truncate_tokens`；`CapabilityToolContextRetention` 整个
  枚举与 `CapabilityMeta::context_retention`；`model_chat::Request` 与 `TurnRequest` 的
  `tool_context_window`。**`build_request_view` 改名 `build_request_sections`**，11 参 → 3 参。
  `cargo test -p symbio --lib` 1778 → **1747**（棘轮基线随批下调，逐条归属见 `35-baseline`）。
- **口径订正（本文原来的表述有一处不准）**：证据段写的「v2 实际在限制上下文的只剩三件」应读作
  **四件**——轮次窗口、L0 单条守卫、L5/L6 语义压缩，加上存储期工具链裁剪（`prune_tool_history`）。
  前三件在请求/加载侧，第四件在保存侧；它们共同点是**都不改写投影正文**，这也是三层该退场的
  正面判据（[AR-014](../../symbio/src/plugins/session/docs/014-context-compression-design.md "AR-014-context-compression-design") §0 原则 2）。
