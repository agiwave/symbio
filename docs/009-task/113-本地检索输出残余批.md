## 内容

本任务由 [T-111](111-本地检索组边界批.md "T-111-本地检索组边界批") 写 `t67` 时实测发现。

### 现象

`content_search` 的 `content` 模式（默认）返回体里，**每匹配行后多一个空行**。
`e2e/cases/t67-content-search-edges.mjs` 的探针实测（两个文件共 5 个匹配行）：

```text
C:\...\src\a.ts:1:const x1 = 'MKA_...';\n
\n
C:\...\src\a.ts:2:const x2 = 'MKA_...';\n
\n
C:\...\src\a.ts:3:const x3 = 'MKA_...';\n
...
```

即输出是 `行\n\n行\n\n行`，而不是 `行\n行\n行`。

### 根因

`content_search.rs::search` 的逐行分支：

```rust
let sink = UTF8Sink(|ln: u64, text: &str| { file_matches.push((ln, text.to_string())); Ok(true) });
...
out.push(format!("{}:{}:{}", disp, ln, text));   // ← text 含行终止符
...
Ok(out.join("\n"))
```

`grep-searcher` 的 `UTF8Sink` 交给闭包的 `text` **含行终止符**（`SinkMatch::bytes()` 的语义），
`format!` 把它原样拼进结果，`join("\n")` 又补一个 ⇒ 行间成 `\n\n`。

### 后果（两件，第二件更要紧）

1. **输出脏**：模型读到的正文里每行之间空一行。
2. **分页与匹配行不对齐**：`apply_line_pagination` 按 `result.lines()` 切——它切的是**输出行**
   （含空行），不是**匹配行**。于是 `head_limit: 2` 只覆盖 **1** 个匹配行，`offset: 1`
   只跳过半个匹配。这正落在 [T-111](111-本地检索组边界批.md "T-111-本地检索组边界批") 自己写的
   「分页参数写错就是『结果看着像对的、其实少了一半』」那句话上——而这里**不写错也少一半**。

### 为什么单测没拦住

`symbio/src/plugins/local/` 下只有 `codebase_search.test.rs`——**`content_search.rs` 没有单测文件**。
输出形状因此只有 e2e 能发现，而 e2e 直到 T-111 才第一次覆盖三种 `output_mode` 的**形状**。

### 边界（不做什么）

不重写搜索实现、不动 `multiline` / 上下文窗口分支的既有语义（那一支的 `text` 同样含行终止符，
但它与 `line_vec[i]` 是两条路径，需一并核对后再改——见处理过程）。

## 处理过程

- 2026-10-15 登记：T-111 写 `t67` 时，`head_limit=2` 的分页断言实测得 1 行，
  探针核对后确认根因在 `UTF8Sink` 的 `text` 含行终止符。当时把 `t67` 的分页判据
  降级为「`offset` 跳过 / `head_limit` 截短」两件不受空行影响的事实，缺口另登本任务。
- 2026-10-15 闭批：修复落在 sink 入口——`content_search.rs` 逐行分支的 `UTF8Sink`
  闭包在入列前 `trim_end_matches(['\n','\r'])` 剥掉行终止符（一处修复同时清掉
  输出脏与分页错位两件后果；上下文窗口分支只消费行号、不受影响，`multiline`
  分支的匹配体语义按边界不动）。补 `content_search.test.rs` 八条单测：三种
  `output_mode` 各一条形状判据 + 分页与匹配行对齐三条（`head_limit=2` 恰 2 个
  匹配行 / `offset` 跳过 / 组合取中）+ 平凡值与无匹配各一。`t67` 的分页判据
  收紧为匹配行口径（`offset=1, head_limit=2` ⇒ 恰为第 2、3 个匹配行）并补
  「行间无空行」断言。单测 8/8 绿 · e2e t67 绿 · clippy 零告警。
