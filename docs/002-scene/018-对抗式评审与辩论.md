# 对抗式评审与辩论

> **一句话**：两个智能体各自独立评审同一份方案，交叉质证、逐条对证事实源，收敛出比任何一方单独都好的结论。
> 支撑能力：缺口——未挂阶梯任务（已有真实先例：[PL-014-单环一表收敛](../004-plan/014-单环一表收敛.md) 的三轮交叉评审）

## 场景

方案 / 文档 / 代码的定稿前评审：一个智能体提出设计与裁定，另一个独立核实并
反驳，双方各自对照代码与文档编号下结论而不是顺着对方措辞走。特征是
**观点必须经过碰撞才被采纳**——反驳方核实过才认，提出方驳回要有更强理由；
分歧与驳回理由全部留痕。今天的痛：单个评审者顺着作者思路走，盲区就是
作者的盲区；多份独立意见没有质证环节，谁也不服谁，最后靠资历裁决。

## 用户判据（诚实账）

| # | 用户应该看到 | 判据现状 |
|---|---|---|
| 1 | 评审方各自独立产出结论，每方至少有对方没发现的发现（独立性可证） | 缺口：无判据（挂 [T-011](../009-task/011.md)；先例见 PL-014 终止性守卫与 F1–F3 均为对抗产物） |
| 2 | 关键裁定逐条对照事实源（代码行 / 文档编号），先查再断 | 缺口：无判据（挂 [T-011](../009-task/011.md)） |
| 3 | 每条意见的采纳 / 驳回都留痕且附理由，终稿能追溯每处修改来自哪轮 | 缺口：无判据（挂 [T-011](../009-task/011.md)；PL-014 两处驳回已留痕） |
| 4 | 收敛有终点：连续一轮无新发现即收，不无限辩论 | 缺口：无判据（挂 [T-011](../009-task/011.md)） |

## 边界

不含自动仲裁——分歧的最终裁决归人或既定判据，不由「辩赢了」裁决；
不含评审方之间的通信协议标准化（那是 A2A / provider 层的事）；
对抗只保证覆盖率、不保证正确性——结论质量由事实源与判据裁决，
评审本身也可能双双出错（同盲区）。
