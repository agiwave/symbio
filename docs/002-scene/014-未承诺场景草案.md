# 未承诺场景草案

> **未承诺（D-157）**：本册五节（深度研究 / 浏览器自动化 / 数据与文件分析 / 定时巡检 /
> 对抗评审）都是已移出承诺清单的草案，不在路线图内；重开条件见该决策。
> 它们共同的形态是「有场景、有用户判据、无机制、无判据」——原先各自成篇，但每篇都只写着
> 「缺口：无判据（未立项）」，分开发布只是把同一句话抄五遍。阶梯总表见
> [DE-030-能力阶梯总览](../003-design/030-能力阶梯总览.md "DE-030-能力阶梯总览") §1。

## 1. 深度研究与报告

> **一句话**：给它一个研究问题，它多源检索、交叉比对，给我一份带引用的报告。

场景：知识工作者的调研活——选型对比、竞品分析、文献综述。特征是多轮「检索 → 阅读 →
综合」的长循环，中途用户常要插话调整方向，最终产出是一份本地报告文档，不是一句回答。

| # | 用户应该看到 | 判据现状 |
|---|---|---|
| 1 | 报告里的关键结论带可回跳的引用源 | 缺口：无判据（未立项） |
| 2 | 长循环中途可插话纠偏，不丢已有进度 | 缺口：无判据（未立项；插话机制见 [场景 §7](001-场景总册.md "SC-001-场景总册")） |
| 3 | 报告作为产物落盘，可导出、可复用 | 缺口：无判据（未立项） |

边界：不含全网爬虫的合规与限流策略；不含团队协同评审；检索源的质量与覆盖是 provider 层
选择，场景只要求「引用可回跳」这一交付形态。

## 2. 浏览器自动化操作

> **一句话**：让它替我操作网页——查单、填表、抓数，每一步留证据。

场景：登录态下的重复网页操作——查快递、填报销单、抓取后台数据。特征是**浏览器会话
状态跨步骤存活**（登录态、已填表单），且部分操作有真实后果（提交、支付），
需要先审批后执行。

| # | 用户应该看到 | 判据现状 |
|---|---|---|
| 1 | 每一步操作有截图 / 证据留存，可回看 | 缺口：无判据（未立项） |
| 2 | 敏感操作（提交 / 支付 / 删除）先审批再执行 | 缺口：无判据（未立项；审批语义见 [场景 §9](001-场景总册.md "SC-001-场景总册")） |
| 3 | 中断后能续操作，登录态不要求重登 | 缺口：无判据（未立项） |

边界：不含验证码对抗；不含分布式抓取；浏览器实例的宿主形态（内嵌 / 借用系统浏览器）
是 provider 层选择，场景只要求会话状态可存活、证据可留存。

## 3. 数据与文件分析

> **一句话**：丢给它一批本地文件和表格，问数、算数、出图，产物留在我的设备上。

场景：本地 CSV / Excel / 文档的问答与统计——算个同比、筛一批行、画张图。
特征是**大产物不进对话**（图表、报表是文件，不是消息），且答案要能
追溯回源文件的行列。

| # | 用户应该看到 | 判据现状 |
|---|---|---|
| 1 | 答案可追溯到源文件与行列，不是凭空数字 | 缺口：无判据（未立项） |
| 2 | 图表 / 报表作为产物落盘，可复用可再编辑 | 缺口：无判据（未立项） |
| 3 | 大文件不撑爆上下文（分页 / 摘要策略可见） | 缺口：无判据（未立项） |

边界：不含数据仓库 / 数据库连接（那是 provider 层扩展）；不含多人共享看板；
统计口径的正确性由用户验证，场景只保证「追溯得到源」。

## 4. 定时任务与自动巡检

> **一句话**：定好规则，它按时自己跑，跑完告诉我结果，出事才吵我。

场景：时间 / 事件触发的无人值守运行——每天巡检一次服务、每周汇总一次开支、
备份前提醒确认。特征是**没有人发起请求**：由外部触发源唤醒，
且静默期不打扰（正常完成不通知，异常才通知）。

| # | 用户应该看到 | 判据现状 |
|---|---|---|
| 1 | 触发历史可查：何时跑了、跑了什么、结果如何 | 缺口：无判据（未立项） |
| 2 | 失败可重试，且失败一定被告知 | 缺口：无判据（未立项） |
| 3 | 静默规则：正常不打扰，异常才通知 | 缺口：无判据（未立项） |

边界：不含服务器级调度器的高可用（本地优先角色的自然边界）；触发与静默是
策略选择，系统只保证「触发发生、历史留痕、异常可见」；自主发起目标
（不靠时间表）是另一件事，见 [场景 §12](001-场景总册.md "SC-001-场景总册")。

## 5. 对抗式评审与辩论

> **一句话**：两个智能体各自独立评审同一份方案，交叉质证、逐条对证事实源，收敛出比任何一方单独都好的结论。

场景：方案 / 文档 / 代码的定稿前评审——一个智能体提出设计与裁定，另一个独立核实并反驳，
双方各自对照代码与文档编号下结论，而不是顺着对方措辞走。特征是**观点必须经过碰撞才被
采纳**：反驳方核实过才认，提出方驳回要有更强理由；分歧与驳回理由全部留痕。今天的痛：
单个评审者顺着作者思路走，盲区就是作者的盲区。

| # | 用户应该看到 | 判据现状 |
|---|---|---|
| 1 | 评审方各自独立产出结论，每方至少有对方没发现的发现 | 缺口：无判据（未立项；历史先例见 `git log`） |
| 2 | 关键裁定逐条对照事实源（代码行 / 文档编号），先查再断 | 缺口：无判据（未立项） |
| 3 | 每条意见的采纳 / 驳回都留痕且附理由，终稿能追溯每处修改来自哪轮 | 缺口：无判据（未立项） |
| 4 | 收敛有终点：连续一轮无新发现即收，不无限辩论 | 缺口：无判据（未立项） |

边界：不含自动仲裁——分歧的最终裁决归人或既定判据，不由「辩赢了」裁决；不含评审方之间的
通信协议标准化（那是 A2A / provider 层的事）；对抗只保证覆盖率、不保证正确性——结论质量
由事实源与判据裁决，评审本身也可能双双出错（同盲区）。
