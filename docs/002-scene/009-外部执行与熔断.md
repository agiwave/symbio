# 外部执行与熔断

> **一句话**：能真的发请求、跑命令、动文件；高风险动作先经用户点头，超预算即熔断，不"先做了再说"。
> 支撑能力：[DE-039-外部执行与熔断](../003-design/039-外部执行与熔断.md "DE-039-外部执行与熔断")

## 场景

智能体的动作第一次产生系统之外的真实后果：写文件、发消息、调外部接口。
用户期望有硬闸门：高风险动作先点头才执行，成本超预算就熔断，熔断之后有看得见的兜底而不是沉默。
今天的痛：一个"能做事"的智能体没有闸门，等于把生产环境向它敞开。

## 用户判据（诚实账）

| # | 用户应该看到 | 判据现状 |
|---|---|---|
| 1 | 高风险动作要先点头才做 | e2e：t27（已有） |
| 2 | 对外真的能产生后果（发请求、抓网页、跑命令） | e2e：t65（`web_fetch` / `http_request` 打本地靶子：同一本地地址两个工具都拒，且靶子留痕为零 ⇒ 拒绝先于发请求）/ t72（`web_search` 经 `search_api_base` 打本地靶子，Tavily 路径载荷真的到靶子；配置热切清空 key ⇒ 同进程落 DDG 回退）（已有）。**跑命令**：能力已在（`local` 的 shell 族工具在运行时存在，Windows 名为 `cmd`；静态工具表只见占位名，见事实表 §2.1 动态项）。高风险命令（含 Windows 的 `del` / `rd` / `format` / `taskkill`、解释器与未知命令）在自动模式下被拒、交互模式下需审批——判据：`policy/mod.test.rs` 的跨平台破坏性命令用例 + CLI 实测 a09（2026-10-24：`vdfs_delete` 被拒后改用 `cmd` 的 `del`，修复前执行成功、修复后同一条命令被判 High 并拒绝） |
| 3 | 熔断触发后有可见兜底，不是静默继续 | **两支分开记**：① **工具面成本熔断已在生产**——判据住执行体（`crates/symbio-plugin-tool/src/breaker.rs::CircuitBreaker::gate`），验收走 Rust 单测 `port.test.rs::exhausted_budget_breaks_and_lands_a_control_event`（预算耗尽 ⇒ `Break` + `control × opened` 带 `reason`，不静默）与反向用例 `affordable_calls_run_without_any_event`；e2e 无专列（读通道禁令下沉，见 t42 头注与 `DE-039` §6）。② **压缩失败的跨轮抑制未落地**——原 t18 契约 E（开闸后不重发摘要请求）与 F（失败节点上重试）随 `57ab3802` 的压缩迁移一并删除，新链路（`D-336` 两行债）没有等价物：失败后每轮照欠一次摘要请求，且不落失败产物 ⇒ 重试入口不可达。缺口与待裁机制（跨轮失败记忆归谁 · 永久失败格是否进 `PortErrorClass`）已登记在任务册；此处如实记「未落地」 |

## 边界

不含"该不该做这个动作"的价值判断——系统只保证有闸门、有授权、有熔断；
对外部世界已发生的事没有撤销；真实流量下的成本读数还没出。
