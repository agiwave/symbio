# 外部执行与熔断

> **一句话**：能真的发请求、跑命令、动文件；高风险动作先经用户点头，超预算即熔断，不"先做了再说"。
> 支撑能力：[DE-039-外部执行与熔断](../003-design/039-外部执行与熔断.md)

## 场景

智能体的动作第一次产生系统之外的真实后果：写文件、发消息、调外部接口。
用户期望有硬闸门：高风险动作先点头才执行，成本超预算就熔断，熔断之后有看得见的兜底而不是沉默。
今天的痛：一个"能做事"的智能体没有闸门，等于把生产环境向它敞开。

## 用户判据（诚实账）

| # | 用户应该看到 | 判据现状 |
|---|---|---|
| 1 | 高风险动作要先点头才做 | e2e：t27（已有） |
| 2 | 对外真的能产生后果（发请求、抓网页） | e2e：t65（`web_fetch` / `http_request` 打本地靶子：同一本地地址两个工具都拒，且靶子留痕为零 ⇒ 拒绝先于发请求）/ t72（`web_search` 经 `search_api_base` 打本地靶子，Tavily 路径载荷真的到靶子；配置热切清空 key ⇒ 同进程落 DDG 回退）（已有）。**跑命令**：未承诺——出厂工具面 19 个工具里没有命令执行工具（事实表 §2.1），不是缺判据是缺能力 |
| 3 | 熔断触发后有可见兜底，不是静默继续 | e2e：t18 契约 E（连续 3 个失败压缩节点 ⇒ 熔断开闸，其后轮次**跳过自动压缩、不再重发注定失败的摘要请求**，回复照常；断言走「摘要请求 HTTP 命中数不增 + 无新压缩节点」两个生产出口）（已有） |

## 边界

不含"该不该做这个动作"的价值判断——系统只保证有闸门、有授权、有熔断；
对外部世界已发生的事没有撤销；真实流量下的成本读数还没出。
