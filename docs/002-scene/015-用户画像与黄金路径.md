# 用户画像与黄金路径

> 产品层回答「谁在用、怎么走到第一次有价值的结果」。用户判据的账本仍是
> [场景总册](001-场景总册.md "SC-001-场景总册")；本文只写角色与旅程，不复制判据——
> 一个事实只有一个 owner。能力边界见
> [行业能力前沿参照](../004-ref/011-行业能力前沿参照.md "RE-011-行业能力前沿参照") 第 4 节。

## 1. 三名画像

### 1.1 本地开发者（桌面端）

在自己的项目上工作，希望助手能读写文件、跑命令、记住上下文。关心的是「少做一遍重复劳动」，而不是架构。入口是桌面端：编译后用左侧模型面板填 API Key，创建一个 Agent，把会话工作目录指向项目根，然后开始多轮对话。工具调用落在工作目录里，产物与转写留在会话目录。

对这位用户，「能对话」只是起点；价值出现在第二次——不必重复交代项目背景时。

### 1.2 自动化接入者（命令行 / 网关）

不需要界面，要把能力接进已有流水线：命令行单次调用与管道、网关 webhook、Telegram 长轮询。入口是命令行工具；系统目录默认在当前工作目录下的隐藏目录，可用 `--homedir` 指向别处。模型配置与桌面端共用同一份系统目录，是先决条件。

对这位用户，「无头」意味着无人值守时也要有确定行为：模型不可用时要给兜底回复，而不是静默中断。

### 1.3 Agent 编排者

把能力装配成可移植的 Agent 包。入口是 examples/fullstack-dev/ 这样的自包含目录：在 agent 根目录用新建类型 `zip` 导入整包，技能与 MCP 目录「存在即安装」。关心的是「换一台机器能不能原样跑起来」——配置与数据同处一个目录，整目录可拷贝。

边界同样明确：多主体机制已亮，但「多智能体社会」整能力仍是纸面；未落地能力不计入产品承诺，
能力边界见 [DE-002-架构总览](../003-design/002-架构总览.md "DE-002-架构总览")。

## 2. 黄金路径

从零到第一次有价值的结果，最短路径六步：

1. **编译与启动**：按 [快速上手](../006-guide/006-QUICK_START.md "GU-006-QUICK_START") 编核心库、启动桌面端。
2. **配置模型**：在模型面板填 API Key，或直接写 provider.json。这是所有路径的共同前置。
3. **选工作目录**：新建会话时按引导选项目目录；不设置，工具会落到默认路径。
4. **第一次对话**：发一条真实任务，观察流式响应与工具调用。
5. **导入一个 Agent**：打包 examples/fullstack-dev/ 后导入，验证能力可装配。
6. **验证环境**：跑 cargo test 与前端 npm test，确认本机安装完整。

> 每一步的命令与字段以 [快速上手](../006-guide/006-QUICK_START.md "GU-006-QUICK_START") 为准；本文不复述，避免两份教程漂移。

## 3. 边界与重开

本文只描述已落地能力的用户旅程。沙箱执行、计算机与浏览器自动化、深度研究、A2A 互操作整轴缺失，不写在黄金路径里——差距性质见
[行业能力前沿参照](../004-ref/011-行业能力前沿参照.md "RE-011-行业能力前沿参照") 与
[DE-002-架构总览](../003-design/002-架构总览.md "DE-002-架构总览")。

当某项能力出现真实用户判据（能指认一条已有读数）时，黄金路径才把它纳入；判据必须先于能力，避免把愿望写成流程。
