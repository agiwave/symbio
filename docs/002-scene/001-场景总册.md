# 场景总册

> 本册是**用户判据的唯一账本**：每个场景一句话说清用户得到什么，一张表逐条列出
> 「用户应该看到什么 / 今天拿什么证明」，一段边界说清不保证什么。机制面不住这里——
> 每个场景的 `支撑能力` 指向它的设计文档，那才是机制的唯一 owner。
>
> 为什么是一册而不是十三篇：十三篇的骨架完全相同（一句话 → 判据表 → 边界），
> 分开只让读者多开十三次文件、让登记面多十三条同形条目。节号保留原编号
> （`## 5` = 原 `SC-005`），代码注释与旧讨论里按编号找得到。

## 1. 最小闭环（SC-001）

> **一句话**：说一句话，得到一条回复；模型挂了也有一句兜底，而不是沉默。
> 支撑能力：[DE-031-最小闭环](../003-design/031-最小闭环.md "DE-031-最小闭环")

### 场景

用户在自己的智能体对话框里说一句话，期望得到恰好一条回复——这是所有高阶能力的地面，
后面十二个场景都是往它上面加，不是替代它。今天最常见的痛不是"接不上模型"，
而是闭环漏了端点：同一句话收到两条回复、模型出错后对话静默中断、或者干脆没有任何回应。
本场景要求四个端点同时成立：收到、思考、发出、兜底。

### 用户判据（诚实账）

| # | 用户应该看到 | 判据现状 |
|---|---|---|
| 1 | 说一句话，恰好收到一条回复（多轮不重复、不丢） | e2e：t1（文本流）/ t4（多轮）（已有） |
| 2 | 模型挂了也有一句话兜底，不是静默中断 | e2e：t5（服务报错后仍产出兜底回复）（已有） |
| 3 | "回复只发一次"用户看得见——收到两条就是坏了 | e2e：转写不变量断言（t1 / t4 普遍引用）（已有） |

### 边界

不含动手干活（没有工具、不留产物）；不记得本窗口以外的任何东西；被打断就丢状态——分别由后续场景承接。

## 2. 工具调用与产物（SC-002）

> **一句话**：能动手调工具干活，并把结果留成看得见、可追溯的凭证。
> 支撑能力：[DE-032-工具调用与产物](../003-design/032-工具调用与产物.md "DE-032-工具调用与产物")

### 场景

用户让智能体做一件实事：搜一下、算一笔、读写一个文件。结果不该只是随口复述，
而要留成一个后续步骤能引用的凭证，对话里也能看见"它调了什么、拿到了什么"。
今天的痛：只会用文字描述结果的智能体干不了实事；干了实事也说不清自己刚才做了什么，
下一轮把同一件事再做一遍。

### 用户判据（诚实账）

| # | 用户应该看到 | 判据现状 |
|---|---|---|
| 1 | 文件被真的读写出去，工具调用真实发生 | e2e：t3（文件写入）/ t2（工具往返）（已有） |
| 2 | 工具调用在对话里看得见——一张工具卡片，不是凭空冒出结果 | e2e：t38 / t26（已有） |
| 3 | 工具失败有可见反馈，不是静默 | e2e：t27（失败重试）/ t48（超限反馈）（已有） |
| 4 | 模型记得自己调用过什么、拿到了什么，不重复调用 | e2e：t27 / t55 / t59（已有） |

### 边界

不含把一件活拆成多步、也不含验退返工；产物不跨会话保留；
"该不该调用这个工具"的判断本身不在系统保证范围内。

## 3. 多步任务与返工（SC-003）

> **一句话**：一件活能拆成多步按序推进；某一步被验出不合格时，打回返工，而不是将错就错。
> 支撑能力：[DE-033-多步任务与返工](../003-design/033-多步任务与返工.md "DE-033-多步任务与返工")

### 场景

用户交一件要分几步完成的活，智能体拆出待办、按先后依赖推进，模型不用每轮重述计划。
某一步被独立验证判为不合格时，产生返工而不是将错就错——历史不被改写，
被取代的步骤自然退出视野。今天的痛：一步到位的智能体做不了长活，中间错了也只能错到底。

### 用户判据（诚实账）

| # | 用户应该看到 | 判据现状 |
|---|---|---|
| 1 | 长任务的待办清单跨轮保持，不用每轮重述计划 | e2e：t55（多轮工具的跨轮记忆）（已有） |
| 2 | 步骤之间的先后序不乱，且能看到当前就绪的那几步 | e2e：t31；生产读数：会话统计的就绪列（已有） |
| 3 | "这一步该派谁做、做完由谁验" | 未承诺：规划者 / 验证者两行只作**资格行**落地（`authz::ROWS`），会话驱动路径按裁决不建——收束闸两臂不覆盖这两项独持能力 ⇒ `closure_denied` ⇒ 派生事实不落；且「任务完成度的真实消费方」不存在（就绪集与执行消费方读的是执行会话自己的事实源，跨会话任务事实流不存在）。无用户可见面即无判据，判据不先于能力 |

### 边界

不含并行抢占（各步骤串行）；任务不跨会话存续，进程重启即丢；
验证判得准不准不由系统保证；规划者 / 验证者作为**会话主体**的驱动路径按裁决未建
（见判据 3）——今天落地的只有资格行，「派谁做、由谁验」没有用户可见面。

## 4. 并发调度与租约（SC-004）

> **一句话**：多个请求同时来时忙则排队、不丢不串；同一份会话同一时刻只有一人在写，冲突被明确拒绝。
> 支撑能力：[DE-034-并发调度与租约](../003-design/034-并发调度与租约.md "DE-034-并发调度与租约")

### 场景

用户同时对同一会话发多个请求，或开两个窗口动同一份会话。期望的并发语义很朴素：
忙则排队、可取消，第二个写者被明确拒绝而不是静默覆盖。
今天的痛：并发之下要么消息丢失、要么互相覆盖，事后说不清哪条才是准的。

### 用户判据（诚实账）

| # | 用户应该看到 | 判据现状 |
|---|---|---|
| 1 | 同一会话并发请求：忙则排队，不丢、不串 | e2e：t15（排队 / 可取消）/ t34（忙窗插话挂起）（已有） |
| 2 | 两个进程同时写同一会话：第二个被明确拒绝，不是静默覆盖 | e2e：t32（已有） |
| 3 | 租约到期就放回，且「判过死」这件事留得下痕迹 | 端口租约：CLI 实测（造「只有 `sent`」的 WAL 并回拨租期后重启，两口各落 `failed{why:"lease_expired"}`，`obligation-ring-accept --strict` 全项通过）；任务租约：调度者每轮扫史把 `until_ms` 已过的那笔判死并落 `task.ready{reason:"lease_expired"}`，`/readyset` 的 `ready` 里它重新出现（`an_expired_lease_is_judged_dead_and_reassigned`） |
| 4 | 能调「同时最多推进几件事」 | `session` 插件配置项 `task_cap`（插件面板可改；`1` = 串行 FIFO），`/readyset` 用同一个数作 `cap`（e2e t31 以 `task_cap: 3` 让两条同进候选）。**未承诺**：优先级与公平性——`session` 无 priority 任何实现，这是缺策略不是缺判据（见「边界」） |

### 边界

- 不含多副本部署下的顺序保证：`seq` 单调只在单写者 FIFO（单进程）下成立。
- 不含优先级与公平性——优先级是策略选择，系统只保证排队、发放、拒绝都**会发生**，
  不保证「谁先」符合某种策略。
- 不含抢占：今天没有抢占面（判定器已删，`D-388`），调度者只派、不夺。

重启**不丢**调度状态：就绪集与租约都由史重算（判据只吃 `seq` 与时间戳，任何地方都不存
「我派过谁」），这是机制而不是边界——写在这里是为了不被误读成「重启即失忆」。

## 5. 长会话与断点恢复（SC-005）

> **一句话**：周五合上电脑，周一接着干——历史压缩了能翻回去，重启了能从断点继续，不从头再来。
> 支撑能力：[DE-035-长会话与断点恢复](../003-design/035-长会话与断点恢复.md "DE-035-长会话与断点恢复")

### 场景

用户跟一个会话连续工作数小时甚至数天：历史太长会被自动压缩，但被压掉的内容仍能翻回去看；
中途进程崩溃或重启，编辑过、截断过的消息和"做到哪一步"都还在。
今天的痛：重启即失忆、从头再来，长会话变成一条不能回看的黑盒。

### 用户判据（诚实账）

| # | 用户应该看到 | 判据现状 |
|---|---|---|
| 1 | 会话长了自动压缩，压掉的内容仍能翻回去 | e2e：t8 / t11 / t45 / t47（已有） |
| 2 | 压缩过程本身是流式的，不是一条黑屏 | e2e：t18（已有） |
| 3 | 编辑 / 截断过的消息，重启后仍是编辑后的样子 | e2e：t44（已有） |
| 4 | "断点在第几步"能被读出来 | 生产读数：会话统计的断点列；e2e：t28（已有） |

### 边界

恢复的是"做到哪一步"，不是"学到了什么"——语义记忆是另一个场景的事；
"能恢复"不等于"能重现同样的模型输出"。

## 6. 长期记忆与语义检索（SC-006）

> **一句话**：这一轮说过的事，下个会话还记得；要用的时候按相关性找回来，而不是存了就沉底。
> 支撑能力：[DE-036-长期记忆与语义检索](../003-design/036-长期记忆与语义检索.md "DE-036-长期记忆与语义检索")

### 场景

用户教过智能体一件事、或它工作中学到过一个结论，期望换一个会话它仍然记得，
并且在新问题来的时候，相关的旧记忆排在前头被带进对话。
今天的痛：失忆助手每轮重新交代背景；或者什么都存、什么都调不出来——"存了"不等于"找得回"。

### 用户判据（诚实账）

| # | 用户应该看到 | 判据现状 |
|---|---|---|
| 1 | 这一轮说的话，下一轮 / 下个会话还在上下文里 | e2e：t29（已有） |
| 2 | 记忆按会话隔离，别的会话的记忆不会串进来 | e2e：t37 / t38（已有） |
| 3 | 与本轮问题相关的旧记忆排在无关的新记忆前面 | 单测判据：召回排序（已有） |
| 4 | 检索有预算，降级时明说"只是一部分"，不静默返回空 | 生产读数：召回降级标记；注入段明示降级（已有） |

### 边界

召回质量不由系统保证——"装得下检索"不证明"检索得到对的东西"；
检索打分的反馈环收敛性未论证；巩固时压什么、留什么是算法问题。

**明确未承诺的四件事**（不是「还没做」，是判过不落，判决表在 [DE-036 §3.2](../003-design/036-长期记忆与语义检索.md "DE-036-长期记忆与语义检索")）：
按存储层过滤、按压缩密度过滤、激活扩散、时间衰减。四条各有不同的缺件——层是既有字段的
派生名（加形参等于给同一维度起第二个名字）、压缩后的源记忆已不在视图里（没有可过滤的并列）、
记忆之间没有「边」的事实、衰减没有能说「该往哪拧」的评测刻度。用户能感觉到的差别是：
**记忆之间不会有「联想」式跳转**，也**不会因为久远而自动降权**——排序按相关性，平手才看新近。

**召回按字面重合，不是按「意思像」**（[DE-036 的 `D-152`](../003-design/036-长期记忆与语义检索.md "DE-036-长期记忆与语义检索")）：
换一种说法问同一件事时，可能召不回来那条记忆——它要求查询词与记忆正文有共同的词或字。
这一条同样是判过不落：向量检索要每轮常驻推理，而索引本该是可重建的、不进事实源。

## 7. 插话与实时打断（SC-007）

> **一句话**：干活干到一半能插话——手头的事不丢、插话排进队里等本轮收尾，切走再切回来形状不变。
> 支撑能力：[DE-037-插话与实时打断](../003-design/037-插话与实时打断.md "DE-037-插话与实时打断")

### 场景

智能体正在说话或跑一个长任务，用户突然插一句：补充信息、改要求、或直接叫停。
期望是第一件事不丢，第二件事有去处（排队到轮末），事后能接着做。
今天的痛：插话要么石沉大海，要么打断之后状态乱掉、收不回来。

### 用户判据（诚实账）

| # | 用户应该看到 | 判据现状 |
|---|---|---|
| 1 | 运行中说第二句：第一句不丢，第二句有明确去处 | e2e：t34 / t19（已有） |
| 2 | 能中止，中止后立刻收敛，不留悬挂 | e2e：t7 / t49（已有） |
| 3 | 实时面是三态的，切走再切回来形状不变 | e2e：t10 / t16 / t9 / t14（已有） |
| 4 | "谁判定该不该让插话先走" | **今天没有判定者**：抢占面已删（`D-388`），忙则排队到轮末是唯一路径；重启需新 D 号（缺口已记，不是待接线） |

### 边界

只支持排队；不挂起在跑任务、不改道（抢占面已删，`D-388`）；不是硬实时控制；多个插话按 FIFO。

## 8. 多主体与对等承诺（SC-008）

> **一句话**：几个身份各干各的、互不串包；彼此能立约，履约情况读得出来。
> 支撑能力：[DE-038-多主体与对等承诺](../003-design/038-多主体与对等承诺.md "DE-038-多主体与对等承诺")

### 场景

子智能体、对等智能体同时存在，各有各的身份和可见范围；对等体之间能立约——
承诺交付什么、何时交付，违约可被观测，声誉可被读出来。
今天的痛：多个智能体一上来就互相串话，说不清"这条是谁说的"，承诺了什么没有账。

### 用户判据（诚实账）

| # | 用户应该看到 | 判据现状 |
|---|---|---|
| 1 | 两个主体各说各的，转写里不会串包 | e2e：t30 / t39（已有） |
| 2 | 对等主体能立约，履约情况读得出来 | e2e：t71；生产读数：会话统计的声誉列（已有） |
| 3 | 子智能体在自己的空间里自驱动，不依赖外部有调用方 | e2e：t15（已有） |
| 4 | "这条是谁说的"按可见范围逐条过滤 | e2e：t73（内容侧可见域：矩阵内主体读得到他人共享内容、矩阵外读不到，且判据随**内容**走）/ t76（召回段按内容可见域 + **本轮主体**预过滤，矩阵外主体真跑一轮证明取的是「谁在跑这一轮」）（已有） |

### 边界

只记录"立了约、是否违约"，不保证守约质量；声誉怎么打分是算法问题；
组织形态（层级 / 市场）是多智能体社会场景的事，本场景只有点对点协作。

## 9. 外部执行与熔断（SC-009）

> **一句话**：能真的发请求、跑命令、动文件；高风险动作先经用户点头，超预算即熔断，不"先做了再说"。
> 支撑能力：[DE-039-外部执行与熔断](../003-design/039-外部执行与熔断.md "DE-039-外部执行与熔断")

### 场景

智能体的动作第一次产生系统之外的真实后果：写文件、发消息、调外部接口。
用户期望有硬闸门：高风险动作先点头才执行，成本超预算就熔断，熔断之后有看得见的兜底而不是沉默。
今天的痛：一个"能做事"的智能体没有闸门，等于把生产环境向它敞开。

### 用户判据（诚实账）

| # | 用户应该看到 | 判据现状 |
|---|---|---|
| 1 | 高风险动作要先点头才做 | e2e：t27（已有） |
| 2 | 对外真的能产生后果（发请求、抓网页、跑命令） | e2e：t65（`web_fetch` / `http_request` 打本地靶子：同一本地地址两个工具都拒，且靶子留痕为零 ⇒ 拒绝先于发请求）/ t72（`web_search` 经 `search_api_base` 打本地靶子，Tavily 路径载荷真的到靶子；配置热切清空 key ⇒ 同进程落 DDG 回退）（已有）。**跑命令**：能力已在（`local` 的 shell 族工具在运行时存在，Windows 名为 `cmd`；静态工具表只见占位名，见 [RE-006-当前事实表](../004-ref/006-当前事实表.md "RE-006-当前事实表") §2.1 动态项）。高风险命令（含 Windows 的 `del` / `rd` / `format` / `taskkill`、解释器与未知命令）在自动模式下被拒、交互模式下需审批——判据：`policy/mod.test.rs` 的跨平台破坏性命令用例 + CLI 实测 a09：`vdfs_delete` 被拒后改用 `cmd` 的 `del`，同一条命令仍被判 High 并拒绝 |
| 3 | 熔断触发后有可见兜底，不是静默继续 | **两支分开记**：① **工具面成本熔断已在生产**——判据住执行体（`crates/symbio-plugin-tool/src/breaker.rs::CircuitBreaker::gate`），验收走 Rust 单测 `port.test.rs::exhausted_budget_breaks_and_lands_a_control_event`（预算耗尽 ⇒ `Break` + `control × opened` 带 `reason`，不静默）与反向用例 `affordable_calls_run_without_any_event`；e2e 无专列（读通道禁令下沉，见 t42 头注与 `DE-039` §6）。② **压缩失败的跨轮抑制与重试已在生产**——`D-336` 两行债的 id 按**前缀指纹**（最旧未压事实 id + provider 上限 + 代）派生：同一前缀判死后失败不换代，其后轮次收束在同一把键上，不再重付摘要请求；失败是**产物**（`compact` 落 `failed` 事实，`stamp.failure = compression`），读面折出 `Failed` 压缩叶、`actions` 含 `retry_compaction`，发 `retry_compaction` = 落一条 `message.removed` 删失败产物并按 `<base>|retry:<移除事实 id>` 换纪元重压。判据：`t18` 契约 E（6 轮摘要请求只有 1 次；读数块每轮额外请求 `[1,0,0,0,0,0]`、额外往返 `[152,0,0,0,0,0] ms`）与契约 F（读出口恰一个可重试失败节点 ⇒ `retry_compaction` 后摘要请求 +1）；摘要输入 ≤ 预算由 `t106` 与 `debt.test.rs::slice_stops_at_budget_instead_of_full_transcript` 钉住（实测 91,320 → 7,731，上限 8,192） |

### 边界

不含"该不该做这个动作"的价值判断——系统只保证有闸门、有授权、有熔断；
对外部世界已发生的事没有撤销；真实流量下的成本读数还没出。

## 10. 个人认知体系注入（SC-010）

> **一句话**：说话前先带上这个人的记忆与偏好——像他那样想，而不只是能做事。
> 支撑能力：[DE-040-个人认知体系注入](../003-design/040-个人认知体系注入.md "DE-040-个人认知体系注入")

### 场景

用户希望智能体"懂自己"：回答带上个人的知识、经验、判断风格，而不是千篇一律的通用助手；
必要时还能按内容类型、通用程度筛选要带上的东西。
今天的痛：换个人用同一个助手，说话方式与关注点完全一样；个人的判断和偏好存不下来、也调不出来。

### 用户判据（诚实账）

| # | 用户应该看到 | 判据现状 |
|---|---|---|
| 1 | 带上某人的认知：说话前先注入他的记忆与偏好 | e2e：t29（记忆召回注入，仅记忆面）（已有） |
| 2 | 按内容类型 / 层级 / 扩散 / 衰减检索记忆 | 未承诺：设计文档已逐条对码——`recall:tag` 在生产（唯一传标签的调用点是巩固），`layer` / `spread` / `decay` / `density` / `min_generality` 五个投影形参**不存在**（`min_generality` 连值的写方都没有）。判据要等能力，不先于能力 |
| 3 | 这个人的认知可供他人借用 | e2e：t76（`vis_scope = shared` 的记忆对矩阵内主体可见、对矩阵外主体不可见；`thread_private` 不进他人召回段——「可供借用」与「隔离」是同一条判据的两半）（已有） |

### 边界

本场景今天可见的是「记忆注入」与「跨主体借用」两面（判据 1 / 3 各有端到端锚），
其余（按内容类型 / 层级 / 扩散 / 衰减检索）基本是纸面；
召回质量系统层零保证；认知内容的正确性、代表性与隐私授权全在系统之外。

## 11. 技能编译与自我改进（SC-011）

> **一句话**：常用套路被攒成技能，命中时不再逐字重推，越用越快；不对劲时自动退回完整推理。
> 支撑能力：[DE-041-技能编译与自我改进](../003-design/041-技能编译与自我改进.md "DE-041-技能编译与自我改进")

### 场景

同一类事做过几次之后，智能体把成功轨迹攒成技能，下次自动带回有用的做法，少走弯路；
遇到异常或没把握的情况，自动退回完整推理而不是硬套旧招。
今天的痛：同样的事每次都从头推理，慢且贵；"越用越好用"无从谈起。

### 用户判据（诚实账）

| # | 用户应该看到 | 判据现状 |
|---|---|---|
| 1 | 常用的套路越用越快：命中技能时不再走一遍完整模型 | **不成立（能力按 D-318 主动退役）**：命中即跳过模型往返的快路已退场，今天只剩编译 + 注入 + 校准账目——判据由 e2e t35 承接 |
| 2 | 技能是从真实轨迹里攒出来的，不是手写的 | e2e：t35（已有） |
| 3 | "这条技能到底有多准"读得出来 | 生产读数：会话统计的校准列（使用 / 回退计数）（已有） |
| 4 | 技能强弱有更细的读数、编译有自己的角色 | 部分：reliability（1 − 回退率）读数已在生产且有判据——e2e：t28（`session/stats.calibration` 各列按已知动作钉死期望值，没编过技能 ⇒ 有据的空）。**凸度 / 密度读数未承诺**：设计文档裁决「全仓 grep 零命中，读数今天不存在，只测 reliability 不许顶着凸度的名字记账」；编译的 `Decider` 角色行同样未立项（编译是写侧函数，类型上不可投影化） |

### 边界

"哪些轨迹值得编译"是算法问题；编译错的技能会持续犯错——没有自动失效，只能观测后下线；
自我改进的收敛性与安全性未证明，系统只保证"改了什么可追溯"。

## 12. 自主层与长期目标（SC-012）

> **一句话**：人不在场它也会自己开工——定时触发、推进长期目标，发起的东西可追溯、可关停、不冒充用户发言。
> 支撑能力：[DE-042-自主层与长期目标](../003-design/042-自主层与长期目标.md "DE-042-自主层与长期目标")

### 场景

用户下班了，期望智能体按计划继续推进手头的长期目标：到点自己开工、跨天运行、自己排期。
前面所有场景都是"有输入才有行为"，本场景第一次是"没有外部刺激也会做事"。
今天的痛：再强的助手也只能等指令；而"会自己做事"的系统若不可追溯、不可关停，用户不敢放手。

### 用户判据（诚实账）

| # | 用户应该看到 | 判据现状 |
|---|---|---|
| 1 | 人不在的时候它也会自己开工（空闲到点自动触发一轮） | e2e：t36（已有） |
| 2 | 自己发起的东西不会冒充用户发言 | e2e：t36（已有） |
| 3 | "它有多主动"能被读出来 | e2e：t36（`session/stats.conation` 主动性列：过闸 ⇒ 一条带 `task_id` 的意图；拒收 ⇒ 同一条目标**也表达过**但 `task_id` 为空、采纳率为 0——分子与分母同出一列，因此读得出「想过但没做成」）（已有） |
| 4 | 长期目标作为一个独立角色在跑 | e2e：t36（心跳触发 ⇒ 闸门批准 ⇒ `task.opened`（`hb-{触发 seq}`）落格并进就绪集；拒收 ⇒ 不升格，就绪集始终为空——两半互为对照）。口径注：今天的「独立角色」是自主发起者（`authz::ROWS` 只持 `define.work`）开格，不是单独的长目标 actor |

### 边界

"该自主发起什么"是价值对齐问题——系统只保证发起了什么可追溯、可关停；
长期目标的拆解质量取决于多步任务能力；不是控制意义上的实时自主。

## 13. 多智能体社会（SC-013）

> **一句话**：一群智能体长期共存、按角色分工，有声誉有契约，能准入能淘汰——形成结构，而不只是点对点协作。
> 支撑能力：[DE-043-多智能体社会](../003-design/043-多智能体社会.md "DE-043-多智能体社会")

### 场景

大量主体长期共存，长出组织的样子：有分工（市场 / 仲裁 / 守门）、有契约网络、
有声誉排序、有准入门槛，失效的主体会被淘汰，且淘汰可审计、可申诉。
今天的痛：智能体一多就是一锅粥——谁该干什么、谁可信、谁该退场，全靠人盯。

### 用户判据（诚实账）

| # | 用户应该看到 | 判据现状 |
|---|---|---|
| 1 | 多个主体按角色分工（市场 / 仲裁 / 守门） | 部分：仲裁角色在生产（淘汰裁决步读它判写侧资格，`session/arbiter` 行五字段取实）且有判据——e2e：t74（裁决落格 + 闸拒 + 跨会话生效三格接在一起）；委派链上的工人角色有 e2e：t75（产物格作者是工人自己，同轮 `todo_write` 被任务表写侧闸诚实拒止）。**市场 / 守门未承诺**：设计文档记录两行只有 grants 数据行，「没有跑轮主体就没有 ActorSpec 构造点——行等主体，不是主体等行」 |
| 2 | 声誉读得出来，淘汰是可审计、可撤销的变更 | e2e：t30 / t42（`session/stats.reputation`：`offered` / `kept` 从同一份事实源读出，按承诺方分列）/ t74（淘汰回路：声誉低于阈值 ⇒ 一条可审计的 `verdict.asserted` 收回 `assign.work` ⇒ `agent_run` 被闸拒，同会话与**别的会话**都拒——「可审计、可撤销」四字由裁决落格 + 跨会话生效两半成立）（已有） |

### 边界

本场景今天接起来的是**仲裁**（淘汰回路：裁决落格 + 闸拒 + 跨会话生效，端到端有判据）
与**委派链上的工人角色**（产物格作者是工人自己）；市场 / 守门两行只有 grants 数据行、
没有跑轮主体；
社会结构的涌现质量完全不由系统保证；博弈、激励、合谋检测是机制设计问题，系统层连断言都写不出。
