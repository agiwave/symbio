# 插话与实时打断

> **一句话**：干活干到一半能插话——手头的事不丢、插话有明确去处（放行 / 挂起 / 排队），切走再切回来形状不变。
> 支撑能力：[DE-037-插话与实时打断](../003-design/037-插话与实时打断.md "DE-037-插话与实时打断")

## 场景

智能体正在说话或跑一个长任务，用户突然插一句：补充信息、改要求、或直接叫停。
期望是极短时间内有反应——第一件事不丢，第二件事有去处，事后能回到被打断的地方。
今天的痛：插话要么石沉大海，要么打断之后状态乱掉、收不回来。

## 用户判据（诚实账）

| # | 用户应该看到 | 判据现状 |
|---|---|---|
| 1 | 运行中说第二句：第一句不丢，第二句有明确去处 | e2e：t34 / t19（已有） |
| 2 | 能中止，中止后立刻收敛，不留悬挂 | e2e：t7 / t49（已有） |
| 3 | 实时面是三态的，切走再切回来形状不变 | e2e：t10 / t16 / t9 / t14（已有） |
| 4 | "谁判定该不该让插话先走" | e2e：t34（`PreemptionDecider` 忙窗里判出**挂起**，插话轮照常收束、历史完整；判定顺序「无在跑任务 ⇒ 放行」「已有收束发言 ⇒ 排队」两条都有生产锚）（已有） |

## 边界

只能在放行 / 挂起 / 排队里选（超时默认继续），不理解插话语义、不做复杂重规划；
不是硬实时控制；多个插话谁优先是策略问题。
