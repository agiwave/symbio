## 内容

现有 e2e（45 条，[e2e/README](../../e2e/README.md)）是**逐个发现式长出来的**：每步实施配一条新用例
（[PL-006-分步实施计划](../plan/PL-006-分步实施计划.md) 纪律 2），它保证了「每步有判据」，但**没有回答「覆盖面
缺什么」**——没有一张从能力出发倒推的矩阵，「漏测的场景」是看见一个才补一个。

本任务把覆盖面本身变成可盘点的东西：

1. **覆盖矩阵**：能力阶 × 场景形态（正常 / 异常 / 边界），每格登记现状
   （有用例 → 编号；缺口 → 待补；明确不做 → 理由）。矩阵是**缺口清单的登记处**，
   不是第二份用例索引（用例的 owner 是 `e2e/cases/` 目录发现式加载 + 用例文件头）。
2. **用例形升级为用户过程**：尽量完整模拟实际用户使用过程——
   - 长驻会话多轮 + 中途去过别的会话再回来（不是每用例一个全新一次性的会话）；
   - 「历史出口 + 实时出口」都要读（真实用户两个窗口都开着）；
   - 恢复 / 审批 / 中止收尾 / 压缩窗口 / 记忆召回这些**过程缝隙**优先于平铺直叙的成功 happy path。
3. **异常场景批量补齐**：依赖 [T-067-mockLLM体系化机制化](T-067-mockLLM体系化机制化.md) 的注入机制——LLM 侧异常（流中断 / 限流 /
   内容不规范 / 429）之外，MCP 侧（T6 已有一条）、网关 / 传输侧、存储侧的异常
   形态逐格落位。
