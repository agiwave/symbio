## 内容

`BASELINE.vitestFiles/vitestTests` 停在 `55/856`，而实测是 `54/838`——前端阶段
（`scripts/gate.d/20-frontend-static.mjs:114`）判「文件/用例数未达基线」而**恒红**：

```
✗ [frontend-static] vitest run --coverage — 文件/用例数未达基线：54/838（基线 55/856）
```

根因是 `76324817`（T-070）退役了被测对象却没跟上基线：`conversation_line.ts` 与其
185 行 spec 整文件删除（⇒ 文件数 -1），`appearance.spec.ts` 随分栏退役收窄（⇒ 用例 -18）。
这批提交的 `门禁：` 段写的是「本次跳过（未跑）」，所以这条棘轮一次都没被触发——
欠账一直躺着，直到本会话跑整轮门禁才暴露。

## 处置

按棘轮的**下修**路径走（不是删判据）：数字改成实测值，并各挂一条 `// baseline-allow`
写明「谁退役了什么、判据下沉到哪」。元守卫按格认豁免、理由非空才算，所以这两条注释
是判据本身，不是说明文字。
