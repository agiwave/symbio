`full` **没被真实会话负载压过**：e2e 全绿只是必要条件，不是「跑过真实负载」

## 处理过程

- 迁自 13 §1 问题登记（2026-10-11 进入登记机制）；批次内容与目标态归 13 §2，实施过程查 `git log`。
- 2026-10-12 落地（口径决策见 [ADR-058](../adr/ADR-058.md)）：

  **落地形态**：门内有界压测，判据全部读生产出口（gateway `session/stats`、
  `vdfs/read(<根>/session/<sid>)`、mock-llm 收到的原样请求体），会话内部存储文件一个都不读。
  负载形状表 / 七段判据归属 / 「没压到的两处」三节的 owner 是用例头部，本条不复述。

  **压测第一次真压出两次压缩，当场压出两个静默分叉**（这是本批的全部收益）：
  压缩把**本轮**的用户发言原文留在快照载荷尾部，而那条发言同时是本轮的开场格、落在快照
  之后 ⇒ 同一个节点身份两条来源。`rebuild` 按「同 id 只认首次」只认一条，
  `transcript` 与 `prompt_fidelity` 此前没有那一步：前者每次换基多产**一条重复的用户发言**
  （两个出口对同一段历史给两种读法，且完全静默），后者对同一条发言**主张两次**，第二次
  找不到未被用掉的匹配 ⇒ 每次压缩后每轮一条「网格→prompt 丢事实」**恒假警报**——
  终点第 1 条（双向完整性防线）靠的就是这个判据，恒红等于没有。
  两处按**同一条纪律**修（快照基线占住的节点身份不再产第二行 / 不再提第二次主张），
  且该判据只作用在换基边界、不作用在事实彼此之间（合成节点 id 的两个出处在 `rebuild`
  里本就是两个节点，去了重是另一种分叉）；各带双向单点判据，反向那条证明绿不是恒绿。

  **夹具侧为它补的能力**：mock-llm 场景可复用 `times: N`（按每次命中计数）与 `failTimes`
  按逻辑请求体指纹计数；跨用例的夹具陷阱记在 `e2e/README.md` 9–13 条（换基后「每个标记
  都在」这种判据本身就是错的，第一条踩过）。

  **配置只动一项**：provider 窗口。水位线是相对的（`0.7 × max_context_tokens`），不调窗口
  就要上万轮才触发一次压缩，那就不再是门内判据；`auto_compress`、`context_messages = 6`、
  `fade_activate_rounds = 40`、`tool_context_window = 15` 全取出厂默认——负载要真实，配置
  就不能是为用例特调的。

  **没做的事**：「对模型变好还是变坏」仍未闭环——mock 不是模型，那需要一次独立的、
  需授权的真实模型对照实验（另登记，不混进本批）；工具级骨架化与轮次淡化**在这条路上
  不可观测**（请求视图每轮只带最近一次工具交换），故未断言其占位符，单点用例 t18 / t45
  继续承担；请求体字节规模只作观测（校准估计器被夹具夹在 0.2 地板，按字节判量的是夹具）。
