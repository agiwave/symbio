## 内容

本任务由 [T-076](T-076-e2e面缺失补齐批.md "T-076-e2e面缺失补齐批") 的本地检索组行开出。
`e2e/cases/t64-local-search.mjs` 把这一行从「三格全空」推到「正常 + 异常各有锚」，
但**缝隙**列还空着——而这一族工具最容易出问题的恰恰是边界：分页参数写错就是
「结果看着像对的、其实少了一半」，索引增量失效就是「搜到的代码是上一版」。

### 为什么这些边界值得单列一批

`codebase_search.rs` 的模块头把「索引的时效性」当作**首要设计约束**（三条机制叠加：
每次调用扫文件集指纹 → 只重嵌改动文件 → 索引落盘），并明写「**静默的过期索引**
比慢更糟——agent 会拿一份不包含自己刚写的代码的索引去搜，且完全无从察觉」。
这句话目前只有 Rust 侧单测，端到端没有读数。

同理 `content_search` 的分页：`apply_line_pagination` 按**行**截断，而
`head_limit` / `offset` 是模型会传的参数（对齐 Trae Grep）——传错了没有任何报错，
只是结果少了。

### 与 T64 的分工

T64 钉的是**「工具真的读了磁盘」**（随机标记）与**「模式自报与结果形状自洽」**。
本任务钉的是**同一条链路上的边界取值**。两批的判据都在同一条用户可见出口上取
（模型收到的 `role=tool` 正文），不引入新的读数面。

## 处理过程

- 2026-10-15 登记：T64 落地后按 RE-005 三列口径清点该行，正常/异常已有锚、缝隙为空。
- 2026-10-15 落地：拆两条用例，**未动生产代码**。
  - `e2e/cases/t67-content-search-edges.mjs`：①`output_mode` 三取值（`content` ⇒
    `<路径>:<行号>:<内容>` / `files_with_matches` ⇒ 纯路径 / `count` ⇒ `<路径>:<条数>`）；
    ②`offset` 跳过 + `head_limit` 截短；③输出超 1 MiB 的截断尾注（1000 行 × ~1.1 KB 的
    大文件，把字节数堆过 `MAX_OUTPUT_BYTES` 而匹配数不超 `MAX_RESULTS`）。
  - `e2e/cases/t68-codebase-index-edges.mjs`：③索引增量（首次 `embedded_files == files`、
    第二次 `embedded_files == 0` 且 `reused_files == files`）；④`rebuild=true` 全量重嵌；
    ⑤`keyword_fallback` 单独驱动（空工作区 ⇒ `get_index` 返回 None）。
  - **两处负向自检**：去掉 `rebuild: true` ⇒ 第三次退化为增量、全量断言红；去掉 `offset: 1`
    ⇒ 第 1 个匹配行出现、跳过断言红。
  - **一处核实订正**：`keyword_fallback` 的「嵌入服务**不可用**」路径**无配置面**——
    `codebase_search.rs` 硬编码 `EMBEDDING_LOCAL`、模型 `include_bytes!` 进二进制，全仓
    没有配置位能切到 `EMBEDDING_NOOP` ⇒ 该路径 e2e 驱动不了（要驱动得先加配置面，属能力
    新增）；可驱动的只有「工作区无可索引文件」这条，本批已驱动。
  - **一处实测发现（生产侧缺口）**：`content` 模式的输出**每匹配行后多一个空行**
    （`UTF8Sink` 给的 `text` 含行终止符 ⇒ `out.push("{path}:{ln}:{text}")` 再 `join("\n")`
    得 `行\n\n行`），`apply_line_pagination` 因此按**输出行**切、与匹配行不对齐
    （`head_limit=2` 只覆盖 1 个匹配行）。`content_search.rs` **没有单测文件**，所以此前
    无人发现。t67 的分页判据因此降级为「`offset` 跳过 / `head_limit` 截短」两件不受空行
    影响的事实，缺口另登 [T-113](T-113-本地检索输出残余批.md "T-113-本地检索输出残余批")。
  - 全量门禁绿，`BASELINE.e2eCases` 64 → 66。
