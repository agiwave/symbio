## 内容

本任务由 [T-076](T-076-e2e面缺失补齐批.md "T-076-e2e面缺失补齐批") 的本地检索组行开出。
`e2e/cases/t64-local-search.mjs` 把这一行从「三格全空」推到「正常 + 异常各有锚」，
但**缝隙**列还空着——而这一族工具最容易出问题的恰恰是边界：分页参数写错就是
「结果看着像对的、其实少了一半」，索引增量失效就是「搜到的代码是上一版」。

### 为什么这些边界值得单列一批

`codebase_search.rs` 的模块头把「索引的时效性」当作**首要设计约束**（三条机制叠加：
每次调用扫文件集指纹 → 只重嵌改动文件 → 索引落盘），并明写「**静默的过期索引**
比慢更糟——agent 会拿一份不包含自己刚写的代码的索引去搜，且完全无从察觉」。
这句话目前只有 Rust 侧单测，端到端没有读数。

同理 `content_search` 的分页：`apply_line_pagination` 按**行**截断，而
`head_limit` / `offset` 是模型会传的参数（对齐 Trae Grep）——传错了没有任何报错，
只是结果少了。

### 与 T64 的分工

T64 钉的是**「工具真的读了磁盘」**（随机标记）与**「模式自报与结果形状自洽」**。
本任务钉的是**同一条链路上的边界取值**。两批的判据都在同一条用户可见出口上取
（模型收到的 `role=tool` 正文），不引入新的读数面。
