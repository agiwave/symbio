## 内容

`docs/CURRENT.md` 现在给的是**结构**（有哪些插件、哪些工具、哪些路由），不给
**语义**（这条工具让用户看见什么、这条路由对应界面上的什么动作）。于是「系统能
做什么」这件事要从代码读一遍才知道，而这份读数无法被复核——它没有 owner。

「用户可见语义」在代码里本来就有，且是**同一份**：`CapabilityMeta.description`
是模型与前端看到的原文、`category` / `risk` / 上下文保留策略决定它怎么被呈现与
审批；每个 `VDFS_*` 常量上方有该操作的一句话定义；`ROUTE_*` 常量与 `route()` 的
`match` 臂上有该地址的职责。把它们抽出来拼成一张矩阵，是**提取**不是复述。

## 边界

- **不新造语义**。抽不到就写「（代码内无语义来源）」，不替它编一句。
  缺的那几条在源码补一句文档注释，**补在注册处**（`match` 臂旁 / 常量旁）——
  描述长在它描述的东西旁边，此后由提取跟随，不进任何表格维护。
- **不与 RE-003 争夺 owner**：路由的**调用方与契约**仍归 RE-003；本节只给
  「这条地址是干什么的」一行摘要，权威清单与缺口仍指向 RE-003。
- **不覆盖 e2e 覆盖矩阵**：本节是「能力有哪些」，不是「测到了什么」。后者归
  [RE-005-e2e覆盖矩阵](../ref/RE-005-e2e覆盖矩阵.md)。

## 处理过程

- 2026-10-16 落成。语义出处三处：工具取 `CapabilityMeta.description` 与同体的
  `category` / `risk` / 保留策略；VDFS 操作取 `VDFS_*` 常量上的 `///`；路由取
  `route()` 臂上的注释。§2 那张人手写的「类别 / 备注」表**保留不动**——它答的是
  「怎么分类」这一层判断，而 §6 答的是「用户看到什么」；两者不争同一句事实。
- **路由职责为什么写在臂上而不是 core 常量上**：`route.rs` 的常量只收「有真实
  Rust 调用方」的路径，20 条里大半是前端专用的，它们没有常量、也就没有注释可抽。
  臂是**注册处**，描述贴在那里，改路由的人必然看到。
- **RE-003 的「用途」列必须一起收敛**：那 92 行与臂上注释是同一句事实的两份副本。
  按 PL-011 §6「原表与迁移不拆批」，出口是「原处只留指路」，留两处半截登记比不做更糟。
  只剩两列且第二列全是指针的表退化成地址清单（表格反而碍眼）。
- 提取侧踩到并修掉的四个坑，每个的失效形态都是**静默少一条**：
  1. 只认 `///` 认不到路由——臂在函数体内，那里 `///` 不是 Rustdoc，作者自然写 `//`；
  2. 注释块不要求「连续紧邻」会把 `match` 上方的**整体**说明挂到第一条臂头上
     （`home/reload` 就是这样挂错了一段讲资源清单的注释）；
  3. `\\.` 匹配不到换行 ⇒ 带行续写的 `format!` 描述（`agent_run`）整条抽不到，
     症状是「那个工具没有描述」，看起来像没写；
  4. 描述里的 `|`（`type（directory|file）`）会把表格那一行**静默错位**，而生成器
     只管吐文本、看不见渲染结果——补了 `cell()` 转义 + 一条列数回归测试。
- `grep-audit` S-010 抓到第四个：工具描述里提到 VDFS 挂载根目录，而根名字面量
  只归 `plugins/vdfs/fs.rs`。§4 的存储布局表早就用占位处理过同一件事，本节沿用
  同一套 `maskRoot()`（取值运行期抽取，不硬编码）。
