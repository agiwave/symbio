## 内容

既有 e2e（55 条）的判据形态是「**发起请求 → 接收响应**」：CLI 退出码、stdout 正文、
转写节点、实时面帧序——全都落在**响应用户**这一侧。而整条链路里最关键的一环
「**用户请求 → 系统实际发给模型的调用**」只有零散探针（t1 的工具清单、t26/t29 的
请求回读、t46 的形状基线），没有一条**系统性**判据面：模型收到的信封参数、system
装配、历史保真、工具反馈、工具面集合、辅助请求形状——每一项坏了，响应侧可能
照样绿（模型自己兜底），而「对模型的调用已经不对了」没有任何东西会红。

这正是 GO-005 两个支撑面之外的**第三个面**：mock-llm 的 `/_requests` 就是模型的
视角，请求体是「系统怎么理解用户请求」的唯一完整投影。本任务把它从零散探针升级为
体系化判据面：

| 面 | 判据 | 拦的失效 |
|---|---|---|
| 信封与模型选择 | provider 配置逐字段进请求；`stream` 恒 true；有工具才 `tool_choice=auto` | 配了不用 / 用错模型 / 参数静默丢失 |
| system prompt 装配 | 注册段（人格 / 记忆 / 智能体 AGENTS.md）+ 请求级前缀合成**一条** system 且置顶 | 段丢失 / 段序错 / 前缀把用户发言顶掉 |
| 多轮历史保真 | 第 N 轮请求 = 前 N-1 轮完整重放，无重复无丢失 | 长轮失忆（T-095 同族复发）/ 历史错位 |
| 工具反馈契约 | 每个 `tool_calls` 都有配对 `role=tool`（id 一致、内容为真实产出） | 有请求无响应 / 结果串格 |
| 工具面契约 | 出厂 19 工具 + 条件工具（read_skill / MCP 桥接）+ 无内部面泄漏 | 工具漂移（与 CURRENT.md §2 对账） |
| 无内部泄漏 | user 消息正文 == 用户原话；prompt 不含 homedir / 端口 / 临时路径 | 环境细节泄进 prompt / 用户发言被包装 |
| 辅助请求形状 | 分类 / 措辞 / 汇报 / 压缩各自的请求形状（单 user、自有 system、无工具面） | 对话面调优静默改变请求形状 |

**与既有判据的分工**（一个事实只有一个 owner）：

| 谁 | 判什么 |
|---|---|
| 本面（LC-001…） | 每次调用的**语义正确性**（值对不对、段全不全、序对不对） |
| `prompt-shape-audit`（PS-001…003） | 出厂主线的**结构形状**（逐字段漂移） |
| t21/t22/t23/t29/t35/t41 | 对话面 / 记忆 / 技能的**行为**（翻开关会红） |
| t46 | 把真实请求体喂给形状脚本（执行方） |

## 边界

- 不重排既有用例的判据（t26 的工具回灌、t29 的记忆注入保持原样），新面只做**系统化
  汇总 + 补缺**；判据口径冲突时以本任务的「分工表」裁决归属。
- 不读任何内部存储文件（T-056 读通道禁令）——模型的请求体是**边界事实**，与
  mock-llm 的 HTTP 记录同源，不属内部状态。
- 协议适配（4 套 wire 形状）归 [T-076](T-076-e2e面缺失补齐批.md "T-076-e2e面缺失补齐批")，本面只走 openai_chat 一条（mock 只实现该线格式）。

- 2026-10-16 落成：`e2e/llm-contract.mjs`（契约断言库，LC-001…007）+ 8 条用例
  （t56–t63，60 例总数）。落地中实测修正的契约认知（都写进了用例的头部注释）：
  - **多工具轮的 wire 形态**是「每次调用各一条 assistant 消息 + 各自相邻的 role=tool
    结果」，不是合并成一条多 tool_calls 的 assistant（t62 按实测钉相邻配对）；
  - **辅助请求（classify/compose/压缩）一律不带工具面**（`execute_turn(_, _, &[], …)`），
    识别按结构特征（system 标记 + 有无 tools），不按调用点顺序（t61）；
  - **mock-llm 请求记录跨场景累积**，多场景用例每场景前必须 `await llm.reset()`
    （t59 场景②③ 曾因此读到场景①的请求）；
  - **`E2E_CASE_SELF=1` 才是用例自执行开关**——直接 `node cases/x.mjs` 时
    `_selfrun.mjs` 的门控让用例根本不执行（退出 0 无输出，最危险的假绿形态），
    单跑必须 `E2E_CASE_SELF=1 node e2e/cases/x.mjs`；
  - 技能的条件注册路径是 `<homedir>/skills/<name>/SKILL.md`（`skill_dirs` 默认来源），
    非空时才注册 `read_skill`（t59 场景②）。
  工具面与文档对账的即时价值：CURRENT.md §2 从 12 补到 19 工具。
  另清偿 [T-074](T-074-压缩中插话判据补齐.md "T-074-压缩中插话判据补齐")（t63）：确立「MockLLM 请求记录 =
  压缩中插话的生产出口」（实时面/转写都是事后出口，插话是否被吞只能从收敛后
  主线请求的 user 消息在场与否判）。
