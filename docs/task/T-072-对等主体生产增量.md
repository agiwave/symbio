## 内容

[ST-008](../stage/ST-008-多主体与对等承诺.md "ST-008-多主体与对等承诺") §3.1 已逐条核实：**机制侧（`principal` / `vis_scope` / `commitment` 格子 /
`reputation` 投影）在生产，对等侧数据行未落地**——今天的多主体只有主从树（委派者 ×
`agent_run`），PL-001 §12 说的「递归是树、协作是图」的图侧**没有一个主体**：`agent:peer-b`
这个名字今天只活在测试与登记表里（`view/mod.test.rs` 的可见域判定、`actors/mod.test.rs` 的立约彩排、
批① 落的 `authz::ROWS` 那一行），**没有任何一条路径真的以它为身份跑一轮**。

排期就是补那两行增量（原 ②/③ 已合并，见下），次序固定：

1. **批 ①（窄行先行）—— 已落地**：授权行与对等主体同批出现（[PL-009](../plan/PL-009-多执行器与多主体加固实施方案.md "PL-009-多执行器与多主体加固实施方案")「闸不能晚于发起者」同纪律）。
   危险面是现成的：未登记 `agent:<id>` 走 `matrix_for` 派生分支拿整套能力（含 `reply.*`），
   [ST-012](../stage/ST-012-自主层与长期目标.md "ST-012-自主层与长期目标") §3.1 已为自主主体修掉同形静默面——对等不许再踩。
2. **批 ②（对等主体跑一轮）**：原 ②（`asserted` 写方）与原 ③（对等角色能跑轮）**是同一批**
   （[ADR-065](../adr/ADR-065.md) 裁定）——`asserted` 的写方住在轮末收束族
   （`symbio/src/plugins/session/v2_facts.rs`，不开第二条写通道，I1），而收束族只在该轮
   **收束成功**时执行；对等主体只持 `produce.artifact`，收束闸恒拒 ⇒ 写方永远执行不到。三件事同批：
   - **收束格按种类判**：`turn_runner::closure_granted` 由 `(principal)` 收为 `(principal, kind)`，
     发言收束问 `reply.*`（今天的行为，一字不变）、产物收束问 `produce.artifact`。今天六个调用点
     全是发言收束，故**形状先定、代码与产物收束的写方同批落地**（没有生产方的机制不进生产）。
   - **对等主体的 ActorSpec 真值**：起步形态 = 第二个会话选定第二个 agent
     （`principal_of` / `matrix_for` 已是通路）；要补的是这条路上 ActorSpec 的真值
     （§3 的 `pattern: translator` / `capabilities: [ProduceArtifact]` / `budget_ms: 30000` /
     `scope: root`），不是新造一条不依附会话的路径。
   - **入站请求的「来源主体」这一格数据**：`asserted` 的 `to` 必须是**数据**（[PL-001](../plan/PL-001-核心架构.md "PL-001-核心架构") §12.2
     「跨体承诺 → `asserted` + 对方 Log 引用」），而今天它是在 `v2_facts` 调用点写死的
     `PRINCIPAL_USER`，网关入站也不带主体——先补这一格，才有「向谁宣告」。
   语义住 [PL-001](../plan/PL-001-核心架构.md "PL-001-核心架构") §12。
