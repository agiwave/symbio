## 内容

[ST-008](../stage/ST-008-多主体与对等承诺.md "ST-008-多主体与对等承诺") §3.1 已逐条核实：**机制侧（`principal` / `vis_scope` / `commitment` 格子 /
`reputation` 投影）在生产，对等侧数据行未落地**——今天的多主体只有主从树（委派者 ×
`agent_run`），PL-001 §12 说的「递归是树、协作是图」的图侧只有测试实例（`agent:peer-b`
仅现于 `symbio/src/symbio_core/actors/mod.test.rs`）。

排期就是补那三行增量，次序固定：

1. **批 ①（窄行先行）**：授权行与对等主体同批出现（[PL-009](../plan/PL-009-多执行器与多主体加固实施方案.md "PL-009-多执行器与多主体加固实施方案")「闸不能晚于发起者」同纪律）。
   危险面是现成的：未登记 `agent:<id>` 走 `matrix_for` 派生分支拿整套能力（含 `reply.*`），
   [ST-012](../stage/ST-012-自主层与长期目标.md "ST-012-自主层与长期目标") §3.1 已为自主主体修掉同形静默面——对等不许再踩。
2. **批 ②（asserted 写方）**：`commitment.opened`（offer）与 `commitment.asserted` 的
   生产写路径，语义住 [PL-001](../plan/PL-001-核心架构.md "PL-001-核心架构") §12；写方仍走轮末 `symbio/src/plugins/session/v2_facts.rs`
   的收束族，不开第二条写通道（I1）。
3. **批 ③（角色能跑轮）**：会话独立的 ActorSpec 构造路径——生产构造点今天唯一在
   `symbio/src/plugins/session/v2_exec.rs`（会话驱动）；对等角色要么复用该点（第二个会话
   选定第二个 agent ⇒ `principal_of` 已是通路），要么立一条新构造路径，**后者必须先过
   core 形状棘轮**（[ADR-055](../adr/ADR-055.md)）。
