## 内容

T-099 收尾时用户指出「`CURRENT.md` 里已经收集的信息，不要在其它文档重复描述」，追查发现
机制缺口有两层，本条是第二层。

**第一层（已做，见 T-101）**：`CURRENT.md` **自身**的重复——§2 工具清单与 §6.1 工具语义
行集交集 25/25、§3.2 与 §6.2 两处列同一批 VDFS 操作、§1 与 §6.3 两处列同一批路由。
根因是 T-098 新增 §6 时没删掉它覆盖掉的旧节。

**第二层（本条）**：`docs/README.md` 的「文档职责边界」是一张**承诺表**——它写着
「不手抄，需要就引用」，但**承诺本身无人守**。D-001…D-010 全是查链 / 查措辞 / 查形态，
没有一条查「同一事实被写了两遍」。于是：RE-003 当年就有过两张路由表并存的形态（各自漂移），
且没有任何东西会红。

已落地的部分（本条是它的延伸，不是从零开始）：`scripts/facts.test.mjs` 已有

- **文件内**判据：CURRENT.md 里每个封闭集只在一处成表；
- **跨文档**判据：CURRENT.md 的三个封闭集不得在别处成表复述，白名单逐条写明它保什么。

两条都做过**反向验证**：把当年那三种重复形态注入回去，判据必须红；不验证的话「全绿」
只说明判据没被触发，不说明它能触发。注入验证当场抓出三次问题——两次是**守卫自己**的
bug（按字面形状判身份，插件目录名长得像工具短名、`vdfs/read` 长得像路由），一次是
**注入脚本**的 bug（从被注入的文件自身取名单，注入了空表）。

## 未覆盖的部分

判据只认 CURRENT.md 投影的三个封闭集（工具 / VDFS 操作 / 路由）。职责边界表里的其余
owner 各有一张表，**尚未**纳入：

| owner | 投影物 | 该怎么判 |
|---|---|---|
| RE-002-ERROR_CODES | 错误码 | 成员 = 错误码字面量；owner = 该表本身 |
| RE-001-CONFIGURATION | 配置项 | 成员 = 配置键路径；注意「配置值里引用别的事实」（白名单那条） |
| GATE_CODES | 判据码 | 已由 `scripts/facts/gate-codes.mjs` 生成，机制上更难漂 |
| PROMPT_SHAPE | prompt 形状基线 | 真实链路生成，改动面是 e2e 而非文档 |

接入方式已经想清楚（读同一份「成员集合 + owner」声明，不新增第二处），但每接一个都要
配一次反向验证——否则只是把「没人守的承诺」换成「没人验证的判据」。
