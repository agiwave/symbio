## 内容

本任务由 [T-110](T-110-通道与自动化面e2e补位.md "T-110-通道与自动化面e2e补位") 第一批的**实测**开出：
原判定写「`home/reload` 经 gateway 直发即可驱动」，实测**推翻了它**——而且推翻的方式暴露出两处不一致。

### 实测到的那件事

`e2e/cases/t69-channel-routes.mjs` 打 `home/get_homedir`，回 **400**：

```
{"error":"插件未找到：Composite: 路径 'home/get_homedir' 无法识别或子插件未挂载"}
```

错误是 **Composite** 发的，说明请求**根本没到 home**。追到源头：

- `gateway/plugin.rs::start_server` → `server::start(&cfg, parent)`，
  而 `parent = ctx.parent()`——gateway 挂在 **worker composite 之下**，
  所以入站请求的 router 是 **worker composite**；
- `composite.rs::route` 对认不出的名字直接 `Err(PluginError::NotFound(...))`，
  **不向上转发**给父（home）；
- 而 `home` 是 composite 的**父**（`home/plugin.rs::rebuild_worker_sync` 挂的 worker），
  它的四条臂 `home/reload` · `home/get_homedir` · `work/set_workspace` · `work/get_workspace`
  因此**都不在入站可达面上**。

`hook/*` · `telegram/*` · `vdfs/*` 这些 composite 的**子插件**路由可达，
所以这个缺口此前一直不可见——它们把「入站能路由」这件事占住了。

### 不一致一：模块文档声称的能力面比实现大

`gateway/server.rs` 的模块头写着：

> 本模块是**现有 Tauri 命令的一对一映射**……因此**没有引入任何新协议**：
> 第三方或另一个 Symbio 实例拿到的能力与前端完全一致。

但前端经 `callPlugin`（Tauri `invoke` → 进程内 `root.route`）调的是**根**，
`home/*` 与 `work/*` 都在它的可达面上（`tauri/src/services/home.ts` 四条都用了）；
入站边界的 router 却是 composite。**「完全一致」少了四条臂**。

### 不一致二：只读白名单里躺着两条走不到的路由

`gateway/config.rs::is_readonly_allowed`（72-88 行）的白名单含：

```rust
| "home/get_homedir"
| "work/get_workspace"
```

这两条**在入站边界上不可达**（同上）⇒ 它们是**死条目**：只读模式下调用它们，
`is_readonly_allowed` 会放行，紧接着 `dispatch_once` 路由到 composite 得 404。
即「允许」的实际效果是「404」，而不是「拒绝调用」——白名单读起来像在守一条存在的路，
实际守的是一条不存在的路。

这与 [T-100](T-100-跨文档复述判据覆盖面补齐.md "T-100-跨文档复述判据覆盖面补齐") 查出的
「恒真的守卫」同族：**看上去在管一件事，实际什么都不管，而且反向验证也照样绿**。

### 两条路各自要做什么

**路①（抬边界）**：让 gateway 拿到**根**而不是 `parent`。
技术上要解决「gateway 在 composite 之下、却需要根的引用」——
可选做法：composite 在 fork 子上下文时把根经一个 ctx 键传下去（与 `PLUGIN_DIR` 同款），
或 `home` 在 `rebuild_worker_sync` 时把一个「根引用」键设进 worker 的子上下文。
**风险要评估**：抬上去之后 `home/reload` 也进入站可达面 ⇒ 非只读令牌能切 homedir。
这不是越权（非只读本来就能写 VDFS），但**能力面变大**这件事要在文档里写明，
并给 `home/reload` 一条判据（改完能读回新 homedir）。

**路②（收白名单）**：承认「入站边界只覆盖 worker 子树」，把两条死条目删掉，
把 `gateway/server.rs` 的「与前端完全一致」改成「与前端在 **worker 子树内**一致」。
这条路更小，但要接受「第三方拿不到 home/work 的能力」这一事实——
**撤销条件**：若将来出现「第三方客户端需要读 homedir / 切工作区」的真实需求，
路① 重开。
