## 内容

能力坐标地图逐阶落地审计（各阶 §3.1）暴露一个**横切形态**：ActorSpec 的机制在生产、
角色数据行只在正文与测试里——生产构造点唯一是 `plugins/session/v2_exec.rs:1063,1314` 的
`ActorSpec::trivial(request_principal)`（pattern=Decider、capabilities=空）。于是：

| 阶 | 正文行 | 今天 |
|---|---|---|
| S01 | reasoner+[ReplyFirst,ReplyAppend], 300ms | 名不符（trivial 顶账；300 无读方） |
| S02 | `agent:worker`, ProduceArtifact | 主体只现于 `governance/mod.test.rs:99,156` |
| S03 | 规划者/验证者 + `scope=child:<id>` | 零构造（`Scope::Child` 类型在、无人建） |
| S04 | 调度者 (AssignWork, 80) | 档位真、行假——等 T-083 |
| S06 | 检索者(Translator,500)/巩固者(Reasoner) | 召回=读路内联、巩固=轮末写方，不过 ActorSpec |
| S07 | 抢占判定者 (JudgeIntent, 80) | `PreemptionDecider` 生产直驱但从不构造行 |
| S09 | 闸门 (ProduceArtifact, 80) | 落地为纯函数判定，非 ActorSpec |
| S11 | 编译者 (5000) | 编译=写方调用，无独立 Actor |

这不是八个小功能，而是**同一个缺口的八次显形**：主体行承载的预算/能力/范围语义在生产里
没有落点。前置正是 [T-072](T-072-对等主体生产增量.md "T-072-对等主体生产增量") 批③（不依附会话
的 ActorSpec 构造路径 + 字段有真读方）——路径一通，本批就是逐阶补数据行的机械活，
每行可独立回退。
