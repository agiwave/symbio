## 内容

「LLM 单响应工具数超限 → 会话卡住 → 内部错误：生成失败」这组修复的三件套里，
两件套已有 e2e 锚（超限丢弃+反馈 = t48；断流可见失败 = t49），第三件套——
**断流后原样重发的槽位处置**（`tool_accumulator` 的 `touched` 过滤 +
`reuse_node_ids` 播种复用，`symbio/src/plugins/model/` 本批）今天只有
`tool_accumulator.test.rs` / `stream.test.rs` 的白盒判据。

它是用户可见的：播种槽位若被当成调用产出，执行层照空壳发请求 ⇒ provider 报
「tool_call 无对应结果」；重试换 id ⇒ 前端同批留两套卡片。黑盒纪律（T-067）下
这两条都该有 e2e 出口，不能只靠「测了累加器自己」。
