## 内容

用户原话的痛点：**「每次运行完门禁无法通过时，只能看到汇总信息，看不到详细的错误信息，
造成经常需要重复运行门禁查看错误日志，非常浪费时间。」**

追查发现这不是一个疏漏，而是两个机制各缺一半：

1. **失败详情只给一行文件名**。`report()` 的失败清单逐项印「· 任务 → 路径」，
   真正的错误正文在那个文件里——终端的失败处与文件里的信息量之间隔了一次重跑
   （或者一次手拼路径的 `cat`）。
2. **日志每轮覆盖**。`run()` 一律以 `flags: 'w'` 写 `.workbuddy-ai/gate-logs/<任务名>.log`。
   于是失败之后**再跑一次门禁**（哪怕只想看看别的阶段过没过）就会把失败证据冲掉。
   两个病叠加：想看得重跑，重跑可能还没得看。

## 不是本任务范围

- **失败原因的智能定位**（从 cargo test 日志里抽出失败的那几条断言）。现在是末 N 行
  的启发式，够用且不猜；更聪明的提取是另一件事，且容易把「猜错的原因」印得和真的一样响。
- **CI 上的日志上传**（artifact）。判据在 58-e2e 已有一条同源教训：CI 上没有本地目录
  可打开，所以失败详情必须**印在日志里**——本条正是按那个方向做的。
