## 内容

接管 [13 §2.1](../archive/13-质量改进总纲.md) 的豁免通道登记（C-003 账本 /
D-004 全文豁免 / dead-code-allow / panic 账本 / color）。这是**机制类元素**：
一条豁免的要素（位置、形态、清除任务、随机制存在的判据）与现有 kind 的字段不完全
对得上——按协议先定案形态：能用 `spec` + 状态承载就不加 kind；确实装不下再按
[PL-011 §2](../plan/PL-011-登记与汇总机制.md "PL-011-登记与汇总机制") 的新增方式加 kind（配置 + 渲染器 +
回归测试，同批落地）。清除任务列的指向关系要变成机械可核（指向存在的条目编号）。

## 处理过程

- 形态定案：**不加 kind**——豁免 = `spec` 条目 + 新增 `clears` 字段。
  复用 `deps` 不行：`deps` 是前置（RG-008 要求 active 条目的前置已闭环），
  而豁免**合法地挂在开放的清除任务上**——那正是「现在不修 + 倒计时」的语义，
  两者语义相反，指认必须走独立字段。
- 机制扩展（同批带回归）：`KINDS.spec.optional` + `clears`；**RG-016**
  （目标必须存在且为 task、不重复，**不要求闭环**）；spec INDEX 的 active 表
  加「清除」列；SP-001 字段表加行（RG-011 对账）；回归 +1（注入 ×2、反向、
  渲染列断言）。
- 迁移（`c167e00`）：5 行 → `SP-027…05`——形态进 `## 规范`，理由 owner 仍
  在各守卫账本/豁免注释（一条一个 owner，不复述）；`clears` 指到 T-059/T-060；
  判据指认各守卫脚本。13 §2.1 保留标题（`#21` 锚点有入站），正文收敛为
  指路 + 登记姿势；同批改口径引用（13 纪律 5 判据列、轨 W 的 T-059/T-060 指向、
