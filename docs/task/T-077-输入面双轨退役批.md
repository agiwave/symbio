## 内容

[ADR-031](../adr/ADR-031.md) 自记残余（正文「未完成（有意留下，需要自己的 ADR）」）：
输入面今天**双轨并存**——inbox 地址写入（用户主路径）与 `chat/send` / `chat/abort` 两条路由
（委派、telegram、CLI 仍走）。按用户裁定「违背目标且因妥协留下的判定 = 历史遗留，必须有任务」，
本条接管该遗留；GO-000「一个事实只有一个 owner」叙事在双轨期间带病运行。

## 处理过程

- 2026-10-13 登记（ADR 全量复核发现：残余无任务承载，`docs/task/` 全目录 grep 零命中）。
- 2026-10-13 **步①（协议决定）落地 = [ADR-066](../adr/ADR-066.md "ADR-066")**：裁决「地址写入**不**承载运行选项」。
  三条依据：① `provider_id` / `mode` / `risk_level` 在契约里**已有会话 metadata 回退**
  （`orchestrator/entry.rs::resolve_session_params` 的三条对称链 `req > metadata > 默认`，
  其中 `provider_id` 那条**代码有、字段文档没写**——已在 `session_chat.rs` 的字段注释里补上，
  并把它标为本 ADR 的不变量）；② 三者描述的是**会话级事实**（这个会话怎么跑），不是消息属性；
  ③ 四个调用方逐个核对，没有一个需要协议变宽——`agent_run` 要的三项它**已经在写
  子会话 metadata**（`register_subsession`）、心跳改走**进程内直连**（`include_history` 是本次发送
  属性，留在 `Request`）、telegram 的 `mode: "auto"` 是通道属性、CLI 原先刻意走 `req` 档做调用级
  覆盖（该意图保留，落点改为会话 metadata）。
  否决了「包裹形状 `{message, params}`」（判别式从一条变两条，把 `parse_inbox_message`
  「取『以 `{` 开头』而不是『能不能解析』」那条纪律在同一个函数里推翻）与「平级保留键 `params`」
  （会成为 `ChatMessage` 字段子集里的保留键，要么静默丢弃、要么给它加一个不该有的字段）。
  据此 AR-010 §5.6 的状态由「⚠️ 前置条件」改为「✅ 已裁决」，§8.2 第 1 项改判为「前置条件已解除，
  待步② 执行」。**步② 的前置条件由此解除。**
  （步② 落地时订正了本条初稿的一处与代码不符：CLI **带**全部三项。见 ADR-066 的「订正」段。）
- **步②（退役两条路由）进行中**：`telegram` 已改走地址面，并**连带修掉一条真实回归**——
  它把 `session/chat/send` 的回包当 `session_chat::Response` 解析，而那条路由的 `message`
  分支只是入队的薄包装、回包恒为 `{"status":"accepted"}`，`Response { message: ChatMessage }`
  又没有 serde 缺省 ⇒ `payload.get::<Response>()` 恒 `Err` ⇒ **用户永远收到「无响应」**（`if let Ok`
  把失败吞了，全程无报错）。同一缺陷 2026-09-22 修过一次，随实时面下沉 VDFS（ADR-025）回归。
  修法是走**实时面**取最终答复（`event_bus` 订阅 + `vdfs/watch <会话地址>` + 会话节点离开
  `working` 收尾），与 CLI / `agent_run` 同构；`mode: "auto"` 按 ADR-066 落成**会话 metadata**
  （一次带 `create` 的 `vdfs/write` 同时覆盖新建与改元数据）。顺带修正两处：轮询循环从串行
  `await` 改为**每条消息各起一个后台任务**（此前串行 ⇒ `latest_version` 那条中断判定恒不成立，
  且改走实时面后一个长轮次会把整个 bot 堵住）；答复为空时给一句诚实的「（本轮没有产生文本输出）」。
- **步② 续（同一批的其余三方 + 路由自身）**：
  - `heartbeat` 改走进程内 `self.enqueue_inbox(...)`（`params` 直接给，不经路由也不经 VDFS）；
  - `cli/src/client.rs` 的 `ask` 改写入面，**选项随行**：新增 `options_dirty` 标记——
    `switch_provider` 置脏，下一次 `ask` 先 `ensure_session`（一次 upsert 同时覆盖「新建会话」
    与「改元数据」）再入队；`switch_session` 落库后清脏。**不每轮都写**——那会让一轮对话多出
    一趟与内容无关的写入（t14「一轮一次会话请求」的判据正建在这上面）；
  - `agent_run` 经 `get_vfs_provider()` 写 `<sid>/inbox`，resume 走
    `action(<sid>/message/<mid>, <ResumeAction 线上词形>)`；`register_subsession` 的 metadata
    补上 `mode` / `risk_level` / `provider_id`（ADR-066 决策 1 的子会话侧落点）；
  - 两条路由 + `ROUTE_SESSION_CHAT_SEND` 常量 + `handle_chat_send_oneoff` /
    `handle_chat_abort_oneoff` 全删，`session` 的 `route()` 只剩 `stats`；
  - e2e：t7 / t9 / t10 / t11 / t18 / t27 / t54 迁到地址面，新增 `sendInbox` / `abortSession` /
    `resumeSession` 三个 helper；t14 的「恰好一次会话请求」改判**地址形状**（留痕带上地址后缀，
    否则 `vdfs/write` 上的两件事——落会话 metadata 与入队——会被混为一件）；
  - 文档：RE-003 移除两行并补退役索引、AR-010 §5.5/§8.2、`CURRENT.md` 与
