## 内容

前端在 v2 的**会话机制**需要一次系统的分析与优化，三个子问题：

（三问的成文分析与裁决见 [ADR-063](../adr/ADR-063.md)：2.1 不支持也未计划——收件箱 FIFO + 单写者 + 单转写 + 单压缩四大前提只允许一条线；2.2 各自独立会话或子智能体空间，不裂开；2.3 分栏退役、呈现合流单窗口，数据层不动。）

### 2.1 现有体系是否支持一个会话内多条实际会话线程

「一个会话里多条不同的与 LLM 沟通的实际会话线程」在现体系下的支持能力：

- 证据点（读代码定，不预设）：会话的事件模型与转写投影（[AR-022-vdfs-session-messages](../../symbio/src/plugins/session/docs/AR-022-vdfs-session-messages.md)）、  节点状态机的 Turn 线性约定（[AR-015-core-loop](../../symbio/src/plugins/session/docs/AR-015-core-loop.md) / [AR-018-node-state-streaming](../../symbio/src/plugins/session/docs/AR-018-node-state-streaming.md)）、子智能体空间自驱动（[ADR-026](../adr/ADR-026.md)）——
  「线程」在现体系有没有一等身份（turn 序列只有一条 FIFO？多主体如何进同一会话？）；
- e2e 侧对应证据：t30（多主体）、t39（子智能体根不被劫持）的实际形状。

### 2.2 多线程放一个会话 vs 各自独立会话，哪个更合理

裁决点：多线程同会话（共享上下文 / 记忆 / 转写）vs 独立会话（隔离、生命周期独立、
投影简单）。裁决要答：上下文共享是否有真实需求；失败与重试的隔离半径；前端显示
模型的复杂度代价。**裁决写 ADR**，理由与被否决方案同框。

### 2.3 前端原则：一个会话线程一个显示区域

**前端原则：一个会话线程对应一个显示区域。** 现状感知是「一个会话线程压进了两个
显示区域」（会话面板 / 工作面板）——这必属其一：

1. 现状就是两个独立 LLM 会话线（那就按线程归口，各自一个窗口）；
2. 现状是一个会话线被强行拆两个窗（那就合并为一个窗口）。

不管落哪格，「一个会话线 → 一个窗口」是终态判据，现状认定以代码事实为准。
