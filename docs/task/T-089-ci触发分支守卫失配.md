## 内容

`64ca8308` 把 `ci.yml` 的触发分支从枚举改成通配形状（`branches: [ main, master, 'v2*' ]`，
push 与 pull_request 两处同批改形，理由是分支改名 `v2-plan → v2` 后枚举名单静默失配、
该分支零 CI），但**同批没有更新钉这件事的守卫**——`scripts/gate.d/_shared.test.mjs` 的
`ci.yml：v2-plan 必须在 push 与 pull_request 的触发分支里…` 仍按字面量 `/v2-plan/` 断言。

后果：**门禁 docs 阶段自此恒红**，而这次失配本身没有任何信号——`64ca8308` 的 pre-commit
只跑了 `--only=facts`（5/5 绿），docs 阶段的 `gate.d/_shared 回归测试` 根本没被调用。
这正是那条守卫注释里自己写的失效模式（「没有信号的漏跑」）以第三种形态复现：第一次漏的是
**文件类型**（`*.css` 不在白名单 ⇒ 四个 job 都不跑），第二次漏的是**分支名**（`v2-plan` 不在
名单 ⇒ 零 run），这一次漏的是**守卫与配置之间的对账**（配置改了、守卫没跟着改 ⇒ 恒红被当噪声）。

## 处置

守卫的**意图**（承载 v2 工作的分支必须触发 CI）不变，把断言从「某一个分支名」换成
「配置里存在覆盖该分支的**通配形状** `v2*`」——这样改名（`v2-plan` → `v2`）不再误报，
而把名单退回枚举（丢掉形状）仍会红。判据口径与 `ci.yml` 里那两行注释写的一致。

## 不是本任务范围

- 不给 `ci.yml` 增删触发条件（`paths-ignore` / job 结构不动）——本批只对齐「守卫断言 ↔ 配置形状」。
