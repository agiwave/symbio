## 内容

三个生成器是三份**各自独立**的脚本，各自带一份「怎么写文件、怎么判漂移、怎么报
溯源」的副本；门禁 `60-facts` 里也是三段手抄的 `autoWork` 调用。

这份形态的代价在**扩充**上：新增一份事实文件要改四处——写脚本、在
`60-facts` 抄一段调用、在 `30-docs` 的 `LIBS` 登记、在各处文档补引用。漏任何
一处的后果不是报错，是**静默**：漏了 `LIBS` 被 GW-004 抓住，漏了 `60-facts`
则那份事实永远不更新，而门禁全绿。

而「事实」在本仓是**会持续增加**的一类产物（能力矩阵、覆盖矩阵、更多投影页
都可能落进来）。所以现在就该把「加一份事实」的成本降到**建一个文件**。

## 边界

- **只收「离线可重生成」的代码投影**。需要跑起来才产出的（如 `docs/ref/PROMPT_SHAPE.md`
  由 e2e `t46` 从真实链路抓）**不进本目录**——它的生成点是 e2e 而非门内脚本，
  放进目录会让 runner 在没有运行时的场合静默产出一份错的。这条边界要在
  目录里写明，否则下一个人会把 e2e 生成物也搬进来。
- **不改任何一份事实的内容**：本任务只搬家 + 收敛调用点，三份生成物逐字节不变
  （除了横幅里指向脚本名的那一句——脚本搬了家，指路必须跟着搬）。
- **不新开判据码命名空间**：runner 自身的失效（目录读不出、契约破损）用退出码
  表达，`60-facts` 的 `autoWork` 已经把「命令报错」判为不通过。

## 处理过程

- 2026-10-16 落成。**契约**（`facts/_lib.mjs`）：`id` / `title` / `out` / `stamp` /
  `render()`，runner 逐条机检；`out` 判越界是因为 runner 在 CI 里以仓库身份跑，
  一个 `../../` 就把它变成任意写文件的口。
- 三条退出码刻意分开：0 全过、1 有漂移或 render 抛错、**2 范围读不出**。第 2 条是
  这份 runner 唯一不能省的判定——空目录会让 `autoWork` 退出 0 而什么也没生成，
  那正是「守卫读空了却全绿」的最坏形态（`registry-audit` 的 RG-010 同款）。
- **门内踩到并修掉的两个真问题**（都不是跑测试跑出来的，是跑起来撞上的）：
  1. `discover` 把同目录的 `routes-ts.test.mjs` 当成一份事实 → 判「契约破损」

     加进 `discover` 而不是搬走测试。

     （同目录 `routes-ts.mjs` 当年也带着）。**这是最难查的那种假绿**，而它是我
     自己刚写的。
