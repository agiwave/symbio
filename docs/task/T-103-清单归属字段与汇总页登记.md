## 内容

用户连续三轮把「同一事实被写两遍」从**修文档**推到**修机制**：

1. 「所有文档的 meta 里表明它包含哪些列表，不写=单内容文档；扫全仓查重复，重叠判红」
   → `lists` 字段 + RG-026…RG-029（声明层），判据分两层：**单文档**判「我声明的清单正文里有没有对应的东西」（RG-029，只读这一篇），**跨文档**判「两篇是否都声称拥有同一份」（RG-027，只读每篇 front-matter，不碰正文表）。
2. 「CURRENT.md 也纳入编号体系，放进 ref，引用标准化」
   → `docs/ref/RE-006-当前事实表.md`，正式登记（原先免登记，所以别人只能手写 `../CURRENT.md#…`——本仓为它专门加过一条节次指路判据，而那条判据本不该存在）。
3. 「再有一个 ref 文档，根据 meta 里的 list 字段生成清单总账，重复则生成即红」
   → `docs/ref/RE-007-清单归属总账.md`。
4. 「INDEX.md 也纳入编号体系，比如 xx-000 替代 index.md」
   → 9 个 kind 汇总页改为 `<前缀>-000-<X>汇总.md`，登记为 `projection: true`；它们各自声明 `lists: [<kind>-entries=owner]`，因此也进 RE-007（14 份清单）。

## 处理过程

- 2026-10-14 登记。四批的落地与各自的反向验证记在下方；**三次判据漏过**是本条最值得留的部分。
- **洞 1（RG-027 漏过）**：owner 是**免登记的生成物**（`CURRENT.md` 在 `SCAN_SKIP_FILES` 里），
  对 registry 隐形 ⇒「两个 owner」永远只看得见一个。修法：`loadEntries` 另返 `projections`，
  清单归属这一族同时看条目与投影（其余判据只看条目——免登记的理由是「它不是条目」，
  而「这份清单有没有主」与它是不是条目无关）。
- **洞 2（RG-028 恒真）**：needle 用了去扩展名的 `CURRENT`，正文里满地都是 `CURRENT.md`
  ⇒「已指路」判据恒真。收紧成带扩展名的文件名。
- **洞 3（我的注入脚本自己的 bug，三次）**：RG-028 的注入先只删含 `../CURRENT.md` 的行
  （第 6 行还有一处代码跨路径）、后只删 `CURRENT.md`、RE-006 搬进 `docs/ref/` 后两者都不对。
  三次都是同一类错误：**注入脚本假设了旧路径，而它自己没跟着搬**。故按**编号**删，不按路径删。
- **`docs/<kind>/INDEX.md` 对机制隐形**（`isGeneratedIndex` 把它们整个排除）⇒ 里面的地址
  既不会被 `gen-doc-refs` 重算，也不会被 RF-003 判红。与洞 1 同类。改名 + 纳入登记后消失。
- **`projection: true` 的豁免是逐条列明的**：状态词（RG-004）、kind 专属必填字段
  （RG-002，如 task 的 `track`）、状态×字段矩阵（RG-007）、必备小节（RG-009）、取代链 /
  清除指认（RG-015/016）；**身份面一条不豁免**（front-matter / 编号形状 / id↔文件名 /
  created / title==H1 / 清单归属）——那几条判的正是「它是不是一份可被引用的文档」。
- **账本计数也要跳过投影页**，否则 `--write` 要三步才收敛（建页 → 它们进计数 → 才稳），
  `registry-audit.test.mjs` 的「第二次逐字节无变化」不变式当场抓到；顺带修了读数问题
  （读者会把「task 100」读成「100 个任务」）。
- **一处未做**：`KIND-000-登记总账.md`（仓根总账）仍是固定名、未登记。它横跨九个 kind，
  按 RG-022「编号前缀一 kind 一个且与 kind 对账」**取不到任何合法编号**——给它 `PL-000`
  会在 `plan` 汇总页里出现一行「计划目录的索引页」，那是撒谎。需要一次裁决：
  新增 kind / 接受它作为唯一不发编号的页面 / 别的方案。
