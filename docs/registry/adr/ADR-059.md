## 决策

**背景**：`docs/plan/02-能力坐标系.md` 是一份**内部自洽**的文档——`verify/capability_frame.rs`
能把名册逐行归位，能把七格生长位对回去。但一次针对它的系统评估暴露出四件它自己没做的事：

1. **天梯 `T` 已经是两套语义，且没有任何程序对账**。02 §3.1 用 `T` 表达**能力语义等级**
   （T8 = 能学习，核心能力含技能编译 / 目标自生成），roadmap 总表与 13 份阶文档头部用 `T` 表达
   **阶段序号**（S11 = T6，而 S11 点亮的技能编译在 §3.1 里是 T8）。同一个符号两处定义，
   `scenario_ladder.rs` 只**打印** stage 的 tier、从不**断言**，`capability_frame.rs` 只校验
   `1 ≤ tier ≤ TIER_MAX`。抽查即得三处互相矛盾的数字（技能编译 / 目标自生成 / 独立验证与返工）。
2. **"高阶"没有刻度**。§3 给的是每条轴的「低阶 | 高阶」两端，名册的「天梯」列回答"属于哪一级"，
   不回答"把这条轴抬到了第几级"——§1 里"无法判断高阶了多少"这条只被解决了一半。
3. **五条轴的独立性从未被检验**。文档声称五维正交完备、五轴足以度量"高阶"，§8 把它们标为
   **判断**；而 §4 的准入规则是"答不出提升哪一轴 ⇒ 它是宽度/工程，不是高度"——这条兜底让
   "五轴足以度量"这句话**永远不会错**：一个公认高阶的能力若落在轴外，会被就地降级成"不高阶"。
4. **坐标系与实施阶梯是两张互不相干的表**。名册 54 行没有一列指向 `roadmap/` 的阶，
   所以"这一阶到底长出了什么能力"在两份文档里各写一遍、互不校验。

**决策**：

1. **给每条轴四级刻度（L1–L4），名册逐行记「等级」**。刻度格数由 §3.1 表的**列数**算出，
   程序不写死"四级"——刻度加一级而判据不动，新一级会静默落在判据之外。
   `L1` 是平凡基线（关闭后系统仍完整运行，J2），`L4` 必须有人占据（死格 = 刻度是装饰）。
2. **天梯不再另立语义**。T1–T8 = "截至该级的全部能力集合"，它在五条轴上的等级向量由名册
   **算出**（`capability_frame.rs` 打印）；§3.2 的「核心能力」列必须逐条对应名册里**该级**的行
   （34 个指认逐条对账）。roadmap 总表、13 份阶文档头部、03 §6 阶段表里的 `T` 列**全部删除**：
   同一个事实抄三遍就必然对不上，删掉副本比调平数字更彻底。链接改由名册的「落点」列承担
   （`SNN`，可多阶），程序据此断言**每一阶、每一级都至少有一条能力落在它上面**。
3. **准入判定加第 5 问，把兜底换成方向**：第 2 问答不出时**不得直接判为宽度**，必须自己说清
   "它高在哪、怎么观察"（观察口径 = §3.1 的刻度），写不出才判伪高阶。同时给"组合"记账：
   同一 `维A × 维B` 登记到 3 条即触发维评审——五维完备性的可检验形态不是"我觉得够了"，
   是**这个逃逸口被用了几次**。
4. **五轴的独立性：一半证明 + 一半测量**。
   §3 五轴表末两列是**极性**（`requires` / `forbids` 两个 token）：两轴极性完全相同 ⇒ 同一条轴；
   A 的要求命中 B 的禁止 ⇒ 互相抵消。冲突矩阵与分组由 `verify/axis_orthogonality.rs` 按
   `lower_bound.rs` 同源的方法算出，组数必须等于轴数。
   正交性证明不了，所以另一半是**测量**：程序统计"一对轴在 8 阶里有几阶同时被抬起"，
   超 §3.3 上限的轴对必须逐条登记理由，声明与算出的**同集合**、每条的阶数逐条相等。
5. **§8 从"是判断"升级为"判断 + 反证现象"**：每条主张必须写出**什么现象出现说明它错了**。
   一条不可能被推翻的主张等价于没有主张——这是本仓验证纪律（03 §5.1）在设计文档上的延伸。
6. **名册加「类型」列**（认知 / 工程 / 治理，闭集由同节那张小表拥有），并把"为什么不能把社会性
   塞进某一维"写清：格子的含义会随主体数变化，**维度是分类、主体数是规模**，混在一起矩阵
   就不再是矩阵——社会性因此是**第 6 个坐标**而不是第六维。

**理由**：

1. **刻度是"度量"与"标签"的分界**。没有刻度，五轴只能回答"属于哪条轴"，
   于是任何一条轴都能被随手填满而系统毫无变化；有了刻度，"抬到第几级"变成一个可写错、
   可被对账的数字（本次 54 行全部要落等级，错了就红）。
2. **重复的真相必须删，而不是校准**。天梯的三处口径已经对不上，且**没有任何程序看它们**
   （那正是 ADR-045 / 复盘 E7 说的"完成判据被一条没人看的列满足"）。删掉两处副本之后，
   "这一阶长出了什么"由落点列唯一承担，`capability_frame.rs` 当场能对账。
3. **把兜底换成方向，才能让主张变成可否证的**。第 5 问不增加分类能力，它增加的是**发现分类
   不够用的那条路**：过去轴外能力被静默降级，现在必须自证观察口径。
4. **极性是可重放的判据，形容词不是**。§3 原来的"低阶 | 高阶"两列无论怎么措辞都判不出
   两条轴是否同一条；两个 token 可以，而且判据的来源（文档）与结论（程序）照旧分家。
5. **删除零新增键的冗余不影响任何声称**。`mechanism_growth.rs` / `scenario_ladder.rs`
   验的是机制键与值域，与天梯标签无关；删列后两者照旧全绿——这也说明那三处 `T` 从来没有承担过
   任何被验证的职责。

**被否决的方案**：

- **保留三处 `T` 并让程序对账它们**：否决。对账要回答"哪个 `T` 是对的"，而**三个里有两个是错的**
  （阶段序号语义），对账只会把错误固化成基线；正确的做法是承认其中两处根本不该存在。
- **把天梯并进名册的「等级」列（删掉 T 级）**：否决。等级是**轴上的刻度**，T 级是**能力集合的序**；
  两者回答不同问题（"这条轴多高" vs "系统整体到哪一步"）。并进去会让"能记住"这种集合概念
  退化成单个刻度值。
- **用外部量表（文献 / benchmark）替五轴定刻度**：否决（本轮）。可行，但要引入本仓现在没有的
  外部依赖与评测集，且**尺子的误差会整批传染**；先落"刻度 + 观察口径 + 反证现象"这层，
  外部效标作为独立任务（`T-011`）挂上去——**在有读数之前先立数字，只会把设定的值说成测到的值**。
- **把社会性加成第六维**：否决。维度回答"这是什么种类的能力"，主体数回答"发生在几个主体之间"；
  加一维会让同一批能力的格子含义随主体数变化，矩阵随之失效。
- **给名册加"代码锚点"列（指到文件与符号）**：否决（本轮）。加一列就必须同时给它一个守卫，
  否则就是 D0 记的"出口挂在一个不会有人去建的东西上"；锚点审计连同它的名字解析口径一起排进
  `T-012`，不在这一批里顺手塞进来。

**后果与不变量**：

- **不变��（机制面零改动）**：F1–F6、机制表 10 个顶层键、事件网格、三条不变量**一个都没动**。
  本决策改的是 `docs/plan/` 里的坐标系与其验证程序，不是 [01 §8](./../../../docs/plan/01-核心架构.md)
  的任何一行参数表——13 阶的 0 新增键结论照旧由 `scenario_ladder.rs` 验证。
- **刻度的格数由文档的**列数**拥有**。加一级刻度要同时给名册里对应的等级取值，
  否则「等级越界」立刻红；这比"程序里写死 4"更早暴露人为的不一致。
- **`verify/*.rs` 的文件集合 = `03 §5.2` 的程序清单**，由 `doc-count-audit` **DC-004** 对账；
  新增程序而不同步清单，今天就会红（此前是 `recall_eval.rs` 已经落进目录、清单里却没有）。
- **共线登记是判断的显式化，不是豁免**：登记一条 = 承认两条轴在当前形态下测同一件事，
  并写下"为什么现在接受"。阶数继续变大时，要么补理由，要么合并。
- **回退**：本决策可整体回退——`git revert` 即可复原 02 的旧形状；`facts/mod.rs` 是生成物，
  随文档一起复原，无数据迁移。
