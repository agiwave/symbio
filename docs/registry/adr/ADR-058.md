## 决策

**背景**：[plan/13 终点第 3 条](../../plan/13-质量改进总纲.md)要求「`full` 是出厂路径，且被
真实负载压过——不是『跑过 e2e』，是『跑过真实会话』」（登记条目
[S-end②](../task/S-end②.md)）。[ADR-057](ADR-057.md) 补上了形状记录，但它自己明说
不回答「压过之后还成立吗」。当时的实情：43 例里**最长会话 4 轮**、单轮最多 3 次工具调用，
压缩 / 滑窗骨架化 / 记忆召回各有单点用例，但**没有一条链路在「会话已经很长」这个前提下
一起跑过**——而 v2 的主用法恰恰是长会话与长 agentic 轮。

**决策**：

1. **压测跑在门内，形状是有界的**。执行方
   [`e2e/cases/t47-real-session-soak.mjs`](../../../e2e/cases/t47-real-session-soak.mjs)：
   21 轮（20 轮正文 ＋ 一轮 45 步工具长轮），mock-llm 驱动，秒级到十几秒级，按目录发现式
   纳入 58-e2e。**负载的形状表**（每项怎么取、为什么这样取）的 owner 是该用例头部，本条
   不复述。
2. **判据只钉「压过之后仍然成立的那些事」**，且**全部读生产出口**：gateway
   `session/stats`（轮次账 / 事实账 / 不变量 / 转写）、`vdfs/read(<根>/session/<sid>)`
   （与前端加载历史同一条地址）、mock-llm 收到的**原样请求体**。
   **会话的内部存储文件一个都不读**。七段判据的逐条归属同样归用例头部。
3. **「没压到的」与「不进判据的」必须写下来**，且写在判据旁边而不是散在提交信息里。
   本用例头部因此有三节：钉的是什么 / 没压到的两处 / 为什么只有配置里的一项被改过。
   一份「跑过了」的清单如果不标出边界，下一轮就会把边界当成已覆盖。
4. **配置除一处外全取出厂默认**（`auto_compress`、`context_messages = 6`、
   `fade_activate_rounds = 40`、`tool_context_window = 15` 都不为用例特调）。被调小的只有
   provider 窗口——水位线是**相对**的（`0.7 × max_context_tokens`），不调窗口就得靠
   上万轮才能触发一次压缩，那就不再是门内的判据。这是口径的取舍，不是产品的旋钮。
5. **换基边界收敛成一条纪律，三个出口都必须遵守**（本条是这次压测的**架构产出**）：
   自动压缩把**本轮**的用户发言原文留在快照载荷尾部，而那条发言同时是本轮的开场格、
   落在快照之后 ⇒ 同一个节点身份有两条来源。
   [`rebuild`](../../../symbio/src/plugins/session/rebuild.rs) 早就按「同 id 只认首次」
   只认一条；`projection/transcript.rs` 与 `projection/prompt_fidelity.rs` 此前**没有**
   那一步。三处现在共用同一口径：**快照基线占住的节点身份，之后的事实不再产第二行 /
   不再提第二次主张**，且该判据**只作用在换基边界**（基线 ↔ 事实之间），不作用在事实
   彼此之间（合成节点 id 的两个出处在 `rebuild` 里就是两个节点，去了重是另一种分叉）。

**理由**：

1. **「跑过真实会话」要能被机器判，才存在**。它现在的形态是「t47 绿」，而不是「有人
   偶尔手工跑一次长跑」。判据不进门就等于没有判据——本仓对「要记得跑」的守卫的结局
   有记录（[ADR-057](ADR-057.md) 被否决方案一节）。
2. **边界缺陷只在「已经换过基」之后出现，所以只有压测能发现它们**。这是本条最硬的证据：
   t47 第一次真压出两次压缩，当场压出**两个静默分叉**——网格里每次换基多一条重复用户
   发言（`transcript` 与 `rebuild` 对同一段历史给两种读法），以及**每次压缩后每轮一条**
   的 `[prompt-fidelity] 网格→prompt 丢事实`**恒假警报**（同一条发言被两条来源各认领一次，
   第二次找不到未被用掉的匹配）。43 例全绿了这么久，两者都不在任何单点用例的前提下
   出现。恒红的保真判据等于没有保真判据——真缺口就淹在假警报里，而终点第 1 条
   （双向完整性防线）靠的就是它。
3. **读生产出口的判据才是「用户遇到什么」**。断言内部存储的字节形状 ⇒ 形状一改就假红，
   红得与「真实会话」无关；这与 ADR-057 对基线来源的取舍同源。
4. **规模不作判据的口径在这里第二次成立**：压测里请求体字节峰值只作观测。理由是校准
   估计器的下限——mock 恒报 `prompt_tokens: 64`，比例被夹到 0.2 地板，于是按字节判
   量的是**夹具**，不是产品（`tokenizer.rs::feedback`）。写下来免得后人以为「忘了钉」。

**被否决的方案**：

- **把真实模型上的付费 A/B（结构化 vs 拍平）当作 S-end② 的落地形态**：否决。它需要预算
  授权、结果非布尔、且不可重复——一次都判不稳的东西不能当门内判据。「对模型变好还是
  变坏」因此仍**未闭环**，它需要的是一次独立的可授权实验，已单独立条目
  [S-end③](../task/S-end③.md)（不混进本批）。
- **门外的长时间 soak（cron / 发版前手动跑一轮）**：否决，理由见理由 1。
- **把字节上限 / 请求体规模钉进判据**：否决（理由 4）。
- **断言工具级骨架化与轮次淡化的占位符**：否决。实测请求视图每个请求只携带**最近一次**
  工具交换——45 步长轮从未让视图里出现第 2 条 `role=tool`，而这两个机制的作用对象正是
  「视图里的多条工具结果」。断言之 = 断言一个不会发生的东西；两者的单点用例（t18 / t45）
  继续承担。
- **只修其中一个出口**（只补 `transcript` 的去重，或只把假警报静音）：否决。同一条边界
  在两个出口上各坏了一次，修一处则分叉仍在；而「静音假警报」更是拿判据闭嘴来换绿。
  两处修法因此必须是**同一条纪律**，各带一条双向单点判据（重复必红、漏配亦红）。
- **让压测的特调配置贴近「更容易触发压缩」**（调小 `context_messages`、放大保留区等）：
  否决，见决策 4。负载要「真实」，配置就不能是为用例调的。

**后果与不变量**：

- **落点**：判据执行方在 58-e2e（用例文件按名自动纳入，无需登记）；夹具侧为它补的
  两个能力——`times: N`（场景可复用 N 次，计数按**每次命中**）与 `failTimes` 按**逻辑
  请求体指纹**计数，口径见 `e2e/README.md`；跨用例的夹具陷阱记在同文件 9–13 条。
- **core 侧改动只收窄语义，不改公共形状**：未新增 `pub trait` / `fn` 成员，
  CS-001 三格不变（复用同一 crate 已有的 `snapshot_entries`）。两条例外的单点判据：
  `the_user_turn_a_snapshot_carries_is_not_emitted_twice`、
  `the_user_turn_a_snapshot_carries_claims_only_once`（反向各一条）。
- **不变量**：新增任何「从快照换基的读面」时，播种集合必须来自快照基线、边界不重复必须
  成立——这条纪律的 owner 是本 ADR，实现分散在三个出口，判据双向钉。
- **它仍然不回答「对模型更好还是更坏」**。mock 不是模型。本条闭环的是「出厂路径被真实
  会话的**形状**压过，且压出的分叉修在了事实层」。
