## 规范

限定名 `04 §4 CI 清单`。**清单本身不再登记在 04**——每条断言（C1…C29 / C-D2…C-D4）的 owner
是各自**可执行的判据**，不是那张手抄表。逐条走向由三个既有守卫 / 程序族承接，本条目只固化对账关系：

1. **主体一（投影 / 事件不变量）**：`symbio/src/plugins/session/stats.rs` 的 `check_all` 第五列 `invariants`
   （含 N1/N3/N5 等），生产调用点 = 读出口；反向 e2e `t28`。
2. **主体二（直连禁令）**：[`no-direct-call-audit`](../../../scripts/no-direct-call-audit.mjs) 的 `NDC-001/002`
   （任意两主体无直连，一切经事实源）。
3. **主体三（硬证据）**：`docs/plan/verify/*.rs` 的可编译验证程序 + `docs/plan/verify/OUTPUT.md` 快照
   （`verifyPrograms` / `verifyAsserts` 棘轮住 `scripts/gate.d/_shared.mjs` 的 `BASELINE`）。

**为何拆**：把 29 条断言抄成一张表，是「同一事实两处登记」的典型——表列漏了一条、或某条改成非断言，
没有任何东西会红。改为「断言 → 承接守卫」的显式绑定，守卫即判据（纪律 4）。

## 判据

`scripts/no-direct-call-audit.mjs`（NDC-001/002）、`scripts/gate.d/55-verify.mjs`（verify 程序 + 断言棘轮）、
`symbio/src/plugins/session/stats.rs::check_all`（不变量列）；回归测试各自随守卫。
