## 内容

把「任务 / 规范 / ……各是一个带元信息的单文档，脚本自动汇总」立为项目推进的顶层机制：

1. **框架**：`registry-lib`（受限 YAML 解析 + schema 校验 + 渲染器）、
   `registry-audit`（守卫，RG-001…013）、`registry-board`（查询台），全部进
   `gate.d/30-docs.mjs` 名单（GUARDS / LIBS / OUT_OF_GATE）；
2. **首批 kind**：`task` 与 `spec`，各配渲染器与状态机；新增 kind 只加一份配置；
3. **汇总**：`docs/registry/INDEX.md` 总账 + `docs/registry/<kind>/INDEX.md`，由门禁
   `gate.d/60-facts.mjs` 的 `autoWork` 自动重生成并暂存（与 `docs/CURRENT.md` 同约定）；
4. **总纲**：`docs/plan/14-登记与汇总机制.md` 讲原则、状态流转、接管清单；
   字段事实的 owner 是 `docs/registry/spec/SP-001.md`，不复述进总纲；
5. **冲突与优先级**：`prio`（now / next / later）只排同层顺序、不参与裁决；
   `supersedes` 让规范取代成为可查询的数据；分层裁决规则（事实归 owner /
   规范靠状态消解 / 规则对任务走豁免）写进总纲 §4。
