## 内容
[T-004](T-004.md) 清点到的**唯一**一处「散落决策」：`docs/design/third-party-plugin-spec.md`
§10 的 6 条待确认决策——`D1` 身份归属已定案（= [ADR-032](../adr/ADR-032.md)），
`D2` 外部插件形态 / `D3` 权限强制程度 / `D4` 连接信息放哪 / `D5` 是否引入 JSON-RPC /
`D6` 生命周期钩子形态**未定**。

决策正文的 owner 是 [`docs/registry/adr/`](../adr/INDEX.md)（每条一个单文件条目）；
本文 §10 是**倾向**（判断），不是决策。定案时每条写一条 ADR、原处留指回。

## 处理过程

- T-004 清点（2026-10-11）：扫 `docs/plan/` + `docs/design/` 的决策型表述，
  只有本文 §10 是「非 ADR owner 的散落决策」（其余处的取舍都已有 owner：
  plan/README §2/§3 是 v2 目标架构取舍的 owner、落地决策各引 ADR）。登记为本条目。
- 2026-10-12 定案并闭环，五条各一条 ADR：

  **D2 = ADR-058**（stdio 首选 + HTTP 次选，动态库出局）：判据是「隔离」而不是「编译期可行」——
  动态库只解决后者；stdio 的成本近零因为宿主已有的 `PluginFrame` 就是 JSON 帧。WASM 明确留待
  单独评估，不在本期承诺。
  **D3 = ADR-059**（只做声明校验，不做运行时沙箱）：`grants ⊇ needs` 的交集校验住装配期；
  闭集是这条成立的前提（能力名可自定义 ⇒ 交集校验退化成字符串游戏）。与 `SecurityPolicy`
  分层共存不替换。运行时沙箱被显式否决并写明「什么时候再来立条」。
  **D4 = ADR-060**（扩展 `plugin_provider` 值语法，零新增连接键）：同一问题写两处必然出现
  「provider 说 stdio、endpoint 说 http」这种没人裁决的组合；新增的两个键
  （`plugin_api` / `plugin_grants`）都不是连接键，各有「必须在宿主侧」的理由。
  **D5 = ADR-061**（不引入 JSON-RPC）：本仓已有两套线上约定，第三套的差别是静默的
  （都能跑通，只在出错形态与字段命名上分家）；从 MCP 借的是**形态与时序**，不是报文规范。
  **D6 = ADR-062**（`start` / `stop` 两钩子 + `reason` 参数）：这条与 [ADR-055](../adr/ADR-055.md)
  的 CS-001 棘轮直接相关——细粒度钩子会把 `Plugin` 这个公共面的 `methods` / `defaults` 两格推宽，
  而「拆成三个方法」与「一处 `match` 按原因分支」的差别只在契约宽度。**先定形态再写代码**，
  实施时若触宽需按 CS-002 挂放宽论证。

  **§10 的收敛写法**：表从「决策点 + 选项 + 本文倾向」改成「决策点 + 定案于（指回 ADR）」，
  并按 14 §6 的决策类登记形态补一句「正文与 ADR 冲突时以 ADR 为准」——规范保留机制与形态，
  不再持有裁决。§3.3 / §6 / §7 / §8 的正文不动：它们是机制描述，其结论现在有了 owner。

  **没做的事**：本条只定案决策，**不实现任何外部插件代码**（规范 §9 的第二/三期）。
  五条 ADR 的 `impl` 全为 `planned`。
