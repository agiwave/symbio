## 内容

按 [14 §6](../../plan/14-登记与汇总机制.md) 的接管协议迁 ADR owner。
原来是两处 owner：`docs/DECISIONS.md` 管 55 行手写索引
（「编号 | 决策 | 状态」），`docs/decisions/{core,session,model,vdfs,agent}.md`
五册管决策正文。索引的**状态列混了两件正交的事**——规范合法性
（现行 / 已被取代 / 已回退）与落地进展（已落地 / 部分实施 / 未实施）；
「分册」这层结构也只是排版，不是语义。

接管口径：**索引与正文一并迁入 registry**——两者拆着放正是「状态列混语义」
与「跨册引用靠锚点」的病根，所以不保留「正文仍在 decisions/*.md」的中间形态。
迁移完成后 registry 是 ADR 的唯一真源，`docs/DECISIONS.md` 与五个分册删除。

## 处理过程

- **形态定案**（decision 类元素的机制延伸）：`spec` 的状态机**装不下第二个维度**——
  「现行（含未完成项）」「已接受 · 部分实施」这类最常见状态在 `spec` 里要么违反
  RG-004 词表封闭、要么污染 `retired` 语义。故按 14 §2 的「新增一个 kind = 三件事」
  **新开 `adr` kind**：`status` 管规范合法性（`active` / `superseded` / `withdrawn`），
  新增 `impl` 字段管落地进展（`planned` / `partial` / `done` / `none`，RG-017），
  新增 `domain` 字段管域（闭集，RG-019，取代原「按域分册」）。判法边界写回 14 §2。
- **机制**（与迁移同批，带回归测试）：`registry-lib` 的 `KINDS.adr` 配置 +
  `renderAdrIndex` 渲染器 + `RENDERERS` 注册；新增 **RG-017**（`impl` 词表）、
  **RG-018**（`adr` 字段 × `id` × 正文标题三面对账）与 **RG-019**（`domain` 闭集）；
  RG-015 扩到同 kind 取代（`adr↔adr` 与 `spec↔spec`）；`ALL_KEYS` 改为从 `KINDS`
  的并集派生（新增 kind 不再手改）。
- **逐条迁移**：55 行索引 + 五册正文 → 55 条 `docs/registry/adr/ADR-*.md` 单文件条目。
  **正文随条目落户**：44 条有真实正文（从五册对应 `## ADR-<num>` 小节整段搬入
  条目的 `## 决策`）；11 条只存在于索引
  （008/009/010/014/017/027/034/037/038/045/050）本无正文，条目写占位说明并把
  出处指向 `git log`。迁移中守卫抓出多处历史数据瑕疵并当场修正：
  ADR-027 `supersedes` 实为部分取代（移除 `supersedes`、改记 `备注` + `impl: partial`）；
  ADR-037 缺 `reason`；ADR-014→ADR-016 与 ADR-017↔ADR-039 的 `supersedes` 方向被
