# MVP 定义与实现计划

> 本文档定义 Symbiont 的最小可行产品（MVP）边界和分阶段实现计划。

---

## 核心定位调整

### Symbiont vs ChatGPT

ChatGPT 已经很好用了，为什么还需要 Symbiont？

```
┌─────────────────────────────────────────────────────────────────┐
│                  ChatGPT 做不到的事                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ❌ ChatGPT 无法执行代码                                        │
│     → Symbiont：内置执行环境，代码直接跑                         │
│                                                                 │
│  ❌ ChatGPT 无法验证结果                                        │
│     → Symbiont：执行后自动检查输出是否正常                       │
│                                                                 │
│  ❌ ChatGPT 无法记录过程                                        │
│     → Symbiont：所有参数、结果自动文档化                         │
│                                                                 │
│  ❌ ChatGPT 无法复用流程                                        │
│     → Symbiont：保存分析流程，下次一键复用                       │
│                                                                 │
│  ❌ ChatGPT 不知道你的数据                                      │
│     → Symbiont：读取你的数据文件，给出针对性建议                 │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

结论：Symbiont 的核心价值是「执行 + 记录 + 复用」，而非「更懂你」。
```

### MVP 验证的核心问题

```
✅ 必须验证：
  1. 用户是否愿意在真实环境中使用？
  2. 执行 + 记录是否真的提升了效率？
  3. 流程复用是否有价值？

❌ 不需要验证：
  - 长期记忆（后期差异化功能）
  - 风格学习（需要大量数据）
  - 隐性需求感知（技术风险高）
  - 用户是否觉得 AI "懂自己"
```

## MVP 核心场景

### 目标用户

**小林**（初级研究员）完成一个 RNA-seq 差异表达分析项目。

### 核心流程

```
用户打开 Symbiont → 上传数据 → 选择分析模板 → 执行分析 → 查看结果 → 生成报告
```

### 详细流程

```
1. 用户上传 FASTQ 数据文件

2. Symbiont 自动识别数据特征：
   - 数据类型：双端测序
   - 序列长度：150bp
   - 物种：人类
   - 文件大小：均值 4.2G/样本

3. Symbiont 推荐分析流程：
   「检测到这是人类双端 RNA-seq 数据，推荐使用 RNA-seq 差异表达流程。
     是否开始？」
   
4. 用户确认后，生成分析文档（包含代码块）

5. 用户点击「执行」，代码在容器中运行

6. 结果自动捕获并展示：
   - 执行日志
   - 输出文件
   - 生成的图表

7. 分析完成后，一键生成分析报告

8. 流程保存，下次可直接复用
```

## MVP 功能边界

### 必须有（核心功能）

| 功能 | 描述 | 核心价值 |
|------|------|----------|
| 数据识别 | 自动识别上传的数据类型 | 替代用户手动判断 |
| 流程模板 | 预置 RNA-seq 分析流程 | 替代用户查教程 |
| 代码执行 | 一键执行代码块 | **ChatGPT 做不到** |
| 结果捕获 | 自动记录输出和日志 | **ChatGPT 做不到** |
| 过程文档化 | 分析过程自动生成文档 | **ChatGPT 做不到** |
| 流程复用 | 保存流程，下次复用 | **ChatGPT 做不到** |

### 不做（MVP 后续）

| 功能 | 理由 |
|------|------|
| 长期记忆 | 需要大量用户数据，冷启动困难 |
| 风格学习 | 技术风险高，早期样本不足 |
| 隐性需求感知 | 误判率高，可能打扰用户 |
| 多项目切换 | 单项目验证核心场景即可 |
| 多种分析类型 | 只做 RNA-seq，验证一个场景 |
| 协作功能 | 单用户先验证 |

## MVP 成功标准

### 核心验证指标

| 指标 | 目标 | 衡量方式 |
|------|------|----------|
| **任务完成率** | > 80% 用户完成 RNA-seq 分析 | 执行记录 |
| **时间效率** | < 2 小时完成完整分析 | 自动记录 |
| **流程复用率** | > 30% 用户在第二个项目中复用流程 | 使用数据 |
| **推荐意愿** | NPS > 0 | 用户问卷 |

### 价值验证问题

MVP 结束后，用户应该能回答：

```
✅ "有了 Symbiont，我不用再查教程了"
✅ "执行代码比用终端方便多了"
✅ "分析过程自动记录，省了我很多时间"
✅ "下次做类似分析，我直接复用流程"
```

而非：

```
❌ "Symbiont 比其他 AI 更懂我"
❌ "它记住了我的习惯"
❌ "它能猜到我想做什么"
```

## 实现阶段

### Phase 1: 核心能力（当前 MVP）

**目标**：验证「执行 + 记录 + 复用」的基本价值

**功能**：
- 数据文件上传与识别
- RNA-seq 分析流程模板
- 代码块执行（Docker 容器）
- 结果自动捕获
- 分析过程文档化
- 流程保存与复用

**里程碑**：用户能在 2 小时内完成一个 RNA-seq 分析

**不包含**：长期记忆、风格学习、隐性感知

### Phase 2: 体验优化 + 结果验证

**目标**：提升执行效率，增加结果验证能力

**功能**：
- 更多分析类型（ChIP-seq、单细胞等）
- 执行进度可视化
- **结果自动验证**：
  - 执行层面：检查返回码、输出文件
  - 逻辑层面：样本数是否匹配、基因数是否合理
  - 领域层面：差异基因数量是否在正常范围
- 错误自动诊断
- 参数智能推荐

**里程碑**：用户能在 1 小时内完成分析，结果可信度有保障

### Phase 3: 学习能力增强

**目标**：帮助用户形成自己的分析套路

**功能**：
- **学习进度追踪**：
  - 记录用户完成了哪些分析
  - 标记哪些步骤需要帮助，哪些已经掌握
  - 生成个人能力图谱
- **流程个性化**：
  - 用户可以修改流程模板
  - 保存自己的分析套路
  - 分享给团队成员
- **知识点关联**：
  - 分析步骤关联到知识点
  - 点击可查看详细解释
  - 帮助用户理解原理

**里程碑**：用户能独立完成分析，并形成自己的套路

### Phase 4: 深度学习

**目标**：长期记忆与风格学习

**功能**：
- 跨项目经验复用
- 用户风格学习
- 隐性需求感知（低干扰模式）

**里程碑**：用户明显感受到效率提升

### 数据安全方案

```
┌─────────────────────────────────────────────────────────────────┐
│  场景                    │  方案                                │
├──────────────────────────┼──────────────────────────────────────┤
│  个人用户（学术）         │  本地执行，数据不上传                 │
│  团队用户（实验室）       │  私有化部署，数据在局域网              │
│  企业用户（医院/药企）    │  私有化部署 + 合规认证                │
└─────────────────────────────────────────────────────────────────┘

原则：敏感数据永远留在用户本地，只有代码和配置可以云端同步。
```

### 防幻觉机制

生信分析对准确性要求高，采用三层防护：

```
1️⃣ 知识库检索：分析流程从预置模板加载，AI 不凭空生成
2️⃣ 执行验证：代码执行后检查返回码和输出文件
3️⃣ 用户反馈：执行失败时，记录错误并优化流程
```

### 结果验证机制（差异化能力）

生信分析最大的痛点之一是**不知道结果对不对**。Symbiont 提供三层验证：

```
┌─────────────────────────────────────────────────────────────────┐
│                      结果验证三层次                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  第 1 层：执行验证                                              │
│  ─────────────────                                             │
│  • 检查命令返回码是否为 0                                       │
│  • 检查预期输出文件是否存在                                     │
│  • 检查输出文件大小是否合理                                     │
│                                                                 │
│  示例：                                                         │
│  ✅ HISAT2 比对完成，输出文件 sample.bam (2.3GB)               │
│  ❌ HISAT2 执行失败：索引文件不存在                             │
│                                                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  第 2 层：逻辑验证                                              │
│  ─────────────────                                             │
│  • 样本数是否匹配设计                                           │
│  • 基因数量是否在合理范围                                       │
│  • 比对率是否正常                                               │
│  • 数据分布是否异常                                             │
│                                                                 │
│  示例：                                                         │
│  ⚠️ 警告：检测到 5 个样本，但设计文档说有 6 个                  │
│  ⚠️ 警告：比对率仅 45%，可能存在数据质量问题                    │
│  ✅ 正常：检测到 25,000 个基因，在人类转录组正常范围内          │
│                                                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  第 3 层：领域验证                                              │
│  ─────────────────                                             │
│  • 差异基因数量是否合理                                         │
│  • 富集结果是否符合生物学预期                                   │
│  • 关键基因是否被检测到                                         │
│                                                                 │
│  示例：                                                         │
│  ⚠️ 提示：差异基因数 8,500 个偏高，建议检查样本质量             │
│  ⚠️ 提示：GO 富集结果中未检测到免疫相关通路，与预期不符         │
│  ✅ 提示：检测到 TP53 差异表达，与肺癌研究一致                  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**验证价值**：
- 帮助用户发现问题，避免错误结果进入论文
- 审稿人可以查看验证记录，增强可信度
- 建立用户对平台的信任

## 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 前端框架 | Vue 3 + TypeScript | 已有基础 |
| 桌面框架 | Tauri | 已有基础、轻量、本地优先 |
| 编辑器 | Milkdown | Markdown + 代码块支持 |
| 执行环境 | Docker | 隔离安全、环境一致 |
| 数据存储 | SQLite | 本地优先、轻量 |
| LLM 接口 | OpenAI / Claude API | 生信知识问答 |

## 风险与对策

| 风险 | 对策 |
|------|------|
| 用户觉得"ChatGPT 够用了" | 强调执行+记录+复用，这是 ChatGPT 做不到的 |
| 执行环境配置复杂 | 预置 Docker 镜像，开箱即用 |
| 数据安全问题 | 本地执行，数据不上传 |
| 学习成本 | 流程模板化，用户只需点「执行」 |
