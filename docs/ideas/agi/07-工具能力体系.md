# 工具能力体系

> 专家之所以强，不是因为他算得快，而是因为他**知道什么时候该用计算器、用什么计算器、如何解读结果**。
>
> 本文档定义了认知系统中工具能力的完整体系，包括工具认知、工具选择、工具编排、工具学习与工具创造五大维度。

## 1. 核心理念

### 1.1 为什么工具能力是专家的核心特征

```
┌─────────────────────────────────────────────────────────────────┐
│                    专家 vs 新手的工具能力差异                     │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  新手面对问题：                                                 │
│  ├── "我该怎么算这个？" → 尝试心算 → 出错                       │
│  └── 不知道有哪些工具可用，更不知道何时使用                     │
│                                                                 │
│  专家面对问题：                                                 │
│  ├── "这个问题需要什么工具？" → 快速扫描工具目录                │
│  ├── "这个场景用 A 工具最合适，因为..." → 精准选择              │
│  ├── "A 工具的局限是 X，需要配合 B 工具" → 组合编排             │
│  └── "现有工具都不够用，我需要写个脚本" → 创造新工具            │
│                                                                 │
│  核心差异：                                                     │
│  ├── 工具目录的广度（知道多少工具）                             │
│  ├── 工具选择的精度（何时用什么）                               │
│  ├── 工具编排的深度（如何组合）                                 │
│  └── 工具创造的能力（能否发明新工具）                           │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 工具能力的心理学基础

| 心理学概念 | 对应工具能力 | 说明 |
|-----------|-------------|------|
| **程序性记忆** | 工具使用技能 | "如何做"的肌肉记忆 |
| **元认知** | 工具选择策略 | "知道何时用什么"的自我监控 |
| **迁移学习** | 工具编排能力 | 将 A 工具的经验迁移到 B 工具 |
| **创造性思维** | 工具创造能力 | 发明新工具解决新问题 |

### 2.2 工具能力各级定义

| 级别 | 名称 | 能力定义 | 验收标准 |
|------|------|---------|---------|
| **L1** | 工具使用者 | 能调用预设工具，但不知道何时使用 | 能正确执行工具调用 |
| **L2** | 工具认知者 | 知道有哪些工具可用，能初步选择 | 工具选择准确率 ≥ 60% |
| **L3** | 工具选择者 | 能根据任务精准选择工具 | 工具选择准确率 ≥ 85% |
| **L4** | 工具编排者 | 能组合多工具完成复杂任务 | 能正确编排 3+ 工具流水线 |
| **L5** | 工具创造者 | 能发明新工具解决新问题 | 能创造 1+ 新工具并被验证有效 |

> **与 L1-L5 能力体系的完整映射**：请参阅 👉 [《05-能力演进体系》](./05-能力演进体系.md)

## 3. 工具认知单元建模

### 3.1 工具知识类型

在现有 7 种认知单元类型基础上，**工具知识作为元知识贯穿所有类型**，而非独立第 8 种类型：

```
┌─────────────────────────────────────────────────────────────────┐
│                    工具知识与认知单元的关系                       │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  工具知识不是独立存储的，而是作为"如何使用"的元知识：            │
│                                                                 │
│  knowledge（知识） + tool_guidance = "知道这个概念，且知道      │
│                                      用什么工具验证/计算"       │
│                                                                 │
│  skill（技能） + tool_guidance = "会这个操作，且知道            │
│                                  用什么工具辅助执行"            │
│                                                                 │
│  experience（经验） + tool_guidance = "有过这个经历，且知道     │
│                                      当时用了什么工具"          │
│                                                                 │
│  judgment（判断） + tool_guidance = "有这个原则，且知道         │
│                                    用什么工具辅助决策"          │
│                                                                 │
│  strategy（策略） + tool_guidance = "有这个框架，且知道         │
│                                    用什么工具执行"              │
│                                                                 │
│  intuition（直觉） + tool_guidance = "有这个感觉，且知道        │
│                                    用什么工具验证直觉"          │
│                                                                 │
│  emotion（情感） + tool_guidance = "有这个偏好，且知道          │
│                                  偏好用什么工具"                │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 工具指导字段

每个认知单元可包含 `tool_guidance` 字段（L2 启用）：

```yaml
# 示例：技能类认知单元中的工具指导
id: sk_20240101_001
type: skill
content:
  summary: "激活扩散是从激活的认知单元出发，沿关系网络传播激活的核心检索机制"
  body:
    # ... 技能详细内容 ...

# L2 启用的工具指导字段
tool_guidance:
  recommended_tools:          # 推荐工具
    - tool_id: "vector_search"
      reason: "用于语义相似度计算"
      when_to_use: "需要检索相关认知单元时"
      limitations: "仅支持文本类型"
    
    - tool_id: "graph_traversal"
      reason: "用于关系网络扩散"
      when_to_use: "需要沿关系传播激活时"
      limitations: "需要关系索引已建立"
  
  selection_criteria:         # 选择标准
    - "任务类型：检索 → 向量搜索"
    - "数据规模：< 1000 单元用内存计算，> 1000 用 Qdrant"
    - "精度要求：近似检索用 ANNS，精确匹配用暴力搜索"
  
  alternative_tools:          # 替代工具
    - tool_id: "full_text_search"
      tradeoff: "速度更快，但语义理解较弱"
```

工具目录本身也作为认知单元存储（type: knowledge, 但包含工具元数据）：

## 4. 工具调用引擎架构

### 4.1 核心 Trait 定义

```rust
/// 工具调用引擎核心接口
///
/// 负责工具目录管理、选择策略、执行编排。
#[async_trait::async_trait]
pub trait ToolEngine: Send + Sync {
    /// 获取可用工具目录
    fn catalog(&self) -> Vec<ToolMeta>;
    
    /// 根据任务选择工具
    async fn select_tool(&self, task: &TaskContext) -> Result<ToolSelection, ToolError>;
    
    /// 执行工具调用
    async fn execute(&self, tool_id: &str, input: ToolInput) -> Result<ToolOutput, ToolError>;
    
    /// 编排多工具流水线
    async fn orchestrate(&self, pipeline: ToolPipeline) -> Result<PipelineOutput, ToolError>;
    
    /// 注册新工具（L5 创造能力）
    async fn register_tool(&self, tool_def: ToolDefinition) -> Result<(), ToolError>;
    
    /// 记录工具使用反馈（用于学习）
    async fn record_usage(&self, tool_id: &str, outcome: ToolUsageOutcome) -> Result<(), ToolError>;
}
```

### 4.2 数据结构定义

```rust
/// 工具元数据
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ToolMeta {
    /// 工具唯一标识
    pub id: String,
    
    /// 工具名称
    pub name: String,
    
    /// 工具分类
    pub category: ToolCategory,
    
    /// 工具描述
    pub description: String,
    
    /// 工具能力列表
    pub capabilities: Vec<String>,
    
    /// 工具局限性
    pub limitations: Vec<String>,
    
    /// 适用场景
    pub when_to_use: String,
    
    /// 调用成本（时间/资源）
    pub cost: ToolCost,
}

/// 工具分类
#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum ToolCategory {
    Calculation,      // 计算类（计算器、数学库）
    Retrieval,        // 检索类（向量搜索、全文检索）
    DataProcessing,   // 数据处理类（清洗、转换、分析）
    Execution,        // 执行类（代码执行、脚本运行）
    Communication,    // 通信类（邮件、消息）
    ExternalApi,      // 外部 API（搜索引擎、数据库）
    Custom,           // 自定义工具
}

/// 工具选择结果
#[derive(Debug, Clone)]
pub struct ToolSelection {
    /// 选中的工具
    pub tool_id: String,
    
    /// 选择理由
    pub reasoning: String,
    
    /// 置信度（0.0 ~ 1.0）
    pub confidence: f64,
    
    /// 备选工具（如果主工具不可用）
    pub alternatives: Vec<String>,
}

/// 工具调用输入
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ToolInput {
    /// 输入数据
    pub data: serde_json::Value,
    
    /// 配置参数
    pub config: Option<serde_json::Value>,
    
    /// 超时设置（毫秒）
    pub timeout_ms: Option<u64>,
}

/// 工具调用输出
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ToolOutput {
    /// 输出数据
    pub data: serde_json::Value,
    
    /// 执行状态
    pub status: ToolStatus,
    
    /// 错误信息（如果失败）
    pub error: Option<String>,
    
    /// 执行耗时（毫秒）
    pub elapsed_ms: u64,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum ToolStatus {
    Success,
    Failed,
    Timeout,
    Partial,  // 部分成功
}

/// 工具流水线
#[derive(Debug, Clone)]
pub struct ToolPipeline {
    /// 流水线步骤
    pub steps: Vec<PipelineStep>,
    
    /// 失败策略（继续/停止/回滚）
    pub failure_strategy: FailureStrategy,
}

#[derive(Debug, Clone)]
pub struct PipelineStep {
    /// 工具 ID
    pub tool_id: String,
    
    /// 输入（可引用上一步输出）
    pub input: ToolInput,
    
    /// 条件执行（可选）
    pub condition: Option<String>,
}

#[derive(Debug, Clone)]
pub enum FailureStrategy {
    Stop,           // 立即停止
    Continue,       // 继续下一步
    Retry(u32),     // 重试 N 次
    Fallback(String), // 使用备选工具
}
```

## 5. 工具选择策略

### 5.1 选择算法

```
┌─────────────────────────────────────────────────────────────────┐
│                    工具选择算法                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  输入：任务上下文 (TaskContext)                                  │
│  ├── 任务类型（计算/检索/分析/执行/通信）                        │
│  ├── 数据特征（文本/数值/图像/混合）                             │
│  ├── 约束条件（时间/资源/精度）                                  │
│  └── 历史偏好（用户/专家的工具使用习惯）                         │
│                                                                 │
│  处理：                                                          │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  Step 1: 候选过滤                                        │   │
│  │  ├── 按任务类型过滤（计算任务 → 计算类工具）              │   │
│  │  ├── 按数据特征过滤（文本 → 支持文本的工具）              │   │
│  │  └── 按约束条件过滤（低延迟 → 排除高成本工具）            │   │
│  └────────────────────────┬────────────────────────────────┘   │
│                           │                                     │
│  ┌────────────────────────▼────────────────────────────────┐   │
│  │  Step 2: 匹配评分                                        │   │
│  │  ├── Score = α·TypeMatch + β·DataFit + γ·CostEff + δ·Hist│   │
│  │  ├── TypeMatch: 任务类型匹配度（0/1）                    │   │
│  │  ├── DataFit: 数据适配度（工具支持的数据类型）            │   │
│  │  ├── CostEff: 成本效率（1 / cost）                       │   │
│  │  └── Hist: 历史偏好（专家常用工具加分）                   │   │
│  └────────────────────────┬────────────────────────────────┘   │
│                           │                                     │
│  ┌────────────────────────▼────────────────────────────────┐   │
│  │  Step 3: 排序与推荐                                      │   │
│  │  ├── 按 Score 降序排序                                   │   │
│  │  ├── 返回 Top-1 作为主推荐                               │   │
│  │  └── 返回 Top-2~3 作为备选                               │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  输出：ToolSelection                                            │
│  ├── tool_id: 选中的工具                                        │
│  ├── reasoning: 选择理由                                        │
│  ├── confidence: 置信度                                         │
│  └── alternatives: 备选工具列表                                 │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 5.2 专家工具偏好建模

专家的工具偏好作为 `emotion` 类型认知单元存储：

```yaml
id: em_tool_preference_001
type: emotion
content:
  summary: "工具使用偏好：偏好简洁直接的解决方案"
  body:
    format: preference
    body:
      tool_preferences:
        - preference: "偏好内置工具而非外部 API"
```

## 8. 与 L1-L5 能力体系的映射

### 8.1 工具能力在 L1-L5 中的演进

| L 级 | 工具能力级别 | 具体表现 | 与认知能力的协同 |
|------|-------------|---------|----------------|
| **L1** | 工具使用者 | 能调用预设工具（计算器、向量检索） | 工具作为独立功能，不与认知联动 |
| **L2** | 工具认知者 | 知道有哪些工具，能初步选择 | 认知单元包含 tool_guidance 字段 |
| **L3** | 工具选择者 | 精准选择工具，简单组合 | 工具选择策略基于认知内容 |
| **L4** | 工具编排者 | 多工具流水线，并行调度 | 工具编排与双系统思维联动 |
| **L5** | 工具创造者 | 发明新工具，构建工具生态 | 工具创造与反思引擎联动 |

### 8.2 工具能力对专家拟合度的贡献

```
┌─────────────────────────────────────────────────────────────────┐
│                    工具能力对拟合度的贡献                         │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  维度：判断一致性 (Judgment Alignment)                           │
│  ├── 工具选择准确率直接影响判断质量                              │
│  ├── 专家用 SQL 查数据，系统用计算器心算 → 判断偏差              │
│  └── 贡献权重：工具能力占判断一致性的 40%                        │
│                                                                 │
│  维度：经验复用率 (Experience Reuse)                             │
│  ├── 专家经验中包含"用什么工具"的隐性知识                        │
│  ├── "这个问题我当时用了 XX 工具，效果很好"                      │
│  └── 贡献权重：工具能力占经验复用率的 30%                        │
│                                                                 │
│  维度：风格匹配度 (Style Matching)                               │
│  ├── 专家的工具偏好是风格的重要组成部分                          │
│  ├── "这个专家偏好开源工具，不喜欢商业软件"                      │
│  └── 贡献权重：工具能力占风格匹配度的 25%                        │
│                                                                 │
│  综合贡献：工具能力对整体拟合度的贡献约为 30%~35%                │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 11. 与工具能力体系的关系

### 11.1 互补关系

```
┌─────────────────────────────────────────────────────────────────┐
│                    工具能力 vs 模型能力                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  工具能力（外部增强）：                                          │
│  ├── 增强模型的外部执行能力                                      │
│  ├── 让模型"知道用什么工具"                                      │
│  └── 效果：灵活可扩展，不受模型限制                              │
│                                                                 │
│  模型能力（内部增强）：                                          │
│  ├── 增强模型本身的理解和生成能力                                │
│  ├── 让模型"像专家一样思考"                                      │
│  └── 效果：内化到权重，不受上下文窗口限制                        │
│                                                                 │
│  协同关系：                                                     │
│  ├── 模型选择 → 选择适合调用工具的模型                           │
│  ├── 工具调用 → 模型生成工具调用参数                             │
│  ├── 微调训练 → 用工具使用记录作为训练数据                       │
│  └── 工具创造 → 新模型可能需要新工具                             │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 附录：工具能力验收清单

### L1 验收（工具使用者）

- [ ] 能调用计算器执行数值计算
- [ ] 能调用向量检索进行语义搜索
- [ ] 工具调用结果能正确返回

### L2 验收（工具认知者）

- [ ] 系统包含至少 10 个预设工具的目录
- [ ] 能根据任务类型初步选择合适的工具
- [ ] 工具选择准确率 ≥ 60%

### L3 验收（工具选择者）

- [ ] 工具选择准确率 ≥ 85%
- [ ] 能给出选择理由
- [ ] 能提供备选工具

### L4 验收（工具编排者）

- [ ] 能正确编排 3+ 工具流水线
- [ ] 支持并行工具调度
- [ ] 支持失败重试和备选切换

### L5 验收（工具创造者）

- [ ] 能定义新工具并注册到目录
- [ ] 新工具能通过沙箱测试
- [ ] 新工具能被后续任务正确调用
