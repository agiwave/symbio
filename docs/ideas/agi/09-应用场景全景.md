## 1. 场景分类框架

### 1.1 三维分类模型

```yaml
┌─────────────────────────────────────────────────────────────────┐
│                    应用场景三维分类模型                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│                        【时间维度】                              │
│                            ▲                                    │
│                            │                                    │
│              过去 ←────────┼────────→ 未来                      │
│          （记录/复盘）      │       （规划/预测）                │
│                            │                                    │
│                            │                                    │
│        【个人维度】 ←──────┼──────→ 【专业维度】                │
│     （生活/成长/情感）      │       （工作/技能/知识）           │
│                            │                                    │
│                            │                                    │
│              个体 ←────────┼────────→ 群体                     │
│          （个人使用）        │       （团队/组织）               │
│                            ▼                                    │
│                        【规模维度】                              │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```yaml

### 1.2 八大场景域

| 场景域 | 时间取向 | 核心价值 | 典型用户 |
|--------|---------|---------|---------|
| **个人历史** | 过去 | 记录、回顾、理解自己 | 所有人 |
| **个人成长** | 未来规划 | 学习、进化、自我提升 | 学习者/转型者 |
| **生活助手** | 现在 | 日常决策、偏好服务 | 所有人 |
| **知识管理** | 跨时间 | 积累、检索、复用 | 知识工作者 |
| **专业增强** | 现在/未来 | 能力放大、效率提升 | 专业人士 |
| **专家传承** | 未来 | 知识传承、人才培养 | 专家/导师 |
| **团队协作** | 现在 | 共享认知、协同决策 | 团队 |
| **组织记忆** | 跨时间 | 组织智慧沉淀 | 组织 |

│                    团队知识共享场景                              │

## 5. 能力边界：不能做什么

### 5.1 架构固有限制

```yaml

├─────────────────────────────────────────────────────────────────┤
│                                                                 │

│  ├── 只能存储和检索已有的认知内容                               │
│  ├── 无法凭空生成新知识（这需要外部学习）                       │

│  ├── judgment 单元来自人类，不是系统生成                        │
│  ├── 在价值观冲突时，系统只能呈现，不能仲裁                     │

│  ├── 可以基于历史经验做概率性判断                               │
│  ├── 无法预测黑天鹅事件                                         │
│  └── 预测准确性受限于历史数据的完备性                           │
│                                                                 │

│  ├── 只知道用户输入或授权获取的信息                             │
│  ├── 无法读取用户"忘记输入"的重要经历                           │
│  └── L3 级别的主动探针仍需要用户授权                            │
│                                                                 │

│  ├── LLM生成存在幻觉风险                                        │
│  └── 即使 L5 也只能达到理论100%+，实践中会有偏差                │

### 5.3 能力层级对应边界

> **核心概念**：表格中的"不能"分为两种性质——**阶段性不能**（更高层级会解锁）和**边界性不能**（任何层级都不应突破）。这不是体系不完整，而是演进路径和责任边界的明确定义。

#### 5.3.1 阶段性不能（演进路径）

| 层级 | 能做什么 | 暂时不能（更高层级解锁） |
|------|---------|------------------------|
| **L1** | 存储检索知识、基础问答 | 关联推理、主动学习、风格匹配 |
| **L2** | 关联推荐、双系统思维、基础风格 | 隐性知识捕获、主动探针 |
| **L3** | 主动信息获取、影子监听、微调 | 多视角辩论、跨域融合 |
| **L4** | 多心智辩论、工具编排、蒸馏 | 超参重写、工具创造 |
| **L5** | 跨域融合、超参重写、工具创造 | —（已解锁全部能力） |

**性质说明**：
- 这是**演进路径**，不是体系缺陷
- 每个阶段需要前一阶段的基础能力才能实现
- L5 包含 L1-L4 所有能力，是能力叠加而非替代
- 例如：L1 不能关联推理，是因为 L1 没有存储关联关系；L2 能关联推理，是因为新增了关联存储

#### 5.3.2 边界性不能（设计边界）

| 边界类型 | 所有层级都不能 | 原因 |
|---------|---------------|------|
| **价值判断** | 替代人类做价值判断 | judgment 单元来自人类，系统只能呈现不能仲裁 |
| **内容创造** | 创造不存在的内容 | 只能存储和检索已有内容，无法凭空生成 |
| **未来预测** | 预测不确定的黑天鹅事件 | 基于历史做概率判断，无法预测未知 |
| **责任承担** | 承担最终决策责任 | AI 幻觉风险，责任需人类承担 |

**性质说明**：
- 这是**设计边界**，不是待实现功能
- "不能做什么"和"能做什么"同样重要，共同定义系统定位
- 边界保护人类主体性，是体系的组成部分
