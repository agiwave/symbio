# 实施路线图 (AGI能力导向版)

> 本路线图已正式舍弃传统外包软件的"按功能块排位"模式，转而全面对接《05-能力演进体系》中的 **L1~L5 智能体阶跃规范**。每一个开发阶段的闭环，都必须向业务方直接交付一个**具有明确代差跨度的可独立运行产品**。
>
> **文档分工说明**：本文（`03`）聚焦「**怎么做 (How)**」—— 具体的工程任务清单与里程碑；关于「**是什么能力 (What)**」—— 每个 L 级的能力特征与专家拟合度指标，请参阅 👉 [《05-能力演进体系》](./05-能力演进体系.md)。
>
> **架构说明**：本路线图基于 Symbio 分形插件架构，认知系统作为 Agent 插件的子模块实现，通过 `connect` 机制实现实时双向通信。

## 2. Phase 1: L1 静态基建期

> 交付目标：拥有 100% 书本知识的问答机器。
> **参考工期**：2 周（重点在于 RAG 基座与数据清洗）
> **验收标准**：用户提问 → 检索认知单元 → 注入 LLM → 返回符合专家风格的回答

### 2.1 存储与网络底座 (`Layer 1`)
```text
任务清单（Week 1: 数据结构 + 存储）：
├── Day 1-2: 定义 Rust 数据结构
│   ├── CognitiveUnit 结构体（id, type, content, generality 四字段）
│   ├── CognitiveUnitType 枚举（7 种类型）
│   ├── GeneralityLevel 结构体（level, llm_coverage）
│   ├── Relation 结构体（target_id, type, strength, weight, context）
│   └── 序列化/反序列化测试（YAML ↔ Rust）
│
├── Day 3-4: 实现基础存储层
│   ├── YAML 文件存储（cognitive_units/units/*.yaml）
│   ├── 反向索引自动生成（cognitive_units/indices/reverse_relations.yaml）
│   ├── 类型索引自动生成（cognitive_units/indices/by_type.yaml）
│   ├── CRUD 操作实现（create, read, update, delete）
│   └── 存储层单元测试
│
├── Day 5: 向量存储集成
│   ├── Qdrant 本地实例部署（Docker）
│   ├── 向量化适配器（fastembed 或 OpenAI Embedding）
│   ├── 认知单元自动向量化（创建/更新时触发）
│   └── 向量检索基础接口（similarity_search）
```

### 2.2 检索引擎与插件 API
```text
任务清单（Week 2: 检索 + 插件集成）：
├── Day 6-7: 检索引擎
│   ├── 向量检索 + generality.level 过滤
│   ├── Top-K 排序（按相似度得分）
│   ├── 检索配置结构体（top_k, min_generality, type_filter）
│   └── 检索引擎单元测试
│
├── Day 8-9: CognitivePlugin 实现
│   ├── 实现 Plugin Trait 的 meta/invoke/connect 方法
│   ├── invoke 动作路由（store, get, delete, retrieve）
│   ├── connect 机制集成（watch 认知单元变化）
│   └── 插件注册到 PluginFactoryRegistry
│
├── Day 10: 端到端集成测试
│   ├── 创建 15 个示例认知单元（覆盖 7 种类型）
│   ├── 测试检索流程：提问 → 检索 → 返回结果
│   ├── 测试存储流程：创建 → 存储 → 索引更新
│   └── 测试 connect 机制：watch → 变化推送
```

### 2.3 LLM 基础链路
```text
任务清单（Week 2 并行）：
├── 初级适配器
│   ├── OpenAI Chat API 集成（async-openai crate）
│   ├── 简单 Prompt 组装（system + user message）
│   └── 上下文注入格式（认知单元 → system prompt）
│
├── L1 级插件 API（通过 Symbio 三命令接口）
│   ├── invoke('agent/cognitive', { action: 'retrieve', query: '...', config: {...} })
│   ├── invoke('agent/cognitive', { action: 'store', unit: {...} })
│   └── stream('agent/cognitive', { action: 'chat', messages: [...] })
│
├── Connect 机制集成
│   ├── connect('agent/cognitive', { action: 'watch' })
│   └── 实时接收认知单元变化事件
│
└── L1 验收测试
    ├── 输入"如何优化 React 性能？"→ 返回包含 sk_001 等认知单元的回答
    ├── 创建新认知单元 → 验证 YAML 文件生成 + 索引更新
    ├── 检索时按 generality.level 过滤 → 验证结果正确
    └── 通过 connect 监听 → 验证变化事件实时推送
```

## 3. Phase 2: L2 逻辑反思期

> 交付目标：能拥有当前任务焦点，懂得“举一反三”的方法论助理。
> **参考工期**：4 - 5 周 (重点在于反思引擎与缓存分页逻辑)

### 3.1 动态短期记忆与环境感知 (`Layer 0`)
```text
任务清单：
├── 极速图谱缓存
│   ├── 为 Agent 提供内存级 (Redis/RAM) 的工作区 (Working Cache)
│   └── 并行处理当前的“长上下文焦点”
│
├── AgentState 情绪控制接入
│   ├── 建立疲劳值、自信度模型
│   └── API: PUT `/state/mood` 允许外源直接干预系统状态
```

### 3.2 抽象学习与深思机制
```text
任务清单：
├── 双系统推演
│   ├── 快响应机制 (System 1) 的就近直觉短路方案
│   └── 长逻辑链 (System 2) 的深层次关系图谱激活扩散巡查
│
├── 后台反思引擎 (Reflection)
│   ├── 将短期经验升维并压缩为大策略的重写逻辑
│   ├── 建立定时巡查触发器
│   └── API: POST `/reflection/trigger` 用于开发调优
```

## 4. Phase 3: L3 自主生长期

> 交付目标：主动挂机巡检互联网、并在后台疯狂偷师主人操作习惯的猎手。

### 4.1 端侧黑盒捕获
```text
任务清单：
├── 潜意识提取插件 (Shadow Observer)
│   ├── Mac / Windows 键盘鼠标焦点全局脱敏收集端
│   ├── VSCode / IntelliJ 开发者环境操作漏斗记录器
│   └── API: POST `/shadow/ingress` —— 高并发脱敏行为回传端点
```

### 4.2 猎犬机制
```text
任务清单：
├── 主动嗅探爬虫 (Foraging Engine)
│   ├── RSS、知名社区的自动检索钩子
│   ├── 夜间算力控制器的激活触发
│   └── 新知识校验与静默图谱扩增队列
```

## 5. Phase 4: L4 多元心智期

> 交付目标：遇到危险能像《头脑特工队》一样打内战商量的万无一失委员会。

### 5.1 沙盘辩论架构
```text
任务清单：
├── 子人格分裂器 (Persona Forks)
│   ├── 根据不同 `Judgment`（激进/保守/法律）生成对应人设 Prompt
│   ├── 为每个进程隔离分配独立的推理空间
│
├── 仲裁控制中心 (Orchestrator)
│   ├── 并发状态树监控
│   ├── Summary Node (聚合节点) 提纯收敛最终策略
│   └── API: POST `/society/interrupt` —— 监控台人工终止内讧
```

## 6. Phase 5: L5 架构跃迁期

> 交付目标：突破单人生理极限，打破代码定死的底座规则。

### 6.1 越级超变基因
```text
任务清单：
├── 跨域融合库 (Neural Synthesis Hub)
│   ├── 解析来自任意不相关领域专家包的元数据热拔插
│   ├── 跨领域重叠交叉校验防止认知崩溃
│
├── 元架构自重写 (Meta Rewrite)

│   ├── 强制挂载 `cost_awareness_limit` 安全预算上限以防暴走
```
