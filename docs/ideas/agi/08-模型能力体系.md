# 模型能力体系

> 专家系统的能力不仅来自"知道用什么工具"（外部增强），更来自"拥有多懂专家的模型"（内部增强）。
>
> 本文档定义了认知系统中模型能力的完整体系，包括模型调用、模型选择、模型微调、模型蒸馏与模型创造五大维度。

## 1. 核心理念

### 1.1 为什么模型能力是专家系统的核心特征

```yaml
┌─────────────────────────────────────────────────────────────────┐
│                    专家系统增强的两条路径                         │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  路径一：外部增强（工具能力）                                    │
│  ├── 方式：调用外部工具（计算器、搜索引擎、数据库）              │
│  ├── 优点：灵活、可随时更换、不受模型限制                        │
│  └── 局限：需要显式调用、无法内化到模型理解                      │
│                                                                 │
│  路径二：内部增强（模型能力）                                    │
│  ├── 方式：微调/训练模型，让模型本身更懂专家                     │
│  ├── 优点：内化到权重、不受上下文窗口限制、风格更自然            │
│  └── 局限：需要训练数据、计算资源、更新不如注入灵活              │
│                                                                 │
│  最佳方案：两条路径结合                                          │
│  ├── 模型微调提供基础理解（"像专家一样思考"）                    │
│  ├── 认知单元注入提供最新知识（"知道专家最新的经验"）            │
│  └── 工具调用提供外部增强（"知道用什么工具验证/执行"）           │
│                                                                 │
│  公式：专家系统能力 = 基础 LLM × 模型增强因子 × 工具增强因子     │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```yaml

### 1.2 模型能力的心理学基础

| 心理学概念 | 对应模型能力 | 说明 |
|-----------|-------------|------|
| **内隐学习** | 模型微调 | 将专家的隐性知识内化到模型权重 |
| **迁移学习** | 模型蒸馏 | 将大模型能力迁移到小模型 |
| **元认知** | 模型选择 | "知道什么任务用什么模型"的自我监控 |
| **创造性思维** | 模型创造 | 训练领域专用模型解决新问题 |

### 1.3 模型能力与 LLM 的关系

```yaml
┌─────────────────────────────────────────────────────────────────┐
│                    模型能力的层级                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  L1: 模型调用者                                                  │
│  ├── 能力：能调用 GPT-4/Claude 等基础模型                        │
│  ├── 局限：不知道何时用什么模型                                  │
│  └── 典型表现："我直接用 GPT-4 回答所有问题"                     │
│                                                                 │
│  L2: 模型适配者                                                  │
│  ├── 能力：能根据任务选择合适模型                                │
│  ├── 进阶：知道各模型的优劣势                                    │
│  └── 典型表现："推理用 GPT-4，创意用 Claude，代码用 Codex"       │
│                                                                 │
│  L3: 模型微调者                                                  │
│  ├── 能力：能用专家数据微调开源模型                              │
│  ├── 进阶：理解微调的原理和最佳实践                              │
│  └── 典型表现："我用专家历史回答微调了 Llama-3"                  │
│                                                                 │
│  L4: 模型蒸馏者                                                  │
│  ├── 能力：能将大模型能力蒸馏到小模型                            │
│  ├── 进阶：平衡性能与成本                                        │
│  └── 典型表现："我把 GPT-4 蒸馏到 7B 模型，成本降 90%"           │
│                                                                 │
│  L5: 模型创造者                                                  │
│  ├── 能力：能训练领域专用模型                                    │
│  ├── 进阶：超越通用模型在特定领域的表现                          │
│  └── 典型表现："我训练了医疗专用模型，超越 GPT-4"                │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```yaml

### 2.1 模型能力五级模型

```yaml
                    模型能力金字塔

                        ┌─────────┐
                        │ L5 创造 │  训练领域专用模型
                        └─────────┘
                       ╱           ╲
                    ╱                   ╲
              ┌─────────┐           ┌─────────┐
              │ L4 蒸馏 │           │ L4 创造 │
              └─────────┘           └─────────┘
            ╱                               ╲
         ╱                                     ╲
    ┌─────────┐                         ┌─────────┐
    │ L3 微调 │                         │ L3 蒸馏 │
    └─────────┘                         └─────────┘
  ╱                                           ╲
 ╱                                               ╲
 ─────────────────────────────────────────────────────
              L2 选择          L2 适配
           知道选什么模型    知道何时用什么
 ─────────────────────────────────────────────────────
```yaml

### 2.2 模型能力各级定义

| 级别 | 名称 | 能力定义 | 验收标准 |
|------|------|---------|---------|
| **L1** | 模型调用者 | 能调用基础 LLM API | 能正确调用并获取回答 |
| **L2** | 模型适配者 | 知道各模型优劣势，能初步选择 | 模型选择准确率 ≥ 60% |
| **L3** | 模型微调者 | 能用专家数据微调开源模型 | 微调后模型在专家测试集上超越基座 10%+ |
| **L4** | 模型蒸馏者 | 能将大模型能力蒸馏到小模型 | 蒸馏后模型性能 ≥ 原模型 85%，成本降低 50%+ |
| **L5** | 模型创造者 | 能训练领域专用模型 | 专用模型在领域测试集上超越通用模型 |

> **与 L1-L5 能力体系的完整映射**：请参阅 👉 [《05-能力演进体系》](./05-能力演进体系.md)

### 3.2 模型指导字段

每个认知单元可包含 `model_guidance` 字段（L2 启用）：

```yaml
# 示例：技能类认知单元中的模型指导
id: sk_20240101_001
type: skill
content:
  summary: "激活扩散是从激活的认知单元出发，沿关系网络传播激活的核心检索机制"
  body:
    # ... 技能详细内容 ...

# L2 启用的模型指导字段
model_guidance:
  recommended_models:         # 推荐模型
    - model_id: "gpt-4-turbo"
      reason: "复杂推理任务，需要强逻辑能力"
      when_to_use: "需要深度分析时"
      limitations: "成本高，延迟较高"
    
    - model_id: "claude-3-sonnet"
      reason: "创意生成任务，文风自然"
      when_to_use: "需要创意表达时"
      limitations: "逻辑推理略弱于 GPT-4"
  
  selection_criteria:         # 选择标准
    - "任务类型：推理 → GPT-4"
    - "成本约束：低预算 → 开源模型"
    - "延迟要求：实时 → 小模型"
  
  alternative_models:         # 备选模型
    - model_id: "llama-3-70b"
      tradeoff: "成本低 80%，但推理能力弱 15%"
```yaml

## 4. 模型训练引擎架构

### 4.1 核心 Trait 定义

```rust
/// 模型训练引擎核心接口
///
/// 负责模型目录管理、选择策略、微调、蒸馏与创造。
#[async_trait::async_trait]
pub trait ModelEngine: Send + Sync {
    /// 获取可用模型目录
    fn catalog(&self) -> Vec<ModelMeta>;
    
    /// 根据任务选择模型
    async fn select_model(&self, task: &TaskContext) -> Result<ModelSelection, ModelError>;
    
    /// 调用模型生成回答
    async fn generate(&self, model_id: &str, prompt: &str, config: GenerationConfig) 
        -> Result<GenerationOutput, ModelError>;
    
    /// 微调模型
    async fn finetune(&self, base_model: &str, training_data: Vec<TrainingSample>, 
                      config: FinetuneConfig) -> Result<FinetuneResult, ModelError>;
    
    /// 蒸馏模型
    async fn distill(&self, teacher_model: &str, student_model: &str,
                     config: DistillConfig) -> Result<DistillResult, ModelError>;
    
    /// 训练新模型（L5 创造能力）
    async fn train(&self, config: TrainConfig) -> Result<TrainResult, ModelError>;
    
    /// 记录模型使用反馈
    async fn record_usage(&self, model_id: &str, outcome: ModelUsageOutcome) -> Result<(), ModelError>;
}
```yaml

### 4.2 数据结构定义

```rust
/// 模型元数据
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ModelMeta {
    /// 模型唯一标识
    pub id: String,
    
    /// 模型名称
    pub name: String,
    
    /// 提供商
    pub provider: String,
    
    /// 模型分类
    pub category: ModelCategory,
    
    /// 模型能力
    pub capabilities: Vec<String>,
    
    /// 模型局限性
    pub limitations: Vec<String>,
    
    /// 适用场景
    pub when_to_use: String,
    
    /// 成本（每 1k tokens）
    pub cost_per_1k_tokens: f64,
    
    /// 上下文窗口大小
    pub context_window: usize,
}

/// 模型分类
#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum ModelCategory {
    General,          // 通用模型（GPT-4, Claude）
    Code,             // 代码专用（Codex, CodeLlama）
    Math,             // 数学专用
    Creative,         // 创意生成
    OpenSource,       // 开源模型
    Custom,           // 自定义/微调模型
}

/// 模型选择结果
#[derive(Debug, Clone)]
pub struct ModelSelection {
    /// 选中的模型
    pub model_id: String,
    
    /// 选择理由
    pub reasoning: String,
    
    /// 置信度
    pub confidence: f64,
    
    /// 备选模型
    pub alternatives: Vec<String>,
}

/// 生成配置
#[derive(Debug, Clone)]
pub struct GenerationConfig {
    /// 温度
    pub temperature: f64,
    
    /// 最大 tokens
    pub max_tokens: usize,
    
    /// Top-p
    pub top_p: f64,
    
    /// 停止序列
    pub stop_sequences: Vec<String>,
}

/// 生成输出
#[derive(Debug, Clone)]
pub struct GenerationOutput {
    /// 生成的文本
    pub text: String,
    
    /// 使用的 tokens
    pub usage: TokenUsage,
    
    /// 生成耗时
    pub elapsed_ms: u64,
}

#[derive(Debug, Clone)]
pub struct TokenUsage {
    pub prompt_tokens: usize,
    pub completion_tokens: usize,
    pub total_tokens: usize,
}

/// 微调配置
#[derive(Debug, Clone)]
pub struct FinetuneConfig {
    /// 基础模型
    pub base_model: String,
    
    /// 训练轮数
    pub epochs: u32,
    
    /// 学习率
    pub learning_rate: f64,
    
    /// 批次大小
    pub batch_size: usize,
    
    /// 验证集比例
    pub validation_split: f64,
}

/// 微调结果
#[derive(Debug, Clone)]
pub struct FinetuneResult {
    /// 新模型 ID
    pub model_id: String,
    
    /// 训练损失
    pub train_loss: f64,
    
    /// 验证损失
    pub val_loss: f64,
    
    /// 相比基座的提升
    pub improvement_over_base: f64,
}

/// 蒸馏配置
#[derive(Debug, Clone)]
pub struct DistillConfig {
    /// 教师模型
    pub teacher_model: String,
    
    /// 学生模型
    pub student_model: String,
    
    /// 蒸馏温度
    pub temperature: f64,
    
    /// 训练样本数
    pub num_samples: usize,
}

/// 蒸馏结果
#[derive(Debug, Clone)]
pub struct DistillResult {
    /// 新模型 ID
    pub model_id: String,
    
    /// 学生模型性能
    pub student_performance: f64,
    
    /// 教师模型性能
    pub teacher_performance: f64,
    
    /// 性能保留比例
    pub performance_ratio: f64,
    
    /// 成本降低比例
    pub cost_reduction: f64,
}

/// 训练配置
#[derive(Debug, Clone)]
pub struct TrainConfig {
    /// 模型架构
    pub architecture: String,
    
    /// 训练数据
    pub training_data: Vec<TrainingSample>,
    
    /// 训练轮数
    pub epochs: u32,
    
    /// 学习率
    pub learning_rate: f64,
}

/// 训练结果
#[derive(Debug, Clone)]
pub struct TrainResult {
    /// 新模型 ID
    pub model_id: String,
    
    /// 训练损失
    pub train_loss: f64,
    
    /// 验证损失
    pub val_loss: f64,
    
    /// 在基准测试上的得分
    pub benchmark_scores: HashMap<String, f64>,
}
```yaml

### 5.1 选择算法

```yaml
┌─────────────────────────────────────────────────────────────────┐
│                    模型选择算法                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  输入：任务上下文 (TaskContext)                                  │
│  ├── 任务类型（推理/创意/代码/数学/通用）                        │
│  ├── 数据特征（文本/代码/混合）                                  │
│  ├── 约束条件（成本/延迟/精度）                                  │
│  └── 历史偏好（专家常用的模型）                                  │
│                                                                 │
│  处理：                                                          │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  Step 1: 候选过滤                                        │   │
│  │  ├── 按任务类型过滤（代码任务 → 代码模型）                │   │
│  │  ├── 按约束条件过滤（低预算 → 排除高成本模型）            │   │
│  │  └── 按延迟要求过滤（实时 → 排除高延迟模型）              │   │
│  └────────────────────────┬────────────────────────────────┘   │
│                           │                                     │
│  ┌────────────────────────▼────────────────────────────────┐   │
│  │  Step 2: 匹配评分                                        │   │
│  │  ├── Score = α·TypeMatch + β·CostEff + γ·Latency + δ·Hist│   │
│  │  ├── TypeMatch: 任务类型匹配度                           │   │
│  │  ├── CostEff: 成本效率（1 / cost）                       │   │
│  │  ├── Latency: 延迟适配（1 / latency）                    │   │
│  │  └── Hist: 历史偏好（专家常用模型加分）                   │   │
│  └────────────────────────┬────────────────────────────────┘   │
│                           │                                     │
│  ┌────────────────────────▼────────────────────────────────┐   │
│  │  Step 3: 排序与推荐                                      │   │
│  │  ├── 按 Score 降序排序                                   │   │
│  │  ├── 返回 Top-1 作为主推荐                               │   │
│  │  └── 返回 Top-2~3 作为备选                               │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  输出：ModelSelection                                           │
│  ├── model_id: 选中的模型                                       │
│  ├── reasoning: 选择理由                                        │
│  ├── confidence: 置信度                                         │
│  └── alternatives: 备选模型列表                                 │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```yaml

## 10. 与 L1-L5 能力体系的映射

### 10.1 模型能力在 L1-L5 中的演进

| L 级 | 模型能力级别 | 具体表现 | 与认知能力的协同 |
|------|-------------|---------|----------------|
| **L1** | 模型调用者 | 能调用基础 LLM API | 模型作为独立功能，不与认知联动 |
| **L2** | 模型适配者 | 知道有哪些模型，初步选择 | 认知单元包含 model_guidance 字段 |
| **L3** | 模型微调者 | 用专家数据微调开源模型 | 认知单元 → 训练数据 → 微调 |
| **L4** | 模型蒸馏者 | 蒸馏大模型到小模型 | 蒸馏数据来自高质量认知单元 |
| **L5** | 模型创造者 | 训练领域专用模型 | 专用模型基于领域认知单元训练 |

### 10.2 模型能力对专家拟合度的贡献

```yaml
┌─────────────────────────────────────────────────────────────────┐
│                    模型能力对拟合度的贡献                         │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  维度：风格匹配度 (Style Matching)                               │
│  ├── 微调后模型更接近专家的表达风格                              │
│  ├── "这个专家喜欢用结构化输出，微调后模型也这样"                │
│  └── 贡献权重：模型能力占风格匹配度的 40%                        │

│  ├── 微调后模型更理解专家的决策逻辑                              │

│  └── 贡献权重：模型能力占判断一致性的 25%                        │
│                                                                 │

│  ├── 微调后模型理解专家特定术语                                  │

│  └── 贡献权重：模型能力占知识还原度的 20%                        │
│                                                                 │
│  综合贡献：模型能力对整体拟合度的贡献约为 25%~30%                │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```yaml

### 11.1 互补关系

│  ├── 微调训练 → 用工具使用记录作为训练数据                       │
│  └── 工具创造 → 新模型可能需要新工具                             │
