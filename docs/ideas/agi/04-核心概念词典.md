## 0. 设计依据与学术基础

> 本章节说明认知架构设计的心理学、认知科学依据，以及理论争议点。

### 0.1 核心理论来源

```
┌─────────────────────────────────────────────────────────────────┐
│                    理论来源图谱                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  【认知心理学基础】                                              │
│  ├── Atkinson & Shiffrin (1968) - 记忆的多存储模型             │
│  │   → 感觉记忆/短时记忆/长时记忆的三层结构                    │
│  ├── Tulving (1972) - 记忆系统分类                             │
│  │   → 语义记忆(Semantic) / 情景记忆(Episodic)                │
│  ├── Baddeley & Hitch (1974) - 工作记忆模型                   │
│  │   → 中央执行系统/语音环路/视空间模板                       │
│  └── Anderson (1983) - ACT-R 认知架构                          │
│      → 陈述性记忆/程序性记忆的区分                             │
│                                                                 │
│  【专家知识与隐性知识】                                          │
│  ├── Polanyi (1966) - 隐性知识概念                             │
│  │   → "我们所知道的比我们能说出来的多"                       │
│  ├── Nonaka & Takeuchi (1995) - SECI 知识转化模型              │
│  │   → 隐性↔显性知识的四种转化模式                           │
│  ├── Dreyfus & Dreyfus (1980) - 技能获得模型                   │
│  │   → 新手→高级初学者→胜任者→精通者→专家的五阶段           │
│  └── Ericsson et al. (1993) - 专家表现研究                     │
│      → 刻意练习与专家直觉形成                                  │
│                                                                 │
│  【双系统理论】                                                  │
│  ├── Kahneman (2011) - 快思考与慢思考                          │
│  │   → 系统1(直觉) / 系统2(理性) 的决策模式                   │
│  └── Stanovich & West (2000) - 双系统心智架构                  │
│      → 启发式系统 vs 分析系统                                  │
│                                                                 │
│  【元认知理论】                                                  │
│  ├── Flavell (1979) - 元认知概念                               │
│  │   → 关于认知的认知，监控和调节自己的认知过程               │
│  └── Nelson & Narens (1990) - 元认知监控模型                   │
│      → 对象层与元层的双向监控关系                              │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 0.2 认知类型与心理学映射

| 认知类型 | 心理学来源 | 核心文献 | 匹配程度 |
|---------|-----------|---------|---------|
| **Knowledge** | 语义记忆 | Tulving (1972) | ✓✓✓ 标准匹配 |
| **Experience** | 情景记忆 | Tulving (1972) | ✓✓✓ 标准匹配 |
| **Skill** | 程序性记忆 | Anderson (1983) | ✓✓✓ 标准匹配 |
| **Strategy** | 元认知策略 | Flavell (1979) | ✓✓ 较好匹配 |
| **Judgment** | 专家直觉/决策 | Kahneman (2011) | ✓✓ 合理扩展 |
| **Intuition** | 程序性记忆自动化 | Dreyfus (1980) | ⚠ 有争议（见下文） |
| **Emotion** | 情感记忆/情绪调节 | LeDoux (1996) | ⚠ 有争议（见下文） |

### 0.3 理论争议与设计决策

```
┌─────────────────────────────────────────────────────────────────┐
│                    理论争议说明                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  【争议1：Intuition 是否应作为独立类型？】                       │
│                                                                 │
│  心理学主流观点：                                                │
│  ├── 直觉不是独立的记忆类型，而是程序性记忆自动化的结果         │
│  ├── Dreyfus 技能模型：直觉是专家阶段的技能内化                │
│  └── Kahneman：直觉是系统1的快速模式识别                       │
│                                                                 │
│  本架构的设计决策：                                              │
│  ├── 仍然独立为类型，理由：                                     │
│  │   1. 专家的核心能力恰恰是无法显式表达的直觉                 │
│  │   2. 直觉需要与 Skill 分离存储（内容 vs 机制）              │
│  │   3. 实际检索时需要区分"有意识的技能"和"无意识的直觉"      │
│  └── 承认这是扩展性决策，需要实践验证                           │
│                                                                 │
│  ────────────────────────────────────────────────────────────   │
│                                                                 │
│  【争议2：Emotion 是否应作为存储内容？】                         │
│                                                                 │
│  心理学主流观点：                                                │
│  ├── 情感通常被视为"状态"或"过程"，而非"可存储的内容"         │
│  ├── 情绪调节是过程，不是静态知识                              │
│  └── 情感记忆通常指"带有情感色彩的记忆"，而非情感本身         │
│                                                                 │
│  本架构的设计决策：                                              │
│  ├── 将 Emotion 定义为"偏好、风格、价值观"等稳定的情感倾向     │
│  ├── 理由：                                                     │
│  │   1. 专家风格是个人独特性的核心组成部分                     │
│  │   2. 风格偏好影响所有认知内容的应用方式                     │
│  │   3. AI 拟真需要显式建模风格才能"像这个人"                 │
│  └── 承认这是创新性尝试，需要实践验证                           │
│                                                                 │
│  ────────────────────────────────────────────────────────────   │
│                                                                 │
│  【争议3：七种类型是否过于复杂？】                               │
│                                                                 │
│  行业对比：                                                      │
│  ├── MemGPT: 3 种记忆类型 (Core/Archival/Working)              │
│  ├── Generative Agents: 2 种 (Memory/Reflection)               │
│  └── 本架构: 7 种认知类型                                       │
│                                                                 │
│  设计理由：                                                      │
│  ├── 目标不同：行业方案追求"够用"，本方案追求"完整专家建模"   │
│  ├── 边际效益：隐性知识的细分是专家建模的关键                  │
│  └── 风险承认：可能存在过度设计，需要实践验证边际效益          │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 三类概念的区分原则

```
┌─────────────────────────────────────────────────────────────────┐

## 2. 第一类：认知内容

### 2.1 总览

```
┌─────────────────────────────────────────────────────────────────┐
│                    认知内容总览                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  定义：个人大脑中可数字化存储的信息和知识                        │
│                                                                 │
│  核心特征：                                                     │
│  ├── 是"存储什么"的答案                                        │
│  ├── 用 CognitiveUnit 数据结构建模                              │
│  └── 是被认知过程操作的对象                                     │
│                                                                 │
│  七种类型：                                                     │
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │                                                         │   │
│  │   显性内容 (Explicit)          隐性内容 (Tacit)         │   │
│  │                                                         │   │
│  │   ├─ Knowledge                 ├─ Experience            │   │
│  │   │  概念、原理、事实          │  案例、教训、最佳实践   │   │
│  │   │  (语义记忆)                │  (情景记忆)            │   │
│  │   │                           │                         │   │
│  │   └─ Skill                     ├─ Judgment              │   │
│  │      流程、方法、步骤          │  原则、规则、价值观     │   │
│  │      (程序性记忆)              │  (经验内化)            │   │
│  │                               │                         │   │
│  │                               ├─ Strategy               │   │
│  │                               │  框架、策略、思维模式   │   │
│  │                               │  (元认知)               │   │
│  │                               │                         │   │
│  │                               ├─ Intuition              │   │
│  │                               │  模式识别、快速判断     │   │
│  │                               │  (自动化认知)           │   │
│  │                               │                         │   │
│  │                               └─ Emotion                │   │
│  │                                  偏好、风格、动机       │   │
│  │                                  (情感记忆)             │   │
│  │                                                         │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  个人核心竞争力：隐性内容（LLM无法从通用训练中获得）            │

```

### 2.2 Knowledge（知识）

```
┌─────────────────────────────────────────────────────────────────┐
│                       Knowledge（知识）                         │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  定义：可编码、可传递的事实、概念、原理和规则                    │
│                                                                 │
│  【心理学基础】                                                  │
│  ├── 对应：语义记忆 (Semantic Memory)                          │
│  ├── 特点：关于世界的一般性知识，不依赖于特定情境               │
│  └── 存储：在大脑中组织为概念网络                               │
│                                                                 │
│  【特征】                                                        │
│  ├── 相对客观：可验证真伪                                       │
│  ├── 可传递：可通过文档、教学传递                               │
│  ├── 结构化：有明确的概念体系和逻辑关系                          │
│  └── 通用性：可在不同情境中迁移应用                              │
│                                                                 │
│  【子类型】                                                      │
│  1. 事实性知识：具体事实（"DCF是现金流折现模型"）              │
│  2. 概念性知识：抽象概念（"估值模型的分类"）                   │
│  3. 原理性知识：因果原理（"价格围绕价值波动"）                 │
│  4. 条件性知识：应用条件（"何时用DCF估值"）                    │
│                                                                 │
│  【与LLM的关系】                                                 │
│  ├── Level 0-1：LLM已覆盖，无需存储或仅补充                    │
│  ├── Level 2：情境特定，需存储                                 │
│  └── 存储重点：个人视角的独特见解                               │
│                                                                 │
│  【CognitiveUnit结构】                                          │
│  ├── summary：核心知识摘要                                       │
│  ├── body：详细内容（可包含公式、图表）                          │
│  ├── context.triggers：激活触发词                                │
│  └── generality：通用度分级                                      │
│                                                                 │
│  【示例：普通人 vs 专家】                                        │
│  ├── 普通人："React useState 的基本用法"（level_1）            │
│  └── 专家："React 18 并发渲染对状态管理的影响"（level_2）      │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.3 Experience（经验）

```
┌─────────────────────────────────────────────────────────────────┐
│                       Experience（经验）                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  定义：在特定情境中通过实践获得的知识和判断力                    │
│                                                                 │
│  【心理学基础】                                                  │
│  ├── 对应：情景记忆 (Episodic Memory)                          │
│  ├── 特点：与特定时间、地点、情境绑定的个人经历                 │
│  └── 存储：以事件-情境-结果的形式组织                           │
│                                                                 │
│  【特征】                                                        │
│  ├── 情境依赖：与特定场景、时间、条件绑定                      │
│  ├── 个人化：难以完全传递给他人                                │
│  ├── 可迁移性有限：需要类比推理才能应用                        │
│  └── 包含情感：常带有成功喜悦或失败教训                        │
│                                                                 │
│  【子类型】                                                      │

### 3.8 社会认知（Social Cognition）

```
┌─────────────────────────────────────────────────────────────────┐
│                    社会认知（Social Cognition）                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  定义：理解他人心理状态、意图和行为的认知能力                    │

│      → 自动化的1阶推理 vs 努力的2阶推理                        │
│                                                                 │
│  【核心能力维度】                                                │
│  ├── 信念归因：推断他人持有的信念                              │

│  ├── 情绪识别：识别他人的情绪状态                              │
│  ├── 观点采择：从他人视角看问题                                │
│  └── 行为预测：基于心智状态预测他人行为                        │
│                                                                 │
│  【团队协作中的应用】                                            │
│  ├── 理解队友的知识边界 → 知道何时解释、何时省略               │
│  ├── 识别利益相关者意图 → 理解需求背后的真实诉求               │
│  ├── 预测他人反应 → 提前准备应对策略                           │
│  └── 协调多方视角 → 整合不同立场达成共识                       │
│                                                                 │
│  【系统实现】                                                    │

│  │   │   └── { person_id: [known_topics] }                    │
│  │   └── interaction_history: []    # 交互历史                │
│  ├── L4 多视角辩论 → 模拟不同利益相关者的心智模型              │
│  └── 协作推荐 → 基于心智理论优化沟通策略                       │
│                                                                 │
│  【示例：项目决策中的心智建模】                                  │

│  │  stakeholder_models:                                    │   │
│  │    - person_id: "产品经理A"                             │   │
│  │      beliefs:                                           │   │
│  │        - "用户增长优先于技术债务"                       │   │
│  │        - "本周必须上线"                                 │   │
│  │      goals: ["完成KPI", "获得晋升"]                      │   │
│  │      constraints: ["老板压力", "时间紧张"]              │   │
│  │    - person_id: "技术负责人B"                           │   │

│                                                                 │

### 3.9 元认知监控（Metacognitive Monitoring）

```
┌─────────────────────────────────────────────────────────────────┐
│                  元认知监控（Metacognitive Monitoring）          │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  定义：对自身认知过程和知识状态的监控、评估与调节                │
│                                                                 │
│  【心理学基础】                                                  │
│  ├── Flavell (1979) - 元认知概念                               │
│  │   → 元认知知识：关于认知的知识                             │
│  │   → 元认知监控：对认知的监控                               │
│  │   → 元认知调节：对认知的调节                               │
│  ├── Nelson & Narens (1990) - 元认知监控模型                   │
│  │   → 对象层(Object Level)：实际认知活动                     │
│  │   → 元层(Meta Level)：监控和控制系统                       │
│  │   → 双向信息流：监控(向上) + 控制(向下)                    │
│  └── Koriat (1997) - 基于线索的元认知判断                      │
│      → 熟悉感、知晓感、舌尖状态等元认知体验                    │
│                                                                 │
│  【核心能力维度】                                                │
│  ├── 知识边界感知：知道自己知道什么、不知道什么                │
│  ├── 置信度校准：判断自己对某知识的把握程度                    │
│  ├── 策略选择：选择最适合当前任务的认知策略                    │
│  ├── 错误检测：发现自己在推理或记忆中的错误                    │
│  └── 学习监控：评估自己的学习进度和效果                        │
│                                                                 │
│  【专家 vs 新手的元认知差异】                                    │
│  ├── 专家：准确的知识边界感知、高置信度校准能力                │
│  ├── 新手：过度自信或自信不足、边界感知模糊                    │
│  └── Dunning-Kruger 效应：能力不足者高估自己                   │
│                                                                 │
│  【系统实现】                                                    │
│  ├── confidence 字段 → 存储对每个认知单元的置信度              │
│  │   ├── overall: float        # 总体置信度 0-1               │
│  │   ├── evidence_based: float # 基于证据的置信度             │
│  │   ├── experience_based: float # 基于经验的置信度           │
│  │   └── calibration_history: [] # 校准历史                   │
│  ├── 知识边界检测 → 自动识别未覆盖的知识领域                   │
│  │   ├── coverage_gaps: []      # 知识覆盖缺口                │
│  │   └── uncertainty_zones: []  # 不确定区域                  │
│  ├── 校准反馈机制 → 记录预测准确性并调整置信度                 │
│  │   ├── prediction_outcomes: [] # 预测结果记录              │
│  │   └── calibration_score: float # 校准得分                  │
│  └── 学习需求推荐 → 基于知识边界推荐学习内容                   │
│                                                                 │
│  【示例：投资判断的置信度建模】                                  │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  id: jd_invest_001                                      │   │
│  │  type: judgment                                         │   │
│  │  content:                                               │   │
│  │    summary: "早期项目投资判断原则"                       │   │
│  │    # ... 判断内容 ...                                   │   │
│  │  confidence:                                            │   │
│  │    overall: 0.85            # 总体置信度                 │   │
│  │    evidence_based: 0.90     # 有大量案例支撑             │   │
│  │    experience_based: 0.80   # 个人经验有限               │   │
│  │    calibration_history:                                 │   │
│  │      - date: "2023-06"                                  │   │
│  │        predicted: 0.85                                  │   │
│  │        actual_accuracy: 0.82  # 实际准确率               │   │
│  │        deviation: -0.03      # 略微过度自信              │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  【与认知内容的关系】                                            │
│  元认知是"自省机制"，为所有认知内容附加置信度元数据            │
│  影响检索排序（高置信度优先）和生成策略（低置信度加谨慎）       │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

│  └── Nonaka & Takeuchi (1995) - SECI 知识转化模型              │

│                                                                 │

│         │                │              │              │        │
│         ▼                ▼              ▼              ▼        │
│  ┌──────────┐      ┌──────────┐    ┌──────────┐   ┌──────────┐ │
│  │ 理解阶段 │ ──▶ │ 应用阶段 │ ─▶│ 熟练阶段 │─▶│ 内化阶段 │ │
│  │          │      │          │    │          │   │          │ │
│  │ 学习理论 │      │ 实践案例 │    │ 重复练习 │   │ 自动直觉 │ │
│  │ 明确规则 │      │ 获得反馈 │    │ 形成肌肉 │   │ 模式识别 │ │
│  │          │      │          │    │ 记忆     │   │          │ │
│  └──────────┘      └──────────┘    └──────────┘   └──────────┘ │
│                                                                 │
│  【内化程度量化】                                                │
│  ├── mastery_level: 1-5  # 掌握程度                            │
│  │   1=了解  2=理解  3=应用  4=熟练  5=内化                    │
│  ├── practice_hours: int  # 练习时长                           │
│  ├── feedback_count: int  # 获得反馈次数                       │
│  ├── error_rate: float    # 错误率（随练习下降）               │
│  └── transfer_success: float # 迁移成功率                      │
│                                                                 │
│  【系统实现】                                                    │
│  ├── learning_trajectory 字段 → 记录学习内化路径               │
│  │   ├── start_date: date         # 开始学习日期              │
│  │   ├── current_stage: enum      # 当前阶段                  │
│  │   ├── practice_log: []         # 练习记录                  │
│  │   │   └── { date, activity, outcome, feedback }            │
│  │   ├── milestone_achievements: [] # 里程碑成就              │
│  │   └── estimated_expert_date: date # 预计专家级日期          │
│  ├── 内化触发机制 → 当 practice_hours 和 feedback_count 达标   │
│  │   → 自动生成 Intuition 类型认知单元                         │
│  ├── 衰减机制 → 长期未练习自动降低 mastery_level               │
│  └── 推荐机制 → 基于当前阶段推荐下一步学习内容                 │
│                                                                 │
│  【示例：编程技能的内化轨迹】                                    │

│  │  id: skill_python_001                                   │   │
│  │  type: skill                                            │   │

### 5.4 关系类型扩展

```
┌─────────────────────────────────────────────────────────────────┐
│                    关系类型扩展定义                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  【基础关系类型】                                                │
│  ├── depends_on：依赖关系（A 需要 B 才能成立）                  │
│  ├── part_of：组成部分（A 是 B 的子部分）                       │
│  ├── related_to：一般关联                                       │
│  ├── supports：支撑关系（B 支撑 A 的成立）                      │
│  ├── contradicts：矛盾关系（A 与 B 相冲突）                     │
│  ├── causes：因果关系（A 导致 B）                               │
│  └── precedes：先后关系（A 在 B 之前）                          │
│                                                                 │
│  【能力协同关系类型】（新增）                                    │
│  ├── validates：验证关系（经验验证判断/策略）                   │
│  ├── instantiates：实例关系（经验是策略的具体实例）             │
│  ├── refines：精化关系（技能是知识的操作化精化）                │
│  ├── conflicts_with：冲突关系（两个判断在特定条件下冲突）       │
│  └── synthesized_from：综合关系（策略综合自多个经验）           │
│                                                                 │
│  【演化关系类型】（新增）                                        │
│  ├── evolved_to：演化关系（知识随时间变为经验/直觉）            │
│  ├── derived_from：派生关系（判断派生自经验总结）               │
│  ├── generalized_from：泛化关系（策略泛化自多个案例）           │
│  └── specialized_to：特化关系（通用知识特化为领域技能）         │
│                                                                 │
│  【时间线关系类型】（新增）                                      │
│  ├── follows：时间后继（A 在 B 之后发生）                       │
│  ├── concurrent_with：同时发生                                  │
│  ├── triggered_by：触发关系（A 触发 B 的发生）                  │
│  └── resolves：解决关系（A 解决了 B 带来的问题）                │
│                                                                 │
│  【使用示例】                                                    │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  # 经验验证判断                                           │   │
│  │  relations:                                               │   │
│  │    - target_id: jd_task_decomposition                     │   │
│  │      type: validates                                      │   │
│  │      context: "这次重构验证了按业务边界分解的判断"        │   │
│  │                                                          │   │
│  │  # 策略泛化自经验                                         │   │
│  │  relations:                                               │   │
│  │    - target_id: exp_refactor_2023                         │   │
│  │      type: generalized_from                               │   │
│  │      context: "从这个案例提炼出通用策略"                  │   │
│  │                                                          │   │
│  │  # 直觉演化自技能                                         │   │
│  │  relations:                                               │   │
│  │    - target_id: sk_code_review                            │   │
│  │      type: evolved_to                                     │   │
│  │      context: "多年代码审查经验形成的直觉"                │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 7.2 LLM与认知内容的结合模式

```

├─────────────────────────────────────────────────────────────────┤

│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  模式3：认知单元验证（Content Validation）              │   │
│  │                                                         │   │

│  │  方式：用专家案例验证LLM输出合理性                      │   │
│  │  效果：让LLM输出"符合专家经验"                          │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
