# 技术实现方案

> 基于 Symbio 分形插件架构的认知系统技术实现方案

---

## 文档定位

**本文档是 01-认知架构模型 的技术实现规格（How）**，遵循以下设计原则：

1. **屏蔽细节，使用简单**：调用者不需要了解任何认知模块的实现细节
2. **高内聚低耦合**：认知模块对外只暴露一个极简接口，内部实现完全封装
3. **自顶向下**：场景需求 → 模块边界 → 极简接口 → 内部架构 → 数据结构
4. **渐进增强**：L1 最小可执行子集优先，L2-L5 按需扩展

**推荐阅读顺序**：01 文档（设计意图）→ 本文档（技术实现）→ 03 文档（实施计划）

## 2. 模块边界与极简接口

### 2.1 核心设计哲学

```yaml
┌─────────────────────────────────────────────────────────────────┐
│                    优秀模块的设计标准                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  错误的设计：                                                    │
│  ├── 暴露内部细节，让调用者控制                                 │
│  ├── 提供大量配置选项，让调用者选择                             │
│  ├── 调用者需要了解：检索策略、过滤条件、注入量...              │
│  └── 结果：调用者认知负担重，容易用错                           │
│                                                                 │
│  正确的设计：                                                    │
│  ├── 屏蔽所有内部细节                                           │
│  ├── 调用者只需要知道：给我一个问题，我返回增强的回答           │
│  ├── 所有决策内部自动完成：                                     │
│  │   ├── 检索多少单元？→ 内部自动决定                           │
│  │   ├── 过滤什么等级？→ 内部自动判断                           │
│  │   ├── 用什么系统模式？→ 内部自动选择                         │
│  │   └── 注入多少上下文？→ 内部自动计算                         │
│  └── 结果：调用者零认知负担，不会用错                           │
│                                                                 │
│  核心认知：                                                      │
│  调用者不应该了解"认知单元"、"激活扩散"、"独特性分级"等概念。    │
│  调用者只需要知道：这个模块能让 LLM 回答更个性化、更专业。       │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```yaml

### 2.2 对外接口：只有一个

```rust
// 路径：agent/cognitive
// 方法：invoke

// 调用方式（极简）
{
  "action": "enhance",
  "params": {
    "question": "如何处理分布式系统故障？"
  }
}

// 返回结果
{
  "answer": "根据我的经验，分布式系统故障排查应该..."
}
```

**就这么简单。**

调用者不需要知道：
- ❌ 认知单元是什么
- ❌ 检索了多少内容
- ❌ 使用了什么过滤条件
- ❌ 注入了多少上下文
- ❌ 用了 System 1 还是 System 2

调用者只需要：
- ✅ 传入一个问题
- ✅ 获得一个增强的回答

### 2.3 可选接口：状态查询（仅用于 UI 展示）

```rust
// 路径：agent/cognitive
// 方法：invoke

// 调用方式
{
  "action": "stats"
}

// 返回结果
{
  "knowledge_units": 1234,
  "learning_progress": "active"
}
```

这个接口**仅用于前端 UI 展示**（如显示"已学习 1234 条经验"），不参与核心业务流程。

### 2.4 与外部模块的关系

```yaml
┌─────────────────────────────────────────────────────────────────┐
│                    认知模块与外部模块关系                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  agent 聊天模块 ──enhance(question)──▶ 认知模块                 │
│  ├── 聊天时调用 enhance() 获得增强回答                        │
│  └── 直接返回给用户，无需任何额外处理                         │
│                                                                 │
│  前端 UI ──stats()──▶ 认知模块                                  │
│  ├── 显示认知单元数量统计（可选）                               │
│  └── 不影响核心功能                                             │
│                                                                 │
│  外部 Agent 接口 ──enhance(question)──▶ 认知模块                │
│  ├── 未来 Agent 框架可调用 enhance()                            │
│  └── 获得个性化的增强回答                                     │
│                                                                 │
│  关键认知：                                                      │
│  ├── 外部模块不直接操作认知单元 CRUD                            │
│  ├── 认知单元的创建/更新由认知模块内部自动完成                  │
│  ├── 例如：聊天历史学习由认知模块内部触发，外部无感知           │
│  └── 调用者零认知负担                                           │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```yaml

## 4. 内部模块划分

### 4.1 模块职责与依赖关系

```yaml
┌─────────────────────────────────────────────────────────────────┐
│                    内部模块依赖关系                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  CognitivePlugin (对外接口层)                                    │
│  ├── 职责：接收 enhance 请求，编排内部引擎，返回增强回答        │
│  ├── 依赖：RetrievalEngine, InjectionEngine, LearningEngine     │
│  └── 对外接口：enhance(question) → answer                       │
│                                                                 │
│  RetrievalEngine (检索引擎)                                      │
│  ├── 职责：根据查询检索相关认知单元                             │
│  ├── 依赖：UnitStore, VectorStore, GraphStore                   │
│  ├── 内部接口：retrieve(query) → Vec<CognitiveUnit>             │
│  └── 算法：向量检索 + 激活扩散                                  │
│                                                                 │
│  InjectionEngine (注入引擎)                                      │
│  ├── 职责：将认知单元转换为 LLM 可理解的上下文                  │
│  ├── 依赖：无（纯函数转换）                                     │
│  ├── 内部接口：format_context(units) → String                   │
│  └── 算法：按类型格式化 + token 控制                            │
│                                                                 │
│  LearningEngine (学习引擎)                                       │
│  ├── 职责：认知单元 CRUD + 权重更新 + 关系发现                  │
│  ├── 依赖：UnitStore, VectorStore, GraphStore                   │
│  ├── 内部接口：                                                   │
│  │   ├── create_unit(unit) → String                             │
│  │   ├── update_weights(unit_id, feedback) → ()                 │
│  │   └── discover_relations(units) → Vec<Relation>              │
│  └── 触发方式：内部自动触发（如聊天历史学习）                    │
│                                                                 │
│  Storage Layer (存储层)                                          │
│  ├── UnitStore: 认知单元持久化（YAML 文件）                     │
│  ├── VectorStore: 向量索引（Qdrant）                            │
│  ├── GraphStore: 关系网络（petgraph）                           │
│  └── WorkingMemory: 工作记忆（内存 + 分页置换）                 │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```yaml

### 4.2 接口分层

| 接口类型 | 接口名 | 调用方 | 说明 |
|---------|--------|--------|------|
| **对外接口** | `enhance(question)` | agent 聊天、外部 Agent | 增强 LLM 回答 |
| **对外接口** | `stats()` | 前端 UI（可选） | 显示统计信息 |
| 内部接口 | `retrieve(query)` | RetrievalEngine 内部 | 检索认知单元 |
| 内部接口 | `format_context(units)` | InjectionEngine 内部 | 格式化上下文 |
| 内部接口 | `create_unit(unit)` | LearningEngine 内部 | 创建认知单元 |
| 内部接口 | `update_weights(id, feedback)` | LearningEngine 内部 | 更新权重 |

**关键认知**：内部接口不对外暴露，外部模块只需要调用 `enhance(question)` 即可获得增强回答。

## 5. 核心数据结构

### 5.1 CognitiveUnit 定义

```rust
// src/plugins/agent/cognitive/models/cognitive_unit.rs

use chrono::{DateTime, Utc};
use serde::{Deserialize, Serialize};

/// 认知单元类型
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum CognitiveUnitType {
    Knowledge,    // 语义记忆
    Experience,   // 情景记忆
    Skill,        // 程序性记忆
    Judgment,     // 经验内化
    Strategy,     // 元认知
    Intuition,    // 自动化认知
    Emotion,      // 情感记忆
}

impl std::fmt::Display for CognitiveUnitType {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        match self {
            Self::Knowledge => write!(f, "knowledge"),
            Self::Experience => write!(f, "experience"),
            Self::Skill => write!(f, "skill"),
            Self::Judgment => write!(f, "judgment"),
            Self::Strategy => write!(f, "strategy"),
            Self::Intuition => write!(f, "intuition"),
            Self::Emotion => write!(f, "emotion"),
        }
    }
}

/// 内容格式

            relations: vec![],

        let importance_factor = self.strength.importance as f32 / 5.0;
        let accessibility_factor = self.strength.accessibility;

        0.4 * semantic_similarity
            + 0.3 * activation
            + 0.2 * importance_factor
            + 0.1 * accessibility_factor
    }

        self.usage.last_accessed = Some(Utc::now());
        self.strength.accessibility = (self.strength.accessibility + 0.1).min(1.0);
    }

    pub fn apply_decay(&mut self, decay_rate: f32) {
        self.strength.accessibility *= (1.0 - decay_rate);
        if self.strength.accessibility < 0.1 {
            self.strength.accessibility = 0.1;
        }
    }

            vector,
            model,
            created_at: chrono::Utc::now(),
        }
    }

    /// 计算余弦相似度
    pub fn cosine_similarity(&self, other: &[f32]) -> f32 {
        let dot: f32 = self.vector.iter()
            .zip(other.iter())
            .map(|(a, b)| a * b)
            .sum();

        let norm_a: f32 = self.vector.iter().map(|x| x * x).sum::<f32>().sqrt();
        let norm_b: f32 = other.iter().map(|x| x * x).sum::<f32>().sqrt();

        if norm_a == 0.0 || norm_b == 0.0 {
            0.0
        } else {
            dot / (norm_a * norm_b)
        }
    }
}

// src/plugins/agent/cognitive/storage/unit_store.rs

use anyhow::{Context, Result};
use std::path::{Path, PathBuf};
use std::collections::HashMap;
use tokio::fs;
use tokio::io::AsyncWriteExt;

use crate::plugins::agent::cognitive::models::CognitiveUnit;

/// 认知单元存储（内部实现）
pub struct UnitStore {
    base_path: PathBuf,
    units: HashMap<String, CognitiveUnit>,
    by_type: HashMap<String, Vec<String>>, // 类型索引
}

impl UnitStore {
    pub async fn new(base_path: impl AsRef<Path>) -> Result<Self> {
        let base_path = base_path.as_ref().to_path_buf();
        let mut store = Self {
            base_path,
            units: HashMap::new(),
            by_type: HashMap::new(),
        };

        store.load_all().await?;
        Ok(store)
    }

    /// 加载所有认知单元
    async fn load_all(&mut self) -> Result<()> {
        let units_path = self.base_path.join("units");

        if !units_path.exists() {
            fs::create_dir_all(&units_path).await?;
            return Ok(());
        }

        let mut entries = fs::read_dir(&units_path).await?;

        while let Some(entry) = entries.next_entry().await? {
            let path = entry.path();
            if path.extension().map(|e| e == "yaml").unwrap_or(false) {
                if let Ok(unit) = self.load_unit(&path).await {
                    let type_key = unit.unit_type.to_string();
                    self.by_type.entry(type_key).or_default().push(unit.id.clone());
                    self.units.insert(unit.id.clone(), unit);
                }
            }
        }

        tracing::info!("Loaded {} cognitive units", self.units.len());
        Ok(())
    }

    /// 加载单个认知单元
    async fn load_unit(&self, path: &Path) -> Result<CognitiveUnit> {
        let content = fs::read_to_string(path).await?;
        let unit: CognitiveUnit = serde_yaml::from_str(&content)
            .with_context(|| format!("Failed to parse unit from {:?}", path))?;
        Ok(unit)
    }

    /// 保存认知单元
    pub async fn save(&self, unit: &CognitiveUnit) -> Result<()> {
        let units_path = self.base_path.join("units");
        fs::create_dir_all(&units_path).await?;

        let file_path = units_path.join(format!("{}.yaml", unit.id));
        let content = serde_yaml::to_string(unit)?;

        let mut file = fs::File::create(&file_path).await?;
        file.write_all(content.as_bytes()).await?;

        tracing::debug!("Saved unit {} to {:?}", unit.id, file_path);
        Ok(())
    }

    /// 获取认知单元
    pub fn get(&self, id: &str) -> Option<&CognitiveUnit> {
        self.units.get(id)
    }

    /// 获取所有 ID
    pub fn all_ids(&self) -> impl Iterator<Item = &String> {
        self.units.keys()
    }

    /// 按类型获取
    pub fn get_by_type(&self, type_name: &str) -> Vec<&CognitiveUnit> {
        self.by_type
            .get(type_name)
            .map(|ids| ids.iter().filter_map(|id| self.units.get(id)).collect())
            .unwrap_or_default()
    }

    /// 添加或更新认知单元
    pub async fn upsert(&mut self, unit: CognitiveUnit) -> Result<()> {
        let id = unit.id.clone();
        let type_key = unit.unit_type.to_string();

        // 更新类型索引
        if !self.units.contains_key(&id) {
            self.by_type.entry(type_key).or_default().push(id.clone());
        }

        // 保存到文件
        self.save(&unit).await?;

        // 更新内存
        self.units.insert(id, unit);

        Ok(())
    }
}

use std::cmp::Ordering;
use serde::{Deserialize, Serialize};

use crate::plugins::agent::cognitive::models::{CognitiveUnit, RelationType};
use crate::plugins::agent::cognitive::storage::UnitStore;

/// 激活节点
#[derive(Debug, Clone)]
struct ActivationNode {
    unit_id: String,
    activation: f32,
}

impl PartialEq for ActivationNode {
    fn eq(&self, other: &Self) -> bool {
        self.activation == other.activation
    }
}

impl Eq for ActivationNode {}

impl PartialOrd for ActivationNode {
    fn partial_cmp(&self, other: &Self) -> Option<Ordering> {
        Some(self.cmp(other))
    }
}

impl Ord for ActivationNode {
    fn cmp(&self, other: &Self) -> Ordering {
        other.activation.partial_cmp(&self.activation).unwrap_or(Ordering::Equal)
    }
}

/// 检索配置 (内部自动调整，调用者无需关心)
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct RetrievalConfig {
    pub initial_activation: f32,
    pub decay_factor: f32,
    pub max_hops: usize,
    pub activation_threshold: f32,
    pub max_results: usize,

    // AGI 终极破极化机制新增参数
    pub is_mutable: bool,            // 允许自我重写标志（元级学习）
    pub cost_awareness_limit: u32,   // 心智社会沙盘推演硬件花销限制
}

impl Default for RetrievalConfig {
    fn default() -> Self {
        Self {
            initial_activation: 1.0,
            decay_factor: 0.7,
            max_hops: 3,
            activation_threshold: 0.1,
            max_results: 20,
            is_mutable: true,
            cost_awareness_limit: 1000,
        }
    }
}

/// 检索引擎（内部实现）
pub struct RetrievalEngine {
    unit_store: UnitStore,
    config: RetrievalConfig,
}

impl RetrievalEngine {
    pub fn new(unit_store: UnitStore, config: RetrievalConfig) -> Self {
        Self { unit_store, config }
    }

    /// 执行检索（内部接口）
    pub async fn retrieve(&self, query: &str) -> Vec<(String, f32)> {
        // 1. 向量检索获取初始候选
        let candidates = self.vector_search(query).await;

        // 2. 激活扩散
        let activations = self.spreading_activation(candidates);

        // 3. 排序并返回
        let mut results: Vec<_> = activations.into_iter()
            .filter(|(_, activation)| *activation > self.config.activation_threshold)
            .collect();

        results.sort_by(|a, b| b.1.partial_cmp(&a.1).unwrap_or(Ordering::Equal));
        results.truncate(self.config.max_results);

        results
    }

    /// 向量检索（简化实现）
    async fn vector_search(&self, _query: &str) -> Vec<(String, f32)> {
        // 实际实现需要调用向量数据库
        vec![]
    }

    /// 激活扩散算法
    fn spreading_activation(&self, initial: Vec<(String, f32)>) -> HashMap<String, f32> {
        let mut activations: HashMap<String, f32> = HashMap::new();
        let mut heap: BinaryHeap<ActivationNode> = BinaryHeap::new();

        // 初始化
        for (id, sim) in initial {
            let activation = sim * self.config.initial_activation;
            activations.insert(id.clone(), activation);
            heap.push(ActivationNode { unit_id: id, activation });
        }

        // 扩散
        let mut hops = 0;
        while let Some(node) = heap.pop() {
            if hops >= self.config.max_hops {
                break;
            }

            if node.activation < self.config.activation_threshold {
                continue;
            }

            // 获取邻居
            if let Some(unit) = self.unit_store.get(&node.unit_id) {
                for relation in &unit.relations {
                    let new_activation = node.activation * self.config.decay_factor * relation.strength;

                    let entry = activations.entry(relation.target_id.clone()).or_insert(0.0);
                    if new_activation > *entry {
                        *entry = new_activation;
                        heap.push(ActivationNode {
                            unit_id: relation.target_id.clone(),
                            activation: new_activation,
                        });
                    }
                }
            }

            hops += 1;
        }

        activations
    }
}

    pub async fn create(&self, unit: CognitiveUnit) -> Result<String> {
        let id = unit.id.clone();
        self.unit_store.upsert(unit).await?;
        Ok(id)
    }

    /// 更新认知单元（内部接口）
    pub async fn update(&self, id: &str, unit: CognitiveUnit) -> Result<()> {
        self.unit_store.upsert(unit).await?;
        Ok(())
    }

    /// 删除认知单元（内部接口）
    pub async fn delete(&self, id: &str) -> Result<()> {
        // TODO: 实现删除逻辑
        Ok(())
    }

    /// 添加关系（内部接口）
    pub async fn add_relation(&self, from_id: &str, to_id: &str, relation_type: RelationType, strength: f32) -> Result<()> {
        if let Some(unit) = self.unit_store.get(from_id) {
            let mut updated = unit.clone();
            updated.relations.push(Relation {
                target_id: to_id.to_string(),
                relation_type,
                strength,
                weight: 1.0,
                context: None,
            });
            self.unit_store.upsert(updated).await?;
        }
        Ok(())
    }

    /// 根据反馈更新权重（内部接口）
    pub async fn update_weights(&self, unit_id: &str, positive: bool) -> Result<()> {
        if let Some(unit) = self.unit_store.get(unit_id) {
            let mut updated = unit.clone();

            if positive {
                updated.usage.feedback_positive += 1;
                updated.strength.confidence = (updated.strength.confidence + 0.05).min(1.0);
            } else {
                updated.usage.feedback_negative += 1;
                updated.strength.confidence = (updated.strength.confidence - 0.05).max(0.0);
            }

            updated.source.updated_at = Utc::now();
            self.unit_store.upsert(updated).await?;
        }
        Ok(())
    }

    /// 应用时间衰减（内部接口）
    pub async fn apply_decay(&self, decay_rate: f32) -> Result<()> {
        for id in self.unit_store.all_ids().cloned().collect::<Vec<_>>() {
            if let Some(unit) = self.unit_store.get(&id) {
                let mut updated = unit.clone();
                updated.apply_decay(decay_rate);
                self.unit_store.upsert(updated).await?;
            }
        }
        Ok(())
    }
}

## 10. LLM 适配层

### 10.1 独特性分级与 LLM 分工

| 级别 | 名称 | LLM 覆盖 | 存储策略 | 处理方式 |
|------|------|---------|---------|---------|
| Level 0 | 人类共识 | 100% | 无需存储 | 直接使用 LLM |
| Level 1 | 半通用知识 | 70-90% | 仅补充独特见解 | LLM + 个人视角 |
| Level 2 | 情境特定知识 | 30-60% | 完整存储 | 认知单元注入 + LLM 推理 |
| Level 3 | 个人独有经历 | 10-30% | 完整存储 | 认知单元注入 + 类比推理 |
| Level 4 | 个人风格/价值观 | 0-20% | 完整存储 | 认知单元引导 LLM 生成 |

### 10.2 三种 LLM 结合模式

| 模式 | 适用类型 | 方式 | 效果 |
|------|---------|------|------|
| **认知单元注入** | Level 2-4 | 将相关认知单元注入 LLM 上下文 | 让 LLM"临时拥有"被建模者的知识 |
| **认知单元引导** | judgment/strategy | 用判断原则和策略框架约束 LLM 输出 | 让 LLM"按照被建模者的思维"生成 |
| **认知单元验证** | experience/intuition | 用个人案例验证 LLM 输出合理性 | 让 LLM 输出"符合个人经验" |

### 10.3 双系统结合模式

| 系统 | 触发条件 | 认知资源 | 处理方式 | 效果 |
|------|---------|---------|---------|------|
| **System 1：快速直觉** | 高相似度、低复杂度 | 高权重 Intuition/Skill | LLM 直接模式匹配 | "秒懂"反应，耗时短 |
| **System 2：慢速推演** | 矛盾/高风险/不确定 | 深层 Strategy/Judgment | 多心智沙盘辩论 | 缜密逻辑与上帝视角 |
