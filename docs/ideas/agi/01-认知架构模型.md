## 1. 项目概述

### 1.1 核心目标

```
┌─────────────────────────────────────────────────────────────────┐
│                        核心问题                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  如何构建一个通用的认知内容存储和检索框架，                      │
│  让 AI Agent 能够理解和运用任何人的认知内容？                    │
│                                                                 │
│  子问题：                                                       │
│  ├── 人的认知内容由什么构成？                                   │
│  ├── 这些内容以什么形式存储？                                   │
│  ├── LLM 如何理解和检索这些内容？                               │
│  ├── 如何实现动态学习和演化？                                   │
```

### 1.2 设计理念：通用为先

```
┌─────────────────────────────────────────────────────────────────┐
│                    设计理念                                      │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  核心定位：                                                      │
│                                                                 │
│  这是一个【通用的个人认知建模框架】，适用于：                    │
│  ├── 普通人：个人经历、生活经验、个人偏好、日常习惯              │
│  ├── 专业人士：专业知识、项目经验、工作方法论                    │
│  ├── 专家：深度判断力、行业直觉、独特决策风格                    │
│  ├── 团队：集体知识、协作经验、团队文化                          │
│  └── 组织：组织记忆、最佳实践、价值观                            │
│                                                                 │
│  框架成功标准：                                                  │
│                                                                 │
│  能够支撑【专家级别】的能力密度，是框架设计成功的证明            │
│  能够服务【普通人】的日常需求，是框架设计可用的前提              │
│                                                                 │
│  类比：                                                          │
│  ├── 文件系统 ─── 能存日记，也能存论文                         │
│  ├── 数据库 ─── 能存购物清单，也能存交易记录                   │
│  └── 大脑 ─── 结构相同，内容密度不同                           │
│                                                                 │
│  关键认知：                                                      │
│  ├── 普通人和专家的区别不是"结构不同"，而是"内容密度不同"       │
│  ├── 同一套 CognitiveUnit 结构，装入不同通用度的内容即可         │
│  └── 专家只是高密度特例，框架天然支持从普通人到专家的完整谱系    │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

```
不同人的差异：
├── 普通人：知识为主，少量经验，弱直觉
```

```
│  ├── emotion: "宁可错过不可冒进的投资风格"                       │
│  └── judgment: "技术债超过30%的项目必须重构"                     │
│                                                                 │
```

### 1.4 核心设计原则

```
┌─────────────────────────────────────────────────────────────────┐
│                        设计原则                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  原则一：结构通用，内容可变                                      │
│  ├── 认知单元结构适用于任何人                                  │
│  ├── 七种类型适用于任何认知内容                                 │
│  └── 密度由内容决定，结构不变                                   │
│                                                                 │
│  原则二：与LLM有效分工                                           │
│  ├── Level 0-1：LLM已覆盖，无需存储                             │
│  ├── Level 2-4：个人独有，需要存储                              │
│  └── 让LLM"临时拥有"被建模者的能力                             │
│                                                                 │
│  原则三：激活扩散检索                                            │
│  ├── 通过关系网络扩散激活（模拟人脑联想）                       │
│  ├── 选择性注入高相关度内容                                     │
│  └── 控制注入量，避免上下文过载                                 │
│                                                                 │
│  原则四：动态学习演化                                            │
│  ├── 根据使用反馈调整权重                                       │
│  ├── 时间衰减机制                                               │
│  └── 持续积累新的认知内容                                       │
│                                                                 │
│  原则五：密度无关的存储                                          │
│  ├── 存储结构支持任意密度的内容                                 │
│  ├── 低密度内容占用少，高密度内容占用多                         │
│  └── 框架本身不预设密度上限                                     │
│                                                                 │
│  原则六：渐进增强，最小先行                                      │
│  ├── 先实现 L1 最小可执行子集（2 周可交付）                      │
│  ├── 通过实际使用验证数据结构设计                               │
│  └── 按需添加 L2-L5 的高级能力                                  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 1.5 最小可执行子集（L1 优先实现）

> **核心思想**：不要试图一次性实现全部七种类型和五层存储。
> 先用 2 周交付一个**能跑通端到端流程**的最小版本，再通过实际使用迭代增强。
>
> **详细技术规格**：请参阅 👉 [《02-技术实现方案》](./02-技术实现方案.md)
> **详细实施计划**：请参阅 👉 [《03-实施路线图》Phase 1](./03-实施路线图.md)

### 1.5.1 L1 核心原则

- **必填字段**：`id`、`type`、`content`、`generality`（4 个）
- **可选字段**：`relations`、`strength`、`usage`、`source`（L2+ 逐步启用）
- **核心功能**：认知单元 CRUD + 向量检索 + 分级过滤
- **L2+ 功能**：激活扩散、工作记忆分页、双系统切换、反思引擎

### 1.5.2 L1 端到端流程

```
用户提问 → 向量化查询 → Top-K 召回 → 分级过滤
  → 格式化为 LLM 上下文 → LLM 生成回答 → 返回给用户
```

> **L1 验收标准**：用户提问后，系统能检索到相关认知单元，注入 LLM 上下文，生成符合个人风格的回答。

> 本认知系统不是独立项目，而是作为 **Symbio 分形插件架构** 中 `agent` 插件的子模块实现。
>
> **详细技术规格**：请参阅 👉 [《02-技术实现方案》](./02-技术实现方案.md)

### 1.6.1 架构位置

```
symbio/plugins/agent/cognitive/  ← 认知系统（本方案）
```

### 1.6.2 通过 Connect 机制实现实时通信

| 方向 | 机制 | 说明 |
|------|------|------|
| 前端 → 认知系统 | `invoke('agent/cognitive', {...})` | 查询、存储、删除等操作 |
| 认知系统 → 前端 | `Connection.emit('cognitive/unit_changed', {...})` | 认知单元变化实时推送 |
| 实时状态推送 | `connect('agent/cognitive', { action: 'watch' })` | 建立持久连接监听状态变化 |

```
外部修改文件 → Explorer FileWatcher 检测 → Connection 发送事件
  → 前端 Explorer Store 接收 → 刷新 UI
  → （可选）认知系统监听文件变化 → 自动更新相关认知单元
```

## 2. 三层概念体系（概览）

本系统所有概念按"**存储什么 → 如何运作 → 如何构建**"划分为三层，这也是 `04-核心概念词典` 的组织主线。

| 层级 | 核心问题 | 核心载体 | 典型概念 |
| :--- | :--- | :--- | :--- |
| **第一类：认知内容** | 存储什么？ | `CognitiveUnit` 数据结构 | 知识、经验、技能、判断、策略、直觉、情感 |
| **第二类：认知过程** | 如何运作？ | 系统机制 / LLM 能力 | 感知→记忆→注意→思维→表达→意识/反思 |
| **第三类：系统实现** | 如何构建？ | 技术架构 / 数据结构 | Agent、认知引擎、知识图谱、向量数据库 |

> **核心公式**：**能力 = f(认知内容 × 认知过程)**
> 同样的框架结构，放入不同密度的认知内容（普通人 vs 专家 vs 顶级专家），能力表现差异巨大。

> **完整定义请参阅**：👉 [《04-核心概念词典》](./04-核心概念词典.md)，该文档是所有概念的**唯一权威来源**。

## 3. 第一类：认知内容（概览）

认知内容使用统一的 **`CognitiveUnit`** 数据结构存储，分为七种类型：

| 类型 | 心理学来源 | 显性/隐性 | 独特性档位 | 个人独特性 |
| :--- | :--- | :---: | :---: | :--- |
| `knowledge` | 语义记忆 | 显性 | Level 0~2 | 低（LLM 大量覆盖） |
| `skill` | 程序性记忆 | 显性 | Level 1~2 | 低中 |
| `experience` | 情景记忆 | 隐性 | Level 2~4 | 高（个人经历唯一） |
| `judgment` | 经验内化 | 隐性 | Level 3~4 | 高 |
| `strategy` | 元认知 | 隐性 | Level 2~3 | 中高 |
| `intuition` | 自动化认知 | 隐性 | Level 3~4 | **极高**（个人核心特征） |
| `emotion` | 情感记忆 | 隐性 | Level 4 | **极高**（个人风格标志） |

> **详细字段定义、YAML 格式及每种类型示例**：请参阅 👉 [《04-核心概念词典》第二章](./04-核心概念词典.md)

### 3.1 工具知识：贯穿所有类型的元知识

工具知识**不是独立的第 8 种类型**，而是作为"如何使用工具"的元知识，贯穿上述七种类型：

```
knowledge + tool_guidance = "知道这个概念，且知道用什么工具验证/计算"
skill + tool_guidance = "会这个操作，且知道用什么工具辅助执行"
experience + tool_guidance = "有过这个经历，且知道当时用了什么工具"
judgment + tool_guidance = "有这个原则，且知道用什么工具辅助决策"
strategy + tool_guidance = "有这个框架，且知道用什么工具执行"
intuition + tool_guidance = "有这个感觉，且知道用什么工具验证直觉"
emotion + tool_guidance = "有这个偏好，且知道偏好用什么工具"
```

> **工具能力完整体系**：请参阅 👉 [《07-工具能力体系》](./07-工具能力体系.md)，包含工具认知/选择/编排/创造的完整设计

### 3.2 模型知识：贯穿所有类型的内部增强

模型知识与工具知识互补，作为"如何训练/选择模型"的元知识：

```
knowledge + model_guidance = "知道这个概念，且知道用什么模型理解/生成"
skill + model_guidance = "会这个操作，且知道用什么模型辅助执行"
experience + model_guidance = "有过这个经历，且知道当时用了什么模型"
judgment + model_guidance = "有这个原则，且知道用什么模型辅助决策"
strategy + model_guidance = "有这个框架，且知道用什么模型执行"
intuition + model_guidance = "有这个感觉，且知道用什么模型验证直觉"
emotion + model_guidance = "有这个偏好，且知道偏好用什么模型"
```

> **模型能力完整体系**：请参阅 👉 [《08-模型能力体系》](./08-模型能力体系.md)，包含模型调用/选择/微调/蒸馏/创造的完整设计

### 3.3 双重增强公式

```
专家系统能力 = 基础 LLM × 模型增强因子 × 工具增强因子

模型增强（内部增强）：
├── 微调让模型"像专家一样思考"
├── 蒸馏降低成本
└── 创造领域专用模型

工具增强（外部增强）：
├── 调用外部工具（计算器、搜索引擎）
├── 编排多工具流水线
└── 创造新工具解决新问题

协同效应：
├── 模型选择 → 选择适合调用工具的模型
├── 工具调用 → 模型生成工具调用参数
├── 微调训练 → 用工具使用记录作为训练数据
└── 工具创造 → 新模型可能需要新工具
```

### 4.2 认知过程与系统实现的映射

| 认知过程 | 系统实现 | 技术组件 |
|---------|---------|---------|
| 感知 | LLM能力 | 多模态输入处理、信息抽取 |
| 记忆 | 系统机制 | 向量数据库、认知单元存储、**工作记忆区(短期追踪)** |
| 注意 | 系统机制 | 激活扩散算法、相关度排序 |
| 思维 | LLM能力 | **System 1 直觉匹配 / System 2 逻辑辩论** |
| 表达/行动 | LLM+Tools | 文本生成、**工具调用(Action)、逻辑反馈闭环** |

### 5.4 内外双轨动作空间 (Action Space)

借鉴业界前沿的 CoALA 模型，本架构对智能调度层（Orchestrator）下发的行为指令集实行**双轨制强隔离**，坚决杜绝“内向推演”与“外部破坏执行”导致的死循环紊乱：

1. **内部独立行为 (Internal Actions)**
   - **定义**：仅发生在系统内部缓存、持久层及大模型虚拟计算推演空间的动作。
   - **动作集**：提取长程记忆置入 Layer 0、发起心智社会 (Society of Mind) 多特工辩论、主动驱动反思引擎改写局部网络权重。
   - **特性**：无系统外环境物理污染、纯算力开销。
2. **外部交互行为 (External Actions)**
   - **定义**：向物理世界（或系统外部）输出实质影响、改变现实状态的终态行为。
   - **动作集**：通过 Shell 执行脚本命令行、调用 API 写库、输出对话气泡给人类使用者。
   - **特性**：极高操作风险，带有显著的不可逆破坏性副作用。

## 6. LLM集成方案

> **详细技术规格**：请参阅 👉 [《02-技术实现方案》](./02-技术实现方案.md)
> **L1-L5 完整定义**：请参阅 👉 [《05-能力演进体系》](./05-能力演进体系.md)

### 6.1 独特性分级与LLM分工

本系统采用**独特性分级**策略，将认知内容按通用度分为 5 级，与 LLM 形成有效分工：

| 级别 | 名称 | LLM覆盖 | 存储策略 | 处理方式 |
|------|------|---------|---------|---------|
| Level 0 | 人类共识 | 100% | 无需存储 | 直接使用LLM |
| Level 1 | 半通用知识 | 70-90% | 仅补充独特见解 | LLM + 个人视角 |
| Level 2 | 情境特定知识 | 30-60% | 完整存储 | 认知单元注入 + LLM推理 |
| Level 3 | 个人独有经历 | 10-30% | 完整存储 | 认知单元注入 + 类比推理 |
| Level 4 | 个人风格/价值观 | 0-20% | 完整存储 | 认知单元引导LLM生成 |

### 6.2 三种LLM结合模式

| 模式 | 适用类型 | 方式 | 效果 |
|------|---------|------|------|
| **认知单元注入** | Level 2-4 | 将相关认知单元注入LLM上下文 | 让LLM"临时拥有"被建模者的知识 |
| **认知单元引导** | judgment/strategy | 用判断原则和策略框架约束LLM输出 | 让LLM"按照被建模者的思维"生成 |
| **认知单元验证** | experience/intuition | 用个人案例验证LLM输出合理性 | 让LLM输出"符合个人经验" |

### 6.3 双系统结合模式 (System 1 & System 2)

| 系统 | 触发条件 | 认知资源 | 处理方式 | 效果 |
|------|---------|---------|---------|------|
| **System 1：快速直觉** | 高相似度、低复杂度 | 高权重 Intuition/Skill | LLM直接模式匹配 | "秒懂"反应，耗时短 |
| **System 2：慢速推演** | 矛盾/高风险/不确定 | 深层 Strategy/Judgment | 多心智沙盘辩论 | 缜密逻辑与上帝视角 |

## 7. 检索与注入机制

### 7.1 检索流程

```
┌─────────────────────────────────────────────────────────────────┐
│                    检索流程                                      │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Step 1: 向量检索（语义相似度）                                 │
│  ├── 输入：用户查询/任务描述                                   │
│  ├── 处理：向量化 → 相似度搜索                                 │
│  └── 输出：Top-K 候选认知单元                                  │
│                                                                 │
│  Step 2: 关系扩散（激活扩散）                                   │
│  ├── 输入：Top-K 候选单元                                      │
│  ├── 处理：沿关系网络扩散激活                                  │
│  └── 输出：扩展的认知单元集合                                  │
│                                                                 │
│  Step 3: 相关度排序                                             │
│  ├── 因素：语义相似度 + 激活强度 + 重要性 + 时效性             │
│  ├── 公式：Score = α·Sim + β·Act + γ·Imp + δ·Time             │
│  └── 输出：排序后的认知单元列表                                │
│                                                                 │
│  Step 4: 容量控制                                               │
│  ├── 原则：控制注入数量，避免上下文过载                        │
│  ├── 限制：总token数 < LLM上下文窗口的30%                      │
│  ├── 策略：按类型比例选择（各类型均衡）                        │
│  └── 输出：最终注入的认知单元列表                              │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

```
│  ├── 输出：生成性结果（个性化回答、建议、内容）                 │
│  ├── 成本：LLM 调用成本                                         │
│  └── 适用：进阶阶段、需要 AI 辅助的场景                         │
│                                                                 │
│  【渐进式使用路径】                                              │
│  阶段1: 独立存储 + 检索                                         │
│  ├── 开始记录认知单元                                           │

│  └── 生成时间线、人物图谱等                                     │
│          ↓                                                      │

│  ├── 对检索结果做总结                                           │

│  └── 成本开始增加                                               │
│          ↓                                                      │
│  阶段3: 完整 Agent 模式                                         │
│  ├── 认知单元注入 + LLM 推理                                    │
│  ├── 风格化输出、决策辅助                                       │
│  └── 高级能力（双系统、反思引擎）                               │
│                                                                 │
│  关键：三个阶段使用同一套数据结构，可平滑演进                    │
```

## 10. 终极演进与能力体系

面对由于大模型天然基于单体统计学概率而导致的“幻觉”、“逻辑短板”和“隐性知识流失”，本架构不再满足于传统 RAG 仅作为“外脑资料库”的定位，而是正式确立了从 **L1 到 L5 的专家智能体进化阶跃模型**。

通过在基础底座外挂 **双系统与反思引擎 (L2) -> 主动探针与无感监听 (L3) -> 多重子心智沙盘辩论 (L4) -> 底层超参自重写与跨域专家包融合 (L5)**，能够将智能体的专业还原度理论值从最初的 40% 暴力拔高至 100% 以上。
