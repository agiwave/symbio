# ST-002 · 工具调用与产物

前置：S01 ｜ **新增机制键 0** ｜ 参数变化 4 ｜ 阶段一

## 1. 场景：要什么能力

不只是"说话"，而是**动手**：调一次外部能力（搜索 / 计算 / 读文件），并把结果留成可追溯的产物。

相对 S01 高了什么：**输出从"一句话"变成"一个可被后续步骤引用的对象"**。这一步是 S03 多步任务的前提——
没有产物，多步之间就只能用自然语言传递中间结果，返工无从判定。

## 2. 为什么它能落在 v2 上（J1）

工具调用看上去像"新的一类东西"（很多架构会为它单开一个 Tool 子系统），拆开看只有三件事：

| 看起来新的东西 | 实际是 |
|---|---|
| 工具调用 | 一个 `Reasoner` 的一次 `progressed`，带了副作用 |
| 工具结果 | 一条 `artifact/asserted` 事件——**它是事实，不是特殊类型** |
| 工具清单 | 数据（`grants` 表里的一行），不是机制 |

**判据**：产物能被后续事件引用（`caused_by`）、能被投影过滤、能被审计——它完全符合"事件"的定义。
按 J1，能用已有元素表达的就是数据，不是机制。**新增机制键 = 0**。

## 3. 增量清单（只加数据）

| 类型 | 内容 |

| 事件格子 | `artifact/asserted`（`artifact.added`） |

**本阶点亮的机制键**（阶梯总表的「新增机制键」由这张块算出；`scripts/gen-verify-facts.mjs` 从这里取输入）：

```capability-assign

```

### 3.2 方向裁决：产物进不进上下文

**裁决（记于 [T-084](../task/T-084-ST-002产物投影方向对账批.md "T-084-ST-002产物投影方向对账批")）：取「进上下文」。**
§3 的增量行与 §6 相应断言按此表述，`capability-assign` 块的**形状**不动
（机读侧只取机制**键**集，`display` 那个取值不参与 `gen-verify-facts` 的判定）。

**依据三条，都是代码事实，不是偏好**：

1. **不给模型看，模型会重复干活。** `turn_runner.rs:948` 写得很直接——「模型必须看到
   『我请求了什么、拿到了什么』，否则会重复调用同一个工具」。工具交换不是外部信息，
   是模型**自己行为的记忆**；把它排除不是省 token，是让同一动作被重复发起。
2. **「不进上下文」从来不是缺机制，而是逐格取舍。** `TranscriptEntry` 上已有
   `exclude_from_context` 字段，且被用在别处：`message.opened` 的压缩记录节恒 `true`
   （它按定义是界面文本），轮边界汇报与对话面开场白带同一标记。产物格写的是 `false`
   ——是**决定**，不是**缺省**。
3. **产物闸的边界已经划清，且与本裁决一致。** `turn_runner.rs:951`：「闸管的是『入格』，
   不是『发生过』」——不持 `produce.artifact` 主体时这一格**不落**，但**结果照进 prompt**。
   把「是否入格」（授权面）与「模型是否看见」（表达面）分开，正是本裁决站得住的原因。

**对齐「言 / 行」两维的读数口径**（`[PL-002](../plan/PL-002-能力坐标系.md "PL-002-能力坐标系")` §2）：
产物属**行**（工具、执行、副作用）；喂回模型的上下文属**言**的表达面。二者不冲突——
进上下文的那份不是「外部输入」，而是「行」在「言」上的**自我回声**。
反过来把它排除，行在言的输入面上就失忆了：那不是省 token，是同一动作重复发起。

> **本裁决买断的是什么**：它**只**决定产物（工具结果）是否进 prompt，
> 不决定**别的**格进不进（那些仍逐格判 `exclude_from_context`），也不决定产物大小怎么截断
> （那是各工具自己的回执口径，见工具 schema）。若将来出现「某个工具回执过大」，
> 处置是**该工具**截断，不是把整族逐出上下文。

**§6 验收断言的执行方**：1 = `turn_runner.test.rs:1728,1783` + e2e t2/t26；2 = `tool_executor.test.rs:1017-1030`；3 = `invariants::unresolved_turns/budget_exceeded`（`invariants/mod.rs:268/314`）+ `docs/plan/verify/budget.rs`；4 = `invariants/mod.test.rs:166,200` + `verify/invariants.rs` 反例档。

**名册 S02 行**：工具接入→锚 `capability/mod.rs` 生产在用 ✓（`CapabilityCategory` 是**分类标签**）；副作用分级→锚 `breaker.rs`（批首判据：授权走 `matrix_for`、已耗走 `cost_ledger`，未授权即 `Refuse`——「分级」的落点在这里，不在分类标签）；幂等与重试→「—」（事实有 `store/mod.rs:106 AppendError::Duplicate`，名册未锚）；执行隔离→「—」（最近似 = WAL 写者令牌 `store/wal.rs`）。

## 4. 平凡值与回退（J2）

| 参数 | 完整值 | **平凡值** | 平凡值下 |
|---|---|---|---|
| `actor.capability` | `produce.artifact` | **`reply.append`** | 仍完整运行——只用文字描述结果，不留产物 |
| `projection` | `transcript`（产物 tool 行） | `turnstate` | 仍完整运行——模型看不到跨轮工具记忆，退化成「每轮重新交代」；不会崩，但会重复调用工具 |

**注意平凡值不是"关掉功能"**：退回 `reply.append` 后系统照样能对话、照样能完成 S01 的闭环，
只是产物不再可被引用 → S03 的返工判定会退化，但**不会崩**。这就是"平凡值下系统完整运行"的含义。

## 5. 静默失效与强制（J3）

| 约束 | 违反时信号 | 强制方式 |
|---|---|---|
| 产物必须带 `caused_by` | **无** | I2 断言 |
| 未授权主体不得产生产物 | **无**（只是多了一条事件） | 写侧 `grants_of` 编译期强制 |
| 工具超时必须有产出 | **无**——静默超时 | I3 断言（`budget.rs` 的 `Yield` 判据：`Silent` 变体即违规） |

## 6. 验收断言

1. 一次工具调用 → 恰好一条 `artifact.added`，`caused_by` 指向发起它的 `task/turn`。
2. 未授权主体尝试写入 → 编译期或运行时拒绝，**且不产生事件**。
3. 工具超时 → 必须产出 fallback 事件，不允许静默。
4. **反向用例**：构造一条 `produced_by` 为空的 `artifact.added` → 断言 1 必须失败。
5. **工具交换必须进上下文**（§3.2 裁决的落点）：一轮里发生过工具调用时，下一次请求的
   messages 里有配对的 `tool` 消息，且 `id` 与请求里的 `tool_calls` 一致、内容是真实
   回执——**模型看不见就重复调用**，这是断言 1 的另一半（事件在格 ≠ 模型看得见）。
   **反向用例**：把该格 `exclude_from_context` 翻成 `true` → 断言 5 必须失败。

**§6 验收断言的执行方**：1 = `turn_runner.test.rs:1728,1783` + e2e t2/t26；2 = `tool_executor.test.rs:1017-1030`；3 = `invariants::unresolved_turns/budget_exceeded`（`invariants/mod.rs:268/314`）+ `docs/plan/verify/budget.rs`；4 = `invariants/mod.test.rs:166,200` + `verify/invariants.rs` 反例档；**5 = e2e `t27`（审批恢复后同轮续写，工具交换不丢）+ `t55`（多轮工具的跨轮记忆）+ `t59`（工具面契约）+ `t46`（prompt 形状基线逐字段比）**。
