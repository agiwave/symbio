# ST-008 · 多主体与对等承诺

前置：S07 ｜ **新增机制键 2**（`principal`、`vis_scope`）｜ 参数变化 5 ｜ 阶段二→三

## 1. 场景：要什么能力

多个主体（子智能体 / 对等智能体 / 人）同时存在，各自有身份、权限、可见域；
彼此之间能**立约**（承诺交付什么、何时交付），违约可被观测，声誉可被计算。

相对 S07 高了什么：**从"一个大脑分身"到"多个独立主体"**。
T4 的定义是"能分工"，T5 是"分工之间有可追责的契约"。

## 2. 为什么它能落在 v2 上（J1）

多主体最容易被做成"第二套架构"（很多系统为 Agent 通信单开一层协议）。在 v2 里：

| 看起来新的东西 | 实际是 |
|---|---|
| 主体 | `principal` —— **字符串 ID，数据，可无限增长** |
| 隔离 | `vis_scope`（`thread_private` / `shared` / `public`）+ grants 表 |
| 通信 | **没有直连**——一切经事实源（I1 的直接推论） |
| 立约 | `commitment` 实体的一格事件 |
| 声誉 | 一个投影（`projection = reputation`） |

**关键**：本阶是**递归是树、协作是图**的分界。子智能体递归（`scope = child`）只能表达树，
覆盖不了对等协作的图——所以才需要 `commitment` 实体加格子。**加格子，不加机制。**

## 3. 增量清单（只加数据）

| 类型 | 内容 |
|---|---|
| 事件格子 | `commitment/opened`（`commitment.offered`）、`commitment/closed`（`commitment.released`、`commitment.broken`）、`commitment/asserted`（`commitment.asserted`） |
| 新参数键 | **`principal`**、**`vis_scope`** —— 本阶两个新增机制键 |
| ActorSpec 行 | 对等体 `{ principal: "agent:peer-b", pattern: translator, capabilities: [ProduceArtifact], budget_ms: 30000, scope: root }` |
| grants 行 | 每个主体一行；**读写成对**（`grants_of` + `sees_of`，缺一不可） |
| 投影参数 | `projection = reputation` |

**本阶点亮的机制键**（阶梯总表的「新增机制键」由这张块算出；`scripts/gen-verify-facts.mjs` 从这里取输入）：

```capability-assign
event.entity = commitment
principal = agent:peer-b
vis_scope = thread_private
projection = reputation
actor.pattern = translator
```

## 4. 平凡值与回退（J2）

| 参数 | 完整值 | **平凡值** | 平凡值下 |
|---|---|---|---|
| `principal` | `agent:peer-b` | **`agent:main`** | 仍完整运行——所有 ActorSpec 同一身份，退化成单主体 |
| `vis_scope` | `thread_private` | `public` | 仍完整运行——无隔离，退化成一个共享大脑 |

**两个平凡值合起来 = S07 的状态**。所以本阶是可整阶跳过的，且跳过不破坏任何低阶能力。

## 5. 静默失效与强制（J3）

| 约束 | 违反时信号 | 强制方式 |
|---|---|---|
| 权限与可见域 | **无**——违反时没有任何测试会失败 | **必须第零天就位**（[PL-001 §7](../plan/PL-001-核心架构.md "PL-001-核心架构")）：事后补要重写所有历史事件 |
| 任意两主体无直连 | **无** | 静态扫描 + CI 断言 |
| 读写授权必须成对 | **无**——只有读侧 = 能给自己授权看一切 | 编译期成对检查 |

> 权限是**静默失效**的典型：它违反时系统照常跑，只是"越权了"。
> 这是三条不变量之外最该做成 CI 断言的一条。

## 6. 验收断言

1. 两个不同 `principal` 的事件在对方 `vis_scope` 之外互不可见。
2. 静态扫描：代码中不存在主体到主体的直接调用（只有 Store）。
3. 只有写侧授权的主体 → 授权检查必须拒绝（成对性）。
4. **反向用例**：把 `vis_scope` 改成 `public` → 断言 1 必须失败（证明可见域参数在生效）。

## 8. 这一阶做不了什么

- 承诺的**履行质量**不由架构保证——`commitment` 只记录"立了约、是否违约"，不保证"守约"
- 声誉算法是打分函数，架构只提供 `reputation` 投影这个位置
- 组织形态（层级 / 市场 / 混合）是 S13 的事，本阶只有点对点协作
