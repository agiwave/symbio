## 决策

`symbio_core` 不设 `schemas/` 目录。跨端契约词按「它描述什么」住进对应域：
会话线格式归 `chat`、对话面控制契约归 `dialog`、宿主呈现方言归 `present`、
轮次面归 `turn`、插件扩展点归 `plugin`、模型状态帧归 `llm`、事件→状态的读侧重放
归 `projection`。

判据有两条：

1. **一个名字要能自证归属**。「schema」等于「暂时没处放」：同一个目录里住着四种
   互不相干的东西——会话线格式、判决契约、宿主呈现方言、轮次交付包，它们的消费方、
   依赖方向、变更理由都不同。加一个前端呈现字段要改 `detail.rs`（模块名读作「详情」，
   却装着机制层的行载荷）；`llm` 的端口入参写 `schemas::session::chat_node::ChatNode`，
   读者要跳两层才知道这是「会话消息」还是「模型入参」。
2. **命名纪律必须覆盖到契约词**。整域登记一条「协议词」豁免的后果是：N-001
   （符号带域前缀）在本层最大的一块代码上不执行。分域之后每个符号都落在某域登记的
   前缀里，判据由 `core-naming-audit` 机械核对。

### §1 归属表（零改名）

| 契约 | 住哪 | 判据（一句话） | 公开面形态 |
|---|---|---|---|
| 会话线格式：一条消息 / 一个主体长什么样 | `chat/` | 线格式，只说形状与解析，不含机制 | 叶子模块（`chat_node` · `principal` · `chat_request` · `session_chat`） |
| 对话面控制契约（`Verdict` / `DecideRequest` / `ComposeRequest` / `WordingReply` / `RunSnapshot`） | `dialog/` | 判决是枚举、措辞是文本 | 根平铺符号 |
| 宿主呈现方言（`Detail*` / `Reading*`） | `present/` | 下发描述、前端零业务知识渲染 | 根平铺符号 |
| 轮次面：怎么交付、怎么造节点、产出什么记录 | `turn/` | 同时看见 `llm` 与 `chat` 的装配面 | 交付包平铺；`facts` / `node_build` 叶子模块 |
| 插件扩展点（`HookEvent` / `HookOutput`）与路由回体（`SimpleResponse` / `SuccessResponse`） | `plugin/` | 插件面的东西归插件域 | 根平铺（契约词） |
| 模型状态帧（`llm_emit_message` 等） | `llm/frames.rs` | 与发射口同一族 | 根平铺（`llm_*`） |
| 事件 → 节点树的读侧重放（`rebuild`） | `projection/rebuild.rs` | 纯函数视图 | 根平铺（`rebuild`） |

**零改名**：标识符一个不动。这些名字已被前端镜像、e2e 快照与 40 余处 `use` 钉住；
搬家的目的是让**归属**可读，不是让协议漂移。带域前缀的只有域自己的词（`Detail*` /
`Reading*` / `Verdict` …），它们作为该域登记的前缀写进 README §1.2，于是
「前缀落在所属域登记的前缀里」第一次覆盖到契约词。

### §2 依赖形状由数据流决定

```text
chat  ◄──  llm  ◄──  turn  ◄──  projection
```

三条边唯一地确定了这个形状：

```text
llm/model_provider::execute_turn(messages: &[ChatNode])   →  llm 依赖 chat
turn/node_build 消费 TurnToolCallInfo（llm）、产出 ChatNode   →  turn 依赖 llm + chat
turn/dispatch 交出 Arc<dyn ModelProvider>                 →  turn 依赖 llm
```

`node_build` 若放进 `chat`，`chat` 就要 `TurnToolCallInfo`，与 `llm → chat` 合成环。
**归属判据**：想知道一个类型该去哪，先问「它需要看见 llm 吗」——需要就是 `turn`，
不需要但需要看见 `chat` 就是 `llm`，都不需要就是 `chat`。

### §3 机制只向下依赖词汇（实测 11 处）

拆域让「谁依赖谁」在代码里可见。本层机制模块引用契约词的 `use` 共 11 处，方向全部向下：

| 机制模块 | 依赖的词汇 | 处数 | 判定 |
|---|---|---|---|
| `capability/row.rs` | `present::DetailField` | 1 | 向下：表单字段本来就是呈现物，表的机制不理解字段语义 |
| `llm` / `adapters` / `exec` / `projection` | `chat_node::{ChatNode, NodeStatus, MessageContent, NodeRole}` | 10 | 向下：一次模型请求的入参就是消息，`ChatNode` 是本系统唯一的消息形状 |

反向边（`chat → llm`、`present → capability`）在依赖图上立刻成环，看得见也拦得住：
`core-vocab-audit` 的 V-002 按环族做基线棘轮，新增一族即红。

### §4 不建 `contracts` 地址空间

把插件 id、路由、事件名、UI 方言整体搬进 `symbio_core::contracts::{…}`，再用
「非 contracts 模块不得 `use contracts`」把方向钉死——这条方案不采用：

1. **它用一层新地址换掉一条本来就能看见的边**：分域之后「谁依赖谁」由目录与
   README §1.2 表达清楚，再加一层 `contracts` 只会让同一个符号有两个合法写法
   （`symbio_core::X` 还是 `symbio_core::contracts::X`）。
2. **判据不闭合**：`plugin` 域的 `ROUTE_*` 被 `plugin` 自己的 `hook.rs` 使用，
   搬进 `contracts` 后要么破例（`plugin → contracts`）、要么把路由词拆成两半。
3. **收益可忽略**：加一个插件只是改 `plugin/ids.rs` 一行，`contracts` 不改变这一步的代价。

**根出口宽度**是另一件事：`pub use` 的符号数由 C-003 棘轮逐格判「有没有 core 外
消费方」，不需要新地址空间。

### §5 判据

| # | 判据 | 命令 | 现状 |
|---|---|---|---|
| 1 | `symbio_core/schemas/` 不存在 | `test ! -d crates/symbio-core/src/schemas` | ✓ |
| 2 | 命名审计覆盖 25 域，无整域豁免 | `node scripts/core-naming-audit.mjs` | ✓ N-001…N-005 全绿 |
| 3 | core 内无 `schemas::` 引用 | `rg "schemas::" crates/symbio-core/src` | ✓ 0 |
| 4 | 域间依赖不新增环（2 族在基线里，只许降） | `node scripts/core-vocab-audit.mjs` | ✓ 2 族 |
| 5 | 根出口无深引（叶子模块之外） | `node scripts/core-export-audit.mjs` | ✓ C-001/C-002 绿 |

**反向自检**：把 `node_build` 一类文件搬回 `chat/` 会造成 `chat → llm` 环。编译器
**不会**报（Rust 允许模块互相引用），报的是 `core-vocab-audit` 的 V-002（Tarjan 强
连通分量）：新增一族环即红。§2 的表是人工判据，V-002 是它的机械兜底。

### §6 不做的三件事

| 不做 | 理由 |
|---|---|
| 给契约词改名 | 跨栈镜像（前端字段名）+ 40 余处引用；收益是「更短」，代价是快照与协议漂移 |
| 把 `ChatNode` 换成 `PromptMessage` 作为 `ModelProvider` 入参 | `PromptMessage` 缺图片 / 工具调用过程 / 节点身份；换掉要么复制字段（两份形状），要么让 provider 无法实现（`provider_adapter` 在 core） |
| 把叶子模块平铺进根 | 节点家族 40 余个名字，平铺会把根出口撑宽一倍，且调用点失去「这是线格式」的自证 |
