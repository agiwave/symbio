## 决策

**背景**：[DE-012](../005-arch/010-session-input-addressing.md "DE-012-会话输入与地址") §5.5 计划退役
`session/chat/send` / `session/chat/abort` 两条路由（输入面双轨：inbox 地址写入 vs 两条全局路由），
§5.6 记下了它的**前置条件**——地址写入面「表达不了本次运行的选项」，而 `agent_run` 必须携带
`provider_id`，故**「地址写入要不要承载运行选项」是一次协议决定**，
[D-031](031.md) 明文「需要自己的 ADR，不顺手发明」。本条就是那次决定。

三条事实（逐条对代码核过）：

1. **三个选项在契约里已经有会话 metadata 回退。**
   `plugins/session/orchestrator/entry.rs::resolve_session_params` 对
   `mode` / `risk_level` / `provider_id` 是**三条完全对称**的解析链：
   `req 字段 > session.metadata > 默认值`（`auto` / `medium` / `none`）。
   （`session_chat::Request` 的字段文档为 `mode` / `risk_level` 写明了这条回退，
   `provider_id` 那一条只写了「为 None 时使用默认 Provider」——**文档落后于代码**，本条一并订正。）
2. **它们描述的是「这个会话怎么跑」，不是「这一条消息说了什么」。**
   `provider_id` = 这个会话用哪个 provider；`mode` = 这个会话是无人值守还是交互；
   `risk_level` = 这个会话的执行风险阈值。三者描述的都是**会话级事实**，与消息内容无关。
   （注意这与「只能写会话」是两件事：解析链的第一档 `req` 今天仍在，它是**调用级覆盖**。
   本条要定的是**地址写入**这一档——它既不是调用，也不是会话，而是「一条消息的写体」。）

`cli/src/client.rs` **显式携带全部三项**（`provider_id` / `mode` / `risk_level`），
注释写明意图是「**即便会话元数据被外部改写，本次发送依然生效**」，即刻意走 `req` 档做
**调用级覆盖**。这个意图成立，但寄托点不是**消息写体**：覆盖由「选项变过就先写会话
metadata」（`ensure_session` upsert，`options_dirty`）表达——它仍然在下一次发送前生效，
落点是会话而不是消息。

3. **四个调用方逐个核对，没有一个需要「地址写入带选项」**：

   | 调用方 | 要带什么 | 为什么不需要协议变宽 |
   |---|---|---|
   | `agent/host/subagent.rs` | `provider_id` / `mode` / `risk_level`（`subagent.rs:346-349`，显式继承父会话的值） | 它是唯一**不能**进程内入队的写者（不持有子会话的插件实例），但它**已经在写子会话 metadata**（`register_subsession`，同一个 `ctx`）——把这三项加进那份 json 即可 |
   | `session/heartbeat/mod.rs` | `include_history`、`mode: "auto"` | 改走**进程内**直连入队（`self.enqueue_inbox`，`PATH` 无读者）；`include_history` 是**本次发送**的属性，留在 `Request` 里，不经地址写入 |
   | `plugins/telegram/plugin.rs` | `mode: "auto"` | 「无人值守通道」是**通道/会话**属性 ⇒ 会话 metadata |
   | `cli/src/client.rs` | **全部三项**，且刻意走 `req` 档做调用级覆盖（见上文订正） | 覆盖意图保留，落点改为会话 metadata：`switch_provider` 置脏、下一次 `ask` 先 `ensure_session` upsert 再入队。一次「开着 REPL 连切几次」只落最后一次 |

**决策**：

1. **地址写入不承载运行选项。** inbox 写入面的形状**一字不动**：`parse_inbox_message` 仍然
   只产一条 `ChatNode`，「以 `{` 开头」仍是**唯一**的判别式。
2. **运行选项按它描述的事实归属**：`provider_id` / `mode` / `risk_level` 写进**会话 metadata**
   （解析链的第二档已经在那儿），**地址写入这一档不带它们**；`include_history` 留在 `Request`
   （它是本次发送的属性），它唯一的非默认调用方（心跳）走进程内入队，不经协议。
   `req` 档**继续存在**：它是调用级覆盖，服务 resume（`mode` / `risk_level`）与进程内入队
   （`include_history`）。本条删掉的是**消息写体**那一档，不是调用档。
3. **DE-012 §5.6 的退役前置条件解除**：§5.5 的两条路由**不再需要**协议变宽就能退役。
4. **`session_chat::Request` 的字段集不动**——三个字段继续存在（resume 分支与进程内入队仍在用），
   退役的是**两条路由**，不是结构体。

**理由**：

1. **问题的实质不是「写入面缺一个字段」，而是「一个会话级事实被放进了消息的写体」。**
   把 `params` 塞进地址写入，等于让一条消息携带「这个会话用哪个 provider」——同一件事有了两个
   owner（写体里的这一次 / 会话 metadata 里的那一次），而 GO-000「一个事实只有一个 owner」
   正是双轨期带病运行的那条叙事。
2. **判别式从一条变两条，是把既有纪律在同一个函数里推翻。** `parse_inbox_message` 的文档明确写：
   判据取「以 `{` 开头」而**不是**「能不能解析成 JSON」，正是为了不让一个手滑的 `{content}`
   被静默当成正文发出去。加第二层形状嗅探（「有没有 `message` 键」）会让那条纪律失效。
3. **解析链已经对称，删掉它的一半是倒退。** `req > metadata > 默认` 三条链对称；
   本条的论证正建立在「第二档存在」上，故它同时是一条**不变量**（见下）。
4. **退役的收益是「一个事实一个 owner」，成本必须低于它。** 变宽协议面来退役协议面，
   是拿一个缺口换另一个缺口。

**被否决的方案**：

- **包裹形状**（`{"message": {…}, "params": {…}}`，靠「有没有 `message` 键」兼容裸 `ChatNode`）：
  否决。见理由 1 / 2：形状嗅探 + 会话属性进消息写体。
- **平级保留键**（`{"content": …, "params": {…}}`）：否决。`params` 会变成 `ChatNode`
  字段子集里的保留键，而 `ChatNode` 不认识它——要么静默丢弃（写方以为生效了），
  要么给 `ChatNode` 加一个它不该有的字段。
- **把 `include_history` 也搬进会话 metadata**：否决。它确实是**本次发送**的属性
  （「这一趟不带历史」）；搬进会话会让「下次带不带」变成有状态的，而它今天无状态且只有一个调用方。
- **新增一条「地址写入专用」的载荷类型**：否决。那是造第二条协议面，而问题的实质是
  「选项不属于这次写入」——协议面不该为一件放错地方的事实让路。
- **保持双轨（不退役）**：否决。[D-031](031.md) 自记这是「有意留下的残余」，
  T-077 是它的清偿任务；本条解除了它的前置条件，没有理由继续留着。

**后果与不变量**：

- **本次不动任何生产代码**：地址写入面、`parse_inbox_message`、`session_chat::Request`、
  两条路由都不动。本条是**决策**，落地是 [T-077](../009-task/077-输入面双轨退役批.md "T-077-输入面双轨退役批") 步②。
- **不变量（本条的论证前提）**：`resolve_session_params` 的三条解析链必须保持对称
  （`req > metadata > 默认`）。若将来某一条链被删掉「metadata」这一档，本条的前提失效——
  那时要重新裁决，而不是默默沿用本条的结论。
- **不变量（协议面）**：inbox 写入面的判别式**恒为一条**（以 `{` 开头）。任何「加一个键来
  承载非消息语义」的改动都撞本条。
- **DE-012 §5.6 的状态**从「⚠️ 前置条件」改为「已裁决（[D-066](066.md)）」；
  §8.2 的第 1 项改判为「前置条件已解除，待 T-077 步② 执行」。
  **（已执行：T-077 步②落地，§8.2 第 1 项现已勾掉。本条的 `impl` 字段随之改为 `done`。）**
