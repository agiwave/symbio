# D-119：执行体的声明面与动作面分家

## 背景

[DE-015](../004-plan/016-义务环.md "DE-015-义务环") §2.3 的 `ActorDecl` 草图把六样东西
写进同一个结构体，其中一栏是：

```rust
run: fn(&Debt, &ActorCtx) -> BoxFuture<'static, Result<Vec<Fact>, ActorError>>,
```

同一篇方案 §2.6 契约 1 要求 `drive` 持 `&mut Session`——执行体在一步里**借**轮内草稿
（本轮消息、节点、成本、步号），跑完还要把草稿留在派发器里接着走下一步。

这两条在类型层面互斥，不是"实现困难"：

1. `BoxFuture<'static>` 意味着 future **拥有**它需要的全部东西。借来草稿的 future
   带一条非 `'static` 寿命，塞不进 `'static` 盒子。
2. 想同时写两条寿命也不行：`dyn Future + 'a + 'b` 是非法类型（rustc E0226，
   trait 对象只允许**一条**显式寿命上界）。草图那个 `'static` 不是可以放宽的保守选择，
   是这条路本来就没有第二个位置。
3. 机制层拼不出这个签名：`symbio_core` 里没有 `Fact` 类型，也没有 `ActorCtx`——
   草稿、七个端口、`Vec<Fact>` 账本的形状都是**部署事实**（哪个插件、哪种模型适配器、
   哪套会话字段）。把它们抬进 core 才能让 `run` 进 core，那是拿机制面去付实现面的账，
   撞 `08 §0 纪律 3`（core 的形状质量高于任何单个插件）。

[[D-118|D-118]] 订正 1 已裁决 `drive` 的 `accept` 谓词退役、未接线行显式
`by = None`。退役之后「一个 `by` 一个动作」必须仍在**构造上**成立——这正是本条要定的
形状：动作放在哪里、由谁保证它和声明不脱节。

## 决策

1. **`ActorDecl` 只有四样静态可查的字段，住机制层。**
   `name` / `mode` / `reads` / `writes`。它是装载期三道检查的输入面（§3.4 的 ⑤ 写入封闭、
   ⑥ 执行体收口、⑦ 声明事实有归宿）加时延闸门；这四样都不需要知道草稿长什么样。
2. **`run` 不是 `ActorDecl` 的字段。** 可调用面住在注册它的那个部署里，与声明**同批**
   构造：`plugins::loop::turn_exec::ACTORS` 是 `ActorEntry { decl, run }` 的静态表，
   `decl` 就是第 1 条那个结构体的同一个常量。
   动作的界面是 `for<'a> fn(&'a mut TurnStep<'a>) -> StepFuture<'a>`——一条寿命，
   借的就是 `TurnStep`（方案里的 `ActorCtx`：本轮草稿 + 七个端口），future 只要求
   `Send`（插件的 `dispatch` 要交回线程池）。
3. **机制层因此不持有任何可执行的东西。** core 只回答「这行欠什么、谁该来还、
   他能不能关上它」；「怎么还」在插件。`drive` 的签名停在纯
   `(rows, frozen, events, now)`（D-118 订正 1），执行体的选择权不经它。
4. **「能选中」⇔「有人跑」由两个方向同时保证，而不是由求解器加过滤条件**：
   - 行指向的 `by` 没有声明 ⇒ `Gap::UnmannedRow` ⇒ 装载红；
   - 声明了的执行体没有行指向它 ⇒ `Gap::OrphanActor` ⇒ 装载红。

   派发器拿到的 `Next` 直接带**动作本体**（不是名字，不是再查一次的句柄），它对 `by`
   只有一个动作 `(next.action)(&mut step)`；按行名 / 端口名分支的那处
   `Executor::for_by` 名字 match 已随之删除。绑定表查不到时按「没有可还的债」显形，
   不猜动作。
5. **执行体仍然不是裸函数**——方案 §2.3 那句主张不因分家而削弱：一个名字要变成动作，
   必须先有带 `mode` / `reads` / `writes` 的声明，且两侧都被装载期对账。裸函数指针
   进不了这张表。

## 理由

| # | 依据 | 本裁决做了什么 |
|---|---|---|
| 1 | DE-015 §2.6 契约 1：`drive` 持 `&mut Session` | 承认草稿是**借**的，动作寿命跟着它，不假装 `'static` |
| 2 | rustc E0226：trait 对象只允许一条显式寿命上界 | 草图无法在类型上成立，改动落在草图上而不是落回旧形状 |
| 3 | `08 §0 纪律 3` / D-055：core 的形状是机制面 | `Fact` / `ActorCtx` 不被抬进 core，机制层不加宽 |
| 4 | DE-015 §2.3「执行体不是裸函数」 | 用双向装载检查（决策 4）替掉求解器侧的第四个过滤条件 |
| 5 | D-118 决策 2：派发器不按业务语义分支 | 派发点只剩一次函数调用，名字 match 退役 |

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 照抄草图：`run` 进 core 的 `ActorDecl`，返回 `BoxFuture<'static, Result<Vec<Fact>, ActorError>>` | 与 §2.6 契约 1 互斥（E0226 堵死两条寿命并存）；要成立就得把 `Fact`、`ActorCtx` 抬进 core，core 为付插件的账而变宽 |
| 把草稿塞进 `Arc` 让 future 真 `'static` | 草稿的可变推进（步号、成本、寄存批次）变成跨 `Arc` 的共享可变状态，`&mut Session` 契约 1 被绕开而不是满足 |
| 保留 `accept` 谓词，让注册表在选债面过滤 | D-118 订正 1 已裁决退役：那是给纯求解器加第四个未声明条件，还把「`by = Some` 却无人可跑」永久合法化 |
| `Next` 只带行名，派发器自己按名查表 | 派发器要重新知道有哪些名字——正是决策 5 要消掉的那处分支 |
| 把整张 `ACTORS`（含 `run`）搬进 core | 机制层从此持有可执行体与端口形状，CS-001 的三格之外多出一条没人数的加宽 |

## 后果

- **实现面**：`symbio_core::decl` 新增 `ActorDecl` + `Builder::actor` + `Frozen::actor/actors`；
  `builtin()` 变成 `builtin_with(&[ActorDecl])`（声明表与执行体注册表一起冻结）。
  `ring::check_rows` 新增四格缺口（`UnmannedRow` / `OrphanActor` / `ActorCannotClose` /
  `ActorModeTooNarrow`）。插件侧 `turn_exec` 长出 `TurnStep` / `Action` / `run_execute`，
  `loop_rows` 长出 `ACTORS` / `action_of` 与带动作的 `Next`。
- **PTS-003 基线**：`drive` 字节变了（`accept` 参数退场），`owed` 没变——同批更新指纹，
  理由挂 D-118 订正 1 与本条决策 3。
- **留下的债（不在本条范围）**：`run` 的**值返回**形状 `Result<Vec<Fact>, ActorError>`
  与「`Err` ⇒ 引擎写 `failed`」还没接——现网动作仍自己经 store 落格、返回 `Option<TurnOutcome>`。
  账本语义的收编（D-118 订正 2 已把它从偏离项改为待落地）连同判据 14 的
  「执行体返回空事实」用例，归 [T-249 · 执行体值返回账本](../009-task/249-执行体值返回账本.md "T-249-执行体值返回账本")。
- **代价**：动作与声明分居两处，靠「同一个常量的两次引用 + 双向装载检查」绑住。
  新增执行体必须同批改 `ACTORS` 与行表，漏一侧装载即红——这是设计意图，不是摩擦。
- **不改变**：`owed` 的字节与输入闭包、行表 `prio`、协议名闭集、端口载荷形状、
  停机判据的归属（D-118 决策 7）。
