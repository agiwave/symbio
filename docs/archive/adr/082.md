## 决策

**背景**：[D-081](081.md "D-081") 把批次 6 分成了 6a（P4 收敛，已落地）与 6b（真切片），
并把 6b 的判据钉成卸载形——停用 ⇒ 不再开新一轮、在飞的轮在有限时间内收敛、存储侧读写照常。
前置读数的实测结论：成片清单（驱动器片 ≈14,352 行 + resume 647 待裁）、出口两面（provider 臂与
收件箱消费者的两处 `start_turn`）、入边九组反向引用。六个问题留给本裁决：装配形状、
留守侧拿「开跑一轮」的接线、九组反向引用归属、`Convergence` 物理落点、`io.rs` 豁免处置、
守卫用例形状。六个一起答。

**裁决一：装配形状 = 独立插件 `plugins/loop`。**

判据决定形状：卸载形的「停用 ⇒ 不开新轮」要能被**运行期表达**，而「停用」的既有机器只有一种
粒度——插件（装配期不构造 ⇒ 路由 `NotFound` ⇒ 消费方按「缺插件」处理，`assembly/mod.rs` 文档
原话；批次 2b 已用它验过心跳）。「驱动器留在 session 内做编译期分层」给不出这个动作：停用
session 连存储面一起失去，「存储侧读写照常」这条断言直接不可达。且落点不是新发明——
DE-014 §5 步 6 原文就写着 `session`(存储+生命周期) / `loop`(驱动器)；
T-167 出口判据「卸载它之后 session 只剩存储与生命周期」也只有独立片才配得上。
`loop` 进 `ASSEMBLY_SUB_AGENT_PLUGINS`（与 session 同批入列，子 Agent 树分形各得一份），
构造注册照 `submit_object_creator!` 先例；本片能力行仍 0，但贡献 **1 条 Mount 行**（裁决二的
起始地址）⇒ 它同时落入 T-167 出口 ② 的卸载判据形式（不再纯依赖方向形——Mount 行就是它的
「该片能力行在下一轮收集里消失」断言对象）。

**裁决二：两个方向的接线各走各的既定机制——触发（session→loop）走地址面，服务
（loop→session）走 core 端口，词表走 core。**
（本条「服务 = core 端口」半已由 [D-083](083.md "D-083") **废除**——触发臂与
留守消费者原样成立；服务的通货改为闭族既有词汇 + P5 运行态归源。）

- **触发 = 地址面**。loop 注册自己的 VDFS provider（一条新根，根名与载荷形状落地批登记进
  ROUTES），两个入口各改成一次地址面写：`plugin/vdfs_provider.rs:525` 的恢复臂在 session 侧
  **再派发**（公开地址不动——前端仍写会话地址，避免把 D-066 的退役单轨改成第二次公开面变更）；
  `transcript/inbox.rs:617` 的收件箱消费者写 loop 起始地址。写是**同步回包**的（心跳先例：
  失败 ⇒ `Conflict` ⇒ 不入队），忙碌拒绝那条线格式随载荷原样迁移——provider 臂的
  「忙碌时明确回绝」是 UI 可见契约，不可破。消费者**留守**：收件箱队列 owner 在存储
  （D-081 裁决三「到达归存储」），loop 停用期间消息继续入队、恢复后照常抽干。
- **服务 = 两个 core trait，形状照 `ModelProvider`（DE-008）**：
  ① `TurnHost`——由留守侧的 `Convergence` 实现（它就是为此存在的收敛半身）：句柄工厂三臂、
  sink 落一帧、broadcast 运行态、consume 清在途、store 读写、配置与目录快照、收件箱取批与变更通知；
  ② 会话句柄端口——`PersistentChatSession` 的方法面（驱动器现用 12 个：`session_id` /
  `session_dir` / `get_messages` / `replace_all` / `persisted` / `context_window` / `cfg_or_default` /
  `delegating_principal` / `parent_session_id` / `list_sub_sessions` / `load_sub_session` /
  `skill_compile_enabled` / `skill_fast_path`；19 处 `.apply` 是投影 apply，**不在**句柄面）。**面 = 迁移既有调用，不新增能力**；`SESSION_HANDLE` 的 ctx 值随端口类型改
  （`ChatSessionHandle` 已是现成载体）。`chat_session.rs:26`「不设 ChatSession trait（唯一实现
  即本结构体）」的旧判词随本裁决反转：切片之后端口有了第二个消费方（跨插件的 loop），
  单实现多态的判断前提不在了。
- E-009（插件互不可见，测试同样判）把「不经端口碰存储」从纪律措辞变成编译事实——
  P3/P4 这条链的最终执行方。

**裁决四：`Convergence` 归位的物理落点 = 留守层顶层。** 它与 `chat_session` / `active` / `store`
同级（6a 裁决已登记归属，随 6b 换目录兑现）；`orchestrator.rs` 底座 238 行随两侧拆分
（词表部分按裁决三第 8 组）。提前换目录不等于卸载能力那条旧理由不再适用——切片就在这批。

**裁决五：`io.rs` 豁免到期 = 废除豁免条目、回退改经端口，契约原样保留。** D-081 把豁免期限
钉在 6b，兑现方式是：缺句柄回退构造（「交付失败 ⇒ 降级内存会话、不阻断对话」）作为
`TurnHost` 句柄工厂的既有 ephemeral 臂留在留守侧，io.rs 调用那一下即可——它今天调的本来
就是 `PersistentChatSession::detached` 的同款构造。**豁免名册归零**，不是废除契约而是契约换载体。

**裁决六：守卫用例 = composite 真实挂载 + 停用 loop，三条断言一条不少。** 形状照批次 2b 先例
（工厂 id + 真实 `mount_all`）：① 停用 ⇒ 写 loop 起始地址 `NotFound`，provider 臂与消费者按
「缺插件」处理、**不再开新一轮**（消息继续入队不丢）；② 在飞的轮在有限时间内收敛——spawned
任务持端口 `Arc` 克隆，`Convergence` 的存储格子比插件活得久（3c-1 设计的这半），看门狗与 abort
路径不动；③ 存储侧读写照常（`list` / `stat` / 读转写 / 写收件箱全绿）。②的「有限时间」断言
若受 1800s 看门狗牵制，用例以注入短时限实现——机制不动，只加测试可注的既有配置面。

**否决的替代方案**：

- **同插件编译期分层**（不独立、判据降回纯依赖方向形）：被否——卸载形不可表达（见裁决一），
  且 DE-014 §5 步 6 原文与 T-167 出口的最强形态都以独立片为准。
- **消费者迁 loop + resume 统一入收件箱队列**：被否——resume 若排队，运行中会被 2f 补充合并
  吸进当前轮（答复语义丢失），而「忙碌同步拒绝」是 UI 可见契约；改契约不是切片的副产品，
  是另开的行为变更。
- **`TurnStarter` 服务端口（session 缓存 loop 的 `Arc`）/ 每派发跑一次收集取行**：被否——
  缓存的 `Arc` 停用不失效（陈旧服务继续开轮 = 判据 ① 的反例），每派发再收集等于每条消息
  双份 traverse；且「持兄弟插件的具体对象」正是 P2 清零、downcast 那条形态的新皮。
- **公开面直改**（前端/CLI 直接写 loop 地址）：被否——D-066 刚把 chat/send 退役单轨到会话
  地址，公开面第二次改形要前端、CLI、e2e 三处重对，代价由全体消费方付；session 侧再派发
  把变更封在插件内部。
- **把 Policy 行入表 / Registry 消失混进 6b**：被否——那是 DE-014 的「注册即事实」收尾小步
  （§5 步 4 收尾注）的账，一刀只服务一条判据；6b 切片不需要策略行也能被卸载形判完。

**后果与分刀**（每刀门禁全绿独立提交，同批次 3/4 先例）：

- **6b-① 词表上移**（行为不变）：节点构造族 + `request_principal` + 四个事实记录类型 +
  跨端口记录词汇进 core；判据 = 九组反向引用的 1/2/3/4/5/6/7 组清零（留守/宿主文件不再
  `use` 驱动器侧符号）。CS-001 只加数据不加口（0 个 trait）。
- **6b-② 端口成形**——**已由 [D-083](083.md "D-083") 再推导改立为 P5「运行态归源」**，
  以下原文仅存史：`TurnHost` + 句柄端口立进 core（Convergence 实现之），
  驱动器侧对 `chat_session` / `active` / `store` / `config` / `paths` / `types` 的具体类型触点
  全部改经端口；判据 = 驱动器文件 grep `use super::super::{chat_session, active, store}` 归零。
  **CS-002 变宽在此**：`pub trait` 18→20（+2 口），基线行挂本裁决；方法总数按落地实测补
  allow 注（面 = 迁移，不新增）。
- **6b-③ 成片搬家**：驱动器文件整体迁 `plugins/loop/`（外壳 = build + Mount provider +
  `stop`），`ASSEMBLY_SUB_AGENT_PLUGINS` 加 `"loop"`；两入口改地址面写、恢复臂再派发；
  `Convergence` 按裁决四归位留守顶层。判据 = E-009 全绿 + `cargo check` 依赖方向成立。
- **6b-④ 守卫用例**（裁决六三条断言）+ 棘轮对账（RE-006 的 Mount 行 +1、session 常驻任务
  仍 1、loop 常驻 0——消费者在留守侧）+ 文档随批（`017-module-layout.md` 双插件化、
  ROUTES 登记新地址）。
- [D-081](081.md "D-081") 的豁免名册条目到期关闭（裁决五兑现）；T-167 只剩
  出口 ③ 的收尾对账；DE-014 剩「注册即事实」收尾小步与 §9.3 对齐宣告。

## 订正：端口面的收窄口径

> 本节经 [D-083](083.md "D-083") 自上而下复核——第 1 条的 trait 半与第 2/3/5 条
> **废除**（裁决对象是端口面，面废 ⇒ 条废），第 4 条与末段「统一通货」**成立并升级为机制裁决**；
> 本节保留论证（其判断全部被 D-083 的 P5 吸收为约束）。

裁决二把「面 = 迁移既有调用」直接照抄了留守层的**类型面**，收窄它的两条判据是——
**后端端口不得以前端契约为通货**（`Session` / `SessionSummary` 是落库读型、`ChatNode` 的
显示形状是前端机制；后端真源是 WAL 事实格，端口若搬这些记录类型等于把前端契约钉成后端协议），
以及**实现词汇不进 core**（config / paths / types 各自住自己的域，拆分后本就不必共享）。
由此定下五条，判据问题本身（六问）不变：

1. **进 core 的只有两样**：两个 trait（`TurnHost`、会话句柄端口）+ 两个纯值记录
   （`WorkerProgress`、`DrainedSupplement`，并入**既有** `turn::facts`，不新开模块）。
   `SessionConfig`、`paths`、`types::{Session, SessionSummary}` **一律不上移**——
   6b-① 已上移的词表不动，此判据只约束 ② 之后的账。
2. **句柄端口面 = 语义方法，不搬枚举**：`MessageChange` / `Carrier` 留守写路径
   （`chat_session::write`），过墙拆为四个语义写方法（`add_by_runner` / `add_here` /
   `edit_nodes` / `remove_nodes`）——owner 判定由方法名承担，「拿不准选 Here」的不对称代价
   论证随实现留在原位。`cfg_or_default` **不过墙**：配置值经标量 getter 过墙
   （`context_window` / `skill_compile_enabled` / `skill_fast_path` 及驱动器实际读的字段组），
   「锁被占回落默认」的语义随 getter 保留；驱动器读不到 `SessionConfig` 这个类型。
3. **广播口 = TurnHost 语义方法**：`SessionStateChange` 与 `OUTCOME_*` 留守，过墙拆为
   `mark_working` / `finish_turn(outcome, error)` / `set_warning` 三个方法；
   `completed()` / `aborted()` 的唯一构造点纪律留在 session 侧（outcome 以 `&'static str`
   传值，不是类型过墙）。
4. **会话记录不过墙，进展整链留守**：端口读侧只交 `Vec<ChatNode>`（`get_messages` /
   `get_context_messages`）、写侧只收 `Vec<ChatNode>`——loop 本就是帧的生产方，`ChatNode`
   是 core 既有词汇；`Session` / `SessionSummary` 不出现在任何端口签名里
   （`chat_session` 的 metadata 触点走 `serde_json::Value`）。`worker_progress` 的存储侧
   多步编排（枚举 + 加载 + 归属复核 + WAL 主读 / v1 回落）按 D-081 裁决一第 4 条
   **整体留守 session**，驱动器经 `TurnHost::sub_session_progress` 一处调用取
   `Vec<WorkerProgress>`。目录快照同理：TurnHost 返回 `PathBuf` 方法
   （会话 WAL 路径 / 工具归档目录等），`paths` 类型不过墙。
5. **裁决五照原样兑现**：`io.rs` 豁免废除，缺句柄回退走 `TurnHost::open_session_handle`
   的 ephemeral 臂，契约（降级内存会话、不阻断对话）原样。

CS-002 的账：`pub trait` 仍 +2；方法成员数按实测补 allow 行
（`core-shape-allow <格>: D-082 <理由>`），「面 = 迁移既有调用，不新增能力」的判据不变。

**统一通货（第二条判据）**：会话引擎的跨插件契约**只走 WAL 事件轨**——
`EventWalStore`（及其 `WalStore` / `Store` 机制、`Seq`、信封类型）与同源**投影**
（`transcript` / `turnstate` 与后续具名投影）就是那唯一通货；**不补一个 "SessionState"
式聚合类型上墙，也不把 EventWalStore 下沉 session**。判据三条：

- **状态是投影的折叠值，不配做通货**——聚合一旦上墙就是「两条引擎各自 fold」的第二真相，
  D-054 终结的正是这个东西；读答案是「取哪个投影」的问题，投影与信封本就同族住 core。
- **下沉 EventWalStore 会制造碎片而非消除它**：core 的投影机制消费它的 snapshot 类型
  （D-062 冻过的泛型写入口，拆开要重造输入面）；驱动器独立成插件后本就是事实的生产方
  与读方——下沉等于逼每一个事实读方经留守层开一个专属 getter，「契约到处都是」恰由此起。
  实测口径：根导出的 WAL 词汇 core 内由投影 / 事件域消费（C-003 第二口径的真共享机制）。
- v2 纲领（D-049「读侧逐点切到事实源」）的目的地就是事件轨；把事件轨钉成唯一跨插件
  协议是顺势，不是新面。

由此三处改判：① 驱动器侧的 WAL 触点（`turn_exec` 写事实、`tools/tool_executor` 的
breaker 计数与 elimination 扫描）**保持直用事件轨**（core 信封 + EventWalStore + 具名投影），
端口不复制这条轨；留守侧的多步链（`worker_progress` 的「枚举 + 归属复核 + 双读法」）不受此影响，
仍走单入口。② **磁盘布局词汇不跨墙**：`paths` 的目录命名与 `V2_WAL_FILE` 从驱动器触点消失，
TurnHost 只交已解析的 `PathBuf`（本会话 WAL 路径 / 工具归档目录 / 全量会话 WAL 清单）。
（本条按 [DE-014 §2.2](../004-plan/014-单环一表收敛.md "DE-014-单环一表")
「体系接口唯一化」**作废**——交 `PathBuf` 只消了名字，存储模式仍随派发包跨墙，而机制层
