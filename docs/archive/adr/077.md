## 决策

**背景**：[D-076](076.md "D-076") 把心跳裁成两件事并逐口定了归属，2a 已把落格与参数推导搬进
`transcript/autonomous.rs`；那条末尾留下一道没答的题——**「标记词汇表进不进 core 由 2b 的切片落点
决定」，而那个落点本身是新的形状裁决**。本 ADR 就答这一题：调度半（间隔 / 抖动 / 空闲基线 / 常驻循环 /
设置工具 / 选项族那一行）住在哪。判它不进施工批顺手定，是因为它同时决定三件架构事实：**卸载单位的
有无**、**core 公开面变不变宽**、**`meta.trigger` 这条标记有几个 owner**。

**读数口径**（实测，全部到行）：

- **装配以「根下一层目录」为单位**：`dir_names`（`plugins/composite/registry.rs:230`）只对插件根
  `read_dir` 一层；`install`（:426）/ `uninstall`（:458）/ `set_enabled`（:376）的参数都是**名字**，
  而那个名字同时是工厂 id = 目录名 = 挂载名 = 实例名（:420-421 自述）；`mount_child`（:276）是
  **私有**的，除 `mount_all` / `install` / `set_enabled(启用)` 三条外无人能挂东西。
- **消费单位归一到同一层**：`unitOf`（`scripts/core-surface.mjs:228`）把 `symbio/src/plugins/<名>/…`
  折成 `plugins/<名>`，core 自身**不算**消费方（`collectConsumers`，:417），`isSelfReference`（:245）
  只对 `PLUGIN_ID_*` / `EMBEDDING_*` 且 slug 同名放行；C-003（`core-export-audit.mjs`）判的是**占公开面**
  的根导出（`collectCoreSurface` 只认 `pub use` 行，`core-surface.mjs:72`）——**≥2 个消费单位**，基线只降。
- **地址面已给得出片需要的全部数据**：`vdfs/list` 的会话项带 `status`（由
  `SessionRuntime::from_state(inner.is_working, …)` 投影，`plugins/session/plugin/vdfs_provider.rs:1039-1054`，
  读不到锁时**保守报 working**，见 :1051）+ `updated_at` + `attributes.metadata`
  （`plugin/nodes.rs:137-152`）；`write(<会话>)` 的覆盖分支就是 metadata 的**键级浅合并**
  （`commands.rs:157-166` → `Session::merge_metadata_object`，`types.rs:172-185`）；
  `write(<会话>/inbox)` 已在（D-076 #4）。

**裁决一：调度半落成一层的插件目录 `symbio/src/plugins/heartbeat/`，工厂 id 与注册 id 都是
`heartbeat`，进 `ASSEMBLY_SUB_AGENT_PLUGINS`。** 三条理由各自独立，任何一条单独都不必然推出这个
落点，合起来别的位置都不成立：

1. **它要有卸载单位。** D-075 给 P3 的判据是「被切的那片不再 `use super::` 宿主的私有项」，而它
   的运行期形态是「停用它 ⇒ 少的是这一个功能，不是整个界面」——执行这句话的是容器注册表的四个动词，
   它们**只认一层目录名**。留在 `plugins/session/heartbeat/` 的那半**没有可停用的单位**：唯一的停用
   对象是 session 整体，而「停用一个装着会话存储的插件」少掉的显然不是心跳这一个功能。判据要能被判，
   落点就必须是判据认的那种东西。
2. **它要给出第二个消费单位，词汇表才谈得上「共享」。** 见上面读数第二条：写标记的一方（调度半）与
   识别标记的一方（收件箱写臂）若同在 `plugins/session/`，`unitOf` 算出的是**同一个**单位 ⇒ 这套词汇
   就不是跨插件的共享词汇，它**应当**是那个插件的私有常量；而切片之后两侧分属两个插件，字典若住在
   任何一个里，另一个就得复述字面量——正是 D-076 数出的那条漂移口径（`meta` 是自由 JSON，键名拼错
   编译器管不到）。落点是一层新目录 ⇒ producer 在 `plugins/heartbeat`、consumer 在 `plugins/session`，
   两个单位成立 ⇒ 词汇表升 core 才名副其实（升的是**位置**，形态见裁决二）。
   **这就是「落点随这一题的答案走」的答案。**
3. **分形不劣化。** `ASSEMBLY_SUB_AGENT_PLUGINS`（`symbio_core/assembly/mod.rs`）逐项进每一棵子树，
   今天每个 `SessionPlugin` 实例自己跑一条心跳循环；切片后每棵子树各有一个 `heartbeat` 实例、各跑
   一条，**循环条数与今天相等**。清单多一行是这张表设计好的加法（`assembly` 域文档：「在列 ≠
   不可卸载」，`classify` / `compose` 是先例）。

**在列的准确含义**：进清单 ⇒ 自动补 `PLUGIN.yml`（`ensure_required`，`registry.rs:179-184`）且
**可停用不可删除**（`uninstall` 对必需插件直接拒绝，:459-462）。因此 D-076 守卫段说的「运行期
卸载该片」，可执行形态是**停用**（`Action(disable)` ⇒ `stop(Disabled)`），不是删目录——这与那条判据
的立意一致：它问的是「少的是不是这一个功能」，而功能确实在运行期消失。

**裁决二：标记词汇表进 core，形态是两条常量 + 一条 `pub(crate)` 根别名，落在 `event` 域。**

- `EVENT_TRIGGER_META_KEY: &str = "trigger"`（写体 `meta` 的键名）与
  `EVENT_TRIGGER_KIND_SCHEDULED: &str = "scheduled"`（`kind` 取值）。命名按 `event` 域的前缀规则
  （`symbio_core/README.md` §1.2：该域常量为 `EVENT_`），PN 判据据前缀认域，不另开例外。
- **出根的形态跟着同族先例走，不占公开面**：两条以 `pub(crate) use` 挂在**自主层事件名字表**那条根
  别名块旁（`symbio_core/mod.rs` 的 `EVENT_SYSTEM_TRIGGERED` 一族——任务格名字表同款，它的消费方
  也全在 crate 内）。而它们**必须在 core** 的理由有两条，各管一条常量：`kind` 的取值同时被 core 自己
  的 `system.triggered` 载荷用着（`actors/autonomic.rs:35`），插件里的常量 core 引不到；键名的两侧
  分属两个插件（裁决一第 2 条），住在任何一侧都要另一侧复述字面量。**字典不能住在任何一侧，就在中间。**
- 同批把 `symbio_core/actors/autonomic.rs:35` 那条 `"scheduled"` 字面量改成引用
  `EVENT_TRIGGER_KIND_SCHEDULED`。这不是顺手：那个字面量与本常量今天**值相同、来源不同**，正是
  「两处各写一遍」的现场；升格之后 `system.triggered` 的载荷 kind 与写体声明的 kind 由同一个名字说话。
- 形状账：零 trait、零 `fn` 成员 ⇒ CS-001 三格（18 / 56 / 18）不动；`PLUGIN_ID_HEARTBEAT` 占公开面，
  走 `isSelfReference` 豁免（单单位、slug 同名），与既有 19 条插件 id 常量同形；两条标记常量走
  `pub(crate)` ⇒ 不在公开面上，C-003 的基线（单消费方 58 / 0 消费方 0 / 仅测试在用 7）与
  [SP-027](../008-spec/027.md "SP-027") 的账本都不动；机制键零新增（DE-001 §8 审的是那 10 条，
  常量不在其列）。

**裁决三：片对世界只说三句话，且都走地址面。** `list(<会话根>)` 取清单（一次拿到 `status` /
`updated_at` / `metadata`，即 D-076 的 #1 + #2）、`write(<会话>/inbox)` 开一轮（#4）、
`write(<会话>)` 存设置（#8）。它不持有 `Weak<SessionPlugin>`（今天 `tools/heartbeat_tool.rs:31`），
不认识事实源，也不认识 `active_mgr`。

- **请求体的形状（对 D-076 #4 那句「`VdfsContext::empty()` 够用」的口径修正，必须点名）**：实测在
  **经容器转发**的场合不成立。`CompositeVdfs::dispatch` 第一件事是 `children_of(ctx)`
  （`plugins/composite/vdfs.rs:487`），而 `children_of` 先 `vdfs_host_ctx(ctx)?`（:143），该函数是
  `ctx.require::<Arc<dyn PluginInvokeRequest>>()`（`symbio_core/vdfs/host.rs:75-77`）——
  `VdfsContext::empty()` 的宿主是 `()`（:64-67），走容器视图当场失败。片的形状因此是**每轮扫描合成
  一个请求体**（`PluginSimpleRequest::new(None, None)`，先例：`init.rs:11` 用它作系统树的构建 ctx、
  `plugins/session/options/mod.rs` 用它造选项定义）再 `vdfs_context(&req)` 包成 `VdfsContext`；
  取 provider 那一跳照子智能体的形状（`plugins/agent/host/subagent.rs:360-395`：
  `parent.clone().get_vfs_provider()` + `vdfs_context(&ctx)` + `dispatch`）。这不是绕路：`empty()`
  表达的是「无宿主态」，而经容器取数**需要**一个宿主态来承载本轮的访客表（`CONFIGURABLE_VISITOR`
  就存在宿主上，`composite/vdfs.rs:149-153`）——这里要声明的是「我这个后台读者没有前端会话」，
  不是「我不需要宿主」。父句柄按 session 同款存 `Weak<dyn Plugin>`、逐 tick `upgrade`（E-007 禁的是
  **强**引用持有兄弟实例，`get_parent` 的形态即 `plugins/session/plugin.rs:419-421`）。
- **设置工具要两跳**：`get` / `set` 的部分更新语义要沿用旧值，故先 `stat(<会话>)` 读
  `attributes.metadata.heartbeat`，再 `write(<会话>)` 带 `{metadata:{heartbeat:{…}}}`——浅合并按**键**
  替换，`heartbeat` 整块换掉，与今天 `write_back` 逐字同义。校验（下限 10 秒、prompt 非空）留在工具里，
  那是设置的判据不是存储的。
- **选项行经表贡献，零新机制**：Option 行本来就是表里的一行（行名 = `field.key`，
  `symbio_core/capability/row.rs`），任何插件 `traverse` 都能 put；会话的选项定义是**收集期汇流**的
  结果（`session_schema()` → `collect_options`），因此心跳插件 put 的那一行原样出现在会话 schema 里，
  而它的保存动作走的是**前端已在用的同一条写通道**。副作用即守卫的后半：停用 `heartbeat` ⇒ 下一轮
  收集里那一行不在，会话选项栏少一格，其余照旧。
- **写体的两片 `meta` 各归各的消费者**：`meta.trigger` 由写臂**就地消费**（D-076 标记落法），
  `meta.heartbeat = true` 仍随消息下发给前端做展示区分。两片不必合成一个——它们的消费点不同，
  而「这次触发是不是自主的」由事实源那四格说话，不由消息上的布尔说话（`heartbeat/mod.rs` 现有说明）。

## 否决的替代方案

- **留在 `plugins/session/heartbeat/`，只把 Tool 行与 Option 行搬进新文件**：裁决一的第 1、2 两条
  同时不成立——没有可停用的单位（判据无法被执行），两个消费方算同一个单位（常量一辈子进不了 core）。
  而 D-075 的判据当场不成立：`active_mgr` / `storage_dir` / `heartbeat_state` 全在原地。
- **在 session 里造「子插件」概念（一层目录以下的挂载单位）**：那是**新机制**——要新词汇（挂载层级）、
  新生命周期（子插件的启停归谁）、新装配路径（`mount_child` 现在只被那三条用过）。DE-014 的守恒律审的
  正是这类「为一次方便加一条机制」；而它换来的能力与「一层目录」完全等价，判据反而更难守（两处能停用
  插件，两处要和收集期对账）。
- **给宿主加端口 trait（`record_trigger`）**、**改走路由臂**、**新增 VDFS 动词**：三条都已在
  [D-076](076.md "D-076") 的否决段判过（CS-001 只降不升 / 双轨刚收成单轨 / 动词是闭集而
  「请开一轮」在地址面上的名字就是写收件箱），本 ADR 不重开。
- **把调度半并进 `gateway` 或某个已有插件**：卸载单位确实有（一层目录），但那片要的是「随会话树分形、
  每个智能体各跑一条」的语义；`gateway` 是外部 API 入口，语义不同。把不相关的两件事挂同一个 id，
  停用时少掉的就不是「一个功能」——判据的粒度当场废掉。
- **常量留在插件内、两边各写字面量**：见裁决一第 2 条。同一条纪律在本仓的现行表述在
  `plugins/session/transcript/supplements.rs:47`。
- **缓存会话清单来省掉每 tick 的广播**：见后果第 4 条——那会造出第二份 `metadata.heartbeat` 副本，
  正是 D-076 #5 要避免的「同一事实两个 owner」。

## 后果

- **施工清单（T-167 的 2b 一批做完，行为不变）**：
  - core：`PLUGIN_ID_HEARTBEAT`（`plugin::ids`，随 `pub use plugin::{…}` 出根）；两条标记常量进
    `event`，以 `pub(crate) use` 挂在自主层事件名字表那条根别名块旁；`actors/autonomic.rs` 改引用；
    `ASSEMBLY_SUB_AGENT_PLUGINS` 加 `"heartbeat"`。
  - 新目录：`plugins/heartbeat/`（`mod.rs` / `plugin.rs` / 调度 / 设置工具 / 选项行 + `README.md` +
    就地 `*.test.rs`），`plugins/mod.rs` 加 `mod heartbeat;`（私有，E-009 的前提）。E-001 要求
    `PluginMeta::new` 首参 == 目录名；常驻循环的启动点同 session（`build` 里 `Handle::try_current()`
    + `handle.spawn`——`Plugin::start` 是**同步**钩子，D-033，起不了 task）。停机沿用 P1 的
    `stop_gate` / 句柄形状（`plugins/session/plugin/resident.rs`），本片只有一条循环。
  - session 侧删除：`heartbeat/` 整目录、`tools/heartbeat_tool.rs`（连同其 test 与 `tools.rs` 门面行）、
    `options` 里心跳三函数与 `ORDER_HEARTBEAT` / `DEFAULT_HEARTBEAT_INTERVAL`、`heartbeat_state`
    字段与初始化、`mark_activity` 及其调用点（`orchestrator/entry.rs`）、`start_resident_tasks`
    少一条 spawn。
  - **开轮的入口不变，变的只是谁来调**：`request_autonomous_round` 是存储所有者的写窗口纪律
    （D-076 裁决一），不搬；`meta.trigger` 的识别落在 `plugin/vdfs_provider.rs` 的收件箱 Write 臂
    （那里已经读了一遍会话存在性，返回值今天被丢掉，改成留下那份绑定 ⇒ #5 的推导零额外读盘），
    落格失败 ⇒ `VdfsError::Conflict`、不入队（失败落在队列之外，`transcript/autonomous.rs` 模块头）。
  - 守卫两处（受 E-009 约束，跨插件的判据不许靠 import 兄弟模块）：`plugins/heartbeat` 自己的测试钉
    本片形状（`traverse` put 两行 + `stop` ⇒ 句柄 `is_finished()`）；容器侧在 `composite` 的测试里经
    **工厂 id / `mount_all`**（不 import 兄弟模块）钉「运行期停用 ⇒ Tool 行与 Option 行的 `heartbeat`
    都不在、其余行仍在、session 侧 list / write 照常」。
- **棘轮跟着动，且是有名有姓的预期变动**：session 的常驻任务从 2 条变 1 条（心跳扫描出去、收件箱
  消费者留下）⇒ `plugins/session/plugin.test.rs:477` 的 `assert_eq!(resident_tasks.len(), 2,
  "心跳扫描 + 收件箱消费者")` 改成 1 并同步那句说明。这是**判据变了所以断言变**（合理预期的变化 ⇒
  基线可下调），不是放宽判据，更不是删断言。
- **段名 `inbox` 会是第三份本地常量**：`plugins/session/plugin/nodes.rs:391`（`pub(crate)`，机制层
  正主）、`plugins/agent/host/subagent.rs:75`、`plugins/telegram/turn.rs:71`——后两条的写法已在
  `telegram/turn.rs:67-70` 写明理由（「机制层的 `SEG_INBOX` 是 session 插件的内部词汇、插件间不可见」）。
  本片照此办理，**这不是新漂移，而是 E-009 那条规则的既有代价**。真要收成一处，收法是把它升进
  `symbio_core::vdfs` 的词汇表（`words.rs` 那一族），那是独立一题，不垫在这一条里。
- **每 tick 的成本要认，并且这次不做优化**：一次扫描 = `list(<会话根>)` 一次，而 session 根清单会算
  一遍 `session_schema()`（全项目 options 广播 + agent 目录扫描，`plugin/vdfs_provider.rs:90`；那条
  代价是它自己在 :104-106 写明并认下的），外加容器 `children_of` 的逐子插件广播（:142-169）。
  合计**两次广播 / 15 秒**，量级与前端点一次会话列表相同。裁决是**接受并命名**：真要省，省法是给
  `list` 加一条「不要 schema」的调用级参数（窗口参数 `limit` / `before` 已有先例，`nodes.rs` 的
  `window_params` ⇒ 不是新机制），那是独立一批。
- **#7 的空闲锚点随片走，`mark_activity` 消除**：`idle_baseline` 的 `max(锚点, updated_at)` 语义不变，
  锚点从宿主的 `HashMap` 变成片自己的调度状态。代价与 D-076 后果量化的一致（零写盘退出 ⇒ 基线回落 ⇒
  多触发一轮）；切片后唯一相关的事实是 `updated_at` 由写臂那一次入队前的写维持，片不再需要宿主替它
  记活动。
