# D-111：消息读数由交付出口装配——口径回到产者，前端只排版

## 背景

一条压缩节点在界面上要交代「压到哪儿了、什么触发的、压掉几条」。这四个数字后端早就给了
（`context/pipeline.rs::compression_stats` 落进 `meta`），但**把它们说成人话的那套口径住在前端**：

| 前端持有的口径 | 为什么它是后端的 |
|---|---|
| 压缩统计（`messageCompactionStats`：读五个 `meta` 键） | 键名与口径由写方定，前端注释只能写「与后端一致」——**复述即漂移** |
| 记忆统计（`messageMemoryStats`：`post_tokens` / `transcript_path` ⇒ 「已转存」） | 「路径存在即为已归档」是对**产物的判定**，不是排版选择 |
| 触发词表（`threshold`→自动整理 / `tool`→模型主动 / `retry`→手动重试） | 取值集合是后端的协议词，前端那份是抄本 |
| token 格式化（`128000`→`128k`） | 同一个数字两处格式化，早晚不一致（[T-208](../009-task/208-消息域读数参数化批.md "T-208-消息域读数参数化批") 点名的正是这一条） |

[D-070](070.md) §决策 2 的顶层字段表里 `stats` 那一格**从未落地**——它当时设想的是轮骨架的
token 统计，而真正需要读数的是两个折叠叶。本条 ADR 把它兑现，并修正它的携带范围。

## 决策

1. **读数片段复用既有呈现域形状**：`ReadingSection { title?, rows[] }`，行 =
   `ReadingRow { label, value, hint?, tone }`（`symbio_core::present::reading`，
   前端镜像在 `tauri/src/schemas/reading.ts`，跨栈字段名由 `protocol-mirror-audit` D 组看守）。
   **不新增投影、不新增 core 导出、不给任何 trait 加成员**——[D-070](070.md) §决策 2 说的
   「值由产者排版」在这里逐字沿用：`value` 是**已排好版的字符串**（含单位），前端不做任何数值格式化。
2. **它挂在 `ChatNode.stats` 顶层**（`Option<ReadingSection>`，`skip_serializing_if`）。
   判据照 [D-070](070.md) §决策 2 那一问：前端**不看 `meta` 语义**能不能消费它？能——渲染器只做
   「有行就逐行排版」，一个业务词都不认 ⇒ 该进顶层（G 组要求它有直接消费者，
   `NoticeNode.vue` 读 `node.stats`，不经 `meta`）。
   **携带范围修正**：不是「只 Skeleton 携带」，而是**由携带读数的节点携带**——今天两个产者
   都是折叠叶（压缩动作 / 压缩产物），骨架上没有只读数。
3. **装配点在交付出口，不在写入路径**。会话把节点交给前端的**三处出口**
   （转写列表、会话叶子读、实时帧投递）统一走一个函数
   `plugins/session/stats_reading.rs::present_message`：先做 core 的形状派生
   （`title`/`icon`/`actions`，[D-070](070.md) §决策 3 / T-155 B3 的既有机制），再补 `stats`。
   ⇒ **存储与事件里的节点永远不含 `stats`**：呈现不是事实，改一次文案不必迁移一份历史。
4. **存量零迁移**：`stats` 从节点**已有的 `meta` 数字**现算，老会话的压缩节点重新读到就带行。
   这条是本裁决选择「出口装配」而不是「写时落格」的决定性理由——后者要么给存量做迁移，
   要么让历史消息显示不出读数，要么把文案抄本永久封在存储里。
5. **`meta` 的数字留在 `meta`**（它们是事实：e2e 与后端判定读它们），但**前端不再读**，
   于是 `protocol-mirror-audit` H 组白名单删掉这七条登记
   （`compact_trigger` / `context_limit` / `before_tokens` / `after_tokens` / `dropped` /
   `post_tokens` / `transcript_path`）。登记面**收窄**，不是新增契约。
6. **行序与文案前端零参与**：压缩动作给「压缩后水位 / 当前水位（缺后值时）」「上限」「触发」「压掉 N 条」，
   压缩产物给「压缩后水位」「完整历史 已转存」（只在转存路径非空时给）。
   任一数字缺失 ⇒ 那一行**不出**（不是出「0」）：编一个 0 会显示成「水位已降到 0」，
   而失败路径根本没有可信的压缩后水位——`compression_stats` 的注释早就写明了这条谎报判据。
7. **VDFS 目录清单不带 `stats`**（`message_node` 只给寻址与预览，与它同样不给 `title`/`icon` 的
   口径一致）：清单不是交互出口，读数只在**渲染消息**的那三条路上出现。

## 理由

- **口径的 owner 是拿着数的那一方**。`context/pipeline.rs` 的文档注释里写着水位口径
  （「内容水位，不含请求级固定开销 ⇒ 与上限相除是下限」），前端那份是**第二处复述**——
  后端改口径，前端不会红，只会静静显示旧标签（这正是 `present/reading.rs` 模块文档立的理由）。
- **呈现装配在出口已有先例并被守卫接受**：`title`/`icon`/`actions` 走的就是「交付前按形状现算」，
  本条只是把同一手法用于第四类呈现数据；不新增机制，也不新增接缝。
- **不动 core 形状**：CS-001 钉的是 `pub trait` 数 / `fn` 成员总数 / 默认体数，
  `ChatNode` 的**结构体字段**不在其中；派生逻辑落在会话插件（域内），core 只多一个数据格。

## 代价与被否掉的方案

- **每帧一次小 JSON 构造**（出口现算，不缓存）。换来的是「改文案不动历史、存量照常可读」，
  一次折叠叶的读数最多四行，成本可忽略。
- **否决：写时把 `stats` 落进消息节点**。封死文案演进、且存量要么迁移要么显示不出来。
- **否决：新增一个 `MessageStats` 专用结构**。`ReadingSection` 已经在两侧镜像并被 D 组看守，
  再造一个形状等于给同一个概念第二个名字（[D-070](070.md) §决策 3 反对的正是换名）。
- **否决：让前端继续读 `meta`、只把格式化搬后端**。那留下三处抄本（键名、触发词表、
  「路径存在即已归档」），H 组白名单还得一直供着七个键。
- **不做**：`meta` 键名生成化（H 组注释里点名的那条根治）。本裁决把这七键的前端读点**清零**，
  漂移面从两处变零处；剩下的是后端内部词汇，不需要跨栈契约。

## 兑现位置

- 后端：`symbio_core/chat/chat_node.rs`（`stats` 字段）、`plugins/session/stats_reading.rs`
  （`present_message` / `notice_stats_of` / `format_tokens`）、三个交付出口的调用点改写。
- 前端：`tauri/src/schemas/chat_node.ts`（`stats?: ReadingSection`）、
  `tauri/src/components/message/NoticeNode.vue`（逐行排版）、
  `tauri/src/stores/sessions.ts`（帧合并「有则覆盖」）、
  `tauri/src/registry/messageTypes.ts`（四条口径删除）。
- 守卫：H 组白名单收窄七条；D 组 `ChatNode` 对增一格。
