## 决策

[T-171-keys域环拆解](../009-task/171-keys域环拆解.md "T-171-keys域环拆解") 把
`core-vocab-audit`（V-002）基线里最大的一族八域连环（`capability⇄chat⇄event_bus⇄exec⇄keys⇄llm⇄plugin⇄present⇄vdfs`）
拆到消失。三条决策，各自独立生效：

1. **键定义搬到值所在的域**（根因一）。`keys` 域 8 个「值类型指向上层域」的键
   （16 个符号）整体外迁：`CAPABILITY_VISITOR` / `OPTION_VISITOR` /
   `CONFIGURABLE_VISITOR` / `CAPABILITY_ERRORS` → `capability`；`EVENT_SINK` /
   `ABORT_SIGNAL` → `exec`；`PLUGIN_PARENT` / `PLUGIN_DIR` → `plugin`。
   `keys/mod.rs` 从此只剩字符串键 + `CONFIG`（`Value`）+ `REQUIRED_PLUGINS`
   （`Vec<String>`）与 `SymbioKey` 机制本身，**对上层域的引用数 = 0**。
   根平铺重导出保持调用点名字不变（`PARENT` 改名 `PLUGIN_PARENT`，见代价 2），
   core 内外消费方近零改动。
2. **`PluginError::Aborted` 收成无载荷变体**（根因二）。半截产出改由 loop 插件
   **私有退出类型**携带（`Vec<ChatNode>`，生产方与消费方都在 loop，两侧编译期
   可见）。`plugin→chat` 这条硬边随之消失。
3. **`vdfs_change_of` 搬到 `event_bus` 域**（第三刀，原任务漏算的一条）。
   函数连同其三则信封测试一并搬迁，改名 `event_bus_vdfs_change_of`。
   `vdfs→plugin` 与 `vdfs→event_bus` 两条边同时消失。

三刀之后 `keys` 成为**汇点**（只入不出：入边 `plugin` / `capability` / `exec`，
出边 0），`vdfs` 也成为汇点（入边 `chat` / `capability` / `plugin` / `present` /
`event_bus`，出边 0）。八域族解散为 DAG，V-002 基线从 2 族降到 1 族
（`adapters⇄projection` 不动——它的拆法见该基线条目自带的说明）。

## 背景

V-002 的基线注释把最大的一族描述成「万能胶型的环，不是拆分错误」——那句
**只对了一半**：环确实由 `keys` 的键值类型触发，但「拆不动」的结论是错的。
拆不动的假象来自两个未竟的勘察：

- 只看到 `keys→{capability,plugin}` 两条硬边，没看到**键与值同住**这个早已
  存在的先例——`TURN_DISPATCH` 一直住在 `turn` 域（值 `Arc<TurnDispatch>`
  是 turn 自己的类型）。「实例一律定义在本域」这条写在 `keys/mod.rs` 的规则
  早有例外，只是没人把它立为通则。
- 只列了两条根因，没看到第三族：拆完 `plugin→chat` 与 `keys→*` 之后，
  `event_bus⇄plugin⇄present⇄vdfs` 仍在环里——`vdfs/change.rs` 的
  `vdfs_change_of` 同时引用 `PluginFrame`（plugin 域）与
  `EVENT_BUS_KIND_VDFS`（event_bus 域），是那一族的最短路径。

SCC 模拟（同口径复刻 `core-vocab-audit` 的边 + Tarjan，含外迁新增的回指边）
确认：三刀之后只剩 `adapters⇄projection`；少任何一刀，族数不降。

## 为什么键可以搬去值所在的域（本条要裁的那件事）

`keys/mod.rs` 的原规则是「实例一律定义在本域……机制与它的键分家」
（`capability/error.rs` 只放读写函数，桶的键 `CAPABILITY_ERRORS` 住 keys）。
该规则让 `keys` 为装一个 `Arc<dyn Registry>` 而**认识 `Registry`**——依赖方向
就此倒立：被依赖的域（capability）反过来要依赖万能胶（keys）的键常量。

**键的两半（类型 + 实例）与值类型同住才是一份数据。** 值在哪个域，键就在哪个
域；`keys` 域的职责收缩为「键机制」（`SymbioKey` trait、`ctx` 查找、字符串键），
不再是「所有键的名册」。这与 `TURN_DISPATCH` 既有的形状一致，也与
「契约词按它描述什么分域」（D-087）同源。

**为什么不走全通道 `Arc<dyn Any>` 擦除**（T-171 原稿的首选拆法）：上下文键的
立身之本是**类型安全**——`ctx.get(&PATH)` 编译期就知道拿到 `String`。整通道擦成
`Any`，等于在每个调用点把编译错误换成运行期 `None`：写错类型不再红，只是静默
取不到值。按本仓自己的判据（「拼错时谁会红」：只有静默失效才值得机制化），
这是用**每个调用点的编译期检查**换**一个域的文本依赖**，方向错了。外迁不付
这个代价：`ctx.get(&CAPABILITY_VISITOR)` 照旧返回 `Arc<dyn Registry>`，调用点
一个字符都不用改。

## 为什么 Aborted 可以不携带半截产出

`PluginError` 是**跨插件共享**的错误词汇——`model` 插件也构造 `Aborted`。
而「半截产出」（正文 / 思考 / 工具节点）从来不是共享词汇的一部分，三条证据：

1. `PluginError::to_frame` 只写错误码与文案，**载荷不过线**——它本就跨不过
   插件墙；
2. 模型侧的中止在 `adapters` 边界就转成 `AdapterError::Aborted`（载荷在那里
   被丢掉），loop 侧由 `turn_exec` 见到 `outcome.aborted` 后**重新构造**一份；
3. 压缩路径的 `Aborted`（`pipeline.rs`）被就地吞掉，转为压缩失败的降级，
   永远到不了消费臂。

也就是说：**唯一的非空载荷生产方（`turn_exec`）与唯一的消费方
（`chat_loop` 的收尾臂）同在 loop 插件内，是一次普通的进程内 Rust 调用**。
为它把 `Vec<ChatNode>` 塞进共享错误词汇，再在另一端拆箱——无论用不用
`Any`——都是给一条不跨墙的数据付跨墙的税。收成无载荷变体后，半截产出改由
loop 私有的退出类型携带，**编译期类型检查一点没丢**（比原稿的「不透明句柄」
方案更强：那个方案要把类型安全挪到运行期 downcast）。

## 第三刀：为什么是 event_bus

`vdfs_change_of` 是「总线帧 → VdfsChange」的唯一解包入口。它匹配的**外层信封**
（`{type: "bus_event", data: {kind, session_id, data}}`）由
`event_bus_build_envelope` 定义，它比较的**频道判别值**是
`EVENT_BUS_KIND_VDFS`——两者都是 event_bus 域的契约；它引用的 `VdfsChange`
才是 vfs 域的载荷形状。住在 vdfs 域，等于让资源域认识总线；搬到 event_bus
只新增 `event_bus→vdfs`（载荷类型）一条边，而 vdfs 拆边后**出边为 0**，
不成环。三则信封测试（手搓信封、独立于产帧方钉形状）随函数搬迁——
测试是这条契约的真正守卫，与实现分居两地正是要消的冗余。

## 代价

1. **键定义散居各域**，「一键一址」的名册不复存在。缓解：根平铺重导出保持
   调用点名字不变，消费方仍从 `crate::symbio_core::X` 一处导入；且判据
   （键与值同住）比名册更可复核——`core-vocab-audit` 的边清单就是名册。
2. **`PARENT` 改名 `PLUGIN_PARENT`**（`ParentKey` → `PluginParentKey`）。
   N-001 要求符号匹配所属域的前缀，而 `plugin` 域的常量格登记的是 `PLUGIN_`
   （下含 `PLUGIN_ID_*` / `PLUGIN_KEY_*` / `PLUGIN_FILE` /
   `PLUGIN_PAYLOAD_KEY`）——把整格改成裸名会让那 20 多个常量集体失去前缀
   核对，不可接受；改一个键名是净成本更低的一侧。`Weak<dyn Plugin>` 本就是
   plugin 域词汇，`PLUGIN_PARENT` 比 `PARENT` 也更自证归属。
3. **`vdfs_change_of` 改名 `event_bus_vdfs_change_of`**。N-002「一个前缀只属
   一个域」：`vdfs_` 已登记给 vdfs 域，event_bus 不能再用。
4. **`execute_turn` 的退出类型从 `PluginError` 变为 loop 私有枚举**
   （`Aborted(Vec<ChatNode>)` / `Failed(PluginError)`），测试夹具同步；
   `PluginError::Aborted` 的四个构造点（`bound_provider` ×3、`pipeline` ×1）
   随之简化为无字段变体。
5. **README §1.2 的域前缀表三格改写**（`keys` 备注、`capability` 常量
   `—` → 裸名、`exec` 常量 `—` → 裸名）。该表是 `core-naming-audit` 的
   规则源，改表与改代码被绑成一件事——这正是它该有的形状。

## 失效边界

- 若 `Aborted` 的载荷要开放给**第二个执行方**（不只是 loop），loop 私有退出
  类型装不下——届时重新裁决共享词汇的形态，不顺手把 `PluginError` 撑宽。
- 若某域的键值类型指向**第二个域**（如 capability 的键要装 exec 的东西），
  「与值同住」不成立——那说明这个键横跨两域，该做的是重新分域，不是搬家。
- `keys` 从此是汇点。若哪天它需要**出边**，说明又有人在往万能胶上挂东西——
  那时先问「这个键的值类型为什么不住自己的域」。
- `adapters⇄projection` 一族不在本批范围（拆法：档位词表下沉一层，属
  adapters 自己的改造）。基线注释保留原说明。
