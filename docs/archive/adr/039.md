## 决策

**背景**：DE-002 把 `session` 的规模债判为「带触发条件的延后」，并写明命中触发条件时应由新 ADR 取代、而非直接删除。现三条同时成立：①「改 A 必须同时改 B」的跨文件连锁确已出现，根因是 `session` 内部职责混杂；②单次改动的 diff 大到无法被人完整审阅——若干文件同时装着几类互不相干的职责；③各部分职责的归属与作用域能明确说清，下放不再需要「先切再看」。

**决策**：`session` 按**域**重组，判据五条：①**一域一目录（或一文件）**——一个职责域 = 一个 `X/` 目录（`mod.rs` + 子模块）或一个 `X.rs`，不允许多类互不相干的职责同居一文件；②**编排层与领域层分离**——编排层只做装配、调度与收口，领域层内聚自己的机制，依赖单向（编排 → 领域）；③**副作用出口唯一**——领域的落库 / 广播 / 事件经该域单一出口；④**域内分层，测试恒外置**——一个实现文件对应一个测试文件，两种合法形态由 `scripts/test-layout-audit.mjs` 判定；⑤**跨域共享面走门面**——`pub` + 域根 `pub use` 导出，`pub(super)` 只表达域内部分工。判据逐条表述与「它挡住什么」见 `symbio/src/plugins/session/docs/017-module-layout.md` §0；域清单与逐文件落点同见，文件数与行数以 [CURRENT.md](../006-ref/006-当前事实表.md "RE-006-当前事实表") 为准，本条不复述。

**理由**：DE-002 反对的是**按现状切几刀**，不是拆分本身；五条判据按职责边界而非行数给切法——每个域都要能一句话回答「它是什么、它不做什么」，答不出就不成域。拆分必须**可证伪**：全程纯搬移、每步零行为变更，用代码行多重集逐条归因、用例数不减、门禁全绿自证「没有丢东西」；测试外置与门面导出是这套自证的**前提**而非结果——`#[path]` / 同级 `tests.rs` 让测试随实现文件走而模块路径不变，门面让跨域调用点在改名时只改一处。编排与领域分开后，「机制变了」与「接线变了」成为两类 diff：前者落在领域内审阅，后者落在编排层——这正是触发条件 ② 所要求的可审阅性。

**被否决的方案**：**按行数阈值机械切分**（行数不表达职责，切出来仍是按现状切几刀，维持 DE-002 对这条的否决）；**只外置测试、不动生产划分**（能解决混放，解决不了跨文件连锁——连锁恰恰都长在生产代码的职责缝上）；**一次性整体重组**（diff 无法审阅，且把搬移风险与行为风险混在一次变更里；改为分阶段纯搬移，每阶段独立验收提交）。

**后果与不变量**：新增职责先归域，无域可归的进编排层或最贴近的既有域，不新建「杂物」文件。与 [D-023](023.md)（core 准入 = 依赖方数量）互补：本条管 **session 域内**的落位，D-023 管 **core 与插件之间**的落位——同源的判据（职责与依赖方），不同的作用面。既有单一实现约束不因重组放松（压缩内核、回合收口、消费循环等的唯一落点），清单见 `symbio/src/plugins/session/docs/015-core-loop.md`。判据约束**新代码与被触碰代码的落位**，不冻结现状、不触发顺手搬迁；域边界将来若不合适，改的是归属，不是机制。
