# D-120：`LazyLock<Option<Arc<Frozen>>>` 与按会话注入是同一个值

## 背景

[DE-015-义务环](../004-plan/016-义务环.md) §3.3 要求「运行期不能注册」写在类型上而不是
纪律上。[T-243-Builder六口与按会话seal](../009-task/243-Builder六口与按会话seal.md) 收口时
`Builder::seal(self)` 已经消耗自身、`Session` 只持 `Arc<Frozen>`，剩下的一处疑点是装载的**存放位置**：
`crates/symbio-plugin-loop/src/loop_rows.rs` 用一枚进程级 `static FROZEN: LazyLock<Option<Arc<Frozen>>>`
汇聚五张注册表，而「按会话构造注入」才是 §3.3 字面写出的形状。

疑点不是空的：一枚进程级的、装过表就再也卸不掉的 static，形状上像一条全局注册通道；
而它的失败态被缓存（`Option::None`），也像「错误被吞了一次就没人再管」。要么改代码，要么
把等价性讲清楚并立在这儿。

## 决策

**保留进程级记忆化，把它明示为纯函数的记忆化，并按 [T-243-Builder六口与按会话seal](../009-task/243-Builder六口与按会话seal.md) 的口径给出类型依据。**

等价性由三条事实支撑，缺一条本裁决就不成立：

1. **输入全是 `&'static` 程序文本**：灌进 `Builder` 的 `Decl` / `PortDecl` / `ActorDecl` /
   `FactDecl` / `ViewDecl` 每个字段都是 `&'static str`、`&'static [_]` 或 `Copy`——没有
   会话状态、没有环境读数、没有时间。
2. **`seal(self)` 按值消耗**：同一份输入只能冻出同一张表，且冻完就没有第二条路能把别的东西
   灌进这张表（编译期反向用例见 `docs/003-design/verify/seal_consumes.rs`）。于是「按会话构造」
   得到的**就是这个值**，不是另一个值。
3. **`Frozen` 无 `&mut self` 方法、无内部可变性**；`Session` 手里的 `Arc<Frozen>` 在共享下
   `Arc::get_mut` 恒 `None`——运行期拿不到可变注册口这一条不依赖 `static` 是否存在。

`Option` 缓存的是**失败**而不是可写状态：缺口已逐条进 error 日志，此后每一场开幕都经
`loop_rows::table()` 带同一个 `Err` 退出，
不存在「这一届会话拿到了半张表」。

## 理由

按会话注入真正能多买到的是**「不同会话可以有不同的表」**。而在 1、2 成立时这个能力没有被消费的
对象：真表就是 `ROWS` 这一份程序文本。为没被消费的能力付一次「每场开幕重灌 + 重跑七道检查」的
成本，是给装载期加一条时序依赖，不是减。

反过来，把 `FROZEN` 换成会话字段会让「表」的存放位置变成调用方的事——那正是 §3.2 要消灭的
「检查跟着调用方走」。

## 被否决的方案

- **每场会话各灌一份表**（字面照抄 §3.3）：否决理由如上——多买的能力无人消费，代价是重复装载
  与「谁负责灌」重新回到调用方。
- **`static RwLock<Vec<Decl>>` 式的全局注册通道**：否决。它能运行期加行，与 §3.3 直接冲突；
  且 `LazyLock` 一旦装好就不再变，前者永远是可变的。
- **失败不缓存、每次开幕重跑 `assemble()`**：否决。会把同一条装载错误按开幕次数重放进日志，
  并且让「装载失败」这件事的**可见次数**取决于运行了多久——判据要的是稳定读数。

## 后果

- 本 ADR 是 [T-243-Builder六口与按会话seal](../009-task/243-Builder六口与按会话seal.md)
  验收口径 1 括号里那条「明文论证等价性并挂 ADR」的落点；`loop_rows.rs` 的小节注释指向本文，
  不复述论证（一个事实一个 owner）。
- **作废条件写死在这里**：一旦出现按会话不同的表（例如按会话声明事实子集，或热装载），
  第 1 条不再成立，本 ADR 立刻作废，改按会话构造注入并留一条订正。
- 唯一保留的差异是**开幕时机**：首次查询即装载。它不影响任何判据读数，因为失败态也带同一个
  `Err` 进每一场开幕。
