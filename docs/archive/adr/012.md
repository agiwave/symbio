## 决策


**背景**：一个真实消费者（审查本仓库的 agent 会话）复盘自己的低效，五类摩擦里三类直接指向**读侧**：无法一次建模；没有可核对的读侧事实表（手抄清单会漂移）；核对不划算时读者会自动切换成「停止验证、退回文档口径」，并用自信语气包装未验证结论。

**决策**：把读侧成本当作与写侧成本对等的设计约束：
- **事实从代码提取，不从人手抄**：`docs/004-ref/006-当前事实表.md` 由 `scripts/facts/current.mjs` 只做提取（插件注册名 / VDFS 挂载点 / 自有路由臂 / LLM 工具 / 存储布局），提取不到就如实标注「运行期动态」，绝不臆造；CI `--check` 门禁保证不漂移。ADR 的「状态」行同理——它回答「这条决策现在是死是活」。
- **骨架化摘要必须支撑一次建模**：列表类 JSON 给 `count=N` + 前若干条目名（`names=[…]`），文本输出给首个有内容的行；摘要预算按能容纳完整条目名推导，不截在半个名字上。
- **占位符必须自描述取回路径**：骨架化结果附带定位锚点与 `Re-run <tool> to get the full output.`——把「要不要赌一把摘要」变成一次可预期的工具调用。

**理由**：写侧收益省的是**改代码**；读侧成本随读者数**相乘**，而反推贵到一定程度，读者会开始输出未验证的结论——这不是能力问题，是成本结构问题。修复方式不需要推翻任何既有设计。

**后果**：`CURRENT.md` 与手抄速览并存，但手抄件必须注明以生成表为准；新增插件 / 工具 / 路由后忘记重跑生成器，CI `--check` 会失败——维护者由此承担「同步事实表」的显式义务。
