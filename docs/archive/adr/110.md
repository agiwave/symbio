# D-110：载荷里不留恒空的向量键——键与写方同批进来

## 决策

1. **`memory.encoded` / `memory.consolidated` 的载荷不再包含 `vec` 键**。写方只写
   今天真有读方的字段：`{ content, tag, generation, vis_scope }`。
2. **位置裁决不变**：向量索引落成时，向量仍然住**这条事件的载荷里**，不是特殊类型、
   不开第二份事实源（[DE-001-核心架构](../004-plan/001-核心架构.md) §9.2 的那一格照旧成立；「记忆就是事实网格里的
   普通事件、没有旁路存储」那条同族纪律见 `plugins/loop/memory_events.rs` 模块文档）。
   被本条淘汰的只有一件事——**在没有写方的时候先把键写空**。
3. **接线的前置条件写在账上**（不是「以后再说」）：语义维要进排序，必须同时解决
   「评测与生产同源」这一条——召回评测集 `verify/recall_eval.rs` 用 `#[path]`
   包含生产排序内核 `projection/recall_score`（[T-085-记忆召回判据面补齐批](../009-task/085-记忆召回判据面补齐批.md) 批③ 立的纪律），
   而它是裸 `rustc` 编译的单文件、拿不到真向量。若先扩 `ScoreEntry` 加浮点位，
   评测要么换成临摹件（静默失效，正是黑盒纪律点名的形态），要么配一份合成向量
   （读数不再说明生产）。**先想清楚评测怎么跟着走，再动载荷。**

## 理由

- **它今天是一处 ③ 纯声明**：机制强制等级清单（[T-184-机制强制等级清单批](../009-task/184-机制强制等级清单批.md)）把
  「embedding 事件 `vec` 恒空」列为「规则写了、无执行方」的实例。审计对整个仓库的
  一句话结论是「**声明多于兑现**」，而一条恒空键正是最省成本的清偿对象：全仓
  **零个生产读方**（`grep '"vec"'` 只命中写方两处与测试夹具），召回投影
  （`projection/recall`）只读 `content` / `tag`，`ScoreEntry` / `RecallEntry`
  里根本没有向量格。
- **接线没有测量驱动**：召回评测的实测读数是 `production 1.000 / paraphrase 0.909 /
  dependency 0.091`（33 案 66 条换述，门禁每轮跑）。字面二元组内核已经被换述压到
  只剩 9% 的措辞依赖，而接线要把一次 ONNX 推理（bge-small-zh，CPU，`MAX_SEQ=512`）
  挂到**每一轮的两条编码**上，还要多养一份与 WAL 双写的向量索引。**用推理成本与
  一份旁路索引去换 0.091 的残差**，而本仓唯一能说明「换来的确实更好」的量具
  （冻结换述集）又会因为第 3 条而失去效力——这笔账在本批算不过来。
- **「写清楚比留空强」不足以留下它**：文档已经写清楚了两遍（事件口径、模块口径），
  恒空键的残留收益是零，残留代价是「后来者以为语义召回已存在」。删掉之后
  「语义记忆」这一格从**看起来有**变成**账上没有**，这正是本仓要的诚实形状。

## 后果

- 存量事件载荷里已有的 `"vec": []` **不清理、不迁移**：载荷是自由 JSON，读方从来
  不认这个键，留着不改变任何行为；新写的不再带它。这不是「两种形状并存」的债——
  事实源里那条事件当时确实带了那个键（[D-053](053.md)：变更即事实，Log 不删）。
- 测试夹具同步删除该键，且判据从「`vec` 恒空」升为「**载荷里没有 `vec` 键**」——
  后者才拦得住「顺手把空键写回来」这个动作（空键判据对空键的回归是绿的）。
- 撤销条件（写进 [T-211-记忆检索兑现批](../009-task/211-记忆检索兑现批.md)，不只在口头）：出现**具体**的
  「近义表述搜不到」案例，或 `dependency` 读数明显上升 ⇒ 按第 3 条的前置条件
  立项接线，`vec` 与它的写方、索引、评测同批进来。
