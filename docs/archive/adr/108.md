# D-108：淘汰的恢复路径——触发器缺席是边界，不是漏接

## 决策

1. **`EliminationDecider::restoration_event` 保持「有形状、无生产写方」**（`#[cfg(test)]`）。
   恢复的**机制半边**是完整的：同格事件（`verdict.asserted`，`change = "restore"`）
   + last-wins 折叠（`GrantsOverlay`）+ 撤销回路单测。**生产触发器缺席**必须按缺席
   登记，不拿测试构造器当已实现——那正是 [T-207](../009-task/207-授权写侧口径统一批.md "T-207-授权写侧口径统一批")
   项 10 要消灭的形态：诚实缺口与假缺口在读面上分不开。
2. **不造「等分数回到阈值之上就自动 restore」的回路**：在本判据下它永远不会开火
   （见下「为什么不可能」）。写了它，审计面上多一条**死臂**，而一条从不执行的分支
   比一条没有分支更容易让人以为这里有出口。
3. **把「不可自动恢复」记为本条边界**，并写明**重开条件**：出现一个**外部触发**
   （申诉受理 / 人工复位）时，摘掉 `#[cfg(test)]` 接上即可——载荷口径（`subject` /
   `capability` / `change` / `why`）不随触发器的形态改动，这是本条刻意把形状与触发器
   分家的原因。
4. **不提前立项**（[D-032](032.md "D-032") 同一条纪律：设计期条目登记成占位任务
   只是把债换个地方放）。归属挂在 [T-133](../009-task/133-多智能体社会.md "T-133-多智能体社会")
   §现状 的缺口①「申诉触发器缺席」上——那条已经登记在任务层，本条补的是**裁决**
   （为什么今天不做、什么条件下做），不是第二张登记表。

## 背景

淘汰回路的写侧（`derived_facts::record_elimination`，[D-100](100.md "D-100") 定的
部署事实面）落一条 `revoke`，读侧（`tools/tool_executor` 的撤销闸）据此拒 `agent_run`。
**收回**这条路每一步都有生产者；**放回来**这条路只有单测写过一条 `restore`。

## 为什么自动恢复不可能（本条的核心判据）

声誉分是**派生**的：`plain_score = 守约 − 违约`，而生产里唯一的承诺写方是**委派**
（`record_derived` 拿 `delegations` 落 `commitment.*`，S08 §3）。于是：

- 被收回的正是 `assign.work`（派活）；
- 收回之后**没有新的立约**，分数被冻在负值；
- 阈值判据（`score < THRESHOLD`）因此恒真，任何「自愈」规则的前提（分数回升）
  在这一格里拿不到。

这不是实现缺一块，是**判据的闭合性**：一个只由「被禁动作的成功」驱动的分数，不可能
被自己禁掉的动作抬回来。恢复必须由**淘汰判据之外**的权威给出——即申诉 / 人工复位。

## 边界现在的效果（如实写，不粉饰）

- **部署表里持 `assign.work` 的主体**（`session/main` / `session/market`）一旦被淘汰，
  在本机构造下**没有人工出口**：既没有申诉入口，也没有复位命令面。
- 唯一的既有出路是**存储布局的后果而非设计**：那条 `revoke` 只活在承载它的那段 WAL
  里，部署级折叠读的是事件切片——承载它的会话被删除，折叠结果随之消失。把这条记在
  账上，**不当作解法**，也不粉饰成「可回退」。
- 覆盖面本身有限：只靠绑定行运作的 `agent:<id>` 不在淘汰面内（[D-100](100.md "D-100")
  「淘汰面为什么只认部署表」第 1、2 条）。所以今天这道单向门只对**部署主体**成立。

## 判据与落地锚

| 半边 | 锚 |
|---|---|
| 机制（撤销 ↔ 恢复同格、last-wins） | `governance` 的 `grants_overlay_supports_the_revoke_restore_revoke_loop` / `a_typoed_revoke_revokes_the_whole_principal` |
| 形状（`restore` 载荷与 `revoke` 对称） | `EliminationDecider::restoration_event`（`#[cfg(test)]`，注释与本条同一读数） |
| 缺席（生产写方只有 `revoke`） | `record_elimination` 只调 `elimination_event`；全仓 `EVENT_VERDICT_ASSERTED` 的生产构造点仅此一处 |
| 不放大 | [D-100](100.md "D-100") 的 `the_elimination_face_ignores_bindings` |

## 代价

淘汰因此是**单向门**：一次违约（一次失败的委派）就让部署主体永久失去派活能力。
本条选择**把门记在账上**而不是先造一个开不了的门——理由如上：自动恢复不可能，
人工复位需要一个尚未存在的权威入口（市场 / 守门两行连跑轮主体都没有，见
[T-133](../009-task/133-多智能体社会.md "T-133-多智能体社会") §现状 缺口②）。
将来接触发器时，改动面是本条决策 3 那一处（摘属性 + 一个调用点），不是重构。
