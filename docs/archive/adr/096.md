## 决策

**快速档 = (ii) 一次受限的模型调用**（不是 (i) 纯规则分类器），
**令牌闸门这一半显式退役**：`ClassifyOnly` / `TokenIssuer::issue_fast()` /
`CanClassify` / `CanGenerate` 从 `symbio_core` 契约面收掉，
`RuleOnly` / `FullModel` 两档令牌与 `LlmAdapter::generate(&FullModel)` 不动。

依据：[T-162-ClassifyOnly快速档路径裁决](../009-task/162-ClassifyOnly快速档路径裁决.md "T-162-ClassifyOnly快速档路径裁决")。
它接续 [DE-002](080.md) 的裁决二——那一条把 `classify/decide.rs` 标记为
「待 T-162 裁决」，本 ADR 就是那个裁决。

### 为什么是 (ii)

`classify/decide.rs` 就是快速档，它发的是一次静默 LLM 往返。这不是待建的设计，
是**已运行的事实**：规则表（`classify_by_rule`）只覆盖问候 / 致谢 / 确认 / 空输入，
其余全部落这次调用。裁 (i) 意味着删掉它——那会让「这句话该不该进工具循环」
退化成关键词匹配，而 [T-157](../009-task/157-ActorSpec-pattern死字段接线.md "T-157-ActorSpec-pattern死字段接线") 已经核出
`text.contains("？")` 那只在 `verify/latency_gate.rs` 里作为编译期桩存在，
生产从未有过纯规则分类器。

### 为什么退役而不是接线（五条，第 4 条是决定性的）

1. **端口从未存在。** `Classifier` 全仓只出现在 `docs/003-design/verify/latency_gate.rs`，
   实现体是 `text.contains("？")`——它存在的唯一理由是证明「低档令牌传给生成端口
   编译不过」这条**类型闸门模式**成立。生产的装配点（`assemble(tier)`）同样只在
   那个验证文件里。令牌因此是「守一个不存在的端口的门卫」。
2. **[DE-002](080.md) 已划界。** 内部请求显式脱离档位闸门，classify 的模型调用
   已按 IM-001 登记。给它发 `ClassifyOnly` = 给一类**已裁决不受闸门约束**的请求
   重新装闸门——两套口径，且新的一套更宽（它管的是 core 公开面）。
3. **返回类型比令牌硬，且管的是同一件事。** `parse_verdict(&str) -> Option<Verdict>`，
   `Verdict` 是四变体闭集。令牌证明「持码者被允许分类」，返回类型证明
   「产出只能是这四个之一」——后者是前者要守的那件事本身。DE-002 裁决三的
   「不许长输出」一行已经这么记了。
4. **端口会当场被 C-003 打回。** `Classifier` 端口只有一个生产消费方（classify 插件），
   按 [`core-export-audit`](../../scripts/core-export-audit.mjs) C-003 的口径
   「名字没跨出 core 的符号不许占根出口」必须下沉到那个插件；而**下沉之后令牌跟着
   下沉**，core 里再也不需要它。所以这不是「代价大所以不做」——是做了也会被下一条
   判据打回，且打回之后现状与本 ADR 相同，只多绕一圈。
5. **可调的提示词与模型ID 没有地方放。** `ClassifyConfig::system_prompt` 与
   `model` 是本插件的可 A/B 配置（设置页能改）。端口若拥有提示词，这两个字段死；
   端口若把提示词收成形参，「输出空间限定」就不再由端口保证，令牌只剩仪式。

### 「不得生成」的强制力搬到哪

约束没有变弱，是**换了承重墙**。三件事各归其位：

| 约束 | 原来靠什么 | 现在靠什么 |
|---|---|---|
| 输出空间限定四选一 | `ClassifyOnly`（令牌，从未签发） | `parse_verdict -> Option<Verdict>`（返回类型，编译期） |
| 不带工具 | 插件切分的巧合 | `internal-model-audit` IM-004 判**形状**：`tools` 必须是 `&[]`（门禁，见 DE-002 裁决四） |
| 不出现在模型工具清单里 | 插件不注册 `Capability`（巧合） | `traverse_contributes_no_tools`：挂真的 `CAPABILITY_VISITOR` 注册表，断言工具行数 = 0（单测） |
| 不产出面向用户文本 | 同左 | `Verdict` 返回类型（措辞归 `compose`，本插件无此路由） |

第三行是本 ADR 新增的牙齿：T-162 的退出条件要求这条「不是靠巧合」。
原断言只查 `traverse` 的**回包**是 `[]`，改后查**注册表**——那才是模型工具清单的
真正来源（`Registry::put` 的能力行）。

### 快速档这个档位还在吗

在。[`LatencyTier::Fast`](../../symbio/src/symbio_core/adapters/mod.rs) 的预算
（300ms）仍被 `actors/skill.rs` 使用，`may_call_model()` / `may_generate()` 仍表达
「可调模型、不许生成」这条语义。退掉的只是**令牌**——档位的预算与语义是数据，
令牌是给它配的端口凭据，而端口不存在。

## 否决的替代方案

- **补 `Classifier` 端口 + `issue_fast` 生产调用**（T-162 的出路 A）：被第 4 条否。
  它会以「单消费方根导出」的形态被 C-003 拦下，下沉后令牌失去存在理由。
  顺带第 5 条：可配置提示词与端口所有权冲突。
- **连 `LatencyTier::Fast` 一起删**：它的预算有生产用户（skill 快路），
  删它会改运行期行为。档位是数据、令牌是凭据，两者不该同进退。
- **改 `docs/003-design/verify/latency_gate.rs` 去掉 `ClassifyOnly`**：那个程序是
  DE-001 §4.1 的**硬证据**，证明的是「零大小能力令牌能当构造期闸门」这个**模式**，
  与生产用了几个令牌无关。改它等于改计划文本去迎合实现，方向相反。
  两者的关系由本 ADR 的「为什么退役」一节书面记录。
- **悬着不裁**：就是 T-162 立项时要消除的现状——一个冻结契约名躺在 core 里、
  有测试守着编译期形状、零生产路径。被否。

## 代价

- `symbio_core/adapters/mod.test.rs` 少一条正向例（`full_model_token_satisfies_classify_and_generate`），
  `RuleOnly` 的负例改由 `LlmAdapter::generate` 的签名承载（那本来就是它的承重墙）。
- 计划文本（DE-001 §4.1 表、DE-018 §3.3 注入表）里仍有 `ClassifyOnly` / `Classifier`。
  **不改**：计划是冻结锚点，与实现的差由本 ADR 记录，与 [DE-002](080.md)
  对同一处计划文本的处理方式一致。
- `verify/latency_gate.rs` 仍自带一套 `ClassifyOnly`（自包含、零 `symbio_core` 依赖）。
  读者可能误以为生产也有——这条写进本 ADR 的「否决的替代方案」第 3 条。

## 失效边界

- 若将来分类**不只**在 classify 插件发生（如 session 内的就地分类、第二个分类消费方），
  第 4 条的前提（单消费方）消失——那时重新裁决端口的形状，本 ADR 的退役结论随之重开。
- 若 `Verdict` 需要加第五个变体（如「需要更多信息」之外的类别），
  「输出空间限定」仍由返回类型保证，但 `CHOICES` 表与提示词要同步——那条已经有
  `decide.test.rs` 穷举守着。
- 若 IM-004 的形状判据被放宽（某处内部请求要带工具），「不带工具」这条回到
  「靠约定」——届时本 ADR 的表格第二行失效，须重新找承重墙。
