# D-098：A2A 对外互操作——暂不接，部署形态还没有对端

## 决策

**暂不接 A2A**；触发条件（真实跨厂商互操作需求 / 部署形态长出对外服务面）满足其一即重开，
届时照本文的映射表直接施工，不重新裁决。理由与被否掉的替代方案见下。

## 背景

[T-174](../009-task/174-A2A对外互操作.md "T-174-A2A对外互操作") 实测：`grep -ril a2a symbio/src cli/src` **零命中**——
全仓没有 A2A 实现，也没有否决记录。缺口的形状不是「没写完」，是「没裁过」。
A2A（Agent-to-Agent，Google 2025-04 发布）解决的是「外部编排器**发现**并**调用**本系统」：
Agent Card 发布能力清单，task 信封承载委派与状态回传。

## 裁决

**暂不接**。但不是「A2A 不值得」——恰恰相反，搜证（2026-10-20）排除了所有
「协议侧」的推迟理由，剩下的唯一真实理由是**部署形态还没有对端**：

1. **协议已稳定**：A2A v1.0（2026-03）、1.0.1 补丁（2026-05）、IBM ACP 并入
   （2025-08）、Linux Foundation / AAIF 治理（2025-12）——「标准还在演化」不成立。
   150+ 组织生产部署，AWS / Cisco / Microsoft / Salesforce / SAP 在列。
2. **但采纳面是跨厂商**：A2A 的价值在**组织边界**的 agent 协作（业界口径一致：
   MCP 对内到工具、A2A 对外到别的厂商的 agent；单组织内 MCP + 自有路由就够）。
   本仓当前的部署形态是**本地单机**：gateway 默认绑定 `127.0.0.1`
   （`gateway/config.rs`，0.0.0.0 需显式谨慎开启），消费方是本机的前端与 CLI。
   **本地单机上跑 A2A = 给没有对端的电话线办开户**——协议的一切价值（发现、
   委派、跨信任边界的状态回传）在对端出现之前都是零。
3. **「高阶智能体平台」是愿景不是现状**：GO-000 的四条判据是架构侧的；定位里的
   「平台」还没有长出对外服务面。入场券论（任务原文）成立的前提是「有人从场外
   来」——当前没有场外来客的通道，先修桥后修路是倒序。

## 为什么仍然写这条 ADR（而不是只在任务里说一句「不接」）

任务原文点出的问题——**task 的语义归谁**——是本仓必须自己回答的，而且它**已经有解**，
与接不接无关。把解先落纸，条件触发时照图施工、不再重新裁决：

| A2A 概念 | 本仓对应物 | 映射纪律 |
|---|---|---|
| Agent Card | 能力名册（`Registry`）+ 天梯 | **投影**：Card 从名册生成（`capability_to_wire` 已有 wire 形态），不新增第二份能力声明 |
| task | session（**不是** turn） | task 的多轮生命周期对齐 session；A2A 的每条 message 对齐一次 `route` |
| task 状态（submitted/working/completed/failed） | 事件信封的**投影** | 不新增可变状态——`session/stats` 的读出口已有全部素材 |
| cancel | 轮内 = `ExecAbortSignal`；轮间 = session 生命周期 | 映射成「杀会话」过粗、映射成「忽略」是假支持——两层各接各的 |
| `produced_by` / agent 身份 | 信封的 actor 模型 | task 层报「哪个 agent 处理」，actor 层保持本地主体模型，不做第二套身份 |

三条施工纪律（接的时候照此验收）：**走现有路径协议**（对端能力 = 一个 route，
不造第二套路由表）；**信封是唯一事实源**（task 状态是投影）；**失败形态钉住**
（对端不可达 / 卡片与本地能力不兼容 / 对端中途取消，三种都要 e2e 断言）。

## 触发条件（满足其一即重开，届时直接照上表施工）

1. **第一个真实的跨厂商互操作需求**：外部编排器要发现并调用本系统的 agent——
   不是假设，是有名字的使用方；
2. **部署形态长出对外服务面**：托管部署 / `0.0.0.0` 成为受支持形态——
   那时本系统有了「别人调我」的物理通道，A2A 是它的协议层。

两个条件都不满足时，每多接一层对外协议都是多养一套生命周期映射（三处错位
的维护成本恒定存在，收益为零）。

## 否决的替代方案

- **「现在就接，反正协议稳定了」**：工程量（A2A 入站插件 + Card 生成 + task 投影
  + 三条 e2e）买不来任何当前用户可用的新能力——当前用户的调用方就在本机。
- **「裁成『永不接』」**：没有依据。搜证显示的每一次协调事件（ACP 并入、AAIF 成立、
  v1.0）都指向这个协议在长期会像 MCP 一样成为默认面——条件触发时接是对的，
  「永不」是把当下的部署形态错当成永久的。
