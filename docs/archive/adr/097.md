## 决策

**「抽象层级」这条轴从「本轴目前只能人工判」改成「离线读数 + 残余人工判」**，由三条具体决定支撑：

1. **读数** = 原述 recall@k − 换述 recall@k，叫**依赖度**（越大越依赖字面）。它由
   [`verify/recall_eval.rs`](../004-plan/verify/recall_eval.rs) 打印——池不动，只把
   33 条用例的查询换成同义换述再跑一遍同一个生产排序内核。
2. **换述集是冻结数据**：[`verify/fixtures/paraphrases.tsv`](../004-plan/verify/fixtures/paraphrases.tsv "verify/fixtures")
   33 案 × 2 条，带 FNV-1a 64 指纹，**改一个字节即红**。
3. **换述不并进 `pass^k`**，单独出数；且同时报两个数——全 33 案 与
   「措辞能左右结果」的 27 案子集。

依据：[T-173-抽象层级外部效标](../009-task/173-抽象层级外部效标.md "T-173-抽象层级外部效标")。
它接的是证据复核（2026-10-19）的 P5 行：五轴里只有这一条没有外部效标，而
[DE-008 §3.1.1](../004-plan/002-能力坐标系.md "DE-008-能力注册表与能力坐标系") 早就把候选口径写好了，
只差实现。

### 为什么这条读数值得存在（而不是继续写「只能人工判」）

- 五轴里另外四条都挂着生产读数口（`span` / `conation` / `autonomy` / `calibration`），
  只有它停在人工判。而它偏是天梯 T2–T6 的**主轴**——「高阶了多少」这句话在没有读数时
  只能靠叙事。
- 计划自己在 §3.1.1 的格子里写了候选口径并标注「**离线可测、尚未实现**」。本 ADR 就是
  把「尚未实现」四个字去掉，并把口径收成可执行的那一半。
- §3.1.1 纪律一说的是「读数没出来之前不得改写成可测量口吻」。现在读数出来了，改口吻是
  纪律要求的**下一步**——但只改到读数覆盖得住的地方（见下「它不覆盖什么」）。
  **没有跟着改的是「可靠性」**：有读数 ≠ 已达标，本 ADR 不声称任何 T 级因此上升。

### 为什么换述集要冻结 + 指纹

换述是人写的 ⇒ 这条读数只是效标的**下界**：换述写得越接近原述，差值越小越好看。
没有锁的时候，「把换述改得更容易命中」在 diff 里是几行措辞，在读数里是「依赖度下降」——
这正是本仓反复撞见的那种**静默变好**（`_shared.mjs` 的基线漏改在同一天发生过两次，
是同一类机制的缺失）。

锁的形状：FNV-1a 64，按 `\r\n → \n` 归一后算字节。**为什么不引 sha**：本程序是裸
`rustc` 编译的单文件，没有 Cargo 依赖可用；这条锁只需要「改一个字节就变」，密码学强度
不是目的。改换述时要做两件事，缺一条程序就红：同步改 `PARAPHRASES_FINGERPRINT`，
并在 `fixtures/README.md` 的**改动记录**里写为什么——理由写在那里而不是提交信息里，
因为提交信息会随历史沉底，而那个文件是下一次改它的人真正会打开的地方。

### 为什么不并进 `pass^k`

`pass^k` 要求「同一问题的全部合法外观都命中」；而换述的未命中**本身就是读数**——
它量的是「这套排序有多靠字面」。把换述塞进 `variants()` 只有两种结局：

- 写换述时照着「能命中」的标准写 ⇒ 读数恒为 1，白测；
- `pass_all >= 0.90` 那条既有断言会逼人删换述（或放宽它）——把一条读数变成一条要绕过的门。

所以换述与 V1–V3 是**同一件事的不同尺**：都是「输入外观」，但一个是稳定性、一个是敏感度。

### 为什么同时报两个数（边界要算出来，不是写出来）

33 案里有 6 案属**时间兜底类**（`recency_fallback`：期望的就是池里最新那条）。这类用例
换成**任何**查询都会命中——包括一句与全场无关的问句。它们的换述读数因此结构上恒为 1，
与措辞毫无关系，却会老老实实地抬高全案平均。

程序用**可执行判据**分类而不是人工标签：`trivial` 口径（无查询 ⇒ 纯 ts 降序）漏掉的用例
才算「措辞能左右结果」，因为只有在那类用例上，命中才是内容匹配挣来的。分类之后两条都验：

- 内容可决定的案上，**每一条换述都是承重的**：把它换成无关问句，依赖度精确上抬
  `1/(n·m)`（该条原本就没命中的，读数必须不动）；
- 时间兜底案上，换掉换述读数**一分不动**——这就是那条边界，写成断言而不是写进注释。

实读（2026-10-20）：换述召回 **0.909**，依赖度 **0.091**（全 33 案）；同一差值在
27 案子集上是 **0.111**。换述与原述的二元组重叠均值 **0.121**（纪律②的读数：
越高说明题出得越像原述）。

### 它不覆盖什么（三句，写进 DE-008 那一格）

1. **测的是排序器对措辞的敏感度，不是「系统会归纳」。** 读数低只说明这套排序不靠字面，
   不说明任何东西理解了同义。从「排序器不靠字面」到「系统会抽象」之间那一步没有任何
   数据支撑。
2. **换述是人写的 ⇒ 只是下界。** 它是**效标的下界**，不是效标的真值。
3. **6 案结构上与措辞无关。** 只能进分母，不能进依赖度的叙述。

## 否决的替代方案

- **继续写「只能人工判」**：诚实，但不可复核。在一份声称「每条轴挂一个外部效标」的表里，
  一格空洞会一直挡着 T2–T6 的叙事，而计划自己已经把口径写出来了——不实现它的理由只是
  「还没做」。
- **把换述并进 `pass^k` 当 V4**：见上，方向相反。合并等于用稳定性指标覆盖敏感度指标。
- **自动生成换述**（用模型改写或 embedding 找近邻）：读数会随模型漂移，「同义」的定义权
  交给一个不可复核的东西；人写的换述至少能逐条审阅，而代价只是量小。
- **不要指纹，靠 code review 守**：措辞变化在 diff 里极不显眼，而「改好一点」在读数上
  是实打实的收益——这类改动天然有动机、天生难发现。
- **顺手把读数接到生产**（线上统计用户改写率之类）：那是另一条轴（有生产读数口才叫
  「有读数」）。现在没有那个口，硬接就是造假读数。

## 代价

- 66 条换述是人写的，量小；`n=33` 对「失败率上界 3/n」够用，对「依赖度」这个连续量
  只是**粗刻度**——0.091 与 0.11 之间的差别不该被当成结论。
- 5 案换述未全中，其中 `mobile-upload-fail` 两条**全不中**（换述说的是同一件事，但与正文
  二元组零交集：`k8s / 容器 / 反复重启` vs 正文的 `Kubernetes / pod / CrashLoopBackOff`）。
  那不是题写坏了，**那正是读数**；但它说明了 `dep` 的分辨率由换述质量决定。
- 指纹锁会在每次改换述时制造一次红——这是刻意的摩擦，不是副作用。

## 失效边界

- **排序内核换掉二元组重叠**（例如换成真 embedding 或混合打分），`dep` 的含义随之改变：
  那时「依赖字面」不再是它测的东西，读数要重新定义。换述集可复用，**口径不行**。
- **用例集变动**（加用例 / 改 `expect` / 改 `k`）必须同步换述（程序会 panic），且指纹要改；
  那一刻 `dep` 与历史值**不可直接比较**——它是同一批题的刻度，换了题就换了尺。
- **将来出现生产侧读数口**（线上改写率、用户澄清率），本 ADR 的「离线」定位要改：
  那才是「有读数」，现在这个不是。
- 若有人把指纹改成「自动写入实际值」，锁立刻退化成记录——这一条写在这里，是因为
  基线类机制被改成自动跟随后就再也不会红，而红正是它唯一的产出。
