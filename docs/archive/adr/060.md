## 决策

**背景**：本仓的健壮性面已逐处登记（`panic-audit` 的 PN-001…003），但**覆盖率**这条相邻的
量化面一直没有判据。[T-013](../009-task/013.md) 接下了这条延后，并写明处置只有两种：接
`cargo-llvm-cov` 逐 crate 阈值进 `RATCHETS`（floor，只许涨），或者**在一条 ADR 里写下
「为什么不划算」**——理由不许只存在于任务条目里。本 ADR 是第二种，它也是这条延后的 owner。

**决策：不做。** 逐 crate 覆盖率阈值**不进门禁**，且不设总量阈值。理由四条：

1. **覆盖率回答的是「有没有被执行」，不是「有没有被断言」**。一个只调用、不断言的测试
   照样把覆盖率顶到 100%，而它守不住任何东西。本仓的纪律是「出口可核对」——覆盖率恰恰是
   最容易被顶上去、又最难核对的一种数：它涨了，看不出是哪条判据变强了。
2. **「测试被删就红」这条已有落点，覆盖率是冗余的第二道**。`gate.d/35-baseline.mjs` 的
   `RATCHETS` 清单已经钉住 Rust / CI / 前端用例数、verify 程序数与断言数、e2e 用例数
   （floor，只许涨，且判据读**基准版本**而不是同一份源码）。真正会漏的是「有测试被删」，
   那一条管住了；覆盖率能额外接住的只有「某个分支从没被执行」，而那类缺口在本仓由
   `panic-audit`、形状基线、e2e 用例集分头接。
3. **成本是每次提交都付的，收益是低频观察量**。全量覆盖率测量要引入 `cargo-llvm-cov` 与
   `llvm-tools`（外部工具链组件），并显著拉长门禁——门禁是每次提交都跑的，而覆盖率是
   「隔段时间看一眼」的量。用每次都付的成本去买一个低频观察，性价比反了。
4. **总量数字会稀释已有的专用判据**。本仓真正的高风险面（panic 面、判据覆盖、形状基线、
   外部效标读数）各有各的判据；挂一个总量覆盖率上去，会出现「覆盖率达标 ⇒ 这一面看过了」
   的错觉，而专用判据本来不需要这个错觉也能红。

**不做的代价（如实写）**：无法机械发现「某段代码从未被任何测试执行」。这条缺口**不闭合**，
只登记——见下面「重开条件」。

## 重开条件（这条决策什么时候失效）

出现下列任一情形，本 ADR 应被取代（不是被绕过）：

1. **出现了一类只有覆盖率能发现的缺陷**——例如某段分支从未执行、且它挂了确实造成过
   线上失败，而现有判据（panic / 形状 / e2e / 断言数棘轮）一条都没红。有实例才谈代价。
2. **工具链成本降到可进门禁**——覆盖率测量不需要额外组件、且增量测量能控制在秒级。
3. **仓的规模或风险面变了**——例如引入大片由外部贡献、且没有配套判据习惯的代码区。

重开的**唯一入口**是写一条新 ADR 取代本条（不是改本条的正文），并在
[T-013](../009-task/013.md) 的 `evidence` 里指认它。

## 不做 ≠ 不看

覆盖率仍然是**人读的观察量**：想看时跑一次（`cargo llvm-cov`，工具本身不在门禁依赖里），
看的是「哪一块从来没跑过」，不是「达没达标」。它与 [RE-004](../006-ref/004-slo-calibration.md "RE-004-slo-calibration")
的「设定值」同款规矩——**没有实测之前，任何文档都不得写成本仓有覆盖率基线**。

## 后果

- [T-013](../009-task/013.md) 关闭（处置 = 不做，理由 owner = 本 ADR）。
- `gate.d/35-baseline.mjs` 的 `RATCHETS` 清单**不变**（不加覆盖率落点）；`scripts/` 不引入
  覆盖率工具依赖。
- `docs/003-design/016-工程落地与验证.md` §7.3 的缺口表里，覆盖率不作为待补项登记——它有 owner 了
  （本 ADR），不再是「无人知的延后」。
- 本条取代 13 篇归档前「明确不做」里那一段随归档退出活跃文档的写法：延后的理由现在有
  一条活跃 ADR 接着。
