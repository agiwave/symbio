## 决策

**背景**：`V2Mode` 是 `off` / `full` 两档的执行旋钮，`off` 档走 v1 执行路径。
它不是中性的「v1 模式」——它静默关掉四样东西（长期记忆召回 / 就绪任务集 /
技能路由 / 轮次事实入格），且 v1
分支与 v2 运行器是同一行为面的两份实现。[D-048](048.md)
已把 `bridge` 退役、出厂 `full`，但旋钮还在：**不被真实消费的那一份永远得不到
验证**（同一条理由），而轨 S 的每一批都会被「还能回 `off` 档吗」这个从未被验证的
回退口污染——S0–S2 的正确性证明需要 v2 是唯一执行路径。

**决策**：

1. `V2Mode` 旋钮**整体移除**：枚举、`SessionConfig::v2_mode` 字段、面板档位项<!-- doc-symbol-allow: 记名的是本决策退役的配置字段，不存在正是决策已落地的状态 -->
   一并退役（项目未发布，不留兼容层；旧配置残留的 `v2_mode` 键被 serde 静默忽略）。
2. 执行分流恒走 v2 运行器（`v2_exec::execute_turn`）；v1 分支死码整体删除。
3. `chat_loop/inputs.rs` 的三处读侧闸（`off` 档关闭记忆召回 / 就绪任务集 /
   技能路由）随之删除，三样无条件开启。
4. 转写桥随之退役：转写写入（`record` / `record_to_wal`）与 `TurnState::v2_executed`<!-- doc-symbol-allow: 记名的是本决策删除的桥用字段，不存在正是决策已落地的状态 -->
   删除，`v2_facts` 只余派生事实与学习两个写方（`record_derived` / `record_learning`，
   调用点都在 `v2_exec`）——轮次事实由 v2 运行器原生记账（D-048）。

**理由**：

1. **一个行为面只能有一份实现。** 两份实现的差别恰好是静默的（都能跑通、形状不同），
   门禁发现不了——[D-048a](048a.md) 否决「双 prompt 形状」是同一条理由。
2. **回退口必须是被验证过的。** `off` 档的四样静默降级说明它不是回退，是换一个
   更差的系统；把它当回退旋钮，等于给一条从未经真实负载验证的路径留后门。
3. **不留兼容代码**（项目未发布）：档位旋钮是过渡设施，留着只会让每个读者
   重新推演一遍它是否还能用。

**被否决的方案**：

- **保留 `off` 作应急回退**：否决。回退后四样静默关闭，「应急」时最难排查的正是
  静默降级；且该档本身从未被验证。
- **把 `off` 改成显式报错档**：否决。那是一个只会失败的档位，比没有更糟。

**后果与不变量**：

- 不变量不变：WAL append-only、同轮单一写方、`session/stats` 无条件读格
  （它本来就不看档位）。
- 对用户零可见变化：v2 执行路径的行为逐字不变。
- [13 §轨 S](../archive/13-质量改进总纲.md) 的 T-051 是本条的落地批，出口判据在该表。
