# D-113：强制等级 ② 认两种形态，③ 只留给「没有任何人判」

## 背景

[RE-010 机制强制等级清单](../006-ref/010-机制强制等级清单.md "RE-010-机制强制等级清单")
把每条机制按「违规时谁会红」分成 ①编译期 / ②运行时阻断 / ③纯声明，
`mechanism-enforcement-audit`（ME-001–005）守这张表的闭合。

这张表的 §0 把 ② 写成「违规**被拒**且有错误信号」。三条机制在收口时撞上了这个措辞：

- **I3 到点必答**（[T-188](../009-task/188-不变量写侧阻断批.md "T-188-不变量写侧阻断批")）：
  新开轮越过未收束的旧轮时**不能拒**——崩溃恢复后的会话恰好长这个形状，拒了就把会话钉死。
  现行形态是写入口当场 `plugin_warn!` 出声 + 计数，读侧
  [`unresolved_turns`](../../crates/symbio-core/src/invariants/mod.rs) 把同一处缺口报成违规。
- **投影签名·降级与预算消费**（[T-187](../009-task/187-投影签名兑现批.md "T-187-投影签名兑现批") ·
  [[D-105|D-105]]）：超窗不拒读数，框架统一截尾并置 `degraded`，
  召回侧把 [`RECALL_DEGRADED_NOTE`](../../crates/symbio-plugin-loop/src/memory_events.rs) 追加进给模型的头。
- **闸·入站边界**（[T-194](../009-task/194-入站边界加固批.md "T-194-入站边界加固批")）：这一条是真拒绝
  （重放 409、超连接上限拒），照旧落在 ②。

前两条因此卡在字面上：它们**有执行方**，但执行方不拒绝。于是清单只剩两个选择，
而这两个选择都是撒谎——把它们留在 ③，等于说「没人判」；把它们改成 ②，等于改了 ② 的定义。

## 判据

> **一条机制有没有执行方，只问：违规发生时，有没有一个具名信号在某处产生。**
>
> 「产生信号」与「拒绝写入」是两件事——拒绝是信号的**一种**形态，不是唯一形态。
> 反过来，「规则写在文档里，违规与不违规产生不出可区分的读数」才是 ③。

这条判据把清单要回答的那个问题（**谁会红**）与「红的方式」分开：方式由各机制的
所在域决定（写侧完整性用拒绝，读侧有界性用降级 + 出声，恢复形状用出声 + 计数），
清单不规定方式，只规定**有没有**。

## 决策

1. **② 的定义收窄到「运行时给出具名信号」，形态有两种**：拒绝（错误返回）与
   显式降级（当场出声 / 计数 / 置位，且读侧同一判据可复现）。
   显式降级要算 ②，必须**两条同时**成立：当场出声（不静默）+ 有一个可判读的
   读数承接同一事实——只打日志没有读数，仍然是 ③。
2. **③ 的定义不变**：规则写了，没有任何执行方。③ 必须挂 `mechanism-allow` 带期限，
   期限指向尚未闭环的任务或一条 ADR（这条不变，ME-004 不动代码）。
3. **RE-010 四行随之改判**：`I2` ③→②（拒绝）、`I3` ③→②（显式降级，本条决策的对象）、
   `闸·入站边界` ③→②（拒绝）、`投影签名·降级与预算消费` ③→②（置位 + 召回消费）。
   四条豁免随之从 §7 删除——豁免是缺口的登记表，缺口补上后留着它，等于让清单
   永久低估自己。
4. **`守卫的本体必须真跑`**：这批失效之所以没人看见，是因为
   `mechanism-enforcement-audit` 一直登记在 `30-docs` 的 **`TEST_ONLY`**（只跑回归测试，
   不跑本体）。它跑的是仓内一份 checked-in 的表，静态可跑，不属于 `TEST_ONLY` 那一族
   （`prompt-shape-audit` 那种「输入要运行时抓」才是）。现移入 `GUARDS`。

## 代价

- **② 变宽了一格**：以前「不被拒就算 ③」，现在要多问一句「那它出声了吗、有读数吗」。
  这一问是可检验的，但它靠人来判——ME 系列只能判「③ 有没有豁免」，
  判不了「该 ③ 的被写成 ②」。这是本决策接受的残余：**清单的等级由改表的人负责，
  机制键与豁免的闭合由守卫负责**。
- **显式降级从此有了义务**：出声 + 读数两件事缺任何一条就不能算 ②，
  所以将来把一条 ② 改成 ③ 比改成 ② 更难——这是有意的方向。
- **`MAX_EXEMPTIONS`（8）不降**：豁免降到 1 条不等于上限该收紧，收紧会让下一条真实的
  ③ 缺口先撞上「上限」而不是「理由」。
