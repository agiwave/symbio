## 决策

`session/<sid>/_run/<op>` 内部动作段（[D-086](../010-adr/086.md "D-086") §4）从
「五处手写同步」改为「一张行表 + 一个泛化端口」，四处同时落：

1. **session 侧一张装配期冻结的行表** `RUN_OPS: &[RunOp]`，每行 = `(op 名, 处理函数)`。
   **闭集就是行表自身**：授权判据第 3 条读它，派发也读它——「在表内」与「有臂」
   从此是同一件事，两份清单对账这件事不复存在。
2. **core 的 `run_ops::ALL` 删除**。op 名词表（15 个常量 + `SEG`）留 core——拼方
   （loop）与解方（session）隔着插件墙，词汇仍须共享；闭集不是词汇，是**执行侧的
   授权事实**，它跟着处理函数走才是一份数据。
3. **loop 侧 `SessionPort` 从 14 个类型化方法收成一个** `call(op, payload) -> Result<Value>`；
   `LoopSession` 的 14 个包装换成两个泛化助手 `run_op<T>` / `run_op_unit`。请求结构体
   （`AddNodesRequest` 等）留 core——**载荷构造仍是编译期类型化的**，丢的只有回体
   类型的编译期检查（见「代价」1）。
4. **`ADD_BY_RUNNER | ADD_HERE` 合一臂改为两行共享一个处理函数**，`Carrier` 成为
   **行级数据**——处理函数里最后一处 `op ==` 字符串比较随之消失。

新增机制键 = 0、新增 trait = 0（`SessionPort` 是 loop 插件内既有端口的**收窄**）、
core 出口面净减（`ALL` 删除）。行为逐一不变：`run_actions.test.rs` 的既有用例
（含授权三条与越权）原样绿。

## 背景

D-086 §4 立面时，加一个 loop→session 交互要同时改五处，且**没有一处会让编译器
提示另外四处**：

| 处 | 形态 | 漏改的结局 |
|---|---|---|
| core `turn/dispatch.rs` | 15 个 op 常量 + 手写 `ALL` 闭集 | 漏 `ALL` 条目 ⇒ **授权缺口**（该 op 永远 `Forbidden`），静默 |
| session `run_actions.rs` | `dispatch_run_op` 的 14 个 `match` 臂 | 漏臂 ⇒ 运行期 `Internal`「未实现」，响声但无编译保护 |
| loop `session_port.rs` | `SessionPort` trait 14 个方法 | 漏方法 ⇒ 编译错（会自己找人） |
| 同文件 | `impl SessionPort` 14 段委托 | 漏委托 ⇒ 编译错 |
| `turn_session.rs` + 各调用点 | `LoopSession` 14 个包装 | 漏包装 ⇒ 编译错 |

两个软肋都在服务端：`ALL` 是手写的第二份清单（与臂对账靠人），臂的模式是字符串
常量——字符串不参与 `match` 穷尽性检查。旧注释写着「新增词条漏实现时由编译器在
这里报错」，**那句话是错的**，已于审计批一改正为事实陈述；本 ADR 把「对账」本身
机制化：行表的 op 与处理函数是同一个数据，不可能单独漏一个。

## 为什么闭集可以住在 session

D-086 §4 让词表住 core 的理由是「拼方与解方隔墙，任一侧私有都会长出第二份
字符串常量」——该理由对 **op 名**成立，对**闭集**不成立：闭集不是两侧共用的词汇，
是「session 实现了哪些动作」这一条**执行侧事实**。它与处理函数同住才保证
「授权允许的」与「实现了的」永远相等；分居两地（core 的 `ALL` vs session 的臂）
正是本次要消的冗余。`e2e` 与单测的越权用例（`run_rejects_unknown_op_and_address_mismatch`）
判的是同一条：不在表内 ⇒ `Forbidden`，一个字的语义都没改。

## 为什么客户端可以只有一个 `call`（本条要裁的那件事）

`SessionPort` 的 14 个类型化方法真正防住的是「调用点写错回体类型」——而那会
**在运行期反序列化时红**，是响声，不是静默。按本仓自己的判据（「拼错时谁会红」：
只有静默失效才值得机制化，编译错误会自己找人），不值得为响声付五处同步。
`run_op<T>` 把回体类型提在调用点的标注上（`let messages: Vec<ChatNode> = session.run_op(...)`），
载荷走 core 的请求结构体（`AddNodesRequest { messages }` 构造即编译期检查）——
类型信息一处没少，少的是**每个动作都要重新声明一遍的机制**。

## 判据（全部可执行）

| 判据 | 用例 | 反证方向 |
|---|---|---|
| 行表覆盖全部 op 常量 | `table_covers_every_run_op_constant`：期望集 = 15 个常量（测试里逐一点名），行表 op 集与之相等 | 加常量不加行 ⇒ 红；加行漏常量 ⇒ 红 |
| 行表无重号 | `table_has_no_duplicate_ops` | 复制一行 ⇒ 红 |
| 越权仍红 | `run_rejects_unknown_op_and_address_mismatch`（既有）：`bogus` op 与地址/动作名不符都 `Forbidden` | 删闭集检查 ⇒ 红 |
| 授权三判据不动 | `run_requires_turn_dispatch_token` / `run_rejects_token_for_another_session` / `run_ephemeral_requires_session_handle`（既有） | 任删一条 ⇒ 红 |
| 假件仍是契约 | loop 既有测试（`resume` / `turn_exec` / `chat_loop`）经收窄后的 `FakeSessionPort::call` 全过 | 假件少一个 op ⇒ 对应测试红 |

## 代价

1. **回体类型从编译期检查变为运行期反序列化检查**。调用点从
   `session.get_messages()` 变成 `session.run_op(run_ops::MESSAGES, ())`（回型由
   `let` 标注或 turbofish 给出）。写错类型在那一次请求里红——响声、可定位，但确实
   不是编译期。这是本条明确的取舍：用「每个动作的编译期回型」换「加一个交互从
   五处同步降到两处」。
2. **测试假件内部又有了一次字符串分派**（`FakeSessionPort::call` 按 op 匹配）。
   假件的本职就是模拟服务端，分派是它的份内事；生产侧的那次分派消失了。
3. **读 core 的人不再能一眼看到「有哪些 op」的全集**——`run_ops::ALL` 没了，
   全集与实现同住 session 行表。可接受：全集与实现必须同住，分居两地正是冗余本身。

## 失效边界

- 若 `_run` 动作要开放给**第二个执行方**（不只是 loop 插件），行表的 fn 指针签名
  （收 `&SessionPlugin`）要泛化成端口 trait——那是新机制，届时重新裁决，不顺手加。
- 若某个交互需要**跨 op 的组合语义**（一次调用触发两个动作），「一行一 fn」装不下，
  需要的是组合层，不是把 fn 签名撑宽。
- 若 `Carrier` 之类的**行级差异变体**超过今天的两个（`add-by-runner` / `add-here`），
  考虑把差异提进请求体字段；两例的时候，行级数据更直白。

## 对 D-086 §4 的修订

§4 授权判据第 3 条「动作名在下面的闭集内」改为「动作名在 session 的行表
`RUN_OPS` 内」；§4 动作表（op → 行为 → 返回）**逐一不变**，本 ADR 只改它的
**组织方式**，不改它的内容。
