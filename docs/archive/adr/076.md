## 决策

**背景**：[D-075](075.md "D-075") 裁决一把 P3 的判据立成「被切的那片不再 `use super::` 宿主的
私有项」，裁决三点名心跳为第一片，并在 P3 那条留下批次 3 的读数与一句结论——**这批的实际工作量在
这些口上，不在搬目录上**。本 ADR 就是那句结论的裁决：逐口定归属，之后才谈施工。

读数口径：P1 落地之后，心跳对宿主的**全部**私有触点，实测八条。分组与 D-075 P3 那句略有出入
（那条把「配置一格」单列，本表把它算进 #6 落格——两者是同一次开档里的两格；本表把「运行参数的来路」
单列为 #5，因为裁决真正要答的是它），**新增的一条是 #8 里的选项族**：`heartbeat` 这个设置字段今天
也住在宿主的选项定义里，D-075 的读数把它漏在了「设置工具」那一栏之外。

**裁决一：心跳不是一片，是两件事。** 「什么时候该开一轮」是**调度**（间隔、抖动、错峰、空闲基线、
常驻循环）；「这一次开轮是一次自主触发，先把事实落进事实源」是**事实源的写窗口纪律**
（`heartbeat/mod.rs:351-488`）。后者不是心跳的属性——它回答的是「谁有资格开这个会话的事实源、
在什么时刻开」，那是存储所有者的事。八个口据此落位：

**裁决二：#6 落格移进写臂，是三处收益，不是一处妥协。**

- **全仓唯一的「非存储写方」消失**。`EventWalStore::open`（写方入口）今天只出现在
  `heartbeat/mod.rs:372` 与存储侧；读数面只有 `stats.rs` 在只读打开（`:266,502`）。移动之后事实源的
  写方只剩「轮末收束」与「收件箱空闲写窗」两条——正是那段代码自己声明的那两条（`:338-345`）。
- **`:347-350` 自认的 TOCTOU 残窗关掉**。今天「检查两个写方 → 开档 → 落格」整个跨在队列之外，注释
  明写残余风险是「检查之后一毫秒内跑完一整轮插话」。落格进写臂后，检查、落格、入队在同一次调用里，
  而入队正是那个会置 `is_working` 的动作的前半——检查与动作之间不再有可插队的缝。
- **自主触发成为地址面上可声明的一件事**。任何触发器（心跳、巡检、外部调度、网关）都能用同一个写体
  表达「这是一次自主开轮」并由事实层落四格；今天只有住在引擎里的那个模块做得到。这与
  [DE-014](../004-plan/014-单环一表收敛.md "DE-014-单环一表") §4 对触发器的定位同向
  （「触发器是环外机制，不是新机制键」）。

**标记的落法**：判别子放在**写体的 `meta`** 上（`meta.trigger = {"kind":"scheduled","idle_ms":N}`），
不放在 `source_principal` 上。三条理由：

- `meta` 是 ChatNode 的既有字段，写体的「判别式以 `{` 开头 ⇒ 它是字段子集」这条规则已覆盖它
  （`plugin/nodes.rs:423-451`），不需要新形状；
- 标记**在写臂就地消费**，不要求它活到转写（真合并多条时 `meta` 会被补充元数据整体替换，
  `transcript/supplements.rs:80-84`——消费点若在下游就得替这个丢失负责，在写臂就不用）；
- `source_principal` 是「这条消息是谁发的」（`symbio_core/keys/mod.rs:113-118`），而那份文档**明写
  心跳属于无来源声明的路径**、缺省落本机用户。改它是 [D-067](067.md "D-067") 的账，不在这里顺手改
  （由此暴露的一条既有不一致登记在后果末条，有名有姓有归属）。

键名与 `kind` 取值**单点定义在 core 的事件词汇表**（与 `actors/autonomic.rs:35` 那个 `"scheduled"`
字面量同一个来源，收进 `symbio_core::event`）：`meta` 是自由 JSON，键名拼错编译器管不到，
生产方与消费方各写一份就是两条漂移的口径——同一条纪律见 `transcript/supplements.rs:47`。

**裁决三：#4/#5/#6 定形之后，片的边界就只剩「调度 + 声明」。** 一片要交的声明是三件：
`traverse` put 两行（Tool 行 `heartbeat`、Option 行 `heartbeat`）、`build` 起一条常驻循环、
`stop` 交句柄（P1 的现成形状）。此外它对世界只说两句话——`list` 一次、`write` 一次。
它不再持有 `Weak<SessionPlugin>`（`tools/heartbeat_tool.rs:31`），#3/#6 两段代码从它里面搬走。

## 否决的替代方案

- **给宿主加一条端口 trait，让片调 `record_trigger`**：最直接的走法，也是 D-075 裁决二否过的同一种
  账——端口要跨插件可见就只能进 `symbio_core`，而 core 的 `pub trait` 数被 CS-001 冻成**只降不升**；
  拿影响面最大的模块变宽去付一片的方便，正是那条纪律要拦的。更何况这条端口传的是**存储内部的写窗口
  纪律**，本就不该跨边界可见。
- **改走路由臂（`session/heartbeat/trigger`）**：输入面双轨刚随 D-066 / T-077 步② 收成单轨，
  `SessionPlugin::route` 现在只剩 `stats` 一条非 CRUD 臂（`plugin.rs:626-641`）。为心跳再开一条
  ＝亲手把刚拆掉的双轨装回去。
- **新增一个 VDFS 动词**（`trigger` 之类）：动词集是闭集（`plugin/words.rs`），而「请开一轮」在地址面
  上的名字**就是**写收件箱（`vdfs_provider.rs:628-646` 的模块说明：写入即入队，跑不跑由空间自己决定）。
  新动词不增加表达力，只多一份要和 `write` 对账的语义。
- **落格留在片内、失败就不入队（保住今天的进程内时序）**：那就是把 #3/#6 留在片里，
  「不再 `use super::` 宿主私有项」这条判据当场不成立——切分白做。
- **落格改到消费期**（`run_inbox_turn` 开轮前，`transcript/inbox.rs:566-601`）：会把失败落在一支
  FIFO 队列的**队首**。一条永远跑不起来的头连同后面的用户消息一起堵死（消费规则 1「FIFO」，
  `inbox.rs:24`）；而今天的形态是「没落格就根本不入队」，重试发生在调度侧、每个 tick 一次。
- **把 `heartbeat/` 整体搬成一个新目录就算切完**：D-075 的否决段已说过「先搬目录再补卸载」，
  更强的理由在于——整搬会把 #6 一起搬走，于是新插件比旧模块**更深**地持有宿主的私有项
  （`active_mgr` + `storage_dir` + `config`），目录动了、判据反而更远。

## 后果

- **施工顺序：先迁落格，后切片。** #5/#6 先动（把落格与参数推导搬出心跳，**行为不变、片还在原地**），
  #1/#2/#4/#8 后动。理由：钉着这段行为的四条用例（`transcript/autonomous.test.rs`——无事实源 /
  有活写方 ⇒ 不触发、闸门默认关、长目标每 goal 只开一次、过宽目标被拒）应当在**搬动之前**就先跟着
  新的写窗口入口跑绿；搬完再改判据就分不清坏在迁移还是坏在切分。对应
  [T-167](../009-task/167-会话插件切分.md "T-167-会话插件切分") 施工批次的 **2a**（迁出落格）与 **2b**（切片 + 守卫）。
- **2a 的边界修正：core 一行都不动。** 上面那条顺序里，「落格进写臂」的**标记词汇表**（`meta` 键名 +
  `kind` 取值）与写臂的识别分支**不在 2a**：新增的 core 公共符号在 2a 只被 `plugins/session` 一个消费
  单位用到，而 `scripts/core-export-audit.mjs` 的 **C-003** 把「根出口的公共符号必须 ≥2 个消费单位」冻成
  只降不升的棘轮（消费单位按 `plugins/<插件名>` 目录归一，同一插件内多处引用只算一个；真豁免的账本见
  [SP-027](../008-spec/027.md "SP-027")）——**单消费方的符号不是架构元素**，把它放进 core 公共面就是拿
  棘轮付实现面的账。于是 2a 只做「同插件内的搬家」：#6 落进 `transcript/autonomous.rs` 的
  `request_autonomous_round`，#5 的参数推导同时搬进入口（调用方不再随身带 `mode` / `include_history`，
  由服务端按会话 metadata 推导），写臂分支留到 2b 复用同一个入口。
- **标记词汇表的归属由「第二个消费单位在哪」决定，2b 必须先答这一题**（上面那条的推论，也是
  裁决二末句的口径修正）：`unitOf` 只认到插件目录那一层，所以**心跳片若仍住在 `plugins/session/` 里，
  producer 与写臂永远算同一个单位**，那条标记就名正言顺地留在插件内、一辈子不进 core；只有切片把
  调度半放进新的插件目录（`plugins/<名>/`，经 `parent.get_vfs_provider()` 走地址面），
  「≥2 消费单位」才成立，词汇表才升进 core 的事件格子旁。**裁决不变，落点随这一题的答案走。**
- **守卫判据的落点**（补 D-075「判据机械化」缺的那一半）：一条用例钉**运行期**卸载 `heartbeat` 片
  ⇒ 下一轮收集里 Tool 行 `heartbeat` 与 Option 行 `heartbeat` 都不在、其余行仍在、该片常驻句柄
  `is_finished()`、且 session 侧 `vdfs/list` 与 `write inbox` 照常。停用侧的后半已由 P1 的
  `plugin.test.rs::stop_terminates_resident_loops` 钉住，前半由这一条补上。
- **#7 消除的代价，指得出场景**：去掉 `mark_activity` 之后，「用户消息已处理、但这一轮零写盘退出」时
  空闲基线回落到 `updated_at`（回合开始之前），心跳会在下个 tick 判定为空闲而触发一轮。这条路径要求
  失败收敛的持久化也失败（`:209-215` 自己列的那种），而那种会话此刻**确实没有任何落盘活动**——
  触发一轮不是错。基线仍是双保险（`max(锚点, updated_at)`），丢的只是第三种下限。
- **两处注释会随之过期，要同批改**：`subagent.rs:369-370` 与模块头 `subagent.rs:25` 今天都拿
  「引擎会话内的心跳走进程内 `enqueue_inbox`」作对照项；#4 落地后那个对照项不存在，对照变成
  「同机模块 vs 跨作用域写者」。留着就是给后来者指一条已拆的路。
- **登记的既有不一致（不改）**：心跳轮的触发事实 actor 是 `PRINCIPAL_AUTONOMOUS`
  （`actors/autonomic.rs:32,46,60`），而这一轮轮末 `commitment.*` 的 `to` 落**本机用户**
  （`v2_exec.rs:1338` 经 `request_source_principal` 回落缺省）——同一件事在事实层里两种来路。
  归 [T-167](../009-task/167-会话插件切分.md "T-167-会话插件切分") 收尾批次裁决；判据是先把
  `commitment.*.to` 的现行读方查清（`to` 从调用点常量变成数据是 [D-067](067.md "D-067") 立的，
  改它的取值不进那条账就是漂移）。
- **core 与机制面**：2a 零新增符号（见上面「2a 的边界修正」两条）；标记常量是否进 core 由 2b 的
  切片落点决定，形态仍是**两条常量**（`meta` 键名 + `kind` 取值），零 trait、零 `fn` 成员
  ⇒ CS-001 三格不动；机制键零新增（守恒律审的是 DE-001 §8 那 10 条，常量不在其列）。
  施工全部落在 `plugins/session` 与一片新目录。
- **`impl` 档位说明（`done`）**：八口逐条落位，2a / 2b 两个批次都已落地。#5 的参数推导与 #6 的落格
  在 `transcript/autonomous.rs::request_autonomous_round`（写臂对 `meta.trigger` 的识别在
  `plugin/nodes.rs::trigger_declaration`，落格失败 ⇒ `Conflict`、不入队）；#1/#2/#4/#7/#8 随调度半
  进 `plugins/heartbeat`——会话列表与 `is_working` 折进 `vdfs/list` 的节点、入队走
  `write(<会话>/inbox)`、空闲锚点归片自己的调度状态、设置工具与选项族那一行由片自己贡献。
  #3（`preempt` 无投影）不需要动，它随落格留守在会话侧写窗口里。
  标记常量的 core 形态与**切片落点**由 [D-077](077.md "D-077") 裁定——本条只点名「落点在哪」是
  一道新的形状裁决，不在施工批里顺手定。
