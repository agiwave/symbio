## 决策

**决策**：`V2Mode` 的 `#[default]` 由 `Bridge` 改为 `Full`，并**退役 `bridge` 档**——
转写路径（`record` / `record_to_wal` / `authorize_close` / `first_user_utterance` /
`last_assistant_text` / `V2Closure`）与只服务于「跳过它」的 `TurnState::v2_executed`<!-- doc-symbol-allow: 记名的是本决策删除的桥用字段，不存在正是决策已落地的状态 -->
一并删除；`v2_bridge.rs` 收缩为只剩派生事实写入两个函数，改名 `v2_facts.rs`。
`full` 档的覆盖面 = **全部轮次**（无工具轮 / 工具轮 / 审批与问答恢复，恢复续写同一
`turn`、用户格不重开）——`PL-008-工具轮v2化实施方案` 批 1 / 2a / 2b 全部落地。

**理由**：

1. **`full` 是唯一能兑现 v2 承诺的档位。** v2 的立身之本是「prompt 从事实网格投影
   出来，而不是另存一份对话副本」——这永久消灭了「转写与对话漂移」那一整类 bug。
   留在 `bridge` 上等于把 v2 钉在旁路位置：**它永远不会被真实负载压到**，缺口也就
   永远不会被照出来。现在把出厂默认从 `bridge` 翻到 `full`，让 v2 上真实负载。
2. **`bridge` 是过渡设施，不是终点形态。** 它的职责只是「在 v2 引擎切换完成前，把生产流量经转写先喂进事实源」——`full` 落地即其退役条件成立。把它留作出厂默认 = **过渡态永久化**。
3. **事实源是同一份，读侧零改动。** v2 原生入格写的 `<会话目录>/v2-events.wal` 与桥写的是同一个文件、同一常量（`paths.rs` 的 `V2_WAL_FILE` 单源），`session/stats` 一行不改。桥在 `chat_loop.rs` 的 `!turn.v2_executed` 处已被正确跳过 ⇒ **同一轮不存在两份记账**（那是假象，不是冗余）。
4. **`full` 档的难处已经补齐。** 流式 UI 帧通道原先无界（`on_delta` 是同步回调、传不回背压），已换成有界队列：满时**合并增量**而非丢帧——`Finalize` 丢一次正文节点永远转在「流式中」，`Snapshot` 丢一次那轮正文整段消失，所以丢帧不是可选项。

**被否决的方案**：

- **保留 `bridge` 档作回退旋钮**：否决。回退旋钮的前提是「`full` 已经跑过真实负载、缺口已被照出并修完」——事实相反：在 `full` 还没被真实负载压过时，`bridge` 恰恰是**缺口能一直活着的条件**（它们在 HEAD 就存在、门禁全绿，因为门禁跑的是 `bridge`）。过渡态的代价不是「配置项多两个」，是「v2 永远得不到验证」。
- **保留 `bridge` 档、等缺口修完再退役**：否决。这与上一条是同一动作的两种时机，代价相同（v2 继续留在旁路、继续不被压到）。既然要退役就一次退役干净，把缺口在 `full` 上修完。
- **给快路另找一个不依赖 `full` 档的落点**：否决。快路要跳过的**正是「v2 运行器里那一次模型调用」**；把它挂到 v1 链路上等于**新写第二条执行链**，而 `v2_exec` 的模块文档明确划界「它不是『又一条执行链』」。为一个开关的可达性去造第二条链，代价与收益不成比例。
- **同时把 `skill_fast_path` / `skill_compile_enabled` 也改默认为 `true`**：否决——这是第二个、独立的行为改变（命中时以技能正文收束、**一次模型调用都不发生**），且它的 `false` 默认带着成文理由（「不加速」是安全退路口）。两处行为改变捆进一批就**没法只回退其中一处**。若确实要出厂即产反射样本，另立一批。
- **把补充塞进运行器的 `exchange`（就地累积）**：否决。那样模型看得见，但它**永久丢失**——`session/stats` 与 transcript 都没有，与 [D-044](044.md)「实测与判据同源」相反。用户补充是**用户确实说了这句话**，它是事实，不是请求级的临时物。
- **改写原 `user.message` 事件**：否决。append-only 与 N3「每轮一条」的组合不允许「已落的事实可变」。

**后果与不变量**：

- **影响面**：`v2_mode` 是**实例配置**。显式写过 `v2_mode` 的实例**完全不受影响**（`serde` 读的是已落盘的值）；没写过的取新默认 ⇒ 影响面 = 「未显式配置的实例，从下一次轮次起走 v2 执行链路」。**既有会话不需要任何迁移**——它读的是同一个 key。
- **反射档样本仍为零，且本 ADR 解决不了。** 反射档要**三个开关同时开**：`skill_compile_enabled`（产出已编译技能）→ `skill_fast_path`（`fast_armed`）→ `v2_mode = Full`。出厂三个默认值 `false / false / bridge` **全部关着**，本 ADR 只开第三个。档位由**令牌类型**给出（`RuleOnly ⇒ reflex`，`run_reflex` 只收 `RuleOnly`），所以没有反射令牌就没有 `reflex` 事件，`session/stats` 的 reflex 桶恒零。
- **13 号 P3 原登记的出口判据建立在一个错误前提上**——它假定「翻 `v2_mode` 一处就能解锁反射档」，实际不能。判据随之改为：**出厂档位下 `session/stats` 的兜底率与时延按 tier 分桶有样本**（`deep` 桶有样本、`unspecified` 不静默吞），反射档产样本另立一批。
- **v2 事实桥降为兼容层**：只在 `off` / `bridge` 档运行。
- **不变量**：`V2_WAL_FILE` 仍单源；同轮不两份记账；`declared_tier` 归属判据不变（`full` 档未命中快路时仍是 `deep`）；流式通道有界（合并而非丢帧）。
- **「v2 让 agent 更强」目前是未验证的假设。** 本仓**没有任何度量能回答「prompt 的呈现方式对模型是变好还是变坏」**——没有 prompt 格式的 A/B、没有工具调用成功率的统计。这不构成回退理由（v2 的架构收益是实在的），但意味着**在补上等价性判据与一份 prompt 形状基线之前，不该基于「更有效」去翻任何默认值**。
- **本仓缺的那类守卫**：**「同一负载跑两条执行路径、比对模型实际看到的内容」**——三个静默缺口在 HEAD 全绿的直接原因就是没有它。已按 [D-048a](048a.md) 补上双向完整性防线，判据住 `symbio/src/symbio_core/projection/prompt_fidelity.rs`（模块文档记其形态与「为什么便宜到每轮都跑」）。
