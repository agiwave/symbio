## 决策

授权面的两处 fail-open 默认翻成 fail-closed，使
「**少一行是一条拒绝，不是一条漏判**」成为全表唯一口径：

1. **`authz::matrix_for` 的派生分支删除**。未登记的 `session/<id>`（子智能体 / 对等体）
   与 `person/*` / `system/*` 同款处理：表里没有它的行 ⇒ 每个谓词为假。要能写自己的
   收束格，就必须在 `authz::ROWS` 里有自己那一行——**窄行是唯一入口**。随之
   `matrix_for` 与 `production_matrix` 合并为一个取表口（同一条需要只允许一种取得方式，
   [DE-014 §2.2](../004-plan/014-单环一表收敛.md "DE-014-单环一表")）。
2. **`GrantsOverlay::is_revoked` 对认不出的能力名不再放行**。查询侧的能力名不在
   `Capability` 闭集内 ⇒ 告警并按**已收回**判；变更流水里带认不出能力名的**收回**项
   对该主体的任何能力查询都按已收回判（一次笔误的收回不得静默落空）。

依据：[T-177-授权与声明面fail-closed批](../009-task/177-授权与声明面fail-closed批.md "T-177")。

### 被推翻的旧口径（记录出处，不是变更史）

- [`authz.rs`](../../symbio/src/symbio_core/authz/mod.rs "authz/mod.rs") 派生分支的注释口径
  「身份分层 ≠ 权限分层（S08 §4 平凡值）：未登记的 `session/<id>` 派生主智能体那一行」
  ——它保的是「子智能体写得了收束格」这条**可用性**，代价是把「忘配窄行」变成一次
  **静默超权**（拿到 `reply.*` 整套），而十条窄行（自主 / 判定 / 对等 / 市场 / 仲裁 /
  守门 / 工人 / 规划 / 验证 / 工具）全靠纪律维护，没有判据钉住「下一个新角色配了行」。
- `GrantsOverlay::is_revoked` 的注释口径「认不出的能力名 ⇒ 未收回——不把载荷的拼写
  错误读成一次静默撤销」——它把笔误的**收不回**当成可接受面，与其余 fail-closed 面
  （`from_names` 认不出即拒绝构造、未登记主体无行即拒）相反。

### 代价（诚实划界）

- 新的子智能体 / 对等体**不登记就写不了收束格**：可用性由窄行登记承载，不再由派生
  兜底。这是有意的交换——少一行的后果从「超权」变成「办不成事」，后者会被看见。
  **本条之后的可用性补齐**见 [D-100](100.md "D-100")：会话创建点把会话主体登记进
  绑定面（根会话继承**会话面缺省行**、委派子会话继承**父行**）——给权仍需一次**可见的
  登记动作**，只是这次动作从「部署配表」扩到「会话创建点绑定」，fail-closed 的方向不变
  （既未部署、又未绑定 ⇒ 每个谓词仍为假）。
- 认不出能力名的收回项按该主体整体已收回判，是**宁红不漏**：极端情况下一次载荷损坏
  会让该主体暂时什么都做不了，但不会让一次本该生效的收回静默消失。

### 不在本条范围

工具自声明行为位的漏声明（`decls` 三闸）由基线判据钉住，是**判据补强**不是授权语义
变更，落在 [T-177](../009-task/177-授权与声明面fail-closed批.md "T-177-授权与声明面fail-closed批") 内，不另立 ADR。
