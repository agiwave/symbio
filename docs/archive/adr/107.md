# D-107：外环驱动器的施工前提

## 决策

1. **终点不变**：DE-014 §2.1 的 `fixpoint(decide) over 事实日志` 仍是目标。本 ADR
   不裁终点，只裁外环的施工路径。
2. **DE-021 §5 动作 A 的三步在现形态上不施工**：A1（五个 `LoopState` 构造器合并为
   一个 `project`）、A2（半判据 → 全判据）、A3（七步直线代码 → `loop { project →
   decide → execute }`）一并推迟。[D-088](088.md "D-088") §2（`Step` 五值无生产者）
   与 §4（四条不做，含不合并构造器）继续有效；§3「drive 不成立」的**适用面收窄**为
   「一次性阶段的事实缺席时，外环 drive 不成立」。
3. **理由是一条可验证的结构事实：一次性阶段的谓词在 drive 里没有「转假」的来源**。
   行表回答的是「这一格要不要进这条产线」，不是「这一步做完没有」。三行是常真谓词：

   - `policy.classify`：`round == 0 ∧ has_utterance ∧ enabled` 在一轮内恒真
     （`turn.request_round` 只在收轮后 +1）——drive 的下一次迭代会再次命中，
     答话 / 升级会被反复执行；
   - `policy.recall`：`round == 0 ∧ has_facts` 同理；召回只写 `TurnState::recall_view`，
     不落任何事实；
   - `policy.compress`：`auto_compress` 是开关不是水位；水位在内核里，未过水位时
     `auto_compress_process` 返回 `Ok(None)`——drive 会反复调用一个 no-op，
     直到撞上兜底步数上界。

   要让谓词转假只有两条路：①给 `LoopState` / `TurnState` 加「本步已做」簿记——
   DE-014 §2 明文禁止的第二份状态；②把「已做」落为事实——这是终点方向，但它是
   **机制变更**（新增事件格），不能夹进一次自称「纯结构」的 A1/A2 里。
4. **层级也错位**：五格里 `round_boundary`（`policy.report`）的提问点在 `turn_exec`
   的轮边界闭包里，`reflex` 在 `turn_exec/assemble`；它们不是外环七步的决策点。
   把外环改成 drive 不会让这两格变成外环的一步，只会让内外两环各有一套时机。
5. **路径改判：先事实、后循环**。阶段输出（尤其 `verdict` 判决事实）与一次性阶段的
   「已做」必须先落为事实；每行满足「执行后下一次问表必须 `Declined`」之后，drive 才
   作为独立批次重新裁决——届时可能直接与内环合一，而不是先造一个粗粒度外环再拆。
6. **不做的具体项**：不合并五个构造器；不新增 `Step` 五值；不为 A2 新增事实之外的
   任何口子。DE-021 §5 动作 A 与 §8 的 A1/A2/A3 行改标「推迟（D-107）」，
   「A1 必须早于 A3」的顺序约束随本 ADR 失效。

## 为什么这不是「实现困难就改架构」

- 若只是难，合法动作是发起一次架构讨论；本 ADR 就是那次讨论的产出，不是绕路记录。
- 判据不是「难」，而是 **A2 的语义前提不成立**：一行的事后状态没有任何事实可读。
  `policy.recall` 今天写不出「本轮已召回否」——这与 DE-014 §5 步骤 3 把「记忆 / 技能
  拆两行」推迟是同一个原因（`loop_registry` 模块文档已写明）。
- 终点没有被放弃：事实就绪后，A2 变成「读事实」，A3 变成「删掉直线代码」。先落事实
  是把终点所需的材料备齐，而不是把终点改成另一个形状。

## 与 D-088 的关系

| D-088 | 本 ADR |
|---|---|
| §1 `Capsule` 闭集 | 保留 |
| §2 `Step` 五值无生产者 | 保留（本 ADR 不引入 `Step`） |
| §3 阶段之间有数据依赖 ⇒ `drive` 不成立 | **收窄**：在一次性阶段的事实缺席时成立；事实就绪后须重审（数据依赖届时由输入 / 输出事实承载） |
| §4 四条不做 | 保留；其中「不合并五个构造器」继续有效 |

|---|---|---|---|
| 1 | 每个 `Capsule` 变体至少被一条内建行产出 | `loop_registry.test.rs::every_capsule_has_a_producing_row`（遍历 `Capsule::ALL`） | 本 ADR 落 |

## 代价与失效边界

- **代价**：策略表继续是「每格一行」的过渡形态，加一个新时机仍要改 5–6 处
  （DE-021 §2 的账）。这是已知且被接受的代价，直到事实就绪。
- **失效边界一**：若事实补全后某行仍无法转假（例如 `policy.compress` 的 no-op 语义），
  该行需要拆成「判定行」与「执行行」——那是策略目录的语义变更，届时另裁。
- **失效边界二**：若 T-189 最终证明阶段行无法脱离直线位置表达（它自己的熔断线），
  drive 的路径需要再次讨论——不得把判据写残来凑形状。
