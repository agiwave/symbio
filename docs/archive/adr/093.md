## 决策

策略表（`plugins/loop/loop_registry`）加上「格」这个维度，四处同时落：

1. **`Site` 是闭集枚举**（`TurnHead` / `RoundBoundary` / `Compress` / `TurnPrepare` /
   `Reflex`），与 [`Capsule`](../010-adr/088.md "D-088") 同一条纪律：加值必须改枚举，
   `name()` 的 `match` 会编译错误。
2. **`Row` 多一个 `site` 字段；`prio` 的唯一性从全局收窄到格内**。跨格共用一个
   `prio` 不是冲突（它们从不在同一次判定里相遇），同格重号仍然启动期 fail-fast。
3. **`LoopState` 从「十个字段的并集 + `blank()` 填假值」改为按格分形的枚举**，
   五个变体各带自己那几格的字段。**这一条是核心**：它让「行只读本格字段」从
   一条要人读五个构造器确认的约定，变成编译错误。
4. **`decide` 只扫本格，格由 `state.site()` 自证**（调用方不必另传），返回值从
   `Option<Hit>` 改为 `Verdict` 三值：`Hit` / `Declined { rows }` / `Unmanned { site }`。

这不是新机制：不增机制键、不增 trait、不增插件 id、不增 `pub` 面（`Site` 与
`LoopState` 都是 `pub(crate)`）。与 [D-089](../010-adr/089.md "D-089")
「一个行形状 + 两个目录」不冲突——改的只是**策略目录**里行的形状，能力目录未动。

## 背景

DE-014 §5 步骤 2–3 已把五个决策点的判据搬进表，但「这一行属于哪一格」只活在
**调用点的隐含约定**里：`chat_loop` 用 `turn_head` 构造的状态、期待 `Decide`；
`progress` 用 `round_boundary`、期待 `Report`。表本身读不到这层信息，于是四条
横向扩展的摩擦同时存在。

### 摩擦一：`prio` 被迫全局唯一，同格加第二行要挤全局编号

`put` 的判据是 `rows.iter().find(|r| r.prio == row.prio)`——**全局**取第一个同号者。
内建五行是 10 / 20 / 30 / 50 / 60，每格恰好一行，所以这条从未暴露。

但 DE-014 §5 步骤 3 明确写着「记忆与技能拆成两行推迟」。一旦要拆，两行同属
`turn_prepare` 格，而新行必须从全局编号空间里挑一个没被占的数。「同格两行谁先」
与「两格撞号」根本不是一回事，用同一个判据挡会把前者误判为冲突——判据错了
一个作用域，代价是每一次同格扩容都要先做一次全局协调。

### 摩擦二：每格扫全表，4/5 的判定是陪跑

五格各问一次 ⇒ 25 次判定，其中 20 次是本格之外的行。数字上不算贵（`fn` 指针 +
布尔短路），但它掩盖了下一件事。

### 摩擦三：`None` 三义不分，「某一步怎么没发生」无从下手

DE-014 §3 规则 g 写着「`decide` 返回 `None` 意味着规则缺口，必须可见」。
但调用点看到的 `None` 有三种成因：本格有行但都不认领（正常）、本格一行都没有
（配错）、不属于任何一行（结构上不可能）。而 `chat_loop` 的日志只在 `Some` 时打，
于是前两种在日志上长得一模一样——正是规则 g 要防的「静默 quiesce」。

### 摩擦四（最硬的一条）：假值把「不适用」混进了数据

五个构造器共用一个十字段的 `struct LoopState`，各自只填自己那几格，其余用
`..blank()` 兜底。于是 `round_boundary` 里 `has_utterance = false`、`classify_enabled
= false`、「`progress` = `ProgressPolicy::disabled()`」——这些 `false` 不是「用户没说
话」，是「此处不适用」。

它当时是对的，靠一句推理自证：`round > 0` 本来就挡得住 `policy.classify`。
但那是一条**每次加字段、每行改判据都要重新复核**的推理。一旦某行读了一个别格
没填的字段，它会静默按假值判定——不崩、不报、日志看不出。这类失效形态是本仓
反复点名的「沉默」，而它的防线只有「读代码的时候注意一点」。

## 为什么 `prio` 的作用域要改，而不是加一个 `group` 字段

加 `group: u32` 与 `prio` 并存等于把「格」编码成两个数，而两者必须同步——
多一个可以漂的字段，就是多一个漂移面。`site` 直接是那个概念本身：它是闭集
枚举（拼错是编译错误），同时充当 `decide` 的过滤键与日志里的格名。

## 为什么 `LoopState` 用枚举而不是每格一个 struct

每格一个 struct 才是「最干净」的（`TurnHeadState` / `RoundBoundaryState` / …），
但 `Row.decide` 是 `fn(&LoopState)`，一张表要装五种签名就必须引入泛型或 trait
object——前者泛型传染，后者回到运行期检查，两条都撞 CS-001 的形状账
（[D-089 §1](../010-adr/089.md "D-089") 已在同类问题上裁过）。

枚举是这两条之外的第三条：**一个类型、五种不可互换的形态**。`decide` 收
`&LoopState`，每行开头 `let ... else { return None }`——变体不对就走不到判据，
而这正是「行只读本格字段」的编译期表达。`else` 分支不是路径而是兜底：
`decide` 已按 `state.site()` 过滤，走到 `else` 说明这一行的 `site` 与判据接受的
变体对不上（改错常量表），由 `every_row_is_reachable_from_its_declared_site` 在
CI 拦，不在生产里 panic。

## 判据（全部可执行，`loop_registry.test.rs`）

| 判据 | 用例 | 反证方向 |
|---|---|---|
| 每格都有行 | `builtin_rows_are_conflict_free_and_ordered` 断言 `unmanned_sites()` 为空 | 删掉任一内建行 ⇒ 红 |
| 每行从它声明的格可达 | `every_row_is_reachable_from_its_declared_site`：全条件满足时必须 `Hit` | 把 `policy.report` 的 `site` 改成 `Compress` ⇒ 实测红（`Unmanned { site: RoundBoundary }`） |
| `decide` 只扫本格 | `decide_only_scans_its_own_site`：别格放一行恒返回 `Some` 的行，本格结论仍是 `Unmanned` | 改回扫全表 ⇒ 拿到 `Hit(policy.bomb)` |
| 跨格同 `prio` 不冲突 | `same_prio_in_different_sites_is_not_a_conflict`：五个内建行 prio 全 10 | 改回全局唯一 ⇒ 表自己注册不进来 |
| `Unmanned` ≠ `Declined` | `declined_and_unmanned_are_distinguishable` | 把两者压回 `None` ⇒ 红 |
| 构造器与格不错位 | `call_of_matches_its_site`：`LoopState::xxx().site()` == `xxx` | 换错变体 ⇒ 红 |

「行只读本格字段」**没有对应用例**，因为它已经是编译错误——一条能被编译器拦下
的东西不该再花一个测试去守。这是本 ADR 相对「哨兵用例」方案的净收益：少一个
要维护的 `Field` 名册、少一个会与构造器漂的 `site_fields` 表。

## 代价

1. **每行开头多一次 destructure**（`let ... else`）。换来的是判据里读不到别格
   字段——不是"读了但没用"，是写不出来。
2. **`round` 出现在三个变体里**（`TurnHead` / `RoundBoundary` / `TurnPrepare`）。
   这是同一个语义三处取值点，不是三份状态：这三处本来就要各自回答「此刻算不算
   轮首」，而答案的来源不同（请求数 vs 运行器工具轮数）。
3. **格是闭集**：加一个决策点要改 `Site`（枚举 + `ALL` + `name()`）与 `LoopState`
   （变体 + 构造器 + `site()`）。这与 `Capsule` 同理，是想要的——格是环的**决策点
   清单**，不是插件可自由扩展的注册项。
4. **`ProgressPolicy::disabled()` 随之删除**。它只为 `blank()` 而存在（「轮首用」的
   汇报快照），枚举化之后 `TurnHead` 变体根本没有 `progress` 字段。

## 失效边界

- 出现**同一格内多行需要基于彼此结论仲裁**的需求（现在只有「先命中者胜」）。
  `prio` 表达的是全序，表达不了「A 命中则 B 让路」这类依赖；届时需要的不再是
  格内序号，而是格内的一次 fold——属 `drive` 的范畴。
- 若两格开始**共读同一个字段**（例如轮边界也要看 `has_utterance`），枚举会逼出
  一个选择：要么在变体里也加这个字段（说明它确实是两格的共同前提），要么建一个
  第三格。这个摩擦是**信号不是噪音**——`site_fields` 式方案会静默允许共读。
- `drive` 落地后 `Site` 与 `LoopState` 的枚举都消失：`store.project()` 只产出
  「当前步需要的量」，格由投影位置隐含。届时本 ADR 状态改为 `superseded`。
