# D-105：投影预算语义收敛到框架层

## 决策

`Projection` 闭包形状从 `Fn(&[Event], Timestamp, Budget) -> View<V>` 收为
**`Fn(&[Event], Timestamp) -> V`**：闭包只产出视图值，「可降级」与「预算」由
[`Projection::apply`](../../../crates/symbio-core/src/projection/mod.rs) 统一执行——

- `budget.ms` 为**输入侧扫描窗口**：1 事件 = 1ms（沿用 recall 的记账口径），下限 1
  （「空且不标降级」永不出现）；
- 超窗只把**切片头部**交给闭包：调用方给定的切片顺序就是它的事件主张顺序，窗口只截尾
  ——recall 旧配额的「按序扫、扫满即停」由此归位成同一处；
- 截断 ⇒ `degraded = true`，`used.ms` = 窗口实际长度；
- 平凡预算 `Budget::generous()`（全部生产调用方的现状）⇒ 窗口 = 全量 ⇒ 行为与
  框架接管前逐字一致。

## 为什么

改造前 19 处 `Projection::new` 闭包里，每一处都要自己回答「我要不要置 `degraded`、
预算怎么记账」——这份决策收敛成框架里的 **1 份**，投影作者没有自觉可用：

- recall 是唯一真有配额语义的投影，它的扫描逻辑（`scanned` / `quota` / 降级计数）
  是闭包里的私账，外壳与视图两处承载、靠 T-104 的誊抄纪律维系；
- 其余 18 处闭包拿着 `Budget` 形参只为把它原样塞回 `View::used`——记账是假的，
  「预算」只是一个必须转手的行李。签名里留着它，等于给每个新投影出一道
  「假装决策」的必答题。

选**输入侧**窗口而非输出侧裁剪：框架不知道 `V` 的形状，只有输入侧能在不新增
trait / 不回调闭包第二 run 的前提下统一执行。选**截尾**不截头：切片顺序是调用方的
事件主张顺序，recall 旧路径的扫描序与它一致——语义无漂移。

## 视图字段 `degraded` 的归属（T-104 的收口）

闭包不再自置 `RecallView::degraded`（恒 `false`）。视图脱离外壳流动时的自描述
由**取值点**从外壳誊抄——`memory_events::recall_view` 是唯一丢外壳的取值点，
也是唯一誊抄处（超配额的降级视图由 `prompt_section_says_degraded_instead_of_pretending_completeness`
钉住）。外壳是唯一的降级事实源，视图字段是它的出口副本。

## 否决的替代

- **保留三参签名，只把 recall 改对**：19 份决策照旧 19 份，下一个投影作者仍要
  自己发明记账——缺陷是机制面的，单点修复治不了。
- **输出侧裁剪（闭包算全量，apply 砍结果）**：框架必须理解 `V`（砍什么、留什么），
  要么加 trait 要么白算全量——两条都违背「最小机制」。
- **闭包返回 `(V, used)`**：记账仍散在各处，只是多了一道转手；`degraded` 的
  决策没有收敛。

## 后果

- 13 个产投影文件的闭包签名收窄；`mutations` / `rebuild` / `turns` /
  `prompt_fidelity`（共享读侧，不含 `Projection::new`）不受影响。
- `View::ok` / `View::degraded` 构造器随闭包签名一并退役——`View` 只由 `apply`
  构造（字段私有的同款思路，构造面归一）。
- 新增静态守卫 `scripts/projection-purity.mjs`（PP-001…003）：产投影不读产投影兄弟
  （L2）、禁隐式全局依赖、构造器必须有投影外生产消费方。二级纯净性从
  「verify 样本自证」升级为「生产目录被扫」。
- `reputation_with` 构造器无投影外消费方，按 PP-003 删除（打分平凡值
  `plain_score` 留在闭包内；`ReputationScore` 类型随之退役）。
- [DE-001](../004-plan/001-核心架构.md "DE-001-核心架构") §1.4 的冻结锚点 F2
  与 §1.4.1 的两级强制表同步改写。
- core 三格不变（闭包是固有实现的形状，不动 `pub trait` 面）。
