## 决策

**背景**：用户视角的前端原则是**一个会话线程对应一个显示区域**。现状（实施于
PL-007 的 S5 步）：`dialog_panel_split` 开启时`ModelChatPanel` 把**同一条会话转写**
渲染成两列——左「对话」（对话线投影）与右「工作」（根级补集）。两列是**同一批节点的
两种读法**（分界判据的前端镜像与后端 `conversation_view.rs` 是同一判据的两个消费方，
不是两个数据源）。

本 ADR 回答三个被这个现状逼出来的问题（分析过程见 [T-069-前端会话机制分析与优化](../009-task/069-前端会话机制分析与优化.md)）。

### 2.1 现有体系是否支持一个会话内多条实际会话线程——**不支持，也未计划**

会话内的「实际会话线程」（可各自交互、各有一条 LLM 轮链）在 v2 机制下的身份只有一条：

- **输入只有一个入口**：收件箱（`inbox`），FIFO 消费；忙时的插话由
  `PreemptionDecider` 判定挂起（t34），轮与轮之间是**串行**的，不是并行的线程；
- **写者只有一个**：WAL 写者令牌独占（`wal.rs` 的 `<wal>.lock`）——两条并行写线
  结构上就冲突；
- **一个会话一条转写**：`seq` 单点分配、终态收敛、压缩是**整会话上下文的一次**操作，
  三者都以「一条线」为前提；
- **多主体不是多线程**（t30）：主体是把任务委托给子智能体时的**请求包归属**属性，
  轮链仍属父会话；
- **子智能体空间的会话自驱动**（[[D-026|D-026]]）：第二条对话线以**子会话**的身份住在
  自己的空间里（`<根>/agent/<id>/session/<sid>`），**不进父会话**。

结论：「一个会话里多条线程」**没有 owner，也没有承载它的机制**；它不是一个缺口，
而是与单写者 / 单转写 / 单压缩三大前提直接冲突的形态。

### 2.2 多实线对话该放哪——**各自独立会话（或子智能体空间），不在一个会话内裂开**

要「另一条可交互的对话线」时，另起新会话；要「委托一条线给另一个智能体」时，
走子智能体空间（D-026，它的第二条线生来就在子会话里）。理由：

1. **机制面代价不成比例**：把一个会话裂成多线程，意味着把user-role 收件箱、WAL
   写者令牌、`seq` 分配、终态收敛、压缩水位**全部按线程一变多**——这五处全是
   改宽要挂 ADR 论证的机制面（[SP-003-分步实施计划](../004-plan/006-分步实施计划.md) 纪律 3 / core 形状棘轮）；
2. **产品价值已有覆盖**：用户真正要的「并行聊两条题」= 开两个会话（前端会话清单
   平铺本来就是平的）；「同任务多智能体并行」= 子智能体空间 + 多执行器（PL-009）；
3. **一个会话一条线让显示区域天然一一对应**：一个会话（一条线程）⇒ 一个显示区域，
   不需要任何前端机制去「区分哪个区域属于哪条线」。

### 2.3 呈现裁决——**分栏退役，工作过程并入同一窗口**

现状的两列违反「一个会话线程一个显示区域」：它们是**一条线被渲染成两个区域**
（不是两条线），而 §2.2 已裁决不要把后端裂成两条真线。因此：

- **呈现合流为单窗口**：完整转发时间轴直排（工具过程保持既有的嵌套折叠形态）。
  分栏**关闭**时的 `ModelChatPanel` 已然是这个形态（AR-024 §4.4 / §5 描述的就是它），
  分栏退役即回归已验证的单列行为；
- **`dialog_panel_split` 呈现开关退役**（实施见 [T-070-会话呈现合流单窗口](../009-task/070-会话呈现合流单窗口.md)）；
- **数据层不动**：[[D-041|D-041]] 的「会话只有一份存储、两条**读法**」维持——
  `conversation_view` 纯函数与它的对话面插件消费方（classify / compose 请求上下文）
  照旧；裁决只落在**呈现层**。

## 后果

- [PL-007-对话面插件拆分实施方案](../004-plan/007-对话面插件拆分实施方案.md) 的 S5 呈现部分由本 ADR 裁决退役；其
  `conversation_view` 纯函数与对话面插件拆分**不受影响**（它们的 owner 是语言侧
  请求上下文，不是显示区域）。
- e2e `t24-panel-split` 的**四个形状锚与实时面锚不变**（它们钉的是转写事实，
  不是呈现分栏）；其文件头「为什么只有一条线」的论述由本 ADR 接走。
- 前端镜像 `conversation_line.ts` 在前端最后一个投影消费方随分栏退役后去留，
  由 [T-070-会话呈现合流单窗口](../009-task/070-会话呈现合流单窗口.md) 处理（镜像纪律见 [[D-019|D-019]]：没有镜像就处写
  `Corresponding Frontend` 假指针）。

## 判据落点

- **呈现合流是用户可见判据**：分栏开启与否这个用户选择从此不存在，界面永远一列。落点在
  [T-070-会话呈现合流单窗口](../009-task/070-会话呈现合流单窗口.md)（前端组件测试对「单列存在、两列不存在」的断言 +
  `dialog_panel_split` 偏好键退役后的设置页回归）。
- **数据层不变的判据已在位**：t24（形状锚 ×4 + 实时面锚 + Rust `conversation_view`
  单测与前端镜像 spec 双侧穷举）——它们保证本 ADR 的合流**不碰**读分界。
