## 0. 一句话

**「实测与判据同源」（D-044）要求同一份事实既能写、能算，还有一条生产路径去读它。**
本计划立的是读侧：`symbio_core/projection/` 下 18 个投影从事件切片算出视图，
每一个都要有一个**生产调用点**去读它——否则「时延 / 兜底 / 成本」三类收益
**无法验收**，回归也看不见：**不是缺数据，是缺读数口**。

读数口是一条只读路由 `session/stats`（§3 批 0 起）：它读的与写方落的是**同一份**
`<会话目录>/v2-events.wal`，判据由读方复算给出，不复用写方口径。
「投影算得出来却没人读」是本文 §2 立的那道闸要防的形状，18/18 有消费者是它的判据。

**这不是"推翻 v2"**：加固只加**读**（出口 + 复算），不改网格、不改写入路径。

## 2. 读写同源：网格的三段（D0 埋点）

### 现状

- **写**：`plugins/loop/turn_exec.rs`（轮末收束）经 `plugins/loop/derived_facts.rs`
  的 `record_derived` / `record_learning` 把每轮事实写进
  `<会话目录>/v2-events.wal`。
- **算**：`symbio_core/projection/` 下 18 个投影（`slo` / `fallback` / `cost` /
  `calibration` / `checkpoint` / `transcript` / `readyset` / `reputation` / `recall` /
  `consolidate` / `mutations` / `rebuild` / `turns` / `turnstate` / `prompt_fidelity` /
  `autonomy` / `conation` / `span`）各自从事件切片算出视图。
- **读**：一条只读出口 `session/stats`（`plugins/session/stats.rs`）——同一份 WAL
  一次读、同一个 as-of，时延 / 兜底 / 成本 / 断点四列起步，再加 `invariants`、
  `calibration`、`transcript`、`readyset`、`reputation` 与外部效标三族。
  出口之外的投影各有自己的生产消费方：`readyset` 在 `plugins/loop/task_events.rs`，
  `recall` / `consolidate` 在 `plugins/loop/memory_events.rs`，`mutations` / `rebuild`
  在 `plugins/session/store/mod.rs`，`turns` 在 `plugins/loop/turn_exec/`，
  `prompt_fidelity` 在 `plugins/loop/turn_runner/prepare.rs`，
  `transcript` / `turnstate` 另在 `plugins/session/worker_progress.rs`。
  **计数口径**：18/18 有生产消费者——「算得出来却没人读」是本文要防的形状，
  它的判据是每批完成条件 ①（§3）。

### 破的是哪条

**D-044 的后半句**（"判据同源"）。同一份事实既能写又能算，却没有任何一条
生产路径去**读它**——那么：

- 分支的收益主张（v2 是否真的降低了往返、兜底率是否真的下降、成本是否可控）
  **无法用数据回答**，只能靠"机制上应该更快"；
- 反过来，**回归也看不见**：兜底率悄悄上升、P99 悄悄劣化，门禁与运行时都无信号
  （与 [PL-009 §0](009-多执行器与多主体加固实施方案.md "PL-009-多执行器与多主体加固实施方案") 的"破了没有信号"同一个形状）。

### 兑现步

**批 0**（见 §3）。**读侧出口是纯读**——它不改写入、不改网格，因此可以先于
[PL-009](009-多执行器与多主体加固实施方案.md "PL-009-多执行器与多主体加固实施方案") 的加固批独立落地。

## 3. 分批计划

排序原则：**先把"已经能算、只是没人读"的接出来（P0，成本最低、证据最直接），
再补"要接线才有数据"的（P1），最后做与 [PL-009](009-多执行器与多主体加固实施方案.md "PL-009-多执行器与多主体加固实施方案")
合流的接线（P2）。**

> **完成判据（每批两件事同时成立，缺一不算完成）**：① 出口接进**生产**调用点（测试调用不算）；
> ② 它引出的 `#[allow(dead_code)]` 承认标记全部摘除——步状态与死码基线只登记在
> 条目（[`T-058`](../009-task/058.md "T-058") / [`SP-015`](../008-spec/015.md "SP-015")；
> [DE-016 §3.1](004-工程落地.md "DE-016-工程落地与验证") 只指路），本节不复述数字。

### 批 0（P0）· 读侧出口 —— 最小可用 —— **已完成**

> **本节按批次记「这一批交付了什么」，不是出口的列清单**：`session/stats` 当前的完整列
> （含后续批次补入的承诺 / 欲 / 时段 / 自主 / 面板各列）由 `symbio/src/plugins/session/stats.rs`
> 的模块文档与 [RE-003-ROUTES](../006-ref/003-ROUTES.md) own，本文不抄第二份——抄了就必然漂移。

- 归属：本文 §2。死码侧：[DE-016 §3.1 批③](004-工程落地.md "DE-016-工程落地与验证")。
- 出口形态：二选一取 **② 一条只读路由 `session/stats`**（非 CLI 子命令），这一批给出
  **四列**——时延（`slo`）、兜底（`fallback`）、成本（`cost`）、断点（`checkpoint`）。
  读数来源 = 该会话的 `v2-events.wal`（`WalStore::open_readonly` → `range` → `apply`；
  只读开档不创建、不截断撕裂尾行）。
- **`invariants` 列（随 [DE-016 §3.1 批④](004-工程落地.md "DE-016-工程落地与验证") 补入）**：同一次读里顺带跑
  `check_all` 的全部不变量（含任务表并入的 `acyclic_deps` / `rework_bounded`），
  空 = 全绿——读数与「这份读数可不可信」一起给出。宽限与预算
  判据在 core（尾轮在途放行 / 按声明档位取预算），出口只取数、不复判。
- **登记处是 [reference/003-ROUTES.md](../006-ref/003-ROUTES.md "RE-003-ROUTES")，不是 [DE-001 §8](001-核心架构.md "DE-001-核心架构")**——
  那张参数表受 `verify/mechanism_growth.rs` 守恒审计，为登记一个路由去加键会让审计失真。
- **为什么先这几个**：P95 与兜底率是报告点名的两类收益，四个投影**都已存在**——
  批 0 不新增计算，只新增**读数口**。
- 判据：✅ e2e（`e2e/cases/t28-session-stats.mjs`）—— 跑一轮成功 + 一轮兜底后，
  从出口读到的 P95 / 兜底率与**读方复算**（同一份 WAL 直接 `apply`）逐字相等；
  **反向用例**三刀：删掉收束事件 ⇒ 样本列 1 → 0，删掉一个开轮事件 ⇒ 兜底率分母
  2 → 1，把一格开轮事件**复制**成两条 ⇒ 不变量列报「每 turn 至多 1 条开轮」
  （第三刀随 [PL-009 批 0-B](009-多执行器与多主体加固实施方案.md "PL-009-多执行器与多主体加固实施方案") 补入；[批 1](#批-1p1-成本与校准--已完成)
  在同一用例上另加一注——证明它真的在算、不是常数）。单测 `stats.test.rs` 覆盖复算 /
  反向手术 / 缺源不创建文件。
- **写侧前提**：用户发言取值锚 = `TurnState::input_utterance`（循环前在 `single_message`
  上锚定，判决与记忆编码共用同一份锚）。详见 [DE-016 §3.1 S2](004-工程落地.md "DE-016-工程落地与验证")。
- 回退：出口是纯读，删掉即回到今天（无写入路径受影响）。

## 4. 出口判据

与 [SP-003 §2](006-分步实施计划.md "SP-003-分步实施计划") 同一口径，三条缺一不可：

1. **单测**：读方**复算**——同一份事件切片，出口的读数与直接 `apply` 逐字相等；
   含**反向用例**（改一个事件 ⇒ 读数必须变）。
2. **e2e**：`node e2e/run-tests.mjs tNN` 绿，从**真实会话目录**的 WAL 读，不是造样本。
3. **门禁**：`node scripts/gate.mjs` 全绿。

> **为什么"复算"是硬要求**：本方案的唯一风险是"出口自己算了一遍，与投影漂移成两份口径"。
> 判据因此必须**同源**：出口只能调**已有的**投影，不得另写一份统计。缺了它，
> 加固等于给同一件事长出了第二个定义（[PL-009 §4](009-多执行器与多主体加固实施方案.md "PL-009-多执行器与多主体加固实施方案") 的反向用例纪律同源）。
