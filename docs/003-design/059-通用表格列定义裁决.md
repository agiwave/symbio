# 059 通用表格列定义裁决

## 机制

`table` 与 text、select、json 同级，表示对象数组按列编辑。值不是对象数组时按空表处理，
数组中的非对象项被过滤；不把非法输入强行包装成单行。

`DetailField.columns` 是列定义唯一挂载点，每列六格：

| 字段 | 语义 |
|---|---|
| `key` | 结果对象中的键，也是新建行的写入键 |
| `label` | 展示标签 |
| `widget` | 列编辑控件，缺省为文本 |
| `options` | 可选值集合 |
| `default` | 新建行的初始值，缺省为空字符串 |
| `placeholder` | 输入提示 |

- 新建行按列顺序写入 `default ?? ''`，不依据同名旧行猜测值。
- 删除按稳定索引执行；索引非整数或越界时保持原数组。
- 渲染器只消费通用列定义，不内置工具名或业务表头规则。
- Rust `DetailColumn` 与 TypeScript `DetailColumn` 是同一协议的镜像；任一侧增删字段必须同步另一侧和审计。
- 机制层不接收业务词汇，不在 widget 注册表中按插件分支。

## 实现入口

- Rust 协议：`crates/symbio-platform/src/kernel/present/detail.rs`。
- TypeScript 协议与纯函数：`packages/ui/src/schemas/vdfs-form.ts`。
- widget 注册：`packages/ui/src/registry/formWidgets.ts`。
- 契约测试：`packages/ui/src/schemas/__tests__/vdfs-form.spec.ts` 及 Rust detail 测试。
