# 插话与实时打断

## 内容

前置：S06 ｜ **新增机制键 0** ｜ 参数变化 4
## 1. 场景：要什么能力

智能体正在说话 / 正在跑长任务时，用户插一句话；系统把它收进收件箱，**忙则排队**，
当前一轮收尾后由空闲分支取下一条，历史完整。**不挂起在跑的任务**——抢占面已删
（`D-388`），重启条件见 §9。

相对 S06 高了什么：**新增机制键 0**——插话只是收件箱的一条写口，没有新机制。

## 2. 为什么它能落在 v2 上（J1）

| 看起来新的东西 | 实际是 |
|---|---|
| 打断信号 | `control/opened`（`task.controlled`）事件（今天只有熔断支在写） |
| 插话 | 收件箱 FIFO：忙窗只入队，不动在跑的那一轮 |
| 派发 | 空闲分支取下一批（`take_inbox_batch_when_idle`） |

**关键**：排队不需要状态机——队列本身就是已有的会话基底；插话不新开机制。

## 3. 增量清单（只加数据）

| 类型 | 内容 |
|---|---|
| 事件格子 | `control/opened`（`task.controlled`） |
| 收件箱 | VDFS 收件箱节点（写口随消息落盘，读口在空闲分支） |
| 投影参数 | `projection = turnstate`（该 turn 的事件，常数开销） |

**本阶点亮的机制键**（阶梯总表的「新增机制键」由这张块算出；`scripts/gen-verify-facts.mjs` 从这里取输入）：

```capability-assign
event.entity = control
event.verb = held
actor.budget_ms = 80
projection = turnstate
```

### 3.1 落地状态：这一节里哪些增量今天存在

上表逐条对代码（本阶核实：**格子与投影在生产；grants 行不存在，且正文断言在生产里被静默推翻**）：

| 增量 | 今天 | 说明 |
|---|---|---|
| `control/opened`（task.controlled） | **已在生产** | `crates/symbio-kernel/src/event/mod.rs:313`（打断/熔断共用一格，`reason` 区分）；写方只剩熔断支（`crates/symbio-plugin-tool/src/breaker.rs` 随收束入格） |
| `task/held` 格 | **只在词汇表** | 单点定义 `EVENT_TASK_HELD = "task.held"`（`event/mod.rs:294`）；**没有生产写方**（`D-388`），`readyset` 的挂起排除仍在（对空集生效） |
| ActorSpec 抢占判定者行 | **已删除** | 判定面（`PreemptionDecider` / `spec` / `decide` / `held_event` / `resume_event` / `control_event`）已删（`D-388`）；**重启必须新开 D 号**，不许复活被删代码 |
| grants 行（只 JudgeIntent、无 `reply.*`） | **表行仍在，无 actor** | `authz/mod.rs` ROWS 的 `session/reflex` 窄行未动；今天没有任何代码构造这个主体 |
| 投影 `turnstate` | **已退场** | 轮次状态不再是可读投影（`D-309`）；残留只有类型面 `WorkerProgress`（`crates/symbio-sdk/src/turn/facts.rs:63`）与端口字段（`crates/symbio-sdk/src/plugin/context.rs:142`），唯一构造点传空切片（`crates/symbio-plugin-model/src/port.rs:450`），无生产写方 |
| readyset 排除 held | **已在生产** | `crates/symbio-plugin-task/src/readyset.rs`（挂起排除那一段，§5 强制点）；折叠随名册 `#23` 进任务能力包（`D-289`），判据在同包 `readyset.test.rs` |

**现状（`D-388`）**：插话今天只有一条路径——忙则排队到轮末（`inbox` FIFO，空闲分支取下一条）。
**没有判定者、没有挂起、没有恢复**；`task.held` 无生产写方，空闲分支也没有第二个写方。
上面表里「已删除」「无 actor」两行就是当前实况，不是待接线项。

**§6 验收断言的执行方**：抢占四条断言随判定面一并删除（`D-388`）。今天可观察的验收在
`e2e/cases/t34-preemption.mjs`：忙窗插话被取走处理、插话轮完整收束、任务留在
`session/stats` 就绪集（不挂起）。"有没有判定"不再有单测判据——因为判定本身不存在。
反射档实测**当前没有单测**：验它的那些用例挂在 `ProviderLlmAdapter` 上，随那个桥一并
退场（`D-437` 的「不做什么」）；系统开销的读数改由 e2e 的模型往返用例观测。零模型往返
（`verify/latency_gate.rs` 的方案）的生产形态已随 B2 退场（`D-318`）。

**裁决（2026-10-13）：本阶只保留「排队」一条路径。** `Preemption` 枚举已删（`D-388`），
不存在「放行 / 挂起 / 排队 / 超时默认继续」四支；忙碌时唯一行为是排队，空闲时派发队列
（`SessionPlugin::take_inbox_batch_when_idle`）。

## 4. 平凡值与回退（J2）

| 参数 | 完整值 | **平凡值** | 平凡值下 |
|---|---|---|---|
| `event.entity` | `control` | **`scope`** | 仍完整运行——不接受插话，退化为 "跑完再说" |
| `actor.budget_ms` | `80` | `60000` | 仍完整运行——判定慢，用户感到迟钝但不出错 |

**`control` 关闭 = 本阶整阶可跳过**，且系统仍完整。这是插话能力"是数据不是机制"的直接证据。
表中 `actor.budget_ms` 一行属已删的抢占面（`D-388`），今天没有读者。

## 5. 静默失效与强制（J3）

本阶不实现抢占，下表的强制点今天**不适用**；它们描述重启（`D-388` 的新 D 号）之后的约束。

| 约束 | 违反时信号 | 强制方式 |
|---|---|---|
| 被挂起的任务不得被二次调度 | **无**——可能重复执行 | `readyset` 排除 `held` 状态（投影过滤，今天对空集生效） |
| 判定者不得直接发言 | **无** | grants 表：无 `reply.*` 写权（今天没有判定者） |

## 6. 验收断言

1. 忙窗插入一条插话 → 不挂起、任务留在 `session/stats` 就绪集。
2. 插话被后续某一轮取走处理（LLM 请求包里有插话正文）。
3. 插话轮完整收束，历史里有该问答与三格用户发言。

**执行方**：全部在 `e2e/cases/t34-preemption.mjs`（真进程、真在跑一轮、真往收件箱写）。
抢占面的四条旧断言随判定面一并删除（`D-388`）——判定不存在，就没有判据可跑。
反射档实测**当前没有单测**：验它的那些用例挂在 `ProviderLlmAdapter` 上，随那个桥一并
退场（`D-437` 的「不做什么」）；系统开销的读数改由 e2e 的模型往返用例观测。零模型往返
（`verify/latency_gate.rs` 的方案）的生产形态已随 B2 退场（`D-318`）。

## 8. 这一阶做不了什么

边界的唯一账本：[SC-007-插话与实时打断](../002-scene/007-插话与实时打断.md "SC-007-插话与实时打断")（用户语言）。机制面独有边界（用户可见范围之外的工程约束）：

- **抢占不在本阶**：判定面已删（`D-388`），重启必须新开 D 号，不许复活被删代码。
- 真正的硬实时（T7 的具身 / 闭环控制）仍无实现。
- 多个插话并发到达时的优先级是收件箱 FIFO 的顺序问题，与 `readyset` 无关。

## 9. 关键决策

### D-380 #14 的阻塞不是补件：没有两个 owner，就没有端口可开

- **背景（按代码核实）**。迁移清单的 #14 行曾把阻塞写成「判定与落格被刻意分开，
  `PreemptPending` 三态由会话状态背着，搬判定要开跨窗端口」；但两端从来没有生产调用方，
  生产代码没有写过 `ActiveSessionState::preempt`，`task.held` 也没有生产写方。没有第二个
  owner，跨窗端口就无从谈起。
- **裁决**。① **不开跨窗端口**：`CS-001` 只许降、`HS-002` / `HS-006` 只许不涨，给一个
  没有第二 owner 的状态机开面，收益为零、代价是永久的机制债。② **#14 不迁**，
  `S7` 的补件计数不 +1。③ **判定面删除**由 `D-388` 执行，本条不再保留「待接线」。
- **谁写谁读（现状）**。写方：无。读方：无。空闲分支的 `preempt` 闸门已随面删除。
- **代价**。`#14` 不以迁移方式关闭；它作为「能力不存在」记边界，重启条件见 `D-388`。
- **判据**。`session-dead-code.json` 的 `batch: preemption` 五条豁免必须消失（死代码审计
  转绿）；任何给三态加端口的提案先回答一句「第二个 owner 是谁」。
- **不做什么**。不为迁而死代码开面；不复活被删代码。

### D-388 抢占判定面删除：今天没有预占，重启必须新开决策

- **为什么现有形状不够**。`PreemptPending` 三态、`preempt_judged`、`Preemption`、
  `PreemptionDecider` 及其 `spec` / `decide` / `held_event` / `resume_event` /
  `control_event` 只在测试里出现；生产唯一的「读方」是恒假的闸门。它们靠 5 条死代码
  豁免活着，这与「不留死代码、不留过渡实现」直接冲突。`D-380` 保留它们的前提是
  「`preemption` 批次会接线」，而该批次没有立项、也没有产品判据支撑。
- **新形状**。全部删除：三态、标记、枚举、判定者与五个函数；空闲分支不再读 `preempt`，
  自主触发的互斥只判 `is_working`。插话一律排队到轮末，`task.held` 没有写方。
- **当前预占判定由谁承担**。没有承担者：忙碌时不挂起任何在跑任务；`readyset` 的挂起排除
  保留（对空集生效），作为重启后唯一已有的折叠面。
- **重启条件**。出现「必须挂起在跑任务」的用户可见判据（带读数口），**新开一条 D 号**，
  写清判定归属、预算、写入窗口与失败方向；不许把旧三态当现成方案，也不许翻回被删代码。
- **代价**。用户插话不能即时打断长任务——与删除前行为相同（判定从未接线），但删掉了
  「看起来有这个能力」的代码支撑，未来重启要重写判定与落格面。
- **不做什么**。不接线（无消费方）；不保留豁免；不在 `S7` 顺手恢复。
