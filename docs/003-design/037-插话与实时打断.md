# 插话与实时打断

当前机制允许插话排队，不允许在跑工作被挂起。忙碌时接收的插话按 FIFO 保存为事实；
空闲分支先消费排队插话，再决定后续工作。

## 1. 忙碌与空闲

忙碌状态只由事实投影判定。新插话到达不取消在飞端口债，不撤销租约，也不改写当前任务
身份。它进入同一 scope 的插话队列，等待当前可收束点。

空闲分支先读取并消费队首，再将处理结果写回事实。重复投递按插话身份吸收；队列不能
只存在于内存，否则重启后插话会消失。

## 2. 不存在的抢占写方

没有决策者在忙碌时提交 `task.held`，也没有可恢复的执行暂停协议。`task.held` 只能作为
其它能力明确声明的挂起事实使用；就绪视图继续排除已挂起任务，但不把“正在运行”自动
转成挂起。

硬实时抢占不在本机制承诺内。需要暂停在跑任务时，必须先定义判定主体、预算、写入窗口、
恢复协议与失败方向，并让提供者支持取消和可重入。不得仅凭一个 held 状态宣称已抢占。

## 3. 与终答的关系

插话是新的用户事实，不直接写终答。当前轮已产生的终答保持原样；插话按事实顺序开启
后续处理。不得把排队插话拼进尚未完成的响应，也不得为省一次派发而覆盖原终答。

取消与失败仍走端口协议。排队不等于无限期不处理；调度器必须在空闲时给出可观察的
消费结果或显式停止理由。

## 4. 能力阶梯赋值

```capability-assign
event.entity = control
event.verb = held
actor.budget_ms = 80
projection = turnstate
```

## 5. 平凡值与回退

| 参数 | 平凡值 |
|---|---|
| `event.entity` | **scope** |
| `event.verb` | `held` |
| `actor.budget_ms` | `80` |

阶梯块只登记能力坐标；`turnstate` 不是可写运行状态，运行状态由事实投影重建。无专门
控制面时按忙碌 FIFO、空闲消费处理，不启用抢占。
