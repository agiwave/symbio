# 过渡方案与现状差距

> **本文只回答「从现在到目标怎么走」。** 目标态的唯一 owner 是
> [DE-001-核心架构](001-核心架构.md "DE-001-核心架构")（系统存在什么、控制面怎么跑、Agent 怎么组织）与
> [DE-015-义务环](015-义务环.md "DE-015-义务环")（债、表、端口、装载检查的机制细则）。
>
> 本文不是目标设计的一部分：任何一条目标裁决都不在这里改写。差距关闭后删除对应小节，
> 不把过渡形状反向写回目标文档。

## §0 读法与边界

| 问题 | 去哪 |

| 最终形态是什么 | [DE-001-核心架构](001-核心架构.md "DE-001-核心架构") / [DE-015-义务环](015-义务环.md "DE-015-义务环") |

## §1 控制面迁移：从多代执行器到一环一表一源

### 1.1 六步路径

目标形状是**一个单环 + 一张行表 + 一个事实源**（[DE-001-核心架构](001-核心架构.md "DE-001-核心架构") §4.3）。
从现网到达它分六步，每步一个 git 提交；回退单位是提交，不是批次。
这条路径与已退场的 [DE-014-单环一表](014-单环一表.md "DE-014-单环一表") 同源；DE-014 只保留决策锚点，施工口径以本节为准。

| 步 | 内容 | 收口判据 | 熔断线 |
|:-:|---|---|---|
| 0 | 基线快照：core 三格数字、LLM 工具清单、`session/stats` 四列 | 现有棘轮脚本可复现 | — |
| 1 | 把 `run_with_tools` 的内循环抽成 Step 循环；显式产出事件批序、静息判定、失败分支映射、增量投影 | e2e 全量 + 全量/增量投影随机切点对拍 | 结构性改动超过 300 行即判定抽象错误，退回 |
| 2 | 建行表，先挂 `policy.classify` 与 `policy.report` 两行 | 事实网格 + Step 序列逐格比对 | 任何一格漂移即停 |
| 3 | 压缩、记忆、技能、反射四类策略移入行表 | 同上；每行有独立开关可逐个验证 | 同上 |
| 4 | 工具、模型两族迁入同一行形状；提示词与挂载两族经裁决**不进环**（不是债，见 [DE-015-义务环](015-义务环.md "DE-015-义务环") 的 D-144） | 工具清单逐条比对 + schema 导出比对；两族的「无等待方」判据 | 某族塞不进闭集即停，先修模型 |
| 5 | 删除 v1 外壳：死分支与 `TurnState` 簿记字段 | e2e + 网格 | — |
| 6 | 切插件：session（存储 + 生命周期）与 loop（驱动器）分片 | 每个插件可独立卸载且系统仍完整 | 步骤 1–5 未完成前不得启动 |

**步骤 2 选 classify / report 的理由**：两者各自对应一个真实判断，且已有独立开关，
失败面最小。`compose` 不做判断，按行表语义它是能力行，随步骤 4 迁入。

**步骤 4 的收尾**：四族迁毕后，注册行可以落为事实——安装 = append 注册事实，
卸载 = 墓碑事实，内建行是代码常量，用户行是事实覆盖。这是终点坐标里的「注册即事实」，
不是另立机制。

**状态与对账**：六步今天各自走到哪，见 [1.1.1](#111-对账2026-10-24)。步 1 / 2 / 3 的
「对拍」判据有一处改判（v1 路径删除后对拍的另一方不存在），理由见
[DE-016-工程落地与验证](016-工程落地与验证.md "DE-016-工程落地与验证") 的 D-143。

### 1.1.2 「控制面只有一个环」对整条链成立

「控制面只有一个环」这句话**没有就地限定**，它管到链的两头。今天只有一个派发点、一个
求解器：

| 派发点 | 跑哪些行 | 借用的面 |
|---|---|---|
| `turn_exec::drive` | 整张表：轮首四行 / 接缝 / 模型往返 / 工具批次 / 汇报 | 本轮草稿与那一片轮首状态（`Ctx`，按步借、按步还） |

轮首那几行与批次边界不再各自是一个派发点：它们是**行**（`prepare-turn` 52 /
`policy.report` 53），由同一个环按 `prio` 选中（`D-222` 裁决 5）。
「一次边界只派发一次」因此从"调用时机白得"变成 `report_due` 的判据（`D-163` 裁决 4）。

**第四个派发点已退场**：它跑的是幕的三笔账（`prepare-turn` /
`announce-turn` / `dispatch-turn`），而幕不是端口也不是迭代单位——`turn` 端口退场之后
那三条行没有「什么算欠」可写，循环也就失去了选债对象（[DE-015](015-义务环.md "DE-015-义务环")
的 D-222 §一 / §二）。幕也不再是一段独立的驱动单位：幕首、幕内、收幕是那个**唯一一个环**的
三段（`turn_exec::drive` 的 `open_stage` / 循环体 / `close_stage`），幕内那些以事实为前件的
步骤（轮首四行 / 接缝 / 汇报 / 模型往返 / 工具批次）是同一张表上的行。

派发点只有一个，选债仍只有 `ring::drive`——它看得见整张表，「谁欠着」由每行的三段模式说。
`chat_loop` 自己**没有环**：它只剩两件事——过闸门，然后把本轮交给那个环；结局由 `DriveEnd`
映射回 `TurnExit`。「还开不开下一幕」是一笔 `continue-turn` 债（`D-222` 裁决 2），前件读
`turn_next_round`、出口是新落的 `round` 格；那一格同时就是下一幕的锚与 `now`
（判据 12：一幕一个锚），所以「第二幕的 `now` 怎么算」不再是悬着的问题——它就是那笔债的
出口时间。

读数：`scripts/obligation-bypass-audit.mjs` 的调度旁路 0/0（幂等点问 3/3，承认在册）。

这条判据的可数后果仍然有效：§3 的调度旁路以「行有执行体、执行体在表上」为前件。策略行的
动作读的是轮首上下文，内环手里没有——所以「把策略行接上执行体」这一步单独做会让本轮落
`exhausted{no_progress}`。前件的形状已裁：借用面是「一次动作借走的那片状态」，**绑定表只剩一张**（DE-022 的 D-158 立前件、
DE-015 的 D-159 定形状、D-222 收掉 host 分片）。

剩下的三项诚实划界（`TurnState` 仍是整轮容器、「幕跑完了没有」仍是返回值、表外的点问）
记在 D-222 的「这一条没有解决什么」——它们是**已知边界**，不是本节的缺口。
**读数按接回的行列降**：一批 = 绑定表添一条 + 那一行原先那处点问删净，
基线跟着减一；行数与基线这两个数都住在判据里（§3），正文不复述。

### 1.1.3 `by = None` 已归零：「在等」改由形状表达

15 行里 **0 行** `by = None`。四个含义各自的去向：

| 含义 | 行数 | 行 | 现状 |
|---|--:|---|---|
| ① 等应答（语义） | 0 | — | **已归零**：`await-model` / `await-tools` 各接上 `waiter` / `waiter-tools`（`D-222` 订正 2、`D-124` 订正 1）。「在等」不再由 `by = None` 表达——它的唯一写法是**形状**：一条 `sent` 没有同 `(id, attempt)` 的 `response` / `failed` / `retry`（`waiting` 与 `stale_sent` 读的正是它）。`by = None` 时代那两行恒 blocked、永不选中，于是「已派出、未收清」只在崩溃恢复的输入上才有值 |
| ② 粗端口过渡 | 0 | — | **已归零**：`dispatch-model` 接在 `relay` 上（DE-022 的 D-166），宣布归 `announce-model`、派出归端口的中转执行体 |
| ③ 待接执行体 | 0 | — | **已归零**：最后一行的判据与动作都回到轮首 host（D-163） |
| ④ 看护（原 `lease`） | 0 | — | **已归零且不再是一行**：`lease` 行删了。「哪些尝试过期了」是 `sent` 与 `lease_ms` 的一份投影（视图 `stale_sent`），`port::reap` 直接读视图——「看护不是还债」，它问的不是「该还哪一笔」 |

归零之后，「按 `by` 数接线率」这个读数没有余量了：**14 行全部有人跑**。`by` 这一位保留
（`blocked = by.is_none() ∨ unless 命中` 的机制不变，`unless` 仍是「有前件、但不该还」的
唯一声明位），但今天的行表上它恒为 `Some`——「这一笔不由引擎执行」不再是任何一行的处境，
它退化成「这一笔在等」，而那是事实的形状，不是声明。
②③ 各自归零时澄清的两件事值得留着——③ 归零时澄清的是快路的**开口**
（`!resumed ∧ skill_hit`）与**档位**都是那条行自己携带的字段，动作的出口
（`turn.stage{stage:"reflex"}`）当场入日志；② 归零时澄清的是**「派发点在哪」本身就是
一条事实**：`dispatch-turn` 长期 `by = None` 不是「还没接」，而是外环不成环就没有能选中
它的地方——那条行连同「要有一个能选中它的地方」一起退场（D-222），是本条最干净的一次收尾。


### 1.2 `Step` 五值已退场：控制面流动的唯一单元是一笔债

五个 `Step` 值（`Ask` / `Act` / `Emit` / `Wait` / `Halt`）从来不是目标词汇，代码里也没有
`enum Step`——它按 [DE-015-义务环](015-义务环.md "DE-015-义务环") 的 D-114 退场，不是「迁移期显式保留」。
今天环上流动的是 core 的 `Debt`，派发器与执行体之间唯一的界面是那一片借用面
（`turn_exec::Ctx`，一次动作借、动作结束还），
动作是 `fn(&mut Ctx) -> StepFuture`。
那五个词各自现在住在哪里：

| 迁移期 Step | 现在的归宿 |
|---|---|
| `Ask` / `Act` | 一次普通的执行体调用：行 `by` 上的名字 + 那一笔 `Debt`，区别只在执行体名字 |
| `Emit` | 执行体写入的事实；账本由引擎从日志尾段读取 |
| `Wait` | `by = None` 的 await 行——这笔账不由引擎执行（[DE-022-行表与派发面](022-行表与派发面.md "DE-022-行表与派发面") §1.2） |
| `Halt` | 无债可还，或触到步数 / 无进展上界 |

**终点语义是 `decide = min_debt`**（[DE-015-义务环](015-义务环.md "DE-015-义务环") §2）：词汇表里从来没有
第六个值，`Step` 也不再是逐格对拍的对象——对拍判据早已换成 e2e 逐条不变 + 事件批序逐项相等。

### 1.3 熔断线

**一处结构性改动超过 300 行，即判定抽象错误。** 熔断线防的不是「改动大」，
是「用一个更大的补丁掩盖错误的抽象」。语义产出物（映射表、批序定义、对拍测试）
不计入改动量。

### 1.4 场景交叉验证

13 个已承诺场景（SC-001…SC-013）逐项问三个问题：它的 Job 在单环上是什么形状？
靠哪一行 / 哪个执行体承载？有没有把机制逼到说不出话的地方？

结论：13/13 可由「一环一表一源」承载，无需第六个 Step 值、无需新机制键。
三处「说不出话」已回灌为机制约束：

- **集合**：一次模型响应可带多个工具调用，派发与等待都必须是集合；
- **租约**：跨步存活的能力实例登记为事实，能力行保持无状态；
- **唤醒**：定时、插话、工具完成是同一种东西——环外事件源写入的事实。

剩余风险在行为面（审批 / 打断 / 恢复的手感），不在表达面。

### 1.5 风险与不动清单

| 风险 | 处置 |
|---|---|
| 事件批序未定义 | 步骤 1 显式产出，不隐含在「网格一致」里 |
| 行为面回归 | e2e 的审批 / 插话 / 心跳 / 并发用例逐项比对 |
| 切插件变成搬家 | 先满足常驻任务可取消、窄句柄、跨片走表或端口三条前置 |
| core 形状变宽 | CS-001 只降不升；放宽必须挂一条决策 |

## §2 端口粒度：两个端口一张模板

目标态的端口是**两个**：`model` / `tool`。两者按同一张两行模板接入，加端口不新增事实名、
不改 `drive` 与 `owed` 的源码（[DE-022-行表与派发面](022-行表与派发面.md "DE-022-行表与派发面") §1.2）。

**「全部同构」这条已删**（D-222 §一）：按「派出之后控制面撒手了哪一段」判，`turn` 不是
端口（应答载荷为空、适配器是内环自己、`awaited = false`），`clock` / `storage` 也不够格
（前者没有派出动作，后者两段在同一次调用里）。

| 端口 | 一笔是什么 | 在途键 | 派发由谁触发 |
|---|---|---|---|
| `model` | 一次模型往返 | `(port, id, attempt)`，id 带幕锚与步号 | 轮内选债（`relay`） |
| `tool` | 批次里的一次工具调用 | 同上，id 带幕锚、步号与调用序号 | 轮内选债（`courier`） |
| `clock` / `storage` | —— | 无 `PortDecl`，不属在途 | —— |

三行的**形状**逐字同源：宣布（落 `request`）与派出（落 `sent`）是两个环步，两步之间
唯一的交接件是一笔 `Call`；协议四格（`sent` / `response` / `failed` / `retry`）只由
引擎写；同端口的 `await-*` 行是「等应答」的折叠（§1.1.3 的 ① 类，`by = None` 是目标态）。

**唯一的差别是「一笔有多大」**，而这是语义，不是接线残缺。它带来两条后果，两条都已
写在目标态里：

- **判按笔**：`reap`（租约看护）/ `kill_dangling` 按 `(port, id, attempt)` 逐笔判死或重试，
  与端口无关——「重启之后哪几笔没回来」因此有答案（DE-015 的判据 16）；
- **跑不自动发生**：没有自动续跑，恢复的入口是用户与唤醒，而两者的轮都已经收尾过
  （`persist_turn` 跑过，消息镜像在日志里）。「崩溃后从头再走一遍」那条路的形状是
  **自动重驱**，它没有实现，也不在目标里。

租约到顶走「判死」；`tool` 端口的唤醒批次是唯一 `sent.awaited = true` 的一类，因此
也是唯一会重试的一类（`max_attempts = 2`，前提见 §4.2）。

## §3 旁路收编

`drive` 是通用派发器：每步问表（`next` → `ring::drive`），任何 `by` 能解析的行都派得动。
但部分行的账在到达它之前就被专门代码关掉——那些路径自己调 `owes()` 点问、再执行。

**收口完成的定义：调度旁路的点数归零。** 「旁路直调 `owes()`」今天数**两个**数，因为那七处
不是同一类东西（分类与理由见 DE-022 的 D-158）：

| 类 | 判据 | 目标 | 现数 |
|---|---|---|--:|
| **调度旁路** | 点名的行 `by = None`（没人跑它）且该处没有承认标记 | **归零** | 0 |
| **幂等点问** | 已接执行体（`by = Some`）的行动手前复核「本行还欠不欠」 | 显式承认、只减不增，**不以归零为目标** | 3（`open-tools` ×1、`authorize-tool` ×2） |

数字住判据，不住正文：

- `scripts/obligation-bypass-audit.mjs` 的 `BYPASS_BASELINE` 与 `PRECHECK_BASELINE`（各自只许降）；
- 两格基线各由门禁 `35-baseline` 的 `obligation-bypass` / `obligation-precheck` 钉住「不许改大」，
  豁免标记分别是 `obligation-bypass-allow` / `obligation-precheck-allow`；
- 两格数的是同一批 `owes(` 调用点里的不同子集；`fn owes(` 的定义行不算，`*.test.rs` 不算，
  派发器（`turn_exec::drive`）的函数体不算，引擎的现读点 `Dispatch::row_owed` 不算（DE-022 的 D-136 之后
  派发前问表只有那一处，它是派发本体的一半，不是绕开派发体的专门代码）。

承认的形态与 R-002 同构：直调点同行或其上三行写
`// obligation-precheck OB-004: <非空理由>`，一句承认只顶一个点。**标记本身不构成承认**——
被承认的那一行必须真的接了执行体（`by: Some`），否则「护栏」两个字就能给调度旁路洗白；
同一件事由行表用例 `the_rows_guarded_by_admitted_prechecks_have_executors` 在 Rust 侧钉住。

判据还检查：每处点名的行、以及每处 `Dispatch { row: "…" }` 的字面点名，必须真实存在于
`ROWS`。点名一个不存在的行时 `owes` 恒 `false`，那段旁路永不执行、那一格永远派不出去，
而编译、测试、门禁全绿——这是「拼错的名字永不被消费」在派发面的变体。

**旁路不是错误，是过渡态。** 它必须在设计中有一个可数的定义，否则「只减不增」无从执行。

## §4 未启用与保留能力

### 4.1 权限执行（`DE-011`）——已收口

`manifest.yaml` 的 `permissions` 四个字段（网络域名、文件系统 glob、资源限额）
**同批落地执行方**：域名在出站请求发出前判、glob 在文件路径入口判、限额在装载期判
（超限即整轮拒载）。语义是授权清单（空清单即拒），glob 只管 Agent 自己的包；
shell / MCP / 模型往返为显式边界。判据与代码归属见
[DE-011-Agent目录规范](011-Agent目录规范.md "DE-011-Agent目录规范") §5.3 与 D-153；「同批为何是硬的、
名字的两态」见同篇 D-140。

### 4.2 `await-*` 行的生产读者

`by = None` 的等待行保留，但它的成立靠两半：形状对偶（开账条件等于同端口派发行的
`sent` 出口）与一个生产读者（`loop_rows::waiting` 把停机理由分为 `waiting` 与
`no_progress`）。缺任一半，它就退化成装饰行。裁决见 [DE-022-行表与派发面](022-行表与派发面.md "DE-022-行表与派发面") 的 D-130。

### 4.3 轮外模型往返

用户主动重试压缩时那一笔摘要往返不属于任何一轮，明文出界、不入账；差额由
`obligation-ring-accept` 的 J9 钉住：未入账的摘要往返数不超过轮外重试行数。
裁决见 [DE-015-义务环](015-义务环.md "DE-015-义务环") 的 D-131。

### 4.4 验收脚本读取归档段

巩固落格成功后，存储把快照前缀搬进 `transcripts/wal-archive/`。验收脚本必须读
「归档段 + live」的全部事实，不能只读 live 文件；否则长会话会满屏假红，而假红比假绿更坏
——它训练人「再跑一遍看看」，判据因此失去牙齿。

### 4.5 任务清单的工具侧记忆是进程作用域

`local/todo_write` 的 `merge = true` 只在同一进程内按 id 合并，跨进程基准为空；
持久真相是 `task.*` 事实（`task_events` 的重建函数从事实快照重建观察状态）。
工具结果只回确认，重启后的「清单还在不在」由请求视图的 `【任务调度】` 段回答。
裁决见 [DE-033-多步任务与返工](033-多步任务与返工.md "DE-033-多步任务与返工") 的 D-133。

**收口判据**（若要做「跨进程续写整张清单」）：给工具一个值形态的任务快照键，
与「能力上下文只递值」同批裁决；在那之前不把工具内存当持久状态。

### 4.6 淘汰恢复的生产触发器缺席

淘汰后唯一能涨声誉的路径是成功委派，而委派恰是被收回的 `assign.work` 那个动作——
自动恢复在本判据下不可能。恢复事件的形状与折叠已完整（`restoration_event` +
`GrantsOverlay` + 撤销回路单测），缺的是**外部触发器**（申诉 / 人工复位）。
这条边界由 [DE-002-架构总览](002-架构总览.md "DE-002-架构总览") 的 D-108 持有；触发器落地时摘掉
`#[cfg(test)]`，载荷口径不变。

### 4.7 `MemoryStore` 不执行 I1/I2/I3

`MemoryStore` 是 S0 平凡值：只保证 `append` 幂等与 `seq` 单调，不判跨事件不变量。
I1/I2/I3 是持久化实现 `WalStore::gate` 的写侧闸门；生产权威恒为持久化实现。
裁决见 [DE-001-核心架构](001-核心架构.md "DE-001-核心架构") 的 D-134。

### 4.8 快路（`classify` 直接作答）与完整轮的分工

`classify` 判 `Answered` 的轮不进驱动循环，但**记忆编码是轮级派生**：答话轮与完整轮
一样在轮末写 `memory.encoded`（经验 + 判断），跳过条件与运行器结局对齐（中止 /
收束被拒 / 兜底只写经验）。裁决见 [DE-036-长期记忆与语义检索](036-长期记忆与语义检索.md "DE-036-长期记忆与语义检索")
的 D-132。

快路**不做召回**：需要跨会话记忆的问题必须由分类器判到 `work`，走完整轮。
这条分工不是永久形状——快路若要做召回，先解决「请求视图前缀由谁拼」，
而不是在分类器里再抄一份召回逻辑。
