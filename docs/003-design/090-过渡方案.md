# 过渡方案与现状差距

> **本文只回答「从现在到目标怎么走」。** 目标态的唯一 owner 是
> [DE-001-核心架构](001-核心架构.md)（系统存在什么、控制面怎么跑、Agent 怎么组织）与
> [DE-015-义务环](015-义务环.md)（债、表、端口、装载检查的机制细则）。
>
> 本文不是目标设计的一部分：任何一条目标裁决都不在这里改写。差距关闭后删除对应小节，
> 不把过渡形状反向写回目标文档。

## §0 读法与边界

| 问题 | 去哪 |

| 最终形态是什么 | [DE-001-核心架构](001-核心架构.md) / [DE-015-义务环](015-义务环.md) |

只是一句愿望。

## §1 控制面迁移：从多代执行器到一环一表一源

### 1.1 六步路径

目标形状是**一个单环 + 一张行表 + 一个事实源**（[DE-001-核心架构](001-核心架构.md) §4.3）。
从现网到达它分六步，每步一个 git 提交；回退单位是提交，不是批次。
这条路径与已退场的 [DE-014-单环一表](014-单环一表.md) 同源；DE-014 只保留决策锚点，施工口径以本节为准。

| 步 | 内容 | 收口判据 | 熔断线 |
|:-:|---|---|---|
| 0 | 基线快照：core 三格数字、LLM 工具清单、`session/stats` 四列 | 现有棘轮脚本可复现 | — |
| 1 | 把 `run_with_tools` 的内循环抽成 Step 循环；显式产出事件批序、静息判定、失败分支映射、增量投影 | e2e 全量 + 全量/增量投影随机切点对拍 | 结构性改动超过 300 行即判定抽象错误，退回 |
| 2 | 建行表，先挂 `policy.classify` 与 `policy.report` 两行 | 事实网格 + Step 序列逐格比对 | 任何一格漂移即停 |
| 3 | 压缩、记忆、技能、反射四类策略移入行表 | 同上；每行有独立开关可逐个验证 | 同上 |
| 4 | 工具、模型、提示词、挂载/选项四族能力逐族迁入同一行形状 | 工具清单逐条比对 + schema 导出比对 | 某族塞不进闭集即停，先修模型 |
| 5 | 删除 v1 外壳：死分支与 `TurnState` 簿记字段 | e2e + 网格 | — |
| 6 | 切插件：session（存储 + 生命周期）与 loop（驱动器）分片 | 每个插件可独立卸载且系统仍完整 | 步骤 1–5 未完成前不得启动 |

**步骤 2 选 classify / report 的理由**：两者各自对应一个真实判断，且已有独立开关，
失败面最小。`compose` 不做判断，按行表语义它是能力行，随步骤 4 迁入。

**步骤 4 的收尾**：四族迁毕后，注册行可以落为事实——安装 = append 注册事实，
卸载 = 墓碑事实，内建行是代码常量，用户行是事实覆盖。这是终点坐标里的「注册即事实」，
不是另立机制。

### 1.2 Step 五值是迁移接口

迁移期显式保留五个 Step 值，作为与现网行为逐格比对的对象：

```rust
enum Step {
    Ask(PromptRef),
    Act(Capsule),
    Emit(Fact),
    Wait(WaitSet),
    Halt(Reason),
}
```

它们不是目标词汇。目标态下：

| 迁移期 Step | 目标态归宿 |
|---|---|
| `Ask` / `Act` | 一次普通的 `actors.run(名字, 债)` 调用，区别只在执行体名字 |
| `Emit` | 执行体写入的事实；账本由引擎从日志尾段读取 |
| `Wait` | `by = None`：这笔账不由引擎执行 |
| `Halt` | 没有债了，或触到步数/无进展上界 |

**终点语义是 `decide = min_debt`**（[DE-015-义务环](015-义务环.md) §2）：`Step` 整个换成 `Debt`，
不是增加第六个值。

### 1.3 熔断线

**一处结构性改动超过 300 行，即判定抽象错误。** 熔断线防的不是「改动大」，
是「用一个更大的补丁掩盖错误的抽象」。语义产出物（映射表、批序定义、对拍测试）
不计入改动量。

### 1.4 场景交叉验证

17 个场景（SC-001…SC-017）逐项问三个问题：它的 Job 在单环上是什么形状？
靠哪一行 / 哪个执行体承载？有没有把机制逼到说不出话的地方？

结论：17/17 可由「一环一表一源」承载，无需第六个 Step 值、无需新机制键。
三处「说不出话」已回灌为机制约束：

- **集合**：一次模型响应可带多个工具调用，派发与等待都必须是集合；
- **租约**：跨步存活的能力实例登记为事实，能力行保持无状态；
- **唤醒**：定时、插话、工具完成是同一种东西——环外事件源写入的事实。

剩余风险在行为面（审批 / 打断 / 恢复的手感），不在表达面。

### 1.5 风险与不动清单

| 风险 | 处置 |
|---|---|
| 事件批序未定义 | 步骤 1 显式产出，不隐含在「网格一致」里 |
| 行为面回归 | e2e 的审批 / 插话 / 心跳 / 并发用例逐项比对 |
| 切插件变成搬家 | 先满足常驻任务可取消、窄句柄、跨片走表或端口三条前置 |
| core 形状变宽 | CS-001 只降不升；放宽必须挂一条决策 |

## §2 端口粒度：从整轮到单次调用

目标态的端口是**同构**的：`turn` / `model` / `tool` / `clock` / `storage` 都按同一张
两行模板接入，加端口不新增事实名、不改 `drive` 与 `owed` 的源码
（[DE-015-义务环](015-义务环.md) §2.4）。

施工分两级：

| 级 | 端口 | 在途粒度 | 当前状态 |
|---|---|---|---|
| 粗 | `turn`（整轮执行） | 一轮 | 在线 |
| 细 | `model` / `tool` / `clock` / `storage` | 单次调用 | 在线 |

**粗端口是施工第一步，不是目标形状。** 粗端口期间，崩溃恢复只能按整轮重放；
细端口落地后，在途从「一轮」细到「一次调用」，工具批次并发回到控制面。
两级之间没有双调度器：`turn` 执行体就是普通 `by = Some` 执行体，细粒度只是把它的
内部拆成更多行，控制面形状不变。

**当前限制**：模型 / 工具端口的两行模板与租约看护已在线；租约到顶走「判死」，
重试通道未启用（见 §4.2）。

## §3 旁路收编

`drive` 是通用派发器：每步问表（`next` → `ring::drive`），任何 `by` 能解析的行都派得动。
但部分行的账在到达它之前就被专门代码关掉——那些路径自己调 `owes()` 点问、再执行。

**收口完成的定义：旁路直调 `owes()` 的点数归零。** 这个数字住判据，不住正文：

- `scripts/obligation-bypass-audit.mjs` 的 `BYPASS_BASELINE`（只许降）；
- 基线由门禁的 `35-baseline` 钉住「不许改大」；
- 数的是 `owes(` 的调用点；`fn owes(` 的定义行不算，`*.test.rs` 不算，
  `drive_steps` 的函数体不算。

判据还检查：每处点名的行必须真实存在于 `ROWS`。点名一个不存在的行时 `owes` 恒 `false`，
那段旁路永不执行，而编译、测试、门禁全绿——这是「拼错的名字永不被消费」在派发面的变体。

**旁路不是错误，是过渡态。** 它必须在设计中有一个可数的定义，否则「只减不增」无从执行。

## §4 未启用与保留能力

### 4.1 权限声明未执行（`DE-011`）

`manifest.yaml` 的 `permissions` 四个字段（网络域名、文件系统 glob、资源限额）
保留线格式，但宿主当前不据它过滤路径、域名或工具数。它是包作者与宿主的沟通面，
不是安全边界。

**收口判据**：四个字段同批接入执行方；部分执行比不执行更坏——它让「哪些字段真管用」
只能靠读代码。裁决与边界见 [DE-011-Agent目录规范](011-Agent目录规范.md) 的 D-102。

### 4.2 重试通道未启用

`lease_keeper` 能落 `retry{attempt}` 与下一次 `request`，但行层债键是 `(port, id)`：
上一 attempt 的出口格已经关行，重试出来的 `request` 不欠任何一行，没有执行体会派它。
因此真表上 `max_attempts` 全为 1，只有「到顶即判死」一条路在跑。

**收口判据**：先裁决重试如何进入债键（键含 attempt，或单开一行），再抬上限。
裁决之前不抬上限。

### 4.3 `await-*` 行的生产读者

`by = None` 的等待行保留，但它的成立靠两半：形状对偶（开账条件等于同端口派发行的
`sent` 出口）与一个生产读者（`loop_rows::waiting` 把停机理由分为 `waiting` 与
`no_progress`）。缺任一半，它就退化成装饰行。裁决见 [DE-015-义务环](015-义务环.md) 的 D-130。

### 4.4 轮外模型往返

用户主动重试压缩时那一笔摘要往返不属于任何一轮，明文出界、不入账；差额由
`obligation-ring-accept` 的 J9 钉住：未入账的摘要往返数不超过轮外重试行数。
裁决见 [DE-015-义务环](015-义务环.md) 的 D-131。

### 4.5 验收脚本读取归档段

巩固落格成功后，存储把快照前缀搬进 `transcripts/wal-archive/`。验收脚本必须读
「归档段 + live」的全部事实，不能只读 live 文件；否则长会话会满屏假红，而假红比假绿更坏
——它训练人「再跑一遍看看」，判据因此失去牙齿。

## §6 收口台账

| 差距 | 目标 | 收口判据 | 当前落点 |
|---|---|---|---|
| 旁路直调 `owes()` | 派发面全部经 `drive` | 计数归零 | 12 处（10 行），基线只减不增 |
| 重试通道 | 可重试端口 | 重试进债键的裁决 | 未启用，`max_attempts = 1` |
| 权限执行 | 四个字段全部生效 | 四字段同批接入 | 声明性质 |
| 粗端口在途 | 单次调用可恢复 | 细端口覆盖模型 / 工具 | 细端口在线，限制见 §2 |
| 组件文档与目标文档 | 目标唯一、实现就地 | 组件文档只写实现并指向目标 | 见各模块 `README.md` |

> **删除条件**：一行差距的「当前落点」与目标一致时，删掉该行；不要留下已经关闭的条目
> 充当进度装饰。
