# 过渡方案与现状差距

> **本文只回答「从现在到目标怎么走」。** 目标态的唯一 owner 是
> [DE-001-核心架构](001-核心架构.md)（系统存在什么、控制面怎么跑、Agent 怎么组织）与
> [DE-015-义务环](015-义务环.md)（债、表、端口、装载检查的机制细则）。
>
> 本文不是目标设计的一部分：任何一条目标裁决都不在这里改写。差距关闭后删除对应小节，
> 不把过渡形状反向写回目标文档。

## §0 读法与边界

| 问题 | 去哪 |
|---|---|
| 最终形态是什么 | [DE-001-核心架构](001-核心架构.md) / [DE-015-义务环](015-义务环.md) |
| 为什么这样设计 | 各目标文档的「关键决策」节 |

只是一句愿望。

## §1 控制面迁移：从多代执行器到一环一表一源

### 1.1 六步路径

目标形状是**一个单环 + 一张行表 + 一个事实源**（[DE-001-核心架构](001-核心架构.md) §4.3）。
从现网到达它分六步，每步一个 git 提交；回退单位是提交，不是批次。
这条路径与已退场的 [DE-014-单环一表](014-单环一表.md) 同源；DE-014 只保留决策锚点，施工口径以本节为准。

| 步 | 内容 | 收口判据 | 熔断线 |
|:-:|---|---|---|
| 0 | 基线快照：core 三格数字、LLM 工具清单、`session/stats` 四列 | 现有棘轮脚本可复现 | — |
| 1 | 把 `run_with_tools` 的内循环抽成 Step 循环；显式产出事件批序、静息判定、失败分支映射、增量投影 | e2e 全量 + 全量/增量投影随机切点对拍 | 结构性改动超过 300 行即判定抽象错误，退回 |
| 2 | 建行表，先挂 `policy.classify` 与 `policy.report` 两行 | 事实网格 + Step 序列逐格比对 | 任何一格漂移即停 |
| 3 | 压缩、记忆、技能、反射四类策略移入行表 | 同上；每行有独立开关可逐个验证 | 同上 |
| 4 | 工具、模型两族迁入同一行形状；提示词与挂载两族经裁决**不进环**（不是债，见 [DE-015-义务环](015-义务环.md) 的 D-144） | 工具清单逐条比对 + schema 导出比对；两族的「无等待方」判据 | 某族塞不进闭集即停，先修模型 |
| 5 | 删除 v1 外壳：死分支与 `TurnState` 簿记字段 | e2e + 网格 | — |
| 6 | 切插件：session（存储 + 生命周期）与 loop（驱动器）分片 | 每个插件可独立卸载且系统仍完整 | 步骤 1–5 未完成前不得启动 |

**步骤 2 选 classify / report 的理由**：两者各自对应一个真实判断，且已有独立开关，
失败面最小。`compose` 不做判断，按行表语义它是能力行，随步骤 4 迁入。

**步骤 4 的收尾**：四族迁毕后，注册行可以落为事实——安装 = append 注册事实，
卸载 = 墓碑事实，内建行是代码常量，用户行是事实覆盖。这是终点坐标里的「注册即事实」，
不是另立机制。

**状态与对账**：六步今天各自走到哪，见 [1.1.1](#111-对账2026-10-24)。步 1 / 2 / 3 的
「对拍」判据有一处改判（v1 路径删除后对拍的另一方不存在），理由见
[DE-016-工程落地与验证](016-工程落地与验证.md) 的 D-143。

### 1.1.2 「控制面只有一个环」的就地限定

这句话只对**一轮之内**成立。实现交付的是一轮内部的模型 / 工具环（`turn_exec::drive_steps`
读行表的债、派发执行体）、轮首那一台 host（`head_exec::drive_head`，跑判决 / 压缩 / 召回
三行）与批次边界那一台（`report_exec::drive_report`，跑汇报那一行）；一轮之外仍是
`chat_loop` 的固定七步（准备 → 执行 → 汇报 → 收束 → 落库 → 唤醒）。
外环收编不在 §1.1 的六步里：host 的形状已裁（DE-015 的 D-159），五条 `policy.*` 行已按那张绑定表
全部接回三台 host；**外环本身也已裁**——幕是迭代单位、「开一幕」是迭代器不是债，七步里没有行的
四段各自有归属（DE-015 的 D-168）。剩下的只是接回：`announce-turn` + `dispatch-turn` → `prepare-turn`
→ 流向折格，每接回一行，本节这段限定就短一行。

写在这里的理由：`DE-015` §0 的目标句没有这条限定，而「内环闭环」与「目标达成」在读数上
长得一样——后续任何评估都会因此**系统性地偏向乐观**。限定写在现状文档里，目标文档保持
只说目标。

这条限定现在有一个**可数的后果**：§3 的调度旁路归零以它的前件为前件。策略行的动作
读的是轮首上下文，内环手里没有——所以「把策略行接上执行体」这一步单独做会让本轮落
`exhausted{no_progress}`。前件的形状已裁：host 是执行体的借用面，一个 host 一张绑定表，行按
`by` 落进哪张表就住哪台 host，选债仍只有一个求解器（DE-022 的 D-158 立前件、DE-015 的 D-159 定形状）。
**读数按接回的行列降**：一批 = 一台 host 的绑定表添一条 + 那一行原先那处点问删净，
基线跟着减一；行数与基线这两个数都住在判据里（§3），正文不复述。

### 1.1.3 `by = None` 的三义与 17 行的四分类

17 行里 5 行 `by = None`。按 `by` 数「接线率」得到一个没有意义的数，因为这一个字段
同时装着三件事：

| 含义 | 行数 | 行 | 目标态 |
|---|--:|---|---|
| ① 等应答 / 看护（语义） | 4 | `await-turn` / `await-model` / `await-tools` / `lease` | **保留**：`by = None` 就是 `Wait` 的折叠 |
| ② 粗端口过渡 | 1 | `dispatch-turn` | 派发点在一轮之外（固定七步里），外环不成环就没有能选中它的派发点；形状已裁（DE-015 的 D-168：它与 `dispatch-model` 同形），`dispatch-model` 已由 `relay` 接管（DE-022 的 D-166） |
| ③ 待接执行体 | 0 | — | **已归零**：最后一行的判据与动作都回到轮首 host（D-163） |

③ 归零之后，`by = None` 只剩「在等」与「粗端口」两义。最后一行的收编顺带澄清了一件事：
快路的**开口**（`!resumed ∧ skill_hit`）与**档位**都是那条行自己携带的字段，动作的
出口（`turn.stage{stage:"reflex"}`）当场入日志；`turn_exec` 只消费「已选中」的结果
（正文与档位），不再取切片问表。

三义的差别是**接线率的分母**：① 永远不该接线，② 是待接线（③ 已归零）。混在一起数，
读数就会把「在等」算成「没做」。


### 1.2 `Step` 五值已退场：控制面流动的唯一单元是一笔债

五个 `Step` 值（`Ask` / `Act` / `Emit` / `Wait` / `Halt`）从来不是目标词汇，代码里也没有
`enum Step`——它按 [DE-015-义务环](015-义务环.md) 的 D-114 退场，不是「迁移期显式保留」。
今天环上流动的是 core 的 `Debt`，派发器与执行体之间唯一的界面是三台 host 的借用面
（`turn_exec::TurnStep` / `head_exec::HeadStep` / `report_exec::ReportStep`），
动作是 `fn(&mut 借用面) -> StepFuture`。
那五个词各自现在住在哪里：

| 迁移期 Step | 现在的归宿 |
|---|---|
| `Ask` / `Act` | 一次普通的执行体调用：行 `by` 上的名字 + 那一笔 `Debt`，区别只在执行体名字 |
| `Emit` | 执行体写入的事实；账本由引擎从日志尾段读取 |
| `Wait` | `by = None` 的 await 行——这笔账不由引擎执行（[DE-022-行表与派发面](022-行表与派发面.md) §1.2） |
| `Halt` | 无债可还，或触到步数 / 无进展上界 |

**终点语义是 `decide = min_debt`**（[DE-015-义务环](015-义务环.md) §2）：词汇表里从来没有
第六个值，`Step` 也不再是逐格对拍的对象——对拍判据早已换成 e2e 逐条不变 + 事件批序逐项相等。

### 1.3 熔断线

**一处结构性改动超过 300 行，即判定抽象错误。** 熔断线防的不是「改动大」，
是「用一个更大的补丁掩盖错误的抽象」。语义产出物（映射表、批序定义、对拍测试）
不计入改动量。

### 1.4 场景交叉验证

13 个已承诺场景（SC-001…SC-013）逐项问三个问题：它的 Job 在单环上是什么形状？
靠哪一行 / 哪个执行体承载？有没有把机制逼到说不出话的地方？

结论：13/13 可由「一环一表一源」承载，无需第六个 Step 值、无需新机制键。
三处「说不出话」已回灌为机制约束：

- **集合**：一次模型响应可带多个工具调用，派发与等待都必须是集合；
- **租约**：跨步存活的能力实例登记为事实，能力行保持无状态；
- **唤醒**：定时、插话、工具完成是同一种东西——环外事件源写入的事实。

剩余风险在行为面（审批 / 打断 / 恢复的手感），不在表达面。

### 1.5 风险与不动清单

| 风险 | 处置 |
|---|---|
| 事件批序未定义 | 步骤 1 显式产出，不隐含在「网格一致」里 |
| 行为面回归 | e2e 的审批 / 插话 / 心跳 / 并发用例逐项比对 |
| 切插件变成搬家 | 先满足常驻任务可取消、窄句柄、跨片走表或端口三条前置 |
| core 形状变宽 | CS-001 只降不升；放宽必须挂一条决策 |

## §2 端口粒度：从整轮到单次调用

目标态的端口是**同构**的：`turn` / `model` / `tool` / `clock` / `storage` 都按同一张
两行模板接入，加端口不新增事实名、不改 `drive` 与 `owed` 的源码
（[DE-022-行表与派发面](022-行表与派发面.md) §1.2）。

施工分两级：

| 级 | 端口 | 在途粒度 | 当前状态 |
|---|---|---|---|
| 粗 | `turn`（整轮执行） | 一轮 | 在线 |
| 细 | `model` / `tool` | 单次调用 | 在线 |
| — | `clock` / `storage` | — | 未声明（无 `PortDecl`，不属在途） |

**粗端口是施工第一步，不是目标形状。** 粗端口期间，崩溃恢复只能按整轮重放；
细端口落地后，在途从「一轮」细到「一次调用」，工具批次并发回到控制面。
两级之间没有双调度器：`turn` 执行体就是普通 `by = Some` 执行体，细粒度只是把它的
内部拆成更多行，控制面形状不变。

**当前限制**：模型 / 工具端口的两行模板与租约看护已在线；租约到顶走「判死」，
重试通道未启用（见 §4.2）。两族的**派发**都由选债触发（`model` 在 `relay`、`tool` 在
`courier`，DE-022 的 D-166）；`turn` 的派发仍由固定七步里那一处直调发起——在途粒度与
重放粒度分处两级，见 §6 那一行的「当前落点」。

## §3 旁路收编

`drive` 是通用派发器：每步问表（`next` → `ring::drive`），任何 `by` 能解析的行都派得动。
但部分行的账在到达它之前就被专门代码关掉——那些路径自己调 `owes()` 点问、再执行。

**收口完成的定义：调度旁路的点数归零。** 「旁路直调 `owes()`」今天数**两个**数，因为那七处
不是同一类东西（分类与理由见 DE-022 的 D-158）：

| 类 | 判据 | 目标 | 现数 |
|---|---|---|--:|
| **调度旁路** | 点名的行 `by = None`（没人跑它）且该处没有承认标记 | **归零** | 0 |
| **幂等点问** | 已接执行体（`by = Some`）的行动手前复核「本行还欠不欠」 | 显式承认、只减不增，**不以归零为目标** | 3（`open-tools` ×1、`authorize-tool` ×2） |

数字住判据，不住正文：

- `scripts/obligation-bypass-audit.mjs` 的 `BYPASS_BASELINE` 与 `PRECHECK_BASELINE`（各自只许降）；
- 两格基线各由门禁 `35-baseline` 的 `obligation-bypass` / `obligation-precheck` 钉住「不许改大」，
  豁免标记分别是 `obligation-bypass-allow` / `obligation-precheck-allow`；
- 两格数的是同一批 `owes(` 调用点里的不同子集；`fn owes(` 的定义行不算，`*.test.rs` 不算，
  `drive_steps` 的函数体不算，引擎的现读点 `Dispatch::row_owed` 不算（DE-022 的 D-136 之后
  派发前问表只有那一处，它是派发本体的一半，不是绕开派发体的专门代码）。

承认的形态与 R-002 同构：直调点同行或其上三行写
`// obligation-precheck OB-004: <非空理由>`，一句承认只顶一个点。**标记本身不构成承认**——
被承认的那一行必须真的接了执行体（`by: Some`），否则「护栏」两个字就能给调度旁路洗白；
同一件事由行表用例 `the_rows_guarded_by_admitted_prechecks_have_executors` 在 Rust 侧钉住。

判据还检查：每处点名的行、以及每处 `Dispatch { row: "…" }` 的字面点名，必须真实存在于
`ROWS`。点名一个不存在的行时 `owes` 恒 `false`，那段旁路永不执行、那一格永远派不出去，
而编译、测试、门禁全绿——这是「拼错的名字永不被消费」在派发面的变体。

**旁路不是错误，是过渡态。** 它必须在设计中有一个可数的定义，否则「只减不增」无从执行。

## §4 未启用与保留能力

### 4.1 权限执行（`DE-011`）——已收口

`manifest.yaml` 的 `permissions` 四个字段（网络域名、文件系统 glob、资源限额）
**同批落地执行方**：域名在出站请求发出前判、glob 在文件路径入口判、限额在装载期判
（超限即整轮拒载）。语义是授权清单（空清单即拒），glob 只管 Agent 自己的包；
shell / MCP / 模型往返为显式边界。判据与代码归属见
[DE-011-Agent目录规范](011-Agent目录规范.md) §5.3 与 D-153；「同批为何是硬的、
名字的两态」见同篇 D-140。

### 4.2 `await-*` 行的生产读者

`by = None` 的等待行保留，但它的成立靠两半：形状对偶（开账条件等于同端口派发行的
`sent` 出口）与一个生产读者（`loop_rows::waiting` 把停机理由分为 `waiting` 与
`no_progress`）。缺任一半，它就退化成装饰行。裁决见 [DE-022-行表与派发面](022-行表与派发面.md) 的 D-130。

### 4.3 轮外模型往返

用户主动重试压缩时那一笔摘要往返不属于任何一轮，明文出界、不入账；差额由
`obligation-ring-accept` 的 J9 钉住：未入账的摘要往返数不超过轮外重试行数。
裁决见 [DE-015-义务环](015-义务环.md) 的 D-131。

### 4.4 验收脚本读取归档段

巩固落格成功后，存储把快照前缀搬进 `transcripts/wal-archive/`。验收脚本必须读
「归档段 + live」的全部事实，不能只读 live 文件；否则长会话会满屏假红，而假红比假绿更坏
——它训练人「再跑一遍看看」，判据因此失去牙齿。

### 4.5 任务清单的工具侧记忆是进程作用域

`local/todo_write` 的 `merge = true` 只在同一进程内按 id 合并，跨进程基准为空；
持久真相是 `task.*` 事实（`task_events::write` 从事实快照重建观察状态）。
工具结果只回确认，重启后的「清单还在不在」由请求视图的 `【任务调度】` 段回答。
裁决见 [DE-033-多步任务与返工](033-多步任务与返工.md) 的 D-133。

**收口判据**（若要做「跨进程续写整张清单」）：给工具一个值形态的任务快照键，
与「能力上下文只递值」同批裁决；在那之前不把工具内存当持久状态。

### 4.6 淘汰恢复的生产触发器缺席

淘汰后唯一能涨声誉的路径是成功委派，而委派恰是被收回的 `assign.work` 那个动作——
自动恢复在本判据下不可能。恢复事件的形状与折叠已完整（`restoration_event` +
`GrantsOverlay` + 撤销回路单测），缺的是**外部触发器**（申诉 / 人工复位）。
这条边界由 [DE-002-架构总览](002-架构总览.md) 的 D-108 持有；触发器落地时摘掉
`#[cfg(test)]`，载荷口径不变。

### 4.7 `MemoryStore` 不执行 I1/I2/I3

`MemoryStore` 是 S0 平凡值：只保证 `append` 幂等与 `seq` 单调，不判跨事件不变量。
I1/I2/I3 是持久化实现 `WalStore::gate` 的写侧闸门；生产权威恒为持久化实现。
裁决见 [DE-001-核心架构](001-核心架构.md) 的 D-134。

### 4.8 快路（`classify` 直接作答）与完整轮的分工

`classify` 判 `Answered` 的轮不进驱动循环，但**记忆编码是轮级派生**：答话轮与完整轮
一样在轮末写 `memory.encoded`（经验 + 判断），跳过条件与运行器结局对齐（中止 /
收束被拒 / 兜底只写经验）。裁决见 [DE-036-长期记忆与语义检索](036-长期记忆与语义检索.md)
的 D-132。

快路**不做召回**：需要跨会话记忆的问题必须由分类器判到 `work`，走完整轮。
这条分工不是永久形状——快路若要做召回，先解决「请求视图前缀由谁拼」，
而不是在分类器里再抄一份召回逻辑。
