# 多步任务与返工

多步任务以追加事实表达计划、进度、依赖与返工。节点是事实投影，不是可写工作树；
更新计划必须写新事实，不能改写已经发生的执行历史。

## 1. 计划与依赖

任务声明使用 `depends_on` 表达有向无环依赖。装载和写事实时拒绝环；计划可以替换，但
必须保留被替换计划的来源与版本，不能让旧执行结果冒充新计划结果。

返工创建有界的新任务事实，引用失败依据与新计划。返工次数、递归深度和总工作量必须
有明确上限；耗尽后产生停止或交还用户的结果，不无限展开。

## 2. 就绪与进度

就绪是纯事实派生的视图：依赖已满足、资源可分配、任务未被终态关闭。调度器只消费
就绪候选，不依据内存中的“下一步”推进。

进度由 `task.progress` 等任务事实表达，包含父任务、执行者、计划版本与可审计依据。
能力阶梯中的 `progressed` 与 `child:<id>` 是能力坐标，不替代任务事实的正式格位。

## 3. 计划与验证分离

规划者不能验证自己的产出。验证结论必须来自独立主体与独立授权：同一 principal 不能
同时持有 `define.work` 与 `assert.verification`。验证失败写新事实并触发有界返工，不得
修改原验证结论。

计划者、执行者与验证者的授权来源均随事实保存。系统级能力也不能在缺少验证事实时把
自身判断当作终验。

## 4. 任务工具记忆

任务工具可在进程内缓存工作上下文以提高性能，但缓存不是持久真相。重启后必须从
`task.*` 事实、工具产物与检查点恢复；缓存缺失只影响加速，不改变任务身份、依赖或
验证结论。

任务助手不持有第二写口，不直接完成终答。其输出回到任务事实或独立端口债，最终答复
仍遵守一个 scope 一条终答的规则。

## 5. 能力阶梯赋值

```capability-assign
event.entity = task
event.verb = progressed
actor.pattern = decider
actor.capability = define.work
scope = child:<id>
```

## 6. 平凡值与回退

| 参数 | 平凡值 |
|---|---|
| `scope` | **root** |
| `event.entity` | `task` |
| `actor.pattern` | `decider` |

无子任务声明时从根 scope 读取计划；根身份不绕过规划／验证授权分离。依赖未满足时
保持未就绪，不以默认成功补位。
