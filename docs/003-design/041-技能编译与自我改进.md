# 技能编译与自我改进

## 内容

前置：S06、S03 ｜ **新增机制键 0** ｜ 参数变化 4 ｜ 阶段四

## 1. 场景：要什么能力

成功的执行轨迹被编译成**可直接命中的技能**，下次遇到同类情况不再走 LLM；
同时保留"反自动化回退"——异常或高不确定时退回完整推理。

相对 S10 高了什么：S10 是"有内容"，本阶是"**内容会自己变好**"。
T6 的定义就是"能从经验中改进自身行为"。

## 2. 为什么它能落在 v2 上（J1）

| 看起来新的东西 | 实际是 |
|---|---|
| 技能 | `memory.encoded{tag:"skill"}` 事件——**是事实，不是特殊类型** |
| 编译 | **写侧函数 + 开关**（`skill_events::compile` → `memory.encoded{tag:"skill"}`）。裁决：**编译不是投影**——投影是纯读函数（事件进、视图出），而编译有外部输入（本轮收束正文）与 `append` 副作用，类型上不可投影化。「一个 `Decider` 产出事件」里的 Decider 是**角色**行，未立项；投影侧读技能的是 `recall{tag:skill}` + `calibration` |
| 加速 | 命中技能后走 `budget_ms` 更小的 ActorSpec |
| 回退 | 同一批事件下的另一个 ActorSpec 取值 |

**关键**：编译后的技能是**一条 `budget_ms` 更小的 ActorSpec，不是另一套机制**。
这也是为什么"系统 1 / 系统 2"在 v2 里不是两个系统——它们之间由 `skill_compile` 与回退规则**动态转换**，
而认知文档把它做成两套静态系统。这一处 v2 的表达力更强。

> 认知体系提出的 System 1 / System 2 **双系统**最终落在这一阶，并且只以"转换"的形式存在：
> `reasoner`（慢、有中间轨迹）→ `skill_compile` → `decider`（快、直接命中）→ 异常时回退。
> **不是两套并存的系统，而是一条参数化的转换链。**

## 3. 增量清单（只加数据）

| 类型 | 内容 |
|---|---|
| 事件格子 | 复用 `memory/encoded`（技能正文）+ `memory/recalled`（命中 / 回退观测）——**不加新格子** |
| ActorSpec 行 | 编译者 `{ pattern: decider, capabilities: [], budget_ms: 5000 }`<br/>技能命中者 `{ pattern: decider, budget_ms: 80 }` |
| 投影参数 | `calibration`（置信度，已在生产，读出口 `stats.rs`）；`projection = skill_compile` 经 裁决为**写侧函数**（§2）——下方 `capability-assign` 块保留该键为**机制键登记**（编译产物入格位置的键名），不意味着编译是投影 |
| grants 行 | 无新增——编译者复用既有写权 |

**本阶点亮的机制键**（阶梯总表的「新增机制键」由这张块算出；`scripts/gen-verify-facts.mjs` 从这里取输入）：

```capability-assign
event.entity = memory
event.verb = progressed
actor.pattern = decider
projection = skill_compile
```

### 3.1 落地状态：这一节里哪些增量今天存在

上表逐条对代码（本阶核实：**快路在生产；事件格行已按生产格收敛**）：

| 增量 | 今天 | 说明 |
|---|---|---|
| 事件格子 | **已在生产** | 编译写 `memory/encoded{tag:"skill"}`（标签常量 `actors/skill.rs::SKILL_TAG`，编译策略在 `plugins/loop/skill_events.rs`）、观测写 `memory.recalled{skill_id,fallback}`（`skill_events.rs`） |
| ActorSpec 技能命中者（80ms） | **已在生产（形态 = 档位）** | 快路执行体 `chat_loop::run_reflex`（`chat_loop/inputs.rs:388`）：命中即作答、**零模型往返**，正文寄进本轮状态由 `turn_runner::land_reflex`（`turn_runner/stream.rs:316`）落成收束格；`SkillRoute::SkillFastPath{80}`（`plugins/loop/skill_events.rs`）给档位——不依附 ActorSpec 行 |
| ActorSpec 编译者（5000ms） | **裁决：形态 = 步内函数**（非 ActorSpec 行） | 编译是会话主体**轮末的一步**（`derived_facts.rs:262`→`skill_events::compile`， 批①已裁「写侧函数 + 开关即目标形态」）。按 [DE-038 §3.1](038-多主体与对等承诺.md "DE-038-多主体与对等承诺") 的「规格粒度 = 主体」判据，编译者**不是独立主体** ⇒ 不建 ActorSpec 行；其声明的 `capabilities: []` 在 `PermissionMatrix::new` 直接被拒（空能力行表形状表达不出），本就落不进表。**预算 5000 撤下**：`compile` 不读任何投影（它的历史读只有「这轮 trigger 编过没有」的一次按 id 查重——那是线性扫，不是能被预算封顶的聚合读），给它编一个读方就是给拟人化记账续命。与巩固者的区别正在这里：巩固者有一处**全史聚合读**，那里的护栏是 `memory_events::HISTORY_WINDOW`（`D-151` 裁决三） |
| 投影 `skill_compile` | **裁决：写侧函数 + 开关即目标形态** | 无此名 Projection，且**不应有**：编译 = `skill_events::compile`（`store.append`，输入含本轮收束正文），投影是纯读函数（§2）。开关 `skill_compile_enabled`（默认 false，`config.rs:435`）的翻向前置条件见本节末。保真度内核（分句 / 合并 / 保真度）已抽为生产与 verify **共有的一份源码** `symbio_core/text/merge_kernel.rs`（住址随 [D-082](014-单环一表.md "DE-014-单环一表") 归位 core 文本域）（`docs/003-design/verify/consolidation_fidelity.rs` 以 `#[path]` 包含——论证的质量约束跑的是生产这条算法） |
| 投影 `calibration` | **已在生产** | `projection/calibration.rs::calibration_for`（名字由调用方在构造期交进来，DE-024 D-205），消费方 `skill_events::route` + 读出口 `stats.rs` 的校准列 |
| 反自动化回退 | **已在生产** | 作用点 = **提示词摘出**：`skill_events.rs:240-248` retain + `chat_loop/inputs.rs:164/183`（`fast_armed` 双开关，`skill_fast_path` 默认 false） |
| 凸度/密度 | **裁决：划出 S11** | 全仓 grep「凸度/sharpness/density」0 命中。读数今天不存在：`calibration` 只有 `uses`/`fallbacks`（按 skill_id），那是 **reliability（1−回退率）**；凸度要的是**竞争分布**（命中 vs 回退的分离度）、密度要的是 recall 的 `density` 形参——两样输入都没有。按 exit 纪律：只测 reliability **不许顶着「凸度」的名字记账**。DE-040 登记表 `C02` 行的「四层是同一个投影的四个参数值」同批订正为登记形态（非生产刻度） |

**§6 验收断言的执行方**：1 = `skill_events.test.rs::compiled_skill_requires_provenance`；2 = `skill_events.test.rs::skill_hit_is_cheaper_and_low_confidence_falls_back`（自造 cost——生产证据实为 e2e t41「命中轮请求数不增」，更强）；3 = 同上（校准值低于阈值 → `ReasonerFallback`）；4 = `compiled_skill_requires_provenance` 的反向段。e2e = t35（编译-召回接线）/ t41（快路）；verify = `latency_gate.rs`（反射档不调模型的构造形态，`chat_loop/inputs.rs:388` 引注）。

**名册 S11 行**：程序记忆→`skill_events.rs`（生产编译链的写方；`plugins/skill/mod.rs` 是市场 / 提示词技能插件，不是这一阶的编译链）；技能编译→`plugins/loop/skill_events.rs::SkillCompiler`、反自动化回退→`plugins/loop/skill_events.rs::SkillRouter`；自我模型 / 校准→`calibration.rs::calibration` ✓ 生产消费。

**`skill_compile_enabled` 翻默认值的前置条件**（写死，翻向动作本身归届时的开关批，不在本批）：

1. **S11 读数落地**——凸度读数或明确替代的刻度（§3.1 裁决：今天不存在），即「这条技能有多强」不止 reliability 一个数；
2. **[DE-016 价值验收埋点](016-工程落地与验证.md "DE-016-工程落地与验证")出数**——编译链路的价值读数在真实流量上出得来做证据。

两条都满足才可翻向。在此之前 `default_skill_compile_enabled = false` 是**安全退路口**（§4：关掉它系统仍完整运行），默认翻向等于把未验证的自我改进塞进默认路径。

## 4. 平凡值与回退（J2）

| 参数 | 完整值 | **平凡值** | 平凡值下 |
|---|---|---|---|
| `actor.pattern` | `decider`（技能命中） | **`reasoner`** | 仍完整运行——永远走完整推理，退化成 S03 |
| 编译开关 | `skill_compile_enabled = true`（写侧编译 + route 命中） | **`false`** | 仍完整运行——不编译，只检索（`recall` 的平凡值路径：技能一条都没有，召回 / 巩固照常） |

**"不编译"是整个自我改进能力的安全退路口**：关掉 `skill_compile_enabled`，
系统性能退化但行为不变——所以自我改进是**可关的**，这一点对生产环境至关重要。

## 5. 静默失效与强制（J3）

| 约束 | 违反时信号 | 强制方式 |
|---|---|---|
| 技能必须有溯源轨迹 | **无** | I2 断言：`produced_by` 指向源轨迹 |
| 高不确定时必须回退完整推理 | **无**——可能一直用错技能 | `calibration` 投影 + 阈值断言 |
| 「凸度 / 密度」不许由 reliability 冒充 | **无**——把 1−回退率印成「凸度」即可读数失真而无人察觉 | 裁决：读数今天不存在（§3.1），`stats` 的校准列只许报 `uses`/`fallbacks`；要立凸度读数先补竞争分布的观测面，另立批次 |
| 编译不得污染在途决策 | **无** | `Timestamp` as-of（同 S06） |

> **必须保留反自动化回退**（Beilock & Carr 2001 *choking under pressure*）：
> 全自动化在压力下会以异常方式失效。这不是保守，是被实证过的失效模式。

## 6. 验收断言

1. 编译产出的技能事件 `produced_by` 必须非空（指向源轨迹）。
2. 命中技能后 `cost_ms` 显著低于未命中路径。
3. 置信度低于阈值 → 必须走 `reasoner`，不得走技能路径。
4. **反向用例**：把编译者的 `produced_by` 置空 → 断言 1 必须失败。

**§6 验收断言的执行方**：1 = `compiled_skill_requires_provenance`（`plugins/loop/skill_events.test.rs:432`）；2 = `skill_hit_is_cheaper_and_low_confidence_falls_back`（同文件 `:451`，40ms vs 5000ms）+ e2e **t41**（技能快路）；3 = 同上一条的校准 / 路由半（置信度 0.5 < 0.8 ⇒ `ReasonerFallback`，反向 0.95 ⇒ `SkillFastPath`）；4 = `compiled_skill_requires_provenance` 的反向半（同文件 `:441-446`，`produced_by` 置空 ⇒ I2 抓住）。

## 8. 这一阶做不了什么

边界的唯一账本：[SC-011-技能编译与自我改进](../002-scene/011-技能编译与自我改进.md "SC-011-技能编译与自我改进")（用户语言）。机制面独有边界（用户可见范围之外的工程约束）：

- **"哪些轨迹值得编译"是算法问题**，架构只提供 `skill_compile` 这个位置。
- **凸度 / 密度读数不存在**：观测面只有 uses / fallbacks（reliability），没有竞争分布；`recall` 也没有 `density` 形参——补读数要先补观测面，另立批次（裁决）。
- 从"改参数"到"改架构"的跨越**不在本阶范围内**（那是决策，不是数据）。
