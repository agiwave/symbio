# 能力包迁出与落地裁决

能力包可以迁移，但所有权边界不随目录移动。每个机制、折叠与报告只能有一个实现和一个
owner。新增能力不得要求修改环、宿主、机制门面或内核。

## 1. 四种所有者

同一事实或报告可能同时出现四种角色，不得互相顶替：

| 角色 | 责任 |
|---|---|
| 事件槽位 owner | 定义事实名、格位、幂等键与写入者集合 |
| 事实形状 owner | 定义共享载荷字段、版本与兼容约束 |
| 载荷写入者 | 产出该事实 payload，并执行其业务写入 |
| 报告 owner | 组装面向宿主或用户的稳定报告区段 |

词表 owner 不必然是载荷写入者。slot 固定报告区段；字段可扩展，但区段的身份与稳定字段
不得随实现细节改名。

## 2. 同装边界

一个能力的事实形状、事实行、折叠与报告必须作为同一装载单元。装配单元不得为了调用
自身事实或视图而运行时依赖兄弟插件。

跨能力读取合法，但只消费对端公开的具名视图或报告。读者不得在本地重新折叠对端载荷，
也不得因为“只是读”而取得对端事实行执行权。若需要对端计算，由对端提供具名视图或报告。

不存在视图读视图、报告读报告的链。多级组合必须经事实：上游把结果落为事实，下游按事实
声明读取。

## 3. 折叠归属

数据折叠跟随载荷写入者。报告 owner 必须等于对应视图／折叠 owner，装配检查必须验证
这一关系。模型使用量、计价与模型报告归模型 owner；其它能力只消费其报告，不重算模型
载荷。

报告只输出稳定 `slot` 区段。占位符是报告的一部分，不得被下游当作另一份事实真相。
报告与事实的 owner 不同时，应显式登记转换边界，而不是把转换藏进视图链。

## 4. 缺视图行为

跨能力读取的具名视图必须声明缺失语义：返回文档化的空形状、显式降级，或拒绝装载。
不得静默返回空数组，也不得自动折叠对端原始载荷补位。宿主门面组合报告时同样按 slot
合并，缺区段保留可解释的空或降级标记。

## 5. 局部性门禁

- 事实与行同装，不产生兄弟插件反向依赖。
- 跨插件读走具名视图／报告，不读内部行、执行体或私有状态。
- 新能力只提交自身包与声明，不改受保护机制树。
- 新增共享槽位必须声明 owner、形状、写入者与消费者。
- 装配期检查报告 owner、视图 owner 和唯一载荷写入者。
- 所有权冲突时拒绝装配，不按目录顺序选最后一个实现。

## 6. 角色判定顺序

1. 决定事实或报告区段是谁的：归事件槽位／报告 owner。
2. 决定 payload 从哪来：归载荷写入者。
3. 决定如何汇总 payload：跟随载荷写入者，不跟随报告消费者。
4. 决定谁能跨包读取：只读公开视图／报告，不取得内部执行权。

任何无法按上述顺序指认 owner 的“公共助手”，都应退回单个能力内部，或拆成有明确事实
槽位的独立能力。历史位置与调用频率不构成所有权依据。
