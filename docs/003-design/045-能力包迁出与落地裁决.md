# 能力包迁出与落地裁决

> **一句话**：每一批把一条能力从控制面 / 机制面搬进能力包时，「为什么这样搬、缺了哪条
> 机制、被否了哪些形状」的裁决都写在这里——判据与名册账归
> [DE-026-能力拆分与影响类](026-能力拆分与影响类.md)，本文只持有**逐批落地**的那一份论证。

## 0. 本文的边界

- **本文持有**：一条能力落进某个能力包的落地裁决——批次实际依赖的机制形状（端口 / 声明
  / 视图 / 事实形状）、落点 crate 与模块、被否决的候选形状。
- **本文不持有**：影响类闭表、名册 54 行的逐行处置与交付段
  （[DE-026-能力拆分与影响类](026-能力拆分与影响类.md) §2 / §2.3）、`EX-00x` 判据的定义与
  执行方（[DE-026-能力拆分与影响类](026-能力拆分与影响类.md) §5）、迁移纪律本身的措辞
  （`D-245` / `D-247`）。本文引用它们，不复述。
- **为什么是两篇**：判据与名册账是**闭表**（改一格要重新裁决），落地裁决是**逐批增量**
  （每迁一条能力就多一段「裁决 + 被否」）。写在一起，增长的那一半迟早把定义的那一半
  挤出它该在的位置。

## 关键决策

### D-260 零往返作答是一条行产物：`RowStep::Answer` 与累计史入参

**裁决**：D-251 把「抢先作答」指到反射行执行体，但 `RowStep::Facts` 这个形状只说得清
「写这些格」，说不清「这一轮到此为止」。本条把它补成两个互补的形状：

1. **`RowStep::Answer{text, facts}`**——行声明「这一步就是这一轮的答复」。宿主按**同一
   份**写入名单先落 `facts`，再落一条 `turn.stage{stage:"reflex", result:"answered"}`
   （宿主代写的那一格），并把正文经 `TurnSession::set_reflex` 寄进本轮草稿；收束格
   `chat.assistant.final` 仍由 `close-turn` 落（D-163 的单一写方不变）。`Facts` 保持
   「中间产物」：落完继续欠下一步。`RowHandler::answers()` 声明本行会走这条出口，
   派发器的写入封闭**只对它**额外豁免 `turn.stage`；其余行的账本口径不动。
2. **`RowRequest.history`**——`facts` 仍只是本轮切片（视图成本上界按轮），另交一份完整
   史，与 `Settling.history` 同形。累计口径的行（技能表、巩固、校准）按它判，不再靠
   「本轮恰好看得见」这个巧合。

**理由**：`Facts` 落完而债仍开着，环会继续选下一笔；若没有「作答」这个类型，宿主只能
认某个载荷约定或按行名分支——前者是隐式协议，后者正是 D-241 要拆掉的东西。单独一个
变体把「写格」与「作答」分开，宿主不需要认识能力。累计史同理：技能的编译在上一轮、
命中在下一轮，只给本轮切片等于让能力自己拼时间窗口；而 `range(0)` 本来就已取在
`plugin_row` 手里，多交一个借用不增加扫描。

**被否**：能力行自己写 `chat.assistant.final`（两个写方，D-163）；把正文塞进 `Facts`
的约定字段（隐式载荷协议，不是类型）；在 `Decl` 上加 `answers` 开关（行表是静态债务图，
不含产物语义）；给能力 store 句柄（写口不唯一，D-241 已否）。

### D-261 门面 SDK 臂补两条机制：校准视图与字符截断

**裁决**：`symbio_plugin_api` 的 SDK 臂增加 `calibration_for` / `CalibrationView` /
`SkillStats` 与 `truncate_chars` 四条转发。它们都已在 `symbio-sdk` 里，不是新机制：
一条是按事件折叠出的「每实体使用/回退次数」只读视图，一条是按**字符**口径的截断。
L3b 把技能编译与回退判断搬进能力包之后，能力的行执行体与收束贡献要读自己的校准格、
要按字符截断触发词与正文——没有这四条，它只能绕过门面直接依赖 `symbio-sdk`（HS-001
判红），或在能力包里再写一份同样的折叠与截断（机制重复）。

**理由**：门面的 SDK 臂本来就装「只碰内核词汇的宿主机制」，而校准折叠只认事件载荷里的
一个 id 与一个布尔，截断只认字符串；两条都与容器概念无关，归 SDK 臂不改变任何形状。
core 臂不动（仍为 6 条，HS-002 棘轮），迁移提交的机制面因此仍为零。

**被否**：让能力行直接依赖 `symbio-sdk`（门面失守，HS-001）；把校准折叠搬进能力包
（同一张表两份实现，且控制面还要读它）；用字节截断凑合（触发词匹配口径与原实现不一致，
e2e t35/t41 的「同一截断后精确相等」会漂）。

### D-262 技能编译与反自动化回退随能力包迁出：一条行、一张回退视图、两张跨插件读面

**裁决**：S6 / L3b 把技能编译（名册 #24）、反自动化回退（#25）与程序记忆（#4）从
`crates/symbio-plugin-loop/src/skill_events.rs` 整体搬进 `crates/symbio-plugin-skill`。
搬完 `loop` 不再持有任何技能策略：编译是能力包的收束贡献，命中与观测是能力包的一条行，
回退是能力包公开的一张视图。落地分六条：

> **落地状态（B2 `60cedd50`，D-318）**：下列第 2 条（观测与命中合一的 `skill.recall` 行、
> `skill.answered` 判定格）与第 3 条中 `turn.recalled` 的生产者、第 4 条中的写入方已随 B2
> 退场；原文保留为当时的裁决。仍在生产的是第 1 条（编译贡献）与 `skill.retreat` 视图。

1. **编译是收束贡献，不是轮末函数**（D-250）。`contributor::SkillCompile` 从
   `Settling` 读本轮收束正文、用户发言、累计史与开关，只对**成功收束**、开关开着、
   同 trigger 尚未编译过的轮次交一条 `memory.encoded{tag:"skill"}`，`produced_by`
   指向本轮开口格。它不再挂 `derived_facts::record_learning` 的轮末段落——loop 的
   `record_learning` 因此回到纯记忆读侧（检索锚 + 巩固）的形状。去重、开关、空正文三条判据都在贡献者
   内部，交空集是合法结局。

2. **观测与命中合成一条 `skill.recall` 行**（D-241 / D-251 / D-260）。债键是
   `(recall, stage)`：`recall` = 技能事实的 seq，`stage` = 召回阶段格的 seq；前件是宿主
   公开的 `turn.recalled` 且 `tag = "skill"`。每条技能**只判一次**，同一次判定同时产出：
   - 观测格 `memory.calibrated{skill_id, fallback}`（校准账的唯一数据源）；
   - 判定格 `skill.answered{recall, stage, skill_id, hit}`（行的出口，一幅幕一条）。
   命中 = 未回退 ∧ `skill_fast_path` 开着 ∧ 本幕不是续写幕（`resumed = false`）∧
   本轮用户发言与 trigger **逐字相等**；命中走 `RowStep::Answer` 交正文，零模型往返。
   找不到 `skill_id` / `trigger` / `content` 的条目（跨会话遗留、巩固产物）**不观测、
   只关账**，原样留在提示词里当背景事实。

3. **两张跨插件读面，方向都不反**：
   - 宿主公开 `turn.recalled`：本幕召回的逐条结果，每条 `{recall, tag, stage, resumed}`，
     只认幕锚之后**最近**那一格召回阶段；
   - 能力包公开 `skill.retreat`：置信度低于 `0.8` 的条目 seq 集，口径与校准账逐字同源
     （今天两处同住 `crates/symbio-plugin-skill/src/decl.rs`：账是 `calibration_ledger`，
     视图只挑低于阈值的那一半——`D-286`）；
   - 宿主按名字读 `skill.retreat` 摘掉本轮提示词里的条目（读不到 / 超预算时 fail-open：
     判定缺席只影响摘除，不影响回合）；能力包按名字读 `turn.recalled` 开自己的债。
     两边只认名字，不链接兄弟插件（E-009 / D-251）。

4. **事实归属随写方走**。`memory.calibrated` 自本条起由技能能力**整条拥有**：
   `decl::EVENTS` 交格位、`decl::FACTS` 交形状（写入方已随 B2 退场，D-318）、`skill.retreat` 与
   会话 `stats` 读；名字经 `PLUGIN.yml` 的 `shared_events` 进生成表。`memory.encoded`
   的**格位仍由 loop 交**（它与会话统计是共同读方，不能被任一插件独占），
   但技能条目的形状与写入跟能力包走（形状申报此后随记忆家族迁进情景记忆能力包，
   见 `D-263`）。

5. **宿主机制只补数据面，不补分支**。`turn.stage{stage:"recall"}` 的载荷增加
   `recalled: [{seq, tag}]` 与 `resumed`（`StageFact::recall` 的唯一写点）；技能行的
   `RowStep::Answer` 之后，宿主代落 `turn.stage{stage:"reflex"}` 并经
   `TurnSession::set_reflex` 寄存正文，`close` 仍按单一写方落 `chat.assistant.final`。
   `turn_head` 升 v17 删去 `skill_hit`，`reflex_answered` 改由宿主代落的
   `stage:"reflex"` 折出；档位 `turn_tier` 因此只读 `reflex_answered`。
   `TurnState` 取走 `skill_route` / `skill_hits` / `head_reflex` 三格（CS-010 基线 21 → 18）。

6. **迁移面**：`crates/symbio-kernel` / `crates/symbio-sdk` / `symbio-plugin-api` 的非生成
   `.rs` diff 为零；`loop` 只删旧实现并接两张读面（通用 glue，不含能力名）；
   `symbio-plugin-skill` 收下编译贡献、召回行、视图与声明。e2e t35 / t41 的接线判据不变。

**理由**：编译的输入与产物都属于技能能力（“这一轮值得记成什么套路”），回退的判据也属于
它（“这条技能还信不信”）；把两者留在 loop，等于让控制面替每张能力表回答本能力自己的
问题，也把「加一类可编译经验」变成改控制面。两张视图把「谁知道什么」切开：宿主只公开
本轮召回了什么，能力包只公开哪条不该进提示词，任何一侧都不需要认识对方的类型或模块。

**被否**：让技能行直接读宿主的召回视图（跨插件的私有面，等于把控制面的类型变成
能力包的依赖；今天这条视图是 `symbio_plugin_api::retrieval::Retrieval`，可交的只有它
这个协议形状，D-264）；让 loop 自己判置信度（回退判据搬回控制面，能力包只剩写格）；把
`turn.recalled` 落成一条事实（它是投影，不是事件；落格会给同一份召回清单制造第二写方）；
让技能行在续写幕重答（会顶掉刚被批准的那次工具，且 `skill.answered` 的幂等键与本幕
召回阶段格撞车）；保留 `policy.reflex` 作为「宿主行 + 能力执行体」的两段式（行名即能力名，
SC-006 仍会把它算作 loop 的能力面）。

### D-263 情景记忆编码随能力包迁出：一条收束贡献、一张形状与归宿行交还、三条名字进清单

**裁决**：S6 / L2 第一刀把名册 #2（情景记忆）的**编码**从
`crates/symbio-plugin-loop/src/memory_events.rs` 搬进新能力包
`crates/symbio-plugin-memory`。搬完 loop 只剩记忆的**读侧与巩固**（召回投影、
检索锚、巩固与注入段）——那是它自己的提示词装配面；「这一轮的哪句值得记成记忆」的
判断不再住在控制面。落地分六条：

1. **编码是收束贡献**（D-250），不是轮末函数。`contributor::EpisodicEncode` 从
   `Settling` 读本轮用户发言、收束正文与完整史，交**两条**草稿：经验（`v2m-{anchor}`，
   `vis_scope = shared`，正文取 `user_text`）与判断（`v2j-{anchor}`，`thread_private`，
   正文取成功收束的 `response`——兜底 / 中止为 `None` 时不写）。空发言不记、
   按字符截断（400）、**跨标签同文去重**、溯源锚指本轮开口格（I2）、`actor` 记
   认知归属人（`with_actor`）——四条判据全部随写方迁进包内 `contributor.test.rs`。
   同轮两条对**同一片史切片**判定 ⇒ 要么都落、要么都不落，与旧实现「先编经验再编
   判断、判据读同一快照」逐字同行为。

2. **事实形状的 owner 随写方走，格位不动**。`memory.encoded` 的 `EventDecl`（格位
   `memory × opened`）仍由 loop 交（loop 与会话统计是共同读方，D-262 第 4 条不变）；
   `FactDecl`（字段全集 `content / tag / generation / vis_scope / skill_id / trigger`）
   与那张 eq 为空的**归宿行**由本包交。归宿行**全进程只有一张**（`DuplicateFact` /
   行名查重按名字，不按 owner）：`tag:"skill"` 那半被 eq-空行覆盖，所以
   `symbio-plugin-skill` 同时交还它的 `FactDecl` 与技能归宿行——技能包对
   `memory.encoded` 只剩一个写方 + 一张读它的视图（`skill.retreat`），其测试二进制
   用夹具镜像包内的形状与行。

3. **三条名字进清单共享表**。`memory.encoded` 本就在 loop 的 `shared_events`；本包
   的去重活集要读 `memory.consolidated` 与 `memory.forgotten`，两条随本批进
   loop 的 `shared_events` → 生成物 `symbio-plugin-api::events`（CS-007：owner 的
   生产 `EventDecl` 已在表里，格位与角色照旧投影）。包内**不自建投影**：去重读的
   活集是一条折叠（encoded ∪ consolidated − forgotten 的 `produced_by`，actor =
   认知归属人，全史无窗口），口径与「去重读的是全史，不是近 N 条窗口」那条判据同批
   迁入包内用例。

4. **顺序不变量靠结构，不靠约定**：贡献者在 `land_contributions` 落草稿，宿主在
   `record_learning` **之前**跑完那一步；`consolidate` 自己重取 `range(0)` ⇒
   巩固永远看得见本轮刚编码的那条（「第 4 条到齐即触发，刚写的对巩固可见」的判据
   随 `derived_facts.test.rs` 改造保留）。生成面与定稿答话面两条收尾路径同形。

5. **判据随迁 + 反向钉**：loop 的编码正向用例删除，`memory_events.test.rs` 的种
   夹具降为镜像（标签与截断上限的字面量一致性由 e2e `t29` / `t82` 钉，与
   `CONSOLIDABLE_TAGS` 同一条口径）；`turn_exec.test.rs` 的编码用例**反转**成
   「宿主一轮跑完不落任何 `memory.encoded`」；`RecallView::contains_content` 随
   最后一个生产消费方迁出而删除（它本来就只是写方的观测面）。

6. **迁移面**：`symbio-sdk` / `symbio-kernel` / `symbio-plugin-api` 的非生成 `.rs`
   diff 为零（`events.rs` 是清单生成物）；loop 只删旧实现并收窄 `record_learning`
   （11 参 → 7 参）；新包只链接 `symbio-plugin-api`（DE-025 D-258），登记进装配表
   （`plugin_order 46`，`sub_agent`）。

**理由**：编码的判据（什么值得记、记成什么标签、和哪些既有记忆重复）是认知内容侧的
判断，与「这一轮何时停、提示词装配成什么样」无关；D-250 造出贡献这一格，等的就是
这类「不保证产出、也不欠成一条行」的收束事实。形状 owner 随写方走而不留 loop，是
「UndeclaredField 的申报者必须看得见字段的全部产地」的落实——本批之后加一个载荷
字段只改能力包一个文件。

**被否**：让包自己申报 `EventDecl` 把 `memory.encoded` 整条拿走（格位 owner 必须是
共同读方之一，会话统计与巩固读侧都在 loop，D-262 第 4 条的同一形状）；把编码做成
一行（`owes` 需要一条「天然空转」的债，环会在同一个债上反复选中直到步数上界——
这正是 D-250 立贡献而非债的理由）；去重用召回窗口切片（实测否过：窗口外旧记忆会
被再记一条，见随迁的全史判据）；技能包保留第二张 `memory.encoded` 归宿行
（`seal` 的 DuplicateFact 按名字查重，一张事实两张形状/归宿就是两个 owner）。

### D-264 长期记忆检索与语义记忆迁出：一条轮首检索面、一格 `Settling` 值、两个记忆能力包

**裁决**：S6 / L2 的第二、三刀把名册 #6（长期记忆检索）搬进
`crates/symbio-plugin-memory` 的 `recall` 子模块（批次 L2b），把名册 #3（语义记忆）搬进
同一个 crate 的 `semantic` 子模块（批次 L2c）。两批共用一份机制补件，补件只有两格：
一条新面与 `Settling` 的一个值字段。落地分五条：

1. **新面：轮首检索（`symbio-plugin-api::retrieval`）**。能力提交纯函数
   `retrieve(&RetrievalRequest) -> Option<Retrieval>`：入参是宿主取好的两个**值**——
   可见切片 `events`（控制面做完可见域收放后交齐的跨会话记忆事件集）与 `query`
   （本轮用户发言文本；`None` = 无新发言，退化纯新近序）。产出是**自有结构值**：
   `degraded` + 排好序的 `entries`（`seq / content / tag`）。宿主按 owner 字典序收集：
   条目按 owner 序拼接（排序判据在包内，宿主不再排第二遍），`degraded` 取**任一**
   （任何一条检索没扫完都要出声）。检索的判据——折叠（encoded ∪ consolidated −
   forgotten 的 `produced_by`）、混合打分、新近序、扫描预算（超预算 ⇒ `degraded`）——
   全部住包内（名册 #6「排序与预算在包内」）。
   **可见域收放留宿主侧**（I-8）：跨会话快照枚举（`RECALL_SNAPSHOTS`，异步 IO）与逐条
   可见判定（`thread_private` / `shared` / `public` 的取值口径住 core 的读侧闸）不迁——
   能力包只准链接 plugin-api，而 `FleetSnapshot` / `VisScope` 是 core 臂的容器面

比加面更宽；`RowHandler` 收事实切片——跨会话快照不在事实面上，硬塞 `snapshots` 会让
**每条**能力行都付一次跨会话扫描的代价。这一面服务的也不只一条能力：RAG、日历、
项目文档是 DE-025 点名的下一批上下文来源，它们要的正是同一副形状——「轮首、可见切片
进、排序读数出」，长期记忆检索是它的第一例。这与 D-250 立贡献口的理由同形：面为一族
时机而立，不为单个名字而立。

**被否**：把检索折进无参视图、让切片形状自己携带查询（「slice 里最后一条 user 消息」
就是查询——这是替能力做容器的裁决，违 D-252；且同一张折叠无法同时服务带预算的检索与

`RowRequest` 加 `snapshots`（引擎认识新数据面，每条行摊付跨会话成本）；检索与渲染同进
provider（见上一条理由的 I-2 输出类）；语义包从 `Settling.history` 的召回阶段格自己数
found、再读 `skill.retreat` 摘第二遍（判据只有一格不假，摘除却执行了两遍——两边的
found/top 必然漂成两个数，正是 D-251「两处各判一遍必然漂移」的反面应用）；语义包在
收束时重算检索折叠（收束时没有跨会话值包：快照只在轮首取一次，重算 = 对盘重扫，一轮
两个时刻两套读数）。

### D-267 记忆是一个所有者：名册四条记忆能力统一落 `symbio-plugin-memory`

**裁决**：名册第 1（工作记忆）/ 2（情景记忆）/ 3（语义记忆）/ 6（长期记忆检索）
四条**不各立 crate**，全部落进已有的 `crates/symbio-plugin-memory`。
`D-263` 建的 `symbio-plugin-memory_episodic` 已并回该插件
（`crates/symbio-plugin-memory/src/episodic/`），`D-264` 里 `-memory_recall` /
`-memory_semantic` 两个包名作废，落点改成同一个 crate 里的三个模块。

**理由**：

1. **归属原则不能有两个所有者**。本插件的模块文档写着「谁能读写它，谁负责注入它」，
   而记忆的三种载体（`AGENTS.md` 文件、`WORKSPACE.md` 文件、`memory.encoded` 事件）
   读的是同一件事——「这个智能体 / 这个项目长期成立的东西」。拆成四个 crate 之后，
   四个插件都声称拥有记忆，而没有任何一处说得出「记忆到底归谁」；停用其中三个，
   剩下那个还在注入、还在写——这是「一个作用域一个所有者」的直接反面。
2. **代价是零**。`symbio-plugin-memory` 本来就以 `sub_agent` 挂载、本来就随装配清单
   生效或停用。并进去只多两个子模块，不新增装配位、不新增 `plugin_id`、
   不改 `gen-facts` 的任何一格（装配清单反而少一行）。
3. **`D-263` 的分包理由是「编码只有一个写方」**——那条判据成立，但它推不出「必须另立
   crate」。同一个插件里一个 `episodic` 子模块同样只有一个写方，而归属是唯一的。
   `D-264` 的两个包同理：检索与语义各自是「一个模块 + 一张面」，不是「一个插件」。
4. **判据面因此更简单**：`HS-001` 的插件面、`E-009` 的事件名 owner、
   `EX-006` 的落点列都少两三个条目，而不是多三个「只差一个文件」的插件目录。

**被否**：

- 保持四个 crate、用 `PLUGIN.yml` 的注释说明「它们是一族」——注释不是归属，
  `deactivate` 时四个插件各停各的，没有任何判据拦得住「只停其中三个」。
- 把文件形态也搬进新 crate（反向：`AGENTS.md` 的读写与 VDFS 挂载是既有插件的
  完整能力，搬它才是真正的破坏性改动）。
- 只并 `-recall` / `-semantic` 两个未来的包、保留已建的 `-episodic`——同一族两个
  归属，比四个更糟：读的人会以为 `-episodic` 是特例，而它恰恰是先例。

**与 `D-263` / `D-264` 的关系**：那两条的**职责划分**（编码走收束贡献、检索走轮首面、
语义走 `Settling.recall`）全部有效，作废的只有「另立 crate」这一半。

### D-268 巩固的格位是债：活集折叠一副，两个读者

**裁决**：名册 #2 的**巩固**（合并算法与触发）住能力包
`crates/symbio-plugin-memory`。四条：

1. **它的格位是债，不是事件**。触发条件是「某标签活条目 ≥ 4」，由记忆包自己的
   `DebtSource` 申报 `memory-consolidate` 一行：活集条数不足 ⇒ **返回空**（不申报），
   不是申报一笔注定 NoDebt 的债；执行体是同一插件的 `memory` 端口，在债 `sent` 之后
   读**计划期快照**落格。环的聚合行仍**不开**（`D-269`：环的判据是事件等值，聚合是
   状态条件），收束贡献仍不收它（无条件、看不见本轮刚落下的编码）。**这是设计结论，
   不是欠账**。
2. **活集折叠一副，两个读者**。折叠（`memory.encoded` ∪ `memory.consolidated` −
   被 `memory.forgotten` 的 `produced_by` 排除的源）住 `crates/symbio-plugin-memory`：
   检索与巩固执行体都在包内私有调用；`memory.live`（`ViewDecl`，`eval` 是同一个折叠
   函数）保留给 `session/stats` 的 `memory` 报表（`D-387`），不再是巩固的跨插件读口。
   这是 `D-221` 已有的机制，**不新增任何面**。
3. **两张事实形状补进 `loop` 的声明表**。`memory.consolidated`（`content` / `tag` /
   `generation` / `fidelity` / `sources` / `vis_scope`）与 `memory.forgotten`（`why` /
   `into`）今天**没有 `FactDecl`**，而 `ViewDecl.reads` 只认已登记的事实字段
   （`seal` 的 `UnknownFact` / `UndeclaredField`）。写方仍在 `loop` ⇒ 形状随写方走，
   补在 `control_decl` 的 `FACTS` 里，不搬去能力包。**（本项已被 `D-270` 订正**：
   形状与归宿行同住能力包——「形状随写方走」只在写方就是词汇 owner 时成立，
   这里不是。**）**
4. **`merge_with_fidelity` 不上门面，也不开共享库**。巩固的执行体在记忆包内直接调
   **包私有**的合并算法（`consolidate/merge.rs`，只依赖 `std`）；机制面这一条不增
   （`D-269` 第 3 条把机制面也纳入棘轮）。全仓普查确认它只有巩固一个生产消费者 ⇒
   「只有一个消费者一律私有，不许库化」，能力包因此不需要 `symbio-sdk` 依赖，
   也不需要 `plugin-entry-allow E-009` 豁免。同族的 `truncate_chars` 有两个不同 owner
   的生产消费者，留在 `symbio_sdk::text::merge_kernel`（字符口径截断）。

**理由**：

1. **一条能力撑不起一次架构改动**。原判（本条改判前）要给轮末开一条面，理由写的是
   「轮首与轮末是两个时刻」——那是 `D-264` 为检索面写的句式的复用，而「族」从来没有
   名册。`D-269` 把准入换成「不提能力名 ∧ ≥2 条能力」，本条过不了第二关：今天只有
   巩固一条能力要这个位置。
2. **代价是明摆着的，收益是零**。把算法留在控制面的代价是「一条算法住控制面」；开轮末
   面的代价是架构多一条位置、机制面多一条门面条目、以及往后每条「≥N」的能力都来要
   同一条面。债是第三条路：位置随 owner 的数据面走，两条代价都不付。
3. **折叠仍然只有一份**。`memory.live` 的 `eval` 与包内检索用的是同一个函数——视图是
   它的**第二种读法**，不是第二份实现。这正是 `D-267`「记忆一个所有者」的兑现：
   若记忆真是四个 crate，这副折叠就得跨 crate，那时只能靠声明视图；现在它是同一个
   crate 里的一个函数 + 一张声明。

**被否**：

- **轮末巩固面 + `merge_with_fidelity` 上门面**（本条改判前的裁决）：为一条能力开位置，
  违 `D-269` 准入 ②；机制面当时无台账，所以那条门面条目是零代价增长——两个错叠在一起。
- **做成收束贡献**：贡献看不见本轮刚落下的编码（巩固特意用刷新后快照），而它要合的
  恰恰是那两条；且拒收是**成组**的（合并产物与两条遗忘同进同退），贡献面没有组。
- **做成环的聚合行**：`Decl.owes` 是 `Pattern{source,key,eq}`，表达不了计数；债每轮开
  一次，而 `RowHandler::run` 必须推进 ⇒ 要么每轮写一条「什么也没合」的事实，要么撞
  步数上界。**（自身的 `DebtSource` 不是这一支**：无物可合时它返回空行，环根本看不见。）
- **`loop` 保留一份私有折叠**：两副折叠（`D-251` 的反面），且迁移后必然漂移。

**一处登记在案的缺口**：`memory.live` 的排除边读的是**信封**字段 `produced_by`，而
`ViewDecl.reads` 只收 `(事实名, 载荷字段)` ⇒ 依赖图少一条「视图依赖遗忘事实」的边。
它不影响读数正确性（折叠拿到的是完整 `&[Event]`），但装配期的依赖图对这条边是乐观的。
不开 `reads` 的口子（那是架构改动，且只为一条边）——这条缺口住这里，不住代码注释。

**落地**：L2b 照原样做**纯迁移**（检索面与 `Settling.recall` 的补件已落，D-264）；
`memory.live` 与两张 `FactDecl` 随 L2b 同批交出（声明面，不涉及架构），`loop` 的
`consolidate` 从「调本地投影」换成「按名字读 `memory.live`」——绑定切换，同一提交。
L2b′（巩固迁出）**由 `D-387` Q3 的债方案恢复**：算法、触发与写口全部住记忆包，
会话不留调用点。

**与 `D-264` / `D-267` / `D-269` 的关系**：`D-264` 第 1 / 2 / 4 条全部有效，第 3 条后半
（「另公开一张无参共享视图 `memory.live`」）**恢复有效**——但性质变了：它是能力包交的
**声明**，不是架构新增的面。`D-267` 的「记忆一个所有者」被第 3 条理由再证一次。
`D-269` 是本条的上级判据：环的聚合行仍不开（第 1 条），本条改用债，不碰那条结论。

### D-270 形状随事实词汇的 owner 走，不随写方走：两张记忆 `FactDecl` 落能力包

**裁决**：`D-268` 第 3 条改判——`memory.consolidated` 与 `memory.forgotten` 的
`FactDecl` **不补进 `loop` 的 `FACTS`**，与它们的归宿行（`episodic::ROWS`）一起住
`crates/symbio-plugin-memory`。三句话：

1. **形状的 owner 是事实词汇的 owner，不是写方**。`D-263` 的「形状随写方走」成立有个
   隐含前提：那条事实的词汇（名字、格子、载荷字段）本来就属于写方那个能力包。
   巩固是反例——写方在宿主，词汇是记忆的（`memory.*` 三格、字段语义都是认知内容侧）。
   写方**借用**词汇时，借用不产生所有权。
2. **`seal` 的两条缺口把它变成硬约束，不是偏好**。`OrphanFact` 要求「被声明的事实
   至少被一行**直接或经视图**读到」，而 `check_rows` 只看**当前装载世界**；`ROWS` 在
   能力包 ⇒ 形状放宿主就必然在自己的小世界里成孤儿（实测：`loop_rows::tests` 58 项
   红，报 `[OrphanFact { fact: "memory.consolidated" }, OrphanFact { fact: "memory.forgotten" }]`）。
   反过来，`memory.live` 的 `ViewDecl.reads` 要读这两条的 `content` / `tag`，形状留宿主
   则包内装载视图报 `UnknownFact`——`E-009`（插件之间不许有兄弟依赖，测试也不许）。
   两头都堵死 ⇒ 唯一活路是形状与行、视图同处。
3. **声明面不算机制增量**。`FactDecl` 是声明，不是面：三棵架构树（`core` / `kernel` /
   `plugin-api`）的 diff 仍为零，`Migration: L2b` 的纯迁移纪律（`EX-003` / `EX-007` /
   `D-245` / `D-247`）不破。

**理由**：

- **写方不需要形状**。写一条事实要的是常量名与载荷，`FactDecl` 只服务声明期的两条检查
  （`ViewDecl.reads` 的字段解析、`OrphanFact` 的归宿配对）——把形状判给写方，是拿
  「谁 append」当「谁定义词汇」。
- **`E-009` 的测试半边同样承重**。能力包的用例必须能在只有自己的声明里装载；形状若
  住宿主，`memory.live` 的每次单测都要拉一个宿主替身，等于把「不许兄弟依赖」改成
  「只许测试依赖」。
- **订正比含糊便宜**。让 `D-268` 第 3 条带一条「已被 D-270 订正」的注，比在代码里留
  一句「此处与设计不符」诚实得多——后者的读者是三个月后的自己。

**被否**：

- **形状放宿主 + 归宿行也搬宿主**：行搬走 `memory.live` 就成了「宿主行读宿主事实」，
  而视图在包内 ⇒ 视图与它读的行分居，`D-268` 第 2 条「一副折叠两个读者」直接散架。
- **`seal` 放宽 `OrphanFact`（允许无行的形状）**：为一次迁移改装载期判据，且会放行
  「拼错名字的静默形态」——那条缺口存在的全部理由。
- **宿主与包各交一份形状**：`DuplicateFact`，装载期直接红。

**落地**：`crates/symbio-plugin-memory/src/episodic/decl.rs` 的 `FACTS` 交两张形状、`ROWS` 交两条归宿行；

**被否**：

### D-293 写口是效果：三类面由能力交纯值草稿，宿主仍是唯一写口

**裁决**：对话面节点、阶段格、实时上线三类面从「宿主函数 / 私有裁决」改为**可声明的
效果**。能力只交纯值草稿，不持写句柄、不拿回调：

| 面 | 能力交的草稿 | 宿主做的写入 |
|---|---|---|
| 对话面节点 | `DialogDraft { role, text, card }`（无轮号、无节点 id） | 定节点 id 与轮号、盖归属与时刻、写转写并实时上线 |
| 阶段格 | `StageDraft { stage }`（无轮号） | `stage_events::land` 折成 `turn.stage`，幂等键 `st-{anchor}-{stage}` |
| 实时上线 | `LiveDraft { frame }`（呈现场景的纯值） | 经既有帧出口发出；失败只记读数，不回写事实 |

宿主按 `(owner, anchor, key)` 顺序处理草稿，并以幂等键拒绝重复投递（重试与续写幕会重复
交同一份草稿）。三类的写口各自仍只有一处：能力交的是**写口的输入**，不是写口本身。
`D-020` / `D-228` 的「唯一作者」因此收窄为「唯一写口」——写法仍一处，作者可以多。I-7 的
上线由「不开放」改为「开放纯值帧声明，执行与失败处置仍归引擎」。

**理由**：

1. **「谁写」与「谁决定写什么」是两件事**。裁决能力（判决、汇报）的产物有一半是对话面，
   而对话面只有一个物理落点；把「能力不能决定说什么」与「能力不能自己写」混成一件事，
   代价就是判决与汇报只能永久留在控制面（`D-291` 的第 3 块）。草稿把两件事拆开。
2. **幂等与顺序只能由宿主守**。能力看不到全局投递次数，也拿不到轮号；幂等键由宿主按
   不透明词干生成（`D-252`），重复投递在写口一处拒绝——这比要求每条能力自觉「只交一次」
   可判得多。
3. **平凡值让「不装插件」逐字不变**。没有任何能力声明某一面时，宿主不会调用写口，输出
   与机制引入前逐字相同；这是「开放效果」不等于「开放语义」的读数。
4. **上线不是事实，是可丢的呈现**。把 `LiveDraft` 的失败限制在读数、不回写事实，才能
   让「帧丢了」与「这件事没发生」保持可分——后者由事实判，不由上线判。

**被否的候选**：

- **B2 窄开**（只开阶段格 + 卡片，对话正文仍宿主）：判决与汇报的措辞仍留控制面，
  `D-291` 的代价原样保留，只解决了落点、没解决说话。
- **B3 不开**：能力永远到不了对话面，与父任务「33 条可插件」冲突。
- **给能力写句柄或回调闭包**：绕开写闸、幂等与盖章，`EventSink` 不再是唯一出站通道。
- **不做幂等键、靠「只调一次」**：重试与续写幕会重复投递；「只调一次」没有任何判据。
- **让能力自带轮号或节点 id**：容器词进端口（`EX-008`），且节点身份有两个作者。

**代价**：能力面多出三个纯值草稿类型，宿主写口要认识三种草稿并按 `(owner, anchor, key)`
排序，写口的测试面变大。能力拿不到节点 id 与轮号，需要身份反馈的产物只能先用宿主给的
幂等键做索引。

**判据**：

- **出现**：一条能力声明三类面之一，端到端能看到节点 / 阶段格 / 帧。
- **重复幂等**：同一 `(owner, key)` 投两次，事实与对话面各只有一条。
- **卸载无静默边**：停用插件后效果面消失，会话照常（`EX-004`）。
- **平凡值**：没有能力声明该面时，输出与未引入效果机制前逐字相同（夹具 diff = 0）。
- `EX-008` 仍绿：草稿字段名不含轮 / 幕（`anchor` 是不透明词干，`stage` 是阶段名）。

**与既有裁决的关系**：

- `D-020`：`EventSink` 仍是唯一出站通道；本条只把「宿主是对话面的唯一作者」收窄为
  「宿主是唯一写口」。
- `D-228`：`stage_events::land` 仍是阶段格的唯一写入口，裁决 1 的「唯一写法」不变。
- I-7：收窄为「流式读取与在途本身不开放」，纯值帧的声明与落格可以开放。
- `D-291`：第 2、3 块（阶段格与对话面）被本条解开；第 1 块（判据在包）与第 4 块（表外
  往返）不变。`D-291` 写的推翻条件②（对话面改成由事实重建）不再是唯一路径——本条走
  的第三条路是「写口效果化」，不改由事实重建。
- `D-093` / `D-222`：草稿不改变行的判据、环的选债与一次一笔债。

**落地**：三类草稿的形状在 `crates/symbio-sdk/src/plugin/effects.rs`（门面转出），唯一写口与幂等键在
`crates/symbio-plugin-tool/src/port.rs` 的 `land_effects`（`:805` 调用、`:810` 定义）；`fn next` 的运行期写入名单按行

`undeclared-write`。按面落地的能力：行执行体这一面当前**无 e2e 证据**（原记录类索引行的用例已随包撤回，D-395）；`SkillRecall`

### D-299 端口单族按名唯一：注册层不再按端口分族

**裁决**：端口注册为**单一 `multi("port")` 族**——注册层（族声明）不再认识端口名，加端口不加族。

- **单一族，每（端口, 提供者）一行**：行名仍为 `<port:{port}>:{provider_id}`
  （`provider_id` 留在表键里，判重文案才有名字可指）；port 行 `active = false`
  （`multi` 族无槽位语义，`put` 的降位块只对带生效位的行触发，active 位不设即互不顶）。
- **按名唯一的读法**：`capability_port_of` 按行名前缀 `<port:{port}>:` 滤出本端口的行——
  0 缺席、1 就绪、`>1` 判重。判重不再依赖 `demote` 的「一活一降」：**两行俱在**
  （谁都没被顶掉），`capability_port_check` 装载期报红并指名两者——比「保一降一」更诚实。
- **闭集与消费面隔离不变**：端口名闭集（`ports::KNOWN`）与「port 行不进六个消费族」的
  结构性用例原样保留。

**为什么不是初稿两案**（对 `Registry::put` 契约的机制核查）：

- **行名固定 `<port:{port}>`（去 provider_id）**：表键是全表唯一名字空间（`IndexMap`
  同名覆盖，见 `Registry::put` 契约），同端口第二提供者会**静默覆盖**第一行——判重从此
  不可判，直接违反 `D-298`「不静默顶掉」的判据。
- **槽位策略加「按名」一档（降位收窄为同族同名）**：同名键覆盖语义下降位副本随即被
  新行覆盖，该档机械上 ≡ `multi`——一个空转的策略是类型里的谎言，不如不加。故本条
  **内核零改动**（`CS-001` 不动，无 `core-shape-allow`）。

**代价**：端口级唯一从「表侧机制」降为「装载期检查」——两个生效者在表内可表达，但任何
装配都会被 `capability_port_check` 判红；读侧 `capability_port_of` 多一次前缀过滤。

**判据**：`port_family` 对闭集内所有端口返回同一族；同端口两提供者 ⇒ 装载期一条指名道姓
的错误 + 调用点 `PortReading::Duplicate`；不同端口互不可见（前缀滤不出对方）；e2e 逐字
不变。

**推翻条件**：某端口确需多提供者共存择优（`D-298` 推翻条件 ③ 的具体化）——届时族策略、
行名与读数一起另裁，不 incremental 打补丁。
