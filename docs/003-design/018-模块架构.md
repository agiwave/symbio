# 模块架构

> [DE-001](001-核心架构.md) 定义机制与契约；本文件定义包拓扑、依赖方向、归属边界与守界判据。
> 包数量不增加机制。共享契约稳定是并行开发的前提；契约不稳定时，增加包边界无助于隔离变化。
> 权威包清单与生产依赖读数由代码和 [RE-006](../004-ref/006-当前事实表.md) 提供。

## 1. 拓扑与职责

| 包 / 臂 | 职责 | 边界 |
|---|---|---|
| `symbio-platform::kernel` | 封闭语法、基础原语契约、声明形状、环求解与冻结机制 | 不含业务 owner、能力名或具体插件 id |
| `symbio-platform::contract` | 稳定的协议线格式与共享数据类型 | 纯形状，零状态、零 IO |
| `symbio-platform::sdk` | 授权、投影、端口、收集、上下文与运行时机制 | 不新增语法，不承载具体业务坐标 |
| `symbio-platform::deploy` | 由插件声明投影的身份、装配位与路由常量 | 生成物，不手改 |
| `symbio-plugin-api` | 扩展插件使用平台能力的显式白名单门面 | 只转发既有契约，不形成第二实现层 |
| `symbio-runtime` | 传输、会话执行、端口行发现、每会话驱动与根工厂协议 | 不认识具体插件或环的类型 |
| `symbio` | 链接插件、执行装配策略、构造根插件 | 不向兄弟插件提供互相可见的出口 |
| `symbio-plugin-*` | 能力包、结构件与控制面 | 扩展插件可卸载；控制面按影响类直接依赖平台 |
| `symbio-providers` / `symbio-provider-*` | 嵌入、检索与存储服务实现 | 不承载架构判据，不反向定义内核语义 |
| `symbio-http` / `symbio-cli` | 通用线路设施与消费面 | 不进入平台依赖环 |

`server` 与 `host` 同住 `symbio-runtime`：前者负责传输与会话执行，后者负责端口行和每会话驱动。
`kernel`、`contract`、`sdk`、`deploy` 同住 `symbio-platform`，对外路径为 `symbio_platform::<臂>::…`。

## 2. 依赖方向

- 平台内部只允许 `sdk → kernel/contract`、`contract → kernel`；`deploy` 不反向定义内核语义。
- 扩展插件的生产依赖闭集为 `symbio-plugin-api`、`symbio-providers`、`symbio-http`。
- 扩展插件不得直接引用 `symbio_platform::*`，不得依赖兄弟插件或装配 crate。
- 控制面按影响类工作，可直接依赖平台；这不改变 manifest 和源码中的边界审计。
- 运行期互调只经共同父容器的显式路由；跨插件载荷使用门面契约中的 JSON 形状。
- 服务实现可替换，但替换不得把 provider 策略推回内核、门面或控制面。

依赖方向由 V-003 守；门面与插件入口由 HS-001、HS-002、HS-003、HS-005、HS-006、E-009 守。

## 3. 归属规则

1. **唯一生产消费方的实现跟随消费方。** 不按文件坐标、生产者 crate 或“谁先写了它”机械决定归属。
2. **跨插件共用的纯机制归 SDK。** 它必须能被不同能力复用，且不携带某个业务名字。
3. **配对契约、封闭语法和全局量词守门留在内核或机制层。** 拆走类型而拆散其约束不成立。
4. **共享词汇由 owner 声明，经生成物表达。** 不复制实现，不建立第二份回落表或兼容别名。
5. **部署与生成事实归 deploy。** 生成物与源码分离，生成物不得手改。
6. **状态跟随唯一权威。** 会话运行、空闲和在途状态只由 runtime 的 host 状态持有；装配层只解析入口和转发查询。

SDK 使用内核类型时走私有导入，不公开镜像内核符号；只有宏卫生或门面转发确需的路径可以例外，且不得形成第二份业务实现。

## 4. 门面与内核准入

### 4.1 门面白名单

- 白名单只许收窄；每一项必须有真实扩展消费方。
- 门面不是第二套实现层，不转发插件类型，不携带会话状态，不替控制面保存副本。
- 扩展插件不使用具体能力实现；控制面需要的机制按影响类直取 SDK。
- 测试设施是门面的显式特性，只在测试夹具或门面自身测试构建中开启，不进入默认生产构建和机制白名单。
- 新增公开项先证明不能由既有契约承担；零调用不自动等于可删，已确权的契约、验证引用和正当转发须先查 owner 与用途。

### 4.2 内核准入

内核只含地址与协议词汇、封闭语法类型、通用形状和冻结机制原语。准入判据是：

| 判面 | 规则 |
|---|---|
| 业务坐标 | 不出现具体插件 id、owner、能力名、业务事件名或 `Entity` 闭集之外的概念 |
| 通用性 | 增加能力或更换部署时不需要修改的字符串，才可能属于地址语法 |
| 策略 | 原语可以包含通用实现，不得长出按具体业务挑分支的策略 |
| 公开形状 | 新增公开项须说明为何不能由既有形状或 SDK 承担 |
| 机械检查 | CS-001、CS-004、CS-005、CS-008、CS-009、CS-010 与人工审共同守界 |

## 5. 可替换性与不可变契约

| 对象 | 可替换性 | 条件 |
|---|---|---|
| `Store` | 实现可替换 | 调用方只依赖基础契约；契约本身不放宽 |
| SDK 机制 | 可替换 | 内核零改动，新增词汇仍走声明 |
| 扩展插件 | 可卸载 | 卸载后系统完整运行，无静默边 |
| runtime / 装配方 | 可替换 | 换装配不改插件；换宿主不改环的类型 |
| 门面白名单 | 只许收窄 | 不得用删除契约或正当转发制造下降 |
| 平台臂职责 | 不可随意互换 | 依赖方向和冻结边界仍由 V-003 与形状棘轮守 |

新增能力的局部性判据是：能力只改自己的声明、装配与实现，受保护树中的非生成物不变，端到端通过。
删除模块或校验时，必须交接其调用方、判据入口和等价用例；没有等价物就不能删除。零调用审计只判新增公开项，存量只许收窄，且不能靠删契约制造“净减”。

## 6. 投影与不变量归属

- 投影只读事件与显式时间，不接收存储句柄、外部 IO 或隐式时钟。
- 唯一生产消费方的投影跟随消费者；共享读取只按名字经声明、报表或冻结视图表进行。
- 不按类型读另一个插件的内部折叠，不复制算法，不建立跨插件编译依赖。
- 投影构造器必须有外部生产消费者；SDK 共享投影面只许收窄，owner 投影仍受 PP-001、PP-002、PP-003 约束。

## 7. 守界判据

- V-001、V-002、V-003：共享词汇面、SDK 域间依赖与平台臂方向。
- HS-001、HS-002、HS-003、HS-004、HS-005、HS-006：扩展门面、白名单消费方、默认特性与旧路径。
- E-009、EX-004：插件编译期零边与卸载完整性。
- CS-001、CS-004、CS-005、CS-008、CS-009、CS-010：内核形状与业务坐标。
- PP-001、PP-002、PP-003、PP-004：投影纯度、消费方与 SDK 投影面。
- RB-001：runtime 不反向依赖装配方。

形状棘轮和门面白名单只许收窄。实现困难时改实现或发起架构讨论，不得放宽机制面。
