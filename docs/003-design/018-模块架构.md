# 模块架构

> [DE-001](001-核心架构.md "DE-001-核心架构") 定义机制与契约；本文件定义 crate 拓扑、依赖方向、归属边界与守界判据。
> crate 数量不增加机制。每个包必须满足：替换它不需要改动 DE-016 的 F1–F6。
> 权威 crate 清单与生产依赖读数由代码和 [RE-006-当前事实表](../004-ref/006-当前事实表.md "RE-006-当前事实表") 提供。

---

## 1. 架构视图与 crate 视图

| 视图 | 问的问题 | “模块”的含义 |
|---|---|---|
| 架构视图（DE-001） | 系统存在哪些机制 | 只有 `Store` 一个原语，其余是数据与契约 |
| crate 视图（本文件） | 代码怎么放、谁依赖谁、谁守边界 | 可独立编译与替换的实现包 |

共享契约稳定是并行开发的前提；契约不稳定时，增加 crate 边界无助于隔离变化。

## 2. crate 拓扑

非插件 crate 共 6 个：装配、运行时、扩展门面、平台、线路、provider 集。

```
                     ┌──────────────────────────────┐
                     │ symbio（装配）               │
                     │ 链接插件 · 装配策略 · 根工厂   │
                     └──────────┬───────────────────┘
                                │
              ┌─────────────────▼──────────┐   ┌──────────────────┐
              │ symbio-runtime（运行时）   │   │ symbio-cli       │
              │ server：传输与会话执行     │◄──│ 控制台客户端     │
              │ host：port 行 · 每会话驱动 │   └──────────────────┘
              └─────────────────┬──────────┘
                                │
     ┌──────────────────────────▼─────────────────────────────┐
     │ symbio-plugin-api（扩展层门面）                        │
     │ 白名单转发 kernel 语法 + contract ABI + sdk 机制 +      │
     │ deploy 常量；testkit 仅在 test-fixtures 特性下编译      │
     └──────┬─────────────────────────────────────────────────┘
            │
   ┌────────▼──────────────────────────────────────────────┐
   │ symbio-platform（一个 crate，四条臂）                  │
   │ kernel    封闭语法                                    │
   │ contract  插件 ABI 纯形状                             │
   │ sdk       宿主机制与策略（依赖 kernel / contract）     │
   │ deploy    生成物：id / 装配位 / 路由常量               │
   └───────────────────────────────────────────────────────┘
```

- `symbio-http` 是插件之下的通用线路层。gateway / heartbeat 等插件直接依赖它，并入运行时会形成环。
- 扩展层插件的生产依赖闭集是 `symbio-plugin-api` + `symbio-providers` + `symbio-http`；共享语法只经门面转出。
- 控制面插件 `loop` / `session` 按影响类直接依赖 `symbio-platform`，不经装配 crate 中转。
- `symbio-providers` 与 `symbio-provider-*` 提供嵌入、检索与 VDFS 落盘等具体服务；服务实现不承载架构判据。

## 3. crate 一览

| crate / 臂 | 职责 | 可替换性 |
|---|---|---|
| `symbio-platform::kernel` | 封闭语法、`Store` 契约、投影形状、声明容器、环求解器与冻结机制原语 | 不可替换；语法改动影响全仓 |
| `symbio-platform::contract` | 插件 ABI 纯形状；零状态、零 IO | 接口形状冻结；只允许 D-486 规则 B 准入的纯形状 |
| `symbio-platform::sdk` | 配置 IO、事件总线、VDFS 地址、授权、默认收集器、actor 策略、共享投影词表、不变量与提示机制 | 机制可替换；不得新增语法或业务坐标 |
| `symbio-platform::deploy` | 由 `PLUGIN.yml` 投影的 id、装配位与路由常量 | 生成物，不手改 |
| `symbio-plugin-api` | 扩展层白名单门面；转出 kernel / contract / sdk / deploy 的既有契约面 | 对扩展插件不可替换；白名单只许收窄 |
| `symbio-runtime` | 传输、会话执行、port 行发现、每会话驱动与缓存、根工厂协议 | 可替换；不认识具体插件或环的类型 |
| `symbio` | 链接插件、执行装配策略、构造完整根插件 | 可替换；插件之间不得经它互相可见 |
| `symbio-plugin-*` | 能力包、结构件与控制面；一个插件一个 crate | 扩展插件可卸载；控制面按影响类 |
| `symbio-providers` / `symbio-provider-*` | 嵌入、检索与 VDFS 服务实现 | 可替换 |
| `symbio-cli` / `symbio-http` | 消费面与通用线路设施 | 不在架构层 |

平台臂只许 `sdk → kernel/contract`、`contract → kernel`；`deploy` 零内部依赖（V-003）。臂边界由 `domain-vocab-audit` 守，不依赖独立 crate。

### 3.1 依赖与投影约束

生产依赖、插件身份与 provider 消费者以 RE-006 的生成事实为准。强制面是：

- `plugin-surface-audit` HS-001 / HS-005：扩展插件只能经门面取共享语法。
- `plugin-entry-audit` E-009：扩展插件不得直连平台、兄弟插件或装配 crate。
- 跨插件通信只经 `parent.route(ctx.set(PATH, ROUTE_X))`。
- `Projection::new` 只接受 `Fn(&[E], Timestamp) -> V`；`Projection::apply` 统一执行预算与降级。闭包无法取得 `Store` 或另一个投影，强制力来自函数签名而非构造器可见性。

### 3.2 时延预算

`LatencyTier` 是内核的四层预算词表，按 `budget_ms` 判档。`port.model` 执行面不按档位拒绝模型调用。模型调用的档位执行约束归 DE-053 的 D-438，本文件不把预算词表称为已实现的闸门。

### 3.3 内核准入判据

kernel 只含语法类型与逐条登记的冻结机制原语，不含业务坐标。

| 半边 | 判什么 | 强制方式 |
|---|---|---|
| 可执行 | 内核生产代码直接出现 `PLUGIN.yml` 的 owner 或能力名完整字面量 | CS-010；CS-004 / CS-005 / CS-008 / CS-001 / CS-009 覆盖插件 id、事件词表与形状棘轮 |
| 人工审 | 新增公开项是否只碰通用形状、是否引入策略、每个字符串属于地址语法还是业务概念 | 新增 `pub fn` / `pub trait` / 模块时逐条审；分类表见 D-398 |

`MemoryStore`、`exec`、`present` / `detail` 属于存储基线、出口与中止、表单求解器等冻结原语。它们可以包含实现，但不得长出按业务挑分支的策略。

## 4. 可替换性与替换判据

| 对象 | 能不能换 | 判据 |
|---|---|---|
| kernel 语法 | 不能 | 改语法即改冻结面 F1–F6 |
| `Store` 实现 | 能 | 调用方只依赖 `Store` trait |
| sdk 机制 | 能 | 替换后内核零改动；新增词汇走声明表 |
| `symbio-plugin-api` 白名单 | 只许收窄 | HS-001 / HS-002 / HS-003 / HS-006 棘轮 |
| 扩展插件 | 能 | 卸载后系统完整运行 |
| `symbio-runtime` / `symbio` | 能 | 换装配不改插件；换宿主不改环的类型 |

新增能力的扩展局部性判据是：新建插件 crate、写 `PLUGIN.yml`、声明自己的端口 / 行 / 工具；kernel、sdk、门面与控制面插件零 diff。该判据由装配与表面审计执行。

## 6. 边界纪律

1. 投影只读事件与时间，签名不接收 `Clock`、存储或外部句柄。
2. 门面每条白名单都必须有真实扩展消费方；门面不是第二套实现层。
3. 形状棘轮与门面白名单只许收窄。实现困难时改实现或发起架构讨论，不得放宽机制面。

## 关键决策

> 本节只记录仍约束当前终态的裁决；推进过程、验证过程与提交记录不属于设计文档。

### D-039 session 按域重组：一域一目录，编排层与领域层分离

session 内部按领域分目录，目录之间只经明确协议通信。跨域连锁修改与单文件承担多项职责都视为边界失效；拆分以完整依赖闭包为单位，不拆散同一领域的状态与算法。

### D-398 kernel 判据：语法类型 + 冻结机制原语

kernel 准入按正向清单，不按“零实现”。允许项只有：

- 地址语法与协议词汇：`session/{name}`、`person/local`、端口名、信封与载荷字段名。
- 封闭语法类型与通用形状。
- 逐条登记的冻结机制原语。

禁止能力名、具体 owner 名与 `Entity` 闭集之外的业务概念。分类判法是：这句话描述“地址怎么写”还是“谁叫什么”；换个部署或增加能力时需要修改的字符串就是业务坐标。

CS-010 机械检查完整字面量；字符串拼接不在其覆盖面，新增公开项仍须人工审词汇、通用形状与默认体策略。`MemoryStore`（存储基线）、`exec`（出口 / 中止 / 帧序）、`present` / `detail`（表单方言与求解器）均属冻结原语。新增原语必须补入本节并说明不能移至 sdk。

### D-399 plugin-api 自有实现行数只许降

`facade-loc-audit` 同时约束五个自有实现文件与 crate 生产行总数：超限即红，读数下降必须同批收紧基线。测试代码、测试专用 cfg 模块、`testkit` 与描述符登记的生成物不计入实现行数；空行与面向读者的注释计入。基线自身受元守卫，不允许通过改大数字绕过棘轮。

### D-400 会话空闲状态只归运行时

`running` / `dirty` / `in_flight` 与唤醒句柄只由 `symbio-runtime` 的 host 状态持有。装配层只解析登记入口并转发查询，不得维护第二份按会话状态表；等待实现必须读取同一份 `KickState`。

### D-405 删模块必须交接校验与判据

删除模块时，提交正文必须用 `Removed-Calls:` 列出旧校验 / 裁剪 / 判据入口及其新等价物。没有等价物时只能同批接线并补用例，或登记有 owner、理由与期限的待裁基线。`arch-dead-code-audit` 在调用点消失的提交上检查新增零调用公开项，防止判据随编排一起静默失效。

### D-408 effects / behaviors 归 sdk 机制臂

`effects`、`behaviors`、`ToolBehavior`、`BehaviorDecl` 与提交宏是同一个链接期类型闭包，整块归 `symbio-platform::sdk::plugin`。`inventory::Collect` 必须在类型定义 crate 生成，契约副本或运行时注册表都不允许。门面只保留既有模块与宏的白名单转出。

### D-412 context 归 sdk 机制臂

`ContextProvider`、请求 / 段落 / 拟合值类型、声明注册表、提交宏与预算裁剪算式同属一个类型闭包，整块归 sdk。门面不保留实现副本；扩展插件继续经门面使用既有名字。

### D-413 链接期注册表归 sdk，门面只转模块名

`retrieval` / `rows` / `settle` / `fact_source` / `drive_entry` 的 trait、值类型、注册表与读取算式整块归 sdk。门面不为这些模块保留纯转发文件；模块名与提交宏在根上显式转出。`drive_entry` 只转出有扩展消费方的 `publish_deployment_root`，宿主与控制面按影响类直取 sdk。

### D-414 端口装配判重归 sdk

`capability_port_check` 读取注册行、派生端口集并写入能力错误桶，属于宿主机制，归 `sdk::capability::port`。`PortProvider` / `PortPayload` / `port_rows` 是插件申报面，留门面；写表与校验不拆成第二份实现。

### D-415 声明表冻结机制归 sdk，词汇读法留门面

`DeclarationsDecl`、链接期收集、装配与 owner 校验、进程冻结表及提交宏归 sdk。`PLUGIN.yml` 的 `shared_events` 生成物与 `vocab()` / `declared_event_cell()` 留门面词汇层；sdk 生产代码不得承载事件名字面量，也不允许第二份回落表。

### D-416 reports 与 ViewUnavailable 归 sdk

报表声明、读取、渲染与 `ViewUnavailable` 共享冻结声明表，整块归 sdk。门面只转出有扩展消费方的模块与提交宏；`ViewUnavailable` 没有扩展消费方，控制面直接取 sdk。

### D-417 插件链接行不使用公开出口

装配 crate 的生成链接行写成 `use symbio_plugin_<id> as _;`，只保证 `inventory` 注册项进入最终二进制，不把插件完整公开面挂到 `symbio::`。出口只保留显式需要的门面与 hooks / routes。

### D-418 扩展插件只经门面使用平台契约

扩展插件生产依赖闭集为 `symbio-plugin-api` + `symbio-providers` + `symbio-http`。它们不得在生产源码或 manifest 中直连 kernel / sdk / contract / deploy；控制面 `loop` / `session` 按影响类直连平台。测试需要 `MemoryStore` 等基线时使用 dev-dependency，不扩大生产依赖承诺。

### D-419 sdk 对内核词汇不保留第二条公开路径

sdk 域内使用内核类型时走私有 `use`，不公开镜像内核符号。只有宏卫生要求的 `$crate` 路径可以保留 sdk 公开出口，避免把 kernel 依赖推给每个扩展插件。`principal_namespace` 等地址解析按职责归 authz，不借纯转出模块保留旧地址。

### D-420 chat 组合模块按词汇与实现分拣

对话线格式与主体类型归 kernel，经门面语法臂转出；sdk 只保留自己的投影与载荷实现。宿主端口载荷归 contract 纯形状，不进 kernel；只有 sdk 自有且有扩展消费方的实现进入门面机制臂。

### D-434 草稿转事件只有写口一条路径

`FactDraft::into_event` 已删除；`draft_into_event` 是草稿进入事件信封的唯一转换器，统一提取 `cost_ms`。`port_of` 是声明表查询口，`with_cost_ms` / `with_status` 是契约构造口，不因本仓生产调用点未直用而删除。零调用基线只对新增项判红，存量只许降且必须有 `why` 与 `evidence`。

### D-470 门面行数不数清单镜像

`facade-loc-audit` 只把非生成物计入实现行数。生成物范围复用 `generatedPaths` 描述符，不按文件名猜测；生成模块仍受存在性登记。增加 `PLUGIN.yml` 声明不应被误判为门面实现增长。

### D-511 简化不删契约、验证引用或正当转发

以下对象不是可供“降数字”清理的实现债：

- `arch-dead-code` 中已确权的公开构造口与查询口；删除即破坏第三方插件契约。
- verify 程序对生产源码的 `#[path]` 引用；它们保证验证器执行真实实现而非副本。
- sdk 中为宏卫生或门面转发保留的少量内核路径；它们不是第二份业务实现。

判断零调用、冻结或耦合能否简化，先查 owner 与 `why`。形状与门面棘轮只针对真实实现债；为读数删除契约或验证机制违反 DE-002 的妥协边界。

### D-513 会话数据目录与记忆所有权

`SESSION_DIR` 是 session 按唯一存储布局解析并下发的会话级插件数据目录；插件只读现成值，不从 `SESSION_ID` 拼路径，子上下文继承该值。它不是事实源路径，不得用于拼 WAL 路径或直接打开事实存储。

文件型长期记忆唯一归 `memory` 插件，按智能体、工作区、会话三层叠加，物理文件均为 `MEMORY.md`，挂载名分别为 `MEMORY.md` / `WORKSPACE.md` / `SESSION.md`。稳定指令 `AGENTS.md` 归 `setting` 两级只读覆盖（D-527）。session 只拥有 WAL、`session.json`、`messages.json` 与子会话存储；事实读写仍只经 `FACT_SOURCE` / `FactSource`。

### D-556 平台四臂同住 symbio-platform

kernel / sdk / contract / deploy 同住 `symbio-platform`，对外路径为 `symbio_platform::<臂>::…`。臂的职责、依赖方向与生成物边界由 V-003 与臂目录审计执行。`#[macro_export]` 仍挂 crate 根，并在 sdk 命名空间显式转回。装配 crate 不重导出平台四臂，插件之间不得经它可见。

### D-557 server 与 host 同住 symbio-runtime

`server` 传输 / 会话执行与 `host` port 行 / 每会话驱动同住 `symbio-runtime`。部署驱动入口归 `src/host/entry.rs`，依赖方向只允许装配方 → 运行时。`symbio-http` 保持插件之下的独立线路层；传输协议与 `ServerConfig` 形状保持稳定。

### D-558 事实边界保留单槽绊线

事实边界由 `facts-boundary-audit` FB-003 / FB-004 执行两条单槽绊线：`submit_fact_source_opener!` 登记点恰好一处，`AddrRootDecl(` 不得重复。能力事实路径禁词、兄弟插件边界、门面白名单与内核形状棘轮有效；不设永久符号冻结账，不放宽其它安全边界。

### D-559 历史路径按显式别名折算

历史审计只使用 `LEGACY_TREES` / `canonicalPath` / `inTrees` / `legacyPathspecs` 的显式别名。git pathspec 必须同时包含旧名与新名；不允许字符串模糊匹配，也不把 `crates/symbio` 放宽为整个装配方。历史决策保留当时路径，现行文档只写当前路径。

### D-560 平台臂依赖方向由 V-003 守

剥注释后只允许 `sdk → kernel/contract`、`contract → kernel`；`deploy` 零内部依赖。反向引用即红。sdk 内部跨域无环由 V-002 管，provider 与插件不属于平台臂依赖图。

### D-561 控制面投影实现归 session

`branch` / `elision` / `mutations` / `transcript` / `prompt_fidelity` / `facts` / `node_build` 的实现与同源测试归 `symbio-plugin-session::projections`。`vocab` 三张共享参数表、`invariants` / `governance` / `drive` 留 sdk；`result_node_id` 是 kernel 规则，sdk 的 `round::node_build` 只保留既有转发。`prompt_fidelity` 由 session 测试直接使用，不经 testkit 转出。迁移不保留运行时别名、不拆函数、不新增适配接口。

### D-562 运行时通过 RootFactory 接收装配能力

`symbio-runtime` 定义最小异步 `RootFactory`：接收 `PluginSimpleRequest`，返回独立根插件。`RuntimeHost::create`、隐藏 worker 命令与 `WorkerSupervisor` 显式接收工厂；CLI / Tauri 在组合边界适配完整装配。运行时的生产、构建与开发依赖及生产源码均不得引用 `symbio`（RB-001）。

控制面根插件与每个会话执行体分别调用工厂，保持独立树、epoch、durable inbox 与 WAL 写锁。HTTP 分发桥先于控制面工厂安装；worker 先规范化 `SYMBIO_HOMEDIR` 与解析会话目录再调用自己的工厂。provider 下沉、服务容器与插件发现不进入运行时。

### D-563 测试设施是门面的显式特性

测试夹具归 `symbio_plugin_api::testkit`，由 `test-fixtures` feature 或门面自身 `cfg(test)` 开启。插件只在 dev-dependencies 中开启该 feature；默认生产构建不编译测试设施。夹具只转出平台机制与门面既有契约，不转发插件类型、不携带会话状态，不进入生产根出口或 HS-002 / HS-006 白名单。

### D-564 默认收集器归 sdk

`DefaultToolVisitor` / `new_registry` / `register_tool*` / `approval_gate*` 与 `FactsOf` / `AsyncFactsOf` / `RiskOf` 归 `symbio-platform::sdk::collectors`。它们是跨插件有状态写入机制，不属于嵌入或 VDFS 服务实现。门面只转出 `collectors` 模块；`composite` / `glossary` / `heartbeat` / `vdfs` / `web` 不依赖 providers，providers 不依赖门面。嵌入与 VDFS 三实现归 providers。

### D-565 TaskVocab 归 task 包

`TaskVocab<'a>` 与 `TASK_VOCAB` 归 `symbio-plugin-task::decl`，只在本 crate 内可见；task 直接引用本包事件常量。平台 sdk 与门面没有 `task_vocab` / `TaskVocab` 出口，也不设兼容别名。actors 测试只声明实际使用的任务事件字面量，不反向依赖 task 类型。

共享 `ChatVocab` / `MessageVocab` / `CommitmentVocab` 归 `sdk::projection::vocab`。任务词汇面不改变任务事件、就绪算式、路由、工具名或存储布局。
