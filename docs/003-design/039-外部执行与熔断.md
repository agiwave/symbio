# 外部执行与熔断

## 内容

前置：S08 ｜ **新增机制键 0** ｜ 参数变化 4
## 1. 场景：要什么能力

智能体能对外部世界产生**不可逆后果**（写文件、发消息、下单、调生产接口），
并且有硬闸门：超预算 / 高风险 / 未授权时**熔断**，而不是"先做了再说"。

相对 S08 高了什么：S08 之前的所有副作用都是"系统内部的"；本阶第一次对外产生真实后果。
**T5→T6 的分界就在这里**：从"能做事"到"做的事有代价"。

## 2. 为什么它能落在 v2 上（J1）

| 看起来新的东西 | 实际是 |
|---|---|
| 外部动作 | 一个 Actor 的一次 `progressed`，写 `artifact/asserted` |
| 熔断 | 一个 `Decider`，`budget_ms = 80`，写 `control/opened` |
| 风险分级 | `grants` 表里的能力名（闭集 7 名；外部轨 = `produce.artifact`）——**数据** |
| 预算控制 | `projection = budget` + I3 |

**关键**：内外双轨（Internal / External）在 v2 里**不是两套动作空间**，而是 grants 表里的能力名 + 高风险组合的构造期拒绝。
> 认知体系提出的"内外双轨动作空间（CoALA）"就落在这一阶——它不需要新机制，
> 只需要"内向推演"与"外部破坏性执行"在授权上分开。
按 J1，能用授权表表达的就不占机制位。**新增机制键 = 0**。

## 3. 增量清单（只加数据）

| 类型 | 内容 |
|---|---|
| 事件格子 | 复用 `control/opened`、`artifact/asserted`——**不加新格子** |
| ActorSpec 行 | 闸门 `{ pattern: decider, capabilities: [ProduceArtifact], budget_ms: 80, scope: root }` |
| grants 行 | 外部执行主体只授予 `produce.artifact`；高风险组合（`ProduceArtifact` 与 `DefineWork`+`AssertVerification` 同持）在**构造期拒绝** |
| 投影参数 | `projection = budget`（累计成本视图） |

**本阶点亮的机制键**（阶梯总表的「新增机制键」由这张块算出；`scripts/gen-verify-facts.mjs` 从这里取输入）：

```capability-assign
event.entity = control
event.verb = asserted
actor.pattern = decider
projection = budget
```

## 4. 平凡值与回退（J2）

| 参数 | 完整值 | **平凡值** | 平凡值下 |
|---|---|---|---|
| `actor.capability` | `produce.artifact`（外部） | **`reply`** | 仍完整运行——只用文字描述要做什么，不真做 |
| `actor.budget_ms` | `80` | `60000` | 仍完整运行——闸门慢，但闸门仍在 |

**`reply` 是本阶唯一安全的退路口**：把"会对外产生后果"降级为"只说不做"，
系统仍是一个完整的对话系统（状态），只是丧失执行力。

## 5. 静默失效与强制（J3）

| 约束 | 违反时信号 | 强制方式 |
|---|---|---|
| 未授权的外部执行 | **无**——只是多了一条事件 | 写侧 `grants_of` 编译期强制 |
| 熔断必须在 80ms 内产出 | **无**——静默超时 | I3：超时必须产出 fallback 事件 |
| 高风险组合不得同主体持有 | **无** | 构造期拒绝——`governance` 建表即校验（`governance/mod.rs`） |

## 6. 验收断言

1. 未持有 `produce.artifact` 的主体尝试外部写入 → 被拒绝，**且不产生事件**。
2. 预算耗尽 → 必须产出熔断事件，不允许静默继续。
3. grants 表中出现高风险组合 → **构造期拒绝**（建表即报错）。
4. **反向用例**：把预算放宽 → 断言 2 的判定必须改变（证明预算在生效而非常量）。

**§6 验收断言的执行方**：闸门判据与开窗事实住 `crates/symbio-plugin-tool` 的执行体（`breaker.rs` + `port.rs::execute`），环只交中性输入（`GateInputs`，D-311 / D-312）；验收 1 / 2 / 4 在那一侧——1 = `crates/symbio-plugin-tool/src/port.test.rs::unauthorized_calls_are_refused_with_zero_events`（未授权 ⇒ 拒绝且零事件）；2 = `crates/symbio-plugin-tool/src/port.test.rs::exhausted_budget_breaks_and_lands_a_control_event`（预算耗尽 ⇒ `Break`，`control × opened` 带 `reason`——不许静默）；3 = `crates/symbio-sdk/src/actors/mod.test.rs::high_risk_grant_combo_is_rejected`（构造期拒绝）；4 = `crates/symbio-plugin-tool/src/port.test.rs::affordable_calls_run_without_any_event` 与验收 2 用例的对照（同一份输入、预算放宽 ⇒ `Allow`）。

熔断不设 e2e 专列：存储层的判断归 Rust 单测，读通道禁令下 e2e 不碰存储布局（理由见 `e2e/cases/t42-full-derives-commitment-task.mjs` 头注）。

## 8. 这一阶做不了什么

边界的唯一账本：[SC-009-外部执行与熔断](../002-scene/009-外部执行与熔断.md "SC-009-外部执行与熔断")（用户语言）。机制面独有边界（用户可见范围之外的工程约束）：

- 不可逆动作的**补偿/回滚**未定义：v2 的撤销语义只覆盖日志内部（`memory.forgotten` 是投影排除）。
- 成本首测已落地（基准见 `RE-004-slo-calibration`）；`budget` 投影读的是实测 `cost_ms`。

## 9. 拆分裁决：闸门的三个出口有两个不在 I-3 里（D-271，已被 D-311 / D-312 取代）

**裁决**：名册第 8「副作用分级」**不迁**，留控制面（守门）；`L4` 批次取消。三句话：

1. **判据的两个输入都不在能力包可读的面上**。授权走 `production_matrix()`（`core` 的封闭
   语法，E 类），已耗走声明视图 `cost.ledger`（`crates/symbio-plugin-cost/src/decl.rs::ledger`，
   D 类共享折叠，owner 是名册 #18 的
   `symbio-plugin-cost`，S8）。能力包只链接 `plugin-api`（DE-025 D-258）、不许兄弟依赖
   （E-009）⇒ 迁走判据就得把这两样一起交出去，而它们一个不能开、一个还没落成。
2. **I-3 的形状表达不了这个闸的两个出口**。`BeforeRefusal` 只有四个字段，拒绝的退出
   语义写死在「可审计拒绝：拒因进结果」这一档。
   本闸要的却是 `ZeroEvent`（§6 验收 1：拒绝**且不产生事件**）与 `Recorded`（验收 2：
   熔断**必须**入格 `control × opened`，不许静默）。三个出口里两个在 I-3 之外 ⇒
   迁它不是迁移，是**新开一格**。
3. **「分级」的另一半本来就不是判据**。风险档来自 `CapabilityMeta::effective_risk()`
   ——工具自己的声明；宿主只做「档 → 串行 / 并行 / 深度档」的映射
   （`policy_for_risk`），那是执行策略，落在 I-7 过程体（不开放）。

**理由**：

- **原判的理由被撤，结论也换了一条理由**。`D-190` 说「归属不构成留守理由」，那一句仍然
  成立；本条不拿归属说事，拿**出口**说事——一条能力的拒绝语义若在影响类里长不出来，
  它就不是「今天没端口」，而是写不进闭表。
- **判据同源，落点各自判**（DE-026 `D-268` 及其订正）：巩固因「活集判据属于记忆」
  随 owner 走债；熔断的判据是**整条都是强制点**——这里成立：授权是 I-8 明列的强制点，
  而「预算耗尽必须留痕」本身就是 §6 的验收断言——留痕义务不是能力的意见。
- **前置条件写得出来，所以这不是一句「不做」**。等 `symbio-plugin-cost` 落成（S8），
  成本台账变成包内视图，那时可以重新评估「熔断判据作为 cost 包的一条 `before`」；
  前提仍是 I-3 的出口先长得出 `ZeroEvent` / `Recorded`，否则同样的墙。

**被否**：

- **给 I-3 加两个出口**（能力说「拒绝且零事件」/「熔断并入格」）：出口语义是引擎口径
  （§6 四条验收逐条钉的就是它）。交给能力，等于把「拒了要不要留痕」变成每个包各自的
  选择，审计面随之不可判。
- **把授权矩阵经端口交进来**：为一次迁移开放封闭语法（E 类）；且授权是 fail-closed 的
  写侧强制，值一旦过端口就变成「能力可以选择不看」。
- **拆成「能力判、宿主记」两半**：判据只是三个标量的比较，拆开之后「为什么熔断」跨两个
  owner，而验收 2 要的是同一处产出的事件。

**落地**：本条已被 D-311 / D-312 取代——`emit` 面兑现了 `ZeroEvent` 与 `Recorded`
两个出口，判据与开窗事实因此搬进 `symbio-plugin-tool` 的执行体（`breaker.rs` +
`port.rs::execute`），环只交中性输入 `GateInputs`（`gates.rs` 的 `GATES` 与
`tool_executor/breaker.rs` 的 `BreakerInputs` 已删除）；DE-026 名册 #8 仍判 `留 守门`
（授权矩阵读侧留环）。
