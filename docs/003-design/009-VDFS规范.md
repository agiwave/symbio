# VDFS 虚拟动态文件系统规范

VDFS 用 **一个协议、一个统一文件系统、一个容器拓扑** 承载全部资源与数据访问。前端和
模型使用同一组 `vdfs/*` 操作、同一种寻址和同一个 `UnifiedFs`。

本文只定义机制。具体资源目录、插件清单和文件位置由代码与 [当前事实表](../004-ref/006-当前事实表.md "RE-006-当前事实表")
提供。

## 1. 不变量

1. **一个协议**：所有资源只经 `vdfs/*` 访问，不新增私有资源协议。
2. **provider 自持**：数据、状态、校验与呈现描述由实现方负责；机制只按访问位判断能力。
3. **路径唯一**：虚拟地址为 `<根>/<子目录>/<相对路径>`，物理地址为工作目录相对或绝对路径。
4. **接口纯净**：VDFS 接口不依赖宿主类型，可独立复用。
5. **访问同源**：前端与模型最终经过同一个 `UnifiedFs`，资源集合与地址规则一致。
6. **位置外置**：provider 不知道自己的挂载位置，只处理自身子树的相对路径。
7. **拓扑归容器**：只有组合容器持有子目录拓扑。
8. **容器同构**：composite 只是包含子目录的 provider，没有不可替代的根级身份。

## 2. 分层

| 层 | 职责 | 边界 |
|---|---|---|
| 纯接口 | `VdfsProvider`、域类型、路径工具、错误 | 不依赖宿主，不暴露线路类型 |
| 宿主桥 | 注入上下文、翻译宿主错误 | 不依赖具体资源插件 |
| 线路协议 | `vdfs/*` 信封、操作常量、路径常量 | 留在插件内部 |
| 访问层 | 拆信封、调用统一文件系统、树遍历、变更投递 | 不含资源语义 |
| 门面 `UnifiedFs` | 根前缀判别、虚拟与物理分流 | 不持有拓扑 |
| 物理层 | 磁盘文件与路径安全守卫 | 只处理物理地址 |
| 组合容器 | 聚合子 provider，提供目录拓扑 | 唯一持有子目录关系 |

依赖只能向下。纯接口不得引用宿主内部类型；宿主状态只经 `VdfsContext` 注入。接口错误由
VDFS 定义，桥层一次性翻译为宿主错误。呈现描述作为不透明 JSON 放入 `schema`，VDFS 不解释。

### 2.1 provider 与位置

`VdfsProvider` 是 object-safe 纯接口，以统一 dispatch 表达列、读、写、删、建、动作和订阅。
不支持的操作返回 `NotImplemented`，消费方据此隐藏入口。

provider 不声明 `mount / category / root`，不接收自身绝对地址，也不在变更中报告挂载名。
容器负责拼接和回填地址。同一实现可放在不同位置，重命名挂载点不修改 provider。

### 2.2 拓扑归容器

容器逐子插件查询其 VDFS 视图，按实例挂载名聚合为“包含子目录列表的 provider”。聚合结果
现场计算，不缓存第二份插件清单。容器可以嵌套容器，父容器只把子容器当普通 provider。

## 3. 地址与节点

### 3.1 地址

```text
<根>                         虚拟根
<根>/<子目录>/<相对路径>       虚拟子树
README.md                    工作目录相对路径
/docs                        文件系统根下路径
<盘符>:/...                  绝对路径
```

规范化折叠空段与 `.`，逐段去除首尾空白，拒绝 `..`，保留首部 `/` 的绝对锚点。`docs` 与 `/docs` 不是同一位置；
工作目录根写作 `.` 或空串。Windows 物理路径拒绝 NTFS 备用数据流别名（盘符冒号除外）；
不能在 `canonicalize` 后才判断，因为它会把 `PLUGIN.yml:stream` 折叠成 `PLUGIN.yml`，隐藏原始流身份。

虚拟根必须独占首段：`<根>foo` 不是虚拟地址，`/<根>/…` 也不是。门面在入口和回程各做一次
口径映射：虚拟层接收去掉根名的相对地址，返回时补回根名；物理层不映射。

根名由 VDFS 插件静态声明，消费方启动时通过 `vdfs/root` 获取并作为运行期数据保存。跨挂载
边界转发时更新上下文中的当前父地址；插件需要绝对地址时使用封装函数拼接，不写死根名。

### 3.2 VdfsNode

`VdfsNode` 是文件与目录的统一自述，不含地址：

| 字段 | 语义 |
|---|---|
| `name` | 父内唯一路径段 |
| `title` / `description` | 展示标题与说明 |
| `kind` | 自由场景标签，机制不据此判定类型 |
| `status` | `active` / `working` / `disabled` / `failed` / `unknown`；缺省 `active`，空串表示无运行态 <!-- vocab:VDFS_STATUS_ --> |
| `access` | 机制唯一能力依据 |
| `ext` | 详情渲染器键 |
| `size` / `updated_at` / `children` / `binary` | 元数据 |
| `new_type` | 该目录可新建的一种节点描述 |
| `schema` | 不透明呈现定义 |
| `attributes` | 场景扩展字段 |

目录性只由 `access.list` 表达，不按 `kind` 猜测。`attributes` 扁平化到线上顶层，因此不得与
机制保留字段同名。

#### hidden

`hidden` 只影响导航列表：默认 `list` 不返回隐藏节点，`children` 计数也不包含；按路径
`stat / read / write` 与子树操作不受影响。隐藏不是权限，也不表示节点不存在。

`list` 的调用级 `with_hidden` 参数把导航读法与发现读法分开。发现可以看见隐藏名称，但
能力仍只由 `access` 决定。过滤由产出列表的一方统一执行，不按 provider 来源区别处理。

### 3.3 VdfsItem 与内容

地址属于某一份列表，不属于节点自述。列表项使用 `VdfsItem { path, node }`；同一节点可在
不同列表中以不同地址出现。

- 常规项由分发层按父地址与 `name` 回填；
- 拥有者明确提供的非默认地址原样透出；
- `stat / read / write` 返回纯节点，地址由请求携带。

`VdfsContent` 只承载文本或二进制，以 `text` 或 `b64` 互斥表达，并由 `binary` 显式标注；
内容不带地址。

## 4. 访问位

| 位 | 语义 |
|---|---|
| `r` | 读取内容 |
| `w` | 写入内容 |
| `l` | 列出直接子节点 |
| `t` | 树状递归遍历 |

访问位按 `r w l t` 顺序表示为紧凑字符串；空串表示不可访问。消费者只能依据访问位判断
可做性，不得按 `kind`、扩展名或目录名猜测。

`t` 是声明式能力：provider 只需实现 `list` 并在目录节点声明 `t`，访问层即可递归生成树，
不要求 provider 另写遍历算法。

## 5. 写入与新建

`vdfs/write` 的路径可以指向具名节点或目录自身：

| 目标 | `create=false` | `create=true` |
|---|---|---|
| 已存在 | 覆盖 | 覆盖 |
| 不存在的具名节点 | 写入型资源创建；字段更新型语义可返回 NotFound | 创建 |
| 不存在的目录自身 | 报错 | 由 provider 生成名字并创建 |

具名写不要求调用方先 `stat` 再选择写或建。配置型资源以地址为身份，不存在时就地创建；
只有更新既有对象字段时，对象缺失才应报错。

目录自身写入表示“在此新建，名称由 provider 决定”。provider 在 `VdfsWriteResponse.name`
返回生成名；具名写返回空名字。调用方用请求目录与返回名定位新节点。

`create` 只表达创建意图，不改变内容处理。新建要求完整合法内容；仅当内容为空且
provider 支持最小合法初始化时，才生成默认内容。字段更新型资源可以把既有资源的写入解释为
**顶层补丁**：省略的键保留旧值，显式值替换旧值，地址是资源身份。补丁的读取、合并与原子
写入必须处于同一串行边界内，不得在锁外读旧值；资源侧内存状态的发布也必须在释放该锁前
完成，删除同样如此，避免并发写/删让磁盘与运行期视图分叉。磁盘提交一旦开始，后续发布与
广播必须作为不可取消的提交继续完成，不能因调用方取消而留下磁盘已变、内存未变的状态。
敏感字段的空值语义由 provider
明确声明，未声明为空值即删除的字段不得被前端脱敏意外清空。未知键是否保留同样由 provider 声明。

导入与导出是节点动作，不新增协议操作。导入载荷和导出载荷使用对称的打包结构，由 provider
解释；不支持的动作返回 `NotImplemented`。

## 6. 协议操作

操作闭集由线路协议声明，权威清单见 [当前事实表](../004-ref/006-当前事实表.md "RE-006-当前事实表")。

| 操作 | 语义 |
|---|---|
| `vdfs/root` | 返回根地址，消费方作为运行期数据 |
| `vdfs/tree` | 按 `t` 位递归 `list` |
| `vdfs/edit` | `read →` 精确替换 `→ write` 的组合操作 |
| `vdfs/search` | 递归 `list` 与 glob 的组合操作 |
| `vdfs/action` | 执行 provider 自持的节点动作 |
| `vdfs/watch` / `vdfs/unwatch` | 成对订阅与取消订阅 |

所有操作都是对统一文件系统的一次调用。不存在独立挂载清单端点；根目录的 `list` 就是
子目录清单。

**不提供 Move**。跨子树移动由外层 `copy + delete` 组合表达，避免把跨 provider 事务和
第二地址字段加入核心协议。

### 6.1 通用守卫

访问层统一处理：

- 拒绝路径穿越；
- 写入必须携带文本或二进制内容；
- 回填响应路径、缺省扩展名与标题；
- 将 provider 相对路径补成完整地址。

门面与容器统一处理：

- 虚拟层目录自身与子目录根不可读、删或 `mkdir`；
- 写目录根仍转发给 provider，不做资源类型特判；
- 回填节点、内容和变更路径；
- 保持请求坐标与响应坐标一致。

字段级校验由 provider 在写入时完成，必须先于落盘和任何下游副作用。错误携带字段路径，
消费方按同一 schema 字段键提示。

## 7. 插件配置

插件配置就是插件目录内普通、可寻址的 `PLUGIN.yml`，没有第二套配置协议。

- 地址为 `<插件目录>/PLUGIN.yml`，与插件数据同处一个目录；
- 节点显式声明表单渲染器、读写访问位和不透明 schema；
- 定义、默认值和校验由配置拥有者提供，不复制第二份 schema；
- 写入顺序为校验、原子写自身文件、发布自身状态、广播变更；落盘失败时内存状态与广播均保持不变；
- 父容器不认识子插件配置，不代理读写；
- 装配保留键与私有配置同处文件，但反序列化时剥离；
- 写完配置后的业务副作用由插件自己执行；
- 凭据与普通配置同样受访问位约束，对外只读面必须显式排除敏感文档；资源型 provider 在
  通用 `read` 出口投影敏感字段，不把安全建立在调用方身份或前端密码控件上；
- 只读排除按规范化后的地址身份判断，配置别名与实际配置文档同禁，不按原始字符串后缀判断；
  Windows 的 NTFS 备用数据流别名也在归一化后、任何文件 I/O 前拒绝，不得依赖 `canonicalize` 还原；
- 宿主把插件配置目录与运行期数据目录作为受保护物理根列表注入 VDFS，物理层对命中这些根的读、列、
  `stat`、写与删除统一拒绝，且在词法规范化与 `canonicalize` 复验两处都按路径段判定。工作目录
  `work` 只保护其 `PLUGIN.yml`，不封锁用户工作区；调用方不能用绝对路径绕过虚拟 provider 的凭据
  投影或配置访问位；
- Windows 只读策略对带尾点或尾空格的配置路径段失败关闭，避免 Win32 归一化后命中真实配置文件。

设置页只提供真实地址指路，不保存副本，也不代理写入。

## 8. 注册与消费

存在两条发现通道，但最终访问同一个 `UnifiedFs`：

| 通道 | 用途 | 入口 |
|---|---|---|
| 系统 / 前端 | 直接查询插件视图 | `Plugin::get_vfs_provider` |
| 模型 / LLM | 能力收集 | 注册表挂载族根位 |

资源插件实现系统查询入口；容器聚合同一判据得到组合视图。LLM 链路只登记根位，不把
子目录再登记一份；子目录由组合视图现场给出。两条通道混用会产生第二份拓扑，必须禁止。

子 Agent 挂载点委托给子容器组合视图，变更路径由每层容器续接自身挂载段。委托条目已有
地址时原样透出，否则由访问层按请求地址补全，避免丢失外层挂载段。

取不到根时虚拟层降级为空目录：根可列出但无内容，具体路径返回 NotFound；物理层照常工作。
消费方无需区分“未装配”和“空资源”。

上下文分为宿主句柄与调用级参数。宿主句柄经类型化上下文注入，运行期参数使用共享常量，
provider 不认识宿主私有键名。前端协议与模型工具共用唯一分发入口。

## 9. 前端呈现

`ext` 是详情渲染器的唯一键；缺省由 `name` 推导，provider 可显式覆盖。`schema` 是不透明
JSON，由渲染器解释。前端只维护扩展名到渲染器等纯 UI 映射，不硬编码资源类型、能力或
路径模板。

`new_type` 描述落成后的节点，使“新建”和“选中”进入同一详情页。是否可新建由描述是否
存在决定，不由类型名字决定。缺少渲染器或 schema 时走通用兜底，不猜测业务语义。

## 10. 实时变更

### 10.1 订阅坐标

provider 的 `watch` 路径和变更路径都使用自身子树坐标，空串表示自身根。变更路径不相对
订阅路径收敛；容器只补挂载名，不重复补订阅前缀。消费者按作用域过滤兄弟子树变更。

`watch / unwatch` 必须配对。无实时能力的 provider 可将 watch 视为 no-op，消费方退回
手动拉取。重叠订阅按最具体路径优先，一条变更只在总线上发布一次。

### 10.2 变更信封

```text
VdfsChange { path, data? }
```

信封没有操作枚举。`path` 恒为被变更节点自身的展示地址，`data` 描述业务数据变成了什么。
容器补树内路径，门面补展示地址后原样发布到 `kind = vdfs` 事件总线。

| data | 消费动作 |
|---|---|
| 含 `delta` 的消息节点 | 热路径就地追加 |
| 全量消息或节点 | 就地替换或状态迁移 |
| 消息删除状态 | 就地移除 |
| 无 data | 幂等回读；NotFound 表示删除 |

`delta` 是传输形态，不是节点权威形态。节点正文以 `read` 结果为准。顺序由节点 `seq`
决定，不依赖投递顺序。每个变更取值必须有生产者和消费者；无人使用的词汇必须删除。

禁止无触发的定时轮询和私有刷新通道。由变更或重同步触发的幂等重读是正常机制；无序、
丢失或重复的变更都通过重读收敛。

## 11. 扩展规则

新增资源只需实现 provider、暴露统一查询入口、在节点声明访问位和呈现信息。不得修改
访问层、门面、容器或前端来识别具体资源；只有新增渲染器时增加 `ext` 映射。

新增容器层使用同一 provider 与查询契约，不新增私有协议。替换宿主只改桥、访问层和容器
接线，纯接口与线路协议保持可复用。

## 12. 一致性要求

- 不绕过 `vdfs/*` 新建资源协议；
- 不把线路类型或宿主类型上浮纯接口；
- 不让 provider 知道或假设挂载位置；
- 不让访问层或门面持有子目录拓扑；
- 不让子目录名出现第二个命名来源；
- 不按 `kind` 判断能力，只按 `access`；
- 不让运行期状态进入 provider 路径语义；
- 不让前端硬编码资源类型、路径模板或能力开关；
- 不在没有生产者时增加变更词汇；
- 不用无触发轮询替代变更机制。
