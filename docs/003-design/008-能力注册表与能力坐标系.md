# 能力注册表与能力坐标系

能力清单是开放集，坐标系是封闭框架。坐标系回答“能力属于哪里、抬高了哪条轴”，注册表
回答“能力以什么形状被发现和消费”。控制面行表见 [核心架构](001-核心架构.md "DE-001-核心架构")，参数表达
见该文“参数面”，Agent 作用域见 [Agent 目录规范](011-Agent目录规范.md "DE-011-Agent目录规范")。

## 1. 五维分类

任何能力必须落入且只落入五维之一：

| 维度 | 回答 | 内涵 | 条数 |
|---|---|---|:-:|
| 知 Episteme | 我知道什么 | 事实、记忆、时间、因果、世界模型、检索 | 10 |
| 行 Action | 我能做什么 | 工具、执行、副作用、具身、承诺 | 13 |
| 言 Utterance | 我如何表达 | 对话、人格、时延、节奏、主动性、多模态 | 8 |
| 省 Reflection | 我做得如何 | 规划、自我模型、校准、评估、审计、信任 | 16 |
| 欲 Conation | 我想要**什么** | 动机、目标生成、好奇、价值偏好 | 7 |

「条数」这一列由 §6.1 的名册算出，逐维核对；名册加一行而这里没同步就红。

“省”判断做得对不对，“欲”判断想不想做以及为什么。缺少欲，系统只有能力没有能动性。
欲的治理规则由 [核心架构](001-核心架构.md "DE-001-核心架构") 定义：留痕、过闸、可关停，不新增原语。

### 1.1 组合

跨维能力登记为“维 A × 维 B”，不增设第六维。组合必须记账；同一组合连续积累到阈值时
必须复核五维是否完备。阈值由可执行判据持有，不靠评审感觉。

时延是“言”的横切参数，由 Actor 预算表达，不单独成维。能力组合、时延和主体数都不是
新维度。

## 2. 五轴刻度

每条轴是一个**连续的量**，不是标签：§2.1 给它四级刻度，§2.2 把天梯定义成这五条轴的组合，
天梯不再另立一套语义。

| 轴 | 低阶 | 高阶 | 要求的性质 | 禁止的性质 |
|---|---|---|---|---|
| **主动性** | 只在被要求时行动 | 主动发现问题、发起目标 | `unprompted` | `prompt_only` |
| **时域跨度** | 单轮、当下 | 可规划数周、跨会话坚守目标 | `cross_session` | `turn_local` |
| **抽象层级** | 具体指令 | 理解意图、处理模糊、归纳规则 | `generalize` | `literal_only` |
| **自我模型精度** | 不知道自己不知道 | 精确校准、知道边界 | `calibrate_self` | `silent_confidence` |
| **自主程度** | 每步请示 | 可长时间独立工作，只在关键点请示 | `unsupervised` | `ask_each_step` |

后两列**是判据，不是描述**：两条轴若「要求的性质」与「禁止的性质」完全相同，它们就是同一条
轴（必须合并）；若 A 轴要求的性质正是 B 轴禁止的，它们互相抵消，不能各自独立度量。这条判据
由 `verify/axis_orthogonality.rs` 按冲突矩阵算出，不是口头保证。「高阶」不能用能力清单衡量，
必须用这五轴度量：一个能力若说不出它把哪条轴抬到第几级，它就没有让系统变高。

### 2.1 刻度（四级）

| 轴 | L1 | L2 | L3 | L4 |
|---|---|---|---|---|
| **主动性** | 只在被要求时行动 | 在既定规则内例行触发 | 主动发现问题并提出，未经指派 | 自主选题，并权衡要不要打扰 |
| **时域跨度** | 单轮内 | 单会话 / 单任务内 | 跨会话可恢复 | 跨周跨月的长期目标与承诺坚守 |
| **抽象层级** | 逐字执行具体指令 | 按意图归纳，识别同义请求 | 抽象出规则并跨任务复用 | 从经验中形成可迁移的原则 |
| **自我模型精度** | 无置信度，不知自己不知 | 有置信度但不据此行动 | 置信度经校准、可度量 | 知道能力边界，据此求助或降级 |
| **自主程度** | 每步请示 | 关键点请示，路径自选 | 长任务独立完成，失败才求助 | 长时间无人值守，行为可审计可回退 |

L1 是平凡基线（关闭后系统仍完整运行），不必由名册行代表；**L4 必须有人**——顶格无人占据的
刻度是装饰。级数由本表的列数算出，程序不写死「四级」。每级必须有可复现读数；没有读数的轴
必须明确标注「只能人工判断」，不得把设定值写成实测值。

### 2.2 天梯 T1–T8 = 五轴的递进

**T 级不另立语义**：T1–T8 是「截至该级的全部能力集合」，它在五条轴上的等级向量由名册算出
（`capability_frame.rs` 打印）。表里的「核心能力」列必须逐条对应名册里**该级的行**——写一个
不在该级名册里的能力名即红。

| 级 | 名称 | 核心能力 | 工具层级 |
|---|---|---|:-:|
| T1 | 能对话 | 多轮对话、工作记忆（≈4 槽）、流式输出 | L1 |
| T2 | 能干活 | 工具接入（L1）、时延分层（反射→自主）、打断与插话、人格语气一致 | L1–L2 |
| T3 | 能记住 | 情景记忆、语义记忆、时序历史、长期记忆检索 | L2 |
| T4 | 能自省 | 因果结构、权限与配额、自我校验、自我模型、校准（说到做到率） | L2 |
| T5 | 能递归 | 制造工具（L2）、造工具的工具（L3）、抽象协议设计（L4）、对等协商、共同目标与分工 | L3 |
| T6 | 能感知时间 | 未来预测、世界模型、主动开口、节奏与时机、独立验证与返工、价值偏好 | L3 |
| T7 | 能具身 | 具身实时闭环 | L4 |
| T8 | 能学习 | 技能编译、反自动化回退、目标自生成、内在动机、好奇与探索、主动求知 | L4 |

每级的验收三问：① 低级场景全部仍工作；② 无新增机制（只有新参数取值）；③ 关闭本级配置可退回
上一级。

### 2.3 轴与轴之间：共线的上限与登记

**共线**指两轴被同一批能力抬起，导致它们度量同一件事。五轴不做正交性证明（做不到），改为
**测量 + 登记**：程序统计「一对轴在 8 阶里有几阶同时被抬起」，超限的轴对必须在本节逐条登记
理由；理由说不清 ⇒ 合并或删轴。天梯只是各轴等级向量的派生视图，每一级都必须对应到名册。

**超限上限 = 4**（8 阶的一半）。

| 轴对 | 共同抬起的阶数（算出） | 为什么接受这条共线 |
|---|:-:|---|
| 时域跨度 × 抽象层级 | 5 | 记忆类能力把“跨会话可复用”与“跨会话可用”同时带上来：语义化本身就是抽象，此处共线是同一件事的两面 |
| 抽象层级 × 自我模型精度 | 5 | 归纳与校准共享同一环（用旧结论验新结论），T2–T5 几乎成对出现；二者分离要到能独立校准时才有意义 |

这张表是**声明**，数据是名册算出的阶数，两者对不上即红；数字变大说明这条共线在加深——
要么在表里写清理由，要么合并。

### 2.4 外部效标

每条轴应绑定与内部实现无关的读数：

| 轴 | 可用读数 |
|---|---|
| 时域跨度 | 事实源首末跨度、可完成任务时长 |
| 主动性 | 自发提议的采纳率，否决与忽略仍计入分母 |
| 自主程度 | 无人干预闭环率 |
| 自我模型精度 | 校准误差与承诺兑现率 |
| 抽象层级 | 原述与换述检索结果差异等离线效标 |

读数只证明其直接测量的对象。检索排序不依赖字面，不等于系统已经会归纳；系统侧下界也
不等于人类对照值。缺少的部分必须保留人工判断说明。

### 2.5 外部等级

不同外部体系的 L0–L5 使用不同定义，不建立统一换算表。对外沟通应同时给出本体系的轴、
等级、读数和口径，不用一个数字替代五轴信息。

## 3. 新能力准入

```text
admit(capability):
  1. 属于哪一维？无法归维 → 登记组合并累计组合次数
  2. 抬高哪条轴、到哪一级？说不出 → 必须回答第 5 问
  3. 能否表达为既有参数的新取值？不能 → 检查是否需要修改机制
  4. 平凡值是什么？没有 → 驳回
  5. 高在哪里、如何观察？写不出 → 判为伪高阶
```

前两问通过且只需增加数据时，不改架构。第 5 问是方向性要求：不能用“这是宽度”当作
免答理由；能力必须说明可观察的高度。

## 4. 伪高阶

| 现象 | 性质 |
|---|---|
| 工具数量更多 | 宽度 |
| 上下文更长 | 容量 |
| 反应更快 | 工程，除非改变了时延预算语义 |
| 支持更多模型 | 配置 |
| 能运行更久但每步请示 | 耐力，不是自主程度 |
| 会写代码 | 技能 |
| 增加护栏或仪表盘 | 工程，除非改变某条轴的观察判据 |

伪高阶不得用于提升能力等级。护栏只有让某条轴可观察、可校准或可回退时，才构成高度。

## 5. 覆盖与生长位

名册按“维 × 轴”计数。空格是潜在生长位，不是缺陷；每个空格必须能说明未来能力如何归入
该坐标。矩阵、条数和天梯分布都由名册计算，不手写第二份统计。

主体数是规模参数，不是第六维。单体与多主体使用同一能力坐标系；对等协商、承诺、声誉、
信任和仲裁通过事实与参数表达，不因主体数增加新原语。

## 6. 能力名册

<!-- list:capability-roster owner -->

名册的一行是一个能力，不是一个文件或一个实现模块。每行必须包含：

| 字段 | 规则 |
|---|---|
| 能力名 | 稳定、唯一，能区分认知、工程与治理性质 |
| 维 | 五维之一或已登记组合 |
| 轴 | 主要抬高的一条轴 |
| 等级 | L1–L4，必须有刻度依据 |
| 类型 | 认知 / 工程 / 治理 |
| 阶段 | 对应能力递进阶段，可多阶段 |
| 实现引用 | 由生成事实或代码符号提供，不手工复制模块路径 |
| 实现状态 | 已实现 / 计划 / 未指定承接 |

实现引用必须指向存在且可检查的符号。实现状态与引用必须一致；计划能力不得进入默认
装配。一个能力可以有多个实现居处，但判据只绑定一个权威主居处，其余职责在代码自述，
不在文档维护逐模块归属表。

### 6.1 名册（全仓唯一一份，`verify/capability_frame.rs` 的输入）

新增能力在这里登记一行，并回答 §3 的追问。**条数、覆盖矩阵、天梯分布全部由这张表算出**
——任何一处对不上就红，不要改那些数字，改名册。

「类型」列区分这个能力是什么性质的东西，避免把工程可靠性与认知能力混在同一张表里计数；
闭集由下表拥有，程序不写死这三个词：

| 类型 | 它管什么 |
|---|---|
| 认知 | 模型、记忆、推理、表达本身的能力 |
| 工程 | 可靠性、时延、隔离、容量、管线这类不抬高智能但决定系统能不能用的东西 |
| 治理 | 权限、预算、闸门、审计、可解释这类决定能力可不可被约束的东西 |

「落点」列把名册接到实施阶梯：写这条能力由 [能力扩充阶梯](030-能力阶梯总览.md "DE-030-能力阶梯总览")
的哪一阶点亮（`SNN`，多阶写 `SNN+SNN`）。每一阶至少要有一行名册落在它上面，否则坐标系与
实施阶梯就是两张互不相干的表。

「锚点」列把名册接到代码：取值 `文件` 或 `文件::符号`（反引号形态），`—` 表示尚未落地。
已标的锚点必须指得到，由 `doc-symbol-audit` 的 D-011 判（文件在仓内存在、`::符号` 查 D-005
同一份 Rust 语料）。`capability_frame.rs` 验的是文档之间的一致（名册 ↔ 矩阵 ↔ 声明），
没有锚点，“坐标系已归位”与“这条能力真的存在”在日志里长得一模一样。

「实现状态」列把设计条目在不在与实现还在不在分成两件事——删实现不等于删设计，名册行也不因
实现撤回而消失：

| 取值 | 含义 |
|---|---|
| `done` | 实现可指出：锚点非 `—`，且锚点文件在仓内存在 |
| `planned` | 设计保留、实现已撤回，待重新实现；该行不得出现在默认装配清单 |
| `planned-unspecified` | 设计在、实现无，且尚未指定承接 |

状态与锚点是同一条事实的两面，不是两个各说各话的字段；判据在 `capability-ledger-audit`。

### 6.2 覆盖矩阵与生长位

程序把 §6.1 按（维 × 轴）计数并打印 5×5 矩阵（每格的行数一并打印——密度不均是事实，
只有“有没有”才是格子语义）。矩阵里空格子的集合必须与下表逐格对应：多一格、少一格、
名册里填了某个空格却没同步这张表，都让 `verify/capability_frame.rs` 变红。

空格子是坐标系预留的**生长位**，不是缺口——它们告诉你下一步可以往哪长：

| 空格 | 可能的生长方向 |
|---|---|
| 知 × 自我模型精度 | “我知道我哪些记忆不可靠”（记忆的元认知） |
| 知 × 自主程度 | 自主决定是否值得记住 |
| 言 × 自我模型精度 | “我说的话有多可能被误解” |
| 言 × 自主程度 | 自主决定什么时候闭嘴 |
| 欲 × 时域跨度 | 跨会话的长期动机 |
| 欲 × 抽象层级 | 从价值到原则的抽象 |
| 省 × 主动性 | 主动发起自省而不只是被动评估 |

清单只告诉你“有什么”，坐标系还告诉你“缺什么、缺在哪”。

### 6.3 主体数与社会性能力

前五个坐标描述一个主体能到哪。多主体不是第六维，而是同一批能力发生在几个主体之间的
结构参数——取值 `1`（单体）与 `N`（多主体）。格子的含义随主体数变化（对等协商在 N=1
时无意义），分类与规模混在一起矩阵就不再是矩阵。

递归是树（主从），对等协作是图。以下能力树结构表达不了，必须显式支持（DE-001 §12）：

| 能力 | 提升的轴 |
|---|---|
| 对等协商 | 抽象层级 |
| 跨体承诺 | 时域跨度 |
| 声誉与互信 | 时域跨度 |
| 传递性信任 | 抽象层级 |
| 共同目标与分工 | 自主程度 |
| 冲突与仲裁 | 自主程度 |
| 可撤销的承诺 | 时域跨度 |

没有承诺机制就没有真正的协作，只有并发。

## 7. 能力注册表

注册表是共享发现面，只接收被多个消费方在共同地址上看见的能力。单消费方知识留在
该消费方自己的目录，不提前变成公共协议。

### 7.1 六个行族

| 族 | 载荷 | 行名 | 主要消费方 |
|---|---|---|---|
| `TOOL` | 能力执行对象 | 能力元数据名称 | 工具循环、子 Agent 投影 |
| `MODEL` | 模型标记与生效位 | provider 标识 | 目录枚举、模型端口 |
| `PROMPT` | 字符串 | 段名 | 系统提示词与组合 |
| `MOUNT` | VDFS provider 与根位 | 保留根名 | VDFS 访问层 |
| `OPTION` | 详情字段与顺序 | 字段键 | 设置表单与选项快照 |
| `CONFIGURABLE` | 配置文档节点 | 目录名 | 可配置目录清单 |

新族通过声明族常量和开放载荷类型扩展，不给注册表增加第七个通用字段，也不把具体载荷
类型上浮内核。只有新族成为跨插件共享词汇时，才把常量移到共享契约。

### 7.2 行形状

```rust
pub struct CapabilityRow {
    pub family: CapabilityFamily,
    pub name: String,
    pub active: bool,
    pub payload: Arc<dyn Any + Send + Sync>,
}
```

- 写入只有 `put` 一个入口；审批、换槽和作用域投影在该处统一执行。
- 读取按族过滤，保持注册序；顺序是模型输入语义的一部分。
- 同族同名注册覆盖旧行；跨族同名必须告警，不得静默互相顶替。
- `active` 是单槽语义。写入新 active 行时先降位旧行，读者不得看到两个生效者。
- schema 从能力自述元数据读取，不在注册表复制一份。
- 表只描述“有什么”，不承载执行；执行体由端口注册面提供。
- `ctx` 与 `Store` 不进入注册数据。执行上下文显式传给执行体，事实由调用方写口落格。
- 工具执行体返回业务结果，不直接产出事实流，避免绕过统一写入口。

### 7.3 作用域

子 Agent 能力是同一注册表的作用域投影，不是第二套注册机制。系统与子 Agent 能力取
并集，按命名空间消歧；投影遗漏必须由包含子 Agent 的端到端用例发现。

## 8. 判断与反证

| 主张 | 性质 | 反证现象 |
|---|---|---|
| 五维完备 | 判断 | 同一组合持续积累，说明组合掩盖了缺失维度 |
| 五轴足以度量高度 | 判断 | 公认高阶能力无法归轴，也无法给出观察口径 |
| 五轴可独立度量 | 测量与登记 | 共线超限且无有效理由 |
| 刻度可用 | 判断与验证 | L4 长期空置，或相邻刻度无可观察差异 |
| 名册每行可归位 | 可执行验证 | 任一字段越界或引用不存在 |

能力清单永远开放，架构与坐标系保持收敛。新增能力不得以“清单会增长”为理由增加原语、
扩大内核门面或复制控制面机制。
