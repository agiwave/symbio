# 引擎收口与简化

> **讨论稿，没有裁决力。** 本文的每一节都在回答同一个问题：`loop` / `session` 里还剩什么、
> 凭什么留、怎么收薄。§5 的每一条都是**待裁决的分叉**，裁决落进宿主文档
> （[DE-015-义务环](015-义务环.md) / [DE-022-行表与派发面](022-行表与派发面.md)）之前不约束任何形状。
> 裁决之后本文按结论改写或删除，不留过程叙述。

## 1 简化的两条腿，第二条没有 owner

「把能力从 `loop` / `session` 拆出去」今天有一条完整的施工线：`loop` 与 `session` 各按能力
逐批迁出、再合流做终态验收（分解住在任务体系，逐批的账也在那里）。判据是
`EX-002` / `EX-003` / `EX-004` / `EX-006` / `EX-007` 与 `SC-006`，定义归
[DE-026-能力拆分与影响类](026-能力拆分与影响类.md)。
它的出口写得很清楚：**控制面里按能力名存在的东西清零，留守只落五类**。

这条线不回答第二个问题：**留下来的五类，本身是不是太厚**。

[DE-026-能力拆分与影响类](026-能力拆分与影响类.md) §1 给五类各写了一句「为什么它不是能力」，但没有给任何一类写
「它该有多大」。于是出现一个结构性盲区：

| 现象 | 由谁判 | 结果 |
|---|---|---|
| `loop` 里还有按能力名写的策略 | `EX-006` / `SC-006` | 会红 |
| 驱动循环有两个、选债口有两处 | `CP-001` / `CP-002` | 会红 |
| 端口渗进引擎、协议格有两个写方 | `PTS-002` / `PTS-005` | 会红 |
| **一处记账/一个字段/一条出参通道根本没有必要** | **无人判** | **绿** |

最后一行就是本文的对象。它不违反任何现有判据，因为现有判据判的都是**形状唯一**
（一个环、一张表、一个写方），不是**必要性**。形状可以既唯一又臃肿：
一次工具调用写 4N 条协议事实、过六站、读十一次全量日志，形状是唯一的，账是厚的。

## 3 判据：一处自持必须回答「事实面答不了吗」

这一条不是新发明的，它是 [DE-022-行表与派发面](022-行表与派发面.md) 的 `D-226` 从一格推广到全引擎：

> `D-226` 对 `TurnState` 的每一格问的是同一句话——「事实面本可以回答它」。
> 答得了的删，答不了的留并写明理由。

推广后的形状：

| 对象 | 问法 | 答「答得了」时 |
|---|---|---|
| 行表的一行 | 这笔债是不是一个事实面直接可判的状态？ | 删行，改由既有行/视图回答 |
| 草稿的一格 | 这个值能不能从日志重算？ | 删格（`CS-010` 只降） |
| 一条出参通道 | 消费方能不能自己从日志读？ | 删通道，读日志 |
| 一处全量读 | 同一幕里前面是不是已经读过一遍？ | 收成一份幕内切片 |

**与现有判据的分工**（不重复，各判一面）：

- `CP-00n`（[SP-033](../005-spec/033.md)）判**形状唯一**：一个循环、一个选债口、守卫同处。
- `PTS-00n` 判**端口不渗引擎**：事实名闭集、`owed` / `drive` 字节冻结。
- `EX-00n` 判**能力出清**：按能力名存在的东西清零、迁移提交只搬运。
- `EL-001…003`（`scripts/engine-ledger-audit.mjs`）判**账本有没有变宽**：行表的行数、
  分发方的出参通道数、工具路径的全量读点数，三样只许降。它是本文判据的**代理**——
  「为什么留」仍归人手填账本表，脚本只让「悄悄变宽」这件事可见。
- **本文的判据判必要性**：留下的东西有没有理由。它不判形状，也不判名字。

## 4 根因：表达力缺口被记成了结构

`loop` 的行表有 15 行，其中 5 行是工具债。把 5 行逐行问「为什么需要你」，
答案有一半不在业务上，在**求解器的表达力**上。

`Decl` 的 `owes` 是一个 `Pattern`：**单一事实源 + 键字段 + 等值约束**，没有跨源合取、
没有否定、没有集合。这个表达力缺口被三处转嫁成了结构：

| 表达力缺口 | 转嫁成的结构 | 代码里的自述 |
|---|---|---|
| 写不出 `request ∧ granted` | `authorize-tool` 与 `dispatch-tools` 拆成两行，用**蕴含**代替合取 | `loop_rows` 在 `authorize-tool` 上的注释原文：「`Decl.owes` 是**一个** `Pattern`（单源等值），跨源合取写不出来；要写就得改求解器，而求解器的字节是 `PTS-003` 的判据面」 |
| 写不出「这一批的 N 笔」 | `expand` 把集合债摊成 N 笔独立债 ⇒ 4N 条事实 | `D-117`：批次是集合，`expand` 落在唯一能看见 `calls` 的创建行 |
| 写不出「没被拒」 | 靠「`denied` ⇒ 无 `granted` ⇒ 派发行永不成立」间接表达 | 同上的注释：「全程没有否定原子」 |

**这是本文最重要的一条判断**：工具端口的实现之所以看起来「一个端口调用要这么复杂」，
**至少一半复杂度不在端口、也不在工具，而在求解器不会说「并且」**。
按仓库纪律，这个缺口不能靠在模块里简化掉——它是一条值得单独立案的架构议题。

## 5 候选裁决

### E-1 求解器表达力：补，还是认下摊平

**现状**：`Decl.owes` 单源单值；工具债 5 行里至少 2 行的存在理由是表达力。

| 案 | 形状 | 收益 | 代价与风险 |
|---|---|---|---|
| **甲 补表达力** | `owes` 收 `&[Pattern]` 做合取 + 跨源键绑定 | 工具债 5 → 3；`authorize` 与 `dispatch` 合一行；「两行模板」退回一行 | `owed` 复杂度上升；`PTS-003` 基线重算；「加端口 = 0 改引擎」的保证按 join 语义重述 |
| **乙 认下摊平** | 不改求解器，把「一个端口两行」写成标准形状 | 零风险，`owed` 字节不动 | 行数不降，两行税永久 |
| **丙 换债的表达** | 端口调用 = 显式状态机，行表只写转移 | 记账从「行」回到「笔」，最彻底 | 动 [DE-015-义务环](015-义务环.md) 的核心定义，等于重写方案 |

**推荐：乙先落地，甲单独立项，丙不做。** 理由：甲的收益（少 2 行）与代价（动全表的公共分母）
不成比例，但它**值得一轮独立讨论**——因为它是唯一能解释「为什么表在长」的答案。
丙会把「债 = 未命中出口的模式」这条定义换掉，那是重写而不是收口。

**已裁（2026-10-31）**：乙写进 [DE-022-行表与派发面](022-行表与派发面.md) 的 `D-265`（「认下，不是认可」，带重开条件）；
甲另立一条独立任务（求解器表达力，未裁）；丙不做。

### E-2 工具路径的 11 处全量读

**现状**：每站各自 `range(0)`，读的是同一份日志。

**原候选**：幕首取一份切片，各站只读切片 + 本站在飞的事实。

**前件已核（2026-10-31）：有，而且是链式的——原候选不成立。**

- `open_batch` 落 `request`，`authorize_calls` 的 `owes("authorize-tool")` 以刚落的 `request` 为源；
- `authorize_calls` 落 `authz`，`begin_calls` 的 `owes("dispatch-tools")` 又以它为源。
- 所以「一份幕首切片」会让第二站看不见第一站刚落的格——那不是收窄，是改语义。

**更硬的否证**：把切片做成 `Store` 视图（幕首切片 + 经视图写入的增量）**也不成立**。视图只能
旁听**经它写入**的事实，而幕内还有经原始 `store` 写的事实（`turn_exec` 的落格、执行层直写）——
视图看不见它们。实测：接上视图后 7 个用例立刻红（授权 / 阈值 / 逐工具放行 / 幕内派生事实）。
这条否证值得留着：**「读侧缓存」与「写侧旁听」是两件事，前者安全，后者会漏写。**

**可做的收窄只剩一处，但它是 N 倍**：`begin_calls` 循环 N 笔，每笔 `port::begin` 内部各读一次
全量（`Dispatch::row_owed` 是唯一的现读点）——一批 N 个调用 = **N+1 次** `range(0)`。11 处静态
位置里，只有它被调用次数放大；其余各站在循环外读一次。收法：批首读一次，`begin` 收下这份切片
（判据仍是 `loop_rows::owes`，只是事实面由调用方给）。

**判定**：纯收窄，不改语义，**不需要裁决**。

### E-3 出参三通道

**现状**：`SessionDispatchPort` 上三条出参通道——`produced`（节点，`Mutex`）、
`derived`（效果与熔断，`Mutex`）、`DispatchOutcome`（返回值），因为 `D-123` 不许执行体
自报写入，`run` 的签名又不带出参。

**候选**：合成一个 `BatchOutput { nodes, effects, breaks, outcomes }`，一次取走。

**实做（2026-10-31）**：只合**两条异步累积的通道**（`produced` / `derived` → `PortOutput`），
`DispatchOutcome` 保持同步返回值。原候选把三样并成一件是错的：前两条跨 `await` 累积、必须
有 `Mutex`；第三条一次调用即交齐，塞进 `Mutex` 反而把它变成第二条通道。「三通道」因此按
实况订正为「两条异步累积 + 一条返回值」。

**判定**：纯收窄，与 `D-123` 不冲突（`D-123` 禁的是**自报账本**，不是交出产物）。
不需要裁决。

### E-4 `TurnState` 的 18 格

**现状**：18 格，`CS-010` 棘轮只许降。

**候选**：逐格问「日志能不能重算」。能重算的删。这是 `D-226` 的原文口径，**不需要新裁决**，
只需要一格一格做完并让棘轮跟着降。

**注意**：`abort`（中止信号）与 `facts`（幕内切片）不是「可从日志重算」的值——它们是
**外部输入**与**读侧缓存**，属于「事实面答不了」的那一半，保留。

**实做（2026-10-31）**：18 格逐格核完，**无删格**。没有一格是「事实的拷贝」——`request_round`
看着最像，但它是 `turn_next_round` 的**求解器结论**（不是 `turn_head.round` 的直接拷贝），
读方 21 处，删了每处要重求值一次；`last_saved` 是增量落库的寄存位，不是事实。逐格分类与
理由记在施工任务的账本里。

### E-5 `dispatch_full` 的 8 个类型参数

**现状**：`dispatch_full<S, T, E, F, Fut, W, X, Y>`，四个闭包。

**候选**：`Dispatch` 已是一个结构体，把 `why` / `extra` / `fail_extra` 三个闭包也收进去，
类型参数降到 5 个。收益小、纯机械。

**判定**：可选，不占裁决额度；做了不亏，不做也不欠。

### E-6 `session` 的 2,826 行能力名模块

已在 `session` 的迁移账上（逐批归属表住在任务体系），不另立裁决。本文只补一条读数：这部分占 `session`
生产代码 14%，**迁完之后 `session` 仍然有 15,649 行基底**——那是它该有的体量，
不要把「`session` 变小」当目标。

## 6 分步

| 步 | 内容 | 前置 | 判据 |
|---|---|---|---|
| 步 0 | 引擎账本：每一处自持（行 / 格 / 通道 / 全量读）一行，写明「事实面答不了吗」的答案 | 无 | 账本全覆盖，无空行 |
| 步 1 | E-3 → E-2 → E-4，各一个提交，端到端逐字不变 | 步 0 的账 | prompt 形状基线 + e2e 全绿 |
| 步 2 | E-1 裁决（甲 / 乙 / 丙），按裁决改 `Decl` 或改条文 | 一轮讨论 | 裁决落进 [DE-022-行表与派发面](022-行表与派发面.md) |
| 步 3 | 与迁移线收口合流，复核「五类之外没有名字」 | 迁移线与验收完成 | `EX-006` + 本文账本 |

步 1 与迁移线**可以并行**：迁出动的是「行与执行体」，步 1 动的是「读法与出参」，
交集只有 `tool_dispatch` 一处，冲突可控。

## 7 划界：不做什么

- **不为行数删功能**：每一条删除都要过「平凡值下系统完整运行」（[DE-015-义务环](015-义务环.md) 的 `J2`）。
- **不动 `owed` / `drive` 的字节**，除非 E-1 裁「甲」并挂 ADR（`PTS-003` / `PTS-004`）。
- **不改五类残留的定义**（[DE-026-能力拆分与影响类](026-能力拆分与影响类.md) §1）——本文只问每一类该多大。
- **不在迁移提交里夹带**（`EX-007`）：步 1 的提交不是迁移提交，不写 `Migration:` 行；
  反过来，迁移提交也不许顺手做步 1。
- **不把 `session` 变小当目标**：它的基底是判据对象，不是待拆对象。
