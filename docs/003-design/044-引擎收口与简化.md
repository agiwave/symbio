# 引擎收口与简化

> **本文是引擎账本的 owner**：它给「留下来的东西有没有理由」立判据，并冻结 `EL-001`…`EL-003`
> 三个只许降的读数（执行方 `scripts/engine-ledger-audit.mjs`，码表见
> [RE-008-判据码登记表](../004-ref/GATE_CODES.md "RE-008-判据码登记表")）。逐条候选的裁决正文住在
> 宿主文档——[DE-051-机制形状规格](051-机制形状规格.md "DE-051-机制形状规格") /
> [DE-022-行表与派发面](022-行表与派发面.md "DE-022-行表与派发面") /
> [DE-046-债务语法的表达力边界](046-债务语法的表达力边界.md "DE-046-债务语法的表达力边界")。
> 本文只留结论与仍生效的边界。

## 1 对象：形状唯一不等于不臃肿

「把能力从 `loop` / `session` 拆出去」有一条完整的施工线，判据是 `EX-002` / `EX-003` / `EX-004` /
`EX-006` / `EX-007` 与 `SC-006`（定义归 [DE-026-能力拆分与影响类](026-能力拆分与影响类.md "DE-026-能力拆分与影响类")），
出口是「控制面里按能力名存在的东西清零，留守只落五类」。它不回答第二个问题：**留下来的五类
本身是不是太厚**。

| 现象 | 由谁判 | 结果 |
|---|---|---|
| `loop` 里还有按能力名写的策略 | `EX-006` / `SC-006` | 会红 |
| 驱动循环有两个、选债口有两处 | `CP-001` / `CP-002` | 会红 |
| 端口渗进引擎、协议格有两个写方 | `PTS-002` / `PTS-005` | 会红 |
| **一处记账 / 一个字段 / 一条出参通道根本没有必要** | **无人判** | **绿** |

最后一行是本篇的对象。它不违反任何现行判据，因为那些判据判的是**形状唯一**（一个环、一张表、
一个写方），不是**必要性**。形状可以既唯一又臃肿：一次工具调用写 4N 条协议事实、过六站——
形状唯一，账是厚的。

## 2 读数

三格是**活的**读数，由 `engine-ledger-audit` 每轮重数、只许降：

| 码 | 读数 | 当前 | 取法 |
|---|---|---|---|
| `EL-001` | 引擎自持的行数 | **0** | `loop` 生产源码里的 `Decl {` |
| `EL-002` | 分发方的出参通道数 | **1** | `CollectingWriter` 的 `Mutex<` 字段 |
| `EL-003` | 驱动 / 回合路径的全量读点数 | **0** | 三处驱动文件的 `Seq::new(0)` |

体量（剥掉 `.test.rs`，2026-11-10 实测）：`loop` 生产 **2,086 行**、`session` 生产 **18,185 行**。
首版读数（2026-10-31）是 `loop` 25,222 行 / `session` 19,798 行、工具路径 11 处全量读、
`session` 的能力名模块 2,826 行——**那批对象已经不在**：环与行表迁出、能力名模块随迁移批收口
（[DE-055](055-能力自配置终态裁决.md "DE-055-能力自配置终态裁决") 的 `D-427` / `D-430`）。
两栏对照说明一件事：**`loop` 瘦了两个数量级，`session` 几乎没动**——后者不是欠账，
它的基底是判据对象（见 §4 `E-6`）。

## 3 判据：一处自持必须回答「事实面答不了吗」

这条不是新发明的，它是 [DE-022-行表与派发面](022-行表与派发面.md "DE-022-行表与派发面") 的 `D-226`
从一格推广到全引擎：

> `D-226` 对 `TurnState` 的每一格问的是同一句话——「事实面本可以回答它」。
> 答得了的删，答不了的留并写明理由。

推广后的形状：

| 对象 | 问法 | 答「答得了」时 |
|---|---|---|
| 行表的一行 | 这笔债是不是一个事实面直接可判的状态？ | 删行，改由既有行 / 视图回答 |
| 草稿的一格 | 这个值能不能从日志重算？ | 删格（棘轮只降） |
| 一条出参通道 | 消费方能不能自己从日志读？ | 删通道，读日志 |
| 一处全量读 | 同一幕里前面是不是已经读过一遍？ | 收成一份幕内切片——**先过 `E-2` 的前件** |

**与既有判据的分工**（不重复，各判一面）：

- `CP-00n`（[SP-033](../005-spec/033.md "SP-033")）判**形状唯一**：一个循环、一个选债口、守卫同处。
- `PTS-00n` 判**端口不渗引擎**：事实名闭集、`owed` / `drive` 字节冻结。
- `EX-00n` 判**能力出清**：按能力名存在的东西清零、迁移提交只搬运。
- `EL-001…003` 判**账有多厚**：三样只许降。它是本文判据的**代理**——「为什么留」仍归人手填账本表，
  脚本只让「悄悄变宽」这件事可见。
- **本文的判据判必要性**：留下的东西有没有理由。它不判形状，也不判名字。

## 4 裁决结论

### E-1 求解器表达力：不补（`D-290`）

`Decl.owes` 保持一个 `Pattern`（单源 + 键字段 + 等值约束），没有跨源合取、没有否定、没有集合。
「补表达力」量出来的收益是 **0 行**：环的单位是「债 = 未命中出口的模式」，行数等于出口格的种数，
把合取补进 `owes` 也省不掉一行。真正能省行的动作是把「判定 + 派发」合进一个执行体，而那是
`D-265` 否过三次的形状。永久代价与三条重开条件同条记在
[DE-046-债务语法的表达力边界](046-债务语法的表达力边界.md "DE-046-债务语法的表达力边界")。

### E-2 全量读：跨站是链式的，不许共用一份幕首切片

工具路径的每一站各自 `range(0)`，读的是同一份日志。**「幕首取一份切片、各站只读切片」不成立**：
`open_batch` 落 `request`，`authorize_calls` 的 `owes("authorize-tool")` 以刚落的 `request` 为源；
`authorize_calls` 落 `authz`，`begin_calls` 的 `owes("dispatch-tools")` 又以它为源——一份幕首切片
会让第二站看不见第一站刚落的格。

**把切片做成 `Store` 视图也不成立**：视图只能旁听**经它写入**的事实，而幕内还有经原始 `store`
写的事实（落格、执行层直写），视图看不见它们（实测接上后 7 个用例即刻红）。这条值得单独记住：
**「读侧缓存」与「写侧旁听」是两件事，前者安全，后者会漏写。**

收窄已落地：派发前每圈只问一次表——`DebtSource::rows` 把行数据切片交给引擎，引擎侧的全量读为 0
（`EL-003` 恒 0，基线已随实测收到 0；留着余量会被下一次新增正好填进来）。

### E-3 出参通道：两条异步累积 + 一条返回值

`SessionDispatchPort` 上是 `produced`（节点，`Mutex`）、`derived`（效果，`Mutex`）、
`DispatchOutcome`（返回值）。**合成一个 `BatchOutput` 是错的**：前两条跨 `await` 累积、必须有
`Mutex`；第三条一次调用即交齐，塞进 `Mutex` 反而把它变成第二条通道。实做只合了前两条
（→ `PortOutput`），`EL-002` 因此是 **1** 而不是 0，也不该是 0。

### E-4 `TurnState` 的 18 格：对象已下线，本条结案

逐格问「日志能不能重算」的结论是**无删格**：没有一格是「事实的拷贝」（`request_round` 是求解器结论，
`last_saved` 是增量落库的寄存位，`abort` 是外部输入，`facts` 是读侧缓存）。该类型随后整体退场，
承载它的棘轮格也随之消失——**不另立读数**：对象没了，再数一遍就是零信息。

### E-5 `dispatch_full` 的类型参数：随引擎改写消失

曾记「8 个类型参数、4 个闭包，可收到 5 个，收益小、纯机械，不占裁决额度」。引擎改写成环驱动后
该函数已不存在，本条按「不做也不欠」结案。

### E-6 `session` 的能力名模块：不把「变小」当目标

能力名模块按迁移批逐批迁出、终态已收口（[DE-055](055-能力自配置终态裁决.md "DE-055-能力自配置终态裁决")）。
剩下的 18,185 行是**存储 / 转写 / 装配**基底——它是判据对象，不是待拆对象。迁移完成后
`session` 仍是这个量级，这不是欠账。

## 5 划界：不做什么

- **不为行数删功能**：每一条删除都要过「平凡值下系统完整运行」（[DE-047](047-义务环判据与归属推导.md "DE-047-义务环判据与归属推导") 的不变量）。
- **不动 `owed` / `drive` 的字节**（`PTS-003` / `PTS-004`）：要动只走 `D-290` 的重开条件，
  且必须先有新决策与重算的 `PTS-003` 基线。
- **不改五类残留的定义**（[DE-026](026-能力拆分与影响类.md "DE-026-能力拆分与影响类") §1）——本文只问每一类该多大。
- **不在迁移提交里夹带**（`EX-007`）：引擎收窄的提交不是迁移提交，不写 `Migration:` 行；反之亦然。
