# 端口机制裁决

本文规定环与外部世界之间的通用端口合同。归属判据归
[DE-047](047-义务环判据与归属推导.md "DE-047-义务环判据与归属推导")，驱动与写口归
[DE-053](053-环驱动与写口裁决.md "DE-053-环驱动与写口裁决")。

## 1. 端口注册

端口种类开放，端口名是数据。所属能力声明 `PortDecl` 并提供 `PortProvider`；宿主在
装配期收集声明，通过 `PortBindings::bind` 建立端口名到执行体的唯一绑定。

- 提供者可以服务多个端口名。
- 每个绑定必须有执行体；无执行体的声明不能形成可等待的债。
- 提供者缺席或被停用时，请求以不可重试失败关账，不静默跳过。
- 租约与尝试上限必须有限；端口声明不承担环的并发策略。
- 新增端口不得修改环、端口接口或注册面。

## 2. 通用合同

| 类型 | 合同 |
|---|---|
| `PortProvider` | 申报 `ports()`、`provider_id()`、可选 `capabilities()` 与 `executor()` |
| `PortExecutor` | `execute(ctx, input) -> outcome`，一次执行一笔债 |
| `PortInput` | `port` 与不透明 `payload` |
| `PortOutcome` | 必填授权结论、事实草稿、可选通用错误与应答承载 |
| `PortErrorClass` | `NonRetryable` / `Retryable` / `NeedsHuman` |
| `PortCapabilities` | 通用能力位：流式、可取消、幂等 |
| `PortExecContext` | 一笔债的通用宿主上下文 |

授权结论没有“未表态”变体；提供者必须显式给出放行或带理由的拒绝。拒绝不落事实或产物。
失败可以携带半截事实。接口不得出现 `ModelProvider`、`ToolProvider`、具名载荷或具名执行
方法。

## 3. 声明行与执行派生

`Decl` 不设 `by` 字段。谁执行由数据派生：

- `owes` 指向 `request(port=…)`：走环的通用端口受理入口。
- 否则：走所属能力登记的 `RowHandler`，输入 `RowRequest`，输出 `RowStep::Facts` 或
  `RowStep::Ask`。

行声明持有名字、`reads`、`owes`、`until` 与配对键。`reads` 是选债前必须已存在的事实或
视图；`owes` 携带通用值草稿。行不调用模型，不持有会话状态，也不自行决定终答。

`Ask` 只落一条 `plugin.row.asked{row, key, prompt}` 并挂起；回执通过同一债键返回，
再由该行解析关账。往返由声明出的端口债完成。需要既询问又终答的行必须拆成两行，以
事实接力，不增加“行级终答”出口。

## 4. 协议事实写方

| 事实 | 写方 | 含义 |
|---|---|---|
| `request` | 声明／能力方 | 依据事实欠出一笔端口请求 |
| `sent` | 环 | 已派发；携带租约、实际执行行与尝试 |
| `response` | 提供者经通用事实草稿出口 | 该尝试的终稿与领域事实 |
| `failed` | 提供者经通用事实草稿出口；环可关闭缺席、过期等协议失败 | 该尝试失败并收束 |
| `retry` | 环 | 推进尝试，并继承实际执行行 |

宿主是唯一物理写口。执行体只能提交 `kind` / `entity` / `verb` / `payload`；债身份、
端口、尝试、归属与溯源信封由宿主按声明和债键盖章。环不解析草稿内容。

## 5. 增量与终稿

一笔债只有一条可配对的终态 `response` 或 `failed`。文本增量走
`PortExecContext.sink` 的瞬时帧，不落事实、不参与重放、不写幂等键；丢帧不影响正确性，
最终内容以 `response` 为准。

节点是事实的投影，不是可写对象。占位、未执行项、父子终态与分支标记均由投影规则
重建；执行体不写节点，也不为节点另立身份账。

## 6. 执行上下文

`PortExecContext` 可携带：

- `abort`、`idempotency_key`、`sink`、`emit`；
- 调用方上下文、会话身份、来源主体、归属与触发事实身份；
- 宿主提供的事实只读面；
- 可选的 `scratch_dir` 纯值。

上下文不含租约 `deadline_ms`。租约是环的簿记；提供者超时由提供者自己持有。宿主路径只
以中性 `scratch_dir` 传入，不拼装世界文件名、不参与债身份，也不由环读回。需要临时文件
时，执行体自行管理其下布局。

## 7. 世界归属

提供者负责载荷组装、世界行为、结果校验、授权、产物、副作用、终答或失败语义、用量与
计价、流式帧及自身重试。环只负责请求、派发、租约、配对与协议记账。

会话本地同步存储与簿记不是外部端口。会话配置与历史以 `session.config` /
`session.recall` 等事实参与，会话动作走插件调用面；只有出现跨进程、跨设备或带租约的
未决往返时，才按当时契约声明新端口。

## 8. 端口准入

端口只用于不可控、有延迟且可能失败的外部交互。本地存储、转写、纯计算与记账以事实或
步内函数参与，不制造“永远立即成功”的假债。端口不得成为绕过授权、写口或能力边界的
旁路。
