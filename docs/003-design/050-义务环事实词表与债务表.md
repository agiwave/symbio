# 义务环事实词表与债务表

本页是插件与环之间的长期契约。共享事实名、owner 与格位由各能力 `PLUGIN.yml` 的
`shared_events` 与 owner 的 `EventDecl` 生成；生成物与声明必须一致。

## 1. 共同约束

- `drive` 只由事实与未收束债推进；轮次、阶段和“第几次”不是环输入。
- 一笔债是 `owes ⇒ ◇ until` 的当前违例；`owes` / `until` / `unless` 都是事实谓词。
- 环只认端口名与五类协议事实，不解释业务载荷。
- 债身份为 `(port, id, attempt)`；`id` 从输入事实派生，禁计数；`attempt` 只随重试推进。
- 领域事实身份使用不含 `attempt` 的 `id`，重试不产生第二份领域真相。
- 唤醒必须先落事实；事实只经宿主唯一写口落库。

`model.speech.denied` 是模型侧私有事实。私有格仍由 owner 的 `EventDecl` 登记，但不生成
共享常量。

### 2.1 关键载荷

- `authz.granted`：`{port, id, attempt, tool, risk, basis, grant, deferred}`。
- `authz.denied`：`{port, id, attempt, tool, detail, why}`。
- `model.speech.denied`：`{port, key, root_id, detail, reason}`，其中
  `key = chat.assistant.final`。
- `plugin.row.asked`：`{row, key, prompt}`。
- `tool.call.requested`：`{request_id, call_id}`；`request_id` 是 `tool.requested` 的事实
  id，`call_id` 是调用 wire id。事实键为
  `tool.call.requested:{request_id}:{call_id}`，同一对重复投递被吸收。
- `session.config` / `session.recall` 的幂等键从对应 `user.message` 事实 id 派生。

环不读取上述载荷；跨插件字段契约由写方声明、读者按需消费。

### 2.2 环自有事实

协议五格与 `plugin.row.asked` 是环机制事实。`driver.stalled` 是宿主驱动入口写的安全阀
通知，载荷含 `{session_id, outcome, steps?, outstanding}`；它不进选债、派发或共享词表。

## 3. 债行谓词闭集

| 谓词 | 语义 |
|---|---|
| `when(kind)` | 本可见域存在该种类事实才欠 |
| `when_id(kind, id)` | 存在该种类与身份的事实才欠 |
| `unless(kind)` / `unless_id(kind, id)` | 条件命中则本行不欠 |
| `after(debt_id)` | 前置债收束前不可还 |
| `when_no_open(port)` | 该端口仍有未收束债时不欠 |
| `after_port(port)` | 该端口本轮仍被行认领时，本行不进计划 |
| 无条件 | 省略以上条件；是否收束仍由配对键判断 |

`after_port` 的“认领”包括本轮申报且仍开着的债，以及本圈已有动作的行。上一轮遗留且
本轮无人再申报的债不算认领，由自己的租约处理。端口无人认领即视为前提已了；认领却
永不收束时，依赖行保持阻塞，驱动不得报 `NoDebt`。

### 3.3 重试

工具端口的 `max_attempts = 2`；行层按 `retry(attempt+1)` 重新开账，重试已经启用，
不是纸面条文。新一轮尝试用新的 attempt 号进入事实，旧尝试的失败与租约各自收束留痕。

## 4. 当前债务表

### 4.1 数据债

| 行名 | 端口 | 债 id | 主要条件 |
|---|---|---|---|
| `model-reply` | `model` | `model:{user_id}` | 本轮用户消息、会话配置已就绪、无对应终答；等 `plugin_row` 端口干净 |
| `model-after-tools` | `model` | `model:after:{artifact_id}` | 有工具请求、调用债全收束；等 `plugin_row` 边界簿记完成 |
| `tool-call` | `tool` | `tool:{request_id}:{call_id}` | 对应逐调用标记存在；租约 600 秒，最多 2 次尝试 |
| `tool-resume` | `tool` | `tool:{request_id}:{call_id}` | 用户答复按 `call_id` 配对；复用原债 id，不开新债 |
| `classify.decide` | `plugin_row` | `classify.decide:id={user_id}` | 本轮用户消息存在；Ask 后等回执；租约 60 秒，最多 1 次尝试 |
| `classify-decide-model` | `model.assist` | `ask_id` | 对应 `plugin.row.asked` 存在 |
| `compose-wording-model` | `model.assist` | `compose-wording-model:{user_id}` | 对应分类答案存在；租约 60 秒，最多 1 次尝试 |
| `compact-summarize` | `model.assist` | `compact-summarize:{user_id}` | 对应终答存在且未巩固；在 `model:{user_id}` 之后 |
| `compact-write` | `compact` | `compact-write:{user_id}` | 同摘要前件；在摘要债之后 |
| `notes-reflect-model` | `model.assist` | `ask_id` | 对应 Ask 存在且尚无对应笔记洞察 |

### 4.2 声明债

| 行名 | 欠什么 | 何时算还 |
|---|---|---|
| `session.close-turn` | `chat.assistant.final[root_id]` | `session.settled[root_id]` |
| `notes.index` | `artifact.added[tool_call_id]`，且工具为 notes、成功 | `notes.indexed[tool_call_id]` |
| `notes.reflect` | `notes.indexed[tool_call_id]` | `notes.insight[tool_call_id]`，Ask |
| `notes.summarize` | `notes.insight[tool_call_id]`，状态为 ok | `notes.summary[tool_call_id]` |

记忆巩固是记忆能力自己申报的一笔条件债，不是环的聚合行。活集不足时能力不申报；执行体
在 `sent` 后读取计划期快照，自己合并并提交事实，会话不保留调用点。

### 4.3 归宿行

`owes` 与 `until` 同源同键时，`owed` 恒空，行只用于给已登记事实声明看护人，不派发。
只有存在 `FactDecl` 的事实格才需要这种归宿行；不得为没有事实登记的格制造空行。

### 4.4 行执行体

声明行返回 `RowStep::Facts` 或 `RowStep::Ask`。`Ask` 落一条 `plugin.row.asked` 后挂起，
`response` / `failed` 回到同一 id，再由 `parse` 关账。执行体不直接调模型；模型往返
由另一笔端口债完成。

## 5. 模型与工具往复

模型执行体为一次响应写入一条 `tool.requested` 与 N 条 `tool.call.requested`。N 次调用
形成 N 笔独立债，各自拥有租约、尝试、审批与终局。工具完成标记 `tool.calls.done` 由工具
侧簿记行在本次调用债收束后补写，不依赖某个执行体“最后一步”必然返回。

同一次请求内，后一笔调用可以前一笔的 `sent` 作为首派顺序条件，但不绑前一笔的终局；
一笔等待用户不阻塞其余调用。跨请求不串派发链。

全部调用收束且边界簿记完成后，`model-after-tools` 以新身份开下一笔模型债。需要授权的
调用由显式放行事实决定是否进入工具端口；拒绝不产生放行，也不伪造成功。

`latest_fact_id` 只适用于同一时刻至多一份有效实例。多实例必须逐条读取；工具恢复按
`user.answer.call_id` 反查所属请求，找不到请求就不恢复，不拿最新请求顶替。同一请求的
多条答复只消费最后一条。

## 6. 完成与重放

一个 scope 完成必须同时满足：

```text
chat.assistant.final(scope)
∧ session.settled(scope)
∧ 不存在更晚于 settled 的 user.message(scope)
∧ 债表对该 scope 不再产出未收束行
```

重起时，已有 `response` / `failed` 的债直接收束；只有 `request` 时补派发；已有 `sent`
且租约过期时先落 `retry(attempt+1)` 再派发。重复 `(kind, key)` 被账本吸收。

重试继承 `sent.row` 指认的实际执行行。指认行仍在时只重跑该行；行已消失则落带理由的
`failed`，不按表序误选另一行。挂起重燃复用同 attempt，不推进尝试。

## 7. 新能力局部性

新能力只提交事实声明、债行与执行体。声明必须是运行期可枚举数据；宿主只收集并装配。
新增能力不得要求修改环、宿主、机制门面或内核，也不得让执行体取得派发句柄或第二写口。
