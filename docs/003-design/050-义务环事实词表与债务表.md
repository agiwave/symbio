# 义务环事实词表与债务表

> 两张表是**插件与环之间的长期契约**：哪些事实可跨插件消费、哪条债由谁在什么时候欠。
> 事实名、owner 与格位由 `scripts/facts/events-rs.mjs` 从各插件 `PLUGIN.yml` 的
> `shared_events:` 与 owner 的 `EventDecl` 生成到 `symbio-plugin-api/src/events.rs`；
> 本页只登记当前口径，生成物为准（门禁 `gen-facts --check`）。

## 设计思想

这一节回答环为什么长成这样。七条是**推理前提**，不是可选约定：形状有争议时回到这里判。

### 环只由事实驱动，轮不是概念

`drive` 的每一次推进都源于「账上有一笔可还的债」，而债只由事实产生。会话轮次、阶段进度
都是业务对事实的解读，不是环的输入——环里没有轮号、没有阶段、没有「第几次」。放弃轮次
换来的是回放可比：同一段日志重放一次，环走出的路径与当时逐字相同。反之，一旦环依赖轮次，
就要同时维护「第几次」这份第二状态，而它一旦与事实分叉，回放再也对不上。

### 债是不变量，判据必须机械可判

一笔债 = `owes ⇒ ◇ until` 的当前违例 + 谁该还。`owes` / `until` / `unless` 只能是对事实的
谓词，不能写成「看代码就知道该不该做」。**靠人读代码判断的地方，就是回放不可重建的地方**：
同一份日志两个人会读出两个结论，崩溃恢复也只能靠猜。因此谓词闭集（§1.2）只收等值匹配、
事实存在性、债状态与端口占位——它在装载期可被检查（每行收口），在运行期可被求值，
不留任何需要解释的判断。

### 端口只是世界，环不认识业务

环对端口的全部知识只有四个动作：**向端口请求、收答复、记失败、重试**。这个端口叫 `model`
还是 `tool`、背后是模型调用还是工具执行，环不知道，也不该知道。一旦环按端口名分支，
加一个端口就要改环，而端口数没有上界。这就是「加一个端口 = 0 个新事实名 + 1 个
`PortDecl` + 适配器 + 行模板，`drive` / `owed` 字节不变」的来源。

### 五条协议事实：一次往返的全部状态变化

环只需要表达「发出去了 / 收到了 / 失败了 / 再试一次」，所以协议格就是 `request` / `sent` /
`response` / `failed` / `retry` 五条，端口与尝试号是**载荷**，不是新的事实种类。若事实种类
随端口数增长，「环认得的世界」就会跟着端口一起膨胀；固定五条，新端口只在载荷里出现。

### 幂等键 `(port, id, attempt)`：重试不长出新债

`id` 由申报方从输入事实派生（禁计数），`attempt` 只由租约推进。同一笔债重试写出的是
`request{attempt+1}`：债身份不变，只是尝试号前进一步；领域事实的 `id` 不含 `attempt`，
执行两次落下的仍是同一条事实。没有这条，重试就是「又一次新的欠账」，账本随重试次数
线性膨胀，且无法判断两条是不是同一件事。

### 只有外部事实能推进；环自己能做的必须一次做到底

`drive` 同步穷尽到「这一圈没有可还的债」才返回。等答复、等授权、等超时这三类只能由外部
事实推进，环不替它们自等；而环自己算得出来的（选债、配对、判死、重派）必须在同一次调用里
做完。否则「环还在等」与「环没事可做」会混进同一个返回码，调用方只能靠猜或轮询。

### 无进展即停

一圈下来 `(kind, key)` 零新增 ⇒ 环不再有可推进的事实，直接停（`Stalled` / 步数上界），
不空转。这是「执行体声称还了债却没写任何事实」这一静默故障的唯一兜底：装载期的「每行收口」
查的是**能不能**收口，运行期的零新增查的是**这次**收没收。

### 单一写口

事实只从一个写口进（宿主的事实写入口），踢环只从驱动入口进（`drive`）。没有第二个写者，
就没有第二份状态；也没有「某个组件顺手把环踢起来」这条旁路——所有唤醒都必须先落成事实。

## 0. 记号与总原则

- `debt(port, id, attempt)`：债身份。`id` 由申报方从事实派生（禁计数）；`attempt` 只由租约推进。
- 环只落五类协议事实：`request` / `sent` / `response` / `failed` / `retry`；领域事实由能力方写。
- 表二的谓词只读两类输入：本可见域的事实（`when` / `when_id` / `unless`）与环自己的债状态
  （`after` / `when_no_open` / `after_port`）。不读任何引擎自述。
- **禁止出现的词**：步骤、阶段、轮次、第 N 次、序号。它们不是事实。
- **事实身份规则**：一条能力事实的 `id` = 产生它的债 `id`（不含 `attempt`）。

### 1.1 关键载荷

载荷由写方定义、读者按自己的需要取；环不读载荷。当前需要跨插件对齐的字段：

- `authz.granted`：`{port, id, attempt, tool, risk, basis, grant, deferred}`。
- `authz.denied`（工具侧私有，D-390）：`{port, id, attempt, tool, detail, why}`；
  `model.speech.denied`（模型侧私有，D-390）：`{port, key, root_id, detail, reason}`，
  `key = chat.assistant.final`。授权依据字段是 `basis`
  （`symbio-kernel/src/capability/mod.rs`）。
- `plugin.row.asked`：`{row, key, prompt}`；行名与键都在载荷里，事实种类只有一个。
- `tool.call.requested`：`{request_id, call_id}`。`request_id` 是 `tool.requested` 的
  **事实 id**，`call_id` 是该调用的 wire id。写方 `model`（与 `tool.requested` 同一
  出口，按 `calls[]` 逐条落）；读者 `tool`（债表 `DebtSource::rows()` 按名字逐条取，
  不读 `tool.requested` 的载荷）；幂等键 `(request_id, call_id)`，事实键即
  `tool.call.requested:{request_id}:{call_id}`，同一对重试被事实源按 `event_id` 吸收。
- `session.config` / `session.recall` 的幂等键由 `user.message` 的事实 id 派生
  （`session_config_id` / `session_recall_id`）。

### 1.2 债行的谓词闭集

一行债只表达「欠不欠」与「什么时候可还」，谓词闭集如下：

1. `when(<种类>)`：该种类的事实在本可见域存在才欠。
2. `when_id(<种类>, <id>)`：该种类、该身份的事实存在才欠；用于**依赖**某条输入事实，
   避免把上一轮的旧事实当成这一轮的输入。
3. `unless(<种类>)` / `unless_id(<种类>, <id>)`：排除条件，已存在则不欠。
4. `after(<债 id>)`：前置债收束之前本行不可还；只写债 id，不写端口名。
5. `when_no_open(<端口>)`：该端口的债全部还清才欠（读债状态）。
6. `after_port(<端口>)`：该端口这一圈还有人认领 ⇒ 本行不进计划；没人认领 ⇒ 前提已了
   （缺席即收束）。
7. 无条件：以上都省略 ⇒ 无条件欠一笔（是否已收束仍由环的配对键判定）。

`when_no_open` 与 `after_port` 是同一条读面、方向相反；依赖方只认端口。前提债不是静默门：
被挡住的行走同一圈的计划，前提行自带租约与尝试上界；认领了却收不了束的，租约到期判死
（`failed`），端口随之清空。一圈没有任何动作、而账上仍有依赖方被挡住时，环报 `Stalled`
（不是 `NoDebt`）。

### 2.4 行执行体

`Decl` 行由 `plugin_rows::PluginRowExecutor` 执行：`run` 返回 `RowStep::Facts` 或

落在同一 id 后行重新触发，`parse` 关账。执行体不调模型——往返由申报方声明的那笔债走端口。

## 3. 三个硬点

### 3.1 模型 ↔ 工具往复 = 条件性再欠一笔

`model` 写一条 `tool.requested` 与 N 条 `tool.call.requested` ⇒ 各欠一次执行
（一调用一笔债）；每次执行完只收自己那一笔。`tool.calls.done` 由工具插件的簿记写方
在**该请求的每一笔工具债都有终局事实**后补写——它不从执行体的最后一步落格，执行体
中途死掉时由租约收束后的同一投影重算。该次应答的调用齐全后，`model-after-tools`
以 `tool:{request_id}` 之后的新身份重新成立（`model:after:{artifact_id}`），这是
**新债**，不是老债的重复执行。需要授权的调用先由 `authz.granted` / `authz.denied`
决定 `tool` 端口执行哪一支。

### 3.2 一个 scope 何时算完

```
complete(scope) :=
      chat.assistant.final(scope)
   ∧ session.settled(scope)
   ∧ 不存在更晚于 settled 的 user.message(scope)
   ∧ 债表对该 scope 不再产出任何未收束行
```

前四项是事实，最后一项是对债表的求值（对同一批事实重算一次行集）。

### 3.3 重放收敛

- **幂等键 = 债身份**：`(port, id, attempt)`；`id` 由输入事实派生，`attempt` 只由租约推进。
- 环只落五类协议事实，并落盘。
- 重起后：已有 `response` / `failed` 的债直接视为收束；只有 `request`、无 `sent` ⇒ 补派发；
  有 `sent`、无收束且租约已过 ⇒ 落 `retry(attempt+1)` 再派发；同一 `(kind, key)` 重复投递
  被账本吸收。
- 领域事实的 `id` 不含 `attempt`：同一债重试执行两次，写出的仍是一条事实。

### 3.4 model 的最小债规则

| 行 | 端口 | 债 id | 谓词 |
|---|---|---|---|
| `model-reply` | `model` | `model:{user_id}` | 有本轮输入、尚无对应终答 ⇒ 欠一笔；等 `plugin_row` 端口干净 |
| `model-after-tools` | `model` | `model:after:{artifact_id}` | 有工具请求、工具端口无未还债 ⇒ 欠一笔 |

第二行不需要执行体写「批次完成」事实：工具是否全部还清由**债状态**回答。

## 4. 加一个新能力只动什么

一个新能力插件只交三样东西，**环与宿主零改动**：

1. 它写的事实名（`EventDecl`；跨插件消费的登记进 `shared_events:`）；
2. 它的债：`DebtSource::rows()` 返回 `DebtSpec`，或 `Decl` 行（`by = plugin_row`，执行体交 `RowHandler`）；
3. 它的执行体（只读写事实，拿不到派发句柄）。

**能力折算判据**：新增一个能力时，只改它自己的 crate（声明 + 执行体），环、宿主、
`plugin-api`、`kernel` 的 diff 为 0；若做不到，先检查是不是行拆错了或事实缺了，而不是先加谓词。

落地前提：

- 插件声明必须是**运行期可枚举的数据**（`PLUGIN.yml` + 声明注册），宿主只做「收集声明 → 交给环」；
- 环只认行数据：端口名是字符串，`until` 是事实名匹配，谓词是事实 / 债状态；
- 谁写哪条事实由声明给出，环不替任何插件写领域事实。

## 5. 关键决策

### D-389 事件 owner 按实际写方移交，清单是唯一登记口

**问题**：`loop/PLUGIN.yml` 的 `shared_events` 仍是 10 条世界事实的唯一登记口，但写方分别在
会话（`session.config` / `turn.branch` / `turn.dispatch`）、工具（`authz.*` 与
`task.controlled`）、代理（`commitment.*`）。环既不读也不写这些事实，manifest 上的 owner
因此与生产代码的写方不一致——登记口在环、写方在别处。

**裁决**：按实际写方逐条移交 owner。**迁移只改声明归属**：kind / 格位 / 载荷形状 / 生成常量
的值 / `SHARED_EVENTS` 的顺序一律不动，读方代码零改动，行为不变。分两批：

1. **批一（同 crate 三条）**：`session.config` / `turn.branch` / `turn.dispatch` 从 loop 的
   `vocab::EVENTS` 与 `shared_events` 移进 `session::declarations::EVENTS` 与会话的
   `shared_events`；`turn.dispatch` 的 `DeclaresBudget` 角色原样照抄。生成物只改
   `← owner` 注释，`SHARED_EVENTS` 与常量数保持 31 / 31。
2. **批二（跨 crate 三组，一次一组）**：`authz.granted` → tool；`commitment.*` → agent
   （agent 需新建 `declarations.rs` 并 `submit_declarations!`，**不得把 `behavior.rs` 里的
   名字复制成第二份字面量**——那会撞 `SV-001`）；`task.controlled` → tool 但走私有化，
   见下。

**`task.controlled` 走私有化，不进共享表**：今天只有 tool 的熔断写它（D-202 记的会话 inbox
写方在生产代码里已不存在），没有第二个插件在生产代码里按名字读它。若把它登记进 tool 的
`shared_events`，CS-007 立刻红（共享名必须有非 owner 消费方）。因此：tool 在自己的
`declarations::EVENTS` 里登记格位、**不写进 `shared_events`**；`plugin-api` 不再生成
`EVENT_TASK_CONTROLLED`；写方改用 tool 的本地常量。本条单独落时 `SHARED_EVENTS` 与
常量数为 30 / 30；与 `D-390` 合并后当前 **29 / 29**。

**`authz.denied` 不在本条**：它有 tool 与 model 两个写方，按「一个名字不能两个写方」另案
裁决（`D-390`），不搭迁移批次。

**判据**：`CS-007`（每条共享名有 owner 的 `EventDecl` 与非 owner 消费方）、`SV-001`（一个字面量
只能在一个插件 crate）、`gen-facts --check`（`events.rs` 与 manifest 一致）。批一 / 批二各自
跑 `gate --full` 并报前后读数。

### D-390 一个名字两个写方：按 owner 拆名，读者改按格位 + 语音键认停

**问题**：`authz.denied` 有 tool（授权拒因，`port.rs::approval_denied_draft` 与产物闸）
与 model（语音键拒因，终答被写侧闸拒）两个写方。迁移 owner 只能把借用关系从一个 crate
搬到另一个 crate，问题（一个名字两个写方、永久借用备注）原样保留。

**勘察结论（本条落笔的前提）**：会话里两处读 `authz.denied` 的投影都**只用**「`(Scope,
Asserted)` 格位 + 载荷 `key = chat.assistant.final` + `root_id`」：

1. `symbio-sdk::projection::rebuild` 的 `denied_speech`——收集被拒轮，把那次答复挡在
   对话面之外；
2. `symbio-plugin-session::convergence` 的 `speech_denied`——同一判据 + `root_id` 归属本轮，
   判本轮正常收束。

事件名只是两道过滤里多余的第一道。`ChatVocab.denied` 在这两处之外没有消费者。因此拆名
**不丢信息**：读者改按格位 + 语音键收集，两种旧事件的载荷都带这两个字段，旧日志照常折叠。

**裁决**：

1. **拆成两个私有名**：tool 的授权拒因保持 `authz.denied`（工具侧私有，与将来的
   `authz.granted` 同域）；model 的语音键拒因改名 `model.speech.denied`。两者各归 owner，
   在各自 `declarations::EVENTS` 登记格位，都**不进** `shared_events`；`plugin-api` 不再生成
   `EVENT_AUTHZ_DENIED`（净减 1：31 → 30，与 D-389 合并后 29）。
2. **角色按语义归位**：只有 model 的 `model.speech.denied` 带 `StopsTurn`，载荷补
   `reason: "denied"`（它才是停轮事实）；tool 那条只是「这一笔调用没放行」，**不带**
   `StopsTurn`——C6 因此不再向它要 `reason`。
3. **会话投影去掉名字字段**：`ChatVocab.denied` 删除，改为 `ChatVocab::denies_speech`
   （`(Scope, Asserted)` ∧ `key = chat.assistant.final`）。写侧闸的否定事实只有这一格；
   定稿格 `chat.assistant.final` 落在 `Scope × Closed`，不会误伤。

**行为变化（读者面）**：

- `rebuild::denied_speech` / `convergence::speech_denied`：判据等价，输出不变；
- `invariants` 的 `is_stop_fact`：tool 的 `authz.denied` 不再计入停机事实（C6 少问一类
  `reason`）；model 的语音键拒因仍计入；
- 事件名层面：tool 那条的日志名不变，model 那条的日志名从 `authz.denied` 变为
  `model.speech.denied`（只有按名字读的读者会察觉，而今天没有这样的读者）。

**判据**：`t73`（发言被拒 ⇒ 不进对话面且轮收束）、`SV-001`（两个私有名字面量各只出现在
一个插件 crate）、`CS-007`、`gen-facts --check`；`gate --full` 报前后读数。

### D-392 测试夹具与词汇层重复定义：同一批 owner 声明生成两处产物

**问题**：`crates/symbio-sdk/src/test_fixtures.rs` 与 `crates/symbio-plugin-api/src/events.rs`
各有一份事件名定义。`event.rs` 是 `scripts/facts/events-rs.mjs` 从各插件 `PLUGIN.yml` 的
`shared_events` 与 owner `EventDecl` 生成的投影；`test_fixtures.rs` 此前是**手抄**。

**重复面（勘察读数）**：夹具的 19 个 `pub const` 名字**逐条**与某个 owner 的 `EventDecl` 同值；
其中 13 条还同时是 `events.rs` 的常量（`EVENT_USER_MESSAGE` / `EVENT_CHAT_ASSISTANT_FINAL` /
`EVENT_CHAT_ASSISTANT_FALLBACK` / `EVENT_TURN_BRANCH` / `EVENT_TURN_BRANCH_SELECTED` /
`EVENT_ARTIFACT_ADDED` / `EVENT_MESSAGE_ADDED` / `EVENT_MESSAGE_REMOVED` /
`EVENT_SESSION_CONSOLIDATED` / `EVENT_COMMITMENT_OPENED` / `EVENT_COMMITMENT_RELEASED` /
`EVENT_COMMITMENT_BROKEN` / `EVENT_COMMITMENT_ASSERTED`），另 6 条是 owner 私有名
（`chat.assistant.reported` / `chat.assistant.opening` / `chat.assistant.progress` /
`model.speech.denied` / `message.edited` / `verdict.asserted`）。夹具的 `EVENTS` 另有
24 行 `EventDecl`（19 条业务名 + 协议五格）逐行重复 owner 声明。

**为什么会存在，以及它不是生产回退**：core（`symbio-sdk`）在 `symbio-plugin-api` 的下层，
core 的用例**不能** import `symbio_plugin_api::events`——那是反向依赖。它被
`#[cfg(any(test, feature = "test-fixtures"))]` 包住，生产构建不编译；`symbio-plugin-api`
`vocab()` 回退 `SHARED_EVENTS` 是另一条生产路径，与夹具无关。因此这是**夹具副本**，
不是第二套生产词汇面——处置是单一源，不是删除。

**依赖方向**：`symbio-plugin-api` → `symbio-sdk` → `symbio-kernel`。让 sdk 依赖 api 会反向
依赖，让夹具搬进独立测试侧 crate 会造 dev-dependency 环（sdk 的 `#[cfg(test)]` 用例要反向
依赖上层）。死结的合法解法只剩「同一份 manifest / owner 声明生成两处产物」。

**裁决**：新增 `scripts/facts/test-fixtures-rs.mjs`，与 `events-rs.mjs` 共用
`pluginDeclarationFaces` 读同一批 owner `EventDecl`，生成 `test_fixtures.rs`：
**选面**（用哪些名字）仍写在生成器的 `GROUPS` 里，**定义**（值 / 格位 / 角色 / host）逐条
取自 owner；协议五格取内核常量。生成物首行带「生成，请勿手改」，手改由 `gen-facts --check`
判红。测试夹具本身挪不进独立 crate，也不留手抄副本。

**行为变化**：夹具 `EVENTS` 里 `user.message` 的格位从旧手抄的 `(Scope, Asserted)` 归位为
owner 的 `(Scope, Opened)`；同格位的其余条目不变，sdk 用例全绿（311 passed / 2 ignored）。

**判据**：`SV-001` 新增第三臂——机制层（`symbio-sdk` / `symbio-kernel` / `symbio`）的生产
代码里出现**词汇层已有的事件名**字面量、或声明与词汇层同名的常量即红，报出「哪个文件、
哪几条名字、词汇家在哪」；扫描范围从插件 crate 扩到机制层，`test_fixtures.rs` 不按
「测试文件」排除，带生成标记的投影整份跳过。`gen-facts --check` 守住两处产物同源。

### D-393 安全阀出口落成机制事实：两条出口共用一种形状，落格走不绑驱动的开面

**问题**：`DriveOutcome` 的 `Exhausted` / `Stalled` 是「这一圈没跑完」的读数，但仓库里
唯一读者是 CLI 的 `drive_notice` → `eprintln!`。没有控制台的宿主（Tauri / gateway）
拿不到 stderr，两条出口在界面上与「正常结束」同形（RE-014 §7）。

**裁决**：

1. **载体选事实，不选会话节点 error 写入**。事实可回放、可订阅，且同一份读数既能被
   会话投影折成节点错误，也能被将来的宿主直接订阅；写会话节点 error 需要第二套写口，
   与「单一写口」冲突。两条出口**共用一种形状**：`driver.stalled`，载荷
   `{session_id, outcome: "exhausted" | "stalled", steps?, outstanding}`——`steps`
   只在 `Exhausted` 出现，`outstanding` 是未收束的债身份列表。
2. **写方只在驱动入口**（宿主运行时 `crates/symbio-host/src/drive.rs::drain`），在已有的
   `drive_notice` 判定点旁写一次；CLI 的 stderr 文案一字不改，调用面行为不变。
3. **落格走不绑驱动的开面**（`open_fact_source` 返回 `drive: None`）。出口事实是**通知**，
   不是环的输入：若经绑定驱动的写口落格，会 kick 出下一轮，`Exhausted` 变成「写完再跑
   一轮」，步数预算失去意义。
4. **读方由会话 `runtime` 投影承担**：`driver.stalled` 折成 `outcome = "failed"` +
   `error`（「驱动停摆：步数预算用尽（N 步，未收束 M 笔）」/「驱动停摆：一圈没有新增
   事实（未收束 M 笔）」），经 VDFS 会话节点对任何进程可见；带终答的一轮不会被它改写
   （投影取最后一条生命周期证据）。

**名字归属**：`driver.stalled` 是**机制私有名**，不在任何插件的 `shared_events`，
不进 `EVENT_*` 生成物、不参与选债 / 派发 / 配对；`plugin.row.asked` 与它同类。
它的字面量只有一处（`symbio-plugin-api::drive::EVENT_DRIVER_STALLED`），环的声明
以 `EventDecl::host` 登记格位。

**判据**：`crates/symbio/src/drive.test.rs`（两种出口各落一条、正常出口不落）与
`crates/symbio-plugin-session/src/runtime.test.rs`（投影折成 `failed` 且带原因、
后到的终答压过停摆）钉住正向；`e2e/cases/t104-driver-safety-valve.mjs` 只钉反向
（正常轮不落 `driver.stalled`、stderr 不出声、会话节点仍 `completed`）。**正向不进 e2e**：
真实装配里工具结果会开新一轮，每一轮各自带着完整步数预算，用户输入没有一条确定性的
路径把安全阀顶开——写一条会撞静止超时的「正向」等于留一条永远绿的判据。
