# 核心架构：事实、Actor 与控制环

> **一句话**：一个智能体系统 = **1 个原语 + 1 个签名约束 + 1 个使用者概念 + 3 条不变量 + N 行参数数据**；
> 它的控制面是**一环 · 一表 · 一源**；它的 Agent 是**一棵插件树**。
>
> 本文只写**目标形态**。演进纪律见 [DE-016-工程落地与验证](016-工程落地与验证.md "DE-016-工程落地与验证")；能力坐标系见
> [DE-008-能力注册表与能力坐标系](008-能力注册表与能力坐标系.md "DE-008-能力注册表与能力坐标系")。义务环的机制细则见 [DE-015-义务环](015-义务环.md "DE-015-义务环")。

## 0. 存在什么

```
 用户消息 / 定时 / 系统信号
 │
 ▼
 ┌──────────────────────────────┐
 │ Store （唯一原语）            │
 │ append(e) → Seq              │◄──── Actor 的写入
 │ range(from) → &[Event]        │
 └──────────────┬───────────────┘
 │ &[Event]
 ▼
 ┌──────────────────────────────┐
 │ Projection （签名约束，非机制）│
 │ (&[E], Timestamp) → V         │
 └──────────────┬───────────────┘
 │ View
 ▼
 ┌──────────────────────────────┐
 │ Actor （一等概念，非原语）     │
 │ Decider │ Reasoner │ Translator│
 │ = 一行 ActorSpec 数据         │
 └──────────────────────────────┘
```

<!-- list:core-elements owner -->
| 元素 | 性质 | 数量 | 随场景增长吗 |
|---|---|:-:|---|
| **Store** | 原语（trait，有方法、有不变量、可编译强制） | 1 | 否 |
| **Projection** | 签名约束（泛型形状受限的薄包装类型，无 trait、无注册、无 impl 扩展） | 1 类型 | 否 |
| **Actor** | 一等概念（3 种模式 = 配置） | 3 模式 | 否 |
| **不变量** | I1 单通道 / I2 无溯源不声明 / I3 到点必答 | 3 | 否 |
| **参数数据** | 事件格子、ActorSpec 行、grants 行、视图定义 | N | **是**（唯一允许增长的东西） |
| **控制面** | 一个环 + 一张行表 + 一个事实源 | 1 环 / 1 表 / 1 源 | 否 |
| **Agent** | 一棵由插件容器装配的树 | 1 树 | 结构不增，实例可增 |

## 1. 为什么只有 1 个原语

### 1.1 三个职责与冲突矩阵

任何智能体系统都必须有三件事。每个职责带一组**带极性的约束**（`要求` / `禁止`）：

| 职责 | 含义 | 约束 |
|---|---|---|
| **Hold** | 事实的持有 + 唯一写入口 | 要求 `write_gate_exclusive`；禁止 `direct_write` |
| **Derive** | 从事件序列纯派生视图 | 禁止 `side_effect`；禁止 `nondeterminism` |
| **Act** | 读事实、产生新事实（调 LLM、有副作用） | 要求 `direct_write`；要求 `side_effect` |

**唯一判据**：同一性质的极性相反，不可合并。

| 组合 | 结论 | 冲突性质 |
|---|---|---|
| Hold ⊕ Derive | 可合并 | 无 |
| Hold ⊕ Act | 不可合并 | `direct_write`：Hold 禁止 / Act 要求 |
| Derive ⊕ Act | 不可合并 | `side_effect`：Derive 禁止 / Act 要求 |

分组结果：`{Hold, Derive}` 与 `{Act}`，不可再分分组数 = 2。

### 1.2 Act 是使用者，不是构成者

`{Hold, Derive}` 与 `{Act}` 不可合并，只说明它们**必须分开存在**，不说明 `{Act}` 是原语。

一个 Actor 在物理上只做三件事：

```
events   = projection(store.range(from), now)   ← 只用 Derive
decision = 模式内部的决策（规则 / LLM / 转述）   ← 配置，不是机制
store.append(new_event)                        ← 只用 Hold
```

Actor 没有自己的状态、接口与不变量。**它是装配线，不是砖。** 因此：

- 把 Act 计入原语，下界 = 2；
- 把 Act 计为一等概念，下界 = 1（本方案）。

### 1.3 投影不做成 trait，但也不是裸别名

把投影做成 trait（`fold` + `filter`）不增加强制力：trait 只规定「有哪些方法」，
不规定「实现里不许干什么」。但**裸 `type` 别名也不够**——它不阻止把带副作用的东西
注册成投影。按 J3（静默失效必须强制），投影纯度需要**不可伪造的构造入口**：

```rust
pub struct Projection<V> {
    f: Box<dyn Fn(&Event, Timestamp) -> V + Send + Sync>,
    _p: PhantomData<V>,
}

impl<V: 'static> Projection<V> {
    pub fn new<F>(f: F) -> Self
    where F: Fn(&Event, Timestamp) -> V + Send + Sync + 'static;

    pub fn apply(&self, ev: &[Event], now: Timestamp, b: Budget) -> View<V>;
}
```

**收益**：少一个 trait、少一层 impl，而强制性比裸别名更强——想写一个带副作用的投影，
在构造那一刻就编译不过。

### 1.3.1 投影纯度的两级强制

| 级 | 拦什么 | 靠什么 | 拦不住的 |
|---|---|---|---|
| **一级** | 句柄进不来（`&Store` / `&mut` / `Clock` / `Principal`） | `Projection::new` 的泛型约束（编译期） | 闭包体内调用全局函数（如 `SystemTime::now`） |
| **二级** | 隐式全局依赖；投影 A 读投影 B；死构造器 | 门禁静态扫描（`projection-purity`） | — |

**一级能拦住「顺手写一笔」，拦不住「偷偷看一眼表」。** 二级不可省。零大小能力令牌
`PureOnly`（私有构造器、`size_of == 0`）用于把「这条链路不写」变成可传递的证明。

### 1.4 记账对照：三种记法，同一个系统

| 记法 | 原语计数 | 派生怎么记 | 行为怎么记 |
|---|:-:|---|---|
| **A** | 3 | 并入原语 `Process` | 原语之一 |
| **B** | 2 | 独立原语 `Project`（做成 trait） | 一等概念 |
| **C（本方案）** | **1 + 1 签名约束** | 泛型形状受限的 `Projection`，不做 trait | 一等概念 |

三者真正的分歧只有一处：**行为算不算原语**。A 说算，B/C 说不算；B 与 C 的差异只在
「派生做成 trait 还是只做签名约束」。本方案用签名约束拿到了 trait 的那条真实收益
（确定性 / 无副作用 / 可降级从约定变成编译期强制），**收益一分不减，抽象少一层**。

| 职责 | 本方案的记账 | 为什么 |
|---|---|---|
| 容器 + 写门 | **原语 `Store`** | 有方法、有不变量、可编译强制 |
| 元素类型 | 数据 `Event` | 无方法、无不变量 |
| 派生 | **签名约束** | 见 §1.3 |
| 行为 | **一等概念 `Actor`** | 见 §1.2 |

### 1.5 诚实标注：这一步是选择

| 命题 | 性质 |
|---|---|
| 三个职责不可两两合并（除 H⊕D） | **已证明**（冲突矩阵） |
| Act 不是系统的构成者 | **判断**（它无状态、无接口、无不变量） |
| 投影不做成 trait | **工程选择**（trait 不增加强制力，却增加抽象层） |

因此「原语 = 1」是一个立场 + 一个工程选择，不是被证明的下界数字。

## 2. 原语 · Store

```rust
pub struct Seq(pub u64);

pub trait Store: Send + Sync {
    type Event: EventEnvelope;

    fn append(&self, event: Self::Event) -> Result<Seq, AppendError>;
    fn range(&self, from: Seq) -> Vec<Self::Event>;
    fn head(&self) -> Seq;
}

pub enum AppendError {
    Duplicate,
    Conflict { expected: Seq, actual: Seq },
    NotTheWriter,
}
```

| 语义 | 保证 | 违反后果 | 强制方式 |
|---|---|---|---|
| **单写者** | 每 thread 一个 FIFO，串行 | 竞态回归 | 运行时 + CI |
| **单调 seq** | thread 内严格递增、无跳号 | 回放顺序错乱 | 类型 + 运行时 |
| **append-only** | 接口上无 `update` / `delete` | 事实可被篡改 | **编译期** |
| **幂等** | 重复 `event_id` / `idempotency_key` → `Duplicate` | 重复副作用 | 运行时 |
| **原子** | 单事件要么完整落盘要么不落 | 回放崩溃 | 运行时 |

**实现替换不构成架构改动**：内存 / WAL / 分片 / 加密全部是 `impl Store`，调用方零改动。
**索引也是实现细节**：向量 / 倒排 / 时间分区 / 混合索引都不进 trait 签名。

## 3. 签名约束 · Projection

```rust
pub struct Projection<V> { /* 私有字段 */ }
impl<V: 'static> Projection<V> {
    pub fn new<F>(f: F) -> Self
    where F: Fn(&Event, Timestamp) -> V + Send + Sync + 'static;

    pub fn apply(&self, ev: &[Event], now: Timestamp, b: Budget) -> View<V>;
}

pub struct View<V> { pub value: V, pub degraded: bool, pub used: Budget }
pub struct Budget { pub tokens: u32, pub ms: u64 }
```

| 性质 | 断言 | 为什么必须 | 强制方式 |
|---|---|---|---|
| **确定性** | 同一事件序列 → 逐字节相同 | 可回放、可对比、可测试 | 二级：单测 / CI 双跑比对 |
| **无副作用** | 不调 LLM、不写库、不读时钟 | 否则回放漂移 | 一级：句柄进不来 + 二级：静态扫描 |
| **可降级** | 超预算返回 `degraded: true`，不抛错 | 对话永不因状态爆炸中断 | 一级：构造即锁定返回 `View<V>` |
| **预算** | 截断与降级由 `apply` 统一执行，闭包只返回视图值 | 预算语义只有一份 | 框架层 |

**视图 = 参数，不是组件。** 系统里的「状态」只有一个来源：

| 视图 | 消费者 | 过滤策略 | 预算 |
|---|---|---|---|
| `Snapshot` | Chat | 合并同任务事件 + 摘要 + 产物引用 | ≤ 1.5k tokens |
| `Display` | 用户 UI | 滤掉系统事件 + 翻译 + 排序 | UI 分页 |
| `ReadySet` | 调度 | 只取终态 + `depends_on` 闭合 | 常数 |
| `TurnState` | 状态机 | 该 turn 的事件 | 常数 |
| `Checkpoint` | 崩溃恢复 | 该 task 全量 + 压缩 | 可序列化 |
| `Recall` | 记忆检索 | 语义 / 时序 / 因果混合打分 | 可配置 |
| `Eval` | CI / 评测 | 事件切片 → 断言 | 离线 |

## 4. 一等概念 · Actor

```rust
pub struct ActorSpec {
    pub principal: Principal,
    pub pattern: Pattern,
    pub capabilities: Vec<Capability>,
    pub budget_ms: u64,
    pub scope: Scope,
}
```

`model` 与 `context` 不是独立字段：`model` 是 `pattern` 的函数（Decider → 无、
Reasoner → LLM、Translator → 小模型），`context` 是投影的参数。**5 个字段，
不是一个 12 字段的配置对象。**

| 模式 | 决策来源 | 确定性 | 典型用途 | 预算量级 |
|---|---|---|---|---|
| **Decider** | 规则 / 代码 | 确定 | 意图判定、就绪判定、权限、熔断、仲裁 | 毫秒级 |
| **Reasoner** | LLM | 非确定 | 规划、生成、语义判定、工具调用 | 秒–分钟 |
| **Translator** | 事件 → 另一种表示 | 确定 | 转述、摘要、检索召回、格式转换 | 百毫秒 |

模式选择的判据函数：

```
pattern(action) = if 可写成确定性规则 → Decider
                  else if 只需重述已有事实 → Translator
                  else → Reasoner
```

**Translator 不创造信息**：它的输出必须能追溯到输入事件，因此它拥有与 `reply` 相同的
写权限，不需要单独的能力。

### 4.1 时延预算 = 事前闸门

把 `budget_ms` 当声明、超时后记录违规，是事后取证，不是预防。按 J3，档位必须
**约束它能拿到哪一档依赖**，做成构造期闸门：

| 档位 | `budget_ms` | 允许模型 | 允许生成 | 注入的依赖句柄 |
|---|:-:|:-:|:-:|---|
| 反射 | 80 | **否** | 否 | 只有 `RuleEngine`（纯规则 / 查表） |
| 快速 | 300 | 是 | **否** | `Classifier`（输出空间限定四选一） |
| 深度 | 60000 | 是 | 是 | 完整 `LlmClient` + 工具 |
| 自主 | 86400000 | 是 | 是 | 完整 `LlmClient`（常驻） |

实现方式是零大小能力令牌（私有字段 → 不可伪造，`size_of == 0`）：

```rust
pub struct RuleOnly { _private: () }
pub struct FullModel { _private: () }

impl LlmClient { pub fn generate(&self, _t: &FullModel, ...) -> String }
```

**「反射层不得调模型」不靠自觉、不靠扫描——它编译不过。** 快速档的「不得生成」由
返回类型与工具集判据强制，不靠 prompt 里写一句「请不要生成」。

**与 I3 的关系**：闸门不替代 I3，而是把 I3 从「事后检测」升级为「事前不可能」。
判据始终是时延，不是形式——一个 10ms 的本地查表在反射档完全合法。

### 4.2 「欲」的最小可执行形态

「欲」必须落成数据，并回答三个可执行的子问题：

| 子问题 | 落点 | 性质 |
|---|---|---|
| **E1 欲是什么？** | 一条事件 `conation.expressed`（走 I1 单通道、I2 带溯源） | 事件网格加一行 |
| **E2 欲如何不直接变成行？** | 欲 → `CandidateIntent`（待评估）→ **闸门** → `ApprovedTask` | **不可伪造的批准类型** |
| **E3 欲如何被关停？** | `ConationPolicy.enabled`，**平凡值 = false** | J2：关闭后退化为纯响应式且仍完整运行 |

`ApprovedTask` 字段私有，模块外造不出，唯一构造点是 `IntentGate::approve`。三道治理
各自落在能判它的地方：授权在闸内判（与任务表写侧闸同一把尺）、预算在动作面判、
审计由事实流承担（`task.opened` 带 `produced_by` 指回那条欲事件）。

> **「欲」解决的是「欲如何被治理」，不是「欲从哪来」。** 架构只保证：想要的都留痕、
> 都必须过闸、都可关停。

### 4.3 控制面：一环 · 一表 · 一源

**终点语义**：

```text
agent = fixpoint(decide) over (事实日志 × 世界端口)

decide : (事实投影 × 事件) → [要追加的事实 | 要发往世界的意图]*
驱动   = 每个事件到达后，迭代 decide 直到不再产出任何东西
```

- **单环**：全系统唯一的控制面循环。一次事件到达，追加进日志，然后反复问
  「现在欠什么、还哪一笔」，直到无债可还。
- **一表**：策略行与能力行使用**同一个行形状与同一套裁决规则**（`(prio, name)` 全序、
  先命中者胜），按消费方分目录存放。表里零代码：模式只有名字、字段等值、键绑定、比较。
- **一源**：`State` 是 Store 的投影，**不允许第二份状态表示**。副作用唯一出口是
  `append`；任何不经 `append` 改 State 的路径都非法。

`drive` 是不动点迭代的工程写法，不是独立机制。回放 = 重放事件序列、逐事件重算不动点、
比对事实日志——L1 确定性从「承诺」变成「定义」。

**交换律**：fixpoint 之所以能与「事件中途到达」复合，是因为一切变化——工具完成、插话、
定时、审批——都在下一次 `project` 之前经 `append` 落为事实。**`append` 是唯一的交换点。**

**并发不在 `drive` 里**：单会话单写者意味着同一会话的债串行还；并发来自多个会话各有
一个 `drive`，以及执行体内部的批次并发。并发集合是事实，不是执行体的自觉。

### 4.4 义务环：一笔债怎么还

> 一个会话收事实、算欠账、还债、再收事实。**没有别的。** 完整机制见
> [DE-015-义务环](015-义务环.md "DE-015-义务环")；这里只给出主文档需要的形状。

```
① 收到事实 → 追加进日志
② 算欠账 → 从日志算出「还欠什么」，取最小的一笔
③ 运行它 → 交给执行体，它把领域事实直接写进同一个 store
④ 对账 → 引擎读回这次动作写进日志的那一段，回到 ②
```

**一笔债 = 一条 liveness 性质 `owes ⇒ ◇ until` 的当前违例，外加「谁该还」。**

```
open(d, key)      := ∃ f ⊨ d.owes ∧ key = bind(f) ∧ ¬∃ g ⊨ d.until ∧ key(g) = key
blocked(d, key)   := d.by = None ∨ ∃ h ⊨ d.unless ∧ key(h) = key
actionable(d,key) := open ∧ ¬blocked
min_debt(now)     := min { (d,key) | actionable } 按 (prio, name, key) 全序
```

时间不进公式：需要时间的条件由视图把 `now` 折成布尔字段，`owed` 本身仍是纯函数。
`now_ms` 只能来自触发事件的时间戳，不读墙钟。

**行表只声明，不执行：**

```rust
struct Decl {
    name: &'static str,
    owes: Pattern,
    until: &'static [Pattern],
    unless: &'static [Pattern],
    expand: Option<(&'static str, &'static str)>,
    by: Option<&'static str>,
    prio: u8,
    tier: LatencyTier,
}
```

`by = Some(名字)`：引擎到绑定表查那一个执行体并运行它；`by = None`：恒 blocked，
永不选中。决策债、搬运债、等待债是**用法**，不是机制——三者在 `drive` 里走同一行代码。

**端口按端口声明一次，不写进行里：**

| 行 | `owes` | `until` | `by` |
|---|---|---|---|
| `dispatch-<port>` | `request(port)` | `sent` / `failed` | `courier` |
| `await-<port>` | `sent(port)` | `response` / `failed` / `retry` | `None` |
| `lease` | `stale_sent`（视图） | `response` / `failed` / `retry` | `lease_keeper` |

**协议事实是闭集**：`request` / `sent` / `response` / `failed` / `retry`。端口是**载荷**，
不是信封；加一个端口 = 0 个新事实名 + 1 个 `PortDecl` + 适配器 + 2 行模板（租约行通用）。
`drive` 与 `owed` 的源码不因端口增加而改变。

**引擎只认识七个词**：事实、模式、键、视图、执行体、优先、前置标记。没有 `model`、
没有 `tool`、没有 `turn`、没有 `user`、没有 `prompt`。插件能往这七个词里填内容，
**不能加第八个**。

**装载期检查在冻结时一次做完**：依赖图无环；每行有出口；字段都在声明里；相交行对被
报告；执行体写入封闭；执行体能够走到出口；每个控制面事实名都有归宿。装载失败即拒绝
启动，不许部分成功。

**覆盖边界**（完整裁决见 [DE-015-义务环](015-义务环.md "DE-015-义务环") §5）：

- 定稿答话轮只欠判决那一行，跑完就在轮首收束，不进轮内驱动循环；
- 轮外模型往返没有轮号，明文出界，但差额必须由一条具名路径解释；
- 流式帧不是事实，走直通出口，不参与 `owed`；
- 审批、用户补充、中止都是外部事件，由唤醒源落事实后重新开账。

## 5. 三条不变量

| | 不变量 | 生成的推论 | 可执行判据 |
|---|---|---|---|
| **I1** | **单通道** | final 发言唯一；任意两主体无直连；投影拿不到写口 | `seq` 严格单调 · `≤1 final/turn` · 静态扫描无主体直连 |
| **I2** | **无溯源不声明** | `produced_by` 不悬空；产出者不自验；兜底话术也是事件 | 断言类事件的 `produced_by` 非空**且不悬空** |
| **I3** | **到点必答** | 反射 / 快速 / 深度 / 自主四层；**禁止静默超时** | `cost_ms ≤ budget_ms`，否则必须存在 fallback 事件 |

**I3 是最容易被漏掉的一条。** 缺了它，「对话」这个基础能力就没有架构级保障，
只剩工程优化。

**I2 的判据是两条**：`produced_by` 非空，且指向同一条日志里真实存在、序号更小的事件。
派生图无环是免费的：`seq` 严格单调 ⇒ 边只能从高指向低 ⇒ 天然 DAG。

## 6. 事件语法网格（实体 × 动词）

> 不维护会膨胀的名字列表，维护一张有限网格。新增事件 = 在网格里加一格。

| 实体 \ 动词 | `opened` | `progressed` | `held` | `closed` | `asserted` |
|---|---|---|---|---|---|
| `turn` | `user.message`<br/>`user.message.edited` | `turn.state_changed` | — | `chat.assistant.final`<br/>`chat.assistant.append`<br/>`chat.assistant.fallback` | — |
| `task` | `task.created`<br/>`task.planned`<br/>`task.decomposed` | `task.started`<br/>`task.progress`<br/>`task.checkpoint`<br/>`task.ready`<br/>`task.assigned` | `task.blocked` | `task.completed`<br/>`task.failed` | `task.verified`<br/>`task.rework_created`<br/>`task.replan_created`<br/>`task.tree_completed` |
| `artifact` | — | — | — | — | `artifact.added` |
| `verdict` | — | — | — | — | `classify.verdict`<br/>`classify.escaped` |
| **`memory`** | `memory.encoded` | `memory.consolidated` | — | `memory.forgotten` | **`memory.recalled`**<br/>`memory.calibrated` |
| **`commitment`** | `commitment.offered` | — | — | `commitment.released`<br/>`commitment.broken` | `commitment.asserted` |
| **`conation`** | **`conation.expressed`**<br/>`conation.proposed` | `conation.evaluated` | — | `conation.dropped` | `conation.gated` |
| `thread` | — | `thread.checkpoint` | — | — | — |
| `control` | `task.controlled` | — | — | — | — |
| `system` | `system.triggered` | `system.health` | — | — | — |
| **`message`** | **`message.added`** | **`session.consolidated`** | — | `message.removed` | `message.edited` |
| **`domain`** | — | — | — | — | — |

`domain` 行是**领域扩展位**（[DE-025](025-能力包与扩展面.md "DE-025-能力包与扩展面") D-209）：它的格子不在这里列举，因为
名字由 owner 的 `EventDecl` 声明、内核不解释。notes / calendar 这类新领域落
`domain × 动词`，各自是 owner 声明表里的一行——**加一个领域不加本表的行**。
这一行存在的意义是「让 `Entity` 的变体数与表的行数仍然相等」，从而 DC-005 这条
两处对账不必为一个扩展位开例外。

`conation` 的四个格子对应「欲」的三个子问题：`expressed` = 想要成为可审计的事实；
`evaluated` + `gated` = 欲不能直接变成行的那道闸门；`dropped` = 关闭「欲」后的平凡路径。
**没有 `conation.acted`**——欲永远不直接产出动作。

`message` 行服务「消息列表的变更」，是闭集：`message.added`（这条诞生了）、
`message.edited`（这条现在读作 Y）、`message.removed`（这段没了）、
`session.consolidated`（这份列表取代了它之前的一切）。新场景若需要第五种 ⇒ 模型错了。

**新增事件的准入三问**：能归入已有实体？能归入已有动词？消费方对未知值安全？
这张表是**语法的闭集，不是事件的闭集**：加行 = 预期演进；加行后无人写或无人读 =
定错信号，删行回到闭集、不留占位。

唯一的例外是 `domain` 行：**新领域不加行**，落那一行由 owner 声明（见上）。判据因此
分成两条——核心实体「加行要同时改枚举」，领域「加领域只改自己的 `EventDecl`」。

## 7. 三个正交维度：身份 / 能力 / 模式

| 维度 | 回答 | 形态 | 随场景增长 |
|---|---|---|---|
| **身份 `Principal`** | 谁 | 字符串 ID | **是（数据）** |
| **能力 `Capability`** | 有权做什么 | 枚举，权限矩阵的键 | **否（6 个封顶）** |
| **模式 `Pattern`** | 怎么做事 | `decider` / `reasoner` / `translator` | **否（3 个）** |

```rust
pub enum Capability {
    JudgeIntent, Reply, DefineWork,
    ProduceArtifact, AssertVerification, AssignWork,
}
```

**授权必须成对**：写侧 `grants_of(p) → can_write(cap, type)`，读侧
`sees_of(p) → can_see(scope)`。只有一侧都意味着另一侧被绕过。

**为什么权限必须第零天就位**：它是**静默失效**的——违反时没有测试会失败（J3）。
事后补，代价是重写所有历史事件。

## 9. 长期记忆：视图 + 检索

### 9.1 五类记忆 = 五个投影参数，不是五套存储

| 记忆 | 投影参数（`Recall` 视图的取值） | 保留策略 |
|---|---|---|
| 工作记忆 | `since(now-5min)` + 容量 4 | 窗口 |
| 情景记忆 | 全量按时间 | 冷层 |
| 语义记忆 | `tagged("semantic")` | 常驻 |
| 程序记忆 | `tagged("skill")` | 常驻 |
| 预测 | `tagged("prediction")` | 短 |

**「记忆类型」不是枚举，是过滤函数的参数**——加第六类记忆只需加一组参数，不动类型系统。

### 9.2 三件事各自的位置

| 事物 | 位置 | 为什么 |
|---|---|---|
| **embedding** | 一条普通事件 `memory.encoded{payload: vec}` | 它是事实，不是特殊类型 |
| **索引** | `Store` 的实现细节 | 不进 trait 签名，替换零改动 |
| **检索** | 一个 `Translator` 模式 Actor，产出 `memory.recalled` | 检索是「读视图 → 产出事实」 |
| **检索质量** | 可复现的 recall@k 数字 | 「存了但找不到」必须有数字，而不是修辞 |

**检索的可见性受 `VisScope` 约束**：A 的记忆默认对 B 不可见，跨主体共享是一次显式授权。

### 9.3 巩固与遗忘

| 过程 | 机制 |
|---|---|
| **巩固** | 空闲触发的 `Reasoner`，产出 `memory.consolidated`（压缩 + 反事实） |
| **遗忘** | `memory.forgotten` 事件（不是物理删除；Log 永不删，投影不再包含） |
| **技能编译** | 从成功轨迹产出 `memory.encoded{tag:"skill"}`，后续由 `Decider` 直接命中 |

**必须保留「反自动化回退」**：异常 / 高不确定时退回 `Reasoner` 重新推理。编译后的技能
是一条 `budget_ms` 更小的 ActorSpec，不是另一套机制。

**巩固的接受条件是两条**：形态（`consolidate:max_gen = 3`，防无限推进）与质量
（`consolidate:min_fidelity = 0.7`，防失真固化）。只有形态约束时，系统会产出「代数合规
但已经失真」的记忆——这是静默失效。

**保真度与源比，不与上一代比**：`similarity(new, gen0_source)`。逐代比较会掩盖累积漂移
——每代只差一点，三代之后早已面目全非而单步都「合格」。**平凡值 `min_fidelity = 0.0`
必须完全退化为「只有 `max_gen`」**（J2）。

## 10. 时延分层 = `budget_ms` 参数

| 层 | 预算 | 是否允许模型 | 对应人类通路 | 典型 Actor |
|---|---|---|---|---|
| **反射** | **≤ 80 ms** | 否（纯规则 / 查表） | 脊髓反射 20–50 ms | Decider |
| **快速** | ~300 ms | 是，但**只允许分类不允许生成** | 视觉简单反应 150–250 ms | Translator / 小模型 |
| **深度** | 秒–分钟 | 是（完整规划 + 工具） | 复杂决策 > 1000 ms | Reasoner |
| **自主** | 小时–天 | 是（常驻、事件驱动） | — | Reasoner（常驻） |

**四条关键语义**：

1. **判据是时延，不是形式。** 一个 10 ms 的本地查表不受「发言路径不得阻塞」的限制。
2. **禁止静默超时。** 到点必须产出：正常事件或 `chat.assistant.fallback`。
3. **四层不是四套架构**，是同一个 `ActorSpec` 的四组 `budget_ms` 取值。
4. **档位是事前闸门**（§4.1）。反射档结构上拿不到模型句柄，所以「超时」不是被检测到，
   而是不可能发生。

**快通道的成本核心**：做的是**分类**（直答 / 派活 / 反问 / 拒绝 四选一），不是生成。
分类比生成便宜一个数量级，这才让 300 ms 预算成立。

## 11. 确定性三级

| 级 | 定义 | 是否成立 | 代价 |
|---|---|---|---|
| **L0 投影确定性** | 同一事件序列 → 投影结果逐字节相同 | **恒成立**（纯函数保证） | 无 |
| **L1 记录可重放** | LLM 输出作为事件落盘后，重放 = 读回记录 | **成立** | 存储 |
| **L2 重执行一致** | 仅靠 `policy_ref` + 输入重建 | **不成立**（采样非确定） | — |

**本方案只承诺 L0 + L1，并明确声明不使用 L2。** 这对下游意味着：

| 场景 | 依赖级别 | 说明 |
|---|---|---|
| 状态回放、崩溃恢复、审计 | L0 | 免费 |
| 评测对比、A/B、回归 | L0（+L1 若需复现 LLM 判定） | 需落盘 LLM 输出 |
| 「换个模型重跑一遍看效果」 | **不支持** | 这是重执行，不是重放；应走离线评测 |

**诚实表述**：L2 不是「以后会支持」，是**原理上不成立**。

## 12. 多主体与对等协作

### 12.1 隔离

| 维度 | 机制 |
|---|---|
| 身份 | `Principal`（事件上的 `actor` 字段） |
| 归属链 | `root_task_id` + `produced_by` |
| 可见域 | `VisScope` + `sees_of / can_see` |
| 权限 | `grants_of / can_write`（6 个能力封顶） |

**主体之间的消息必须进 Log**。20 轮对话就是 20 条事件（存储便宜），但上下文不是 20 条
——投影按预算折叠。**判据只有一条：这条消息跨越了主体边界吗？** 是 → 进 Log，没有例外。
为此开旁路 = I1 静默失效。

### 12.2 对等协作：递归是树，覆盖不了的图

递归是**树**（主从），对等协作是**图**。以下不能由递归表达：

| 能力 | 机制 | 参数 / 事件 |
|---|---|---|
| 对等协商 | 双方不从属，共同达成一致 | `commitment.offered` / `.asserted` |
| 跨体承诺 | 「我答应你」如何被对方验证 | `commitment.asserted` + 对方 Log 引用 |
| 可撤销的承诺 | 已发出的承诺如何协商撤回 | `commitment.released` / `.broken` |
| 声誉与互信 | 基于历史交互判断可靠性 | `Reputation` 投影（从事件派生） |
| 传递性信任 | A 信 B，B 信 C，A 是否信 C | `Recall` / `Reputation` 的深度参数 |
| 共同目标与分工 | 多个独立主体自发组织 | `commitment` + `scope` |
| 冲突与仲裁 | 目标冲突时的裁决 | 一个 `Decider` 模式 Actor |

**全部落在事件网格与参数表内**：加两个实体（`memory`、`commitment`）与两个投影
（`reputation`、`calibration`），没有一个是新机制。

### 12.3 Agent 的组织形态

**一个 Agent = 一个目录；目录里有什么，它就会什么。**

| 维度 | 形态 |
|---|---|
| 单元 | Agent 目录（不是包格式） |
| 技能 | 目录下的 `skill/` 插件实例，复用宿主已有的技能系统 |
| 工具 | 目录下的 `mcp/` 插件实例，复用宿主已有的 MCP 客户端 |
| 人格与记忆 | 根目录 `AGENTS.md`，由托管该目录的宿主插件解释 |
| 装配 | 宿主用同一个插件容器装配系统 Agent 与子 Agent |

**同构**：

```text
系统 Agent = 系统根 ← 由插件容器装配
子 Agent   = 系统根/agent/<id> ← 由同一个插件容器装配
```

两者的内部结构完全相同：一层目录 = 一个插件，配置与数据同处。差别只有两处：
**谁托管它**（系统 Agent 由宿主直接装配；子 Agent 由 Agent 插件托管），以及
**插件清单多少**（子 Agent 只挂 `mcp` / `skill` 等认知能力插件，不挂会话编排、模型网关、
宿主基础设施）。由此得到一条实用推论：**任何能装进子 Agent 的东西，都能装进系统 Agent；
反之亦然。**

**并集，不是替换**：会话绑定某个 Agent 时，系统 Agent 与子 Agent 双方的能力都生效。
并集以命名空间隔离为前提——提示词段加来源标记，同名工具必须消歧或拒绝加载，
VDFS 挂载点按来源分层。装配顺序不得被依赖。

**一个作用域只有一个所有者**：同一个 `AGENTS.md` 不得被两个所有者同时拥有。注入该文件
的、提供可编辑地址的、执行容量闸门的，必须是同一个所有者。系统 Agent 与每个子 Agent
各有一份文件、各是一个作用域，不得用一份文件兼任。宿主必须把它注入系统提示词，
且注入内容与文件一致，不得改写。

**能力插件的边界**：目录里的插件若构造失败，是软故障（记诊断并跳过）；`manifest` 缺失
或校验失败是硬错误（拒绝加载整个 Agent）。`manifest` 只承载无法从目录推导的信息：
身份、兼容性门槛、权限声明；能力由目录承载，不在 `manifest` 里重复登记。

**权限声明**：`manifest` 的网络域名、文件系统 glob、资源限额是**声明**，不是安全边界。
把包设计成「只申请了读 `/data` 所以写不进去」会落空。四个字段的执行方与反向用例见
[DE-011-Agent目录规范](011-Agent目录规范.md "DE-011-Agent目录规范") 的 D-153。

| 位置 | 为什么必须读/写残留格 |
|---|---|
| `model/types.rs`、`adapters/provider_adapter.rs` | `NativeMessage.role` 是协议/线格式的形状，节点不落库；身份由落库点补 |

| `chat_node.test.rs` / `subagent.test.rs` 的存量夹具 | 判据本身就是「主体缺席时残留格兜底」，必须真的摆出那一格 |

- 「测例夹具全量迁到 `principal`」——按面归位：模仿落库面 / 流式面的夹具写主体，

### D-169 工作目录的变更账是 `artifact.added` 的一条投影，不新立 `file` 实体

[DE-020](020-前端UI-UX.md "DE-020-前端UI-UX") P2-2 要一份「本会话改了哪些文件」的可回读清单。曾拟在网格里加一行
`file`（`file.opened` / `file.asserted` / `file.closed`，载荷 `{path, bytes}`），由 VDFS 写侧落事实。
**否决**：那不是一条事实，而是**第二份写点**——工作目录的真实内容由文件系统持有，任何「文件变了」
的登记都只是它的影子；影子与本体之间没有机制能强制一致，而不一致时两边都能自证正确。

准入三问在这一案上的答案：

- **能归入已有实体？** 能。变更的来源是一次工具调用，`artifact.added` 已经逐笔记下 `tool`、
  定稿参数 `args`（含 `path`）、`success` 与 `produced_by`（本轮用户格）。清单从这些事实折出来，
  不需要新写点。
- **能归入已有动词？** 「现在是这个」在 `file.asserted` 之外还有一个更诚实的答案：**没人写下过它**。
  写侧根本不在 VDFS 手上：agent 的 `vdfs_*` 工具走 `UnifiedFs → PhysicalFs`，不经过
  `SessionPlugin::workdir_at`；shell / MCP / 操作系统的写入完全不经过 VDFS；唯一完整的观察者
  `FsWatcher` 只在界面订阅工作目录时启动，且拿不到可靠的轮归属。在这三条路径之外再竖一个写点，
  只会记下「经由某条特定路径的变更」，并把「不完整」伪装成「完整」。
- **消费方对未知值安全？** 这条不构成支持——它只说明加载荷不会炸，不说明载荷可信。

决策：

1. **事实 owner 不动**：`artifact.added` 是工具输出的唯一登记处。新增
   `workdir_changes(&[Event]) -> Vec<FileChange>` 是一条纯投影（住哪由消费方分布定，
   现居会话插件的 `projections/`，见 RE-009 §3），按「每路径最新一条
   胜出」折出 `{path, op, turn, changes}`；只认 `success = true`、工具属于写族
   （`vdfs_write` / `vdfs_edit` / `vdfs_delete` / `vdfs_mkdir`）、参数能解析出工作目录内相对路径
   的记录；虚拟根（`AddrRootDecl` 声明的挂载名）下的路径与界外绝对路径不计入。
2. **读侧一个只读路由** `session/changes`，与 `session/stats` 同构：下发的行已经**呈现就绪**
   （`{path, address, op, label, turn, changes}`），前端不解析 `args`、不认识工具名——
   业务词汇只存在于后端一处。
3. **边界写在这里**：面只覆盖「本会话的智能体工具改了哪些文件」。用户编辑器保存、shell / MCP /
   其它进程的写入留在实时面（`FsWatcher` → `VdfsChange`），不入账——它们没有可溯源的轮归属。
   清单**不承诺重建旧内容**：`artifact.added` 不带写入前全文，所以面板打开的是**当前**文件；
   「看 diff」需要另一条事实（写入前内容），不在本条决策内。

网格因此维持 11 行。**被否决的候选**：

- 「用 `FsWatcher` 落事实」——它没有轮归属，且可用性由界面订阅决定；拿它当权威会让清单随
  「有没有打开页面」而变。
- 「在 `artifact.added` 之外加 `file.*`，两者互校」——两份可能不一致的登记不是互校，是让每个
  消费方自行选择信哪一份。

### D-171 钱在 **adapter 边界**折好：整数纳单位、按币种分桶，投影与前端都不算价

[DE-020](020-前端UI-UX.md "DE-020-前端UI-UX") P2-4 要「这次往返花了多少钱」可读回来。
token 那一半没有争议（`LlmTurn.usage` 是实测值，投影只做累加）；**钱不是实测值，是价格 × 用量**，
而价格是**配置**。于是本案真正要裁的只有一件事：**折算发生在哪一侧**。

**裁决：在 `crates/symbio-plugin-model/src/bound_provider.rs` 的成功臂折**——那里同时握着用户配的
`ModelProviderConfig.pricing` 与模型报回的 `ModelUsage`，折完得到一个**事实**
（`ModelSpend { amount_nano, currency }`），随 `TurnOutput.spend` → `LlmTurn.spend` 落进
`response{port=model}` 载荷的 `spend` 键。此后每一层（投影、读数列、界面）都只是**搬运与排版**。

为什么不往后放：

- **投影里折价 = 把配置读进纯函数**。投影的输入只有事件流；让它去拿价格表，等于同一个 WAL
  在两个时刻折出两个账面数——用户中途改价，**历史花费跟着变**。而花费恰恰是拿来对账的。
  入格的必须是「当时按当时单价算出来的数」，不是「现在按现在单价重算的数」。
- **前端按模型名猜单价 = 界面替用户拍一个他没同意过的价**。本仓的多供应商是常态（自建端点、
  同名不同价），猜出来的数字看起来和对账单一样危险。
- **不新立一条事实**：钱是这一次往返的属性，`response` 载荷装得下它。第二处写点必然带来
  「哪个是真的」这个问题（同 D-169）。

三条口径随本案一起立，都在同一处实现：

1. **整数纳单位**（nano = 1e-6 货币单位，`u64`）。浮点累加会漂，而账单不允许漂；单价仍按
   人读的「每百万 token」填，折算时一次乘除。格式化只在 `format_money` 一处（单位与精度一张表，
   与 `format_tokens` 同族）。
2. **按币种分桶、桶内按主体累计**（`spend_ledger`：`by_currency` → `{currency, amount_nano, charges, by_principal}`）。
   **不同币种永不相加**——没有汇率，也没有「折成美元」这种擅自换算。
3. **「没定价」与「明确免费」是两个状态**：前者载荷里**没有** `spend` 键（面板不出花费行），
   后者 `charges > 0` 而 `amount_nano == 0`（出「0.00」行）。写侧靠
   `ModelPlugin::normalize_pricing` 兑现这条区分：计价表单交回空对象 = 没配置（`pricing: None`），
   填了单价却没填币种直接拒绝——否则一次「清空表单」会被记成「这轮免费」，读侧再也分不出来。

三本账因此分立，谁也不替谁：`cost_ledger` 是**时延**（`cost_ms` 按 actor）、`token_ledger` 是
**token**（按内容的 `principal`）、`spend_ledger` 是**钱**（按币种再按主体）。名字上
「cost」已经被时延占了，所以金额那本叫 spend 而不是第二个 cost——**同一份账有两个名字比没有名字更难查**。

### D-173 重试留下的是「并存几支 + 一个选中态」：**读法**入格，历史不删

[DE-020](020-前端UI-UX.md "DE-020-前端UI-UX") P2-5 要「同一问题的几个候选可切换且不重挂载会话」，
而它的前件不是 UI 顺序，是一条事实面的裁决。此前重试是**删除式**重跑
（`chat_loop/wake.rs` 的 `WakeOutcome::NewTurn`：删掉失败轮的消息，按普通新轮重来），日志上因此
不产生第二支——树上没有第二个孩子，界面就没有候选可切。

**裁决：重试 = 同一 parent 下并存几支，「此刻读哪一支」是一条事实。**

为什么不是「替换但留档」：投影是纯函数（`rebuild(events) -> Vec<ChatNode>`），「用户现在看的是
哪一支」是**读法**而不是存储位置。留档方案要么真的删掉旧轮（那还是删除式：用户改主意时，代价是
上下文已经被砍过一刀），要么留着但让投影自己猜「哪条算新的」——那就是在事实面之外多一个默认值，
同一个 WAL 在两个时刻能读出两棵树。

三条口径随本案一起立：

1. **两条事实，都进格**：`turn.branch{of,into}` 说「这一支存在」，`turn.branch_selected{selected}`
   说「此刻读这一支」。二者都是 `(Turn, Asserted)`——落 `asserted` 的一半理由是 I2（断言类事实必须
   带非空 `produced_by`），分支的溯源锚就是触发它的那条格。**组的键是成员根的节点 id，不是轮号**：
   一支的边界由呈现档决定（`flat` 档把轮骨架的孩子升成根），按轮号键会把同一个组读成两组。
2. **「读哪一支」由这两类事实共同说，组内后到的胜出**。重试本身隐含「读新支」，所以 `turn.branch`
   也写组的选择——不必为每条新支补一条 `branch_selected`。**被否决的过渡形态**：「只有
   `branch_selected` 写选择、缺省读旧支」，那等于把「刚重试出来的那一支看不见」定成默认行为，
   而看不见的新支对用户不存在，重试就还是替换式，只是多留了一份没人读的历史。
3. **「看不见」≠「不存在」**。切换只落一条 `turn.branch_selected`，不删任何消息（`message.removed`
   是另一件事，另有自己的入口）。藏只发生在**给模型的那一份**上。**给模型的对话只有一处来源**
   ——事实网格的转写投影；另有一处同源的节点树读侧（`get_context_messages`）也按同一份折法藏，
   因为它喂的是水位、批次边界汇报与本幕的输入装配，那些东西若还带着被换掉的那一支，量出来的
   就不是这一轮真正会发出去的那一体。两处认**同一份折法**
   （`projection::branch::marks` → `unselected_roots` / `stamp_branches`）：
   - 请求包 = 事实网格的转写投影（`projection::transcript`）：未选中支的助手侧条目照样进转写
     （`TranscriptView` 的 `entries`），只是标成不进 `to_messages()`；双向复核（`prompt_fidelity`）
     跟着同一份折法跳读，否则重试过的会话每轮都报一串假「丢事实」——恒红的判据等于没有判据。
   - 节点树 = `get_context_messages`（`branch_hide_unselected`，排在 `drop_orphan_messages` 之前）：
     它喂的是水位、批次边界汇报与本幕的输入装配，**不是** prompt。
   两处的判据都**先有读法、再谈藏**：读法由事实折出，不由「那一支有没有节点」决定——重试那一幕在
   备输入那一步只落了分支格，新支的 Turn 根那时还没有任何节点，按「有没有节点」问就等于没换支。
   呈现读侧一条不丢（`get_messages` 永远交全树）。否则「切回去」没有东西可切，而事实面上那一支
   已经消失了——界面骗人，日志也跟着骗。
4. **这条读法只管对话那一段，不管请求级前缀**。长期记忆召回段与委派真源段是**另一条路**进来的
   （`turn_runner` 的 `prefix`），而 `memory.encoded` 的载荷说不出这条记忆产自哪一支——它只锚到
   那一轮的用户格。于是「切走一支之后，那一支产出的记忆仍被召回」不归本案管，缺件与边界登记在
   [DE-036-长期记忆与语义检索](036-长期记忆与语义检索.md "DE-036-长期记忆与语义检索") §8。

**子树同一性只有一份实现**：一支的子孙 = `parent_id` ∪ `meta.turn_root`（`flat` 档升根的节点没有
`parent_id`，只按父边收子树会把它们漏在外面，于是模型与界面各读一套）。后端
`symbio_core/node_build::subtree_of`，前端 `dropUnselectedBranches` 同一条口径，跨栈镜像由
`protocol-mirror-audit` D 组守着。

**几个容易放错的位置**：

- **换支的藏在投影，不在轮侧**。`chat_loop` 手里那份 `context.messages` 是节点树，剪它不会影响
  请求包一个字（prompt 由事实网格投影，见口径 3）——判据点名叫「重试了但答案一模一样」时，
  合法动作是去问投影，而不是在主循环里补一刀。
- **实时面补发在轮次收尾，不在落格处**。新支的节点要等本轮消息落盘才进入投影；落 `turn.branch`
  那一刻重建里只有一条现存成员（单支不成组，`meta.branch` 一个字段都不盖）。所以标注帧由
  `chat_loop::finish_turn` 的 `republish_branch_group` 按组重发，读的是 `MESSAGES`（全树）而不是
  `CONTEXT_MESSAGES`（已藏掉未选中支的那一份）。
- **切换的入口是成员根节点自身**：`<sid>/message/<mid>` 上的 `switch_branch`（载荷 `{to}`），与
  `truncate` / `expand_skeleton` 同一个位置——「对这条消息做点什么」的地址就是它自己。它不开轮、
  不产生消息，因此**不进** `ResumeAction` 的词表，必须排在恢复那臂 catch-all 之前；目标不是同组
  兄弟一律 `Invalid`（切到别人的分支组 = 改写了另一个问题的读法，那不是「没生效」而是做错了事）。
