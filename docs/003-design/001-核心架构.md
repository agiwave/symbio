# 核心架构：原语、Store、Projection、Actor

> 本文件只描述**系统里存在什么**。演进纪律见 [DE-016](016-工程落地与验证.md "DE-016-工程落地与验证")，能力坐标系见 [DE-008](008-能力注册表与能力坐标系.md "DE-008-能力注册表与能力坐标系")。
> 三条判据 J1/J2/J3 的定义见 [docs/003-design/README](002-架构总览.md "DE-002-架构总览")，本文只写它们在各处的应用。

---

## 0. 存在什么

> **1 个原语 + 1 个签名约束 + 1 个使用者概念 + 3 条不变量 + N 行参数数据。**

```
 用户消息 / 定时 / 系统信号
 │
 ▼
 ┌──────────────────────────────┐
 │ Store （唯一原语） │
 │ append(e) → Seq append-only │◄──── Actor 的写入
 │ range(from) → &[Event] │
 └──────────────┬───────────────┘
 │ &[Event]
 ▼
 ┌──────────────────────────────┐
 │ Projection （签名约束，非机制） │
 │ (&[E], Timestamp, Budget) │
 │ → View{value, degraded} │
 └──────────────┬───────────────┘
 │ View
 ▼
 ┌──────────────────────────────┐
 │ Actor （一等概念，非原语） │
 │ Decider │ Reasoner │ Translator│
 │ = 一行 ActorSpec 数据 │
 └──────────────────────────────┘
```

<!-- list:core-elements owner -->
| 元素 | 性质 | 数量 | 随场景增长吗 |
|---|---|:-:|---|
| **Store** | 原语（trait，有方法、有不变量、可编译强制） | 1 | 否 |
| **Projection** | 签名约束（1 个**泛型形状受限**的薄包装类型，无 trait、无注册、无 impl 扩展；`new` 是 `pub`，强制来自泛型边界而非可见性） | 1 类型 | 否 |
| **Actor** | 一等概念（3 种模式 = 配置） | 3 模式 | 否 |
| **不变量** | I1 单通道 / I2 无溯源不声明 / I3 到点必答 | 3 | 否 |
| **参数数据** | 事件格子、ActorSpec 行、grants 行、视图定义 | N | **是**（这是唯一允许增长的东西） |

## 1. 为什么只有 1 个原语（诚实版）

> 这里有一个常见陷阱：把“下界”写成一个数字，却用硬编码的返回值冒充推导。
> 因此本节把**计算得出的部分**与**属于选择的部分**分开列（§1.6）。

### 1.1 三个职责与冲突矩阵

任何智能体系统都必须有三件事。每个职责带一组**带极性的约束**（`要求` / `禁止`）：

| 职责 | 含义 | 约束 |
|---|---|---|
| **Hold** | 事实的持有 + 唯一写入口 | 要求 `write_gate_exclusive`；禁止 `direct_write` |
| **Derive** | 从事件序列纯派生视图 | 禁止 `side_effect`；禁止 `nondeterminism` |
| **Act** | 读事实、产生新事实（调 LLM、有副作用） | 要求 `direct_write`；要求 `side_effect` |

**唯一判据**：同一性质的极性相反 → 不可合并。

### 1.2 分组结果（由程序计算，非硬编码）

`verify/lower_bound.rs` 实测输出：

```
Hold ⊕ Derive → 可合并
Hold ⊕ Act → 不可合并（direct_write：Hold 禁止 / Act 要求）
Derive ⊕ Act → 不可合并（side_effect：Derive 禁止 / Act 要求）

分组 1：{Hold, Derive} 分组 2：{Act}
不可再分分组数 = 2
```

### 1.3 Act 是使用者，不是构成者

`{Hold, Derive}` 与 `{Act}` 不可合并，只说明它们**必须分开存在**，不说明 `{Act}` 是原语。

```
一个 Actor 在物理上做了什么？
 events = projection(&store.range(from), now, budget) ← 只用 Derive
 decision = 模式内部的决策（规则 / LLM / 转述） ← 这是配置，不是机制
 store.append(new_event) ← 只用 Hold
Actor 自己的状态？无。自己的接口？无。自己的不变量？无。
```

**它是装配线，不是砖。** 因此：

- **若把 Act 计入原语 → 下界 = 2**（即把“行为”也算作“系统由什么构成”）
- **若把 Act 计为"一等概念" → 下界 = 1**（本方案立场）

### 1.4 投影为什么不是原语，也不是 trait

另一种更重的做法是把投影做成 trait（`fold` + `filter` 两个方法）。按 J1 检验，这是多余的：

| 质疑 | 结论 |
|---|---|
| 投影需要动态分派吗？ | 不需要。调用方静态知道自己要哪个视图（`V` 是具体类型） |
| trait 比自由函数更强制吗？ | **不**。trait 的实现照样能持有 `Arc<Clock>`——**trait 只规定"有哪些方法"，不规定"实现里不许干什么"** |
| 少一层抽象有损失吗？ | 无。投影的注册是**命名数据**（一张名字→函数的表），不是类型系统的事 |

**但"不做 trait"不等于"降级成一个裸 `type` 别名"。** 一个裸别名不提供任何强制：
它只说"满足这个形状的函数**可以**当投影用"，不阻止你把别的东西当投影注册进去。
按 J3（静默失效 → 必须做成编译期强制），投影纯度需要**不可伪造的构造入口**：

```rust
/// 投影 = 一族纯函数：字段私有 + 唯一构造入口 `new`，形状即纯净性的全部表达。
pub struct Projection<V> {
 f: Box<dyn Fn(&[Event], Timestamp) -> V + Send + Sync>,
 _p: PhantomData<V>,
}
impl<V: 'static> Projection<V> {
 pub fn new<F>(f: F) -> Self
 where F: Fn(&[Event], Timestamp) -> V + Send + Sync + 'static
 { Projection { f: Box::new(f), _p: PhantomData } }

 /// 降级与预算由框架统一执行（[D-105](001-核心架构.md "D-105")）：超窗只交切片头部，截断 ⇒ `degraded`。
 pub fn apply(&self, ev: &[Event], now: Timestamp, b: Budget) -> View<V> {
 let quota = (b.ms as usize).max(1);
 let window = if ev.len > quota { &ev[..quota] } else { ev };
 View { degraded: window.len < ev.len, used: Budget::new(0, window.len as u64),
 value: (self.f)(window, now) }
 }
}
```

**收益**：少一个 trait、少一层 impl，而**强制性比裸别名更强**——
想写一个带副作用的投影，在构造那一刻就编译不过，而不是等 CI 扫描。

#### 1.4.1 投影纯度的**两级强制**（诚实划界）

强制不是"一级就够"，必须说清哪一级拦住什么：

| 级 | 拦什么 | 靠什么 | 拦不住的 |
|---|---|---|---|
| **一级** | 句柄进不来（`&Store` / `&mut` / `Clock` / `Principal`） | `Projection::new` 的**泛型约束**（编译期） | 闭包体内调用**全局函数**（如 `SystemTime::now`）——它的形参表是合法的 |
| **二级** | 隐式全局依赖（时钟、随机数、全局可变状态）；投影 A 读投影 B（L2）；死构造器 | 门禁静态扫描（[`projection-purity`](../../scripts/projection-purity.mjs)，PP-001…003） | — |

> **一级能拦住"顺手写一笔"，拦不住"偷偷看一眼表"。** 二级不可省。
> 反例（形参表合法但内部读时钟）已写在 `verify/projection_purity.rs` 的
> `should_not_compile` feature 里**并明确标注它编译得过** —— 边界必须被写下来，而不是假装不存在。

**`verify/projection_purity.rs` 实测**：正常编译 8 条断言全绿；反向验证退出码 1，
错误为 `error[E0593]: closure is expected to take 3 arguments, but it takes 4 arguments`
—— **拒绝的理由恰是纯净性形状**，不是被无关约束顺手挡掉。零大小能力令牌 `PureOnly`
（私有构造器 → 不可伪造，`size_of == 0`）用于把"这条链路不写"变成可传递的证明。

### 1.5 记账对照：三种记法，同一个系统

同一套架构至少有三种记法，**它们描述的系统是同一个**：

| 记法 | 原语计数 | 派生怎么记 | 行为怎么记 |
|---|:-:|---|---|
| **A** | **3** | 并入原语 `Process` | 原语之一 |
| **B** | **2** | 独立原语 `Project`（做成 trait） | 一等概念（不算原语） |
| **C（本方案）** | **1 + 1 签名约束** | 泛型形状受限的 `Projection`，不做 trait | 一等概念（不算原语） |

**三者真正的分歧只有一处：行为（Act）算不算原语。** A 说算，B/C 说不算。
B 与 C 的差异更小，只在"派生是做成 trait 还是只做签名约束"。

**选择 B 还是 C，判断标准是那条真实收益**：
> 把派生从容器里独立出来的意义，在于让**确定性 / 无副作用 / 可降级**三条性质
> 从"约定"变成"编译期强制"——这是记法 A 的 `Store::view` 做不到的，也是 A 与 B/C 的实质差距。

**本方案用签名约束（泛型形状受限）拿到了这条收益**（见 §1.4：唯一构造入口 + 一级编译期强制），
所以记作 1 个原语 + 1 条签名约束：**收益一分不减，抽象少一层。**

| 职责 | 本方案的记账 | 为什么 |
|---|---|---|
| 容器 + 写门 | **原语 `Store`** | 有方法、有不变量、可编译强制 |
| 元素类型 | 数据 `Event` | 无方法、无不变量；把它算作原语会高估计数 |
| 派生 | **签名约束（泛型形状受限，非机制）** | 见 §1.4；按 J1，trait 不增加强制力，但**裸别名会丢失强制力** |
| 行为 | **一等概念 `Actor`** | 见 §1.3 |
| **原语计数** | **1**（+ 1 条签名约束） | 若改按记法 B 记账，架构一字不改，只是计数变 2 |
| **机制表条目** | **11**（含 `projection` 与 `projection.param`） | 机制表记的是"系统里有哪些可调的东西"，与原语计数不是同一把尺 |

### 1.6 诚实标注：这一步是选择

| 命题 | 性质 |
|---|---|
| 三个职责不可两两合并（除 H⊕D） | **已证明**（冲突矩阵，`lower_bound.rs`） |
| Act 不是"系统的构成者" | **判断**（依据：它无状态、无接口、无不变量） |
| 投影不做成 trait | **工程选择**（依据：trait 不增加强制力，却增加抽象层） |

**因此本方案的"原语 = 1"是一个立场 + 一个工程选择，不是一个被证明的下界数字。** 若将来有人主张 Act 也算原语，架构一字不改，只是记账从 1 变 2。

## 2. 原语 · Store

```rust
/// 不可伪造的单调序号（newtype，调用方无法自己构造）
pub struct Seq(pub u64);

pub trait Store: Send + Sync {
 type Event: EventEnvelope;

 /// 唯一写入口
 fn append(&self, event: Self::Event) -> Result<Seq, AppendError>;

 /// 读取 [from, head) 的事件区间，返回不可变数据
 fn range(&self, from: Seq) -> Vec<Self::Event>;

 fn head(&self) -> Seq;
}

pub enum AppendError {
 Duplicate, // 幂等去重命中
 Conflict { expected: Seq, actual: Seq },// 并发写冲突
 NotTheWriter, // 违反单写者约束
}
```

| 语义 | 保证 | 违反后果 | 强制方式 |
|---|---|---|---|
| **单写者** | 每 thread 一个 FIFO，串行 | 竞态回归 | 运行时（FIFO）+ CI |
| **单调 seq** | thread 内严格递增、无跳号 | 回放顺序错乱 | 类型（`Seq` newtype）+ 运行时 |
| **append-only** | 接口上无 `update` / `delete` | 事实可被篡改 | **编译期** |
| **幂等** | `event_id` / `idempotency_key` 重复 → `Duplicate` | 重复副作用 | 运行时 |
| **原子** | 单事件要么完整落盘要么不落 | 回放崩溃 | 运行时 |

**实现替换不构成架构改动**：内存 / WAL / 分片 / 加密 / 分布式，全部是 `impl Store`，调用方零改动。
**索引也是实现细节**：向量 / 倒排 / 时间分区 / 混合索引都不进 trait 签名——这是 §9 长期记忆能落地的前提。

## 3. 签名约束 · Projection（泛型形状受限，编译期强制一级）

```rust
/// 字段私有 → 不可伪造；唯一构造入口 → 纯净性由泛型约束强制。详见 §1.4。
pub struct Projection<V> { /* 私有字段 */ }
impl<V: 'static> Projection<V> {
 pub fn new<F>(f: F) -> Self
 where F: Fn(&[Event], Timestamp, Budget) -> View<V> + Send + Sync + 'static;
 pub fn apply(&self, ev: &[Event], now: Timestamp, b: Budget) -> View<V>;
}

pub struct View<V> { pub value: V, pub degraded: bool, pub used: Budget }
pub struct Budget { pub tokens: u32, pub ms: u64 }
```

| 性质 | 断言 | 为什么必须 | 强制方式（**分级**） |
|---|---|---|---|
| **确定性** | 同一事件序列 → 逐字节相同 | 可回放、可对比、可测试 | 二级：单测/CI 双跑比对（签名无法表达"确定性"） |
| **无副作用** | 不调 LLM、不写库、不读时钟 | 否则回放漂移 | **一级：`new` 的泛型约束让句柄进不来**（无 `&Store`/`&mut`/`Clock`）+ 二级：静态扫描查隐式全局依赖 |
| **可降级** | 超预算返回 `degraded: true`，不抛错 | 对话永不因状态爆炸中断 | **一级：构造即锁定返回 `View<V>`（而非 `Result`）** |

> **"一级" = 编译期强制，"二级" = CI 断言。** 分级不是含糊其辞，是诚实划界：
> 一级能拦"句柄进不来"，拦不住"体内调全局函数"（后者形参表合法）。见 §1.4.1。

**视图 = 参数，不是组件。** 系统里的"状态"只有一个来源：

| 视图 | 消费者 | 过滤策略 | 预算 |
|---|---|---|---|
| `Snapshot` | Chat | 合并同任务事件 + 摘要 + 产物引用 | ≤ 1.5k tokens |
| `Display` | 用户 UI | 滤掉系统事件 + 翻译 + 排序 | UI 分页 |
| `ReadySet` | 调度 | 只取终态 + `depends_on` 闭合 | 常数 |
| `TurnState` | 状态机 | 该 turn 的事件 | 常数 |
| `Checkpoint` | 崩溃恢复 | 该 task 全量 + 压缩 | 可序列化 |
| `Recall` | 记忆检索 | 语义/时序/因果混合打分 | 可配置 |
| `Eval` | CI / 评测 | 事件切片 → 断言 | 离线 |

## 4. 一等概念 · Actor（三种模式）

```rust
pub struct ActorSpec {
 pub principal: Principal, // 身份（数据，无限增长）
 pub pattern: Pattern, // 三种模式之一（机制，3 个封顶）
 pub capabilities: Vec<Capability>,// 能力（机制，6 个封顶）
 pub budget_ms: u64, // I3 时延预算
 pub scope: Scope, // 作用域（递归）
}
```

> **`model` 与 `context` 不是独立字段**：`model` 是 `pattern` 的函数（Decider→无、Reasoner→LLM、Translator→小模型），
> `context` 是 `projection` 的参数。按 J1，能由别的东西算出来的就不占字段。**5 个字段，不是一个 12 字段的配置对象。**

| 模式 | 决策来源 | 确定性 | 典型用途 | 预算量级 |
|---|---|---|---|---|
| **Decider** | 规则 / 代码 | 确定 | 意图判定、就绪判定、权限、熔断、仲裁 | 毫秒级 |
| **Reasoner** | LLM | 非确定 | 规划、生成、语义判定、工具调用 | 秒–分钟 |
| **Translator** | 事件 → 另一种表示 | 确定 | 转述、摘要、检索召回、格式转换 | 百毫秒 |

**模式选择的判据函数**（不是清单）：

```
pattern(action) = if 可写成确定性规则 → Decider
 else if 只需重述已有事实 → Translator
 else → Reasoner
```

> **Translator 不创造信息**：它的输出必须能追溯到输入事件，
> 因此它拥有与 `reply` 相同的写权限，**不需要单独的能力**。

### 4.1 时延预算 = **事前闸门**，不是声明 + 事后断言

一个容易停在半路的做法：把 `budget_ms` 当**声明**——Actor 说自己 80ms 内返回，
超了就事后记一笔违规。**这不是预防，是事后取证。**

> 一个 Reasoner 声明 `budget_ms = 80`，但 LLM 实际要 2000ms。
> 系统只能在事后发现"超预算"，然后用 `chat.assistant.fallback` 兜底。
> **兜底是正确的降级，但它不是预防**——用户已经等了 2000ms。

按 J3（静默失效 → 编译期强制），档位必须**约束它能拿到哪一档依赖**，做成**构造期闸门**：

| 档位 | `budget_ms` | 允许模型 | 允许生成 | 注入的依赖句柄 |
|---|:-:|:-:|:-:|---|
| 反射 | 80 | **否** | 否 | 只有 `RuleEngine`（纯规则/查表） |
| 快速 | 300 | 是 | **否** | `Classifier`（输出空间限定四选一） |
| 深度 | 60000 | 是 | 是 | 完整 `LlmClient` + 工具 |
| 自主 | 86400000 | 是 | 是 | 完整 `LlmClient`（常驻） |

实现方式（**零新机制，是 §05 ⑤ `adapters` 包的依赖注入策略**）——零大小能力令牌：

```rust
pub struct RuleOnly { _private: } // 私有字段 → 不可伪造；size_of == 0
pub struct FullModel { _private: }

// 依赖句柄只接受对应令牌 —— 反射档**类型上就拿不到** LlmClient
impl LlmClient { pub fn generate(&self, _t: &FullModel, ...) -> String }
```

**生产形态只有两枚令牌**（详见 [D-096](../../symbio/src/plugins/model/README.md "symbio/src/plugins/model/README")）：
`TokenIssuer::issue_reflex -> RuleOnly` 与 `TokenIssuer::issue_deep -> FullModel`。
「快速档不得生成」不靠第三枚令牌：快速档是 `classify/decide.rs` 的一次受限模型调用，
强制力在**返回类型** `parse_verdict(&str) -> Option<Verdict>`（四变体闭集）与工具集判据上。
生产也没有一个叫 `assemble(tier)` 的装配器——反射档的落地形态是
`loop/turn_runner/reflex.rs::run_reflex`，它的签名**结构上就没有 LLM 字段**；
`assemble(tier)` 只作为可执行论证住在 `verify/latency_gate.rs`。

于是：

> **"反射层不得调模型"不靠自觉、不靠扫描 —— 它编译不过。**

`verify/latency_gate.rs` 实测：正常编译 20+ 条断言全绿；反向验证退出码 1，
错误为 `error[E0277]: the trait bound RuleOnly: CanClassify is not satisfied` 与
`error[E0308]: mismatched types`（快速档拿 `ClassifyOnly` 去调完整 LLM 被拒）。
两枚生产令牌 `size_of` 均为 0 —— **强制零运行时开销**。

**与 I3 的关系**：闸门**不替代** I3，而是把 I3 从"事后检测"升级为"事前不可能"：

| | 没有闸门 | 有闸门 |
|---|---|---|
| 反射层超时 | 调用 2000ms → 事后兜底（用户已等 2s） | **结构上不可能发生** |
| I3 的角色 | 违规检测器 | 兜底契约的**最后一道**保障 |

> **判据始终是时延，不是形式。** 闸门约束的是"这一档能拿到哪类依赖"，
> 不是"能不能调工具"——一个 10ms 的本地查表在反射档完全合法。

### 4.2 「欲」的最小可执行形态（不是分类，是设计）

「欲」最容易停在**分类学**上：把"动机 / 目标生成 / 好奇 / 价值偏好"归成一维，说一句"缺了它不高阶"就结束。
[DE-008 §2.3](008-能力注册表与能力坐标系.md "DE-008-能力注册表与能力坐标系") 已经指出：**「欲」必须落成数据**，并回答三个可执行的子问题。

| 子问题 | 落点 | 性质 |
|---|---|---|
| **E1 欲是什么？** | 一条事件 `conation.expressed`（走 I1 单通道、I2 带溯源） | 事件网格加一行 |
| **E2 欲如何不直接变成行？** | 欲 → `CandidateIntent`（待评估）→ **闸门** → `ApprovedTask` | **不可伪造的批准类型**（字段私有，唯一构造点 `IntentGate::approve`） |
| **E3 欲如何被关停？** | `ConationPolicy.enabled`，**平凡值 = false** | J2：关闭后系统退化为纯响应式且仍完整运行 |

**E2 是「欲」的全部难点。** "想要"直接产生动作，等于绕开治理——所以欲与行之间
**必须有一道编译期闸门**（不是约定、不是 CI 断言）：

```rust
/// 欲只产出候选意图；字段私有 ⇒ 模块外造不出，唯一构造点是闸门。
pub struct ApprovedTask { from_seq: u64, goal: String }

/// 唯一构造点：关停开关 → 授权（`define.work`）→ 目标宽度。
pub fn approve(c: &mut CandidateIntent, policy: &ConationPolicy,
 grants: &EffectiveMatrix, principal: &str)
 -> Result<ApprovedTask, &'static str>;
```

强制力来自**类型的可见性**而非一枚令牌：令牌若由不做任何检查的同点函数签发就只是
一层壳（[D-104](008-能力注册表与能力坐标系.md "DE-008-能力注册表与能力坐标系") 的裁决）。三道治理各自落在能判它的地方、
没有一道被绕过——**授权**在闸内判（与任务表写侧闸同一把尺 `can_write ▸ define.work`）、
**预算**在动作面判（§4 熔断闸对真实调用计费）、**审计**由事实流承担（`task.opened` 带
`produced_by` 指回那条欲事件）；升格本身不花预算，也不产生第二条写入通道。

同一类「不可伪造类型 / 令牌」模式在 §1.4 的 `PureOnly` 与 §4.1 的
时延闸里各用过一次——模式可复用，但**没有可判的检查时不再多造一个元素**。

> **「欲」解决的是"欲如何被治理"，不是"欲从哪来"。**
> 后者是价值对齐问题，架构只保证"想要的都留痕、都必须过闸、都可关停"。
> `verify/conation_minimal.rs` 实测：4 项「欲」能力全部落在**已有机制键的新取值**上
> （`event.entity=conation`、`projection=conation`），**新增机制键 = 0**；
> 关闭 `enabled` 后 `approve` 返回 `Err("conation disabled")`，系统其余部分完好。

## 5. 三条不变量

| | 不变量 | 生成的推论 | 可执行判据 |
|---|---|---|---|
| **I1** | **单通道** —— 一切状态变更只有一个入口，一切协作只经事实源 | final 发言唯一；任意两主体无直连；投影拿不到写口 | `seq` 严格单调 · `≤1 final/turn` · 静态扫描无主体直连 · `projection` 签名无 `&Store` |
| **I2** | **无溯源不声明** —— 任何声称都必须能追溯到产生它的事件 | `produced_by` 不悬空；产出者不自验；兜底话术也是事件 | 断言类事件的 `produced_by` 非空**且不悬空** |
| **I3** | **到点必答** —— 发言路径上的 Actor 必须在预算内产出，或产出兜底事件 | 反射/快速/深度/自主四层；**禁止静默超时** | `cost_ms ≤ budget_ms`，否则必须存在 fallback 事件 |

**I3 是最容易被漏掉的一条。** 缺了它，"对话"这个基础能力就没有架构级保障，只剩工程优化。

**I2 的落地落点**：字段与覆盖检查都已在（`Event.produced_by` / `provenance_violation`），缺的是「不查指向谁」——`Some(999)` 照样绿；补法见 [DE-015 §4.1](015-义务环.md "DE-015-义务环")，本节判据不变。

`verify/invariants.rs` 实测（6 条事件健康日志 → 0 违规；注入 4 类违规 → 4 条全部捕获）：

```
I1SeqNotMonotonic { seq: 4, prev: 6 }
I1DoubleFinal { turn: 1 }
I2NoProvenance { seq: 8 }
I3BudgetExceeded { seq: 9, cost_ms: 5000, budget: 1500 }
```

**J3 的应用**：三条不变量里，"单通道"和"无溯源"违反时**不产生任何错误信号**（违反时没有任何测试会失败），
所以它们必须做成 CI 断言，不能靠自觉。

> 加粗的三行（`memory`、`commitment`、`conation`）分别服务长期记忆（§9）、对等协作（§12）
> 与「欲」的最小可执行形态（[§4.2](#42-欲的最小可执行形态不是分类是设计)）。
> 三者都是**加格子**，不是加机制——按 J1 通过。
>
> **`conation` 的四个格子对应「欲」的三个可执行子问题**（见 §4.2）：
> `expressed` = "想要"成为可审计的事实（I1 + I2）；
> `evaluated` + `gated` = 欲**不能直接变成行**的那道闸门（ZST 令牌，编译期强制）；
> `dropped` = 关闭「欲」后的平凡路径（J2）。**注意这里没有 `conation.acted` 这一格** ——
> 「欲」永远不直接产出动作，它只能产出**候选意图**，由 `task` 实体承接——这正是闸门的语义。
>

**新增事件的准入三问**（缺一不可）：能归入已有实体？能归入已有动词？消费方对未知值安全（`switch` 有 `default`）？

**这张表是语法的闭集，不是事件的闭集**：**加行 = 预期演进**（枚举 + 本表 + §8 三处同批，`DC-005` 断言行数
= 枚举变体数）；**加行后无人写或无人读 = 定错信号**，删行回到闭集、不留占位。`doc-count-audit` 每次打印
`实体 × 动词 = 55 格，已填 N 格`，膨胀可被趋势读出。

**`chat.assistant.fallback` 也是网格里的一格** —— 兜底话术不是特殊通道，它是一条普通事件，可被 I2 审计、可被元认知统计。

## 7. 三个正交维度：身份 / 能力 / 模式

| 维度 | 回答 | 形态 | 随场景增长 |
|---|---|---|---|
| **身份 `Principal`** | 谁 | 字符串 ID | **是（数据）** |
| **能力 `Capability`** | 有权做什么 | 枚举，权限矩阵的键 | **否（6 个封顶）** |
| **模式 `Pattern`** | 怎么做事 | `decider` / `reasoner` / `translator` | **否（3 个）** |

```rust
// 能力：按「权威动作的种类」划分，不按「有多少个智能体」划分
pub enum Capability {
 JudgeIntent, Reply, DefineWork,
 ProduceArtifact, AssertVerification, AssignWork,
}
```

**授权必须成对**：

| 侧 | 函数 | 缺失后果 |
|---|---|---|
| 写侧 | `grants_of(p) → can_write(cap, type)` | 只有读侧 = 能给自己授权看一切 |
| 读侧 | `sees_of(p) → can_see(scope)` | 只有写侧 = 看得到一切 |

**为什么权限必须第零天就位**：它是**静默失效**的——违反时没有测试会失败（J3）。事后补，代价是重写所有历史事件。

**机制数 = 10（顶层键），恒定。** 场景数从 1 增长到 20，用到的机制种类从 5 增长到 9——**增长的是"启用了哪些已有参数"，不是"发明了多少机制"**。

> **`conation`（「欲」）落在已有键的新取值上**：`event.entity=conation`、`projection=conation`、

> 按 J1 通过：欲不需要新原语、新模块、新 trait（见 §4.2）。**新增机制键 = 0。**

## 9. 长期记忆：视图 + 检索

> 一个容易停在半路的论证是：“相似检索不需要新原语（索引是 Store 实现、embedding 是元素类型）”——**这是放置论证，不是设计**。
> 结果 T3「能记住」落不了地，而它是 T4–T8 的前提。本节把它做成可落地的。

### 9.1 五类记忆 = 五个投影参数，不是五套存储

| 记忆 | 投影参数（`Recall` 视图的取值） | 保留策略 |
|---|---|---|
| 工作记忆 | `since(now-5min)` + 容量 4（Cowan 2001: 4±1 组块） | 窗口 |
| 情景记忆 | 全量按时间 | 冷层 |
| 语义记忆 | `tagged("semantic")` | 常驻 |
| 程序记忆 | `tagged("skill")` | 常驻 |
| 预测 | `tagged("prediction")` | 短 |

**"记忆类型"不是枚举，是过滤函数的参数**——加第六类记忆只需加一组参数，不动类型系统（J1）。

### 9.2 三件事各自的位置

| 事物 | 位置 | 为什么 |
|---|---|---|
| **embedding** | 一条普通事件 `memory.encoded{payload: vec}` | 它是事实，不是特殊类型 |
| **索引**（向量/倒排/时间分区/混合） | `Store` 的实现细节 | 不进 trait 签名，替换零改动 |
| **检索** | 一个 `Translator` 模式 Actor，产出 `memory.recalled` 事件 | 检索是"读视图 → 产出事实"，符合 Actor 定义 |
| **检索质量（recall@k）** | `verify/recall_eval.rs`（口径与用例见 DE-016；`#[path]` 包含生产排序内核 `projection/recall_score.rs`，出生产投影的数） | 「存了但找不到」要有一个**可复现的数字**，而不是修辞 |

**检索的可见性受 `VisScope` 约束**——A 的记忆默认对 B 不可见，跨主体记忆共享是一次显式授权（写一行 grants）。——A 的记忆默认对 B 不可见，跨主体记忆共享是一次显式授权（写一行 grants）。

### 9.3 巩固与遗忘

| 过程 | 机制 |
|---|---|
| **巩固** | 空闲触发的 `Reasoner`，产出 `memory.consolidated`（压缩 + 反事实，不是逐帧回放） |
| **遗忘** | `memory.forgotten` 事件（不是物理删除；Log 永不删，只是投影不再包含） |
| **技能编译** | 从成功轨迹产出 `memory.encoded{tag:"skill"}`，后续由 `Decider` 直接命中，不再走 LLM |

> **必须保留"反自动化回退"**（Beilock & Carr 2001 *choking under pressure*）：异常 / 高不确定时退回 `Reasoner` 重新推理。
> 编译后的技能是一条 `budget_ms` 更小的 ActorSpec，**不是另一套机制**。

**巩固的接受条件是两条，不是一条**（形态 + 质量）：

| 约束 | 参数 | 性质 | 拒收时的行为 |
|---|---|---|---|
| **形态** | `consolidate:max_gen = 3` | 代数上界（防无限推进） | 拒收 `RejectedMaxGen` |
| **质量** | `consolidate:min_fidelity = 0.7` | 保真度下界（防失真固化） | 拒收 `RejectedLowFidelity` |

**为什么必须有质量约束**：只写 `max_gen` 时，系统会产出"代数合规但已经失真"的记忆——
巩固满 3 代，代数是合规的，可那条记忆与源已经不像了。这是**静默失效**（J3）：
代数悄悄爬升、信息悄悄塌陷，两者都不报错。

**保真度的度量口径**（决定这条约束是否可执行）：

1. **与源比，不与上一代比。** `similarity(new, gen0_source)`，而不是 `similarity(new, prev)`。
 逐代比较会掩盖累积漂移——每代只差一点，三代之后早已面目全非而单步都"合格"。
 这正是业界经验法则"≥3 跳必须从源重推"的落地形式。
2. **双失效模式都算。** 归因抹除（维度丢失 → 方向改变）+ 数值精度损失（量化 → 幅度改变）。
3. **平凡值 `min_fidelity = 0.0` 必须完全退化为"只有 `max_gen`"**（J2）。

`verify/consolidation_fidelity.rs` 实测断言（含 3 条反向用例 + 1 条平凡值用例）：

```
只给 max_gen：gen 0→5 保真度 1.00 → 0.80 → 0.62 → 0.51 → 0.41 → 0.38 ← 形态合规，信息已失真
加 min_fidelity=0.7：停在 gen 1（保真度 0.80 ≥ 0.7）
 min_fidelity=0.9 → 0 代 | 0.7 → 1 代 | 0.5 → 3 代 | 0.3 → 10 代（阈值确实在算）
 min_fidelity=0.0 → 5 代 = 纯 max_gen 行为（J2 平凡值）
拒收理由可区分：RejectedLowFidelity{fidelity, min_fidelity} ≠ RejectedMaxGen{gen, max_gen}
```

**读法**：`max_gen` 保证"不无限跑"，`min_fidelity` 保证"跑到还有用为止"。
它们约束的是**不同性质的东西**——前者是形态，后者是质量。
加固后，"最多巩固 3 次"变成"**巩固到信息失真为止**"，后者更接近生物记忆的真实机制。

## 10. 时延分层 = `budget_ms` 参数（一等契约）

| 层 | 预算 | 是否允许模型 | 对应人类通路 | 典型 Actor |
|---|---|---|---|---|
| **反射** | **≤ 80 ms** | 否（纯规则/查表） | 脊髓反射 20–50 ms | Decider |
| **快速** | ~300 ms | 是，但**只允许分类不允许生成** | 视觉简单反应 150–250 ms | Translator / 小模型 |
| **深度** | 秒–分钟 | 是（完整规划 + 工具） | 复杂决策 > 1000 ms | Reasoner |
| **自主** | 小时–天 | 是（常驻、事件驱动） | — | Reasoner（常驻） |

`verify/budget.rs` 实测断言：四层预算严格递增、反射层 ≤80ms 且禁止模型调用、超时必须产出 `Fallback`。

**四条关键语义**：

1. **判据是时延，不是形式。** 一个 10 ms 的本地查表不受"发言路径不得阻塞"的限制——约束的是 `budget_ms`，不是"工具"这个名词。
2. **禁止静默超时。** 到点必须产出：正常事件或 `chat.assistant.fallback`。两者都是网格里的一格，都可被审计。
3. **四层不是四套架构**，是同一个 `ActorSpec` 的四组 `budget_ms` 取值 + 一个模型依赖。
4. **档位是事前闸门，不只是声明**（见 §4.1）。反射档**结构上**拿不到 `Classifier` / `LlmClient`，
 所以"超时"在这个档位不是"被检测到"，而是**不可能发生**。`verify/latency_gate.rs` 实测。

> **快通道的成本核心**：做的是**分类**（直答 / 派活 / 反问 / 拒绝 四选一），不是生成。
> 分类比生成便宜一个数量级，这才让 300 ms 预算成立。
> **而"只允许分类"由令牌类型强制**（`ClassifyOnly` 不满足 `CanGenerate`），不靠 prompt 里写一句"请不要生成"。

## 11. 确定性三级

> 一个极易出现的自相矛盾：一边把“从 seq=0 重放，结果完全一致”当作核心验收项，一边又说“LLM 原始响应不持久化、由 `policy_ref` 重建”。
> 这两句话不可能同时为真——`policy_ref` 只记录身份，不消除采样非确定性（若设计里从不出现 `temperature` / `seed`，这个矛盾就会被藏起来）。

**把"重放一致"拆成三级，各自适用不同场景**：

| 级 | 定义 | 是否成立 | 代价 |
|---|---|---|---|
| **L0 投影确定性** | 同一事件序列 → 投影结果逐字节相同 | **恒成立**（纯函数保证） | 无 |
| **L1 记录可重放** | LLM 输出作为事件落盘后，重放 = 读回记录 | **成立** | 存储 |
| **L2 重执行一致** | 仅靠 `policy_ref` + 输入重建 | **不成立**（采样非确定） | — |

**本方案的验收项只承诺 L0 + L1，并明确声明不使用 L2。** 这对下游意味着：

| 场景 | 依赖级别 | 说明 |
|---|---|---|
| 状态回放、崩溃恢复、审计 | L0 | 免费 |
| 评测对比、A/B、回归 | L0（+L1 若需复现 LLM 判定） | 需落盘 LLM 输出，成本可控 |
| "换个模型重跑一遍看效果" | **不支持** | 这是重执行，不是重放；应走离线评测而非回放 |

**诚实表述**：L2 不是"以后会支持"，是**原理上不成立**。把它写清楚，比含糊地承诺"重放一致"更安全。

## 12. 多主体与对等协作

### 12.1 隔离

| 维度 | 机制 |
|---|---|
| 身份 | `Principal`（事件上的 `actor` 字段） |
| 归属链 | `root_task_id` + `produced_by` |
| 可见域 | `VisScope` + `sees_of / can_see` |
| 权限 | `grants_of / can_write`（7 个能力封顶） |

**主体之间的消息必须进 Log**。20 轮对话就是 20 条事件（存储便宜），但上下文不是 20 条——投影按预算折叠。
**判据只有一条：这条消息跨越了主体边界吗？** 是 → 进 Log，没有例外。为此开旁路 = I1 静默失效。

### 12.2 对等协作（递归是树，覆盖不了的图）

递归是**树**（主从），对等协作是**图**。以下不能由递归表达：

| 能力 | 机制 | 参数/事件 |
|---|---|---|
| 对等协商 | 双方不从属，共同达成一致 | `commitment.offered` / `.asserted` |
| 跨体承诺 | "我答应你"如何被对方验证 | `commitment.asserted` + 对方 Log 引用 |
| 可撤销的承诺 | 已发出的承诺如何协商撤回 | `commitment.released` / `.broken` |
| 声誉与互信 | 基于历史交互判断可靠性 | **`Reputation` 投影**（从事件派生，不是存储字段） |
| 传递性信任 | A 信 B，B 信 C，A 是否信 C | `Recall`/`Reputation` 的**深度参数** |
| 共同目标与分工 | 多个独立主体自发组织 | `commitment` + `scope` |
| 冲突与仲裁 | 目标冲突时的裁决 | 一个 `Decider` 模式 Actor |

> **全部落在 §6 的事件网格与 §8 的参数表内**：加两个实体（`memory`、`commitment`）+ 两个投影（`reputation`、`calibration`）。
> **没有一个是新机制**。

## 14. 边界：本架构明确不做

| 不做 | 理由 |
|---|---|
| 修改 `Store` 的 trait 签名 | 这是唯一的架构变更定义 |

## 关键决策

> 本节是**仍然约束现行代码的取舍**：每条一句决策、一句理由。已退场或主题已消失的决策不在其中（`git log` 是历史）。

### D-020 EventSink + AbortSignal 取代 PluginChannel 的双职责

流式链路曾有 8 跳，其中两跳是纯开销，根因是 `PluginChannel` 出（`serde_json::to_value(NodeOp)` → `PluginFrame::Data` → 通道 → 消费循环 `from_value::<NodeOp>` 再解回来）与入（Abort 帧 + `abort_flag` 的 100ms 轮询 + `cancel_token`，三源并存）。

### D-021 两个执行接口同形（ExecEnv）

D-020 把数据面收干净了（通道换成出口 / 信号），但签名（控制面）没动，于是同一个「执行期」概念有两种到达方式：`Capability::execute` 把出口 / 中止藏在 `ctx` 的两个无名键里、参数靠 `ctx.payload::<Value>` 无类型自读、返回多态载荷；`ModelProvider::execute_turn` 则是显式类型化参数与类型化返回。

### D-023 symbio_core 的准入规则 = 依赖方数量

`symbio_core` 是跨模块的系统架构，不是通用工具箱——它的作用是给互相不可见的插件提供唯一的共同可见处。批次 J 曾以「这是跨插件约定」为理由往 core 里加了两样东西（工具结果字段名读取器、`CapabilityVisitor::resolve_name` 默认方法），两者都只有 `session` 一个模块依赖。判错的根源是把「约定」与「跨模块」当成一回事——约定可以只在一个模块内成立。

### D-035 provider 化的三个条件与构造契约

D-007 定了 `submit_object_creator!` + `inventory` 的静态注册，D-023 定了「依赖方 ≤ 1 就下沉回该模块」。

### D-043 v2 事件地基：契约居中，store / projection 按冻结形状进 core

`symbio_core` 新增五个模块：`event`（事件契约：`Seq` / `Entity` × `Verb` 闭集 / 信封）/ `view`（`View` + `Budget`）/ `store`（`Store` trait + `MemoryStore`，F1）/ `projection`（`Projection<V>`，F2）/ `invariants`（N1 / N3 / N5 可执行断言）。

### D-046 事实能力进 symbio_core：不以「可选插件」承载必须有值的机制

B 系列（`feat/v2-bridge-b1-fact-envelope`，停更于 ）走的是「事实能力做成插件」的路线——`plugins/fact_log`（8 文件 字节，含 3 份测试）加 `projection` / `retrieval` / `actor` / `delegate` 四个配套插件，配一份落地方案（已归档）。

### D-055 核心形状棘轮：symbio_core 的公共面只许收窄，放宽必须挂得住一条决策「`VdfsProvider` 去样板」的动议（把 `PluginConfigMount` 那类单点分发推广成 默认实现）要把 `symbio_core::VdfsProvider` 从一个方法扩成十个方法，其中 9 个带默认体。 按当时门禁口径算一遍：C-001 / C-002 看的是根出口的形状字符串，一个字符 没动；C-003 数的是符号表，`VdfsProvider` 早就是多消费方导出，符号 +0；

### D-061 store = distributed 从值域退役：多副本不在计划内，留一格「将来也许能用」比删掉更脏

[01 §8](001-核心架构.md "DE-001-核心架构") 的 `store` 值域里写着 `distributed`，而 `Store` 的不变量里写着 `seq` 单调（I1）。这两条在多副本下副本 A 与副本 B 各自追加，谁先谁后没有全局顺序；

### D-083 自上而下再推导：废除「服务端口进 core」——跨插件通货闭族在既有机制词汇，切片补立前置 P5「运行态归源」

批次 6b-②「端口成形」冻结的候选面（`TurnHost` ≈25 法 + 会话句柄端口 ≈16 法， CS-001 预估 18/56/18 → 20/~97/18、两条 `core-shape-allow` 挂 D-082）是自下而上从实现触点 凑出来的契约面。

### D-084 能力模块公用基础协议：上下文只递值，事实只经引擎——A/B/C/D/E 五类需要的唯一取得方式

P6-③ 把 `WalStore` 一族请出机制层之后，能力在编译上已经拿不到 WAL；但「拿不到」 只解决了禁止，没回答替代——每个要在会话里读事实、落事实、发起一轮、对外作用的模块， 仍然各自决定「从哪拿、往哪写」。会话插件的十二个文件是现成标本：同一份会话事实源曾被它们 用 `session_dir → join(V2_WAL_FILE) → open*` 各自重放、各自取令牌。

### D-087 契约词按「它描述什么」分域：取消 schemas 目录，机制只向下依赖词汇

`symbio_core` 不设 `schemas/` 目录。跨端契约词按「它描述什么」住进对应域： 会话线格式归 `chat`、对话面控制契约归 `dialog`、宿主呈现方言归 `present`、 轮次面归 `turn`、插件扩展点归 `plugin`、模型状态帧归 `llm`、事件→状态的读侧重放 归 `projection`。 判据有两条： 一个名字要能自证归属。
