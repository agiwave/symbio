# 与判据冲突的旧决策（D-29x 之前）

> 本篇自 DE-047 的 §5 拆出；逐条判断仍以 DE-047 的判据与作废清单为准。

## 与判据冲突的旧决策（显式列出，不折中）

1. **DE-015 §0 第 3 / 5 条**：把「工具批次」与「轮收束」并列为内环倒置的三组行，并声明批是
   集合、可 `expand` 并发。与 I-1 / I-4 冲突 ⇒ 作废（X-3 / X-4）。
2. **DE-015 §6 判据 1「加端口 = 1 个 `PortDecl` + 适配器 + 2 行模板」**：形式没错，但当前
   `loop_rows.rs` 的 `PORTS` 曾是**静态硬编码两个端口**，第三人端口必然要改 loop 生产源码
   ⇒ 判据未兑现，`loop_rows.rs` 判「改写」（§2.1）。**2026-11-02 部分兑现**：`PORTS` 已移出
   （端口声明由 `symbio-plugin-model` / `symbio-plugin-session` 提交，环按端口名读冻结表），
   **2026-11-03 进一步兑现到执行面**：通用受理入口 `port` 进绑定表（D-301），真实插件端口
   `notify` 零 loop 改动接入（D-302）。**仍未兑现的部分**：`ROWS` 里的 model / tool 编排行
   仍在 loop（随 `tools/**` 迁移收口），且第三方插件没有自己的**开债口**（`request` 事实的
   生产者仍是环）——后一条是下一笔的独立范围。
3. **DE-045 D-298 的 M3 段**：把「批形状合同」作为 M3 的落点（推荐 ③）。与 I-1 冲突 ⇒
   M3 的批部分作废，合同处置改为**整体收回**（X-9）。
4. **`loop` 文件级审计的旧任务登记（第三 / 四 / 五节与 6.1–6.3 小节）**：多处把「批循环 /
   gate 读数」当作需在 loop 与 session 之间**分配归属**的对象。与 I-1（批不是单元）与
   I-4（环不读 gate）冲突 ⇒ 该登记的第六节已按本文重写，判断由本文接管。
5. **DE-022 / DE-014 的 `open-tools` 语义**：「一个模型响应的 `calls` 逐条落 `request(port=tool)`」
   ——这是**批由模型响应产生**的旧 turn 语义。与 I-2（债由 decl 欠出）冲突 ⇒ 该行改写为
   「decl 依据事实逐笔欠债」，不由环拆响应。
6. **`PortDecl.concurrency`**：该字段把「并发上限」放进端口声明，环因此可读并发策略。
   与 I-4 / I-5 冲突 ⇒ 并发策略整体归 provider。字段本身按 X-15 **保留为插件自声明
   配置**，但**只许执行体自读自限**：环不得读取该值、不得据此决定同时派几笔
   （`D-311`）。
7. **DE-045 D-298 的「执行面必须以方法形式落在 `PortProvider`」**（`llm_round_trip` /
   `model` / `tool_execute`）：形式没错（跨 `dyn` 边界确实要一个合同对象），但**方法名与返回
   类型具名了世界**，与 I-6.2 冲突 ⇒ 改为通用 `executor() -> Arc<dyn PortExecutor>`（X-11）。
8. **`symbio-plugin-api/src/port.rs` 模块文档「端口名是闭集」与 `ports::KNOWN`**：与 I-6.1 /
   I-6.7 冲突 ⇒ 闭集作废，端口集由注册行派生，新增端口不改注册面（X-12 / X-14）。
9. **`ToolCallExecutor`「tool 端口的执行合同」**：合同形状（异步、跨 `dyn`、一次一笔）成立，
   但名字与载荷具名世界，与 I-6.2 冲突 ⇒ 由 `PortExecutor` + `PortInput` / `PortOutcome`
   取代（X-13）。
10. **`plugin-api` 的 `ports::MODEL` / `ports::TOOL` 常量**：本身是数据、不违反 I-6，但
    **loop 生产源码**若按名字取用（`model_port()` / `tool_port()`）就把世界写回了环 ⇒
    loop 侧取用按 LP-003 只许降，随 `tools/**` 迁移删除。
11. **B4/B5 WIP 冻结与 I-6 的冲突**：工作区有 12 个未提交的 B4/B5 文件仍使用
    `ToolCallRequest` / `PendingPrompt`（`tools/tool_executor.rs` 等）。I-6 要求这些类型
    「不得出现」，但删除会当场破坏冻结中的 WIP ⇒ 本批只做**加法**（通用接口 + 开放端口 +
    通用执行入口），旧类型判「作废」并把删除排进 `tools/**` 迁移步（X-11 / X-13），
    **不静默保留**：LP-004 / LP-005 以只许降的基线记录它们仍在，直到迁移完成归零。
    这是排期冲突，不是判据放宽。
