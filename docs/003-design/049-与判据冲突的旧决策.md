# 与判据冲突的旧决策（D-29x 之前）

> 逐条判断以 DE-047 的判据与作废清单为准。

## 与判据冲突的旧决策（显式列出，不折中）

1. **旧环的「内环倒置 = 模型请求、工具批次、轮收束」**：把「工具批次」与「轮收束」并列为
   内环倒置的三组行，并声明批是集合、可 `expand` 并发。与 I-1 / I-4 冲突 ⇒ 作废（X-3 / X-4）。
2. **「加端口 = 1 个 `PortDecl` + 适配器 + 2 行模板」**：当前判据已兑现——
   端口声明由所属插件提交，债行由插件的 `DebtSource::rows()` 产出，行执行体由 `Decl` 的
   `by == plugin_row` 派发到 `RowHandler`；环没有静态端口表或静态行表。真实插件端口 `notify`
   零 loop 改动接入（D-301 / D-302）。
3. **DE-045 D-298 的 M3 段**：把「批形状合同」作为 M3 的落点（推荐 ③）。与 I-1 冲突 ⇒
   M3 的批部分作废，合同处置改为**整体收回**（X-9）。
4. **DE-022 / DE-014 的 `open-tools` 语义**：「一个模型响应的 `calls` 逐条落 `request(port=tool)`」
   ——这是**批由模型响应产生**的旧 turn 语义。与 I-2（债由 decl 欠出）冲突 ⇒ 该行改写为
   「decl 依据事实逐笔欠债」，不由环拆响应。
5. **`PortDecl.concurrency`**：该字段把「并发上限」放进端口声明，环因此可读并发策略。
   与 I-4 / I-5 冲突 ⇒ 并发策略整体归 provider。字段本身按 X-15 **保留为插件自声明
   配置**，但**只许执行体自读自限**：环不得读取该值、不得据此决定同时派几笔
   （`D-311`）。
6. **DE-045 D-298 的执行面合同**：现行合同是通用 `executor() -> Arc<dyn PortExecutor>`，
   方法名与返回类型不含世界名（X-11）。
7. **端口名不是闭集**：端口集由注册行派生，新增端口不改注册面（X-12 / X-14）。
8. **行执行合同**：异步、跨 `dyn`、一次一笔；载荷只用 `PortInput` / `PortOutcome`
   （X-13）。
9. **loop 生产源码按端口名取用**：端口名是数据，但 loop 生产源码不得按名字取用世界端口；
   取用按 LP-003 只许降。
