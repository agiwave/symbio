# 行表与派发面

> 行表只声明“欠什么、何时算还、何时才能做”；派发面从声明与事实选出一笔可动作的债。
> 执行体只还这一笔，记账口负责把结果写成事实。三者不互相兼任。

结构事实以 [RE-006](../004-ref/006-当前事实表.md) 为准；封闭语法与扩展边界见 [DE-023](023-内核边界与扩展局部性.md)，执行面种类见 [DE-025](025-能力包与扩展面.md)。

## 1. 声明形状

一行是数据，不是函数：

```rust
pub struct Decl {
    pub name: &'static str,
    pub reads: &'static [&'static str],
    pub owes: Pattern,
    pub expand: Option<(&'static str, &'static str)>,
    pub until: &'static [Pattern],
    pub unless: &'static [Pattern],
}
```

`reads` 是行级硬前件，回答“看见什么才可动手”；`owes` 回答“什么一出现就欠一笔”。
两者不能互换：没有前件是 `blocked`，没有欠账源则根本不入账。`until` 命中表示同键已还，
`unless` 命中表示这笔不成立；二者都不等于“暂时不能执行”。

模式只做等值和键绑定：

```rust
pub struct Pattern {
    pub source: &'static str,
    pub key: &'static [&'static str],
    pub eq: &'static [(&'static str, Lit)],
}
```

`source` 可以是事实或视图，二者共用冻结后的名字空间。字段先查事实载荷，再查普遍信封
`seq/ts`；视图数组逐元素成实例，对象成一条实例，`null` 或求值失败没有实例。复杂比较、
否定、函数调用不进行表；需要时由 owner 折成声明视图。

`expand` 只展开 `owes`：列表外层先判等值，再从每个元素绑定键。元素身份字段必须属于
`owes.key`，否则多个元素会合成同键债，`until` 无法分辨还了哪一笔。`until/unless` 已按
唯一键配对，不再展开。

装载期由 `Builder::declare(owner, declarations)` 收集，由 `Builder::seal(row_writes)` 一次
冻结并返回全部缺口。名字未知、前件无生产者、写入重叠、会开账却无执行体，都是装载错误，
不留到运行期自旋。归属在交表时给出，不在每行重复存一个 owner 字段。

## 2. 欠账与可动作

对一行 `d` 与键 `key`：

```text
open(d,key) := ∃ f ⊨ d.owes ∧ key = bind(f)
               ∧ ¬∃ g ⊨ d.until ∧ key(g) = key
               ∧ ¬∃ h ⊨ d.unless ∧ key(h) = key
blocked(d,key) := ¬∃ 全部 d.reads 的实例
actionable(d,key) := open(d,key) ∧ ¬blocked(d,key)
```

`owed` 返回全部 `open`，包括被前件挡住的债。读者因此能区分“还在等前件”和“已经无事”，
不能用空的可动作集冒充空账本。

时间不直接进入模式。需要时限时，视图接收事实时间轴上的 `now`，把结果折成布尔字段或实例；
求解器不读墙钟、配置或内存缓存。同一份事实日志必须得到同一组债与同一次租约判断。

一行自己回答“做过没有”：一次性阶段在事实日志中留下产出，下一圈由 `until` 命中而不再开账。
不能另存一份布尔状态，也不能让执行体用“返回空”表达不再推进。

## 3. 端口与五类协议事实

端口只覆盖“派出与应答分两段”的跨界往返。端口名在协议事实载荷里，不放普遍信封；
业务事实仍保留各自名字与语义，不压成通用请求格。

| 事实 | 含义 | 写入边界 |
|---|---|---|
| `request` | 这次调用应当发生；承载业务载荷 | 决策侧声明请求，派发面在开跑前落格 |
| `sent` | 已经派出，租约开始 | 引擎独占，先于执行体 |
| `response` | 成功应答 | 端口记账层独占 |
| `failed` | 不可重试失败、判死或中止 | 端口记账层独占 |
| `retry` | 当前尝试作废，下一尝试接管同一逻辑调用 | 端口记账层独占 |

`request/sent/response/failed` 记在当前尝试键 `(port, id, attempt)` 下。`id` 是跨尝试的
逻辑身份，外部适配器按它做幂等；`attempt` 区分事实层尝试。`retry` 把同一逻辑调用推进到
`attempt + 1`，新记录带有 `from` 指回旧尝试；旧尝试的迟归应答不能关闭新账，也不能让已判死
尝试的产物重新落格。

端口级参数按端口声明一次：

```rust
pub struct PortDecl {
    pub port: &'static str,
    pub before: &'static str,
    pub lease_ms: u64,
    pub max_attempts: u64,
    pub concurrency: u16,
}
```

`before` 是开跑前由引擎落的事实，当前为 `sent`。租约、尝试上限和端口自报并发是不同约束：
`concurrency` 只供执行体自我限流，环不读取，也不据此调度；环的单位是一笔债。
新增端口只增加声明、适配器和用法行，不增加一套求解或记账机制。`PTS-001…004` 守这一边界。

扇出使用 `Decl.expand`，不复制端口实现。批次中的每一笔独立配对、独立失败、独立重试；
一笔失败不连坐兄弟，也不把整批伪装成一笔。

## 4. 执行体与派发分离

行声明不写 `by/prio/tier`。派发先查这一行的注册实现；没有注册实现且 `owes` 指向端口开启侧时，
才交给通用端口受理入口。两者都没有而该行会开账，装载期报 `UnmannedRow`。

纯值行执行形状为：

```text
RowRequest → RowStep::Facts(Vec<FactDraft>) | RowStep::Ask(ModelAsk)
RowReply → RowHandler::parse → Vec<FactDraft>
```

`RowRequest` 只含行名、债键、幂等词干、事实时间、主体、溯源序号、本轮事实、完整历史和
可选上游端口。实现不拿 `&mut Ctx`，不拿存储句柄，也不自行决定下一笔债。

需要模型时只交提示正文；供应商、凭据、预算、租约和重试归宿主。回执成功或失败都必须经
`parse` 产出推进事实，不能把失败留成原债再问。`run` 返回空而债仍开，会在同一笔上重复选中，
最终由步数上界显式报错；正确的“不做”必须由行的模式排除。

需要调用兄弟插件时，只能使用 `run_ctx` 提供的不透明路由上下文：fork 子上下文、设置 PATH
与载荷，并经 `ctx.parent()` 路由。该上下文不是存储面，也不是全局状态面；默认 `run_ctx`
原样转调 `run`，无需跨插件的行保持同步入口。

端口执行体与纯值行执行体共用同一记账纪律：领域产物先缓冲，只有该尝试仍开着才提交；
执行体不得自报 `sent/response/failed/retry`。领域草稿经唯一写口转事件，协议事实由记账层
生成，没有第二条转换路径。

`ActorDecl.writes` 是共享执行体的写入并集；`RowWrites` 是逐行实际写入名单。依赖图和运行期
对账使用逐行名单，避免并集给每一行制造不存在的写入边。实际写入超出声明必须对账失败。

## 5. 选择、排序与时序

候选由同一次事实快照求出。计划阶段先判触发、排除、前序债、租约和端口前提，再按当前全序
稳定排列：

```rust
candidates.sort_by(|a, b| {
    (a.row.name, &a.row.id, a.row.port.as_str()).cmp(&(
        b.row.name,
        &b.row.id,
        b.row.port.as_str(),
    ))
});
```

排序只消除并列者的偶然顺序，不承担业务时序。先后关系由 `after`、`after_port`、
`when_no_open`、`reads` 或事实依赖表达：

- `after`：指定前序债收束后才可还。
- `when_no_open`：某端口或指定批次没有开放债时才开这笔。
- `after_port`：该端口在本圈没有认领时才可还；方向与 `when_no_open` 相反。
- `reads`：所需事实或视图已有实例。

同一 `(port,id,attempt)` 一圈至多入批一次。多个执行体共键时，重试按 `retry` 载荷中的行
归属指认执行者，不按表序抓第一行；指认行无人申报则成孤儿，必须判死。

同批执行体读取计划时的同一份事实快照。后一个执行体刚写的事实不改变前一个的输入，否则
重放顺序会受后台完成时机影响。确实需要先后时，拆成两圈，用事实依赖连接。

## 6. 记账、租约与停机

一次派发先写 `sent` 与 `request`，再启动执行体。执行体挂死时租约仍在账上；租约到期按当前
attempt 的 `sent.row` 找归属，还有尝试额度就写下一 attempt 的 `retry`，否则写 `failed`。

挂起不是普通在飞：以 `deadline_ms:null` 表示执行体已退出、等待外部事实。只有挂起点之后
出现的新触发能重新点燃；没有新触发时既不重试也不自旋。

迟归整笔丢弃：完成时若 attempt 已推进、同键已收束或租约已过，执行体连同它缓冲的世界产物
都不再提交。世界产物与收束事实只在仍有效时落格，避免工具结果先于工具债收束而提前叫醒
消费方。

“收束”和“在途”是两个问题，各有唯一判据：收束回答本轮是否已结束，在途回答是否还有已派未
清的尝试。不能合并成一个 `done`，也不能让空的可动作集代替空账本。

驱动出口必须可诊断：

| 出口 | 条件 | 宿主动作 |
|---|---|---|
| `NoDebt` | 没有任何未收束债，也没有被前提挡住的候选 | 可记正常完成 |
| `Waiting` | 只剩租约未过的在飞尝试 | 等应答或租约，不记 `idle` |
| `NeedsHuman` | 只剩挂起、等外部事实的债 | 交还控制权 |
| `Exhausted` | 步数上界用尽，仍有开放债 | 显式报未完成 |
| `Stalled` | 一圈没有新增事实，继续只会自旋 | 交回开放债，不伪报完成 |

`CP-001/CP-009` 守唯一推进循环；`CP-006` 守机制面形状不随能力增长。任何新退出理由都必须
能让调用方看见未收束债，不能退化成静默停摆。

## 7. 预算、模型往返与表外调用

主体声明的时延档与本轮调度预算是两个量。`ActorDecl` 只声明执行体的 `name/mode/writes`；
行级前件在 `Decl.reads`。本轮预算由已记录的调度事实给出，不能反向改主体身份，也不能从
“哪一行刚好跑完”猜档位。

需要多次模型往返时，每次往返有独立逻辑身份，在宣告与派出之间留下事实。后续往返必须能
从事实判出“当前没有在飞、上一批已收、仍允许继续”，不能依赖整数优先级制造隐含先后。
一次简单分类若在同一动作窗口内完成，可作为该行的同步点问；一旦派出后要跨步等待，就必须
行化并进入端口账本。

行外点问只允许从闭集记账入口发出，调用点与记账函数保持一一对应。禁止在动作内部另开
求解器、另选一笔债或绕过 `dispatch` 自行完成可记账的模型往返。新增调用点必须同时落在
该闭集与静态检查内。

## 8. 读侧窗口与上下文省略

环内视图按声明的 `cost` 读取有界窗口；读侧仍按调用方需要读取完整事实，不能把窗口缺席
解释成历史不存在。一次行执行可按需读取完整历史，不受环内视图扫描上界限制。

上下文省略是一条业务事实，与取代它的摘要同事实写入。省略区间只认存储分配的 `seq` 闭区间，
不认轮号或切片下标；没有 `seq` 的事件不命中显式区间。区间非法时按“没有省略”处理，容错
方向必须是少藏，而不是悄悄多藏。显式省略与未选分支在同一读点合流，不各写一套过滤。
