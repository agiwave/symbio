# 长会话与断点恢复

恢复只重放已提交事实。检查点可以加速或提供可序列化视图，但不能成为比事实账本更真的
第二真相。

## 1. 追加写与提交头

每次追加必须原子更新记录、索引与提交头。进程在追加中途退出时，允许尾部记录不完整；
恢复从最后完整提交头继续，截断或忽略尾部残片，不把残片计入投影。

记录头、长度与校验共同决定完整性。只有完整提交的记录能进入提交头；写缓存 flush 与
目录同步按存储实现保证，但规范只认提交头以内的记录。

恢复投影必须与崩溃前从同一提交头构建的投影逐字节一致，包括事实顺序、节点、消息、
工具状态与身份。不能借恢复重跑模型或补写当时不存在的结果。

## 2. 检查点边界

检查点是从提交头构建的可序列化派生视图，包含恢复所需投影与排序信息。检查点不替代
原始事实，也不允许跳过检查点之后已经提交的记录。

轻量重建使用可重放记录与确定性投影；重量级检查点只减少重复投影，不改变事实权威。
检查点损坏时退回上一个有效提交头重建，不得静默接受缺尾版本。

## 3. 重放层次

- L0：同一事实集上的投影确定，包括节点与界面状态。
- L1：提交头以内的记录可重放为同一事实序列。
- L2：跨外部提供者的重执行一致不作承诺；外部调用事实只重放结果，不重新执行。

## 4. Tokenizer 校准

校准只发生在提供者成功返回的分支。分母是截断前完整请求经未校准 `HeuristicTokenizer`
估算的 token 数，包含系统提示、工具定义、上下文与历史；分子采用提供者回报的实际
用量。

缺少 usage 或估算为零时跳过反馈。校准值只留在进程内，不写事实、不进入检查点，也不
改变重放结果。后续请求可以使用校准后的估算，但校准本身不得成为事实真相。

## 5. 能力阶梯赋值

```capability-assign
event.entity = thread
projection = checkpoint
store = wal
```

## 6. 平凡值与回退

| 参数 | 平凡值 |
|---|---|
| `store` | **memory** |
| `event.entity` | `thread` |
| `projection` | `checkpoint` |

无持久存储声明时可用进程内存储完成闭环，但必须遵守同样的追加、提交头、投影与重放
契约。`wal` 与 `checkpoint` 是能力坐标，不表示检查点可以替代事实。
