# 长会话与断点恢复

## 内容

前置：S04 ｜ **新增机制键 1**（`store`）｜ 参数变化 3 ｜ 阶段二

## 1. 场景：要什么能力

会话可以很长（跨小时、跨天），进程崩溃后能从断点继续，而不是从头再来。

相对 S04 高了什么：**系统状态从"内存里"变成"可持久、可恢复"**。
这一步真正的意义是——它逼出 `store` 这个参数，而 `store` 是后面 S10（入库过滤）唯一会触及原语的地方。

## 2. 为什么它能落在 v2 上（J1）

| 看起来新的东西 | 实际是 |
|---|---|
| 持久化 | `store = wal`（参数的一个取值） |
| 断点 | `projection = checkpoint` 产出的 `CheckpointState`——**派生视图**，随重放重算 |
| 恢复 | 从 `seq` 重放投影——**投影是纯函数，所以恢复只要重放，不需要状态迁移** |
| 崩溃一致性 | `seq` 单调 + append 原子，两条已有性质 |

**关键**：因为投影是 `(&[E], ts, budget) -> View` 的纯函数，**恢复不需要任何"状态迁移代码"**。
这是单原语设计在工程上最直接的回报：别的架构要写"从旧格式迁移到新格式"，这里只需要重放。

## 3. 增量清单（只加数据）

| 类型 | 内容 |
|---|---|
| 事件格子 | 无新增——断点是派生视图（见 §2），恢复只重放。`thread.checkpoint` 是 [plan/DE-001 §6 网格](001-核心架构.md "DE-001-核心架构")里的**预留格**：落锚（让恢复从锚点起跳）是重放变贵之后的优化，届时由 [plan/DE-016 §3 第 10 步](016-工程落地与验证.md "DE-016-工程落地与验证") 崩溃恢复演练决定 |
| 新参数键 | **`store`**（值域与平凡值的唯一 owner 是 [DE-001 §8](001-核心架构.md "DE-001-核心架构")；本阶第一次取非平凡值 `wal`） |
| 投影参数 | `projection = checkpoint`（该 task 全量 + 压缩，可序列化） |
| grants 行 | 无新增——恢复者复用已有主体的读权限 |

**本阶点亮的机制键**（阶梯总表的「新增机制键」由这张块算出；`scripts/gen-verify-facts.mjs` 从这里取输入）：

```capability-assign
event.entity = thread
projection = checkpoint
store = wal
```

## 4. 平凡值与回退（J2）

| 参数 | 完整值 | **平凡值** | 平凡值下 |
|---|---|---|---|
| `store` | `wal` | **`memory`** | 仍完整运行——重启即丢，但单进程内一切照常 |
| `projection` | `checkpoint` | `snapshot` | 仍完整运行——不压缩，上下文变长但不错 |

**`store = memory` 是 S01–S04 的实际取值**：前四阶根本不需要碰这个参数，
到本阶才第一次取非平凡值。这说明前四阶"没有持久化"不是缺陷，而是**参数还没被点亮**。

## 5. 静默失效与强制（J3）

| 约束 | 违反时信号 | 强制方式 |
|---|---|---|
| checkpoint 可序列化 | **有**（序列化会失败） | 无需额外强制 |
| 恢复后 `seq` 单调 | **无** | CI 断言 |

## 6. 验收断言

1. 写到一半杀进程 → 重启后 `head` 与崩溃前最后一条已提交事件一致。
2. 从 `seq=0` 重放得到的投影 == 崩溃前的投影（逐字节）。
3. `store = memory` 下重启 → 事件为空，但系统仍能启动并完成 S01 闭环。
4. **反向用例**：故意丢掉最后一条未提交事件 → 断言 1 的 `head` 必须不同（证明"已提交"边界真实存在）。

## 8. 这一阶做不了什么

边界的唯一账本：[SC-005-长会话与断点恢复](../002-scene/005-长会话与断点恢复.md)（用户语言）。机制面独有边界（用户可见范围之外的工程约束）：

- `distributed` 取值下的 `seq` 一致性未展开，本阶只到 `wal`。
- 回放只承诺 **L0 投影确定** 与 **L1 记录可重放**；**L2 重执行一致原理上不成立**（[DE-001 §11](001-核心架构.md "DE-001-核心架构")）。
