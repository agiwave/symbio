# 会话输入与地址

本文定义会话输入、停止、审批和分支的地址契约。实时变更见
[VDFS 规范](009-VDFS规范.md "DE-009-VDFS规范")，线路载荷见 [协议规范](005-协议规范.md "DE-005-协议规范")。

## 1. 身份与入口

会话身份是完整地址 `<A> = <挂载目录>/<sid>`，不是裸 session id。同一 sid 可以出现在不同
Agent 空间中，跨进程寻址、选择、订阅和动作都必须使用完整地址。

会话输入只有两种形态：对地址的 VDFS 写入或节点动作。不存在与地址无关的全局发送或
停止入口；路由只负责定位，不承担输入语义。

## 2. 地址表

| 意图 | 地址操作 | 语义 |
|---|---|---|
| 发用户消息 | `write(<A>/inbox/<iid>)` | 写入即入队，空闲时由会话消费 |
| 取消排队消息 | `delete(<A>/inbox/<iid>)` | 删除未消费项；已出队返回 NotFound |
| 清空排队 | `action(<A>/inbox, "clear")` | 只清未消费项 |
| 停止当前轮 | `action(<A>, "abort")` | 收敛在途轮次 |
| 重试、审批、补充、回答、切支 | `action(<A>/message/<mid>, "<动作>")` | 作用于转写中的具体消息 |

三个作用域不可混用：

- `<A>` 表示正在运行的当前轮；
- `<A>/inbox/<iid>` 表示尚未成为消息的队列项；
- `<A>/message/<mid>` 表示已经存在于转写中的消息。

## 3. 停止

UI 停止由两个动作组合：

```text
action(<A>, "abort")
action(<A>/inbox, "clear")
```

`abort` 只负责在途轮次，`clear` 只负责排队项。不得给 `abort` 增加清队开关；组合由调用方
表达，机制动词保持单一职责。只中止不清队会让下一条排队消息立即继续运行。

会话不存在或没有在途轮次时，`abort` 必须返回明确失败，不静默成功。会话忙时写入和重试
留在队列中；忙碌是排队状态，不是错误。

## 4. 消息动作

动作词表为：

```text
retry_subtree / retry_compaction / retry / approve / reject /
supply / answer / switch_branch
```

线上使用 `snake_case`。词表之外的动词返回 `NotImplemented`，不猜测语义，也不新增第二套
动作名。

通用载荷可包含 `args / reason / answer / mode / risk_level`。消息动作只落事实，随后由
事实写口唤醒控制面；动作内部不得直接重跑模型或建立第二条执行路径。

| 动作族 | 事实语义 |
|---|---|
| `switch_branch` | 落分支选择事实，不开启新轮 |
| `retry_subtree` | 落分支创建事实，由会话复用开轮单元开启新轮 |
| `approve / reject / answer` | 落用户回答事实，挂起调用由控制面续接 |

`retry_subtree` 的落点必须是用户消息节点，因为分支以轮根身份分组。现代转写中用户
`body` 节点就是轮锚；旧转写若把动作声明在轮骨架上，消费端只能沿父子结构解析到对应
用户节点，不得把骨架 id 当作动作靶子。新轮根标识由会话铸造，调用方不得指定；创建
分支与开启新轮使用同一标识。请求装配和转写投影必须消费同一份分支选择事实，未选中支
的产出保留在转写中但不进入请求。

转写读面与实时帧必须交付后端派生的 `actions`。失败或中止的用户轮锚声明
`retry_subtree`，工具与压缩分别声明自己的动作；前端只执行已声明动作，不按节点类型
补造恢复语义。编辑后重试先持久化用户正文，再对同一轮锚执行 `retry_subtree`；保留旧支
不等于撤销旧支已产生的外部副作用。失败正文也必须挂在所属用户轮锚下，避免呈现与
请求装配仅筛选轮根时把未选中支的失败内容带入当前读面。

## 5. 收件箱

收件箱项以自身地址为身份。写入保留工作目录回退源；运行模式、风险级别和模型提供方
由会话 metadata 与缺省链解析，不在每次输入中重复承载。只有出现真实的逐次覆盖需求时，
才扩展输入正文的可选字段。

消费方出队后必须发布该队列项的无载荷变更。消费端据此移除排队项，再以同一消息 id
接受后端权威转写；不能依赖投递顺序或额外私有刷新通道。

## 6. 消费端契约

- 会话列表、选择、订阅和动作保存完整地址；id 只用于地址末段派生。
- 按挂载目录缓存和登记地址方案，不使用单一全局挂载目录。
- 实时消费端维护已登记挂载前缀集合；进入新 Agent 空间时先登记再消费。
- 写入 inbox 不等于已落库，用户消息不得乐观回显。
- 工作态可以乐观显示，但必须由后端状态接管。
- 排队消息以“待发送”状态可见；出队后由同一 id 的权威转写接管。
- 骨架反馈与排队可见性是两个独立机制，不得互相替代。

## 7. 一致性要求

- 会话身份恒为完整地址；
- 输入只经 VDFS 写入或节点动作；
- 停止是 `abort + clear` 的组合；
- 消息动作只落事实，由环续接；
- 分支选择只有一份事实读法；
- 出队必须发布无载荷变更；
- 所有发送方共享同一可见性与权威转写链路；
- 不保留全局输入路由、私有轮询或客户端猜测的落库状态。
