# 义务环

> **一句话**：一个会话收事实、算欠账、还债、再收事实。**没有别的。**
>
> 本文是 [DE-001 §4.4](001-核心架构.md "DE-001-核心架构")「义务环」的机制细则：
> 债的形状、四步与执行契约、引擎与插件的契约、装载期检查与判据。
> **行与端口的声明形状归 [DE-022](022-行表与派发面.md "DE-022-行表与派发面")**——
> 本文 §2.3 / §2.4 只留指针与环这一侧的两句话。
> 控制面的总纲（一环 · 一表 · 一源）在 DE-001；施工路径与现状差距在
> [DE-090](090-过渡方案.md "DE-090-过渡方案")；判据的执行与取证归
> [DE-016](016-工程落地与验证.md "DE-016-工程落地与验证")。

## §0 结论先行

1. **控制面只有一个环。** `drive` 每步问表、取最小可还债、运行、对账，直到无债 ⇒ 静息；
 没有第二个调度器。
2. **一笔债 = `owes ⇒ ◇ until` 的当前违例 + 「谁该还」。** `by` 只有 `Some(执行体)` 与
 `None`（恒 blocked）两种取值；决策债 / 搬运债 / 等待债是用法，不是机制。
3. **内环倒置 = 三组行**：模型请求、工具批次、轮收束。三组行复用
 `request` / `sent` / `response` / `failed` / `retry` 五个协议名，**不新增事实名**。
4. **流式不是债。** 流式帧走 `ExecEventSink` 直通，不改变事实面；债只描述请求 / 应答 / 失败。
5. **工具批次是集合，不是单项。** 一次模型响应可带多个工具调用；一个 `tool` 债的
 `expand` 把批次展开成元素，元素之间并发。
6. **粒度是参数，不是机制。** 加一个端口 = 0 个新事实名 + 1 个 `PortDecl` + 适配器
 + 2 行模板（租约行通用），`drive` 与 `owed` 的源码不变（判据 1）。

## §2 目标形状

### 2.1 四步

```
① 收到事实 → 追加进日志
② 算欠账 → 从日志算出"还欠什么"，取最小的一笔
③ 运行它 → 交给一个执行体，它把领域事实直接写进同一个 store
④ 对账 → 引擎读回这一次动作写进日志的那一段，回到 ②
```

④ 出现两次：填了 `before` 的行在运行前先落一条标记（`sent`），运行后读回尾段对账。
**执行体不交回事实清单**（写不经过返回值，形状裁决见
[D-123](022-行表与派发面.md "DE-022-行表与派发面") 决策 1、5）——它交回的只有"成功 / 失败"。

```rust
impl Session {
    async fn on_event(&mut self, e: Fact) -> Result<(), EngineError> { // ①
        self.log.append(e)?;
        // now 取**这条事件的时间戳**，不在 owed 里读墙钟（D-115 决策 1）。
        self.drive(e.ts).await
    }

    async fn drive(&mut self, now_ms: i64) -> Result<(), EngineError> {
        let mut steps = 0;
        loop {
            if self.abort.aborted {
                self.log.append(closed(ClosureReason::Interrupted, "abort"))?;
                return Ok(());
            }
            if steps >= MAX_STEPS_PER_DRIVE { // 步数上界
                self.log.append(closed(ClosureReason::Exhausted, "step_limit"))?;
                return Ok(());
            }
            let Some(d) = self.min_debt(now_ms) else { // ② 无债 ⇒ 静息
                return Ok(());
            };
            let before = self.log.head()?;
            if let Some(k) = d.decl.before { // ④a 前置标记
                self.log.append(Fact::envelope(k, &d.key))?;
            }
            match self.actors.run(d.decl.by, &d, &self.abort).await { // ③
                // ④b 账本 = 日志尾那一段（引擎读，不由执行体自报）：写已经在 store 里，
                // 引擎不再二次落格。见 DE-022 §1.1「账本是日志的一段」与 D-123 决策 1。
                Ok(()) => {
                    let ledger = self.log.range(before)?; // 这一次动作的实际写入
                    self.reconcile(d.decl.by, &ledger)?; // 名单 ⊆ 声明的写入封闭
                    // 本轮收没收也读这同一段：出现停机格（或收束于等待用户那一格进展）
                    // ⇒ 收工，产出从草稿取——执行体不交回 outcome（D-123 决策 5）。
                    if ledger.iter().any(|e| self.ends_the_drive(e)) {
                        return Ok(());
                    }
                }
                Err(e) => self.log.append(Fact::failed(&d, e))?, // 失败也是事实
            }
            if self.log.range(before)?.is_empty() { // 空账本 = 无进展
                self.log.append(closed(ClosureReason::Exhausted, "no_progress"))?;
                return Ok(());
            }
            steps += 1;
        }
    }
}
```

**没有别的调度代码。** 七个词里"优先"与"前置标记"就落在这两处。四个不是第八个词、
但必须由引擎承担的动作是：**读触发事件的时间戳**、**写 `sent`**、**写 `failed`**、
**在步数上界 / 无进展 / 中止处写收束事实**——它们都是"执行者交不回事实时，引擎兜底
把状态变化落成事实"，不引入任何业务判断。

> **`now_ms` 只能来自触发事件。** 没有事件就没有 `drive`，因此"静默 30 秒该汇报了"
> 这类时间条件只在**下一次有事件**时被求值。若需要独立定时唤醒，那是唤醒源
> （[DE-001 §6](001-核心架构.md "DE-001-核心架构") 事件网格）的一条事实，不是让 `owed`
> 去读墙钟。**墙钟进入日志的唯一合法通道**：唤醒方（启动 / 心跳 / 插话接收）在落那条
> 唤醒事实时读一次墙钟写进它的 `ts`——此后本次 `drive` 的 `now_ms` 就是这个 `ts`；
> 崩溃重启的租约求值（判据 16）走的也是这条通道。

### 2.2 债

> **一笔债 = 一条 liveness 性质 `owes ⇒ ◇ until` 的当前违例，外加"谁该还"。**

```
open(d, key) := ∃ f ⊨ d.owes ∧ key = bind(f) ∧ ¬∃ g ⊨ d.until ∧ key(g) = key
blocked(d, key) := d.by = None ∨ ∃ h ⊨ d.unless ∧ key(h) = key
actionable(d,key) := open ∧ ¬blocked
min_debt(now) := min { (d,key) | actionable } 按 (prio, name, key) 全序
```

`owes` / `until` / `unless` 的匹配对象是**事实与视图**。时间不进公式：需要时间的条件
（"静默够久了""租约过期了"）由视图把 `now` 折成一个**布尔字段**，行只匹配
`report_due{due:true}` / `stale_sent{stale:true}`。因此 `owed` 本身仍是一个
`(&[Fact], &[View], i64) -> Vec<Debt>` 的纯函数——`now` 是入参，不是它去读的墙钟。

**`prio` 是全局的，不是格内的。** 义务环只有一个环、一次取最小，跨行必须可比：
权限行（`prio: 0`）必须早于派发行（`prio: 10`），轮首判决必须早于执行行。
同 `prio` 的并列由 `(name, key)` 决出，**不依赖注册顺序**（顺序是数据，不是插入顺序）。

**`by` 只有两种取值，引擎只有一个动作：**

| `by` | 引擎做什么 | 谁负责不阻塞 |
|---|---|---|
| `Some(名字)` | 到绑定表查那一个动作、跑它；写了什么由引擎读日志尾段（DE-022 §1.1） | **那个执行体自己** |
| `None` | **什么都不做**——恒 blocked，永不选中 | — |

"决策债 / 搬运债 / 等待债"是**用法**，不是机制：`by` 指向纯函数叫决策债，
指向 `courier` 叫搬运债，是 `None` 叫等待债。**三者在 `drive` 里走同一行代码。**
同步与异步是执行体的实现细节，**不在协议里**，引擎也没有能力管（代价见 §3.4）。

### 2.3 表与两行主模板

**行的声明面归 [DE-022-行表与派发面](022-行表与派发面.md "DE-022-行表与派发面") §1.1**：
`Decl` / `PortDecl` 的字段、每端口两行 + 一条通用租约行的模板、`(port, id, attempt)` 三键、
租约到顶即判死、执行体的声明面与动作面为什么分家。

留在这节的只有环这一侧的一句：**`by = None` 那一行对 `drive` 是透明的**（恒 blocked，永不
选中），它存在的理由不是"它是一类债"，而是让 `open ≠ ∅ ∧ actionable = ∅` 这个状态可表达——
「在等」与「没事」由此可分（两个停机理由见 §4.3）。

### 2.4 五个协议名 + 端口

**协议面归 [DE-022](022-行表与派发面.md "DE-022-行表与派发面") §1.2**：`request` / `sent` /
`response` / `failed` / `retry` 五名、端口的适配器与租约、以及「端口是载荷，不是信封」的裁决。
环这一侧只用一句话：**五条同键 `(port, id, attempt)`**——重试写出的 `request{attempt+1}` 重新欠
派发 / 授权 / 等待三行，而不是被上一 attempt 的出口格提前关掉
（[D-138](022-行表与派发面.md "DE-022-行表与派发面")）。

### 2.5 决策输入闭包：`owed` 只许读三样东西

> **`owed` 的入参 = 事实切片 + 视图值 + 触发事件的时间戳。没有第四样。**

这不是洁癖，是"回放可重建"的定义。五个策略行的输入全部来自事实面：

| 行 | 需要的判断 | 事实来源 |
|---|---|---|
| `classify` | 这句话该派活吗 | `turn.stage{stage:"round"}` / `user.message` / `session.config` |
| `report` | 干了一会儿了该说一句吗 | `now - last_spoke_at`（两者都来自事实）+ `chat.assistant.reported` 计数 + `session.config` → `report_due` 视图 |
| `compress` | 这一轮要不要压缩 | `session.config` / `turn.stage{stage:"compress"}` |
| `recall` | 要不要召回 / 路由技能 | 存储能力声明折成 `session.config`；命中落 `turn.stage{stage:"recall", result:"hit"\|"miss"}` |
| `reflex` | 能不能续跑 | `turn.stage{stage:"resume"}` 的有无 / `turn.stage{stage:"recall", result}` |
| `execute` | 本幕还欠不欠一次执行（三条让位前件都没命中） | `turn_head` 视图的三格：`tools_open`（工具批还开着）/ `reflex_answered`（快路已作答，D-164）/ `model_open`（已宣布未派出，D-166） |

三条硬规则：

1. **`user.message` 先于一切判决入格。** `owes` 要匹配它。写入点在 `drive` 之前，
 `produced_by` 仍指向用户请求。
2. **配置是事实，不是旁路快照。** `session.config` 在一轮开始时落一条（开关注记 +
 阈值 + 存储能力），`owed` 只读它。改配置 = 落新事实，回放能重建当轮判定。
3. **"这一步做过没有"是 `turn.stage` 事实，不是进程缓存。** `done` 直接接进视图，
 任何 `stages_done` 式缓存都是第二份状态。

**`now_ms` 从事件时间戳来，不从 `clock_now_ms` 读。** 否则同一个日志重放两次会
得到不同结论。需要"未来某刻"的行（汇报、租约）由视图把 `now` 折成布尔，见 §2.2。

### 2.6 执行契约：`drive` 不是一段同步循环

`drive` 是异步的：模型调用、工具执行、流式写出都 `await`，中止信号随时可能置位。
契约七条：

| # | 契约 | 不做的后果 |
|---|---|---|
| 1 | `drive` 是 `async fn`，持 `&mut Session`（单写者） | 双写者 = 第二份状态；`&self` 又写不了日志 |
| 2 | `actors.run` 返回 `Result<(), ActorError>`，写入由引擎从日志尾读（[D-123](022-行表与派发面.md "DE-022-行表与派发面") 决策 1） | 失败只能靠执行体自己落事实，漏了就静默停摆 |
| 3 | 失败要落成事实：**端口往返**的 `Err` 由端口记账层写 `failed{port,id,attempt,why}`（唯一写点，`via` 随事实走）；**动作本身**的 `Err` 今天有**两个**变体——`Append`（落格失败，写不出任何事实，不伪造、原样上抛，[D-141](022-行表与派发面.md "DE-022-行表与派发面")）与 `Read`（动作要读的那一侧没交出它要的东西：发生在任何请求格之前，端口面上没有一笔账可关，因此交回编排层走 `finish_turn(TurnExit::Failed)` 的兜底格既有路径） | 失败不是事实，回放看不见 |
| 4 | 每步之前检查 `ExecAbortSignal`；中止 ⇒ 收束 `interrupted` | 中止只能等执行体自觉返回 |
| 5 | `MAX_STEPS_PER_DRIVE = 64`，超界 ⇒ 收束 `exhausted{step_limit}` | 一条坏行可以让 drive 永远转 |
| 6 | 每步之后读**账本**（动作前 `head` 起的日志尾段）；空账本 ⇒ 收束 `exhausted{no_progress}` | "执行体这一步什么都没写"是静默停摆的第一来源 |
| 7 | 在途请求带**租约**（尝试号进载荷）；租约看护（`port::reap`，读 `stale_sent` 视图——**不经行表**，`lease` 行已删，见 [DE-090](090-过渡方案.md "DE-090-过渡方案") §1.1.3 的 ④ 类）在重试前提成立时落 `retry` 并重开下一笔（D-138：`sent.awaited` ∧ 未到上限），否则到顶即判死、落 `failed`。重试已启用（`tool` 端口 `max_attempts = 2`），行层债键含 `attempt`，重试出来的 `request{attempt+1}` 重新欠授权与派发 | `sent` 之后崩溃 ⇒ `await` 恒 blocked、永久在等；唤醒批次的等待方可由事实重建，崩溃后仍能重试 |

第 6 条与 §3.4 第 6 条（执行体写入必须与 `until`/`unless` 相交）是一对：装载期查
"它**能不能**收口"，运行期查"它**这次**收没收"。两条都不做，才会出现 §3.4 第 7 条
那种"停用插件后永久停在等"的静默故障。

**第 7 条的边界：窗口有界，不是保证。** 租约看护只扫快照尾部若干条事实
（`chat_loop/drive.rs` 的 `lease_tail`）：**窗口 ≥ 同会话两次唤醒之间长出的事实量 ⇒ 覆盖完整；
否则窗口外的陈旧租约只能由 `waiting` 行挂着**（账仍开着，不静默判死）。

窗口的长度**不在这里抄一个数**：它就是视图声明的求值上界
（`Frozen::scan_bound`，全表最小的 `cost`）。这一点是判据而不是风格——一份事件切片要喂给
每一条视图，所以「切片多长」与「视图能算多长」必须是同一个数，否则超界那一侧会静默回
`None`、`owed` 把它折成空集（「算不出来」冒充「没有欠账」）。切点因此从声明读，声明的分歧
由装载期的 `Gap::ViewCostMismatch` 拦下。三条用例钉住这段行为：
`the_lease_window_keeps_only_the_newest_facts`（`chat_loop/drive.test.rs`）、
`reap_only_sees_the_facts_it_is_handed`（`port.test.rs`）与
`the_turn_slice_is_trimmed_to_the_scan_bound_keeping_the_newest`（`loop_rows.test.rs`）。

**写封闭是事后判，不是前置闸——这是取舍，不是缺陷。** 执行体的实际写入由引擎在动作
**之后**从日志尾段读（第 6 条同一份账本）；越界的那条**已经入账、不回滚**，引擎落停机格
`undeclared-write` 并收束本轮，让越界在事实面显形。不前置的理由：预写闸要求执行体先申报
「这次我要写哪些格」，那是把封闭面复制成一次陈述，而自报正是 [D-123](022-行表与派发面.md "DE-022-行表与派发面")
决策 1 要避开的东西。代价明确：**越界事实留在日志里**——不干净但可追（停机格的 `reason` 与警告
指名行与格）。判据因此不是「越界不可能发生」，是「发生了必被看见、且本轮停止」。

**并发不在 `drive` 里。** 单会话单写者意味着同一会话的债是串行还的；并发来自
多个会话各有一个 `drive`，以及执行体内部（工具批次）自己的并发。同一个批次的并发
由 `PortDecl.concurrent` 声明并由集合事实表达（§2.8），不是执行体的自觉。

### 2.7 流式与审批

- **流式**：`courier` 在 `sent` 之后把 `ExecEventSink` 的帧直通给前端；
 帧不是事实，不参与 `owed`。`response` 只在流结束时落一条。
- **审批 / 用户补充 / 中止**：都是**外部事件**，由唤醒源落事实（`approval.*` /
 `user.message` / 收束格），`await-tools` 的 `until` 增加对应的事实名。
 审批恢复只能从事实进环：审批格落事实 ⇒ 重新开账 ⇒ 由行表派发。
- **`ask_user`**：`request{port:user}` 的 `await` 行，`until: user.message`。
 这是 `Wait` 折叠在细粒度端口上的自然形态，不需要新机制。

### 2.8 并发

创建行 `open-tools` 的 `expand` 让一个批次成为 N 笔子债（派发行仍欠 `authz.granted`，
两段债的划分见 D-117）；`drive` 仍串行取最小，
但 `PortDecl` 声明 `concurrent: true` 时，同一 `batch_id` 的子债可并发派发，
引擎等整批 `sent` 后再进入 `await`。**并发集合是事实**，不是执行体的自觉。

## §3 引擎与插件契约

### 3.1 引擎只认识七个词

**事实 · 模式 · 键 · 视图 · 执行体 · 优先 · 前置标记。**

没有 `model`、没有 `tool`、没有 `turn`、没有 `user`、没有 `prompt`。**一个业务词都没有。**
插件能往这七个词里填内容，但**不能加第八个**。

### 3.2 插件交什么：六张表，两个口

```rust
impl Builder {
    fn declare(&mut self, owner: &'static str, p: PluginDeclarations<'_>); // 一次交齐
    fn seal(self) -> Result<Arc<Frozen>, Vec<Gap>>; // 冻结
}
```

`PluginDeclarations` 的六张表是：`events`（事件名 → 格位）、`facts`（载荷形状）、
`views`、`actors`、`ports`、`rows`。**事件与事实分开**：前者回答「写闸认不认这个
名字、它落在哪一格」，后者回答「这一格的载荷有哪些字段、键是什么」；一条事实要在
写闸上可写，就必须有同名事件（D-197）。

`FactDecl` 是**一个事实名一条**，不是一族一条：`request` / `sent` / `response` /
`failed` / `retry` 各声明一次（字段完全相同），端口是载荷取值，不是声明维度。
`ViewDecl` 带三样：`ver`（视图口径版本，进 §3.4 第 6 条）、`reads`（它读的 `(事实名, 字段名)` 列表，装载期逐条查声明）、
`evidence`（**输出是哪些事实名的证据**；只作窗口 / 幕锚的那几格不在里面。§3.4 第 1 条按它配依赖边，判据与被否的形状见 [D-160]）。

`ActorDecl` 的四个字段不是装饰——裸函数也能跑，但**三样静态检查会全部失效**：

| 字段 | 谁用它 | 缺了会怎样 |
|---|---|---|
| `mode` | 令牌闸门（§3.4） | 分不清"反射档不许调模型" |
| `reads` | 装载期检查视图存在 | 视图名打错 ⇒ 运行期静默返回空 |
| `writes` | 写入封闭 / 死事实名检查 | 查不出"这个事实名没有任何人会产出" |

### 3.3 装载：三个时点

| 时点 | 谁在做 | 发生什么 |
|---|---|---|
| 编译期 | `linkme` / `inventory` | 收集插件实现，形成清单 |
| 装载期 | `Builder` | 填六张注册表 |
| 冻结 | `seal` | 跑七道检查；通过则产出不可变 `Arc<Frozen>` |

**"运行期不能注册"不是纪律，是类型**：`Session` 只拿得到 `Arc<Frozen>`，没有可变注册口。

### 3.4 装载期七道检查

| # | 检查 | 查什么 | 缺了会怎样 |
|---|---|---|---|
| 1 | 依赖图无环 | "谁还清谁"的图：行出口里的视图按 `ViewDecl.evidence` 展开成事实名，再按**出口格**（两边 `eq` 相容）配边（[D-160]） | 类型级互相等待 ⇒ 死锁；按 `reads` 全集展开会把共写一族的行连成假环，只按事实名配边会把同族不同档读成同格——两条都是表装不上 |
| 2 | **每行收口** | `owes` 的每种应答至少命中一次 `until`/`unless` | 运行期死循环 |
| 3 | 字段都在声明里 | 模式与 `ViewDecl.reads` 引用的 `(事实,字段)` ∈ `FactDecl.fields` | 运行期取不到字段 |
| 4 | 相交行对 | 可能同时命中的行对 | 静默遮蔽（静态不可判，只报告） |
| 5 | 写入封闭 | 执行体实际写入 ⊆ `ActorDecl.writes`；`PortDecl` 覆盖 `response`/`failed`。**判定输入是日志尾段**（引擎在动作前后各读一次），不是执行体交回的陈述——装载期只能查声明面，"实际写入"那一半在运行期对账（[D-123](022-行表与派发面.md "DE-022-行表与派发面") 决策 1–2） | 决策者伪造 `response` |
| 6 | **执行体收口** | `by=Some(a)` 的行：出口里有可声明的领域格 ⇒ `a.writes ∩ (until ∪ unless 的事实名) ≠ ∅`；出口**全是**引擎独占格（派发行的形状，引擎落 `before` / `failed` 替它关门）⇒ `a.writes` 非空**或**出口里有某个端口的 `before` 格（[D-124](015-义务环.md "DE-015-义务环") 订正 1） | 执行体返回空事实 ⇒ 每一步都无进展 |
| 7 | **声明事实有归宿** | 每个 `FactDecl`（控制面声明集）至少出现在某行的 `owes` / `until` / `unless` | 拼错的名字静默永不被消费 |

第 2 条与第 6 条是一对：**2 查"这笔债有没有出口"，6 查"这个执行体能不能走到出口"。**
只有 2 时，执行体可以什么都不写，配置照样绿；只有 6 时，行可以没有 `until` 可匹配。
第 6 条对**派发行**（出口只有 `sent` / `failed` 这类引擎独占格）改判为「有没有交出去的凭据」：
它不能要求执行体声明一条被第 5 条禁止声明的格——两条检查互斥等于「这一行永远不许接线」。
凭据有两种：名单非空（执行体自己写得出领域格），或出口里挂着某个端口的 `before` 格
（它挂上了一条派出契约，`check_ports` 已经要求那条端口有应答出口⇒关门链条完整）；
两者都不成立才红。而这一半（"这次真没写"）本来归运行期的空账本守卫判（§3.4 第 5 条 +
[D-123](022-行表与派发面.md "DE-022-行表与派发面")），裁决见 [D-124](015-义务环.md "DE-015-义务环")
订正 1。
第 7 条只约束**控制面声明集**（交给 `Builder` 的事实），不约束业务事实——
业务事实的读方是投影，不是表；强迫它们各挂一行只会造出装饰行。

**声明集的准入资格就是第 7 条本身**：一个事实名进 `Builder`，就必须有行以它为
`owes` / `until` / `unless`，或有一条**被行用到的**视图读它。只在审计 / SLO 投影里
读的断言格（例：`turn.dispatch` 由 `invariants::declared_budget_ms` 读）属业务事实，
留在事件名表里，不进声明集——它写与读都照旧，只是不要求表里给它配一行。

**事件表的格位检查（D-197）**：事件名唯一（`DuplicateEvent`）；每条插件声明的事实都
必须有一条同名事件（`FactWithoutEvent`）。前者防同一名字有两个格位，后者防「能写进
声明、写闸却不认」——这一半在装载期就该红，不留给第一次写入。

**装载失败即拒绝启动，不许部分成功。**

> **`turn.closed` 是概念名，线上名是收束格。** 本文档用 `turn.closed` 指"这一轮收束了"，
> 代码里它是 `chat.assistant.final` / `chat.assistant.fallback`（`turn × closed`），
> `reason` 是被定下的闭集字段。**不要新增一个叫 `turn.closed` 的事件名**——
> 那会让"本轮收束"有两个真源。

## §4 三处硬约束

**以下三条不是可选项：缺任何一条，形状不能成立。** 补法都刻意做轻——不新增机制键。

### 4.1 溯源：不悬空且更小

溯源边是信封里的 `produced_by: Option<u64>`。规则三条：

1. **名字只有 `produced_by`**，不引入第二个名字（如 `caused_by`）。
2. **不悬空且更小**：`produced_by < seq`，且指向的 seq 确实在同一条日志里。
 前一半几乎免费（`produced_by` 只能取自一条已入库事件的 seq，而 seq 严格单调）；
 后一半要一条检查——回放时按 seq 建索引，落一条违规。
3. **派生图无环是免费的**：seq 严格单调 ⇒ 边只能从高指向低 ⇒ 天然 DAG
 （`seq` 严格单调即可直接推出），**不另加无环检查**。

「哪些事件算声称」若按事件种类硬枚举，加一类就要改那个函数。它属 I2 的判据范围，
与本方案的形状无关（见 §7 不做清单）。

### 4.2 权限：否定要落成事实，判定位置不动

授权判定由 fail-closed 的 `PermissionMatrix` 承担：写侧按**种类**分两臂判
（`can_reply` / `can_produce_artifact`），读侧判 `can_see`。**判定本身是健全的**——
缺的不是判定，是**否定的表达**：

> 拒绝 = 拒绝入格 ⇒ 该轮**留在未收束态**。这是用「状态缺失」表达否定：
> 事后无法回答「谁、何时、因为什么被拒」，回放也重现不出这次拒绝。

**这违反的是 I1（单通道），不是权限语义。** 既然一切状态变更只经事实源，
那么「被拒绝」这个状态变更也必须是一条事实。

**补法**：`denied{key, why}` 与 `granted{key}` 都落成事实；矩阵与判定位置**一个字不动**——
装载期第 5 条管这一格的形状，这一行管资格。

**不用否定模式，用正事实级联。** `owes: request(port) ∧ ¬permitted(key)` 会让
`¬` 进 `owes`，逼 `Pattern` 长出否定原子；而 `open` 的公式里本来就有"不存在 `until`"，
两者叠加会让"没有授权记录"与"被拒绝"在匹配上不可区分（fail-open 风险）。改成两行：

```
行 authorize  owes: request(port, id)
              until: authz.granted(id) | authz.denied(id)
              by: authorizer
              prio: 0     ← 必须早于 dispatch

行 dispatch   owes: request(port, id) ∧ authz.granted(id)
              until: sent(port, id, attempt) | failed(port, id)
              by: courier
              prio: 10
```

`authorize` 先还清（`prio: 0`）；它交回 `granted` 后，`dispatch` 的 `owes` 才成立；
交回 `denied` 后 `dispatch` **永不成立**（没有 `granted`），一个 `denied` 行负责把拒绝
说给用户。**没有否定原子、没有异常分支、没有"没写 = 不许"**：拒绝是一条写了的事实。
`key` 是 `id` 的取值；"主体 × 能力 × 资源"三维编码进 `id`（例如
`session/main#chat.assistant.final#turn-42`），匹配仍是等值，不需要引擎认识三个维度。

**级联落在细粒度端口。** 级联成立的前提是 `request` 携带**一个可判的能力维度**。
整轮 `turn` 往返不携带这个维度——在它上面按 Speech 授权会让「不持 `reply.*` 但持
产物能力」的主体连轮都跑不了。所以 `authorize` / `dispatch` 两行按工具批次端口声明：
那里的每次调用自带审批与权限面。

**为什么不做成 `drive` 里的前置检查**：那会让引擎认识「授权」这个业务概念，
且拒绝路径变成异常分支——义务环里没有异常分支，只有事实。

**三维判不升成引擎维度**：三维可以编码成 `key` 的取值，`Pattern` 只做等值匹配即可。
若将来需要"按维度分别匹配"（如"某主体对所有 artifact 的授权"），那是 `Pattern`
的键表达式问题，走新裁决——本形状不为它预留口子。

### 4.3 停机原因：统一到收束格的 `reason`，不新增载体

控制环的每次终止都必须落为事实，否则重启后无从知道为何停；并要区分策略终止 /
自然完结 / 兜底上界三种。义务环里没有 `Halt` 这个值。

**补法**：**不新增机制，把 `reason` 定为必填。**

| 终止 | 谁写 | 载体 |
|---|---|---|
| 业务判定终止 | 业务行 | 收束格 `{reason}` |
| 自然完结 | 业务行 | 同上 |
| 步数上界 | 引擎 | `{reason: exhausted, detail: step_limit}` |
| 无进展 | 引擎 | `{reason: exhausted, detail: no_progress}` |
| 规则缺口 | **不存在** | 装载期第 2 / 6 / 7 条已消除 |

**关键**：义务环里"规则缺口"不是运行期状态——`owes` 只有 `until` 一个去处，
装载期"每行收口"保证每种应答都有归宿。

`Verdict` 的三值（`Hit` / `Declined` / `Unmanned`）与 `every_site_is_manned` 只能回答
「这一格有没有行」，不能回答「这一行的 `owes` 有没有归宿」——**有行但归错行，
照样死循环。** "每行收口"（§3.4 第 2 条）补的就是这一档。

**检查**：审计断言收束格（`chat.assistant.final` / `chat.assistant.fallback`）的
`reason` 非空；缺则红。**`turn.closed` 只是本文档的概念名，不新增事件名**（见 §3.4 末注）。

**「在等」与「没事」是两个停机理由。** `open ≠ ∅ ∧ actionable = ∅` 时本轮停下来，
但停下来的原因不同：`waiting` 指有一笔**已派出未收清**的往返（`sent` 之后、`response` /
`failed` / `retry` 之前），`no_progress` 指真的没事可做。判据是 `loop_rows::waiting`，
它认的是**形状**（开账条件 = `sent`）而不是 `await-` 前缀——前缀是命名约定，改名就静默失效；
`await-<port>` 行的对偶形状与这条读者一起，才让它不成为装饰行（[D-130](022-行表与派发面.md "DE-022-行表与派发面")，
形状见 [DE-022](022-行表与派发面.md "DE-022-行表与派发面") §1.1）。

**"无进展"为什么不新增闭集值**：`ClosureReason::Exhausted` 的语义是"被上界掐断"，
步数上界与"一步没有推进"都是上界的一种；`detail` 才回答"哪一种"。闭集只回答"哪一类"，
不把可统计性让给自由文本（分工），也不为了一个细分值再改一次闭集。

## §5 覆盖边界

行表调度的是**还没还的债**，不是「轮」。这个边界有三处必须写明——否则看表会得出
「它应该被派发」的结论，而那条结论在产品路径上不成立。

### 5.1 定稿答话轮不进轮内驱动循环

有一类轮只欠判决：`classify` 判成答话的**定稿答话轮**（[D-125](015-义务环.md "DE-015-义务环")）。它在轮首 host
上还掉 `policy.classify` 那一笔就收束（结论折成 `turn_head.answered` 一格，[D-162](015-义务环.md "DE-015-义务环")
裁决 1），而压缩与召回的前件写着 `answered = false`，轮内那台 host 一步都不走；两条收束格由**轮首准备
就地**落（[D-162](015-义务环.md "DE-015-义务环") 裁决 2）。答话要么由模板产线出话（判决走规则，零模型往返），
要么其措辞由 `compose` 在轮首**之前**发起并已入账（`via=compose/wording`，那一笔不是本轮的债）。

`close` 执行体的「唯一写方」因此限定为「**驱动循环内**两条收束格的唯一写方」——
它约束的本来就是执行体之间的写集不相交，而不是「任何地方都不许写」。

### 5.2 轮外往返：没有轮号的模型调用

唤醒路径（例：用户点压缩失败节点上的重试）按定义不产生对话轮次。这类往返**没有**
`turn` 号，也没有幕锚（`Round` / `Compress` 的 `turn` / `produced_by` / `drive_seq`
三个字段），三格里写不下「这属于哪一轮」。硬凑一个轮号，等于让 `lease` / `retry`
去管辖一个引擎无法按轮重放的往返。

**裁决：明文出界，并用一条具名判据钉住边界**（[D-131](015-义务环.md "DE-015-义务环")）。
三个候选与它们为什么被否掉：

| 候选 | 裁决 | 理由 |
|---|---|---|
| ① 给「无轮的往返」一个入账面（`turn` 位放唤醒 id / 硬凑轮号） | **否** | 压缩折叠的是**跨轮**历史，它不属于任何一轮；硬凑轮号会让 `turn_slice` 把这次往返算进一个早已结束的轮的切片里，`lease` 去管辖一个引擎不会重放的轮——正是 D-122 决策 1 拒掉的形状 |
| ② 明文出界 + 具名判据 | **采纳** | 边界本身无害（它是**一条**已知路径，不是「随手打模型」的许可）；有害的是它**没有名字**——差额出现了却没人说得清是哪一笔 |
| ③ 给压缩重试造一个「最小轮」 | **否** | 与 D-125 的裁决冲突（环覆盖的是「欠着的往返」，不是「轮」）；为零对话的轮重开一条驱动，代价远大于收益 |

这条边界由一条**具名**的验收判据钉住，两半：未被解释的往返数必须 **≤** 具名唤醒
路径的计数（多出来的是「一条新长出的静默路径」，少了也判）；并且差额在往返对账里
以一个**具名项**出现，于是「又长出一条静默的模型路径」会当场变红，而「这次差额是
重试造成的」不需要人去解释。判据从**日志**里数，不依赖一张会腐烂的豁免表——
具名这件事由**代码位置**保证，不是文档承诺。验收实现见
[DE-016](016-工程落地与验证.md "DE-016-工程落地与验证")。

### 5.3 边界由名字与判据守，不靠措辞

这三条边界都不是「假设不会发生」：定稿答话轮由前件与准备路径的形状钉住，轮外往返由
具名差额判据钉住，流式帧由「帧不是事实」的类型边界钉住（§1 的分工表：执行与取证归 DE-016）。

## §6 判据

全部可执行，**零新增机制键**。

| # | 判据 | 检查方式 |
|:-:|---|---|
| 1 | 加一个端口 = **0 个新事实名** + 1 个 `PortDecl` + 适配器 + 2 行模板（第三行通用），**`drive` 与 `owed` 源码 diff = 0** | 源码级断言（本方案相对 DE-001「机制键守恒」的等价物） |
| 2 | 表里零代码 | 类型上：模式只有名字 / 字段等值 / 键绑定 / 比较 |
| 3 | 视图互不可见 | 类型上：`eval` 只接 `&[Fact]` + `now`，拿不到别的视图 |
| 4 | 依赖图无环；相交行对被报告 | 装载期 |
| 5 | 每行收口 | 装载期 |
| 6 | 字段都在声明里（模式 + `ViewDecl.reads`） | 装载期 |
| 7 | **清空整张表 ⇒ 系统仍完整**（`owed = ∅` ⇒ 永不前进） | 用例 `an_empty_row_table_owes_nothing_and_never_panics`：运行期 `owed(&[]) = ∅` 且不 panic；装载期一半由**第 7 道检查**执行——空行表 ⇒ 声明事实全成孤儿 ⇒ `seal` 拒绝（同一用例第二段钉住 `load(&[])` 为 `Err`，[D-141](022-行表与派发面.md "DE-022-行表与派发面")） |
| 8 | 事实的任意前缀都合法 | 用例 `every_prefix_of_a_session_log_is_a_legal_ledger`：27 格会话逐前缀截断重放，每段都确定、且追加一格无害事实不改账（拆批前先过粒度判据） |
| 9 | `produced_by` 不悬空且更小 | 装载期 + 审计 |
| 10 | 收束格 `reason` 非空 | 审计断言 |
| 11 | **每个控制面声明的事实名都有归宿**（某行以它为 `owes` / `until` / `unless`） | 装载期（接住 `Gap::UnmannedRow` 的可观测性） |
| 12 | **`owed` 输入闭包**：只读事实、视图、事件时间戳；不读配置、墙钟、内存缓存 | grep 源码（`ring.rs` 无 `SystemTime` / `Instant::now`）+ 用例 `owed_has_no_input_beyond_its_four_arguments`：隔过真实时间两次求值逐字相同，显式 `now` 动结论才动 |
| 13 | **执行体收口**：`by=Some` 的行，执行体 `writes` 与某条 `until`/`unless` 相交 | 装载期 |
| 14 | **无进展守卫**：每步后账本（日志尾段）必须非空，否则收束 `exhausted{no_progress}` | 用例 `an_actor_that_writes_nothing_stops_as_no_progress`（夹具绑定表，D-123 决策 4） |
| 15 | **写入顺序**：`user.message` 的 seq 早于本轮任何判决 / 阶段事实 | 用例 + 审计 |
| 16 | **租约可恢复**：只有 `sent` 没有应答的日志，重启后 `lease` 行能重试或判死 | 用例 `the_lease_row_opens_only_after_the_deadline`（只给日志，不给内存）；CLI 取证见 [DE-016](016-工程落地与验证.md "DE-016-工程落地与验证") |

判据 5 / 11 / 13 是三档，别混：**5 问"这一行的 `owes` 有没有去处"，11 问"这个事实名有没有人管"，
13 问"这个执行体能不能走到出口"**。三者各防一种静默失效：死循环、拼错的名字永不被消费、
执行体返回空导致环不前进。`every_site_is_manned` 只做到了 11 的更弱版。

判据 1 是本方案最硬的一条：它不是"机制键数不变"，是**这两段代码的字节不变**。
端口是载荷，所以新增端口不新增事实名。

判据 11 的"控制面声明集"是**交给 `Builder` 的事实**，不是全仓事实。业务事实的
读方是投影，强迫它们各挂一行会造出装饰行——那是把判据当指标，不是当护栏。

**判据的形状与退场规则不归本节**：哪条判据该留、该并入、该降为读数，由
[SP-033](../005-spec/033.md) 的六条终态判据与 `J0` 判决；本节只写**每条判什么**。

### D-120 声明表的进程级记忆化 ≡ 按会话注入：等价性建立在三条类型事实上

### D-121 唤醒事实的行语义：await 行的收清走协议格，审批与补充重新开账

协议五名是闭集（[DE-022-行表与派发面](022-行表与派发面.md "DE-022-行表与派发面") §1.2），端口是载荷。让一条 `(turn)` 键的事实去收一笔 `(port, id)` 键的债，等于给求解器加第二个匹配维度——那是判据 1「加端口 ⇒ `drive`/`owed` diff = 0」的反例。 「审批之后要重跑工具」的形状是「审批格落事实 ⇒ 重新开账 ⇒ 由行表派发」，不存在第二条执行路径。
### D-124 装载期第 6 条对派发行的改判——出口全为引擎格时判「执行体有登记」，不判「它写得出出口」

第 6 条要防的故障是「行被选中、执行体什么都不写、环不前进」。这个故障有两个可执行的拦截点：静态（名单里有没有这一行的出口格）与动态（账本尾段空不空）。静态那一个先把条文写成 ∩；[D-123](022-行表与派发面.md "DE-022-行表与派发面") 之后动态那一个存在并且更准—— 静态只能判「声明上够不够得到」，判不出「这次实际写了什么」。

**订正 1：这一档改判「有没有交出去的凭据」——名单非空，或出口里挂着某个端口的 `before` 格**

原文这一档判的是 `a.writes` 非空（不空即「执行体有登记」）。它对 `relay`（`dispatch-model` 的
派出执行体）成立——那一条的控制面失败路径真的落一条 `chat.assistant.fallback`，领域格在名单上。
它对**纯派发半**不成立：派出与收应答分处两个环步（[D-222](015-义务环.md "DE-015-义务环") 订正 2
的形状）之后，派出的那半手里只有一件事——**把这一笔交出去**。它落的 `sent` 是引擎格
（`PortDecl::before`，由 `port::begin` 写），而第 5 条禁止执行体把它写进名单；于是这一半的
名单必然为空，而旧判据判它「什么都没写」。

要求它声明一条领域格是**两条检查互斥**：第 5 条不许声明引擎格，第 6 条要求声明出口格——
出口全是引擎格时，没有任何一格能同时满足两条。所以旧口径的实际含义是「这一行永远不许接线」。

这一档因此改判两个条件之一成立即可：

| 凭据 | 形态 | 它证明什么 |
|---|---|---|
| 名单非空（旧口径，仍成立） | 执行体自己写得出领域格 | 它有领域事实要落 |
| **出口里有某个端口的 `before` 格**（订正 1） | 这一行挂上了一条**派出契约** | 关门链条完整：`check_ports`（§3.4 第 5 条）已经要求那条端口的 `response` / `failed` 落在某行的出口上，所以这一笔终局有着落；这一行只需要「把这一笔交出去」 |

这一档**不是豁免**：出口不是任何端口的 `before` 且名单为空的行照样红——那才是「注册了一段
什么都不写的动作」。判据由
`an_actor_serving_an_engine_exit_row_needs_a_write_or_a_port_contract` 三条断言钉住（旧口径
仍成立 / 纯派发行可接线 / 两样都没有则红）。

「这次真没写」那**一半**仍然归运行期判，两支各有各的探测器：领域格那一支看空账本
（`exhausted{no_progress}`），派出那一支看 `sent` 关不关账（`waiting` ⇒ 步数上界与 `reap`）。
静态判据只管「声明上有没有凭据」，运行期管「这一次写没写」——两条不是同一件事，不能互相顶替。

| 被否的候选 | 否掉的理由 |
|---|---|
| 把批次边界的汇报派发点（`chat.assistant.reported`）从收尾半挪进派出半 | 汇报时机变成「工具还没跑完」，[D-163](015-义务环.md "DE-015-义务环") 要的「往返进行中落地」在这一侧反而失真——为了让一条静态判据绿，改掉的是汇报的语义 |
| 为派出半造一条领域落格 | 今天没有这样的事实；为一个装载期判据造一格事实，是把判据的成本转嫁给事实面，而且那格还得真有人写，否则运行期写封闭对账（`D-123` 决策 1）多出一个永远不写的名字 |
| 保留旧口径（纯派发行的名单必须非空） | 与第 5 条互斥 ⇒ 这一行永远不许接线。四格全在收尾半（`waiter-tools` 的名单），派出半天然为空 |
### D-125 定稿答话轮不进轮内驱动循环——环覆盖的是「欠着的往返」，收束格由轮首准备就地落

环的覆盖范围是「欠着的往返」，不是「轮」。 行表调度的是还没还的债 （[DE-022](022-行表与派发面.md "DE-022-行表与派发面") §1.2 五事实、[DE-001](001-核心架构.md "DE-001-核心架构") §4.3 一环一表一源）。判成答话的一轮欠的只有判决那一行（`policy.classify`，轮首 host，[D-162](015-义务环.md "DE-015-义务环")），它跑完本轮就地收束，因此**进不了轮内驱动循环**（§5.1）。
### D-129 中断轮的终态不按 Turn 配对补——Turn 已退役，终态归骨架节点

### D-144 一行该不该存在：判据是「有没有一个跨步的等待方」，不是「这一族有没有代码」

[DE-090-过渡方案](090-过渡方案.md "DE-090-过渡方案") §1.1 步 4 要求工具、模型、提示词、挂载四族逐族迁入行形状。前两族有行，后两族
没有。补行还是裁决，取决于同一件事：**这一族有没有「欠」**。判据三条，缺一条就不是能力行：

1. 有一个**跨步**的等待方——这件事今天做不完，要等一个外部事件（模型应答 / 工具结果 /
   时钟）才继续；
2. 欠与还可以只用事实表达（`owes` / `until` 全是事件模式），不需要请求作用域状态；
3. 它有独立开关——关掉这一行，这一族的调用**不再发生**，而不是「发生但结果被忽略」。

按这三条过两族：

- **提示词组装**不满足 ①：它发生在 `execute` 行的执行体内部，输入输出都在一次模型往返的
  载荷里，没有任何跨步等待；也不满足 ③（不存在「关掉组装」这个状态，关掉就没有请求了）。
  它是 `execute` 的**载荷加工**，不是一笔债（D-115 决策 5：没有第二个调度器）。
- **挂载 / 选项**不满足 ①：挂载是**装配期声明**——容器在一次遍历广播里登记自己的根行，
  子目录则完全由组合视图现场算出，运行期没有「等挂载完成」这回事。它属于装载期检查的
  形状，不是运行期债。

所以两族的终态是**不进环**，步 4 的判据随之改写（目标判据的改写属过渡方案允许的范围）。

**挂载族读口的终态：只留根位，按名的那两个读口退场。** 写侧与读侧要对称——按名登记的挂载行
没有任何生产读点，它答的问题（「哪个目录由谁提供」）已由组合视图（`CompositeVdfs`）与
`Plugin::get_vfs_provider` 按**同一个判据**现场算出，不需要收集期那次广播维持第二份；而可见域
裁剪不在这一层（它是地址解析 `hidden` / `resolve` 的事，清单做集合减法会把「看不见」与「没装」
抹成同一件事）。这条事实的终态、理由与代码名归 [DE-009-VDFS规范](009-VDFS规范.md "DE-009-VDFS规范") §6.1——
本条只裁「挂载族不进环」，不复述那一族该怎么读。

| 被否的候选 | 否掉的理由 |
|---|---|
| 为「四族齐全」补两行 prompt / mount | 没有等待方就没有「何时欠」，行只能靠请求作用域状态判，违反第 2 条；这就是「为看起来完整而硬造行」 |
| 给 `capability_mounts` 接可见域裁剪 | 裁剪属于地址解析（`hidden` / `resolve`），不属于清单；清单做减法会把「看不见」和「没装」抹成同一件事 |
| 保留并继续写「落点 = S3 第 7–8 步」 | 那两步所在的计划已归档，落点不可施工；「有落点」变成一句安慰 |
| 把 prompt 组装做成 `compose` 的能力行 | `compose` 的往返是模型端口的一次调用，已经在 `dispatch-model` / `await-model` 里；再加一行是同一笔债的第二个名字 |
### D-159 外环收编的形状：host 是执行体的借用面，行按 host 归属，选债仍只有一个求解器

这条裁 [D-158] 留下的前件。**host 不是新的机制词，是一次执行体调用里被 `&mut` 借走的那片可变状态**：
轮内（`Turn`）借走本轮草稿，轮首（`Head`）借走本轮状态与会话上下文，批次边界（`Report`）

| # | 裁决 | 立它的理由（也就是被否的那一种形状） |
|---|---|---|
| 1 | **行按 `by` 归属，归属不写在 `Decl` 上**：一张绑定表，条目是 `(ActorDecl, 动作)`；`by` 在表里就是有人跑，不在就是 `UnmannedRow` | 在 `Decl` 上加 `host` / `owner` 字段就是两处 owner——「谁跑它」与「它归谁」可以互相矛盾而装载不红。**一张表而不是「一台 host 一张」**：表数由 `run` 的签名个数唯一决定，签名统一之后第二张表是编译错误（D-222 裁决 5） |
| 2 | **一张行表 + 一张绑定表**：派发点把整张行表交给 `ring::drive`；「这行现在能不能跑」只由 `by` 在不在表里判定 | 求解器字节不动（判据 1 / PTS-003）。不再派生行子集：子集是「一台 host 该看哪些行」的产物，一台 host 之后它恒等于整张表，留着只会让人以为还有第二个 owner。`prio` 仍是全局序——一张表下它退化成「同一刻多笔债的次序」，这正是它的本义 |

| 4 | **执行体不交回产出**（D-123 决策 5 照用）：轮首执行体只 `&mut` 借走本轮状态与会话上下文，三份产物寄存进本轮状态、由编排层收工时取；**出口那一格由执行体自己落** | 允许返回 `TurnExit` 就是让编排层按返回值分支——选债权回到外层（D-118 决策 1–2）。出口格若也寄存，派发点在本幕的第二次选债照样读到「没做过」⇒ 同一笔债再还一遍。本条只裁五行怎么接回，不裁七步本身（那是外环，前件见 [D-158]） |

**五行归位（按借用面，不按归属）**：`classify`(10) / `compress`(30) / `recall`(40) / `reflex`(50) 的动作要改

模型往返共用同一次借用。这些差别是**这一次动作借走了什么**的差别，不是**谁拥有这些行**的差别：
一张表、一个签名（D-222 裁决 5）。`reflex` 的出口与收束分工见 [D-164]。

> 标题里的「行按 host 归属」已作废：归属只有一处——`by`。host 不再是声明面，它退化成一次动作借走的那片状态。
### D-160 依赖图的边按**出口格**配：视图按输出证据集展开，同族不同档不成边

### D-222 幕是环的身份，不是端口也不是债：控制面收成一个环、一张表

本条**先删后裁**。删掉的三处形状互相矛盾（幕是迭代器 / 幕是一个端口 / 一台 host 一张表），
它们的错误是同一个：把「一次借用跨了几步」这个 Rust 事实升格成了调度结构。替代形状只有一条。

**被删的表述（删除即失效，不再约束任何形状）**

| 被删的表述 | 出处 | 为什么必须删 |
|---|---|---|
| 幕是迭代器：`open_stage` → `while stage_next(..)` → 判停 | D-168 全文 | 两个循环体、两个选债入口。`TC-1` 说「只有一个循环体」，它从第一行起就不成立 |
| 「端口（本轮执行 / 模型 / 工具 / 时钟 / 存储）全部同构」 | DE-022 §1.2 | 五个里只有两个是真端口；`turn` 的应答载荷为空、适配器是内环、`awaited = false` ⇒ 它不是往返，是重入 |
| 「一个 host 一张绑定表，行的 `by` 落在哪张表就住哪台 host」 | D-159 裁决 1–2 | host 是借用面的别名。把借用面升格成调度面，第四台 host 就是它的必然结果 |
| 「`Turn` 按借用面拆成轮内 / 批次边界两片，绑定表三张」 | D-163 裁决 1 | 同上；借用面改成按步获取之后，「拆片」没有对象 |

#### 一、端口闭集

> **端口** = 一次跨出控制面的往返：派出（`sent`）与应答（`response`）之间，控制面**不持有**对方的任何状态。

按这条定义，今天只有两个端口：`model`、`tool`。三个被排除的：

| 候选 | 排除的理由（都可核） |
|---|---|
| 本轮执行 | 应答载荷为空（派发点传的是空值闭包）；`awaited: false`、`max_attempts: 1`（只会判死，永不重试）；适配器就是内环自己（`execute_turn` → `drive_steps`）⇒ 它是**重入**，不是往返 |
| 时钟 | `now` 是 `owed` 的入参（D-115 的输入闭包），没有派出动作，也没有应答 |
| 存储 | `Store` 是同步能力（`range` / `append`），两段在同一次调用里，没有「派出之后控制面撒手」的区间 |

由此得到一条**可判**的加端口判据：**新端口若需要一台 host 或一段循环才能跑，它就不是端口，是环的一部分。**

#### 二、幕是身份，不是推进

幕 = 事实信封上的 `turn` + 视图的成本界（`turn_slice`）。这两处之外，机制层不认幕。

| # | 裁决 | 立它的理由（也是被否的那一种形状） |
|---|---|---|
| 1 | **开一幕是交换点，不是环**：`begin_drive` 落用户格或恢复格，环从那一刻起才有账 | 用户消息 / 审批恢复是「外部把人话变成一笔请求」（DE-001 §4.3）：**有入口没有前件**，所以它不属于环。做成迭代器就要在环里判「该不该开」，那正是自指 |
| 2 | **幕的推进是一笔债**：`continue-turn` 一行，`owes` 取 `turn_next_round` 的 `{round: N+1}`，`until` 是那一格 | 轮已经存在，「再跑一段」就有完整的前件（`closure = exhausted` ∧ 轮次未到上限）与出口（新的 `round` 格）。判据 2 要的就是这个：流向由事实决定，不由步骤号决定 |

**三条可判断言（各配一个反向用例，改坏必红）**

| # | 断言 | 反向用例 |
|---|---|---|
| A | 行表里没有以幕命名的行；`PORTS` 的每一项都能指出「派出去之后控制面撒手了哪一段」 | 加一条 `open-stage` 行；或把时钟声明成 `PortDecl` |
| B | **选债口只有一个**，且控制面只有一个 `loop`，五道守卫都在它的函数体里（第五道由签名守） | 在编排层再写一段 `loop { drive(..).await? }`；或在派发器之外直问 `ring::owed` 再自行派发；或让某个动作拿得到第二份 `&mut Session`。**本条兑现后无实例**：`port::reap` 已改读 `stale_sent` 视图（看护不是还债，`lease` 行随之删除）；`port::round_trip` 不直问求解器，身份由入参定死，它自己落 `request` 是**重入**的记账（`awaited = false`、付款方是闭包），与 §一 判 `turn` 不是往返同一条理由 |

**这一条没有解决什么（诚实划界）**

1. **`TurnState` 仍是整轮编排容器**：它装着请求轮次、落库锚点、中止信号与十来格读侧产物。本条只把它的借用从「跨步」改成「按步」。
2. **表外的点问**（`classify_round_trip` / `wording_round_trip`）不在射程：一个环里没有「表外点问」的位置，但它们的消失要靠各自那一段行化。
3. **`turn_head` 的体量不在射程**：它是幕内状态的折叠。幕从「推进单位」降成「身份」之后它会缩，缩多少由归一后的行去定，不由条文定。
4. **三处静默退化**，各自要一条裁决，不许在实现里顺手改：工具批次的 `expand` 元素仍串行派发（与 §2.8「`concurrent: true` 时同批子债可并发派发」不一致）；~~视图 `cost` 超界时静默回空集（"算不出来"与"没有欠账"同形）~~ —— **已收口**，见下面的订正 1；`await-*` 的 `sent` 与 `response` 落在同一个动作窗口内，两次选债之间恒假（在途不可观测）。
5. **兑现顺序是两步**：先删端口与第四台 host（可独立回退）→ 再把一张表、一个签名、一个环并出来。
   守卫归一是第 2 步的**结果**，不是独立可做的一步：守卫同处的落点是那个唯一的循环体，
   而唯一循环体的前提是一张表一个签名——把守卫单独提前，只能得到"三处调用同一个函数"，
   选债口仍有三处，`TC-1b` 照旧红。两步各自可绿，不许合成一次改动。

**订正 1：视图 `cost` 超界不再冒充「没有欠账」**

上面「这一条没有解决什么」第 4 条点名的三处静默退化，第一处在这里收掉。它的形状是：
`Frozen::eval` 在事件条数超过视图声明的 `cost` 时回 `None`（求值侧**不**静默），而
`ring::owed` 把这个 `None` 折成空集（`_ => Vec::new()`）——于是「算不出来」与「没有欠账」
在 `owed` 的返回值上同形：那一轮**整张表**的行都不开账，环看起来无事可做，零告警。

`owed` 的字节是基线（判据 1：加端口 = 改引擎 0 行），所以修法两头都不在它里面：

| 半边 | 终态 | 为什么 |
|---|---|---|
| 切点只有一个真源 | `Frozen::scan_bound()` = 全表最小的 `cost`；`turn_slice` 与 `lease_tail` 都从它取，不再各自抄数 | 一份切片喂给每一条视图 ⇒ 上界只能是同一个数。「手抄同值」不是同步：任一侧单独改动，另一侧就静默失效，而失效的形状正是上面那条 |
| 声明的分歧在装载期红 | `Gap::ViewCostMismatch` | 运行期没有第三种解法：按大的切，声明小的那族每轮回 `None`；按小的切，声明大的那族静默漏账。两支都是「算不出来」冒充「没有欠账」，所以它不许存在 |

切尾而不是报错，是因为失效方向不对称：切掉的是一轮里更早的事实，缺席的是 `request`
（那一笔债还不上，环空转、可见），而 `response` 总在尾部（漏还账才是不可见的那一头）。
超界时留一条告警，写明超了多少、上界是多少、该调 `cost` 还是该拆轮——静默降级正是本条要收的那一格。

判据由四条用例钉住，两两成对（`an_over_bound_slice_makes_the_views_uncomputable` 先证明
缺口真实存在，`a_trimmed_turn_slice_leaves_every_view_evaluable` 再证明切点堵住了它；
只留后一条的话，把上界调到无穷大也能绿）。

**订正 2：`await-*` 的 `sent` 与 `response` 分处两个环步（在途可观测）**

第二处静默退化的**终态形状**。缺口是：`sent` 与 `response` 落在同一个动作窗口
（`port::dispatch_full` 把 `run().await` 包在中间），所以在两次选债之间，「已派出、未收清」
在环里读不出来——`waiting` 只在**崩溃恢复**的输入上才有值，正常跑里恒假。

## 为什么「把 dispatch 拆成两行」不是改行表就够

直觉解法是把 `dispatch-*` 的出口从 `response|failed` 改成 `sent`，让它落完就返回，
由 `await-*` 收尾。但这条路会撞上一个死结，两半都走不通：

- **`await-*` 保持 `by = None`**：它不可还 ⇒ 环下一圈选不到任何债 ⇒ `drive_steps` 落
  `exhausted{waiting}` 结束本幕 ⇒ **那次往返永远收不回来**（模型已经发出去了，应答扔了）。
- **`await-*` 改成 `by = Some(poll)`**：那就得先回答「poll 什么」。应答由谁持有？

所以终态的**类型前件**必须先立：一个 **in-flight 槽**，`dispatch-*` 把「发出 + 等应答 +
落 `response`」整段 `async move` 包成 future 寄存进去，`await-*` 的动作 poll 它一次。

## 借用面为什么这次能过去（与 D-222 §一 的判据同源）

寄存 future 的经典障碍是自引用：future 借草稿、草稿又要存 future。这一条**不成立**——
`call_model` 交给 `dispatch_full` 的闭包是
`|| llm.generate_turn(tok, messages, tools, sink.clone())`，它捕获的是 `llm` / `tok` /
`messages` / `tools` / `sink` 五个**参数**，**不捕获 `&mut Prepared`**（`run` 只被读
`turn` / `drive_seq` / `user_seq` 三个 `Copy` 字段，都在闭包外取好了）。

**订正：槽是 `'static` 的，草稿不带生命周期参数。** 走到「槽带 `'a`、`TurnSession` 带
生命周期参数」那一版会在落地时卡住，原因不在自引用，而在**动作的类型**：

`Action = for<'a> fn(&'a mut TurnStep<'a>) -> StepFuture<'a>` 是 HRTB。`TurnSession` 一带
生命周期，`TurnStep` 就成了双生命周期结构（`&'a mut TurnSession<'b>`），那个 `for<'a>` 必须
对**两个**生命周期成立，而绑定表只给得出一个可调的名字。这不是语法修补能过去的。

所以出路不是给草稿加参数，而是**把借用消灭掉**：`TurnStep` 的端口全部改成可克隆句柄——
`Arc<dyn Store>` / `Arc<dyn LlmAdapter>` / `Arc<[CapabilityMeta]>` / `Arc<dyn DeltaSink>`，
以及零大小的 `FullModel`（`Copy`）。仍借的只有两样：`session`（本轮草稿，派发器持有）
与 `dispatch`（工具分发方，它自己就在派发动作的栈上）。于是 future 捕获的每一样都是
owned，槽就是 `Option<Pin<Box<dyn Future<Output = …> + Send + 'static>>>`。

`FullModel` 加 `Copy` 不放松闸门：签发点仍是 `TokenIssuer` 唯一一处（`mint` 私有）。令牌
证明的是「持码者处于哪一档」，不是「哪一个变量持有它」——复制只是让**已签到手的档位**
能随一次派发搬进 future。

这条订正顺带解开了「先把三种 `Step` 收成一个 `Ctx`」那个借用面死结：`Ctx` 不必先立，
本任务可以独立做完。

## 三处随之一并改的语义

| # | 改什么 | 为什么不能只改一处 |
|---|---|---|
| 1 | `dispatch-*` 的出口 `response\|failed` → `sent` | 落完 `sent` 这一笔就该还清；出口不改，它永远欠着，环会反复选中它 |
| 2 | `await-*` 的 `by`：`None` → `Some(poll)` | 否则环停（见上）。**`by = None` 从此不再表示「在等」**——「在等」的唯一表达回到它本来就有的那一处：`waiting` 视图（`sent` 有、`response` 无）与 `exhausted{waiting}` 这个停机理由（`D-126`）。`by = None` 只剩它字面的意思：「这一笔不由引擎执行」 |
| 3 | `no_progress` 守卫：poll 返回 `Pending` 算**有进展** | 否则第一步就判死。这是 `TC-1c` 第四道守卫（空账本）与「在途」的区分点：环合法地不前进（等 I/O）不等于环没账可还 |

## 落地时的四处连带（都由第 1–3 条推出来，不是新的裁决）

| # | 连带着 | 为什么躲不开 |
|---|---|---|
| 4 | `turn_head.model_open` 的**关账格**从 `sent` 挪到 `response` / `failed` / `retry` | 第 1 条一落地，`sent` 就不再表示「这一圈过去了」。按旧口径，派出一落 `sent` 执行行（60）立刻重新欠账、抢在 `await-model`（71）之前再宣布一笔——同一步号的幂等键撞上，那一圈零写入，环读成 `exhausted{no_progress}`。关账口径与 `open_calls` 同源，「在等」在派生面上只有一份定义 |
| 5 | `waiting` 改成**按形状问**（`open_calls` 非空），不再看「哪一行 `blocked`」 | 第 2 条一落地，`blocked` 就不再携带「在等」——`await-*` 是可还的债。剩下来的唯一写法是形状本身 |
| 6 | 步数上界**不在一笔往返没落地时生效** | 一次往返占两个环步，上界可能正好落在「已派出、未收清」那一圈。此时停机会留下一条 `sent` 无终局——重启后 `reap` 要判死一笔**其实已经答了**的往返，而钱已经花过。判据同样是形状（`waiting`），不是行名 |
| 7 | `await-*` 与同端口 `dispatch-*` **不许共用执行体名**（取代原先的「`by = None`」） | 原先那条禁令防的是「一个动作两副身份」，不是「等待有人跑」。等待接成可还的债之后，作用点落到名字上 |

第 6 条同时解释了为什么这条判据的**反向用例**只能是「有没有在途」，不能是「poll 了几次」：
`poll` 一次与 `await` 到底在结果上同形，差别只在窗口——所以钉「那一圈零写入不被判死」，
而把「窗口没合上」交给 `waiting` 自身的观察点（每写一格就问一次）。

## 判据

- `waiting` 在正常跑的窗口里**该真时真**：`sent` 落了、`response` 未落的那一圈，环读到
  `waiting = true`，`stale_sent` 在租约到点后变真、`reap` 判死或重试（`D-138`）。
- **反向用例**：把派出与应答挪回同一个动作窗口（即今天的 `dispatch_full` 形状）⇒ 该判据红。
  这条反向用例必须真的能被写出来并变红，否则「可观测」只是散文。落地形状是一个**装饰
  事实源**：每次 `append` 之后按那一刻的日志问一次 `waiting`，一轮正常的模型往返必须
  在某一刻为真（`an_in_flight_round_is_observable_between_selection_rounds`）。
- **第二条反向用例**（`no_progress` 那一头）：去掉空账本守卫里的「有没有在途」半句 ⇒
  一个**正常**的模型往返被判成 `exhausted{no_progress}`，
  `a_round_still_in_flight_parks_the_ring_instead_of_killing_it` 变红。

## `tool` 端口那一半：与 `model` 端口同形（`D-124` 订正 1 之后兑现）

「两个端口必须同形」这条要求现在**两个端口都兑现**了：`dispatch-model` / `dispatch-tools`
的出口都是 `sent`，`await-model` / `await-tools` 都接上了执行体，派出与收应答分处两个环步。

`tool` 端口这一侧比 `model` 侧多两件事，形状因此略有不同：

1. **一批 N 笔，不是一笔**。`await-tools` 的键取 `(port, id, attempt)`（D-138）：重试后新
   attempt 的 `sent` 要重新开一笔等待，而不是被旧 attempt 的应答关掉。
2. **收尾半还要落业务事实**。产物（`artifact.added`）、等待进展（`chat.assistant.progress`）、
   轮内注入（`turn.supplemented`）、批次边界汇报（`chat.assistant.reported`）全在收尾半——
   所以 `courier`（派出半）一条领域格都不写，四格全归 `waiter-tools`。这正是
   [D-124](015-义务环.md "DE-015-义务环") 订正 1 要放行的那种形状：**派出半的凭据是它挂上
   的那条派出契约，不是它的名单**。

两个执行体不共名（`courier` / `waiter-tools`）：共名就等于让一个动作按「现在是第几个环步」
分支，那正是绑定表要消灭的东西（D-118 决策 1–2）。

名字取 `waiter-tools` 而不是别的，是按**族际对称**裁的：`model` 端口那一对是
`relay`（派出）/ `waiter`（收回），`tool` 端口这一对因此取 `courier`（派出）/ `waiter-tools`
（收回）——**派出半用信使词，收回半用等待词**。这样两个端口的名字表在读的人眼里是同一族，
而不必先知道哪条行接哪个执行体才能对上。

`deny-tools` 也归 `waiter-tools`：被拒的那几笔的终局（`failed{why}`）由批尾关账写出，而批尾
就在收尾半；派发半在拒绝路径上一格都不落（`begin_calls` 只写放行的那些）。

- `check_ports`（§3.4 第 5 条：每个端口的 `response` / `failed` 必须落在某行的出口上）在
  拆分之后仍须成立——出口从 `dispatch-*` 搬到 `await-*`，判据本身不改。

### 「槽空」的两条出路

收尾半被选中而槽里没有在飞的那一批时，有两种处境，处置不同：

1. **这一批没有跨边界的往返**（一批全被拒 / 唤醒的用户结果）：结论本地可算，起批之后直接
   跑到完——那一条路上没有「在等」这一圈可言；
2. **等待方随进程没了**（日志上有 `sent`、草稿里没有批次）：按与 `kill_dangling_round`
   同一条处置判死（`kill_dangling_sent`，`why = "no_pending_batch"`），不猜、不重放。

判死不重试的理由与 `model` 端口逐字相同：等待方是那一刻的栈帧，它已经不存在了。租约看护
（`reap`）对同一形态的处理是「等到期再判死」——那是**同一个结论的更早时点**，不是两套处置。

## 边界

- **这不是「超时即失败」**：判死仍归 `reap` 与 `D-138` 的两条前提（`awaited` ∧ 未到上限）。
  本条只让「已派出、未收清」在事实面上可见。
- **不动 `D-115` 的时间模型**：`now` 仍只有一个来源（幕锚 `ts`）。于是「等了多久」在轮内
  不流动——这不妨碍「有一笔在等」可读（那是 `waiting` 的事，「多久」是 `stale_sent` 的事）。
  被判死的仍是**上一个幕**遗留的在途，不是本轮正在等的那一笔。要让轮内也判死，得先给
  `now` 第二个来源，那是另一条裁决。
- **不改 `ring.rs`**：拆分动的是行表与派发器，`owed` / `drive` 的字节不变（`PTS-003`）。

**订正 3：草稿先于第一次选债——`Ctx` 只有一个生命周期，字段面在幕首填满**

缺口：`Ctx` 要当「那一次动作借走的那片状态的**超集**」（裁决 5），而三处可变借用
（`&mut TurnSession` / `&mut SessionContext` / `&mut TurnState`）在同一幕里并不同时存在。
今天的 `run_stage` 是「备输入（末尾起轮首那台 host）→ 跑一轮（`TurnRunner::begin` 在这里
才产出草稿）→ 收好产出」，**轮首四行跑的时候草稿还没建**。

裁决按终态判：**草稿在幕首就建**（`begin_drive` 之后、任何选债之前）。`Ctx` 里 `session`
是 `&'a mut TurnSession`（**不是** `Option`），轮首四行不再挂在 `prepare` 的尾巴上，
而是那个唯一环的**开头几步**。三条理由都是终态判据，不是实现便利：

| # | 终态判据 | 它否掉什么 |
|---|---|---|
| 1 | `TC-1a` 判**循环体的份数**。轮首四行留在 `prepare` 里派发，那个派发点就是第二个选债口——`Ctx` 合得再干净也不成立 | 「先合 `Ctx`，派发点以后再收」 |
| 2 | 裁决 8 要求中止守卫**在环里**。守卫在环首 ⇒ 环开始于任何动作之前 ⇒ 草稿必须在它之前存在 | 「先按今天的时序合字段面」 |
| 3 | 裁决 8 同时否掉用运行期断言补类型洞：`Option<&mut TurnSession>` 会让每个轮内动作写一句 `expect("轮内动作必有草稿")` | 「`Option` 换零行为变化」 |

**「被中止的幕不再跑判决 / 压缩 / 召回」不是这次改动的副作用**：它是「守卫在环首」的直接
后果，在终态里本来就该这样。反过来，把守卫留在备输入之后才是要解释的那一种。

被否的第三条路（轮首四行搬进环、草稿仍在 `run_turn` 里建）不成立：它要求环跨过 `prepare`
的边界，而 `policy.compress` 的产出在 `prepare` 结束时被取走（`consolidation`），搬动会改
「压缩影响哪一幕」的语义。草稿提前之后这一条自动消失——`prepare` 不再派发，只备输入。

代价写明白：`begin` 提前之后，中止 / 失败两条收尾路径的**入口**提前了一整个备输入段。
这不妨碍回退：`begin` 的产出本来就分两支（`Done(outcome)` / `Run(session)`），提前只是让
`Done` 那一支在备输入之前返回，它落的事实（用户格 / 中止收束格）一个字不变。

| 被否的候选 | 否掉的理由 |
|---|---|
| 保留 `turn` 端口，只把它「降级」成不重试的闩 | 闩不需要 `request` / `sent` / `response` 三格事实：没有应答载荷、没有跨进程等待。用协议往返表达一个闩，是在事实面上为「没有信息」造三格 |
| 保留幕的迭代器，只把守卫抽成公共函数 | 抽出来的仍是第二段循环的一部分。`TC-1` 判的是**循环体出现次数**，不是守卫代码的份数 |
| 把 `continue-turn` 留在循环里（读 `closure` 分支） | 那是 D-168 裁决 4 的形状：判定点回到代码，选债权回到外层 |
| 为「一个环」把借用面改成 `RefCell` / 内部可变性 | 用运行期借用检查换类型层保证：`BorrowMutError` 从编译期错误变成运行期崩溃，而崩溃点在动作中间——回放接不回来 |
| 让 `await-*` 保持 `by = None`，靠环停（`exhausted{waiting}`）等下一个幕 | 环停就收不回应答：模型已经发出去了，`response` 永远不会落，那一笔在事实上永久在途。它把「在等」做成了「放弃」 |
| 给 `now` 加第二个来源（轮内心跳事实）让租约在轮内到点 | 那是一条**时间模型**的裁决（`D-115` 的输入闭包），不是「在途可见」的实现手段。两者的代价差一个量级：前者每步落一条事实，后者只改动作的边界。而且在途不可观测的根因是「派出与应答同窗」，不是「now 不动」——`waiting` 本来就不需要 `now` |
