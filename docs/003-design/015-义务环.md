# 义务环

> **一句话**：一个会话收事实、算欠账、还债、再收事实。**没有别的。**
>
> 本文是 [DE-001 §4.4](001-核心架构.md "DE-001-核心架构")「义务环」的机制细则：
> 债的形状、行表的声明面、引擎与插件的契约、装载期检查与判据。
> 控制面的总纲（一环 · 一表 · 一源）在 DE-001；施工路径与现状差距在
> [DE-090](090-过渡方案.md "DE-090-过渡方案")；判据的执行与取证归
> [DE-016](016-工程落地与验证.md "DE-016-工程落地与验证")。

## §0 结论先行

1. **控制面只有一个环。** `drive` 每步问表、取最小可还债、运行、对账，直到无债 ⇒ 静息；
 没有第二个调度器。
2. **一笔债 = `owes ⇒ ◇ until` 的当前违例 + 「谁该还」。** `by` 只有 `Some(执行体)` 与
 `None`（恒 blocked）两种取值；决策债 / 搬运债 / 等待债是用法，不是机制。
3. **内环倒置 = 三组行**：模型请求、工具批次、轮收束。三组行复用
 `request` / `sent` / `response` / `failed` / `retry` 五个协议名，**不新增事实名**。
4. **流式不是债。** 流式帧走 `ExecEventSink` 直通，不改变事实面；债只描述请求 / 应答 / 失败。
5. **工具批次是集合，不是单项。** 一次模型响应可带多个工具调用；一个 `tool` 债的
 `expand` 把批次展开成元素，元素之间并发。
6. **粒度是参数，不是机制。** 加一个端口 = 0 个新事实名 + 1 个 `PortDecl` + 适配器
 + 2 行模板（租约行通用），`drive` 与 `owed` 的源码不变（判据 1）。

## §2 目标形状

### 2.1 四步

```
① 收到事实 → 追加进日志
② 算欠账 → 从日志算出"还欠什么"，取最小的一笔
③ 运行它 → 交给一个执行体，它把领域事实直接写进同一个 store
④ 对账 → 引擎读回这一次动作写进日志的那一段，回到 ②
```

④ 出现两次：填了 `before` 的行在运行前先落一条标记（`sent`），运行后读回尾段对账。
**执行体不交回事实清单**（写不经过返回值，形状裁决见
[D-123](015-义务环.md "DE-015-义务环") 决策 1、5）——它交回的只有"成功 / 失败"。

```rust
impl Session {
    async fn on_event(&mut self, e: Fact) -> Result<(), EngineError> { // ①
        self.log.append(e)?;
        // now 取**这条事件的时间戳**，不在 owed 里读墙钟（D-115 决策 1）。
        self.drive(e.ts).await
    }

    async fn drive(&mut self, now_ms: i64) -> Result<(), EngineError> {
        let mut steps = 0;
        loop {
            if self.abort.aborted {
                self.log.append(closed(ClosureReason::Interrupted, "abort"))?;
                return Ok(());
            }
            if steps >= MAX_STEPS_PER_DRIVE { // 步数上界
                self.log.append(closed(ClosureReason::Exhausted, "step_limit"))?;
                return Ok(());
            }
            let Some(d) = self.min_debt(now_ms) else { // ② 无债 ⇒ 静息
                return Ok(());
            };
            let before = self.log.head()?;
            if let Some(k) = d.decl.before { // ④a 前置标记
                self.log.append(Fact::envelope(k, &d.key))?;
            }
            match self.actors.run(d.decl.by, &d, &self.abort).await { // ③
                // ④b 账本 = 日志尾那一段（引擎读，不由执行体自报）：写已经在 store 里，
                // 引擎不再二次落格。见 §2.3「账本是日志的一段」与 D-123 决策 1。
                Ok(()) => {
                    let ledger = self.log.range(before)?; // 这一次动作的实际写入
                    self.reconcile(d.decl.by, &ledger)?; // 名单 ⊆ 声明的写入封闭
                    // 本轮收没收也读这同一段：出现停机格（或收束于等待用户那一格进展）
                    // ⇒ 收工，产出从草稿取——执行体不交回 outcome（D-123 决策 5）。
                    if ledger.iter().any(|e| self.ends_the_drive(e)) {
                        return Ok(());
                    }
                }
                Err(e) => self.log.append(Fact::failed(&d, e))?, // 失败也是事实
            }
            if self.log.range(before)?.is_empty() { // 空账本 = 无进展
                self.log.append(closed(ClosureReason::Exhausted, "no_progress"))?;
                return Ok(());
            }
            steps += 1;
        }
    }
}
```

**没有别的调度代码。** 七个词里"优先"与"前置标记"就落在这两处。四个不是第八个词、
但必须由引擎承担的动作是：**读触发事件的时间戳**、**写 `sent`**、**写 `failed`**、
**在步数上界 / 无进展 / 中止处写收束事实**——它们都是"执行者交不回事实时，引擎兜底
把状态变化落成事实"，不引入任何业务判断。

> **`now_ms` 只能来自触发事件。** 没有事件就没有 `drive`，因此"静默 30 秒该汇报了"
> 这类时间条件只在**下一次有事件**时被求值。若需要独立定时唤醒，那是唤醒源
> （[DE-001 §6](001-核心架构.md "DE-001-核心架构") 事件网格）的一条事实，不是让 `owed`
> 去读墙钟。**墙钟进入日志的唯一合法通道**：唤醒方（启动 / 心跳 / 插话接收）在落那条
> 唤醒事实时读一次墙钟写进它的 `ts`——此后本次 `drive` 的 `now_ms` 就是这个 `ts`；
> 崩溃重启的租约求值（判据 16）走的也是这条通道。

### 2.2 债

> **一笔债 = 一条 liveness 性质 `owes ⇒ ◇ until` 的当前违例，外加"谁该还"。**

```
open(d, key) := ∃ f ⊨ d.owes ∧ key = bind(f) ∧ ¬∃ g ⊨ d.until ∧ key(g) = key
blocked(d, key) := d.by = None ∨ ∃ h ⊨ d.unless ∧ key(h) = key
actionable(d,key) := open ∧ ¬blocked
min_debt(now) := min { (d,key) | actionable } 按 (prio, name, key) 全序
```

`owes` / `until` / `unless` 的匹配对象是**事实与视图**。时间不进公式：需要时间的条件
（"静默够久了""租约过期了"）由视图把 `now` 折成一个**布尔字段**，行只匹配
`report_due{due:true}` / `stale_sent{stale:true}`。因此 `owed` 本身仍是一个
`(&[Fact], &[View], i64) -> Vec<Debt>` 的纯函数——`now` 是入参，不是它去读的墙钟。

**`prio` 是全局的，不是格内的。** 义务环只有一个环、一次取最小，跨行必须可比：
权限行（`prio: 0`）必须早于派发行（`prio: 10`），轮首判决必须早于执行行。
同 `prio` 的并列由 `(name, key)` 决出，**不依赖注册顺序**（顺序是数据，不是插入顺序）。

**`by` 只有两种取值，引擎只有一个动作：**

| `by` | 引擎做什么 | 谁负责不阻塞 |
|---|---|---|
| `Some(名字)` | 到绑定表查那一个动作、跑它；写了什么由引擎读日志尾段（§2.3） | **那个执行体自己** |
| `None` | **什么都不做**——恒 blocked，永不选中 | — |

"决策债 / 搬运债 / 等待债"是**用法**，不是机制：`by` 指向纯函数叫决策债，
指向 `courier` 叫搬运债，是 `None` 叫等待债。**三者在 `drive` 里走同一行代码。**
同步与异步是执行体的实现细节，**不在协议里**，引擎也没有能力管（代价见 §3.4）。

### 2.3 表与两行主模板

一行 = 一笔可能欠的账：

```rust
struct Decl {
    name: &'static str,
    owes: Pattern,
    until: &'static [Pattern],     // 任一命中即视为还清
    unless: &'static [Pattern],    // 任一命中即挂起
    expand: Option<(&'static str, &'static str)>, // (列表字段, 元素键字段)
    by: Option<&'static str>,      // None ⇒ 无执行体，恒 blocked
    prio: u8,
    tier: LatencyTier,             // 这一行动作允许的时延档
}

// 端口级的东西按端口声明一次，不写进行里（写进去就是三份会漂的副本）。
struct PortDecl {
    port: &'static str,
    before: &'static str,          // 引擎在跑执行体之前落的事实名（`sent`）
    lease_ms: u64,
    max_attempts: u64,
}
```

每个端口在表里固定占**两行**，另有一条**管所有端口**的租约行：

```
行 A dispatch-<port>  owes: request(port=<port>)
                      until: sent(port=<port>) | failed(port=<port>)
                      before: PortDecl.before ← 引擎在运行前落
                      by: courier

行 B await-<port>     owes: sent(port=<port>)
                      until: response(port=<port>)
                           | failed(port=<port>)
                           | retry(port=<port>)
                      by: None ← 全部差异就在这个 None

行 C lease           owes: stale_sent(stale) ← 视图，带 now
                      until: response | failed | retry（同一 port / id）
                      by: lease_keeper
```

**键取 `(port, id, attempt)`（D-138）。** 五条协议事实同键；行层的派发 / 授权 / 等待
三行跟着同键开账——重试写出的 `request{attempt+1}` **重新欠**这三行，而不是被上一
attempt 的出口格提前关掉。`open-tools` 例外：它开的是 N 笔调用（`expand` 的一侧），
不是某一次尝试，键仍是逻辑 `(port, id)`。尝试级口径归视图（`in_flight` /
`stale_sent`）；幂等键仍是逻辑 `id`：重复派发到外部世界仍可能发生（at-least-once），
由适配器按 `id` 去重；事实层按 `(port, id, attempt)` 去重。

**行 C 只有一条，不按端口写。** `stale_sent` 的实例已经带 `port`，债键里就有它；
加一个端口 = **0** 行租约 + 2 行模板 + 1 条 `PortDecl`。

**租约到顶或没人等，即判死。** 尝试上限由 `PortDecl.max_attempts` 声明（上限是
端口级的天花板，不是「每个调用都会重试」的承诺）；重试的两个前提是
`sent.awaited`（这次尝试有活着的等待方——普通批次的等待方随进程消失，唤醒批次
能由事实重建）与未到上限（读 `stale_sent.exhausted`），缺一即落 `failed`（D-138）。
重试由此**是生产里的第二条路**：`tool` 端口 `max_attempts = 2`，重试出的
`request{attempt+1}` 重新开账、由执行体派发。

**行 C 没有 `unless`。** 尝试到顶要做的事是**判死**（落 `failed`），而 `unless`
命中会把行挂起——看护者永远跑不到，「到顶即判死」成了死代码。行只管「这笔卡住了、
有人要管」，怎么收归执行体。

`by = None` 那一行**对 `drive` 是透明的**（恒 blocked，永不选中）。它存在的理由不是
"它是一类债"，而是让 `open ≠ ∅ ∧ actionable = ∅` 这个状态可表达——也就是让
"在等"与"没事"可区分。**它是"这笔账不由引擎执行"的唯一声明位。**

这个区分要**被谁看见**才算成立：`open ≠ ∅ ∧ actionable = ∅` 时的停机理由分
`waiting`（有一笔已派出未收清的往返）与 `no_progress`（真的没事），判据是
`loop_rows::waiting`。`await-<port>` 行的对偶形状与这条读者一起才让它不成为装饰行
（[D-130](015-义务环.md "DE-015-义务环")）。

**执行体不是裸函数。** 它的声明形状是：

```rust
struct ActorDecl {
    name: &'static str,
    mode: Mode,                    // 令牌闸门（反射档拿不到模型句柄）
    reads: &'static [&'static str],  // 视图名，装载期查存在
    writes: &'static [&'static str], // 事实名，写入封闭 + 收口检查
}

// 动作面与声明**同批**注册在部署层（谁装配这行表，谁提供这个 `by` 的活）：
struct ActorEntry {
    decl: ActorDecl,
    run: for<'a> fn(&'a mut ActorCtx<'a>) -> StepFuture<'a>,
}
```

> **`run` 不是 `ActorDecl` 的字段，也不写 `'static`。** 声明与动作分家不是实现妥协，
> 而是下面 §2.6 契约 1（`drive` 持 `&mut Session`，执行体**借**轮内草稿）唯一允许的
> 形状：借来的草稿带一条非 `'static` 寿命，而 `dyn Future + 'a + 'b` 是非法类型
> （trait 对象只允许一条显式寿命上界）。机制层也拼不出 `'static` 那个签名——
> `Fact` / `ActorCtx` 是部署事实（哪个插件、哪种适配器、哪套会话字段），抬进 core
> 就是拿机制面付实现面的账。形状裁决见 [D-119](015-义务环.md "DE-015-义务环")：
> **声明面进机制层、动作面留部署层**，机制层只持有四样静态可查的字段
> （三道装载检查 + 时延闸门的输入面），可调用面住在注册它的部署里。
> 「能选中 ⇔ 有人跑」不靠求解器加第四个过滤条件，而由
> `by` 查不到声明（`UnmannedRow`）与声明没有行（`OrphanActor`）两个方向同时拒绝装载。

`run` 是异步且可失败的。**失败不是"没返回"**：引擎在 `Err` 时写 `failed`，把失败
变成一条事实，再让 `await` / `lease` 行收清——义务环里没有异常分支。

**协议事实的写方只有引擎一个。** `sent`（`before` 位）、`response`（`Ok`）、
`failed`（`Err`）都由引擎写，搬运者只做活：它的 `run` 可能**不产生任何事实就返回**，
把「派出去了 / 回来了」交给它自觉，忘一次就没有任何东西会红。只留 `request`
给决策者（「这一轮欠一次调用」是判断，不是执行）。

**账本是日志的一段，不是执行体交回的一份报告**（形状裁决见
[D-123](015-义务环.md "DE-015-义务环") 决策 1）。执行体的 `run` 交回 `Result<(), ActorError>`：
**写不经过返回值**——执行体在执行中把**自己声明过的领域事实**（流式节点、
`artifact.added` 这类需要读改写的格）直接写进同一个 store，单写者是 store，不是引擎函数。
于是「实际写入 ⊆ `ActorDecl.writes`」（装载期第 5 条 + 运行期对账）的判定输入只能是
**引擎在动作前后各读一次日志取出的尾段**；执行体自报的那份 `Vec` 只是陈述，
漏报一条就对账不上一条，而漏报正是这条判据要拦的事。
协议四格（`sent` / `response` / `failed` / `retry`）不适用本条：它们永远只由引擎写。

### 2.4 五个协议名 + 端口

| 名字 | 含义 | 谁写 |
|---|---|---|
| `request{port, id, attempt}` | 该调了 | 决策者 |
| `sent{port, id, attempt}` | 已经派出去了 | 引擎（`before`） |
| `response{port, id, attempt}` | 回来了 | 搬运者 |
| `failed{port, id, why}` | 没成功 | 搬运者；引擎在 `run = Err` 时兜底 |
| `retry{port, id, attempt}` | 这次尝试作废，换一次 | `lease_keeper` |

**协议名与业务事实分属两个词汇层。** 业务事实（`memory.recalled` /
`task.rework_created` / `chat.assistant.final` / `commitment.broken` …）有各自真实的
读方，把它们压成几个协议名不是简化，是**销毁语义**。协议名只覆盖控制面的五类往返；
把「我要调模型」「我要调工具」这类一直只活在内存里的请求变成可回放的事实，是
**补上一类从未存在的事实**，不是替换业务词汇。

端口（本轮执行 / 模型 / 工具 / 时钟 / 存储）**全部同构**：子智能体是
`request{port:tool, tool:"agent_run"}`——"模型调用"可以是"工具调用"的一个取值，
所以框架层没有理由把它们分成两类。

**`port` 的位置已裁决：载荷，不是信封。** 只有这 5 个协议名有端口；放信封等于让
"每条事实都有端口"在 31/36 的情况下是假话。`FactDecl` 声明 `port` 字段，`PortDecl`
声明端口的适配器 / 租约 / 最大尝试数。**加一个端口 = 0 个新事实名 + 1 个 `PortDecl`
+ 适配器 + 2 行模板（第三行通用）**——这是判据 1 的正确口径。"2 行模板"指
dispatch / await 这对模板行；端口若有授权前件或批次展开，另加**端口用法行**
（`authorize-*` / `open-*`，工具批次即 4 行）——用法行是表的行数不是
机制的个数，判据 1 守的是"新端口不触引擎代码"，不是"新端口不多写行"。

**判据 1 的执行方**：源码级审计（`scripts/port-surface-audit.mjs`，PTS-001…004）——
① 带端口的事实名 ⊆ 这 5 个协议名（端口是载荷）；② 求解器不读端口字段（引擎对端口无感）；
③ 求解器 `owed` / `drive` 的字节与基线一致。细目归
[DE-016](016-工程落地与验证.md "DE-016-工程落地与验证")。

### 2.5 决策输入闭包：`owed` 只许读三样东西

> **`owed` 的入参 = 事实切片 + 视图值 + 触发事件的时间戳。没有第四样。**

这不是洁癖，是"回放可重建"的定义。五个策略行的输入全部来自事实面：

| 行 | 需要的判断 | 事实来源 |
|---|---|---|
| `classify` | 这句话该派活吗 | `turn.stage{stage:"round"}` / `user.message` / `session.config` |
| `report` | 干了一会儿了该说一句吗 | `now - last_spoke_at`（两者都来自事实）+ `chat.assistant.reported` 计数 + `session.config` → `report_due` 视图 |
| `compress` | 这一轮要不要压缩 | `session.config` / `turn.stage{stage:"compress"}` |
| `recall` | 要不要召回 / 路由技能 | 存储能力声明折成 `session.config`；命中落 `turn.stage{stage:"recall", result:"hit"\|"miss"}` |
| `reflex` | 能不能续跑 | `turn.stage{stage:"resume"}` 的有无 / `turn.stage{stage:"recall", result}` |
| `execute` | 前置是否齐 | `turn.inputs.ready` 视图（所有前置阶段已完成） |

三条硬规则：

1. **`user.message` 先于一切判决入格。** `owes` 要匹配它。写入点在 `drive` 之前，
 `produced_by` 仍指向用户请求。
2. **配置是事实，不是旁路快照。** `session.config` 在一轮开始时落一条（开关注记 +
 阈值 + 存储能力），`owed` 只读它。改配置 = 落新事实，回放能重建当轮判定。
3. **"这一步做过没有"是 `turn.stage` 事实，不是进程缓存。** `done` 直接接进视图，
 任何 `stages_done` 式缓存都是第二份状态。

**`now_ms` 从事件时间戳来，不从 `clock_now_ms` 读。** 否则同一个日志重放两次会
得到不同结论。需要"未来某刻"的行（汇报、租约）由视图把 `now` 折成布尔，见 §2.2。

### 2.6 执行契约：`drive` 不是一段同步循环

`drive` 是异步的：模型调用、工具执行、流式写出都 `await`，中止信号随时可能置位。
契约七条：

| # | 契约 | 不做的后果 |
|---|---|---|
| 1 | `drive` 是 `async fn`，持 `&mut Session`（单写者） | 双写者 = 第二份状态；`&self` 又写不了日志 |
| 2 | `actors.run` 返回 `Result<(), ActorError>`，写入由引擎从日志尾读（[D-123](015-义务环.md "DE-015-义务环") 决策 1） | 失败只能靠执行体自己落事实，漏了就静默停摆 |
| 3 | 引擎在 `Err` 时写 `failed{id, why}` | 失败不是事实，回放看不见 |
| 4 | 每步之前检查 `ExecAbortSignal`；中止 ⇒ 收束 `interrupted` | 中止只能等执行体自觉返回 |
| 5 | `MAX_STEPS_PER_DRIVE = 64`，超界 ⇒ 收束 `exhausted{step_limit}` | 一条坏行可以让 drive 永远转 |
| 6 | 每步之后读**账本**（动作前 `head` 起的日志尾段）；空账本 ⇒ 收束 `exhausted{no_progress}` | "执行体这一步什么都没写"是静默停摆的第一来源 |
| 7 | 在途请求带**租约**（尝试号进载荷）；`lease` 行在重试前提成立时落 `retry` 并重开下一笔（D-138：`sent.awaited` ∧ 未到上限），否则到顶即判死、落 `failed`。重试已启用（`tool` 端口 `max_attempts = 2`），行层债键含 `attempt`，重试出来的 `request{attempt+1}` 重新欠授权与派发 | `sent` 之后崩溃 ⇒ `await` 恒 blocked、永久在等；唤醒批次的等待方可由事实重建，崩溃后仍能重试 |

第 6 条与 §3.4 第 6 条（执行体写入必须与 `until`/`unless` 相交）是一对：装载期查
"它**能不能**收口"，运行期查"它**这次**收没收"。两条都不做，才会出现 §3.4 第 7 条
那种"停用插件后永久停在等"的静默故障。

**并发不在 `drive` 里。** 单会话单写者意味着同一会话的债是串行还的；并发来自
多个会话各有一个 `drive`，以及执行体内部（工具批次）自己的并发。同一个批次的并发
由 `PortDecl.concurrent` 声明并由集合事实表达（§2.8），不是执行体的自觉。

### 2.7 流式与审批

- **流式**：`courier` 在 `sent` 之后把 `ExecEventSink` 的帧直通给前端；
 帧不是事实，不参与 `owed`。`response` 只在流结束时落一条。
- **审批 / 用户补充 / 中止**：都是**外部事件**，由唤醒源落事实（`approval.*` /
 `user.message` / 收束格），`await-tools` 的 `until` 增加对应的事实名。
 审批恢复只能从事实进环：审批格落事实 ⇒ 重新开账 ⇒ 由行表派发。
- **`ask_user`**：`request{port:user}` 的 `await` 行，`until: user.message`。
 这是 `Wait` 折叠在细粒度端口上的自然形态，不需要新机制。

### 2.8 并发

创建行 `open-tools` 的 `expand` 让一个批次成为 N 笔子债（派发行仍欠 `authz.granted`，
两段债的划分见 D-117）；`drive` 仍串行取最小，
但 `PortDecl` 声明 `concurrent: true` 时，同一 `batch_id` 的子债可并发派发，
引擎等整批 `sent` 后再进入 `await`。**并发集合是事实**，不是执行体的自觉。

## §3 引擎与插件契约

### 3.1 引擎只认识七个词

**事实 · 模式 · 键 · 视图 · 执行体 · 优先 · 前置标记。**

没有 `model`、没有 `tool`、没有 `turn`、没有 `user`、没有 `prompt`。**一个业务词都没有。**
插件能往这七个词里填内容，但**不能加第八个**。

### 3.2 插件交什么：六个注册口

```rust
impl Builder {
    fn fact(&mut self, d: FactDecl);   // 事实声明
    fn view(&mut self, d: ViewDecl);   // 视图声明
    fn actor(&mut self, d: ActorDecl); // 执行体
    fn port(&mut self, d: PortDecl);   // 端口适配器 + 租约 + 尝试上限
    fn row(&mut self, d: Decl);        // 表行
    fn seal(self) -> Result<Arc<Frozen>, Vec<CheckError>>; // 冻结
}
```

`FactDecl` 是**一个事实名一条**，不是一族一条：`request` / `sent` / `response` /
`failed` / `retry` 各声明一次（字段完全相同），端口是载荷取值，不是声明维度。
`ViewDecl` 带 `ver`（视图口径版本，进 §3.4 第 6 条）与 `reads`（它读的
`(事实名, 字段名)` 列表，装载期逐条查声明）。

`ActorDecl` 的四个字段不是装饰——裸函数也能跑，但**三样静态检查会全部失效**：

| 字段 | 谁用它 | 缺了会怎样 |
|---|---|---|
| `mode` | 令牌闸门（§3.4） | 分不清"反射档不许调模型" |
| `reads` | 装载期检查视图存在 | 视图名打错 ⇒ 运行期静默返回空 |
| `writes` | 写入封闭 / 死事实名检查 | 查不出"这个事实名没有任何人会产出" |

### 3.3 装载：三个时点

| 时点 | 谁在做 | 发生什么 |
|---|---|---|
| 编译期 | `linkme` / `inventory` | 收集插件实现，形成清单 |
| 装载期 | `Builder` | 填五张注册表 |
| 冻结 | `seal` | 跑七道检查；通过则产出不可变 `Arc<Frozen>` |

**"运行期不能注册"不是纪律，是类型**：`Session` 只拿得到 `Arc<Frozen>`，没有可变注册口。

### 3.4 装载期七道检查

| # | 检查 | 查什么 | 缺了会怎样 |
|---|---|---|---|
| 1 | 依赖图无环 | "谁还清谁"的保守图 | 类型级互相等待 ⇒ 死锁 |
| 2 | **每行收口** | `owes` 的每种应答至少命中一次 `until`/`unless` | 运行期死循环 |
| 3 | 字段都在声明里 | 模式与 `ViewDecl.reads` 引用的 `(事实,字段)` ∈ `FactDecl.fields` | 运行期取不到字段 |
| 4 | 相交行对 | 可能同时命中的行对 | 静默遮蔽（静态不可判，只报告） |
| 5 | 写入封闭 | 执行体实际写入 ⊆ `ActorDecl.writes`；`PortDecl` 覆盖 `response`/`failed`。**判定输入是日志尾段**（引擎在动作前后各读一次），不是执行体交回的陈述——装载期只能查声明面，"实际写入"那一半在运行期对账（[D-123](015-义务环.md "DE-015-义务环") 决策 1–2） | 决策者伪造 `response` |
| 6 | **执行体收口** | `by=Some(a)` 的行：出口里有可声明的领域格 ⇒ `a.writes ∩ (until ∪ unless 的事实名) ≠ ∅`；出口**全是**引擎独占格（派发行的形状，引擎落 `before` / `failed` 替它关门）⇒ `a.writes` 非空（[D-124](015-义务环.md "DE-015-义务环")） | 执行体返回空事实 ⇒ 每一步都无进展 |
| 7 | **声明事实有归宿** | 每个 `FactDecl`（控制面声明集）至少出现在某行的 `owes` / `until` / `unless` | 拼错的名字静默永不被消费 |

第 2 条与第 6 条是一对：**2 查"这笔债有没有出口"，6 查"这个执行体能不能走到出口"。**
只有 2 时，执行体可以什么都不写，配置照样绿；只有 6 时，行可以没有 `until` 可匹配。
第 6 条对**派发行**（出口只有 `sent` / `failed` 这类引擎独占格）改判为「名单非空」：
它不能要求执行体声明一条被第 5 条禁止声明的格——两条检查互斥等于「这一行永远不许接线」，
而这一半（"这次真没写"）本来归运行期的空账本守卫判（§3.4 第 5 条 +
[D-123](015-义务环.md "DE-015-义务环")），裁决见 [D-124](015-义务环.md "DE-015-义务环")。
第 7 条只约束**控制面声明集**（交给 `Builder` 的事实），不约束业务事实——
业务事实的读方是投影，不是表；强迫它们各挂一行只会造出装饰行。

**声明集的准入资格就是第 7 条本身**：一个事实名进 `Builder`，就必须有行以它为
`owes` / `until` / `unless`，或有一条**被行用到的**视图读它。只在审计 / SLO 投影里
读的断言格（例：`turn.dispatch` 由 `invariants::declared_budget_ms` 读）属业务事实，
留在事件名表里，不进声明集——它写与读都照旧，只是不要求表里给它配一行。

**装载失败即拒绝启动，不许部分成功。**

> **`turn.closed` 是概念名，线上名是收束格。** 本文档用 `turn.closed` 指"这一轮收束了"，
> 代码里它是 `chat.assistant.final` / `chat.assistant.fallback`（`turn × closed`），
> `reason` 是被定下的闭集字段。**不要新增一个叫 `turn.closed` 的事件名**——
> 那会让"本轮收束"有两个真源。

## §4 三处硬约束

**以下三条不是可选项：缺任何一条，形状不能成立。** 补法都刻意做轻——不新增机制键。

### 4.1 溯源：不悬空且更小

溯源边是信封里的 `produced_by: Option<u64>`。规则三条：

1. **名字只有 `produced_by`**，不引入第二个名字（如 `caused_by`）。
2. **不悬空且更小**：`produced_by < seq`，且指向的 seq 确实在同一条日志里。
 前一半几乎免费（`produced_by` 只能取自一条已入库事件的 seq，而 seq 严格单调）；
 后一半要一条检查——回放时按 seq 建索引，落一条违规。
3. **派生图无环是免费的**：seq 严格单调 ⇒ 边只能从高指向低 ⇒ 天然 DAG
 （`seq` 严格单调即可直接推出），**不另加无环检查**。

「哪些事件算声称」若按事件种类硬枚举，加一类就要改那个函数。它属 I2 的判据范围，
与本方案的形状无关（见 §7 不做清单）。

### 4.2 权限：否定要落成事实，判定位置不动

授权判定由 fail-closed 的 `PermissionMatrix` 承担：写侧按**种类**分两臂判
（`can_reply` / `can_produce_artifact`），读侧判 `can_see`。**判定本身是健全的**——
缺的不是判定，是**否定的表达**：

> 拒绝 = 拒绝入格 ⇒ 该轮**留在未收束态**。这是用「状态缺失」表达否定：
> 事后无法回答「谁、何时、因为什么被拒」，回放也重现不出这次拒绝。

**这违反的是 I1（单通道），不是权限语义。** 既然一切状态变更只经事实源，
那么「被拒绝」这个状态变更也必须是一条事实。

**补法**：`denied{key, why}` 与 `granted{key}` 都落成事实；矩阵与判定位置**一个字不动**。

**不用否定模式，用正事实级联。** `owes: request(port) ∧ ¬permitted(key)` 会让
`¬` 进 `owes`，逼 `Pattern` 长出否定原子；而 `open` 的公式里本来就有"不存在 `until`"，
两者叠加会让"没有授权记录"与"被拒绝"在匹配上不可区分（fail-open 风险）。改成两行：

```
行 authorize  owes: request(port, id)
              until: authz.granted(id) | authz.denied(id)
              by: authorizer
              prio: 0     ← 必须早于 dispatch

行 dispatch   owes: request(port, id) ∧ authz.granted(id)
              until: sent(port, id, attempt) | failed(port, id)
              by: courier
              prio: 10
```

`authorize` 先还清（`prio: 0`）；它交回 `granted` 后，`dispatch` 的 `owes` 才成立；
交回 `denied` 后 `dispatch` **永不成立**（没有 `granted`），一个 `denied` 行负责把拒绝
说给用户。**没有否定原子、没有异常分支、没有"没写 = 不许"**：拒绝是一条写了的事实。
`key` 是 `id` 的取值；"主体 × 能力 × 资源"三维编码进 `id`（例如
`session/main#chat.assistant.final#turn-42`），匹配仍是等值，不需要引擎认识三个维度。

| 好处 | 说明 |
|---|---|
| 引擎不认识权限 | 权限是表里的一行，不是引擎的第八个词 |
| 拒绝可审计 | `denied` / `granted` 都是事实，不是日志字符串 |
| 与「写入封闭」分工清楚 | 装载期第 5 条管「形状」，这一行管「资格」 |
| fail-closed 不变 | 没有 `granted` ⇒ `dispatch` 不成立；缺记录等于不放行 |

**级联落在细粒度端口。** 级联成立的前提是 `request` 携带**一个可判的能力维度**。
整轮 `turn` 往返不携带这个维度——在它上面按 Speech 授权会让「不持 `reply.*` 但持
产物能力」的主体连轮都跑不了。所以 `authorize` / `dispatch` 两行按工具批次端口声明：
那里的每次调用自带审批与权限面。

**为什么不做成 `drive` 里的前置检查**：那会让引擎认识「授权」这个业务概念，
且拒绝路径变成异常分支——义务环里没有异常分支，只有事实。

**三维判不升成引擎维度**：三维可以编码成 `key` 的取值，`Pattern` 只做等值匹配即可。
若将来需要"按维度分别匹配"（如"某主体对所有 artifact 的授权"），那是 `Pattern`
的键表达式问题，走新裁决——本形状不为它预留口子。

### 4.3 停机原因：统一到收束格的 `reason`，不新增载体

控制环的每次终止都必须落为事实，否则重启后无从知道为何停；并要区分策略终止 /
自然完结 / 兜底上界三种。义务环里没有 `Halt` 这个值。

**补法**：**不新增机制，把 `reason` 定为必填。**

| 终止 | 谁写 | 载体 |
|---|---|---|
| 业务判定终止 | 业务行 | 收束格 `{reason}` |
| 自然完结 | 业务行 | 同上 |
| 步数上界 | 引擎 | `{reason: exhausted, detail: step_limit}` |
| 无进展 | 引擎 | `{reason: exhausted, detail: no_progress}` |
| 规则缺口 | **不存在** | 装载期第 2 / 6 / 7 条已消除 |

**关键**：义务环里"规则缺口"不是运行期状态——`owes` 只有 `until` 一个去处，
装载期"每行收口"保证每种应答都有归宿。

`Verdict` 的三值（`Hit` / `Declined` / `Unmanned`）与 `every_site_is_manned` 只能回答
「这一格有没有行」，不能回答「这一行的 `owes` 有没有归宿」——**有行但归错行，
照样死循环。** "每行收口"（§3.4 第 2 条）补的就是这一档。

**检查**：审计断言收束格（`chat.assistant.final` / `chat.assistant.fallback`）的
`reason` 非空；缺则红。**`turn.closed` 只是本文档的概念名，不新增事件名**（见 §3.4 末注）。

**"无进展"为什么不新增闭集值**：`ClosureReason::Exhausted` 的语义是"被上界掐断"，
步数上界与"一步没有推进"都是上界的一种；`detail` 才回答"哪一种"。闭集只回答"哪一类"，
不把可统计性让给自由文本（分工），也不为了一个细分值再改一次闭集。

## §5 覆盖边界

行表调度的是**还没还的债**，不是「轮」。这个边界有三处必须写明——否则看表会得出
「它应该被派发」的结论，而那条结论在产品路径上不成立。

### 5.1 定稿答话轮不进驱动循环

有一类轮一件都不欠：`classify` 直接判出答话的
**定稿答话轮**（[D-125](015-义务环.md "DE-015-义务环")）——要么模板产线出话（零往返），
要么措辞由 `compose` 在轮首**之前**发起并已入账（`via=compose/wording`，那一笔不是本轮的债）。
这一轮不进驱动循环，两条收束格由轮首准备**就地**落。

`close` 执行体的「唯一写方」因此限定为「**驱动循环内**两条收束格的唯一写方」——
它约束的本来就是执行体之间的写集不相交，而不是「任何地方都不许写」。

**这条边界有个必须写明的后果**：`close-turn` 的前件（`turn.has_final ∧ ¬closed`）对
「措辞产线出话」那一类**可能成立**（措辞往返的 `response(port=model)` 带 `calls: []`），
但驱动不进 ⇒ **表根本不被问**。看表得出「它应该被派发」的结论是对的，只是那条结论
在该路径上不会发生。撤销条件见 [D-125](015-义务环.md "DE-015-义务环") 决策 4：
先把「草稿」立成日志事实，再回表改前件。

### 5.2 轮外往返：没有轮号的模型调用

唤醒路径（例：用户点压缩失败节点上的重试）按定义不产生对话轮次。这类往返**没有**
`turn` 号，也没有幕锚（`Round` / `Compress` 的 `turn` / `produced_by` / `drive_seq`
三个字段），三格里写不下「这属于哪一轮」。硬凑一个轮号，等于让 `lease` / `retry`
去管辖一个引擎无法按轮重放的往返。

**裁决：明文出界，并用一条具名判据钉住边界**（[D-131](015-义务环.md "DE-015-义务环")）。
三个候选与它们为什么被否掉：

| 候选 | 裁决 | 理由 |
|---|---|---|
| ① 给「无轮的往返」一个入账面（`turn` 位放唤醒 id / 硬凑轮号） | **否** | 压缩折叠的是**跨轮**历史，它不属于任何一轮；硬凑轮号会让 `turn_slice` 把这次往返算进一个早已结束的轮的切片里，`lease` 去管辖一个引擎不会重放的轮——正是 D-122 决策 1 拒掉的形状 |
| ② 明文出界 + 具名判据 | **采纳** | 边界本身无害（它是**一条**已知路径，不是「随手打模型」的许可）；有害的是它**没有名字**——差额出现了却没人说得清是哪一笔 |
| ③ 给压缩重试造一个「最小轮」 | **否** | 与 D-125 的裁决冲突（环覆盖的是「欠着的往返」，不是「轮」）；为零对话的轮重开一条驱动，代价远大于收益 |

这条边界由一条**具名**的验收判据钉住，两半：未被解释的往返数必须 **≤** 具名唤醒
路径的计数（多出来的是「一条新长出的静默路径」，少了也判）；并且差额在往返对账里
以一个**具名项**出现，于是「又长出一条静默的模型路径」会当场变红，而「这次差额是
重试造成的」不需要人去解释。判据从**日志**里数，不依赖一张会腐烂的豁免表——
具名这件事由**代码位置**保证，不是文档承诺。验收实现见
[DE-016](016-工程落地与验证.md "DE-016-工程落地与验证")。

### 5.3 边界由名字与判据守，不靠措辞

覆盖边界不是「假设不会发生」，而是每一条都有名字和判据：定稿答话轮由前件与准备
路径的形状钉住；轮外往返由具名差额判据钉住；流式帧由「帧不是事实」的类型边界钉住。
判据的执行与取证归 [DE-016](016-工程落地与验证.md "DE-016-工程落地与验证")，
本文只声明边界本身。

判据 5 / 11 / 13 是三档，别混：**5 问"这一行的 `owes` 有没有去处"，11 问"这个事实名有没有人管"，
13 问"这个执行体能不能走到出口"**。三者各防一种静默失效：死循环、拼错的名字永不被消费、
执行体返回空导致环不前进。`every_site_is_manned` 只做到了 11 的更弱版。

判据 1 是本方案最硬的一条：它不是"机制键数不变"，是**这两段代码的字节不变**。
端口是载荷，所以新增端口不新增事实名。

判据 11 的"控制面声明集"是**交给 `Builder` 的事实**，不是全仓事实。业务事实的
读方是投影，强迫它们各挂一行会造出装饰行——那是把判据当指标，不是当护栏。

### D-120 声明表的进程级记忆化 ≡ 按会话注入：等价性建立在三条类型事实上

按会话注入真正能多买到的是「不同会话可以有不同的表」。而在 1、2 成立时这个能力没有被消费的对象：真表就是 `ROWS` 这一份程序文本。为没被消费的能力付一次「每场开幕重灌 + 重跑七道检查」的成本，是给装载期加一条时序依赖，不是减。 反过来，把 `FROZEN` 换成会话字段会让「表」的存放位置变成调用方的事——那正是 §3.2 要消灭的 「检查跟着调用方走」。

### D-121 唤醒事实的行语义：await 行的收清走协议格，审批与补充重新开账

协议五名是闭集（[DE-015-义务环](015-义务环.md) §2.4），端口是载荷。让一条 `(turn)` 键的事实去收一笔 `(port, id)` 键的债，等于给求解器加第二个匹配维度——那是判据 1「加端口 ⇒ `drive`/`owed` diff = 0」的反例。 「审批之后要重跑工具」的形状是「审批格落事实 ⇒ 重新开账 ⇒ 由行表派发」，不存在第二条执行路径。

### D-122 插件内部的模型往返不进环——调用搬进行表，插件不再自己打模型

协议格的写方不增加。 `request` / `sent` / `response` / `failed` / `retry` 只由引擎在它自己派发的那一次往返里写（[DE-015-义务环](015-义务环.md) §2.4 五事实、 [D-118](015-义务环.md#d-118-引擎与执行体的边界drive-只选债执行体只做一行停机判据留在派发器 "DE-015-义务环") 决策 6 写权按行切）。任何插件都不经由 `ctx` 拿事实源句柄自己 announce 一组三格——候选 ① 否。

### D-123 执行体的账本由引擎从日志尾读，不由执行体自报——ActorError 进机制层，写入封闭在运行期对账

账本 = 引擎在动作前后各读一次日志，取尾部那段。 执行体不自报写了什么： `run` 的签名取 `Result<(), ActorError>`（`Option<TurnOutcome>` 那一半的退役见决策 5，两半同批换的理由见决策 3 的改判注），派发器以 `ledger = store.range(head)`（`head` = 动作前的 `store.head`）得到这一次动作的实际写入集。

### D-124 装载期第 6 条对派发行的改判——出口全为引擎格时判「执行体有登记」，不判「它写得出出口」

第 6 条要防的故障是「行被选中、执行体什么都不写、环不前进」。这个故障有两个可执行的拦截点：静态（名单里有没有这一行的出口格）与动态（账本尾段空不空）。静态那一个先把条文写成 ∩；[D-123](015-义务环.md#d-123-执行体的账本由引擎从日志尾读不由执行体自报actorerror-进机制层写入封闭在运行期对账 "DE-015-义务环") 之后动态那一个存在并且更准—— 静态只能判「声明上够不够得到」，判不出「这次实际写了什么」。

### D-125 定稿答话轮不进环——环覆盖的是「欠着的往返」，草稿的收束格由轮首准备就地落

环的覆盖范围是「欠着的往返」，不是「轮」。 行表调度的是还没还的债 （[DE-015](015-义务环.md "DE-015-义务环") §2.4 五事实、[DE-001](001-核心架构.md "DE-001-核心架构") §4.3 一环一表一源）。

### D-129 中断轮的终态不按 Turn 配对补——Turn 已退役，终态归骨架节点

「进程被杀时那一轮在事实源里永不收束」这个问题，**不复刻旧形状**去修：它的出口判据建立在
「一轮 = `Opened` / `Closed` 两个 turn 节点」上，而 `Turn` 概念已从协议里退役、会话面统一按
`ChatNode` 父子树呈现。中断轮的终态由骨架节点的 `aborted` 状态承担——在退役概念上立判据
等于给它续命，代价是两套终态并存。

### D-130 `await-<port>` 是 Wait 折叠的声明位，不是装饰行——由「对偶形状 + 一个生产读者」两半成立

`by: None` 且从未被任何 `owes()` 直调点问过的行（`await-turn` / `await-model` /
`await-tools`）**保留**，理由不是「D-114 说 Wait 折叠合法」——那句话只说明它不违反设计，
不说明它有用。一个从没被问过的行与一个「问过但不派发」的行在审计上不可区分，而
「没有消费者的行」正是行表长出装饰行的入口（GO-002 T1「架构足够简洁」）。

它成立靠两件事，缺一即退化成装饰：

1. **形状对偶**（机器可判，`every_await_row_is_the_dual_of_its_dispatch_row`）：
   `await-<port>` 的开账条件必须**等于**同端口 `dispatch-*` 行的某个出口（`sent`），
   出口必须是往返终态（`response` / `failed` / `retry`）且落在同一端口上；反向要求
   「每条 `dispatch-*` 都有 `await-*`」（新增端口不能只派不等）；且必须 `by: None`
   ——接上执行体它就成了同一笔账的第二个派发器。
2. **一个生产读者**（`loop_rows::waiting`）：`drive_steps` 选不到可还债时，理由分
   `waiting`（有一笔已派出未收清的往返）与 `no_progress`（真的没事）。此前一律写
   `no_progress`，于是「这一轮为什么停」在事实面上不可判——而恢复路径恰恰要认这一种。

**为什么形状判据是用例而不是装载期检查**：夹具刻意只写一行（`ring.test.rs` 的
`await-x` 用例就在验单行形状），装载期强制对偶会把最小夹具判成非法；而 `ROWS` 是
`&'static` 常量，对它跑用例与装载期判**等价**，且不向夹具收税。

**为什么 `waiting` 按形状认而不按行名认**：派发器不认行名（D-118 决策 1），而
「开账条件 = `sent`」正是「请求已派出、应答没回来」在表上的唯一写法；按
`await-` 前缀匹配会让判据依赖命名约定，改名就静默失效。

### D-131 轮外模型往返明文出界——不入账，但差额必须由一条具名路径解释

用户主动重试压缩（`ResumeAction::RetryCompaction`）时那一笔摘要往返**不入账**：
压缩折叠的是**跨轮**历史，它不属于任何一轮，三格的 `turn` 位没有真值可填；硬凑轮号
会让 `turn_slice` 把它算进一个早已结束的轮的切片，`lease` 去管辖一个引擎不会重放的轮
——正是 D-122 决策 1 拒掉的形状。另两个候选（造「最小轮」、给无轮往返新开入账面）
的理由见 §5.2 的裁决表。

「不入账」不等于「不管」：边界由一条具名判据钉住——未入账的摘要往返数必须 **≤**
具名唤醒路径的计数，而往返对账里那一项是**具名**的。于是「又长出一条静默的模型路径」
会当场变红，而「这次差额是重试造成的」不需要人去解释。**不进豁免表**：靠一张只许减
不许加的表兜住边界，它迟早会腐烂。

### D-136 派发前问表收进引擎：调用点声明行名，不声明「还欠不欠」

`dispatch` / `begin` 原来收一个 `owed: bool`——由调用点自己 `owes()` 算完再交进来。
这个形状与 D-118 决策 1（`drive` 是唯一选债口、执行体不重问）是同一条理由的反面：
**「这一行欠不欠」是行表的事实结论，不是调用点的意见**。交布尔值等于把同一个问题
分给四个调用点各答一遍，而答错的代价不对称：

- 答成 `true`（切片问旧了、行名记错了）⇒ 一次没人承认的调用静默跑完，正是这张表
  要拦的那件事；
- 答成 `false` ⇒ 该派的派不出去，日志少一格，同样没人报警。

现在 `Dispatch` 带的是**行名 + 读账的 `now`**（都是声明），结论由引擎在落 `before`
之前现读（`Dispatch::row_owed`，唯一的现读点）。不欠 ⇒ `NotOwed(那一行的名字)`。

**这条改动当场抓到一个已经漂了的名字**：旧的 `NotOwed` 由引擎自己
`format!("dispatch-{}", call.port)` 拼出，对工具调用报的是 `dispatch-tool`——`ROWS`
里叫 `dispatch-tools`。一句给人与日志看的错名都能与表不一致，说明「谁算结论」不是
理论问题。现在行名只有一个来源（调用点声明的字面量），判据
`obligation-bypass-audit` 的 OB-003 把它与旁路直调一起核对存在性。

**被否的两种形状**：

| 候选 | 否掉的理由 |
|---|---|
| 让 `dispatch` 自己去问 `next`（彻底不传行名） | 派发发生在执行体内部，而 `next` 是**选债口**：在执行体里再问一次就是第二个调度器（D-118 决策 1 直接拒掉的形状）。调用点知道自己站的是哪一行，这半信息必须留着 |
| 保留 `owed`，只加一条「调用点必须刚读过表」的纪律 | 纪律无可执行形式：读没读、读得多新，都不在事实面上。而这一批的真实目的就是把旁路直调的**点数**降下来（DE-090 §3），一个「口头要求调用点自觉」的改动连计数都不动 |

**代价说清**：引擎多读一次日志切片（`store.range(0)` 后按轮过滤）。派发是每步一次、
不是每条事实一次，而 `range` 本来就在轮首与每次判决里跑——它为「结论只有一个出处」
买单，不为性能买单。

### D-138 五条协议事实同键 `(port, id, attempt)`：`failed` 收窄到一次尝试，「不再重试」由「没有后继 request」表达

`failed` 原来关**逻辑 id**（键 `(port, id)`，关所有尝试），其余四条协议事实
（`request` / `sent` / `response` / `retry`）键含 `attempt`。这个不对称使重试通道
永远开不了：行层按 `(port, id)` 开账时，第一次失败就把 `dispatch-*` / `await-*` /
`authorize-tool` 全关掉，重试写出的 `request{attempt+1}` **不欠任何一行**，
没有执行体会派它——真表上 `max_attempts` 全为 1，租约看护只剩「到顶即判死」一条路
（DE-090 原「重试通道未启用」一节记录的缺口，本决策落地后该节退场）。

**裁决**：五条同键。`failed` 收窄到「这一次尝试失败」；「这笔调用不再重试」不再由键的
粒度表达，而由**没有后继 `request`** 表达——这在回放与断言里都是可判的（数一遍
`(port,id)` 的最大 `attempt` 即可）。`authz.granted` / `authz.denied` 随之带 `attempt`，
授权级联与派发关同一**次尝试**；`open-tools` / `deny-tools` 仍按 `(port, id)` 读
`failed`（行的模式只取自己声明的键字段，逻辑级读者行为不变）。

**租约重试的两个前提**（缺一即判死，判死路径与旧行为逐字相同）：

1. 这次尝试**有活着的等待方**（`sent.awaited`）——否则重试只会造出一条永远没人派发的
   `request`。`awaited` 是**逐次尝试**的属性而不是端口属性：普通工具批次的结果等在当前
   草稿里，进程一死等待方就没了；唤醒调用能由 `wake_batch` 从事实重建，所以它算「有人等」。
2. 还没到 `attempt_cap`（`max_attempts` 是端口级的天花板，**不是**「每个调用都会重试」的承诺）。

**被否的候选**：

| 候选 | 否掉的理由 |
|---|---|
| 单开一行 `retry-<port>` | 一行只写「欠什么」，重试不是新的欠，是同一笔债的下一次尝试；单开一行会让「同一笔调用的第 N 次」有两个宿主 |
| `failed` 保留逻辑键，重试另立事实名 | 事件词汇表要为一个粒度问题加词；且逻辑键的 `failed` 会继续把重试后的尝试提前关掉，与重试在同一笔上打架 |
| 只抬 `max_attempts` 不改键 | 抬了也没人派发，等于一条永不执行的债——DE-090 原「重试通道未启用」一节记录的正是这个形状 |

**代价说清**：`failed` 的载荷多 `attempt` 一字段（事件词汇表**增**不减，符合 D-091
「只增不改」）；旧日志的 `failed` 没有 `attempt`，按三元组绑定取不到实例——**旧事实
不参与尝试级收口**。本仓不承诺跨版本回放：回放服务的是同版本崩溃恢复，跨版本升级
不携带旧 WAL。`authz.denied` 的收束格拒绝那条载荷只有 `key`，按任何端口键都取不到
实例——它本来就不该关一笔工具授权，行为不变。
