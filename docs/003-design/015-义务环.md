# 义务环与端口细粒度

> **一句话**：一个会话收事实、算欠账、还债、再收事实。**没有别的。**
>
> 本方案是 [DE-014 §2.1](014-单环一表.md "DE-014-单环一表") 那句终点语义的直接实现，并把它的
> **两类产出收敛成一类**——裁决见 [D-114](015-义务环.md "DE-015-义务环")。
> 它改的是**终点形状**，不是**施工路径**；DE-014 的六步路径与熔断线继续有效。

## §0 结论先行

1. **端口已走完粗→细两级。** `turn` 端口让"一轮"进了日志；`model` / `tool` 端口
 把单次调用也变成债（两行模板 + 引擎写 `before` + 租约看护），今天都在线，
  `obligation-ring-accept --strict` 的 J1…J8 有 CLI 实证。粒度是**参数不是机制**：
  加一个端口 = 0 个新事实名（判据 1）。
2. **内环倒置 = 三组行**：模型请求、工具批次、轮收束。三组行复用 DE-015 的
 `request` / `sent` / `response` / `failed` / `retry` 协议名，**不新增事实名**。
3. **流式不是债。** 流式帧仍走 `ExecEventSink` 直通（DE-014 §3 末段），
 它不改变事实面；债只描述"请求 / 应答 / 失败"。
4. **工具批次是集合，不是单项。** 一次模型响应可带多个工具调用；一个 `tool` 债
 的 `expand` 把批次展开成元素，元素之间并发（DE-014 F1）。
5. **前置已完成。** DE-014 步骤 1（"把 `run_with_tools` 抽成 Step 循环"）已落地，
 所以本方案没有变成一次 747 行重写——**这条前置是硬约束**，缺了它这次改造的
 回退单位就不是 git 提交，而是整篇。

## §2 目标形状

### 2.1 四步

```
① 收到事实 → 追加进日志
② 算欠账 → 从日志算出"还欠什么"，取最小的一笔
③ 运行它 → 交给一个执行体，它把领域事实直接写进同一个 store
④ 对账 → 引擎读回这一次动作写进日志的那一段，回到 ②
```

④ 出现两次：填了 `before` 的行在运行前先落一条标记（`sent`），运行后读回尾段对账。
**执行体不交回事实清单**（写不经过返回值，形状裁决见
[D-123](015-义务环.md "DE-015-义务环") 决策 1、5）——它交回的只有"成功 / 失败"。

```rust
impl Session {
 async fn on_event(&mut self, e: Fact) -> Result<, EngineError> { // ①
 self.log.append(e)?;
 // now 取**这条事件的时间戳**，不在 owed 里读墙钟（D-115 决策 1）。
 self.drive(e.ts).await
 }

 async fn drive(&mut self, now_ms: i64) -> Result<, EngineError> {
 let mut steps = 0;
 loop {
 if self.abort.aborted {
 self.log.append(closed(ClosureReason::Interrupted, "abort"))?;
 return Ok();
 }
 if steps >= MAX_STEPS_PER_DRIVE { // 步数上界
 self.log.append(closed(ClosureReason::Exhausted, "step_limit"))?;
 return Ok();
 }
 let Some(d) = self.min_debt(now_ms) else { // ② 无债 ⇒ 静息
 return Ok();
 };
 let before = self.log.head?;
 if let Some(k) = d.decl.before { // ④a 前置标记
 self.log.append(Fact::envelope(k, &d.key))?;
 }
 match self.actors.run(d.decl.by, &d, &self.abort).await { // ③
 // ④b 账本 = 日志尾那一段（引擎读，不由执行体自报）：写已经在 store 里，
 // 引擎不再二次落格。见 §2.3「账本是日志的一段」与 D-123 决策 1。
 Ok() => {
 let ledger = self.log.range(before)?; // 这一次动作的实际写入
 self.reconcile(d.decl.by, &ledger)?; // 名单 ⊆ 声明的写入封闭
 // 本轮收没收也读这同一段：出现停机格（或收束于等待用户那一格进展）
 // ⇒ 收工，产出从草稿取——执行体不交回 outcome（D-123 决策 5）。
 if ledger.iter.any(|e| self.ends_the_drive(e)) {
 return Ok();
 }
 }
 Err(e) => self.log.append(Fact::failed(&d, e))?, // 失败也是事实
 }
 if self.log.range(before)?.is_empty { // 空账本 = 无进展
 self.log.append(closed(ClosureReason::Exhausted, "no_progress"))?;
 return Ok();
 }
 steps += 1;
 }
 }
}
```

**没有别的调度代码。** 七个词里"优先"与"前置标记"就落在这两处。四个不是第八个词、
但必须由引擎承担的动作是：**读触发事件的时间戳**、**写 `sent`**、**写 `failed`**、
**在步数上界 / 无进展 / 中止处写收束事实**——它们都是"执行者交不回事实时，引擎兜底
把状态变化落成事实"，不引入任何业务判断。

> **`now_ms` 只能来自触发事件。** 没有事件就没有 `drive`，因此"静默 30 秒该汇报了"
> 这类时间条件只在**下一次有事件**时被求值。这是当前系统的真实行为（汇报本来也只
> 在工具轮边界被调用），不是本方案的降级；若将来要独立定时唤醒，那是唤醒源（DE-014
> F3）的一条事实，不是让 `owed` 去读墙钟。**墙钟进入日志的唯一合法通道**：唤醒方
> （启动 / 心跳 / 插话接收）在落那条唤醒事实时读一次墙钟写进它的 `ts`——此后本次
> `drive` 的 `now_ms` 就是这个 `ts`；崩溃重启的租约求值（判据 16）走的也是这条通道。

### 2.2 债

> **一笔债 = 一条 liveness 性质 `owes ⇒ ◇ until` 的当前违例，外加"谁该还"。**

```
open(d, key) := ∃ f ⊨ d.owes ∧ key = bind(f) ∧ ¬∃ g ⊨ d.until ∧ key(g) = key
blocked(d, key) := d.by = None ∨ ∃ h ⊨ d.unless ∧ key(h) = key
actionable(d,key) := open ∧ ¬blocked
min_debt(now) := min { (d,key) | actionable } 按 (prio, name, key) 全序
```

`owes` / `until` / `unless` 的匹配对象是**事实与视图**。时间不进公式：需要时间的条件
（"静默够久了""租约过期了"）由视图把 `now` 折成一个**布尔字段**，行只匹配
`report_due{due:true}` / `stale_sent{stale:true}`。因此 `owed` 本身仍是一个
`(&[Fact], &[View], i64) -> Vec<Debt>` 的纯函数——`now` 是入参，不是它去读的墙钟。

**`prio` 从此是全局的，不是格内的。** 今天每格一行、`prio` 从未真正参与裁决
（DE-014/D-093 的格内编号）。义务环只有一个环、一次取最小，跨行必须可比：
权限行（`prio: 0`）必须早于派发行（`prio: 10`），轮首判决必须早于执行行。
同 `prio` 的并列由 `(name, key)` 决出，**不依赖注册顺序**（顺序是数据，不是插入顺序）。

**`by` 只有两种取值，引擎只有一个动作：**

| `by` | 引擎做什么 | 谁负责不阻塞 |
|---|---|---|
| `Some(名字)` | 到绑定表查那一个动作、跑它；写了什么由引擎读日志尾段（§2.3） | **那个执行体自己** |
| `None` | **什么都不做**——恒 blocked，永不选中 | — |

"决策债 / 搬运债 / 等待债"是**用法**，不是机制：`by` 指向纯函数叫决策债，
指向 `courier` 叫搬运债，是 `None` 叫等待债。**三者在 `drive` 里走同一行代码。**
同步与异步是执行体的实现细节，**不在协议里**，引擎也没有能力管（代价见 §3.4）。

### 2.3 表与两行主模板

一行 = 一笔可能欠的账：

```rust
struct Decl {
 name: &'static str,
 owes: Pattern,
 until: &'static [Pattern], // 任一命中即视为还清
 unless: &'static [Pattern], // 任一命中即挂起
 expand: Option<(&'static str, &'static str)>, // (列表字段, 元素键字段)
 by: Option<&'static str>, // None ⇒ 无执行体，恒 blocked
 prio: u8,
 tier: LatencyTier, // 这一行动作允许的时延档
}

// 端口级的东西按端口声明一次，不写进行里（写进去就是三份会漂的副本）。
struct PortDecl {
 port: &'static str,
 before: &'static str, // 引擎在跑执行体之前落的事实名（`sent`）
 lease_ms: u64,
 max_attempts: u64,
}
```

每个端口在表里固定占**两行**，另有一条**管所有端口**的租约行：

```
行 A dispatch-<port> owes: request(port=<port>)
 until: sent(port=<port>) | failed(port=<port>)
 before: PortDecl.before ← 引擎在运行前落
 by: courier

行 B await-<port> owes: sent(port=<port>)
 until: response(port=<port>)
 | failed(port=<port>)
 | retry(port=<port>)
 by: None ← 全部差异就在这个 None

行 C lease owes: stale_sent(stale) ← 视图，带 now
 until: response | failed | retry（同一 port / id）
 by: lease_keeper
```

**键取逻辑 id `(port, id)`，不是尝试号。** `failed` 关的是逻辑 id（所有尝试）
——带 `attempt` 的键永远匹配不上它。尝试级口径归视图（`in_flight` /
`stale_sent`），行层是逻辑账。幂等键因此也是逻辑 `id`：重复派发到外部世界仍可能
发生（at-least-once），由适配器按 `id` 去重；事实层按 `(port, id, attempt)` 去重。

**行 C 只有一条，不按端口写。** `stale_sent` 的实例已经带 `port`，债键里就有它；
加一个端口 = **0** 行租约 + 2 行模板 + 1 条 `PortDecl`。

**重试通道未启用。** `lease_keeper` 的代码能落 `retry{attempt}` + `request{attempt+1}`
（有合成用例），但行层债键是 `(port, id)`：上一 attempt 的出口格已经把那一行关掉，
重试出来的 `request` 不欠任何一行，没有执行体会派它。所以 `PortDecl.max_attempts`
在真表上全为 1 ⇒ **只有「到顶即判死」这一条路在跑**。重试要不要进债键（键含 attempt，
还是单开一行）是下一条机制裁决，裁决之前不抬上限。

**行 C 没有 `unless`。** 尝试到顶要做的事是**判死**（落 `failed`），而 `unless`
命中会把行挂起——看护者永远跑不到，「到顶即判死」成了死代码。到顶是看护者的
判断（读 `stale_sent.exhausted`），不是行的出口：行只管「这笔卡住了、有人要管」，
怎么收归执行体。尝试上限由 `PortDecl.max_attempts` 声明，今天三个端口全为 1 ⇒
到顶即判死（`turn` 是一次往返，等待方随进程一起消失）。`model` / `tool` 的内环还在，
「重试后由同一幕接着 await」是设计的下一步——它等债键裁决，不是今天的取值。

`by = None` 那一行**对 `drive` 是透明的**（恒 blocked，永不选中）。它存在的理由不是
"它是一类债"，而是让 `open ≠ ∅ ∧ actionable = ∅` 这个状态可表达——也就是让
"在等"与"没事"可区分。**它是"这笔账不由引擎执行"的唯一声明位。**

**执行体不是裸函数。** 它的声明形状是：

```rust
struct ActorDecl {
 name: &'static str,
 mode: Mode, // 令牌闸门（反射档拿不到模型句柄）
 reads: &'static [&'static str], // 视图名，装载期查存在
 writes: &'static [&'static str], // 事实名，写入封闭 + 收口检查
}

// 动作面与声明**同批**注册在部署层（谁装配这行表，谁提供这个 `by` 的活）：
struct ActorEntry {
 decl: ActorDecl,
 run: for<'a> fn(&'a mut ActorCtx<'a>) -> StepFuture<'a>,
}
```

> **`run` 不是 `ActorDecl` 的字段，也不写 `'static`。** 声明与动作分家不是实现妥协，
> 而是下面 §2.6 契约 1（`drive` 持 `&mut Session`，执行体**借**轮内草稿）唯一允许的
> 形状：借来的草稿带一条非 `'static` 寿命，而 `dyn Future + 'a + 'b` 是非法类型
> （trait 对象只允许一条显式寿命上界）。机制层也拼不出 `'static` 那个签名——
> `Fact` / `ActorCtx` 是部署事实（哪个插件、哪种适配器、哪套会话字段），抬进 core
> 就是拿机制面付实现面的账。形状裁决见 [D-119](015-义务环.md "DE-015-义务环")：
> **声明面进机制层、动作面留部署层**，机制层只持有四样静态可查的字段
> （三道装载检查 + 时延闸门的输入面），可调用面住在注册它的部署里。
> 「能选中 ⇔ 有人跑」不靠求解器加第四个过滤条件，而由
> `by` 查不到声明（`UnmannedRow`）与声明没有行（`OrphanActor`）两个方向同时拒绝装载。

`run` 是异步且可失败的。**失败不是"没返回"**：引擎在 `Err` 时写 `failed`，把失败
变成一条事实，再让 `await` / `lease` 行收清——义务环里没有异常分支。

**协议事实的写方只有引擎一个。** `sent`（`before` 位）、`response`（`Ok`）、
`failed`（`Err`）都由引擎写，搬运者只做活：它的 `run` 可能**不产生任何事实就返回**，
把「派出去了 / 回来了」交给它自觉，忘一次就没有任何东西会红。只留 `request`
给决策者（「这一轮欠一次调用」是判断，不是执行）。

**账本是日志的一段，不是执行体交回的一份报告**（形状裁决见
[D-123](015-义务环.md "DE-015-义务环") 决策 1）。执行体的 `run` 交回 `Result<, ActorError>`：
**写不经过返回值**——执行体在执行中把**自己声明过的领域事实**（流式节点、
`artifact.added` 这类需要读改写的格）直接写进同一个 store，单写者是 store，不是引擎函数。
于是「实际写入 ⊆ `ActorDecl.writes`」（装载期第 5 条 + 运行期对账）的判定输入只能是
**引擎在动作前后各读一次日志取出的尾段**；执行体自报的那份 `Vec` 只是陈述，
漏报一条就对账不上一条，而漏报正是这条判据要拦的事。
协议四格（`sent` / `response` / `failed` / `retry`）不适用本条：它们永远只由引擎写。

### 2.4 五个协议名 + 端口

| 名字 | 含义 | 谁写 |
|---|---|---|
| `request{port, id, attempt}` | 该调了 | 决策者 |
| `sent{port, id, attempt}` | 已经派出去了 | 引擎（`before`） |
| `response{port, id, attempt}` | 回来了 | 搬运者 |
| `failed{port, id, why}` | 没成功 | 搬运者；引擎在 `run = Err` 时兜底 |
| `retry{port, id, attempt}` | 这次尝试作废，换一次 | `lease_keeper` |

> **`retry` 今天是保留字，不产生。** 它的写方 `lease_keeper` 代码在场、有合成用例，
> 但真表上 `PortDecl.max_attempts` 全为 1 ⇒ 只有「到顶即判死」（落 `failed`）这一条路在跑。
> 机制理由（行层债键是 `(port, id)`，上一 attempt 的出口格已关行，重试出来的 `request`
> 不欠任何一行）见 §2.3「重试通道未启用」。**这是裁决过的形状，不是漏实现**——
> 别把它当缺陷重开。要抬上限，先裁决重试怎么进债键。

**这五个名字是新增的，不是替换。** 现网 30 个事实名（`memory.recalled` /
`task.rework_created` / `chat.assistant.final` / `commitment.broken` …）**一个不动**——
它们是业务词汇，有各自真实的读方（385 处引用、24 处前端）。把它们压成几个协议名
不是简化，是**销毁语义**。

**真正的变化是补上一类从来不存在的事实**：今天"我要调模型""我要调工具"**不落日志**——
它们正是 DE-014 §2.1 里"意图"那一类产出。所以本方案不是"减少事件名"，
而是"把一直只活在内存里的那一类请求，变成可回放的事实"。

端口（本轮执行 / 模型 / 工具 / 时钟 / 存储）**全部同构**：子智能体是
`request{port:tool, tool:"agent_run"}`——"模型调用"可以是"工具调用"的一个取值，
所以框架层没有理由把它们分成两类。

**`port` 的位置已裁决：载荷，不是信封。** 只有这 5 个协议名有端口；放信封等于让
"每条事实都有端口"在 31/36 的情况下是假话。`FactDecl` 声明 `port` 字段，`PortDecl`
声明端口的适配器 / 租约 / 最大尝试数。**加一个端口 = 0 个新事实名 + 1 个 `PortDecl`
+ 适配器 + 2 行模板（第三行通用）**——这是判据 1 的正确口径。初稿的"3 条 `FactDecl`"
是错的：协议名是全局的，端口是载荷，新增端口不新增名字。**"2 行模板"指
dispatch / await 这对模板行**；端口若有授权前件或批次展开，另加**端口用法行**
（`authorize-*` / `open-*`，DE-015 的工具批次即 4 行）——用法行是表的行数不是
机制的个数，判据 1 守的是"新端口不触引擎代码"，不是"新端口不多写行"。

**判据 1 的执行方**：`scripts/port-surface-audit.mjs`（PTS-001…004）——① 带端口的
事实名 ⊆ 这 5 个协议名（端口是载荷）；② 求解器不读端口字段（引擎对端口无感）；
③ 求解器 `owed` / `drive` 的字节与基线一致（判据 1 的原话，基线在
`scripts/baselines/port-surface.json`，改引擎必须同批更新基线并挂一条决策）。

**端口分两级落地**（D-115 决策 3）：

| 级 | 端口 | 哪批 | 在途粒度 |
|---|---|---|---|
| 粗 | `turn`（整轮执行，内含 `run_with_tools`） | | 一轮 |
| 细 | `model` / `tool` / `clock` / `storage` | [DE-015](015-义务环.md "DE-015-义务环") · | 单次调用 |

粗粒度不是终点，是**唯一不撞 300 行熔断线的第一步**：把 `run_with_tools` 的内环
倒过来是 DE-014 步骤 1 的活，塞进会让一次形状替换变成执行引擎重写。
粗端口期间，"在途"只覆盖整轮，模型单次调用尚不可按调用恢复——这条限制写进 §3.4，
不靠措辞掩盖。

### 2.5 决策输入闭包：`owed` 只许读三样东西

> **`owed` 的入参 = 事实切片 + 视图值 + 触发事件的时间戳。没有第四样。**

这不是洁癖，是"回放可重建"的定义。今天五个策略读的输入里，一半不是事实：

| 行 | 今天的输入 | 闭包后从哪来 |
|---|---|---|
| `classify` | `request_round`、`first_utterance`、`classify_enabled` | `turn.stage{stage:"round"}` 事实 / `user.message` 事实 / `session.config` 事实 |
| `report` | `quiet_ms`（墙钟差）、`reports` 配额、四个配置旋钮 | `now - last_spoke_at`（两者都来自事实）+ `chat.assistant.reported` 计数 + `session.config` → `report_due` 视图 |
| `compress` | `auto_compress` 开关、`done` | `session.config` 事实 / `turn.stage{stage:"compress"}` 事实 |
| `recall` | `has_facts`、`done`、内存里的 `skill_hits` | 存储能力声明折成 `session.config`；召回/技能命中落 `turn.stage{stage:"recall", result:"hit"\|"miss"}` |
| `reflex` | `resume_allowed`、内存里的 `has_match` | `turn.stage{stage:"resume"}` 的有无 / `turn.stage{stage:"recall", result}` |
| `execute` | 上述全部 + 请求体 | `turn.inputs.ready` 视图（所有前置阶段已完成） |

三条硬规则：

1. **`user.message` 先于一切判决入格。** 今天 `turn_runner::prepare_turn` 在 classify
 之后才落用户格（`EVENT_USER_MESSAGE`，`prepare.rs`）；义务环里这是非法顺序——
 `owes` 要匹配它。写入点前移到 `drive` 之前，`produced_by` 仍指向用户请求。
2. **配置是事实，不是旁路快照。** `session.config` 在一轮开始时落一条（开关注记 +
 阈值 + 存储能力），`owed` 只读它。改配置 = 落新事实，回放能重建当轮的判定。
3. **"这一步做过没有"是 `turn.stage` 事实，不是 `TurnState` 缓存。** `stage_events`
 今天已经有这条事实与 `done` 的规范定义；义务环直接把 `done` 接进视图，
 `TurnState::stages_done` 这份缓存退役（DE-014 §2 禁第二份状态）。

**`now_ms` 从事件时间戳来，不从 `clock_now_ms` 读。** 否则同一个日志重放两次会
得到不同结论。需要"未来某刻"的行（汇报、租约）由视图把 `now` 折成布尔，见 §2.2。

### 2.6 执行契约：`drive` 不是一段同步循环

现网是异步的：模型调用、工具执行、流式写出都 `await`，中止信号随时可能置位。
DE-015 初稿的 `fn drive(&mut self)` 把这个事实抹掉了。契约补全为七条：

| # | 契约 | 不做的后果 |
|---|---|---|
| 1 | `drive` 是 `async fn`，持 `&mut Session`（单写者） | 双写者 = 第二份状态；`&self` 又写不了日志 |
| 2 | `actors.run` 返回 `Result<, ActorError>`，写入由引擎从日志尾读（[D-123](015-义务环.md "DE-015-义务环") 决策 1） | 失败只能靠执行体自己落事实，漏了就静默停摆 |
| 3 | 引擎在 `Err` 时写 `failed{id, why}` | 失败不是事实，回放看不见 |
| 4 | 每步之前检查 `ExecAbortSignal`；中止 ⇒ 收束 `interrupted` | 中止只能等执行体自觉返回 |
| 5 | `MAX_STEPS_PER_DRIVE = 64`，超界 ⇒ 收束 `exhausted{step_limit}` | 一条坏行可以让 drive 永远转 |
| 6 | 每步之后读**账本**（动作前 `head` 起的日志尾段）；空账本 ⇒ 收束 `exhausted{no_progress}` | "执行体这一步什么都没写"是静默停摆的第一来源 |
| 7 | 在途请求带**租约**（尝试号进载荷）；`lease` 行**到顶即判死**，**重试通道未启用**——真表 `max_attempts` 全为 1，重试出来的 `request` 在 `(port, id)` 债键下不欠任何一行 | `sent` 之后崩溃 ⇒ `await` 恒 blocked、永久在等 |

第 6 条与 §3.4 第 6 条（执行体写入必须与 `until`/`unless` 相交）是一对：装载期查
"它**能不能**收口"，运行期查"它**这次**收没收"。两条都不做，才会出现 §3.4 第 7 条
那种"停用插件后永久停在等"的静默故障。

**并发不在 `drive` 里。** 单会话单写者意味着同一会话的债是串行还的；并发来自
多个会话各有一个 `drive`，以及执行体内部（工具批次）自己的并发。DE-014 F1 的
"一次派发多项"在细粒度端口（DE-015）里才回到控制面；粗端口期间由 `turn` 执行体
内部保留。这是明确的代价，不是遗漏。

### 2.7 端口粒度：为什么先 `turn`，后 `model` / `tool`

`run_with_tools`（747 行）本身就是"模型 → 工具批次 → 模型"的内环。把每一次模型 /
工具调用变成债，等于把这个内环倒过来——它是 DE-014 步骤 1 的目标，不是本方案的一步。硬塞的后果是：DE-014 那两批的 300 行熔断线必然被顶穿，而熔断线的含义正是
"抽象错了"；这里抽象没错，是**批次放错了**。

因此：

- **先落粗端口 `turn`**：控制面只看到"这一轮该执行了 / 正在执行 / 回来了"。
 `run_with_tools` 原样作为执行体内部实现，零改动。
- **DE-015 落细端口**：把内环倒成 `model` / `tool` 债，`in_flight` 从"一轮"
 细到"一次调用"，崩溃恢复按调用重放，工具批次并发回到控制面。
- **两批之间没有双调度器**：`turn` 执行体是普通 `by=Some` 执行体，不是第二个环；
 DE-015 只是把它的内部拆成更多行，控制面形状不变。

### 2.8 流式与审批

- **流式**：`courier` 在 `sent` 之后把 `ExecEventSink` 的帧直通给前端；
 帧不是事实，不参与 `owed`。`response` 只在流结束时落一条。
- **审批 / 用户补充 / 中止**：都是**外部事件**，由唤醒源落事实（`approval.*` /
 `user.message` / 收束格），`await-tools` 的 `until` 增加对应的事实名。
 `resume.rs` 的旁路**已退役**——它当年存在，是因为内环没有事实面；现在审批恢复只能从事实进环。
- **`ask_user`**：`request{port:user}` 的 `await` 行，`until: user.message`。
 这是 `Wait` 折叠在细粒度端口上的自然形态，不需要新机制。

### 2.9 并发

创建行 `open-tools` 的 `expand` 让一个批次成为 N 笔子债（派发行仍欠 `authz.granted`，
两段债的划分见 D-117）；`drive` 仍串行取最小，
但 `PortDecl` 声明 `concurrent: true` 时，同一 `batch_id` 的子债可并发派发，
引擎等整批 `sent` 后再进入 `await`。**并发集合是事实**（F1），不是执行体的自觉。

## §3 引擎与插件契约

### 3.1 引擎只认识七个词

**事实 · 模式 · 键 · 视图 · 执行体 · 优先 · 前置标记。**

没有 `model`、没有 `tool`、没有 `turn`、没有 `user`、没有 `prompt`。**一个业务词都没有。**
插件能往这七个词里填内容，但**不能加第八个**。

### 3.2 插件交什么：六个注册口

```rust
impl Builder {
 fn fact(&mut self, d: FactDecl); // 事实声明
 fn view(&mut self, d: ViewDecl); // 视图声明
 fn actor(&mut self, d: ActorDecl); // 执行体
 fn port(&mut self, d: PortDecl); // 端口适配器 + 租约 + 尝试上限
 fn row(&mut self, d: Decl); // 表行
 fn seal(self) -> Result<Arc<Frozen>, Vec<CheckError>>; // 冻结
}
```

`FactDecl` 是**一个事实名一条**，不是一族一条：`request` / `sent` / `response` /
`failed` / `retry` 各声明一次（字段完全相同），端口是载荷取值，不是声明维度。
`ViewDecl` 带 `ver`（视图口径版本，进 §3.4 第 6 条）与 `reads`（它读的
`(事实名, 字段名)` 列表，装载期逐条查声明）。

`ActorDecl` 的四个字段不是装饰——裸函数也能跑，但**三样静态检查会全部失效**：

| 字段 | 谁用它 | 缺了会怎样 |
|---|---|---|
| `mode` | 令牌闸门（§3.4） | 分不清"反射档不许调模型" |
| `reads` | 装载期检查视图存在 | 视图名打错 ⇒ 运行期静默返回空 |
| `writes` | 写入封闭 / 死事实名检查 | 查不出"这个事实名没有任何人会产出" |

### 3.3 装载：三个时点

| 时点 | 谁在做 | 发生什么 |
|---|---|---|
| 编译期 | `linkme` / `inventory` | 收集插件实现，形成清单 |
| 装载期 | `Builder` | 填五张注册表 |
| 冻结 | `seal` | 跑七道检查；通过则产出不可变 `Arc<Frozen>` |

**"运行期不能注册"不是纪律，是类型**：`Session` 只拿得到 `Arc<Frozen>`，没有可变注册口。

### 3.4 装载期七道检查

| # | 检查 | 查什么 | 缺了会怎样 |
|---|---|---|---|
| 1 | 依赖图无环 | "谁还清谁"的保守图 | 类型级互相等待 ⇒ 死锁 |
| 2 | **每行收口** | `owes` 的每种应答至少命中一次 `until`/`unless` | 运行期死循环 |
| 3 | 字段都在声明里 | 模式与 `ViewDecl.reads` 引用的 `(事实,字段)` ∈ `FactDecl.fields` | 运行期取不到字段 |
| 4 | 相交行对 | 可能同时命中的行对 | 静默遮蔽（静态不可判，只报告） |
| 5 | 写入封闭 | 执行体实际写入 ⊆ `ActorDecl.writes`；`PortDecl` 覆盖 `response`/`failed`。**判定输入是日志尾段**（引擎在动作前后各读一次），不是执行体交回的陈述——装载期只能查声明面，"实际写入"那一半在运行期对账（[D-123](015-义务环.md "DE-015-义务环") 决策 1–2） | 决策者伪造 `response` |
| 6 | **执行体收口** | `by=Some(a)` 的行：出口里有可声明的领域格 ⇒ `a.writes ∩ (until ∪ unless 的事实名) ≠ ∅`；出口**全是**引擎独占格（派发行的形状，引擎落 `before` / `failed` 替它关门）⇒ `a.writes` 非空（[D-124](015-义务环.md "DE-015-义务环")） | 执行体返回空事实 ⇒ 每一步都无进展 |
| 7 | **声明事实有归宿** | 每个 `FactDecl`（控制面声明集）至少出现在某行的 `owes` / `until` / `unless` | 拼错的名字静默永不被消费 |

第 2 条与第 6 条是一对：**2 查"这笔债有没有出口"，6 查"这个执行体能不能走到出口"。**
只有 2 时，执行体可以什么都不写，配置照样绿；只有 6 时，行可以没有 `until` 可匹配。
第 6 条对**派发行**（出口只有 `sent` / `failed` 这类引擎独占格）改判为「名单非空」：
它不能要求执行体声明一条被第 5 条禁止声明的格——两条检查互斥等于「这一行永远不许接线」，
而这一半（"这次真没写"）本来归运行期的空账本守卫判（§3.4 第 5 条 +
[D-123](015-义务环.md "DE-015-义务环")），裁决见 [D-124](015-义务环.md "DE-015-义务环")。
第 7 条只约束**控制面声明集**（交给 `Builder` 的事实），不约束 30 个业务事实——
业务事实的读方是投影，不是表；强迫它们各挂一行只会造出装饰行。

**声明集的准入资格就是第 7 条本身**：一个事实名进 `Builder`，就必须有行以它为
`owes` / `until` / `unless`，或有一条**被行用到的**视图读它。只在审计 / SLO 投影里
读的断言格（例：`turn.dispatch` 由 `invariants::declared_budget_ms` 读）属业务事实，
留在事件名表里，不进声明集——它写与读都照旧，只是不要求表里给它配一行。

**装载失败即拒绝启动，不许部分成功。**

> **`turn.closed` 是概念名，线上名是收束格。** 本文档用 `turn.closed` 指"这一轮收束了"，
> 代码里它是 `chat.assistant.final` / `chat.assistant.fallback`（`turn × closed`），
> `reason` 是 定下的闭集字段。**不要新增一个叫 `turn.closed` 的事件名**——
> 那会让"本轮收束"有两个真源。

## §4 三处前置缺口与补法

**这三处不补齐，形状不能换。** 补法都刻意做轻——不新增机制键。

### 4.1 溯源：边已经有了，缺的是「不悬空」

**缺口**（核对后的实况，与本方案初稿的说法不同）：信封**已经有**这条边——
`Event.produced_by: Option<u64>`（`symbio_core/event/mod.rs`），20+ 个构造点已经在填，
`invariants::provenance_violation` 也已经在查「断言类 / 记忆类 / 收束类事件必须非空」。
**真正的缺口是另外三处**：

| # | 缺口 | 后果 |
|---|---|---|
| 1 | 只查「有没有」，不查「指向谁」 | `produced_by: Some(999)` 指向一条不存在的事件，照样绿 |
| 2 | 名字两套 | 代码叫 `produced_by`，本方案初稿写 `caused_by`——两个名字 = 后来者查两遍 |
| 3 | 判据按事件种类硬枚举 | `needs_provenance` 里列了三种 kind，加一类就要改这个函数 |

**补法**：

1. **口径统一到 `produced_by`**：代码已有、构造点已铺开、不变量已在用。
 本方案的 `caused_by` 一律改称 `produced_by`，**不引入第二个名字**。
2. **加「不悬空且更小」**：`produced_by < seq`，且指向的 seq 确实在同一条日志里。
 前一半几乎免费（`produced_by` 只能取自一条已入库事件的 seq，而 seq 严格单调）；
 后一半要一条检查——回放时按 seq 建索引，落一条违规。
3. **派生图无环是免费的**：seq 严格单调 ⇒ 边只能从高指向低 ⇒ 天然 DAG
 （`seq` 严格单调即可直接推出），**不另加无环检查**。

**为什么不反向改名成 `caused_by`**：20+ 构造点、一条不变量、两处审计都在用 `produced_by`。
改名是纯机械 diff、零语义收益——**该动的是还没落地的新文档，不是已落地的代码**。

**为什么第 3 条（按种类枚举）不在本批修**：它问的是「哪些事件算声称」，属 I2 的判据范围，
与本方案的形状无关；登记进 §7 不做清单。

### 4.2 权限：否定要落成事实，判定位置不动

**缺口**（核对后的实况，与本方案初稿的说法不同）：授权**不是**「`drive` 在 `run` 前查一次」。
`symbio_core/authz/mod.rs` 有一张 fail-closed 三层的 `PermissionMatrix`：写侧在
`turn_runner::closure_gate` 按**种类**分两臂判（`can_reply` / `can_produce_artifact`），
读侧在 `stats` 判 `can_see`。**判定本身是健全的**——缺的不是判定，是**否定的表达**：

> 拒绝 = 拒绝入格 ⇒ 该轮**留在未收束态**。这是用「状态缺失」表达否定：
> 事后无法回答「谁、何时、因为什么被拒」，回放也重现不出这次拒绝。

**这违反的是 I1（单通道），不是权限语义。** 既然一切状态变更只经事实源，
那么「被拒绝」这个状态变更也必须是一条事实。现状是全项目唯一一处
**用「没写」表达「不许写」**的地方。

**补法**：`denied{key, why}` 与 `granted{key}` 都落成事实；矩阵与判定位置**一个字不动**。

**不用否定模式，用正事实级联。** 初稿写 `owes: request(port) ∧ ¬permitted(key)`——
`¬` 进 `owes` 会逼 `Pattern` 长出否定原子，而 `open` 的公式里本来就有"不存在 `until`"，
两者叠加会让"没有授权记录"与"被拒绝"在匹配上不可区分（fail-open 风险）。改成两行：

```
行 authorize owes: request(port, id)
 until: authz.granted(id) | authz.denied(id)
 by: authorizer
 prio: 0 ← 必须早于 dispatch

行 dispatch owes: request(port, id) ∧ authz.granted(id)
 until: sent(port, id, attempt) | failed(port, id)
 by: courier
 prio: 10
```

`authorize` 先还清（`prio: 0`）；它交回 `granted` 后，`dispatch` 的 `owes` 才成立；
交回 `denied` 后 `dispatch` **永不成立**（没有 `granted`），一个 `denied` 行负责把拒绝
说给用户。**没有否定原子、没有异常分支、没有"没写 = 不许"**：拒绝是一条写了的事实。
`key` 是 `id` 的取值；"主体 × 能力 × 资源"三维编码进 `id`（例如
`session/main#chat.assistant.final#turn-42`），匹配仍是等值，不需要引擎认识三个维度。

| 好处 | 说明 |
|---|---|
| 引擎不认识权限 | 权限是表里的一行，不是引擎的第八个词 |
| 拒绝可审计 | `denied` / `granted` 都是事实，不是日志字符串 |
| 与「写入封闭」分工清楚 | 装载期第 5 条管「形状」，这一行管「资格」 |
| fail-closed 不变 | 没有 `granted` ⇒ `dispatch` 不成立；缺记录等于不放行 |

**本批只做前半**（`denied` 已落地；`granted` + 两行待落），因为行需要
`Decl`与协议名。

**级联的适用范围已收窄到细粒度端口**（落地后核对，理由未立项）：
级联要成立，`request` 必须携带**一个可判的能力维度**。粗端口 `turn` 的 `request` 只说
「这一轮欠一次往返」——在它上面按 `Speech` 授权会让「不持 `reply.*` 但持产物能力」的
主体连轮都跑不了（产物本可在轮内落），恒过则是一个永远能还清的空行。所以两行
`authorize` / `dispatch`（`prio 0` / `prio 10`）移交后续批次
第 3 步（工具批次端口，那里的每次调用自带审批与权限面），作为它的判据 8b。
该条随之收口后，
本批判据 16 条全绿；第 11 步（细粒度端口）仍不属本批。

**为什么不做成 `drive` 里的前置检查**：那会让引擎认识「授权」这个业务概念，
且拒绝路径变成异常分支——义务环里没有异常分支，只有事实。

**初稿担心"三维判会让权限升成引擎维度"，核对后不成立**：三维可以编码成 `key` 的
取值，`Pattern` 只做等值匹配即可。若将来需要"按维度分别匹配"（如"某主体对所有
artifact 的授权"），那是 `Pattern` 的键表达式问题，走新裁决——今天的形状不为它预留口子。

### 4.3 停机原因：统一到收束格的 `reason`，不新增载体

**缺口**：DE-014 §3 规则 f/g 要求 `Halt` 必须落事实，否则重启后无从知道为何停；
并区分策略终止 / 自然完结 / 兜底上界三种。义务环里没有 `Halt` 这个值。

**补法**：**不新增机制，把 `reason` 定为必填。**

| 终止 | 谁写 | 载体 |
|---|---|---|
| 业务判定终止 | 业务行 | 收束格 `{reason}` |
| 自然完结 | 业务行 | 同上 |
| 步数上界 | 引擎 | `{reason: exhausted, detail: step_limit}` |
| 无进展 | 引擎 | `{reason: exhausted, detail: no_progress}` |
| 规则缺口 | **不存在** | 装载期第 2 / 6 / 7 条已消除 |

**关键**：义务环里"规则缺口"不是运行期状态——`owes` 只有 `until` 一个去处，
装载期"每行收口"保证每种应答都有归宿。

**这里要说准，别把它算成新功劳**：现网的 `Verdict` 已经分了三值
（`Hit` / `Declined` / `Unmanned`），`Unmanned` 由 CI 的 `every_site_is_manned` 拦下——
**"本格没人值守"这个缺口今天已经可见**，不靠引擎分支。义务环加的是更硬的一档：
`every_site_is_manned` 只查"这一格有行"，不查"这一行的 `owes` 有没有归宿"。
**有行但归错行，照样死循环。** "每行收口"（§3.4 第 2 条）补的就是这一档。

**检查**：审计断言收束格（`chat.assistant.final` / `chat.assistant.fallback`）的
`reason` 非空；缺则红。**`turn.closed` 只是本文档的概念名，不新增事件名**（见 §3.4 末注）。

**"无进展"为什么不新增闭集值**：`ClosureReason::Exhausted` 的语义是"被上界掐断"，
步数上界与"一步没有推进"都是上界的一种；`detail` 才回答"哪一种"。闭集只回答"哪一类"，
不把可统计性让给自由文本（分工），也不为了一个细分值再改一次闭集。

## §5 覆盖边界

行表调度的是**还没还的债**，不是「轮」。这个边界有三处必须写明——否则看表会得出
「它应该被派发」的结论，而那条结论在今天的产品路径上不会发生。

### 5.1 定稿答话轮不进驱动循环

有一类轮一件都不欠：`classify` 直接判出答话的
**定稿答话轮**（[D-125](015-义务环.md "DE-015-义务环")）——要么模板产线出话（零往返），
要么措辞由 `compose` 在轮首**之前**发起并已入账（`via=compose/wording`，那一笔不是本轮的债）。
这一轮不进驱动循环，两条收束格由轮首准备（`turn_runner/prepare.rs` 的 1b 分支）**就地**落。

`close` 执行体的「唯一写方」因此限定为「**驱动循环内**两条收束格的唯一写方」——
它约束的本来就是执行体之间的写集不相交，而不是「任何地方都不许写」。

**这条边界有个必须写明的后果**：`close-turn` 的前件（`turn.has_final ∧ ¬closed`）对
「措辞产线出话」那一类**可能成立**（措辞往返的 `response(port=model)` 带 `calls: []`），
但驱动不进 ⇒ **表根本不被问**。看表得出「它应该被派发」的结论是对的，只是那条结论
在今天的产品路径上不会发生。撤销条件见 [D-125](015-义务环.md "DE-015-义务环") 决策 4：
先把「草稿」立成日志事实，再回表改前件。

### 5.2 轮外往返：没有轮号的模型调用

唤醒路径（例：用户点压缩失败节点上的重试）按定义不产生对话轮次。这类往返**没有**
`turn` 号，也没有幕锚（`Round` / `Compress` 的 `turn` / `produced_by` / `drive_seq`
三个字段），三格里写不下「这属于哪一轮」。硬凑一个轮号，等于让 `lease` / `retry`
去管辖一个引擎无法按轮重放的往返。

这条边界今天**没有机器判据**：`obligation-ring-accept` 的 J8 只在真的触发一次压缩
重试时才报出 `HTTP = sent(model) + 1`。裁决与落地在任务册的「轮外压缩重试不入账」条目，
结论定稿后要回填到本节。

### 5.3 旁路收编：派发面 = `drive` 驱动的行 + 直调点

`drive()` 今天驱动 6 行（`authorize-tool` / `close-turn` / `execute-turn` /
`open-tools` / `dispatch-tools` / `deny-tools`）；另有若干处**旁路**直接调 `owes()`
再用专门代码执行（`policy.classify` / `policy.report` / `policy.compress` /
`policy.recall` / `dispatch-turn` / `dispatch-model` 等）。

这是已知过渡态，不是错误。但「收口完成」必须有定义，否则「过渡结构只减不增」
（GO-003 E5）无从执行：

> **收口完成的定义 = 旁路直调 `owes()` 的点数归零。**

**这个数字住判据，不住正文**：`scripts/obligation-bypass-audit.mjs` 的
`BYPASS_BASELINE`（OB-001，只许降），并由 `35-baseline` 的 `obligation-bypass` 那一格
钉着「不许改大」——放宽一个数字看起来像维护，实际是在取消一条已经写进设计的定义。
本节只写口径：正文会漂，基线不会。

口径三条，每条都对应一种**会让棘轮变松**的算法错误：

- 数的是 `owes(` 的**调用点**，`fn owes(` 的**定义行**不算。立这条判据时的原始记录
  写「13 处」并列了 12 个位置——多出来的那一个正是定义行。**清单对、总数错，而错的那
  一位没有任何东西会去核**，所以口径必须写成代码。
- `*.test.rs` 不算：那里的 `owes(...)` 是在**断言行表**，不是在旁路执行。算进来数字会
  从两位数跳到三位数，然后被人「下调」成三位数。
- `drive_steps` 的函数体不算：派发器本体问债不是旁路。

判据还判第三条（OB-003）：**每处点名的行必须真实存在于 `ROWS`**。点名一个不存在的行时
`owes` 恒 `false`，那段旁路代码**永不执行**，而编译、测试、门禁全绿——这与判据 11
「拼错的名字永不被消费」是同一个病，只是发生在派发面这一侧。

**别把 J8 当成全覆盖的保证**：它的口径写着「没有别的调度代码」，但它只对账
**模型往返**；工具与策略行的旁路它看不见。那句话今天只被检查了三分之一。

端口是载荷，所以新增端口不新增事实名；这条口径与初稿"3 条 `FactDecl`"不同，见 §2.4。

判据 11 的"控制面声明集"是**交给 `Builder` 的事实**，不是全仓事实。30 个业务事实的
读方是投影，强迫它们各挂一行会造出装饰行——那是把判据当指标，不是当护栏。

「不做」和「还没做」是两件事。这一节只放**裁决过的不做**，每条一句理由；

| 重试进债键（抬 `max_attempts`） | 行层债键是 `(port, id)`，上一 attempt 的出口格已关行，重试出来的 `request` 不欠任何一行。要重试就得改键（键含 attempt，或单开一行）——这是下一条机制裁决，裁决之前不抬上限（§2.3）。 |

协议五名是闭集（[DE-015-义务环](015-义务环.md) §2.4），端口是载荷。让一条 `(turn)` 键的事实去收一笔 `(port, id)` 键的债，等于给求解器加第二个匹配维度——那是判据 1「加端口 ⇒ `drive`/`owed` diff = 0」的反例。 「审批之后要重跑工具」**当年**由 `resume.rs` 的旁路做（执行 + 落结果）；那个文件已退役，今天的形状是「审批格落事实 ⇒ 重新开账 ⇒ 由行表派发」。

### D-122 插件内部的模型往返不进环——调用搬进行表，插件不再自己打模型

协议格的写方不增加。 `request` / `sent` / `response` / `failed` / `retry` 只由引擎在它自己派发的那一次往返里写（[DE-015-义务环](015-义务环.md) §4 五事实、 [D-118](015-义务环.md#d-118-引擎与执行体的边界drive-只选债执行体只做一行停机判据留在派发器 "DE-015-义务环") 决策 6 写权按行切）。任何插件都不经由 `ctx` 拿事实源句柄自己 announce 一组三格——候选 ① 否。

### D-123 执行体的账本由引擎从日志尾读，不由执行体自报——ActorError 进机制层，写入封闭在运行期对账

账本 = 引擎在动作前后各读一次日志，取尾部那段。 执行体不自报写了什么： `run` 的签名取 `Result<, ActorError>`（`Option<TurnOutcome>` 那一半的退役见决策 5，两半同批换的理由见决策 3 的改判注），派发器以 `ledger = store.range(head)`（`head` = 动作前的 `store.head`）得到这一次动作的实际写入集。

### D-124 装载期第 6 条对派发行的改判——出口全为引擎格时判「执行体有登记」，不判「它写得出出口」

第 6 条要防的故障是「行被选中、执行体什么都不写、环不前进」。这个故障有两个可执行的拦截点：静态（名单里有没有这一行的出口格）与动态（账本尾段空不空）。粗端口期只有静态那一个，所以条文写成 ∩；[D-123](015-义务环.md#d-123-执行体的账本由引擎从日志尾读不由执行体自报actorerror-进机制层写入封闭在运行期对账 "DE-015-义务环") 之后动态那一个已经存在并且更准—— 静态只能判「声明上够不够得到」，判不出「这次实际写了什么」。

### D-125 定稿答话轮不进环——环覆盖的是「欠着的往返」，草稿的收束格由轮首准备就地落

环的覆盖范围是「欠着的往返」，不是「轮」。 行表调度的是还没还的债 （[DE-015](015-义务环.md "DE-015-义务环") §4 五事实、[DE-014](014-单环一表.md "DE-014-单环一表") 单环一表）。


### D-129 中断轮的终态不按 Turn 配对补——Turn 已退役，终态归骨架节点

「进程被杀时那一轮在事实源里永不收束」这个问题，**不复刻旧形状**去修：它的出口判据建立在
「一轮 = `Opened` / `Closed` 两个 turn 节点」上，而 `Turn` 概念已从协议里退役、会话面统一按
`ChatNode` 父子树呈现。中断轮的终态由骨架节点的 `aborted` 状态承担——在退役概念上立判据
等于给它续命，代价是两套终态并存。
