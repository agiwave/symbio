# 义务环判据与归属推导

> **一句话**：环只认「债」这一种单位——**一次端口调用一笔债**，债由 decl 欠出、由 provider 还清，
> 环只做七项职务；不是这七项的东西，不得以机制形式留在环里。
>
> 本文是归属判定的**唯一判据**。凡与本文冲突的既有判断，按 §3 作废清单处理：
> **原文标注作废并指向本条编号，不静默改写**。

## §0 五条不变量

**I-1 单位是债。** 一次端口调用 = 一笔债，事实五格 `request` / `sent` / `response` /
`failed` / `retry`，幂等键 `(port, id, attempt)`。环上**没有「批」这种单元**，也没有
「一个响应包一批调用」；N 次调用 = N 笔债。

**I-2 债由 decl 欠出。** decl 只引用**事实行与端口名**，不引用端口实现、不读端口载荷。
「要调工具」不是模型响应携带的语义，而是声明方（行为 / 能力插件里的 decl）依据事实欠出
`request(port=<工具端口>)`。

**I-3 环的职务只有七项。** 选债 / 派发 / 等待 / 配对 / 记账 / 预算与租约 / 重放。
「保留」的环元素必须能指认它属于其中哪一项。

**I-4 环不碰世界语义。** 环不解析端口载荷、不读 gate、不做批、不做并发策略、不做重试判据、
不做终答判定、不按 turn 组织。

**I-5 provider 只做两件事。** 按契约执行一笔债、把事实写到行上。执行、并发、guard、熔断、
广播、超时、结果守卫全部是 provider 的内部实现。

**I-6 端口接口必须通用。** `PortProvider`（及 `plugin-api` 里所有端口受理面）是环通向世界
的唯一入口，**世界端口种类是开放的**，接口不得具名任何具体世界。

1. **端口身份是数据不是类型**：provider 申报自己服务的端口名（可多个），环只按端口名解析
   provider；不得出现 `ModelProvider` / `ToolProvider` 这类按世界命名的 trait 或分支。
2. **载荷通用**：输入 = 端口名 + 行 / 值草稿；输出 = 事实草稿或错误（错误只带通用分类：
   不可重试 / 可重试 / 需人介入）。接口中不得出现 `ToolCall`、`ModelAsk`、`tool_batch`
   一类具名载荷或具名方法。
3. **行形状归端口插件**：某端口有哪些行、字段如何校验，由该端口所属插件声明，provider
   执行时按行契约自校验；接口不承载世界契约细节。
4. **一次一笔**：`execute` 只承诺执行一笔债。并发由宿主调度多笔债或 provider 内部自理，
   接口不出现批、并发度、熔断、gate 读数等策略参数。
5. **执行上下文通用**：`deadline`、取消、幂等键作为通用上下文传入，命名不得带世界词。
6. **能力协商通用**：可选能力位只允许 `streaming` / `cancel` / `idempotent` 这类通用词。
7. **注册即扩展**：沿用 `multi("port")` 族与行名 `<port:{port}>:{provider_id}`，新增世界
   端口不需要改环、改注册面、改接口。

I-6 是 I-5 的**接口面**：I-5 说「provider 做什么」，I-6 说「环用什么形状问它」。
只要接口具名了一个世界，第二个世界就要么复制一份接口、要么往环里长一个分支——两种都
把世界语义搬回了环。

## §1 唯一判定式

对任一元素，依次问：

1. **它是七项职务之一吗？** 是 ⇒ 归环（保留 / 改写），并指明哪一项职务。
   否 ⇒ 进入 2。
2. **能写成「读事实 → 欠 `request(port=…)`」吗？** 能 ⇒ 归 decl。
3. **能写成「执行一笔债 → 写 `response`」吗？** 能 ⇒ 归 provider。
4. **两者都写不出** ⇒ **不得以机制形式存在**：删除，或降成数据（纯值 / 声明）。

判定式只有这四行；「实现困难」「已有代码顺手」都不构成改变归属的理由（SP-003 纪律 0）。

**端口受理面的额外一问（I-6）**：判为「归 provider」的元素，若它落在**环与 provider 的
接口**上（`PortProvider` 及其方法、端口合同类型），还要再问一次「这个形状具名了某个世界吗？」
具名 ⇒ 改写为通用形状（端口名 + 行 / 值草稿 + 通用错误分类），或移交 provider 内部；
不具名 ⇒ 保留。

## §6 关键决策

### D-300 `Frozen::ports()` 只读取用口：端口清单不归环

- **裁决**：`symbio-kernel` 的 `Frozen` 增加 inherent `ports() -> &[PortDecl]`；端口声明由
  所属插件经 `submit_declarations!` 提交，环只按端口名查这张表。`Frozen` 不加字段、
  不加 trait、不占 CS-001 的三格（CS-001 只数内核五 trait 的成员；CS-009 只数字段）。
- **为什么非动内核不可**：端口是环与世界的唯一边界（I-6），环要按端口名解析 provider，
  就必须有一个**只读**、与世界无关的表访问口。把端口清单留在 loop 等于把世界写回环
  （I-6.1 / I-6.7），而让 loop 反向依赖 provider 插件取清单违反 LP-002。取用口是机制面
  最小的一格：不解析载荷、不读 gate、不做批。
- **它服务哪些能力**：任何新增世界端口（`model` / `tool` 之外的第三端口）都靠这条取用口
  零改动接入；`model` 与 `tool` 的声明分别移到 `symbio-plugin-model` /
  `symbio-plugin-tool`，`loop_rows::ports()` 是唯一取用口。
- **未收口**：`ROWS` 里的编排行仍排在 `tools/**` 迁移步；本决策只裁决「端口清单不归环」。
  第三端口的接入面由 D-302 验收。

### D-301 通用受理入口进生产绑定表：环为开放端口付的一次性固定成本

- **裁决**：绑定表新增动作 `port`（`symbio_plugin_api::rows::PORT_ACTOR`），执行体是
  `port::run_port`。它只读三样东西：**债键**里的（端口名 / `id` / `attempt`）、派发器写在
  `Ctx.row` 的行、同名 `request` 事实的载荷；随后调 `execute_one`（`before` / `response` /
  `failed` 仍由引擎写）。环里没有 `tool` / `model` / `llm` / `batch` / `gate` 任何世界名，
  也没有按端口名的分支。
- **一次性固定成本**：动作 + `Ctx` 的两格执行面（请求句柄 / 增量出口）+ 一个通用 provider
  解析口（`provider_of`）。之后新增端口只由所属插件声明 `PortDecl` 与行
  （`by = PORT_ACTOR`），loop 一行不改。
- **不构成对 I-6 的放宽**：入口不解析载荷（原样交 `PortExecutor`）、不读 gate、不做批、
  不持有端口清单；`PortInput` / `PortOutcome` / `PortExecutor` 是本笔唯一接口面。存量两端
  的类型化入口仍随 `tools/**` 迁移收口，本笔不为其写任何特例路径。
- **未绑定时不留孤儿**：没有行绑到 `port` 时，动作仍在绑定表（派发器要能找到它），但不进
  声明投影（否则 `OrphanActor` 会让零端口的装配装不上表）；判据只看「有没有行绑到这张
  通用入口」，与端口叫什么无关。

### D-302 第三端口验收：`notify`（`symbio-plugin-telegram`）零 loop 改动接入

- **裁决**：`model` / `tool` 之外的第三个**真实插件端口**是 `notify`（外部消息推送），由
  `symbio-plugin-telegram` 自己声明与实现。验收通过，`D-301` 的通用入口成立。
- **接入由谁声明**（全部在插件侧）：
  - `crates/symbio-plugin-telegram/src/declarations.rs`：`PortDecl { port: "notify",
    before: sent, … }` + 一条行 `by = PORT_ACTOR`、`owes = request(port=notify)`、
    `until = {sent, response, failed, retry}`；
  - `crates/symbio-plugin-telegram/src/port.rs`：`PortProvider`（`ports()` / `provider_id()` /
    `executor()`）与 `PortExecutor`（只吃 `PortInput`、只吐 `PortOutcome`，真实发出 Bot API
    请求）；
  - `plugin.rs` 的 `traverse` 用 `port_rows` 把执行面挂进能力表——注册面不随端口数写死。
- **零改动的证据**：本笔 `git diff --stat` 不含 `crates/symbio-plugin-loop/**`，也不含
  `crates/symbio-plugin-api/src/port.rs`；改动的只有 telegram 插件、`crates/symbio` 的验收
  测试与 dev-dependency。
- **验收断言**（`crates/symbio/tests/notify_port_acceptance.rs`）：链接 loop 与全部插件的
  冻结表能 `seal`（装载期无 `PortWithoutAnswerExit` / `UnmannedRow`）；`notify` 的
  `PortDecl` 在 `Frozen::ports()` 里；`PORT_ACTOR` 进执行体声明；给一条
  `request(port=notify)` 事实，`ring::owed` 选中该行。执行面另有插件侧测试，对本地 HTTP
  靶子发出真实请求（注册读数 `Ready` + 执行成功）。
- **本笔不兑现的部分（如实记）**：第三方插件没有开债口——`request` 事实的生产者仍是环
  的 `announce`。因此该端口能被**执行**、不能被插件自己**开债**。补齐这一口是下一笔的
  独立范围；本笔不以任何特例冒充它已兑现。

### D-303 工具世界的宿主是独立插件 `symbio-plugin-tool`：执行缝换成通用端口合同

- **裁决**：`tool` 端口的**声明与提供者**归 `crates/symbio-plugin-tool`；工具世界（线上名
  解析、路由回落、结果提取、空闲超时与中止）整体住在那里。`symbio-plugin-session` 只承担
  会话范围世界（消息列表 / 会话动作），不再声明或提供任何端口。
- **为什么不是 session**：「会话范围世界」与「工具世界」是两件事。把工具执行体挂在 session
  里，等于让会话所有者顺带认工具词汇（`tool` / `Tool*` / 模型线上名），也就把世界语义塞回
  了一个并不拥有它的插件；端口名 `tool` 与插件 id 分离后，工具世界可以整体停用而不影响会话。
- **执行缝只有一份**：环侧调用点只认 `PortInput` / `PortOutcome` / `PortExecutor`；`loop` 的
  `execute_tool_async` 只做「按端口名取提供者 → 交一笔输入 → 收复三格事实」，线名解析、超时
  与结果契约都在提供者一侧。`ToolCallRequest` / `ToolCallOutcome` / `ToolCallExecutor` 与
  提供者上的具名工具执行方法一并删除，不留薄壳。
- **端口与行**：端口名 `tool`（`ports::TOOL`，数据）；端口声明
  `PortDecl { port: "tool", before: sent, lease_ms: 600_000, max_attempts: 2, concurrency: 4 }`；
  执行面登记为 `port_rows(&provider)` 生成的 `<port:tool>:tool` 一行。端口名不带 `Turn` 语义。
- **未收口（如实记）**：`ROWS` 里 `model` / `tool` 的**编排行与动作**仍在 `loop_rows.rs`；
  它们吃 `Ctx`（`TurnSession` / `store` / `ports`），动作是环私有的 `Action` 类型，插件无法
  实现。把这两端的编排行搬进插件需要一份**新的编排契约**（本决策不预设它的形状），故步二
  不以「把 `by` 改个名」冒充搬迁。`turn_exec` / `tool_dispatch` / `tools/**` 的删除同样以
  「按债驱动路径先接上并验证」为前提，本决策不授权机械删旧链。

### D-304 行去动作化：行只留声明，动作按判定式三处归位

本条即 D-303 所说「新的编排契约」的形状裁决。

- **裁决一：删 `Action`。** 绑定表不再持有 `ActorEntry.run`
  （`Action = for<'a> fn(&'a mut Ctx<'a>) -> StepFuture<'a>`）。`Decl.by` 的合法值收敛到
  两个**宿主词汇**（`plugin-api` 的 `rows` 模块，非世界名）：
  - `PORT_ACTOR`：端口债行。执行体是环的通用受理入口 `execute_one`
    （选债 / 派发 / 等待 / 配对，`I-3` + 判定式行 1）；
  - `PLUGIN_ROW`：世界行。执行体是该行所属插件提交的 `RowHandler`，入参 `RowRequest`、
    出参 `RowStep`，**纯值**（`I-2` + 判定式行 2 / `I-5` + 判定式行 3）。
  其余 `by` 名字（`EXECUTE` / `RELAY` / `OPENER` / `COURIER` / `WAITER` / `WAITER_TOOLS` /
  `AUTHORIZER` / `CLASSIFY` / `COMPRESS` / `RECALL` / `SEAM` / `REPORT` / `CLOSE` /
  `CONTINUE`）全部作废：它们既非七项职务，又写不成「读事实欠债」，也不是一次端口调用
  （判定式行 4）。
- **裁决二：行形状。** 一行的字段只有 `name`（数据）/ `phase` / `anchor`（排序与幂等词干）/
  `reads`（选债前件：事实行或视图名单）/ `owes`（欠哪一笔 `request(port=…)`，端口名是数据）/
  `until`（还账模式）/ `key`（配对键 `port` / `id` / `attempt`，响应按同一键配对）。
  `by` 只区分两类执行体，不承载世界语义。依据：`I-1`（一笔债五格）/ `I-2`（decl 只引用
  事实行与端口名）/ `I-3`（选债 / 派发 / 配对）+ 判定式行 2。
- **裁决三：`Ctx` 去 `TurnSession`。** 环侧只剩：`store`（记账）、`frozen`（行 / 端口只读
  取用口）、`row` / `key`（本笔债身份）、`facts` / `history`（事实切片）、
  `now` / `turn` / `produced_by`（事实行给的时序与溯源）、`request_ctx` / `event_sink`
  （交给 provider 的两份宿主句柄）。**不再有** `session`（`TurnSession` 的世界草稿）与
  `head` 里的桥（orchestrator / context / turn / bridge）。前者是 `I-4`「不持 turn 状态」，
  后者是 `I-5`「世界实现归 provider」；依据：`I-3` 七职 + `I-4` + 判定式行 1 / 4。
- **裁决四：纯值 handler 的输入输出。** 入 `RowRequest`（`row` / `key` / `anchor` / `now_ms` /
  `principal` / `user_seq` / `facts` / `history`），出 `RowStep::{Facts, FactsWithEffects, Ask}`。
  `Ask` 不是环去调模型，而是「这一行欠一笔 `request(port=model)`」，由宿主按 `I-1` 记账后
  把回执交 `parse`（`I-2` + 判定式行 2）。`RowStep::Answer` 与 `answers()` 作废：零往返作答
  是终答判定，归 provider（`I-4` + 判定式行 4）。
- **裁决五：原 `by` 动作逐行去向。**

  | 行 | 去向 | 依据 |
  |---|---|---|
  | `authorize-tool` | provider（`tool` 执行体内部） | 执行前 guard 是 provider 内部实现；环不读 gate |
  | `policy.classify` | provider（`model`，`via` 只是行/请求数据） | 一次模型往返 = 一笔债；环不按 `via` 分支 |
  | `policy.compress` | provider（`model`） | 同上 |
  | `policy.recall` | `session` 插件的 `RowHandler`（纯值） | 读事实产事实，判定式行 2 |
  | `prepare-turn` | `session` 插件的 `RowHandler`（纯值） | seam 读事实欠请求；世界装配不归环 |
  | `policy.report` | `session` 插件的 `RowHandler`（纯值） | 汇报名单是数据，判定式行 1 |
  | `close-turn` | `session` 插件的 `RowHandler`（纯值） | 收束落终答事实 = 记账数据 |
  | `continue-turn` | `session` 插件的 `RowHandler`（纯值） | 续轮判据是事实读数 |
  | `announce-model` | `model` 插件的 decl（无执行体） | 「读视图欠 `request(port=model)`」= 行 2 |
  | `open-tools` | provider（`model` 执行体写 `request(port=tool)`） | `I-2` 禁止 decl 读端口载荷（`calls`）；`I-5` provider 写事实 |
  | `deny-tools` | provider（`tool` 执行体） | 拒绝结果 = 世界结果形状，判定式行 3 |
  | `dispatch-model` / `await-model` / `dispatch-tool` / `await-tool` | 端口所属插件声明的通用行（`by = PORT_ACTOR`），环只执行 | `I-3` 派发 / 等待 / 配对 + `I-6.1` / `I-6.7` |
  | 协议覆盖行（`phase = 8`） | 保留（`by: None`，记账 / 归宿） | `I-3` 记账 |

- **裁决六：绑定表与 `actors()` 的演进。** `actors()` 从「14 个动作的静态表」降成一次判别：
  `by == PORT_ACTOR` ⇒ 环通用受理入口；`by == PLUGIN_ROW` ⇒ `rows::handler_for(row)`；
  无实现 ⇒ 装载期红（`EX-005`）。`ActorDecl` 的写名单由 `RowHandler::writes()` 并集给出（现成
  机制，D-241 / D-248）。`loop_rows.rs` 不再出现 `model` / `tool` 字面：端口债行由端口所属
  插件随 `PortDecl` 一起声明（`notify` 已是这个形状，D-302），环只按 `Frozen::ports()` 与
  行表执行。依据：`I-3` 选债 / 派发 + `I-6.1` / `I-6.7` + 判定式行 1。
- **裁决七：施工顺序的一处重排（如实记）。** `Action` 是当前轮管线的唯一执行器，
  第一笔就删它只能得到「编译过、跑不起来」。合法顺序因此是：先把每一行的纯值 handler /
  provider 执行体落地（原「步 2」），再切 `drive` 走「行 + 债 + provider」（原「步 3」），
  最后删 `Action` 与旧链（原「步 1 的执行面」+「步 4」）。行形状本身（`Decl` 不再绑动作、
  `Ctx` 去 `TurnSession`）在切换提交里一次到位。目标不变，只是把「可编译、可跑」放到
  每一步前面。

### D-305 新编排契约：通用执行上下文、无 turn schema、批不成立

本条兑现 `D-303` 留白、`D-304` 裁决七所依赖的那份「新编排契约的形状」。

- **裁决一：执行上下文通用化（`ExecCtx` 加 `emit`）。**
  - `PortExecContext` 在 `deadline_ms` / `abort` / `idempotency_key` / `sink` / `ctx`
    之外增加通用 `emit`：provider 执行一笔债期间可追加**事实草稿**，由宿主唯一写口按
    幂等键落行。流式增量、用量记账、进度全部走它或 `sink`，两者都**不得具名世界**
    （`I-6.2`）。
  - 环只见「一笔 `request` → 一笔 `response`」；`emit` 落下的行归 provider 所有，
    环不解析、不识别（`I-4`）。幂等键由 provider 在草稿里给出，宿主吸收重复
    （重试与续写幕会重复投递同一份草稿）。
  - 载荷组装归**欠债的那个行**（从事实组装）；环把 `request` 载荷原样交给 provider，
    不渲染 prompt、不做终止判定、不做结果提取（`I-2` + 判定式行 2）。
  - `model` 端口补齐通用 `executor()`：`begin_model` / `await_model` 里属于「一次往返」
    的语义（请求构造、流式帧、工具调用累计、用量与计价、终止判定、收容）搬进
    `symbio-plugin-model`；环只剩选债 / 派发 / 等待 / 配对 / 记账。依据：`I-5` +
    判定式行 3 + `I-6.2`。
- **裁决二：不立 turn 状态 schema。**
  - 禁止为 `turn_head` 的格子新造事实 schema（不引入任何持久化的幕 / 步游标）。
  - 逐格消解：世界事实（`answered` = 模型 `response`）直接派生；可由债与配对算出的
    （`closeable` = 配对完成、`request_overhead` = 预算 / 租约）派生；编排记忆
    （`prepared` / `opening_text` 等）删除；展示内容进平铺 item 流。
  - 环判断「当前该欠哪笔债」只能来自**已存在的事实行 + 未配对 / 未偿的债**。依据：
    `I-4` + 判定式行 1 / 4。
- **裁决三：批不成立，多笔并行成立。**
  - 一次调用一笔债（`I-1`）；一个响应由 decl 决定派多个调用时，是 N 笔独立债，各自配对。
  - 「批尾关账」= 配对完成；「等待进展」= `response` 事实；「轮内注入」= provider 写展示
    item。三者都不作为机制存在（判定式行 4）。
  - 并发度上限落在既有预算 / 租约，不新立策略机制、不进端口接口、不进 `PortDecl`（`I-6.4`）。
  - `tool` 端口维持单笔执行；`tool_dispatch` / `tools/**` 里按批写的生命周期按此重写为
    「多笔债 + provider 内部」。
  - session 那六个直接握环内可变状态的动作行（`run_classify` / `run_recall` /
    `run_compress` / `run_seam` / `run_report` / `run_continue`）按第二条逐条判：
    降成事实行、或作为 provider 执行、或删除；不允许继续以 `fn(&mut Ctx)` 存在。
- **施工顺序（每笔可编译可跑、每笔单独提交）**：① 本条文档；② `ExecCtx` 加 `emit` +
  `model` 通用 `executor()` + 一次往返语义搬入 provider；③ 行去动作化（取消 `by: Action`、
  行只留 `phase` / `anchor` / `reads` / `owes` / 配对、`Ctx` 去 `TurnSession`）；④ 接通
  「行 + 债 + provider」驱动路径并让 e2e 全通；⑤ 删旧链（`turn_exec` / `turn_runner` /
  `turn_session` / `tool_dispatch` / `tools/**` 与 `chat_loop` 里按 turn 判决的分支，不留
  薄壳、不留仅测试引用的死模块）；⑥ `loop_rows.rs` 只留环行，同步收窄 LP-003 / LP-004 /
  LP-005 基线与 turn 词根基线（棘轮按实测下调，不留虚假余量）。
- **纪律**：不以难度、棘轮、既有判定为由让步；棘轮调整须写清「现有数值本身错在哪 /
  判据该改」，禁止为过门禁上调。每笔跑 check / fmt / clippy `-D warnings` / loop 纯度 /
  迁移审计；阶段跑 `gate --full` + 全量 e2e + 干净 HEAD 上的 `cargo test --workspace`。
  任何一步若需改 loop 才能接入新的世界端口，判为该步设计错误，就地回退。

### D-306 行不再是动作函数：`by` 移除、可还性三派生、载荷与增量归世界

本条兑现 `D-304` 裁决二 / 裁决六的留白（`by` 的两个宿主词汇也不留）与 `D-305` 剩余的
契约缺口，是「行去动作化」批次的**最终口径**。

- **裁决一：`Decl.by` 移除，「谁执行」与「还不能执行」都由数据派生。**
  - `Decl` 不再有 `by`；`loop_rows::ACTORS` 绑定表、`bound_rows`、`dispatch_gaps`、
    `actor_names` 一并删除。
  - **谁执行**只由两样数据决定：`owes` 是否指向 `request(port=…)`。是 ⇒ 环的通用受理
    入口（`D-301` / `execute_one`）；否 ⇒ `rows::handler_for(row)`（该行所属插件提交的
    `RowHandler`）。`PORT_ACTOR` / `PLUGIN_ROW` 的判别保留为**环内派生**，不再是
    `Decl` 上的字段——行不能声明自己归谁，只能由它的 `owes` 与注册表回答。
  - **还不能执行**由三条派生，取代旧的 `blocked = (by = None) ∨ unless 命中`：
    ① `reads` 未全部产出（`UnproducedPrecondition`）；
    ② 存在**未配对的前序债**（按 `(phase, anchor, name, key)` 更小、且无 `response` /
    `failed` 同键事实）；
    ③ 端口 `provider` 缺失或被停用（按 `D-298` 响亮失败，不静默跳过）。
  - `reads` 从 `ActorDecl` **上移**到 `Decl`：行级声明「这一行可执行前必须已在事实源里
    成立」的名单（事实名或视图名）。`ActorDecl` 只留 `name` / `mode` / `writes`；
    `ActorDecl::reads` 删除，装载期的视图存在性检查改由行侧 `reads` 承担。
  - `unless` 的语义收窄为「这笔债不成立」（与 `until` 同键同效）：旧语义「欠着但没人还」
    不再是一个可表达的态，它被上述三条替代。存量声明的 `unless` 全为空，本步不改行为。
  - **内核冻结面变更（须随 `Core-Change` 提交）**：只动
    `symbio-kernel::decl::ring` 的 `Decl` 字段集与 `owed` 的可还性判定；`drive` / `next`
    的选择规则（`phase, anchor, name, key` 全序）与一笔债的五格**不动**。
    替代机制：可还性从「看声明的 `by` 是否为空」换成「看上述三条派生」。
    迁移路径：先给 16 行与全部插件行补 `reads` → 再删 `by` → 最后删绑定表与过滤函数；
    中间态只允许存在于本批次内，收口时 `by` 不得残留。
    影响面：`Decl { by: … }` 构造点 89 处 / 44 个文件、`ACTORS` 16 条、环侧
    `bound_rows` / `dispatch_gaps` / `actor_names` 三个函数。
  - 依据：`I-1`（一笔债五格）/ `I-2`（decl 只引用事实行与端口名）/ `I-3`（七职）/
    `I-4`（不持 turn 状态）+ 判定式行 1 / 4。
- **裁决二：载荷装配留在行，端口只收值。**
  - `owes` 携带**通用载荷**（行的值草稿 / 值集合）：行把「这一次要发什么」写成
    `request(port=…)` 的 `FactDraft`，`payload` 是通用 JSON；provider 只读这笔 request
    的载荷，不扫事实、不认识键。
  - `RowStep::Ask` / `ModelAsk` / `AnswerStep` / `answers()` 一类**具名载荷类型**删除：
    「要一次模型往返」就是「欠一笔 `request(port=model)`」，与任何端口同形。
  - **不扩 `RowRequest` 的世界能力面**（不加工具清单、不加配置快照），也不让 provider
    反向扫事实补载荷；缺的能力面若确需，只能由所属插件在自己的声明/执行体里持有。
  - 依据：`I-2` / `I-6.2`（端口只收 `port + payload`）+ 判定式行 2 / 3。
- **裁决三：文本增量不新开通道。**（**「增量入事实」这一半已撤回，见 `D-314`**）
  - ~~增量**就是** provider 经 `emit` 落下的自有事实行（带 `seq`）；展示层按行名投影
    item，不读 provider 的私有流。~~

    任何一条；逐 token 落事实会让环按载荷粒度读事实（`I-4` / `I-6.2`）。替代：增量走
    `PortExecContext.sink` 的瞬时帧（与工具帧同一个面），不进事实表、不参与重放、不写
    幂等键；丢帧不影响正确性，最终以 `response` 为准。
  - 后半段（`DeltaSink` / `UiBridge` / `stage_events` 按角色拆）不变；「不新开通道」判据
    也不变——走既有 `sink`，不新增私有流。
- **裁决四：`TurnState` 十格去向表（逐格落地，不新造 turn schema）。**

  | 格 | 去向 | 依据 |
  |---|---|---|
  | `request_round` | 删除（`D-074` 已判恒 0 的轮内计数） | 判定式行 4 |
  | `last_saved` | 事实行（已落库锚点） | `I-2` |
  | `input_utterance` | 用户消息事实 | `I-2` |
  | `recall_view` | 能力包检索事实行 | 判定式行 2 |
  | `context_sections` | 能力包检索事实行 | 判定式行 2 |
  | `opening_text` | 展示 item | `I-4` |
  | `opening_dialog` | 展示 item | `I-4` |
  | `head_answer` | 模型 `response` 事实 | `I-2` |
  | `request_overhead` | 预算 / 租约（`I-6.4`） | 判定式行 1 |
  | `consolidated` | 写者令牌 + 幂等事实 | `I-3` 记账 |

  环判断「当前该欠哪笔债」只能来自**已存在的事实行 + 未配对 / 未偿的债**；不引入任何
  持久化的幕 / 步游标（`D-305` 裁决二）。
- **裁决五：`after` 效应归各自能力包的行。**
  - 巩固 / 校准 / 技能落格（`derived_facts` / `memory_events` / `tools/**::effects`）不是

### D-311 P1c 的端口三动作形状：开账 / 派发 / 配对

- **依据。** `D-308` 把 P1c 排给「派发 / 配对」，但只给了排期，没给端口边界的形状。
  §0 的 I-1 已钉死：环的单位是**债**，一次端口调用一笔；「批」是旧「模型 + 工具合并
  轮次」的残留，不是环的机制。本条把三动作的归属与合同一次裁决，P1c 各切点只照它施工。
- **开账：环做。** `open-tools` 依据 response 事实开出 **N 笔独立**
  `request(port=tool)`，一笔债对应一次调用；债由声明方欠出，执行体只消费、不生成债。
  载荷只带**中性键**（调用标识、名称、参数值）与授权结论的引用，不带世界类型；世界
  语义（线上名解析、风险档、参数含义）留在提供者一侧。
- **派发：环按端口名 + 债走 `execute_one` 通用入口。** 允许 N 笔在途，但**没有「批」
  这一单元**：并发策略、顺序、熔断、重试节奏全部归 provider 内部，环不知道也不参与。
  环只认「这一笔债派出去、等它还」。
- **配对：环做。** 按调用标识把 `response` / `failed` 与 `request` **逐笔**配上；租约
  超时由环写 `failed` 事实（这是环的「预算与租约」职务）。产物落格、进展帧、拒绝事实
  由执行体经 `emit` 落——写方与读方在同一份事实面上，不是环的私有记账。
- **`PortDecl.concurrency` 的边界。** 该字段是**插件自声明配置**，只由执行体自己读、
  用来限制自己的执行窗口；**环不得读取它，也不得据此决定同时派几笔**（X-15）。环的
  派发单位是债，一次一笔。
- **执行体的上下文边界。** 执行体**不得**持有 `store` / `ActorSpec` / 环的 actor 表：
  写只有 `emit`（宿主写口），读只走既有只读事实面（`facts` / `history`）；读数不够就
  扩这个**通用只读面**，不开写句柄、不留特例。
- **三道闸门归能力包。** 淘汰 / 承诺 / 任务表三道按名闸门是**能力包策略**，搬去各自
  能力包的行或执行体；它们不是环的机制面，不留在 `tools/dispatch/gates.rs`。
- **影响面。** `symbio-plugin-loop` 的 `tool_dispatch`（三动作契约与 `close_batch`
  配对）、`tools/tool_executor`（`RoundEnv` 信封装配）、`tools/dispatch/batch.rs`、
  `gates.rs`、`unfinished.rs`、`parallel.rs`（并行编排移 provider）；开账入口
  `open-tools` 的债化；`symbio-plugin-tool` 的 `execute_one` 通用入口与 provider 内
  并发。旧的批入口与并行编排在 P1c 各切点随替代品删除，不保留兼容层。
- **切点顺序。** P1c-1 开账（N 笔 `request`，删旧开账/批入口中被替代部分）→ P1c-2
  派发（`execute_one`，删 `tools/tool_executor.rs` 信封装配与 `dispatch/parallel.rs`
  编排）→ P1c-3 配对 + 删除（配对与租约超时留环，删 `tool_dispatch.rs` 与
  `tools/dispatch/**` 已被替代的部分）。每切点独立可编译、e2e 绿、独立提交。
- **到期点。** 旧链（`ToolDispatch` 的三动作与批配对）在 **P4** 统一删除；`D-307` /
  `D-310` 所述旧授权动作的到期点同挂在 P4。本条属核心面变更（提交说明当场带字面
  `Core-Change:` 行，`Core-Change: D-311`）。

### D-312 P1c-4 的方向：节点是事实的投影，不是可写对象

- **依据。** `D-311` 把 P1c-4 排成「用 `emit` 面替换三段」，默认前提仍是「节点由写侧

### D-314 模型往返四类事实的写方：`sent` / `retry` 留环，`response` / `failed` 归执行体

- **依据。** `D-313` 的 P2-3 承接句把「写 `sent` / `response` / `failed` / `retry`」一并压给
  模型执行体，而端口契约的「谁写哪一条」表把四类都归引擎；`D-305` 裁决一只说「一次往返的
  语义归执行体」，没说协议记账归谁。两处说法不一致，本条把写方一次裁决，后续 P2-3 各切点只照它施工。
- **`sent` / `retry` 留环。** 写 `sent` 需要三样只有环持有、且不含世界语义的记账输入：
  `PortDecl`（`before` 事件种类、`lease_ms`、`max_attempts`）、按冻结行表现读「这一行还欠不欠」
  （`D-136` 的唯一现读点，`port::begin_with_facts`），以及 `Call::via`；`retry` 由租约看护者
  `reap` 在过期判定后写出。把这些推进执行体，等于把「欠不欠」的结论或一份 `PortDecl` 副本交给
  执行体（`D-136` 禁止前者，两个 owner 违反后者），而 `PortExecContext` 今天也不暴露这些面。
  **它们是环的记账机制，不是世界语义。**
- **`response` / `failed` 归执行体。** 这两条是「一次往返对他说了什么、为什么没说完」的载荷，
  世界语义全在执行体一侧：执行体经 `emit` 落事实（`PortFactEmit` + `FactDraft`），载荷自行
  构造，环不装配、不复述。宿主写口 `HostFactWriter` 仍是唯一落库通道，执行体只提交事实草稿。
- **端口模块的「谁写哪一条」表按此改。** 不再写「四类都由引擎写」：`request` 决策者、
  `sent` / `retry` 引擎与租约看护者、`response` / `failed` 执行体（经 `emit`）。
- **两条通道（账 / 流），不许混。**
  1. **账**（事实表）：`request` / `sent` / `response` / `failed` / `retry`。一笔债一条，
     可配对、可重放、有幂等键。`sent` / `retry` 留环；`response` / `failed` 由执行体经
     `emit` 落格。**`response` 只存终稿全文**，不存增量。
  2. **流**（瞬时帧）：token 增量走 `PortExecContext.sink`（与工具帧同一个面），**不进
     事实表、不参与重放、不写幂等键**。丢帧不影响正确性，最终以 `response` 为准；展示层
     直接消费这些帧。
  - **判定依据**：增量不满足上面四条中的任何一条，且逐 token 落事实会让环按载荷粒度读
