# 义务环判据与归属推导

> **一句话**：环只认「债」这一种单位——**一次端口调用一笔债**，债由 decl 欠出、由 provider 还清，
> 环只做七项职务；不是这七项的东西，不得以机制形式留在环里。
>
> 本文是归属判定的**唯一判据**。凡与本文冲突的既有判断，按 §3 作废清单处理：
> **原文标注作废并指向本条编号，不静默改写**。

## §0 五条不变量

**I-1 单位是债。** 一次端口调用 = 一笔债，事实五格 `request` / `sent` / `response` /
`failed` / `retry`，幂等键 `(port, id, attempt)`。环上**没有「批」这种单元**，也没有
「一个响应包一批调用」；N 次调用 = N 笔债。

**I-2 债由 decl 欠出。** decl 只引用**事实行与端口名**，不引用端口实现、不读端口载荷。
「要调工具」不是模型响应携带的语义，而是声明方（行为 / 能力插件里的 decl）依据事实欠出
`request(port=<工具端口>)`。

**I-3 环的职务只有七项。** 选债 / 派发 / 等待 / 配对 / 记账 / 预算与租约 / 重放。
「保留」的环元素必须能指认它属于其中哪一项。

**I-4 环不碰世界语义。** 环不解析端口载荷、不读 gate、不做批、不做并发策略、不做重试判据、
不做终答判定、不按 turn 组织。

**I-5 provider 只做两件事。** 按契约执行一笔债、把事实写到行上。执行、并发、guard、熔断、
广播、超时、结果守卫全部是 provider 的内部实现。

**I-6 端口接口必须通用。** `PortProvider`（及 `plugin-api` 里所有端口受理面）是环通向世界
的唯一入口，**世界端口种类是开放的**，接口不得具名任何具体世界。

1. **端口身份是数据不是类型**：provider 申报自己服务的端口名（可多个），环只按端口名解析
   provider；不得出现 `ModelProvider` / `ToolProvider` 这类按世界命名的 trait 或分支。
2. **载荷通用**：输入 = 端口名 + 行 / 值草稿；输出 = 事实草稿或错误（错误只带通用分类：
   不可重试 / 可重试 / 需人介入）。接口中不得出现 `ToolCall`、`ModelAsk`、`tool_batch`
   一类具名载荷或具名方法。
3. **行形状归端口插件**：某端口有哪些行、字段如何校验，由该端口所属插件声明，provider
   执行时按行契约自校验；接口不承载世界契约细节。
4. **一次一笔**：`execute` 只承诺执行一笔债。并发由宿主调度多笔债或 provider 内部自理，
   接口不出现批、并发度、熔断、gate 读数等策略参数。
5. **执行上下文通用**：`deadline`、取消、幂等键作为通用上下文传入，命名不得带世界词。
6. **能力协商通用**：可选能力位只允许 `streaming` / `cancel` / `idempotent` 这类通用词。
7. **注册即扩展**：沿用 `multi("port")` 族与行名 `<port:{port}>:{provider_id}`，新增世界
   端口不需要改环、改注册面、改接口。

I-6 是 I-5 的**接口面**：I-5 说「provider 做什么」，I-6 说「环用什么形状问它」。
只要接口具名了一个世界，第二个世界就要么复制一份接口、要么往环里长一个分支——两种都
把世界语义搬回了环。

## §1 唯一判定式

对任一元素，依次问：

1. **它是七项职务之一吗？** 是 ⇒ 归环（保留 / 改写），并指明哪一项职务。
   否 ⇒ 进入 2。
2. **能写成「读事实 → 欠 `request(port=…)`」吗？** 能 ⇒ 归 decl。
3. **能写成「执行一笔债 → 写 `response`」吗？** 能 ⇒ 归 provider。
4. **两者都写不出** ⇒ **不得以机制形式存在**：删除，或降成数据（纯值 / 声明）。

判定式只有这四行；「实现困难」「已有代码顺手」都不构成改变归属的理由（SP-003 纪律 0）。

**端口受理面的额外一问（I-6）**：判为「归 provider」的元素，若它落在**环与 provider 的
接口**上（`PortProvider` 及其方法、端口合同类型），还要再问一次「这个形状具名了某个世界吗？」
具名 ⇒ 改写为通用形状（端口名 + 行 / 值草稿 + 通用错误分类），或移交 provider 内部；
不具名 ⇒ 保留。

## §4 三道门禁

可机械校验的都落成脚本（判据码 `LP-*`，挂 `gate.d`），不可机械校验的留在 §2 判定表。

**LP-001 类型边界**：`crates/symbio-plugin-loop/src` 的生产源码不得 import 任何端口载荷类型
（`ToolCallRequest` / `ToolCallOutcome` / `ToolCallExecutor` / `PortPayload` / `PortReading` /
`PendingPrompt` / `tool_batch::*`），只许端口名、事实行、债。
现状有存量（`port.rs` / `tools/tool_executor.rs`），基线**只许降**；删除步骤见 §2.1 的作废与移运行。

**LP-002 依赖边界**：`symbio-plugin-loop` 的 Cargo 清单不得依赖任何 provider / 插件 crate
（`symbio-provider-*`、`symbio-plugin-<name>`；`symbio-plugin-api` 是机制门面，不在禁列）。
现状把 `symbio-providers` 作为**测试夹具**依赖——生产段已清空，测试段按基线只许降。

**LP-003 世界语义词根**：loop 生产源码不得出现 `batch` / `gate` / `read_gates` / `llm` /
`tool` / `model` / `Batch*` / `Gate*` / `Tool*` / `Model*` / `Turn*` / `turn_*` 词根与硬编码
端口行名（`"tool"` / `"model"` 字面量；`session_port.rs` 的端口名常量
`const PORT: &str = "session"` 同列——loop 里其余 `"session"` 是日志 target，不计）。
基线**只许降**，新增即红。
（`llm` / `tool` / `model` 三个词根并入后，存量计数由 1402 升到 2169——这是**判据覆盖面
变宽、不是实现变宽**；基线按机制重算并从 2169 起只许降。）

**LP-004 端口接口世界词根（I-6.1 / I-6.2）**：`crates/symbio-plugin-api/src/port.rs` 的
`pub trait` / `pub fn` / `pub struct` / `pub enum` 名字与 `PortProvider` 方法名不得出现
`llm` / `tool` / `model` / `batch` / `gate` 词根。`ports::MODEL` / `ports::TOOL` 两个**取值**
常量是数据、不受判（但它们的名字本身由端口插件自报，登记为冻结债直到 `tools/**` 迁移完成）。
存量 **6**（`llm_round_trip` / `model` / `tool_execute` / `ModelProvider` / `ToolCall*` 一组），
基线只许降，见 §5 第 11 条。

**LP-005 载荷类型通用（I-6.2）**：端口受理面的函数签名只许出现通用载荷类型
（`PortInput` / `PortOutcome` / `PortExecContext` / `PortCapabilities` / `PortErrorClass` /
`&dyn PortProvider` / `Arc<dyn PortExecutor>`）；`ToolCall*` / `ModelAsk` / `tool_batch` 一类
具名载荷入签名即红。存量 **3**（同一批冻结债），与 LP-004 同基线，**只许降**。

**两人端口验收（不可机械校验的那一半）**：新增两个与 Model、Tool 无关的世界端口
（`echo` 与 `store`），由两个**各自独立**的测试专用 provider 实现同一套通用接口
（`PortProvider` + `PortExecutor`），跑通 `request → sent → response` 与
`request → sent → failed` 两条完整债链路；两个端口都走同一个 loop 通用执行入口
`execute_one`。**已跑通**：`crates/symbio-plugin-loop/src/port.test.rs` 两条用例全绿
（20/20），`plugin-api` 端口接口在本次验收中零改动。
验收判据是**新增端口本身零 loop 改动、零 `plugin-api` 接口改动**——loop 为「通用执行入口」
付的那一次固定成本（`execute_one` + `write_before` 抽取）登记在案，之后每加一个端口都不再
增加。`loop_rows.rs` 的 `PORTS` 静态表已参数化：端口声明由所属插件提交
（`model` → `crates/symbio-plugin-model` 的 `declarations.rs`，`tool` →
`crates/symbio-plugin-session` 的 `declarations.rs`），环只经 `Frozen::ports()` 按端口名取用
（`loop_rows::ports()` 是唯一取用口）。**尚未搬走**：`ROWS` 里 model / tool 的编排行仍在 loop
——它们的 `by` 动作住环的绑定表，搬行与搬动作是同一件事，排在 `tools/**` / 模型路径迁移步。
生产第三端口（非测试端口）的**接入面**已跑通：`execute_one` 已接进绑定表（D-301），
`symbio-plugin-telegram` 以 `notify` 端口完成「声明 `PortDecl` + 行（`by = PORT_ACTOR`）
+ 提供者注册 + 真实执行体」，接入该端口 **loop 侧零改动**（D-302）。
仍欠的一环是**开债口**：`request` 事实的生产者仍在 loop 内（`announce` 是环的私事），
第三方插件只能实现端口的执行面、不能从自己的一侧宣布一笔 `request(port=…)`——
这一条不在本笔范围，也不能靠给某端口写特例来掩盖（§5 第 2 条同步记录）。

- **风险与回退点。**
  - **锚歧义**：`open-turn` 须同一次追加落 `turn.stage` 与 `user.message`，驱动只取「最新未收束」；P2-1 首个绿点专门验恢复与中止。
  - **过渡期双写**：每刀只允许一个写方；P2-2 行落格与旧 `finish_turn` 不得同写一格。
  - **预算归属**：`request_overhead` 在 P2-3 变端口载荷 + 租约；执行体不写 `response` 时，环按 `budget_ms` 写 `failed`（与 `D-311` 配对口径一致）。
  - **投影就绪**：P2-4 / P2-5 依赖 P1c-4a 投影（子项、父终态、未执行占位）；未覆盖则先补
    投影，不在环里恢复节点写侧。
  - **回退单元**：每刀一笔，绿点见上表（执行时回填）；失败只回退该笔，
    不整批回退 `D-306` / `D-313`。
  - **不做**：不跑 `gate --full`；不在 `tool_dispatch.rs` 内继续分片；不碰展示面投影实现（承接所必需的前置除外）；不保留薄壳、`#[deprecated]` 空函数或仅测试引用的死模块。
