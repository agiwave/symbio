# 058 沙箱机制（D-531）

> 一句话：沙箱是一个**与 hook 同形的横切能力句柄**——架构层只定义接口与 ctx 键，
> 策略、工具清单、虚拟环境配置全住在沙箱插件内部；工具自声明意图事实，沙箱只匹配事实，
> 既不认识工具名，也不要求架构或插件为它改声明。

本篇登记沙箱机制从「需要全系统适配的上层机制」回退后的重新落地。完整理论推导与
被否方案见 `tmp/沙箱机制重构讨论稿_机制化再梳理.md`（讨论稿，不进门禁）。

### D-531 沙箱作为横切接口：架构只留一个句柄 + ctx 键

**背景**：上一轮实现把 `shell.exec` / `vdfs.write` 等工具实现词汇写进
`symbio-plugin-api` 的 `vocab.rs`，在注册收口处按工具名分流，并给 `CapabilityMeta`
加 `operation` 让沙箱识别工具——每一步都在让架构和插件为沙箱做修改。用户整体回退后
重申：「插件化机制是当前架构设计的核心……沙箱是被调用的执行环境，而不是反过来依赖
于工具实现。」本次重做必须把依赖方向钉正。

**裁决**：

1. **架构层（唯一产物）**：`symbio_sdk::sandbox` 模块只定义四样东西——
   `SandboxFace`（通用能力句柄）、`SandboxFact`（开放意图事实 `{kind, value}`）、
   `SANDBOX`（ctx 键，值类型 `Arc<OnceLock<Arc<dyn SandboxFace>>>`）、
   建槽/发布/读取三个 helper。**零工具名、零 op 常量、零沙箱配置项、零策略**。
2. **两种核心机制由同一句柄屏蔽**（讨论稿 §1.7）：沙箱有两个正交维度——
   执行隔离（转发式拦截，`intercept`）与能力约束（查询式，`permits`），机制不同是本质，
   架构用同一个 `SandboxFace` 把它们统一暴露，具体是转发执行还是规则裁决是插件内部的事。
3. **工具查询只返回 bool**：`permits(&[SandboxFact]) -> bool`；`ask`（询问用户）由沙箱
   在拦截点统一产出审批载荷，不让每个工具实现询问逻辑。
4. **事实是开放数据**：`SandboxFact.kind` 是开放字符串，工具自报新种类无需改 SDK 或沙箱；
   这与被否定的 `CapabilityMeta.operation`（工具身份）本质不同——这里是数据形状。
5. **缺席 = 全放行**：没有沙箱句柄时消费方全放行，保留既有的「无默认沙箱、批准不等于
   隔离」诚实提示（不新增机制）。
6. **发布唯一性**：`sandbox_publish` 用 `OnceLock::set`，第二个发布方被拒、不静默顶掉——
   与端口判重「同名冲突即不可执行」同一纪律。

**不做什么**（明确的反例，防止下一个人再踩）：

- 不向 `vocab.rs` 加任何工具 op 常量；
- 不给 `CapabilityMeta` 加 `operation` 或任何沙箱专用字段；
- 不在 `register_tool` 收口按工具名/操作分流；
- 不让沙箱 `is_known_op` 认识工具清单；
- 不新增 `PORT_SANDBOX` 之类的专用机制键（复用 `SANDBOX` 句柄 + ctx 键，与 hook 同形）。

**Core-Change**：这是内核/SDK 改动，理由是本轮必须在共享层定义一个**与 hook 同形的横切
接口**，让发布方（sandbox 插件）与互不认识的消费方（tool / 各工具）能在进程内交换句柄
而不直连——这是 DE-023「插件只依赖宿主机制层」的同一条归属规则（与 `AGENT_PERMS`
共享槽同判据）。改动严格限于接口形状 + ctx 键 + helper，不含任何策略或工具名。

**门禁影响**：门面 SDK 臂转出沙箱接口条目时按 HS-002 两条准入逐条过（不提能力名 ✅、
≥2 条能力要用 ✅——发布方 sandbox + 拦截消费方 tool + 查询消费方工具），并同步上调
`SDK_BASELINE`（记在本条，随门面转出同批提交）。门面纯 `pub use` 转发不改自有实现行数
（FA-001/FA-002 不触发）。

### D-533 沙箱安全修复：授权、裁决与管理主体都必须是服务端事实

**背景**：首轮实现把模型参数 `approved` 当授权、把通用 VDFS 写入当管理入口、把缺失
档案当全放行，并把 `risk <= threshold` 的阈值方向在界面上写反。局部补判断无法消除
「策略读取—审批—执行」之间的竞态，也无法证明一次批准只属于原调用。

**裁决**：

1. **模型参数不是授权**。`args.approved` 只可作为历史载荷兼容读取，执行链一律忽略；
   审批恢复只能由宿主在验证 `user.answer=approve`、原 `call_id` 与 artifact 后，签发
   绑定调用、规范化工具名、参数摘要、会话、档案版本和有效期的内存一次性
   `ApprovalGrant`。grant 只在执行闸门原子消费；改参、重放、过期、版本变化均不放行。
2. **沙箱裁决是一次快照读取**。`SandboxFace::decide` 在同一档案快照内返回许可、风险、
   拦截载荷、审批模式和阈值；执行链只消费这一次结果，不再分别读取 `permits` /
   `risk_of` / 会话中装配期写入的审批参数。规则风险是工具风险的**下限**，不得调低。
3. **显式选中的档案失败即拒绝**。`selected=None` 保留「无沙箱」语义；`selected=Some(id)`
   但档案缺失、损坏或读取失败一律拒绝。重载事务化，新档案集未完整校验前继续使用
   上一份已知良好快照；首次加载失败不发布放行快照。
4. **阈值表示最大自动放行风险**。`risk <= threshold` 比较不变，内置 `strict` 取 `low`，
   界面与 schema 统一写「高于阈值需审批」。`unattended` 只改变无人值守时的失败方式，
   不表示更宽松或更严格。
5. **管理面与模型面分离**。VDFS 调用携带宿主注入的可信主体；沙箱档案 Write / Delete /
   Action 仅接受 Manager。模型工具调用即使走通用 VDFS 根也不能改策略；`builtin` 与路径
   字符串都不是授权依据。未知主体拒绝管理写入。
6. **事实与路径按语义归一化**。工具提交命令、子命令、重定向目标、路径和 URL 的结构化
   事实；无法安全解析的执行意图不得降级成放行。路径前缀按段比较，物理写入检查全部
   现存祖先，物理读拒绝已发现的链接 / 重解析点；外部进程在校验后替换组件的 TOCTOU
   仍是平台限制，不声称当前机制提供进程隔离。
7. **边界保持诚实**。上述修复收紧的是策略、授权和文件访问，不把当前实现声称为容器级
   执行、网络或进程隔离；真正隔离另立实施项，不能以「沙箱」命名冒充已提供。
8. **出站每一跳都是新决策**。禁用自动重定向；scheme、字面主机、完整 DNS 答案、Agent
   域名授权和沙箱 URL 规则逐跳重验，连接钉住已校验公网地址并禁用代理。Location 不在
   原调用已审批参数内，命中高于自动放行阈值的规则必须在工具内拒绝并提示单独审批；
   超时预算覆盖整条重定向链，不能每跳重置。唯一例外是管理员显式配置的 `web_search`
   上游初始 origin：它等价于宿主选定的服务地址，允许内网 / 回环以支持自建搜索服务；
   模型仍不能选择地址，scheme / 凭据 / Agent 域名 / 沙箱裁决不豁免，重定向即使回到
   同一内网 origin 也按公网规则拒绝。
9. **沙箱事实不入义务环**。命令、路径、URL、MCP 参数等只是执行授权面的意图投影，不写成
   会话业务事实，也不进入承诺 / 义务记账；会话只保留 `sandbox_id` 作为执行上下文选择。
10. **解析、凭据与恢复不得留下旁路**。内层 shell 脚本只递归投影，不再作为外层路径事实；
    Windows cmd 插入符转义无法安全枚举时失败关闭；路径规则先折叠 `..` 且越根拒绝，避免
    前置 allow 遮蔽后续 deny。MCP 凭据字段与 URL userinfo 在投影前删除。审批答复的并发
    领取以进程内进行中集合原子化，不依赖某个端口执行体实例的生命周期；完成后由产物
    收束状态阻止顺序重放。首次注册表加载失败时，即使未显式选档也拒绝发布放行裁决。
    续会话的授权事实读取目标会话存储的 `workdir` / `agent_id`，显式声明与存储不一致即拒绝，
    不能用调用参数给实际执行主体贴上另一个 Agent 的规则。

**Core-Change**：SDK 新增 `SandboxDecision` 与能力域 `ApprovalGrant` 两条跨插件契约，
前者供 sandbox 发布方与 tool 执行闸门交换同一次裁决，后者供 tool 恢复审批与 collectors
执行闸门交换一次性凭据；两者都不含工具清单、路径策略或业务字段。加上进程内可信主体
`VdfsCaller` / `VDFS_CALLER`，门面 SDK 臂共 +4，`SDK_BASELINE` 113 → 117，理由即本条
1 / 2 / 5；共享路径纯语法 `vdfs_normalize_path` 与 `vdfs_resolve_path` 使门面
语法臂 110 → 112，理由即本条 6。VDFS 可信主体落实为进程内 `VdfsCaller` 类型键：宿主管理
入口写 `Manager`，模型执行链写 `Model`，元数据无法构造该类型；理由即本条 5。
CS-009 另显式放宽公共 struct 字段 622 → 630：`SandboxDecision` 七格与 `ApprovalGrant`
一格分别是完整裁决快照和跨 crate 一次性凭据的必需载体，不含策略或业务词；public enum
变体 256 → 258，`VdfsCaller` 两格随可信主体一起入扫。两组都钉到实测、不留余量，理由即
本条 1 / 2 / 5 / 10。

**不做什么**：

- 不保留任何「模型说自己已批准」的执行旁路；
- 不把损坏档案、读取失败或未知主体解释成默认放行；
- 不通过前端隐藏按钮替代后端授权；
- 不在机制层加入 shell / path / sandbox 等业务词。
