# 058 沙箱机制

## 职责边界

- 沙箱是工具调用前的横切策略，不进入义务环，也不产生承诺事实。会话只保留 `sandbox_id` 作为选择。
- 工具拥有调用意图、动态风险与审批摘要；sandbox 拥有档案、规则、审批策略与永久授权；
  平台拥有不可绕过的授权执行；前端只渲染服务端给出的范围、原因与档案绑定。
- 架构层定义开放事实 `SandboxFact`、兼容裁决 `SandboxDecision`、`SandboxFace` 与
  `ApprovalPolicy` 接口形状，不定义具体工具、策略或配置。
- `GatedExecutor` 仍是所有注册工具的唯一执行前闸门。策略缺席时拒绝执行，不得把“未装配”
  解释为“无需审批”。

## 档案与缺席

- 宿主在 `SANDBOX` 与 `APPROVAL_POLICY` 共享槽发布实现；同趟收集幂等发布，不替换首份句柄。
- 未选择档案时使用内置 `default`；显式选择 `none` 才表示不限制。显式档案缺失、损坏或
  注册表没有良好快照时拒绝执行。
- 重载使用事务化快照；新档案未完整校验前继续使用旧的可用快照，管理面显式提示最近错误。
- 每个档案有独立 revision。档案内容变化或删除后同名重建都会使旧一次性审批绑定失效；
  无关档案变化不改变当前档案绑定。

## 单次决策

`SandboxFace::decide` 在同一档案快照内返回兼容裁决。新执行路径由 `ApprovalPolicy::evaluate`
直接返回放行、拒绝、拦截或需审批，不再把阈值与授权优先级拆成多次跨快照读取。

- `permits` 匹配工具提交的意图事实，`risk_of` 给出动态风险下限，`intercept` 处理显式拦截。
- 风险阈值是最大自动放行风险；无人值守只改变需审批时的失败处理，不提高阈值。
- 会话运行模式是本次调用的硬约束：档案声明交互审批但会话是 `auto` 时，平台返回
  `PERMISSION_DENIED`，不产出无人可批的确认卡，也不把会话钉死在等待态。
- 工具提交可安全解析的命令、子命令、重定向、路径、URL 等事实；解析失败时失败关闭。
- 路径按段比较，先折叠 `..`。物理写检查全部现存祖先；物理读拒绝已发现的链接与重解析点。
- 上述检查不能消除检查与使用之间的时间窗，本机制不声称进程级、容器级或网络级隔离。

## 审批与授权

- 模型参数中的 `approved` 不是授权。平台验证用户答复、`call_id` 与审批产物后才能签发
  一次性 `ApprovalGrant`；闸门原子消费，内层执行体只认平台写入的可信标记。
- 固定优先级为：硬拒绝、拦截、事实解析失败 → 有效一次性批准 → 会话自动放行偏好 →
  永久自动放行授权。任何授权都不能覆盖硬拒绝。
- 有效风险为 `max(工具动态风险, 沙箱规则风险下限)`；有效会话阈值为
  `min(会话偏好, 档案阈值)`；永久授权有效上限为 `min(已存上限, 档案阈值)`。
- `once` 始终可用；`session` 与 `permanent` 由档案明确开放。风险超过档案阈值时只提供
  `once`，因为长期授权不能合法突破档案上限。
- grant 绑定调用、规范化工具名、参数摘要、会话、`(profile_id, revision)` 和有效期。
  改参、重放、过期或绑定变化均拒绝；恢复执行仍用完整事实重新裁决。
- 审批卡携带 `approval_scopes`、`approval_reason` 与 `policy`。前端不重算阈值，不根据
  工具名或沙箱类型猜范围；缺失长期授权绑定时不得静默回落 `default`。

## 永久授权与迁移

- 永久授权按 `(profile_id, canonical_tool)` 隔离，存储在 sandbox 插件目录的
  `approval-grants.json`，不进入档案列表。只抬不降，撤销按档案与工具定向删除。
- `sandbox/grant`、`sandbox/grants`、`sandbox/revoke` 是管理面控制协议，仅可信 Manager
  可调用；Model 不能修改策略或授权。授权消费必须经工具执行闸门，Control 路由不是执行面。
- 旧会话 `PLUGIN.yml.approval_grants` 只迁入内置 `default`。非空迁移先备份，再写新文件，
  最后原子清理旧字段；已有备份、损坏文件或不支持版本均失败关闭，不双读双写。
- 执行前投影当前档案且受阈值封顶的授权清单，保证工具环预检与最终闸门使用同一上限。

## VDFS 与凭据

- VDFS 管理调用携带可信 `VdfsCaller`。只有 Manager 能写、删或执行沙箱档案，Model 不能改策略。
- MCP 凭据字段与 URL userinfo 在对外投影前删除；投影失败不得回退为原文上送。
- 出站每一跳重新校验，禁用自动重定向。校验 scheme、完整主机、DNS 解析结果、
  Agent 域名授权与沙箱规则；连接钉住已校验公网地址并禁用代理。
- 管理员显式配置的 `web_search` 上游初始 origin 是唯一例外；模型不能选择地址，重定向仍按公网规则拒绝。
- Windows cmd 无法安全枚举插入符转义时失败关闭。

## 关键决策

### D-001 审批策略协议需要四个公共数据格

策略求值必须把“谁判”（sandbox）与“谁强制执行”（平台）分开，跨 crate 的双方因此
需要一份最小形状：

- `PolicyBinding{profile_id, revision}` 两格：一次性批准只属于当前档案快照。删档后
  同名重建不能复用旧凭据；无关档案变化不应使绑定失效。两格折成一格就丢掉其中一条
  约束，降为 `pub(crate)` 又跨不过 crate 边界。
- `ApprovalEvaluation` 与 `ApprovalScopes` 各一格不透明 tuple：前者把放行、拒绝、拦截、
  需审批及原因收在一次调用内，避免平台跨快照重组裁决；后者把服务端允许的范围交给
  前端，前端不再猜长期授权。内部表示均为私有 enum / 位集，公共面不暴露业务字段。

被否候选：把策略塞回平台会比较工具风险与会话偏好，但读不到档案 revision 与规则快照；
把范围字符串直接交给前端会形成第二份阈值口径。四格承载的是通用审批协议，不认工具名、
路径策略或业务词汇。基线钉到实测 613，不留余量。
