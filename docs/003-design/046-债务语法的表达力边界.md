# 债务语法的表达力边界

本文只规定债前件的表达力与前件生产者检查。债的推进、词表和驱动形状分别归
[DE-050](050-义务环事实词表与债务表.md "DE-050-义务环事实词表与债务表")、
[DE-051](051-机制形状规格.md "DE-051-机制形状规格") 与
[DE-053](053-环驱动与写口裁决.md "DE-053-环驱动与写口裁决")；行声明归
[DE-022](022-行表与派发面.md "DE-022-行表与派发面")。

## 1. 前件语法

`Decl.owes` 接受且只接受一个 `Pattern`：

- 一个事实源；
- 从该事实派生的键字段；
- 字段上的等值约束。

语法不含跨源合取、否定原子或集合表达式。需要“多个条件同时成立”时，拆成有因果关系的
多行，用蕴含与显式标记事实表达；需要“尚未发生”时，用正向放行事实的缺席表达
fail-closed，不增加否定原子。

蕴含链必须保持同键一对一：前置行的出口是后一行的唯一源，且两行使用同一债身份。
授权与派发因此分成两行；拒绝不产生放行事实，派发行自然不成立。集合调用在写入方展开为
逐项标记事实，每次调用形成一笔独立债，不把集合塞进 `Pattern`。

`PTS-003` 冻结求解器形状。增加表达力必须先说明现有谓词无法表达的反例，不得以行数、
实现难度或门禁读数为由扩大语法。

## 2. 前件生产者检查

装载期对每一笔能够开账的行，检查其 `owes` 源；视图源先按 `reads` 展开。每个源事实必须
至少有一个已声明生产者，否则以 `UnproducedPrecondition { row, fact }` fail-closed。

生产者只认四类：

| 生产者 | 范围 |
|---|---|
| 行写入 | 行执行体与能力声明登记的事实写入 |
| 引擎协议事实 | `request` / `sent` / `response` / `failed` / `retry` |
| 宿主事实 | 声明允许宿主代写的事实 |
| 提供者事实写入 | 提供者声明并登记的事实与产物写入面 |

检查只回答“谁能写出这个前件”，不按阶段先后判红。后写先读是合法依赖：事实未出现时
该行不欠账，出现后再开账。唯一生产者缺席必须报错；合法的反向依赖必须通过。

`owes` 被 `until` 完整覆盖的归宿行开不出账，不参与本检查。没有 `FactDecl` 的事实格也
不要求制造一条只为满足检查而存在的行。

## 3. 边界

- 不把宿主事实挪进行执行体来凑生产者。
- 不把跨源键绑定、合取或否定偷偷放进载荷解释。
- 不用端口载荷语义补前件；需要业务判断时，由能力先落显式事实。
- 新增谓词必须同时满足：现有闭集无法表达、答案只能由债状态给出、与既有谓词的对偶
  关系可用一个词说明。
