# 债务语法的表达力边界

> **一句话**：一条债的前件（`Decl.owes`）**能说到多细**、说不到的部分**被转嫁成什么**、
> 那份转嫁的**前提归谁守**——只有这三件事是本文的，其余（债的定义、行表的形状）各有 owner。

## 1 归属：本文不管什么

| 事实 | owner |
|---|---|
| 「债 = 未命中出口的模式」、选债与推进的机制 | [DE-015-义务环](015-义务环.md "DE-015-义务环") |
| 一行怎么声明、派发面怎么记账、带前置判定的端口固定两行 | [DE-022-行表与派发面](022-行表与派发面.md "DE-022-行表与派发面") 的 `D-265` |
| 求解器字节被哪条判据冻结 | `PTS-003`（执行方 `scripts/port-surface-audit.mjs`，基线 `scripts/baselines/port-surface.json`） |

本文只有两条：`owes` 的语法是**一个** `Pattern`（单一事实源 + 键字段 + 等值约束），
没有跨源合取、没有否定原子、没有集合——**这条边界是裁过的，不是默认的**；
以及「前件里的事实由谁写出」这一前提的守法人（`D-296`）。

## 2 说不到的部分被转嫁成了什么

| 表达力缺口 | 转嫁成的写法 | 代码里的自述 |
|---|---|---|
| 写不出 `request ∧ granted` | `authorize-tool` 与 `dispatch-tools` 用**蕴含**代替合取（两行各欠一格，与合取无关） | `loop_rows` 在 `authorize-tool` 上的注释原文：「`Decl.owes` 是**一个** `Pattern`（单源等值），跨源合取写不出来；要写就得改求解器，而求解器的字节是 `PTS-003` 的判据面」 |
| 写不出「这一批的 N 笔」 | `expand` 把集合债摊成 N 笔独立债 ⇒ 4N 条事实 | `D-117`：批次是集合，`expand` 落在唯一能看见 `calls` 的创建行 |
| 写不出「没被拒」 | 靠「`denied` ⇒ 无 `granted` ⇒ 派发行永不成立」间接表达 | 同上的注释：「全程没有否定原子」 |

**转嫁不是近似**：`denied ⇒ 没有 granted ⇒ 派发行永不成立`（fail-closed），而「还没判」是
`authorize-tool` 仍开着、`dispatch-tools` 不欠——两种状态在匹配上可分，全程没有否定原子。

## 3 关键决策

### D-290 求解器不补合取：债的条数由出口格决定，前件写不出「并且」省不出一行

[DE-044-引擎收口与简化](044-引擎收口与简化.md) 的 `E-1` 把「补表达力」列成案**甲**，收益写的是
「工具债 5 行降到 3 行」。`D-265` 把这份税认下时留了一句「那条裁下来时本条作废」——裁它之前先量。
量的口径与引擎账本一致：**一行为什么存在**。环的单位是「债 = 未命中出口的模式」，所以行数等于
这串事实里**出口格的种数**，不等于前件的复杂度。逐行走一遍工具路径的五行：

| 行 | 源 → 出口 | 补了合取能省掉它吗 |
|---|---|---|
| `open-tools` | 模型响应 → `request`（`expand` 摊成 N 笔） | **省不掉**：它的出口是下一行的源，与合取无关 |
| `authorize-tool` | `request` → `authz.granted` \| `authz.denied` | **省不掉**：省它要把判定与派发交给同一个动作，那是 `D-265` 否过三次的形状 |
| `dispatch-tools` | `authz.granted` → `sent` \| `failed` | **省不掉**：同上 |
| `deny-tools` | `authz.denied` → `failed` | **省不掉**：它是一条业务事实（被拒的调用也要收尾），源与出口各一个 `Pattern` |
| `await-tools` | `sent` → `response` \| `failed` | **省不掉**：它存在是因为「在飞」要在两次选债之间读得出来（`D-222` 订正 2） |

⇒ **收益是 0 行**。「5 → 3」把省行的原因记错了账：真正省行的动作是把「判定 + 派发」合进一个执行体，
而那个动作已被 `D-265` 否掉；合取只是它顺带要的语法。另两条缺口同样对不上：「写不出这一批的 N 笔」
由 `expand` 承担（集合展开，不是合取）；「写不出没被拒」是**否定**原子，而甲只提供合取与跨源键绑定，
补完之后 fail-closed 那条间接表达照样留着。三条缺口里甲覆盖一条，那条省 0 行。

**裁决**：**不补**。`Decl.owes` 保持**一个** `Pattern`（单源 + 键字段 + 等值约束），`owed` / `drive`
的字节不动，`PTS-003` 的基线因此**不重算**——这条判据在「不补」分支上的兑现方式就是继续冻结，
后来者想变宽时撞的是同一道红。丙（端口调用改显式状态机）不在本题面上：它换的是债的定义，不是债的语法。

**永久代价**：蕴含代替合取不是免费的等价改写，它有一条**前提**——一行读的源格必须**只能**由前一行的
出口写出来，且与那行**同键 1:1**。今天 `dispatch-tools` 欠 `granted` 而 `granted ⇒ request` 成立，靠的是
两件事：`authz.granted` 只有**一个构造点**（`symbio-plugin-tool` 的 `authz_draft`，从一笔 `port::Call` 长出来，
幂等键由债务 id 给出），且键 `(port, id, attempt)` 在两行之间同形（`D-138`）。
**这个前提没有判据守着**。所以缺口的长期形态不是「多两行」——两行是看得见的——而是：将来出现第二个
`granted` 写方、或一笔请求扇出成 N 条放行、或键不再同形时，蕴含链在数据上悄悄断掉，`dispatch-tools`
就能欠一笔没人开账的派发，而门禁全绿。今天接受的代价是可量的：**行数税 = 带前置判定的端口 1 行**，
**事实税 = 0**（补了合取也不会少写一条 `authz`，那一格是审批卡要拿的理由）。

**重开条件**（任一成立即重开；重开的是「债怎么表达」，不是「合取」这个词）：

1. 出现**第二个** `authz.granted` 构造点，或某行出口与下一行源不再同键 1:1 ⇒ 蕴含不再等价，
   这时先要补的是**跨源键绑定**（甲的半边）；
2. 出现一条债**必须**说「源 A 有、源 B 也有、且同键」，而 fail-closed 表达不出「还没判 / 判了被拒 /
   判了放行」三态可分 ⇒ 补合取；
3. 需要否定原子（「从未发生过 X」）⇒ 那是**第三条**缺口，本条不覆盖，另立决策。

| 被否的候选 | 否掉的理由 |
|---|---|
| 甲：`owes` 收 `&[Pattern]`（合取 + 跨源键绑定） | 省 0 行（上表）；代价是每一行的求解语义与 `PTS-003` 的字节。收益为零的机制变宽，挂不出可辩护的 ADR |
| 为「把 `EL-001` 的 16 降下来」而补 | `EL-001` 判的是**读数**，它存在的目的是逼问「这一行为什么留」；答案是「出口格各一」，那就该留着。用一条机制改动去付一个基线数字，是拿判据当目标 |
| 丙：端口调用改显式状态机 | 动 [DE-015-义务环](015-义务环.md "DE-015-义务环") 的核心定义「债 = 未命中出口的模式」，等于重写方案；本条裁表达力，不裁债的定义 |

### D-296 前件的生产者面：行执行体、引擎格与事件声明上的宿主写口

`D-290` 的「永久代价」留了一句：蕴含替合取的前提（**源格只能由前一行出口写出**）今天没有判据守着。
本条把那条前提收成装载期的一格检查，并先回答「谁算生产者」。

**裁决**：装载期对每一行**会派发**的行（`by = Some`）的 `owes` 源（事实源取自身，视图源按其
`reads` 展开）逐条事实问「生产者集合里至少有一方写出它」；没有 ⇒
`Gap::UnproducedPrecondition { row, fact }`，**fail closed**。`by = None` 的行不在此列：
它在 `owed` 里恒为 blocked，是「尚未接线」的声明位（DE-015 §2.2），不是可还的债。

生产者集合是**四档**，不是一个「有没有行写」的问题：

| 档 | 成员 | 为什么在这一档 |
|---|---|---|
| 行执行体 | 全部 `ActorDecl.writes` + 行级写入名单（`seal(row_writes)`） | 环里由动作落格的事实 |
| 引擎独占格 | `sent` / `response` / `failed` / `retry` | 引擎自己写，不经执行体 |
| 宿主写口 | `EventDecl.host = true` 的格（今天 `user.message`） | 开轮那条事实在循环开始之前就落格；不认这一档，`turn_head` 一类视图会把几乎所有行误报成孤儿 |
| 效果写入声明 | `D-293` 的三类效果（对话面 / 阶段格 / 上线）交出的写入面 | 与宿主写口同义，只是写方是能力而不是运行器 |

**不按阶段先后判红**。检查只问「有没有人写」，不问「谁先谁后」：后阶段写、前阶段读是合法的反向依赖
（`continue-turn` 读的轮次格就比它晚写），`drive` 反复回访的语义也不因此改变。越序的代价由环自己付——
没写出之前那一行不欠账，写出之后它开账；这条前提在账里写明即可，不升格成第二条判据。

**反向用例**（两条，缺一不可）：

1. 删掉某前件的**唯一**生产者 ⇒ 红。这是本条存在的意义：`D-290` 的蕴含链在数据上断掉时，
   装载期就要看见。
2. 保留「后阶段写、前阶段读」的合法反向依赖 ⇒ 绿。把这一条做成红，就会逼实现去改行的阶段划分，
   那是拿判据迁就实现。

**通用补件的边界**：宿主 / 效果一侧若今天没有声明，补的是**生产者面**（内核的事件声明格 +
`plugin-api` 的共享表），不含任何能力名；**不把宿主事实挪进行**来凑绿——挪进环会改变谁负责写，
那是另一条语义改动。

| 被否的候选 | 否掉的理由 |
|---|---|
| 写成「没有任何**行**生产」 | `session.config` / `message.added` 这类宿主事实会被误红，判据从「断链可见」退化成「全部红」 |
| 按 `phase` 判先后，前件必须由更早阶段写出 | 合法反向依赖被误伤；且它把「何时写出」与「有没有人写」两个问题合成一条，红的时候分不清是哪一问 |
| 只查 `owes` 的源名，不展开视图 `reads` | 行实际读的是视图，不展开等于放过了真正的源 |
