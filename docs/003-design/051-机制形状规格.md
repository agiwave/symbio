# 机制形状规格

> **一句话**：DE-047 给的是判据（七职、五事实、归属），本文补的是**形状**——债表长什么样、
> 驱动何时返回、流式怎么分片、同轮能不能并发、何时算完。形状写死之后，「加一个能力」
> 才有一份可检验的局部性承诺，而不是每次遇边界都拿最熟的那种形状（债 / 端口 / 阶段）来补。
>
> 本文只写机制形状，**不写任何业务规则**；业务如何用这些形状，归各能力插件的设计。

## §0 总判据：局部性

五条形状各配一条验证方式，形式统一：**新增能力只动一个插件 crate**，
`crates/symbio-plugin-loop` / `crates/symbio-plugin-api` / `crates/symbio-kernel` 的 diff 为 0。
验证方式不给「应该只动插件」的散文，给可执行的断言：验收提交里对上述三个 crate 跑
`git diff --stat <batch>^ -- <crate>`，输出必须为空；同时跑 `loop-purity-audit`（LP-001…LP-005）。

## §1 债表是数据，且带条件

**形状。** 一行债 = 身份 + 触发条件 + 排除条件。

- 身份：`(scope, port, id)`。`id` 由欠债方从**产生这笔债的事实**派生，禁计数；`attempt` 在债键里推进，不进身份。
- 触发条件（「某事实出现才欠」）：`after = <前置债 id>`。前置债收束（`response` / `failed`）之前，本行不可还。
- 排除条件（「某事实已存在则不欠」）：`unless = <事实 id>`。命中即本圈不产出该行。
- 行只读事实投影，不读引擎自述；表由**端口插件自报**，宿主按族收集，环按行选债。

**环需要什么。** 每圈重问一次 `rows(view, scope)`；每行只给身份、条件、载荷、租约与尝试上限。

**环不需要什么。** 不需要认识行名、端口语义、触发 / 排除的业务含义；不需要保存上一圈的选债结果。

**判据。** 往复（A → B → A）与终止（没有行可还）全部由条件表达，环的 `plan` 源码不变；
跨行前置只写 `id`，不写端口名（否则加端口就要动别的插件）。

**验证方式。** 假插件只在自己的 crate 里申报两行：B 的 `after = A.id`、C 的 `unless = A.id`；
驱动一次 ⇒ 只派发 A；还清 A 后驱动 ⇒ 只派发 B、C 不出现；不碰三个冻结 crate。

**与现有代码的冲突。**
- `DebtRow` 有 `after`，**没有** `unless`。排除目前只能由 `DebtSource` 这一圈少给行来表达——
  判据仍成立（环零改动、加能力只动插件），但「一行」的排除条件被拆进了 source 的代码。
  最小改法：`DebtRow` / `DebtSpec` 各加一个 `unless: Option<String>`，`plan` 加一行过滤。
  这是环的一次性机制改动，不属于「加端口」；改法与 LP-006 的序号禁令无关。

## §2 驱动边界 = 无债即返

**形状。** `drive(ctx, scope)` 同步穷尽到「这一圈没有可还的债」就返回，
出口二选一：`NoDebt`，或 `Waiting(<在飞债的键>)`。它**不阻塞**等用户、等审批、等外部回调；
那些都只是「新事实到达 → 再调用一次 `drive`」。

**环需要什么。** 事实投影的读写、每圈的当前时刻、按端口名解析执行体。

**环不需要什么。** 不需要「人」端口，不需要「会话」端口，不需要任何表示「正在等外部世界动作」的挂起态——
在飞债已经是全部状态（`sent` + 租约）。

**判据。** `drive` 的返回时刻只取决于「有没有可还的债」，不取决于任何外部事件；
同一 scope 两次 `drive` 之间，环不留跨步状态。

**验证方式。** 假插件的执行体只在「入队事实到达」时才可派发：第一次 `drive` 返回 `NoDebt`（瞬时）；
宿主落一条入队事实后再 `drive`，同一行才被派发；全程不新增端口、不改环。

**与现有代码的冲突。** 无。当前 `drive` 已是无债即返；`outlet()` 已经把世界事实转出环外。

## §3 流式 = 分片

**形状。** 一笔债可以产出**多条** `response` 事实：分片按产出顺序落账，末条带完成标记；
配对键始终是 `(scope, port, id, attempt)`，分片序号**只在载荷里**（不进身份、不进配对键）。

**环需要什么。** 执行体返回 / `emit` 的多条 `response` 草稿：按序落账，不合并、不挑第一条。

**环不需要什么。** 不需要认识分片序号的含义，不需要「流式」专用事实种类、专用出口或专用等待态。

**判据。** 加一个流式端口不改环：分片只是同一笔债的多条收束前事实。

**验证方式。** 假插件的执行体 `emit` 三条 `response`（载荷含 `shard: 1|2|3`，末条 `done: true`）；
断言落账三条、`DebtKey` 三处完全相同；不改环。

**与现有代码的冲突。**
- `response_payload` 只取**第一条** `response` 草稿，其余被丢弃；环最后只追加一条 `response`。
  最小改法：环按 `CollectingWriter` 的收集顺序逐条追加。
- 宿主的写口按 `(kind, key)` 吸收重复，多条同键 `response` 会被吞成一条。
  最小改法：宿主的吸收键扩为 `(kind, key, 载荷里的分片号)`；分片号缺席时退回 `(kind, key)`。
  两处都是一次性机制改动，不增加事实种类。

## §4 同轮可派发多笔债

**形状。** 债表里**互不依赖**的若干行可以同时派发；一次 `drive` 的等待集合 = 这一圈全部在飞债的键。
前置条件（§1 的 `after`）仍串行：前置未收束的行不参与并发。

**环需要什么。** `plan` 一次给出全部可派发行；`drive` 并发执行它们，全部收束后再重算一圈。

**环不需要什么。** 不需要并发度参数、不需要批单元、不需要调度策略——并发是「这一圈有几行可还」的直接结果。

**判据。** 同轮多笔债不引入新单元：N 行 = N 笔债，只是同一圈的 N 次 `dispatch`。

**验证方式。** 假插件申报两行互不依赖的债；断言一次 `drive` 的 `dispatched == 2`、`Waiting` 同时包含两键；
第二笔的执行体在与第一笔同圈被调用；不改环之外的任何 crate。

**与现有代码的冲突。**
- `plan` 返回第一个可派发行就停；`dispatch` 内联 `await` 执行体，因此一次 `drive` 实际串行。
  `DriveOutcome::Waiting` 也只收第一个在飞键。
  最小改法：`plan` 返回可派发批；`drive` 用并发组合（如 `futures::join_all`）执行批内各笔；
  `Waiting` 收集全部在飞键。环的一次性机制改动。

## §5 终止 = 事实谓词

**形状。** 一个 scope 算完 = 已落终答事实 ∧ 该 scope 无未还债（`unresolved(scope)` 为空）。
判定由**写方**做：它读事实投影，谓词成立就落一条收束事实。环既不判、也不写。

**环需要什么。** 无新增——环只提供只读投影。

**环不需要什么。** 不需要「收幕」动作、终结指令、阶段出口；`drive` 出口没有「完成」这一态。

**判据。** 「算完」是事实的函数，不是一次控制动作；同一事实集重复驱动只得到同一结论。

**验证方式。** 写方只在新事实到达后重算谓词；断言同一事实集重复驱动不产生第二条收束事实（幂等），
并且删掉写方这一行谓词后，环照常运转（环零知识）。

**与现有代码的冲突。**
- **缺机制。** 本地写方目前读不到环的事实投影：宿主把 `FactView` 只交给 `DebtSource::rows`
  这一处，`DebtFacts` 又是按 `id` 归并的窄视图（只有结局与尝试号，没有终答载荷）。
  最小改法（环 / 契约零改）：宿主在每次 `drive` 前后，把同一份只读投影交给**簿记写方**
  （宿主自己持有的事实，不经环）。这需要一条宿主侧的写方注册面——它属于宿主，不属于环；
  在实现前须先裁决该注册面的形状。
- 若顺序 1（建会话 → 用户发一句 → 模型回复 → 落库）被这一处挡住，按纪律停下报「缺哪个机制」，
  不在环里补终答判定。

## §6 门禁判据：不是外部世界，就不是端口

端口 = 与外部世界交互：**不可控、有延迟、可能失败**。本地能力（存储、转写、簿记）一律以
「写事实」参与，**不许声明端口**。

**机器覆盖（两臂）。**
- 结构臂：`symbio-host` 的收集面只认 `PORT_FAMILY` 行，且每条 port 行的提供者必须有执行体
  （`executor()` 为 `Some`）；任何 `DEBT_FAMILY` 行的端口必须有对应 port 行与执行体，
  租约与尝试上限必须有限。没有执行体的「端口」在装配期即缺席，欠不出可等待的债。
- 语词臂：`scripts/loop-purity-audit.mjs` LP-003（环与端口受理面零世界语义词根）、
  LP-004 / LP-005（`plugin-api` 的端口契约不具名任何世界）。

**边界。** 两臂判的是**装配形状**，判不出一个插件是否在「假装」外部世界——那要评审。
把本地能力做成端口时，它的债会表现为「永远立即成功、租约永远用不上」的一类假债；
这类行的存在本身就是评审信号，本规格不靠脚本识别它。

## §7 落地顺序

1. 宿主独立 + 债表自报（宿主按族收集、无端口白名单；端口插件各自申报债行）；
2. 假插件 `"demo"` 验收：注册 `demo` 端口 + 一笔债，只改新 crate，跑通
   「环选债 → 透传字符串 → 宿主查到执行体 → 执行体还事实 → 环配对」；
3. 回到 e2e 顺序 1。

第 2 步跑不通就停下报「哪一处挡住了」；不绕过、不放宽本规格。

## §8 需要先裁决的环一次性改动

§1 的 `unless`、§3 的两处分片追加、§4 的同轮并发与完整等待集合，都是环的一次性机制改动，
不属于「加端口」。在接受任何能力实现之前先裁决这三处；做完后 §1 / §3 / §4 的验证方式
应当直接可跑。

## 关键决策

### D-324 端口准入：不是外部世界，就不是端口

端口 = 与外部世界交互（不可控、有延迟、可能失败）。本地能力（存储、转写、簿记）一律以
「写事实」参与，不许声明端口。把它做成端口的代价是：环为它欠债、等待、配对，凭空多出
一类「永远立即成功」的假债，租约与重试对它形同虚设；同时多出一个必须实现的执行体接口，
加能力时多一处必改点。门禁覆盖见 §6。

### D-325 机制形状五条固化

债表带触发 / 排除条件；驱动无债即返；流式 = 同一债键的多条事实分片；同轮可并发多笔互不
依赖的债；终止 = 事实谓词。五条是**形状**，不是建议：加能力只动插件，三条判据线
（环、接口、内核）都不因新增端口或新增债务行而改动（验证方式见 §0–§5）。
