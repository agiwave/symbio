# 环驱动与写口裁决（D-320–D-323、D-326–D-327、D-336–D-341）

> 本篇自 DE-048 拆出（同一批裁决只搬家，不改写）：端口机制裁决（D-300–D-319）见
> [DE-048-端口机制裁决](048-端口机制裁决.md)；判据、判定式、作废清单与门禁见 [DE-047-义务环判据与归属推导](047-义务环判据与归属推导.md)。
> D-313 的迁移排期留在 DE-047。

## 关键决策

### D-320 驱动二分：编排入口 `entry` 与薄环 `ring`（已作废，见 D-321）

- **状态：已作废（D-321）。** 本节保留原文以便追溯；判据与授权一律以 D-321 为准。
- **裁决。** 原 `stage_driver.rs` 拆成两份：`entry.rs` 只做**编排**（幕的开启、
  收束与幕间接续；按结局决定「收幕还是接下一幕」），`ring.rs` 只做**债表上的一层薄
  循环**。`stage_driver.rs` 不再存在，也不以中性名保留同一台阶段机。
- **环的白名单（五类，超出即判残留）。** ① 选债：读事实切片 → `loop_rows::next`
  取最小可还的一笔；② `run_port(端口名)`：把这一笔交给绑定表里的动作，由动作按端口名
  受理；③ 落事实与关账：读动作前后的账本尾段，判写封闭与停机格；
  ④ 预算 / 租约守卫：`over_step_limit`（判据是**已 `sent` 的笔数**，不读任何阶段格）、
  `waiting`（未收清）；⑤ 停机判据：无债可还时「在等 / 不前进」两档。
  环不按阶段号 / 轮次序号分支，也不解释行名与端口名。
- **编址归端口。** 协议配对键（`s{n}`、`call id`）由 `port=model` / `port=tool` 的
  执行体生成与解释；环只传递与配对，不用轮号当序。会话推进（开轮 / 唤醒 / 收尾 /
  `finalize`）由 `port=session` 以事实表达（`session.opened` / `session.finalized`
  一类），不在端口内复刻按序号推进的阶段表。
- **判据面。** `CP-003` 的「循环体内」按 `entry.rs` + `ring.rs` 这一对文件判：五道
  守卫仍各只许一个调用点（`aborted` / `abort_before_first_request` 属幕的边界，落在
  `entry.rs`；其余三道在 `ring.rs`），不许出现第二条检查路径。`CP-001` / `CP-002`
  仍只认 `ring.rs` 的唯一循环体与唯一选债口。
- **本次不完成的（如实记）。** `turn.stage` 行与其格子仍在，其内容二分（协议格 →
  `port=model`、会话推进 → `port=session`）是下一个退场单元；本决策只裁驱动文件的
  二分与环白名单，不授权任何端口内阶段机。

### D-321 撤销 D-320：编排不属环内七职，判据主语回到整个 loop

- **D-320 作废。** 编排不属环内七职；判据主语为 `crates/symbio-plugin-loop`
  全部生产文件，不缩到 `ring.rs`；`entry.rs` 为残留，去留按残留处理。
- **撤销理由。** D-320 把「编排」立为环内合法住民，并把判据范围从整个 crate
  缩到 `ring.rs`；结果 `entry.rs` 的 `loop {}` / `open_stage` / `close_stage` /
  `next_stage_round` / `StageRuntime` 仍在，门禁全绿而阶段机健在——这是判据空转，
  不是漏检。
- **环的白名单只约束 `ring.rs` 的代码形状，不构成对任何编排的授权。** 判据主语为
  `crates/symbio-plugin-loop` 全部生产文件。幕的开启 / 收束 / 接续要么归
  `port=session` 的协议线（由事实驱动，不按序号推进），要么由「选债 +
  `run_port`」自然涌现。
- **阶段值不造新名。** 八个 `turn.stage` 取值一律化归为「某端口的一笔 `request`
  及其 `response`」；世界事件名只许出现在该端口自己的声明域，不作为环的判据常量。
- **例外：`turn.stage` 作为能力效果面类型名与 `event_id` 形状属契约冻结**
  （`EffectFace::Stage`，D-293；e2e `t96` / `t97` 已发出的对外契约）。仅许在
  能力 / 效果端口的声明域声明与写入；`symbio-plugin-loop` 不许 import、不许写、
  不许拿它当 `until` 判据、不许解析 `event_id` 里的轮号。清除条件：B3 展示面
  turn 拆除时同批改 e2e，届时一起消失。不得写成永久豁免。

### D-322 环内「已发生」是非债领域事实 `loop.step`，不伪造债务答复

- **背景。** D-321 要求八个阶段值化归债配对。但若环自己写 `request` 又写
  `response`，就是「自问自答」的假账：`response` 是世界的答复，环写它等于配对
  自证，`until` 永远「已还」。授权拒绝的调用同理——没碰到世界的调用写 `sent`
  也是假账。
- **决定。** 环内的一次性步骤不改写成端口债务，而是**环自己的领域事实**
  `loop.step`：`id`（行表数据）+ `anchor`（幕锚）+ `round`（载荷之数）+ 不透明
  载荷。判据是「已发生」，不带 `attempt`，不使用 `request` / `response` 词汇。
- **配对键 = `scope` + `anchor` + 债 id。** 轮号**不进键、不进事件 id**：同一轮
  可以先后开好几幕，轮号重复而幕锚不重复。`round` 只作预算的数（
  `over_step_limit` 数已 `sent` 的笔数）。
- **步 id 只住行数据。** `STEP_*` 常量属于 `loop_rows.rs` 的行表数据（终极形态由
  C 批注册表引入）；事实层（`stage_events`）不持有任何步名闭集，端口名与债务 id
  由调用方当实参传入。环按表查，不按行名分支。
- **`stage_events.rs` 的长期去向。** 它是「环写世界事实」的工地：
  `land_effect`（效果面 `turn.stage`）随 B3 展示面拆除缩成协议数据或整体搬进
  `port=session`；`land`（`loop.step`）随 C 批行表参数化收窄。本文件不是终点。
- **判据。** 环内同一笔不得既写 `request` 又写 `response`；`response` / `failed`
  只由端口执行体写。`loop.step` 不承担任何端口答复语义。

### D-323 债 id 归环、由事实派生；端口只回显（`next_round_trip` 按此删除）

- **依据。** D-320 已被 D-321 撤销，「协议键由执行体生成」随之作废，D-314 与 D-320
  的表面冲突消失。因此不向端口要 id（那会把债的身份交给世界），也不新增 `model.trip`
  按 `trip_no` 配对（那只是把计数器搬进世界，环仍要数）。
- **裁决三条。**
  1. `request.id` 由**欠债方（环）**生成，且必须**由事实派生**：id 里只许出现端口名 +
     产生这笔债的那条事实的 id。首趟用会话开启 / 用户消息事实的 id；续趟用触发它的
     那组调用的 id（多个按稳定顺序拼 / 散列成定长串）。**禁止计数**——不许 `s{n}`、
     不许 `round+1`、不许 `d{anchor}` 中的序号段。理由一句：幂等键必须是一笔债的
     身份，不是它的编号。
  2. 执行体不解读 id，只回显：`response` / `failed` 带同一个 id 与 `attempt`；
     执行体不得自己造 id。
  3. `until` 配对键 = `(port, id, attempt)`；`attempt` 由环的租约递增，属中性字段。
- **落点。** `next_round_trip` 不是换键：**删掉计数器**、改成上述派生规则（P2-6 段 3
  施工）；`loop_rows.rs` 里 announce-model 的 `owes` 随之改指派生 id。
- **连带。** `loop.step`（D-322）不作长期机制：它是环给自己开的进度条，P2-6 段 3
  整条删除，不改名、不改判据。

### D-327 退役文档登记：历史文档的符号指认不随代码回改

- **问题。** `doc-symbol`（D-005）要求文档里的符号在代码里找得到；但**历史文档**记的是
  当时的实现——符号改名的动作本身就会让那些记录「查无此名」。逐条写 allow 会把同一件事
  写七八遍，每条还得解释一次，承认通道被噪声吃掉；写假符号更不行（那是把记录改成假账）。
- **裁决。** 登记为**退役文档**的篇目全文不进入符号判定：一次登记、一个条目，**范围与
  生效条件都写在这里**。`scripts/doc-symbol-audit.mjs` 的 `RETIRED_MD` 是它的机器可读投影
  （每条带 `D-327`），不改脚本判据的语义，只改判定对象。

| 文件 | 为什么是历史 | 登记范围 | 生效条件（何时删这一条） |
|---|---|---|---|
| `docs/007-task/007-loop存量能力迁移.md` | loop 存量能力迁移的实施记录，符号是迁移当时的读法 | 全文符号指认 | 任务收口删除该文件时同提交删本行；任一段落被复用进现行文档，复用段须按现行代码改指 |
| `docs/007-task/031-loop文件级审计与世界语义重分批.md` | loop 文件级审计的分批记录，引用被审当时的文件与符号 | 全文符号指认 | 同上 |
| `docs/007-task/033-旁路替换取材与退役.md` | L2b 取材与退役的执行记录 | 全文符号指认 | 同上 |

- **空转禁令。** 条目与文件同生命周期：文件被删除或被重写进现行文档时，同提交删掉登记行；
  脚本对「目录还在、条目指向的文件已不在」判红——承认通道不许变成永久空转。
- **范围边界。** 只登记上表三篇，**不扩到整个 `docs/007-task/`**：同目录其它任务文档照常判。
  本决策也不豁免**现行**文档：现行文档里的符号查无此名仍是红，改指仍按 D-005 做。
- **不属于本表的退役。** 实现快照类设计文档（如 `DE-102`）走文档自己的 `status: retired`
  登记（正文随退场删除，D-145 约定），由设计目录的汇总表列出，不占本表。

### D-336 跨插件模型往返：共享载荷住 SDK 词汇层 + 端口按用途分成员 + 执行体归端口提供方

- **裁决四条。**
  1. **端口名与执行体均全局按名解析**，债行申报方的端口不必由自己提供。宿主把全部
     `port` 行的端口名 → 执行体建一张全局表（`crates/symbio-host/src/lib.rs:188-199`），
     环派发时只按 `row.port` 取（`crates/symbio-plugin-loop/src/ring/engine.rs:260`，
     解析口 `engine.rs:36`）；`DebtSpec.port` 是端口名字符串，没有「申报方必须提供同名
     端口」的断言。因此 compact 可以申报一行欠 `model` 插件的端口。
  2. **执行体归端口提供方**，因此「拿摘要」与「落压缩事实」必须分属两行。`compact-summarize`
     的 `port = model.assist`，执行体在 model 插件，只负责一次问答；`compact-write` 的
     `port = compact`，执行体在 compact 插件，负责读回摘要并落 `session.consolidated`。
     把两件事塞进一行等于让 model 插件写会话世界的事实，违反 I-4（环与端口不碰世界语义）
     的同一条归属尺子。
  3. **共享载荷住 SDK 词汇层**（与 `ChatNode` 同层：`symbio_sdk::chat::chat_node`，
     经门面既有转发到 `symbio_plugin_api::chat_node`），不进 `plugin-api` 的白名单。
     理由：问答请求 / 回复是**词汇形状**，不是宿主机制；门面新增条目会同时动 HS-002 棘轮
     与「机制层不认识世界语义」的判据。
  4. `model.assist` **只做一次性问答**：不参与对话轮、不带工具、不留会话历史。它的
     `response` 不进入 `turn_input` 的 messages（会话历史只收 `port == model` 的应答），
     也不往展示面写流式帧。
- **被否项。**
  - **A（猜 `model` 载荷形状）**：compact 直接给 `model` 端口写一个「请摘要」载荷，
    model 执行体靠键名猜用途——端口名不表达用途，第二种用途到来时无从区分。
  - **B（`plugin-api` seam）**：在门面上开一个跨插件调用缝。那会把世界语义（问答请求
    的形状与用途）塞进机制层，并让 HS-002 为一条世界需求变宽。
  - **C（事实接力要改 model 债表）**：让 model 自己申报「摘要欠债」。model 不知道会话
    何时需要压缩，改它的债表等于把 compact 的策略写进 model。
  - **②（`@@SUMMARY@@` 隐式替换约定）**：用正文里的标记串在重建面做隐式替换——标记
    会漏进用户可见文本，且把「摘要」变成第二种隐式协议。
- **落点。** 共享载荷 `chat_node::AssistRequest` / `AssistReply`；model 插件新增独立
  提供者 `AssistPort`（端口 `model.assist`，执行体只调 `round_trip`、传空工具表、
  静默流式出口）；compact 的两行债见其 `debt.rs`。端口名避开环事件 id 的保留字符
  （`:`），协议事实的端口位仍从事件 id 还原。
- **已知项（编码风险）**：环的事件 id `ring:{port}:{id}:{attempt}:{kind}` 是
  **「分隔符与内容共用字符空间」**的形态——端口位按 `:` 定界，而债 id 自身也含 `:`，
  靠从右定界把两者分开。端口名一旦含 `:`，端口位就被截断（`model:assist` 会被读成
  `model`），事实键与债键对不上：实测同一笔摘要被重派 39 377 次。**唯一防线是注册期
  拒绝**——`port_rows` 在种行前对保留集 `PORT_NAME_RESERVED`（目前只有 `:`）做
  fail-closed 校验，不转义、不做解码兜底。新增端口名必须避开保留集。
- **已知项（水位字段耦合）**：`compact` 的 `rows()` 读 `chat.assistant.final` 载荷里的
  `context.request_tokens` / `limit_tokens`；这两个字段由 model 执行体写，**不是 SDK
  共享类型**——被否项 A「猜载荷形状」的缺陷在选债层复现。当前唯一消费者是 compact，
  先认；**第二个插件需要同一字段时，提升为 SDK 共享类型，不许各自猜**。

### D-337 只读声明句柄进执行上下文：`PortDeclReader`

- **裁决。** `PortExecContext` 增一格 `decls: Option<Arc<dyn PortDeclReader>>`（随
  `PortExecHandles` 由宿主装配、环原样转交）。句柄只有两个读口：`view(name)` 取
  `ViewDecl`（段身份 / 视图口径），`rows()` 取全部 `Decl`（债行声明：`by` / `owes` /
  `until`）。**没有写口**，也不暴露 `Frozen` 的其余面。
- **为什么不选「session 把段正文写进请求载荷」。** 那要求 session 认识 task 的段语义：
  哪一段、叫什么身份、优先级多少、何时收集。装配（段在请求里的位置、计量与裁剪、
  `role: system`）归 `model` 端口执行体，session 只该说「这一轮发生了什么」。
  把段正文塞进载荷还有一个旧病复发：载荷里重新出现世界形状的「段」，而端口名不表达
  用途——与 D-336 被否项 A（猜载荷形状）同一条理由。
- **为什么必须只读。** 声明表的唯一写通路是插件自己的 `traverse` + 能力收集
  （`submit_declarations!` → 冻结表）。执行期若能写声明，就绕过了那条收集：新增的
  行 / 视图没有任何装载期检查的对象（写入封闭、依赖图、`OrphanActor` 全部空转），
  而「停用即缺席」也立刻失效。`Frozen` 本身没有 `&mut self` 方法；本句柄只是把已有
  的只读表发进执行上下文，不新建第二张表。
- **两个读口服务谁。** `view` 给装配侧取段身份（名字来自声明，不由执行体拼字符串）；
  `rows` 给运行期债适配读「这一行欠什么、什么时候算还」（`plugin_row` 行执行体的输入）。
- **未收口。** 句柄只挂在 `PortExecContext`；环自己的债源读同一张冻结表（`rows()`），
  不复用本句柄——两处的读法各自成立，合并要等第三处读点出现。
- **本决策已回退（`9802eabc`）。** 找不到自然消费者：段身份在 `ContextSection.slot`、
  债行由 `sealed_declarations().rows()` 直接读，全仓没有执行体通过该句柄读声明；
  只读声明句柄不保留（`PortDeclReader` / `sealed_decl_reader()` 与上下文两格一并删除），
  不留空壳。

### D-338 `Ask` 的债归申报方：在等事实 + 机制派生身份

- **裁决。** `RowStep::Ask` 不调模型：`plugin_row` 执行体落一条「在等」事实后挂起；债由
  **申报方**自己声明（notes 申报一条 `model.assist` 行）。端口名可以写别的插件的成员——
  这是 D-336 裁决 1 的既有形态（compact 同样写着 `model.assist`），不是跨世界依赖。
- **事实形状。** 种类 `plugin.row.asked`（`rows::ASK_KIND`，**一个**名字）；id =
  `rows::ask_id(row, key, attempt)`＝`<row>:<key trace>:<attempt>`；载荷
  `{"row": <行名>, "key": <债键>, "prompt": <提示正文>}`。**谁写**：`plugin_row`
  执行体（唯一写方，机制侧）。**谁读**：申报方的债行按 `row` 从载荷里挑自己那行、
  按同一 id 做 `when_id`、并从载荷取提示；`plugin_row` 执行体按同一 id 找
  `response` / `failed` 配对。
- **为什么种类是一个名字。** 世界格子只认声明表上的名字（`wal.rs` 的 `declared_vocab`
  按 `(Entity, Verb)` 校验）。逐行造名（`plugin-row.asked:<行名>`）会让任何未登记的行名
  落进 `OffGrid`，而 `PortFactEmit::emit` 不返回错误——事实会静默丢失。行名因此进载荷，
  种类只剩一个（`plugin-loop/src/vocab.rs` 登记）。
- **为什么必须落事实。** 静态债表没有「这一行此刻在 Ask」这个状态；没有事实，申报方
  只能靠全局 `unless` 猜，第二次反思就再也开不出来。
- **为什么身份由机制派生。** `(row, key, attempt)` 三样环已经都有；让插件在 `ModelAsk`
  里自带 id 等于把配对职责搬进插件载荷（与 D-242 被否项 1 同一条）。
- **为什么端口取 `model.assist`。** `model` 端口的执行体只从会话事实装配输入、载荷只带
  身份（`model/src/port.rs`），一行提示插不进去；`model.assist` 正是一次性问答的成员
  （D-336 裁决 4）。D-304 写的「`request(port=model)`」指的是**模型世界的那一笔往返**，
  到了实现层按一次性问答成员落地。
- **挂起与再触发。** `Ask` 之后执行体返回 `NeedsHuman`：环落 `sent{deadline_ms:null}`，
  债务留在原地。回执落在 sent 之后，行按 `when = response` 重新触发，**同一 attempt** 再
  派发一次；这次执行体读回执并调 [`RowHandler::parse`]，不重发提示、不加 attempt。
- **被否 A（环从事实合成债务）。** 那会把「一次世界交互 = 一笔债」从债表下沉到环，属于
  D-325 五级机制形状的改动；并且与 model 的 `model-reply` 形成两个 owner 认领同一笔 request。
- **被否 C（给 `Decl` 加伴随声明字段）。** 与 D-306（最终删掉 `by` / `tier`）方向相反。
- **债表载荷读口。** 申报方要拿提示正文，只能读「在等」事实的载荷；`DebtFacts` 增
  `facts_of(kind)`（该种类的身份 + 载荷全集）与 `fact_payload(kind, id)`（只读副本，
  判定仍只看种类与身份，不因载荷分支）。申报方用 `key` 里的 `tool_call_id` 认自己那笔
  输入，并以同一键的 `notes.insight` 做 `unless_id`：没有它，同一「在等」事实会在回执
  之后继续产债。

### D-339 写口归属只看声明：`emit` 不再有宿主默认值，`@principal` 由会话装配解析

- **裁决一：归属是声明格，不是写口的默认值。** `EventDecl` 增 `owner` 字段，表示这一格
  落账时信封 `actor` 的主体。`PortFactWriter::emit`（无归属的通用出口）与
  `plugin_row` 执行体的 `emit_attributed` 都只按 `Frozen::event_writer(kind)` 取值；
  查不到就显式失败（写口拒绝猜一个默认值），不再沿用运行期的 `"host"`。
- **裁决二：装配期判红。** 声明 `owner` 为空由 `Builder::seal` 判 `Gap::EventWithoutOwner`
  （启动即红），避免「落账时再猜」把归属变成静默失效。
- **裁决三：`@principal` 是会话哨兵。** 声明写 `@principal` 表示归属由会话装配决定；
  `SessionFactSource::append` 在落格时解析成该会话主体（`principal_of(agent_id)`），
  `session/main` / `session/arbiter` / `session/worker` 由此得到。载体缺失（取不到
  `agent_id`）显式失败，不回落主体；载体在而值为空是「会话确实没有绑定智能体」，
  其主体定义就是 `session/main`——这不是缺主体的兜底，是 `principal_of` 的定义。
  **入口记法**：空串 `agent_id` = 未绑定 ⇒ `session/main` 是入口，不是兜底。
- **裁决四：同族收口。** `RowRequest.principal` 与 `DriveRequest.principal` 都取自开面时
  唯一设置的 `AGENT_ID` 载体，不再写死 `"user"`；`model` 债表载荷的 `principal` 随驱动
  请求而来。`Contribution.actor` 删除——贡献者只交事实，归属由声明给定（记忆
  `memory.encoded` / `memory.consolidated` / `memory.forgotten` 声明 `person/local`；
  `task.ready` / `task.assigned` 声明 `scheduler/main`；其余默认 `@principal`）。
- **裁决五：owner 的第二态是已登记的主体名（不加前缀语法）。** `EventDecl::owner`
  的合法取值只有两种：`@principal`（会话主体，由会话装配按 `agent_id` 解析），或一个
  **已登记的主体名**——各插件 `PLUGIN.yml` 的 `principal_*` 行（运行时投影为
  `production_matrix()` 的行）里查得到的字符串，例如 `session/arbiter`。装配期校验就是
  查这张表：查不到即 panic，不接受任意字符串，也不接受运行期拼出来的名字（声明是
  `'static` 数据，拼出来的名字进不来）。落账时该名字**原样**用作信封 `actor`，声明表
  不做第二次改写。
  - **人的主体是登记过的第二态**：`person/local`（`PRINCIPAL_USER`）刻意不入能力表
    （发言不是「智能体的权威动作种类」，D-099），但它是登记过的主体常量，属合法具名态。
  - **行为仍无权指定作者**：把主体名写进声明是设计决定，不是执行体在落账时的自由
    （`DE-026 D-252` 不变）。
  - **边界**：能用 `@principal` 盖出来的地方一律不许写具名主体；具名态只为「作者主体
    ≠ 会话主体」这一种情形存在。t75 的 `session/worker` 若来自 worker 会话的
    `agent_id`，必须走 `@principal`。
- **不改的面。** 不新增会话端口、不给 `FactDraft` 加 `actor` 字段、不改
  `PortFactWriter::emit_owned` 签名：行为无权指定归属（DE-026 D-252）。
- **只链接部分插件的用例。** 冻结表之外，写口再查 `SHARED_EVENTS`（共享词汇已登记归属）；
  两处都没有才判失败。这不是运行期默认值，而是「共享声明也是声明」。

### D-340 跨会话裁决开面播种：复制已裁决事实，不搬索引

- **问题。** 淘汰的**写侧**是会话级的（读本会话 WAL 算声誉、判既有裁决），闸的**读侧**
  要部署级口径（别处的裁决也要拒）。读侧不能为此去读别人的会话——那等于给执行体开一个
  fleet 读口。缺的只是「新会话的事实流里没有那条裁决」。
- **裁决：由既有的开面调用方在开面时复制。** 播种点是 `SessionPlugin::fact_source`
  （`crates/symbio-plugin-session/src/plugin.rs`）——开轮写面的唯一开面，由
  `vdfs_inbox.rs` 的「入队即开轮」调用、`handle_consume` / `handle_project` 经
  `fact_source_for` 落到同一函数。读面 `crates/symbio/src/drive.rs::open_fact_source`
  发生在开轮之后（CLI 投影 / `session/project`），**不作播种点**；`symbio-deploy` 只是
  插件集合清单，没有开面代码。**不为这条裁决新开 crate / 新组件。**
- **播种判据（`SessionStore::seed_open_verdicts`）。** 仅在会话**尚无事实**
  （`head() == 0`）时执行一次：扫描既有的部署级读 `deep_snapshots()`，按
  `(subject, capability)` last-wins 取**时刻最后**的一条（`ts` 定序，同刻按 `seq` /
  `event_id` 定序），把该条 `verdict.asserted` 复制进本会话 WAL。复制保留原
  `actor` / `payload` / `produced_by`；**不新增信封字段**，审计对账用
  `produced_by` + 载荷 `source_seq`（被复制事实的 `seq`）。复制走 `Store::append`
  直落 WAL，不经 `FactSource::append`——播种**不踢驱动**。
- **唯一允许的直写点（第二处即红）。** `seed_open_verdicts` 里的 `Store::append`
  是**唯一**获准绕过 `FactSource::append` 的**开面 / 部署级复制**直写点，理由只有
  三条：① 播种发生在开轮业务事实之前，踢驱动会开出一个没有 `user.message` 的空轮；
  ② `actor` 是复制来的原值，不是在这里新盖主体（解析 `@principal` 仍只发生在
  `FactSource::append`）；③ 播入事实不参与 owes / settled。它仍经 `WalStore` 的
  写侧闸（形状 / 归属 / 溯源），不是绕过事实源校验的暗门。会话自己的业务事实仍只走
  `FactSource::append`；既有的两个存储所有者写窗口（自主触发事实、消息投影格）不在
  「开面复制」判据内。**再出现第二个面向开面 / 部署级复制的直写口，即红**——它不是
  本裁决留给后来者的通用旁路。
- **诚实边界（台账：已知缺口）。** 只保证**开面时**一致，**运行期不追发**：会话开面
  之后才被撤销（或恢复）的主体，在该会话内**仍按开面时的读数行动**，直到它下一次开面
  （新会话）才看到变化。这是已知缺口，不假装实时同步，也不在文档里暗示「一撤销就全网
  生效」。
- **播入事实不参与 owes / settled。** 它是普通的 `verdict × asserted` 事实：义务环不认
  这个格子（`crates/symbio-plugin-loop` 不读 verdict），既不产生债、也不结算债；唯一
  读方是读侧覆盖层（`EliminationDecider::verdict_grants_changes` → `GrantsOverlay`）。
- **索引不出开面那一处。** 跨会话折叠只在 `seed_open_verdicts` 内出现：不进
  `DriveTarget`、不进 `PortExecContext`、不随任何执行体传递；执行体仍只看会话本地切片
  （`HostReader`）。否则就是换了个名字的 fleet 读口。
- **幂等与失败。** 同一 `(subject, capability)` 只播一条；重复 `append` 按 `Duplicate`
  视为已播（并发开面不重复）。目标 WAL 写失败显式报错，不静默跳过。

### D-341 收束后第二问；判决落事实、措辞走效果（W2c 形状）

**裁决一：收束后第二问。**

- **位置。** `project_final_turn`（驱动空闲、本轮编码已落格之后）再询一次**已注册的
  收束贡献者**。第一问仍在同一收束点、同一批贡献者上完成；第二问是同一批对象的第二次
  求值，不是新开一轮、不新开一个触发位。
- **写口复用同一条归属通道。** 两次问的产物都经 `FactSource::append` 落地，`owner`
  **只从声明表来**（`Settling` 的归属由冻结表判定），不因「第二次问」新增写口、不把
  owner 交给调用方或贡献者自报。
- **`settle.rs` 的既有承诺要兑现。** `crates/symbio-plugin-api/src/settle.rs` 写明
  「每问一个之前重取一次史」——现状是 `flat_map` 一次收尾、一条快照到底，第二问拿到的
  仍是第一问前的史。这不是新裁决，是本条要求落实的**既有承诺**：每次询问前重新取一次
  事实切片，第二问必须看得见第一问刚落下的编码。
- **适用范围收窄（`D-268` / `D-269`）。** 两条裁决判的是**巩固策略**归 memory：
  合并算法、阈值（同标签 ≥4 合并最旧两条）是能力的知识，住 `symbio-plugin-memory`。
  **触发位**（什么时候问、问几次）是控制面的编排，不因策略归能力包而搬走；`D-268`
  的「巩固留控制面」在策略层面仍成立，本条只在触发位补一句：第二问发生在
  `project_final_turn` 的同一控制面时刻，问的对象是声明表上的贡献者。

**裁决二：召回不迁（台账一句）。** `session.recall` 的**选取**在 memory（可见切片与
优先级是记忆策略）、**收放**在宿主隔离面（跨库/跨会话的边界不进能力包）、**存储**
是中性投影。三点各自成立，判定不迁，不再展开。

**裁决三：W2c 形状。**

- **不给 `parse` 加效果通道，不扩 `ModelAsk` 形状。** `parse` 只落事实；一次模型往返
  的载荷仍是提示正文，不背效果。
- **两行接力：回执落事实 → 第二行交效果。** 判决行的一次模型往返（`model.assist`）
  由 `parse` 落一条**判决事实**（`classify.answered` / `classify.escalate`，owner 是
  classify）；措辞行读同一条判决事实，交**纯值效果草稿**（`DialogDraft`，`D-293`），
  由宿主唯一写口落对话面。判决事实是终点事实，不是给下一行临时拼的中间变量。
- **多段请求走 `model.assist` 的 `system` / `user` 载荷。** 对话线投影进 `user`，
  指令进 `system`；不另开「段收集」通道，也不在载荷里再拼世界形状的段。
- **判决必须落成一条事实。** 环只认事实：主线的 `model-reply` 债按该事实的
  `when` / `unless` **抑制**（`classify.answered`）或**放行**（`classify.escalate`），
  分类器缺席时没有该事实，主线照常运行（卸载即缺席）。
- **compose 读同一条 `session.config` 事实。** 提示段、工具表与主体都从本轮
  `session.config` 取，不另起一次段收集、不复制第二份配置读法。
- **不违背 `D-291`。** `D-291` 否掉「两行接力」的前提是：当时没有效果通道，判决只能
  作为被下一行消费的中间事实，且出口卡在 `turn.stage` 的写口上。`D-293` 已把对话面
  改成可声明的纯值效果、写口归宿主；本条接力中的判决事实是 classify 的**领域终点
  事实**（同一条事实被主线门控与展示面读，不依赖某个阶段格的幂等键），往返走
  `D-338` 的 `model.assist` 成员，不是 `D-235` 的 `announce` / `dispatch` / `await`
  三行。`D-291` 的翻案条件（对话面由事实重建 + 「做过没有」由领域事实回答）在本条
  以声明事实的形状兑现，因此不构成翻案，也不与它冲突。

**本轮落地（W2c-1，只做分类）。** classify 能力自有行（规则短路 0 次往返 → `Facts`；
未命中 → `Ask`，回执经 `parse` 落判决事实）＋自有 `model.assist` 债；`model-reply`
按判决事实抑制或放行；compose 的措辞形状与段收集留 W2c-2，本轮不改 compose 插件本体。
