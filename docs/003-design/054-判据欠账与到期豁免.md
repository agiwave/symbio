# 判据欠账与到期豁免

> **一句话**：`EX-007` 的欠账按台阶递减；台阶当天压不动时，只允许「另裁一条带期限的
> 决策」推迟到期——不许凑数迁移，也不许**为了消账**而改计数口径。

`EX-007` 的绝对欠账线、台阶表与逐笔读数的算法见
[DE-026-能力拆分与影响类](026-能力拆分与影响类.md)。本篇承载台阶之外的两种动作：
**到期豁免**，以及**口径本身的修正**（后者必须证明「改完之后没有任何存量欠账消失」）。

### D-403 EX-007 欠账的到期豁免：7 笔，至 2026-11-12

**背景**：`D-375` 的台阶在 `2026-11-09` 把绝对欠账上限压到 6，而存量欠账是 7
（累计补件 25 − 迁移 18）。其中 6 笔是尚待搬迁的存量批次；第 7 笔来自 `91b097fc`
（`D-402` 的压缩失败投影新增 pub 项），把 `2aaa213c` 上的 6 笔推到 7。迁移批次必须
是真的该搬的东西，为对齐日程去搬一段没准备好的代码，等于用假迁移把红刷绿。

**裁决**：

1. 按 `D-375` §5 的「另裁一条新决策」路径起一条**有期限豁免**：`EX-007` 在
   `2026-11-12` 之前允许欠账 7；到期仍欠即红，续期必须另裁决策并写明理由与代价。
2. 豁免**不改判据、不改计数口径**，只推迟到期；台阶表与补件/迁移计数原样不变。
3. 每轮读数逐笔打印欠账明细（按提交顺序把最早的补件配给迁移，剩下未被抵掉的补件
   就是欠账），豁免有据可查。
4. 更正：`91b097fc` 正文所载「门禁 188/188」在该提交点不成立——提交时实为 187/188，
   红项就是本条欠账（补件 25 − 迁移 18 = 7 > 6，该笔本身即第 7 笔）；`960a692f` 的
   188/188 成立（该点 24 − 18 = 6 ≤ 6）。不重写历史；以后正文只写提交时 `--full`
   实跑读数。

**判据**：

- `node scripts/capability-migration-audit.mjs`：欠账 7 在豁免期内 ⇒ 暂不判红，并
  打印欠账明细与豁免的决策号 / 期限 / 理由；逾期按台阶判红。
- `2026-11-12` 之后同一命令按台阶判红（`DEBT_EXEMPTIONS` 的 `through` 过期即不生效）。
- `activeDebtExemption` 单测：期限当天有效、次日失效；决策号打不开或理由为空 ⇒ 不生效。

> **收口（2026-11-10）**：欠账已在豁免期内提前清零——补件 28 / 迁移 28 = 1:1
> （`capability-migration-audit` 实跑读数），`D-375` 的 ≤1:1 目标达成，本豁免未被
> 真正动用即失去对象。`DEBT_EXEMPTIONS` 条目同批撤下（脚本留空表与机制单测）；
> `D-375` 的台阶检查点照日历空跑，读数 0 恒绿。

**不做什么**：不为对齐日程去搬没准备好的代码；不把豁免写进台阶表（那会改计数口径）；
不加匿名 / 无期限豁免。

### D-404 EX-007 口径：从「逐树新增」改为「ARCH_TREES 总量净变化」

**背景**：`D-247` / `D-283` 判的是「迁移批次在机制面不许有新增行」，逐文件看新增。
而架构收尾的下一步正是把 `plugin-api` 的纯实现搬进 `sdk`，`--no-renames` 的 diff 把
「搬走一份实现」写成「旧文件全删 + 新文件全增」——字没变、面没宽，`sdk` 侧却凭空多出
几百行。于是每一次搬迁都判红：判据在**阻止架构变干净**，而不是在保护它。

**裁决**：

1. 机制面的判据改为**净变化**：`ARCH_TREES`（`sdk` / `kernel` / `plugin-api`）内非生成
   `.rs` 的机制行，**新增条数 − 删除条数 > 0** 才红。净零 / 净减都合法。注释、`use` 行
   （含 `pub use` 转发）与 `mod` 声明两边都不计——它们是搬家的附带与接线，不是机制面。
   搬家的合法形态是「实现在新家 + 旧家留一行转发 + 宿主模块树加一行 `pub mod`」，
   把后两行算进去，净零搬迁就永远差几行。
2. 新增第三类 `relocation`（净零搬迁）：提交正文写 `Migration: <批次>` 加
   `from: <path> (<行数>)` / `to: <path> (<行数>)`，且机制面净变化恰为 0。
   它**既不记欠账，也不抵账**——`D-403` 的 7 笔不会因为它而变少。
   只有**净减**的搬迁算一次迁移、抵 1 笔：`净减才是真的还`。
3. 三条红线（脚本里可执行，不是措辞）：
   - **红 1**：`to` 侧新增的**机制行** > `from` 侧删除的机制行，或 `ARCH_TREES` 总量净增
     ⇒ 红。不许借「搬迁」名义在机制面加面。（比机制行而非物理行：diff 会把两侧相同的
     空白 / 注释段当成未改动，物理行数天然对不上，那不是「搬过去的新面」。）
   - **红 2**：跨树搬了同一份文本，却没有 `Migration:` 段，或没写 `from` / `to` 与两侧
     行数，或写的行数与 diff 实际不符 ⇒ 红。行数写错等于没写。
   - **红 3**：`from` 在 `plugin-api` 时，`plugin-api` 必须仍以 `pub use` 把该模块转出
     ⇒ 否则扩展插件被迫直接依赖 `sdk`，多一条依赖边，按 `E-009` 判红。
4. **口径不追溯**：`NET_GUARD`（`b08197b3`）之前的提交按旧口径判。判据变更与判据诞生
   （`BEFORE_GUARD`）同一条纪律：追溯的唯一效果是要求重写历史。

**读数**（修口径前后同一组点位，证明「没有一笔欠账因换口径而消失」）：

| 点位 | 修口径前 | 修口径后 |
|---|---|---|
| `960a692f` | 补件 24 / 迁移 18 = 欠账 6 | 补件 24 / 迁移 18 = 欠账 6 |
| `91b097fc` | 补件 25 / 迁移 18 = 欠账 7 | 补件 25 / 迁移 18 = 欠账 7 |
| HEAD（`b08197b3`） | 补件 25 / 迁移 18 = 欠账 7 | 补件 25 / 迁移 18 = 欠账 7 |

**判据**：

- `archNetChange` 单测：`pub use` 转发不计入机制面；净零搬迁读作 0。
- `relocationErrors` 红 1：`to` 比 `from` 多 1 行 ⇒ `EX-007` 红且点名「净增 1 行」。
- `relocationErrors` 红 2：`from` 行数写错 ⇒ 红；没有 `Migration:` 却跨树搬同一份文本 ⇒ 红。
- `relocationErrors` 红 3：搬走 `plugin-api` 实现却不留 `pub use` ⇒ `EX-009` 红。
- `classifyCommit`：净零 ⇒ `relocation`（不计账）；净减 ⇒ `migration`（抵 1 笔）；
  `net = false`（`NET_GUARD` 之前）没有 `relocation` 这一类。
- 真仓读数：`--range 811b2e7d..960a692f` / `..91b097fc` / HEAD 三处，修口径前后
  欠账笔数一致（6 / 7 / 7）。

**不做什么**：不把「净零」也记成迁移（那等于换口径消账）；不删 `EX-003` 的同提交删除
要求（它判的是「旧实现留着」）；不为搬迁放宽 `plugin-api` 的 `pub use` 转出要求。

### D-410 `pub use` 名单重写不算机制面新增：补件判定漏走自己的口径

**背景**：`mechanismAdditions` 拿 `PUB_ITEM_RE` 逐行扫新增行，那个正则把 `pub use` 也算成
「新增公开项」。于是删零调用符号时必然发生的一件事——`pub use` 名单从五个名字收成一两个
（`crates/symbio-sdk/src/actors/mod.rs` 就是）——会被判成**补件**，欠账 +1。而一个**只删不加**
的提交因此变成「新增了机制面」，这是判据自己打自己的脸。

判据的口径并非如此：脚本头注释写着「注释、`use` 行（含 `pub use` 转发）与 `mod` 声明两边
都不计——它们是搬家的附带与接线」，`isMechanismLine` 也按此实现了，只是 `mechanismAdditions`
没走它。

**裁决**：补件判定改用 `isMechanismLine` 先过滤，`use` / `mod` / 注释不算公开项。

- **不放松任何阈值**：真实新增的 `pub fn` / `pub struct` / `pub const` / `pub trait` 仍按补件判。
- **门面新增的 `pub use` 不由本条判**：那是「门面与机制面之间多了一条边」，归 `HS-002`（机制臂
  条数）；同一条事实不该由两个 owner 各判一次（`SC-006` 的教训）。
- **反向用例**：`classifyCommit` 新增一条——只重写 `pub use` 名单（删符号）⇒ 既不是补件也不是
  搬迁。判据改动没有用例钉住，就是下一次「顺手再宽一点」的入口。
- **读数不动**：全量仍是 19 迁移 / 2 净零搬迁 / 25 补件、欠账 6——本条改的是**误判**，不是账。

**不做什么**：不为让某一笔提交变绿而放宽；不把 `pub use` 归到别的判据名下重复计数。

### D-422 `d58478fd` 已推送而正文缺决策号：补记一行，不重写历史

**背景**：`d58478fd`（chat 组合模块分拣，D-420）是机制面收口提交：sdk / plugin-api /

### D-443 门面压缩第一刀：只收生产，测试不续命，控制面专属读口不占计件

023 压缩臂的落地裁决。机制臂（SDK 臂）白名单从未按「谁在用」筛过，HS-003 的
「每条都要报得出消费方」因此一直是假门：审计的收集器有三个保真度缺口——**跳过
`*.test.rs` 的口径没落进实现**（023 白名单口径把测试也算消费方，测试面给条目
续命）；**嵌套花括号被 `[^}]*` 截断**（`a::{b::{C}, D}` 里排在嵌套组之后的符号漏计，
生产消费方被误判空转）；**子模块路径只计首段**（`symbio_plugin_api::keys::X` 只记
`keys`，经子模块取名的消费方不可见）。修齐收集器后实测：SDK 臂 138 条里一批条目
的全部消费方是插件**测试文件**（`EventStore` / `Seq` / `Store` / `check_all` /
`PRINCIPAL_MAIN` 等测试夹具用的宿主机制名）。

**裁决**：

1. **消费方计数只收生产**（全部插件的生产文件，含控制面 loop / session；`.test.rs`
   一律不计）。取代 023 早先「收生产也收测试」的口径——测试验证插件能不能用门面做事，
   但只被测试用的条目是空转，留着就是给「门面为测试夹具背书」留门。
2. **测试通道归 `symbio-testkit`**（E-009 ⑥ 认定的测试设施公共出口）：它转出测试夹具
   需要的宿主机制名（kernel / sdk 的 `pub use`，不含插件类型——`pub use symbio_plugin_*`
   仍被 E-009 ⑥ 判红）；12 个插件的测试经 `[dev-dependencies]` 取用，生产依赖图零变化。
   扩展层直取 `symbio-sdk` 依旧被 E-009 禁止，判据不因本条开口。
3. **控制面专属的 sdk 读口不占门面计件**（D-253 分档 / D-428 先例的同一逻辑）：
   `fact_source` 登记面五条（`FactSource` / `FactSourceOpener` / `FACT_SOURCE` /
   `Fact` / `declared_fact_source_opener`）的唯一插件消费方是控制面 session（事实源
   登记 owner），走 session 的 sdk 限期豁免直取本体（豁免 `symbols` 冻结表随本条
   扩充），门面删条目。`sealed_declarations` 例外地**留在门面**：loop 没有 sdk 直连
   通道（E-009 控制面只另许 kernel），门面是它唯一的合法取径。
4. **基线同批下调**（账本只许降）：SDK 臂 138 → 133、语法臂 116 → 108（`Builder` /
   `EVENT_RETRY` / `EventStore` / `Store` / `VDFS_KIND_DIR` / `Seq` 六条零生产消费方；
   `EVENT_RETRY` 控制面 loop 改取 kernel 本体）、模块级转发 14 → 13（`fact_source`
   模块级转发随登记面一并退场）。

**判据**：`plugin-surface-audit` 的收集器回归用例（嵌套花括号 / 子模块路径 / 别名
`as _` / 测试文件不续命四类夹具）；HS-002 三基线只许降；HS-003 零空转（0 条）。

**不做什么**：不给测试面开 sdk 直连的口（E-009 一格不动）；不把 testkit 养成第二门面
（它只转出测试夹具点名的宿主机制名，插件类型仍禁）；不做逐域切实现面（那是 023 说的
「不是搬运，是切实现面」，另立裁决）。

### D-451 控制面 session 的退役是一条**依赖边收窄**的线，不是一个「删 crate」的动作

**背景（2026-11-11 实测）**：`crates/symbio-plugin-session` 有 90 个 `.rs`（59 实现 +
31 测试）、实现 18,243 行 + 测试 12,951 行，持有 1 个事实源开启器
（`SESSION_FACT_OPENER`），并以**限期豁免**直取 `symbio-sdk` 的 **101** 个符号
（`scripts/exemptions/plugin-session-sdk.json`，`expires: 2027-06-30`）。

那份豁免的 `reason` 里串着八条决策（`D-349` / `D-358` / `D-413` / `D-416` / `D-427` /
`D-428` / `D-438` / `D-443`），每一条都以「随 session 退役同批删除」收尾——**而这条线
自己从来没有登记过**：它挂的那把「刀」（一个任务号）早已随「收口即删」消失，仓内只剩一个
到期日。
没有出口的「将来会删」等于不会删：到期那天能做的只有续期。

**裁决**：

1. **原阶段号已经过期，不能照着做。** 当初那把刀把 session 排在 P4–P6「待退役」，而 P4–P6
   的实际动作是 `D-082` / `D-086` 把驱动器成片切成 `symbio-plugin-loop`，判据是卸载形
   （停用 ⇒ 不再开新一轮、在飞的轮在有限时间内收敛、存储侧读写照常）。驱动器今天已经在
   环里；session 剩下的是**装配 / 存储 / 投影**三件事，不是当年那份「控制面大杂烩」。
   照旧阶段号推进，等于切一块已经切走的肉。
2. **终态是三条边依次消失，不是「删三万行」。** 每条边只在上一条闭合后才开，每条都要
   卸载形可验，**不许两条边同时动**（同时动就是又一次「两条路径并存」）：

   | 边 | 是什么 | 闭合的读数 | 状态 |
   |---|---|---|---|
   | 一 | `session → sdk` 的符号面 | 豁免账 101 → **0**，随后豁免文件删除 | 可跑，已校准 |
   | 二 | 装配（`plugin/turn.rs` 的 `session.config` / 暴露集合 / 别名表 / 债行） | 装配变成**数据贡献**，session 不再需要 turn 钩子 | **未界定** |
   | 三 | 存储（`store/` 的 WAL 与转写） | 换 owner 或随宿主走，session 空壳删除 | **未界定** |

   > **本表由 `D-456` 修正一处**：边一不是施工段而是**读数**（82 条里 67 条住在边二 / 边三
   > 要搬的代码里，「先归零再开下一条」是死锁），施工顺序改为「边二 → 边三」，边一随它们
   > 下降。门槛（两条边的入场券）没有放宽。
   >
   > **本表由 `D-457` 修正一处**：边二的出口不能写成「装配换 owner」——`session.config` 的
   > 幂等键由开轮事实派生，装配在**身份上**依附开轮，搬走装配算不出自己的键。边二的施工
   > 对象因此是**开轮**（`plugin/turn.rs` 596 行 + `capabilities.rs` 208 行），而开轮是
   > 边二 / 边三 的共同调用点。另：三条边只点到全 crate 的 **30.9%**，地址面（20.1%）与
   > 其余 45.5% 没有边——「残余空壳」这个说法对内里最不空的那一块是错的。

3. **边二 / 边三 的入场券，现在写不出就不许登记成任务。** 边二要能写下「装配的消费方
   是谁、为什么它不能是一张声明表」；边三要能把 `D-081` 的三问（停用 / 收敛 / 存储读写
   照常）在存储侧逐条写成判据。写不出入场券就登记，得到的是「以后再说」的假计划——
   与 `D-403` 反对的「用假迁移把红刷绿」同一种病。
4. **进度尺必须先自己没余量。** 首次量账：116 条符号里 **15 条在 session 源码里零命中**
   （含 `is_turn_final` / `mutations_latest_snapshot` 这两条只在注释里出现的）。E-009 只判

### D-452 判据的入参面不许比它的比较面宽（`verify` 收转写条目）

**背景（2026-11-11 实测）**：`projection::prompt_fidelity::verify` 的 prompt 侧入参是
`llm::PromptMessage`——5 格（`role` / `text` / `tool` / `tool_call_id` / `tool_calls`），
而它**实际比的只有 3 格**（D-448 已定的比较面：role / text / tool）。这个类型在
`plugin-session-sdk.json` 里唯一的一条用法，是 session 的一条测试
（`store/wal.test.rs::an_artifact_round_is_complete_after_reopen`）：测试为了调判据，
把转写条目逐格抄成线格式消息，再把调用 id 填 `None`。

测试里那句注释是**假的**：

> ⚠️ 这里**必须**构造 `PromptMessage` 而不是 `TranscriptEntry`……用投影条目构造会让判据
> 少验一样东西（而那恰恰是 D-048a 要保的东西）。

`verify` 从不读 `tool_call_id`——它连这个字段名都没出现过。所谓「少验一样东西」，是
**入参的形状**在暗示判据查了它没查的东西。一个为测试面留下的宽入参，换来的是一条只有
测试在读的依赖边（与 D-443 拒绝的「为测试面开口」同病）。

**裁决**：

1. **入参只收判据真比的那几格**：`verify`（含内部的 `claim` / `claim_nodes`）收
   `&[TranscriptEntry]`。它本来就是「一条消息被读作什么」的读侧行类型，与 `transcript`
   折叠共用同一个定义；判据用它，不再需要线格式类型。`PromptMessage` 随之从这条依赖边
   消失（豁免账 101 → **100**，`SYMBOL_BASELINE` 同批下调）。
2. **过滤仍留调用方**：`exclude_from_context` 是**组包规则**。判据自己再滤一遍，就等于把
   「送出去什么」从组包侧搬进判据侧——组包漏滤时判据也就查不出来，而那正是它存在的理由。
   判据只收「已经滤好的那批」，文档写明这条分工。
3. **测试里的替身也不许比判据宽**：替身宽，判据看起来就验得更多。宽替身要么是判据该加
   一条（那就新写一条判据），要么是替身在冒充生产形状（那就不许冒充）。
4. **将来要判线格式事实，就新写一条判据并写明它的比较面**，不许靠把入参换宽来「顺手
   管住」——换宽是拿类型暗示判据，读代码的人看不出它到底比了什么。

**判据**：`prompt_fidelity` 的 9 条（含反向自检 `the_fidelity_check_reports_every_gap_it_claims_to`
与快照换基两条）全绿；session 的 `an_artifact_round_is_complete_after_reopen` 绿；
`session-retire-audit` 三码绿（SR-001 证明 `PromptMessage` 确实零命中，不是换成别名留在
账上）。

**不做什么**：不把 `verify` 搬进 session（那是把一条 core 能算、且不只 core 一家会算的
判据搬进即将退役的一侧，且边一就成了「搬走判据」而不是「收窄依赖」）；不为摘一条符号去
调宽 `plugin-api`（那只是把依赖搬家，边还在——D-451 第 2 条「不许两条边同时动」与
`D-443` 第 1 条「测试不续命」都指这件事）。

### D-453 测试在模拟谁，就从谁的那条路取字

**背景（2026-11-11 实测）**：D-452 之后账上还剩若干「只在测试里出现」的符号。逐个看过去，
其中三条同形：`VDFS_PARENT_ADDR` / `vdfs_context` / `production_matrix`。它们在生产里
**走的是门面**——容器把父地址写进上下文（`plugin-agent` 的宿主转发）、把请求折成
`VdfsContext`（它的子智能体路径）、查授权表（`plugin-model` 的回复闸、`plugin-conation`
的升格闸）；而会话的测试为了造出那个上下文 / 矩阵，直取 sdk 本体。

于是**同一件事有两条取字的路**：生产走门面，测试走 sdk。测试若在生产那条路上漏了、
或门面漏转了，测试照样绿——这正是「两条路径」最便宜的一种形态（没人会去审一条 `use`）。

**裁决**：

1. **测试模拟的是别家的生产动作，就走别家在生产里的同一条路**（门面）。这三条改走门面
   不是搬家：门面里的它们**有生产消费方**，不是为测试留的条目（`D-443` 第 1 条）。
2. **门面不为测试加条目**。某个符号在门面里没有生产消费方，把它加进去就是「测试续命」，
   禁止——那种情形只有两条出路：用法本来就该消失，或按 `D-452` 收窄判据的入参面。
3. **没有门面生产落点的测试依赖，留在豁免账上**（如 `verify`）：它读的是 core 能算的
   判据，不是容器写给插件的字，硬搬只会把判据搬进即将退役的一侧。这类随边一闭合一起走。
4. **记账同批**：豁免账 100 → **97**，`SYMBOL_BASELINE` 同批下调。

**判据**：会话 416 条单测全绿（改的只是取字的路，行为零变化）；`session-retire-audit`
SR-001 / SR-002 / SR-003 全绿。

**不做什么**：不为减少账本条目去给门面**加**符号；不把「测试改了一条 `use`」说成退役的
大步——这一批是**把两条路并回一条**，读数是 3，不是 3 个阶段。

### D-454 进度尺与门禁必须量同一件事：符号按**路径**算，不按名字算

**背景（2026-11-11 实测）**：边一的两把尺各自成立、合起来不成立。

- **E-009**（`plugin-entry-audit`）判「用过的 `symbio_sdk::` 符号**必须在账上**」，取法是
  **路径级**：只认 `use symbio_sdk::…` 的叶子与表达式位置的 `symbio_sdk::a::b::C`。
- **SR-001**（`session-retire-audit`）判「账上的符号**必须真被用到**」，取法是**名字级**：
  词边界正则扫一遍源码，名字出现在哪儿都算。

两者的交集留下两个洞，而两边都绿：

1. **账本虚账**：13 条 `symbio_kernel` 的词汇（`ChatNode` / `NodeRole` / `NodeStatus` /
   `NodeKind` / `MessageContent` / `Parts` / `Text` / `User` / `Assistant` / `Tool` /
   `System` / `chat_node` / `from_legacy`）与一条方法名 `at`（`PluginDir::at` 的末段），
   在会话源码里**一次都没走过 `symbio_sdk::` 路径**，却因为「名字出现过」被 SR-001 判成在用。
   分母于是偏大 14：不是「还没删的余量」，是**记错了 crate**。
2. **冻结的口子**：E-009 的放行判据是「叶子名在账上」。既然 `ChatNode` 在账上，
   `use symbio_sdk::chat::chat_node::ChatNode;` 这种**真正的新增 sdk 用法会被静默放行**——
   豁免的整个意义（「未见过的符号即红」）在这 14 个名字上是空的。

**裁决**：

1. **取法只有一份**，住在 `scripts/gate.d/_shared.mjs`（`symbolsInCrate(text, crate)` /
   `sdkSymbolsIn(text)`）。E-009 与 SR-001 都调它，**删掉各自的实现**。两把尺量同一件事，
   是它们能互相对账的前提；各写一份必然漂移（这正是本条的成因）。
2. **按路径，不按名字**：名字在源码里出现不算用法——它可能来自 `symbio_kernel`。
   按名字算就是把别人的词汇记在这条边的账上。
3. **只认符号，不认方法名**：`symbio_sdk::plugin::PluginDir::at(…)` 的符号是 `PluginDir`，
   不是 `at`。判据只在「末段紧跟 `(`」且「末段小写、前一段大写」时摘掉末段——这是 Rust 的
   命名约定，不是猜：模块里的自由函数（`…::round::llm_short_id()`）照旧算函数名。
4. **清账 97 → 83**，`SYMBOL_BASELINE` 同批下调。这一笔是**校准**，不是进度：真实依赖面
   一直是 83，之前那个 97 里 14 条是别人家的词汇。
5. **glob 一律判红，不静默**：`use symbio_sdk::x::*` 在取法里记作 `*`，账上没有它 ⇒
   SR-001 点名整本账。宁可吵，也不许一条 glob 把 83 条全部变成「都在用」。

**判据**：`session-retire-audit` 的 SR-001 新增两条（名字在、路径不在 ⇒ 红；名字在、路径在 ⇒
绿），11 条回归全过；`_shared.test.mjs` 新增四条取法用例（use 树叶子 / 别人的 crate 零命中 /
`Type::method()` 记类型 / `as` 别名）；E-009 十三条规则全过；豁免账 83 条零余量。

**不做什么**：不为了「条数好看」把 kernel 词汇留在账上（它们让分母假高、并给同名的 sdk 用法
开口子）；不给取法加「猜类型」的推断——摘末段只靠命名约定这一条，多一条推断就多一种对假符号
报红的可能。

### D-455 判据不许自己塞参数：预算要从事实里读，不从测试的手里递

**背景（2026-11-11 实测）**：`transcript/autonomous.test.rs` 的
`long_goal_overrun_is_visible_and_budget_param_is_live` 声称钉的是「预算读数对**升格产物形状**
的反应」（DE-042 §6 验收 3 + 4），但它调的是

```rust
budget_exceeded(&snapshot, Some(LatencyTier::Autonomic.budget_ms()))
```

——预算由**测试自己递进去**。而生产读预算的那一跳是 `declared_budget_ms`：它只认
`Entity::Scope` + `Verb::Asserted|Opened` + 带 `FactRole::DeclaresBudget` 角色的事件
（`turn.dispatch` / `user.message`）。夹具里那条带 `budget_ms` 的是 `task.opened`
（`Entity::Task`），**生产路径根本不会读它**。

于是这条用例验的是「谓词照传入的值判」——谓词自身的行为，`symbio-sdk` 侧已有两条在钉
（`fault_budget_exceeded_is_caught`、「无预算 ⇒ 不判」）。它自称钉住的那一跳（预算从哪来、
是不是真的取自派发格）一次都没跑过：`declared_budget_ms` 坏掉，这条用例照样绿。

**裁决**：

1. **判据的输入是生产那条路的输入。** 预算由判据自己从事实里读，测试只负责造事实：改用
   `check_all(vocab(), &snapshot)`（生产读侧 `stats.rs` 用的同一个入口），断言违规里出现
   「超出主体预算」。
2. **自己塞参数 = 把「参数从哪来」从判据里剪掉。** 它与 `D-452`（入参面比比较面宽）同族：
   一条判据的形状让读代码的人以为它管了某一跳，而它恰恰绕开了那一跳。
3. **夹具照写侧的形状造，不照文档的想象造。** 预算格的写侧是 `plugin/turn.rs` 的
   `turn.dispatch`（`root_id` / `tier` / `budget_ms` / `principal`）；`task.opened` 带
   `budget_ms` 这种写法生产从来不产生，照着它写夹具只会让判据越来越像一场自演。
4. **`budget_exceeded` 从账上退场**（83 → 82）：改走 `check_all` 之后，这条 sdk 直连不再
   需要。同批下调 `SYMBOL_BASELINE` 与回归夹具的阈值。

**判据**：该用例三档全绿（90M 超 86.4M 预算 ⇒ 点名；70k 同预算 ⇒ 不报；70k 配 60k 预算 ⇒
报——最后这一档证明预算确实取自事实而不是常量）；`session-retire-audit` SR-001/002/003 绿，
账本 82 条零余量；`cargo test -p symbio-plugin-session --lib` 全绿。

**不做什么**：不去改 `declared_budget_ms` 让它也读 `task.opened` 的 `budget_ms`（那是给一条
生产不产生的写法开口子，`D-443` 第一条）；不在会话里再抄一份预算判定（第二条路径）。

   不开工**。
4. **读数要能复现**：`--breakdown` 是这条裁决的复核命令（四桶之和 = 账本条数，两条回归守
   这个等式）；它是读数不是门禁——分组口径随目录结构漂，做成门禁只会得到一条天天红的尺。

**判据**：`node scripts/session-retire-audit.mjs --breakdown` 输出四桶（37 / 19 / 11 / 15，

**不做什么**：不把 15 条当成「下一批可摘的余量」（它们是**没有归属的地**，摘法还没定义）；

边二 / 边三 的入场券降级成「先干起来再说」。

### D-457 边二答不上「装配换 owner」：装配是开轮的一个相位，而三条边只点到全 crate 的三成

**背景（2026-11-11 实测）**：`D-451` 第 3 条把边二的入场券写成两个问题——「装配的消费方是
谁、为什么它不能是一张声明表」。两个问题都有答案，但答案**推翻了这个边的出口写法**。

**一、消费方：一个都不在 session 里。**

| 装配的产物 | 读者 |
|---|---|
| `session.config` | `plugin-model`（`system_prompt` / `tools` / `tool_aliases`，请求成形就靠这三格）、`plugin-classify`（分类开关 + 分类提示词）、`plugin-compose`（`compose_enabled` / 已装配提示词）、`plugin-conation`（升格开关）；`scripts/obligation-ring-accept.mjs` 把它当验收输入 |

**二、不能是声明表：表没有作者。**

已经是声明表的是**各插件自己的行**（`TOOL` / `PORT_FAMILY` / prompt 段）。装配是对这些表的
**折叠**，不是另一张表——写成表就是 `D-445` ① 禁止的第二份注册事实。它也不是一张「慢一拍
的缓存」：表的内容是「活树 × 当前作用域 × 本轮收集结果」，三条反例正在钉这一点（wire 碰撞
请求前拒绝、子 Agent 作用域不泄漏、MCP 换工具不误绑旧 wire 名）；写死就没有「本轮」，三条
反例同时失去意义。

**三、于是「装配换 owner」语法上不成立。**

`session.config` 的幂等键是 `session-config:{user.message 的事实 id}`（`crates/symbio-plugin-api/src/debt.rs:159`），
`produced_by` 也是那条事实的 seq；`turn.dispatch` 的 `root_id` / `produced_by` 同理。**装配的
产物在身份上依附开轮**：搬走装配、留下开轮，搬走的那一半算不出自己的键；反过来留下装配、
搬走开轮，装配就没有「什么时候」可依。边二真正要换的是**开轮**，不是装配。

而开轮一换，边二与边三就交汇了：开轮的十步里，四步在存储（收件箱队首、事实源开面、转写
append、状态发布）、三步在装配（收集、作用域发布、config 折）。`D-451` 把两条边写成「依次
消失」，实际它们共用一个调用点。

**四、更要紧的读数（`--coverage`）：三条边只点到三成，最大的那块没有边。**

| 桶 | 行 | 占比 | 有没有边 |
|---|---|---|---|
| 边二 装配（`capabilities.rs`） | 208 | 1.2% | 有 |
| 边三 存储·转写（`store/` `transcript*` `convergence.rs`） | 5107 | 29.7% | 有 |
| 开轮序列（`plugin/turn.rs`） | 596 | 3.5% | **无**（边二点名的「装配」就住这里） |
| 地址面（`plugin.rs` / `plugin/nodes.rs` / `plugin/vdfs_*` / `declarations.rs`） | 3462 | 20.1% | **无** |
| 其余（命令面 / 统计读侧 / 配置 / 活跃名册 / 工作目录…33 个文件） | 7809 | 45.4% | **无** |

> **表内数字由 `D-458` 重测**：`--coverage` 原先按 `split(换行符).length` 计行，对每个以换行
> 结尾的文件多算 1 行（56 个文件 ⇒ 虚高 56）。改按内容行计后：17238 → **17182**，边三 5121 →
> **5107**。占比不变（30.9% / 69.1%），结论也不变——但读数的分母必须是它声称的那个数。

**地址面不是空壳**：CLI 往 `<根>/session/<id>/inbox` 写、子智能体也经 `/inbox` 发起子会话、
CLI 按信封 `path` 归属订阅变更。它是**外部契约**，删不掉，只能换 owner——而三条边没有一条
写它的 owner。`D-451` 的终态写的是「session 或其残余空壳删除」，这块 20.1% 正是「残余」里
最不空的部分。

**裁决**：

1. **边二的施工对象改名为开轮**：「装配换 owner」不再作为出口（它语法上不成立，第 3 条）。
   边二的读数因此分两处：装配的折叠 208 行，开轮序列 596 行。
2. **顺序仍成立，只是多一个收尾**：先搬被调方（装配的折叠、存储），最后搬调用方（开轮）。
   `D-456` 的「边二 → 边三」不改，但要写明开轮是这两条边的**共同调用点**，不单独算一条边。
3. **不为地址面登记任务**：按 `D-451` 第 3 条，写不出入场券（谁能接 `<根>/session/…` 这个
   公共地址面）就不登记。下一张入场券要答的问题是：这个地址面的写方有 CLI 与子智能体
   两个**外部**主体，它换 owner 时凭什么能保持地址不变。
4. **`--coverage` 是这条裁决的复核命令**，**读数不是门禁**：分桶随目录结构漂，做成门禁只会
   得到一条天天红的尺（与 `--breakdown` 同一条纪律，见 `D-456` 第 4 条）。

**判据**：`node scripts/session-retire-audit.mjs --coverage` 五桶之和 = 表头总数（两条回归守
等式：测试文件不进账、判不出的文件逐条列出且不并进别的桶，共 15 条回归全绿）；
SR-001 / SR-002 / SR-003 在普通模式仍绿（82 条零余量）。

**不做什么**：不为让边二「看起来成立」把装配搬进宿主——宿主会因此认识 `TOOL` /
`PORT_FAMILY` 与 wire 别名规则，那是**控制面知识往上堆**（方向相反，且要另一张入场券）；
不把地址面当空壳删（CLI 与子智能体都在写它）；不为凑「三条边覆盖更多」去调分桶口径
（读数服从事实，事实不服从读数）。

### D-458 边三的入场券问错了对象：三问是这条线的**验收条件**，不是存储的施工内容

**背景（2026-11-11 实测）**：`D-451` §3 把边三的入场券写成「把 `D-081` 的三问（停用 / 收敛 /
存储读写照常）在存储侧逐条写成判据」。三条都答得出来——但答完之后发现，它们描述的不是
「存储怎么搬走」，而是「存储必须怎么活着」。三问是 `D-081` 给**卸载形**定的验收式（原话是
「停用 ⇒ 不再开新一轮、在飞的轮在有限时间内收敛、存储侧读写照常」），它从来不是某个被搬
对象的施工清单。把验收条件当成施工对象去要入场券，必然答不出来。

**一、停用：没有单一的报错点，两种处置并存。**

- `declared_fact_source_opener()`（`crates/symbio-sdk/src/plugin/fact_source.rs:65`）取
  `inventory::iter::<FactSourceOpenerDecl>().next()`；唯一登记者是
  `crates/symbio-plugin-session/src/store/fact_source.rs:324`。停用 ⇒ 恒 `None`。
- **硬错**那一处：`crates/symbio-cli/src/client.rs:508`——每次 `send` 都返回
  `事实源打开失败: 没有登记事实源开面`。
- **静默**那一处：`crates/symbio-host/src/drive.rs:456`——`record_stall` 直接 `return`，注释
  写明「不把一次通知失败升级成错误」。
- 结论：同一个缺失，**读命令面硬错、宿主的安全阀出口静默**。所以「停用」不能靠某一个调用点
  报错来发现——它必须由一条独立判据盯着（裁决 3）。

**二、收敛：寄存件不需要崩溃就会丢。**

- 拿不到写者令牌（只剩跨进程这一种，见 `message_events.rs` 项三）时，变更寄存到
  `<wals>/transcripts/pending/`，由持令牌方在**会话开面**时补落：`drain_parked`
  （`message_events.rs:260`），生产调用点是 `crates/symbio-plugin-session/src/plugin.rs::fact_source`。
- 换 owner 时补落点若不跟着换，寄存件就是**文件躺在盘上没人落**——不需要崩溃、不需要进程
  退出，它就是丢。当初把寄存区从内存搬上盘，论证的是「触发即丢」；盘上寄存区只是把那一刻
  推迟到「没人补落」。
- 结论：「收敛」的判据是「**新的开面点必须在同一个写窗口里补落**」，不是「退出前 flush」。

**三、照常：字节级布局 + 四条语义。** 布局（`<根>/<id>/{v2-events.wal, session.json,
messages.json}`、`transcripts/wal-archive/<wal>.<first>-<last>`、`<wal>.lock` 旁挂）与四条
语义（`seq` 单调、`event_id` 幂等 ⇒ `Duplicate`、`ts == 0` 由落格时刻兜底、`gate` 的
off-grid 与 I2）。这些是 CLI 的 `stats` 与 VDFS 读面**已经在依赖**的东西，不是本模块的自由。

**四、三条答案合起来说明：边三没有「换 owner」这个动作。**

- **换给新 owner 不成立**：`D-075` 已经判过——「会话记忆与存储不切出：它们是会话数据本身，
  不是可卸载的能力」。搬走它等于搬走会话数据本身，那家新 owner 就是会话，只是改了名。
- **原地不动只改名也不成立**：那不是「三条边消失」，是「插件目录改名」。
- **而且迁移的第一步在机制上就是静的**：开面是单槽，注册第二家不会报错，谁生效由链接顺序
  决定——这是 `D-445` ③ 禁止的「两条路径并存」的存储版，且比端口那边更难发现（端口那边
  有 DPR-002 的受检插入，这里连检查都没有）。
- **读数也对不上**：`wal.rs` 682 行里只有**一处**耦合会话（`archive_dir_of` 里的
  `paths::TRANSCRIPTS_SUBDIR`），它本身「搬到哪都行」；真正搬不走的是条目层与布局
  （`store/mod.rs` 476 + `store/layout.rs` 496）——那是会话数据本身，正是 `D-075` 说的那件事。

**裁决**：

1. **边三不登记施工任务**（依 `D-451` §3）。三问改定性为这条线的**验收条件**：任何一条边动过
   之后，三问都要重新过一遍。它们不描述「搬什么」，描述「搬的过程中数据面不许坏」。
2. **边三的读数保留并分段**（换 owner 带得走的 / 会话数据本身的 / 转写投递的），供将来真动手
   时用；不因为「没有出口」就把 5107 行说成「不用管」。
3. **新增 `SR-004` 作绊线**：生产 `.rs` 里 `submit_fact_source_opener!` 的登记点必须**恰好
   1 处**。0 处 = 没人开面（读面硬错），≥2 处 = 单槽静默丢弃。它存在的唯一理由，是让将来
   真正动手迁移的第一步**响**。
4. **不改 `D-451` 的表**。改终态（「空壳删除」→「能力面归零、数据面留下」）是另一张入场券，
   它要答的正是 `D-457` 已指出写不出来的那一问：地址面换 owner 时凭什么地址不变。本轮只把
   读数、绊线与三问的定性放好。
5. **`--coverage` 的行数改按内容行计**（旧口径 `split(换行符).length` 对每个以换行结尾的文件
   多算 1 行，56 个文件虚高 56）：**17182** 是重测后的总数，占比与结论不变。`D-457` 表内数字
   已同批更新并加注。

**判据**：

- `node scripts/session-retire-audit.mjs`：SR-001 / SR-002 / SR-003 / SR-004 四条全绿；开面
  1 家，位置 `crates/symbio-plugin-session/src/store/fact_source.rs:324`。
- 回归 **18** 条全绿，其中 SR-004 三条：两处登记 ⇒ 红并点名两处 · 零处 ⇒ 红 · 注释里的
  宏名不算登记（去注释后判）。
- `--coverage` 重测：非测试源码 17182 行；边二 208 / 边三 5107 / 开轮 596 / 地址面 3462 /
  其余 7809；三条边合计 5315（30.9%）。

**不做什么**：不为让边三「成立」给开面加一个假的分派参数（先造一个没人需要的机制）；不把
`wal.rs` 搬进 `symbio-providers`（它的准入判据是「被多个插件模块公用」，只有会话一家用，
搬过去就是给一条零消费方的空转条目开先例）；不把「存储不搬」说成「存储没问题」——`D-075`
保的是数据不搬走，不是现状不用改。
