# 判据欠账与到期豁免

> **一句话**：`EX-007` 的欠账按台阶递减；台阶当天压不动时，只允许「另裁一条带期限的
> 决策」推迟到期——不许凑数迁移，也不许**为了消账**而改计数口径。

`EX-007` 的绝对欠账线、台阶表与逐笔读数的算法见
[DE-026-能力拆分与影响类](026-能力拆分与影响类.md)。本篇承载台阶之外的两种动作：
**到期豁免**，以及**口径本身的修正**（后者必须证明「改完之后没有任何存量欠账消失」）。

### D-403 EX-007 欠账的到期豁免：7 笔，至 2026-11-12

**背景**：`D-375` 的台阶在 `2026-11-09` 把绝对欠账上限压到 6，而存量欠账是 7
（累计补件 25 − 迁移 18）。其中 6 笔是尚待搬迁的存量批次；第 7 笔来自 `91b097fc`
（`D-402` 的压缩失败投影新增 pub 项），把 `2aaa213c` 上的 6 笔推到 7。迁移批次必须
是真的该搬的东西，为对齐日程去搬一段没准备好的代码，等于用假迁移把红刷绿。

**裁决**：

1. 按 `D-375` §5 的「另裁一条新决策」路径起一条**有期限豁免**：`EX-007` 在
   `2026-11-12` 之前允许欠账 7；到期仍欠即红，续期必须另裁决策并写明理由与代价。
2. 豁免**不改判据、不改计数口径**，只推迟到期；台阶表与补件/迁移计数原样不变。
3. 每轮读数逐笔打印欠账明细（按提交顺序把最早的补件配给迁移，剩下未被抵掉的补件
   就是欠账），豁免有据可查。
4. 更正：`91b097fc` 正文所载「门禁 188/188」在该提交点不成立——提交时实为 187/188，
   红项就是本条欠账（补件 25 − 迁移 18 = 7 > 6，该笔本身即第 7 笔）；`960a692f` 的
   188/188 成立（该点 24 − 18 = 6 ≤ 6）。不重写历史；以后正文只写提交时 `--full`
   实跑读数。

**判据**：

- `node scripts/capability-migration-audit.mjs`：欠账 7 在豁免期内 ⇒ 暂不判红，并
  打印欠账明细与豁免的决策号 / 期限 / 理由；逾期按台阶判红。
- `2026-11-12` 之后同一命令按台阶判红（`DEBT_EXEMPTIONS` 的 `through` 过期即不生效）。
- `activeDebtExemption` 单测：期限当天有效、次日失效；决策号打不开或理由为空 ⇒ 不生效。

> **收口（2026-11-10）**：欠账已在豁免期内提前清零——补件 28 / 迁移 28 = 1:1
> （`capability-migration-audit` 实跑读数），`D-375` 的 ≤1:1 目标达成，本豁免未被
> 真正动用即失去对象。`DEBT_EXEMPTIONS` 条目同批撤下（脚本留空表与机制单测）；
> `D-375` 的台阶检查点照日历空跑，读数 0 恒绿。

**不做什么**：不为对齐日程去搬没准备好的代码；不把豁免写进台阶表（那会改计数口径）；
不加匿名 / 无期限豁免。

### D-404 EX-007 口径：从「逐树新增」改为「ARCH_TREES 总量净变化」

**背景**：`D-247` / `D-283` 判的是「迁移批次在机制面不许有新增行」，逐文件看新增。
而架构收尾的下一步正是把 `plugin-api` 的纯实现搬进 `sdk`，`--no-renames` 的 diff 把
「搬走一份实现」写成「旧文件全删 + 新文件全增」——字没变、面没宽，`sdk` 侧却凭空多出
几百行。于是每一次搬迁都判红：判据在**阻止架构变干净**，而不是在保护它。

**裁决**：

1. 机制面的判据改为**净变化**：`ARCH_TREES`（`sdk` / `kernel` / `plugin-api`）内非生成
   `.rs` 的机制行，**新增条数 − 删除条数 > 0** 才红。净零 / 净减都合法。注释、`use` 行
   （含 `pub use` 转发）与 `mod` 声明两边都不计——它们是搬家的附带与接线，不是机制面。
   搬家的合法形态是「实现在新家 + 旧家留一行转发 + 宿主模块树加一行 `pub mod`」，
   把后两行算进去，净零搬迁就永远差几行。
2. 新增第三类 `relocation`（净零搬迁）：提交正文写 `Migration: <批次>` 加
   `from: <path> (<行数>)` / `to: <path> (<行数>)`，且机制面净变化恰为 0。
   它**既不记欠账，也不抵账**——`D-403` 的 7 笔不会因为它而变少。
   只有**净减**的搬迁算一次迁移、抵 1 笔：`净减才是真的还`。
3. 三条红线（脚本里可执行，不是措辞）：
   - **红 1**：`to` 侧新增的**机制行** > `from` 侧删除的机制行，或 `ARCH_TREES` 总量净增
     ⇒ 红。不许借「搬迁」名义在机制面加面。（比机制行而非物理行：diff 会把两侧相同的
     空白 / 注释段当成未改动，物理行数天然对不上，那不是「搬过去的新面」。）
   - **红 2**：跨树搬了同一份文本，却没有 `Migration:` 段，或没写 `from` / `to` 与两侧
     行数，或写的行数与 diff 实际不符 ⇒ 红。行数写错等于没写。
   - **红 3**：`from` 在 `plugin-api` 时，`plugin-api` 必须仍以 `pub use` 把该模块转出
     ⇒ 否则扩展插件被迫直接依赖 `sdk`，多一条依赖边，按 `E-009` 判红。
4. **口径不追溯**：`NET_GUARD`（`b08197b3`）之前的提交按旧口径判。判据变更与判据诞生
   （`BEFORE_GUARD`）同一条纪律：追溯的唯一效果是要求重写历史。

**读数**（修口径前后同一组点位，证明「没有一笔欠账因换口径而消失」）：

| 点位 | 修口径前 | 修口径后 |
|---|---|---|
| `960a692f` | 补件 24 / 迁移 18 = 欠账 6 | 补件 24 / 迁移 18 = 欠账 6 |
| `91b097fc` | 补件 25 / 迁移 18 = 欠账 7 | 补件 25 / 迁移 18 = 欠账 7 |
| HEAD（`b08197b3`） | 补件 25 / 迁移 18 = 欠账 7 | 补件 25 / 迁移 18 = 欠账 7 |

**判据**：

- `archNetChange` 单测：`pub use` 转发不计入机制面；净零搬迁读作 0。
- `relocationErrors` 红 1：`to` 比 `from` 多 1 行 ⇒ `EX-007` 红且点名「净增 1 行」。
- `relocationErrors` 红 2：`from` 行数写错 ⇒ 红；没有 `Migration:` 却跨树搬同一份文本 ⇒ 红。
- `relocationErrors` 红 3：搬走 `plugin-api` 实现却不留 `pub use` ⇒ `EX-009` 红。
- `classifyCommit`：净零 ⇒ `relocation`（不计账）；净减 ⇒ `migration`（抵 1 笔）；
  `net = false`（`NET_GUARD` 之前）没有 `relocation` 这一类。
- 真仓读数：`--range 811b2e7d..960a692f` / `..91b097fc` / HEAD 三处，修口径前后
  欠账笔数一致（6 / 7 / 7）。

**不做什么**：不把「净零」也记成迁移（那等于换口径消账）；不删 `EX-003` 的同提交删除
要求（它判的是「旧实现留着」）；不为搬迁放宽 `plugin-api` 的 `pub use` 转出要求。

### D-410 `pub use` 名单重写不算机制面新增：补件判定漏走自己的口径

**背景**：`mechanismAdditions` 拿 `PUB_ITEM_RE` 逐行扫新增行，那个正则把 `pub use` 也算成
「新增公开项」。于是删零调用符号时必然发生的一件事——`pub use` 名单从五个名字收成一两个
（`crates/symbio-sdk/src/actors/mod.rs` 就是）——会被判成**补件**，欠账 +1。而一个**只删不加**
的提交因此变成「新增了机制面」，这是判据自己打自己的脸。

判据的口径并非如此：脚本头注释写着「注释、`use` 行（含 `pub use` 转发）与 `mod` 声明两边
都不计——它们是搬家的附带与接线」，`isMechanismLine` 也按此实现了，只是 `mechanismAdditions`
没走它。

**裁决**：补件判定改用 `isMechanismLine` 先过滤，`use` / `mod` / 注释不算公开项。

- **不放松任何阈值**：真实新增的 `pub fn` / `pub struct` / `pub const` / `pub trait` 仍按补件判。
- **门面新增的 `pub use` 不由本条判**：那是「门面与机制面之间多了一条边」，归 `HS-002`（机制臂
  条数）；同一条事实不该由两个 owner 各判一次（`SC-006` 的教训）。
- **反向用例**：`classifyCommit` 新增一条——只重写 `pub use` 名单（删符号）⇒ 既不是补件也不是
  搬迁。判据改动没有用例钉住，就是下一次「顺手再宽一点」的入口。
- **读数不动**：全量仍是 19 迁移 / 2 净零搬迁 / 25 补件、欠账 6——本条改的是**误判**，不是账。

**不做什么**：不为让某一笔提交变绿而放宽；不把 `pub use` 归到别的判据名下重复计数。

### D-422 `d58478fd` 已推送而正文缺决策号：补记一行，不重写历史

**背景**：`d58478fd`（chat 组合模块分拣，D-420）是机制面收口提交：sdk / plugin-api /

### D-443 门面压缩第一刀：只收生产，测试不续命，控制面专属读口不占计件

023 压缩臂的落地裁决。机制臂（SDK 臂）白名单从未按「谁在用」筛过，HS-003 的
「每条都要报得出消费方」因此一直是假门：审计的收集器有三个保真度缺口——**跳过
`*.test.rs` 的口径没落进实现**（023 白名单口径把测试也算消费方，测试面给条目
续命）；**嵌套花括号被 `[^}]*` 截断**（`a::{b::{C}, D}` 里排在嵌套组之后的符号漏计，
生产消费方被误判空转）；**子模块路径只计首段**（`symbio_plugin_api::keys::X` 只记
`keys`，经子模块取名的消费方不可见）。修齐收集器后实测：SDK 臂 138 条里一批条目
的全部消费方是插件**测试文件**（`EventStore` / `Seq` / `Store` / `check_all` /
`PRINCIPAL_MAIN` 等测试夹具用的宿主机制名）。

**裁决**：

1. **消费方计数只收生产**（全部插件的生产文件，含控制面 loop / session；`.test.rs`
   一律不计）。取代 023 早先「收生产也收测试」的口径——测试验证插件能不能用门面做事，
   但只被测试用的条目是空转，留着就是给「门面为测试夹具背书」留门。
2. **测试通道归 `symbio-testkit`**（E-009 ⑥ 认定的测试设施公共出口）：它转出测试夹具
   需要的宿主机制名（kernel / sdk 的 `pub use`，不含插件类型——`pub use symbio_plugin_*`
   仍被 E-009 ⑥ 判红）；12 个插件的测试经 `[dev-dependencies]` 取用，生产依赖图零变化。
   扩展层直取 `symbio-sdk` 依旧被 E-009 禁止，判据不因本条开口。
3. **控制面专属的 sdk 读口不占门面计件**（D-253 分档 / D-428 先例的同一逻辑）：
   `fact_source` 登记面五条（`FactSource` / `FactSourceOpener` / `FACT_SOURCE` /
   `Fact` / `declared_fact_source_opener`）的唯一插件消费方是控制面 session（事实源
   登记 owner），走 session 的 sdk 限期豁免直取本体（豁免 `symbols` 冻结表随本条
   扩充），门面删条目。`sealed_declarations` 例外地**留在门面**：loop 没有 sdk 直连
   通道（E-009 控制面只另许 kernel），门面是它唯一的合法取径。
4. **基线同批下调**（账本只许降）：SDK 臂 138 → 133、语法臂 116 → 108（`Builder` /
   `EVENT_RETRY` / `EventStore` / `Store` / `VDFS_KIND_DIR` / `Seq` 六条零生产消费方；
   `EVENT_RETRY` 控制面 loop 改取 kernel 本体）、模块级转发 14 → 13（`fact_source`
   模块级转发随登记面一并退场）。

**判据**：`plugin-surface-audit` 的收集器回归用例（嵌套花括号 / 子模块路径 / 别名
`as _` / 测试文件不续命四类夹具）；HS-002 三基线只许降；HS-003 零空转（0 条）。

**不做什么**：不给测试面开 sdk 直连的口（E-009 一格不动）；不把 testkit 养成第二门面
（它只转出测试夹具点名的宿主机制名，插件类型仍禁）；不做逐域切实现面（那是 023 说的
「不是搬运，是切实现面」，另立裁决）。

### D-451 控制面 session 的退役是一条**依赖边收窄**的线，不是一个「删 crate」的动作

**背景（2026-11-11 实测）**：`crates/symbio-plugin-session` 有 90 个 `.rs`（59 实现 +
31 测试）、实现 18,243 行 + 测试 12,951 行，持有 1 个事实源开启器
（`SESSION_FACT_OPENER`），并以**限期豁免**直取 `symbio-sdk` 的 **101** 个符号
（`scripts/exemptions/plugin-session-sdk.json`，`expires: 2027-06-30`）。

那份豁免的 `reason` 里串着八条决策（`D-349` / `D-358` / `D-413` / `D-416` / `D-427` /
`D-428` / `D-438` / `D-443`），每一条都以「随 session 退役同批删除」收尾——**而这条线
自己从来没有登记过**：它挂的那把「刀」（一个任务号）早已随「收口即删」消失，仓内只剩一个
到期日。
没有出口的「将来会删」等于不会删：到期那天能做的只有续期。

**裁决**：

1. **原阶段号已经过期，不能照着做。** 当初那把刀把 session 排在 P4–P6「待退役」，而 P4–P6
   的实际动作是 `D-082` / `D-086` 把驱动器成片切成 `symbio-plugin-loop`，判据是卸载形
   （停用 ⇒ 不再开新一轮、在飞的轮在有限时间内收敛、存储侧读写照常）。驱动器今天已经在
   环里；session 剩下的是**装配 / 存储 / 投影**三件事，不是当年那份「控制面大杂烩」。
   照旧阶段号推进，等于切一块已经切走的肉。
2. **终态是三条边依次消失，不是「删三万行」。** 每条边只在上一条闭合后才开，每条都要
   卸载形可验，**不许两条边同时动**（同时动就是又一次「两条路径并存」）：

   | 边 | 是什么 | 闭合的读数 | 状态 |
   |---|---|---|---|
   | 一 | `session → sdk` 的符号面 | 豁免账 101 → **0**，随后豁免文件删除 | 可跑，已校准 |
   | 二 | 装配（`plugin/turn.rs` 的 `session.config` / 暴露集合 / 别名表 / 债行） | 装配变成**数据贡献**，session 不再需要 turn 钩子 | **未界定** |
   | 三 | 存储（`store/` 的 WAL 与转写） | 换 owner 或随宿主走，session 空壳删除 | **未界定** |

3. **边二 / 边三 的入场券，现在写不出就不许登记成任务。** 边二要能写下「装配的消费方
   是谁、为什么它不能是一张声明表」；边三要能把 `D-081` 的三问（停用 / 收敛 / 存储读写
   照常）在存储侧逐条写成判据。写不出入场券就登记，得到的是「以后再说」的假计划——
   与 `D-403` 反对的「用假迁移把红刷绿」同一种病。
4. **进度尺必须先自己没余量。** 首次量账：116 条符号里 **15 条在 session 源码里零命中**
   （含 `is_turn_final` / `mutations_latest_snapshot` 这两条只在注释里出现的）。E-009 只判
   「用了的必须在账上」，是**单向**的，于是用法消失之后条目静默留了下来。余量本身无害，
   **冒充进度**有害：它让「退役走了多远」读出一个偏大的分母。本批摘除 15 条（116 → 101），
   并把这条纪律落成判据（见下）。

**判据**：

- `node scripts/session-retire-audit.mjs`（SR-001 / SR-002 / SR-003）：豁免账每条符号
  必须真被用到（余量即红）· 条数 ≤ 基线只许降 · 豁免自洽（到期日是将来、`retire` 写明
  删除动作、`knife` 指得出登记号）。回归用例 10 条（含「只在注释里出现仍红」「102 > 101
  即红」「JSON 读不出即红」「源码目录被搬走即红」），已接进 `30-docs.mjs` 的 `GUARDS`。
- 边一每收窄一次，`SYMBOL_BASELINE` 同批下调（账本只许降，与 `D-443` 的基线纪律同源）。

### D-452 判据的入参面不许比它的比较面宽（`verify` 收转写条目）

**背景（2026-11-11 实测）**：`projection::prompt_fidelity::verify` 的 prompt 侧入参是
`llm::PromptMessage`——5 格（`role` / `text` / `tool` / `tool_call_id` / `tool_calls`），
而它**实际比的只有 3 格**（D-448 已定的比较面：role / text / tool）。这个类型在
`plugin-session-sdk.json` 里唯一的一条用法，是 session 的一条测试
（`store/wal.test.rs::an_artifact_round_is_complete_after_reopen`）：测试为了调判据，
把转写条目逐格抄成线格式消息，再把调用 id 填 `None`。

测试里那句注释是**假的**：

> ⚠️ 这里**必须**构造 `PromptMessage` 而不是 `TranscriptEntry`……用投影条目构造会让判据
> 少验一样东西（而那恰恰是 D-048a 要保的东西）。

`verify` 从不读 `tool_call_id`——它连这个字段名都没出现过。所谓「少验一样东西」，是
**入参的形状**在暗示判据查了它没查的东西。一个为测试面留下的宽入参，换来的是一条只有
测试在读的依赖边（与 D-443 拒绝的「为测试面开口」同病）。

**裁决**：

1. **入参只收判据真比的那几格**：`verify`（含内部的 `claim` / `claim_nodes`）收
   `&[TranscriptEntry]`。它本来就是「一条消息被读作什么」的读侧行类型，与 `transcript`
   折叠共用同一个定义；判据用它，不再需要线格式类型。`PromptMessage` 随之从这条依赖边
   消失（豁免账 101 → **100**，`SYMBOL_BASELINE` 同批下调）。
2. **过滤仍留调用方**：`exclude_from_context` 是**组包规则**。判据自己再滤一遍，就等于把
   「送出去什么」从组包侧搬进判据侧——组包漏滤时判据也就查不出来，而那正是它存在的理由。
   判据只收「已经滤好的那批」，文档写明这条分工。
3. **测试里的替身也不许比判据宽**：替身宽，判据看起来就验得更多。宽替身要么是判据该加
   一条（那就新写一条判据），要么是替身在冒充生产形状（那就不许冒充）。
4. **将来要判线格式事实，就新写一条判据并写明它的比较面**，不许靠把入参换宽来「顺手
   管住」——换宽是拿类型暗示判据，读代码的人看不出它到底比了什么。

**判据**：`prompt_fidelity` 的 9 条（含反向自检 `the_fidelity_check_reports_every_gap_it_claims_to`
与快照换基两条）全绿；session 的 `an_artifact_round_is_complete_after_reopen` 绿；
`session-retire-audit` 三码绿（SR-001 证明 `PromptMessage` 确实零命中，不是换成别名留在
账上）。

**不做什么**：不把 `verify` 搬进 session（那是把一条 core 能算、且不只 core 一家会算的
判据搬进即将退役的一侧，且边一就成了「搬走判据」而不是「收窄依赖」）；不为摘一条符号去
调宽 `plugin-api`（那只是把依赖搬家，边还在——D-451 第 2 条「不许两条边同时动」与
`D-443` 第 1 条「测试不续命」都指这件事）。
