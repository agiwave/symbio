# 插件路由与地址

本文定义插件树内的绝对地址、相对臂与路由规则。协议载荷见
[协议规范](005-协议规范.md "DE-005-协议规范")，容器组织见 [架构总览](002-架构总览.md "DE-002-架构总览")。

## 1. 地址模型

一个可路由地址由父容器的 `route` 前缀与插件内部相对臂组成。绝对地址在每层只剥离一次；
最终叶子收到的不是完整绝对地址，而是相对于自身的臂。

| 规则 | 约束 |
|---|---|
| 前缀 | 插件目录名是其在父容器中的路由前缀 |
| 绝对地址 | 由父容器沿插件树逐层解析，不由叶子拼接全局路径 |
| 相对臂 | 插件只声明和匹配自己拥有的地址片段 |
| `PATH` | 只表达跨 `route` 的下一跳，不承载业务状态 |
| 资源地址 | 经 `vdfs/*` 协议进入对应资源根，再按 VDFS 规则寻址 |
| 常量 | 协议路径和相对臂使用生成常量，不散落字符串字面量 |

前缀与相对臂必须能唯一还原绝对地址。禁止在插件内部匹配其他兄弟插件的绝对臂，也禁止
通过强引用绕过父容器直接调用兄弟插件。

## 2. 容器与叶子

容器收到绝对地址后，将属于自身的段剥离，再把剩余相对臂交给子容器或叶子。叶子只在
自身相对臂内匹配；未命中时返回协议错误，不得回退到全局路由。

调用方跨插件时只需知道共同父容器和下一跳路径。父容器负责定位，不参与业务实现；容器
与叶子使用同一 `Plugin` 契约，因此调用方不区分目标类型。

## 3. 发现与工具名

`traverse` 是能力发现入口。容器把自身路径前缀下传，叶子返回能力元数据；工具对模型的
完整名称由挂载前缀与短名组成。

发现结果必须来自实际装配的插件树。未挂载、已停用或装载失败的插件不得出现在可用工具
清单中；发现过程不得为了补全清单而实例化未声明能力。

## 4. 审计规则

| 判据 | 要求 |
|---|---|
| E-001 | 绝对路由入口与相对臂声明必须成对 |
| E-002 | 插件不得强引用兄弟插件 |
| E-003 | `PATH` 不得被当作业务数据存储 |
| E-004 | 相对臂不得包含其他插件的挂载前缀 |
| E-005 | 协议路径与资源根不得由消费方硬编码 |
| E-006 | 工具完整名必须可由前缀与短名重建 |
| E-007 | 文本扫描只检查路由声明与调用面，不把普通说明文字误判为路由 |

审计以声明和实际调用为输入。扫描命中后必须能定位到具体符号；无法机械判定的语义边界
通过类型约束或测试执行，不以关键词数量代替协议正确性。
