# 能力包与扩展面

能力包拥有自己的实现、声明、状态转换、效果、上下文贡献与部署身份。架构只提供封闭的
判断语法、扩展位置和执行顺序。新增能力是在既有位置落一个实例，不是给宿主增加按能力名
分支的字段或策略。

跨插件地址与词汇生成见 [DE-024](024-能力横向扩充的通路.md)，内核与门面边界见 [DE-023](023-内核边界与扩展局部性.md)，影响类与全面拆分见
[DE-026](026-能力拆分与影响类.md)。本文规定能力包的结构与扩展位置的准入，不维护插件、视图或模块去向清单。

## 1. 能力包的四元组

一个完整能力由四个成员构成：

```text
事实（FactDecl / EventDecl） + 视图（ViewDecl） + 行（Decl） + 执行体（RowHandler）
```

四元组不一定对应四个文件或四个 crate；能力包是一个插件 crate 及其全部声明。事实说明
写什么，视图说明如何纯计算，行说明何时欠账与如何收口，执行体说明如何产出。宿主提供
写口、选择、预算、租约和协议记账，不代替能力做业务判断。

行执行体只收债实例、本行声明的事实切片与宿主值，交出：

```text
Vec<FactDraft> | RowStep::Ask(ModelAsk)
宿主统一写口落格；应答经 RowReply → RowHandler::parse 再产生 FactDraft
```

需要调用其它插件时，`run_ctx` 只用于建立子上下文、设置路径或载荷，并经 `ctx.parent()`
路由。它不获得 `&mut Ctx`、存储句柄或兄弟插件类型。模型往返与跨插件接力可以拆成多行，
由事实衔接；不为某个能力把两种出口压成私有协议。

## 2. 效果：能力产出，宿主落格

`ToolBehavior` 自报 owner、行为名和产出种类，宿主按声明选择实现：

```text
call → before → execute → after → Vec<FactDraft> → 唯一写入口
```

- `before` 接收纯值请求，只返回放行或拒绝。任一拒绝即拒绝，先拒绝者胜；它不写事实，
  也不改写模型已经看到的参数。
- `after` 产生事实草稿，不接触 WAL。宿主补齐归属、溯源、时刻与主体，经写闸落格。
- `annotate` 只补全既有产品格，不新造事实格。是否新建格由业务语义决定，不由工具名决定。

宿主外部授权先执行，声明行为随后按 owner 序求值。工具通过 `CapabilityMeta.behaviors`
声明自己接受哪些行为；未声明的实现不会被调用。需要历史判断时，`BeforeRequest` 提供只读
事实切片；跨会话结论由宿主按通用读数口径算好后传入。

行为实例是开放集合：新实例在自己的包内声明名字并注册实现。新的判断语义、权威动作或
全局量词守卫不是普通实例，必须进入封闭语法或引擎强制点。行为名跨插件共享时遵循
[DE-024](024-能力横向扩充的通路.md) 的单一词汇源规则。

## 3. 上下文与检索贡献

`ContextProvider` 注册到编译期收集面。宿主按 owner 序收集，先发言级、再请求级；请求级
可获得已收集的工具清单、委派结论与进展。provider 只渲染宿主已经判定的值，不重新决定授权、
预算或控制流。

`ContextSection` 携带段身份、正文与裁剪优先级。成本由宿主用与预算相同的计量尺回填，
provider 不自行估算第二套 token。拼接次序是模型读取次序；超预算时按优先级降序、收集序
升序确定性裁剪，输出仍保持收集序。跳过放不下的段而不是停止整轮，并留下裁剪读数。

轮首检索由 `Retriever` 贡献排好序的结构值。宿主负责可见域、快照与预算边界，能力负责
自己的折叠和排序。贡献端口只交值，不交会话句柄、活配置或其它 provider 的私有类型。

## 4. 领域与行为的扩展位

`Entity` 与 `Verb` 是封闭语法。新领域事实使用 `Domain × Verb`，事件名、格位、角色和
载荷由 owner 的 `EventDecl` 声明；`FactRole` 不随领域开放。

写闸对领域格没有特判：声明存在才放行，自述挪格或未声明格 fail-closed。放行不意味着宿主
理解该领域；领域事实不是对话槽位，读侧不得为了显示某个领域新增对话种类。领域区分靠
声明的事件名，不靠把 `Entity` 改成开放字符串。

行为、上下文段名和工具命名空间按需要开放实例，但协议事实、量词角色、权威动作、停机
原因、写闸与不变量保持封闭。一个开放名称只有在存在实际跨插件消费时才进入公共词汇面。

## 5. 部署与两种停用粒度

`PLUGIN.yml` 是部署事实源，生成物只读、不手改。身份、装配、路由、共享事件、主体权限、
工具命名空间、触发种类和链接信息都由 owner 清单或目录事实投影。名字及理由仍住代码，
生成器对代码常量与清单集合双向核对。

生成形态只有三类：整份行表文件、混合文件中的标记块、供成员资格判断的登记表。消费方
只使用生成结果，不另抄一份。结构事实由 [RE-006](../004-ref/006-当前事实表.md) 自动提取。

停用必须区分两层：

| 开关 | 粒度 | 实际效果 |
|---|---|---|
| 运行期装配位 | 每棵插件树 | 不构造该树实例；工具、路由与后台行为不再触发 |
| 链接期装配 | 每份二进制 | crate 不进入二进制，其声明、行为与上下文贡献一并消失 |

编译期 inventory 属于进程，不属于某一棵树。运行期停用不会自动移除链接期贡献；上下文
provider 仍可能渲染历史事实。不得用进程全局“已启用 owner”表伪造按树过滤，也不让插件
反向读取部署面。彻底移除能力使用构建裁剪。

## 6. 投影与报表跟随消费方

投影是纯折叠，只有一个生产消费方时跟随该消费方；跨插件共享的无状态机制按
[DE-023](023-内核边界与扩展局部性.md) 的归属规则安置。owner 公开视图时声明 `ViewDecl` 并通过 `submit_reports!`
登记报表，读方只遍历登记结果。

`ViewDecl.eval` 处理单片，`agg` 可选地合并多片；`reads` 与 `evidence` 分开。读侧按名字
取得 JSON 值，不反序列化成第二份同名类型，也不调用 owner 插件重算。`cost` 只约束环内
窗口，不是读侧历史上限。未密封与未知视图必须可诊断地区分。

报表槽位、顺序、视图和实例落点都由 owner 声明，非法登记返回错误。文档不复制这些运行
时清单；唯一契约事实源是 `ReportDecl`。

## 7. 扩展位置闭表

扩展按“时刻 × 输入 × 产出 × 触发”闭合，不按使用热度增加位置。

| 时刻 | 输入 | 产出 | 触发 | 扩展面 |
|---|---|---|---|---|
| 轮首 | 可见切片与当前发言 | 排序后的结构值 | 无条件 | `Retriever` |
| 环内一步 | 债键、本行事实、全史 | 事实草稿、模型提问、解析结果 | 事件等值 | `RowHandler` |
| 段渲染 | 声明与宿主取值 | 文本段 | 无条件 | `ContextProvider` |
| 调用前 | 请求纯值与批首读数 | 放行或拒绝 | 每次调用 | `ToolBehavior::before` |
| 调用后 | 调用现场纯值 | 事实草稿或产品格富化 | 每次调用 | `ToolBehavior::after/annotate` |
| 收束 | 全史与宿主值格 | 逐条事实草稿 | 无条件 | `Contributor` |
| 读侧 | 事件切片与 as-of | 单片值或多片汇总 | 按名读取 | `ViewDecl` |
| 装配 | 声明 | 冻结声明表 | 一次 | `PluginDeclarations` |

以下位置明确关闭：

- 收束时的成组原子写入：贡献逐条过写闸，没有“整组同进同退”的扩展端口。
- 计数阈值、时间窗口未发生等聚合触发：环的开启条件是事件等值。状态条件先由 owner 投影
  为事实，不能直接变成新的触发语法。
- 轮外空闲或定时拟人推理：调度走既有触发种类，不新增能力位置。

新增位置必须先能用不提任何能力名的通用术语描述缺口，并有真实生产消费者及撤除路径。
只满足通用描述而没有消费者时，先记账等待；只有通用缺口、真实消费与可执行撤除计划同时
成立才允许开格。开格属于架构补件，与能力迁移分开，不能夹在搬迁中完成。

## 8. 收束贡献

`Contributor` 在收束后按 `(prio, owner)` 顺序被询问，每次询问前刷新事实，因此后续贡献者
可以看到早先贡献已经落格的值。端口只交不透明幂等词干，归属信封由宿主补齐；不把存储写口
或会话状态交给贡献者。

空贡献是正常结果，不表示故障。贡献可以读取事实中的开关与配置，不读取进程活值；同一份
历史回放必须得到相同贡献。贡献逐条落格，因此不承诺组原子性。

## 9. 强制点与准入判据

能力可以产出判定，引擎强制“什么算合法”。闭的是全局量词守卫、唯一写口、声明冻结与
执行顺序，不是判定的生产者。授权、不变量、承诺配对和单写者顺序不能由单个插件自行
改写。

| 判据 | 规则 |
|---|---|
| `E-009` | 能力间编译期零依赖，运行期只走父容器 JSON 路由 |
| `EX-002` | 新增能力包不改受保护机制树；已有生成路径不豁免新公共面 |
| `EX-003` | 迁移同提交删除旧实现并切换绑定，不保留双写 |
| `EX-004` | 卸载后能力及其静态边消失，系统仍完整运行 |
| `EX-005` | 开账行必须有注册实现，或由端口开启侧受理 |
| `EX-008` | 扩展 API 不重新引入容器词汇与宿主会话类型 |
| `HS-002/HS-006` | 门面三个暴露面只许不涨，且每项有真实扩展消费者 |
| `CS-009` | 封闭实体的公开字段与变体只许收窄 |

门面暴露面与机制补件告警由脚本重算，文档不抄基线数字。补件必须通用；迁移只做删除与
绑定切换。机制面净增不为正，净零搬迁不能抵消净负迁移的义务。具体结构事实以
[RE-006](../004-ref/006-当前事实表.md) 为准。

## 10. 明确不做

- 不建立插件间类型共享模块、`pub use` 转发或“只共享类型”的依赖。
- 不从 YAML 生成跨插件 Rust 类型；跨包协议使用 JSON 形状或显式通用契约。
- 不向能力开放 WAL、`&mut Ctx`、会话存储句柄或进程活配置。
- 不按工具名增加端口、行为分支、布尔位或实体变体。
- 不把领域放行解释成领域理解，不把运行期停用解释成链接期移除。
- 不让新旧实现同时生效，不把能力实现搬进机制层冒充通用端口。
- 不为某个消费者扩大封闭语法；先证明缺口通用，再按架构补件处理。
