# 自主层与长期目标

## 内容

前置：S11、S09 ｜ **新增机制键 0** ｜ 参数变化 4 ｜ 阶段四

## 1. 场景：要什么能力

没有用户消息时，系统**自己发起**工作：定时触发、长期目标推进、跨天运行、自我排期。

相对 S11 高了什么：前面 11 阶全部是**响应式**的——有输入才有行为。
本阶第一次出现"**欲**（Conation）"这个维度：**没有外部刺激也会做事**。
[DE-008 能力坐标系](008-能力注册表与能力坐标系.md "DE-008-能力注册表与能力坐标系") 明确指出：缺了这一维，系统再强也永远在等指令。

## 2. 为什么它能落在 v2 上（J1）

| 看起来新的东西 | 实际是 |
|---|---|
| 定时触发 | `system/opened`（`system.triggered`）事件——**触发器产出事件，不是旁路** |
| 长期目标 | 一条 `task/opened` 事件，`budget_ms = 86400000` |
| 自主排期 | 一个 `Decider`，输入 `ReadySet`，输出 `task.assigned`（同 S04） |
| 健康自检 | `system/progressed`（`system.health`） |

**关键**：自主层**不是一个新架构层**，只是 `budget_ms` 的第四个取值（86400000ms）。
反射 80 / 快速 300 / 深度 60000 / 自主 86400000——**四层都是同一个参数，不是四种架构**。
这是本阶"新增机制键 = 0"的根本原因。

## 3. 增量清单（只加数据）

| 类型 | 内容 |
|---|---|
| 事件格子 | `system/opened`（`system.triggered`）、`system/progressed`（`system.health`）；<br/>**`conation/expressed`（`conation.expressed`）**——「欲」的事件形态（见 [DE-008 §2.3](008-能力注册表与能力坐标系.md "DE-008-能力注册表与能力坐标系")） |
| ActorSpec 行 | 自主发起者 `{ pattern: decider, capabilities: [DefineWork], budget_ms: 86400000, scope: root }`——**裁决不建**（形态 = 常量 + 档位，理由见 §3.1） |
| grants 行 | 自主发起者 ▸ `define.work` 写；**不可写 `chat.assistant.*`**（自主行为不得冒充用户对话） |
| 投影参数 | `projection = readyset`（复用 S04）；**`projection = conation`**（读出「欲」及各自的升格状态，见 §3.1） |

> **「欲」不需要新机制键**：它是 `event.entity = conation` 与 `projection = conation` 两个**新取值**。
> 完整可执行形态见 [DE-008 §2.3](008-能力注册表与能力坐标系.md "DE-008-能力注册表与能力坐标系") 与 `verify/conation_minimal.rs`。

### 3.1 落地状态：这一节里哪些增量今天存在

上表逐条对代码（本批核实：**三行成立、一行只是目标**）：

| 增量 | 今天 | 说明 |
|---|---|---|
| 事件格子 | **已在生产** | `AutonomousInitiator` 的四个构造子；写方 = `plugins/session/transcript/autonomous::record_autonomous_trigger`（先落事实、再开轮，溯源锚 = 落格前上一格 seq） |
| 投影参数 `conation` | **已在生产** | `symbio_core::projection::conation`（`ConationView` / `ConationIntent`）：读 `conation.expressed` 与它**有没有升格成任务**，升格靠**溯源**认（`task.opened` 的 `produced_by` 指回欲 seq，不是 goal 字符串相等）。生产消费方 = `transcript/autonomous::long_goal_declared` 的去重判据 `is_declared(goal)`——此前那是插件里的一次**直接全表扫**，判定现在住 ③、插件只消费。判据 = `conation.test.rs`（五条）+ `transcript/autonomous.test.rs::gate_opens_the_long_goal_exactly_once_per_goal`（集成后果） |
| grants 行 | **已在生产**（本批补的） | `authz::ROWS` 里 `PRINCIPAL_AUTONOMOUS` 那一行：**只持 `define.work`**、不持 `reply`。未登记主体按 [D-099](011-Agent目录规范.md "DE-011-Agent目录规范") fail-closed（不派生主智能体能力集），可用性由**装配点绑定登记**承担（[D-100](008-能力注册表与能力坐标系.md "DE-008-能力注册表与能力坐标系")：根会话继承会话面缺省行、委派子会话继承父行，可见域不登记）——静态行不被改写，自主行仍窄。判据 = `authz/mod.test.rs::the_autonomous_row_is_narrower_than_main` |
| ActorSpec 行 | **未落地** | 见下 |

**为什么 ActorSpec 行不照抄落地**：`AutonomousInitiator` 不构造 `ActorSpec`，也**不该**构造——
心跳这条链**直接落事实**（`system.triggered` → `conation.expressed` → `task.opened`），
不走「装配主体 → 跑一轮」那条路（那条路的生产构造点只有 `loop/chat_loop/state.rs::request_actor_spec` 一处，
主体是会话选定的那个 agent）。硬造一个只会得到一件**没有消费方**的值；而若把 `capabilities`
一并写进去，就多出**第二份能力清单**与授权表对峙——两边都是合法能力名，漂移了没有任何东西
会变红（这正是 `authz` 模块头在讲的那类失效）。故本阶只认**两处单点定义**：
主体名 = `authz::PRINCIPAL_AUTONOMOUS`（表里那一行与四个事件的 `actor` 是同一个常量）、
预算 = `LatencyTier::Autonomic`。`AutonomousInitiator` 的类型文档写的是**形状**
（`pattern: decider` / 只 `define.work` / 自主档预算），**权威在表与档位表里**。

**「未完成」这个词在本阶读不出来**：没有 `conation.fulfilled` 事件，欲一旦升格就一直是
「已声明」——所以视图只表达**已表达 / 已升格**两态，不假装知道完成与否（`conation` 模块头
的边界一节）。§3 上表原文写的「读出当前未完成意图」是设计意图的表述，落到生产是这两态。

**§6 验收 2 的判据换过一次**（本批）：原先那条用例自造
`PrincipalPolicy::paired("session/autonomous", …)` 矩阵，再断言「拒绝 ⇒ `store.head` 不变」
——自造矩阵只证明「一个我自己写的策略拒绝了我自己」，而空 store 上「拒绝 ⇒ 零事件」是
**同义反复**（没有任何主体尝试过写）。现在它查 `authz::production_matrix`（生产表），并加两条对照：
自主发起者**持** `define.work`（否则拒绝可能只是「矩阵整个是空的」的平凡真）、
主智能体**持** `reply`（拒绝是**针对这个主体**的）。「拒绝 ⇒ 不产生事件」的**执行**
在写侧闸 `turn_runner::closure_gate`，其判据用例见
`turn_runner.test.rs::closure_is_withheld_when_the_principal_lacks_the_grant`。

**本阶点亮的机制键**（阶梯总表的「新增机制键」由这张块算出；`scripts/gen-verify-facts.mjs` 从这里取输入）：

```capability-assign
event.entity = system
event.verb = opened
actor.pattern = decider
actor.budget_ms = 86400000
```

## 4. 平凡值与回退（J2）

| 参数 | 完整值 | **平凡值** | 平凡值下 |
|---|---|---|---|
| `event.entity` | `system` | **`turn`** | 仍完整运行——无定时触发，退化成纯响应式（S11 状态） |
| `actor.budget_ms` | `86400000` | `60000` | 仍完整运行——长目标被当成普通深度任务推进 |
| **`ConationPolicy.enabled`** | `true` | **`false`** | 仍完整运行——「欲」不升格为任务，读侧投影照常工作（纯响应式） |

**`system` 实体不启用 = 自主性整阶可关闭**，这是生产环境最需要的一个开关：
一个"会自己发起行为"的系统必须有能力被一键退回"只响应"。
同理 `ConationPolicy.enabled = false` 关掉的是**欲望侧**的升格，两层开关独立。

## 5. 静默失效与强制（J3）

| 约束 | 违反时信号 | 强制方式 |
|---|---|---|
| 自主行为不得写入用户对话通道 | **无** | grants：无 `reply` 写权 |
| 长目标必须在预算内产出或兜底 | **无**——静默挂起数天 | I3：86400000ms 到点必答 |
| 自主发起的工作可追溯 | **无** | I2：触发器产生的事件带 `produced_by` |
| **「欲」不得直接变成「行」** | **无**——绕过授权与事实流 | **不可伪造的批准类型**：`ApprovedTask` 字段私有、唯一构造点是 `IntentGate::approve`，且闸内判授权（`define.work`）（[DE-008 §2.3](008-能力注册表与能力坐标系.md "DE-008-能力注册表与能力坐标系")） |
| **「欲」必须有溯源** | **无**——来路不明的意图混入 | I2 强化：`conation.expressed` 无 `derived_from` 时**构造不出** `CandidateIntent` |

## 6. 验收断言

1. 无用户消息时，定时触发必须产生 `system.triggered` 事件。
2. 自主发起者尝试写 `chat.assistant.final` → 授权拒绝且不产生事件。
3. 长目标超过 86400000ms → 必须产出兜底事件（`budget.rs` 已覆盖四层）。
4. **反向用例**：把预算改成 60000ms → 断言 3 的判定必须改变。
5. **「欲」治理三条**（`conation_minimal.rs` 已覆盖）：
 - `CandidateIntent` 造出来一定 `approved = false`，过闸门后才可执行；
 - 无溯源的 `conation.expressed` 构造不出候选意图（I2）；
 - 关闭 `ConationPolicy.enabled` → 无任何自主任务，但读侧投影仍完整工作（J2）。

**§6 验收断言的执行方**：1 = `scheduled_trigger_produces_event_not_side_channel`（`symbio_core/actors/mod.test.rs:2041`）+ e2e **t36**；2 = `autonomous_actor_cannot_write_to_dialog`（同文件 `:2075`）+ `the_autonomous_row_is_narrower_than_main`（`symbio_core/authz/mod.test.rs:55`）；3 = `long_goal_overrun_is_visible_and_budget_param_is_live`（同文件 `:2100`）+ 设计级 `verify/budget.rs`（四层预算）；4 = 同上一条的反向半（预算改成 60000ms ⇒ 判定改变）；5 = 设计级 `verify/conation_minimal.rs` + `symbio_core/projection/conation.test.rs`（`as_of_hides_intents_and_promotions_from_the_future` 等）。

## 8. 这一阶做不了什么

边界的唯一账本：[SC-012-自主层与长期目标](../002-scene/012-自主层与长期目标.md)（用户语言）。机制面独有边界（用户可见范围之外的工程约束）：

- 「欲」的**内容**（想要什么）不由架构决定，架构只管"欲如何被治理"（[DE-008 §2.3](008-能力注册表与能力坐标系.md "DE-008-能力注册表与能力坐标系")）。
- 自主系统的**成本失控**风险：`budget` 投影读的是实测 `cost_ms`（基准见 `RE-004-slo-calibration`），真实流量下的 P99 仍待出数。
