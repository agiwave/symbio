# 自主层与长期目标

## 内容

前置：S11、S09 ｜ **新增机制键 0** ｜ 参数变化 4
## 1. 场景：要什么能力

没有用户消息时，系统**自己发起**工作：定时触发、长期目标推进、跨天运行、自我排期。

相对 S11 高了什么：前面 11 阶全部是**响应式**的——有输入才有行为。
本阶第一次出现"**欲**（Conation）"这个维度：**没有外部刺激也会做事**。
[DE-008 能力坐标系](008-能力注册表与能力坐标系.md "DE-008-能力注册表与能力坐标系") 明确指出：缺了这一维，系统再强也永远在等指令。

## 2. 为什么它能落在 v2 上（J1）

| 看起来新的东西 | 实际是 |
|---|---|
| 定时触发 | `system/opened`（`system.triggered`）事件——**触发器产出事件，不是旁路** |
| 长期目标 | 一条 `task/opened` 事件，`budget_ms = 86400000` |
| 自主排期 | 一个 `Decider`，输入 `ReadySet`，输出 `task.assigned`（同 S04） |
| 健康自检 | `system/progressed`（`system.health`） |

**关键**：自主层**不是一个新架构层**，只是 `budget_ms` 的第四个取值（86400000ms）。
反射 80 / 快速 300 / 深度 60000 / 自主 86400000——**四层都是同一个参数，不是四种架构**。
这是本阶"新增机制键 = 0"的根本原因。

## 3. 增量清单（只加数据）

| 类型 | 内容 |
|---|---|
| 事件格子 | `system/opened`（`system.triggered`）、`system/progressed`（`system.health`）；<br/>**`conation/expressed`（`conation.expressed`）**——「欲」的事件形态（见 [DE-008 §2.3](008-能力注册表与能力坐标系.md "DE-008-能力注册表与能力坐标系")） |
| ActorSpec 行 | 自主发起者 `{ pattern: decider, capabilities: [DefineWork], budget_ms: 86400000, scope: root }`——**裁决不建**（形态 = 常量 + 档位，理由见 §3.1） |
| grants 行 | 自主发起者 ▸ `define.work` 写；**不可写 `chat.assistant.*`**（自主行为不得冒充用户对话） |
| 投影参数 | `projection = readyset`（复用 S04）；**`projection = conation`**（读出「欲」及各自的升格状态，见 §3.1） |

> **「欲」不需要新机制键**：它是 `event.entity = conation` 与 `projection = conation` 两个**新取值**。
> 完整可执行形态见 [DE-008 §2.3](008-能力注册表与能力坐标系.md "DE-008-能力注册表与能力坐标系") 与 `verify/conation_minimal.rs`。

### 3.1 落地状态：这一节里哪些增量今天存在

上表逐条对代码（本批核实：**三行已在生产，第四行按裁决不建构造点**）：

| 增量 | 今天 | 说明 |
|---|---|---|
| 事件格子 | **已在生产** | `crates/symbio-plugin-session/src/transcript/autonomous.rs` 的 `AutonomousInitiator` 四个构造子；写方 = 同文件的 `record_autonomous_trigger`（先落事实、再开轮，溯源锚 = 落格前上一格 seq） |
| 投影参数 `conation` | **已在生产** | `crates/symbio-plugin-conation/src/decl.rs::intents`（能力包 `conation`，站位见 [D-269](025-能力包与扩展面.md "DE-025-能力包与扩展面")）：读 `conation.expressed` 与它**有没有升格成任务**，升格靠**溯源**认（`task.opened` 的 `produced_by` 指回欲 seq，不是 goal 字符串相等）。生产消费方 = `crates/symbio-plugin-session/src/transcript/autonomous.rs` 的 `long_goal_declared`——按名字读视图、查 `declared` 那一格，读不到就不升格；判定住能力包，会话只消费。判据分两层：**数字**归 owner（`crates/symbio-plugin-conation/src/decl.test.rs` 九条）；**组合**归端到端（`e2e/cases/t36-autonomous-initiator.mjs` 真跑两个 tick，就绪集里始终只有一条心跳任务）——读方单测只钉「读不到 ⇒ 退化成什么」，见 [D-269](025-能力包与扩展面.md "DE-025-能力包与扩展面") §5.3 |
| grants 行 | **已在生产**（本批补的） | `authz::ROWS` 里 `PRINCIPAL_AUTONOMOUS` 那一行：**只持 `define.work`**、不持 `reply`。未登记主体按 [D-099](011-Agent目录规范.md "DE-011-Agent目录规范") fail-closed（不派生主智能体能力集），可用性由**装配点绑定登记**承担（[D-100](008-能力注册表与能力坐标系.md "DE-008-能力注册表与能力坐标系")：根会话继承会话面缺省行、委派子会话继承父行，可见域不登记）——静态行不被改写，自主行仍窄。判据 = `authz/mod.test.rs::the_autonomous_row_is_narrower_than_main` |
| ActorSpec 行 | **不建（裁决）** | 心跳链直接落事实，不经「装配主体 → 跑一轮」——形状本身是错的，见下 |

**为什么 ActorSpec 行不照抄落地**：`AutonomousInitiator` 不构造 `ActorSpec`，也**不该**构造——
心跳这条链**直接落事实**（`system.triggered` → `conation.expressed` → `task.opened`），
不走「装配主体 → 跑一轮」那条路（那条路的生产构造点只剩 `crates/symbio-plugin-session/src/transcript/inbox.rs` 与 `crates/symbio-sdk/src/actors/control.rs` 两处，
主体是会话选定的那个 agent）。硬造一个只会得到一件**没有消费方**的值；而若把 `capabilities`
一并写进去，就多出**第二份能力清单**与授权表对峙——两边都是合法能力名，漂移了没有任何东西
会变红（这正是 `authz` 模块头在讲的那类失效）。故本阶只认**两处单点定义**：
主体名 = `authz::PRINCIPAL_AUTONOMOUS`（表里那一行与四个事件的 `actor` 是同一个常量）、
预算 = `LatencyTier::Autonomic`。`AutonomousInitiator` 的类型文档写的是**形状**
（`pattern: decider` / 只 `define.work` / 自主档预算），**权威在表与档位表里**。

**「未完成」这个词在本阶读不出来**：没有 `conation.fulfilled` 事件，欲一旦升格就一直是
「已声明」——所以视图只表达**已表达 / 已升格**两态，不假装知道完成与否（`conation` 模块头
的边界一节）。§3 上表原文写的「读出当前未完成意图」是设计意图的表述，落到生产是这两态。

**§6 验收 2 的判据换过一次**（本批）：原先那条用例自造
`PrincipalPolicy::paired("session/autonomous", …)` 矩阵，再断言「拒绝 ⇒ `store.head` 不变」
——自造矩阵只证明「一个我自己写的策略拒绝了我自己」，而空 store 上「拒绝 ⇒ 零事件」是
**同义反复**（没有任何主体尝试过写）。现在它查 `authz::production_matrix`（生产表），并加两条对照：
自主发起者**持** `define.work`（否则拒绝可能只是「矩阵整个是空的」的平凡真）、
主智能体**持** `reply`（拒绝是**针对这个主体**的）。「拒绝 ⇒ 不产生事件」的**执行**
在写侧闸 `crates/symbio-sdk/src/governance/mod.rs::can_write`，其判据用例见
`crates/symbio-sdk/src/governance/mod.test.rs` 的配对矩阵用例。

**本阶点亮的机制键**（阶梯总表的「新增机制键」由这张块算出；`scripts/gens/gen-verify-facts.mjs` 从这里取输入）：

```capability-assign
event.entity = system
event.verb = opened
actor.pattern = decider
actor.budget_ms = 86400000
```

## 4. 平凡值与回退（J2）

| 参数 | 完整值 | **平凡值** | 平凡值下 |
|---|---|---|---|
| `event.entity` | `system` | **`scope`** | 仍完整运行——无定时触发，退化成纯响应式（状态） |
| `actor.budget_ms` | `86400000` | `60000` | 仍完整运行——长目标被当成普通深度任务推进 |
| **`ConationPolicy.enabled`** | `true` | **`false`** | 仍完整运行——「欲」不升格为任务，读侧投影照常工作（纯响应式） |

**`system` 实体不启用 = 自主性整阶可关闭**，这是生产环境最需要的一个开关：
一个"会自己发起行为"的系统必须有能力被一键退回"只响应"。
同理 `SessionConfig.conation_enabled = false` 关掉的是**欲望侧**的升格，两层开关独立。

## 5. 静默失效与强制（J3）

| 约束 | 违反时信号 | 强制方式 |
|---|---|---|
| 自主行为不得写入用户对话通道 | **无** | grants：无 `reply` 写权 |
| 长目标必须在预算内产出或兜底 | **无**——静默挂起数天 | I3：86400000ms 到点必答 |
| 自主发起的工作可追溯 | **无** | I2：触发器产生的事件带 `produced_by` |
| **「欲」不得直接变成「行」** | **无**——绕过授权与事实流 | **不可伪造的批准类型**：`ApprovedIntent` 字段私有、唯一构造点是 conation 的 `IntentGate::approve`，且闸内判授权（`define.work`）（[DE-008 §2.3](008-能力注册表与能力坐标系.md "DE-008-能力注册表与能力坐标系")） |
| **「欲」必须有溯源** | **无**——来路不明的意图混入 | I2 强化：升格执行体按 `produced_by` 回读那条 `conation.expressed`，无溯源**升不了格** |

## 6. 验收断言

1. 无用户消息时，定时触发必须产生 `system.triggered` 事件。
2. 自主发起者尝试写 `chat.assistant.final` → 授权拒绝且不产生事件。
3. 长目标超过 86400000ms → 必须产出兜底事件（`budget.rs` 已覆盖四层）。
4. **反向用例**：把预算改成 60000ms → 断言 3 的判定必须改变。
5. **「欲」治理三条**（`D-384` / `D-386`）：
 - `ApprovedIntent` 写不出结构体字面量（字段私有），唯一构造点过闸门；
 - 无溯源的 `conation.expressed` 升不了格（执行体回读不到 `produced_by`）；
 - 开关关 / 目标过宽 / 已声明 ⇒ `conation.promote` 债不欠，无任何自主任务，但读侧投影仍完整工作（J2）。

**§6 验收断言的执行方**：1 = `scheduled_trigger_produces_event_not_side_channel`（`crates/symbio-plugin-session/src/transcript/autonomous.test.rs::scheduled_trigger_produces_event_not_side_channel`）+ e2e **t36**；2 = `autonomous_actor_cannot_write_to_dialog`（`crates/symbio-sdk/src/actors/mod.test.rs::autonomous_actor_cannot_write_to_dialog`）+ `the_autonomous_row_is_narrower_than_main`（`crates/symbio-sdk/src/authz/mod.test.rs::the_autonomous_row_is_narrower_than_main`）；3 = `long_goal_overrun_is_visible_and_budget_param_is_live`（`crates/symbio-plugin-session/src/transcript/autonomous.test.rs::long_goal_overrun_is_visible_and_budget_param_is_live`）+ 设计级 `verify/budget.rs`（四层预算）；4 = 同上一条的反向半（预算改成 60000ms ⇒ 判定改变）；5 = `crates/symbio-plugin-conation/src/port.test.rs`（`the_executor_opens_one_long_task_anchored_to_the_intent` / `an_orphan_intent_never_promotes`）+ `crates/symbio-plugin-conation/src/debt.test.rs`（开关 / 宽度 / 已声明三条 early return，`D-386`）+ `crates/symbio-plugin-session/src/transcript/autonomous.test.rs::without_the_capability_pack_nothing_promotes`（读不到 ⇒ 不升格）。

## 8. 这一阶做不了什么

边界的唯一账本：[场景 §12](../002-scene/001-场景总册.md "SC-001-场景总册")（用户语言）。机制面独有边界（用户可见范围之外的工程约束）：

- 「欲」的**内容**（想要什么）不由架构决定，架构只管"欲如何被治理"（[DE-008 §2.3](008-能力注册表与能力坐标系.md "DE-008-能力注册表与能力坐标系")）。

## 关键决策

### D-384 内在动机的判据随能力包走：`conation.policy` 一条判决视图

- **背景**。`D-379` 只给开关的事实形状，并明确「`#32` 的迁移不在本条」。剩下的是：
  「这一条欲该不该升格」的**判据**（开关 + 目标宽度 200 字节）仍以 `ConationPolicy`
  的形式住在 `session/transcript/autonomous.rs`——读方替能力包记着一条它自己的策略。
  `DE-026` 的逐行处置账把 #32 判为「判定生产者随包」，`E2` 的强制点（授权 + 不可伪造的
  `ApprovedIntent`）留会话。跨插件不能传类型（`E-009`），也不许为它新开端口
  （迁移提交不含机制增量，`EX-007`）。
- **裁决**。
  ① 能力包新增共享视图 `conation.policy`：输入是最新一条**带溯源**的
  `conation.expressed` 与最新一条 `session.config`，输出
  `{seq, goal, enabled, max_goal_len, promotable, reason}`。开关关 ⇒ `conation disabled`；
  目标超过 `MAX_GOAL_LEN`（200 字节）⇒ `goal too broad`；否则 `promotable = true`、
  `reason = null`。`seq` 是绑定锚：会话拿候选的 seq 去对，对不上即视为读不到。
  ② 视图**不交 `agg`**：判决逐会话，没有「N 片合起来该不该升格」这种东西；
  读方要汇总时该格可诊断地缺席（`D-281`），不是「汇总下来为零」。
  ③ 会话只留**强制点**：`PolicyVerdict` 是读形状（不认识 `SessionConfig`），
  `IntentGate::evaluate` 先认 `promotable`、再判 `define.work`，仍由它构造
  `ApprovedIntent`。会话不再比较长度、不再读开关。
  ④ 读不到（能力包不在 / 视图未公开 / 切片超预算 / `seq` 对不上）⇒ 本轮**不升格**：
  四种都是可诊断的缺席，既不当作「该升格」，也不当作「没声明过，于是每 tick 重开」。
- **代价**。本包多一条视图与一条 `D-282` 第二种读法（`session.config` 无 `FactDecl`）；
  会话那侧删结构体与本地读法、加一个按名字读的读形状。`sdk` / `kernel` / `plugin-api`
  零改动（报表名是 owner 的报表登记，不是机制公开项），因此不计入 `D-372` 的补件账。
  会话的单测二进制不链接能力包（`E-009`），所以「判据的数字」只能住在 owner：
  开关读法、宽度边界、as-of、只判带溯源的那一条，全钉在 `decl.test.rs`；会话侧只钉
  「读不到 ⇒ 不升格」与闸门自身的强制（判决否决 / 授权）。组合仍归 `t36`。
- **判据**。owner 五条：`policy_refuses_when_the_switch_is_off` /
  `policy_defaults_the_switch_to_off` / `policy_refuses_only_a_goal_wider_than_the_owner_limit`
  （200 字节放行、201 拒）/ `policy_binds_the_latest_sourced_intent_as_of_now` /
  `policy_without_an_intent_says_so_instead_of_guessing`；会话侧
  `without_the_capability_pack_the_gate_opens_nothing` 与闸门用例仍绿；`t36` 仍绿
  （真实装配里两个 tick 只长一条心跳任务）。
- **不做什么**。不在会话里留一份「算法一样」的宽度比较；不把 `max_goal_len` 提成
  `SessionConfig` 字段（它是能力策略，不是编排旋钮）；不让 `session` 依赖
  `symbio-plugin-conation` 的 Rust 类型。
- **被 `D-386` 接替**：判决视图删除，判据改为 conation 自申报的债与端口执行体；
  本条保留为「判据随能力包走」这一裁决的记录。

### D-386 升格改为自申报债 + 端口执行体：视图不再承载动作，`enabled` 读本轮 config

- **背景**。`D-384` 把判据交回能力包，但形式是「共享视图 + 会话读」：判决是**查询面**，
  动作仍由会话做——授权闸、`ApprovedIntent`、已声明去重因此全留在会话，跨插件的
  「判定生产者随包」只兑现了一半；而且会话必须在开轮**之前**读视图，读到的只能是
  上一轮 `session.config`。机制面已经有两块现成的：债（`DebtSource`，环的计划层）与
  端口（`PortProvider` / `PortExecutor`，环的派发层，`D-385` 后授权自判）。
- **裁决**。
  ① **删除** `conation.policy` 视图与它在 `PLUGIN.yml` 的 `shared_views` 登记；视图只回答
     「发生过什么」，动作面不借查询面绕路。
  ② conation 自申报 `conation.promote` 债（`debt_row` + `DebtSource::rows`），三个 early
     return 在 `rows()`：本轮 `session.config` 的 `conation_enabled` 未开 / 不持
     `define.work` / 已有 `task.opened` 的 `payload.goal` 与本条相同 ⇒ 不欠。目标宽度
     上界 200 字节仍归本包（`debt::MAX_GOAL_LEN`）；无 `source_seq` 的「欲」也不欠
     （构造不出溯源锚）。
  ③ 执行体住 conation：自判授权并交 `AuthzVerdict`（`D-385`），通过后把 `task.opened`
     作为世界事实草稿交宿主写口。`ApprovedIntent` 在 conation 内重建（字段私有，唯一
     构造点 `IntentGate::approve`）；执行体是唯一能把它变成草稿的地方。
  ④ **`enabled` 口径变化**：`D-384` 的会话读点发生在开轮前（上一轮 config）；现在债在
     环里算，读的是**本轮** `session.config`（开轮时写），与模型债同一时点。本轮关掉
     即本轮不升格，不等下一轮。
  ⑤ `PRINCIPAL_AUTONOMOUS` 经 `plugin-api` re-export 给扩展层（conation 的债源与执行体
     共用一把尺）。HS-002：`SDK_BASELINE` 105 → 106，一处上调、理由在本条。
- **代价**。会话侧删 `IntentGate` / `ApprovedIntent` / `PolicyVerdict` / `ConationCandidate`
  与视图读点（净删）；conation 多一份债源与一个端口提供者。`sdk` / `kernel` / `loop`
  零改动。授权判据在 `rows()` 与执行体各调一次 `authorized()`——同一个函数，不是两份
  口径：前者省掉无意义的派发，后者是 `D-385` 要求的表态。
- **边界（诚实）**。自判只约束**诚实执行体**：执行体交 `Authorized` 时环无法验证它真的
