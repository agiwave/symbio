# 自主层与长期目标

自主层可以表达与执行长期意图，但不能冒充用户对话。自主主体的输出不得写用户对话面，
也不得取得 `reply` 授权。

## 1. 双层启用

自主行为必须同时满足两层独立条件：

1. 能力包已经装配并启用；
2. 当前 scope 的自主配置允许该能力运行。

任一层关闭即不产生触发债。配置按快照读取，不通过反向依赖直接读取 `SessionConfig`
类型；缺字段取禁用值。同一轮内使用一致快照，避免条件与执行体读到不同真源。

## 2. 触发、健康与欲求

自主触发、健康状态与 `conation.expressed` 都是事实。每条活欲求使用自身事实身份，
幂等键从来源与目标身份派生，不按“第几条”计数。

自主端口债必须携带触发来源、目标与预算。预算按自主延迟层声明；来源缺失时不升格为
用户意图，也不得写入对话终答。执行失败落显式事实，不以心跳或空响应伪装成功。

## 3. 意图升格

用户意图只能由带来源的显式提升事实产生。提升必须同时满足：

- 原始目标与来源事实可追溯；
- 提升主体拥有目标能力授权；
- `ApprovedIntent` 审批值不可伪造，且绑定来源、能力与作用域；
- 当前策略允许；
- 同一来源与目标的重复提升被去重。

策略声明只描述允许宽度与排除条件，不把历史批次或实现位置写进规则。审批在声明债源与
执行体两处检查：前者避免无意义派发，后者保证执行时显式表态。审批不是环解析授权载荷
的借口；提供者必须返回通用授权结论。

## 4. 视图边界

欲求视图只表达“已声明”或“已升格”，不表达“已满足”。满足、失败、撤销与完成由对应
事实投影。视图缺失时按具名视图契约返回空或降级，不折叠他方原始载荷补位。

长期目标改变计划时写新事实；不能改写旧目标或把自主判断记成用户批准。自主层需要用户
对话时，只能生成待确认意图，由用户事实确认后再进入普通处理链。

## 5. 能力阶梯赋值

```capability-assign
event.entity = system
event.verb = opened
actor.pattern = decider
actor.budget_ms = 86400000
```

## 6. 平凡值与回退

| 参数 | 平凡值 |
|---|---|
| `actor.pattern` | `decider` |
| `actor.budget_ms` | **60000** |
| `event.entity` | `system` |

无自主预算声明时使用普通延迟层的 60 秒预算，不获得无限运行权。升格与启用条件仍须
显式满足；`opened` 不表示用户已批准。
