# Agent 目录规范

协议标识：`agent-dir/v2`。Agent 的高层组织见 [核心架构](001-核心架构.md "DE-001-核心架构")，目录挂载见
[VDFS 规范](009-VDFS规范.md "DE-009-VDFS规范")，能力发现见 [能力注册表](008-能力注册表与能力坐标系.md "DE-008-能力注册表与能力坐标系")。

本规范定义目录协议，不定义插件容器扫描算法、能力插件私有配置或具体宿主实现。

关键词“必须 / 不得 / 应当 / 可以”按 RFC 2119 解释。

## 1. 核心主张

**一个 Agent 一个目录；目录里有什么，它就会什么。**

| 内容 | 载体 |
|---|---|
| 身份、版本、权限 | `manifest.yaml` |
| 稳定指令与人格 | 根目录 `AGENTS.md` |
| 动态记忆 | 根目录 `MEMORY.md` |
| 技能、工具等能力 | 目录下的能力插件 |
| 装配 | 通用插件容器 |

系统 Agent 与子 Agent 内部结构相同，都由同一容器装配；差别只在托管者和能力集合。
任何能装入子 Agent 的能力也能装入系统 Agent，不存在只有系统上下文才成立的隐藏能力。

宿主不得为 Agent 再实现一套技能或 MCP 解析。能力插件必须交给宿主既有系统处理，避免
两条解析链长期漂移。

## 2. 目录结构

```text
<agent dir>/
├── manifest.yaml
├── AGENTS.md
├── MEMORY.md
├── mcp/
│   └── PLUGIN.yml
├── skill/
│   └── PLUGIN.yml
└── <其它能力插件>/
    └── PLUGIN.yml
```

目录内相对路径一律以 Agent 根为基准。所有资源引用不得越出 Agent 目录，归档导入必须
逐条目校验规范化路径。

能力插件目录使用单数，因为一个目录就是一个插件实例，不是分类容器。能力由目录承载，
不在 manifest 重复登记。manifest 只保存无法从目录推导的身份、兼容性和权限。

没有插件清单文件的目录不是能力插件，装配时跳过。`AGENTS.md` 与 `MEMORY.md` 是 Agent
自己的文件，不是插件，不为其创建空壳解释器。

## 3. Manifest

```yaml
spec: "agent-dir/v2"
id: "com.acme.code-reviewer"
name: "代码评审专家"
version: "1.2.0"
description: "以资深评审视角审查代码"
authors: ["acme@example.com"]
license: "MIT"
icon: "assets/icon.svg"

requires:
  spec: "^2"

permissions:
  network:
    domains: ["api.github.com"]
  fs:
    read: ["assets/**"]
  limits:
    max_prompt_bytes: 65536
```

<!-- list:agent-dir-fields owner -->

| 字段 | 要求 |
|---|---|
| `spec` | 必须为 `agent-dir/v2` |
| `id` | 必须；以小写字母或数字开头，仅含小写字母、数字、`.`、`-`、`_`，长度 1–128 |
| `name` | 必须；展示名 |
| `version` | 必须；semver |
| `requires.spec` | 必须；形如 `^N` 或 `N` |
| `icon` | Agent 目录内相对路径，不得越界 |
| `permissions.fs.read / write` | 相对 Agent 根的 glob，不得含 `..` |
| 未知字段 | 必须允许并忽略，以保持向前兼容 |

manifest 不得声明 `skills / mcps / tools / prompts` 等重复目录事实的字段。

### 3.1 身份与目录名

子 Agent 目录名是实例名，应当与 `manifest.id` 的末段一致。文件系统限制导致变形时，以
`manifest.id` 为权威身份，目录名只用于本地定位。

### 3.2 失败语义

- 单个能力插件构造失败是软故障：记录诊断并跳过，其余部分继续装配。
- manifest 缺失、无法解析或校验失败是硬错误：拒绝加载整个 Agent。
- 协议版本不匹配是硬错误，不得降级为无指令的通用助手。

## 4. 权限执行模型

`network / fs / limits` 是 fail-closed grant，不是“未声明即允许”的上限。空清单表示拒绝，
列出的能力才可用。

| 字段 | 执行点 | 规则 |
|---|---|---|
| `network.domains` | 出站请求发出前 | 按主机标签边界匹配；空清单拒绝 |
| `fs.read / fs.write` | 文件路径入口 | 相对 Agent 根匹配；空清单拒绝 |
| `limits` | 装载期 | 超限整轮拒载，不运行时截断 |

`*.example.com` 命中裸域名与任意子域，不命中 `evil-example.com`。glob 中 `*` 不跨目录段，
`**` 跨任意段，`?` 匹配单字符；Agent 根本身只被 `**` 与 `.` 命中。含 `..` 的 glob 在
装载期拒绝。

`fs` 只约束 Agent 访问自己的目录及子树。用户工作目录由宿主工作区策略和审批守卫，
其他 Agent 目录不得由当前 manifest 授权。虚拟地址与物理绝对路径落在 Agent 目录内时
按同一规则处理。

shell 命令、MCP 服务器自身出站和模型 API 往返不属于 Agent `fs / network` glob 的直接
守卫范围。它们分别由命令策略、MCP 授权和模型选择控制，不能用参数串 glob 冒充完整安全。

权限四类字段必须作为同一装载契约生效。不得提交只执行其中一部分的中间态；确需豁免时，
必须明确哪些字段尚未执行、理由和清除期限。

## 5. 指令与记忆

两份文件语义和物理隔离，不得合并：

| | `AGENTS.md` | `MEMORY.md` |
|---|---|---|
| 语义 | 稳定指令与人格 | 动态记忆 |
| 写入 | 人维护，模型只读 | 人与模型可读写 |
| 层级 | 工作区、Agent 两级 | 会话、工作区、Agent 三层 |
| 组合 | 覆盖 | 叠加 |
| 注入 | 只读 | 注入并提供编辑地址与容量闸门 |

两者都必须是 UTF-8 纯文本。文件缺失或为空表示该层没有内容，不报错，也不注入占位文本。
清空通过写入空内容完成，不物理删除。

### 5.1 注入规则

宿主必须把内容原意注入系统提示词，不得改写。注入量和超限处理由宿主容量策略决定。

- 工作区指令存在且非空时，不再读取 Agent 级指令；否则回退到 Agent 级。
- 三层记忆分别注入、独立开关、互不覆盖。
- 指令不向模型提供编辑地址。
- 记忆应同时提供编辑地址和容量闸门。

### 5.2 唯一所有者

一个作用域只能有一个文件所有者。注入者、编辑地址提供者和容量闸门执行者必须是同一方。
系统 Agent 与每个子 Agent 各有独立作用域和文件，不得让两个所有者同时注入同一份内容。

所有者必须从自身实例所在目录推导作用域，不得通过重指其他插件的作用域共享文件。
工作区作用域也不能因装配子树而被改写到 Agent 目录。

## 6. 能力插件

能力插件格式由宿主既有系统定义。目录协议只要求插件可被通用容器识别，并交给对应
能力系统处理。

子 Agent 应当只装配认知能力插件，不挂载会话编排、模型网关和宿主基础设施。具体推荐
目录和默认清单属于宿主装配事实，不在本规范复制。

## 7. 装配语义

宿主必须用同一容器装配系统 Agent 和子 Agent。容器扫描一层目录，为每个能力插件构造
实例，并把插件自己的目录告知它。

会话绑定子 Agent 时，系统 Agent 与子 Agent 的能力取并集，不替换系统基础设施。并集必须
满足：

1. 提示词段带来源标记，同名段都保留；
2. 同名工具必须消歧，或拒绝加载并给出明确诊断；
3. 同类 VDFS 挂载点按来源分层；
4. 装配顺序不得成为语义，后注册覆盖不能作为消歧策略。

子 Agent 目录不能被父容器当作普通能力插件重复扫描。宿主可以惰性构造并缓存子 Agent，
但枚举、构造和绑定必须使用同一身份。

## 8. 版本接入

`spec` 是协议匹配基准，`version` 只是 Agent 自身版本信息。

1. Agent 用 `requires.spec` 声明协议主版本；
2. 宿主在加载期严格匹配主版本；
3. 不匹配必须拒绝，并同时报告双方版本；
4. 不得静默兼容或降级。

## 9. 安全约束

- 所有目录内路径必须防穿越，归档导入逐条目校验；
- 指令和技能可能进入提示词，宿主应明示 Agent 来源并提示不可信内容风险；
- 工具隔离和审计由对应能力插件策略负责；
- 权限与资源限额必须在装载或执行入口强制，不能只写在 manifest；
- 能力缺失可以软跳过，身份与协议错误不得软跳过。

## 10. 一致性要求

- 一个 Agent 一个目录，一个作用域一个所有者；
- 能力由目录承载，manifest 不重复登记；
- 系统与子 Agent 同构，能力取并集；
- 权限 fail-closed，限额超限整轮拒载；
- 指令只读、记忆可写，二者不合并；
- 版本严格匹配，未知字段前向兼容；
- 不把宿主实现清单、搬迁过程或测试记录写入目录协议。
