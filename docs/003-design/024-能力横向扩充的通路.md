# 能力横向扩充的通路

能力横向扩充有两条正交通路：**能力内部沿自己的声明与实现生长；需要被其它能力使用时，只共享
地址、词汇或纯机制，不建立插件间编译依赖。** 归属由生产消费关系决定，跨插件调用由容器路由，
公共制品由 owner 声明生成。本文规定这些通路的准入条件，不登记逐模块搬迁结果。

## 1. 编译期隔离与运行期互操作

插件 crate 之间没有编译依赖边。生产源码不 import 兄弟插件，清单不声明兄弟插件，也不经宿主
门面转发兄弟实现；开发依赖不构成例外。不得用 `include!`、`#[path]` 或共享源码目录绕过 crate
边界。

运行期互操作只走父容器：

```text
ctx.parent() → parent.route(ctx)
PluginFrame / PluginPayload 的 JSON 形状
```

地址来自生成常量，载荷只包含接收方声明并验证的 JSON 字段。调用方不得把兄弟插件的 Rust
类型、内部错误类型或私有存储句柄带过边界。零编译依赖不意味着零互操作，而是把互操作限制在
显式、可生成、可校验的协议上。

`E-009` 同时检查生产清单、源码引用、宿主门面使用和源码重定位。清单别名、包名替换与
workspace 继承都按解析后的依赖边判定。控制面插件可以直接依赖平台，但这项许可不改变任何
插件的生产清单白名单；来源前缀豁免也不豁免 manifest 边。

## 2. 地址与词汇由 owner 声明

跨插件地址、共享事件、工具命名空间、触发种类、授权行、装配信息和插件链接由各 owner
在自己的清单与声明中提供，生成到宿主或扩展门面。新增一项公共制品只改 owner 的声明与生成
输入，不手改共享宿主文件。

生成物只读、不手改。生成器与审计读取同一份事实源，避免“产物里有、判据说没有”。手工复制
一份生成结果不是共享定义；`SV-001` 禁止同一结构化名字在多个插件中各写一份字面量或常量。
名字进入公共词汇面的条件是存在实际跨插件消费，不是实现者单方面宣布它公共。

共享不等于上移到内核：

- 唯一生产消费方的实现跟随消费方。
- 跨插件共用的无状态机制进入 sdk；伴随它的封闭契约可以进入 contract。
- 封闭语法、全局量词守卫和协议语法留在机制层。
- 业务事实名与格位由 owner 声明，共享清单只是投影。
- 一个符号只有一个权威可写路径；具体归属由依赖、消费与生成事实体现。

## 3. 事件格位与环内载荷分离

`EventDecl` 与 `FactDecl` 回答不同问题，不能互相推导：

| 声明 | 回答的问题 | 主要内容 |
|---|---|---|
| `EventDecl` | 业务事实叫什么、落在哪个实体与动词格、谁可写 | 名字、格位、角色、宿主权限、事实主体 |
| `FactDecl` | 环内实例如何匹配、幂等、展开 | 名字、载荷字段、端口字段、键、展开字段 |

同一条事实可以同时出现在两张表中，但只有进入义务环的事实需要 `FactDecl`。`port` 是载荷
字段而不是信封字段；`key` 与 `expand` 引用的字段必须包含在 `fields` 中。空切片表示该维度
不存在，不表示留待以后补充。

声明通过 `Builder::declare(owner, declarations)` 提交，`Builder::seal(row_writes)` 统一冻结
并返回缺口。owner 在交表时给出，不在每条声明中重复。冻结后按事实与视图检查重名、载荷
字段引用、端口/键/展开字段以及声明资格。

业务格位不在内核另建第二张表。内核只拥有协议五格及语法。控制面的事实与视图由控制面
owner 声明，普通能力只声明自己确实消费或生产的格位。判据检查名字形状、owner、格位、
角色和真实引用，不靠业务名字白名单维持运转。

`CS-007` 要求共享清单中的每个名字除 owner 外至少有一个生产消费方，且不得同时留在内核业务
事件表。`CS-011` 要求四种 `FactRole` 各有生产居住者；删除角色声明不能使守卫静默失效。
角色表达事实在治理中的作用，不用角色名替代业务判断。

## 4. 视图是纯投影

视图求值只接收事实切片与时间戳，不获得写口、其它视图或自行读取时钟的能力。同一份日志在
相同 `now` 下重放必须得到相同结果。多片聚合由 `ViewDecl::agg` 完成，读方不另写一套聚合口径。

`reads` 声明实际读取的 `(事实, 字段)`，`evidence` 声明输出能够证明哪些事实收束。两者不能
混用：依赖图只按 `evidence` 展开出口，否则会把“帮助计算”误判为“负责关门”。

`ViewDecl.cost` 只约束义务环窗口求值；超界时该窗口没有可用结果。它不是跨插件历史读取的
上限，读侧仍按调用方提供的完整切片计算。视图不可用时只区分 `NotSealed` 与 `Unknown`，
不把窗口无结果伪装成未知视图。

视图读取只存在于事件断言格的名字时，seal 返回 `AssertionRead`。这既不是静默跳过，也不是
接受一个不存在于事实表中的名字；断言格可以证明状态，不能提供环内载荷。

## 5. 报表由 owner 登记与排版

公共读侧通过 `submit_reports!` 收集 owner 注册的 `ReportDecl`，读方遍历登记结果，不维护
第二张报表清单。每条声明提供 owner、全局唯一 `slot`、顺序、所读视图、可选实例级落点及
会话/实例/面板渲染函数。

登记在装载期返回 `ReportError`：空槽位、空视图、空名称、重复槽位、视图重复登记或空实例
落点都不能静默忽略。报表 owner 必须与所读视图 owner 对账；两个 owner 的标识形式可以不同，
对账按归一后的插件身份进行。

输出按 `(order, slot)` 稳定排序。同一份登记重复运行必须得到逐字节相同的结果。`render`
接收主体与读侧许可，自行决定空形状、截断和权限降级；读方不解释 owner 的业务形状。

报表出口是 JSON 契约；`slot` 一进 JSON 顶层就是对外形状，owner 不能随手改名。下表登记
顶层路径与实例级落点，`submit_reports!` 的登记必须与它逐行相等（SV-003 双向核对）；
视图内容与渲染形状仍由 `ReportDecl` 提供，不在文档复制第二份实现清单。

| `slot` | 顶层路径 | 实例级落点 |
|---|---|---|

## 6. 行为名与产出种类自报

工具行为通过 `ToolBehavior` 自报 owner、行为名和事实产出种类：

- `after` 产生 `FactDraft`，只有显式进入事件转换口才能成为事件。
- `before` 做纯 fail-closed 判断。
- `annotate` 只补全已有产品格。

宿主收集实现，不维护行为名到种类的中央映射。`expects_facts` 按声明种类判断，不运行期猜测。
行为名称属于 owner 词汇；需要跨插件消费时进入公共词汇投影，否则保持局部。

## 7. 准入与局部性判据

| 判据 | 通用规则 |
|---|---|
| `E-009` | 插件生产依赖闭包只含扩展门面、providers、独立 http 设施及不暴露宿主语义的第三方库；没有兄弟插件边、宿主转发或源码重定位 |
| `CS-007` | 共享业务事件有跨插件生产消费者，且不与内核业务表重复 |
| `CS-011` | 事件治理四类角色都有真实生产居住者 |
| `SV-001` | 公共词汇只有一个定义处，生成投影不视为手写副本 |
| `EX-002` | 新增能力包不得改动受保护机制树；已有生成路径不豁免新生成的公共面 |
| `EX-008` | 扩展 API 形状不得重新引入容器词汇或宿主语义 |
| `FA-001…004` | 扩展门面只保留契约与投影，其自有实现受只降棘轮约束 |

这些判据检查依赖、声明、生成与真实消费，不要求文档维护模块去向表或验证数字。新增能力
应优先改自己的清单、声明和实现；若必须改公共机制，先证明它由真实生产消费关系要求且
不含业务特例，再按既有边界安置。机制面净增不为正，局部性以代码与生成事实判定。
