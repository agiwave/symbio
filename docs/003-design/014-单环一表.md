### D-081 P4：驱动器不解存储、不把存储内部对象拿回家、构造只住在收敛手柄——批次 6 分 6a / 6b

[D-075](002-架构总览.md#d-075-卸载能力先于目录分离session-切分立三条前置会话记忆与存储留守 "DE-002-架构总览") 给驱动器切片留了一句前置——「它对存储的触点核到只剩 sink 与句柄」。逐条核对证明这句话 `PersistentChatSession` 本身就是存储域对象（会话引擎）， 拿到句柄与调用存储域构造器在代码里是同一件事；按字面执行只会得出一条永远满足不了的判据。

### D-082 6b：驱动器成片落为独立插件 loop——触发走地址面、服务走端口、词表先上移，分四刀

[D-081](014-单环一表.md#d-081-p4驱动器不解存储不把存储内部对象拿回家构造只住在收敛手柄批次-6-分-6a--6b "DE-014-单环一表") 把批次 6 分成了 6a（P4 收敛，已落地）与 6b（真切片）， 并把 6b 的判据钉成卸载形——停用 ⇒ 不再开新一轮、在飞的轮在有限时间内收敛、存储侧读写照常。 前置读数的实测结论：成片清单（驱动器片 ≈14,352 行 + resume 647 待裁）、出口两面（provider 臂与 收件箱消费者的两处 `start_turn`）、入边九组反向引用。

### D-086 loop↔session 切片契约：TurnDispatch 进程内交付、TurnSpec 纯值面、内部动作走地址面

[D-082](014-单环一表.md#d-082-6b驱动器成片落为独立插件-loop触发走地址面服务走端口词表先上移分四刀 "DE-014-单环一表") 裁决一/二/四把 6b-③ 的形状定成「驱动器独立成 `plugins/loop`、触发走地址面、服务走 core 机制词汇」，[D-083](001-核心架构.md#d-083-自上而下再推导废除服务端口进-core跨插件通货闭族在既有机制词汇切片补立前置-p5运行态归源 "DE-001-核心架构") 把跨墙通货闭族成四类、把判据改为「驱动器文件 import 根 ⊆ 闭族」， P5（运行态归源）与 P6（体系接口唯一化）已把运行态与存储实现请出机制层。

### D-088 环的指令集是闭集：Capsule 收成枚举，Step 五值与 drive 不成立

环认识的指令集必须是闭集。臂名（`decide` / `report` / `compress` / `recall` / `reflex`）是环与策略表之间的唯一接口，它由枚举承载，不是自由字符串。 DE-014 §3 的 `Step` 五值（`Ask` / `Act` / `Emit` / `Wait` / `Halt`）与 §4 的 `drive` 不动点迭代它们的每个变体缺生产者（§2），且阶段之间有数据 依赖（§3）。

### D-089 「一表」的准确表述：一个行形状 + 两个目录（按消费方分），删除 Policy 死变体

DE-014 §4 机制 2 的「一张表装策略行与能力行（同表异 kind）」，落地形状是： 一个行形状 + 两个目录。能力行在 core 的 `capability::Registry`（`CapabilityRow`）， 策略行在 loop 插件的 `loop_registry::Registry`（`Row`），两张表两个类型。

### D-093 策略表的「格」是数据也是类型：Site 闭集 + prio 格内唯一 + LoopState 按格分形

策略表（`plugins/loop/loop_registry`）加上「格」这个维度，四处同时落： `Site` 是闭集枚举（`TurnHead` / `RoundBoundary` / `Compress` / `TurnPrepare` / `Reflex`），与当初 `Capsule` 那条「加值必须改枚举」的纪律同源：加值必须改枚举， `name` 的 `match` 会编译错误。

### D-094 内部动作段注册化：行表即闭集——run_ops::ALL 删除，SessionPort 收成一个 call

`session/<sid>/_run/<op>` 内部动作段（[D-086](014-单环一表.md#d-086-loopsession-切片契约turndispatch-进程内交付turnspec-纯值面内部动作走地址面 "DE-014-单环一表") §4）从 「五处手写同步」改为「一张行表 + 一个泛化端口」，四处同时落： session 侧一张装配期冻结的行表 `RUN_OPS: &[RunOp]`，每行 = `(op 名, 处理函数)`。


### D-127 一次性阶段的「已做」必须是一条事实，不是私有簿记

`classify` / `recall` / `compress` 这类**一次性阶段**的谓词在行表里找不到「转假」的来源：
它们做完了就完了，没有「事实回退 ⇒ 重新欠」的路径。私有簿记被明令禁止（状态只能是事实），
于是只剩一条路：**新增一条「已做」事实**。落成的形状就是它——三段各落一格 `turn.stage`，
由它自己的执行体当场入日志，轮首派发点重读日志时才看得见关账
（[D-159](015-义务环.md "DE-015-义务环") / [D-162](015-义务环.md "DE-015-义务环")，判据侧的推理见 D-107）。
行表管的是**欠着的往返**，而一次性阶段"做完没有"由事实面回答。
