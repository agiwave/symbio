# 并发调度与租约

调度只消费事实派生的就绪视图。就绪是候选，不是已执行状态；租约是带期限的派发事实，
不能由读方凭墙钟自行关闭。

## 1. 就绪与容量

就绪集按依赖、资源、挂起与终态纯函数计算。有效容量从重放的 `session.config` 贡献
得出，并归一为至少一；容量不写进行常量，也不由调度器内存持有。

候选按确定顺序出队。同一写者使用单写者 FIFO；不同写者各自保序，跨写者顺序由稳定
任务身份与事实时间决定。重启后从事实重建队列，不继承进程内游标。

## 2. 租约事实

调度器独占 `task.assigned` 写入，载荷至少含 `task`、`assignee` 与 `until_ms`。授权由
`assign.work` 控制；执行者不能自行延长或改写租约。

租约到期时，调度器先落
`task.ready{reason: "lease_expired"}`，再允许重新分配。迟到的完成结果仍可审计，但不得
覆盖新 assignee 的工作；协议迟归按 attempt 与租约丢弃。

挂起是生命周期排除条件，没有时间语义。不能把 `until_ms` 塞进挂起状态，也不能让读方
通过修改投影完成判死。

## 3. 确定性与失败

调度输入是同一事实快照。时间取最新事实时间，不读墙钟；实际延迟通过更晚的事实进入
时间轴。缺配置容量时回退到至少一个执行位，不能形成零容量永久等待。

提供者缺席、租约缺失或执行行无法重认时，产生可见失败。失败后任务回到可解释的就绪、
挂起或终态，不保留只能由活进程识别的“正在执行”标记。

## 4. 并发层次

环机制允许同一圈存在多笔独立在飞债；实际同时派发多少由宿主装配容量控制；提供者
内部并发是第三层。三者不得互相冒充：机制能力不等于配置值，配置值也不扩大提供者
内部策略。

## 5. 能力阶梯赋值

```capability-assign
event.verb = held
actor.capability = assign.work
actor.budget_ms = 80
projection = readyset
```

## 6. 平凡值与回退

| 参数 | 平凡值 |
|---|---|
| `projection` | **readyset:cap=1** |
| `actor.capability` | `assign.work` |
| `actor.budget_ms` | `80` |

无配置贡献时有效容量至少一。阶梯 `held` 只登记能力坐标；实际派发、到期与重新就绪
分别由 `task.assigned` 与 `task.ready` 表达。
