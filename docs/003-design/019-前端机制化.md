# 前端机制化

> 前端只消费通用的树、形态、状态、主体和呈现数据，不认识轮、工具、压缩等业务概念。
> 协议形状归 [DE-005](005-协议规范.md)，会话地址与作用域归 [DE-012](012-会话输入与地址.md)，当前路由和结构事实归 [RE-006](../004-ref/006-当前事实表.md)。

## 1. 节点模型

会话消息统一为 `ChatNode`。节点身份是会话内稳定的 `id`，顺序由存储分配的 `seq` 决定，`timestamp` 只是业务时刻，不是排序键。

- `parent_id` 表达父子关系；没有父节点的节点是根。
- `content` 是完整正文；`delta` 是流式追加，只存在于出方向帧，不落存储，二者不得同帧出现。
- `status` 表达 `Pending`、`Streaming`、`WaitingUserAction`、`Completed`、`Aborted`、`Failed`、`Removed`。
- `title`、`icon`、`actions`、`stats` 是后端交出的呈现数据；前端照数据显示，不按业务词反推动作或读数。
- `meta` 只承载结构化业务载荷。新增顶层字段必须有前端或宿主读方的非 `meta` 消费理由，不能仅为少嵌套一层而扩面。

协议镜像以前后端逐字段对账为准；线格式变化必须同批更新 Rust schema、TypeScript schema 和协议审计。

## 2. 形态轴

`NodeKind` 是前端唯一形态分派轴，取值为：

```rust
pub enum NodeKind {
    Body,
    Notice,
    Skeleton,
    Interaction,
    Typing,
}
```

- `Body`：正文。
- `Notice`：系统提示、推理或其它说明性内容。
- `Skeleton`：正在执行或等待展开的组合骨架。
- `Interaction`：需要用户回答、审批或补参的交互。
- `Typing`：尚未收到真实子节点的本地占位。

形态注册表必须穷尽 `NodeKind`，漏一格在编译期失败。未知业务形态先折到通用形态，不在前端新增业务分支。

`style_tag` 只是后端业务注记，供后端判据和模型重建使用；它不是前端分派轴。同格业务差异由 `title`、`icon`、`actions`、`stats` 等数据表达，不在前端建立业务名字到组件的映射表。

## 3. 主体轴

`principal` 是身份唯一权威，结构为 `{ kind, id, title? }`；主体种类为 `person`、`agent`、`tool`、`system`。

- 生产写方必须写 `principal`，不能只写旧角色字段。
- 身份、可见域、署名和恢复动作的归属都读同一主体。
- 存量反序列化和读边界可以折叠旧形状，但旧字段不再序列化；兼容只发生在边界，不形成第二套身份协议。
- 主体地址与 `NodeKind` 正交：工具可以是骨架或正文，用户可以发起交互，系统可以发说明。

## 4. 结构与递归

结构轴与形态轴分离：

1. 分派器按 `NodeKind` 选择渲染器。
2. 分派器按实际子节点是否存在决定是否提供 `subtree` 插槽。
3. 子流经 `subtree` 交渲染器；渲染器决定放在折叠体内、折叠体外或不展示。
4. 空子流不提供插槽，避免容器被误判为有后代。

“有子就递归”是唯一结构判据，不能写成“骨架才递归”。任何形态都可以拥有后代，折叠只影响本节点内容的展示，不吞掉后代。

建树与组合策略由后端声明和事实决定，前端不假设一轮只有一个根、工具结果固定挂在何处，或某种业务形态必然是容器。

## 5. 状态与流式更新

状态由后端事实和全量节点视图驱动，不按事件到达顺序猜测。

- 节点补丁按稳定 `id` 合并；`content` 替换，`delta` 追加。
- 外部工具调用的原始标识不直接替代会话节点身份；节点 id 在诞生时唯一分配。
- `Typing` 是本地占位：父节点仍在流式且没有真实子节点时显示；同父真实子节点到达后即让位。
- `Removed` 表示节点退出当前视图，不把占位或释放的骨架当作真实业务结果。
- 失败原因随节点持久化，切换会话后仍能显示；恢复动作只执行后端下发的动作。`retry_subtree` 的靶子按父子结构解析到用户轮锚，前端不按类型补造动作，也不把旧式骨架 id 直接交给后端。

## 6. 骨架惰性展开

大型子树可以只交骨架和摘要，正文后代按需展开。

- 骨架声明当前摘要、后代类型分布和运行状态。
- 展开是显式 VDFS 动作；请求只针对该骨架，不重放整个会话。
- 释放摘要时保存子树统计；重取失败保留原摘要，不伪造“没有内容”。
- 重取语义与释放语义同源，深度和范围一致；前端只消费宿主动作和节点形状。
- 后端返回真实后代后，前端按节点 id 合并，不改变原有父子关系。

## 7. 路由与契约生成

路由常量和协议镜像由唯一注册处生成，前端不手写第二份地址表。

- 生成物是完整契约面；当前未使用不等于可删除。
- R-003 对生成文件的未用导出作文件头承认，未使用项仍保留。
- 路由新增或改名必须从后端注册处重生成，并同批验证可达性。
- 生成物不得手改；幽灵地址和漂移必须失败。

## 8. 呈现边界

- 组件只认 `NodeKind`、`principal`、`status` 和通用呈现字段。
- 图标词只查前端资产表，不按业务名生成组件。
- 动作列表是数据渲染，不由工具名或压缩等业务词反推。
- 读数由后端排成通用标签值行，前端不读取业务数字自行拼句。
- 交互输入、恢复请求和错误展示沿用同一节点协议，不建立业务专属弹层协议。
- 可访问名称、替代文本和键盘可达性由通用 UX 判据守，见 [DE-020](020-前端UI-UX.md)。

## 9. 判据

- 协议镜像审计守 Rust / TypeScript 字段、枚举和线格式一致。
- 前端注册表以穷尽映射守 `NodeKind` 全覆盖。
- 源码审不得按业务形态名分支，不得让 `style_tag` 成为第二分派轴。
- R-003 守生成路由常量的完整契约面。
- 状态与递归测试必须覆盖真实子到达、空槽、深度展开、失败重取和会话切换。
- 路由结构事实以 [RE-006](../004-ref/006-当前事实表.md) 为准，不在本文维护数量或逐条清单。
