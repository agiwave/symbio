# 最小闭环

## 内容

前置：无 ｜ **新增机制键 6** ｜ 参数变化 6
## 1. 场景：要什么能力

用户说一句话，系统回一句。**这是全部高阶能力的地面**——后面 12 阶都不是替代它，而是往它上面加。

这一阶的难点不在"接个大模型"，而在**闭环的四个端点必须同时成立**：

| 端点 | 要求 | 缺了会怎样 |
|---|---|---|
| 收到 | 用户消息成为一条事件 | 后面所有溯源无从谈起 |
| 思考 | 有一次生成动作 | 只是 echo |
| 发出 | 发言只有一条 final | 用户对同一句话收到两次回复 |
| 兜底 | 生成失败也要有输出 | 对话静默中断——**这是最常被漏掉的** |

## 2. 为什么它能落在 v2 上（J1）

四个端点全部是已有参数取值，不需要任何新类型：

- 收到 = `event.entity = scope` × `event.verb = opened`
- 思考 = `actor.pattern = reasoner`
- 发出 = `event.verb = closed` + `actor.capability = reply`
- 兜底 = `chat.assistant.fallback` 事件（网格里已有的一格，**不是特殊通道**）

**关键设计**：兜底话术也是一条普通事件。所以它可被 I2 审计（谁产生的）、可被元认知统计（兜底率多少）。
如果兜底走的是例外分支，它就永远逃出审计——这正是"静默失效"的典型形态。

## 3. 增量清单（只加数据）

| 类型 | 内容 |
|---|---|
| 事件格子 | `scope/opened`（`user.message`）、`scope/closed`（`chat.assistant.final`、`chat.assistant.fallback`） |
| ActorSpec 行 | `{ principal: "session/main", pattern: reasoner, capabilities: [Reply], budget_ms: 300, scope: root }`——`budget_ms` 是**档位**的取值（`fast` = 300ms），不是行里另写的常量（[D-328](031-最小闭环.md "DE-031-最小闭环")） |
| grants 行 | `session/main` ▸ `reply` 写 |
| 投影参数 | `projection = snapshot`（≤1.5k tokens 是 `Budget` / 压缩阈值给的，不是名字自带） |

**本阶点亮的机制键**（阶梯总表的「新增机制键」由这张块算出；`scripts/gens/gen-verify-facts.mjs` 从这里取输入）：

```capability-assign
event.entity = scope
event.verb = closed
actor.pattern = reasoner
actor.capability = reply
actor.budget_ms = 300
projection = snapshot
```

## 4. 平凡值与回退（J2）

| 参数 | 完整值 | **平凡值** | 平凡值下系统是否完整运行 |
|---|---|---|---|
| `actor.pattern` | `reasoner` | **`decider`** | 是——规则应答仍产生 final，对话不中断 |
| `actor.budget_ms` | `300` | `60000` | 是——只是慢 |
| `projection` | `snapshot` | `turnstate` | 是——只看当前 turn |

**这一阶的平凡值是整个阶梯的地基**：把 `pattern` 退回 `decider`，系统退化成"规则应答机器人"，
但它**仍然是一个能完成对话的系统**。后面每一阶都要能退回这一阶。

## 5. 静默失效与强制（J3）

| 约束 | 违反时有无错误信号 | 强制方式 |
|---|---|---|
| 每 turn ≤ 1 条 final | **无**——用户只是收到两条回复 | 义务环的债表：一笔模型债一次派发只收一条响应（配对归环，SDK 不按轮号另判） |
| 兜底必须产生事件 | **无**——超时后什么都没发生 | I3 断言：无事件且无 fallback = 违例 |
| 回复必须有 `produced_by` | **无** | I2 断言（`invariants.rs` 的 `I2NoProvenance`） |

三条全是"违反时没有测试会失败"的类型，所以必须第零天就做成 CI 断言。

## 6. 验收断言

1. 一条 `user.message` → 恰好一条 `turn/closed` 事件（`assert_eq!(finals, 1)`）。
2. 强制生成失败 → 必须存在 `chat.assistant.fallback`，且它的 `produced_by` 非空。
3. 投影两次运行结果逐字节相同（确定性）。
4. **配对**：每轮的作答由义务环按债务键配对（同一键一次派发只收一条响应），不按轮号另判。

**§6 验收断言的执行方**：1 = `one_user_message_yields_exactly_one_final`（`actors/mod.test.rs`）+ e2e `helpers.mjs:727 assertTranscriptInvariants`（t1/t4 普遍引用）；2 = `forced_failure_produces_fallback_with_provenance`（同文件）+ e2e t5/t7；3 = 同文件的双跑逐字节用例 + `docs/003-design/verify/projection_purity.rs`（gate 55）；4 = 义务环的债表（`ring/engine.rs` 的 `closing` / `expire`；`engine.test.rs::an_unpaired_request_is_closed_by_lease_not_left_pending`）——按轮配对归环，SDK 不再另判。

## 9. 关键决策

### D-328 本阶两个取值以实现为准——`snapshot` 的承接方在会话侧，预算值只来自档位

本阶 §3 的 `capability-assign` 块有两处取值与下文对不上，处置不同：**找错地方的改账，阶段值不冒充实例值**。

**投影：`snapshot` 有承接方，只是不在 core。** `symbio_sdk/projection/` 里没有 `snapshot.rs`，
旧账因此写成「不存在此名」——那是**只翻了 core 一层**。它的实现住能力包：
`crates/symbio-plugin-compact/src/port.rs::snapshot`（分层压缩：把历史压成快照，落
`session.consolidated` 的折叠叶）；core 的 `transcript.rs` 是逐条读视图（`turnstate` 已随
`TurnState` 退役，`D-317`），分工在 [RE-009](../004-ref/009-投影映射.md "RE-009-投影映射") 的
两张表里已登记（`snapshot` 那行形态就是「会话侧」）。`≤1.5k tokens` 也不是名字自带的语义，而是 `Budget` / 压缩阈值给的
——**旧账把「不是 core 投影」误记成了「没有实现」，本条把它改回来**。
取值域因此一个不动（[DE-001 §8](001-核心架构.md "DE-001-核心架构") 的 `snapshot` 保留），
键集与机制数也一个不动。

**预算：`300` 是 `fast` 档，不是写死的行常量。** 四档是
`LatencyTier`（80 / 300 / 60000 / 86400000），本阶声明的是 `fast`（300ms，
「只许分类、不许生成」那一层——无工具的最快应答）。生产里 `session/main` 的轮会吃工具往返，
实际预算取 `deep`（60000）。两处不是矛盾：**阶段声明「这一阶要求多快」，实例取「这个
会话需要多快」**，行里不另写一份常量。

[D-223 订正 2](022-行表与派发面.md "DE-022-行表与派发面") 之后，这两句话各归其位：
`actor.budget_ms` 是主体的**声明档**（由 `pattern` 派生——`reasoner` ⇒ `deep`），
**本幕实际花多久**归 `turn.dispatch.budget_ms`（由档位直接折出）。旧账把 `300` 写成
「未落地」，是把「阶段值 ≠ 生产实例值」误记成了缺口——本条把它记清，并禁止再往行里写裸数字。

**买断的是什么**：只钉死「取值必须有真承接方（本体在哪一层不重要，名字不能被误判成假）」
与「预算值只有档位一个来源」。它**不**决定 `snapshot` 的截断策略（各调用点的 `Budget` 决定），
也**不**把 `display`（[DE-032 §3.2](032-工具调用与产物.md "DE-032-工具调用与产物") 已裁为节点重建）拉进投影集。

### D-329 无事实源的会话驻留退场：只剩磁盘一种驻留

- **问题。** 会话层留着一族「临时会话」构造：存储的临时构造器、引擎的临时 / 分离构造器，
  以及它们背后的内存驻留脚手架（内存条目表、可空的落盘根、每条读写口的「有没有磁盘」分支）。
  按形状它是一项能力——「不落盘的会话」。
- **依据。** 事实源是唯一真相（D-318 / D-324）。临时会话的 `fact_source`
  恒为 `None`，它既读不到历史、也落不进任何格；而它**唯一的生产构造方**（`open_session_handle`）
  已随旧编排删除（D-318 B2），新环里没有任何合法构造点。一个永远跑不起来的会话壳不是能力，
  是**旧形状的残骸**：留着它，每个读口都要背一条永远不会走的分支。
- **裁决。** 删除三处构造器：存储的 `ephemeral`、引擎的 `ephemeral` 与 `detached`。
  `detached` **没有独立语义**——它只是同一件事换了个配置传入方式（配置以值快照传入），
  不是只读视图、不是第二种驻留，因此与 `ephemeral` 一并删除，不分开处置。
- **连带收口（不留不可达分支）。** 删构造器还不够：内存驻留脚手架仍在，等价于把空壳挪进
  不可达分支。故此批同时收掉——
  1. 存储的内存条目表与可空落盘根：落盘根改为非可选，读写 / 删 / 清单 / 迁移 / 事实源读
     不再有「没有磁盘」早退；「目录不存在」仍按 `None`（那是缺目录，不是缺事实源）；
  2. 引擎的 `prune_on_write` 开关：删掉临时会话后它恒为真，保留就是一条永远为真的条件；
  3. 相关注释与模块文档里「临时会话豁免 / 跳过」的说法。
- **配套登记。** 任务文档 §二 的 `store/` 行写明
  「无事实源的驻留方式已退役（D-329）」，不再承诺一个不存在的能力。
- **判据（不许悄悄长回来）。** 未来若需要非磁盘会话，那是**一项新能力**：须立新决策，
  同时给出事实源（或明确它为何不需要）、写点与消费者。不得以「加一个构造器 / 把一个字段
  改成 `Option` / 复活旧名字」的方式回来——退役的名字与形状都不许悄悄复活。

### D-330 会话级告警退场：永不被构造的状态变体不是能力

- **问题。** 会话收敛枚举里留着一个告警变体，运行态里留着一个告警字段，会话节点属性里有
  一个告警格，前端还有一张按会话索引的告警表——四样合起来声称「会话有一个可恢复的告警态」。
- **依据。** 它的**唯一写方**（旧转写的告警出口）已随旧编排退场，048 / 051 里没有任何
  告警写点。于是这个变体永远不被构造、这个字段永远不被写入、这个属性永远为空、前端那张表
  永远读不到值。按判据——**一个永不被构造的状态变体不是能力**，它只是读侧为旧形状背的书。
- **裁决。** 删除告警变体本身，并连同读侧一起清掉：运行态的告警字段与其写方法、节点属性里的
  告警格、前端的状态表与解析字段、测试里的告警用例。只删写方而留读侧，等于把「读一个永不
  被写的状态」固化下来。
- **与 D-083 的关系。** 那条决策论证的是「告警不落事实格、由宿主局部持有」——在**写点缺席**
  的前提下，这份论证不构成一项能力。那里只加**退场注记**（指向本条），原文不改：它记的是当时
  的裁决理由，不是现行承诺。
- **判据（重新引入须按新能力设计）。** 告警语义若再要，必须**写点 + 事实（或明确的宿主局部
  持有论证）+ 消费者一起**设计，并立新决策。不得靠白名单、空变体、只读字段或「先把读侧
  接上、写点以后再说」悄悄长回来——本条的退役范围就是判据，复活越过它即红。
