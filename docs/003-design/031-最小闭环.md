# 最小闭环

## 内容

前置：无 ｜ **新增机制键 6** ｜ 参数变化 6 ｜ 阶段一

## 1. 场景：要什么能力

用户说一句话，系统回一句。**这是全部高阶能力的地面**——后面 12 阶都不是替代它，而是往它上面加。

这一阶的难点不在"接个大模型"，而在**闭环的四个端点必须同时成立**：

| 端点 | 要求 | 缺了会怎样 |
|---|---|---|
| 收到 | 用户消息成为一条事件 | 后面所有溯源无从谈起 |
| 思考 | 有一次生成动作 | 只是 echo |
| 发出 | 发言只有一条 final | 用户对同一句话收到两次回复 |
| 兜底 | 生成失败也要有输出 | 对话静默中断——**这是最常被漏掉的** |

## 2. 为什么它能落在 v2 上（J1）

四个端点全部是已有参数取值，不需要任何新类型：

- 收到 = `event.entity = turn` × `event.verb = opened`
- 思考 = `actor.pattern = reasoner`
- 发出 = `event.verb = closed` + `actor.capability = reply`
- 兜底 = `chat.assistant.fallback` 事件（网格里已有的一格，**不是特殊通道**）

**关键设计**：兜底话术也是一条普通事件。所以它可被 I2 审计（谁产生的）、可被元认知统计（兜底率多少）。
如果兜底走的是例外分支，它就永远逃出审计——这正是"静默失效"的典型形态。

## 3. 增量清单（只加数据）

| 类型 | 内容 |
|---|---|
| 事件格子 | `turn/opened`（`user.message`）、`turn/closed`（`chat.assistant.final`、`chat.assistant.fallback`） |
| ActorSpec 行 | `{ principal: "session/main", pattern: reasoner, capabilities: [Reply], budget_ms: 300, scope: root }`——`budget_ms` 是**档位**的取值（`fast` = 300ms），不是行里另写的常量（[D-137](031-最小闭环.md "DE-031-最小闭环")） |
| grants 行 | `session/main` ▸ `reply` 写 |
| 投影参数 | `projection = snapshot`（≤1.5k tokens 是 `Budget` / 压缩阈值给的，不是名字自带） |

**本阶点亮的机制键**（阶梯总表的「新增机制键」由这张块算出；`scripts/gen-verify-facts.mjs` 从这里取输入）：

```capability-assign
event.entity = turn
event.verb = closed
actor.pattern = reasoner
actor.capability = reply
actor.budget_ms = 300
projection = snapshot
```

## 4. 平凡值与回退（J2）

| 参数 | 完整值 | **平凡值** | 平凡值下系统是否完整运行 |
|---|---|---|---|
| `actor.pattern` | `reasoner` | **`decider`** | 是——规则应答仍产生 final，对话不中断 |
| `actor.budget_ms` | `300` | `60000` | 是——只是慢 |
| `projection` | `snapshot` | `turnstate` | 是——只看当前 turn |

**这一阶的平凡值是整个阶梯的地基**：把 `pattern` 退回 `decider`，系统退化成"规则应答机器人"，
但它**仍然是一个能完成对话的系统**。后面每一阶都要能退回这一阶。

## 5. 静默失效与强制（J3）

| 约束 | 违反时有无错误信号 | 强制方式 |
|---|---|---|
| 每 turn ≤ 1 条 final | **无**——用户只是收到两条回复 | CI 断言（`invariants.rs` 的 `I1DoubleFinal`） |
| 兜底必须产生事件 | **无**——超时后什么都没发生 | I3 断言：无事件且无 fallback = 违例 |
| 回复必须有 `produced_by` | **无** | I2 断言（`invariants.rs` 的 `I2NoProvenance`） |

三条全是"违反时没有测试会失败"的类型，所以必须第零天就做成 CI 断言。

## 6. 验收断言

1. 一条 `user.message` → 恰好一条 `turn/closed` 事件（`assert_eq!(finals, 1)`）。
2. 强制生成失败 → 必须存在 `chat.assistant.fallback`，且它的 `produced_by` 非空。
3. 投影两次运行结果逐字节相同（确定性）。
4. **反向用例**：注入两条 final → 断言 1 必须失败。

**§6 验收断言的执行方**：1 = `one_user_message_yields_exactly_one_final`（`symbio_core/actors/mod.test.rs:217`）；2 = `forced_failure_produces_fallback_with_provenance`（同文件 `:236`）；3 = `turnstate_projection_is_deterministic`（同文件 `:258`，N1 双跑逐字节）；4 = `two_finals_are_caught_by_n3`（同文件 `:274`）+ `two_finals_in_one_turn_is_detected`（`symbio_core/invariants/mod.test.rs:84`）。

## 8. 这一阶做不了什么

边界的唯一账本：[SC-001-最小闭环](../002-scene/001-最小闭环.md "SC-001-最小闭环")（用户语言）。机制面独有边界（用户可见范围之外的工程约束）：

## 9. 关键决策

### D-137 本阶两个取值以实现为准——`snapshot` 的承接方在会话侧，预算值只来自档位

本阶 §3 的 `capability-assign` 块有两处取值与下文对不上，处置不同：**找错地方的改账，阶段值不冒充实例值**。

**投影：`snapshot` 有承接方，只是不在 core。** `symbio_core/projection/` 里没有 `snapshot.rs`，
旧账因此写成「不存在此名」——那是**只翻了 core 一层**。它的实现住会话侧：
`crates/symbio-plugin-loop/src/context/pipeline.rs`（分层压缩：把历史压成快照）+ `conversation_view.rs`
（从同一份存储里切出对话线）；core 的 `transcript.rs` 是逐条读视图、`turnstate.rs` 是轮次水位，
三者分工在 [RE-009](../004-ref/009-投影映射.md "RE-009-投影映射") 的两张表里已登记（`snapshot` 那行
形态就是「会话侧」）。`≤1.5k tokens` 也不是名字自带的语义，而是 `Budget` / 压缩阈值给的
——**旧账把「不是 core 投影」误记成了「没有实现」，本条把它改回来**。
取值域因此一个不动（[DE-001 §8](001-核心架构.md "DE-001-核心架构") 的 `snapshot` 保留），
键集与机制数也一个不动。

**预算：`300` 是 `fast` 档，不是写死的行常量。** 四档是
`LatencyTier`（80 / 300 / 60000 / 86400000），本阶声明的是 `fast`（300ms，
「只许分类、不许生成」那一层——无工具的最快应答）。生产里 `session/main` 的轮会吃工具往返，
实际预算取 `deep`（60000）。两处不是矛盾：**阶段声明「这一阶要求多快」，实例取「这个
会话需要多快」**，行里不另写一份常量。

[D-223 订正 2](022-行表与派发面.md "DE-022-行表与派发面") 之后，这两句话各归其位：
`actor.budget_ms` 是主体的**声明档**（由 `pattern` 派生——`reasoner` ⇒ `deep`），
**本幕实际花多久**归 `turn.dispatch.budget_ms`（由档位直接折出）。旧账把 `300` 写成
「未落地」，是把「阶段值 ≠ 生产实例值」误记成了缺口——本条把它记清，并禁止再往行里写裸数字。

**买断的是什么**：只钉死「取值必须有真承接方（本体在哪一层不重要，名字不能被误判成假）」
与「预算值只有档位一个来源」。它**不**决定 `snapshot` 的截断策略（各调用点的 `Budget` 决定），
也**不**把 `display`（[DE-032 §3.2](032-工具调用与产物.md "DE-032-工具调用与产物") 已裁为节点重建）拉进投影集。
