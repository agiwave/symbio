# 横向扩充与插件切分

> 三个行表（能力目录 / 策略目录 / 动作目录）承担了横向扩充的接入面，接入成本已经很低。
> 剩下的摩擦不在"再加一层抽象"，而在三处**直线代码**：主循环的固定七步、臂的分派、
> 三个巨型函数。本方案只做这三处，不新增机制键、不新增 trait、不新增插件。

## §0 结论先行

1. **加一条策略 = 一条声明 + 一个执行体**（`loop_rows.rs` 的 `ROWS` 一行 `Decl` +
 `ACTORS` 一项绑定），core 零改动。一次性阶段目前还各有一个调用点，那正是旁路收编
 （DE-090 §3）要收掉的第二套调度；收编后新增策略只剩表内两处。
2. **加一个新时机（格）= 3 处 + 1 个调用点**，仍全部在 `plugins/loop` 内，core 零改动。
 成本高的原因不是"缺机制"，是主循环是**固定七步**、格必须提前声明。
3. **加一个执行体 = 表内一处**（`ACTORS` 一项 `ActorEntry`）。本方案原先要修的第一处——
 「调用点各比较一次臂、漏掉一处则那条臂永不派发」——已随 `Capsule` 退场：行没有执行体就
 恒 `blocked`，未登记的事实名在装载期判红（§4.2）。
4. **拆分已到插件级的尽头**：`loop` 已是独立插件（无 `route` 臂、无能力行、无常驻任务、
 只 1 条 Mount 行），再切没有判据可用。剩下的只能走**模块级 / 函数级**。
5. 方案两步：**A 驱动器**（把格与臂分派收进一个不动点循环）、**B 阶段拆分**（三个巨型
 函数按处理阶段拆，不按职责拆）。B 可独立开工，A 必须先做完投影收口。

## §1 现行形状：一轮怎么走

### 1.1 四层

| 层 | 落点 | 职责 |
|---|---|---|
| ① 装配 | `session/orchestrator/entry.rs` | 收件箱取批 → 落用户消息 → 装配 `chat_ctx` / `TurnDispatch` → 派发 `loop/<sid>` |
| ② 宿主 | `loop/provider.rs` | 取 `TURN_DISPATCH`（授权三条）→ 建 `LoopSession` → await ③ → 回 `TurnReport` |
| ③ 循环 | `loop/chat_loop.rs` + `chat_loop/{inputs,turn,compose}` + `head_exec.rs` | 前步骤 + **固定七步**（轮首派发点在这里）+ 唯一收尾 `finish_turn` |
| ④ 单轮执行 | `loop/turn_exec.rs` → `turn_runner.rs` → `tools/tool_executor.rs` | LLM 调用 + 工具轮 + 工具批处理 |

循环只能由 `return finish_turn(...)` 离开。四层结构、四个收口点的完整说明见
[DE-102-core-loop](../../symbio/src/plugins/session/docs/102-core-loop.md "DE-102-core-loop")。

### 1.2 三个行表（形状一份，目录三份）

| 目录 | 位置 | 行形状 | 裁决规则 | 消费方 |
|---|---|---|---|---|
| 能力目录 | `symbio_core::capability` | `{name, payload}`，六族 | `put` / `get` / `list(kind)` | ≥2（模型工具列表、VDFS、设置页、统计） |
| 策略目录 | `plugins/loop/loop_rows.rs` | `Decl { owes, until, unless, by, prio, tier, expand }` | `(prio, name, key)` 全序，先命中者胜 | 1（环） |
| 动作目录 | `plugins/session/plugin/run_actions.rs` | `{op, 处理函数}` | 表内即闭集，装配期冻结 | 2（loop 派发、授权判据） |

三张表**不共类型**，但共一条形状纪律：一行 = 一个纯判据或一个处理函数 + 一份声明数据，
表本身不写分支。这条纪律的两次独立实例化见 [D-089](014-单环一表.md "DE-014-单环一表")
（按消费方分目录）与 [D-094](014-单环一表.md "DE-014-单环一表")（闭集即行表）。

> D-088 / D-089 / D-093 / D-094 的锚点保留在已退场的 [DE-014-单环一表](014-单环一表.md "DE-014-单环一表")，
> 它们仍然约束现行代码；目标形状以 [DE-001 §4.3](001-核心架构.md "DE-001-核心架构") 与
> [DE-015-义务环](015-义务环.md "DE-015-义务环") 为准。

### 1.3 一条事实轨

`State` 是 Store 的投影，`append` 是唯一交换点。策略行的判据读的是**投影**，不是环的私有
字段——这是"策略可以纯、可以回放"的前提（[DE-001 §4.3](001-核心架构.md "DE-001-核心架构") 的「一源」）。

### 1.4 一个问表点

一轮里的债由派发器问表：三台 host 各有一个派发调用点——轮首 `head_exec::drive_head`、
轮内 `turn_exec::drive_steps`、批次边界 `report_exec::drive_report`，它们把"这一轮此刻欠什么"
整个交给 `ring::drive`：取本 host 绑定表里按 `(prio, name, key)` 全序最小的一笔可还债，
按 `by` 查出执行体跑掉。**调用点不按名点问"这一行欠不欠"，也不按臂分支**——派发前那一次
问表收敛在引擎的现读点 `Dispatch::row_owed`（[D-136](022-行表与派发面.md "DE-022-行表与派发面")）。

表外**没有**按行名点问的调用点了：快路那一处也接回了轮首 host（[D-163](015-义务环.md "DE-015-义务环")）。
判定（`policy.reflex` 的 `owes`）由 `drive_head` 问一次，执行体当场落出口格
（`stage:"reflex"`）并把正文寄进本轮状态；轮内只消费「已选中」这件事——正文随
`ExecTurn::reflex` 进来，档位由那条行的 `tier` 给出，不再取切片问表。这正是
[DE-090](090-过渡方案.md "DE-090-过渡方案") §3 的**调度旁路读数归零**那一格。
批次边界那一台把 `policy.report` 接了回来（[D-163](015-义务环.md "DE-015-义务环")）：静默 / 配额 / 工具轮数
三条判据全在 `report_due` v4 的 `due` 里，调用点只剩「跑完了一批工具」这个时刻。

另有三处 `tool_dispatch.rs` 的**幂等点问**：执行体动手前复核"本行还欠不欠"，不选行、
不排行，是并发 / 重放下的护栏，与上面两处不同类（DE-090 §3 的第二个计数，归零不是目标）。

## §2 横向扩充的现状账

判据只有一条：**加一样东西要改几处，其中几处在 core，漏改时谁会红。**

| 扩充对象 | 落点 | 改几处 | 其中 core | 漏改时谁红 |
|---|---|---|---|---|
| 一个 LLM 工具 | 实现 `Capability` + `traverse` 收集 | 1 个文件 | 0 | 模型看不见它（e2e 兜） |
| 一个模型服务 / 提示词 / 挂载 / 选项 / 可配置 | 行上 `put` | 1 处 | 0 | 消费方读不到（各自用例） |
| 一个插件 | 目录 + `PLUGIN.yml` + `ASSEMBLY_SUB_AGENT_PLUGINS` 一行 | 3 处 | 0（不涨 CS-001 三格） | 不在名册 ⇒ 不装配 |
| **一条策略** | `loop_rows.rs`：一行 `Decl` + `ACTORS` 一项绑定 | **2 处** | **0** | 行无执行体 ⇒ 恒 `blocked`；装载检查对未登记的事实名判红 |
| **一条新时机** | 一个 `owes` 模式 + 写它的生产者 + 消费它的出口格 | **3 处** + 1 调用点 | **0** | 装载期「每个控制面事实名都有归宿」；调用点仍要接（D-107 的 A2/A3） |
| **一个执行体** | `ACTORS` 一项 `ActorEntry`（`decl` + `run`）+ 写入面声明 | **1 处** | **0** | 装载期 `writes_closed` 封闭写入面，未声明的写入判红（§4.2） |
| 一个 loop→session 动作 | core 纯值常量 · `RUN_OPS` 行 · 处理函数 | **3 处** | 1（`&'static str`） | 漏行 ⇒ 授权 `Forbidden` |
| 一个新能力族（第七族） | core 两个 enum 各加一个变体 + 生产点 | 3 处 | 3 | 无生产点 ⇒ 决策门 |
| 一个新 `Verb` / `ActorSpec` 字段 / 参数键 | 封闭集 | —— | —— | 编译错误 / 决策门 |

三格读数不手写：以 `node scripts/core-shape-audit.mjs` 的 CS-001 输出为准（只降不升，放宽须挂决策）。

**这张表说明两件事**：

- **core 已经不是瓶颈**。九行里只有一行真正改 core，而且改的是一个字符串常量；其余
 全部落在插件内。所谓"必须改 `symbio_core` 才能扩充"在今天是**不成立**的。
- **瓶颈是"格"和"臂"两处**，都因为主循环是固定七步：格要提前声明、臂要在调用点分派。

## §3 三条已裁决的边界（不再讨论）

| 裁决 | 内容 | 违反要付什么 |
|---|---|---|
| [D-089](014-单环一表.md "DE-014-单环一表") | 策略行**不**进 core 能力表；它那一档的 kind 变体已删除（不设第二份行形状）。"一表"读作"一个行形状 + 两个目录" | 合表要么把**本轮的债视图**写进 core（控制面细节进机制层），要么泛型传染；单消费方占公共面违反 C-003 |
| [D-093](014-单环一表.md "DE-014-单环一表") | 行自带完整判据，跨行竞争由 `prio` 全局定序（历史上的 `Site` 闭集 + `LoopState` 按格分形已随 A0 退场，原则不变） | 没有独立判据的行只能靠代码位置隐含时机；行读本行判据之外的状态会静默按假值判定 |
| [D-094](014-单环一表.md "DE-014-单环一表") | 动作面**行表即闭集**，`ALL` 由表派生 | 手写第二份清单 ⇒ "在表内"与"有臂"分居两地，漏一份是静默的授权缺口 |

这三条共同定义了本方案的活动空间：**不再往 core 加行族、不再靠全局编号排顺序、
不再手写第二份清单。**

## §4 三处真摩擦

### 4.1 时机已是判据，派发点的位置仍是代码

加一格要改 3 处 + 1 个调用点（§2 第 5 行）。这不是"少写了个注册口"：行已自己回答
"现在该不该做"——`owes` / `until` / `unless` 三段时间条件读的全是事实，判决那一行写的
是 `round = 0 ∧ 有发言 ∧ 开关开着 ∧ 本幕没落过 decide 格`。由**代码位置**承载的只剩一件事：
**这台 host 的派发点坐在七步的哪一格**。

```text
轮首 drive_head（准备段 ①② 之后、水位与流式骨架之前）→ 轮首子集最小的一笔债
   classify 10 → compress 30 → recall 40
轮内 drive_steps（开轮块的不动点循环）→ 轮内子集最小的一笔债
   authorize-tool 0 → … → close-turn 55 → execute 60 → dispatch-* 65…69 → lease 80
```

于是：

- 加时机 = 改行的 `owes` 模式 **+ 选它住哪台 host**（`by` 落进哪张绑定表就住哪台，
  派发点读的那一行子集随之变），时机再没有第三种写法；
- 拆一行 = 给拆出来的每行一个自己的出口格。同一位置上两件可竞争的事（"记忆召回"
  与"技能路由"）合在一行，是因为三段产物寄存进本轮状态由编排层一次取用，
  而它们的判据**完全同形**——拆成三行只多三个出口格与三份寄存，判据不会更宽。

`policy.recall` 至今是一行带三件事，这是它的**结构性**原因，不是偷懒。

### 4.2 执行体的分派：绑定表 + 写入面封闭

此前的形状是「调用点各比较一次」：

```text
if builtin.decide(&state).capsule == Some(Capsule::Recall) { ... }
```

每个调用点各比较一次。加一个 `Capsule` 变体、写好 `name`、忘掉某个调用点——
编译通过、运行通过、**这条臂永远不派发**：本方案里唯一一个**静默失效**的扩充点。

`Capsule` 这一层已随轮执行阶段数据化退场。今天分派收在 `loop_rows::ACTORS` 上：
`Decl.by` 是数据，`ActorEntry` 按名解析；执行体写出的每一格都要在 `ActorEntry` 的
`decl` 里声明，`drive_steps` 用 `writes_closed` 对账日志尾段，未声明的写入当场判红。
漏接不再是「永不派发」——行没有执行体就恒 `blocked`，装载期也能对未登记的事实名判红。

**仍未消除的成本**是「新**时机**」：它仍要选一台 host 并在七步里占一个位置（§2 第 5 行），
而表外那一处（§1.4）在它接回之前仍由调用点直问 `owes()`。那是外环收编的射程
（[D-158](022-行表与派发面.md "DE-022-行表与派发面")），不是执行体分派的残余。

### 4.3 三个巨型函数

`symbio/src/plugins` 下 `session` + `loop` 是主体（行数随时变，不在这里写死）。

拆分前它们各是一个上千行的顺序过程（准备输入 → 逐条处理 → 收口），不是"多个职责挤在一起"。
按职责拆会把一条线性流程切成互相传参的碎片；按**阶段**拆才是它们本来的形状。
拆分的收益不是行数好看，而是：每个阶段可以单独被判据钉住（"这一段错了谁会红"）。

## §5 方案

### 动作 A：驱动器——让"时机"消失

**目标形状**（[DE-001 §4.3](001-核心架构.md "DE-001-核心架构") 的不动点语义；它的裁决与
落地形状归 [DE-015-义务环](015-义务环.md "DE-015-义务环")，本节只记施工切分与判据）：

```rust
loop {
    let Some(next) = pick(本 host 的行子集, facts, turn, now) else { break }; // 唯一求解器
    run(next.action, &mut step).await;   // 执行体只拿到一笔 Debt，拿不到选择权
    // 动作前后各读一次日志：尾段 = 这一次的实际写入，名单外与空账本都出声
}
```

> **动作 B 的现状**：`run_with_tools` / `execute_turn` / `process_tool_calls_async` 三个巨型函数已按阶段拆出
> （`loop/turn_runner/{prepare,stream,batch,boundary,settle,facts,reflex}.rs`、`loop/turn_exec/`、
> `loop/tools/dispatch/`），本节只保留拆分纪律，不再按旧行数描述。

**A1 投影收口（已落）**：入口只有一个——`frozen()` 交冻结的表，`turn_slice` 把切片收窄到
本轮，`view` 按视图口径折叠。行判据不再各自拼一份输入。

**A2 判据补全（已落）**：每行自己回答"现在该不该做"——三段模式读的全是事实，一次性阶段的
「已做」落成 `turn.stage` 那一格（阶段事实化是它的前提，[D-107](015-义务环.md "DE-015-义务环")；
判决的效应折成 `turn_head.answered` 一格见 [D-162](015-义务环.md "DE-015-义务环")）。
时机不再是类型，是判据的一个合取项——这是本方案**唯一的语义工作量**，已经付掉。

**A3 不动点循环（每台 host 已落，外环未完）**：轮内 `turn_exec::drive_steps` 与轮首
`head_exec::drive_head` 各是一台 host 的不动点循环；按 host 分片的绑定表让"这行归谁跑"
只写在 `by` 上，host 由绑定表派生（[D-159](015-义务环.md "DE-015-义务环")）。剩下的**不是**
把七步换成假的不动点，而是把七步本身收成外环：表外那处点问（§1.4）随那一步消失，
前件见 [D-158](022-行表与派发面.md "DE-022-行表与派发面")，承载路径在 [DE-090](090-过渡方案.md "DE-090-过渡方案") §1.1.2。

**代价（诚实划界）**：

- 每次迭代扫**本 host 的行子集**（不是整张表：`prio` 是全局序，传整张表会被别的 host 的
  低 `prio` 债堵死）。行表在 17 行量级，代价可忽略；但**"行只读本格字段"从编译期性质
  退回判据期性质**——这一档靠每行的用例补，不能靠自觉。
- 动作的实现体仍散在各自模块（这是对的：动作是环的指令集，不是环的实现）。

**判据**：e2e 全量逐条不变 + 事件批序逐项相等 + 每个控制面事实名都有归宿（装载期
`OrphanFact`，D-107 判据 1）+ 派发面全部经 `drive`（DE-090 §3 的两个计数）。

**熔断线**：单批结构性改动 >300 行 = 抽象错了，退回（[DE-090 §1.3](090-过渡方案.md "DE-090-过渡方案") 的熔断线）。

### 动作 B：三个巨型函数按阶段拆

| 函数 | 阶段切点 | 落点 |
|---|---|---|
| `run_with_tools` | ① 轮首准备 ② 请求 / 流式 ③ 工具批派发 ④ 轮边界判定 ⑤ 收束 | `turn_runner/{prepare,stream,batch,boundary,settle}.rs` |
| `execute_turn` | ① 装配（提示词 / 工具 / 视图）② 调用 ③ 结局归类 ④ 落格 | `turn_exec/{assemble,call,outcome,persist}.rs` |
| `process_tool_calls_async` | ① 批首闸门读数 ② 逐条执行 ③ 未执行收口 | `tools/dispatch/{gates,batch,unfinished}.rs` |

三条纪律：

1. **按阶段切，不按职责切**——切完每一段仍是一条顺序流程的一段，段间只传值。
2. **不改行为**：拆分批次与语义批次分开提交。拆分批次里出现任何 `if` 条件变化 = 切错了。
3. **每段一条判据**：切出来的段若说不出"这段错了谁会红"，说明切点选在流程中间而不是
 阶段边界。

**判据**：拆分前后事件批序逐项相等；lib 用例数与断言数不减；单文件回到 800 行以内。

### 动作 C（正交，不排期）：注册即事实

[DE-090 §1.1](090-过渡方案.md "DE-090-过渡方案") 步骤 4 收尾留下的那条：注册行落为事实（安装 = append、卸载 = 墓碑），
`Registry` trait 随之消失、core 三格再降一格。它与本方案无依赖关系，**不要混做**——
它改的是能力目录的**持久化方式**，本方案改的是策略目录与环的形状。

## §6 下界：哪些永远不为 0

| 下界 | 为什么 |
|---|---|
| 新的副作用出口（loop→session 动作） | 跨插件墙的地址面必须有词表；词表在 core 是**纯值**，不是机制 |
| 新能力族的载荷变体 | 行载荷是 `enum`，新族 = 新变体 + 生产点；这是"一表装六族"的定义成本 |
| 新的封闭集值（`Verb` / `ActorSpec` 字段 / 参数键） | 封闭集是刻意的：开放它等于让机制面被数据改写 |
| 过程型时机（在途工具、流式 token） | 它们不是"状态转移"，是"过程本身"；格子化要求先有事实，而它们尚未成为事实 |

## §7 不做清单

| 不做 | 理由 |
|---|---|
| 把策略行合进 core 能力表 | D-089 已裁决；单消费方占公共面 |
| 给 `Registry` 加第四个方法 | 三方法是 DE-008 的收敛结果；加方法就是十六方法糜烂的来路 |
| 谓词 DSL / 脚本热加载策略 | 判据要能回放、能 diff、能被编译器检查；字符串谓词三条全丢 |
| 继续切插件 | 判据耗尽：`loop` 无 `route` 臂、无能力行、无常驻任务、只 1 条 Mount 行 |
| 按职责拆三个巨型函数 | 它们是顺序过程；按职责拆会产生互相传参的碎片 |
| 为了对称给 gate 脚本造统一 trait | 往 core 灌只为对称而存在的抽象，撞 CS-001（已核验否决） |
