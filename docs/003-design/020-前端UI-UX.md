# 前端 UI/UX

> 目标是统一资源工作台与会话优先的抵达体验：用户看见的是地址、事实和通用呈现，不是按业务拼出的页面。
> 当前结构事实归 [RE-006](../004-ref/006-当前事实表.md)；节点与呈现协议归 [DE-019](019-前端机制化.md)；前端代码结构归 [DE-110](../../apps/desktop/docs/110-FRONTEND.md)。

## 1. 信息架构

- VDFS 是统一资源空间。列表、详情、动作、筛选、空态和错误态由同一台工作台控件承担。
- 会话是默认着陆；类别顺序由后端目录声明，前端不硬编码资源清单。
- **导航即地址。** 选中、进入、返回和深链都改变地址；刷新与冷启动按同一地址重建。
- 不恢复模糊的“上次位置”。需要回中性位置时提供显式入口，不从分形地址猜用户意图。
- 不为每种资源建专属页面。详情就是工作台右栏，新资源通过声明获得列表、表单和动作。
- 首启引导可跳过、可重开；每一步由后端事实判断是否已完成，不由组件内的流程状态判断。
- 空态必须给出下一步动作，且动作文案来自资源自述，不写死类别名。

## 2. 抵达与搜索

- 类别层显示该层直接子项；叶子资源没有子目录时，左栏回到其挂载类别的清单。
- 当前目录筛选与全库跳转分开：筛选改变当前列表，命令面板负责跨类别抵达。
- 全库候选来自统一资源树的地址与自述，本地筛词；不把只能匹配文件的文件搜索当作资源搜索。
- 搜索不完整时保留截断和待读取标记，不把“没返回”画成“不存在”。
- “去某一类”和“在这一类新建”共用同一目的地；新建草稿由目标目录和当前选择决定。
- 加载用骨架，空态给动作，错误给可恢复路径；缺事实时不用假数据补齐界面。

## 3. 动作与快捷键

- 资源特有能力动作由后端声明，前端只投影与启用，不按类型名写第二份动作表。
- 动作位置在工作台统一决定；“进入下一级”等主动作固定在末尾。相关动作、忙碌和禁用状态必须一起重排。
- 删除功能时连同重叠协议入口一起交接，避免只删界面、留下可被重新接回的第二条路。
- 快捷键机制只有一份：判键、平台修饰键、输入优先、模态让路和失效守卫集中实现。
- 绑定放在状态所在组件，随组件挂载注销；速查表渲染当前绑定登记表，不手写第二份清单。
- 条件不成立的快捷键不吞键；只有快捷键没有可见把手的交互不作为唯一出口。
- 模态框打开时，关闭模态优先于停止生成等全局动作，防止一次按键触发两个后果。

## 4. 长会话与会话状态（P1）

- 消息的权威副本始终来自存储。窗口化只控制当前帧铺多少 DOM，不把分页变成第二份历史真相。
- 历史窗口以根节点为单位，保留整棵子树；新节点追加到尾部，不把用户正在看的内容从上方挤走。
- 更早历史由显式入口展开，展开时补偿高度，保持阅读位置。
- 会话 UI 状态按会话保存，至少包括输入草稿、窗口范围和离底距离；不缓存消息权威副本。
- 离底距离与窗口范围成对恢复。滚动位置只用在该窗口下仍稳定的“距最新一条多远”表示。
- 节点折叠默认由通用形态和深度决定，不把完整正文主体收成不可读的一行。

## 5. 图标与资产

图标查询只有一条实现，回退顺序固定为：

1. 节点自报图标。
2. 项级具体身份。
3. 配置键或名单级具体身份。
4. 名字级身份。
5. 笼统容器类型。
6. 通用兜底。

规则是**自报在前、具体在前、笼统在后**。`dir`、`file` 等容器形态不区分成员，不能压过名字或项级身份。
卡片、侧栏和导航必须调用同一查询函数；不允许中间层各写一条回退链。自报图标无效时继续回退，不留空白。
测试夹具必须使用真实资源形状，尤其不能把笼统容器类型留空。

## 6. 信任面：读数与事实

- 上下文水位、用量、花费和变更账全部来自后端事实或读数方言，前端不重算口径。
- 读数优先复用既有 `ReadingSection` / `ReadingBar`；放不进去时扩通用几何方言，不新增业务键。
- 缺分母、缺实测或无法折算时整条不出现，不补零、不画空条。
- 自动整理阈值与界面参考线读同一后端读数；健康水位不提供手动压缩按钮。
- 手动恢复只由失败节点下发的动作决定，前端不从业务名反推。
- 用量按输入、输出、合计和必要的主体拆分展示；金额按 provider 配置在 adapter 边界折算后入事实，不按模型名猜价格。
- 会话头和详细面板消费同一读数；不能按中文标签猜读数身份。
- 变更账按路径展示动作、轮归属和次数；打开的是当前文件，不伪造没有事实依据的 diff。
- 实时性来自共享交付出口，不靠前端轮询制造第二读取通道。

## 7. 授权与分支

- “仅本次批准”“本会话同档免问”“此工具永久免问同档”是三笔不同生命周期的事实，界面必须分开。
- 审批卡首屏展示工具自声明的动作、目标与效果类别；原始参数折叠为技术详情。效果文案只消费后端契约，不按工具名或参数名猜测。
- 会话放行抬会话风险阈值；永久放行只影响指定工具且受其上限约束；没有风险档时不显示放行选项。
- 先更新授权状态再执行本次调用；执行闸和授权记录必须读同一判定。
- 分支历史不删。切换只写选中事实并改变读法，不删除节点、不重跑、不改变运行态。
- 节点树保留全史；上下文和可见集按同一后端选择折叠，前端不自行猜默认分支。
- 分支读数和切换器常驻；到头的一侧置灰而不是消失。标注不齐时宁可显示全组，不静默少一条。
- 渲染器只上抛“打开节点”等意图，路径拆解与导航由工作台宿主完成。

## 8. 呈现前件

任何“要呈现 X”的提案先确认 X 的事实前件：

| 要呈现的东西 | 必须有的事实 | 没有时的禁止行为 |
|---|---|---|
| 候选切换 | 候选及选中关系 | 前端伪造第二候选或默认选择 |
| 花费 | 已折算的金额与币种 | 按模型名猜价格 |
| 文件变更 | 带归属的写入事实 | 用文件监听结果冒充会话账 |
| 水位与额度 | 分子、上限及阈值口径 | 前端另算阈值或把缺失补零 |
| 动作可用性 | 后端声明与禁用判据 | 按业务类型猜动作 |

前件不在事实面时，先补后端判据，不先画组件。

## 9. 可用性机械规则

| 判据 | 规则 |
|---|---|
| UX-001 | 禁止 `alert` / `confirm` / `prompt`；确认与提示使用统一组件 |
| UX-002 | 无文字的图标按钮必须有 `title`、`aria-label` 或 `aria-labelledby` |
| UX-003 | 表单控件必须有标签、`aria-label` 或 `aria-labelledby`；placeholder 不算标签 |
| UX-004 | `img` 必须显式提供 `alt`；装饰图使用空替代文本 |

加载、空态、错误恢复、防重复提交、焦点与键盘路径无法由静态正则完整判定，必须由组件测试覆盖。

## 10. 边界

- 不按资源类型复制工作台页面，不建立业务专属导航协议。
- 不为美观引入与现有设计令牌冲突的第二套组件语言。
- 不把事实缺失包装成“暂时为零”，不把界面状态写成业务事实。
- 不用前端算法替代后端授权、分支选择、预算或变更账。
- 所有资源新增先复用声明、表单、读数与动作机制；只有机制确实缺失时才扩机制。
