# 协议规范

本文定义帧、载荷、通道、路由上下文、发现、事件总线与数据契约。地址规则见
[插件路由与地址](006-插件路由与地址.md "DE-006-插件路由与地址")，VDFS 线路见 [VDFS 规范](009-VDFS规范.md "DE-009-VDFS规范")，
第三方插件边界见 [第三方插件体系](007-第三方插件体系.md "DE-007-第三方插件体系")。

## 1. PluginFrame

沿 `PluginChannel` 发送的最小消息单位是两态穷尽枚举：

| 变体 | 用途 | 载荷 |
|---|---|---|
| `Data` | 正常业务数据 | `serde_json::Value` |
| `Error` | 执行异常 | 消息与结构化 details |

`Error.details` 应包含稳定的 `code`。错误码是跨进程 ABI，不得随意改名或复用；完整码表见
[错误码参考](../004-ref/002-ERROR_CODES.md "RE-002-ERROR_CODES")。

帧只表达传输结果，不承担会话状态机。中止、审批和轮次推进必须由各自的事实或控制协议
表达，不能偷偷增加一种全局“中止帧”。

## 2. PluginPayload

`route` 与 `traverse` 的返回类型是三态穷尽枚举：

| 变体 | 用途 | 跨进程行为 |
|---|---|---|
| `Empty` | 成功但无返回值 | JSON `null` |
| `Data` | 一次返回的数据 | JSON |
| `Session` | 长连接流式会话 | 返回连接，后续发送帧 |

- `new` 自动推断载荷类别；进程内读取允许零拷贝 downcast；`serialize` 强制 JSON 表达。
- 不设置“原生对象”返回变体。进程内对象通过请求上下文扩展桶传递，不进入返回协议。
- 一次性与长连接的分类只有一个权威实现，HTTP 与 WebSocket 不得各自发明判定规则。
- HTTP 对 `Session` 可折叠为最终结果，WebSocket 进行双向转发；二者必须保持相同业务语义。

## 3. PluginChannel

`PluginChannel` 是全双工流式传输通道，两端各持一个发送与接收端。

1. `pair(buffer_size)` 创建一对通道；
2. 调用方持peer端，实现持本地端；
3. 实现通过本地发送端推送 `PluginFrame`；
4. 通道 drop 或关闭后，接收端收到 EOF。

缓冲区以帧数计，用于限制慢消费者反压。通道只负责传输和关闭，不定义模型执行、工具调用或
轮次生命周期。

## 4. PluginInvokeRequest

请求上下文使用标准键注入。`PATH` 是路由下一跳，资源类请求使用 `vdfs/*` 与资源根地址。

<!-- list:protocol-messages owner -->

| 键 | 类型 | 用途 |
|---|---|---|
| `PATH` | String | 目标路由路径 |
| `payload` | 调用方定义 | 业务载荷 |
| `WORKDIR` | String | 当前工作区根 |
| `SESSION_ID` | String | 会话标识 |
| `TRACE_ID` | String | 调用链追踪标识 |
| `AGENT_ID` | String | 当前 Agent 标识 |
| `SOURCE_PRINCIPAL` | String | 入站来源主体；缺省为本机用户 |
| `CONTENT` | String | 通用内容 |
| `KIND` | String | 通用类型 |
| `ID` | String | 通用标识 |
| `NAME` | String | 通用名称 |
| `SCOPE` | String | 作用域 |
| `DESCRIPTION` | String | 描述 |

`SOURCE_PRINCIPAL` 表示“这次输入由谁发出”，必须保留完整主体身份；跨主体承诺的接收方由它
派生，不另传一个可被调用方覆盖的隐式身份。

`SymbioKey::WIRE` 声明键能否跨进程表达，缺省允许。标为不可跨进程的父插件句柄、访问者、
事件 sink 和中止令牌没有字符串或 JSON 形态，解析时必须返回不可表达，不得静默丢失。

## 5. 能力发现

发现入口为：

```rust
pub const TRAVERSE_AVAILABLE_TOOLS: &str = "available_tools";
```

发现流程：

1. 调用根插件的 `traverse`；
2. 容器下传自身路径前缀；
3. 叶子返回能力元数据；
4. 完整能力名由挂载前缀与短名组成。

```rust
pub struct CapabilityMeta {
    pub name: String,
    pub description: String,
    pub input_schema: Value,
    pub category: Option<CapabilityCategory>,
    pub examples: Option<Vec<String>>,
    pub risk: Option<CapabilityRiskLevel>,
}
```

审批摘要由工具经能力收集器的注册入口自声明：`ApprovalSummary` 只描述通用动作、效果类别与
目标参数名，不进入内核 `CapabilityMeta`，也不持有某次调用的值。审批闸门按本次 `args` 取出
目标后原样放进 `prompt.approval`，不得按工具名硬编码文件、命令或网络语义。未声明摘要时保留
`description + args` 的兼容回退。

`ApprovalSummary` 是工具意图，`ApprovalPolicy` 是 sandbox 策略。平台闸门把策略结果转换为既有
执行信封，并向审批卡写入 `approval_scopes`、`approval_reason` 与 `policy` 绑定；前端只消费这些
字段，不自行推算风险上限或授权档案。授权范围与档案绑定的缺席语义见 [DE-058-沙箱机制](058-沙箱机制.md)。

发现结果必须来自实际装配且可用的插件。完整名必须可由路由重建；未挂载或停用的能力不得
靠静态清单补进模型工具集。

## 6. 跨进程线格式

```rust
pub struct PluginMessageWire {
    pub metadata: serde_json::Value,
    pub payload: serde_json::Value,
}

pub enum PluginPayloadWire {
    Data(serde_json::Value),
    Connection(String),
}
```

`metadata` 至少承载路径、追踪标识和可选来源。连接标识用于后续发送与关闭。

流式建立流程：

1. 初次路由返回 `Connection(conn_id)`；
2. 宿主向该连接的事件通道推送帧；
3. 调用方经发送入口提交后续帧；
4. 调用方显式关闭连接，宿主释放订阅与资源。

宿主命令的权威面由 [当前事实表](../004-ref/006-当前事实表.md "RE-006-当前事实表") 提供，本文不复制命令清单。

## 7. 会话流

会话没有独立流协议。输入通过 VDFS 写入或节点动作进入，输出通过 VDFS 变更广播。

1. 发消息写入会话 `inbox`，写入即入队；
2. 消费方订阅事件总线并 watch 会话节点，两者缺一不可；
3. 首帧提供权威全量，后续提供窄增量；
4. 会话节点离开 `working` 表示本轮结束，结局由节点属性表达；
5. 消费方按节点 `seq` 排序，不依赖网络到达顺序。

地址与动作见 [会话输入与地址](012-会话输入与地址.md "DE-012-会话输入与地址")。

## 8. 事件总线

事件总线是广播通道，不是按业务频道分流的服务。订阅建立后持续接收：

```json
{
  "type": "bus_event",
  "data": { "kind": "system", "session_id": "...", "data": {} }
}
```

`kind` 是闭集：`system` / `vdfs` <!-- vocab:EVENT_BUS_KIND_ -->。

| `kind` | 语义 |
|---|---|
| `system` | 总线自身握手与系统控制信号 |
| `vdfs` | 一切资源、消息和运行态变更 |

发布方必须引用常量。消费方按地址分派，不按到达先后猜语义。

线路帧只有两类：VDFS 变更与背压重同步指令。重同步指令不带路径，含义是“按自己的作用域
幂等重读”；消费方不得用手写条件猜它。通道满时丢弃部分变更、保留订阅并补发重同步指令，
不假装投递可靠。顺序是节点属性，不是投递属性。

## 9. 数据契约

### 9.1 归属与命名

跨端数据类型住在它描述的域中，不集中到通用 schemas 目录。纯数据形状归契约层，带 IO 或
机制的实现归 SDK，封闭语法归内核。具体文件地址以代码和当前事实表为准。

内部结构使用 `snake_case`，Rust 字段与线上键逐字对应，不做宿主侧 camelCase 转换。镜像
外部规范的结构是显式例外，例如 MCP 报文按外部规范使用 camelCase，并在序列化处声明。

事件 schema 采用只增不改：新增字段必须可缺省，已有字段不得静默改变含义。线格式演进必须
保持旧消费方安全。

### 9.2 会话事实与节点

用户消息节点就是一轮的可见起点，不额外创建不可见的 Turn 容器。轮次身份由事实与分支
标记表达，节点标识在写入前确定。

失败轮和工具卡必须能由事实重建：

- 失败节点由自身诞生事实承载，不依赖内存中的异常对象；
- 工具卡以工具请求调用列表为存在性来源，不按助手往返次数猜测；
- 同一事实只构造一次终答树，多个产出路径只写载荷，不各自拼树。

### 9.3 压缩输入

压缩只装入预算允许的最旧前缀，并从明确边界换基。压缩包必须携带前缀指纹与重试纪元，
避免把旧摘要误接到新分支。

端点缺失、前缀不完整或预算无法满足时必须响亮失败，不得回退为整份转写。压缩失败必须落
事实；重试产生新身份，不覆盖失败记录。失败分类属于能力策略，不扩成通用错误码枚举。

## 10. 注册与扩展

静态插件在编译期注册构造器，宿主首次使用时惰性收集。只有存在多个可替换实现的服务才
登记工厂；固定接口的具体实现可以直接组合，不为了统一外观增加字符串查表。

容器根据目录与 manifest 装配子插件，不在容器内嵌具体插件清单。每个插件只读写自己的
`PLUGIN.yml`。

### 10.1 manifest 保留键

保留键归装配方，插件私有配置不得占用同名键。

| 键 | 写入方 | 语义 |
|---|---|---|
| `plugin_provider` | 装配方 | 构造器标识 |
| `plugin_name` | 装配方 | 实例名，缺省为目录名 |
| `plugin_enabled` | 装配方 | 是否启用，缺省启用 |
| `plugin_title` / `plugin_description` / `plugin_version` / `plugin_author` | 装配期投影 | 展示身份 |
| `plugin_api` | 插件作者 | 所需宿主 API 版本 |
| `plugin_grants` | 宿主 | 宿主授予的能力 |

身份投影方向为“出厂声明 → 装配期 manifest → 运行期读取 manifest”。停用插件仍有身份，
只是不被构造。新增插件通过声明、注册和装配数据进入系统，不修改共享驱动分支。

## 11. 兼容性

协议变更必须向后兼容。新增可选字段、错误码或路由不得让旧消费方把未知值误当成功；破坏性
改变需要新协议身份和明确迁移边界。所有跨端声称都必须有可执行断言与反向用例。
