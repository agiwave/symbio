# 能力拆分与影响类

一个能力由事实、视图、行与执行体组成。全面拆分要求这些成员随能力包走，控制面只保留环、
写口、全局守门、过程体与会话基底。新增能力容易插件化不等于拆分完成；存量实现、按能力名
分支和双写路径都必须退出。

扩展位置与能力包契约见 [DE-025](025-能力包与扩展面.md)，声明与封闭语法见 [DE-023](023-内核边界与扩展局部性.md)，行选择和执行见
[DE-022](022-行表与派发面.md)。本文规定拆分判据、影响类与不变量，不维护逐能力处置、搬迁批次或验证读数。

## 1. 三条判据

| 判据 | 要求 | 回答的问题 |
|---|---|---|
| `T1 新增` | 新能力只改自己的声明、装配与实现，受保护机制树没有该能力的特例；行为用例通过 | 加能力是否必须改架构 |
| `T2 拆除` | 存量实现退出控制面，插件等价提供，外部可观察行为不变 | 存量是否能真正拆出 |
| `T3 卸载` | 卸载后能力及其静态边消失，系统仍完整运行，不留下静默边 | 能力是否可移除 |

`T1` 是新增准入，`T2` 是全面拆分的终态，`T3` 是共同约束。只满足 `T1` 而保留控制面旧
实现，扩展性只是表面成立。拆分对象是完整能力集合，不能只挑容易搬迁的样本；每一条未能
拆出的实现都必须能归入下列合法残留类。

## 2. 控制面合法残留

| 残留类 | 允许保留的内容 | 不允许保留的内容 |
|---|---|---|
| 环 | 选债、推进、停机与端口协议记账 | 某能力的业务策略或私有状态机 |
| 写口 | 事实草稿盖章、声明校验、唯一落格路径 | 工具或能力自己的 WAL 写口 |
| 全局守门 | 跨全量授权、不变量、承诺配对、单写者顺序 | 单能力可以自行修改的合法标准 |
| 过程体 | 模型流式读取、工具批次在途等不可拆分过程 | 可以表达为事实转移的业务判断 |
| 会话基底 | 存储、转写与收件箱的通用接缝 | 按能力名增长的工具分支或策略表 |

残留必须有与能力无关的机制理由。端口暂时不存在、实现搬迁困难或历史一直如此，都不是
留守理由。能表达为“读事实 → 交出影响类值”的实现属于能力；写不进影响类时，先证明它
属于上表，而不是扩大控制面。

## 3. 影响类闭表

能力可以产出判定，引擎强制“什么算合法”。闭的是强制点与执行顺序，不是判定的生产者。

| 影响类 | 能力交出 | 宿主负责 |
|---|---|---|
| `I-1 写事实` | `Vec<FactDraft>` 或逐条 `Contribution` | 补宿主信封、过写闸、唯一落格 |
| `I-2 上下文段` | 带身份、正文与优先级的段 | 按序收集、统一计量、确定性裁剪 |
| `I-3 提示前裁决` | `Allow` 或 `Refuse` | fail-closed 合并，先拒绝者胜 |
| `I-4 模型往返` | `ModelAsk` 与 `RowHandler::parse` | 调模型、预算、租约、请求与应答落格 |
| `I-5 上下文省略` | 摘要与显式区间的替代事实 | 在统一应用点排除被替代区间 |
| `I-6 请求下一段` | 让既有行前件成立的事实 | 由环继续推进，不另开调度语义 |
| `I-7 过程体` | 不开放 | 引擎执行流式与在途过程 |
| `I-8 强制` | 不开放 | 引擎执行全局量词守卫 |

新增能力只能实例化 `I-1…I-6`。它不能新增判断种类、权威动作、协议事实、停机原因或写闸。
`I-7/I-8` 不是能力扩展位；把可搬的业务实现藏进这两类，属于反向拆分。

## 4. 实体与词汇边界

`Entity` 保持闭集，`Domain` 是领域扩展位；`Verb` 与 `FactRole` 不随能力开放。新领域事实
由 owner 声明名字、格位和角色，宿主不解释领域业务含义。能力不新增实体，也不把领域格
当作对话格。

跨插件共享地址、事件、行为、视图和路径名进入单一词汇源；插件之间仍无编译依赖。能力
内部名字保持局部，只有真实跨插件消费才生成公共常量。详见 [DE-024](024-能力横向扩充的通路.md)。

## 5. 行级写入与共享执行体

行声明只描述债务、前件、出口与端口，不写执行者姓名。装载时先查已注册行实现；没有实现
且 `owes` 指向端口开启侧，才交给通用端口受理。没有实现又不是端口开启侧的行在 seal 期
失败，不能被派发器静默过滤。

共享执行体按行声明处理写入：

- `ActorDecl.writes` 是共享执行体可写事实的并集。
- `RowWrites` 是该行实际写入清单，用于依赖图和运行期对账。
- `Builder::seal(row_writes)` 是唯一冻结入口。

依赖图按每行实际写集展开，不按共享执行体的并集制造假依赖。行执行体不获得 `&mut Ctx`
或存储句柄；模型往返经 `RowStep::Ask` 与 `parse`，跨插件调用经父容器路由。零模型往返的
反射行直接返回 `Vec<FactDraft>`。

## 6. 顺序、失败与权限

行计划按 `(row.name, row.id, row.port)` 稳定排序，只消除偶然并列顺序。业务时序来自
`after`、`after_port`、`when_no_open`、`reads` 与事实依赖，不来自排序键。能力不得假设
收集顺序就是执行顺序，也不能自行改写全局次序。

路由失败或执行超时不偿还债务，由租约与最大尝试次数收口。迟到结果在请求已被取代、关闭
或租约失效时丢弃；缓冲事实只有在该尝试仍有效时才提交。失败不能被吞成空成功。

权限对插件行与工具相同，由 owner 清单生成授权行并通过统一授权面执行。插件代码可信、
装配可停用不等于沙箱隔离；本设计不把沙箱或第三方进程隔离伪装成已提供的能力。

## 7. 上下文省略是事实

一次摘要替换由同一条 `message.added` 事实同时承载替代正文与省略区间。区间使用存储分配
的闭 `seq` 范围 `[from,to]`，不轮号、不切片下标。缺少 `seq` 的事实不能匹配显式区间。

`from > to`、非正整数或无法解析的区间视为没有省略，容错方向是少藏。替代正文与被替代
区间不可拆成两条独立事实；读侧不需要在半连接状态猜哪一半已经生效。

显式省略与未选中分支在同一个 `Elisions::elides` 应用点合流。转写仍保留历史，组装模型
上下文时按事实排除区间；不在组装点按能力名或事件名另写一套压缩分支。

## 8. 收束贡献

收束派生事实使用 `Contributor`，不伪造永远空转的债务。贡献天然可能为空；空结果是正常
结束，不触发重试，也不等于失败。

宿主按 `(prio, owner)` 询问贡献者，并在每次询问前刷新事实。后续贡献者因此能看到早先
贡献落格后的值。贡献者只接收收束时刻的宿主值与不透明幂等词干，返回逐条事实草稿；归属
信封由宿主补齐。开关与容量从事实读取，不读取进程活配置；同一份历史必须重放出相同贡献。

贡献逐条过写闸，没有组原子端口。需要依赖先前落格值时用顺序声明，不靠私有可变状态。
轮首检索、上下文段与收束贡献各有独立节奏，不能把其中一种实现硬编码进另一种端口。

## 9. 补件与迁移分开

架构补件先于依赖它的搬迁，必须能用不提能力名的术语描述，并有真实生产消费者与撤除
路径。补件只提供通用端口、契约或机制，不把某个能力的实现搬进 sdk、kernel 或控制面。

迁移只做实现落位、绑定切换与旧实现删除。切换与删除同提交，不允许新旧双写同时生效。
机制面净增不为正；允许收窄，但净零搬迁不能抵消另一笔净负迁移。补件与迁移分别提交，
避免把设计缺口藏在搬运 diff 中。

新增扩展位置的通用性由 review 判定，代码不含能力名由审计判定；两者不能互相替代。脚本
判据以输入变化导致结论变化为准，不在文档复制历史批次、豁免、哈希或计数。

## 10. 判据与失效方向

| 判据 | 通用规则 |
|---|---|
| `EX-002` | 新增能力包提交不改受保护机制树；已有生成路径不豁免新公共面 |
| `EX-003` | 迁移同提交删除受保护树中的旧实现并切换绑定 |
| `EX-004` | 可卸载能力没有外部编译期边，卸载后系统仍完整 |
| `EX-005` | 开账行必须有注册实现，或由端口开启侧受理 |
| `EX-007` | 迁移不净增机制源码、不在控制面新增能力名分支；补件通用且独立 |
| `EX-008` | 扩展 API 形状不泄漏容器词、轮号或宿主配置类型 |
| `SC-006` | 控制面非测试代码中的工具名特例只许减少 |
| `E-009` | 插件生产依赖闭包不含兄弟插件、宿主转发或源码重定位 |
| `CS-009` | 封闭实体的公开字段与变体只许收窄 |

删去一条能力时，同步删除它的实现、声明、路由、权限与静态引用；只删开关会留下静默边。
`SC-006` 与 `EX-007` 各自守不同形状，不互相替代。

## 11. 终态检查

全面拆分完成时：

- 新能力不改机制层，也不改其它插件。
- 控制面没有按能力名的工具分支、行、常量或策略。
- 每个留守项属于五类残留之一，并能说明为什么不能表达为影响类实例。
- 共享执行体按行写集判定依赖，不按并集误连。
- 省略、收束、检索与上下文都通过声明和纯值端口贡献。
- 停用与卸载的粒度诚实，不把运行期旗标当作链接期移除。
- 机制面只降不涨，结构事实以 [RE-006](../004-ref/006-当前事实表.md) 的生成结果为准。
