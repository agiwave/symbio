# 长期记忆与语义检索

## 内容

前置：S05 ｜ **新增机制键 0** ｜ 参数变化 4 ｜ 阶段二

## 1. 场景：要什么能力

跨会话记住东西，并在需要时**找回来**——不是"存了"，是"能检索到"。

相对 S05 高了什么：S05 恢复的是流程状态（做到哪一步），S06 是语义状态（学到了什么）。
**T3 的定义就是这一阶**；而且它是 T4–T8 的前提：没有记忆，后面所有高阶能力都在空转。

## 2. 为什么它能落在 v2 上（J1）

[DE-001 §9](001-核心架构.md "DE-001-核心架构") 已经把三件事各自归位，本阶只是把它们点亮：

| 事物 | 位置 | 为什么 |
|---|---|---|
| embedding | 一条普通事件 `memory.encoded{payload: vec}` | 它是事实，不是特殊类型 |
| 索引（向量 / 倒排 / 时间分区 / 混合） | `Store` 的**实现细节** | 不进 trait 签名，替换零改动 |
| 检索 | 一个 `Translator` Actor，产出 `memory.recalled` 事件 | 检索 = 读视图 → 产出事实 |

**"记忆类型"不是枚举，是过滤函数的参数**——加第六类记忆只需加一组参数，不动类型系统。

## 3. 增量清单（只加数据）

| 类型 | 内容 |
|---|---|
| 事件格子 | `memory/opened`（`memory.encoded`）、`memory/progressed`（`memory.consolidated`）、`memory/closed`（`memory.forgotten`）、`memory/asserted`（`memory.recalled`、`memory.calibrated`） |
| ActorSpec 行 | 检索者 `{ pattern: translator, capabilities: [], budget_ms: 500 }`<br/>巩固者 `{ pattern: reasoner, capabilities: [DefineWork], budget_ms: 86400000 }`（空闲触发） |
| grants 行 | `vis_scope = thread_private` —— 记忆默认对他人不可见 |
| 投影参数 | `projection = recall`（语义 / 时序 / 因果混合打分）、`consolidate`、<br/>认知内容标签 `recall:tag=...`（七类）、密度 `recall:density=...`、层级 `recall:layer=...`（五层）、<br/>扩散 `recall:spread=on`、衰减 `recall:decay=exp` |

> **认知体系（`reference/01-认知架构模型.md`）的内容 schema 与检索策略整体落在这一阶**：
> 七类认知内容、内容密度金字塔、五层存储、向量/关系/时间索引、激活扩散、时间衰减与使用反馈——
> 全部是 `recall` 的取值或 `Store` 的实现细节。完整分布见 [DE-030 §5](030-能力阶梯总览.md "DE-030-能力阶梯总览")。

**本阶点亮的机制键**（阶梯总表的「新增机制键」由这张块算出；`scripts/gen-verify-facts.mjs` 从这里取输入）：

```capability-assign
event.entity = memory
event.verb = asserted
actor.pattern = translator
projection = recall
```

### 3.2 四个投影参数为什么不落地（`layer` / `density` / `spread` / `decay`）

§3 的「投影参数」一行写着 `recall:layer=...` / `density=...` / `spread=on` / `decay=exp`
四个名字。逐条对代码之后，四个**都不落**——但不是同一个理由，也不许合成一句「还没做」。
判据只有一条：**一个参数要么「值有产地、读方会用它」，要么撤下**；中间态有两个已知坏形状：

- **死旋钮**：形参在、值恒缺省 ⇒ 过滤器恒真（[DE-016](016-工程落地与验证.md "DE-016-工程落地与验证") 批的「能算却没人读」）；
- **活旋钮没刻度**：能拧、拧了确实改变行为，但没有任何判据说该往哪拧——比死旋钮更难发现，
  因为它看起来在工作。

| 参数 | 值的产地 | 读方会拿它做什么 | 裁决 | 缺的是哪一件 |
|---|---|---|---|---|
| `layer`（五层存储） | **已由三个既有字段确定**：`entity`（原始 = turn 格、记忆 = memory 格）/ `tag`（情景 / 语义 / 技能）/ `generation`（原始 vs 压缩） | 按层过滤 | **阶外** | 不是缺产地，是**本来就有**：层是那三个字段的**派生名**。再加一个 `layer` 形参等于给同一维度起第二个名字（[D-147](001-核心架构.md "DE-001-核心架构") 的反面），两个过滤器迟早对不上——一个说「语义层有 3 条」、另一个说 4 条 |
| `density`（密度金字塔） | **两层有**：`generation` = 0 是原文、≥1 是压缩产物；「要点 / 模式」两层**无产地**（那要一个能分两档压缩的分级器，是算法不是架构） | 按压缩层过滤 / 优先原文 | **阶外** | 缺**消费场景**：被压缩的源记忆已经过排除式遗忘离开视图（[`consolidate`] 写 `memory.forgotten{why: consolidated}`），活集里本来就不存在「原文与摘要并列」⇒ 按密度过滤会得到一个与其名字不符的空洞旋钮。另加：四层只覆盖两层，参数名会承诺它做不到的事 |
| `spread`（激活扩散） | **无**。记忆之间没有「边」的事实：关系索引是 `Store` 的实现细节（§2 `C06`），而今天没有任何写方产出边 | 多跳扩展候选集 | **阶外** | 缺**边的产地**。按 `tag` 假造边就是把「同标签」当成「有关系」，扩散退化成标签扩展；而沿 `sources` 溯源链扩散会**召回已被压缩掉的源记忆**，与排除式遗忘（`C13`）直接冲突。`verify/cognitive_fit.rs` Q3.2 的正向读数来自程序内自 mock 的扩散，不构成产地 |
| `decay`（时间衰减） | **有**：`ts` 在载荷里，as-of 的 `now` 在投影闭包手里 | 排序：让年龄压过相关性 | **阶外** | 缺**刻度**。今天「旧但相关 vs 新但无关」由 `rank` 的**字典序次级键**解决（重叠分降序，平手 ts 降序）——那已经是「相关性优先、新近其次」的确定策略；指数衰减做的是让年龄**盖过**相关性，那是换策略不是补缺口。而评测集（`recall_eval` 的 33 例 + 换述表）的 `ts` 是合成刻度、没有「该忘掉」的标注 ⇒ 既证不出它有用，也证不出它不伤。落一个「拧了确实改排序、但没有任何数说该往哪拧」的旋钮，正是上面第二种坏形状 |

**共同结论**：四个都不落，各记一行（`layer` 派生已有 / `density` 无消费场景 / `spread` 无边产地 /
`decay` 无刻度）。它们不是「以后有空再说」——每一条都写明了**落地时先要补的那一件**：
`layer` 要先有「层 ≠ tag/generation」的判据，`density` 要先有分两档压缩的分级器，
`spread` 要先有边的写方并裁掉与排除式遗忘的冲突，`decay` 要先有带真实时间刻度与遗忘标注的评测集。
在此之前，参数名留在 §3 是设计记法，不是生产刻度。

## 6. 验收断言

1. 后台追加 `memory.consolidated` 后，`as-of=T` 的视图**逐字节不变**。
2. 检索预算耗尽 → 返回 `degraded: true` 且带部分结果，**不允许返回空且不标降级**。
3. A 的记忆在 B 的 `recall` 视图中不出现，除非有显式 grants 行。
4. **反向用例**：忽略 as-of 的投影实现 → 断言 1 必须失败。

## 8. 这一阶做不了什么

边界的唯一账本：[SC-006-长期记忆与语义检索](../002-scene/006-长期记忆与语义检索.md)（用户语言）。机制面独有边界（用户可见范围之外的工程约束）：

- 召回质量由 `verify/recall_eval.rs` 的评测集出数——该程序 `#[path]` 包含**生产排序内核**（`projection/recall_score.rs`），出的是生产投影的 recall@k。
- 检索打分之间的**反馈环收敛性未论证**：若启用"使用反馈调权"，检索结果会改变下一次检索，v2 目前没有任何收敛性论证（`termination.rs` 只证任务终止，不证投影序列收敛）。
- 巩固策略（压什么、留什么）是算法问题，架构只提供位置。
- 语义（向量）维不落：召回按**字面重合**（拉丁词 + CJK 二元组）排序，同义 / 换述 / 跨语言
  召不回来。这不是「没做完」，是判过不落——写时成本与读时收益的方向在这个场景里是反的，
  索引属 `Store` 的实现细节（`D-152`）。

## 9. 关键决策

### D-132 记忆编码是**轮级派生**，不依附驱动循环——答话轮（快路）同样要编码

**背景**：`classify` 判 `Answered` 的轮在轮首就收尾，不进驱动循环（[D-125](015-义务环.md "DE-015-义务环")）。
`execute_final_reply_turn` 曾据此把 `record_learning` 一并跳过，理由是「这一轮没有工具交换、
没有模型参与，没有派生副作用」。这个理由对承诺 / 任务表 / 熔断成立，对记忆不成立：
记忆编码的是「这一轮用户说了什么、智能体答了什么」，与有没有工具交换无关。

**实测后果**（默认配置，`classify_enabled` / `compose_enabled` 均为 `true`）：用户说
「请记住：我的幸运数字是 7」，分类器判答话 ⇒ WAL 里没有任何 `memory.encoded` ⇒
新会话召不回来。SC-006 判据 1「这一轮说的话，下一轮 / 下个会话还在」在默认路径上
是**假的**；`t29` 因为钉死 `DIALOG_FACE_OFF` 而看不见它。

**裁决**：`record_learning` 是**轮级**写方，两条收尾路径（`persist_turn` /
`execute_final_reply_turn`）都调它，跳过条件只有与运行器结局对齐的那三个：

| 结局 | 经验（用户发言） | 判断（定稿答话） | 理由 |
|---|---|---|---|
| 正常收束 | 写 | 写 | 这一轮发生了 |
| 兜底（`fell_back`） | 写 | **不写** | 失败的路不该被固化成判断（与技能编译同一条纪律） |
| 中止（`aborted`） | 不写 | 不写 | 没有定稿产出（与 `classify_turn` 同一出口） |
| 收束被授权拒绝（`closure_denied`） | 不写 | 不写 | 收束格未入格，派生事实全不写 |

**召回仍不建**：答话轮不构造召回视图——分类器判 `direct` 的前提就是「当前对话里
答得出」，这一轮没有检索往返，也就没有 `memory.recalled` 可记。需要记忆才能回答的
问题（过去会话、偏好、长期设定）必须判 `work`，由完整轮去检索；分类提示词把这条
写成显式判据（`plugins/classify/decide.rs` 的 `SYSTEM_PROMPT`）。分类器误判成
`direct` 时仍会答错——这是模型质量边界，不是第二条记忆路径，不在本决策内。

**判据**：e2e `t82-fastpath-memory.mjs`——A 会话一句显式记忆请求被 `classify` 判
`direct`，WAL 必须同时有 `memory.encoded{tag:经验}` 与 `{tag:判断}` 且有一条
`chat.assistant.final`；B 会话的完整轮请求包必须置顶注入 A 那句话。反向：去掉
`execute_final_reply_turn` 里的 `record_learning` 调用，本用例在第一条断言就红。

### D-151 四个投影参数暂不落地：四种不同的缺件，读史窗口立为护栏而非旋钮

§3 的四个参数（`layer` / `density` / `spread` / `decay`）一直以「形参不存在」的状态挂在
§3.1 里，既不像缺口（有名字、有阶段归属）也不像承诺（没有代码）。本决策把它们**逐条判完**，
并顺手把「巩固者的预算没有读方」这条同样悬着的记账一起收口。

**裁决一：四个参数一个都不落，理由是四件不同的缺件**（逐条见 §3.2 的判决表）。合成
一句「还没做」是不允许的——那会让下一个人以为它们是同一件事、同一个人、同一个前置。
四条各自的第一件待补也写在那张表里：`layer` 要先有「层 ≠ tag/generation」的判据；
`density` 要先有能分两档压缩的分级器（且要先回答「活集里没有并列，过滤它做什么」）；
`spread` 要先有边的写方，并裁掉「沿 `sources` 扩散」与排除式遗忘的冲突；
`decay` 要先有带真实时间刻度与遗忘标注的评测集。

**裁决二：判据是「产地 + 读方」，中间态有两种坏形状**。死旋钮（值恒缺省 ⇒ 过滤器恒真）是
已知的第一种；本阶补上第二种——**活旋钮没刻度**：能拧、拧了确实改变行为，但没有任何数说
该往哪拧。`decay` 正是第二种：它不缺产地、不缺读方，缺的是「往哪拧」的判据。两种形态的
共同点是**用户看不出区别**（都像在工作），所以判据只看一件事：这个值有谁产出、谁消费、
消费的后果有没有判据能说好坏。

**裁决三：巩固者的「预算」换成读史窗口，并且它是护栏不是旋钮**。原记账「巩固者预算
86400000ms 无读方」把两件事混在了一起：巩固者不是独立主体（不建 ActorSpec 行，预算的
载体本来就不存在），而真正该被问的是**「一轮收尾最多读多久的史」**。所以落地的是
`memory_events::HISTORY_WINDOW`（4096 条，快照尾部）：

- 它是**护栏**：值不由用户调、没有参数面，作用只在超窗那一刻可见（`plugin_debug` 说得出
  「看了多少 / 全史多少 / 这一轮少了什么」）；
- 它封的是**聚合扫**（巩固的召回扫描），不封**按 seq 点查**（代数 / 可见域 / 最初一代溯源
  ——那几处取的是具体一条事实，与总长无关，且窗外那几条恰恰是溯源链要的）；
- **窗口是常量，不是保证**：极长会话里比窗口更旧的记忆这一轮不压缩（仍在召回视图里），
  这是选值的边界，与 DE-015 §2.6 第 7 条同一条纪律。

**被否的候选**：

| 候选 | 否掉的理由 |
|---|---|
| 把四个形参都补上，值取平凡值（等于不启用） | 那就是四枚死旋钮：`recall(viewer, tag, query, layer=None, density=None, spread=false, decay=None)` 每个调用点都得按位置传四个「不启用」——形状变宽、行为零变。DE-016 全篇批的就是这个形态 |
| 先落 `decay`，默认关、等以后调 | 默认关 ⇒ 生产上永不执行 ⇒ 死旋钮；默认开 ⇒ 拿没刻度的旋钮改所有会话的召回排序。两条都不可接受，差别只在于坏得明显还是隐蔽 |
| 巩固者预算照字面给个读方（`consolidate` 用 `Budget::new(0, 86400)`） | 86400000ms 是「空闲触发的 reasoner 可以跑一天」的拟人化记账，换成 86400 条事件的扫描配额是把一个没来由的数字换成另一个。护栏该由「一轮收尾读多久的史」定，不由继承来的毫秒数定 |
| 读史窗口超过就**跳过本轮巩固** | 长会话里窗口恒被切 ⇒ 巩固永远跳过 ⇒ 记忆无界增长且**每一轮都有读数说「跳过了」**。有读数不等于没坏：坏的是策略（永远不压缩），读数只让它显得诚实 |

**代价说清**：极长会话（>4096 条事实）里，比窗口更旧的记忆不再被压缩——这是有意的边界，
判据 `memories_older_than_the_window_wait_for_a_later_round`（含反向：同样四条放回窗口里
立刻合并）；四个参数继续以「设计记法」留在 §3，读的人必须先看 §3.2 才知道它们没有产地。

### D-152 语义维不落：不写 `vec`，索引归 `Store`——写时成本与读时收益的方向在这里是反的

§2 把 embedding 定成「一条普通事件 `memory.encoded{payload: vec}`」，D-110 又把「恒空预留键
不进事实形状」立成规则，于是一直悬着一个问题：**向量到底写不写**。本决策判完：**不写**，
并且不是「等模型好了再写」，而是当前形状下写它就是错的。

**四条理由，按分量从重到轻**：

1. **读写比是反的**。写侧是每轮**两次**编码（经验 + 判断），读侧是每轮**一次**召回。
   `vec` 的收益在「一次写、多次读」时才成立（索引的经典前提）；这里正好倒过来——写时
   常驻两次 ONNX 推理（模型 24MB，CPU 上单条几十毫秒）加在**每一轮**，换来的只是让
   「每轮一次」的召回少算一点。方向错了，优化得再准也是负收益。
2. **事实形状里存的是「用某个模型算出来的中间量」**。`vec` 不是「用户说了什么」，是
   「某个版本的模型把这句话映射到的一个点」。模型一换（换模型 = 换 embedding 空间），
   历史 `vec` 全部失效，而事实**不可改**——于是 WAL 里会永久留着一批与当前模型不兼容的
   向量，读侧还得先判断「这条 vec 是哪个模型算的」。要判就得把模型指纹也写进事实……
   为一个中间量付出的形状代价，一路传染下去。
3. **索引是 `Store` 的实现细节**（§2 的 `C06` 行，来自 [DE-001 §9.2](001-核心架构.md "DE-001-核心架构")）。
   把 `vec` 写进事件，等于把索引搬进事实源：以后想换索引（倒排 / 混合 / 分层）就要动事实
   形状，而「不动 trait 签名、替换零改动」这条承诺正是靠「索引不在事实里」换来的。
4. **WAL 体量与不可逆性**：一条记忆正文 ≤400 字符，一个 384/768 维 float 向量是它的
   数倍到数十倍。WAL 是**永不删**的（遗忘是投影排除，不是物理删除），所以每写一条就永久
   多一份索引数据——这与「Log 存事实、索引可重建」的分层直接冲突。

**替代路径（今天就在用的那一条）**：召回走**词面重叠分**——`recall_score::rank` 的
拉丁词 + CJK 二元组（`terms` / `overlap`），无查询时退化为纯新近度。它不依赖模型、
零常驻成本、与评测集共用同一份源码，`recall_eval` 的**换述读数**（原述 − 换述的依赖度）
就是它「有多靠字面」的诚实数——那个数不高不低，正是「够用但不神」的诚实形状。

**未来要落时的正确形态**（写在这里，省得下次重新推一遍）：索引住 `Store` 侧
（`v2-events.wal` 旁边的一份可重建产物，像 `codebase_search` 的索引那样），读侧只在
**候选集**上嵌入重排（top-K，而不是全窗）——写时零成本、模型换了就重建索引、事实形状
一个字不动。先要有的判据是**刻度**：评测集要有真实时间刻度与「该找到但字不同」的标注，
否则又是 [D-151](#d-151-四个投影参数暂不落地四种不同的缺件读史窗口立为护栏而非旋钮 "DE-036-长期记忆与语义检索")
说的「活旋钮没刻度」。

**被否的候选**：

| 候选 | 否掉的理由 |
|---|---|
| 编码时写 `vec`（`memory.encoded` 载荷带向量） | 上面四条；核心是读写比倒了 + 事实里存派生值。代价是每轮常驻推理与永久 WAL 膨胀，收益是「同一批候选换个算法排序」——而这批候选已经由词面分选出来了 |
| 读侧对**全部**召回窗口嵌入（500 条） | 每轮 500 次推理。不是「贵一点」，是把一个 O(1) 次推理的读路径变成 O(n)——而召回的**预算口径**（`RECALL_SCAN_QUOTA`）本来就是按「轻读」定的 |
| 读侧对 top-K 重排（今天不落） | 形态是对的（见上面「未来要落时的正确形态」），但今天缺两件：`Store` 侧索引的载体、以及能说「重排之后更好了」的标注。缺刻度先落地 = `D-151` 的第二种坏形状；等刻度出现时按上面的形态落，不需要再改一次形状 |
| 加一个 `vec` 开关，默认关 | 默认关 ⇒ 生产永不执行（死旋钮）；默认开 ⇒ 上面四条全中。开关不能把一个方向错的成本变成对的 |

**代价说清**：字面不重合的记忆（同义、换述、跨语言）召不回来——这是**已承诺判据之外**的
能力（SC-006 判据 3 要求的是「相关的排在无关的前面」，词面分给得出这个），所以它不是违约，
只是没做的增强；用户能看到的差别写在 SC-006 的边界里。
