# GO-002 · 三栏机制

> **这个 kind 回答什么**：要达成什么——价值主张与可度量的验收判据。
> 父目标：[GO-001 · 前端去业务化 / 机制化](GO-001-前端去业务化.md "GO-001-前端去业务化")
> （`parent` 指向它；四层分工见 [docs/README · 目标分层与依赖链](../README.md "docs/README")）。

## 1. 要达成什么

左导航 / 中列表 / 右详情三栏成为资源管理的**唯一框架**：会话、模型、智能体与
Agent 内部资源（prompt / skill / mcp）全部走同一套三栏、同一套条目化登记——
三栏组件不认资源类型，只认「一份 kind 配置 + 一个渲染器」。

## 2. 可度量判据

| 判据 | 执行方 / 现状 |
|---|---|
| 新增一类资源 = 一份 kind 配置 + 一个渲染器 + 一条导航注册；三栏框架代码零 kind 分支 | 读数待建（本条目的出口）——分支读数建立前不编数 |
| 任一资源类型的中列表支持状态过滤与拓扑排序（task 看板同款能力） | `registry-board`（现行，机制已具备） |

## 3. 本层不放什么

设计（三栏的组件划分 / 状态提升 / 路由形状）归 plan 层，本条目不描述「怎么实现」。
