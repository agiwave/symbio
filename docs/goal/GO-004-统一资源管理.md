# GO-004 · 统一资源管理

> **这个 kind 回答什么**：要达成什么——价值主张与可度量的验收判据。
> 父目标：[GO-001 · 前端去业务化 / 机制化](GO-001-前端去业务化.md "GO-001-前端去业务化")
> （`parent` 指向它；四层分工见 [docs/README · 目标分层与依赖链](../README.md "docs/README")）。

## 1. 要达成什么

三栏机制抽象为**统一资源管理机制**：覆盖 Agent 内部资源（prompt / skill / mcp）与
SessionView，任意资源从任意入口经**全局跳转**进入独立全页路由——资源之间不再
各有一套「列表页 + 详情页 + 编辑页」的私有实现。

## 2. 可度量判据

| 判据 | 执行方 / 现状 |
|---|---|
| 任一资源可从任一入口全局跳转到独立全页；跳转目标由登记解析（同 `gen-doc-refs` 的精神：身份在编号，位置由机制算） | 读数待建（本条目的出口）——路由表生成机制建立前不编数 |
| 资源管理面板与文档登记机制同构（资源 = 条目 = 单文档投影） | 形态先行：文档侧已由登记机制落地（`registry-audit` 现行）；资源侧同款化是本条目要推进的事 |

## 3. 本层不放什么

设计（路由表形状 / 跳转协议 / 全页生命周期）归 plan 层，本条目不描述「怎么实现」。
