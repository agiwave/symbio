# GO-001 · 前端去业务化 / 机制化

> **这个 kind 回答什么**：要达成什么——价值主张与可度量的验收判据。
> 四层分工（goal / stage / plan / task 各回答什么、依赖怎么表达）的唯一解释在
> [docs/README · 目标分层与依赖链](../README.md "docs/README")，本文不复述。

## 0. 一句话

宿主（对话面 / 三栏 / 表单）不再承载任何业务分支：**同一套机制跑全部资源类型**，
业务差异收敛为**数据**（注册一份配置）而非**代码分支**。

## 2. 可度量判据

| 判据 | 执行方 / 现状 |
|---|---|
| 新增一类资源（会话 / 模型 / 智能体 / Agent 内部资源）只加**数据**（一份 kind 配置 + 一个渲染器 + 一条导航注册），三栏与表单框架零分支 | 读数待建——它是子目标 [GO-002-三栏机制](GO-002-三栏机制.md) / [GO-003-表单机制](GO-003-表单机制.md) 的出口判据；建立之前不编一个数出来 |
| 同一套机制覆盖系统级与模块级资源（就近放置、单一来源） | `registry-audit` 的 RG-020（现行：仓内每个活跃 `.md` 都在登记机制内） |

判据之所以是判据，是因为它会在违反时变红；还没变红能力的，写明「读数待建」——
**缺口写在这里，比编一个数字诚实**（同 [GO-000 §2](GO-000-价值主张.md "GO-000-价值主张") 的形态）。
