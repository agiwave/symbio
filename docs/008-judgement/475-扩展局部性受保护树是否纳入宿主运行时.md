# 扩展局部性受保护树是否纳入宿主运行时

> 待裁讨论稿。`EX-002` 判「新增能力只改自己目录」，受保护树是 `D-372` 定的五棵并集；
> `symbio-host` 是唯一持有驱动族唯一 runner 的架构层，却不在并集里。本条只把现场、
> 约束、可选走法与待裁问题摆齐：不写裁决，不动代码与判据，不登记任务。

## 现场

- 受保护树的唯一一份是 `scripts/capability-migration-audit.mjs` 的 `PROTECTED_TREES`，
  由机制面 `ARCH_TREES` 与控制面 `CONTROL_TREES` 取并集，`scripts/extension-locality-audit.mjs`
  的 `TREES` 直接引用它（`D-372`）。`symbio-host` 不在两份常量里。
- `symbio-host` 的职责是发现族行、按会话起驱动、把债表当数据读；它对驱动族强制唯一
  runner（多一个直接返回装配失败）。插件不依赖它，但「加能力不碰架构面」因此留了一条
  可机读的缺口：一个新增能力包的提交可以顺手在 host 里加一行按能力名分支，五棵树指纹
  不变，`EX-002` 判绿。
- 历史实测（本条开工前的只读回放）：判据起点之后所有新增 `PLUGIN.yml` 的提交，逐条
  检查 `crates/symbio-host` 的改动，触碰数为 0。按新口径回溯不会判红这件事有实测依据，
  不是「为了让门禁绿」的推测。
- `DE-051 §0` 写三棵树、`DE-002:164-166` 写四棵，`D-372` 自陈同一判据曾三处三套口径。
  加严时若不把这些正文一起收口，会再造一次分叉。

## 一句话张力（裁决前的问法）

「加能力不碰架构面」里的架构面，是**能力能看见的门面**，还是**系统跑起来的那一层**？
前者已由五棵树守住，后者还留着唯一 runner 的持有者没有判据覆盖。把 host 纳入是加严，
代价是历史提交要按新口径回放；不纳入的理由若是「纳入后要补豁免、现在门禁正绿」，
那是实现成本，不是架构判据。

## 既有约束（本条不重审）

- `DE-002 §4`：架构面（切分 / 封闭集合）不得妥协，额度只够用在「怎么写」。
- `CS-002` / `D-278`：收窄不需要批准，变宽需要论证；但**树名单是判据面**，改它属架构
  调整，按「架构改动只认方案为源」必须先落裁决，裁决落定后再动脚本与回归用例。
- `D-372`：受保护树取并集、少一棵就留一条路；名单只有一个 owner。
- `D-474`：判据自守的线不占任务账——本条不新开施工任务，裁决与施工按批次分开。
- `SP-003`：门禁全绿是每批提交的唯一出口；不把红灯带入库。

## 可选走法（都不在本条开工）

| 走法 | 做什么 | 会牵动什么 / 已被判过的墙 |
|---|---|---|
| 甲 · 纳入并集 | `PROTECTED_TREES` 加 `crates/symbio-host`，`TREES` 自动跟随；回归用例与门禁注释同步 | 判据覆盖面加严；`ARCH_TREES` / `CONTROL_TREES` 不动（迁移批次的机制面口径不变） |
| 乙 · 单独一条 host 守卫 | 不动 `PROTECTED_TREES`，另建一个只判 host 的审计 | 同一命题两份判据，`D-372` 已否掉「三处三套」的形态 |
| 丙 · 维持五棵 | 在文档里说明 host 由唯一 runner 的代码级硬约束守住，不进判据 | 代码约束拒绝第二个驱动，拒不了「加一行按能力名分支」，缺口仍在 |
| 丁 · 把 host 并进机制面 | 让迁移批次的机制面口径也包含 host | 会改 `EX-007` 的净变化判据与补件判定面，属改另一条判据，超出本条范围 |

## 待裁问题

1. `symbio-host` 是否属于「能力不该碰」的面？判据按 `DE-002` 的架构面定义，还是按
   「插件是否依赖它」？两者在 host 上给出相反答案。
2. 历史提交如何处置：既然只读回放证明零回溯判红，还要不要为口径再加严预留
   `BEFORE_GUARD` 条目？还是按「名单只减不增」一条不加？
3. 纳入后 `EX-002` 的正向夹具 `f5e4bbed` 与回归用例怎样证明新覆盖面真的会红——
   是把 `judgeNewCapability` 的注入用例扩到六棵树，还是补一条专门点名 host 的反向用例？
4. `DE-051 §0` / `DE-002:164-166` / `D-372` 三处名单口径收敛到谁？按「一个事实一个
   owner」，正文是否只写常量名与裁决号、不再抄树名单？
5. 纳入 host 是否改变 `EX-007` 迁移批次的判定面？若不变，如何在裁决里写清「受保护树」
   与「机制面三棵树」是两件事，避免后来者把它们合并？

## 不做什么

不改 `scripts/capability-migration-audit.mjs` / `scripts/extension-locality-audit.mjs`；
不新增 `BEFORE_GUARD` / `GRANDFATHERED` 条目；不登记施工任务；不在本条写裁决。
裁决落定后另开批次。
