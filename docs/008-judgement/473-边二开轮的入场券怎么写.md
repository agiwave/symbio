# 边二开轮的入场券怎么写

> 归属：退役线的最后一条施工边。`D-451` 把边二的出口写成「装配变成数据贡献，
> session 不再需要 turn 钩子」；`D-457` 把施工对象改名为开轮。本条量出现场后裁决：
> **这个出口问的是贡献面，而贡献面今天已经成立**——边二没有可施工对象，施工边
> 全部闭合，退役线只剩冻结账守成（2026-11-12 裁定，标准：更符合最终目标态、
> 架构与分工更合理 / 简单）。

## 现场（今天的代码形状）

- 开轮在 `crates/symbio-plugin-session/src/plugin/turn.rs` 的 `consume_item_turn`：
  十步里三步是装配（收集能力、发布 agent 作用域、折 `session.config`），其余是写格
  （收件箱队首、`user.message`、`turn.dispatch`、`session.recall`、`session.config`、
  转写 append、状态发布）。装配本身**不落事实**；落格全走
  `crates/symbio-plugin-session/src/store/fact_source.rs` 那一个开面。
- `session.config` 的幂等键由 `user.message` 的事实 id 派生（`session_config_id`），
  `produced_by` 是那条事实的 seq——这是 `D-457` 判「装配换 owner 语法上不成立」
  的依据。读方在 `crates/symbio-plugin-model/src/port.rs`（`system_prompt`、
  `tools`、`tool_aliases`）、`plugin-classify` / `plugin-compose` /
  `plugin-conation` / `plugin-skill`（各自的能力开关），以及
  `scripts/obligation-ring-accept.mjs`。
- `symbio-plugin-loop` 今天是**纯机制环**：`crates/symbio-plugin-loop/PLUGIN.yml`
  自述不再导出任何跨插件事件名，`crates/symbio-plugin-loop/src/vocab.rs` 只剩两条
  机制私有名；它经 `traverse` 只交一行 `drive_row`，由 `symbio-host` 从 `drive` 族
  取出并调 `drive(support)`。session 与 loop **不直接互调**：session 写事实 ⇒ 事实源
  append 踢宿主 ⇒ 宿主调环。
- 环的行表 `crates/symbio-plugin-loop/src/ring/table.rs` 的 `DebtRow` 带 `when`、
  `when_id`、`unless`、`after` 等数据格：「这一步做过没有」在原则上可以表达成一条
  事实的在场，不必加第二份状态——与 `D-107` 的前件同形。
- `D-440` 之后 session 的**能力面**是零：工具零条、端口零条，prompt 正文来自各插件
  的 PROMPT 行；`declarations.rs` 交的是 `events` / `facts` / `rows`，`ports`、
  `views`、`actors` 三格为空。`traverse` 里 `visitor.put(...)` 的全集是选项行与几条
  `debt_row`，全是数据。`D-460` 把这条线的终态改判为「能力面归零 + 数据面与地址面
  随身份留下」，并定性豁免账为不设归零的冻结账。

## 一句话张力（裁决前的问法）

「装配变成数据贡献」在**贡献面**今天已经是事实：session 交出去的全是数据行，它不
贡献能力。剩下没变的是 `turn.rs` 里那段**自己的**开轮编排——它不是对环的贡献，
而是写自身存储的调用点。于是「由 loop 侧接住」这句要先答：接的是**贡献面**（已经
接住了），还是**开轮这段编排本身**（那会同时碰到 `D-458` / `D-459` 判「存储与
地址面随身份留下」，以及 `SRA-004` 盯的「事实源开面恰好一家」）？两者混在一句
exit 里，「还差什么」就永远读不清。

## 裁决

1. **出口问的是贡献面——而它已经成立。** 「装配变成数据贡献」在 `D-440` 之后就是
   今天的现场：session 贡献出去的全是数据行，turn 钩子里不再有**能力**（工具零条、
   端口零条）。出口里「session 不再需要 turn 钩子」这半句从此读作「不再需要 turn
   钩子里的**能力贡献**」——不是「turn.rs 这个文件消失」。
2. **开轮编排是数据面的一部分，随身份留下。** 十步里的写格走的是 session 自己的
   存储开面，存储不能换 owner（`D-458`：会话记忆与存储是会话数据本身）；装配在
   身份上依附开轮（`D-457`：幂等键与 `produced_by` 都从它派生）。把编排搬去任何
   一方，都是在搬**已经判过随身份留下的数据面**。`turn.rs` 自己编排自己存储的写
   入，就是「数据面随身份留下」的形状——**边二没有可施工对象，不登记任务**。
3. **拒绝「甲 · 把开轮表达成环的行数据」，理由记档。** 按最终目标态与架构简单度
   两条标准：① 甲要给十步里没有事实可读的步**新增事件格**——机制变更，且那些步
   写的是 session 自己的存储，环要执行就得经 `drive_entry` 写进 session 的存储
   语义，「loop 认得 session」只是换了写法；② 编排知识并没有消失，只是被重编码成
   第二份表示（行数据 + 环的解释执行）——**同一份顺序知识两处持有**，恰是
   「一个事实一个 owner」反对的形状；③ `D-445` 不许两条路径并存，而行数据执行
   与 turn 钩子在过渡期必然并存。乙（整单元搬进 loop）撞 `D-457` 与 `SRA-004`
   的唯一登记点；丙（只折 `session.config`）被 `D-457` 判语法上不成立；丁（宿主接）
   被判控制面知识往上堆。四条都有墙，且都比现状复杂。
4. **`D-451` 的表就地修正一处**（与 `D-456` / `D-457` / `D-459` / `D-460` 同法）：
   边二行状态「未界定」改为「**闭合（D-473）**」。施工边（二）与两条改判边
   （一读数 / 三验收条件）就此全部定性完毕：**退役线从此没有施工边**，只剩符号
   冻结账守成（只许降）与边四读数线。`D-081` 的三问验收式不变——
   下一次任何一边被动到时照跑，本条没有施工，无须重跑。

## 不做什么

不登记施工任务；不改 `crates/symbio-plugin-session/src/plugin/turn.rs`、
`crates/symbio-plugin-loop/` 下任何文件、不改 `PLUGIN.yml` 与声明面；不动
`submit_fact_source_opener!` 的登记点；不给开轮补「已做」事件格。边二闭合后这条线
的剩余动作只有：冻结账随取字同源逐格收窄（只许降）、门禁守成、以及边四读数线上
`D-472` 施工批的判据接通。
