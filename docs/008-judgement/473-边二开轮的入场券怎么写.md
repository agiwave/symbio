# 边二开轮的入场券怎么写

> 待裁讨论稿。`D-451` 把边二的出口写成「装配变成数据贡献，session 不再需要 turn
> 钩子」；`D-457` 把施工对象改名为开轮。退役线账本里这条边是三条边中**唯一还标着
> 施工可能**的一条，而它的入场券被记为「需要 loop 侧接住」。本条只把现场、张力、
> 可选走法与待裁问题摆齐：不写裁决，不登记任务，不动代码。

## 现场（今天的代码形状）

- 开轮在 `crates/symbio-plugin-session/src/plugin/turn.rs` 的 `consume_item_turn`：
  十步里三步是装配（收集能力、发布 agent 作用域、折 `session.config`），其余是写格
  （收件箱队首、`user.message`、`turn.dispatch`、`session.recall`、`session.config`、
  转写 append、状态发布）。装配本身**不落事实**；落格全走
  `crates/symbio-plugin-session/src/store/fact_source.rs` 那一个开面。
- `session.config` 的幂等键由 `user.message` 的事实 id 派生（`session_config_id`），
  `produced_by` 是那条事实的 seq——这是 `D-457` 判「装配换 owner 语法上不成立」
  的依据。读方在 `crates/symbio-plugin-model/src/port.rs`（`system_prompt`、
  `tools`、`tool_aliases`）、`plugin-classify` / `plugin-compose` /
  `plugin-conation` / `plugin-skill`（各自的能力开关），以及
  `scripts/obligation-ring-accept.mjs`。
- `symbio-plugin-loop` 今天是**纯机制环**：`crates/symbio-plugin-loop/PLUGIN.yml`
  自述不再导出任何跨插件事件名，`crates/symbio-plugin-loop/src/vocab.rs` 只剩两条
  机制私有名；它经 `traverse` 只交一行 `drive_row`，由 `symbio-host` 从 `drive` 族
  取出并调 `drive(support)`。session 与 loop **不直接互调**：session 写事实 ⇒ 事实源
  append 踢宿主 ⇒ 宿主调环。
- 环的行表 `crates/symbio-plugin-loop/src/ring/table.rs` 的 `DebtRow` 带 `when`、
  `when_id`、`unless`、`after` 等数据格：「这一步做过没有」在原则上可以表达成一条
  事实的在场，不必加第二份状态——与 `D-107` 的前件同形。
- `D-440` 之后 session 的**能力面**是零：工具零条、端口零条，prompt 正文来自各插件
  的 PROMPT 行；`declarations.rs` 交的是 `events` / `facts` / `rows`，`ports`、
  `views`、`actors` 三格为空。`traverse` 里 `visitor.put(...)` 的全集是选项行与几条
  `debt_row`，全是数据。`D-460` 把这条线的终态改判为「能力面归零 + 数据面与地址面
  随身份留下」，并定性豁免账为不设归零的冻结账。

## 一句话张力

「装配变成数据贡献」在**贡献面**今天已经是事实：session 交出去的全是数据行，它不
贡献能力。剩下没变的是 `turn.rs` 里那段**自己的**开轮编排——它不是对环的贡献，
而是写自身存储的调用点。于是「由 loop 侧接住」这句要先答：接的是**贡献面**（已经
接住了），还是**开轮这段编排本身**（那会同时碰到 `D-458` / `D-459` 判「存储与
地址面随身份留下」，以及 `SRA-004` 盯的「事实源开面恰好一家」）？两者混在一句
exit 里，「还差什么」就永远读不清。

## 可选走法（都不在本条开工）

| 走法 | 做什么 | 会牵动什么 / 已被判过的墙 |
|---|---|---|
| 甲 · 把开轮表达成环的行数据 | session 只贡献一组 `DebtRow`，环按 `when` / `unless` 现读；开轮十步的「已做」逐条落为事实 | 与 `D-107`「先事实、后循环」同形，方向最正。但十步里有七步是**写自身存储**，环要写就得经宿主的通用写口 `drive_entry`；每一步都要有一条可读的「已做」事实，`D-107` 的前件今天是否齐备须逐条量。`D-445` 不许两份注册事实，不许两条路径并存。 |
| 乙 · 整个开轮单元搬进 loop | 把 `consume_item_turn` 与收轮投影连同 inbox 触发一起挪走 | `D-457` 已判装配身份依附开轮；`D-458` / `D-459` 判存储与地址面不换 owner；搬动必然碰 `submit_fact_source_opener!` 的唯一登记点（`SRA-004` 会响）；宿主会认控制面知识，`D-457` 的「不做什么」已否掉这个方向。 |
| 丙 · 只折 `session.config` 那一步 | 把 config 折叠单独搬走，三条开轮事实仍由 session 写 | `D-457` 第 3 条明确判「语法上不成立」：幂等键与 `produced_by` 都依附开轮，搬走的一半算不出自己的键。 |
| 丁 · 由宿主接 | 不动 loop，把折叠放宿主 | `D-457` 已否：宿主会因此认识工具行、端口族与 wire 别名规则，是控制面知识往上堆。 |
| 戊 · 判定边二没有可施工对象 | 不登记任务；把「装配变成数据贡献」改判为「贡献面已归零，开轮是数据面的一部分、随身份留下」，与边三 / 地址面同列 | 施工边全部闭合，只剩 `D-460` 的冻结账守成。代价是 `D-451` 的边二出口要改判，且必须写清「turn 钩子」这四个字今天指的是自己的内部编排、不是能力贡献——否则那句话会一直被读成欠账。 |

## 待裁问题

1. 「装配变成数据贡献」问的是**贡献面**还是**编排面**？前者今天已成立（`D-440`），
   后者要动开轮。这两者不能混在一句 exit 里。
2. 若选甲：开轮十步里，哪几步的「已做」已经有事实可读？没有的那几步是**新增
   事件格**（机制变更，按 `D-107` 须单独裁决），还是可以用现有的
   `user.message` / `turn.dispatch` / `session.config` / `session.recall` 覆盖？
3. 若选甲：环经 `drive_entry` 写 session 的存储，算不算「loop 认得 session」？
   判据落在哪一层——是 `EX-007` 的插件名字面量，还是「写口的 owner 只有一个」？
4. 若选戊：退役线从此没有施工边，`D-451` 的表与 `DE-054` 的边二段怎么改 owner
   而不留下第二份复述？`D-460` 的冻结账是否就是这条线的终态？
5. 无论选哪条：`D-081` 的三问（`D-458` 定性为验收条件）在动过之后要重跑一遍；
   这一步由谁登记？

## 不做什么

不登记任务；不改 `crates/symbio-plugin-session/src/plugin/turn.rs`、
`crates/symbio-plugin-loop/` 下任何文件、不改 `PLUGIN.yml` 与声明面；不动
`submit_fact_source_opener!` 的登记点；不把 `D-451` 的边二出口当作已经改判。
裁决落定后另开批次。
