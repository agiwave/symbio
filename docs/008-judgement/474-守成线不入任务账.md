# 守成线不入任务账

> 归属：退役线（`D-451`）的账务形态裁决。施工边全部闭合（`D-473`）、边一改判读数
> （`D-456`）、豁免账定性为不设归零的冻结账（`D-460`）之后，这条线剩下的唯一「在办」
> 条目是一个没有施工动作的守成任务。本条裁定：**判据自守的守成线不占任务账**——
> 账本就是现场，判据就是守卫，不需要一个任务文档当容器（2026-11-12 裁定）。

## 现场（今天的形状）

- 退役线的四条边全部定性完毕：边二是读数（`D-456`）、边二（开轮）闭合且无可施工对象
  （`D-473`）、边三是验收条件（`D-458`）、边四第三格的判据已接通对账闭合（`D-471` /
  `D-472` 施工批按 RG-031 收口）。施工边为零。
- 边一的冻结账（`scripts/exemptions/plugin-session-sdk.json`，51 条）由五条判据自守：
  `SRA-001` 零余量即摘、`SRA-002` 只许降、`SRA-003` 豁免三字段自洽、`SRA-004` 事实源
  开面单槽、`E-009` 不得新增——每一条都是门禁里的红绿判据，不依赖任何任务文档存在。
- 冻结账的 `knife` 字段指着一个持刀任务号。`SRA-003` 的设计**早已预留**了这个场景：
  它不判 `knife` 是否存活（任务按「收口即删」消失是常态，把存活写进判据会让两阶之间
  永远红），只接受 `T-NNN` 或 `D-NNN` 两种登记号、并在报告里打印出来供人确认主人。
- 任务账里留下的这个条目没有任何可做之事：账只随代码搬走 / 取字同源而降，每一步
  降格都发生在别的施工批里、由那批的提交与判据记账。任务文档自己不动手。

## 一句话张力（裁决前的问法）

「冻结账守成」登记成一个 `doing` 任务，读出来像「这条线正在推进」；实际上它的每一格
进度都由别的施工批贡献，任务文档只负责「记得有这条账」。可是「记得」这件事判据已经
做了——账本文件在门禁里、复核日写在 `expires`、保留依据写在 `retire`。一个既无施工
面、又不承担记忆职责的 `doing` 条目，就是 `D-451` §3 反对的「以后再说」的假计划，
只是换了个方向：不是「写不出入场券就登记」，而是「施工面写完了，任务却赖着不走」。

## 裁决

1. **无施工面的守成线不占任务账。** 判据能自守的账，不需要任务文档当容器。任务账
   的条目必须有可执行的动作；守成动作（跑门禁、看读数）不属于任何一条任务，属于
   每一次施工批的收尾纪律。
2. **冻结账的主人换成裁决号。** `knife` 从持刀任务号改指 `D-460`——保留依据、
   复核日（2027-06-30）与「随身份保留」的定性都由它给出；裁决不随任务收口消失，
   比「主人是个已删文件」稳定。`SRA-003` 的通道本就为此预留，判据逻辑零改动。
3. **持刀任务按 RG-031 收口删除。** 两份任务文档的结论早已住在判定与设计文档里
   （`D-451` / `D-456` / `D-458` / `D-459` / `D-460` / `D-473` 与各自的施工批决策），
   删文档不删知识；任务索引随登记投影自动收敛。
4. **复核机制不变。** 2027-06-30 复核日是 `SRA-003` 盯着的日期，不是任务清单上的
   到期项——到点重新裁决的是账的定性（`D-460`），本条只裁决「谁持有它」。

## 不做什么

不动豁免账的符号面与判据逻辑（`session-retire-audit` 只改夹具字面量与真实账的
`knife` 一处）；不把「跑门禁」「复核豁免账」登记成新任务；不提前删除或续期冻结账
——`expires` 仍是 2027-06-30 复核日，本条与它无关。
