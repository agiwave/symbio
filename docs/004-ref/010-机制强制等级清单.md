# 机制强制等级清单

> 本文回答一个问题：**每条机制违规时，谁会红？**
>
> 它是「强制等级」这件事的唯一 owner。判据本体在同一目录的守卫脚本
> [`scripts/mechanism-enforcement-audit.mjs`](../../scripts/mechanism-enforcement-audit.mjs)
> （ME-001–005），本表只记**谁在执行**——执行细节住各自的守卫脚本与生产代码，
> 这里不复述规则（第二份规则必然漂移）。

## 0. 怎么读

三个等级按「约束的实际兑现方式」分，不按「设计意图」分：

| 等级 | 含义 | 典型形态 |
|:-:|---|---|
| ① | **编译期强制**：违规编译不过 | 类型 / 泛型边界 / 枚举穷尽 |
| ② | **运行时有执行方**：违规当场产生**具名信号**——两种形态之一：拒绝（错误返回）或显式降级（当场出声 + 一个可判读的读数承接同一事实） | 闸门 / 守卫 / 白名单校验；降级面 = 写入口 `warn` + 计数 + 读侧同一判据 |
| ③ | **纯声明**：规则写了，**没有任何人判**——违规与不违规产生不出可区分的读数 | 文档 / 配置 / 默认值 |

「拒绝」与「显式降级」的分别由机制所在域决定（写侧完整性只能拒，恢复形状拒了会钉死会话），
**本表不规定方式，只规定有没有**——判据与这条口径的裁决见
[D-113](../003-design/002-架构总览.md "DE-002-架构总览")；只打日志、没有任何读数承接同一条事实，仍算 ③。

三条边界（不随条目增长放宽）：

1. **豁免有上限**：③ 类条目数超过 `MAX_EXEMPTIONS` 即红——否则「全部挂豁免」等于没有清单；
2. **豁免带期限**：每条豁免指向一个承载它的任务编号或决策，解析不出即红；
3. **清单是判据的索引，不是判据本身**：执行细节住各自的守卫脚本。

③ 与「还没做」不是同义词：③ 是**已经承认的缺口**，必须挂 `mechanism-allow`
（见 §7）。从一个 ③ 变成 ①② = 在豁免块里删掉那一行，同时把执行方填进 §1–§5。

## 7. 豁免（③ 纯声明）

一行一条，格式 `mechanism-allow <机制键>: <决策编号或任务编号> <理由>`。
③ 类行**没有对应豁免 ⇒ 红**；①② 类行**带豁免 ⇒ 红**（等级与豁免必须一致）。
理由不可为空；总数超过 `MAX_EXEMPTIONS`（守卫脚本内）即红。

```mechanism-allow
```

上面**一条豁免都没有**，是因为清单里再没有「纯声明」行：`声明·Agent 权限` 随四字段
执行面落地升上 ②（域名出站前判 / glob 路径入口判 / 限额装载期判，
[D-153](../003-design/011-Agent目录规范.md "DE-011-Agent目录规范")），其余四条
（`I2` / `I3` / `闸·入站边界` / `投影签名·降级与预算消费`）各有执行方，按 §0 的等级判据
落在 ②——豁免是缺口的登记表，缺口补上后还留着它，清单就会永久低估自己。
`I3` 与投影那两条的形态是**显式降级**而不是拒绝，这条口径的裁决见
[D-113](../003-design/002-架构总览.md "DE-002-架构总览")。
