# Symbio 投影映射（§8 取值 ↔ 代码模块）

> **文档类型：参考（手写）** — 左列的唯一 owner 是 [DE-001 §8](../003-design/001-核心架构.md "DE-001-核心架构") 的
> `projection` 行；本表只回答「这个取值在代码里由谁承接」，不复述取值域，也不判取值。
>
> **为什么需要这张表**：同一层存在两套名字。§8 的取值是**事件里能写的视图名**，`symbio_core/projection/`
> 里的是**实现文件**，两者不一一对应（`budget` 由 `cost.rs` 承接、`replay` 由 `rebuild.rs` 承接、
> `conation` 有文件却没有第二处声明）。这些对应关系此前只写在各自文件头的散文注释里——
> 读得到、机器读不到，于是没人能证明它没漂。
>
> **守卫**：[`doc-symbol-audit`](../../scripts/doc-symbol-audit.mjs) 的 **D-014** 三方对账——
> §8 的取值集合 ↔ 本表的两张表 ↔ 真实目录。加取值不填表、加模块不归类、填了不存在的文件，任一即红。

## 1. §8 的 14 个取值，各自由谁承接

| §8 取值 | 承接方 | 形态 | 一句话 |
|---|---|---|:-:|
| `readyset` | `projection/readyset.rs` | 模块 | 就绪判定（`非终态 ∧ depends_on 全部终态`），纯函数 |
| `turnstate` | `projection/turnstate.rs` | 模块 | 平凡值链的终点：轮态是最小的「有状态可读」 |
| `checkpoint` | `projection/checkpoint.rs` | 模块 | 可序列化的检查点（J3：序列化失败有信号） |
| `eval` | — | 平凡值 | 平凡值本身就是「不启用任何投影」，故无文件——这一行是 §8 的自指，不是缺实现 |
| `recall` | `projection/recall.rs` | 模块 | 长期记忆的检索与排序；排序内核 `recall_score.rs` 与 verify 共有 |
| `consolidate` | `projection/consolidate.rs` | 模块 | 巩固的接受边界（架构只给位置，不给算法） |
| `reputation` | `projection/reputation.rs` | 模块 | 声誉 = 从同一份事实源算出的投影，不是一套机制 |
| `calibration` | `projection/calibration.rs` | 模块 | 技能的使用次数 / 回退次数，校准观测 |
| `budget` | `projection/cost.rs` | 模块（异名） | 成本台账。实现名 `cost`——`budget` 一词让给 view 域的 `Budget`（记账口径） |
| `replay` | `projection/rebuild.rs` | 模块（异名） | 回放重建：事件网格 → `ChatNode` 节点树（D-049 的读侧真源）。文件没沿用 `replay` 这个名字 |
| `skill_compile` | — | 写侧函数 | 该批 裁决：写侧函数 + 开关，没有读侧投影，因此没有文件 |
| `conation` | `projection/conation.rs` | 模块 | 「欲」的读侧形态：表达了哪些欲、各自有没有升格成任务 |
| `snapshot` | — | 会话侧 | 压缩快照是会话上下文产物（`plugins/loop/context/pipeline.rs`），不是 core 投影 |
| `display` | — | 已裁决不做 | 该批 裁决：产物进上下文是目标形态；UI 侧渲染是 `rebuild.rs` 的节点重建，不是投影 |

**读法**：`形态 = —` 的三行不是「待办」，是**已裁决的现状**；凡将来落地，把 `—` 换成模块路径即可，
D-014 不会因此变红（它判的是覆盖，不判「必须实现」）。

## 2. 没有 §8 取值的模块

`symbio_core/projection/` 里不是每个文件都对应一个 `projection` 取值——它们分三类：

| 模块 | 类别 | 职责 / 为什么不进 §8 |
|---|---|---|
| `projection/mod.rs` | 目录 | trait 与冻结锚点 F2（构造形状），不是某个视图 |
| `projection/recall_score.rs` | 内核 | `recall` 的排序实现，被 `recall.rs` 调用；与 `verify/recall_eval.rs` 共有 |
| `projection/autonomy.rs` | 读数口 | [DE-008 §3.1.1](../003-design/008-能力注册表与能力坐标系.md "DE-008-能力注册表与能力坐标系")「自主程度」的复算口径——报数，不建视图 |
| `projection/span.rs` | 读数口 | 同表「时域跨度」的复算口径——报数，不建视图 |
| `projection/slo.rs` | 统计列 | SLO §1.2 时延列的统计口径（`chat.assistant.final` 的 `cost_ms`） |
| `projection/fallback.rs` | 统计列 | SLO §1.2 兜底率列的统计口径 |
| `projection/turns.rs` | 水位 | 轮次水位（含压缩快照的 `turns`），session 与 loop 读同一份口径 |
| `projection/transcript.rs` | 读视图 | 对话转写，`Reasoner` 组 prompt 的输入 |
| `projection/mutations.rs` | 索引 | 消息列表变更的读侧索引（D-053） |
| `projection/prompt_fidelity.rs` | 判据 | 事实网格 → prompt 的双向完整性判据（D-048） |

**为什么它们不该有取值**：`projection` 取值描述的是「有哪些视图可以被指名启用」。读数口、统计列、
水位、判据都是**无条件存在**的读侧函数——没有「不启用」的形态，自然也不需要被登记成一个取值。
把这类文件塞进 §8，等于让 `projection` 行同时表达两种东西，守恒律就失效了。
