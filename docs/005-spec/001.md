## 规范

每篇文档是**一个带 front-matter 的单文档**：front-matter（受限 YAML 子集）承载机读字段，
正文承载人读内容。**文件本身就是条目**——没有第二处登记表。

**全仓一套编号规范**（形状判据 RG-022，代码侧真相在 `registry-lib` 的 `loadKinds` / `entryIdRe`——前缀与形状由各 kind 的 README meta 自描述）：

| 形态 | 判定 | `id` = | 例子 |
|---|---|---|---|
| 编号条目 | 各 kind 的全部条目 | `<前缀>-<三位序号>[-名称]`；**落点两种等价**：平铺 `008.md`（文件名 = 去前缀主干）或目录 `008/README.md`（目录名 = 去前缀主干） | `` 住 `docs/007-task/008.md`；`DE-001-核心架构` 住 `docs/003-design/001-核心架构.md` |
| 导航文档 | 各目录 `README` 与仓根门户页 | 仓根相对路径（去 `.md`） | `docs/README` 住 `docs/README.md` |

前缀一 kind 一个，**闭集住各 kind 目录 `README.md` meta 的 `prefix` 字段**（本条不复述——
机制从 meta 读）。**前缀与 kind 对账**（RG-022）：
`plan` 的编号必须 `PL-` 开头——编号空间才可盲信。**导航文档不发编号**（通用名没有编号段、
不构成命名空间），也**不进 `deps`**（RG-023：依赖图只收编号条目，要指它用 `[[...]]` 引用）。
**分解关系不进编号**：父子分解走 `parent` 字段（见[分解：parent](#分解parent父子机制)），
编号保持平铺——层级是投影（README 汇总块分解树 / board `--children`），不是身份。

**目录不参与判定**：`kind` 只来自 front-matter，没有「`kind` 必须与目录一致」这条判据——
规范化的目录（`docs/<kind>/` + 模块文档就地）是组织习惯，文档换目录不破机制。
换目录的唯一义务是**把身份一起改**（编号条目：文件名或目录名；导航文档：`id`），两条都是两面对账
（RG-003），文档类另对 `title` 与首个 H1（RG-021）。

### 受限 YAML 子集（零外部依赖，只认以下形状）

- 首行 `---` 起始、`---` 闭合；键形如 `key: value`（取第一个冒号之后整段为值）；
- **值必须与键在同一行**：块标量 `|` / `>` 与缩进续行都不在这个子集里——续行会被当成
 一个没有冒号的行，按 RG-001 判红（**宁红不漏**，不会静默丢掉半截值）；
- 整行注释以 `#` 开头；**行内 `#` 属于值的一部分**，不剥离；
- 值四种形态：裸标量、`"..."` / `'...'`（去外层引号，不支持转义）、
 `[]` / `[a, b]` 行内列表、键后换行的 ` - item` 块列表；
- 未知字段、重复字段、不合形状的行一律判红（RG-001）——**宁红不漏**，
 拼错的字段名不会被静默忽略。

### 状态词（闭集由各 kind 自声明，本节只立规则）

状态词是**闭集**，由**各 kind 目录 `README.md` meta 的 `status.*` 键自声明**（装载进
`statusRules`）——本文不复述任何 kind 的状态词表：kind 有几类、每类几个状态，是各处
自注册后**统计出来的事实**，写进规则必然漂移。判定方是 RG-004（状态词不在该 kind 的
闭集即红）。

对所有 kind 成立的**规则**只有两条：

- **`status` 只管「还算不算数」**，不承载进展；「做到哪一步」必须另立字段（见 `impl`）。
 把进展压进状态词的自由文本（「现行（含未完成项）」）会让机读面表达不出最常见的中间态。
- **状态 × 字段矩阵**（谁必须填、谁必须空）的执行方是装载后的 `statusRules`
 （`status.<词>.require` / `.forbid`）——同样住在各 kind meta，冲突时以装载结果为准。

### 正文小节

必备小节由**各 kind README meta 的 `sections` 声明**（RG-009 缺一即红）；声明为空 =
没有必有小节（文档类如此——正文结构由文档自己定，按 kind 强切只会逼出空壳小节）。
各小节承载什么，随声明住在各 kind 自己的 meta / README，本文不复述。

对所有 kind 成立的**规则**：**状态只在 front-matter**——正文里复述状态（「已完成」
「部分实施」之类的叙述列）是第二处状态，必然漂移；进展由字段档位承载，不由小节承载。

### 引用别的文档：只写编号（地址由机制生成）

正文引用其它已登记文档时，人**只写编号**：`[[编号]]`；要显示文字写 `[[编号|显示文字]]`，
要锚点写 `[[编号#小节]]`（可组合）。链接地址由
[`gen-doc-refs`](../../scripts/gen-doc-refs.mjs) 从登记解析生成并在每次门禁重算
（已展开的地址也重算，RF-002）；引用不存在的编号判红且不写盘（RF-001）；
指向已登记文档的手工地址（既无编号标签、也无编号标题）判红（RF-003）。
**不手写、也不维护站内地址**：身份在链接文字或链接标题（两者其一是编号），
地址是位置（会变）——机制见 [DE-017 §1.1](../003-design/017-登记与汇总机制.md "DE-017-登记与汇总机制")。
行内代码段里的 `[[…]]` 是字面量，不展开。

### 优先级与取代

- `prio` 是**排序提示**（`now / next / later`，缺席 = 最低档）：只影响同一拓扑层内的排序，
 拓扑序（`deps`）永远在前——`deps` 是义务（事实），`prio` 是提示（判断）。
- `supersedes` 是**显式取代链**：同 kind 之间不允许两条**生效档**条目矛盾并存，消解方式是
 一条改入**退场档**（`reason` 写明被谁取代 / 为何作废）——生效档 / 退场档由各 kind meta
 自声明，本文不复述词表。
 **取代关系只在同 kind 之间**（`spec↔spec`、`design↔design`），跨 kind 取代没有语义。
 **优先级不参与裁决**——分层裁决规则的 owner 是
 [DE-017 · 登记与汇总机制](../003-design/017-登记与汇总机制.md "DE-017-登记与汇总机制")，本文只登记字段。

## 字段

下表是全部合法字段的**封闭集合**——首列反引号键名的集合必须与代码侧 schema
（`registry-lib` 的 `allKeys`）恰好相等，不等即红（RG-011）。新增 / 删除字段必须
同时改这里与代码，两条腿一起走。**字段属于哪些 kind、是否必填、哪些状态档必须填 /
必须空，全部由各 kind 目录 `README.md` meta 的 `required` / `optional` / `status.*`
声明**（RG-001 / RG-002 / RG-007 执行）——本表只登记字段语义与判据，不复述这张对账面：
一个字段服务几个 kind、几个状态档用到它，是自注册后**统计出来的事实**，写进规则必然漂移。

| 字段 | 说明 |
|---|---|
| `kind` | **只来自本字段**（目录不参与判定），取值是 kind 闭集的一员（闭集由各 kind 目录 README meta 自注册） |
| `id` | 全局唯一（含跨 kind）；编号条目 = `<前缀>-<三位序号>[-名称]`，文件名 = 去前缀主干（RG-003 对账，RG-022 前缀对 kind）；导航文档 = 仓根相对路径 |
| `title` | 一句话标题；文档类必须**逐字等于正文首个 H1**（RG-021） |
| `status` | 状态词是该 kind 闭集的一员（闭集由该 kind meta 自声明，RG-004） |
| `created` | `YYYY-MM-DD`，登记日期 |
| `deps` | 前置编号列表，可跨 kind；`[]` = 无前置。**强制性机制、全部 kind 同一套**：目标必须是**编号条目**（id 不含 `/`，导航文档不进图——RG-023）；目标编号必须存在（RG-006）；条目进入生效档时前置必须已闭环（RG-008）——生效档与闭环态的定义由各 kind meta 声明（`requiresDepsDone` / `closedStatus`），裁决语义见 [plan/DE-017](../003-design/017-登记与汇总机制.md "DE-017-登记与汇总机制") |
| `parent` | 分解归属（父子树的边，单值）：子条目指向父条目编号。**只许同 kind**（分解是同类事物的大小之分：总目标→子目标、大任务→小任务、产品功能→子功能；跨 kind 关联走 `deps` 或 `[[引用]]`）；目标必须存在、不自指、不成环（RG-024）；父子状态档位单调——子生效 ⇒ 父生效、父退场 ⇒ 子退场（RG-025）。**编号平铺不体现层级**：层级是投影（README 汇总块分解树 / `board --children`），不是身份。语义与约束见[分解：parent](#分解parent父子机制) |
| `lists` | 本文**包含哪些清单**、各自是不是 `owner`（我维护它）。行内列表 `[id=role, …]`，role 闭集**只有 `owner`**（RG-026；`view` 已取消——投影重渲是把重复换个形态留下，生成的重复也是重复）；**同一个 id 只能有一个 owner**（RG-027，分工重叠即红）。**不写 = 本文不含任何清单**（单内容文档），不需要为「没有」额外声明。语义与动机见[清单归属 lists](#清单归属-lists-一份清单一个-owner) |
| `projection` | `true` = 这一页**有身份、没内容**：正文由渲染器决定，不是人写的。用于各 kind 的汇总页——它需要编号与 id 才能被 `[[…]]` 引用（否则指向它的是手写地址，机制搬不动），但条目 kind 会拖来该 kind 的状态机与必备小节，一份投影页满足它们没有意义。**豁免逐条列明**：状态词（RG-004）、状态×字段矩阵（RG-007）、必备小节（RG-009）、取代链 / 清除指认（RG-015/016）；**身份面一条不豁免**（front-matter / 编号形状 / id↔文件名 / created / title==H1 / 清单归属） |
| `track` | 轨 / 分组（自由短词，如 `meta`、`doc`） |
| `prio` | 排序提示 `now` / `next` / `later`（RG-014）；**只影响同层排序，不参与冲突裁决** |
| `where` | 落点：任务类指涉及的文件 / 章节（**可指向尚不存在的文件、不判存在性**）；决策类是**指认**正文所在分册，指认的文件必须存在（RG-012） |
| `exit` | 出口判据；其中反引号的 `docs/` `scripts/` `e2e/` 指认必须存在（RG-012）。**写路径时要写当前位置**：地址随文件搬走而变，机制只重算「标签是编号的站内链接」，不认自由文本里的路径 |
| `signal` | 问题核实快照（坏状态的证据）；进入闭环态后必须清空（状态×字段矩阵由该 kind meta 声明） |
| `evidence` | 完成证据（提交 / 守卫锚）；只在闭环态必填、闭环态之外不得填（同上，由该 kind meta 声明） |
| `reason` | 不做 / 废止的理由；仅在退场态必填（同上，由该 kind meta 声明） |
| `scope` | 适用范围（一句话） |
| `supersedes` | 显式取代链（RG-015）：目标必须存在且**同 kind**，不得与自己同为闭环态、不得成环 |
| `clears` | 清除任务编号（RG-016）：目标必须存在且为 `task`；**不要求闭环**——豁免挂在开放的清除任务上是合法语义（`deps` 是前置，`clears` 是指认） |
| `impl` | 落地进展（RG-017）：`planned` / `partial` / `done`，或 `none`（未落地 / 作废）。**与 `status` 正交**——`status` 管算不算数，`impl` 管做到哪一步。**档位必须可解释**（2026-10-13 全量复核确立）：`done` 要指得出落地锚；`partial` 的**每处残余**要指得出归属（承载它的任务编号，或在正文里写明还差什么）——「`partial` 却没人解释还差什么」是**登记瑕疵**，不是合法的中间态 |

### `deps` 的值域与语义（严格约束——它是依赖图的边，不是叙述）

`deps` 的每个元素是一条**边**，供程序建图，书写不受阅读习惯影响：

- **值 = 确切编号**：元素必须是登记体系里存在的**编号条目** `id`（编号规范见上表）——
 导航文档（`README` / `INDEX`，id 含 `/`）不进依赖图（RG-023）：要指它用 `[[...]]` 引用。
 禁止别名、相对路径、散文、`§` 小节片段。猜写的编号判红（RG-006）：不存在「差不多指向」，
 悬空的边在门禁就红，不会留到运行时。
- **粒度 = 条目级**：编号指向整篇条目。「依赖某一节」没有机读载体——`§` 级指引走正文引用
 （`[[编号#小节]]`），不进 `deps`。
- **语义 = 集合**：顺序无意义（程序按拓扑序消费）；**书写按编号字典序**，使同一依赖集合
 只有一种写法，diff 稳定。重复元素判红（RG-006）。
- **推导 = 转写**：边来自本篇正文声明的「上游 / 前置」，转写为已登记编号。互相引用的伴生文档
 受不成环约束只保留一条边——这是 DAG 的机械要求（RG-006），不是逐篇的取舍；另一方向的
 引用留在正文。
- **强制 = 全员同套**：存在性 / 形状 / 不成环（RG-006）与生效档前置闭环（RG-008）对全部 kind
 同一套，文档类不特殊化——档位与闭环态定义见
 [plan/DE-017 · 状态流转](../003-design/017-登记与汇总机制.md "DE-017-登记与汇总机制")。

### 清单归属 lists 一份清单一个 owner

**问题**：「一个事实只有一个 owner」在 `docs/README.md` 里是一张**没人执行的承诺**——
它写着「不手抄，需要就引用」，而 D-001…D-010 查链、查措辞、查形态，**没有一条查
「同一份清单被两处各自维护」**。后果是实测出来的：`CURRENT.md` 内部并存过两张工具表
（行集交集 25/25），`RE-003` 与 `CURRENT.md §2.3` 各持一份路由地址，而两处**保证等级
还不一样**（一处「必然与代码一致」、一处「人工维护，因此也是唯一会漂移的一份」）。

`lists` 把承诺变成**可机读的声明**：每篇文档在 front-matter 里写它包含哪些清单、
每份是不是 `owner`（我维护它）。

```
lists: [routes=owner, tools=owner, vdfs-ops=owner] # 我维护这三份
# 不写 ⇒ 本文不含任何清单（单内容文档），不需要为「没有」额外声明
```

- **role 只有一个：`owner`**。曾有的第二个角色 `view`（只呈现/引用）已**整体取消**：
 这套机制的初衷是**消灭重复**——一个事实只在一个文档里出现，那篇文档就是它的 owner；
 而 `view` 是一条绕开重复的旁路（A 维护、B 投影重渲，「没有第二个手写 owner」成立，
 读者面前的事实仍是两份）。**生成的重复也是重复**，投影还会随 B 的组织需要越铺越大。
 想读另一份清单就**指路**（正文写 `[[编号]]`），不重渲。同理 `mirror`（镜像副本）
 永不给合法角色——镜像正是重复的别名。
- **同一个 id 只能有一个 owner**（RG-027）：两个 owner = 同一份清单两处各自维护，
 判红；零个 owner 同样判红（无主清单）。
- **id 是共享名词**，不是编号：两份清单内容不同就是两份清单，各起各的 id。

**边界（写明而非掩盖）**：这套机制管的是**声明层**——两份文档都声称拥有同一份清单，
必然判红。它管不到「有人抄了一张表却没在 front-matter 里声明」；那要靠**扫描层**
（判文档里的表形状），两者是互补的两道，见 `scripts/facts.test.mjs` 的跨文档判据。

### 分解：parent（父子机制）

「整体分解出部分」是跨 kind 的普遍需求：总目标分解出子目标（`GO→GO`）、大任务分解出小任务
（`T→T`）、产品功能分解出子功能、大阶段分解出子阶段。承载它的是 `parent` 字段——
**与 `deps` 正交的两个字段，各答一个问题**：

| | `deps` | `parent` |
|---|---|---|
| 回答什么 | 必须先有什么（前置义务） | 是谁的一部分（分解归属） |
| 图论形状 | DAG 的边（可跨 kind） | 树的边（只许同 kind，RG-024） |
| 强制性 | 生效档要求前置闭环（RG-008） | 父子状态档位单调（RG-025） |
| 与编号的关系 | 无约束 | 无约束——编号平铺，层级不进身份 |

- **值 = 单个父编号**（单值标量）：一个子条目只有一个父亲。多父没有语义——「两个大任务
 共享一个小任务」用两条 `deps` 边表达，`parent` 保持树形，渲染与查询才确定。
- **同 kind**：分解是同类事物的大小之分。任务服务于某阶段（跨 kind）用 `deps` 或正文引用，
 不塞进 `parent`——**一个字段一种语义**，塞两种就两种都读不出。
- **编号不体现父子**：`GO-001-前端去业务化` 的子目标是 `GO-002`、`GO-003`——平铺分配，
 弱约定「子条目在父编号之后取最近可用序号」（便于人读聚类与 diff，不是判据）。
 把层级编进编号（`GO-001.1`）是让身份承担会变的东西——与「目录不参与判定」同款哲学：
 位置与层级都是投影，编号是身份。
- **状态档位单调**（RG-025）：子条目进入生效档 ⇒ 父条目不得停在未生效档
 （「小任务都动起来了，大任务还没生效」是谎报）；父条目进入退场档 ⇒ 子条目不得停在生效档
 （「大任务已了结，还有小任务在进行」是谎报）。中间组合合法：父生效而子未生效（分解未动）、
 子退场而父仍生效（中途砍子项）。
- **呈现 = 投影**：各 kind `README.md` 汇总块的「分解树」小节（该 kind 用到 `parent` 时才出现）与
 `node scripts/registry-board.mjs --children=<编号>` / `--parent=<编号>` 是同一数据的
