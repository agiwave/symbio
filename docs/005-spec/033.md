## 规范

### §1 裁判权在条文，不在脚本

控制面的形状以**本规范的六条不变量**为准。既有判据码（`PTS-*` / `OB-*` / `CS-*` / `M-*` / `ME-*` / `IM-*`
以及 [DE-015-义务环](../003-design/015-义务环.md "DE-015-义务环") §6 的十六条）是**执行方**，不是裁判：

- 形状与脚本冲突时，**改脚本**；不得为保住一条绿而保留一个与不变量冲突的形状。
- 任何判据的新增、放宽、退场，必须能引用本规范的一条 `TC-n` 或 §2 的 `J0`；
  引不出来的改动视为"用脚本改形状"，评审直接否。
- 判据**降级为读数**（打印、计数、不判红）是合法的中间态；静默删除不合法——可观测性归读数，裁决权归条文。

这条规则的动机是**判据不能反过来冻结形状**：一条断言"当前中间构件有几份"的判据，
在形状收敛时必然变红，于是收敛动作被它挡住——那时候被改的通常是形状，不是判据。

### §2 元判据 J0：判据的断言对象必须在终态存在

> **J0**：一条判据的断言对象，必须是**目标形状里仍然存在的结构**。
> 若它断言的是一个只在过渡期存在的中间构件（host 份数、绑定表条数、旁路基线、视图行数、
> 结果壳个数、"这一步做过没有"的写法数量），它在终态下只有两种结局：
> **恒真**（失去判据作用）或**变红**（挡住收敛）。两种都不是判据。

`J0` 是剪枝规则，不是新增机制：它判的是**已有判据的性质**，不引入任何运行期概念。

例：`OB-001` 的"调度旁路点数 = 0"是**读数**（它数的是"过渡代码还剩多少"），
终态判据是 `TC-1` 的"选债口唯一"——读数可以留，裁决必须换。

### §3 六条终态判据

每条三样：**断言什么 / 为什么它是终态而非进度 / 反向用例**（无反向用例的判据不算判据）。

#### TC-1 唯一驱动形状

三句话，三个子判据——**只判其中一句会漏掉一整类退化**：

- **断言**：
  - `TC-1a` **循环体唯一**：控制面存在且只存在**一个**"选债 → 还债 → 读尾段对账"的循环体；
    其它任何推进路径必须是它的**调用**，不是它的复制。
  - `TC-1b` **选债口唯一**：任何一次"现在该还哪笔债"的判定，只能由那个循环体的选债调用做出。
    **在派发器之外直问求解器（`ring::owed`）再自行派发 = 第二个选债口**，即使它不是一段 `loop`。
    本条曾点名两处，两处各给了结论：`port::reap`（租约看护）**已不是反例**——它改读
    `stale_sent` 视图，「哪些尝试过期了」不是「该还哪一笔」，`lease` 行随之从 `ROWS` 删除；
    `port::round_trip`（自己 announce 又自己 dispatch）**也不是**——它不直问求解器，走的是
    `dispatch_with`，而身份由入参 `Round` 定死（集合里只有一个元素，「选」没有对象）；
    它自己落 `request` 是重入的记账（`awaited = false`、`max_attempts = 1`、付款方是闭包），
    与 `D-222` §一 判 `turn` 不是往返同一条理由。它的消失方式是 `D-222` 划界第 2 条：那三段
    各自行化之后自然没有调用点。
    **判据原文不变**：仍然禁"直问求解器再自行派发"，只是目前没有实例。
  - `TC-1c` **守卫同处**：中止 / 步数上界 / 空账本 / 写封闭 / **不重入**五道守卫在该循环体内各只有一份。
    "不重入"指：一个执行体的动作窗口内不得再起第二个环去还同一个 `store` 的债——
    它与前四道的区别是**它由类型守**（动作只拿到 `&mut Ctx`，拿不到第二份 `&mut Session`），
    而不是由一段 `if` 守；判据判的是"签名是否给得出第二份"。
- **终态性**：这是 [DE-015-义务环](../003-design/015-义务环.md "DE-015-义务环") §2.1 的原文
  （"没有别的调度代码"），并由 `D-222` 收掉了与它冲突的那条形状（幕是迭代器 / 幕是端口）——
  "幕"从此只是事实信封上的分区，不是推进单位。它与"有几个幕、几台 host、几种执行体"无关。
  五道而非四道的理由是可核的：`环不重入` 在四段循环的形状下**四段全是缺口**（嵌套环本身
  就是一次重入），把它漏在 `TC-1c` 之外，'一个环' 就只判到"循环体份数"，判不到"环里还能开环"。
  `TC-1b` 单独成句的理由是可执行的：**"一个循环体"与"一个选债口"不等价**，而退化更常发生在后者
  （一段一次性代码不需要循环，就能绕开派发器）。
- **反向用例**（三个，缺一不算判据）：
  - `1a`：在编排层再写一段 `loop { ring::drive(..).await? }` 的影子推进 ⇒ 红。
  - `1b`：在派发器之外 `ring::owed(...)` 之后自己写 `sent` / `response` ⇒ 红。
  - `1c`：把步数上界只放在某一个循环里，或让某一段推进不检查中止信号，或让执行体的动作
    拿得到第二个 `&mut Session`（重入）⇒ 红。
- **今天**：三条子判据的**形状**都已成立、**执行方**都未落地。形状的读数：循环体只剩
  `turn_exec::drive` 一处（`loop_rows::next` 只有一个调用点，五道守卫同在该函数内，第五道由类型守）；
  表外点问（`port::round_trip` 的判决 / 措辞两处调用）按 `D-222` 划界第 2 条不是选债口——
  它们各自行化之后调用点自然消失，行化本身是剩余施工。

#### TC-2 机制层无域名

- **断言**：`symbio-kernel` 与 `symbio-core` 的源码中，除声明表与测试外，
  不出现端口名 / 行名 / 执行体名 / 业务事件名的字面量。
- **终态性**：这是 §3.1「引擎只认识七个词」的直接形式化；名字永远属于插件，不属于机制层。
- **反向用例**：在 `kernel` 里写 `if port == "model"`、或按行名分支 ⇒ 判据必须红。
- **今天**：`PTS-002` 覆盖端口名、`CS-008` 覆盖事件名；**行名 / 执行体名无判据**。

#### TC-3 声明面封闭

- **断言**：装载期六张表一次交齐、七道检查全过、`seal` 是唯一出口；空行表被拒。
- **终态性**：这是"运行期不能注册"的类型表达，与形状无关。
- **反向用例**：让 `Session` 拿到可变注册口，或让 `seal` 在缺表时返回 `Ok` ⇒ 判据必须红。
- **今天**：判据 4/5/6/7/11/13 与装载期七道检查已成立。**保留它，是为了收敛动作不破坏它。**

#### TC-4 事实面唯一写方

- **断言**：每一笔往返（`request` / `sent` / `response` / `failed` / `retry`）、
  每一次控制面写入、每一个收束，在事实面有**唯一**写方（引擎格 / 端口记账层 / 执行体名单三者之一），
  且该写方可由日志判定。
- **终态性**：唯一写方是"回放可重建"的前提；它不随驱动循环有几段而变。
- **反向用例**：让执行体写 `sent`；或让两条路径都能写收束格 ⇒ 判据必须红。
- **今天**：`PTS-005` 守协议格、判据 9/10/15 守溯源与顺序；**收束格的多写方无判据**。

#### TC-5 横向扩展零改机制

- **断言**：新增一个世界端口的改动集 = 声明（`PortDecl` + 两行模板 + 事件名）+ 适配器；
  `symbio-kernel` 与 `symbio-core` 的公开面与求解器字节不变，且**不新增 host / 视图 / 驱动循环**。
- **终态性**：这是 [DE-002-架构总览](../003-design/002-架构总览.md "DE-002-架构总览") §5
  的"新增能力 = 加格子 + 加参数"；"加端口有多贵"是终态性质，不是进度。
- **反向用例**：让新端口必须自带一台 host 或一段循环才能跑 ⇒ 判据必须红。
- **今天**：判据 1 与 `PTS-003/004` 只冻结引擎字节，**数不到编排侧成本**。

#### TC-6 判据集是闭集

- **断言**：控制面判据的条数不随能力数增长；每条判据能指到唯一执行方，
  且其断言对象通过 `J0`。
- **终态性**：这是 [DE-002-架构总览](../003-design/002-架构总览.md "DE-002-架构总览") §3
  "清单会增长，判据不会"的自我应用：**判据集本身也受这条约束**。
- **反向用例**：为某一个新能力单独加一条专用判据（而不是让它落进 `TC-1`…`TC-5`）⇒ 判据必须红。
- **今天**：**无执行方**。

### §4 既有判据码的去向

三档处置：**保留**（断言终态结构）／**并入**（同类合并成一条，码保留为子判据）／**退场**（按 `J0` 降为读数）。

| 既有 | 处置 | 依据 |
|---|---|---|
| `PTS-001` 协议名闭集 | 保留 | `TC-2` 的子判据：端口是载荷，名字闭集 |
| `PTS-002` 引擎对端口无感 | 保留 | `TC-2` |
| `PTS-003` 求解器字节基线 | 保留 | `TC-5`：字节不变是终态性质 |
| `PTS-004` 基线挂得住决策 | 保留 | 冻结必须可追溯到一条决策 |
| `PTS-005` 协议格写方唯一 | 保留 | `TC-4` |
| `PTS-006` 契约 7 引重试裁决 | 保留 | 租约语义的唯一出处 |
| `OB-001` 调度旁路点数 | **退场（降为读数）** | `J0`：它数的是过渡代码残留量；裁决归 `TC-1b`（选债口唯一）——旁路点就是第二个选债口 |
| `OB-002` 幂等点问条数 | **退场（降为读数）** | `J0`：行内"再问一次还欠不欠"是过渡形状的伴随物；终态由 `TC-1b` 覆盖（在派发器之外问求解器就是第二个选债口） |
| `OB-003` 直调点点名的行必须存在 | **并入 `TC-3`** | 它断言的"行名可解析"在终态不是运行期读数，而是装载期的事（第七道检查：执行体收口）。码保留为子判据，判红照旧 |
| `OB-004` 幂等点问就地承认 | **退场（降为读数）** | `J0`：`by: None` 的行**唯一的派发点就是那一处直问**——这正是"没有选债口"的形状。终态由 `TC-1b` 判，承认账本随直问一起消失 |
| `CS-001` / `CS-002` 形状棘轮 | 保留 | 只许降的棘轮断言的是"机制面不变宽"，是终态性质 |
| `CS-008` 零事件名字面量 | 保留 | `TC-2` 的一半 |
| `CS-003` / `CS-009` | 保留 | core 纯度与体量棘轮 |
| `M-*` / `ME-*` / `IM-*` | **出范围** | 三者分别断言前端机制化、机制强制等级清单、内部请求绕过档位闸门——没有一条落在本规范的 `scope`（控制面的环与派发面）里。它们的裁判权归各自那篇文档；本规范不替它们背书，也不替它们退场 |
| DE-015 §6 判据 1–13、15 | 并入 | 成为 `TC-3` / `TC-4` 的子判据，码与执行方不动 |
| DE-015 §6 判据 14（无进展守卫） | **改写** | 形态随 `TC-1` 归一：守卫只有一处，"落不落收束格"不再按 host 逐个判 |
| DE-015 §6 判据 16（租约可恢复） | 保留 | 终态仍要有"只给日志也能恢复" |
| J1–J9 运行期取证 | 并入 | 归 `TC-4` 的运行期半边；判定脚本不废 |

**本表不再有"待裁定"行**：每条都有 `J0` 判决，且判决在执行方上已经生效（退场的四条改成读数、并入的保留判红）。
新增判据仍按同一条纪律回写本表——**"待裁定"是暂时状态，不是空白支票**。

### §5 退场程序

1. **先写读数，再撤红**：把判据从"判红"改成"打印计数"是一次改动，撤掉脚本是下一次改动；
   两次改动都能单独回退。
2. **退场必须留承接**：被退场的判据，其覆盖面必须由某条 `TC-n` 的子判据接住，
   并在本规范 §4 写明是哪一条。接不住的不许退场。
3. **豁免不许长期**：任何"暂时跳过"的豁免必须挂期限与承接任务，不挂的不进仓。
4. **反向用例先落地**：`TC-n` 的执行方落地时，反向用例与该判据同批提交——没有反向用例的判据
   无法区分"真的在算"与"恰好没写错"（[DE-002-架构总览](../003-design/002-架构总览.md "DE-002-架构总览") §6 纪律 3/4）。

## 判据

本规范的判据面由三处既有脚本承接，逐条对应到 `TC-n`：

| `TC-n` | 今天的执行方 | 落地后 |
|---|---|---|
| `TC-1` | 无（人工评审） | `scripts/` 下的控制面不变量脚本（新增，判据码待登记） |
| `TC-2` | `scripts/port-surface-audit.mjs`（`PTS-002`）、`scripts/core-shape-audit.mjs`（`CS-008`） | 同一脚本扩到行名 / 执行体名 |
| `TC-3` | 装载期七道检查 + `scripts/obligation-ring-accept.mjs` | 不变 |
| `TC-4` | `scripts/port-surface-audit.mjs`（`PTS-005`）+ `scripts/obligation-ring-accept.mjs`（J 组） | 补"收束格唯一写方" |
| `TC-5` | `scripts/port-surface-audit.mjs`（`PTS-003` / `PTS-004`） | 补"不改 host / 视图 / 驱动循环"的静态判据 |
| `TC-6` | `scripts/gate-codes-audit.mjs`（码命名空间） | 补"判据条数不随能力增长"的元判据 |

`TC-n` 是本规范的条文编号，不是判据码：判据码（`@ns` 声明的 `XX-000`）在执行方脚本落地时
按 `scripts/gate-codes-audit.mjs` 的命名空间规则登记，并由
[RE-008-判据码登记表](../004-ref/GATE_CODES.md "RE-008-判据码登记表") 汇总。
