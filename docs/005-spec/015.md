## 规范

`#[allow(dead_code)]` 的承认必须同时满足三条，否则死码审计等于自废：

1. **承认必须挂计划步**：理由里写 `04 §3.1 批N`（或 `04 §3.1 C 类`），且 N 属于本条的批号闭集——
 「一处死码 ↔ 一个清偿步」双向可查；
2. **棘轮只许降**：基线 `R002_BASELINE` 随批次下调，不随意志上调；每次下调在代码里写明理由；
3. **C 类结构性承认**：消费方是前端镜像 / JS 审计而非 Rust 调用点，rustc 永远会报；
 其完成判据不是「接入」，而是**理由写明消费方名**，且数量锁死。

**批号闭集**（本条是它的唯一 owner）：批① · 批② · 批③ · 批④ · 批⑤ · 批⑥ · 批⑦ · 批⑧ ·
批⑨ · 批⑩ · 批⑪ · 批⑫ · C 类。终局基线 = **8**（余下全是 C 类）。

## 判据

`scripts/dead-code-audit.mjs` 的 R-002 段（`R002_BASELINE = 8` + 批号对账 `REF_RE`）；
