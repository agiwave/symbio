## 规范

五条纪律各自治一种「看起来闭环、实际空转」的形态。它们原先各自成篇，但失效面是同一批
（文档与注释的写法、问题的收口方式、出口与豁免的可核对性），合并后共同前提只写一遍。

## 1. 只写目标态：注释只写不变量与陷阱，不写过程

**只写目标态**：注释与文档**只描述现在是什么**。以 `TODO` / `FIXME` 起头的注释、
或只写「批 N」却不给任务编号出处的注释，都是过程叙述 ⇒ 红。
追溯走 `git log -S<符号>` / `git log --grep=<词>`；要保留「为什么否决 A 选 B」的结论，
写进 [docs/003-design/](../003-design/README.md "DE-000-设计总览") 的一条决策——**那才是它的 owner**。

它防的是：注释叙述过程 ⇒ 代码改了注释不改，且读者分不清哪句还成立。

## 2. 机制优先：每条问题落成守卫 / 真源 / 类型约束

**机制优先**：每条问题必须落成**一个守卫 / 一份真源 / 一个类型约束**；
只做人工修正不算闭环——人工修一次，同类问题下一轮再来（本仓同类削格已发生两次）。

它与 §4（出口可核对）是同一件事的两半：本条要求问题落守卫，§4 要求**出口不许依赖一个
尚不存在的守卫**。

## 3. 不新增真相：改文档前先确认那条事实的 owner

**不新增真相**：改文档时先确认那条事实的 **owner**（职责边界表见
[docs/README.md](../README.md "docs/README")），其余位置一律**链接**，不复述。
同一事实写两处 ⇒ 改一次要动两处，必然漂移。

## 4. 出口可核对：判据要么是守卫，要么是脚本可核对的锚

**出口可核对**：批次的出口判据要么是**一条守卫**，要么是一处**脚本可核对的锚**
（存在性 / 计数 / 逐字一致）；「靠人读完觉得对」不算出口。

**锚必须是版本化的地址**：写进 `evidence` / `where` / `exit` 的仓内路径若被 `.gitignore`
覆盖（`tmp` 与 `logs` 目录、`.workbuddy-ai` 一类），它在**下一次提交**就不可核对——
那不是锚，是「此刻在我机器上存在」。

它防的是：出口挂在一个不会有人去建的东西上 ⇒ 那一批退化成一次性人工修正，
**而它看起来已经闭环**。决策型改进无法整条机械化时，出口必须收窄到本条认可的那类锚。

## 5. 豁免必有清除任务：无清除任务的豁免不许登记

**豁免必有清除任务**：任何豁免（守卫豁免注释 / 豁免账本条目）必须登记成
[docs/005-spec/](README.md "SP-000-规范汇总") 的 `WVR-*` 条目，且 `clears` **非空**（指到一个任务编号）；
无清除任务的豁免不许登记。

它防的是：豁免是「现在不修」的决定——没有清除任务的豁免会变成**永久豁免**，
问题被静默豁免掉之后再也没人回来看它。

**清除任务闭环即当批删除。** `baseline-allow` 这类挂在基线数字上的豁免，一旦门禁
（`baseline-scope`）判定「相对基线已无 diff」，豁免本身就到了清除点：当批删除，
不许留给下一批。过期豁免与「补记不是消红工具」（`scripts/core-change-backfill.mjs`
的头注释、`D-333`）是一对：一个不许拿豁免当橡皮图章，一个不许把过期豁免留成下一批
的债。两者都是「把判断留在当下」，不是「把流程走完」。

| §4 | `registry-audit` 的两半：`RG-012`（`exit` 指认的路径此刻存在）、`RG-032`（`evidence` / `where` / `exit` 里的仓内路径不被 `.gitignore` 覆盖）；「这条出口够不够强」是评审的事 |
