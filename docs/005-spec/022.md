## 规范

五条纪律共同回答一个问题：**「已证明」这句话什么时候算数**。它们原先各自成篇，
但判据面是同一批（`docs/003-design/verify/` 的程序与断言），分开发布只会让读者
逐篇拼出同一条推理链——合成一篇，编号保留为节号。

### 1. 每条声称对应一条可执行断言

它拦住的反模式：零断言的程序不可能失败：多个程序只有一条断言时，「全部通过」是空的。

### 2. 断言的输入不得包含结论

把结论写成常量再断言常量：例如把「是否会增长」硬编码成 `false`，再断言它不增长。

### 3. 每条断言配反向用例（改输入，结论必须变）

它拦住的反模式：硬编码返回值：改任何输入，结论都不变。

### 4. 声称「编译期强制」必须附一段已知编译不过的代码

「强制」没有反向用例时，无法区分「真的强制」与「恰好没写错」。

### 5. 编译期反例必须写在外部模块里

私有字段同模块内可访问；反例写错位置会「编译通过」，于是「必须失败」变成假话。
