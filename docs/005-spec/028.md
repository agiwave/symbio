## 规范

本册收四处**形态特殊**的豁免：它们都不是「以后会修」，而是**随机制存在**或**契约登记**，
所以清除任务一栏是「无（已闭环）」。每处只记「该豁免存在、形态为何、谁来清」；逐条理由
归各处注释，豁免的通用纪律（必有清除任务、闭环即删）见 [SP-010 §5](010.md "SP-010")。

## 1. doc-link D-004 全文豁免（定义变更史禁区的两处反例措辞）

**形态：随机制存在**——定义「现行文档不写变更史」这条规矩的文档，必须引用反例措辞（「曾经…已改为…」、带量词的 `五条 → 七条`）才能界定禁止范围。
范围：`docs/README.md` 首行的 `doc-link-allow D-004`。
清除任务：无（复核了全部四条豁免通道，本条判为机制自指、随机制存在）。

## 2. dead-code R-002 契约登记存量（8 处）

**形态：契约登记（非待清）**——协议契约键 / 词表常量先于接线，消费方是协议字段表与前端镜像（Rust 侧无调用点）。
范围：`scripts/audits/dead-code-audit.mjs` 的 R-002 死码承认账本（终局基线 8；账本与理由见 [DE-016](../003-design/016-工程落地与验证.md "DE-016-工程落地与验证") 的 SLO 与量化一节）。
清除任务：无（复核后保留为契约登记形态）；逐条理由归账本注释。

## 3. panic-allow 不变量登记（C7，56 个登记项 / 71 处 panic 面）

**形态：不变量显式登记（非事故）**——逐处写明「为何它是不变量而非事故」，数量走只减棘轮；空理由仍红。
范围：`crates/**` 的 panic-allow 注释、`scripts/audits/panic-audit.mjs` 账本与 `scripts/gate.d/_shared.mjs` 的 `BASELINE.panicSites`。
清除任务：无（复核后保留为登记形态）；逐条理由归各处 `panic-allow` 注释。

## 4. color 守卫自指豁免（测试与实现提到禁用模式）

**形态：随机制存在**——守卫必须能提到模式才能检出它：回归测试的夹具与实现的匹配逻辑本身就会写出这些字样。
范围：`scripts/color.test.mjs`（守卫回归与实现里的禁用模式字样）。
清除任务：无（本条判为机制自指、随机制存在）。

## 判据
