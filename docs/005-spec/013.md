## 规范

限定名 `13 §0 纪律 4`（编号沿用 13 篇的命名空间）。

**出口可核对**：批次的出口判据要么是**一条守卫**，要么是一处**脚本可核对的锚**
（存在性 / 计数 / 逐字一致）；「靠人读完觉得对」不算出口。

**锚必须是版本化的地址**：写进 `evidence` / `where` / `exit` 的仓内路径若被 `.gitignore`
覆盖（`tmp` 与 `logs` 目录、`.workbuddy-ai` 一类），它在**下一次提交**就不可核对——
那不是锚，是「此刻在我机器上存在」。判据码 `RG-032`。

它防的是：出口挂在一个不会有人去建的东西上 ⇒ 那一批退化成一次性人工修正，
**而它看起来已经闭环**。决策型改进无法整条机械化时，出口必须收窄到本条认可的那类锚。

## 判据

`registry-audit` 判两半、评审判强度：

- `RG-012`：`exit` 指认的路径**此刻存在**；
- `RG-032`：`evidence` / `where` / `exit` 里的仓内路径**不被 `.gitignore` 覆盖**（可核对性）。

它判不出「这条出口够不够强」——判强度是评审的事。
