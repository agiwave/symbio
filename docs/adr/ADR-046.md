## 决策

**背景（为什么补这一条）**：B 系列（`feat/v2-bridge-b1-fact-envelope`，停更于
2026-09-30）走的是「事实能力做成插件」的路线——`plugins/fact_log`（8 文件
39679 字节，含 3 份测试）加 `projection` / `retrieval` / `actor` / `delegate`
四个配套插件，配 `docs/plan/06-落地桥接方案.md`。这条路线在本分支**既没被使用
也没被记录**：`docs/plan/` 与 `docs/decisions/` 里 `fact_log` 命中 **0 次**，
06 号文档已由 [会话响应性落地](../archive/06-会话响应性落地.md) 取代。ADR-043/044 记的是事实
**怎么**入网格，没有一条记「为什么**不是**一个插件」。

缺的不是文风：下一个人打开那个分支，无从判断它是废弃实验还是待合并的工作。

**决策**：事实的**写入**与**派生**都留在 `symbio_core`（`store` + `projection`，
即 ADR-043 已冻结的形状），不引入 `fact_log` 这类可选插件；事实的可选消费走既有
`CapabilityVisitor` / `transcript` 投影面。

**理由**：

1. **「可选」与「必须有值」不能是同一个机制。** `fact_log` 自述是「可选的……
   停用/未装 ⇒ 系统照常运行（平凡值）……它提供的**增强**，不是地基」。而
   ADR-044 要求成本/时延/兜底率是事件网格的**一等数据**。地基不能由一个可以被
   关掉的插件提供：关掉它，审计照旧全绿，**数字却整体消失，没有任何东西变红**。
2. **从磁盘派生 ≠ 落盘即有。** `fact_log` 明写「**不订阅运行时事件，而是从磁盘
   派生**」（读 `<homedir>/session/<id>/messages.json` 重建）。这把「发生过什么」
   变成每次消费的全量重放，且轮次编号与幂等键需要从存储形状**反推**——ADR-044
   要求的恰恰是它们**靠构造成立**（`attempt` 递增、N2 溯源）。core 侧 `wal` 在
   发生时写，两者不是同一类东西。
3. **「零插件依赖」是伪装的契约依赖。** 它自称「只读磁盘上的公开布局，不 import
   任何插件 ⇒ 零插件依赖」。不 import 是真的，但它对 `messages.json` 的形状有**硬
   契约**——一条没有类型、没有编译期信号的耦合，正是 ADR-023 说的「模块间隐式
   耦合」：谁都不认识谁，却谁也改不动。
4. **位置由依赖方数量决定（ADR-023）。** 消费事实的不是某一个能力，而是审计 /
   SLO / 检索 / 巩固 / 会话恢复……多方依赖 ⇒ 进 core；只有一方用 ⇒ 才沉回插件。
   按这条判据，它本来就不该以「增强」的身份存在。
5. **ADR-043 已经把位置定死了**：契约居中于中性层，`store` / `projection` 按
   冻结形状进 core。再开一个 `fact_log` 就是**同一事实第二个写方**，与本仓
   「一个事实只有一个 owner」直接冲突。

**被否决的方案**：

- **插件式 `fact_log`（B 系列路线）**——见理由 1–3。否的不是实现质量（那 8 个
  文件带 3 份测试，实现是完整的），是**它把地基做成了增强**。
- **把 `projection` 也做成插件**——同上，且会让 ADR-043 的「冻结形状」变成可选项，
  F1 / F2 面随插件装卸而存在或消失。
- **两条路线并存（插件与 core 各写一份）**——直接违反「一个事实只有一个 owner」，
  且两边对同一份 `messages.json` 的解读必然漂移。

**后果与不变量**：`feat/v2-bridge-b1-fact-envelope` 的状态 = **设计已被取代，
代码未移植**——它的**插件式结构**不在移植清单上；其中的**体验价值**（前端主会话
快照化、委派者三项真源等）另按 `docs/plan/` 的路径评估，且改行为面的先写 ADR。
本分支事实链路保持单写方：`v2_bridge` / `v2_exec` 转写 → `symbio_core::store`
（WAL）→ `symbio_core::projection`，`check_all` 全绿。
