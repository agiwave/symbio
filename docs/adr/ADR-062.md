## 决策

事实源里的每条事件必须完整回答**谁（actor）、何时（ts）、发生了什么**。这条不变量此前只对 seq 成立（2026-09-30 事故后收口到 [`Store`](../plan/PL-001-核心架构.md "PL-001-核心架构") 唯一写入口），对 actor 与 ts 一直裸奔，`d781a6c7` 号会话把它暴露成灾：363 条助手与工具产出被记成 `actor: "user"`（写入方写死 `PRINCIPAL_USER`），548 个事件 `ts` 全为 0（十余处 `Event::pending` 构造点多数没填时刻）。本 ADR 定下两个字段的收口位置与理由：

1. **actor 归属收口在写入方**（`plugins/session/v2_messages` 的 `append_actor_and_ts`）：按消息真实来源派生——消息自带 `principal` 则认它（转播不许串主体）；否则按 role 派生（user 消息 → `user`，其余 → 会话主体），复用 `plugin::attributed` 的既有纪律。**不收口到存储层**：存储层拿到的事件 actor 字段已填，无法机械判定对错；错值只有知道「这条消息从哪来」的写入方能防。
2. **ts 兜底收口在 [`WalStore::append`](../plan/PL-001-核心架构.md "PL-001-核心架构")**：落格时 `ts == 0`（`Event::pending` 的「没填」哨兵）⇒ 以落格时刻为准，与 `assign_seq` 同点同纪律（仅由 Store 在唯一写入口调用，见 [`EventEnvelope::fallback_timestamp`](../plan/PL-001-核心架构.md "PL-001-核心架构")）。**MemoryStore 刻意不兜底**：它是平凡基线（`store = memory`，S0），大量测试靠 `ts = 0`（时间起点）+ 小 `now` 做 as-of 断言，兜底会毁掉测试确定性（实测：两处都兜底时 9 个 actors 测试转红）。
3. **判据落点**：`v2_messages.test` 四条归属用例（助手产出署本会话主体 / 工具结果不署 user / 用户消息才署 user / 自带 principal 优先）+ 一条 ts 用例（没带时刻退到落格时刻，不许写 0）。

## 后果

- 事实源里从此不再产生 `actor 冒用` 与 `ts = 0` 的新事件（WAL 路径）；`turn_runner` 等十余处构造点**不需要逐处手改**——这正是收口的意义：修一处 = 修全部。
- 代价：as-of 语义在 WAL 上多一层约定——「没带时刻的事件以落格时刻计」，读侧无需感知（`0` 本来就被投影当过去处理）。
- 不变量从此有守卫：谁再在写入方写死 `PRINCIPAL_USER`、或新造一条 ts=0 入 WAL 的路径，判据测试与既有用例都会红。
