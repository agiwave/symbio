## 决策

**背景**：ADR-048 把「`full` 让工具结果从 `role=tool` **降级**成 user 消息里的纯文本」记为「未验证的假设」。**复核后判定：这不是假设，是明确的退步**——本条把它钉成决策。

**决策**：v2 的 prompt **必须是结构化消息数组**，保留 `role`（`user` / `assistant` / `tool`）与 `tool_call_id`，**不得**把整段对话渲染成一条 user 消息的纯文本。

**理由**：

1. **工具结果的承载方式是协议，不是排版。** `ModelProvider::execute_turn` 的签名就是 `(system_prompt, messages: &[ChatMessage], tools, root_id, env)`——`role: tool` + `tool_call_id` 是**跨栈契约**（模型插件把它序列化成各家协议的 tool 段）。v2 在 `ProviderLlmAdapter::generate_turn` 里把渲染结果包成**一条** user 消息（`&[message]`，单元素），等于**在适配器边界把结构化输入拍平成纯文本**：工具结果失去「这是哪个调用的结果」的机器可读关联（只剩散文里的 `工具结果(名)`）；整段会话以「用户说的内容」的身份进模型，而不是以**对话**的身份；模型是在 `role: tool` 结构上训练工具使用的，把它降级进 user 消息是格式上的退步。
2. **「prompt 从事实网格投影」的正确形态是「投影成消息数组」，不是「投影成一段文本」。** ADR-048 的立身之本（事实网格 = 对话的唯一真源）**不要求**把消息拍平——transcript 投影本来就有 `role`（`user` / `assistant` / `tool`）这个字段，是**拍平**把它渲染成了散文。投影出 `Vec<ChatMessage>`，「唯一真源」与「结构化协议」两个目标可以同时成立。
3. **飞轮的方向相反。** 行业在往「显式结构 + 更长的工具链 + 更强的工具调用」走，把结构拍平成散文是往回走。

**被否决的方案**：

- **保持拍平，理由是「渲染点唯一、模型看到的就是事实源投影」**：否决。可观测性归 `session/stats` 与 transcript 投影，**不归 prompt 形状**；拍平换来的「一处渲染」收益，远小于丢掉协议结构的代价。
- **「先跑一段，看效果再定」**：否决。当时本仓没有任何度量能回答「拍平对模型是变好还是变坏」（ADR-048 后果节已记），所以「看效果」在没有度量时等于凭感觉拍板——而现状是**已知的协议退步**，不需要实验来证明它更差。（该缺口后来补上了：模型侧读数见 [T-048](../task/T-048.md) 与其报告 `docs/ref/PROMPT_AB.md`。它**不改本条判定**，但把代价换了位置：拍平在「把题做对」上没有可测的损失，代价落在它新引入的失败面上——调用信息从协议字段掉进正文，运行时必须再写一个「模型内部格式」解析器才读得到同一个工具名。）
- **在 `full` 档保留拍平、另加一个「结构化 prompt」档**：否决。两个 prompt 形状意味着两条要各自验证的行为面，而它们的差别恰好是**静默**的（形状不同、都能跑通），无法靠门禁发现。形状只该有一个。

**后果与不变量**：

- **落点**：transcript 投影的「投影成消息数组」出口（`to_messages`）；`TurnRunner` 把基线 prompt 从 `String` 改为 `Vec<ChatMessage>`；`LlmAdapter` 的 `generate*` 系列相应改为收消息数组（**adapter 边界不再拍平**）；`ProviderLlmAdapter` 把数组原样交给 `ModelProvider::execute_turn`。
- **`TurnInput::prefix` 的位置**：前缀是「排在基线之前的若干行」，落成**插在消息数组最前的一条 `system` 消息**（记忆段 / 就绪段 / 委派者段拼在一条里、按空行分段）——标成 `user` 就是在说「这是用户说的话」。语义优先级（记忆 → 就绪 → 委派者）不变。
- **本轮工具交换直接进消息数组**（`tool` 角色 + `tool_call_id`），不拼格式。
- **不变量**：事实网格仍是唯一真源（投影换呈现不换来源）；不变量集合不变（新增投影出口不新增事件、不改既有判据）。
