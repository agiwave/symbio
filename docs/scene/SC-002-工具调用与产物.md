# 工具调用与产物

> **一句话**：能动手调工具干活，并把结果留成看得见、可追溯的凭证。
> 支撑能力：[ST-002-工具调用与产物](../stage/ST-002-工具调用与产物.md)

## 场景

用户让智能体做一件实事：搜一下、算一笔、读写一个文件。结果不该只是随口复述，
而要留成一个后续步骤能引用的凭证，对话里也能看见"它调了什么、拿到了什么"。
今天的痛：只会用文字描述结果的智能体干不了实事；干了实事也说不清自己刚才做了什么，
下一轮把同一件事再做一遍。

## 用户判据（诚实账）

| # | 用户应该看到 | 判据现状 |
|---|---|---|
| 1 | 文件被真的读写出去，工具调用真实发生 | e2e：t3（文件写入）/ t2（工具往返）（已有） |
| 2 | 工具调用在对话里看得见——一张工具卡片，不是凭空冒出结果 | e2e：t38 / t26（已有） |
| 3 | 工具失败有可见反馈，不是静默 | e2e：t27（失败重试）/ t48（超限反馈）（已有） |
| 4 | 模型记得自己调用过什么、拿到了什么，不重复调用 | e2e：t27 / t55 / t59（已有） |

## 边界

不含把一件活拆成多步、也不含验退返工；产物不跨会话保留；
"该不该调用这个工具"的判断本身不在系统保证范围内。
