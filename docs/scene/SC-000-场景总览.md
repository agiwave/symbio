# 场景总览 · 角色与用户判据

> **这一组文件是什么**：`scene` 是产品层的 kind，回答**「用户拿它做什么」**——
> 这正是 [GO-000 §2](../goal/GO-000-价值主张.md "GO-000-价值主张") 承认没人回答的问题：
> 全部判据都是架构项，没有一条回答用户得到了什么。SC-001…013 与
> [ST 阶梯](../stage/ST-000-路线图总览.md "ST-000-路线图总览") 13 阶一一对应
> （**播种的巧合，不是结构承诺**——未来一个阶段可以点亮半个场景，一个场景可以跨两阶）：
> 场景回答「用户得到了什么、拿什么证明」，阶梯回答「要长这个能力需要改架构吗」；
> **用户判据与边界的唯一账本在本组**，ST 的 §7/§8 只是指针。

---

## 1. 服务对象（角色）

**在自己的设备上运营自己智能体的个人**——先是自己这样的开发者 / 知识工作者，
不是团队席位，不是 SaaS 租户。依据是三条已成立的事实，不是愿景：

1. **本地优先**：Tauri 桌面壳 + `~/.symbio` 实体仓，没有服务器租用形态；
2. **个人认知域**：S10 的目标是注入"**某个人的**认知体系"，不是组织知识库；
3. **没有多人协作面**：前端没有团队 / 权限 / 共享工作区的任何产品化设计。

多主体（S08）与多智能体社会（S13）扩展的是 **agent 之间的组织**，不是人与人协作；
第二类角色（被服务的人）何时成为一等公民，是 S08 落地后的修订题，届时改本节。

## 2. 概念栈：谁拥有哪个词

| 概念 | 回答什么 | 唯一 owner |
|---|---|---|
| **角色** | 谁在用 | 本文 §1 |
| **场景** | 什么情境下完成什么 Job | SC-001…013 单文档（本文 §3 只做汇总表） |
| **能力** | 平台可复用的行为单元 | [PL-002 能力坐标系](../plan/PL-002-能力坐标系.md "PL-002-能力坐标系")（五维 + 高阶判定）；ST 阶 = 点亮顺序 |
| **功能** | 能力在界面 / 协议上的用户可见切片 | [RE-006 §2/§3](../ref/RE-006-当前事实表.md "RE-006-当前事实表")（代码投影，不手抄） |
| **品质** | 横切属性（时延 / 回放承诺 / 可关闭） | [PL-001 核心架构](../plan/PL-001-核心架构.md "PL-001-核心架构") 三条不变量 + [PL-010 价值验收与基线埋点](../plan/PL-010-价值验收与基线埋点.md "PL-010-价值验收与基线埋点")（读数口） |

功能层**不在此建清单**：它是能力×界面的投影，事实表每次从代码重生成——
在场景文档里手抄功能清单，等于再造一张必然漂移的表。

## 4. 判据与边界：本组是唯一 owner

用户判据（看到什么 / 拿什么证明 / 缺什么）与边界的**唯一账本在本组，不在 ST**——
ST 的 §7/§8 是指针。判据现状逐行如实（已有 e2e / 已有读数口 / 缺口），
缺口统一挂 [T-011](../task/T-011.md)（外部效标）——它是本组文件与 GO-000 §2 诚实缺口的共同执行方。规则：

- **补判据 / 销缺口 / 改边界** = 只改对应 SC 单文档，不动 ST；
- **新场景** = 新建 SC 单文档 + 本文 §3 加一行；
- **场景废止** = 该文档 `status: retired`，本文表行同步移除，不物理删除；
- **角色修订** = 只改本文 §1；
- **禁止**在场景文档里复制 ST 的机制论证（§1–§6）——那是指向 `[[ST-0NN]]` 的事。
